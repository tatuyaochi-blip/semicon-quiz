# 企画案: 解説記事のコーナー「やさしい解説」(2026-10-23)

運営者の依頼(初心者が素朴な疑問から読み始め、意味・しくみ・身近な使われ方まで理解できる記事のコーナー)に対する企画案。今回は企画まで。実装・記事の作成はしていない。

## 1. サイトの現状(確認できた事実)

2026-10-23 時点で、リポジトリと Search Console のデータから確認した。

- 量: 分野80・問題3,787問・用語1,332語(うち詳しい解説と FAQ つき812語)・比較ページ129件・図解45点・計算ツール63本・学習コース8本。7言語で公開ページ約3.7万
- 記事に近いページはすでに少しある: 「微細化の先へ」(beyond-scaling、約1.8万字の読み物)、IT 試験ガイド、ニュースの言葉(5語。なぜ話題か・背景・違いの形式)、職種の紹介(8職種)、面接の質問集
- **入門の入口がない**: 用語集に「CPU」「半導体」「トランジスタ」「メモリ」「OS」「集積回路」「クラウド」「2進数」「プロセスノード(◯nm)」の項目がない。自動リンクの都合で一般的すぎる語を避けてきたため。いちばん検索される素朴な疑問(〜とは)に答えるページがサイトにない
- **既存の説明は中〜上級向け**: 用語の詳しい解説は1語あたり中央値で約1,100字。たとえば GPU の解説は SM・ワープ・SIMT から始まる。分野の紹介文も「半導体の性質は…バンドギャップで大きく決まります」から始まる。予備知識の少ない人には入りにくい
- 学習コース「はじめての半導体」「トランジスタからソフトウェアまで」は、分野を並べた道順はあるが、分野に入る前の読み物がない
- 検索(Google に出て約1週間、10-15〜10-20): クリックは1日6 → 59と伸びている。表示の約8割が用語ページ。1ページあたりの表示は比較ページが最も多い。問題ページは少ない。言語別では繁体字が平均約9位と強く、英語は50〜80位(新しいサイトで被リンクが少ないため、とみている)

## 2. 有用性と課題(率直な評価)

### 有用な点
1. **空いている層を埋める**: 今のサイトは学生・技術者・資格の受験者向けで、「ニュースで聞いた」「仕事で半導体に関わることになった」という初心者が最初に読むページがない。記事はこの層の入口になる
2. **ほかのページの価値を上げる**: 記事は、すでにある用語1,332語・比較129件・図解45点・クイズ3,787問へ読者を案内する「道」になる。中身をゼロから作るのではなく、既存の資産を初心者向けにつなぎ直せる
3. **半導体からソフトウェアまでを一続きで説明できる**: 「トランジスタ → 論理回路 → CPU → OS → ネットワーク」を一つのサイトで通せるのは、半導体専門のサイトにも IT 用語辞典にもない強み
4. **共有されやすい**: 用語やクイズよりも、読み物のほうが SNS や授業・社内研修で紹介されやすい。被リンクが少ないという英語版の弱点にも長い目で効く

### 課題
1. **「〇〇とは」の大きな検索語は競争が激しい**: 「CPUとは」の上位は IT 用語辞典・メーカー・大手メディア・Wikipedia。新しいサイトがすぐに上位に入ることは期待しにくい。→ 大きな語だけを狙わず、「なぜ」「どうやって」「◯◯の数字の意味」など、答えがまとまっていない疑問を主に狙う。大きな語の記事は、サイトの入口と内部の道としての価値を主に見込む
2. **用語ページとの食い合い**: 同じ語の記事と用語ページが両方あると、検索でどちらも弱くなるおそれがある。→ 役割を分ける(3章)。用語集にない入門の語(CPU など)は、記事をその語の唯一の「とは」のページにする
3. **やさしく書くほど誤りが入りやすい**: たとえ話や省略で、誤解を生むことがある(「CPU は脳」「nm はトランジスタの大きさ」など)。→ 記事ごとに「たとえの限界」「よくある誤解」を書き、事実確認を別の担当が行う(6章)
4. **大量生産に見えると逆効果**: 似た型の記事を短期間に大量に出すと、検索エンジンにも読者にも価値が低いと見られるおそれがある。→ 1本ごとに独自の図・既存のクイズやツールとの連携を入れ、本数より質を優先する(週1〜2本が上限の目安)
5. **翻訳と更新の手間**: 記事は長く、7言語に訳すと手間が大きい。市場シェアや最先端の数字はすぐ古くなる。→ まず日本語で出し、成績を見て英語・繁体字に広げる。古くなる数字には時点を書き、見直しの時期を決める
6. **成果が出るまで時間がかかる**: 検索で評価されるには数か月かかる。短期の判断は、検索の順位よりもサイト内の回遊(記事からクイズ・用語へ進んだ割合)で見る

総合: **やる価値は高い**。ただし「大きな語で検索1位を取る」ではなく、「初心者の入口と、既存の大量の中身への道を作る」ことを主な目的にし、少ない本数から始めて成績で広げるのがよい。

## 3. 推奨する企画

### 名前と場所(仮定)
- コーナー名: 日本語「やさしい解説」、英語「Explainers」、繁体字「入門解說」
- URL: /learn/(一覧)、/learn/{slug}/(記事)。ヘッダーのメニューに「やさしい解説」を加える

### 対象読者と応える疑問
| 読者 | 状況 | 応える疑問・困りごと |
|---|---|---|
| A. ニュースで気になった一般の人 | TSMC 熊本・Rapidus・NVIDIA・「2nm」などを見聞きした | そもそも何か、なぜ大事なのか、なぜ日本や世界が騒いでいるのか |
| B. 半導体・IT の会社に入った人、就活生 | 文系出身や営業・事務・新人技術者。社内の言葉がわからない | 会社の製品や工程の言葉の意味、全体の中での位置づけ |
| C. 高校生・高専・大学1〜2年、IT パスポート・基本情報の受験者 | 教科書では式や用語から入るので、イメージがつかめない | しくみのイメージ、試験で問われる言葉の意味 |
| D. 既存の利用者(クイズ・用語) | 問題を解いたが、土台の理解があいまい | 分野に入る前の全体像 |

主な対象は A〜C。専門家向けの内容は既存の用語の詳しい解説・比較・クイズに任せ、記事はそこまでの橋渡しに徹する。

### 既存のページとの役割分担
| 種類 | 役割 | 読者の問い | 長さの目安 |
|---|---|---|---|
| **やさしい解説(新)** | 素朴な疑問から全体像としくみを理解する読み物 | 「それって何? なぜ? どうやって?」 | 4,000〜7,000字 |
| 用語集 | 正確な定義を引く辞書 | 「この語の意味は?」 | 1行〜1,500字 |
| 比較 | 似たものの違いを表で整理 | 「AとBの違いは?」 | 表+解説 |
| 図解 | 一つのしくみを1枚の図で | 「どういう構造?」 | 図+説明 |
| クイズ | 理解の確認と定着 | 「わかったか確かめたい」 | 10問〜 |
| 計算ツール | 数字を変えて試す | 「数字で確かめたい」 | — |
| 学習コース | 分野を学ぶ順番 | 「何から学べばいい?」 | 分野の並び |
| ニュースの言葉 | 時事の語を短く | 「ニュースのこの語は?」 | 短め |

- 記事は「理解の入口」、用語は「辞書」、比較・図解は「部品」、クイズは「確認」。記事の中で用語・比較・図解を引用・参照し、同じ説明を二重に書かない
- 用語集にある語(GPU・DRAM など)の記事は、用語ページと違う問いを狙う(例: 用語「GPU」は定義と構成、記事は「なぜ AI に GPU が使われるの?」)
- 用語集にない入門の語(CPU・半導体・トランジスタなど)は、記事がその語の「とは」のページになる。用語集には入れない(自動リンクが多すぎるため)。用語集の検索で該当する語を引いたら記事を案内する
- 既存の「微細化の先へ」は、このコーナーの記事の1本として移す(URL は変えずに一覧に載せる)。ニュースの言葉はそのまま残し、関連する記事から相互にリンクする

### カテゴリ(シリーズ)と学ぶ順序
クイズの80分野をそのまま使わず、初心者が選びやすい7つのシリーズにまとめる。各シリーズの中は、前の記事を読んでいる前提で順に並べる(番号つき。どこから読んでもわかるように、前提は記事の冒頭で一言で補う)。

1. **はじめての半導体**: 半導体とは → トランジスタとは → 集積回路(チップ)とは → 「◯nm」の数字の意味
2. **半導体ができるまで**: チップの作り方の全体 → ウエハ → 露光 → エッチング・成膜 → 検査とパッケージ → クリーンルーム
3. **身近な半導体**: スマホの中の半導体 → メモリとストレージ → パワー半導体と電気自動車 → カメラのセンサ → 車の半導体
4. **コンピュータのしくみ**: 0と1で計算するしくみ → CPU とは → メモリの階層 → GPU と AI → OS とは → プログラムが動くまで
5. **ネットワークとインターネット**: インターネットでデータが届くしくみ → IP アドレス → Wi-Fi → HTTPS(鍵マーク)の意味
6. **セキュリティと暮らしの IT**: 暗号のしくみ → パスワードが破られる理由 → クラウドとは → AI はどう動くのか
7. **半導体の業界とニュース**: 半導体はなぜ「産業のコメ」・戦略物資なのか → ファウンドリと分業 → 半導体不足はなぜ起きたか → 半導体の仕事

おすすめの読む順(入門の一本道): 半導体とは → トランジスタ → 0と1で計算するしくみ → CPU → メモリとストレージ → チップの作り方 → ◯nm の意味。これは既存の学習コース「はじめての半導体」「トランジスタからソフトウェアまで」の手前に置く「ステップ0」とする。

## 5. 記事の基本構成・文体・図解

### 構成(全記事で共通の型)
1. **題**: 疑問の形(「CPU とは? パソコンやスマホの中で何をしているのか」)
2. **冒頭の答え(3行)**: 検索から来た人が最初の画面で答えを得られるように、結論を先に書く
3. **この記事でわかること / 対象の読者と前提知識 / 読む時間の目安**
4. **身近なところでは**: 読者がすでに知っている場面から入る(スマホ・家電・ニュース)
5. **しくみ**: 小さな段階に分けて説明する。新しい専門用語は1段落に1つまでとし、使う前に普通の言葉で説明する。用語ページへのリンクは「もっと詳しく」の意味で添える
6. **図解**: 1記事に1〜3点。既存の図解を使えるときは使い、ないときはその記事用に作る。図には「この図で省略していること」を一言そえる
7. **たとえで言うと**: 使う場合は「どこが似ていて、どこが違うか」を必ず書く(下の決まりを参照)
8. **よくある誤解**: 2〜3個。正しい説明と、なぜ誤解が生まれるかを書く
9. **数字で見る**: 大きさ・速さ・数を身近な量と比べる。数字には単位・時点・出典を書く
10. **理解度チェック**: 3問。答えると解説が出る。既存のクイズから初心者向けを選ぶか、記事用に作る
11. **もっと詳しく学ぶ**: 用語の詳しい解説・比較・図解・ツール・クイズの分野への案内(中級への橋渡し)
12. **次に読む**: シリーズの次の記事、関連する記事2本
13. **最終更新日・参考にした資料**

### 文体
- です・ます調。1文は60字程度までを目安にする。1段落は3〜5文
- 専門用語を専門用語で説明しない。どうしても使う語は、先に普通の言葉で説明してから名前を出す(「電気を通す道を開け閉めする部分。これをゲートと呼びます」)
- 「〜と言われています」のようなあいまいな書き方を避け、根拠か出典を書く
- 単純化したときは、単純化したと書く(「ここでは話を簡単にするため、〜は省きます」)
- 数式は原則として使わない。使う場合は、意味を言葉で説明してから示す

### たとえ話の決まり
- 一つのたとえで説明するのは一つの性質だけにする
- 「似ている点」と「たとえが当てはまらない点」を両方書く
- 誤解を生みやすいたとえは使わない。例:
  - 「CPU は脳」→ CPU が自分で考えるように誤解されやすい。代わりに「指示書(プログラム)のとおりに、決まった種類の計算をとても速く繰り返す係」
  - 「◯nm はトランジスタの大きさ」→ 今の世代の名前は実際の寸法と一致しない。たとえではなく事実として「世代の名前」と説明する
  - 「電流は水の流れ」→ 電圧と電流の関係の説明には使えるが、電子そのものの速さの説明には使えないことを書く
- 有名なたとえ(「メモリは机、ストレージは本棚」など)は、使うなら限界(電源を切ると机の上が消える点は似ているが、CPU のキャッシュなど中間の段階がある点は表せない)をそえる

### 図解の使い方
- 1枚の図で伝えることは一つ。図の中の文字は少なく、説明は本文と図の下の説明文に書く
- 既存の図解(45点)と同じ見た目の SVG で作る。ダークモードとスマホの幅で読めることを確かめる
- 図には代替テキストをつける。大きさの比較の図は、縮尺が正確か、正確でないならその旨を書く

## 6. 記事から関連する記事やクイズへつなぐ方法

> **2026-10-23 の変更(運営者の指示)**: 記事の中に問題を解くリンクが多く、不快に感じるとの指摘を受けた。記事は読み物にし、クイズへの誘導は最小限にする。理解度チェック(3問)と「問題に挑戦」のボタンをやめ、記事の後に「この分野の問題: 分野名」を1行だけ出す。本文から分野ページ・クイズ・学習コースへはリンクしない(check-learn.js が誤りにする)。下の「理解度チェックからクイズへ」の項は取り消し。逆向き(用語・分野・コースのページから記事へ)のリンクはそのまま

- **記事の中から**: 本文の専門用語は、各段落の初出だけ用語ページにリンクする(リンクだらけにしない)。比較・図解・ツールは、話の流れの中で「試してみる」「違いを表で見る」として案内する
- **理解度チェックからクイズへ**: 3問を解いた後に「この分野の問題に挑戦(10問)」を出す。初心者向けの問題から出題する(難しい問題ばかりだと離脱するため。分野の中で正答率の高い問題を選ぶ、などで仮に決める)
- **ほかのページから記事へ**:
  - 用語ページ: 関係する記事があれば「やさしい解説で読む」を上部に出す
  - 分野ページ: 紹介文の前に「この分野をはじめて学ぶ人へ」として入門の記事を出す
  - 学習コース: 各コースの最初に「ステップ0: 読み物」として記事を置く
  - トップページ: 「はじめての人へ」の欄に入門の一本道を出す
  - 用語集・サイト内検索: 「CPU」など用語集にない語を引いたら、該当する記事を案内する
- **記事どうし**: シリーズの前後の記事と、別のシリーズの関連記事(例: 「トランジスタ」→「0と1で計算するしくみ」)
- **計測**: GA4 の cta_click に article_quiz・article_term・article_next などを加え、記事からほかのページへ進んだ割合を見る

## 7. 無理なく追加・更新し、品質を保つ運営

### 1本を作る手順
1. **テーマを選ぶ**: Search Console の検索語、クイズの正答率が低い分野、ニュースから候補を出し、4章の基準で点数をつける
2. **読者の疑問を書き出す**: その題で初心者が持つ疑問を10個ほど挙げ、記事で全部に答える
3. **書く**: 型(5章)に沿って書く
4. **事実を確かめる(書いた担当とは別の担当)**: 数字・年・固有名詞を出典で確かめる。たとえ話と単純化が誤解を生まないかを点検する
5. **やさしさを確かめる(さらに別の担当)**: 予備知識のない読者の立場で読み、説明なしに出てくる専門用語・飛躍している段落を挙げる。挙がった所を直す
6. **自動検査**: リンク切れ、1文の長さ、説明なしの専門用語(用語集の語が、記事の中で説明される前に出ていないか)、数字の単位、図の代替テキスト
7. **公開**: 日本語で公開する。英語・繁体字は公開から2〜4週間後、日本語での読まれ方を見て訳す。韓国語・ドイツ語・オランダ語・フランス語は成績のよい記事から

### 数と更新
- 本数の目安: 最初の1か月で5本、その後は週1〜2本。量より、1本ごとの質と連携を優先する
- 古くなる情報(市場の数字・最先端の世代・企業の動き)は本文に時点を書き、記事のデータに「見直す時期」を持たせる。毎月、見直しの時期が来た記事を点検する
- 既存の点検の仕組み(audit-log)に記事も加え、3か月ごとに読み直す

### 成績の見方と、続けるかの判断
- 2週間ごと: 記事からクイズ・用語へ進んだ割合、記事の最後まで読まれたか(スクロール)
- 1〜3か月: Search Console の記事ごとの表示・クリック・順位、用語ページとの食い合いがないか
- 判断の目安: 公開から8週間で、記事の1ページあたりの表示が用語ページの平均を下回り、記事からクイズへ進む割合も低いなら、新しい記事を止めて書き方を見直す

## 9. 仮定したこと(運営者の確認なしで決めた点)
