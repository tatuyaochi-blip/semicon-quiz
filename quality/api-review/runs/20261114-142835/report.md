## adc-dac

### adc-snr [P1 / missing-condition / 確度 medium] all・code
> const q = 6.02 * bits + 1.76 + 10 * Math.log10(Math.max(osr, 1));

- 問題: OSRの利得を量子化雑音にだけ加え、ジッタ雑音には加えていない。ジッタ雑音が白色で広帯域なら、デジタルフィルタで帯域外を除くとジッタ雑音も10·log10(OSR)だけ減る。画面の注記と本文には、この扱いの前提が書かれていない。そのため、OSRを上げると合計SN比がジッタの値に頭打ちになる結果を、一般的な性質と誤解させるおそれがある。どちらの扱いが妥当かは、ジッタの周波数分布をどう仮定するかで決まる。
- 案: 注記に「オーバーサンプリングの利得は量子化雑音にだけ適用し、ジッタによる雑音は帯域内に全部残ると仮定しています(ジッタが白色なら、実際にはジッタ雑音も減ります)」と書き足す。あるいは、白色ジッタを仮定して j にも 10·log10(OSR) を加える。

## analog

### dbm [P2 / other / 確度 high] all・code
> fromDbm(dbm, val('r', 1e-9))

- 問題: 負荷抵抗に 0 や負の値を入れると、reader が黙って既定値の 50 Ω に置き換えます。入力欄には 0 などが表示されたまま、50 Ω での電圧が出るので、結果を取り違えます。
- 案: R が 0 以下のときは、電圧と dBµV を「–」と表示する。または入力欄にエラーを示し、既定値で黙って計算しないようにする。

### dbm [P2 / missing-condition / 確度 medium] all・sections
> 電圧への換算は、正弦波で負荷抵抗が分かっている場合に限ります。

- 問題: Vrms = √(P·R) は、純抵抗の負荷なら波形によらず成り立ちます。正弦波の仮定が要るのは、ピーク間電圧(2√2倍)だけです。「正弦波に限る」と書くと、実効値の式にも正弦波が必要だと誤解させます。2節目の「正弦波の実効電圧は」や、結果の名前「実効電圧 (正弦波)」も同じです。en・zh-hant も同じ内容です。
- 案: 実効電圧 Vrms = √(P·R) は、負荷が純抵抗で値が分かっていれば、波形によらず求められます。ピーク間電圧を 2√2·Vrms とするのは、正弦波の場合に限ります。

### divider [P1 / other / 確度 high] all・code
> r1: val('r1', 1e-9) * 1e3, r2: val('r2', 1e-9) * 1e3

- 問題: 入力欄は min="0" で 0 を入れられますが、reader は 1e-9 未満の値を既定値(10 kΩ)に置き換えます。そのため R2 = 0 と入れると、本来 0 V になる出力が 2.5 V と表示されます。R1 = 0 でも、Vin になるはずの出力が別の値になります。どちらも、置き換えたことは画面に示されません。境界の値で誤った結果を出しています。
- 案: 0 を物理的にありうる値として扱い、0 Ω のときの式を正しく計算する(R1=0 なら Vout=Vin、R2=0 なら Vout=0。両方 0 のときは「計算できない」と表示する)。または入力欄の min を 0 より大きくし、範囲外の値は既定値に黙って置き換えず「–」と注記を出す。

### jitter [P2 / overclaim / 確度 medium] all・sections
> データシートでは範囲を必ず添えて示します

- 問題: 積分範囲を書くべきなのは確かだが、すべてのデータシートが範囲を書いているとは言えない。「必ず」は定義や物理法則で成り立つ言い切りではない。en「always state it」、zh-hant「一定會註明」、ko「반드시 대역이 명시됩니다」も同じ。
- 案: ja: データシートのジッタの値は、積分範囲とあわせて見る必要があります。/ en: so a jitter value on a datasheet is meaningful only together with its band. / zh-hant: 因此資料手冊上的抖動值必須連同積分頻帶一起看。/ ko: 데이터시트의 지터 값은 적분 대역과 함께 보아야 합니다.

## circuits

### series-parallel [P2 / other / 確度 medium] all・code
> <td>${si(c.a, UNIT[kind])} + ${si(c.b, UNIT[kind])}</td>

- 問題: 組み合わせの表で、並列の組も「1 kΩ + 2.2 kΩ」のように「+」でつないで表示している。行の頭に「並列」とあっても、「+」は和と読まれやすく、並列の値を足し算と誤解させるおそれがある。
- 案: 並列の行は「1 kΩ ∥ 2.2 kΩ」のように並列の記号を使い、直列の行だけ「+」にする(c.how === 'p' ? ' ∥ ' : ' + ')。

### series-parallel [P2 / overclaim / 確度 low] ja・sections

### cmos-power [P1 / missing-condition / 確度 medium] all・sections

- 問題: 用語集の「活動率」の説明文は「信号が1クロックあたりに切り替わる割合」です。これは0→1と1→0の両方を数える定義に読めます。この定義では、ツールの注記と FAQ の説明により式は ½αCV²f になるはずです。ところが「動的消費電力」の説明文は αCV²f としています。用語集とツールで α の定義が食い違っています。
- 案: 用語集の活動率の説明文を「回路のノードが1クロックあたりに0から1へ切り替わる確率(または割合)。動的消費電力の式αCV²fのα。切り替わり全体を数える定義では½αCV²fとなる」のように、ツールの定義とそろえる。

### cmos-power [P2 / desc-mismatch / 確度 high] ja・text

- 問題: 電源電圧の低下は、微細化に比べて鈍化・停滞しましたが、完全に止まったとまでは言い切れません。言い切りが強すぎます。en・zh-hant・ko も同じ趣旨です。

### cmos-power [P2 / translation / 確度 medium] ko・sections

### cmos-power [P2 / other / 確度 medium] ja・code
> const num = (k, min = 0) => { const v = Number(form.elements[k].value); return Number.isFinite(v) && v >= min ? v : Number(form.elements[k].defaultValue); };

- 問題: 上限を確かめていません。このため α>1 や DVFS の割合 >100% を入れても、そのまま計算されます。たとえば割合 150% では「DVFS後」が元より大きくなります。割合の下限も JS では 1 で、フォームの min=10 と合っていません。

### cmos-power [P2 / other / 確度 low] ja・sections

- 問題: 用語集の zh-hant の項目名は「MTTF(平均失效時間)」なのに、FAQ では「平均故障時間」と訳しています。サイト内で用語がそろっていません。

### availability [P2 / other / 確度 high] ja・code
> if (!(a >= 0 && a <= 1 && n >= 1 && k >= 1 && k <= n)) { bad = true; out(`g${i}`).textContent = '–'; continue; }

- 問題: 入力が不正な行を飛ばしたまま、残りの行だけで「システム全体の稼働率」と停止時間を表示します。エラー文は出ますが、全体の値が正しい結果のように見えてしまいます。

### availability [P2 / missing-condition / 確度 low / 要出典] ja・sections
> MTBF(平均故障間隔)は故障から次の故障までの平均の動作時間

- 問題: MTBF を修理時間を含まない「動作時間」とする定義は、A = MTBF ÷ (MTBF + MTTR) の前提です。一方で、MTBF を故障の間隔(修理時間を含む)とする定義もあり、その場合はこの式になりません。用語集の MTBF の説明文は「故障が起きる平均の間隔」で、多くを同期化回路の式の説明に割いているため、本文と読み比べると混乱しやすいです。どちらの定義をとるかは、信頼性の教科書や JIS Z 8115 で確かめる必要があります。
- 案: 「ここでは MTBF を、修理時間を含まない平均の動作時間とします(試験の稼働率の計算はこの定義です)」と前提を書き添える。

### availability [P2 / overgeneralization / 確度 low] ja・sections
> ネットワーク機器、サーバ、ストレージのように、処理の経路にあるものはどれか1つでも止まると全体が止まるので、直列として考えます。

- 問題: これらの機器は冗長化(並列)されていることも多いです。この書き方では、機器の種類で直列か並列かが決まるように読めます。直列になるのは、冗長化されていない単一の経路のときだけです。
- 案: 「冗長化されていないネットワーク機器・サーバ・ストレージが処理の経路に1つずつ並ぶ場合は、どれか1つでも止まると全体が止まるので、直列として考えます。」

## system-architecture

### raid [P2 / other / 確度 high] all・code
> document.getElementById('rd-error').textContent = T.invalid[level];

- 問題: 入力が無効なときは、どの入力が原因でも、レベルごとの台数の文言が出る。たとえば RAID 5 で65台以上、容量0、故障率が範囲外のときも「RAID 5 はディスクが3台以上必要です。」と表示され、原因が伝わらない。
- 案: 台数の上限(1〜64台)、容量(0より大きい値)、故障率(0〜100%)の誤りには、それぞれ専用の文言を出し、レベルの台数条件の文言はレベルの条件を満たさないときだけ出す。

### raid [P2 / other / 確度 high] all・code
> const prob = v => (v < 1e-6 ? v.toExponential(2).replace('e-', '×10^-') : `${num(v * 100)}%`);

- 問題: 故障率0%のとき、v=0 で toExponential が「0.00e+0」を返し、置換もされないため「0.00e+0」と表示される。また 1e-6 未満の値は % が付かない確率の値になり、ほかの行の % 表示と単位が混ざる。
- 案: v === 0 のときは「0%」を返す。指数表記にする場合も %(または「×10^-n」の後に単位)をそろえて表示する。

### raid [P2 / overgeneralization / 確度 medium] all・text

- 問題: 注記は全レベルに当てはまるように書かれているが、RAID 0 は冗長性がなく再構築できないため、交換しても確率は小さくならない(このモデルの値がそのまま当てはまる)。比較表に RAID 0 も並ぶので誤解を招く。

- 問題: 用語集の RAID の zh-hant の説明ではストライピングを「等量分割」と訳しているが、本文・図の説明・FAQ では「條帶化」「條帶」を使っており、サイト内で訳語がそろっていない。

### raid [P2 / desc-mismatch / 確度 low] ja・sections
