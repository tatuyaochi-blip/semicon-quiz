# 問題作成・検証の基準

問題を新しく作るときや直すときの基準です。データの形式は `tools/validate.js`、中身の機械的な検査は `tools/check-content.js` が確かめます。

## 1. 問題の作り方

- **正解はただ1つ:** 3つの選択肢のうち、正しいのは1つだけにします。ほかの2つは、明確に誤りか、問題文の条件で明確に外れるものにします。「最も適切なもの」を問う場合は、2番目に良い選択肢との差が、解説ではっきり説明できるようにします。
- **条件を書く:** 数値には、温度・電圧・材料・世代・規格の版などの条件を付けます。例:
  - 「室温の Si で」
  - 「220 nm SOI のストリップ導波路で」
  - 「DDR4 では」
  - 「12 V 系では」

  条件で値が大きく変わるものは、範囲で書きます。
- **断定を避ける:** 「必ず」「常に」「唯一」は、定義や物理法則で成り立つときだけ使います。経験則や業界の慣習は「一般に」「目安として」と書きます。
- **規格を正確に書く:**
  - 規格の名前・番号・種類を正確に書きます(EU の「指令」と「規則」、IPC/JEDEC の共同規格など)。
  - 版によって値が変わる規格では、版を書くか、版によらない書き方にします。
  - 規格が表で定めているものは、覚え方の式を書く場合でも「表で定められている」ことを明記します。
- **時期で変わる情報:** 市場規模・製品の世代・価格は「20xx年時点で」と時期を書きます。見直す時期は `data/audit-log.json` の記録日から判断します。
- **計算問題:**
  - 解説に計算の過程を書き、正解の数値が解説に出てくるようにします(`check-content.js` が検査)。
  - 誤りの選択肢の補足に「〜と取り違えた値」と書く場合は、その計算で本当にその値になることを確かめます。
- **解説と補足を合わせる:** 解説、各選択肢の補足(`choiceNotes`)、正解の番号が、互いに矛盾しないようにします。

## 2. 出典の扱い

- 確かめる資料の優先順位:
  1. 規格(ISO・IEC・JEDEC・AEC・IEEE など)
  2. 査読付き論文・定番の教科書
  3. 半導体メーカーの技術文書
  4. 大学・研究機関の資料
- 出典は、実際に開いて確認したものだけを記録します。存在しない出典、読んでいない箇条番号、推測の DOI は書きません。
- 有料の規格で本文を読めない場合は、「本文未確認」と明記します。そのうえで、二次資料のどれに基づくかを書きます。
- 根拠が不十分な記述は、断定せずに [UNVERIFIED_CLAIMS.md](UNVERIFIED_CLAIMS.md) に載せます。

## 3. 修正の記録

問題を直したら、`data/audit-log.json` に記録を足します。

```json
"wafer-009": [
  { "date": "2026-10-19", "type": "fix", "severity": "major", "fields": ["explanation", "en.explanation"],
    "summary": "何が誤っていて、どう直したか", "sources": [{ "title": "...", "url": "...", "note": "どこまで確認したか" }],
    "by": "誰が確認したか(人の専門家か、AI の点検か)" }
]
```

- `type`: 内容を直したら `fix`、変えずに正しいと確かめたら `verify`。
- `severity`:
  - `critical`: 正解の誤り
  - `major`: 事実・数値の誤り
  - `minor`: 条件の抜け・言い過ぎ・古い情報
- 人の専門家が確認した問題は、問題データの `reviewed` を `true` にします。AI による点検だけでは `true` にしません。

## 4. 多言語

- 日本語の問題が原文です。日本語を直したら、すべての言語の訳を直してから、`node tools/i18n-stale.js --update <言語>` で追従の記録を更新します。
- 訳では数値・単位・式を変えません。小数点と桁区切りは、その言語の書き方に合わせます(ドイツ語・オランダ語・フランス語は「0,5」「1.000」「1 000」)。「3,000」のような、小数にも読める書き方はしません(`check-content.js` が検査)。
- 訳だけが誤っていた場合は、訳だけを直し、記録の `fields` に `en.explanation` のように言語を付けます。

## 5. 公開前の検査

```sh
npm test            # 形式の検査 + 中身の検査(注意が0件) + 訳の追従
npm run build       # docs/ を作り直す
PLAYWRIGHT=/opt/node-tools/node_modules/playwright/index.mjs npm run check:ui   # 表示の回帰テスト
```

- `npm test` は、次の三つをまとめて実行します:
  - `tools/validate.js`: ID・選択肢の数・正解の番号・必須項目・重複・訳の形式
  - `tools/check-content.js --strict`: 正解の数値が解説にあるか、訳の選択肢の数値、小数点の書き方、正解の位置の偏り、修正の記録の形式
  - `tools/i18n-stale.js`: 日本語を直したあと、訳し直していない言語がないか
- `check-content.js` の注意のうち、確かめたうえで問題ないとしたものは、理由を添えて `data/qa-ignore.json` に載せます。理由のない除外はしません。
- 機械的な検査で見つかるのは、形式と数値の不整合だけです。技術的な正しさは、この文書の基準に沿って人が確認します。
