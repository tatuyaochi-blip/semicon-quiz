## 数式と単位(2026-11-11)

運営者の指摘(数式や単位が見にくい)を受けて、本文の数式と単位を共通の処理で整える。原稿(data/ の文章)は変えず、ビルド時に HTML を、クイズ画面では表示のたびに DOM を整える(src/js/mathify.js。テスト tools/tests/mathify.test.mjs)。

| 項目 | 前 | 後 |
|---|---|---|
| 添字 | VGS、Vth、μnCox、gm が平文 | V_GS、V_th、μ_n C_ox、g_m のように下付き(`<sub>`) |
| 数値と単位 | 「0.5 V」「200 µA/V²」「0.05 /V」が行の途中で切れる | 間を行が切れないスペースにする |
| 値の代入 | 「VGS」と「= 1.5 V」が別の行になる | 「V_GS = 1.5 V」は1つのかたまり |
| 長い式 | どこででも折り返す | 「=」の前でだけ折り返す。演算子(−、+、×、·)の前後では切らない |
| ギリシャ文字・演算子 | 日本語の書体の全角幅で描かれ、間延びする | λ・μ・Ω・×・−・≈ などだけ、端末の欧文の書体で描く(CSS の @font-face と unicode-range。書体は読み込まない) |

- 添字にするのは、意味が1つに決まる記号(V_GS、V_th、g_m、C_ox、μ_n、φ_F、θ_JA など)。IC・ID・NA・R1 など、ほかの意味もある語は、式の中にあり、同じ段落にデバイスの記号があるときだけ変える(「このIC」「ユーザーID」「開口数 NA」は変えない)
- タグの属性、script、pre、code、入力欄、選択肢(option)の中は変えない
- ページの更新日は整形前の本文で判定する(整形の変更だけで更新日が変わらない)
- 同時に直した不具合: PN接合・MOSFET のページで、式の中の NA(アクセプタ濃度)が用語「開口数(NA)」にリンクされていた。用語の linkOnlyIn を露光・計測・光の分野に限った

## 教科書のような組み方の式(2026-11-11)

運営者の依頼(÷ や √ を教科書のように書き直す)。本文の1行書きの式(例: DPW ≈ πr²/S − πd/√(2S))を、分数を上下に重ね、根号を中身の上に伸ばした形で、1行を使って中央に出す。

- 表示はブラウザの標準の数式表示(MathML)。外部のライブラリや書体のファイルは使わない。書体は端末の数式用の書体(iPhone・Mac は STIX Two Math、Windows は Cambria Math)を指定
- 対象の式は data/math.json に挙げたものだけ(1,396本)。本文に同じ文字列があれば、どの言語でも置き換わる。原稿は変えない
- 1行書きから MathML への変換は src/js/mathml.js。読み方の決まり: 並べて書いた積は割り算より強い(Eg/2kT = Eg/(2kT))、「·」でつないだ積は分子に入る、スペースで囲んだ「×」は分数どうしの積
- あいまいな記号は式ごとに指定する(開口数の NA は名前、fT・rπ・コレクタ抵抗の RC は添字、拡散の Dt は積)
- 式を足すときは、変換結果を画面で確かめてから data/math.json に足す(テスト tools/tests/mathml.test.mjs が、表の式がすべて変換でき本文にあることを確かめる)

### ほかの記号と、ほかのページへの拡張(2026-11-11)

運営者の依頼(「その他記号も同様です」)。÷、指数の「^」、微分、単位つきの計算例、日本語の言葉の式も同じ組み方にし、問題の解説・比較ページ・やさしい解説・クイズ画面にも広げた。

| 書き方 | 出し方 |
|---|---|
| 等号などの関係がある式(V = L·di/dt、480 ÷ 500 = 0.96) | 段落から独立させ、分数を上下に重ねる。前後のスペースは落とし、すぐ後ろの句読点は式の行の末尾に付ける |
| 関係がなく「÷」を含む式(容量 ÷ ラインサイズ) | 文の流れの中で分数にする |
| 根号・指数だけの短い式(1/√2、e^(−t/τ)、2^N − 1) | 文の中に置き、根号と指数だけを組む。割り算は斜線のまま(行の高さを乱さない) |
| 関係も「÷」もない「/」だけの式(1/2、cm²/(V·s)、I/O) | 変えない。選択肢がそのまま式になっているものだけ、表で mode: compact を付けて分数にする |

- 「÷」は「×」と同じ強さで左から順に読む(a × b ÷ c は分子が a × b)。指数表記の数(3×10⁸)は1つの数。指数の中の割り算は斜線のまま(e^(−t/RC))
- 数値の後ろの単位は立体で数値に付ける。スペースなしで続く1文字(2A、6.02N)は変数。分母の数に付いた「倍」「%」は分数全体の後ろに置く
- 日本語の語(ドーズ量、ラインサイズ)は、演算子でつないだときだけ式の一部。式の前に付いた見出しの語(「出力抵抗 ro = …」)は式に入れない
- 微分 dV/dt は d を立体にする。虚数単位 j の後ろの数字、指数の付いた e の前の文字は添字にしない
- 見出し・表・選択肢・問題文の中では、関係のある式も独立させず、文の流れの中の分数にする
- クイズ画面は同じ表(data/math.json を生成物の data/math.json として配る)と同じ変換(src/js/mathml.js)をブラウザで使う。表が読めなくても、式が1行書きのまま出るだけでクイズは動く
- 載せないもの: 整数の割り算(13 ÷ 2 = 6)、0 ÷ 0 などの演算の例、単位が分母の数に付く式(1/3 F、π/6 rad)、単位どうしの式、プログラムの式
- 残っているもの: 日本語以外の言語の、言葉で書いた式(size ÷ line size など)は1行書きのまま。数値と記号だけの式は全言語で変わる

## 問題を解く画面の色(2026-11-11)

「カラフルすぎて見づらい」という指摘を受けて、色に意味を持たせ直した。

- 色は3つの意味だけに使う: 正解(緑)、不正解(赤)、操作(青)。それ以外は地の色と灰色にする
- グラデーションは問題を解く画面では使わない(進み具合の棒、ボタン、結果の点数)
- 分野の札と選択肢のA・B・Cは、枠と灰色の文字にする。色が付くのは、答えたあとの正解と自分の選んだ選択肢だけ
- 不正解の選択肢は赤い枠だけにして、面は塗らない。面を塗るのは正解の1つだけ
- 解説の箱は、色の付いた太い左線をやめ、当たり外れは見出しの丸い印(緑のチェック、赤のバツ)だけで示す
- 塗りのボタンは1画面に1つ。解説の上の「次の問題へ」と、個別の問題ページの前後の移動・分野への入口は枠だけにする
- 個別の問題ページの右の欄(PC)の「まず10問解いてみる」も分野への入口なので枠だけにする(2026-11-12。グラデーションの塗りが残っていて、答えたあとは「続けて解く」と塗りのボタンが2つになっていた)。用語ページの右の欄は今までどおり塗り
- 解説の中の用語リンクは本文の色のままにして、下線だけで示す
- 判定の行と、結果画面の問題文は、flex で並べない。文の途中に下付き文字(V<sub>GS</sub>)があると、文字ごとに列が割れるため。印は絶対配置にして、文は字下げする

## 数値の合格基準(2026-11-13)

| 項目 | 基準 | 根拠 |

| 文字と背景の明るさの比 | 4.5 以上(24px 以上か 18.66px 以上の太字は 3 以上) | WCAG 2.2 AA 1.4.3 |
| 最小の文字 | 12px 以上(図・数式・添え字は除く) | 携帯で読める下限の目安 |
| 本文の段落 | 15px 以上、行間は 1.5〜2 倍 | WCAG 1.4.12 の行間 1.5 |
| 1行の字数 | 日本語・中国語・韓国語は 45字以内(半角は 0.55字)、英語は 80字以内 | 日本語の組版の目安(35〜45字)、WCAG 1.4.8 |
| 文字の大きさの種類 | 1ページ 10種以内 | 種類が多いと階層が読み取れない |
| 押せる部品 | 24px 以上(小さいときは隣の部品と 24px 以上離す)。文の中のリンクは除く | WCAG 2.2 AA 2.5.8 |

| 塗りのボタン | 1画面(画面の高さ1つ分)に1つまで。押した状態の切り替えは除く | このサイトの決まり |
