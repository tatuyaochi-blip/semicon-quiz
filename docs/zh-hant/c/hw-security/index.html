硬體安全的重點

第一次學習的人: 指紋辨識、臉部辨識的原理是什麼？手機如何認出本人？ / 作業系統（OS）是什麼？它在電腦和手機裡做些什麼

即使軟體沒有錯誤，資訊也可能因為硬體的特性而洩漏。Spectre與Meltdown這類弱點，利用的正是為提升效能而設計的推測執行與快取，會留下原本應該看不到的資料痕跡。另外也有旁路攻擊，從耗電量或處理時間的細微差異推測出加密金鑰。

防禦方面的技術包括：只啟動正確軟體的安全開機、連OS也無法觸及的隔離安全執行環境（TEE）、把每顆晶片的製造差異當作指紋使用的PUF，以及針對在設計或製造過程中被植入的不當電路（硬體木馬）的對策。本單元的目的不在攻擊步驟，而在於理解原理與對策。

這個領域的比較

  • 安全開機與量測開機的差異：簽章驗證、TPM 記錄、遠端證明比較從確認的對象、阻止或記錄、信任根、遭竄改時的行為、所需的元件、結果的用途、限制與搭配方式等面向，以表格比較安全開機與量測開機（measured boot）。
  • TPM、HSM、安全元件的差異：配置位置、用途、金鑰保護、認證比較從配置的位置、主要目的、使用的裝置、金鑰的保護方式、密碼運算效能、抗竄改性與認證（FIPS 140-3、共同準則）、遠端證明、成本與代表性用法等面向，以表格比較 TPM、HSM 與安全元件。
  • TrustZone、SGX、SEV/TDX 的差異：隔離單位、信任範圍、記憶體加密比較從隔離的單位、防範的對象、信任範圍（TCB）、記憶體加密、遠端證明、主要用途、移植的工作量、已知的攻擊類型與提供狀況等面向，以表格比較 Arm 的 TrustZone、Intel 的 SGX（飛地）與 AMD SEV、…
