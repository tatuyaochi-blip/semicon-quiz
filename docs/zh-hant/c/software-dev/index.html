軟體開發與專案管理的重點

軟體的品質與交期，與其說取決於寫了多少程式碼，不如說取決於以什麼順序做什麼、如何確認、如何管理時程與費用。在韌體、驅動程式、EDA 腳本、驗證環境等接近半導體與硬體的開發中，這套做法的好壞同樣左右產品的成果。

本單元學習瀑布式模型與 V 模型、Scrum、測試驅動開發、CI/CD 等開發方式，非功能需求、UML、模組的內聚力與耦合度等設計思維，以及等價類劃分、邊界值分析、分支涵蓋率等測試技法。此外，也以計算題為主，介紹箭線圖的要徑、三點估計、實獲值管理的計算、風險應對、SLA 與問題管理等專案管理與服務管理的基礎，有助於準備資訊相關證照考試的軟體開發與管理領域。

軟體開發與專案管理的題目列表（40題）
  1. 關於軟體開發的瀑布式模型，下列何者是其特徵？
  2. 在軟體開發的 V 模型中，與需求定義工程相對應、確認是否滿足該工程所決定內容的測試為下列何者？
  3. 在 Scrum 中，負責產品待辦清單（Product Backlog）項目的內容與排序（優先順序），並使產品價值最大化的角色為下列何者？
  4. 在 Scrum 中，於衝刺（Sprint）結束時，將完成的增量（可運作的產出物）展示給利害關係人並取得回饋，以重新檢視今後方向與產品待辦清單的事件為下列何者？
  5. 在極限程式設計（XP）等敏捷開發中進行的，不改變程式從外部看到的行為，將內部結構整理得容易理解且容易修改的作業為下列何者？
  6. 關於測試驅動開發（TDD）的進行方式，下列何者適當？
  7. 關於持續整合（CI）的說明，下列何者適當？
  8. 關於持續交付與持續部署的差異，下列說明何者適當？
  9. 某業務系統的需求中，屬於非功能需求的是下列何者？
  10. 在 UML 中，像電鍋的控制軟體那樣，要表示物件的狀態如何隨事件（按下按鈕、計時器到期、達到溫度等）而改變時，適合使用的圖為下列何者？
  11. 在 UML 中，將多個物件之間往來的訊息（呼叫或回應）依時間順序由上往下排列表示的圖為下列何者？
  12. 在評估模組獨立性的模組強度（內聚力）中，強度最高、被認為最理想的是下列何者？
  13. 在模組間的耦合度中，耦合最弱、模組獨立性最高的是下列何者？
  14. 在 GoF 設計模式中，當某物件的狀態改變時，自動通知依賴它的多個物件的模式為下列何者？
  15. 對韌體的原始碼使用靜態分析工具時，在不執行程式的情況下最容易找出的問題為下列何者？
  16. 關於黑箱測試的說明，下列何者適當？
  17. 某個只會輸入整數的欄位，接受1以上100以下的值，其他值則顯示錯誤。以等價類劃分切分輸入時，等價類的數量（有效等價類與無效等價類的合計）為下列何者？
  18. 某程式依年齡（0以上的整數）決定入場費：0～17歲為兒童票價，18～64歲為一般票價，65歲以上為敬老票價。為了確認票價類別改變的交界，以邊界值分析選擇的測試值組合，下列何者最適當？
  19. 規格是「溫度在85 ℃以上時發出警告」，但韌體中誤寫成「if (t > 85)」。溫度 t 為整數。下列測試值中，能發現此錯誤的是何者？
  20. temp 與 err 的值可彼此獨立決定。對於處理「if (temp > 80) { fan = HIGH; } else { fan = LOW; } if (err) { log(); }」，要滿足敘述涵蓋（所有敘述至少執行一次）所需的最少測試案例數為下列何者？
  21. a、b、c 的真偽可彼此獨立決定。對於處理「if (a) { S1; } if (b) { S2; } if (c) { S3; }」，要滿足分支涵蓋（所有判斷的真與偽至少各執行一次）所需的最少測試案例數為下列何者？
  22. 對於判斷「A 且 B」（A 與 B 是可彼此獨立決定真偽的條件），執行了測試案例（A = 真、B = 偽）與（A = 偽、B = 真）這2個。關於涵蓋基準，下列何者正確？
  23. 在由下而上測試中，為了代替尚未完成的上層模組，呼叫受測的下層模組、傳入測試資料並接收結果而製作的是下列何者？
  24. 在測試工程中，以測試時間（或已執行的測試案例數）為橫軸、以發現缺陷的累計件數為縱軸，畫出可靠度成長曲線。當曲線仍持續上升、看不出趨於飽和（持平）時，下列判斷何者最適當？
  25. 在規模25 k行（2萬5,000行）韌體的整合測試中，發現了30件缺陷。依組織過去的實績，此工程發現缺陷的參考值為每1 k行2～4件。對此結果的評估，下列何者最適當？
  26. 在 Git 中，兩位開發人員在不同分支各自修改了同一檔案的同一行，然後將一個分支合併到另一個分支。此時會發生的情況，下列何者適當？
  27. 在設計書或原始碼的審查方法中，由主持人（moderator）主導、決定參加者的角色、使用檢查表等正式進行，並記錄找到的缺陷且確認到修正完成的是下列何者？
  28. 在已知可正常運作的韌體版本之後有1,000個提交，最新的提交會發生缺陷。假設缺陷是由某1個提交引入，其後的提交全都會發生。像 git bisect 那樣以二分搜尋找出原因提交時，需要建置並測試的次數最多為下列何者？
  29. 在將專案的產出物與工作階層式分解的工作分解結構（WBS）中，位於最下層、用來估算工期與成本並指派負責人的單位為下列何者？
  30. 將結點設為①～⑥，以「名稱：起點→終點、所需天數」表示作業，有一張箭線圖為：A：①→②、6天，B：①→③、4天，C：②→④、4天，D：③→⑤、4天，E：④→⑥、2天，F：⑤→⑥、3天，虛作業：②→③（所需天數0）。專案整體最短的所需天數為下列何者？
  31. 某專案的作業、所需天數與前置作業為：A：4天（無前置作業）、B：2天（無）、C：3天（A）、D：2天（B）、E：5天（C）、F：4天（C 與 D）、G：2天（F）。其他作業都盡早開始時，作業 B 延後開始而不使整體所需天數增加的最大天數為下列何者？
  32. 某專案的作業、所需天數與前置作業為：A：6天（無）、B：4天（無）、C：4天（A）、D：4天（A 與 B）、E：2天（C）、F：3天（D），整體所需天數為13天。各作業縮短1天所需的追加費用為：A 30萬日圓、B 5萬日圓、C 10萬日圓、D 20萬日圓、E 8萬日圓、F 25萬日圓。要將整體所需天數縮短1天，追加費用最少的方法為下列何者？
  33. 以三點估計估算某作業的所需天數，得到樂觀值4天、最可能值7天、悲觀值16天。以 PERT 公式求得的所需天數期望值為下列何者？
  34. 在完工預算（BAC）為2,000萬日圓的專案中，某時間點的計畫值（PV）為800萬日圓、實獲值（EV）為600萬日圓、實際成本（AC）為750萬日圓。此時間點專案的狀況，下列何者正確？
  35. 在完工預算（BAC）為1,200萬日圓的專案中，目前的計畫值（PV）為600萬日圓、實獲值（EV）為480萬日圓、實際成本（AC）為600萬日圓。假設今後目前的成本效率持續下去，完工估算（EAC）為下列何者？
  36. 在進度落後的軟體開發專案中，將開發人員從5人增加到10人。兩人之間溝通路徑的數量（兩人組合的數量）會變為增加前的幾倍？
  37. 在專案的風險應對中，為發生時的損失投保，或以契約請專業公司承接該工作，將影響轉移給第三方的是下列何者？
  38. 關於用於估算軟體規模的功能點分析法，下列說明何者適當？
  39. 某服務的 SLA 規定每月可用率為99.95%以上。以1個月為30天，且計畫停機也納入計算。本月已因故障合計停止15分鐘。本月為了遵守 SLA，剩餘期間允許的停機時間為下列何者？
  40. 在 IT 服務管理中，以調查反覆發生之故障的根本原因，並透過永久性對策防止再發生為主要目的的流程為下列何者？
