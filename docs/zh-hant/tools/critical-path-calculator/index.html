要徑計算工具

由專案作業的順序與所需天數，計算整體最短需要幾天完成，以及哪些作業延誤會使整體延誤（要徑），也就是以要徑法（CPM）進行計算。可在表格中確認箭線圖（PERT 圖）題目中使用的最早開始日、最晚開始日與寬裕天數。

收藏與最近使用的工具只儲存在這個瀏覽器（localStorage）中。

作業清單

作業名稱最多8個英數字或中文字，所需天數為0以上的數，前置作業以空白或逗號分隔排列，沒有前置作業則省略。作業最多26項。

什麼是要徑

專案的作業之間有先後關係，有些作業必須等前面的作業完成才能開始。從開始到結束的作業串連中，所需天數合計最長的就是要徑，它的長度就是專案整體最短的所需天數。要徑上的作業只要延誤1天，整體就會延誤。在「6項作業」的例子中，B（5天）→ D（4天）→ E（3天）的12天是要徑，A、C、F 則有寬裕。

最早開始日與最晚開始日的求法

最早開始日是所有前置作業結束日中最晚的一天，從開始依序以「前置作業最早結束日的最大值」求出（順推計算）。最晚開始日是為了不延長整體所需天數而最晚必須開始的日子，從結束往回以「後續作業最晚開始日的最小值 − 自己的所需天數」求出（逆推計算）。最晚開始日與最早開始日的差就是寬裕天數（總浮時），把寬裕為0的作業連起來就是要徑。

箭線圖與 PERT

以箭頭表示作業先後關係的圖稱為箭線圖，用於稱為 PERT（Program Evaluation and Review Technique，計畫評核術）的手法。在箭線圖中，作業以箭頭表示，作業的分隔點以圓圈（結點）表示，有時也會使用只表示先後關係的虛線箭頭（虛作業，所需天數為0）。本工具以為每項作業列出前置作業的方式（與前置關係圖相同的思維）輸入，因此不需要虛作業。

縮短時程

要讓專案提早完成，只有縮短要徑上的作業才有效果。縮短有寬裕的作業，整體天數也不會改變。方法有增加人力以縮短作業的趕工（crashing），以及將依序進行的作業部分重疊、平行推進的快速跟進（fast tracking）等。縮短要徑上的作業後，可能由其他路徑成為新的要徑，請一邊看表格一邊確認。

練習相關題目

將結點設為①～⑥，以「名稱：起點→終點、所需天數」表示作業，有一張箭線圖為：A：①→②、6天，B：①→③、4天，C：②→④、4天，D：③→⑤、4天，E：④→⑥、2天，F：⑤→⑥、3天，虛作業：②→③（所需天數0）。專案整體最短的所需天數為下列何者？

  1. A11天
  2. B12天
  3. C13天
查看答案與解析

正確答案：C. 13天

虛作業②→③表示作業 D 要開始，不只 B，A 也必須已經完成。各結點的最早時間為：②是6天，③是 max(4, 6 + 0) = 6天，④是 6 + 4 = 10天，⑤是 6 + 4 = 10天，⑥是 max(10 + 2, 10 + 3) = 13天，因此整體所需天數為13天，要徑為 A→虛作業→D→F。若漏看虛作業，D 就變成可在第4天開始，使 A→C→E 的12天成為最長。11天只是 B→D→F 路徑的天數。

某專案的作業、所需天數與前置作業為：A：4天（無前置作業）、B：2天（無）、C：3天（A）、D：2天（B）、E：5天（C）、F：4天（C 與 D）、G：2天（F）。其他作業都盡早開始時，作業 B 延後開始而不使整體所需天數增加的最大天數為下列何者？

  1. A0天
  2. B1天
  3. C3天
查看答案與解析

正確答案：C. 3天

最早開始日為 C 第4天，E 與 F 第7天（F 取 C 結束的第7天與 D 結束的第4天中較晚者），G 第11天，整體為 A→C→F→G 的 4 + 3 + 4 + 2 = 13天。從後面往前求最晚開始日，G 為第11天、F 為第7天、D 為 7 − 2 = 第5天、B 為 5 − 2 = 第3天，因此 B 的總浮時（寬裕天數）為 3 − 0 = 3天。延後 B 也會使 D 的開始延後，但 D 也有相同的寬裕，所以延後3天以內整體不會延長。0天是 B 的自由浮時（不延後後續作業 D 最早開始的寬裕），1天是 E 的寬裕天數。在要徑法（CPM）中，會像這樣求出寬裕天數，並把寬裕為0的作業連成的路徑當作要徑。

某專案的作業、所需天數與前置作業為：A：6天（無）、B：4天（無）、C：4天（A）、D：4天（A 與 B）、E：2天（C）、F：3天（D），整體所需天數為13天。各作業縮短1天所需的追加費用為：A 30萬日圓、B 5萬日圓、C 10萬日圓、D 20萬日圓、E 8萬日圓、F 25萬日圓。要將整體所需天數縮短1天，追加費用最少的方法為下列何者？

  1. A將作業 B 縮短1天（5萬日圓）
  2. B將作業 D 縮短1天（20萬日圓）
  3. C將作業 A 縮短1天（30萬日圓）
查看答案與解析

正確答案：B. 將作業 D 縮短1天（20萬日圓）

要徑是 A→D→F（6 + 4 + 3 = 13天），其他路徑 A→C→E 為12天、B→D→F 為11天。要縮短整體，必須縮短要徑上的作業，其中費用最少的是 D 的20萬日圓，縮短後 A→D→F 與 A→C→E 都變成12天。B 雖然最便宜，但不在要徑上，縮短後整體仍為13天。縮短 A 整體也會變成12天，但費用要30萬日圓。像這樣投入費用縮短作業期間，稱為趕工（crashing）。

常見問題

總浮時與自由浮時有什麼不同？

總浮時是在不延誤專案整體的範圍內可以延後的天數。自由浮時是在也不延後下一項作業最早開始日的範圍內可以延後的天數，會在總浮時以下。用完總浮時，後續作業的寬裕也會減少。

要徑會有2條以上嗎？

會。若有多條路徑的所需天數合計同為最長，每一條都是要徑。此時要縮短整體，必須縮短所有的要徑。

所需天數不確定時該怎麼辦？

PERT 有一種方法，是估計樂觀值 a、最可能值 m、悲觀值 b 這3個值，並以 (a + 4m + b) ÷ 6 作為期望值使用。請在輸入本工具前，先計算每項作業的期望值。

考試中會怎麼出題？

日本的基本資訊技術人員考試與應用資訊技術人員考試中，常出現從箭線圖求專案整體的所需天數或要徑、某作業的最早開始日、最晚開始日與寬裕天數的題目，以及詢問縮短作業時整體會縮短幾天的題目。
