IaaS、PaaS與SaaS的差異：提供的範圍、使用者管理的部分、自由度與維運工作量比較

IaaS、PaaS與SaaS，是依業者提供到哪個範圍來區分雲端服務的名稱。IaaS（Infrastructure as a Service，基礎設施即服務）提供虛擬機器、儲存、網路等基礎設施，作業系統以上由使用者管理。PaaS（Platform as a Service，平台即服務）由業者提供到作業系統、中介軟體、程式語言的執行環境，使用者準備自己的應用程式與資料。SaaS（Software as a Service，軟體即服務）提供應用程式本身，使用者只需透過網頁瀏覽器等使用。越從IaaS往SaaS，維運的工作越少，但使用者能自由選擇的範圍也越窄。

項目IaaSPaaSSaaS
業者提供的部分虛擬機器、儲存、網路等基礎設施（包含其下的建築物、實體設備與虛擬化平台）除了IaaS的範圍，還有作業系統、中介軟體、程式語言的執行環境等直到應用程式的全部

適用於什麼情況

IaaS
想自行選擇作業系統與中介軟體時、想把在自家伺服器上運作的系統幾乎原樣移到雲端時，或想執行特殊組態的軟體時。相對地，作業系統的更新與安全性設定也要自己處理。
PaaS
想把基礎設施的管理交給業者，專心開發應用程式時。必須在業者支援的程式語言與執行環境範圍內開發。
SaaS
想不必開發軟體，就立即使用電子郵件、文書處理、顧客管理等一般業務功能時。能使用的功能僅限於所提供的範圍。

常見問題

無伺服器運算（FaaS）屬於IaaS、PaaS、SaaS中的哪一種？

只需準備函式的程式碼，執行環境的準備與台數增減交給業者，因此一般被視為接近PaaS的形態。提供容器執行平台的服務有時稱為CaaS（Container as a Service），並被放在IaaS與PaaS之間。這類細部分類，會因業者或文獻而有所不同。

使用SaaS時，安全性全都是業者的責任嗎？

不是。在共同責任模型中，SaaS雖由業者負責到應用程式，但儲存的資料、使用者的帳號與密碼、多因素驗證的設定、檔案的共用範圍等，仍是使用者的責任。因設定錯誤而讓任何人都能檢視檔案的事故，屬於使用者端的問題。

IaaS、PaaS、SaaS的定義是在哪裡訂定的？

最常被引用的是美國NIST（國家標準暨技術研究院）於2011年公開的雲端運算定義（SP 800-145）。其中將SaaS、PaaS、IaaS三者定為雲端的服務模式。

自建機房（地端）與IaaS有什麼不同？

自建機房是自行購買設備並放在自家設施中，從建築物、電源以上全部自行管理的形式。IaaS則把建築物、實體設備與虛擬化平台的管理交給業者，在需要時只租用需要的量。相對地，使用期間會持續產生費用，也會受到業者故障的影響。

理解度檢測

在雲端服務中，由業者提供虛擬機器、儲存、網路等基礎設施，而作業系統、中介軟體、應用程式由使用者自行安裝與管理的是下列何者？

正確答案：B. IaaS

雲端服務依業者提供的範圍來分類。IaaS（Infrastructure as a Service）提供虛擬機器、儲存、網路等基礎設施，其上的作業系統與應用程式由使用者管理。PaaS（Platform as a Service）由業者提供到作業系統、中介軟體等執行環境，SaaS（Software as a Service）由業者提供到應用程式，使用者的管理工作相應減少。

在雲端運算服務的 IaaS 中，一般由使用者自行管理的是下列何者？

  1. A資料中心的建築物，以及電源與空調設備
  2. B伺服器與儲存設備等實體設備，以及虛擬化基礎
  3. C在虛擬機器上運作的作業系統、中介軟體與應用程式
查看答案與解析

正確答案：C. 在虛擬機器上運作的作業系統、中介軟體與應用程式

在 IaaS（Infrastructure as a Service）中，由業者管理建築物、設備、實體設備與虛擬化基礎，使用者自行管理虛擬機器上作業系統以上的部分。在 PaaS 中，作業系統與中介軟體也由業者管理，使用者管理應用程式與資料；在 SaaS 中，應用程式也由業者管理，使用者管理資料與使用設定。如此，業者與使用者分擔責任的範圍會隨服務型態而改變。

相關名詞的解說

共同責任模型
使用雲端時，由雲端業者與使用者分擔安全與營運責任的想法。資料中心的建築物與實體設備由業者負責，所儲存的資料、帳號與存取權限的設定、來自網路的連線許可等由使用者負責。兩者之間的範圍依 IaaS、PaaS、SaaS、託管服務等服務形態而改變。因設定錯誤造成的資訊外洩，多半發生在使用者責任的範圍內。
無伺服器運算
把伺服器的準備、數量管理、作業系統更新等交給雲端業者，使用者不必意識這些就能執行應用程式的形態。代表是 FaaS（Function as a Service），只在要求或事件到來時執行函式，依執行次數、時間與記憶體量計費。依負載的增減自動進行，不使用時幾乎不產生費用。另一方面，有一段時間未使用後第一次呼叫變慢的冷啟動，以及執行時間上限等限制。
虛擬機器監視器(Hypervisor)
在一台電腦上執行多個虛擬機器的軟體。將CPU、記憶體與裝置分配給各虛擬機器的作業系統，並使彼此隔離。也稱為虛擬機器監視器(VMM)。
自動擴展
依負載指標（CPU使用率、要求數、佇列長度等）自動增減伺服器或容器數量的機制。增加數量稱為水平擴展（scale-out），減少稱為縮減（scale-in）。Kubernetes 的 HorizontalPodAutoscaler 以 ⌈目前數量 × 目前值 ÷ 目標值⌉ 求出所需數量。新增的執行個體開始運作需要時間，因此常以保留餘裕的目標值因應負載急增，並在減少前設置觀察時間，避免數量變動得太頻繁。
物件儲存
把資料作為附有鍵（名稱）與中繼資料的物件保存，並透過 HTTP 的 API 整個讀寫的儲存方式。不必預先決定容量，幾乎可以無限增加，資料一般會複製到多個裝置或地點，具有高耐久性。適合存放圖片、影片、備份、日誌與靜態網站的檔案。不適合像檔案系統那樣只改寫一部分，或放置資料庫的資料檔；這些用途會使用提供虛擬磁碟的區塊儲存，或提供共用檔案系統的檔案儲存。
SLA（服務水準協議）
IT 服務的提供者與使用者之間，約定可用率、回應時間、從故障恢復所需時間、問題受理時間等品質水準，以及其量測方式與未能達成時之處理方式的協議（Service Level Agreement）。
