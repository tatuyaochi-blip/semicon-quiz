中斷與輪詢的差異：比較機制與使用時機

處理器得知裝置需要處理的方式有兩種。輪詢是由 CPU 在迴圈中反覆確認裝置的狀態。中斷則是由裝置向 CPU 送出訊號，CPU 暫停手邊的工作去執行一個小型的處理常式，之後再回到原本的工作。輪詢簡單且容易預測，但會浪費時間；中斷有效率且回應快，但會增加負擔，也讓程式的行為更難掌握。

項目輪詢中斷
機制CPU 反覆讀取狀態暫存器，確認裝置是否就緒裝置發出訊號，CPU 中斷工作並執行中斷處理常式(ISR)
等待期間的 CPU忙碌。耗用週期來進行確認閒置。可以處理其他工作或進入睡眠
回應時間由迴圈的確認間隔決定。容易預測快(微秒等級)。但會因遮罩、優先權與上下文儲存而改變
額外負擔即使什麼都沒發生也是固定的每個事件都有成本。事件非常多時，CPU 會來不及處理(中斷風暴)
複雜度容易撰寫，也容易除錯複雜。處理常式必須簡短，與主程式共用的資料也要小心(volatile、原子存取)
耗電量讓 CPU 一直保持喚醒可在低耗電下睡眠，直到被事件喚醒
時序是否容易掌握容易掌握處理常式與主程式之間可能發生並行處理的錯誤
主要用途非常快速或連續的事件、簡單的程式、高速網路驅動程式計時器、按鈕、通訊事件、感測器警報、從睡眠中喚醒

數值為具代表性的大致參考值，會因世代或產品而異。

適用於什麼情況

輪詢
事件頻繁時，或是迴圈簡單、想要可預測的時序而不想有處理常式的複雜度時。
中斷
事件罕見或無法預測、想要快速回應與低耗電，且 CPU 還有其他工作時。
併用
也有系統會組合使用。以中斷通知第一個事件，在通訊量大的期間由驅動程式改用輪詢。高速網路驅動程式即是一例。

常見問題

中斷與輪詢哪一個比較好？

不能說哪一個永遠比較好。中斷回應快，也能讓 CPU 睡眠；輪詢簡單且容易預測。罕見的事件用中斷，非常頻繁的事件用輪詢。

中斷處理常式應該做什麼？

要保持簡短。只做最少的處理，設置旗標或把工作放入佇列後就返回。在處理常式中做冗長的處理或會產生等待的呼叫，會損害回應性。

什麼是中斷風暴？

事件來得太快，使 CPU 把時間全花在進出處理常式上的狀態。高速網路驅動程式在這種情況下會切換成輪詢。

為什麼中斷能節省耗電量？

因為 CPU 不必一直醒著確認，可以睡眠到被事件喚醒為止。

理解度檢測

在得知週邊電路狀態的方法中，輪詢（polling）與中斷的差異，下列何者正確？

  1. A輪詢是CPU反覆去檢查狀態，中斷是在狀態改變時由週邊電路通知CPU
  2. B輪詢與中斷是相同的東西
  3. C中斷是CPU反覆去檢查狀態的方式
查看答案與解析

正確答案：A. 輪詢是CPU反覆去檢查狀態，中斷是在狀態改變時由週邊電路通知CPU

輪詢的結構簡單，檢查的間隔固定，因此動作容易預測；但即使什麼都沒發生，CPU也持續檢查，會浪費時間與電力。中斷只在有變化時CPU才回應，因此等待期間可以做其他處理或進入睡眠。不過若中斷過於頻繁，反而會使處理的負擔變大，所以區分使用很重要。

在中斷處理常式中應避免的事項，下列何者最為適當？

  1. A在旗標變數寫入1，通知主程式
  2. B清除表示中斷原因的位元
  3. C以printf輸出長字串，或是持續等待某事發生的迴圈這類耗時的處理
查看答案與解析

正確答案：C. 以printf輸出長字串，或是持續等待某事發生的迴圈這類耗時的處理

中斷處理常式若長時間執行，這段期間就無法回應其他中斷，主程式也會停住。printf需要花時間到輸出完成，內部還可能使用中斷，特別危險。處理常式中只應進行最低限度的處理，例如接收資料放入緩衝區、設立旗標，繁重的處理則交給主程式或工作（task）。也別忘了清除原因位元。

在可為中斷設定優先順序的微控制器上，執行低優先順序中斷的處理常式期間，發生了高優先順序的中斷。一般會如何（假設設定為允許中斷巢狀）？

  1. A中斷低優先順序的處理常式，執行高優先順序的處理常式，結束後回到低優先順序處理常式的後續
  2. B在低優先順序的處理常式結束之前，高優先順序的中斷會被捨棄
  3. C兩個處理常式在同一個CPU上同時並行執行
查看答案與解析

正確答案：A. 中斷低優先順序的處理常式，執行高優先順序的處理常式，結束後回到低優先順序處理常式的後續

為中斷設定優先順序後，緊急的中斷即使在其他處理常式執行中，也能插入並被處理。例如，若將馬達過電流的偵測設為高優先順序，通訊接收設為低優先順序，即使在接收處理中，也能立即因應過電流。Arm Cortex-M的NVIC等具備此機制。優先順序相同或較低的中斷，則要等到目前的處理常式結束才會被處理。

  1. 將中斷處理常式的處理，分成立即執行的簡短部分，以及稍後在一般環境下執行的其餘部分，其理由為下列何者？
  2. 主程式正以「reg |= mask;」（讀取、修改、寫回）操作暫存器的位元時，中斷處理常式改寫了同一暫存器的另一個位元，可能發生的問題與對策的組合，下列何者正確？
  3. 將16 MHz的時脈經預除器除以16後供計時器計數，設定每計數1000次產生一次中斷。中斷的間隔是多少？

相關名詞的解說

中斷
回應外部裝置的請求等，暫時中止執行中的處理，優先進行對應處理的 CPU 機制。結束後回到原本的處理。
輪詢（Polling）
CPU 反覆去檢查周邊電路的狀態，藉以發現變化的方式。雖然單純，但即使什麼都沒發生也持續檢查，因此耗費時間與電力。
中斷處理常式
發生中斷或例外時CPU所執行的處理。儲存被中斷處理的狀態，依原因進行相應處理後，回到原本的處理。原則上處理要盡可能簡短。
