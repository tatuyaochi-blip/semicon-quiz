行程與執行緒的差異：比較記憶體、切換與使用時機

行程是擁有專屬位址空間與資源、正在執行的程式。執行緒是行程中的執行單位。同一個行程的執行緒共用記憶體，因此建立成本小、通訊也快，但一個錯誤或異常終止會影響整個行程。不同的行程彼此隔離，較為安全，但建立的成本以及行程間通訊的成本都比較大。

項目行程執行緒
是什麼擁有專屬位址空間與檔案等資源、正在執行的程式行程中的執行流程。擁有自己的堆疊與暫存器
記憶體各自獨立的虛擬位址空間。與其他行程隔離共用行程的程式碼、堆積與全域資料。專屬的只有堆疊
建立成本重。必須準備新的位址空間(可利用寫入時複製來降低成本)輕。不需要新的位址空間
情境切換高。位址空間會改變，位址轉換結果的快取(TLB)可能失效便宜。位址空間與快取維持不變
通訊需要管線、通訊端、共用記憶體等行程間通訊可直接讀寫共用記憶體，速度快
隔離與故障異常終止多半只限於該行程之內一個執行緒的異常終止，可能牽連整個行程
同步在行程之間共用記憶體或檔案時需要共用資料時一律需要。若沒有互斥鎖或不可分割操作，就會發生資料競爭或死結
排程包含一個以上的執行緒由作業系統實際分配給CPU核心的單位
主要用途為了隔離與安全。瀏覽器的分頁、服務、Shell的管線單一程式內的平行處理。處理大量連線的伺服器、背景處理、平行運算

數值為具代表性的大致參考值，會因世代或產品而異。

適用於什麼情況

行程
需要隔離、強健性與安全性時。或是由不同開發者製作的軟體不可共用記憶體時。
執行緒
處理之間必須快速共用資料，且想在一個程式中使用多個CPU核心時。
注意
執行緒共用記憶體，既是優點也是風險。共用資料要以鎖或不可分割操作保護，也要留意死結。

常見問題

執行緒會共用記憶體嗎？

會。同一個行程的執行緒共用該行程的程式碼、堆積與全域資料。各執行緒專屬擁有的只有堆疊與暫存器。

為什麼建立執行緒的成本比行程小？

新的行程需要專屬的位址空間，而執行緒使用行程的位址空間。執行緒的切換也不必改變位址空間，因此成本較小。

一個執行緒異常終止會怎麼樣？

因為執行緒共用記憶體，可能牽連整個行程。一個行程的異常終止，通常不會影響其他行程。

什麼時候應該使用行程而不是執行緒？

需要隔離與強健性時(瀏覽器的分頁、獨立的服務等)，或想避免元件彼此破壞對方的記憶體時。

理解度檢測

複製行程時使用寫入時複製（copy-on-write）的優點，下列何者正確？

  1. A複製出的行程與原行程，永遠能共用寫入的內容
  2. B只在之後才複製被寫入的分頁，因此速度快且節省記憶體
  3. C每次寫入時都會複製所有分頁，因此資料的安全性提高
查看答案與解析

正確答案：B. 只在之後才複製被寫入的分頁，因此速度快且節省記憶體

複製行程時，若立即複製所有記憶體，會耗費時間與記憶體，而且如果隨後載入的是另一個程式，這些複本就白費了。寫入時複製會讓雙方的頁表都以唯讀方式指向相同的實體分頁，當任一方寫入時就會發生分頁錯誤，由作業系統只複製該分頁。寫入的內容不會被共用，而是各行程分別保有。也不會複製所有分頁。

在環境切換（context switch）時，必須儲存切換前行程的哪些內容？

  1. A該行程所使用的磁碟檔案內容
  2. B暫存器的值與程式計數器等CPU的執行狀態
  3. C該行程在實體記憶體中的全部內容
查看答案與解析

正確答案：B. 暫存器的值與程式計數器等CPU的執行狀態

在環境切換時，為了之後能從相同狀態繼續執行，會儲存通用暫存器、程式計數器、堆疊指標、運作模式等CPU的狀態，並載入接下來要執行行程的狀態。切換行程時，也會一併切換指示頁表位置的暫存器。記憶體與檔案的內容原本就保留著，因此不必在每次切換時儲存。

行程的環境切換有時造成的效能下降，實際上比儲存與還原暫存器所花的時間更大，其主要理由為何？

  1. A因為每次切換，CPU的時脈頻率都會下降
  2. B因為每次切換，都要重新從磁碟讀取程式
  3. C因為切換之後，快取與TLB的未命中會增加
查看答案與解析

正確答案：C. 因為切換之後，快取與TLB的未命中會增加

儲存與還原暫存器本身只需很短的時間，但對切換後的行程而言，快取與TLB裡的內容是前一個行程的，在重新載入所需的資料與轉換結果之前，未命中會持續發生。在沒有ASID的CPU上，切換位址空間時還必須清空TLB。這種間接的成本，有時會比直接的切換時間更大。時脈並不會下降，也不會從磁碟重新讀取程式。

相關名詞的解說

環境切換
切換在CPU上執行的行程或執行緒。儲存並還原暫存器與程式計數器等狀態，切換行程時也會切換位址空間。
互斥鎖（Mutex）
同一時間只有一個執行緒能持有的鎖。無法取得時讓執行緒休眠並讓出 CPU，鎖被釋放時由作業系統喚醒，是一般常見的實作。
死結（Deadlock）
多個執行緒各自持有資源，並互相等待其他執行緒所持有的資源，使得誰都無法前進的狀態。可藉由全體統一取鎖順序來防止。
