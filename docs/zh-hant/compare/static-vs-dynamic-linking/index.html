靜態連結與動態連結的差異：比較函式庫的結合方式

連結是把編譯後的程式碼與它所使用的函式庫程式碼結合起來的作業。靜態連結會在建置時把所需函式庫的程式碼複製進執行檔，因此程式本身就能獨立運作。動態連結的執行檔只記錄所需的共享函式庫，在程式啟動時由作業系統載入，因此許多程式可以共用同一份副本。靜態連結便於散布，動態連結則能節省記憶體，也更容易更新。

項目靜態連結動態連結
何時進行建置時。把函式庫的程式碼複製到執行檔中載入時或執行時。由動態連結器尋找共享函式庫(.so、.dll)並進行對映
執行檔大小大小
記憶體使用量每個程式各自持有函式庫程式碼的副本共享函式庫的同一份副本可由多個行程共用
更新與安全性修補必須重新建置並重新散布程式只要更新一次函式庫就有效，不必重新建置(前提是介面相容)

適用於什麼情況

靜態
想要在任何地方都能執行、自我完備的二進位檔時；或是像嵌入式韌體那樣沒有作業系統載入器時。
動態
許多程式共用同一個函式庫，想節省記憶體並一次修正函式庫時。

常見問題

為什麼程式會因為找不到函式庫的錯誤而無法啟動？

因為程式是動態連結的，而所需的共享函式庫(.so 或 .dll 檔案)沒有安裝在該電腦上。請安裝函式庫，或改用靜態連結。

動態連結能節省記憶體嗎？

能。共享函式庫的同一份副本可由多個行程共用。

靜態連結比較快嗎？

稍微快一些。沒有啟動時的符號解析，也沒有經由 GOT 與 PLT 的間接呼叫，還能進行整個程式的最佳化。

為什麼動態連結有助於安全性更新？

因為共享函式庫只要修正一次，所有使用它的程式不必重新建置就能受惠。

理解度檢測

關於靜態連結，下列說明何者正確？

  1. A將所使用函式庫的程式碼複製到執行檔中加以結合
  2. B每次執行程式時，載入函式庫並加以結合
  3. C不使用函式庫，將所有處理寫在單一原始檔中
查看答案與解析

正確答案：A. 將所使用函式庫的程式碼複製到執行檔中加以結合

靜態連結是由連結器從靜態函式庫（Linux中為.a檔）取出所需的函式，嵌入執行檔。即使執行環境中沒有該函式庫也能運作，也不需要啟動時的結合作業，但執行檔會變大，且每個使用相同函式庫的程式都各自持有一份副本。即使函式庫有錯誤修正，不重新建置也不會反映。

關於動態連結（共用函式庫）的優點，下列何者正確？

  1. A即使執行環境中沒有函式庫，也一定能運作
  2. B多個程式可在記憶體上共用一個函式庫，更新函式庫後不必重新建置即可反映修正
  3. C啟動時的處理完全不需要，一定比靜態連結啟動得更快
查看答案與解析

正確答案：B. 多個程式可在記憶體上共用一個函式庫，更新函式庫後不必重新建置即可反映修正

在動態連結中，執行檔只記錄「要使用哪個共用函式庫的哪個函式」，執行時由動態連結器載入函式庫並加以結合。共用函式庫的程式碼不會被改寫，因此實體記憶體上的同一份副本可由許多行程共用。錯誤與漏洞的修正，也只要替換函式庫即可。不過啟動時需要花費結合的功夫。

將使用動態連結的程式複製到另一部電腦上執行，卻無法啟動。最可能的原因為下列何者？

  1. A因為函式庫的程式碼全都包含在執行檔中，檔案太大了
  2. B因為動態連結的程式規定只能在建置它的電腦上運作
  3. C沒有安裝所需的共用函式庫，或只有不相容的版本
查看答案與解析

正確答案：C. 沒有安裝所需的共用函式庫，或只有不相容的版本

動態連結的程式會使用執行它的電腦上的共用函式庫。如果沒有所需的函式庫，或只有缺少函式的舊版本，動態連結器就無法結合，導致啟動失敗。在Linux中可用ldd指令確認程式所需的共用函式庫，以及是否能找到它們。為了便於散布，有時也會刻意採用靜態連結。

前往連結器與載入器與執行檔格式的練習題

相關名詞的解說

靜態連結（Static linking）
將所使用的函式庫程式碼複製到可執行檔中結合的方式。即使執行環境沒有函式庫也能運作，但檔案會變大，函式庫的修正必須重新建置才會反映。
動態連結（Dynamic linking）
在執行時載入共享函式庫並加以結合的方式。函式庫可在行程間共用，抽換即可反映修正，但執行環境需要相符的函式庫。
共享函式庫（Shared library）
在動態連結時於執行期載入的函式庫。在 Linux 為 .so，在 Windows 為 .dll。以位置無關程式碼建置，程式碼的分頁可由多個行程共用。
靜態函式庫（Static library）
將多個目的檔彙整為一個的封存檔（在 Linux 為 .a）。進行靜態連結時，連結器只取出需要的目的檔並組入可執行檔。
