邊界防禦與零信任的差異：信任的前提、驗證的頻率、遠端存取比較

邊界防禦是信任公司內部網路的內側，在與網際網路的邊界配置防火牆或 VPN 設備，以阻擋來自外部攻擊的想法。零信任則不依網路位置給予信任，對使用者、裝置與存取對象的每一種組合，在每次存取時確認後，只允許必要的部分。美國 NIST 在 SP 800-207（2020 年）中定義了零信任架構。雲端服務與從公司外部的使用增加，需要保護的對象移到了邊界之外，是零信任普及的背景。

項目邊界防禦零信任
信任的前提信任公司內部網路的內側，不信任外側不依網路位置給予信任。來自公司內部的存取，也與外部一樣每次都要確認
防禦配置的位置與網際網路的邊界（防火牆、VPN 設備、代理伺服器等）使用者、裝置與存取對象（應用程式與資料）之間的每一條存取路徑。設置判斷是否允許的地方（政策決策點），以及依判斷放行的地方（政策執行點）
驗證與授權的時機進入公司內部網路時（例如連上 VPN 時）一次依存取對象、依工作階段進行。由使用者驗證（多因素驗證等）、裝置狀態、地點與時間等判斷，情況改變時重新評估
從公司外部的存取以 VPN 連上公司內部網路，視同在公司內一樣對待以 ZTNA（零信任網路存取）等方式，只連到允許的應用程式。不讓使用者進入整個網路
遭入侵後的橫向擴散一旦被入侵內側，內部設備之間的通訊限制少，容易擴散到其他設備細分存取並只給予必要的權限（最小權限），因此不易擴散
裝置的處理容易信任連在公司內部網路上的裝置裝置是否受管理、作業系統更新與惡意程式防護是否正常，每次存取時都作為判斷的依據
可視化與記錄會記錄通過邊界的通訊，但內部設備之間的通訊不易看見記錄所有存取的請求與判斷，用於持續的監視與判斷政策的改善
與雲端的契合度雲端服務與在家使用增加後，需要保護的對象會移到邊界之外。若所有通訊都經由 VPN 集中到公司內部，線路與設備容易壅塞不論地點都以相同的政策判斷，因此適合雲端服務與遠距工作
遷移的難度機制容易理解，許多組織已經具備需要身分管理、裝置管理、應保護資產的清單與存取政策的設計，需分階段遷移。並非導入一項產品就能實現

適用於什麼情況

邊界防禦
使用者與要保護的系統主要都在公司內部網路，限縮出入口就能保護的環境。即使遷移到零信任之後，邊界的防火牆仍會作為縱深防禦的一層保留下來。
零信任
以雲端服務與遠距工作為主，公司內外界線模糊的環境。也適合以遭入侵為前提，想縮小損害擴散範圍的情況。
分階段遷移
許多組織會與邊界防禦的機制並用，逐步遷移，例如全面採用多因素驗證、管理裝置、從重要的應用程式開始依序移到 ZTNA。

常見問題

採用零信任後，就不需要 VPN 了嗎？

為了從公司外部使用內部應用程式的 VPN，常會以 ZTNA 取代。因為 VPN 連線後就能進入整個網路，而 ZTNA 只連到允許的應用程式，並在每次存取時確認。不過，像連接各據點的 VPN 這類用於其他目的者，也會繼續使用。

零信任是產品的名稱嗎？

不是產品，而是資安設計的想法。NIST 的 SP 800-207（2020 年）將零信任及其架構說明為：不只依網路位置或資產的擁有者給予信任，而是在每次存取資源時進行驗證與授權的想法。實現時需搭配身分管理、多因素驗證、裝置管理、ZTNA、記錄與監視等。

採用零信任後，就不需要防火牆了嗎？

並非如此。零信任是指不只因為位在邊界內側就給予信任，並不是取消邊界的防禦。防火牆仍會作為在入口減少不必要通訊的一層，也會用來將網路細分成區段。

理解度檢測

下列驗證方法中，屬於多因素驗證的是哪一項？

  1. A輸入密碼後，再輸入本人智慧型手機的應用程式所顯示的一次性密碼
  2. B輸入密碼後，再輸入安全提問的答案
  3. C輸入長度加倍、更複雜的密碼
查看答案與解析

正確答案：A. 輸入密碼後，再輸入本人智慧型手機的應用程式所顯示的一次性密碼

多因素驗證是組合知識、持有物、生物特徵中兩種以上不同要素的驗證。密碼（知識）與本人智慧型手機產生的一次性密碼（持有物）的組合，使用了兩種不同的要素，因此是多因素驗證。即使密碼外洩，攻擊者沒有本人的智慧型手機也無法登入。密碼與安全提問都是知識要素，即使分兩個步驟確認，也不是多因素驗證（有時稱為兩步驟驗證）。重疊相同種類的要素，可能被同一種手法（例如以網路釣魚騙取）一併竊取。此外，一次性密碼也有讓使用者當場輸入到假網站而被冒用的攻擊，因此在2020年代中期，在假網站上無法完成驗證的方式（如FIDO2的通行金鑰）正逐漸普及。

下列何者正確描述單一登入（SSO）？

  1. A只要驗證一次，就能使用多個相互串接的服務而不必重新登入的機制，便利性提高，但該驗證一旦被突破就會影響許多服務，因此最好搭配多因素驗證
  2. B指所有服務都重複使用同一組密碼，為提高安全性而受到推薦
  3. C讓一個服務同時只能有一個人登入的機制
查看答案與解析

正確答案：A. 只要驗證一次，就能使用多個相互串接的服務而不必重新登入的機制，便利性提高，但該驗證一旦被突破就會影響許多服務，因此最好搭配多因素驗證

在單一登入（SSO）中，使用者登入一次負責驗證的系統（IdP，身分識別提供者）後，結果會以安全的方式傳給各個串接的服務，不必在每個服務重新登入就能使用。代表性的協定有SAML與OpenID Connect。由於不必把密碼交給各個服務，需要管理的密碼減少，也有能在一處停用離職人員帳號等管理上的好處。然而IdP的帳號一旦遭盜用，所有串接的服務都會被入侵，因此在IdP實施多因素驗證特別重要。重複使用密碼則是另一回事，它會讓從某個服務外洩的密碼被用來登入其他服務（撞庫攻擊）。

下列何者是符合最小權限原則的做法？

  1. A為了減少作業的工夫，給所有人管理員權限
  2. B為了簡化權限設定，讓所有人都能讀寫所有檔案
  3. C只給使用者與程式業務所需的最低限度權限，平時的作業以非管理員的帳號進行
查看答案與解析

正確答案：C. 只給使用者與程式業務所需的最低限度權限，平時的作業以非管理員的帳號進行

最小權限原則是只給使用者、程式與服務帳號完成其角色所需之最低限度權限的想法。限縮權限後，即使帳號遭盜用、惡意軟體執行或操作失誤，也能縮小損害的範圍。例如平時收發電子郵件與瀏覽網頁使用一般權限的帳號，只有在需要的作業時才使用管理員權限。對於資訊，也有「只讓需要知道的人知道（need-to-know）」的想法，只讓業務上需要的人存取。在調職或離職時立即撤銷不再需要的權限也很重要。

前往資訊安全基礎的練習題

相關名詞的解說

多因素驗證
組合知識（密碼等）、持有物（智慧型手機、IC卡等）、生物特徵（指紋、臉部等）中兩種以上不同要素來確認本人的驗證。即使密碼外洩，沒有其他要素也無法登入。也稱為MFA。
最小權限原則
只給予使用者、程式與服務完成其角色所需之最低限度權限的想法。即使發生帳號遭盜用、惡意軟體或操作失誤，也能縮小損害的範圍。
TLS
Transport Layer Security（傳輸層安全性協定）。進行通訊加密、竄改偵測，以及以憑證驗證伺服器的協定。HTTPS是以TLS保護的HTTP。
VLAN
虛擬區域網路。以交換器的連接埠等為單位，在實體上相同的設備上建立邏輯上各自獨立之網路（廣播網域）的功能。交換器之間以IEEE 802.1Q的標籤區分。
勒索軟體
把電腦中的檔案加密等使其無法使用，並以還原為條件要求贖金的惡意軟體。也有威脅要公開所竊取資料的手法。與網路隔離保存的備份是重要的防護。
