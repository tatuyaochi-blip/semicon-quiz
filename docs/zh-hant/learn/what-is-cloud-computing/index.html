雲端運算是什麼？資料和應用程式在「哪裡」運作

約 10 分鐘 · 更新：2026年10月23日

雲端，就是透過網際網路，租用別家公司擁有的大量電腦來使用的機制。這些電腦放在稱為資料中心的專用建築物裡。儲存照片、網頁郵件等許多日常服務都在雲端運作，而它們的安全由業者和使用者分工守護。

這篇文章可以了解

  • 「放在雲端」的資料，實際上在哪裡
  • 公司使用雲端的理由，以及費用、故障等注意事項
  • IaaS、PaaS、SaaS的差異，以及虛擬化的原理
  • 資料中心裡有什麼，以及表示用電效率的數字
  • 由業者和使用者分擔安全的「共同責任模型」

先備知識：不需要。只要用手機存過照片，或用過網頁郵件就夠了。

生活中的例子

換了新手機，以前的照片有時還是能直接看到。這是因為照片不只存在手機裡，也存在網際網路的另一端。網頁郵件、影音串流，以及在瀏覽器上使用的文書處理和試算表也一樣。它們的資料和計算本體都不在手邊，而在遠方的電腦上。

像這樣把資料交給遠方的電腦保管，或把計算交給它處理的使用方式，稱為「雲端」。正式名稱是「雲端運算」（cloud computing）。英文的cloud是「雲」的意思。

雲端的真面目是「別家公司的電腦」

說是「存到雲端」，資料並不是飄在空中。有一種電腦會依照要求交出資料或進行計算，稱為「伺服器」。雲端的實體，就是雲端業者擁有的伺服器。

手邊的手機和伺服器之間，透過網際網路相連。資料怎麼傳送，在「網際網路怎麼傳送資料？」中說明。

業者把大量伺服器集中放在專用的建築物裡。這種建築物為大量機器集中準備了電力、空調和通訊線路，稱為「資料中心」。使用者平常不會意識到自己用的是裡面的哪一台機器。

美國國家標準與技術研究院（NIST）在2011年公布了雲端的定義。這裡把定義中列出的5項特徵整理成3點，用淺顯的話重新說明。

  • 透過網路，想用的時候自己申請，馬上就能使用
  • 許多使用者共用大型設備，能快速增減使用量
  • 使用量會自動計量，使用者也看得到（是計費的依據）

公司使用雲端的理由

在雲端普及之前，公司通常自己買伺服器，放在公司內的機房運作。這種形態稱為「本地部署」（on-premises，台灣也常稱「地端」）。買機器的錢要先付，等機器送到、能運作也要花時間。更換零件、汰換老舊機器，也都要自己來。

用雲端的話，租用伺服器的手續在網頁畫面上幾分鐘就能完成。費用基本上依使用的時間和儲存的量來付。即使不知道新服務會不會成功，也能先從小規模開始，邊看情況邊擴大。

能配合使用者人數改變伺服器台數，也是優點。例如，只有在售票開賣日才湧入大量連線的網站，可以只在那段時間增加伺服器。依照忙碌程度自動增減台數的機制，稱為自動擴展。

用比喻來說

使用雲端，就像不買車而改用共享汽車。只在需要時租用，依使用的時間付費。檢查和修理由出租的公司負責。相似的是「不擁有而租用，只為用到的部分付費」這一點。

比喻的限制：車子是自己在手邊駕駛，伺服器卻在遠方的建築物裡，只能透過網路使用。而且資料寄放在業者那裡時，即使沒在用，儲存費用也會一直產生。一台機器同時由許多人分著用，這點也和車子不同（見後面「虛擬化」一節）。

費用，以及依賴業者的風險

雲端不一定比較便宜。只要還在租用，每個月都會持續收費。如果要讓大量伺服器多年不停地運作，有時自己買反而便宜。也有服務在把寄放的資料移出時，要收取傳輸費用。

依賴業者和網路這一點也要注意。網路一斷，不在手邊的資料就無法使用。業者那邊發生故障時，自己也修不了，只能等待恢復。各家業者的使用方式不同，所以要換到別家業者，有時很費工夫。

2025年10月19～20日（美國時間），Amazon的雲端「AWS」在美國北維吉尼亞區域發生了大規模故障。由名稱查出伺服器號碼的機制，稱為DNS（網域名稱系統）。根據AWS的事後報告，原因是某項資料庫服務中，自動管理DNS紀錄的機制裡潛藏的錯誤。紀錄變成空的，導致無法建立對該資料庫的新連線。影響也擴大到依賴它的其他服務。從最初的異常，到AWS宣布故障結束的時間，約14個半小時。

自家的伺服器也會故障。差別在於，一家業者的故障會同時波及許多公司的服務。業者會在1個區域裡準備好幾組建築物，彼此的電源、空調和線路各自獨立。這樣的一組稱為可用區域，重要的系統會分散放在多個可用區域。不過，像上面的例子那樣，也有波及整個區域的故障，所以也要考慮在別的區域做準備。

IaaS、PaaS、SaaS：租用到哪個範圍

雲端服務依業者準備到哪個範圍，大致分成3種。這也是NIST定義中出現的分法。名稱後半的「aaS」是as a Service（以服務的形式提供）的縮寫。

開頭的字母表示租用的是什麼。I是基礎設施（Infrastructure），P是平台（Platform），S是軟體（Software）。這裡的平台，指作業系統和執行應用程式所需的軟體。作業系統是像Windows、Linux那樣，管理整台電腦的基本軟體。

種類業者準備的部分例子
IaaS伺服器、儲存空間、網路等基礎設施。作業系統以上由使用者管理出租虛擬伺服器
PaaS直到作業系統和執行程式的環境。使用者放上自己的應用程式應用程式的執行環境、資料庫服務
SaaS應用程式本身。使用者只要透過瀏覽器等使用網頁郵件、線上文書處理

用比喻來說

三者的差異，就像準備晚餐的方式。IaaS是租一間空廚房，連工具都要自己準備。PaaS是在工具和調味料都齊全的廚房裡，照自己的食譜做菜就好。SaaS是在餐廳吃做好的料理。相似的是「自己要做的範圍，從IaaS到SaaS依序變小」這一點。

比喻的限制：在餐廳吃飯，連收拾都是餐廳的工作。但即使是SaaS，寄放的資料和「給誰看」的設定，始終是使用者的工作（見後面的章節）。而且實際的服務不會整齊地分成這3種，也有介於中間的。

以自由度和維運工作量比較三者的表格，在「IaaS、PaaS與SaaS的差異」。也有幾乎不必意識伺服器管理、只執行簡短程式的形態，稱為無伺服器運算。

虛擬化：把1台機器分成好幾台

資料中心的伺服器效能很高，只用在一種用途上，常常用不完。所以要靠軟體的力量，把1台機器分成好幾台「看起來像獨立的電腦」。這個機制稱為「虛擬化」。

分出來的每一台，稱為「虛擬機器」。每台虛擬機器都有自己的作業系統，在使用者看來就是獨立的1台電腦。同一台機器上，也可能並排著別家公司的虛擬機器。

把機器的資源分給各虛擬機器，並隔開它們、讓彼此看不到內部的，是一種專用軟體。這種軟體稱為虛擬機器監視器（Hypervisor）。建立虛擬機器不必新買機器，所以申請後很快就能使用。用完就刪除，把那部分資源轉給其他使用者。

還有更輕量的分法。不像虛擬機器那樣執行整套作業系統，而是共用1個作業系統的核心部分，再依應用程式區隔開來。這種區隔稱為容器。容器輕巧、啟動快，但隔離的強度一般不如虛擬機器。差異整理在「虛擬機器與容器的差異」的表格中。

資料中心裡有什麼？

資料中心裡，一排排高大的架子並列著。這種架子稱為「機櫃」，裡面疊放著好幾台薄箱子形狀的伺服器。還有儲存資料的裝置（儲存設備），以及把機器彼此、和外部線路連起來的通訊設備。

讓系統不停機的設備也很重要。為了因應停電，會準備能立刻供電的電池，以及緊急用的發電機。伺服器運作時會發熱，不持續冷卻就會停機或損壞。除了大型空調，也有讓冷的液體流到機器附近來冷卻的方法。

表示資料中心用電效率、也就是用電有多少沒浪費的數字，是PUE（電力使用效率）。它是整棟建築物的用電量，除以伺服器等IT設備用電量所得的值。如果空調和電源轉換完全沒有浪費，就是1.0，越接近1表示效率越好。

調查機構Uptime Institute在2024年進行的全球調查中，PUE的平均是1.56。這是各受訪者營運的最大設施1年間的值。換算起來，IT設備每用1，就要在空調等方面多用0.56。大型業者公布的值更低，例如Google在2024年自家大型資料中心整體是1.09。不過，量測方式和氣候不同，所以不能單純比較。

AI和GPU也在雲端運作

最近的資料中心，最受關注的話題是AI。AI的訓練和使用，需要處理大量同樣形式的計算。所以會使用能同時進行大量計算的GPU這種零件。理由在「AI為什麼要用GPU？」中說明。

大型AI的訓練需要大量昂貴的GPU，能自己買齊的公司並不多。所以雲端業者準備了裝有GPU的伺服器，依使用時間出租。

隨著AI普及，資料中心的用電量也在增加。用電量以TWh（兆瓦時）為單位，1 TWh是10億kWh（度）。根據國際能源總署（IEA）2025年的報告，2024年全球資料中心的用電約415 TWh。這約占全球用電的1.5%。IEA預估，2030年會達到約945 TWh，增加為2倍多。

安全要「分工」守護：共同責任模型

雲端的安全，由業者和使用者分擔範圍來守護。這個想法稱為共同責任模型（也稱責任共擔模型）。AWS的說明是：業者負責「雲端本身」的安全，使用者負責「雲端之中」的安全。

業者負責的是建築物、機器、虛擬化平台等。管理建築物的出入、修理機器、修正平台軟體，都屬於這部分。使用者負責的是自己的帳號、允許誰做什麼的設定，以及儲存的資料。如果是IaaS，更新虛擬機器的作業系統也是使用者的工作。

Microsoft表示，不論哪種形態，資料和身分（帳號）都屬於使用者，守護的責任也在使用者。Google則提出更積極支援使用者的想法，例如由業者提供安全設定的範本。

事故也常常來自使用者這一方的設定錯誤。美國國家安全局（NSA）在2020年的文件中，把雲端資源的設定錯誤列為最常見的弱點。例如，把檔案的存放位置設成「任何人都能看」，內容就被外部讀取的事故。

密碼也是攻擊目標。如果使用容易猜中的密碼，或重複使用在別處外洩過的密碼，不論業者的設備多堅固，還是會被入侵。防範方法在「密碼為什麼會被破解？」中說明。除了密碼，再用手機等其他方式確認本人的機制，稱為多因素驗證，在雲端是基本配備。

常見的誤解

誤解：雲端就像在天上，沒有固定的地點

實際上，資料存放在某個國家、某棟建築物裡的機器上。多數業者都讓使用者能選擇放資料的區域。依存放地點所在的國家，適用的法律也可能不同，所以公司會確認並選擇存放地點。這個誤解，容易來自「雲」這個名稱，以及不必在意地點就能使用的便利。

誤解：放在雲端的資料會自動備份，所以很安全

實際上，業者為了因應機器故障，常會把資料複製到多台裝置上。但這並不能防範自己刪除或覆寫的情況。在讓手邊和雲端內容保持一致的同步服務中，在手邊刪除，雲端上的也可能跟著消失。也可能遭遇帳號被盜，或勒索軟體（讓資料無法讀取並要求贖金的程式）的損害。重要的資料，要在別的地方也留一份備份。

誤解：改用雲端，一定會變便宜

實際上，使用量起伏大的用途，或想從小規模開始時，比較容易變便宜。另一方面，多年持續使用同樣的量，有時自己建置反而便宜。忘了關掉沒在用的伺服器，那部分也會被收費。比較時，要用包含電費和管理人力在內的總額來考量。
