什麼是裝置驅動程式

用來驅動特定周邊裝置的作業系統元件。負責裝置暫存器的操作與中斷的處理，讓應用程式能以共通的程序使用裝置。

日文名稱: デバイスドライバ

「裝置驅動程式」出現在1領域的2道練習題中（作業系統與硬體等）。

這個名詞所屬的領域: 作業系統與硬體

驅動程式實際做些什麼

驅動程式把核心發出的通用請求，轉譯成特定裝置所期望的精確操作序列。啟動時，它會探測裝置、將其暫存器對映到位址空間（記憶體對映 I/O），並把硬體置於已知狀態。運作期間，它寫入命令與狀態暫存器、準備 DMA（直接記憶體存取）描述符，讓裝置能在不需 CPU 複製的情況下與記憶體互相搬移資料，並處理裝置在工作完成時發出的中斷。向上，它接入區塊裝置、網路或字元裝置介面等共通框架，讓應用程式看到的是一般的讀取、寫入與控制呼叫。

中斷處理與延後工作

中斷處理常式執行時，該 CPU 上的一般工作會被暫停，因此驅動程式會讓它盡量簡短：回應裝置、記下發生了什麼，再排定其餘工作。較繁重的處理，例如把收到的封包往上交給協定堆疊，或完成磁碟請求，則稍後在可排程的情境中執行。這種分工常稱為上半部（top half）與下半部（bottom half）。高速網路卡等極高速率的裝置，在負載高時可能從每個事件一次中斷改為輪詢，因為每個封包都觸發一次中斷所浪費的 CPU 時間，會比在迴圈中檢查佇列還多。

驅動程式錯誤為何危險

大多數驅動程式在核心模式下執行，與核心其他部分擁有相同權限。因此，一個錯誤的指標、一個遺漏的鎖，或以錯誤位址設定的 DMA 緩衝區，都可能破壞任何地方的記憶體，或讓整個系統當機，而不只是單一程式。因此驅動程式是系統不穩定與安全漏洞的常見來源。有些設計把驅動程式移到使用者空間行程中，以額外的情境切換換取隔離；而 IOMMU 即使在驅動程式行為異常時，也能限制裝置可存取的記憶體範圍。

驅動程式、韌體與 Hypervisor 的區別

韌體是在裝置本身上執行的程式碼，例如在 SSD 或網路卡內部的控制器上；驅動程式則在主機 CPU 上執行，並透過暫存器與共享記憶體與該韌體溝通。Hypervisor 位於整個作業系統之下，在虛擬機器之間分享硬體。在虛擬機器內，客體作業系統要不是使用能與 Hypervisor 高效溝通的半虛擬化驅動程式，就是在裝置指派（device assignment）的情況下，為交給它的實體裝置執行一般的驅動程式。

練習裝置驅動程式的題目

關於裝置驅動程式（device driver）的作用，下列何者正確？

  1. A負責各裝置專屬的操作，使其能以共通的程序來使用
  2. B設計裝置的電路，並產生製造所需的資料
  3. C配合使用者的喜好，更改應用程式的畫面外觀
查看答案與解析

正確答案：A. 負責各裝置專屬的操作，使其能以共通的程序來使用

每種裝置的暫存器排列方式與操作程序都不同。裝置驅動程式是承擔這些差異的作業系統元件，負責裝置的初始化、暫存器的讀寫、DMA的設定及中斷的處理，並向上層提供像檔案讀寫這樣的共通程序。因此，應用程式不需要知道裝置的細部差異就能使用。設計裝置電路或更改畫面外觀，都不是驅動程式的工作。

常見問題

裝置驅動程式是作業系統的一部分嗎？

通常是。大多數驅動程式是以核心權限執行、接入作業系統裝置框架的核心模組，不過有些系統也支援以使用者空間行程執行的驅動程式。

驅動程式和韌體有什麼差別？

韌體在裝置內部的處理器上執行，直接控制硬體。驅動程式則作為作業系統的一部分在主機 CPU 上執行，透過暫存器、DMA 緩衝區與中斷，與裝置及其韌體溝通。

為什麼一個有問題的驅動程式會讓整台電腦當機？

核心模式驅動程式共用核心的位址空間與權限，因此一個錯誤就可能覆寫任何核心資料，或讓硬體處於不一致的狀態。相較之下，使用者程式的錯誤只會侷限在它自己的行程內。
