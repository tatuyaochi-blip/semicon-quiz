什麼是Slack(時序裕度)

表示時序餘裕的值。設定檢查以要求時間減去到達時間，保持檢查以到達時間減去要求時間求得，為負值即表示違反。

日文名稱: スラック

「Slack(時序裕度)」出現在1領域的1道練習題中（時序分析與CDC等）。

這個名詞所屬的領域: 時序分析與CDC

計算設定時間的 slack

靜態時序分析（STA）比較資料的到達時間與要求時間。就設定時間而言，在某個時脈邊緣發出的資料，必須在下一個擷取邊緣減去設定時間之前到達，因此 slack = 要求時間 − 到達時間。若週期為 2.0 ns、時脈到輸出延遲 0.2 ns、邏輯延遲 1.4 ns、設定時間 0.1 ns，則到達時間為 1.6 ns，要求時間為 1.9 ns，slack 為 +0.3 ns。代表抖動與尚未建構之時脈樹的時脈不確定度，也要從要求時間中扣除；而設定為 2 的多週期路徑，會讓擷取邊緣再往後延一個週期。

保持時間的 slack，以及為何降頻沒有幫助

保持時間檢查的是相反的問題：由某個邊緣發出的新資料，是否到得太早，以致破壞了同一個邊緣正在擷取的值？此時 slack = 到達時間 − 要求時間，使用最小延遲，且要求時間 = 擷取時脈到達時間 + 保持時間。由於兩者都參照同一個邊緣，時脈週期不會出現在式子裡，因此降低時脈頻率永遠無法修正保持時間違反；在實際晶片上這通常是致命的。保持時間問題出現在移位暫存器等短路徑上，一般是在資料路徑上插入延遲單元來修正。

時脈偏移、OCV 與 CRPR

時脈偏移（skew）會讓這兩種檢查朝相反方向變化。若擷取時脈比發出時脈晚到（正偏移），設定時間 slack 會增加該量，保持時間 slack 則減少同樣的量；負偏移則相反。晶片內變異（OCV）降額讓分析趨於悲觀，以設定時間檢查為例，會讓發出時脈與資料路徑變慢，並讓擷取時脈變快。當兩條時脈路徑從根部開始共用緩衝器時，這段共用部分不可能同時又快又慢，因此共同路徑悲觀消除（CRPR）會把這個差值加回來。

解讀時序報告

報告會按每個端點彙整 slack。WNS（最差負 slack）是單一最差值，顯示時脈距離收斂還有多遠；TNS（總負 slack）則加總所有違反端點的負 slack，顯示還剩下多少工作量。三個端點各為 −0.1 ns 時，WNS 為 −0.1 ns，TNS 為 −0.3 ns。兩者都會針對設定時間與保持時間、以及各時脈群組分別報告。設定時間違反的對策是縮短邏輯、加大單元尺寸或重新架構；只有在邏輯確實每隔一個週期才擷取時，設定多週期例外才是正當的。

練習Slack(時序裕度)的題目

關於STA報告中出現的WNS與TNS，下列說明何者正確？

  1. AWNS是表示違規路徑條數的指標，TNS是表示所有已分析路徑條數的指標
  2. BWNS是最差的餘裕值，TNS是負餘裕的總和
  3. CWNS是保持時間的餘裕，TNS是建立時間的餘裕
查看答案與解析

正確答案：B. WNS是最差的餘裕值，TNS是負餘裕的總和

WNS（Worst Negative Slack）是所有路徑中最差的餘裕，可作為頻率能提高到多少的參考。TNS（Total Negative Slack）是將違規路徑各終點的負餘裕加總的值。例如若有3個 −0.1 ns 的終點，WNS為 −0.1 ns，TNS為 −0.3 ns。即使WNS的絕對值小，若TNS的絕對值大，就需要修正許多路徑。違規的條數以其他指標表示，WNS與TNS則分別針對建立時間與保持時間求出。

常見問題

時序分析中的負 slack 是什麼意思？

表示該路徑違反了時序限制：就設定時間而言，資料到得太晚，趕不上擷取邊緣；就保持時間而言，資料到得太早，可能覆寫正在擷取的值。其大小表示必須減少或增加多少延遲。

WNS 和 TNS 有什麼差別？

WNS 是單一最差路徑的 slack，TNS 則是所有端點負 slack 的總和。當許多路徑都只差一點點而失敗時，設計可能 WNS 很小但 TNS 很大。

保持時間違反要怎麼修正？

在較短的資料路徑上增加延遲，通常是使用緩衝器或延遲單元；或減少使擷取時脈延後的時脈偏移。降低時脈頻率沒有幫助，因為保持時間檢查與週期無關。
