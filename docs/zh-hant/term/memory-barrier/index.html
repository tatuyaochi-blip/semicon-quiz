什麼是記憶體屏障（Memory barrier）

保證屏障之前的記憶體操作會先於之後的操作被其他核心看見的指令。亦稱 fence。例如 RISC-V 的 fence。

日文名稱: メモリバリア

「記憶體屏障（Memory barrier）」出現在1領域的2道練習題中（多核心與同步等）。

這個名詞所屬的領域: 多核心與同步

記憶體屏障保證了什麼

記憶體屏障又稱 fence，是一種將執行緒的記憶體操作分為「之前」與「之後」兩部分的指令，保證之前的操作會在之後的操作執行前就被其他核心看見。若沒有它，處理器可能讓對不同位址的載入與儲存亂序完成，例如把儲存留在儲存緩衝區中，而讓後續載入先行。發出指令的執行緒本身所看到的結果永遠不會改變，因此屏障只有在資料於核心之間，或與 DMA 引擎等裝置共享時才有意義。

儲存緩衝區範例

設核心 0 執行 x = 1 後執行 r1 = y，核心 1 執行 y = 1 後執行 r2 = x，x 與 y 初始為 0。在循序一致性下，必有一個儲存先發生，因此至少有一個載入會回傳 1。在包括 x86 在內的實際處理器上，每個儲存都可能在自己核心的儲存緩衝區中等待，而接下來的載入從快取讀取舊值，因此 r1 與 r2 可能都是 0。在每個執行緒的儲存與載入之間放置完整屏障，可迫使儲存在載入執行前變得可見，從而排除這種結果。

實際 ISA 上的屏障指令

RISC-V 提供 fence 指令，其運算元指明哪些較早的存取必須排在哪些較晚的存取之前，因此 fence rw, rw 會為所有讀取與寫入排序；其原子指令與 load-reserved/store-conditional 指令則帶有 acquire 與 release 位元。Arm 有用於排序的 dmb（資料記憶體屏障）、需要等待完成時使用的 dsb，以及 load-acquire 與 store-release 指令。x86 的總儲存順序（TSO）已保留大多數順序，主要只在需要讓儲存排在較晚的載入之前時，才需要 mfence 或帶 lock 前綴的指令。屏障並非沒有代價，因為它可能讓核心停頓直到待處理的儲存全部排出。

鎖與編譯器中的屏障

大多數程式設計者從不直接撰寫屏障。取得鎖時具備 acquire 語意，使後續存取無法移到它之前；釋放鎖時具備 release 語意，使較早的寫入在鎖被釋放前就已可見；這就是受鎖保護的資料能在執行緒之間正確傳遞的原因。程式語言則透過帶有記憶體順序的原子操作提供相同的概念，例如 C11 與 C++11。編譯器屏障是另一回事：它阻止編譯器將存取移過某一點，但不產生任何指令，因此無法約束硬體。

練習記憶體屏障（Memory barrier）的題目

關於記憶體屏障（fence）指令的作用，下列何者正確？

  1. A保證屏障之前的記憶體操作，會比屏障之後的操作更早被其他核心看到
  2. B將記憶體在物理上隔開，禁止存取
  3. C讓程式的執行暫停，直到所有執行緒都到齊
查看答案與解析

正確答案：A. 保證屏障之前的記憶體操作，會比屏障之後的操作更早被其他核心看到

由於CPU有時會調換記憶體操作的順序，若要以既定的順序與其他核心交換資料，就需要阻止調換的指示。記憶體屏障會讓之前的讀寫全部完成（使其他核心看得到）之後，才進行後面的讀寫。鎖的取得與釋放之中也含有屏障的作用，因此受鎖保護的變數才能被正確地傳遞。

常見問題

記憶體屏障（memory barrier）和 fence 有什麼不同？

兩者是同一個概念的兩種名稱，都是指一種讓其他核心觀察到「其之前的記憶體操作排在其之後的操作前面」的指令；RISC-V 將其指令稱為 fence，Arm 則稱為 barrier。

x86 需要記憶體屏障嗎？

比弱排序架構少，因為 x86 的總儲存順序讓大多數載入與儲存維持程式順序。但當儲存必須在之後對另一位址的載入之前變得可見時，仍需要 mfence 等屏障或帶 lock 前綴的指令。

編譯器屏障和記憶體屏障有什麼差別？

編譯器屏障只阻止編譯器將記憶體存取移過它，不會產生任何機器指令。記憶體屏障則是一條硬體指令，約束處理器讓存取被其他核心看見的順序。
