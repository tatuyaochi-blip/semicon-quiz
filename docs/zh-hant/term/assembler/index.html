什麼是組譯器

將以組合語言撰寫的程式，轉換成機器碼指令位元序列的軟體。將標籤改為位址，並將虛擬指令替換成真正的指令。

日文名稱: アセンブラ

「組譯器」出現在2領域的6道練習題中（指令集與組合語言, 編譯器等）。

這個名詞所屬的領域: 指令集與組合語言

從助憶符號到位元模式

組譯器逐行讀取組合語言原始碼。對每一條指令，它會查詢助憶符號、檢查運算元，並將運算碼、暫存器編號與立即值填入指令格式的固定欄位中，例如一個 32 位元的 RISC-V 字組。.text、.data、.word 與 .globl 等指引，則告訴組譯器要輸出到哪個區段、要配置哪些資料，以及要匯出哪些符號。由於組合語言幾乎一對一對應到機器指令，每個指令集架構（ISA）都有自己的組合語言。

標籤、符號與兩階段處理

標籤讓程式設計師可以寫出分支目標與資料名稱，而不必寫數字位址。標籤可能在定義之前就被使用，因此傳統的組譯器會進行兩階段處理：第一階段走訪原始碼，為每個標籤指定位址並建立符號表；第二階段再使用這些位址編碼每條指令。到同一區段內標籤的距離會直接填入。對其他檔案中符號的參考，或取決於最終配置位置的位址，此時還無法解析，因此組譯器會留下預留值，並在輸出的目的檔中為連結器記錄一筆重定位項目。

虛擬指令與展開

組譯器接受硬體中不存在的便利虛擬指令。在 RISC-V 中，nop 變成 addi x0, x0, 0，mv rd, rs 變成 addi rd, rs, 0，j label 變成 jal x0, label，ret 則變成 jalr x0, 0(ra)。li 可載入任何常數：小的數值只需一條 addi，完整的 32 位元數值則變成以 lui 處理上方 20 位元、再以 addi 處理下方 12 位元；由於 addi 會對其立即值做符號延伸，當下方部分為負時，上方部分要加一來調整。組譯器也可能把目標超出約 4 KiB 範圍的條件分支，改寫成跳過一條 jal 的反向條件分支。

組譯器與編譯器、連結器及反組譯器

編譯器翻譯的是高階語言，一個敘述可能變成許多條指令，而這種對應涉及暫存器配置與最佳化等實質決策。組譯器幾乎不做這類選擇；它的工作是編碼、解析標籤與展開虛擬指令。其輸出是目的檔，而不是可執行的程式：連結器還必須合併目的檔與函式庫，並確定最終位址。反組譯器則進行反向翻譯，將位元模式轉回助憶符號，但它無法還原註解，而且若沒有符號表，也無法還原原本的標籤名稱。

練習組譯器的題目

RISC-V的虛擬指令「nop」（什麼都不做），實際上會被組譯器替換為下列哪一個指令？

  1. Aaddi x0, x0, 0
  2. Bjal ra, 0
  3. Clw x0, 0(sp)
查看答案與解析

正確答案：A. addi x0, x0, 0

RISC-V沒有「什麼都不做」的專用指令，nop以「addi x0, x0, 0」表示。由於寫入x0的內容會被捨棄，暫存器與記憶體都不會有任何改變。同樣地，「mv rd, rs」是「addi rd, rs, 0」，「j label」是「jal x0, label」，「ret」是「jalr x0, 0(ra)」。善用x0來減少指令的種類，是RISC-V的設計理念。

常見問題

組譯器和編譯器有什麼差別？

編譯器將 C 等高階語言翻譯成組合語言或機器碼，並決定暫存器的使用與最佳化。組譯器則將組合語言幾乎一對一地翻譯成機器碼，主要工作是編碼指令並將標籤轉為位址。

組合語言的虛擬指令是什麼？

它是硬體不直接實作的便利助憶符號；組譯器會將它替換成一條或多條真正的指令。例如在 RISC-V 中，nop 會被組譯成 addi x0, x0, 0，而 li 可能變成 lui 後接 addi。

組譯器會產生可執行檔嗎？

通常不會。它產生的是包含機器碼、符號表與重定位項目的目的檔，再由連結器將一個或多個目的檔轉成可執行檔。
