什麼是原子指令（Atomic instruction）

將記憶體的讀取與寫入，作為不會被其他核心中途打斷的單一操作來進行的指令。包括 CAS、fetch-and-add、LR/SC 等。

日文名稱: アトミック命令

「原子指令（Atomic instruction）」出現在2領域的7道練習題中（多核心與同步, 指令集與組合語言等）。

這個名詞所屬的領域: 多核心與同步

為什麼一般的載入與儲存不夠

像 counter++ 這樣的敘述會被編譯成一個載入、一個加法與一個儲存。若兩個核心同時執行它，兩者可能都載入相同的舊值，並都儲存 舊值 + 1，導致少加一次。原子指令將整個讀取－修改－寫入作為一個不可分割的操作來執行：其他核心對該位置的存取無法插入其中，其他核心只會觀察到操作之前或之後的值。這項保證是多核心處理器上鎖、計數器與無鎖資料結構的基礎。

常見的原子操作種類

測試並設定（test-and-set）與原子交換會寫入新值並回傳舊值。fetch-and-add 對記憶體加上一個值並回傳先前的值。比較並交換（CAS）只有在記憶體仍保存預期值時才寫入新值，並回報是否成功。載入保留／條件式儲存（LR/SC）將操作分為一個建立保留的載入，以及一個在保留遺失時會失敗的儲存。RISC-V 也提供 amoadd 與 amoswap 等原子記憶體操作（AMO）指令，而 x86 則在 cmpxchg 與 xadd 等指令上加上 LOCK 前綴。

硬體如何維持原子性

早期系統在操作期間鎖住共享匯流排。現代核心則改用快取一致性協定：核心取得該快取線的獨占所有權，即 MESI 式協定中的 Modified 或 Exclusive 狀態，並延後其他核心對該快取線的要求，直到讀取－修改－寫入完成為止。因此原子操作比一般的快取載入慢得多，而在競爭激烈時，該快取線會在核心之間來回傳遞。原子操作也與記憶體排序有關；在 x86 上，加上 LOCK 的指令會作為完整的記憶體屏障。

從原子操作到鎖

自旋鎖嘗試以原子指令設定鎖變數，若鎖已被占用，就在迴圈中重試。直接重試原子寫入會造成大量一致性流量，因為每次嘗試都要求獨占所有權。test-and-test-and-set 模式則是以一般讀取在本地快取中的共享副本上自旋，只有在鎖看起來空閒時才嘗試原子操作。無鎖結構直接使用 CAS 或 LR/SC，但以 CAS 為基礎的設計必須防範 ABA 問題，即某個值改變後又改回原值而未被察覺。

  2. B用來計算原子數量的、物理計算用的指令
  3. C一定能在1個時脈內完成的、最快的指令

正確答案：A. 將記憶體的讀取與寫入，作為不會被其他核心中途插入的單一操作來執行的指令

原子指令會以不讓其他核心的讀寫插入其間的方式，執行讀取、運算、寫入這一連串的處理。從其他核心看來，只能看到操作之前或之後的狀態。有CAS（比較並交換）、取得並相加（fetch-and-add），以及RISC-V的LR/SC與AMO指令等，是建構鎖與無鎖資料結構的基礎。

關於原子指令CAS（比較並交換，compare-and-swap）的動作，下列何者正確？

  1. A只有在記憶體的值等於預期值時才寫入新值，並可得知是否成功
  2. B比較兩個記憶體的值，把較大的值寫入兩者
  3. C無條件地交換記憶體的值與暫存器的值
查看答案與解析

正確答案：A. 只有在記憶體的值等於預期值時才寫入新值，並可得知是否成功

CAS不可分割地執行「若此位址的值仍是預期值，就改為新值」。若在讀取到寫入之間，其他執行緒已改變了值，就會失敗，所以能在確認未被更動的情況下進行更新。失敗時只要重新讀取、計算並重做CAS，形成迴圈，就能在不使用鎖的情況下安全地更新共用的值。x86的cmpxchg指令等便屬於此類。

常見問題

原子指令和鎖有什麼不同？

原子指令由硬體使對單一記憶體位置的一次讀取－修改－寫入不可分割；鎖則是以原子操作建構的軟體機制，用來保護存取許多位置的較長程式碼區段。

什麼是比較並交換（compare-and-swap）？

比較並交換只有在記憶體位置仍含有預期值時才寫入新值，並回報成功或失敗，這一切都作為單一原子操作完成。

為什麼原子操作很慢？

核心必須取得快取線的獨占所有權，且常需強制記憶體排序；當多個核心爭用同一條快取線時，它會在核心之間反覆傳遞與失效。
