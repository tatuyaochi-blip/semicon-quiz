什麼是資料競爭（Data race）

多個執行緒未經同步就同時存取同一變數，且至少有一個是寫入的狀態。結果每次執行都可能不同。在 C 語言與 C++ 中屬於未定義行為。

日文名稱: データ競合

這個名詞所屬的領域: 多核心與同步

更新遺失是怎麼發生的

counter++ 這個敘述看似不可分割，實際上會編譯成三個步驟：載入值、加 1、存回去。假設兩個執行緒各自將共享計數器遞增 100,000 次。若執行緒 A 載入 100，而執行緒 B 在 A 存回之前也載入了 100，兩者都會存入 101，其中一次遞增就消失了。依執行緒交錯的方式不同，最終值可能是低於 200,000 的任何數字，而且每次執行都不一樣。程式不會當掉，因此這種錯誤很容易被忽略，而且在以除錯器或日誌讓程式變慢時還可能消失。

資料競爭與競爭條件

資料競爭有精確的定義：兩個執行緒同時存取同一個記憶體位置，其中至少一個是寫入，且沒有任何同步機制規範它們的順序。競爭條件的範圍更廣：凡是結果取決於時序的錯誤都算。兩者有重疊但不相同。由各自皆為原子操作所組成的「先檢查再行動」序列沒有資料競爭，卻仍可能是競爭條件，因為其他執行緒可能在檢查與行動之間插入動作。各語言對資料競爭的處理不同：在 C 與 C++ 中，含有資料競爭的程式屬於未定義行為；而 Java 則為有競爭的程式提供有定義但較弱的語意。

解決方法：鎖與原子操作

解決之道是為相衝突的存取強加順序。鎖（mutex）將更新變成一次只有一個執行緒能執行的臨界區段；讓臨界區段保持簡短可減少等待。對於簡單的操作，原子指令更快：fetch-and-add（例如 x86 的 lock xadd 或 RISC-V 的 amoadd.w）以不可分割的方式完成讀取、相加與寫入並回傳舊值，因此永遠不需要重試。較複雜的更新則使用 compare-and-swap 迴圈。在 C 或 C++ 中將變數宣告為 volatile 並不能防止資料競爭，因為它既不提供原子性，也不提供執行緒之間的順序保證。

為何編譯器與硬體會讓競爭更糟

由於 C 與 C++ 假設程式沒有競爭，編譯器可以合法地將共享變數保留在暫存器中、把載入移出迴圈，或合併多次儲存，因此一個執行緒若在未同步的情況下反覆檢查另一個執行緒寫入的旗標，可能永遠看不到變化。硬體也會透過儲存緩衝區與快取產生自己的重新排序。同步操作，例如取得鎖以及具備適當記憶體順序的原子操作，正是告訴編譯器與硬體哪裡必須維持順序的手段。ThreadSanitizer 等動態競爭偵測工具，有助於找出單靠測試很少會暴露的競爭。

練習資料競爭（Data race）的題目

關於資料競爭（data race），下列說明何者正確？

  1. A多個執行緒只是同時讀取同一個變數的狀態
  2. B一個執行緒對同一個變數連續寫入兩次的狀態
  3. C多個執行緒未經同步就同時存取同一個變數，且至少有一個是寫入的狀態
查看答案與解析

正確答案：C. 多個執行緒未經同步就同時存取同一個變數，且至少有一個是寫入的狀態

資料競爭是指，由於對同一位置的讀寫順序沒有經由同步來決定，使結果隨著執行順序而改變的狀態。因為會依時機點時而發生、時而不發生，所以是在測試中難以發現的缺陷。在C語言與C++中，含有資料競爭的程式其行為被視為未定義。必須以鎖或原子變數來決定順序。

常見問題

資料競爭和競爭條件有什麼差別？

資料競爭是對同一記憶體位置的同時且未同步的存取，且至少有一個是寫入。競爭條件則是任何與時序相關的錯誤，即使每一次存取都經過適當同步，它仍可能存在。

單核心 CPU 上也會發生資料競爭嗎？

會。若作業系統在某執行緒的載入與儲存之間將它搶佔，另一個執行緒就可能執行並更新同一個變數，因此即使沒有真正的平行執行，遞增仍可能遺失。

C/C++ 的 volatile 關鍵字能防止資料競爭嗎？

不能。volatile 只強制編譯器確實執行每一次存取，並不會讓「讀取－修改－寫入」序列變成原子操作，也不會規範執行緒之間的順序。應改用原子操作或鎖。
