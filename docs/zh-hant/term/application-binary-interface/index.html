什麼是ABI(應用程式二進位介面)

讓已編譯的程式與函式庫能一起運作的機器碼層級約定。包含呼叫慣例、資料型別的大小與對齊、系統呼叫的呼叫方式等。

日文名稱: ABI(アプリケーションバイナリインターフェース)

「ABI(應用程式二進位介面)」出現在2領域的3道練習題中（指令集與組合語言, 連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 指令集與組合語言

ABI 規定了哪些事

應用程式二進位介面（ABI）規定兩段已編譯的程式碼要在不重新建置的情況下互相呼叫時，必須達成一致的所有事項。這包括呼叫慣例（哪些暫存器傳遞參數與回傳值、哪些暫存器須由被呼叫端保存、堆疊如何對齊與配置）、int、long 與指標等基本型別的大小與對齊、結構體的配置與填補（padding）、C++ 名稱如何修飾（mangling）、例外如何展開（unwind）、目的檔格式，以及向作業系統發出系統呼叫時使用的指令序列。

API 與 ABI

應用程式介面（API）是原始碼層級的契約：程式設計者所看到的函式名稱、參數型別與行為。ABI 則是同一份契約在編譯後的形式。函式庫可能維持 API 不變卻破壞 ABI，例如在公開結構體中新增欄位，就會改變結構體大小以及後續欄位的偏移量。這時程式仍能以新標頭檔順利編譯，但依舊版建置的二進位檔除非重新編譯，否則會錯誤解讀記憶體內容。共享函式庫的版本號碼很大程度上就是為了標示這類 ABI 破壞而存在。

一個 ISA，多種 ABI

指令集架構（ISA）定義處理器執行什麼；ABI 則是疊加在其上的軟體慣例，因此一個 ISA 可以有多種 ABI。在 x86-64 上，Linux 使用的 System V ABI 以 RDI、RSI、RDX、RCX、R8、R9 傳遞前 6 個整數參數，並使 long 為 64 位元；而 Windows x64 ABI 使用 RCX、RDX、R8、R9，且 long 維持 32 位元。RISC-V 定義了 ilp32、lp64、lp64d 等 ABI，其中 lp64d 以浮點暫存器傳遞浮點參數。

讓函式庫的 ABI 保持精簡

共享函式庫匯出的每個符號都會成為其 ABI 的一部分，必須保持相容。匯出的函式也可能被其他模組中的同名符號覆蓋，因此即使是函式庫內部的呼叫也必須經過程序連結表（PLT）或全域偏移表（GOT）。將內部函式標記為 hidden 可見性，就能把它們從公開介面中移除：動態連結器需要解析的符號變少、內部呼叫變成直接的 PC 相對呼叫、避免與其他函式庫發生名稱衝突，函式庫日後也能自由修改這些函式。

ABI是讓編譯完成的程式或函式庫能一起運作的機器語言層級的約定，包含呼叫慣例、int、long與指標的大小、結構體的對齊、系統呼叫的呼叫方式等。API是在原始碼層級規定函式使用方式的東西，即使API相同，只要ABI不同，函式庫不重新製作就無法使用。即使是相同的RISC-V ISA，依作業系統或用途不同，ABI也可能不同。

常見問題

API 和 ABI 有什麼不同？

API 是程式設計者撰寫程式時依循的原始碼介面，ABI 則是已編譯程式碼所依賴的二進位層級約定，涵蓋暫存器、資料配置與呼叫序列。若保留 API 但改變 ABI，相依的程式就必須重新編譯。

為什麼函式庫更新會讓沒改過的程式壞掉？

若更新改變了 ABI，例如結構體大小或函式參數型別，既有的二進位檔仍使用舊的配置，以錯誤的形式傳遞資料。原始碼也許不經修改就能編譯，但已建置的程式在重新建置前都會出錯。

呼叫慣例是 ABI 的一部分嗎？

是的。呼叫慣例規定參數與回傳值放在哪裡，以及雙方各自必須保存哪些暫存器，是 ABI 最核心的部分之一。
