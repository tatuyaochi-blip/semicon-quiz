什麼是連結器（Linker）

將多個目的檔與函式庫結合，進行符號解析與重定位，產生可執行檔或共享函式庫的軟體。

日文名稱: リンカ

「連結器（Linker）」出現在3領域的19道練習題中（連結器與載入器與執行檔格式, 指令集與組合語言, 編譯器等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

連結器在建置流程中的位置

建置 C 程式通常會依序執行編譯器（產生組合語言或目的碼）、組譯器（產生機器碼目的檔），最後是連結器。每個目的檔都是單獨編譯的，因此其中包含機器碼與資料、記錄所定義與參照名稱的符號表，以及標示所有位址尚未確定之處的重定位項目，例如對另一個檔案中 printf 的呼叫。連結器將許多這樣的目的檔與函式庫結合成作業系統可以載入的單一可執行檔或共享函式庫。

符號解析、配置與重定位

連結器的核心工作分為三部分。符號解析將每個被參照的名稱綁定到唯一的定義，否則就回報未定義參照或重複定義錯誤。配置將所有輸入中的同類區段合併，例如程式碼的 .text、常數的 .rodata、已初始化變數的 .data 以及零初始化變數的 .bss，並指定其最終位址，這通常由連結器指令檔控制。接著重定位會逐一處理每個重定位項目，將正確的絕對位址或 PC 相對距離寫入指令或資料字組中。

靜態連結與動態連結

靜態函式庫（Linux 上的 .a）是目的檔的封存檔，連結器只會複製用來解析仍未定義之參照所需的成員，並由左至右掃描輸入；這就是函式庫要列在使用它的檔案之後的原因。靜態連結會產生自給自足的可執行檔，但每個程式都會重複包含函式庫程式碼，且函式庫修正後需要重新連結。使用共享函式庫（.so）時，連結器只記錄相依關係，由動態連結器在載入或執行時透過 PLT 跳板（stub）與 GOT 綁定函式庫函式。

main 之前執行了什麼

連結器還會加入 C 執行環境的啟動目的檔，例如 crt1.o，並將其 _start 符號設為進入點。_start 會設定參數、初始化函式庫與全域物件，接著呼叫 main，並將其回傳值傳給 exit。C++ 的全域建構子會被收集到 .init_array 表中，由啟動程式碼在 main 之前呼叫。C++ 編譯器會修飾名稱以編碼參數型別，讓多載函式擁有不同的符號，而 extern "C" 則對與 C 程式碼共用的函式停用名稱修飾。

  1. A結合多個目的檔與函式庫，將名稱對應到位址，產生執行檔
  2. B找出原始碼的語法錯誤並通知
  3. C執行中的程式使用完畢後，自動釋放其記憶體
查看答案與解析

正確答案：A. 結合多個目的檔與函式庫，將名稱對應到位址，產生執行檔

連結器會將各目的檔中所參照的名稱（符號），對應到其他地方所定義的實體（符號解析），並排列各檔案的程式碼與資料以決定最終位址，再將指令中的暫時位址改寫為正確的值（重定位）。必要時還會從函式庫中取出函式加入。如此就能產生可由作業系統載入並執行的執行檔。

關於連結器所進行的符號解析，下列說明何者正確？

  1. A將某檔案中使用的函式或變數名稱，對應到另一個檔案中的該定義
  2. B將原始碼的變數名稱換成較短的名稱，使其難以閱讀
  3. C將含有數學符號的算式重新計算成數值
查看答案與解析

正確答案：A. 將某檔案中使用的函式或變數名稱，對應到另一個檔案中的該定義

若在main.c中呼叫sum函式，並在sum.c中定義其內容，則main.o會記錄「參照sum」，sum.o會記錄「定義sum」。連結器會蒐集所有目的檔的符號表，為每個參照找出一個對應的定義。若找不到定義，就會出現「未定義的參照」錯誤；若有兩個以上，則會出現「重複定義」錯誤。

常見問題

編譯器和連結器有什麼差別？

編譯器將一個原始檔翻譯成位址尚未解析的目的檔，而連結器將多個目的檔與函式庫結合起來，解析彼此之間的名稱並確定最終位址，產生可執行檔。

用 GCC 連結時，為什麼函式庫的順序很重要？

GNU 連結器由左至右掃描輸入，只會為已經未定義的符號從靜態函式庫中取出成員，因此若函式庫列在使用它的目的檔之前，就不會貢獻任何內容。

靜態連結和動態連結有什麼差別？

靜態連結在建置時將所需的函式庫程式碼複製到可執行檔中，而動態連結則留下對共享函式庫的參照，由動態連結器在程式載入或執行時進行綁定。
