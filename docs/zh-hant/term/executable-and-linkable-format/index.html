什麼是ELF（可執行與可連結格式）

Executable and Linkable Format 的縮寫。在 Linux 等 UNIX 系列作業系統與嵌入式裝置中，用於目的檔、可執行檔與共享函式庫的檔案格式。

日文名稱: ELF

「ELF（可執行與可連結格式）」出現在1領域的3道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

ELF 檔案裡有什麼

可執行與可連結格式（ELF）檔案以 ELF 標頭開頭，標頭起始為魔術位元組 0x7F，後面接著字母 E、L、F。標頭記錄檔案是 32 位元還是 64 位元、位元組順序、目標 CPU、檔案類型，以及開始執行的進入點位址。同一種格式涵蓋編譯器產生的可重定位目的檔、可執行檔、共享函式庫與核心傾印（core dump）。標頭之後是程式標頭表、內容本身，以及描述各區段的區段標頭表。

區段與節段

ELF 對同樣的位元組提供兩種視角。連結器處理細粒度的區段（section），例如程式碼的 .text、常數的 .rodata、已初始化變數的 .data，以及零初始化變數的 .bss；.bss 在檔案中不佔空間，載入時才填零。載入器則處理程式標頭中列出的節段（segment），節段依權限將區段分組：.text 與 .rodata 通常放入可讀可執行的節段，.data 與 .bss 則放入可讀寫的節段。依權限分組讓設定分頁層級的記憶體保護變得簡單。

ELF 如何支援連結與載入

目的檔帶有符號表與重定位項目，告訴連結器在合併程式碼與資料時要修補哪些位址。動態連結的可執行檔會在程式標頭中指定一個直譯器，也就是動態載入器，並包含列出所需共享函式庫的動態區段；對這些函式庫的呼叫通常經由程序連結表（PLT）與全域偏移表（GOT），使位址能在執行時解析。除錯資訊儲存在額外的區段中，可由工具移除（strip）。嵌入式工具鏈常輸出 ELF，再轉換成原始二進位檔或 hex 檔以燒錄。

ELF 與 PE、Mach-O 的比較

Linux、BSD 系列與許多嵌入式系統使用 ELF，Windows 的 .exe 與 .dll 檔使用可攜式執行檔（PE）格式，macOS 與 iOS 則使用 Mach-O。程式碼與資料區域、符號、重定位以及動態連結資訊等基本概念相似，但格式不同，程式所預期的系統呼叫介面與函式庫也不同。這就是為什麼即使在同一顆 CPU 上，編譯好的程式也無法不經修改就在不同的作業系統上執行。

ELF（Executable and Linkable Format）是Linux以及許多UNIX系作業系統與嵌入式裝置所使用的程式檔案格式。開頭的ELF標頭記載了目標CPU、是否為64位元、開始執行的位址等，其後接著.text、.data等區段，以及表示載入器要載入記憶體之單位的程式標頭（program header）。Windows使用PE格式，macOS使用Mach-O格式。

關於ELF檔案中的「區段（section）」與「段（segment）」的差異，下列何者正確？

  1. A區段是Windows的稱呼，段是Linux的稱呼，兩者內容相同
  2. B區段是連結器處理的細小單位，段則是載入器載入記憶體的單位，將權限相同的區段彙整在一起
  3. C段只存在於磁碟上，不會載入記憶體
查看答案與解析

正確答案：B. 區段是連結器處理的細小單位，段則是載入器載入記憶體的單位，將權限相同的區段彙整在一起

ELF有兩種觀點。連結器以.text、.rodata、.data、.bss等細小的區段為單位進行結合與重定位。載入器則以程式標頭所記載的段為單位對應到記憶體，例如將.text與.rodata彙整到可讀取與執行的段，將.data與.bss彙整到可讀寫的段。依權限彙整，較容易設定以分頁為單位的保護。

常見問題

ELF 是什麼的縮寫？

ELF 是 Executable and Linkable Format（可執行與可連結格式）的縮寫，是 Linux 及許多其他類 UNIX 系統與嵌入式系統上，目的檔、可執行檔與共享函式庫的標準檔案格式。

ELF 的 section 和 segment 有什麼差別？

section（區段）是 .text、.data 等由連結器合併與重定位的細粒度單位。segment（節段）由程式標頭描述，將權限相同的區段歸為一組，成為載入器映射到記憶體的單位。

ELF 執行檔可以在 Windows 上執行嗎？

無法原生執行。Windows 預期的是 PE 格式與其自身的系統介面，因此 ELF 程式需要相容層、執行 Linux 的虛擬機器，或是針對 Windows 重新編譯。
