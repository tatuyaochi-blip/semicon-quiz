什麼是中斷向量表

依中斷或例外的種類，排列對應的中斷處理常式起始位址的表。CPU由原因的編號查這張表，決定處理的起始位置。

日文名稱: 割り込みベクタテーブル

「中斷向量表」出現在2領域的3道練習題中（作業系統與硬體, C語言基礎等）。

這個名詞所屬的領域: 作業系統與硬體

CPU如何使用這張表

當中斷或例外被接受時，硬體會決定一個用來識別其原因的編號，稱為向量：可能是計時器、特定周邊裝置、分頁錯誤、非法指令或系統呼叫。CPU保存下一道指令的位址以及操作模式等狀態，接著以該向量作為中斷向量表的索引，通常讀取位於「基底 + 向量 × 項目大小」的項目。該項目存放處理常式的起始位址。處理常式會保存它所使用的暫存器，處理該事件，並執行中斷返回指令。

表放在哪裡

細節依架構而異。在Arm Cortex-M微控制器上，表位於程式記憶體的開頭：第一個字組是初始堆疊指標，第二個是重置處理常式位址，之後的字組則指向故障與周邊裝置的處理常式；在大多數核心上，向量表偏移暫存器（VTOR）可讓軟體搬移這張表。在x86真實模式中，表佔用記憶體最前面的1 KB，共有256個4位元組項目；保護模式與長模式則使用由IDTR暫存器定位的中斷描述符表（IDT）。RISC-V使用mtvec暫存器，可將所有陷阱送到同一個處理常式，或將中斷向量化到不同位址。

在嵌入式韌體中的設定

在沒有作業系統的微控制器上，向量表從重置的那一刻起就必須位於硬體預期的位址。啟動程式碼將其定義為放在專屬區段中的函式指標陣列，再由連結器腳本將該區段放到所需的快閃記憶體位址。典型的啟動檔會為每個項目提供弱定義的預設處理常式，通常是無窮迴圈，因此應用程式只需定義名稱相符的函式，即可覆寫自己用到的中斷。也因此，處理常式名稱拼錯時仍能順利編譯，中斷卻會默默地被導向預設的迴圈。

向量表與輪詢的比較

向量式架構會將每種原因直接送到各自的處理常式，因此CPU不需要讀取狀態暫存器來找出發生了什麼事，從而縮短中斷延遲。另一種做法是單一進入點，由其處理常式讀取原因暫存器並以軟體分派，RISC-V的直接模式就是如此。在通用作業系統上，核心會在開機時填寫這張表，讓計時器滴答、裝置中斷、分頁錯誤與系統呼叫都能各自到達正確的核心常式。

練習中斷向量表的題目

  1. A依種類記錄中斷發生的次數
  2. B依中斷或例外的種類，決定開始處理的位址
  3. C記錄接下來要執行哪個行程的順序
查看答案與解析

正確答案：B. 依中斷或例外的種類，決定開始處理的位址

發生中斷或例外時，CPU會取得與該原因對應的編號（向量編號），從中斷向量表讀取處理常式的起始位址，並將處理轉移過去。表中的內容由作業系統在開機時設定，使計時器、各裝置、分頁錯誤、系統呼叫等能分別呼叫不同的處理常式。計算次數是統計用的另一種機制，而要執行的行程順序則由作業系統的排程器管理。

常見問題

什麼是中斷向量？

中斷向量是分配給中斷或例外來源的編號，用作向量表的索引。這個詞也常被寬鬆地用來指表中存放處理常式位址的項目本身。

ARM Cortex-M微控制器的向量表在哪裡？

預設位於開機記憶體（通常是快閃記憶體）的開頭。第一個項目是初始堆疊指標值，第二個是重置處理常式；在大多數核心上，可透過向量表偏移暫存器（VTOR）將其搬移，例如搬到RAM。

x86的IVT和IDT有什麼差別？

中斷向量表（IVT）是真實模式下、位於記憶體最底部的256個「區段:偏移」位址的表。中斷描述符表（IDT）在保護模式與長模式中取代了它，存放含有權限資訊的描述符，並可透過IDTR暫存器放在任意位置。
