什麼是動態記憶體配置

在程式執行期間配置所需大小的記憶體，用完後再釋放。C語言以 malloc(大小) 配置並取得開頭位址，以 free(位址) 釋放。calloc 回傳以0初始化的區域，realloc 回傳改變大小後的區域。配置失敗時會回傳 NULL，因此必須確認。區域位於堆積中，在釋放之前即使函式返回也會保留。小型微控制器上由於有碎片化問題，且配置所需時間難以預測，常會避免使用。

練習動態記憶體配置的題目

C語言中，(1) 在函式中沒有加 static 宣告的區域變數、(2) 以 malloc 配置的區域、(3) 在函式外宣告的變數，各自存在的期間（生命週期）的組合，下列何者正確？

  1. A(1) 到程式結束為止、(2) 到配置它的函式返回為止、(3) 到程式結束為止
  2. B(1) 到離開宣告它的區塊為止、(2) 到以 free 釋放為止、(3) 到程式結束為止
  3. C(1) 到離開宣告它的區塊為止、(2) 到程式結束為止（中途無法釋放）、(3) 到最先使用該變數的函式返回為止
查看答案與解析

正確答案：B. (1) 到離開宣告它的區塊為止、(2) 到以 free 釋放為止、(3) 到程式結束為止

(1) 的自動變數一般放在堆疊上，進入宣告它的區塊時建立，離開時消失。(2) 以 malloc 配置的區域位於堆積，函式返回後仍保留，在以 free 釋放之前都能使用。(3) 函式外的變數（以及加上 static 的變數）在程式執行期間一直存在，放在 .data 或 .bss 這類靜態區域。使用指向生命週期已結束之區域的指標，或忘了 free 而讓區域一直殘留，是常見錯誤的原因。

在小型微控制器的韌體中，經常避免使用malloc等動態記憶體配置，其理由下列何者正確？

  1. A因為微控制器完全無法使用C語言的函式
  2. B因為RAM很小，可能因碎片化而配置失敗，且配置所需的時間難以預測
  3. C因為動態配置的記憶體即使關閉電源也不會消失
查看答案與解析

正確答案：B. 因為RAM很小，可能因碎片化而配置失敗，且配置所需的時間難以預測

在只有數KB～數百KB RAM的微控制器上反覆配置與釋放，空閒空間會被切得細碎，即使總量足夠，也可能在配置較大區塊時失敗。對於持續運作數個月的裝置，總有一天會有失敗的風險。此外，配置所需的時間不固定，不適合即時處理。因此常採用事先靜態配置所需記憶體的設計。
