什麼是OCV(晶片內變異)

即使在同一晶片中，電晶體與導線的延遲也會因位置而有所差異。STA 中對發送端與接收端路徑分別乘上不同係數(例如 1.1 倍與 0.9 倍)，假設最不利的組合進行分析。

日文名稱: OCV(オンチップばらつき)

「OCV(晶片內變異)」出現在2領域的3道練習題中（時序分析與CDC, LSI設計流程與EDA等）。

這個名詞所屬的領域: 時序分析與CDC

晶片內變異的來源

即使在同一個晶粒內，電晶體與導線也不會完全一致。隨機摻雜擾動、線邊緣粗糙度與局部微影效應會使臨界電壓與通道長度偏移；導線寬度與厚度隨局部圖案密度而變化；IR 壓降與熱點則使局部電源電壓與溫度有所不同。全域的 PVT 角落（製程、電壓、溫度）涵蓋晶片之間的偏移，但同一晶片上的兩條路徑仍可能不同，而 setup 與 hold 檢查比較的正是這樣的路徑對。

對發送與擷取路徑進行降額

在 flat OCV 中，STA 會將延遲乘上針對每項檢查悲觀選定的降額係數。對 setup 而言，發送時脈與資料路徑設為慢（例如 ×1.1），擷取時脈路徑設為快（×0.9）。若發送時脈 1.0 ns、資料路徑 1.5 ns、擷取時脈 1.0 ns、週期 3.0 ns、setup 時間 0.1 ns，則到達時間為 2.75 ns、要求時間為 3.8 ns，slack 為 1.05 ns，而不降額時為 1.40 ns。對 hold 則將係數對調。

CRPR：去除不可能的悲觀性

當發送與擷取時脈從時脈根部到分支點共用一段路徑時，flat 降額會在同一次檢查中將同一串緩衝器同時視為慢與快，這對單一時脈邊緣而言是不可能發生的。共同路徑悲觀性去除（CRPR，也稱 CPPR）會將這個差值加回 slack。對於係數為 1.1 與 0.9、長 1.0 ns 的共同區段，可找回 0.2 ns。它並不是將共同延遲設為零，而只是去除重複計算的部分。

AOCV 與 POCV

flat 降額很粗略。隨機變異在深的路徑上會部分平均掉，而相距較遠的單元則會有較大的系統性差異。Advanced OCV（AOCV）使用以邏輯深度與距離為索引的表格，使長路徑得到較小的降額。Parametric 或 statistical OCV（POCV、SOCV）則為每個單元賦予延遲的平均值與標準差，並沿路徑以統計方式合併。兩者都能找回 flat OCV 所浪費的邊限，同時仍以選定的信賴水準涵蓋變異。

練習OCV(晶片內變異)的題目

作為OCV降額（derating），在建立時間分析中將發送端時脈路徑與資料路徑的延遲乘以1.1倍，接收端時脈路徑的延遲乘以0.9倍。當發送端時脈路徑為 1.0 ns、資料路徑（含時脈→輸出）為 1.5 ns、接收端時脈路徑為 1.0 ns（無共同部分）、週期為 3.0 ns、建立時間為 0.1 ns 時，建立時間的餘裕是多少？

  1. A1.05 ns
  2. B1.40 ns
  3. C1.25 ns
查看答案與解析

正確答案：A. 1.05 ns

OCV降額是考量即使在同一晶片內，延遲也會因位置而變異，並對建立時間假設最不利之組合（發送端較慢、接收端的時脈較快）的方法。到達時間為 1.1 × (1.0 + 1.5) = 2.75 ns，要求時間為 3.0 + 0.9 × 1.0 − 0.1 = 3.8 ns，因此餘裕為 1.05 ns。1.40 ns 是未降額的值，1.25 ns 是只對資料路徑乘上係數的值。在保持時間分析中，係數的乘法方式相反。

在使用OCV降額的STA中，當發送端與接收端的時脈路徑在中途之前為共同路徑時，所進行的CRPR（共同路徑悲觀消除）的說明何者正確？

  1. A將共同部分的延遲視為0，重新計算時脈的到達時間
  2. B去除因對共同部分分別套用慢速值與快速值所造成的、不可能發生的多餘悲觀
  3. C對共同部分乘上更大的降額係數，使其偏向安全側
查看答案與解析

正確答案：B. 去除因對共同部分分別套用慢速值與快速值所造成的、不可能發生的多餘悲觀

在OCV中，發送端的時脈路徑估得較慢、接收端估得較快，但從根部到分歧點的共同部分在物理上是相同的緩衝器與繞線，在一次邊緣中不可能既慢又快。若共同部分的延遲為 1.0 ns、係數為1.1與0.9，則 1.1 ns 與 0.9 ns 之差的 0.2 ns 就是多餘的悲觀。CRPR將這個差值加回餘裕，使結果更接近實際。這並不是把共同部分的延遲當作0，而加大係數則是相反的操作。

常見問題

OCV 和 PVT 角落有什麼不同？

PVT 角落模擬整顆晶片一起偏移到慢速或快速的狀態。OCV 則模擬在給定角落下同一晶片上路徑之間的差異，因此是疊加在角落分析之上套用的。

靜態時序分析中的 CRPR 是什麼？

共同路徑悲觀性去除會將 OCV 降額把發送與擷取時脈路徑的共用部分同時視為慢與快時所損失的 slack 加回來。

為什麼 setup 和 hold 套用 OCV 降額的方式不同？

每項檢查都假設各自的最壞情況：setup 受發送晚、擷取早的影響，hold 則受發送早、擷取晚的影響，因此慢與快的係數要對調。
