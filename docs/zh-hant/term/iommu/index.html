什麼是IOMMU(輸入輸出記憶體管理單元)

將周邊裝置以DMA使用的位址轉換為實體位址並加以保護的裝置。可防止裝置寫入不被允許的記憶體，在將裝置分配給虛擬機器時也會使用。

日文名稱: IOMMU

「IOMMU(輸入輸出記憶體管理單元)」出現在3領域的3道練習題中（作業系統與硬體, 硬體安全, 硬體安全的進階主題與趨勢等）。

這個名詞所屬的領域: 作業系統與硬體

IOMMU 如何轉換 DMA 位址

有了 IOMMU（輸入輸出記憶體管理單元），裝置就不再發出原始的實體位址。它的 DMA 請求帶有 I/O 虛擬位址，由 IOMMU 在作業系統為該裝置或裝置群組所建立的分頁表中查詢；在 PCIe 上，裝置以請求者的匯流排、裝置與功能編號識別。最近的轉換會快取在 IOTLB（I/O 轉譯後備緩衝區）中。對沒有有效對映的位址、或讀寫權限不符的存取，會被阻擋並以錯誤（fault）回報給作業系統，而不會到達記憶體。

IOMMU 與 MMU 的比較

兩者都透過分頁表轉換位址，但服務的對象不同。CPU 的 MMU 為每個行程轉換虛擬位址，使程式彼此隔離。IOMMU 則為每個裝置轉換位址，把 DMA 引擎限制在其驅動程式所對映的緩衝區內。由於對映彼此獨立，作業系統可以交給裝置一個分散在許多實體分頁上、但在裝置的位址空間中看起來連續的緩衝區，這讓本身無法進行分散－集中（scatter-gather）傳輸的裝置得以簡化。

阻擋 DMA 攻擊

DMA 繞過 CPU 及其記憶體保護，因此在沒有 IOMMU 的情況下，任何能主控匯流排的裝置都能讀取金鑰或竄改核心程式碼。對於向插入的硬體開放 PCIe 式 DMA 的外部連接埠而言，這是實際存在的風險。啟用 IOMMU 後，作業系統只對映各驅動程式所使用的特定緩衝區，通常只在每次傳輸期間有效，其他所有區域都無法從該裝置存取。許多平台也用 IOMMU 重新對映裝置中斷，使裝置無法偽造任意的中斷訊息。

將裝置指派給虛擬機器

客體作業系統以它認為是實體位址的位址來設定裝置，但那其實是客體實體位址。當 Hypervisor 將 GPU 或網路卡等實體裝置直接穿透（passthrough）給虛擬機器時，它會設定 IOMMU，把這些客體實體位址轉換成支撐該 VM 的主機實體分頁。如此一來，裝置就能全速使用 DMA，而 Hypervisor 不必攔截每一次傳輸，同時裝置仍無法觸及其他 VM 的記憶體。代價是一些轉換開銷，主要是 IOTLB 未命中，以及對映與解除對映緩衝區的成本。

練習IOMMU(輸入輸出記憶體管理單元)的題目

關於IOMMU的主要作用，下列何者正確？

  1. A將CPU的指令翻譯成輸入輸出裝置的指令後執行
  2. B在輸入輸出裝置閒置時自動切斷電源，以降低耗電量
  3. C轉換裝置DMA的位址，防止非法存取
查看答案與解析

正確答案：C. 轉換裝置DMA的位址，防止非法存取

使用DMA的裝置可以直接讀寫主記憶體，因此誤動作或惡意的裝置有可能改寫作業系統的記憶體。IOMMU就像CPU的MMU一樣，將裝置所使用的位址轉換成實體位址，並阻擋對允許範圍以外的存取。它也能讓不連續的實體記憶體對裝置而言看起來是連續的，並在將裝置直接分配給虛擬機器時使用。它不是負責翻譯指令或控制電源的裝置。

常見問題

GPU 直通（passthrough）需要 IOMMU 嗎？

需要。把實體裝置交給虛擬機器，要靠 IOMMU 轉換客體的 DMA 位址，並防止裝置存取該 VM 以外的記憶體，因此必須在韌體與作業系統中支援並啟用 IOMMU。

啟用 IOMMU 會讓 I/O 變慢嗎？

轉換未命中以及建立和移除對映會增加一些成本，對極高速率的裝置可能有影響。在大多數工作負載中，IOTLB 快取與較長期的對映能讓開銷維持在適度範圍。

IOMMU 和 MMU 有什麼差別？

MMU 轉換 CPU 代表行程發出的位址，IOMMU 則轉換進行 DMA 的裝置所發出的位址。兩者都使用分頁表與權限位元，但 IOMMU 的表格是以裝置或裝置群組為單位。
