什麼是符號解析（Symbol resolution）

連結器將某個檔案中所參照的函式或變數名稱，對應到存在於他處的定義的處理。若沒有定義會發生未定義參照錯誤，若有兩個以上則會發生重複定義錯誤。

符號解析做什麼

每個目的檔都帶有一份符號表，列出它所定義的名稱（例如函式與全域變數），以及它參照但未定義的名稱。若 main.c 呼叫 sum 而 sum.c 定義了它，main.o 會記錄對 sum 的未定義參照，sum.o 則記錄其定義。符號解析是連結器收集所有符號表、並將每個參照綁定到唯一定義的步驟。它在重定位之前進行，隨後重定位會把這些定義的最終位址寫入參照它們的指令與資料中。

未定義與重複定義

若某個參照找不到任何定義，連結器會回報未定義參照，通常是因為某個原始檔或函式庫沒有被連結，或是名稱拼錯。若兩個非 static 的全域定義使用相同名稱，則回報重複定義錯誤，因為連結器無法決定參照應綁定到哪一個。將函式宣告為 static 會賦予它內部連結（internal linkage），對其他檔案隱藏，因此同一名稱可以重複使用。像 extern int count; 這樣的宣告不會配置儲存空間，只是保證定義存在於別處。

弱符號與函式庫順序

弱符號（weak symbol）是一種備用定義，只有在不存在同名的一般（強）定義時才會被採用，嵌入式程式碼常以此模式提供預設的中斷處理常式。靜態函式庫是目的檔的封存檔，GNU 連結器由左至右處理輸入，只有當函式庫成員定義了當下仍未定義的符號時才會取出該成員。因此 gcc -lmylib main.o 這樣的命令會失敗，因為掃描函式庫時 main.o 中還沒有任何未解析的符號。函式庫應放在使用它的檔案之後。

C++ 名稱與動態連結

連結器純粹以名稱字串比對符號。C++ 允許 print(int) 與 print(double) 這類多載函式，因此編譯器會將參數型別與命名空間編碼進符號名稱中，稱為名稱修飾（name mangling）。C 不做名稱修飾，所以 C++ 程式碼要以 extern "C" 宣告 C 函式，使名稱一致。使用共享函式庫時，部分符號解析會延後進行：動態連結器在載入時或第一次呼叫時，通常透過 PLT 跳板與 GOT 項目，將參照綁定到函式庫函式。

  2. B將原始碼的變數名稱換成較短的名稱，使其難以閱讀
  3. C將含有數學符號的算式重新計算成數值

正確答案：A. 將某檔案中使用的函式或變數名稱，對應到另一個檔案中的該定義

若在main.c中呼叫sum函式，並在sum.c中定義其內容，則main.o會記錄「參照sum」，sum.o會記錄「定義sum」。連結器會蒐集所有目的檔的符號表，為每個參照找出一個對應的定義。若找不到定義，就會出現「未定義的參照」錯誤；若有兩個以上，則會出現「重複定義」錯誤。

常見問題

undefined reference 錯誤是什麼原因造成的？

連結器找到了對某個函式或變數的參照，但在所有被連結的目的檔或函式庫中都找不到定義。常見原因是連結命令中缺少某個檔案或函式庫、順序擺錯，或是名稱不一致。

符號解析和重定位有什麼不同？

符號解析決定每個被參照的名稱指向哪一個定義。接著重定位將這些定義的實際位址修補進使用它們的機器碼與資料中。

multiple definition 錯誤要怎麼解決？

確保每個非 static 的全域函式或變數只在一個原始檔中定義，在標頭檔中使用 extern 宣告，並將只在檔案內使用的項目標為 static，以免名稱衝突。

解析中的「符號解析（Symbol resolution）」

  • 連結器會將各目的檔中所參照的名稱（符號），對應到其他地方所定義的實體（符號解析），並排列各檔案的程式碼與資料以決定最終位址，再將指令中的暫時位址改寫為正確的值（重定位）。
