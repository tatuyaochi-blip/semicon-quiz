什麼是框指標

持續指向進入函式時堆疊位置而不移動的暫存器。在RISC-V中是s0(fp)。可用固定距離指定區域變數，也容易追蹤呼叫的串連。

日文名稱: フレームポインタ

「框指標」出現在1領域的1道練習題中（指令集與組合語言等）。

這個名詞所屬的領域: 指令集與組合語言

框指標的作用

呼叫函式時，會在堆疊上配置放置返回位址、保存的暫存器與區域變數的區域（堆疊框）。堆疊指標（sp）在函式中可能因為配置可變長度陣列或推入引數而移動，但框指標（fp）會一直指向進入函式時決定的位置，直到函式返回都不移動。因此區域變數與引數可以用「距fp多少位元組」的固定距離來指定。RISC-V以s0（x8）兼作fp，x86-64使用rbp、AArch64使用x29作為框指標。

序言與尾聲

函式開頭的部分（序言，prologue）會降低sp以配置堆疊框，把返回位址與呼叫端的fp保存到框中，再為fp設定新的值。在典型的64位元RISC-V例子中，會從sp配置16位元組，保存ra與s0之後，把進入函式時的sp值放入s0。函式結尾的部分（尾聲，epilogue）則相反，讀回保存的ra與s0，還原sp之後返回呼叫端。在x86-64中，則以先把rbp推入堆疊、再把rsp的值複製到rbp的2個指令完成同樣的事。

追蹤呼叫的串連

若在每個堆疊框中保存呼叫端的fp與返回位址，各框就會像鏈結串列一樣串連起來。從目前的fp依序追蹤保存的fp，即使沒有除錯資訊，也能快速得知哪個函式呼叫了哪個函式（回溯，backtrace）。除錯器顯示堆疊、當機時的紀錄，以及以固定間隔暫停執行中的程式並記錄呼叫來源的效能分析工具（profiler），都會使用這種方法。由於追蹤的處理簡單又快速，在核心內部或在正式環境中持續執行的效能分析工具裡也容易使用，這是其優點。

省略框指標

框指標會占用一個暫存器，序言與尾聲的指令也會增加，因此最佳化時常被省略。GCC與Clang在許多目標平台上，啟用最佳化後預設為-fomit-frame-pointer，區域變數改以距sp的距離來指定。即使省略，也能利用編譯器輸出的DWARF呼叫框資訊（CFI）求得回溯，但處理較耗時。近年來，為了方便效能分析，也開始有Linux發行版保留框指標來建置套件。

練習框指標的題目

下列何者是在函式中使用框指標（frame pointer，RISC-V中為s0/fp）的優點？

  1. A不必多用一個暫存器，所以效能必定提升
  2. B即使函式途中sp有移動，也能以固定的距離指定區域變數或引數，除錯器也更容易追蹤呼叫的串連
  3. C堆疊的區域會自動變大，不會溢位
查看答案與解析

正確答案：B. 即使函式途中sp有移動，也能以固定的距離指定區域變數或引數，除錯器也更容易追蹤呼叫的串連

框指標是在進入函式的時間點，一直指向堆疊位置而不移動的暫存器。即使因為可變長度陣列等而使sp在途中改變，也能以「距fp多少位元組」來指定區域變數。此外，若在各個框中保存前一個fp，藉由追蹤就能得到呼叫的串連（回溯，backtrace）。不過因為會佔用一個暫存器，在最佳化時也常被省略。

常見問題

框指標和堆疊指標有什麼不同？

堆疊指標指向堆疊目前的頂端，每次存取值或配置堆疊框時都會移動。框指標則一直指向進入函式時的位置而不移動，因此能以固定距離指定區域變數，也是追蹤呼叫串連的起點。

框指標是必要的嗎？

並非必要。區域變數也可以用距sp的距離指定，所以最佳化時常被省略。不過，在因可變長度陣列等而使sp中途改變的函式中會使用框指標，想輕鬆取得回溯時保留框指標也很方便。

RISC-V的框指標是哪個暫存器？

是x8。由被呼叫端保存的暫存器s0兼作框指標，也可以用別名fp來寫。在不使用框指標的函式中，s0當作一般的保存暫存器使用。
