什麼是快取行

快取與下層之間讀寫資料的單位。也稱為快取區塊。多數CPU為64位元組，位址的低位元表示行內的位置(位移)。

日文名稱: キャッシュライン

「快取行」出現在3領域的26道練習題中（記憶體階層與效能, DRAM, 資料結構與演算法等）。

這個名詞所屬的領域: 記憶體階層與效能

為什麼快取以整行為單位搬移

程式存取某個位址後，通常很快也會存取其鄰近位址，這種特性稱為空間局部性。快取利用這一點，以固定大小的區塊（通常為 64 位元組）而非單一字組來搬移資料，而這個大小恰好符合一次 DRAM 突發傳輸：在 64 位元的 DDR4 通道上進行八次、每次 8 位元組的傳輸。每個快取行都帶有識別其位址的標籤、表示資料有效的有效位元、寫回式快取中的髒位元，以及替換與一致性狀態。因此位址會被拆成標籤、索引與位移欄位；以 64 位元組的快取行來說，最低 6 位元就是位移。

快取行大小與存取模式

快取行大小會把存取模式轉化為失誤率。依序讀取 4 位元組整數的陣列時，每 16 個元素才失誤一次，失誤率為 6.25%，因為每次失誤都會一併載入接下來的 15 個元素。若每隔 16 個元素才讀取一個，則每次都會失誤。C 語言以列優先順序儲存二維陣列，因此在內層迴圈走訪行索引會存取連續位址；若把兩層迴圈對調，每次存取都會跳過一整列，快取行可能在被重複使用前就遭到逐出。較大的快取行有利於循序存取的程式碼，但若每行只用到一小部分，就會浪費頻寬與容量。

一致性以快取行為單位運作

在多核心處理器中，一致性協定以快取行為粒度追蹤擁有權。在 MESI 協定下，每個快取行處於以下其中一種狀態：Modified（已修改且只存在此處，因此記憶體中的資料已過時）、Exclusive（未修改且只存在此處）、Shared（其他地方可能存在未修改的副本）或 Invalid。核心要寫入前，必須先讓其他快取中的副本失效；已處於 M 狀態的快取行則可重複寫入而不必通知任何人。小型系統以廣播方式發送這些請求，大型系統則使用目錄記錄哪些快取持有各個快取行，讓流量能隨核心數擴展。

偽共享

由於一致性以快取行為單位，兩個執行緒即使寫入的是不同變數，只要這些變數剛好位於同一個 64 位元組的快取行，每次寫入仍會使對方的副本失效。這個快取行會在核心之間來回彈跳，結果雖然正確，效能卻可能大幅下降。各執行緒專用的計數器或旗標陣列就是典型案例。解決方法是對每個執行緒的資料進行填充或對齊，使其各自獨占一個快取行，例如在 C 與 C++ 中使用對齊屬性。與此相對的是真共享，也就是執行緒確實存取同一個變數，這種通訊無法靠資料配置來避免。

練習快取行的題目

位址為32位元、容量32 KB、快取行大小64位元組的直接映射（direct-mapped）快取，其標籤（tag）為幾位元？

  1. A15位元
  2. B19位元
  3. C17位元
查看答案與解析

正確答案：C. 17位元

快取行大小64位元組 = 2⁶，所以偏移量（offset）為6位元。行數為 32 KB ÷ 64 B = 32768 ÷ 64 = 512 = 2⁹，在直接映射中行數就是組數，所以索引（index）為9位元。其餘為標籤，32 − 9 − 6 = 17位元。19位元是改為4路組相聯、索引減少2位元時的值，不適用於直接映射。

位址為32位元、容量32 KB、快取行大小64位元組的4路組相聯（set-associative）快取，其組數為多少？

  1. A128
  2. B512
  3. C32
查看答案與解析

正確答案：A. 128

行數為 32 KB ÷ 64 B = 512。4路時每組可放入4條快取行，所以組數為 512 ÷ 4 = 128 = 2⁷，索引為7位元，標籤為 32 − 7 − 6 = 19位元。512就是行數本身，是直接映射時的組數。提高相聯度會使組數減少，相對地標籤的位元數增加，比較器也隨之增加。32是把組數128又再除以路數4所得的值。

常見問題

快取行有多大？

目前大多數 CPU 為 64 位元組，但也有處理器使用 32 或 128 位元組；這是硬體特性，軟體可以查詢。

快取行和分頁有什麼不同？

快取行通常為 64 位元組，是在各級快取與記憶體之間搬移的單位；分頁通常為 4 KB，是由作業系統與 MMU 管理的虛擬記憶體對應單位。

如何避免偽共享？

把不同執行緒寫入的資料放在不同的快取行，通常的做法是將各執行緒的結構填充或對齊到 64 位元組。
