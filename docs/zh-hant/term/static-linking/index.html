什麼是靜態連結（Static linking）

將所使用的函式庫程式碼複製到可執行檔中結合的方式。即使執行環境沒有函式庫也能運作，但檔案會變大，函式庫的修正必須重新建置才會反映。

日文名稱: 静的リンク

「靜態連結（Static linking）」出現在1領域的2道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

連結器做了什麼

在靜態連結中，連結器讀取程式的目的檔，以及命令列上指定的靜態函式庫，取出解析未定義符號所需的封存成員，並把同類區段合併在一起：所有程式碼合併成一個 text 區段，所有已初始化資料合併成一個 data 區段，依此類推。接著它分配最終位址，利用重定位項目修補每一個參照，並寫出單一的執行檔。使用 GCC 時，-static 選項會要求對包括 C 標準函式庫在內的所有函式庫進行靜態連結，前提是已安裝這些函式庫的靜態版本。

靜態連結與動態連結的比較

靜態連結的執行檔是自給自足的：啟動時不需要尋找任何東西，沒有動態連結器的符號繫結，對函式庫程式碼的呼叫也是直接的。代價是大小與維護。每個程式都帶有它所使用之每個函式庫常式的自有副本，因此這些副本不像共用函式庫的分頁那樣在行程之間共用記憶體；而函式庫的安全修正，也要等到程式重新連結才會生效。動態連結則顛倒了這些取捨，代價是必須仰賴程式執行的每台機器上都有相容的函式庫版本。

自給自足的限度

靜態執行檔仍然取決於 CPU 架構與作業系統的系統呼叫介面，因此無法直接在其他作業系統上執行。有些函式庫功能在背後也預設會動態載入。例如 GNU libc 會警告，在靜態連結程式中使用的 getaddrinfo 等函式，執行時仍需要共用函式庫來進行名稱服務查詢。靜態連結也意味著程式無法那麼容易地使用 dlopen 式的外掛，因為外掛是預期由動態連結器處理的共用目的檔。

應用場合

微控制器的韌體幾乎總是靜態連結成單一映像，因為執行時沒有載入器或檔案系統可以提供函式庫。在伺服器與精簡的容器映像中，靜態執行檔受到重視，因為單一檔案就能複製到任何具有相容核心的地方。開發者也會對必須在許多發行版上執行、又不想煩惱函式庫版本的命令列工具使用靜態連結，以較大的檔案換取避開共用函式庫缺失或不相容等問題。

練習靜態連結（Static linking）的題目

關於靜態連結，下列說明何者正確？

  1. A將所使用函式庫的程式碼複製到執行檔中加以結合
  2. B每次執行程式時，載入函式庫並加以結合
  3. C不使用函式庫，將所有處理寫在單一原始檔中
查看答案與解析

正確答案：A. 將所使用函式庫的程式碼複製到執行檔中加以結合

靜態連結是由連結器從靜態函式庫（Linux中為.a檔）取出所需的函式，嵌入執行檔。即使執行環境中沒有該函式庫也能運作，也不需要啟動時的結合作業，但執行檔會變大，且每個使用相同函式庫的程式都各自持有一份副本。即使函式庫有錯誤修正，不重新建置也不會反映。

常見問題

如何用 gcc 靜態連結 C 程式？

在連結命令中加上 -static，例如 gcc -static main.c -o main。必須安裝所有相關函式庫（包括 C 函式庫）的靜態（.a）版本，才能成功。

為什麼我的靜態連結執行檔這麼大？

它包含了所使用之所有函式庫程式碼的副本，包括部分 C 執行時期函式庫，而不是參照系統上已有的共用函式庫。移除符號（strip）以及使用區段垃圾回收進行連結，可以縮小檔案。

靜態連結的程式比較快嗎？

啟動通常較快，因為不需要載入與繫結共用函式庫，呼叫也省去一層間接。對大多數長時間執行的程式而言，穩態速度的差異很小。
