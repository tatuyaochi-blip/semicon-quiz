什麼是馮紐曼架構

將程式與資料放在同一個主記憶體，依序讀出指令並執行的電腦架構。

日文名稱: ノイマン型アーキテクチャ

「馮紐曼架構」出現在1領域的1道練習題中（CPU與架構等）。

這個名詞所屬的領域: CPU與架構

儲存程式方式

馮紐曼架構是將程式（指令）與資料放在同一個主記憶體中，由CPU反覆逐一讀出指令、解碼並執行的電腦架構。由於馮紐曼於1945年撰寫的EDVAC設計報告使這種方式廣為人知，因而以他命名，但埃克特、莫克利等其他開發者也對儲存程式的概念有所貢獻。程式可以像資料一樣寫入記憶體，因此不必重新接線就能切換到其他處理，作業系統也能載入並執行程式。

構成要素與指令的執行

馮紐曼型電腦由進行運算的運算單元、控制整體動作的控制單元、儲存指令與資料的記憶單元，以及輸入輸出裝置構成。控制單元從程式計數器所指的位址讀出指令（擷取），加以解讀（解碼），在運算單元中執行，再把結果寫入暫存器或記憶體。程式計數器通常前進到下一個指令的位址，遇到分支指令時則改寫為其他位址。這個循環是馮紐曼架構的基本動作，使用管線或亂序執行的CPU，也被設計成從程式看到的結果會符合這個順序。

馮紐曼瓶頸

由於指令與資料使用同一個記憶體與同一條路徑，不論CPU多快，與記憶體之間的傳輸速度都會決定效能的上限。這稱為馮紐曼瓶頸。記憶體速度的成長跟不上CPU速度的成長，使這個問題日益嚴重。對策是在CPU附近放置小而快的快取，把常用的指令與資料放在手邊的記憶體階層。在AI計算這類大量讀寫資料的處理中，搬移資料的耗電也成為問題，在記憶體內部或附近進行運算的記憶體內運算與近記憶體運算的研究正在推進。

與哈佛架構的比較

哈佛架構把指令用的記憶體與資料用的記憶體分開，以各自的路徑連接。由於可以同時讀取指令與讀寫資料，在頻寬上較有利，DSP以及AVR、PIC這類小型微控制器多半採用這種方式。不過，程式不易當作資料來讀寫，在彈性方面不如馮紐曼架構。現今多數高效能CPU採用稱為修正型哈佛架構的構成：主記憶體與馮紐曼架構一樣由指令與資料共用，但L1快取分成指令用與資料用，可以同時存取。

練習馮紐曼架構的題目

  2. B藉由重新接線來更改程式

查看答案與解析

正確答案：C. 將程式（指令）與資料存放在同一個主記憶體中，依序讀出指令並執行

馮紐曼型（stored-program 儲存程式方式）將指令與資料放在同一個主記憶體中，由 CPU 依序讀出指令並執行。其優勢在於能把程式當作資料來改寫，具有高度彈性，是現今電腦的基礎。另一方面，指令與資料爭用同一條路徑會成為速度上的限制，稱為馮紐曼瓶頸。因此許多 CPU 會將 L1 快取分成指令用與資料用（哈佛型的觀念）。

常見問題

馮紐曼架構與哈佛架構有什麼不同？

馮紐曼架構把指令與資料放在同一個記憶體，以同一條路徑讀寫；哈佛架構則把指令用與資料用的記憶體與路徑分開。哈佛架構可以同時存取指令與資料，速度較快；馮紐曼架構構成簡單且具彈性。多數CPU採用只把L1快取分開的修正型哈佛架構。

馮紐曼瓶頸是什麼？

是指令與資料爭用同一個記憶體與路徑，使CPU與記憶體之間的傳輸速度限制了整體效能的問題。以快取等記憶體階層來加以緩解。

為什麼稱為馮紐曼架構？

因為數學家約翰·馮紐曼於1945年整理EDVAC設計的報告，使這種方式廣為人知。埃克特、莫克利等其他開發者也對儲存程式的概念有所貢獻。
