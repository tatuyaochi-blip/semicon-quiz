什麼是非同步 FIFO

寫入與讀取使用不同時脈的 FIFO，用於在時脈域之間傳遞多位元資料。將指標轉換為格雷碼後同步到對方的時脈域，以判定滿(full)與空(empty)。指標比位址多 1 位元，用以區分繞回。

日文名稱: 非同期FIFO

「非同步 FIFO」出現在2領域的11道練習題中（時序分析與CDC, LSI設計流程與EDA等）。

這個名詞所屬的領域: 時序分析與CDC

非同步 FIFO 的架構

非同步 FIFO 是一種雙埠記憶體，以發送端的時脈寫入、以接收端的時脈讀取。寫入指標位於寫入時脈域，讀取指標位於讀取時脈域。每個指標都經由同步器傳到對方的時脈域：寫入端將自己的指標與同步過來的讀取指標比較，產生 full；讀取端將自己的指標與同步過來的寫入指標比較，產生 empty。資料本身從不經過同步，而是穩定地存放在記憶體中，直到指標顯示可以讀取為止。

為什麼指標要用格雷碼

二進位計數器可能一次翻轉許多位元，例如從 0111 變為 1000，而分別同步的各位元可能在不同週期穩定，產生與前後兩值都無關的數值。格雷碼每次遞增只改變一個位元，因此即使該位元在變化途中被擷取，接收端看到的也只會是舊指標或新指標，頂多落後一步。深度通常是 2 的冪次，讓序列能乾淨地繞回。指標位元不應直接宣告為 false path：應以最大延遲限制，把它們的偏移控制在一個發送週期以內。

區分 full 與 empty

有 16 個項目時，4 位元位址無法區分空的 FIFO 與已經繞了一整圈的 FIFO，因為兩者的位址相同。加上第五個圈數位元即可解決。以二進位表示時，五個位元全部相等代表 empty，只有 MSB 不同代表 full。以格雷碼表示時，full 的條件變成最高兩個位元反相、較低三個位元相等；讀取指標為 00000 時，full 為 11000。由於雙方看到的都是對方指標稍舊的副本，full 與 empty 可能會被維持得稍久一些，但絕不會過早解除，因此誤差總是偏向安全側。

決定深度

深度必須能吸收突發傳輸期間的速率差。若寫入端以 100 MHz 送出 100 個字組，讀取端以 80 MHz 每週期取出一個字組，則突發持續 1000 ns，讀取端取走 80 個字組，剩下 20 個，這可由 突發長度 × (1 − 讀取速率 / 寫入速率) 求得。實際設計會再多加幾個項目，以涵蓋 2 至 3 個週期的指標同步延遲。相較於每筆資料需要 8 個以上週期的 req/ack 交握，非同步 FIFO 可持續每週期傳送一個字組，是串流資料的標準選擇。

練習非同步 FIFO的題目

在非同步FIFO中，將寫入指標與讀取指標轉換為格雷碼後，再同步化到對方時脈域的理由何者正確？

  1. A轉換為格雷碼後位元數減半，所需的同步器較少
  2. B每前進1步只有1個位元改變，因此即使在變化途中取入，也會是前進前或前進後的正確值
  3. C格雷碼的訊號不會成為亞穩態，因此不需要同步化
查看答案與解析

正確答案：B. 每前進1步只有1個位元改變，因此即使在變化途中取入，也會是前進前或前進後的正確值

二進位的指標會像從 0111 變為 1000 這樣同時改變多個位元，若對各位元分別同步化，可能收到完全無關的值。若使用格雷碼，1次遞增只會改變1個位元，因此即使該位元成為亞穩態，無論穩定為新值或舊值，結果都會是前進前或前進後的值。只是看到稍舊的值，FIFO並不會因此損壞。位元數不變，亞穩態本身也可能發生，因此仍需要同步器。

在深度16字組的非同步FIFO中，讓寫入指標與讀取指標比位址多1位元、成為5位元的理由，何者正確？

  1. A表示16字組的位址需要5位元
  2. B指標一致時，可區分同一圈為空、相差1圈為滿
  3. C將多出的位元作為同位元，用來偵測指標的錯誤
查看答案與解析

正確答案：B. 指標一致時，可區分同一圈為空、相差1圈為滿

16字組的位址用4位元即可表示，但只用4位元的指標，在讀取與寫入的位址一致時，無法區分是全部讀完的空狀態，還是寫了1圈後追上的滿狀態。加入第5位元作為表示圈數的位元後，以二進位比較時，5位元全部一致即為空，只有最高位元不同即為滿。使用格雷碼指標時，滿的判定比較方式會稍有不同。並非作為同位元使用。

常見問題

為什麼非同步 FIFO 的指標要用格雷碼？

每次遞增只改變一個位元，因此即使另一個時脈在變化途中取樣指標，也會穩定成遞增前或遞增後的有效值。二進位指標則可能被擷取成完全錯誤的值，破壞 full 或 empty 的判定。

為什麼 FIFO 指標比位址多 1 位元？

多出的位元用來計算圈數。位址相同時，圈數位元相等代表 empty，圈數位元不同則代表寫入端已超前一整圈，也就是 full。

跨時脈域該用非同步 FIFO 還是交握？

像設定暫存器這種偶發性的傳輸，可以接受每筆資料 8 個以上週期的代價，就使用交握。若資料必須以最高每週期一個字組的速率持續流動，則使用非同步 FIFO。
