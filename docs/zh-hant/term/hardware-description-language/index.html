什麼是硬體描述語言（Hardware description language, HDL）

以文字描述數位電路結構與行為的語言。HDL。有 Verilog、SystemVerilog、VHDL，並藉由邏輯合成轉換為電路。

日文名稱: ハードウェア記述言語

「硬體描述語言（Hardware description language, HDL）」出現在1領域的2道練習題中（LSI設計流程與EDA等）。

這個名詞所屬的領域: 硬體描述語言與驗證

HDL 描述的是什麼

硬體描述語言描述的是電路，而不是一連串指令。每個 assign 敘述、always 區塊與模組實例都代表隨時在運作的硬體，因此程式碼的順序並不代表執行順序。設計通常以暫存器傳輸層級（RTL）撰寫：暫存器在時脈邊緣更新，組合邏輯則計算其下一個值。主要語言有 Verilog、其擴充版 SystemVerilog，以及型別較嚴格的 VHDL。每種語言中只有可合成的子集合能對應到邏輯閘，其餘部分是為了模擬與驗證而存在。

撰寫可合成的 RTL

always @(posedge clk) 這類時脈區塊會變成正反器，慣例上使用非阻塞式賦值（<=）。組合邏輯區塊應使用 @(*) 或 always_comb 搭配阻塞式賦值（=），且必須在每條路徑上對每個輸出賦值（例如使用 default case），否則合成會推論出閂鎖器。for 迴圈會被展開成平行硬體，因此對八個位元執行的迴圈會變成八個加法器。狀態機由狀態暫存器、次態邏輯與輸出邏輯組合而成。三態輸出保留給晶片外的雙向腳位；內部的選擇則使用多工器。

以 HDL 進行驗證

同樣的語言也用來建構驗證環境。測試平台（testbench）會實例化待測設計，產生時脈、重置與激勵訊號，並檢查輸出；由於它永遠不會被合成，因此可以使用延遲、檔案 I/O 與顯示敘述。SystemVerilog 加入了類別、約束隨機激勵、功能覆蓋率與斷言，UVM 則提供可重複使用之測試平台的標準類別庫。Lint 工具以靜態方式檢查程式碼中的位元寬度不一致、推論出的閂鎖器與不可合成的語法結構。驗證所花的心力往往與設計本身相當，甚至更多。

HDL 在設計流程中的位置

HDL 位於規格與邏輯閘層級網表之間。工程師依規格撰寫 RTL 並加以模擬，接著由邏輯合成在製程設計套件（PDK）與時序約束條件的引導下，將其對應到晶圓代工廠元件庫中的元件。以這種方式描述行為，才使大型設計成為可能：即使是 32 位元加法器，也需要 2⁶⁴ 列的真值表。高階合成從 C 或 C++ 產生 RTL，進一步提高抽象層級；FPGA 工具則採用相同的 HDL，但將其對應到查找表而非標準元件。

  2. BHTML
  3. CSQL
查看答案與解析

正確答案：A. Verilog HDL或VHDL

RTL設計是以Verilog HDL（及其擴充版SystemVerilog）或VHDL等硬體描述語言，描述每個時脈下資料如何在暫存器之間流動。與軟體語言不同，所描述的處理會以電路形式同時並行運作。HTML是網頁的描述語言，SQL是資料庫的查詢語言，都無法描述電路。

常見問題

Verilog 和 VHDL 有什麼差別？

兩者都在 RTL 描述硬體，並受到合成與模擬工具支援。Verilog 語法簡潔、類似 C，VHDL 則較冗長且型別嚴格；SystemVerilog 則在 Verilog 上擴充了重要的驗證功能。

HDL 算是程式語言嗎？

它看起來像，但可合成的 HDL 程式碼描述的是同時運作的硬體，而不是依序執行的指令。每一行都會佔用電路面積，因此設計者是以暫存器與邏輯而非步驟來思考。

Verilog 中阻塞式和非阻塞式賦值該什麼時候用？

常見的準則是在時脈 always 區塊中使用非阻塞式（<=），在組合邏輯區塊中使用阻塞式（=）。在同一區塊中混用兩者，是模擬與合成結果不一致的常見原因。
