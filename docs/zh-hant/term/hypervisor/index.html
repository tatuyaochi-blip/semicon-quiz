什麼是虛擬機器監視器(Hypervisor)

在一台電腦上執行多個虛擬機器的軟體。將CPU、記憶體與裝置分配給各虛擬機器的作業系統，並使彼此隔離。也稱為虛擬機器監視器(VMM)。

日文名稱: ハイパーバイザ

「虛擬機器監視器(Hypervisor)」出現在2領域的8道練習題中（作業系統與硬體, 車用半導體與功能安全等）。

這個名詞所屬的領域: 作業系統與硬體

如何掌控 CPU

Hypervisor（又稱虛擬機器監視器）在比客體作業系統更高的特權等級執行。客體核心以為自己掌控硬體，但當它執行特權指令或存取受保護資源時，CPU 會陷入（trap）到 Hypervisor，由其在該虛擬機器的狀態上重現該操作的效果，再讓客體繼續執行。這就是陷入並模擬（trap-and-emulate）。硬體虛擬化擴充功能新增了專用模式，並在每次切換時快速儲存與還原客體狀態；例如 RISC-V 就在其機器、監督者與使用者模式之外，加入了 Hypervisor 模式。

記憶體虛擬化

每個客體都管理自己的分頁表，將客體虛擬位址對應到它認為的實體位址。這些客體實體位址還必須再對應到真正的主機記憶體。使用巢狀分頁時，硬體會自動完成兩個階段：先透過客體的分頁表從客體虛擬位址轉換到客體實體位址，再透過 Hypervisor 的分頁表轉換到主機實體位址。早期系統使用以軟體維護的影子分頁表，使得客體每次修改分頁表時，Hypervisor 都必須介入。兩階段轉換的代價是 TLB 失誤時的分頁表走訪變長，使用較大的分頁有助於減輕這個問題。

I/O 虛擬化

逐一暫存器地模擬真實裝置雖然完全透明，但速度很慢，因為每次存取暫存器都會退出到 Hypervisor。半虛擬化則在客體中安裝能感知虛擬化的驅動程式，透過共享記憶體中的佇列與 Hypervisor 批次交換請求，這是虛擬磁碟與網路卡的常見做法。若要追求最高效能，可以將實體裝置直接指派給單一客體，並由 I/O 記憶體管理單元（IOMMU）將其 DMA 限制在該客體的記憶體範圍內，以維持隔離。

Hypervisor、容器與信任

Type 1 Hypervisor 直接在硬體上執行，例如雲端伺服器；Type 2 Hypervisor 則以應用程式的形式在主機作業系統上執行。容器又是另一回事：它們共用同一個核心，只分割行程、檔案系統與資源，因此比各自啟動自己核心的虛擬機器更輕量，但隔離較弱。Hypervisor 也用於在車用 SoC 上分割不同關鍵等級的軟體。一般情況下 Hypervisor 可以讀取所有客體記憶體；機密運算功能則會加密 VM 記憶體，讓連主機都無法讀取。

練習虛擬機器監視器(Hypervisor)的題目

關於虛擬機器監視器（hypervisor）類型的說明，下列何者正確？

  1. A有直接在硬體上運作的類型，也有在一般作業系統上以應用程式形式運作的類型
  2. B一定是在一般作業系統上以應用程式形式運作，不會直接在硬體上運作
  3. C沒有類型上的差異，全都不使用硬體而僅靠軟體運作
查看答案與解析

正確答案：A. 有直接在硬體上運作的類型，也有在一般作業系統上以應用程式形式運作的類型

虛擬機器監視器有直接在硬體上運作並管理作業系統的類型（類型1，裸機型，bare metal），以及在Windows或Linux等一般作業系統上以應用程式形式運作的類型（類型2，主機型，hosted）。類型1沒有多餘的層次，效能與隔離性較佳，因此多用於伺服器與雲端；類型2使用方便，常用於個人電腦上的開發與測試。兩者都會利用CPU的虛擬化支援功能等硬體。

當虛擬機器的作業系統執行需要特權的指令時，處理會轉移到虛擬機器監視器，由其代為重現該指令效果的方式，稱為什麼？

  1. A捕捉並模擬（trap-and-emulate）
  2. B寫入時複製（copy-on-write）
  3. C需求分頁（demand paging）
查看答案與解析

正確答案：A. 捕捉並模擬（trap-and-emulate）

虛擬機器的作業系統本以為自己是直接操作硬體而執行特權指令，但實際上它是在特權較低的模式下運作，因此會發生例外（trap）。虛擬機器監視器接收到後，會模擬（emulate）該指令的效果，使結果對該虛擬機器而言是正確的，然後再回到虛擬機器。CPU的虛擬化支援功能，能讓這種切換更快速且確實。寫入時複製與需求分頁都是記憶體管理的方式。

常見問題

Hypervisor 和虛擬機器有什麼差別？

Hypervisor 是建立並執行虛擬機器、在虛擬機器之間分配硬體的軟體層；每個虛擬機器則是一個執行自己作業系統的獨立客體環境。

Type 1 和 Type 2 Hypervisor 有什麼不同？

Type 1（裸機型）Hypervisor 直接在硬體上執行，Type 2（寄居型）Hypervisor 則以應用程式的形式在一般作業系統上執行。

容器和虛擬機器一樣嗎？

不一樣。容器共用主機核心，較為輕量；虛擬機器則各自在 Hypervisor 上執行自己的核心，隔離性較強，也能執行不同的作業系統。
