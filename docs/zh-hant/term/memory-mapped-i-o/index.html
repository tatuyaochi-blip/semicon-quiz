什麼是記憶體對映I/O

將周邊裝置的暫存器配置到與記憶體相同位址空間的特定位址，以一般的讀寫指令操作的方式。該區域會設定為不快取。

日文名稱: メモリマップドI/O

「記憶體對映I/O」出現在2領域的3道練習題中（作業系統與硬體, CPU與架構等）。

這個名詞所屬的領域: 作業系統與硬體

運作方式

處理器的位址解碼器會把特定位址範圍導向周邊裝置，而非 RAM。計時器的控制暫存器、UART 的資料暫存器或 GPIO 埠，各自出現在固定的位址上，一般的 load 與 store 指令就成為對該裝置的讀寫交易。與記憶體不同，這些存取可能帶有副作用：讀取狀態或資料暫存器可能清除旗標或從 FIFO 取出資料，寫入 1 可能清除中斷，而且由於硬體獨立於程式更新數值，值隨時都可能改變。

記憶體對映 I/O 與埠對映 I/O 的比較

埠對映 I/O 為裝置提供獨立的位址空間，只能透過專用指令存取，例如 x86 的 IN 與 OUT。記憶體對映 I/O 不需要特殊指令，因此可以用所有定址模式、指標與 C 結構體來存取暫存器，讓指令集保持簡單。它是 ARM 與 RISC-V 微控制器的標準做法；即使在 x86 系統上，PCI Express 裝置也透過記憶體對映區域公開大部分暫存器，傳統的埠 I/O 主要是為了相容性而保留。

快取、volatile 與順序

裝置區域必須設定為不快取；否則 CPU 可能一直重讀過時的快取副本而看不到裝置的變化，或把寫入留在快取中。在 C 語言中，暫存器指標會宣告為 volatile，讓編譯器完全照寫法執行每一次存取，而不是只讀一次然後無限迴圈，或刪除重複的寫入。不過 volatile 無法控制硬體的重新排序或寫入緩衝。處理器與匯流排可能延後送出（post）寫入，因此驅動程式會使用記憶體屏障或裝置記憶體屬性，有時還會回讀，以確保順序與完成。

作業系統中的 MMIO

在具有虛擬記憶體的系統上，裝置暫存器的實體位址必須先以不快取屬性對映到核心的虛擬位址空間，驅動程式才能使用；有時也會為了使用者空間驅動程式而對映到使用者行程。MMIO 通常用於控制與狀態：設定裝置、啟動操作與確認中斷。大量資料則通常以 DMA（直接記憶體存取）搬移，由裝置本身讀寫主記憶體，而非由 CPU 透過暫存器複製。

練習記憶體對映I/O的題目

在微控制器等中，將周邊裝置的暫存器對應到與記憶體相同的位址空間，並以一般的記憶體讀寫指令來操作的方式是下列何者？

  1. A虛擬記憶體
  2. B記憶體對映 I/O（memory-mapped I/O）
  3. C快取一致性
查看答案與解析

正確答案：B. 記憶體對映 I/O（memory-mapped I/O）

在記憶體對映 I/O 中，為計時器、UART 等周邊裝置的控制暫存器分配特定位址，以一般的載入／儲存指令來操作。與另行準備輸入輸出專用指令的方式（x86 的 IN/OUT 等埠對映 I/O）相比，可以使指令集更為單純，在 ARM 與 RISC-V 的微控制器上是標準做法。需要注意讓周邊暫存器不被快取、不讓編譯器對其最佳化（volatile）等事項。

一般的作業系統不讓應用程式直接讀寫裝置暫存器，其主要理由為何？

  1. A因為在應用程式中寫不出讀寫暫存器的指令
  2. B因為若多個程式任意操作裝置，裝置的狀態可能遭到破壞，保護機制也可能被突破
  3. C因為裝置的暫存器只有在剛開機通電後才能讀寫
查看答案與解析

正確答案：B. 因為若多個程式任意操作裝置，裝置的狀態可能遭到破壞，保護機制也可能被突破

裝置暫存器所在的位址，若為記憶體映射I/O則透過頁表，若為x86的I/O埠則透過輸入輸出指令的特權設定，被設定為使用者模式無法存取，只有作業系統的驅動程式才能操作。這是因為若多個程式任意操作同一個裝置，過程中的狀態會混在一起而使裝置誤動作，也可能透過DMA改寫任意記憶體而突破保護。應用程式是透過系統呼叫，請作業系統代為操作。並不是寫不出指令，而是被保護機制所禁止。

常見問題

記憶體對映 I/O 和埠對映 I/O 有什麼差別？

記憶體對映 I/O 把裝置暫存器放在一般的記憶體位址空間中，以一般的 load 與 store 存取；埠對映 I/O 則使用獨立的位址空間與 x86 IN、OUT 等特殊指令。

記憶體對映暫存器為什麼必須宣告為 volatile？

裝置可能獨立於程式改變暫存器的值，因此 volatile 強制編譯器執行每一次讀寫，而不是把值暫存在暫存器中或刪除看似多餘的存取。

記憶體對映 I/O 空間為什麼不快取？

快取會傳回過時的值而非裝置的目前狀態，也可能延遲或合併寫入，因此裝置區域會以不快取或裝置屬性對映。
