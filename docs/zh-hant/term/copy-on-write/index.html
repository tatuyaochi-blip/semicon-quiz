什麼是寫入時複製

複製出來的記憶體起初與原本共用，直到其中一方要寫入時，才只複製該頁面的方式。可加快行程的建立並節省記憶體。

日文名稱: コピーオンライト

「寫入時複製」出現在2領域的5道練習題中（作業系統與硬體, 連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 作業系統與硬體

寫入時複製的運作方式

複製行程時，核心只複製分頁表。父行程與子行程的項目指向相同的實體頁框，所有可寫入的私有頁面都暫時被標記為唯讀，同時核心會為每個頁框維護參考計數。讀取以全速進行。任一行程第一次寫入時會引發保護錯誤；核心辨識出這是寫入時複製頁面後，會配置新的頁框、複製該頁面，將副本以可寫入方式映射給寫入的一方，並重新執行引發錯誤的指令。若參考計數顯示該頁面已不再被共用，則不必複製，只要重新設為可寫入即可。

為什麼對行程建立特別有效

在類 Unix 系統上，常見的模式是 fork 之後幾乎立刻執行 exec，例如 shell 啟動指令時。exec 會丟棄整個位址空間並載入新程式，因此若積極地複製父行程的記憶體，就完全是浪費。有了寫入時複製，fork 的成本大約只是複製分頁表的時間，而且只有在 exec 之前實際被修改的頁面（通常是少數堆疊與資料頁面）才會被複製。記憶體也得以節省，因為雙方都不寫入的頁面（例如程式碼與唯讀資料）在兩個行程的整個生命週期內都保持共用。

其他會遇到它的地方

只要資料在邏輯上被複製、但通常不會被修改，就會出現相同的概念。私有檔案映射就使用它：共享函式庫的可寫入資料區段一開始與檔案快取共用，每個行程只有在寫入某個頁面時才會得到自己的副本。許多核心會將新配置的匿名記憶體映射到單一共用的零頁面，直到被寫入為止。寫入時複製檔案系統與儲存快照會將修改過的區塊寫到新位置，而不是覆寫原處；虛擬機器快照與部分程式語言執行環境，也將此原則應用於磁碟映像檔與字串。

成本與陷阱

寫入時複製是轉移成本，而非消除成本。每次對共用頁面的第一次寫入，都會引發錯誤、陷入核心並複製頁面，遠比一般的儲存操作慢。若大型行程執行 fork 後，父行程持續寫入其大部分記憶體，幾乎每個頁面最終都會被複製，記憶體用量可能接近兩倍。在 fork 時將頁面標記為唯讀，也需要使其他核心上過時的 TLB 項目失效。寫入時複製不可與共享記憶體混淆：共享記憶體讓兩個行程都能看到彼此的寫入，而寫入時複製則讓每個寫入者得到私有副本。

練習寫入時複製的題目

複製行程時使用寫入時複製（copy-on-write）的優點，下列何者正確？

  1. A複製出的行程與原行程，永遠能共用寫入的內容
  2. B只在之後才複製被寫入的分頁，因此速度快且節省記憶體
  3. C每次寫入時都會複製所有分頁，因此資料的安全性提高
查看答案與解析

正確答案：B. 只在之後才複製被寫入的分頁，因此速度快且節省記憶體

複製行程時，若立即複製所有記憶體，會耗費時間與記憶體，而且如果隨後載入的是另一個程式，這些複本就白費了。寫入時複製會讓雙方的頁表都以唯讀方式指向相同的實體分頁，當任一方寫入時就會發生分頁錯誤，由作業系統只複製該分頁。寫入的內容不會被共用，而是各行程分別保有。也不會複製所有分頁。

常見問題

fork 會複製父行程的全部記憶體嗎？

在現代系統上不會。fork 會複製分頁表，並共用被標記為唯讀的實體頁面；只有當其中一個行程第一次寫入某頁面時，該頁面才會被複製。

fork 之後子行程寫入記憶體會發生什麼事？

寫入會觸發分頁錯誤，核心將該單一頁面複製到新的頁框，並以可寫入方式映射給子行程。父行程保留原本的頁面，因此雙方都看不到對方的變更。

寫入時複製和共享記憶體一樣嗎？

不一樣。共享記憶體刻意讓寫入後的內容對兩個行程都可見，而寫入時複製只在有人寫入之前共用頁面，一旦寫入，寫入者就會得到私有副本。

  • 寫入時複製會讓雙方的頁表都以唯讀方式指向相同的實體分頁，當任一方寫入時就會發生分頁錯誤，由作業系統只複製該分頁。
