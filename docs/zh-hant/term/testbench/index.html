什麼是測試平台（Testbench）

對待驗證電路給予輸入，並確認輸出是否正確的模擬用描述。因為不做邏輯合成，所以可自由使用延遲與顯示指令等。

日文名稱: テストベンチ

「測試平台（Testbench）」出現在2領域的8道練習題中（硬體描述語言與驗證, LSI設計流程與EDA等）。

這個名詞所屬的領域: 硬體描述語言與驗證

測試平台包含什麼

測試平台是一個頂層的 HDL 模組，通常沒有埠，它實例化待測設計（DUT），並在其周圍提供驅動它所需的一切。它產生時脈，例如 always #5 clk = ~clk;，每 5 個時間單位切換一次，在時間單位為 1 ns 時得到 10 ns 的週期；它也施加重設、驅動輸入激勵並觀察輸出。它還可能從檔案讀取測試向量、寫出日誌並傾印波形。DUT 是可合成的設計；測試平台則只存在於模擬中。

僅供模擬使用的語法

由於測試平台永遠不會被合成，它可以使用不具硬體意義的功能。#10 之類的延遲敘述會推進模擬時間，$display 與檔案 I/O 會印出或記錄數值，而 case 相等運算子 === 會按字面比較 X 與 Z 位元，讓測試能偵測到變成未知值的輸出。邏輯合成會忽略或拒絕這些語法，因此它們不能出現在 RTL 中。若它們混入設計程式碼，模擬與硬體的行為可能以難以除錯的方式出現分歧。

避免在時脈邊緣發生競爭

常見的測試平台錯誤，是在與時脈上升緣完全相同的模擬時間，以阻塞指定改變 DUT 的輸入。此時 DUT 的正反器擷取到的是舊值還是新值，取決於模擬器執行事件的順序，形成一種競爭，其結果甚至可能因模擬器而異。較安全的做法是在相反的時脈邊緣或有效邊緣稍後驅動輸入、使用非阻塞指定，或使用明確定義取樣與驅動時間的 SystemVerilog 時脈區塊。

從看波形到自我檢查測試

對於小型區塊，用肉眼檢查波形或許就足夠，但這種做法無法擴展。自我檢查測試平台會為每個輸入計算或查出預期結果（通常借助參考模型），自動與 DUT 的輸出比較，並將不一致回報為錯誤。如此一來，數千個測試就能在無人看管的情況下執行，例如在夜間進行回歸測試。較大型的專案會在此基礎上加入受限隨機激勵、計分板與覆蓋率收集，驗證工作量常與設計工作量相當甚至更多。

常見問題

測試平台（testbench）可以合成嗎？

不行。測試平台只為模擬而撰寫，因此會自由使用延遲、顯示敘述、檔案 I/O 以及其他無法成為硬體的語法。

測試平台中的 DUT 是什麼？

DUT 是 design under test（待測設計）的縮寫，指測試平台所實例化、施加激勵並加以檢查的可合成模組。

Verilog 測試平台中 == 和 === 有什麼差別？

== 運算子在任一運算元含有 X 或 Z 位元時會回傳 X，如同硬體比較器。=== 運算子則按字面比較 X 與 Z，永遠回傳 0 或 1，因此測試平台用它來偵測未知的輸出。
