什麼是KPTI（核心分頁表隔離）

Kernel page-table isolation。在使用者程式執行期間，將大部分核心記憶體從分頁表中移除，以防止 Meltdown 的作業系統對策。

日文名稱: KPTI

「KPTI（核心分頁表隔離）」出現在2領域的3道練習題中（硬體安全的進階主題與趨勢, 硬體安全等）。

這個名詞所屬的領域: 硬體安全

需要KPTI的背景

以往許多作業系統會在使用者行程的分頁表中也放入核心區域，並在核心分頁標上「使用者無法存取」的標記。這樣一來，因系統呼叫或中斷進入核心時不必切換分頁表，可以快速處理。然而2018年公布的Meltdown顯示，在受影響的CPU上，核心的資料會在權限檢查完成之前被推測讀取，並可從殘留在快取中的痕跡推測出其值。KPTI（核心分頁表隔離）就是以分頁表的構成來阻止這類讀取的作業系統對策。

兩組分頁表

KPTI為每個行程準備兩組分頁表。核心執行時使用的那組，同時映射使用者與核心的區域。使用者程式執行時使用的那組，只映射使用者區域，以及系統呼叫與中斷的進入處理所需的一小部分核心區域。沒有位址轉換，就連推測執行也讀不到核心的資料。進入核心時，由進入處理把分頁表切換為核心用，返回使用者模式時再切回使用者用。Linux於2018年初導入此機制，在研究階段稱為KAISER。

對效能的影響與PCID

KPTI在每次系統呼叫、中斷與例外時都要切換分頁表，因此會多花時間。在無法使用PCID的CPU上，每次切換還會使TLB的內容失效，之後的TLB未命中也會降低效能。影響程度依處理內容而有很大差異：以計算為主的程式幾乎感覺不到，但系統呼叫頻繁的資料庫或大量輸入輸出的處理，影響往往較大。使用x86的PCID（行程上下文識別碼），可以為使用者用與核心用的分頁表分配不同的編號，切換時不必清空TLB，因此能減少損失。

不需要KPTI的情況

KPTI是為受Meltdown影響之CPU所設的對策，不受影響的CPU並不需要。Meltdown公布後設計的CPU，多數已在硬體上修正，使無權限的資料不會傳給後續指令；Linux會依據CPU回報的資訊等判斷是否受影響，不需要時便不啟用KPTI。也有像AMD的x86 CPU這樣，被認為原本就不受Meltdown影響的CPU。Windows則導入了稱為KVA Shadow的類似對策。另外，KPTI是針對Meltdown的對策，利用分支預測的Spectre需要其他對策。

練習KPTI（核心分頁表隔離）的題目

下列關於作為Meltdown的軟體對策而導入的KPTI（核心分頁表隔離）的概念，何者正確？

  1. A在使用者程式執行期間，將核心記憶體的大部分從分頁表中移除，使其連推測也無法讀取
  2. B將核心整個加密後放在磁碟上
  3. C禁止執行使用者的程式
查看答案與解析

正確答案：A. 在使用者程式執行期間，將核心記憶體的大部分從分頁表中移除，使其連推測也無法讀取

以往的作業系統為了加快切換，會在使用者行程的分頁表中也放入核心記憶體（並標上禁止存取的標記）。在Meltdown中，由於能在檢查該標記之前就推測讀取，KPTI便在使用者程式執行期間，連核心分頁的對應本身都移除。位址無法轉換，就連推測也讀不到。不過，每次系統呼叫都要切換分頁表，因此效能會下降。

常見問題

KPTI是什麼？

是核心分頁表隔離（Kernel Page-Table Isolation）的簡稱，在使用者程式執行期間，將大部分核心記憶體從分頁表中移除，以防止經由Meltdown讀取的作業系統對策。

為什麼KPTI會使效能下降？

因為每次因系統呼叫或中斷進出核心時都要切換分頁表，需要花費切換本身以及之後TLB未命中的時間。在可使用PCID的CPU上，不必清空TLB，可以減少損失。

可以停用KPTI嗎？

在不受Meltdown影響或已在硬體上修正的CPU上並不需要，作業系統一般也會自動停用。若在受影響的CPU上停用，核心記憶體仍有被讀取的風險。
