什麼是目錄式一致性（Directory-based coherence）

以表記錄各行由哪個核心持有，只通知相關核心的一致性方式。用於核心數多的系統。

日文名稱: ディレクトリ方式

這個名詞所屬的領域: 多核心與同步

目錄儲存什麼

每條記憶體快取線都有一個主節點（home node），通常由其位址決定，主節點為它保存一個目錄項目：一致性狀態，例如未快取、共用或獨占，以及哪些快取持有副本的紀錄。最簡單的紀錄是完整位元向量，每個核心或快取對應一個位元。目錄項目位於記憶體控制器旁，或在共用的最末級快取中。由於請求只送往一個主節點而非所有節點，互連網路可以是點對點連結構成的網格，而不必是廣播匯流排。

一次寫入的逐步流程

想要寫入自己不擁有之快取線的核心，會向該快取線的主節點送出請求。主節點查詢目錄，只向標記為共用者的快取送出失效訊息；這些快取丟棄其副本並回覆確認，對象可能是主節點或直接是請求者。所有確認都到齊後，請求者取得獨占所有權，目錄則將其記錄為擁有者。若另一個快取以修改狀態持有該快取線，主節點會把請求轉送給該擁有者，由它把資料送給請求者，這就是所謂的三跳（three-hop）交易。

窺探式與目錄式的比較

窺探式（snooping）把每次未命中廣播給所有快取，由於不需要額外查詢，延遲較低，但流量與窺探工作量會隨核心數增加，因此只適用於小型系統。目錄式增加了在主節點查詢的延遲，有時還多一跳，但只把訊息送到需要的地方，因此流量隨實際共用程度而非核心數增加。所以大型多核心晶片與多插槽系統使用目錄式或混合式設計，例如以窺探過濾器（snoop filter）追蹤哪些快取可能持有某條快取線，從而省去大部分廣播。

讓目錄本身保持精簡

隨著核心數增加，為每條記憶體快取線都配置完整位元向量會耗費過多儲存空間，因此實際設計會設法節省。有限指標方案只儲存少數幾個共用者 ID，當共用的快取更多時則退回廣播；粗粒度向量則每一組核心使用一個位元。稀疏目錄只追蹤實際被快取的快取線，其本身也像快取一樣組織。當稀疏目錄的項目用完時，必須逐出一個項目，這會迫使所有持有該快取線的快取將其失效，因此其容量必須相對於所追蹤的快取配置得相當充裕。

常見問題

為什麼目錄式一致性比窺探式更具擴展性？

它只把失效訊息與請求送給實際持有該快取線的快取，而不是廣播給所有快取。因此流量取決於實際的共用情形，而不會隨核心數增加。

目錄式一致性比窺探式慢嗎？

每次未命中可能耗時較久，因為必須查詢主節點的目錄，請求也可能被轉送；但在大型系統中，減少的流量與競爭通常勝過增加的延遲。

什麼是窺探過濾器（snoop filter）？

這是一種記錄哪些快取可能持有各條快取線的結構，使一致性請求只送往那些快取。本質上它是用於窺探式設計中、以削減廣播流量的目錄。
