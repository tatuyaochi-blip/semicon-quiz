什麼是SMT(同步多執行緒)

以 1 個 CPU 核心同時處理多個執行緒的指令，有效利用核心內運算單元的技術。Intel 稱之為超執行緒(Hyper-Threading)。

日文名稱: SMT(同時マルチスレッディング)

「SMT(同步多執行緒)」出現在2領域的2道練習題中（硬體安全, CPU與架構等）。

這個名詞所屬的領域: CPU與架構

SMT如何共用一個核心

現代的亂序執行核心每個週期可發出多道指令，但由於相依性、分支預測失誤與快取未命中，單一執行緒很少能讓所有執行單元都保持忙碌。同步多執行緒（SMT）為每個硬體執行緒提供各自獨立的架構狀態，例如程式計數器與架構暫存器，而執行緒之間則共用執行單元、快取、分支預測器與內部緩衝區。在同一個週期內，來自不同執行緒的指令可以發送到不同的單元。作業系統將每個硬體執行緒視為一個邏輯處理器，通常每個核心有兩個。

可預期的加速幅度

由於執行緒競爭相同的執行資源，SMT無法像增加第二個核心那樣使效能加倍。典型的提升幅度約在0到30%之間。經常停頓的工作負載，例如等待記憶體的工作，受益最多：一個執行緒等待快取未命中時，另一個執行緒能讓執行單元保持忙碌。已經讓浮點運算單元或記憶體頻寬飽和的工作負載則幾乎沒有好處，共用快取中的競爭甚至可能使個別執行緒變慢，這對延遲敏感的應用程式影響很大。

SMT與其他多執行緒方式的比較

粗粒度多執行緒只在快取未命中等長時間停頓時才切換到其他執行緒。細粒度多執行緒則逐週期交錯執行各執行緒，但每個週期只從一個執行緒發送指令，這種做法常見於GPU與部分網路處理器。SMT更進一步，在同一個週期內從多個執行緒發送指令，適合寬度大的超純量核心。相對地，多核心則是複製整個核心。Intel將其雙向SMT命名為超執行緒（Hyper-Threading），部分伺服器處理器則支援每核心4或8個執行緒。

安全性與排程上的考量

兩個SMT執行緒以極細的粒度共用L1快取、分支預測器、執行埠與緩衝區，因此一個執行緒可以透過量測自身的執行時間，推測另一個執行緒在做什麼。好幾種旁通道漏洞正是依賴這種架構。因此，在同一硬體上執行不同客戶之不受信任程式碼的系統，可能會停用SMT，或採用核心排程（core scheduling），只讓同一信任域的執行緒放在同一核心的兄弟邏輯處理器上。這兩種做法都會降低吞吐量，因此必須在效能與隔離性之間權衡。

練習SMT(同步多執行緒)的題目

下列關於在處理機密的系統中，有時會停用CPU的同時多執行緒（SMT）的原因，何者正確？

  1. A在同一個核心上運作的兩個執行緒會共用L1快取與運算單元等，因此容易被另一個執行緒細緻地觀察處理的痕跡
  2. B因為停用SMT後，CPU的效能一定會提升
  3. C因為SMT無法進行密碼運算
查看答案與解析

正確答案：A. 在同一個核心上運作的兩個執行緒會共用L1快取與運算單元等，因此容易被另一個執行緒細緻地觀察處理的痕跡

在SMT中，一個核心內有兩個執行緒同時運作，細緻地共用L1快取、分支預測器、運算單元、緩衝區等。因此，一方的執行緒容易藉由時間測量來觀察另一方使用的資源，在幾個漏洞中，這成了攻擊的條件。為了不與不可信賴的對象共用同一核心，會關閉SMT，或只在同一核心上放置同一使用者的執行緒。

常見問題

超執行緒（Hyper-Threading）和SMT是一樣的嗎？

是的。超執行緒是Intel對其同步多執行緒實作所取的品牌名稱，每個實體核心在作業系統看來就像兩個邏輯處理器。

SMT能讓CPU效能加倍嗎？

不能。兩個執行緒共用一個核心的執行單元與快取，因此依工作負載不同，典型的吞吐量提升約為0到30%，遠低於增加第二個核心的效果。

為什麼有些系統會停用SMT？

同一核心上的執行緒共用快取與執行資源的程度，足以讓一個執行緒透過時序旁通道觀察另一個執行緒。停用SMT，或只讓彼此信任的執行緒一起排程，可消除這種風險，但會犧牲部分吞吐量。
