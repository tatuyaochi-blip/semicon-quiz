什麼是記憶體合併存取（Memory coalescing）

當 warp 內相鄰的執行緒存取相鄰的位址時，將其合併為較少次數的記憶體存取。

日文名稱: メモリコアレッシング

「記憶體合併存取（Memory coalescing）」出現在1領域的2道練習題中（GPU程式設計等）。

這個名詞所屬的領域: GPU程式設計

合併存取如何運作

GPU 的全域記憶體是以固定大小的區塊存取的，通常是 128 位元組快取行中的 32 位元組磁區（sector），而不是以個別字組存取。執行緒以稱為 warp 的群組執行，通常是 32 個執行緒一起發出同一條載入指令。當 warp 中第 i 個執行緒讀取位於 base + 4i 的 4 位元組元素時，這 32 個請求會落在連續的 128 位元組中，硬體便將它們合併成一次或少數幾次記憶體交易。這種合併就是記憶體合併存取，它讓 GPU 能用到所搬移的幾乎所有位元組。

什麼會破壞合併存取

若執行緒以跨距存取位址，例如每隔 4 個元素存取一次，warp 就會觸及 4 倍數量的磁區，而每個擷取到的磁區大部分都被丟棄。隨機或間接存取可能需要為每個執行緒各發出一次交易。起始位址未對齊時，可能多出一個區段。在這些情況下，有效頻寬都會降到峰值的一小部分；而由於許多 GPU 核心函式受限於記憶體頻寬而非運算，未合併的存取常會讓核心函式大幅變慢。

結構陣列與陣列結構

資料配置在很大程度上決定存取能否合併。若粒子座標以結構陣列（AoS）儲存，粒子 0 的 x、y、z 之後緊接著粒子 1 的 x、y、z，因此每個執行緒讀取 x 時，位址彼此相隔 12 位元組。若採用陣列結構（SoA），所有 x 值都是連續的，相鄰執行緒讀取相鄰位址，warp 的載入就能合併。基於同樣的理由，SoA 通常也較適合 CPU 的 SIMD 向量化：相鄰的通道需要相鄰的元素。

技巧與常見的混淆

常見的修正方式包括：將變化最快的執行緒索引（CUDA 中的 threadIdx.x）對應到陣列的連續維度、將 AoS 資料轉換為 SoA，以及透過晶片上的共享記憶體暫存資料，例如以合併的列讀取載入矩陣區塊，再轉置後寫出。合併存取關乎的是全域記憶體的交易。它不應與共享記憶體的記憶庫衝突（bank conflict）混淆；後者是指 warp 中多個執行緒存取同一個共享記憶體記憶庫中的不同位址，導致其存取被序列化。

練習記憶體合併存取（Memory coalescing）的題目

關於GPU的記憶體合併存取（coalescing），下列說明何者正確？

  1. A將兩個GPU的記憶體合而為一，使容量加倍
  2. B壓縮記憶體的資料以增加容量
  3. C當線程束中相鄰的執行緒讀取相鄰的位址時，可合併為較少次數的記憶體存取
查看答案與解析

正確答案：C. 當線程束中相鄰的執行緒讀取相鄰的位址時，可合併為較少次數的記憶體存取

GPU的記憶體是以32位元組或128位元組等成塊的單位進行讀寫。當線程束的32個執行緒各自讀取連續位址的4位元組時，合計128位元組的區塊只需1次到數次的存取即可讀完。若位址分散，每個執行緒就得讀取不同的區塊，連用不到的資料也一併搬運，有效頻寬會降到原來的幾分之一。

以GPU處理具有粒子位置x、y、z的資料時，就記憶體合併存取而言，下列何種排列方式較有利？

  1. A做成依粒子逐一排列x、y、z的結構陣列
  2. B將所有值以隨機的順序排列
  3. C分成只有x的陣列、只有y的陣列、只有z的陣列（不是結構的陣列，而是陣列的結構）
查看答案與解析

正確答案：C. 分成只有x的陣列、只有y的陣列、只有z的陣列（不是結構的陣列，而是陣列的結構）

在結構陣列（AoS）中，會依序排成粒子0的x、y、z，粒子1的x、y、z……因此各執行緒讀取x時，位址會以每12位元組為間隔而零散。若改為陣列結構（SoA），將x連續排列，相鄰的執行緒就會讀取相鄰位址的x，因而成為合併存取。在CPU的SIMD中，基於同樣的理由，SoA往往也較為有利。

常見問題

CUDA 的記憶體合併存取（coalescing）是什麼？

它是硬體將一個 warp 中各執行緒的全域記憶體存取，合併成盡可能少的交易，當相鄰執行緒存取相鄰且對齊的位址時就會發生。

為什麼陣列結構（SoA）比較適合 GPU 記憶體存取？

在陣列結構中，每個欄位都連續儲存，因此讀取同一欄位的相鄰執行緒會存取連續的位址，其載入便能合併；結構陣列則會在它們之間產生跨距。

記憶體合併存取和記憶庫衝突有什麼不同？

合併存取關乎 warp 的全域記憶體存取如何對應到記憶體交易，而記憶庫衝突則是多個執行緒存取晶片上共享記憶體的同一個記憶庫，迫使存取序列化。
