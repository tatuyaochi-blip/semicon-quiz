什麼是CAS 延遲

在 DRAM 中，從指定行位址的讀取指令到資料輸出為止的時脈數。簡稱 CL。數值越小，響應越快。

日文名稱: CASレイテンシ

這個名詞所屬的領域: DRAM

CAS延遲衡量的是什麼

CAS是column address strobe（行位址選通）的縮寫。DRAM讀取時，會先啟動（activate）一列，將其內容複製到感測放大器中，接著發出帶有行位址的讀取指令。CAS延遲（CL）是從該讀取指令到第一筆資料出現在輸出端所經過的時脈週期數。之後，叢發中的其餘資料會在接續的時脈邊緣依序輸出。由於CL以週期數計算，實際的奈秒延遲為CL乘以時脈週期，只有在時脈速度相同時，CL較小才代表較快。

將CL換算成奈秒

DDR記憶體的資料速率是時脈頻率的兩倍，因此DDR4-3200在1600 MHz時脈（週期0.625 ns）下每秒傳輸32億次。此時CL22相當於22 × 0.625 ns ≈ 13.75 ns。DDR3-1600的時脈為800 MHz、週期1.25 ns，因此CL11同樣約為13.75 ns。新世代較大的CL數字背後，延遲其實幾乎沒變，因為記憶單元陣列的速度在世代之間進步有限，而介面時脈卻持續提高。

CL在DRAM時序參數中的定位

CL只是一次存取中的一部分。如果所需的列尚未開啟，控制器必須先對記憶庫預充電以關閉舊列（tRP），再啟動新列並等待列位址至行位址延遲（tRCD），之後才能發出讀取指令，接著再等待CL。時序參數常以CL-tRCD-tRP的形式一併標示。若該列已在感測放大器中開啟（頁面命中），則只需要CL，因此記憶體控制器會重新排序請求，將對同一列的存取集中處理，以提高命中比例。

延遲與頻寬

CAS延遲描述的是第一個字組需要多久才能取得，頻寬則描述資料開始傳輸後串流的速度。較快的記憶體世代主要是藉由提高資料速率與叢發長度來提升頻寬；以奈秒計的首字組延遲則一直維持在相近的範圍。串流大量資料區塊的工作負載受益於頻寬，而指標追逐以及未命中處理器快取的隨機存取，則對延遲較為敏感。因此比較記憶體模組時，必須將CL換算成奈秒，並一併考慮其他時序參數，而不能只看CL數字。

常見問題

記憶體的CAS延遲是什麼意思？

CAS延遲是從帶有行位址的讀取指令到第一筆資料輸出之間的記憶體時脈週期數。將其乘以時脈週期，即可得到以奈秒計的實際延遲。

CAS延遲越低一定越快嗎？

只有在時脈速度相同時才成立。時脈頻率較高、CL較大的模組，以奈秒計的延遲可能相同甚至更低，因此比較前必須先以時脈週期換算CL。

為什麼新世代DDR的CAS延遲數值比較大？

DRAM記憶單元陣列以奈秒計的響應時間變化不大，而時脈週期卻持續縮短，因此需要更多時脈週期才能涵蓋大致相同的延遲。
