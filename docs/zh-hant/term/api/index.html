什麼是API（應用程式介面）

Application Programming Interface的縮寫。讓其他程式呼叫並使用軟體功能的約定（函式或操作的名稱、引數、傳回值、資料格式等）。有作業系統的API、函式庫的API，以及以HTTP交換資料的Web API（REST API等）。不必了解內部實作即可使用，只要API相同就能替換實作。機器碼層級的約定稱為ABI。

日文名稱: API

「API（應用程式介面）」出現在4領域的9道練習題中（Web技術基礎, 雲端與容器基礎, 網路攻擊與防禦實務等）。

練習API（應用程式介面）的題目

把雲端儲存用於以下3種用途：①作為磁碟連接到虛擬機器並建立檔案系統，放置資料庫的資料檔；②從多台伺服器同時掛載，作為共用目錄使用；③透過 HTTP 的 API 指定鍵（名稱）讀寫大量圖片，且不預先決定容量而持續增加。適合①～③的儲存種類組合，下列何者適當？

  1. A①物件儲存、②區塊儲存、③檔案儲存
  2. B①檔案儲存、②物件儲存、③區塊儲存
  3. C①區塊儲存、②檔案儲存、③物件儲存
查看答案與解析

正確答案：C. ①區塊儲存、②檔案儲存、③物件儲存

區塊儲存是把固定大小的區域作為虛擬磁碟連接到虛擬機器，在上面建立檔案系統使用，適合資料庫這類需要快速進行細小讀寫的用途。檔案儲存透過 NFS 或 SMB 等，提供多台伺服器可同時掛載的共用檔案系統。物件儲存把資料作為以鍵識別的物件，透過 HTTP 的 API 整個讀寫，容量幾乎不必在意就能增加，適合存放圖片、備份與日誌。它不適合只改寫物件一部分的用法，因此不放資料庫的資料檔。

  1. AAccept: application/json
  2. BContent-Type: text/html
  3. CContent-Type: application/json

正確答案：C. Content-Type: application/json

本文資料的種類以Content-Type標頭表示，值寫成text/html或image/png這類「類型/子類型」形式的媒體類型（MIME類型）。JSON的媒體類型是application/json。JSON是以名稱與值的組合及陣列表示資料的文字格式，例如 {"id": 42, "tags": ["a", "b"]}，比XML簡潔，也容易從JavaScript處理，因此廣泛用於Web API。Accept標頭是在請求中告知用戶端想接收之格式的標頭。
