什麼是特權模式

只有作業系統核心可以使用的CPU運作模式。可執行頁表設定或輸入輸出操作等危險指令，與應用程式執行的使用者模式有所區別。

日文名稱: 特権モード

「特權模式」出現在1領域的4道練習題中（作業系統與硬體等）。

這個名詞所屬的領域: 作業系統與硬體

練習特權模式的題目

CPU設置特權模式（核心模式）與使用者模式，主要目的為何？

  1. A讓應用程式的指令能比核心的指令更快、更優先地執行
  2. B保護頁表與裝置，避免應用程式任意操作
  3. C讓一顆CPU能同時執行兩個指令
查看答案與解析

正確答案：B. 保護頁表與裝置，避免應用程式任意操作

若應用程式能自由改寫頁表、操作輸入輸出裝置或停用中斷，就可能破壞其他程式的記憶體，或讓整個系統停擺。因此CPU規定這些指令只能在特權模式下執行，只有作業系統的核心才能使用。若在使用者模式下嘗試執行，就會產生例外。這並不是為了提升速度或同時執行而設計的機制。

解析中的「特權模式」

  • 因此CPU規定這些指令只能在特權模式下執行，只有作業系統的核心才能使用。

    CPU設置特權模式（核心模式）與使用者模式，主要目的為何？

  • 所以要使用系統呼叫，透過專用指令切換到特權模式並呼叫核心的處理程序，來請求檔案讀寫、記憶體配置、行程建立等服務。

    應用程式請求作業系統進行檔案讀寫等操作的機制稱為什麼？

  • 發生例外或中斷時，CPU會將返回位置的位址，以及之前的運作模式、中斷是否原本為允許的狀態，儲存到專用暫存器後進入特權模式。

    處理完中斷或例外而回到原本的程式時，不使用一般函式的返回指令，而是使用專用的返回指令（RISC-V的sret、mret…

  • 系統呼叫每次都需要從使用者模式切換到特權模式、儲存暫存器、檢查引數、返回等處理，即使處理的量只有1位元組，也會產生這些固定的負擔。

    寫出小量資料時，與其逐位元組每次都呼叫系統呼叫，不如先暫存在使用者空間的緩衝區再一併寫出，速度會比較快，其主要理由為何？

出現「特權模式」的題目（4題）

  1. CPU設置特權模式（核心模式）與使用者模式，主要目的為何？
  2. 應用程式請求作業系統進行檔案讀寫等操作的機制稱為什麼？
  3. 處理完中斷或例外而回到原本的程式時，不使用一般函式的返回指令，而是使用專用的返回指令（RISC-V的sret、mret等），其理由為何？
  4. 寫出小量資料時，與其逐位元組每次都呼叫系統呼叫，不如先暫存在使用者空間的緩衝區再一併寫出，速度會比較快，其主要理由為何？
