什麼是循序一致性（Sequential consistency）

所有核心的操作可排成單一順序，且各核心的操作看起來都依程式順序的、最直觀的記憶體一致性模型。

日文名稱: 逐次一貫性

「循序一致性（Sequential consistency）」出現在1領域的3道練習題中（多核心與同步等）。

這個名詞所屬的領域: 多核心與同步

此模型保證了什麼

循序一致性由 Leslie Lamport 於 1979 年定義，要求任何執行的結果都必須與「所有核心的記憶體操作交錯成單一全域序列，且各核心的操作在該序列中依程式順序出現」時相同。就像把好幾副撲克牌洗在一起，但不改變任何一副牌內部的順序：交錯方式可以是任意的，但所有核心看到的都是同一種。程式設計者可以想像各執行緒輪流執行來推理並行程式碼，這也是它被視為最直觀的記憶體一致性模型的原因。

實際 CPU 為何放寬它

對所有記憶體存取嚴格維持程式順序，會讓許多硬體最佳化無法使用。儲存緩衝區讓核心在寫入後不必等待寫入抵達快取即可繼續執行，亂序執行則讓較晚的載入先於較早的儲存完成。兩者都會破壞循序一致性。因此大多數處理器實作的是較弱的模型：x86 採用總儲存順序（TSO），允許較晚的載入越過較早的、對不同位址的儲存；Arm 與 RISC-V 則採用更弱的模型，除非程式插入 fence，否則允許更多重新排序。

儲存緩衝區 litmus 測試

設核心 0 執行 x = 1 後執行 r1 = y，核心 1 執行 y = 1 後執行 r2 = x，x 與 y 初始值皆為 0。在循序一致性下，其中一個寫入必定在全域順序中先發生，因此至少有一個讀取會看到 1，r1 = r2 = 0 是不可能的。在 x86 上，每個寫入都可能停留在自己核心的儲存緩衝區中，而接下來的讀取則從快取取得舊值，因此兩個讀取都可能回傳 0。在每個核心的寫入與讀取之間放置完整的記憶體屏障，即可恢復循序一致的結果。

循序一致性與快取一致性

快取一致性只涉及單一記憶體位置：所有核心對該位址的寫入順序有共識，並最終看到最新的值。循序一致性這類記憶體一致性模型則涉及對不同位址存取的順序，這是快取一致性本身無法約束的。程式語言填補了這個落差：C11 與 C++11 的原子操作預設為 memory_order_seq_cst，沒有資料競爭的程式其行為就如同循序一致。當不需要完整順序時，acquire/release 或 relaxed 等較弱的順序能讓編譯器產生較少的屏障。

練習循序一致性（Sequential consistency）的題目

  3. C所有操作都只在一個核心上執行
查看答案與解析

正確答案：B. 所有核心的操作被排成某一個順序，且各核心的操作看起來會依程式所寫的順序出現

在循序一致性中，多個核心的操作就像洗牌一樣被排成一列，而各核心的操作在其中看起來維持程式的順序。對程式設計師而言這是最容易理解的模型，但它會大幅限制硬體以儲存緩衝區等方式調換順序的最佳化，所以實際上許多CPU採用更寬鬆的模型。

常見問題

x86 是循序一致的嗎？

不是。x86 實作的是總儲存順序（TSO），允許載入在較早的、對不同位址的儲存被其他核心看見之前完成，因此儲存緩衝區 litmus 測試中 r1 = r2 = 0 的結果可能發生。MFENCE 等 fence 或帶 lock 前綴的指令可以防止這種情況。

循序一致性和快取一致性有什麼差別？

快取一致性保證每個個別位址都有一個共同認定的寫入順序。循序一致性更強，涵蓋所有位址上操作的相對順序，形成一個符合各核心程式順序的全域交錯。

C++ 的 memory_order_seq_cst 是什麼意思？

它是 std::atomic 操作的預設順序，讓所有 seq_cst 操作看起來位於單一的全序中，且與各執行緒的程式順序一致。它最容易推理，但可能需要成本最高的屏障指令。
