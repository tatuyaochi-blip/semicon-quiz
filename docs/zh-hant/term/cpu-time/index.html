什麼是CPU 時間（CPU time）

CPU 執行該程式指令的時間總和。不含等待時間，在平行執行時可能比牆上時間更長。

日文名稱: CPU時間

「CPU 時間（CPU time）」出現在5領域的5道練習題中（效能評估與效能剖析, 車用半導體與功能安全, 多核心與同步等）。

這個名詞所屬的領域: 效能評估與效能剖析

CPU 時間與牆上時間

牆上時間又稱經過時間或實際時間，是使用者從開始到結束所等待的時間，包括等待磁碟、網路或鎖的時間，以及分配給其他程式的時間片。CPU 時間只計算處理器實際執行該程式的時間。在類 Unix 系統上，time 指令會同時顯示兩者：real 是牆上時間，user 與 sys 則將 CPU 時間分成程式本身的程式碼，以及核心代為執行的工作（例如系統呼叫）。

解讀兩者的比例

比較兩個數值可看出時間花在哪裡。若單執行緒程式的牆上時間遠大於 CPU 時間，表示它大多在等待，通常是等待 I/O 或鎖，換成更快的處理器幫助不大。若 CPU 時間接近牆上時間，該程式就是運算受限。當多個執行緒平行執行時，總 CPU 時間可能超過牆上時間：四個執行緒各忙碌 10 秒，會在約 10 秒的經過時間內產生約 40 秒的 CPU 時間。

CPU 效能方程式

在計算機結構中，程式的 CPU 時間寫成 指令數 × CPI（每道指令的平均時脈週期數）× 時脈週期，或等價地寫成 指令數 × CPI ÷ 時脈頻率。此方程式將編譯器與指令集（指令數）、微架構（CPI）以及電路技術（時脈速率）的貢獻區分開來。它也說明了為何以犧牲某一因素為代價來改善另一因素（例如提高頻率但 CPI 變差）未必能讓程式變快。

作為預算的 CPU 時間

忙碌的 CPU 時間不一定是有用的工作。在被長時間持有的鎖上自旋的執行緒會白白消耗 CPU 時間，在單核心上甚至可能延遲鎖的持有者直到其時間片結束；長時間等待應使用會進入睡眠的 mutex。在即時系統與車用系統中，CPU 時間是按任務分配並監控的，時間分割可確保行為異常的低關鍵度任務無法耗用安全關鍵軟體所需的執行時間。

  1. A牆上時鐘時間是從開始到結束實際經過的時間，包含等待輸入輸出等；CPU時間則只計算CPU執行該程式的時間
  2. B牆上時鐘時間與CPU時間一定是相同的值
  3. CCPU時間是指以房間裡的時鐘測量的時間
查看答案與解析

正確答案：A. 牆上時鐘時間是從開始到結束實際經過的時間，包含等待輸入輸出等；CPU時間則只計算CPU執行該程式的時間

牆上時鐘時間是使用者實際等待的時間，也包含等待磁碟或網路，以及讓給其他程式的時間。CPU時間是CPU執行該程式指令的時間總和。若牆上時鐘時間遠長於CPU時間，就表示等待某些事物的時間很長。反之，若以多個執行緒平行運作，CPU時間的總和會比牆上時鐘時間長。

常見問題

為什麼 CPU 時間比實際時間還長？

因為程式使用了在不同核心上同時執行的多個執行緒或行程，而 CPU 時間會將它們全部加總。例如四個滿載的執行緒，每經過 1 秒大約累積 4 秒的 CPU 時間。

time 指令中的 real、user、sys 是什麼意思？

real 是經過的牆上時間，user 是花在程式本身程式碼上的 CPU 時間，sys 是核心代為執行（例如處理系統呼叫）所花的 CPU 時間。

CPU 時間包含等待 I/O 的時間嗎？

不包含。程式在等待磁碟或網路時並未執行，因此該時間會出現在牆上時間中，但不會出現在 CPU 時間中。
