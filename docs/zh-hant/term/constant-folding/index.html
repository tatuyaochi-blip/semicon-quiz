什麼是常數摺疊

將編譯時就能確定值的運算式事先算好，替換成結果常數的最佳化。例如把 3 * 4 變成 12。可減少執行時的計算。

日文名稱: 定数畳み込み

「常數摺疊」出現在1領域的6道練習題中（編譯器等）。

這個名詞所屬的領域: 編譯器

編譯器實際做了什麼

在最佳化過程中，編譯器會掃描其中間表示，找出所有運算元皆為常數的運算，計算其值，再以所得的字面值取代該運算。算術運算、位元運算、移位、型別轉換與比較都可以摺疊。摺疊比較運算的威力特別大：若 10 > 100 這樣的條件成為已知的 false，它所保護的分支就永遠不會執行。編譯器通常會將摺疊與代數化簡一起進行，把 x * 1 或 x + 0 之類的運算式改寫為 x，但嚴格來說這是另一種轉換，因為 x 本身不是常數。

與常數傳播、內嵌及無用程式碼消除的配合

常數摺疊很少單獨發揮作用。常數傳播會將已知持有常數之變數的使用處替換成該常數，為摺疊創造新的機會，而摺疊的結果又可以再傳播。例如 n = 8; m = n * 2; return m + 1 會簡化成 return 17，之後無用程式碼消除會移除未使用的指派。內嵌則讓這個循環持續進行：一旦呼叫 sq(6) 被其函式本體取代，6 * 6 + 1 就會摺疊成 37。以 SSA 形式為基礎的編譯器，常將傳播、摺疊與不可達分支移除結合成一個演算法，稱為稀疏條件常數傳播。

保持程式的語意

摺疊的結果必須與目標機器在執行時計算出的值完全相同。因此編譯器必須模擬目標機器的整數寬度與溢位環繞，這在從 64 位元主機交叉編譯到 32 位元目標時特別重要。浮點數摺疊必須依原始碼順序，對每個運算重現 IEEE 754 的捨入，這就是除非 fast-math 等選項允許，否則編譯器不會重新結合浮點運算式的原因。會引發錯誤的運算（例如整數除以零），除非確定該程式碼一定會執行，否則不得變成編譯期錯誤。

常數摺疊與語言層級的常數運算式

有些編譯期求值是語言所要求的，而非最佳化器自行選擇。在 C 語言中，陣列大小、case 標籤與靜態變數的初始值都必須是常數運算式，而 C++ 的 constexpr 函式可依要求在編譯期求值。最佳化層級的常數摺疊範圍更廣，且屬於選擇性：它適用於程式的任何地方，包括經過傳播或內嵌後才成為常數的值，並可發生在多個階段，從前端、中間表示一直到指令選擇；在指令選擇階段，位址偏移加上常數可能被合併成一個立即值。

練習常數摺疊的題目

關於編譯器的常數摺疊（constant folding），下列哪個範例正確？

  1. A將多次呼叫相同函式的部分，彙整為一次呼叫
  2. B將 x = 3 * 4 在編譯時計算，變成 x = 12
  3. C將迴圈主體並排4次份，以減少重複次數
查看答案與解析

正確答案：B. 將 x = 3 * 4 在編譯時計算，變成 x = 12

常數摺疊是一種最佳化，會事先計算在編譯時值就已確定的運算式，並替換為結果常數。3 * 4 每次執行都會得到相同的12，因此不需要在執行時做乘法。與常數傳播搭配使用時，連經由變數的計算也能一併摺疊。浮點數還有需要統一捨入方式等注意事項。並排迴圈主體的是迴圈展開，彙整函式呼叫則是另一種最佳化。

常見問題

常數摺疊和常數傳播有什麼差別？

常數摺疊是計算所有運算元皆為常數的運算式，例如將 3 * 4 變成 12。常數傳播則是將變數已知的常數值代入其使用處，這常會產生可再被摺疊的新運算式。

關閉最佳化時還會進行常數摺疊嗎？

簡單的字面值運算式即使未開啟最佳化，也常會被摺疊，因為前端在剖析時就會計算它們。經由變數的摺疊、函式內嵌與分支移除，一般則需要開啟最佳化。

常數摺疊會改變浮點數的結果嗎？

符合標準的編譯器會以與硬體相同的 IEEE 754 捨入方式摺疊浮點運算，因此結果不會改變。fast-math 等放寬浮點規則的選項則允許重新結合，可能改變結果的最後幾個位元。
