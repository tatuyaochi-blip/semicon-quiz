什麼是自旋鎖（Spinlock）

以迴圈持續檢查鎖變數直到鎖被釋放來等待的鎖。等待時間短時很快，但等待期間仍持續佔用 CPU。

日文名稱: スピンロック

「自旋鎖（Spinlock）」出現在1領域的4道練習題中（多核心與同步等）。

這個名詞所屬的領域: 多核心與同步

自旋鎖如何取得與釋放

自旋鎖是一個共享變數，通常空閒時為 0、被持有時為 1。要取得它，執行緒會使用 test-and-set、swap 或 compare-and-swap 等原子「讀取－修改－寫入」指令，在一個不可分割的步驟中將變數設為 1 並回傳舊值；在 RISC-V 上則是原子 swap 或 load-reserved/store-conditional 指令對。若舊值為 0，該執行緒便擁有了鎖；否則就在迴圈中再試一次。釋放只需存入 0。取得與釋放也必須具備記憶體屏障的作用，使臨界區段內的存取保持在兩者之間。

test-and-test-and-set 與快取流量

在緊密迴圈中不斷重試原子指令，在多核心晶片上效能很差。每次原子操作都需要獨佔該快取行，因此等待中的核心會不斷把快取行拉進修改（M）狀態，並使彼此的副本失效，讓一致性互連網路充斥流量。test-and-test-and-set 模式則改用一般的載入來等待：每個等待者讀取自己快取中的共享副本，不產生任何流量，只有在看到鎖變為空閒時才嘗試原子操作。指數退避（exponential backoff）以及票號鎖（ticket lock）或佇列式鎖能進一步減少爭用並增加公平性。

自旋鎖與互斥鎖

會休眠的互斥鎖（mutex）讓等待的執行緒進入阻塞狀態，把 CPU 交給其他執行緒；鎖被釋放時再由作業系統將其喚醒。這不會浪費 CPU 時間，但需要付出系統呼叫、排程與情境切換的成本，通常為數微秒。自旋鎖完全避免了這些額外負擔，當鎖只被持有很短的時間（短於一次休眠與喚醒所需時間）時更有優勢。持有時間長時情況就會反過來，因此許多函式庫的互斥鎖會先短暫自旋再進入休眠，兼具兩者的優點。

自旋鎖的適用與失效情境

自旋鎖常見於作業系統核心內部，用於多處理器上的短臨界區段，以及與不能休眠的中斷處理常式共享的資料。持有自旋鎖的程式碼不可休眠，核心在持有期間通常會停用搶佔，必要時也會停用中斷，以免同一核心上的中斷處理常式永遠自旋等待自己核心所持有的鎖。在單核心系統上，使用者層級的自旋鎖特別浪費：等待者自旋時，持有者無法執行來釋放鎖，因此等待者會耗盡整個時間片。

練習自旋鎖（Spinlock）的題目

關於自旋鎖（spinlock），下列說明何者正確？

  1. A在鎖被釋放之前，讓執行緒休眠並由作業系統喚醒的鎖
  2. B在鎖被釋放之前，以迴圈持續檢查鎖的變數來等待的鎖
  3. C旋轉磁碟以保護資料的機制
查看答案與解析

正確答案：B. 在鎖被釋放之前，以迴圈持續檢查鎖的變數來等待的鎖

自旋鎖會以原子指令嘗試取得鎖，若取不到就立刻反覆再試。由於沒有呼叫作業系統來休眠與喚醒的額外負擔，在持有鎖的時間極短時運作很快。常用於作業系統核心內，或與中斷處理常式之間的互斥。另一方面，它的缺點是等待期間仍會持續占用CPU。

下列何者是最不適合使用自旋鎖的情境？

  1. A持有鎖的時間很長，等待的執行緒白白持續占用CPU的情境
  2. B持有鎖的時間只有數十奈秒，非常短的情境
  3. C在作業系統核心內，無法休眠的處理情境
查看答案與解析

正確答案：A. 持有鎖的時間很長，等待的執行緒白白持續占用CPU的情境

以自旋鎖等待的執行緒，在鎖被釋放之前會持續使用CPU。若持有鎖的時間很長，那段CPU時間就全部浪費，也會妨礙其他執行緒的執行。尤其只有一個核心時，除非持有鎖的執行緒被執行，否則鎖不會被釋放，所以等待會持續到時間配額用完為止。長時間的等待應使用休眠等待的互斥鎖，也有先自旋一小段時間再休眠的方式。

常見問題

自旋鎖和互斥鎖（mutex）有什麼不同？

自旋鎖以反覆檢查鎖變數的迴圈來等待，會持續佔用 CPU，只有在等待非常短時才有效率。互斥鎖則讓等待的執行緒休眠、讓其他執行緒執行，適合較長的等待，但會增加休眠、喚醒與情境切換的成本。

什麼時候該用自旋鎖？

當臨界區段非常短且執行緒在不同核心上執行時，或是在不允許休眠的核心情境（例如中斷處理常式）中使用。若鎖可能被長時間持有，或是在單核心系統上，則應避免使用。

什麼是 test-and-test-and-set？

這是一種自旋鎖技巧，等待者以一般載入從自己的快取反覆讀取鎖，只有在鎖看起來空閒時才嘗試原子的 test-and-set。這能避免快取行不斷失效，大幅減少一致性流量。
