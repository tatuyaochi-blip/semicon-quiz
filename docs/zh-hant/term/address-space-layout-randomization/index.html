什麼是ASLR（位址空間配置隨機化）

Address Space Layout Randomization 的縮寫。每次執行都改變堆疊、堆積區、共享函式庫與可執行檔的位址，使攻擊者難以預測位址的防護措施。

日文名稱: ASLR

「ASLR（位址空間配置隨機化）」出現在1領域的3道練習題中（連結器與載入器與執行檔格式等）。

ASLR 如何移動行程

程式啟動時，核心與動態載入器會為位址空間的每個主要區域選擇隨機且對齊分頁的基底偏移量：堆疊、堆積、映射共享函式庫的 mmap 區域，以及建置為位置無關可執行檔（PIE）時的可執行檔本身。各區域的相對順序維持慣常的樣子（text、data、BSS 與堆積在低位址，堆疊在頂端），但它們的絕對位址每次執行都不同。因此，位址空間配置隨機化（ASLR）改變的是東西放在哪裡，而不是程式做什麼。

攻擊者為何需要位址

堆疊緩衝區溢位等記憶體破壞攻擊，通常會以某個有用目標的位址覆寫返回位址或函式指標：堆疊上的 shellcode、return-to-libc 攻擊中的 system() 等函式庫函式，或是返回導向程式設計（ROP）中的一連串指令片段。這些都需要精確的位址。有了 ASLR，攻擊者必須猜測位址，猜錯通常只會讓行程當掉，而不會交出控制權。這種保護是機率性的，因此其強度取決於可用的隨機位元數，而 32 位元位址空間的隨機位元遠比 64 位元少。

PIE 與位置無關程式碼

ASLR 只能移動不假設固定載入位址的程式碼。共享函式庫長期以來都編譯為位置無關程式碼（PIC），透過 PC 相對定址與全域偏移表（GOT）存取資料。然而舊式可執行檔是針對固定位址連結的，因此主程式的程式碼停留在已知位置，為攻擊者提供了可靠的 ROP gadget 來源。以 -fPIE 與 -pie 建置可讓可執行檔也能重定位，載入器便能將其一併隨機化。在 x86-64 上，由於原生支援 PC 相對資料存取，成本很小。

限制與搭配的防禦機制

隨機化是以區域為單位，因此只要洩漏函式庫中的一個指標，就會暴露整個函式庫的偏移量，進而得知其中每個函式的位置。由 fork() 建立的子行程會繼承父行程的配置，讓攻擊者可以反覆探測會 fork 的伺服器。因此 ASLR 會與不可執行的可寫記憶體（W^X 或 NX）、堆疊保護值（stack canary）以及控制流程保護搭配使用。作業系統核心也可以隨機化，稱為 KASLR。在 Linux 上，此設定可從 /proc/sys/kernel/randomize_va_space 查看。

練習ASLR（位址空間配置隨機化）的題目

關於ASLR（位址空間配置隨機化）的目的，下列何者正確？

  1. A每次執行時改變堆疊、堆積、函式庫等的位址，使攻擊者難以預測所瞄準的位址
  2. B隨機選擇記憶體位址，以提高快取命中率
  3. C隨機釋放未使用的記憶體，以增加可用容量
查看答案與解析

正確答案：A. 每次執行時改變堆疊、堆積、函式庫等的位址，使攻擊者難以預測所瞄準的位址

在利用緩衝區溢位等的攻擊中，知道函式庫函式與堆疊上資料的位址相當重要。ASLR會在每次啟動行程時，將堆疊、堆積、共用函式庫、執行檔的放置位址錯開，讓攻擊者無法預先鎖定位址。它單獨並不能完全防禦，需與寫入與執行分離等其他對策搭配使用。

常見問題

ASLR 能防止緩衝區溢位攻擊嗎？

不能。ASLR 並不會阻止溢位本身，只是讓攻擊者難以知道該跳到哪個位址，因此大多數嘗試會導致當機而非成功。只要有資訊洩漏暴露了一個真實位址，就可能將其破解，這也是它要與 NX 記憶體及堆疊保護值搭配的原因。

ASLR 和 PIE 有什麼差別？

ASLR 是作業系統的機制，每次執行時將記憶體區域載入到隨機位址。PIE 是一種編譯與連結可執行檔的方式，使其程式碼在任何位址都能運作，讓 ASLR 除了函式庫、堆疊與堆積之外，連主程式也能隨機化。

如何確認 Linux 上 ASLR 是否啟用？

讀取 /proc/sys/kernel/randomize_va_space：0 表示停用，1 會隨機化堆疊、mmap 區域與共享函式庫，2 則再加上以 brk 為基礎的堆積隨機化。大多數發行版預設為 2。
