什麼是Spectre

使分支預測出錯，讓處理器推測性地讀取機密資料，並從快取中殘留的痕跡推測其值的弱點類型。於 2018 年公布。

日文名稱: Spectre

「Spectre」出現在3領域的5道練習題中（硬體安全, 硬體安全的進階主題與趨勢, CPU與架構等）。

這個名詞所屬的領域: 硬體安全

Spectre 攻擊如何運作

典型的邊界檢查繞過形式，針對的是像 if (x < size) y = table[data[x] * 4096] 這樣的程式碼。攻擊者先以有效的 x 多次呼叫它，訓練分支預測器預期檢查會通過。接著，攻擊者在 size 不在快取中時提供超出範圍的 x。在等待 size 期間，CPU 會推測性地讀取 data[x]（實際上是記憶體中其他位置的機密位元組），並載入由該位元組選定的 table 快取行。檢查結果確定後，這些工作會被捨棄，但該快取行仍留在快取中；對每條 table 快取行計時存取，就能找出哪一條較快，從而得知機密。

架構狀態與微架構狀態

指令集架構（ISA）保證預測錯誤的路徑不會在程式可見的（即架構上的）狀態中留下痕跡：暫存器與記憶體會被精確地回復。微架構狀態，例如快取內容、分支預測表與轉換緩衝區，只是為了效能而存在，並不會被還原。Spectre 透過量測時間差（通常使用 flush-and-reload 技術），將這些隱藏狀態變成隱蔽通道。由於並未違反任何 ISA 規則，這個問題才會遍及許多廠商的處理器，也因此被描述為一類弱點，而非單一錯誤。

Spectre 與 Meltdown 的比較

同時公布的 Meltdown，利用了某些設計中的亂序執行：在權限錯誤被引發之前，使用者模式的載入就能將核心資料轉送給相依的指令。它主要先透過作業系統分離核心與使用者頁表、再透過硬體變更而得到修正。Spectre 則是誘使受害者推測性地存取受害者本身有權定址的記憶體，並以分支預測器操控它。由於它依賴的是推測執行本身，而非某一種實作上的捷徑，因此幾乎影響所有高效能 CPU，且沒有單一的完整修正方法。

緩解措施及其代價

軟體防禦會在敏感的邊界檢查之後插入推測屏障，例如 x86 的 lfence，或以遮罩限制索引範圍，使推測性存取也維持在範圍內。污染間接分支預測的分支目標注入變體，則以 retpoline 程式碼序列，以及在特權或行程邊界之間限制或清除預測器狀態的微碼與硬體控制來對抗。瀏覽器降低了計時器精度，並將網站隔離在不同的行程中。每一項措施都會犧牲部分效能，因此只會套用在易受攻擊之處，而不是完全停用推測執行。

練習Spectre的題目

下列關於稱為Spectre的推測執行漏洞的原理，何者正確？

  1. A因CPU的運算錯誤，加法的結果會改變
  2. B依分支預測而推測執行的指令，即使結果被取消，載入快取的痕跡仍會殘留，並能以時間測量讀取出來
  3. C因推測執行而使CPU溫度過度上升
查看答案與解析

正確答案：B. 依分支預測而推測執行的指令，即使結果被取消，載入快取的痕跡仍會殘留，並能以時間測量讀取出來

CPU在分支結果確定之前，會先執行預測那一側的指令，預測錯誤時再捨棄結果。在Spectre中，攻擊者讓分支預測出錯，在原本不會執行的路徑上讀取機密資料，並使對應該值的位置被載入快取。即使結果被取消，快取的狀態也不會復原，因此可藉由快取旁路推測出該值。

下列關於為何即使推測執行的指令結果被取消，Spectre這類攻擊仍會洩漏資訊的原因，何者正確？

  1. A因為取消處理失敗，暫存器中殘留機密的值
  2. B因為推測執行的結果會被儲存到磁碟
  3. C因為被取消的只有暫存器等架構（architectural）狀態，快取等微架構（microarchitectural）狀態不會復原
查看答案與解析

正確答案：C. 因為被取消的只有暫存器等架構（architectural）狀態，快取等微架構（microarchitectural）狀態不會復原

CPU被設計成，對於程式可見的狀態（暫存器與記憶體的內容），預測錯誤時會完全復原。然而快取的內容與分支預測器的狀態等微架構狀態，屬於為了提升效能的內部狀態，不會被復原。即使遵守了ISA的約定，內部狀態仍會以時間差異的形式被外界看見，這正是此類漏洞的本質。

常見問題

現代 CPU 已經修正 Spectre 了嗎？

特定變體已透過微碼、編譯器與作業系統的變更以及硬體更新加以緩解，但在不放棄推測執行的情況下，無法根除這一類弱點。自 2018 年以來，仍持續有新的變體被發現。

Spectre 和 Meltdown 有什麼不同？

Meltdown 利用某些處理器中延遲的權限檢查，讓使用者程式碼讀取核心記憶體，修正方式相對直接。Spectre 則誤導分支預測，使程式推測性地洩漏它可定址的資料，因此影響範圍更廣，也更難緩解。

為什麼 Spectre 需要量測快取時間？

推測執行的結果會被捨棄，因此機密永遠不會出現在攻擊者可讀取的暫存器中。將其編碼為載入了哪一條快取行，再對載入計時，才能還原出該值。

    下列關於稱為Spectre的推測執行漏洞的原理，何者正確？

  • 因應Spectre的對策，有在條件分支之後插入停止推測執行的指令（x86的lfence等）、遮罩索引使範圍之外無法讀取、避免間接分支預測被濫用的寫法（retpoline等），以及藉由更新CPU微碼控制預測器等。
