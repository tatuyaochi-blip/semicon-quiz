什麼是中斷處理常式

發生中斷或例外時CPU所執行的處理。儲存被中斷處理的狀態，依原因進行相應處理後，回到原本的處理。原則上處理要盡可能簡短。

日文名稱: 割り込みハンドラ

「中斷處理常式」出現在2領域的5道練習題中（嵌入式與韌體, CPU與架構等）。

這個名詞所屬的領域: 作業系統與硬體

練習中斷處理常式的題目

主程式正以「reg |= mask;」（讀取、修改、寫回）操作暫存器的位元時，中斷處理常式改寫了同一暫存器的另一個位元，可能發生的問題與對策的組合，下列何者正確？

  1. A中斷所做的變更會被主程式的寫回覆蓋而消失。在操作期間禁止中斷，或使用各位元專用的設定、清除暫存器
  2. B暫存器損壞而再也無法使用。更換微控制器
  3. C什麼事都不會發生。不需要對策
查看答案與解析

正確答案：A. 中斷所做的變更會被主程式的寫回覆蓋而消失。在操作期間禁止中斷，或使用各位元專用的設定、清除暫存器

「reg |= mask」是讀取暫存器、做OR運算、再寫回的三個動作。若在讀取之後立刻發生中斷，處理常式改變了另一個位元，主程式仍會依據中斷前讀到的舊值寫回，使處理常式的變更消失。只要在操作期間禁止中斷，或使用只有寫入1的位元才會改變的設定用、清除用暫存器，一次寫入即可完成，就不會發生這個問題。

在中斷處理常式中應避免的事項，下列何者最為適當？

  1. A在旗標變數寫入1，通知主程式
  2. B清除表示中斷原因的位元
  3. C以printf輸出長字串，或是持續等待某事發生的迴圈這類耗時的處理
查看答案與解析

正確答案：C. 以printf輸出長字串，或是持續等待某事發生的迴圈這類耗時的處理

中斷處理常式若長時間執行，這段期間就無法回應其他中斷，主程式也會停住。printf需要花時間到輸出完成，內部還可能使用中斷，特別危險。處理常式中只應進行最低限度的處理，例如接收資料放入緩衝區、設立旗標，繁重的處理則交給主程式或工作（task）。也別忘了清除原因位元。

解析中的「中斷處理常式」

  • 中斷處理常式若長時間執行，這段期間就無法回應其他中斷，主程式也會停住。
