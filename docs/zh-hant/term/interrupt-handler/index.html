什麼是中斷處理常式

發生中斷或例外時CPU所執行的處理。儲存被中斷處理的狀態，依原因進行相應處理後，回到原本的處理。原則上處理要盡可能簡短。

日文名稱: 割り込みハンドラ

「中斷處理常式」出現在5領域的11道練習題中（作業系統與硬體, 嵌入式與韌體, CPU與架構等）。

這個名詞所屬的領域: 作業系統與硬體

接受中斷時會發生什麼事

當裝置發出中斷訊號時，CPU會完成目前的指令，保存原本要執行的下一個位址以及操作模式、旗標等狀態，然後跳到中斷處理常式，也稱為中斷服務常式（ISR），通常透過中斷向量表找到其位置。處理常式會保存它所使用的暫存器，處理中斷原因，清除裝置的中斷旗標，恢復狀態並執行中斷返回指令。被中斷的程式接著從停止的確切位置繼續執行，既不會被丟棄，也不會重新開始。

為什麼處理常式必須簡短

處理常式執行期間，同等或較低優先權的其他中斷通常會被擋住，主程式也會停住，因此冗長的處理常式會增加其他所有工作的延遲。printf這類緩慢的呼叫尤其危險，因為它們耗時，而且本身可能依賴中斷。好的處理常式只做最少的事，例如將接收到的資料搬進緩衝區或設定旗標，把繁重的處理留給主迴圈或任務。作業系統核心則將此正式化，把工作分成立即處理的部分與延後處理的部分。

與主程式共用資料

處理常式與主程式之間共用的變數會引發典型錯誤。若主程式在迴圈中等待一個只由處理常式設定的旗標，最佳化編譯器可能只將它載入暫存器一次，從此看不到更新；將其宣告為volatile可強制每次存取都讀寫記憶體。像reg |= mask這樣的讀取—修改—寫入操作，可能在讀取與寫入之間被中斷，抹掉處理常式對另一個位元所做的變更。短暫停用中斷或使用硬體的設定／清除暫存器可以避免這個問題，而多位元組變數則需要防止讀到不一致的值（torn read）。

排程與看門狗中的中斷

週期性的計時器中斷讓作業系統能從不主動讓出CPU的程式手中收回CPU，從而實現搶占式排程與內文切換。中斷是來自硬體的非同步事件，而分頁錯誤或除以零等例外則是由正在執行的指令同步引發，不過兩者都透過類似的處理常式進入核心。一個常見錯誤是在計時器中斷內無條件地重置看門狗計時器：即使主迴圈已經當掉，中斷仍持續觸發，看門狗就永遠偵測不到故障。

  2. B因為後半部分的處理由硬體自動完成，所以不需要軟體
  3. C為了縮短停止中斷的時間，並把繁重的處理留到之後再做

正確答案：C. 為了縮短停止中斷的時間，並把繁重的處理留到之後再做

在中斷處理常式執行期間，相同種類或優先順序較低的中斷多半必須等待，若進行冗長的處理，整個系統的回應就會變差。因此一開始只做緊急的處理，例如從裝置讀取狀態並通知已受理，而資料加工、向上層通知等耗時的處理，則留到之後允許中斷的一般環境下進行。處理總量並不會減少，後半部分也是由軟體執行。

主程式正以「reg |= mask;」（讀取、修改、寫回）操作暫存器的位元時，中斷處理常式改寫了同一暫存器的另一個位元，可能發生的問題與對策的組合，下列何者正確？

  1. A中斷所做的變更會被主程式的寫回覆蓋而消失。在操作期間禁止中斷，或使用各位元專用的設定、清除暫存器
  2. B暫存器損壞而再也無法使用。更換微控制器
  3. C什麼事都不會發生。不需要對策
查看答案與解析

正確答案：A. 中斷所做的變更會被主程式的寫回覆蓋而消失。在操作期間禁止中斷，或使用各位元專用的設定、清除暫存器

「reg |= mask」是讀取暫存器、做OR運算、再寫回的三個動作。若在讀取之後立刻發生中斷，處理常式改變了另一個位元，主程式仍會依據中斷前讀到的舊值寫回，使處理常式的變更消失。只要在操作期間禁止中斷，或使用只有寫入1的位元才會改變的設定用、清除用暫存器，一次寫入即可完成，就不會發生這個問題。

常見問題

中斷處理常式和ISR有什麼差別？

實際上沒有差別：中斷服務常式（ISR）是中斷處理常式的另一個名稱，即CPU回應中斷時所執行的程式碼。

為什麼與中斷處理常式共用的變數要宣告為volatile？

若沒有volatile，編譯器可能假設該變數在迴圈內不會改變而將它保留在暫存器中，使主程式永遠看不到處理常式的更新。volatile會強制每次存取都讀寫記憶體。

中斷和例外有什麼差別？

中斷是來自計時器或周邊裝置等硬體的非同步訊號，與目前的指令無關。例外則是由正在執行的指令同步引發，例如分頁錯誤或非法操作。
