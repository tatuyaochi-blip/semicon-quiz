什麼是堆疊指標

指向堆疊目前頂端位址的暫存器。在RISC-V中是sp(x2)。在多數ISA中，堆疊朝位址較小的方向延伸。

日文名稱: スタックポインタ

「堆疊指標」出現在5領域的6道練習題中（指令集與組合語言, CPU與架構, 作業系統與硬體等）。

這個名詞所屬的領域: 指令集與組合語言

堆疊指標追蹤的對象

堆疊是函式呼叫所用的後進先出（LIFO）記憶體區域，堆疊指標則是存放其目前頂端位址的暫存器。在 RISC-V 中是暫存器 x2，名稱為 sp；在 x86-64 上則是 RSP。在大多數 ABI 中，堆疊朝較低位址方向延伸，因此配置空間就是將堆疊指標減去某值，釋放則是加回去。x86 有專用的 push 與 pop 指令會自動調整 RSP，而 RISC-V 使用一般指令，例如先執行 addi sp, sp, -16，再以距 sp 的偏移量進行儲存。

堆疊框與函式呼叫

進入函式時，其序言（prologue）會將堆疊指標往下移，以保留一個堆疊框。堆疊框存放返回位址（若該函式還會呼叫其他函式）、它將使用的被呼叫者保存暫存器，以及放不進暫存器的區域變數。在標準 RISC-V 呼叫慣例中，前 8 個整數參數經由暫存器 a0–a7 傳遞，其餘參數則放在堆疊上距 sp 固定偏移的位置。尾聲（epilogue）會還原暫存器並把堆疊框大小加回去。由於每次呼叫都有自己的堆疊框，遞迴自然就能運作。

堆疊溢位與堆疊攻擊

堆疊的大小有限，由作業系統為每個執行緒設定；在微控制器上則由初始化堆疊指標的連結器指令檔與啟動程式碼決定。過深的遞迴或大型區域陣列會使堆疊指標超出界限，形成堆疊溢位，破壞其他記憶體或觸發錯誤。由於返回位址就位於堆疊上、緊鄰區域緩衝區，寫入超出區域陣列尾端時可能覆寫返回位址，這是一種經典攻擊手法。堆疊保護值（stack canary）與不可執行堆疊是標準的防禦措施。

堆疊指標與框架指標

每當配置空間時堆疊指標就會移動，因此在一個函式內，到某個變數的偏移量可能會改變。框架指標（RISC-V 的 s0/fp，或 x86-64 的 RBP）可在進入函式時一次設定為堆疊框中的固定點，使區域變數與參數的位址偏移保持不變，也容易追溯堆疊回溯（stack trace）；最佳化編譯器常會省略它以騰出一個暫存器。在情境切換時，堆疊指標會與程式計數器及其他暫存器一起被保存，因為每個執行緒都有自己的堆疊，並且必須在其上恢復執行。

練習堆疊指標的題目

在RISC-V的標準呼叫慣例中，進入函式時的堆疊指標sp規定要對齊為16位元組的倍數。下列何者是最適當的理由？

  1. A因為堆疊的容量若不是16位元組的倍數，作業系統就無法啟動
  2. B因為要在sp的低4位元記錄函式的編號
  3. C因為即使將最大16位元組的大型資料放在堆疊上，也能不跨越邊界而有效率地讀寫
查看答案與解析

正確答案：C. 因為即使將最大16位元組的大型資料放在堆疊上，也能不跨越邊界而有效率地讀寫

資料若放在其大小的倍數的位址（對齊），就能不跨越邊界而一次讀寫。只要讓sp永遠保持為16的倍數，即使將8位元組的double或16位元組的long double等放在堆疊上，對齊也能維持。因此函式會以16的倍數來配置框的大小，即使只保存一個暫存器，也是「addi sp, sp, -16」。

常見問題

RISC-V 的堆疊指標是哪個暫存器？

在 RISC-V 中，堆疊指標是 x2，ABI 名稱為 sp。標準呼叫慣例讓它保持 16 位元組對齊，堆疊則朝較低位址延伸。

為什麼堆疊是往下長的？

這是大多數 ABI 採用的慣例，歷史上的便利之處在於堆積（heap）可從低位址往上長、堆疊從高位址往下長，兩者共用中間的空閒空間。方向由硬體或 ABI 定義，而往下長是目前最常見的方式。

堆疊指標和框架指標有什麼差別？

堆疊指標永遠標示堆疊目前的頂端，並隨空間配置而移動。框架指標在一次函式呼叫期間保持固定，為區域變數提供穩定的偏移量，除錯時也容易沿著堆疊框鏈結追溯。
