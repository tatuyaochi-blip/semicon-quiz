什麼是瀑布式模型

將需求定義、設計、程式撰寫、測試等工程由上游依序進行，原則上在前一工程的產出物確定後才進入下一工程的軟體開發模型。容易管理計畫與進度，但若在後面的工程才發現需求錯誤，重工的範圍會很大。

日文名稱: ウォーターフォールモデル

「瀑布式模型」出現在1領域的1道練習題中（軟體開發與專案管理等）。

這個名詞所屬的領域: 軟體開發與專案管理

練習瀑布式模型的題目

關於軟體開發的瀑布式模型，下列何者是其特徵？

  1. A將需求定義、設計、實作、測試等工程由上游依序進行，原則上在前一工程的產出物確定後才進入下一工程
  2. B反覆進行短期間的迭代，每次都做出可運作的軟體並納入使用者的意見
  3. C先製作原型（prototype）給使用者看，確認需求後再正式開發
查看答案與解析

正確答案：A. 將需求定義、設計、實作、測試等工程由上游依序進行，原則上在前一工程的產出物確定後才進入下一工程

瀑布式模型如同水由上往下流，依需求定義、設計、程式撰寫、測試的順序進行各工程的開發模型。每個工程都以審查確定產出物，因此容易擬定計畫與管理進度；但若在後面的工程才發現需求錯誤，重工的範圍就會很大。它適用於需求明確且不易變動的開發，或必須與硬體一起及早確定規格的開發。透過迭代納入使用者意見是敏捷開發等迭代式開發的特徵，以原型確認需求則是原型模型的特徵。
