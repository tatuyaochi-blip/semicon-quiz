什麼是系統呼叫

應用程式請求作業系統進行檔案讀寫或記憶體配置等的機制。以專用指令引發例外並切換到特權模式，呼叫核心的處理。

日文名稱: システムコール

「系統呼叫」出現在5領域的12道練習題中（作業系統與硬體, 硬體安全的進階主題與趨勢, 指令集與組合語言等）。

這個名詞所屬的領域: 作業系統與硬體

系統呼叫的逐步流程

在 RISC-V Linux 上，程式將系統呼叫編號放入暫存器 a7，將參數放入 a0 起的暫存器，然後執行 ecall。這個指令會刻意引發例外：CPU 記錄 ecall 的位址，切換到監督者模式，並跳到核心的陷阱進入點。核心儲存使用者暫存器，依編號查找處理常式，檢查參數，執行工作，並將結果放入 a0。接著它將儲存的位址推進到 ecall 之後，再以 sret 返回使用者模式。其他架構則使用 x86-64 的 syscall、Arm 的 svc 等指令。

系統呼叫與函式庫函式的差異

程式通常透過函式庫的包裝函式來使用系統呼叫，因此兩者的界線容易被忽略。像 printf 這樣的函式完全在使用者空間執行，將文字格式化到緩衝區中，只偶爾呼叫 write 系統呼叫將該緩衝區交給核心。許多函式庫函式，例如字串處理或數學常式，完全不會進入核心。系統呼叫的定義在於是否切換到特權模式，而不是函式的命名方式。

系統呼叫為何耗時

每次呼叫都要付出固定的額外負擔：模式切換、儲存與還原暫存器、參數驗證及返回。進入核心也會干擾快取與 TLB，而針對推測執行攻擊的對策，例如核心頁表隔離（KPTI），還會在每次進入時加上一次頁表切換。因此，每次呼叫只寫入一個位元組，會比在使用者空間緩衝數 KB 再以一次呼叫寫入慢得多。

避免呼叫的方法

除了緩衝之外，程式也可以用 mmap 將檔案對映到記憶體，之後的讀取就是一般的載入，首次存取時由頁面錯誤處理，而不必每次讀取都進行一次呼叫。以一次呼叫提交多個操作的介面，可進一步減少跨越次數。某些作業系統也會將唯讀的核心資料（例如目前時間）對映到使用者空間，使頻繁的查詢完全不需要陷阱。

練習系統呼叫的題目

寫出小量資料時，與其逐位元組每次都呼叫系統呼叫，不如先暫存在使用者空間的緩衝區再一併寫出，速度會比較快，其主要理由為何？

  1. A因為一併寫出後，要寫出的資料總量本身會減少
  2. B因為可以藉由減少次數，來壓低每次系統呼叫的固定負擔
  3. C因為暫存在緩衝區的話，不使用磁碟也能保存資料
查看答案與解析

正確答案：B. 因為可以藉由減少次數，來壓低每次系統呼叫的固定負擔

系統呼叫每次都需要從使用者模式切換到特權模式、儲存暫存器、檢查引數、返回等處理，即使處理的量只有1位元組，也會產生這些固定的負擔。此外，進入核心還會擾亂快取與TLB的內容。若先暫存在緩衝區，再以數KB為單位一併寫出，系統呼叫的次數就會大幅減少，整體也會變快。要寫出的資料總量不變，最終也會寫入磁碟。

某項處理在加入推測執行的對策之前需要10秒，期間呼叫了500萬次系統呼叫。假設加入對策後，每次系統呼叫的處理時間從0.4 µs增加為0.6 µs，其他部分的時間不變。整個處理時間的增加比例是下列何者？

  1. A約10%
  2. B約30%
  3. C約50%
查看答案與解析

正確答案：A. 約10%

系統呼叫所花的時間，對策前為 500萬次 × 0.4 µs = 2秒，對策後為 500萬次 × 0.6 µs = 3秒。增加的是1秒，整體從10秒變為11秒，增加比例為 1 ÷ 10 = 10%。即使每次系統呼叫慢了1.5倍（增加50%），對整體的影響仍取決於該部分所占的時間比例（此處為20%）。因此，在KPTI這類對策中，系統呼叫或中斷越多的資料庫與輸入輸出處理，效能下降越大。

常見問題

系統呼叫和中斷有什麼不同？

系統呼叫是程式以專用指令刻意觸發的同步陷阱。中斷則是來自計時器或裝置等硬體的非同步訊號，無論程式正在做什麼都會到來。

printf 是系統呼叫嗎？

不是。printf 是在使用者空間格式化輸出的 C 函式庫函式；它最終會呼叫 write 系統呼叫，將緩衝的資料交給核心。

為什麼系統呼叫很慢？

每次呼叫都要切換到特權模式、儲存狀態、驗證參數並返回，還會干擾快取與 TLB。這個成本每次呼叫都是固定的，因此大量的小型呼叫會累積起來。
