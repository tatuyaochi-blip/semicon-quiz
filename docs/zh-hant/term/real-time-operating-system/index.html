什麼是RTOS（即時作業系統）

依優先權切換多個任務，使其能在規定時間內回應的嵌入式作業系統。例如 FreeRTOS 與 Zephyr。

日文名稱: RTOS(リアルタイムOS)

「RTOS（即時作業系統）」出現在1領域的7道練習題中（嵌入式與韌體等）。

這個名詞所屬的領域: 嵌入式與韌體

RTOS 如何排程任務

即時作業系統（RTOS）將韌體組織成多個任務，每個任務都有優先權與狀態，例如就緒、執行中或阻塞。大多數 RTOS 採用可搶占的優先權排程：當中斷或訊息使較高優先權的任務進入就緒狀態時，核心會儲存執行中任務的上下文並立即切換，被中斷的任務之後再從停止處繼續執行。由硬體計時器產生的週期性節拍（通常為 1 ms）驅動逾時與延遲；例如 16 MHz 除以 16 的預除頻器可得到 1 µs 的計數，每 1000 個計數產生一次中斷，即為 1 ms 的節拍。

即時代表可預測，而不只是快

其目標是讓馬達控制或通訊協定等關鍵工作具有有上限且可預測的回應時間，而不是最大的平均產出量。通用作業系統以公平性與產出量為最佳化目標，可能以無法預測的方式延遲任務；RTOS 則保持核心精簡、排程決策具確定性，這也讓它能在記憶體很少的微控制器上執行。在沒有任何作業系統時，韌體常使用超級迴圈：在 while (1) 迴圈中依序呼叫每項工作，由中斷處理緊急事件並設定旗標。這種方式簡單又精簡，但只要有一項工作較慢，就會拖延所有工作，這時 RTOS 就值得採用。

任務之間的通訊

RTOS 提供各種基本機制，讓任務不必忙碌等待就能協作。訊息佇列讓感測器任務送出讀值，而顯示任務則在阻塞狀態下休眠、不使用 CPU，直到資料到達；緩衝多筆資料可吸收暫時的速度差異，避免資料遺失。互斥鎖保護匯流排或緩衝區等共用資源，號誌用於通知事件（通常來自中斷處理常式），而定時等待則讓任務可以帶逾時地阻塞。使用這些機制取代共用變數與輪詢旗標，可以避免資料競爭與浪費週期。

優先權反轉與優先權繼承

優先權反轉發生在高優先權任務等待由低優先權任務持有的互斥鎖，而一個無關的中優先權任務又搶占了低優先權任務時。低優先權任務無法完成並釋放互斥鎖，因此高優先權任務實際上被中優先權任務阻擋了不定長的時間。1997 年火星拓荒者號登陸器就因此反覆發生系統重置。優先權繼承的解決方法是暫時將互斥鎖持有者的優先權提高到等待任務的優先權，直到它釋放資源為止，許多 RTOS 的互斥鎖都內建此選項。

練習RTOS（即時作業系統）的題目

在嵌入式裝置中使用RTOS（即時作業系統）的主要目的，下列何者正確？

  1. A在畫面上顯示美觀的視窗
  2. B使處理的平均速度一定比個人電腦的OS更快
  3. C依優先順序切換多項處理（工作），使其能在規定的時間內回應
查看答案與解析

正確答案：C. 依優先順序切換多項處理（工作），使其能在規定的時間內回應

RTOS將處理分成工作（task），一旦優先順序較高的工作成為可執行，就立即切換執行。目的是讓馬達控制或通訊回應這類延遲就會出問題的處理，能確實在規定時間內完成。同時也備有在工作之間傳遞資料的佇列、保護資源的互斥鎖（mutex），以及等待時間的功能等。例如FreeRTOS、Zephyr、μITRON等。

在搶先式（preemptive）RTOS中，執行優先順序較低的工作時，優先順序較高的工作收到了等待的資料而成為可執行狀態。一般會發生什麼事？

  1. A高優先順序的工作要等到低優先順序的工作自行結束
  2. B兩個工作都停止，微控制器重新啟動
  3. C中途停止低優先順序的工作，立即切換到高優先順序的工作
查看答案與解析

正確答案：C. 中途停止低優先順序的工作，立即切換到高優先順序的工作

在搶先式RTOS中，當中斷等原因使優先順序較高的工作成為可執行狀態，核心會儲存並停止執行中的低優先順序工作狀態，切換到高優先順序的工作。高優先順序的工作結束或進入等待狀態後，低優先順序的工作會從中斷處繼續執行。因此能縮短高優先順序處理的回應時間，並使其容易預測。

常見問題

RTOS 和 Linux 這類通用作業系統有什麼差別？

RTOS 的設計目標是可預測的最差回應時間，採用嚴格的優先權搶占，且占用資源少。通用作業系統以平均產出量與公平性為最佳化目標，提供更豐富的服務，但時序的確定性較低。

RTOS 的優先權反轉是什麼？

高優先權任務卡在等待低優先權任務持有的資源，而低優先權任務本身又被中優先權任務搶走執行時間。優先權繼承會暫時提高持有者的優先權來防止這種情況。

什麼時候該用 RTOS 而不是超級迴圈？

當有多個時序要求不同的活動，而超級迴圈中的長時間工作會拖延時間關鍵的工作時。簡單、負載輕的韌體通常用超級迴圈加中斷就足夠了。
