什麼是寫入配置(Write-allocate)

寫入時發生快取失誤，先將該行載入快取再進行寫入的方式。多與寫回方式組合使用。不載入而直接寫到下層的方式稱為非寫入配置。

日文名稱: ライトアロケート

「寫入配置(Write-allocate)」出現在1領域的4道練習題中（記憶體階層與效能等）。

這個名詞所屬的領域: 記憶體階層與效能

寫入失誤時會發生什麼

採用寫入配置時，發生失誤的儲存會先從下層擷取整條快取行並放入快取，再將要儲存的位元組合併進去。在寫回快取中，該行接著會被標記為髒，直到之後被逐出時才寫入記憶體。在多核心系統中，這次擷取也會取得該行的獨占所有權，因此其他核心的副本會在寫入前失效；這種為取得所有權而讀取（read-for-ownership）的動作，正是儲存失誤在記憶體匯流排上看起來像讀取的原因。

寫入配置與非寫入配置的比較

非寫入配置會將失誤的儲存直接送往下層，而不動到快取。當寫入的資料很快會再次被讀取或寫入時，寫入配置較划算，因為之後的存取會命中；因此它通常與寫回搭配。非寫入配置適合只寫一次且不再使用的資料，通常與寫穿搭配。請注意，寫回或寫穿決定的是命中時如何傳遞，而配置與否決定的是失誤時的處理方式；兩者是各自獨立的選擇。

只寫資料的隱藏成本

當程式寫入一個近期不會讀取的大型緩衝區時，例如清除記憶體或產生輸出，寫入配置會先從記憶體讀取每一條快取行，只是為了覆寫它，之後再寫回，使通訊量大約加倍。這些快取行也會逐出有用的資料。非時間性（non-temporal）或串流式儲存可避免這個問題，它們會合併寫入並直接送往記憶體。有些 ISA 也提供不擷取舊內容即可將整條快取行清零的指令。

相關的失誤處理技術

寫入配置決定是否將快取行帶入，但其他技術會影響失誤需要多久時間。關鍵字優先（critical word first）會先送出所要求的字，再送 64 位元組快取行的其餘部分，讓 CPU 能提早恢復執行。寫入緩衝區可在寫穿快取中隱藏儲存延遲，受害者快取（victim cache）則保存最近被逐出的快取行。它們各自針對失誤成本的不同部分，這是常見的混淆來源。

練習寫入配置(Write-allocate)的題目

在直寫（write-through）快取中，設置寫入緩衝器（write buffer）的主要目的為下列何者？

  1. A讓CPU不必等待對主記憶體的寫入完成，即可進行下一個處理
  2. B讓快取中的資料保持比主記憶體更新的狀態
  3. C對寫入時未命中的快取行，一定先從主記憶體載入快取後再寫入
查看答案與解析

正確答案：A. 讓CPU不必等待對主記憶體的寫入完成，即可進行下一個處理

直寫方式每次寫入時也會寫入主記憶體，若直接等待其完成，CPU會頻繁停頓。若將寫入暫時存放在寫入緩衝器，CPU就能立刻進入下一條指令，由緩衝器在背景寫出到主記憶體。讓快取比主記憶體更新是寫回（write-back）方式的性質，在直寫中兩者反而是一致的。未命中的快取行是否要載入，是寫入配置（write-allocate）的選擇，與寫入緩衝器是不同的問題。

寫入時發生快取未命中，不載入該快取行而直接寫入下一層階層的方式為下列何者？

  1. A寫入配置（write-allocate）
  2. B寫回（write-back）
  3. C不寫入配置（no-write-allocate）
查看答案與解析

正確答案：C. 不寫入配置（no-write-allocate）

寫入未命中時不載入快取行、直接寫入下一層階層的方式是不寫入配置，多與直寫方式搭配使用。對於寫過一次就不會再讀回的資料，可以省去多餘的載入。寫入配置則相反，是先載入快取行再寫入的方式，在寫入的資料馬上又會被使用的情況下有利，因此多與寫回方式搭配使用。寫回是決定寫入命中時如何處理的方式，與未命中時是否載入屬於不同的軸線。

常見問題

寫入配置和非寫入配置有什麼不同？

在寫入失誤時，寫入配置會將快取行載入快取並在快取中寫入；非寫入配置則直接寫入下層，不載入該行。

為什麼寫入配置通常與寫回搭配？

快取行一旦進入寫回快取，之後對它的寫入都會命中，並在不產生記憶體通訊量的情況下被吸收，因此最初擷取的成本得以回收。

非時間性儲存（non-temporal store）有什麼用途？

它們將近期不會再使用的大量資料直接寫入記憶體，避免寫入配置所造成的逐行讀取，並讓快取保留給有用的資料。
