什麼是KV 快取（KV cache）

在大型語言模型的推論中，保存已處理過之詞元的注意力 Key 與 Value 的記憶體。可避免重新計算，但會隨文章長度與批次而變大。

日文名稱: KVキャッシュ

這個名詞所屬的領域: AI硬體與軟體堆疊

LLM 推論為何要保存 Key 與 Value

Transformer 語言模型一次產生一個詞元。在每個注意力層中，新詞元的 query 會與所有先前詞元的 key 比較，其結果用來加權它們的 value。由於注意力是因果性的，先前詞元的 key 與 value 一旦算出就不會再改變。KV 快取按層儲存它們，因此每個解碼步驟只需計算新詞元的 query、key 與 value，並將後兩者附加上去，而不必重新處理整個序列。這把反覆的完整重算轉變為每個詞元一份適度的成本。

KV 快取會有多大

快取大小為 2（key 與 value）× 層數 × 每層的 key/value 維度 × 詞元數 × 批次大小 × 每個元素的位元組數。舉例來說，一個 32 層、隱藏維度 4096、使用標準多頭注意力的模型，在 FP16 下每個詞元約需 0.5 MB。於是 4096 詞元的上下文每個序列約需 2 GB，8 個這樣的序列組成的批次約需 16 GB，超過 70 億參數 FP16 模型的權重所佔的約 14 GB。

預填、解碼與記憶體頻寬

推論分為兩個階段。預填（prefill）以平行方式處理整個提示詞，並將其 key 與 value 寫入快取；這個階段主要受限於運算。接著解碼（decode）每一步產生一個詞元，每一步都必須讀取模型權重以及該序列的整個 KV 快取，因此通常受限於記憶體頻寬。較大的批次讓更多請求分攤權重的讀取，提高吞吐量，但也會讓 KV 快取變大、每一步變長，增加個別請求的延遲。

縮小與管理 KV 快取的方法

有多種技術可以減輕 KV 快取的壓力。分組查詢注意力（GQA）與多查詢注意力（MQA）讓多個 query 頭共用一組 key 與 value 頭，按比例縮小快取。以 8 位元或更低的精度儲存快取，相較於 FP16 可減半或更進一步降低記憶體用量。以固定大小的小區塊配置快取，而不是為每個序列按最大長度配置一整塊連續區域，可以避免碎片化，讓更多請求放得下；這也讓具有共同提示詞前綴的序列能共用區塊。有些模型還會將注意力限制在最近詞元的滑動視窗內。

常見問題

大型語言模型的 KV 快取是什麼？

它是保存已處理詞元之注意力 key 與 value 的記憶體，讓每個新產生的詞元只需計算自己的 key 與 value，而不必重新計算整個序列。

為什麼 KV 快取這麼吃記憶體？

它的大小與層數、注意力寬度、上下文長度以及批次大小成線性增加，因此長上下文或大量同時請求可能使它比模型權重還大。

KV 快取會影響輸出品質嗎？

快取精確的 key 與 value 在數學上等同於重新計算；只有低精度快取儲存或捨棄舊詞元等近似做法才可能改變輸出。
