什麼是計算圖（Computational graph）

以節點表示運算、以箭頭表示張量傳遞，來表現模型運算的圖。是自動微分與 AI 編譯器最佳化的基礎。

日文名稱: 計算グラフ

「計算圖（Computational graph）」出現在1領域的4道練習題中（AI硬體與軟體堆疊等）。

這個名詞所屬的領域: AI硬體與軟體堆疊

節點、邊及其承載的內容

計算圖通常是有向無環圖。節點是運算，例如矩陣乘法、卷積、加法或激活函數；邊是張量，每個張量都有已知的形狀與資料型別，從產生它的運算流向使用它的運算。輸入與可訓練的權重則以來源節點表示。由於相依關係是明確的，計算圖能讓人一眼看出哪些運算可以平行執行、哪些必須等待；它也為軟體提供一份完整、可分析的模型描述，與建立它的 Python 程式碼無關。

計算圖與自動微分

訓練需要求出損失對每個權重的梯度。在前向傳遞期間，框架會記錄計算圖；接著反向模式自動微分會從損失開始反向走訪計算圖，套用每個運算的局部導數規則與連鎖律來累積梯度，這就是反向傳播。這需要在前向傳遞中保存的中間輸出（激活值），這也是訓練比推論使用多得多的記憶體的原因。激活檢查點（activation checkpointing）會捨棄部分激活值，並在反向傳遞時重新計算，以運算換取記憶體。

靜態圖與動態圖

在靜態的先定義後執行（define-and-run）風格中，會先建構整張圖再執行，容易進行全域最佳化，但依賴資料的控制流程與除錯會變得複雜。在動態的邊執行邊定義（define-by-run）或即時（eager）風格中，運算在程式執行時立即執行，並同步記錄計算圖，具有彈性，但幾乎沒有跨運算最佳化的空間。現代框架通常混合兩者：程式碼以即時方式撰寫，再透過編譯步驟追蹤或擷取計算圖，讓編譯器在執行前加以最佳化。

編譯器與執行環境如何運用計算圖

AI 編譯器會在產生程式碼之前改寫計算圖。運算子融合會將矩陣乘法、加偏差與激活函數等一連串運算合併成一個核心，使中間張量留在晶片上的記憶體中，而不必往返 DRAM。其他處理步驟包括常數折疊、移除未使用的節點、選擇張量的記憶體配置、為配合快取或暫存記憶體而進行分塊，以及重複使用生命週期不重疊之緩衝區的記憶體規劃。ONNX（Open Neural Network Exchange）等交換格式會將計算圖與權重序列化，讓不同的執行環境與硬體工具鏈能執行同一個模型。

計算圖是將矩陣相乘、加法、啟動函數等運算作為節點，將在它們之間流動的張量作為箭頭的模型計算藍圖。框架逆向走訪這張圖，自動計算反向傳播的梯度，編譯器則檢視整張圖來進行融合與重新排序的最佳化。哪些運算彼此獨立而可以平行進行，也能從圖中看出。

常見問題

深度學習中的計算圖是什麼？

它將模型表示為由彼此傳遞的張量（邊）所連接的運算（節點）。框架利用它自動計算梯度，編譯器則利用它最佳化執行。

為什麼運算子融合能加速神經網路？

激活函數與正規化等許多運算受記憶體限制，將其輸出寫入 DRAM 再讀回所花的時間佔了大部分。將它們融合成一個核心，可讓中間結果留在晶片上，減少記憶體通訊量。

即時執行（eager execution）和圖模式有什麼不同？

即時執行會在 Python 執行到每個運算時立即執行它；圖模式則先建構或擷取整張圖，再加以最佳化並執行。即時執行較容易除錯；圖模式則可進行融合與其他針對整個模型的最佳化。
