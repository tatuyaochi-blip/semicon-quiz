什麼是進入點（Entry point）

開始執行程式的位址。記錄於 ELF 標頭。在 C 語言中通常不是 main，而是 _start 等啟動程式碼，先進行初始化後再呼叫 main。

日文名稱: エントリポイント

「進入點（Entry point）」出現在1領域的1道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

進入點與 main 的區別

進入點是載入器轉交控制權時第一條指令的位址，儲存在執行檔的標頭中，例如 ELF 檔案的 e_entry 欄位。對 C 程式而言，進入點通常不是 main。連結器會加入 C 執行環境的啟動物件，例如 crt1.o，並將其中的 _start 符號設為進入點。對 C 程式碼來說，main 看起來是起點，但它只是被這段啟動程式碼呼叫的普通函式。必要時，連結器允許指定不同的進入符號。

啟動程式碼做了什麼

在 Linux 上，核心啟動新行程時，會在堆疊上排好 argc、argv 指標、環境變數指標與輔助向量（auxiliary vector）。_start 常式會蒐集這些資料、對齊堆疊，並呼叫 C 函式庫的初始化，後者會設定標準函式庫、執行全域物件的建構子與初始化函式，然後呼叫 main。當 main 返回時，其回傳值會傳給 exit，exit 會執行已註冊的 atexit 處理函式、清空緩衝的輸出，最後要求核心終止該行程。

動態連結的程式

動態連結的執行檔會在程式標頭中指定其動態連結器，例如 Linux 上的 ld.so。核心會同時映射程式與動態連結器，並從動態連結器自己的進入點開始執行，而不是從程式的進入點。動態連結器載入所需的共享函式庫、套用重定位、繫結符號並執行函式庫的初始化函式，然後跳到程式的進入點 _start。因此在動態連結的行程中，在程式自己的第一條指令之前，就已經執行了相當多的程式碼。

核心與微控制器中的進入點

這個術語也涵蓋其他開始執行的地方。作業系統會向 CPU 註冊例外與中斷的進入點；例如在 RISC-V 上，ecall 指令會引發例外，切換到較高的特權模式，並跳到作業系統所設定的陷阱向量（trap vector）。在裸機微控制器上，重置向量指向啟動程式碼，由它準備堆疊、將已初始化資料從快閃記憶體複製到 RAM、將未初始化的 .bss 區段清零，之後才呼叫 main。

查看答案與解析

正確答案：C. 通常不是main，而是_start等啟動用的程式碼，完成初始化後才呼叫main

連結器會將C執行期（runtime）所提供的啟動用目的檔（crt1.o等）嵌入程式，並以其中的_start作為入口。_start會從堆疊取出命令列引數，進行標準函式庫與全域物件的初始化後，才呼叫main。main返回後，則使用其回傳值呼叫exit，進行結束處理。

常見問題

main 是 C 程式的進入點嗎？

通常不是。執行檔的進入點是 _start 之類的啟動程式碼，它會準備引數與執行環境、呼叫 main，然後將 main 的回傳值傳給 exit。

ELF 檔案的進入點存放在哪裡？

存放在 ELF 標頭的 e_entry 欄位中，它保存程式載入後開始執行的虛擬位址。

C 程式在 main 之前會執行什麼？

C 執行環境的啟動程式碼、函式庫初始化以及全域物件的建構子；在動態連結的程式中，動態連結器還會先載入共享函式庫並進行重定位。
