什麼是全相聯快取

任何資料都可放在快取內任何位置的快取結構。不會發生衝突失誤，但必須與所有標籤比對，不適合大型快取。用於TLB等。

日文名稱: フルアソシアティブ方式

「全相聯快取」出現在1領域的1道練習題中（記憶體階層與效能等）。

這個名詞所屬的領域: 記憶體階層與效能

沒有索引，只有標籤與位移

在全相聯快取中，整個快取就是一個集合，因此任何區塊都可以存放在任何一條快取線中。不需要用來選擇集合的位元：索引為 0 位元，位址只分成快取線內的位移，以及由其餘所有位元構成的標籤。每次存取時，都必須將要求的標籤同時與所有有效快取線的標籤比較，這通常以內容可定址記憶體（CAM）實現，其中每個項目都有自己的比較器。

為什麼只用於小型結構

具有 N 個項目的 CAM，每次查詢都需要 N 個寬比較器同時運作，還需要一個大型多工器來輸出相符的資料。面積、功耗與命中時間都隨項目數迅速增加，因此大型資料快取改用集合相聯。全相聯適合用在使用頻繁、且每次失誤代價都很高的小型結構中，在那裡它既負擔得起又值得，例如快取頁表項目的轉譯後備緩衝區（TLB），或保存最近從直接映射快取逐出之快取線的小型受害者快取。

替換策略決定效能

由於任何一條快取線都可能被逐出，快取需要替換策略。最近最少使用（LRU）會逐出最久未被存取的快取線。在只有兩條快取線、參考序列為 A、B、A、C、B、A 的情況下，LRU 會產生五次失誤：A 的命中使 C 到來時 B 成為受害者，接著 A 與 C 依序被逐出。項目很多時，追蹤真正的 LRU 成本很高，因此硬體常使用偽 LRU（pseudo-LRU）或隨機替換。對於比快取稍大的循環存取模式，LRU 的表現也很差，此時隨機替換可能表現更好。

全相聯無法解決的問題

全相聯消除了衝突失誤，因為區塊永遠不會爭奪特定的集合。事實上，在常用的三分類模型中，衝突失誤的定義正是相同大小的全相聯快取所能避免的失誤。首次存取的強制性失誤仍然存在，工作集大於整個快取時的容量失誤也是。這些需要更大的快取、預取，或重構程式碼以更早重複使用資料，例如迴圈分塊（tiling）。

練習全相聯快取的題目

容量為2條快取行、採LRU替換的全相聯快取一開始為空，依A、B、A、C、B、A的順序參照區塊時，會發生幾次未命中？

  1. A4次
  2. B5次
  3. C6次
查看答案與解析

正確答案：B. 5次

依序追蹤：A（未命中，[A]）、B（未命中，[A,B]）、A（命中，A變成最近使用）、C（未命中，逐出最舊的B，[A,C]）、B（未命中，逐出最舊的A，[C,B]）、A（未命中，逐出最舊的C，[B,A]），共未命中5次。算成4次，是例如在放入C時誤以為逐出了A等的算法，在LRU中重點在於命中的A已變成最新。6次是漏看第3次A的命中所得的次數。

常見問題

全相聯快取有幾個索引位元？

零個。整個快取是單一集合，因此位址只由標籤與位移組成，標籤要與每一條快取線比較。

為什麼 TLB 常採用全相聯？

TLB 很小，而每次失誤都會引發代價高昂的頁表查找（page-table walk），因此為了完全避免衝突失誤，額外的比較器是值得的。

全相聯快取能消除所有失誤嗎？

不能。它能消除衝突失誤，但首次使用時的強制性失誤，以及工作集大於快取所造成的容量失誤仍會發生。
