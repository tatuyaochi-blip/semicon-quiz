什麼是頁面錯誤

存取的頁面未配置到實體記憶體，或進行了不被允許的存取類型時，CPU引發的例外。作業系統準備好頁面後重新執行指令，或將其視為非法存取處理。

日文名稱: ページフォルト

這個名詞所屬的領域: 作業系統與硬體

頁面錯誤發生時會怎樣

記憶體管理單元（MMU）在轉譯虛擬位址時會檢查分頁表項目。若該項目無效，或存取類型不被允許，MMU 就會引發頁面錯誤，這是與造成錯誤之指令綁定的同步例外。作業系統的處理常式會檢查該位址是否屬於行程可使用的區域。若是，就找出一個空閒的實體頁框（必要時逐出另一個分頁），從磁碟載入內容或填入零，將項目標記為有效，然後重新執行造成錯誤的指令。若否，該行程就會收到區段錯誤（segmentation fault）。

次要錯誤與主要錯誤

並非每次頁面錯誤都會存取磁碟。次要（軟）錯誤不需 I/O 即可解決，例如分頁已經在記憶體的檔案快取中、只需要一個新的填零頁框，或因寫入時複製而必須複製。主要（硬）錯誤則必須從儲存裝置讀取分頁，需要數毫秒。兩者差異極大：在記憶體存取為 100 ns、錯誤處理時間為 8 ms 時，即使主要錯誤率只有每一百萬次存取一次，平均存取時間也會從 100 ns 增加到約 108 ns。

刻意利用頁面錯誤

作業系統把頁面錯誤當成延遲求值的工具。需求分頁會先對應程式而不載入，等到第一次存取時才載入每個分頁。記憶體對應檔案（mmap）也以相同方式讀取檔案內容。寫入時複製讓 fork 以唯讀方式共用分頁，只複製之後被寫入的分頁。沒有任何存取權限的防護頁位於堆疊之外，讓失控的遞迴觸發錯誤，而不是破壞資料。在 NUMA 系統上，Linux 會把分頁放在第一次寫入它的執行緒所在的節點上，因此初始化順序會影響效能。

頁面錯誤、TLB 未命中與快取未命中

這三者經常被混淆。快取未命中完全由硬體處理，硬體會從較低層的記憶體取回該快取行。TLB 未命中表示該轉譯沒有快取在轉譯後備緩衝區中；在大多數現代 CPU 上，由硬體分頁表走訪器取得轉譯，若項目有效，就不會發生例外。只有當分頁表項目本身無效或禁止該存取時，頁面錯誤才會交給作業系統處理。當頁面錯誤頻繁到系統大部分時間都在進行分頁時，這種狀況稱為輾轉（thrashing）。

常見問題

頁面錯誤是一種錯誤嗎？

不一定。大多數頁面錯誤是正常事件，用於需求分頁、寫入時複製與記憶體對應檔案；只有存取行程不被允許存取的位址時，才會變成區段錯誤之類的錯誤。

次要頁面錯誤和主要頁面錯誤有什麼差別？

次要錯誤不需磁碟 I/O 即可解決，例如對應一個已在記憶體中的分頁；主要錯誤則必須從儲存裝置讀取分頁，速度慢了數千倍。

頁面錯誤為什麼要重新執行指令，而不是跳過它？

造成錯誤的存取從未完成，因此作業系統修正對應關係後，會從頭重新執行該指令，讓程式像什麼事都沒發生一樣繼續執行。
