什麼是遠端證明（Remote attestation）

裝置以晶片內的金鑰簽署自己內部所執行軟體的狀態，出示給遠端伺服器，由其確認是否可信賴的機制。

日文名稱: リモートアテステーション

「遠端證明（Remote attestation）」出現在1領域的2道練習題中（硬體安全等）。

這個名詞所屬的領域: 硬體安全

證明的是什麼

遠端證明（remote attestation）是讓網路另一端的裝置，以可信的方式向遠端伺服器出示自己在什麼硬體上啟動了什麼軟體的機制。若只是由裝置內的軟體自己回答「我很正常」，被入侵的軟體也能給出同樣的回答。因此，裝置會把開機時記錄的量測值（軟體的雜湊值），以無法從晶片中取出的金鑰簽章後送出。一般會把角色分開來看：提出證據的裝置、驗證證據的驗證者，以及依據結果決定是否提供資料或服務的一方。

使用TPM的流程

在PC等系統中，開機的各階段會依序把下一個要執行之軟體的雜湊值擴充（extend）到TPM的PCR（量測啟動，measured boot）。進行驗證的伺服器送出用來防止重複使用的新亂數（nonce），TPM將PCR值與nonce一併以無法匯出的證明金鑰簽章（quote）。裝置再附上開機紀錄（事件日誌）回傳。伺服器驗證簽章，從事件日誌重新計算PCR值確認一致，並將各量測值與已知正確的值比對。至於金鑰確實屬於真正的TPM，則透過從TPM製造商延伸而來的憑證鏈來確認。

在機密運算與嵌入式裝置中的應用

在雲端的機密運算中，透過AMD SEV-SNP或Intel TDX等功能，由CPU量測加密虛擬機器的初始狀態，並輸出以CPU內部金鑰簽章的報告。使用者驗證報告、確認是預期中的虛擬機器之後，才交出解密資料用的金鑰。在智慧型手機上，用於證明金鑰是在安全硬體內產生，以及出示裝置的開機狀態。小型微控制器則會使用像TCG制定的DICE這類輕量方式，由每一層依據該層的量測值推導出金鑰。也用於確認連接企業網路之裝置的健全性。

可證明內容的限制

遠端證明所顯示的，是量測當下載入了什麼。若開機後執行中的軟體在記憶體中遭到攻擊，開機時的量測值可能不會改變。此外，若沒有配合軟體更新來維護正確值的清單，就可能拒絕正常的裝置，或接受舊的有漏洞版本。每台裝置的金鑰可能被用於追蹤個別裝置，因此也需要顧及隱私。證明的可信度，前提是能夠信任保護金鑰的硬體及其製造商。

在遠端證明中，機器將記錄於TPM或TEE的軟體度量值，以無法從晶片內取出的金鑰簽章後送給伺服器。伺服器驗證簽章與度量值，只對以指定軟體運作的機器提供機密資料或服務。用於委託雲端進行機密運算，或確認連接企業網路的機器等情況。

常見問題

什麼是遠端證明？

是裝置把自己內部所啟動軟體的量測值，以晶片內無法取出的金鑰簽章後送到遠端伺服器，由伺服器確認其是否處於可信狀態的機制。伺服器只對通過驗證的裝置提供機密資料、服務或網路存取。

與安全開機有什麼不同？

安全開機是讓簽章驗證失敗的軟體無法在該裝置內啟動的機制。遠端證明則是把啟動了什麼的紀錄出示給外部，由對方的伺服器做判斷。兩者會搭配使用。

nonce的用途是什麼？

驗證者每次送出新的亂數，裝置將其納入簽章內容，就能確認該報告是剛剛產生的。若沒有nonce，就無法防止攻擊者記錄裝置正常時的舊報告再重新送出（重放攻擊）。
