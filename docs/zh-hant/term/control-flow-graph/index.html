什麼是控制流程圖

以基本區塊為節點、區塊之間的分支或轉移為箭頭，表示程式執行流程的圖。用於迴圈的偵測與資料流的分析。

日文名稱: 制御フローグラフ

「控制流程圖」出現在1領域的3道練習題中（編譯器等）。

這個名詞所屬的領域: 編譯器

以基本區塊為節點

控制流程圖（CFG）是由基本區塊構成的：基本區塊是最長的指令序列，只能從第一條指令進入，也只能從最後一條指令離開。為了形成基本區塊，編譯器會標出領頭指令（leader），即函式的第一條指令、每個分支目標，以及緊接在分支之後的每條指令。每個區塊從一個領頭指令延伸到下一個領頭指令之前。由於區塊內的指令總是依序執行，因此共同子運算式消除等局部最佳化很容易在單一區塊內套用。

邊以及圖的形狀所揭示的資訊

邊代表可能的控制轉移：條件分支使區塊有兩個後繼者，即分支成立的目標與順序執行的下一個區塊，而無條件跳躍則只有一個。許多分析會加入單一的進入節點與離開節點。圖的形狀會揭示結構。若從進入節點到區塊 n 的每條路徑都經過區塊 d，則 d 支配（dominate）n；若一條邊的目標支配其來源，該邊就是識別迴圈的回邊（back edge）。從進入節點無法到達的區塊是可以移除的死碼。

在 CFG 上進行資料流分析

許多最佳化仰賴資料流分析，沿著 CFG 的邊傳遞資訊並反覆迭代，直到不再變化為止。存活分析（liveness analysis）以反向方式找出在每個點上哪些值之後仍可能被讀取，其結果用於建立暫存器配置所用的干涉圖。到達定義（reaching definitions）分析以正向方式找出哪些指派可能提供某個變數的值。大多數現代編譯器所使用的靜態單一賦值（SSA）形式也是在 CFG 上建構的，在控制流程路徑匯合處插入 phi 函式。

CFG 與呼叫圖的比較

CFG 描述單一函式內部的流程，而呼叫圖以整個函式為節點、以呼叫為邊；程序間分析兩者都會使用。CFG 也出現在編譯器以外的領域。測試中的分支涵蓋率要求確認 CFG 的每條邊是否都已執行，二進位分析工具從機器碼重建 CFG，而控制流程完整性（control-flow integrity）防禦則將間接跳躍限制在 CFG 所允許的邊上，阻擋將執行導向非預期程式碼的攻擊。

練習控制流程圖的題目

在控制流程圖中，節點與箭頭所代表的事物，下列組合何者正確？

  1. A節點是變數，箭頭是變數值被指派的順序
  2. B節點是基本區塊，箭頭是區塊之間的分支或轉移
  3. C節點是函式，箭頭是檔案之間的載入關係
查看答案與解析

正確答案：B. 節點是基本區塊，箭頭是區塊之間的分支或轉移

控制流程圖是以基本區塊為節點，並以箭頭表示執行某個區塊之後可能接續的區塊之轉移（條件分支的兩個去向，或直接進入下一個區塊的流程）的圖。可用於從往回指的箭頭找出迴圈，或分析變數的值從何處傳遞到何處。函式之間的呼叫關係以另外的呼叫圖表示，與檔案的載入關係無關。

常見問題

控制流程圖中的基本區塊是什麼？

一段直線式的指令序列，只有頂端一個進入點與底端一個離開點，因此只要其第一條指令被執行，所有指令都會依序執行。

如何在控制流程圖中找出迴圈？

計算支配關係並尋找回邊，也就是目標支配其來源的邊；每條回邊定義一個以其目標區塊為首的自然迴圈。

控制流程圖和呼叫圖有什麼不同？

控制流程圖顯示單一函式內基本區塊之間的可能路徑，而呼叫圖顯示哪些函式呼叫了哪些其他函式。

  • 區塊內的執行順序是固定的，因此容易進行區域性的最佳化，並以區塊作為節點的控制流程圖來表示整體的流程。

    關於基本區塊的說明，下列何者正確？

  • 存活區間分析會沿著控制流程圖，求出在程式的各個時間點，某個值往後是否有可能被讀取（存活）。
