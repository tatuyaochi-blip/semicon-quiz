什麼是符號擴展

將位元數較少的有號整數擴展為位元數較多時，把最高位元(符號)複製到上方所有位數。可在不改變值的情況下擴展。以0填滿高位的是零擴展。

日文名稱: 符号拡張

「符號擴展」出現在1領域的5道練習題中（指令集與組合語言等）。

這個名詞所屬的領域: 指令集與組合語言

為何複製符號位元能保持數值

在 n 位元二補數中，最高位元的權重為負的 2 的 n-1 次方，其他位元則是一般的正權重。將負數擴展一個位元時，會加上一個權重為負的 2 的 n 次方的新最高位元，並使原本的最高位元變成正的 2 的 n-1 次方；兩者合計仍貢獻負的 2 的 n-1 次方，因此數值不變。對每個新增位元重複此推論，即可證明此規則。例如，4 位元的 1010（-6）會變成 8 位元的 11111010，仍為 -6。

ISA 在哪些地方進行符號擴展

立即值是最常見的情況：RISC-V 的 12 位元 I 型立即值會被符號擴展，因此 addi 可接受 -2048 到 2047，負常數不需另外的減法指令即可使用。載入指令成對出現，lb 與 lh 做符號擴展，lbu 與 lhu 做零擴展。在 RV64 上，lw 把 32 位元值符號擴展為 64 位元，lwu 則做零擴展，而 addw 等字組指令會把其 32 位元結果符號擴展。x86 為同樣目的提供 movsx 與 movzx。在硬體上，符號擴展的成本只不過是把最高位元接線到所有新的位置。

經典陷阱：lui 加 addi

要建構 32 位元常數，RISC-V 程式碼以 lui 處理上位 20 位元，以 addi 處理下位 12 位元。由於 addi 會符號擴展其立即值，0x800 以上的下位部分會被當作負數，即其值減去 4096。組譯器的補償方式是：只要常數的第 11 位元為 1，就在上位部分加 1，而 %hi 與 %lo 重定位運算子會自動做到這一點。若手寫程式碼單純地分割常數，產生的值會恰好差 4096，這種錯誤在測試中很容易被忽略。

C 語言中的符號擴展與零擴展

C 語言依來源型別選擇擴展方式：將 signed char 或 int16_t 轉換為 int 時做符號擴展，轉換無號型別時則做零擴展。單純的 char 在某些平台上是有號的、在其他平台上是無號的，例如在 x86 上為有號，但在大多數 Arm Linux 系統上為無號，因此位元組值 0xFF 可能依目標平台變成 -1 或 255。當位元組與常數比較或用作陣列索引時，這種差異就會造成錯誤。原始位元組使用 unsigned char 或 uint8_t 可避免這種歧義。

練習符號擴展的題目

RISC-V的addi指令的立即值是12位元帶正負號的整數。下列何者是此立即值能表示的範圍？

  1. A0～4095
  2. B-2048～2047
  3. C-4096～4095
查看答案與解析

正確答案：B. -2048～2047

12位元的二補數所能表示的，是從-2的11次方＝-2048到2的11次方-1＝2047。立即值在計算前會先符號擴充為32位元（RV64則為64位元），所以負數也能直接相加。要使用超出此範圍的常數，需組合多個指令，例如以lui指令設定高20位元，再以addi加上低12位元。

在RISC-V中以lui與addi兩個指令產生常數0x12345FFF時，正確的組合是下列何者？

  1. Alui t0, 0x12346 之後接 addi t0, t0, -1
  2. Blui t0, 0x12345 之後接 addi t0, t0, 0xFFF
  3. Clui t0, 0x12345 之後接 addi t0, t0, -1
查看答案與解析

正確答案：A. lui t0, 0x12346 之後接 addi t0, t0, -1

addi的立即值會被符號擴充，所以當低12位元為0xFFF（最高位元為1）時，會被當成-1來相加。因此將lui產生的高位部分改為大1的0x12346，再對0x12346000加上-1，就得到0x12345FFF。當低12位元的位元11為1時，須事先在高位加1，這種修正由組譯器與連結器自動進行。

常見問題

符號擴展和零擴展有什麼差別？

符號擴展以原本最高位元的複本填滿新的高位元，保持有號數的值。零擴展則以零填滿，保持無號數的值。

RISC-V 的 addi 為什麼要對立即值做符號擴展？

這樣一條指令就能加上負常數，例如 addi sp, sp, -16。12 位元欄位因此涵蓋 -2048 到 2047，而不只是非負值。

在 C 語言中如何對數值做符號擴展？

把它存放在原始寬度的有號型別中，例如 int8_t 或 int16_t，再指派給較寬的有號型別；轉換會自動進行符號擴展，編譯器也會產生對應的符號擴展指令。
