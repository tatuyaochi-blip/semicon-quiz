什麼是Meltdown

在部分 CPU 上，於權限檢查造成例外之前，可推測性地讀取核心記憶體，並能從快取痕跡推測其值的弱點。已用 KPTI 等對策因應。

日文名稱: Meltdown

「Meltdown」出現在2領域的3道練習題中（硬體安全, CPU與架構等）。

這個名詞所屬的領域: 硬體安全

攻擊的運作方式

2018 年揭露的 Meltdown 濫用了亂序執行。使用者程式對核心位址發出載入。依架構規定，這必須引發權限錯誤且不傳回任何東西，但在受影響的處理器上，載入的值在錯誤生效之前就已轉送給相依的指令。這些暫態指令以該機密位元組作為索引，存取使用者擁有的探測陣列，將特定的一條快取線拉進快取。最終引發錯誤時，暫存器結果會被捨棄，但快取狀態並不會被回復。

透過快取讀出機密

接著攻擊者對探測陣列的每個項目量測存取時間。唯一一個載入很快的項目（快取命中，而非緩慢地存取 DRAM）就揭露了被暫態讀取的值。這種時序旁通道通常以 flush-and-reload 技術建構，逐位元組重複執行以傾印核心記憶體。權限錯誤本身可以用訊號處理常式攔截或以其他方式抑制，因此洩漏能以實用的速率進行。

Meltdown 與 Spectre

兩種攻擊都依賴暫態執行在快取中留下的痕跡，但繞過的對象不同。Meltdown 利用太晚完成的權限檢查，直接突破使用者／核心的權限邊界，且它依賴部分處理器設計中特有的微架構行為。Spectre 則是誤導分支預測器，使受害者自身具合法權限的程式碼推測性地存取攻擊者選定的資料。Spectre 影響幾乎所有高效能推測執行 CPU，也更難完全消除。

KPTI 與硬體修正

主要的軟體對策是核心頁表隔離（KPTI），在使用者程式碼執行時所用的頁表中不再映射大部分核心記憶體；只保留進入核心所需的一小段 stub。沒有位址轉換，資料就連暫態地載入都不可能。代價是每次系統呼叫、中斷與例外都要切換頁表，可能明顯拖慢大量使用系統呼叫的工作負載；行程上下文識別碼（PCID）可減輕 TLB 清除的損失。已在硬體上修正的處理器不需要 KPTI。

練習Meltdown的題目

下列關於部分CPU出現問題的Meltdown漏洞的原理，何者正確？

  1. ACPU因熱而熔化，資料洩漏到外部
  2. B即使是讀取無權限的核心記憶體的指令，在因權限檢查而產生的例外確定之前，值就已被推測讀取，依賴該值的痕跡會殘留在快取中
  3. C核心記憶體對所有行程公開的設定錯誤
查看答案與解析

正確答案：B. 即使是讀取無權限的核心記憶體的指令，在因權限檢查而產生的例外確定之前，值就已被推測讀取，依賴該值的痕跡會殘留在快取中

當使用者程式想讀取核心記憶體時，原本會因權限違規而產生例外，得不到值。然而在受影響的CPU上，到例外確定為止的短暫期間，使用所讀取之值的後續指令會被推測執行，對應該值的位置被載入快取。即使例外使結果被捨棄，仍可藉由快取旁路推測出核心的資料。

下列關於作為Meltdown的軟體對策而導入的KPTI（核心分頁表隔離）的概念，何者正確？

  1. A在使用者程式執行期間，將核心記憶體的大部分從分頁表中移除，使其連推測也無法讀取
  2. B將核心整個加密後放在磁碟上
  3. C禁止執行使用者的程式
查看答案與解析

正確答案：A. 在使用者程式執行期間，將核心記憶體的大部分從分頁表中移除，使其連推測也無法讀取

以往的作業系統為了加快切換，會在使用者行程的分頁表中也放入核心記憶體（並標上禁止存取的標記）。在Meltdown中，由於能在檢查該標記之前就推測讀取，KPTI便在使用者程式執行期間，連核心分頁的對應本身都移除。位址無法轉換，就連推測也讀不到。不過，每次系統呼叫都要切換分頁表，因此效能會下降。

常見問題

Meltdown 和 Spectre 是一樣的嗎？

不一樣。兩者都透過推測執行的快取痕跡洩漏資料，但 Meltdown 是越過延遲的權限檢查讀取核心記憶體，而 Spectre 是誘使受害程式自身的推測執行去存取機密資料。

為什麼 Meltdown 修補程式會讓電腦變慢？

KPTI 在使用者模式與核心模式之間每次轉換時都切換頁表，使每次系統呼叫與中斷都增加額外負擔與 TLB 未命中。大量進行系統呼叫的程式受影響最大。

新的 CPU 還會受到 Meltdown 影響嗎？

揭露後設計的處理器一般會阻止引發錯誤的資料傳到相依指令，作業系統偵測到這類 CPU 時會略過 KPTI。較舊的受影響 CPU 仍需依靠軟體對策。
