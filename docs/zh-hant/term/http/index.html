什麼是HTTP（超文字傳輸協定）

在網頁瀏覽器與網頁伺服器等之間，交換HTML、影像與資料的應用層協定。用戶端送出由方法、URL、標頭、本文組成的請求，伺服器回傳由狀態碼、標頭、本文組成的回應。作為協定是無狀態的，登入等狀態要用Cookie等方式維持。HTTP/1.1使用文字格式與持續連線，HTTP/2在一條TCP連線上多工傳送多個串流，HTTP/3則使用UDP之上的QUIC。以TLS保護的HTTP稱為HTTPS。

日文名稱: HTTP

「HTTP（超文字傳輸協定）」出現在4領域的17道練習題中（Web技術基礎, 電腦網路基礎, 雲端與容器基礎等）。

這個名詞所屬的領域: Web技術基礎

請求與回應的形式

請求依序由「GET /index.html HTTP/1.1」這類請求列、Host或Accept等標頭、空行、本文組成。回應由「HTTP/1.1 200 OK」這類狀態列、Content-Type或Cache-Control等標頭，以及本文組成。標頭是「名稱: 值」的形式，用來傳達本文的種類、快取的處理方式、驗證資訊、壓縮方式等。

各版本的差異

HTTP/1.1以重複使用一條TCP連線的持續連線為預設，但在一條連線上只能依序一個一個接收回應。HTTP/2把訊息分成二進位的訊框，在一條連線上多工傳送多個請求與回應，也會壓縮標頭。HTTP/3以UDP之上的QUIC作為傳輸層，減少封包遺失連帶卡住無關串流的問題，也減少建立連線所需的往返。

無狀態與狀態管理

HTTP是把每個請求獨立處理的無狀態協定。伺服器不必記住先前的請求，因此容易把負載分散到許多伺服器。登入等狀態是在應用程式端維持，例如以Cookie傳遞伺服器發出的工作階段ID，或以Authorization標頭送出帶簽章的值。

練習HTTP（超文字傳輸協定）的題目

把雲端儲存用於以下3種用途：①作為磁碟連接到虛擬機器並建立檔案系統，放置資料庫的資料檔；②從多台伺服器同時掛載，作為共用目錄使用；③透過 HTTP 的 API 指定鍵（名稱）讀寫大量圖片，且不預先決定容量而持續增加。適合①～③的儲存種類組合，下列何者適當？

  1. A①物件儲存、②區塊儲存、③檔案儲存
  2. B①檔案儲存、②物件儲存、③區塊儲存
  3. C①區塊儲存、②檔案儲存、③物件儲存
查看答案與解析

正確答案：C. ①區塊儲存、②檔案儲存、③物件儲存

區塊儲存是把固定大小的區域作為虛擬磁碟連接到虛擬機器，在上面建立檔案系統使用，適合資料庫這類需要快速進行細小讀寫的用途。檔案儲存透過 NFS 或 SMB 等，提供多台伺服器可同時掛載的共用檔案系統。物件儲存把資料作為以鍵識別的物件，透過 HTTP 的 API 整個讀寫，容量幾乎不必在意就能增加，適合存放圖片、備份與日誌。它不適合只改寫物件一部分的用法，因此不放資料庫的資料檔。

HTTPS（以TLS保護的HTTP通訊）能保護的是下列何者？

  1. A所連線網站的營運者是沒有惡意、值得信賴的個人或組織
  2. B正在通訊這件事本身，以及所連線伺服器的IP位址，在途中的路徑上都看不到
  3. C通訊內容在途中不會被竊看或竄改，以及所連線的伺服器是憑證上網域名稱的正當擁有者
查看答案與解析

正確答案：C. 通訊內容在途中不會被竊看或竄改，以及所連線的伺服器是憑證上網域名稱的正當擁有者

TLS提供三項功能：通訊加密（機密性）、竄改偵測（完整性）與伺服器驗證。伺服器出示憑證，瀏覽器沿著所信任之憑證機構（CA）的簽章確認憑證是否正確，並確認是否與URL的網域名稱一致。不過，能確認的只是「正在與該網域名稱的擁有者通訊」，並無法得知網站的營運者是否善良。即使是詐騙網站，也能取得自己網域名稱的憑證。此外，IP標頭不會被加密，因此與哪個IP位址、在何時、通訊了多少量，在途中的路徑上都看得到。

常見問題

HTTP與HTTPS有什麼不同？

HTTPS是以TLS加密HTTP的交換，並加上竄改偵測與伺服器驗證。請求與回應的形式與HTTP相同，預設連接埠號碼HTTP為80、HTTPS為443。為了保護密碼與Cookie，網站一般使用HTTPS。

GET與POST如何區分使用？

GET是取得資源的方法，被視為不改變伺服器狀態的「安全」方法，瀏覽器或快取可能重複送出或保存結果。POST用於讓伺服器進行處理或登錄資料，例如下單或發文。GET的查詢會放在URL中，留在存取紀錄與瀏覽歷程裡，因此不要放入密碼等機密資訊。
