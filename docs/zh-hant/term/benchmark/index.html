什麼是基準測試（Benchmark）

為比較電腦或程式的效能，在固定條件下執行的代表性程式。重要的是選擇接近實際用途者。

日文名稱: ベンチマーク

「基準測試（Benchmark）」出現在1領域的6道練習題中（效能評估與效能剖析等）。

這個名詞所屬的領域: 效能評估與效能剖析

為什麼工作負載很重要

效能沒有單一的數值；它取決於執行的內容。以整數運算為主的程式碼、浮點運算核心、受記憶體限制的處理與受 I/O 限制的工作，會對系統的不同部分造成負荷，因此在某一項勝出的機器，在另一項可能落敗。所以有意義的基準測試是實際的應用程式或與其相近的程式，並在每台受比較的機器上以相同的輸入、編譯器設定與系統條件執行。實際工作負載的執行時間仍是最可信的指標。

SPEC CPU 如何呈報結果

SPEC CPU 等標準套件收錄許多源自實際應用的程式，例如編譯器、壓縮與物理模擬。對每個程式，將參考機器的執行時間除以實測時間得到比值，數值越高代表越快，再以幾何平均將這些比值合併成單一分數。幾何平均使相對比較與選哪台機器作為參考無關。執行規則固定了編譯器選項與程序，公開的結果會列出完整的硬體與軟體細節。

微基準測試與常見陷阱

合成基準測試與微基準測試只隔離出單一特性，例如記憶體頻寬或單一迴圈，適合用於診斷，但難以預測整體效能。典型的陷阱包括專門為某基準測試調校編譯器、比較輸入大小或設定不同的執行、忽略暖機與快取效應，以及只呈報一次執行結果而未檢查各次執行間的變異。資料完全裝得進快取的核心程式，會讓系統看起來比處理實際資料集時快得多。

基準測試與指標

基準測試是工作負載；指標則是你從中呈報的數值，例如執行時間、以每秒操作數表示的傳輸量、延遲百分位數或每項任務的能耗。MIPS 與峰值 FLOPS 根本不是基準測試：它們忽略了每道指令完成多少有用的工作，以及實際上有多常達到峰值速率。公平的比較會一併說明基準測試、指標與條件。

  2. B無論什麼用途，都只以一個小迴圈的速度來決定
  3. C只以製造商公布的時脈頻率來決定

正確答案：A. 以接近實際用途的程式來測量，並以其結果進行比較

某部電腦是否夠快，會因用途而異。整數處理、浮點運算、大量使用記憶體的處理、大量輸入輸出的處理等，各自擅長的工作都不同。因此，以盡可能接近實際用途的程式，或是彙整許多代表性程式的標準基準測試來測量，並在條件相同的情況下進行比較，是很重要的。

  2. B只測量一個加法能做幾次
  3. C基準測試的結果可由製造商自由決定

正確答案：A. 依固定規則執行許多以實際應用程式為基礎的程式，並以與基準電腦的比值彙整後的值來表示效能

SPEC CPU是由編譯器、壓縮、物理模擬等許多以實際應用程式為基礎的程式所組成的基準測試。它求出各程式的執行時間與基準電腦的時間之比，再以幾何平均彙整成一個值。編譯器的設定與執行方式也有規則，結果會連同詳細條件一併公開。

常見問題

為什麼 SPEC 使用幾何平均？

由於比值是以參考機器正規化的，無論選擇哪台參考機器，幾何平均都會得出相同的相對排名，也不會有單一程式只因比值大就主導分數。

合成基準測試和應用程式基準測試有什麼差別？

合成基準測試是針對單一特性的人工程式，應用程式基準測試則執行實際或貼近實際的軟體。後者更能預測真實世界的效能，但較難標準化。

基準測試分數較高，代表我的程式會跑得比較快嗎？

只有在基準測試與你的工作負載相似時才是。針對運算密集測試調校的系統，在受記憶體或 I/O 限制的程式上可能幾乎沒有提升，因此應以接近實際用途的程式碼進行測試。
