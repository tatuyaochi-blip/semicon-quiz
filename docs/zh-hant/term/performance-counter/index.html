什麼是效能計數器（Performance counter）

計數 CPU 內發生的指令執行、快取未命中、分支預測失誤等事件的硬體計數器。PMU。

日文名稱: 性能カウンタ

「效能計數器（Performance counter）」出現在2領域的9道練習題中（效能評估與效能剖析, 記憶體階層與效能等）。

這個名詞所屬的領域: 效能評估與效能剖析

練習效能計數器（Performance counter）的題目

以內建於CPU的效能計數器（PMU）可計數的項目，下列何者為正確的例子？

  1. A執行的指令數、快取失誤的次數、分支預測錯誤的次數等
  2. B撰寫程式的人數
  3. C鍵盤的按鍵數
查看答案與解析

正確答案：A. 執行的指令數、快取失誤的次數、分支預測錯誤的次數等

效能計數器是計算CPU內部發生的各種事件的硬體計數器。可由週期數與指令數求得IPC，也能得知各層級的快取失誤、TLB失誤、分支預測錯誤等的次數。可使用Linux的perf等工具，一邊執行程式一邊計數，作為區分花費時間的原因是記憶體、分支，還是運算本身的線索。

以效能計數器測量後，發現某程式的IPC（每個週期的指令數）非常低，為0.3，且最後一級快取的失誤很多。下列何者是最可能的狀況與對策的組合？

  1. A因等待記憶體，CPU停滯的時間很長。改變資料的排列方式或進行分塊（blocking），以有效利用快取
  2. B運算太快了。提高頻率
  3. C分支太少了。增加分支
查看答案與解析

正確答案：A. 因等待記憶體，CPU停滯的時間很長。改變資料的排列方式或進行分塊（blocking），以有效利用快取

現今的CPU每個週期可執行數個指令，所以IPC為0.3表示大部分時間都在等待某些東西。若最後一級快取的失誤很多，就可以認為是在長時間等待來自主記憶體的資料。將資料排在連續的位址、改變迴圈的順序、藉由分塊重複使用同樣的資料等，來減少快取失誤是有效的。

  3. 以效能計數器發現分支預測錯誤非常多。下列何者是適用的改善方法？
