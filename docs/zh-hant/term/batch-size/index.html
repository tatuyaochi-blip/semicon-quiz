什麼是批次大小（Batch size）

一併處理的輸入數量。增大後可重複使用權重而提高效率，但回應的延遲與記憶體也會增加。

日文名稱: バッチサイズ

「批次大小（Batch size）」出現在2領域的8道練習題中（AI硬體與軟體堆疊, 機器學習基礎等）。

這個名詞所屬的領域: AI硬體與軟體堆疊

為什麼批次處理能提高效率

在神經網路的一層中，所有輸入使用的權重都相同。批次大小為 1 時，全連接層是矩陣向量乘積：每個權重從記憶體擷取後只用於一次乘加運算，在 FP16 下運算強度約為 1 FLOP/byte，因此運算單元大多在等待記憶體。批次大小為 B 時，該層變成矩陣矩陣乘積：權重流量不變，運算量卻增加 B 倍，因此運算強度大約提高 B 倍，工作負載便從受記憶體限制轉向受運算限制。伺服器會將來自眾多使用者的請求分組，以善用這一點。

延遲與記憶體的代價

較大的批次能提高總產出量，但不會提高個別請求的速度。請求可能需要等待其他請求到達，每個批次的運算時間也較長，因此每個請求的延遲會增加；互動式服務只會在回應時間目標允許的範圍內加大批次。記憶體也會增加。在 LLM（大型語言模型）推論中，KV 快取用來儲存先前 token 的注意力鍵與值，避免重新計算，其大小與層數、鍵與值的維度、token 數、批次大小以及每個元素的位元組數成正比。在長上下文或大量請求下，它可能達到數十 GB，超過權重本身。

LLM 解碼時的典型數值

在批次大小為 1 的解碼過程中，每產生一個 token 都需要讀取所有權重。因此，在頻寬 2 TB/s 的 GPU 上執行 FP16 權重約 14 GB 的模型，每個 token 至少需要 14 GB ÷ 2 TB/s = 7 ms，也就是每秒最多約 140 個 token。將權重量化為 4 位元（約 3.5 GB）可將這個下限降到約 1.75 ms。較大的批次每讀取一次權重就能產生多個 token，使總產出量成倍增加，直到運算能力或 KV 快取記憶體成為限制。KV 快取的壓力可透過較低精度的快取、在多個注意力頭之間共用鍵與值，以及以區塊為單位的記憶體管理來緩解。

訓練中的批次大小

在訓練中，批次（mini-batch）是指為了進行一次權重更新而將其梯度平均的一組樣本。較大的批次能更有效率地使用硬體，每走過一次資料（一個 epoch）所需的更新步數也較少，但反向傳播所需的激活值記憶體會隨批次大小與模型深度增加。梯度檢查點可以因應這一點，只儲存部分激活值，其餘重新計算，代價約為多一次前向傳遞。大幅改變批次大小通常需要重新調整學習率，因為它會改變梯度雜訊。

練習批次大小（Batch size）的題目

以小批次大小（批次大小）50，訓練1萬筆訓練資料。1個epoch中權重的更新次數為何者？

  1. A50次
  2. B200次
  3. C2000次
查看答案與解析

正確答案：B. 200次

1個epoch是把全部訓練資料使用過一輪為止的訓練單位。小批次學習對每個小批次求出梯度並更新一次權重，因此1個epoch的更新次數（迭代次數）為 10000 ÷ 50 = 200次。訓練10個epoch，更新總計為2000次。小批次學習介於以全部資料只更新一次的批次學習，與每筆資料更新一次的線上學習之間。

輸入只有1筆（批次大小為1）時，全連接層的計算（權重矩陣與向量的乘積）容易受記憶體限制，其原因下列何者正確？

  1. A因為向量的元素數量太多，放不進運算單元
  2. B因為矩陣與向量的乘積無法在GPU上計算
  3. C因為權重的每個元素即使從記憶體讀取，也只用於1次乘加，所以運算強度非常低
查看答案與解析

正確答案：C. 因為權重的每個元素即使從記憶體讀取，也只用於1次乘加，所以運算強度非常低

在矩陣與向量的乘積中，權重矩陣的每個元素只讀取1次，與輸入的一個元素相乘再相加1次而已。以FP16來說，每2位元組只做2次運算，運算強度約為1。讀取權重耗費時間，運算單元幾乎都在等待。若將輸入集中起來（加大批次）讓同一份權重可用於多筆輸入，運算強度就會提高。

常見問題

批次大小越大，推論就越快嗎？

它會提高總產出量，因為每次讀取權重能服務更多輸入，但每個個別請求通常要等更久，因此延遲會變差。

為什麼加大批次大小會增加 GPU 記憶體用量？

激活值（在 LLM 中還有 KV 快取）是依每個輸入分別儲存的，因此會隨批次大小線性增加，而權重則維持不變。

批次大小和 epoch 有什麼差別？

批次大小是每個步驟或每次權重更新處理的樣本數；epoch 則是完整走過訓練資料集一次，所需步數為資料集大小除以批次大小。
