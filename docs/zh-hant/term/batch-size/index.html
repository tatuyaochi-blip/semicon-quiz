什麼是批次大小（Batch size）

一併處理的輸入數量。增大後可重複使用權重而提高效率，但回應的延遲與記憶體也會增加。

日文名稱: バッチサイズ

「批次大小（Batch size）」出現在1領域的7道練習題中（AI硬體與軟體堆疊等）。

這個名詞所屬的領域: AI硬體與軟體堆疊

練習批次大小（Batch size）的題目

輸入只有1筆（批次大小為1）時，全連接層的計算（權重矩陣與向量的乘積）容易受記憶體限制，其原因下列何者正確？

  1. A因為向量的元素數量太多，放不進運算單元
  2. B因為矩陣與向量的乘積無法在GPU上計算
  3. C因為權重的每個元素即使從記憶體讀取，也只用於1次乘加，所以運算強度非常低
查看答案與解析

正確答案：C. 因為權重的每個元素即使從記憶體讀取，也只用於1次乘加，所以運算強度非常低

在矩陣與向量的乘積中，權重矩陣的每個元素只讀取1次，與輸入的一個元素相乘再相加1次而已。以FP16來說，每2位元組只做2次運算，運算強度約為1。讀取權重耗費時間，運算單元幾乎都在等待。若將輸入集中起來（加大批次）讓同一份權重可用於多筆輸入，運算強度就會提高。

在推論中加大批次大小（一次處理的輸入數量），整體效率容易提升，其原因為下列何者？

  1. A因為輸入越多，每筆輸入的計算次數越少
  2. B因為加大批次會使權重的數量減少
  3. C因為讀取一次的權重可以用於多筆輸入的計算，運算強度提高，能有效運用運算單元
查看答案與解析

正確答案：C. 因為讀取一次的權重可以用於多筆輸入的計算，運算強度提高，能有效運用運算單元

若批次大小為B，權重矩陣與B個向量的乘積，就變成權重矩陣與寬度為B的矩陣的乘積。權重的讀取不變，運算卻變為B倍，因此運算強度也約變為B倍，從受記憶體限制趨近於受運算限制。在伺服器上的推論，是藉由將許多使用者的請求集中處理，來有效率地運用GPU。

解析中的「批次大小（Batch size）」
