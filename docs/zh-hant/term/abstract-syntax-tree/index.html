什麼是抽象語法樹(AST)

以運算與敘述作為節點的樹來表示程式的結構。省略括號或分隔符號等沒有意義的資訊，運算子的優先順序以樹的形狀表示。

日文名稱: 抽象構文木(AST)

「抽象語法樹(AST)」出現在1領域的2道練習題中（編譯器等）。

這個名詞所屬的領域: 編譯器

從剖析樹到 AST

照字面遵循文法的剖析器會產生具體語法樹（剖析樹），每套用一條文法規則就有一個節點，每個語彙單元（token）都有一個葉節點，包括括號、逗號與分號。以運算式、項、因子等不同規則來表達優先順序的文法，還會產生一長串只有單一子節點的節點鏈。AST（抽象語法樹）則捨棄所有這些。每個節點都是有意義的構造，例如二元運算、函式呼叫、if 敘述或變數參照，並且恰好擁有該構造所需的子節點。

樹的形狀如何表達優先順序與結合性

先求值的運算位在樹的較深處。對 2 + 3 * 4 而言，根節點是 +，子節點為 2 以及位於 3 與 4 之上的 * 節點；對 (2 + 3) * 4 而言，根節點則是 *，而括號在完成任務後就消失了。結合性也以相同方式表達：a - b - c 的意思是 (a - b) - c，因此根節點的左子節點是另一個減法，形成向左傾斜的樹。因此，以後序走訪（先子節點、後父節點）即可按正確順序求值。

編譯器如何運用 AST

剖析之後，語意分析會走訪 AST，把每個名稱解析到其宣告、檢查並推論型別、插入隱式轉換，並回報使用未宣告變數等錯誤。節點通常會被加註這些資訊。加註後的樹接著被降轉（lower）成中間表示（IR），例如三位址碼或 SSA 形式，在其中控制流程成為基本區塊之間明確的分支。簡單的樹走訪直譯器直接執行 AST，而格式化工具、靜態檢查工具（linter）與重構引擎等工具也都在 AST 上運作。

AST 與 IR 的比較

AST 反映原始語言：它仍保有巢狀迴圈、結構化的 if 敘述與原始碼層級的運算式，因此非常適合針對程式原貌進行的檢查與轉換。IR 則更接近機器，由一連串扁平的簡單運算與明確的跳躍構成，適合資料流分析與最佳化。兩者常被混淆，但大致的分界是：AST 回答程式設計師寫了什麼，IR 回答必須計算什麼。

練習抽象語法樹(AST)的題目

關於抽象語法樹（AST）的特徵，下列何者正確？

  1. A連原始碼的括號與分隔符號都全部保留為節點
  2. B省略與語意無關的符號，並以樹狀結構表示運算子的優先順序
  3. C與CPU的指令一對一對應，可直接執行
查看答案與解析

正確答案：B. 省略與語意無關的符號，並以樹狀結構表示運算子的優先順序

語法分析會依照文法規則產生連括號與分隔符號都包含在內的樹（具體語法樹），但其中含有許多後續處理不需要的資訊。抽象語法樹則是只將程式語意所需的運算與敘述作為節點的樹，例如在(a + b) * c中，加法節點位於乘法節點之下，因此即使沒有括號也能得知運算的順序。與CPU指令對應的，是更後面的階段所產生的程式碼。

運算式 2 + 3 * 4 的抽象語法樹之形狀，下列何者正確？

  1. A根節點是 + 的節點，其右子節點是表示 3 * 4 的 * 節點
  2. B根節點是 * 的節點，其左子節點是表示 2 + 3 的 + 節點
  3. C2、3、4、+、* 這5個節點全部並列為根節點的直接子節點
查看答案與解析

正確答案：A. 根節點是 + 的節點，其右子節點是表示 3 * 4 的 * 節點

乘法的優先順序高於加法，所以此運算式會被解釋為 2 + (3 * 4)。在抽象語法樹中，越先計算的運算會放在越下面，所以根節點是 +，其左子節點是2，右子節點是以3和4為子節點的 * 節點。若由下往上對樹求值，會先計算 3 * 4 = 12，再得到 2 + 12 = 14。根節點成為 * 的是寫成 (2 + 3) * 4 的情況，而把全部並列在根節點之下，則無法表示計算的順序。

常見問題

剖析樹和抽象語法樹有什麼差別？

剖析樹記錄每一條文法規則與每個語彙單元（包括標點符號），AST 則只保留有意義的構造。剖析樹以規則鏈表示的優先順序，在 AST 中只需看哪個節點是父節點就能表示。

AST 中如何表示括號？

括號不會被存成節點。其作用由樹的結構表達：被括號包住的子運算式會成為一棵子樹，在其父運算之前求值。

直譯器會使用 AST 嗎？

許多直譯器會。樹走訪直譯器直接對 AST 求值，而較快的直譯器通常會先把 AST 編譯成位元組碼再執行。
