什麼是共享記憶體（GPU shared memory）

位於 GPU 各 SM 內，可由同一區塊的執行緒共用的小型高速記憶體。由程式決定放置什麼內容。

日文名稱: シェアードメモリ

「共享記憶體（GPU shared memory）」出現在2領域的15道練習題中（GPU程式設計, AI硬體與軟體堆疊等）。

這個名詞所屬的領域: GPU程式設計

練習共享記憶體（GPU shared memory）的題目

將32×32的float表格放在共享記憶體中，由線程束的32個執行緒沿著行的方向（縱向）讀取時會發生記憶庫衝突。下列何者是常用的對策？

  1. A表格維持32×32，將讀取的順序改為隨機
  2. B不再使用共享記憶體，全部從全域記憶體讀取
  3. C將表格如32×33般多配置一欄，使每一列的記憶庫位置錯開
查看答案與解析

正確答案：C. 將表格如32×33般多配置一欄，使每一列的記憶庫位置錯開

若一列有32個float（128位元組），每一列都從同一個記憶庫開始，因此同一欄的元素全都落在同一個記憶庫，縱向讀取時32個執行緒會集中到一個記憶庫。若將一列改為33個，每前進一列記憶庫就會錯開一個，同一欄的32個元素便會全部分散到不同的記憶庫，一次即可讀完。這只是多加一欄用不到的記憶體，是個簡單的做法。

以GPU計算大型矩陣的乘積時，將矩陣分成小的圖塊（tile）讀入共享記憶體，其理由下列何者正確？

  1. A讓從全域記憶體讀入的資料在共享記憶體中反覆重複使用，減少對慢速記憶體的存取次數
  2. B縮小矩陣的值，以防止溢位
  3. C減少計算次數，以近似求出結果
查看答案與解析

正確答案：A. 讓從全域記憶體讀入的資料在共享記憶體中反覆重複使用，減少對慢速記憶體的存取次數

在矩陣乘積中，同一個元素會被反覆用於計算。若照樸素的寫法，每個執行緒每次都得重新從全域記憶體讀取，記憶體頻寬就會不足。若分成圖塊讀入共享記憶體，區塊的所有執行緒就能反覆使用該圖塊，從全域記憶體讀取的量會隨圖塊大小成比例地減少。這與CPU快取上的分塊（blocking）是相同的概念。

解析中的「共享記憶體（GPU shared memory）」

  • 若分成圖塊讀入共享記憶體，區塊的所有執行緒就能反覆使用該圖塊，從全域記憶體讀取的量會隨圖塊大小成比例地減少。

  • 若先將圖塊讀入共享記憶體，再交換執行緒的分工後讀出，對全域記憶體的讀取與寫入就都能使用連續的位址。

    以GPU轉置大型矩陣（b[j][i] = a[i][j]）時，經由共享記憶體的主要目的為下列何者？

  • 同一個區塊的執行緒會在同一個SM（運算單元的集合）上執行，可透過共享記憶體合作並進行同步。

    下列何者是CUDA執行緒階層的正確組合（由大到小）？

  • 共享記憶體是位於各SM內、每個區塊數十KB左右的高速記憶體，讀寫速度比全域記憶體（GPU的DRAM）快數十倍。

    關於CUDA共享記憶體（shared memory）的特徵，下列何者正確？

  • 在使用共享記憶體的處理中，必須先讓某個執行緒的寫入完成，其他執行緒才能讀取其寫入的值。
