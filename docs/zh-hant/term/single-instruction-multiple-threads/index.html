什麼是SIMT（單指令多執行緒）

單一指令、多個執行緒的方式。程式是以每個執行緒為單位撰寫，但硬體會以 warp（NVIDIA 為 32 個）為單位將執行緒綁在一起，以相同指令執行。

日文名稱: SIMT

「SIMT（單指令多執行緒）」出現在1領域的2道練習題中（GPU程式設計等）。

這個名詞所屬的領域: GPU程式設計

SIMT 如何執行執行緒

在單指令多執行緒（SIMT）模型中，程式設計者把核心函式（kernel）寫成單一執行緒的一般程式碼，再由數千個執行緒對不同的資料執行它。硬體將執行緒分成固定的組，在 NVIDIA GPU 上稱為 warp（32 個執行緒），在 AMD GPU 上稱為 wavefront（64 或 32 個）。整組只擷取並解碼一次指令，再由其中所有執行緒以鎖步（lockstep）方式執行，各自擁有自己的暫存器與資料。這讓控制邏輯的成本分攤到許多運算通道上，使晶片面積大多用於運算。

分支發散

由於每個執行緒都是獨立撰寫的，同一個 warp 中的執行緒可能走向不同的分支。硬體的處理方式是依序執行每條路徑，並將不在該路徑上的執行緒遮罩掉，之後再重新匯合。正確性得以保持，但若 if-else 兩側各有一半的執行緒，warp 就要在兩邊都花時間，其吞吐量大約減半。注重效能的程式碼會安排資料，讓同一個 warp 中的執行緒走相同的路徑，例如讓分支條件取決於 warp 索引，而不是各執行緒的資料。

SIMT 與 CPU SIMD 的比較

CPU 的單指令多資料（SIMD）擴充指令集，是將一條指令套用到存有固定數量元素（例如 4 或 8 個）的向量暫存器上。程式或編譯器必須以這個寬度為前提撰寫，使用明確的向量指令，並以遮罩處理邊界情況。SIMT 則將寬度隱藏起來：程式碼描述的是純量執行緒，由硬體從許多執行緒組成向量，並在發散時管理遮罩。底層的執行方式其實相似，這也是為什麼 SIMT 的效能仍取決於讓 warp 中的執行緒步調一致。

實務上的影響

許多常見的 GPU 程式設計規則都源自 SIMT。執行緒區塊的大小通常是 32 的倍數，以免有 warp 只部分填滿。當 warp 中相鄰的執行緒存取相鄰的位址時，記憶體存取最快，因為硬體能將它們合併成少數幾次寬幅交易，這種模式稱為合併存取（coalescing）。此外，GPU 會讓許多 warp 同時駐留，並在某個 warp 停頓時切換到另一個就緒的 warp，以此隱藏冗長的記憶體延遲，這就是為什麼高佔用率（每個核心有足夠的活躍 warp）往往對效能很重要。

CPU的SIMD是對集結了4個或8個資料的向量暫存器施加一個指令，因此撰寫程式時必須留意向量的寬度。GPU的SIMT則是程式設計師照一般方式撰寫一個執行緒的處理，再由硬體每32個一組，以相同指令運作。各執行緒也可以分支，硬體會依序執行分歧出的路徑，但此時效率會下降。

常見問題

GPU 運算中的 warp 是什麼？

warp 是 NVIDIA GPU 上由 32 個執行緒組成、以鎖步方式一起執行同一條指令的群組。它是 SIMT 模型中發出指令的基本單位；AMD 的對應概念稱為 wavefront。

SIMT 和 SIMD 有什麼差別？

SIMD 提供固定寬度的向量指令，必須由程式設計者或編譯器明確使用。SIMT 則讓每個執行緒都能寫成獨立的純量程式碼，由硬體將執行緒組成 warp 並處理發散的分支。

什麼是 warp 發散（warp divergence）？

warp 發散是指同一個 warp 中的執行緒走上不同的分支路徑。硬體會將每條路徑依序執行，並遮罩不活躍的執行緒，因此在路徑重新匯合之前效率會下降。
