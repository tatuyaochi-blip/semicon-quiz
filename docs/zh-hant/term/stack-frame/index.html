什麼是堆疊框

每次函式被呼叫時，在堆疊上配置的區域。放置返回位址、已儲存的暫存器、區域變數等，並在從函式返回時釋放。

日文名稱: スタックフレーム

「堆疊框」出現在3領域的5道練習題中（指令集與組合語言, 編譯器, 連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 指令集與組合語言

堆疊框裡放了什麼

堆疊框是單一函式呼叫所擁有的那一段堆疊。依函式而定，它包含返回位址、函式打算使用之被呼叫者保存暫存器的舊值、放不進暫存器或被取址的區域變數、暫存值的溢出位置，以及超出暫存器傳遞數量的引數；可選用的框架指標暫存器（RISC-V 中為 s0）可標示框內的固定參考點。由於每次呼叫都會得到新的堆疊框，每一次遞迴呼叫都有自己獨立的一份區域變數。

序言與尾聲

依一般慣例，堆疊朝較低位址成長，因此函式透過將堆疊指標減去某值來配置其堆疊框。典型的 RISC-V 序言是 addi sp, sp, -16，接著是 sw ra, 12(sp) 與 sw s0, 8(sp)。對應的尾聲會重新載入 s0 與 ra，執行 addi sp, sp, 16，再以 ret 返回。標準 RISC-V 呼叫慣例讓 sp 保持 16 位元組對齊，這就是小的堆疊框會被向上取整為 16 的原因。配置與釋放只需要一次加法，這也是堆疊儲存遠比堆積配置便宜的原因。

葉函式與 ISA 的差異

在 RISC-V 中，以 jal 進行的呼叫會將返回位址寫入暫存器 ra，因此會呼叫其他函式的函式，必須在第一次呼叫之前將 ra 存入其堆疊框。不呼叫任何函式的葉函式永遠不會覆寫 ra，可以不儲存它就返回；若它也只使用呼叫者保存暫存器，並將區域變數保存在暫存器中，就完全不需要堆疊框。x86 的情況則不同：call 指令總是將返回位址推入堆疊，因此每次呼叫都會存取記憶體。尾呼叫最佳化會將最後的呼叫轉成重複使用目前堆疊框的跳躍，因此深層的尾遞迴不會讓堆疊成長。

堆疊框與堆積，以及常見錯誤

堆疊框的內容只存在到函式返回為止，而堆積上的物件則持續存在直到被釋放。因此回傳指向區域變數的指標是錯誤的：那塊記憶體會屬於下一個被推入的堆疊框。無上限或極深的遞迴會耗盡堆疊（每個執行緒的堆疊大小固定，通常為數 MB 以下），造成堆疊溢位。寫入超過區域陣列的結尾，可能會覆寫已儲存的返回位址，這是典型的安全漏洞；編譯器以堆疊金絲雀來對抗它，也就是在尾聲中返回前檢查的防護值。

練習堆疊框的題目

不呼叫其他函式的函式（葉函式、leaf function），在很多情況下不需要將ra保存到堆疊。下列何者是其理由？

  1. A因為葉函式不使用ret指令
  2. B因為葉函式的返回位址是由CPU自動堆入堆疊
  3. C因為不呼叫其他函式，ra不會被覆寫，返回位址會原封不動地保留
查看答案與解析

正確答案：C. 因為不呼叫其他函式，ra不會被覆寫，返回位址會原封不動地保留

ra會在每次呼叫函式的jal時被覆寫，所以呼叫其他函式的函式，必須一開始就將自己的返回位址保存到堆疊。葉函式不使用jal，所以ra不會被破壞，不必保存就能ret。此外，如果也不使用被呼叫端保存的暫存器，甚至不需要建立堆疊框（stack frame）。x86的call指令一定會將返回位址堆入堆疊，這是與RISC-V的差異。

下列何者是在RISC-V函式開頭執行「addi sp, sp, -16」的目的？

  1. A讓堆疊往位址較小的方向延伸，確保16位元組的工作區域
  2. B釋放堆疊上的16位元組
  3. C將sp中的值減16，作為回傳值回傳
查看答案與解析

正確答案：A. 讓堆疊往位址較小的方向延伸，確保16位元組的工作區域

依包含RISC-V在內的許多ISA的慣例，堆疊是從位址較大的一方往較小的一方延伸。將sp減16，則從新的sp到原本的sp之間的16位元組，就成為這個函式的堆疊框，可以放置返回位址、已保存的暫存器及區域變數。在函式結束時以「addi sp, sp, 16」將sp還原，區域就會被釋放，回到與呼叫前相同的狀態。

常見問題

堆疊指標和框架指標有什麼差別？

堆疊指標標示目前堆疊的頂端，在函式執行期間可能移動。框架指標（若有使用）則保存目前堆疊框內的固定位址，讓區域變數與已儲存的暫存器可用固定偏移找到，這也有助於除錯器追溯呼叫鏈。

為什麼深層遞迴會造成堆疊溢位？

每次遞迴呼叫都會配置新的堆疊框，而堆疊有固定的最大容量。遞迴夠深時，堆疊框就會超出該空間；尾呼叫最佳化或將遞迴改寫成迴圈可避免這種成長。

為什麼函式不應該回傳指向區域變數的指標？

區域變數位於函式的堆疊框中，而堆疊框在返回時會被釋放，並由之後的呼叫重複使用。該指標所指向的記憶體內容因此隨時可能改變。
