什麼是環境切換

切換在CPU上執行的行程或執行緒。儲存並還原暫存器與程式計數器等狀態，切換行程時也會切換位址空間。

日文名稱: コンテキストスイッチ

「環境切換」出現在1領域的4道練習題中（作業系統與硬體等）。

這個名詞所屬的領域: 作業系統與硬體

儲存與還原哪些內容

核心會儲存即將讓出的執行緒的 CPU 狀態，也就是其通用暫存器、程式計數器、堆疊指標，以及先前模式等狀態位元，之後再重新載入，使該執行緒能從停止處精確地繼續執行。浮點與向量暫存器也是狀態的一部分，有些核心只在下一個執行緒實際使用時才延遲儲存它們。在行程之間切換時，指向頁表的暫存器也會變更，讓新行程擁有自己的位址空間。記憶體內容與開啟的檔案則留在原處，不會被複製。

何時發生切換

當執行中的執行緒被阻塞（例如等待磁碟 I/O 或鎖）、主動讓出，或計時器中斷告知排程器其時間片已用完、應改由其他執行緒執行時，就會觸發切換。在每種情況下，CPU 都已經在核心中處理系統呼叫或中斷，由排程器挑選下一個執行緒。同一行程內的執行緒之間切換成本較低，因為位址空間不會改變。

直接成本與間接成本

儲存與載入暫存器花費的時間很少；包含排程在內的整個核心路徑，通常約為微秒量級。更大的成本往往是間接的：新行程會發現快取與 TLB 中充滿前一個行程的資料與位址轉換，因此在它們暖機之前會反覆失誤。以位址空間識別碼（ASID）標記 TLB 項目的 CPU，可避免每次切換都清空 TLB，但快取暖機的成本仍然存在。因此，頻繁的切換對吞吐量的影響，會比單看切換時間所預期的更大。

環境切換與模式切換的差異

系統呼叫或中斷會使 CPU 從使用者模式切換到特權模式再返回，但之後繼續執行的是同一個行程；這是模式切換，而不是環境切換。環境切換會改變由哪個執行緒或行程擁有 CPU。兩者經常同時發生，因為切換總是在核心內進行，但返回原呼叫者的系統呼叫完全不涉及環境切換。

練習環境切換的題目

在環境切換（context switch）時，必須儲存切換前行程的哪些內容？

  1. A該行程所使用的磁碟檔案內容
  2. B暫存器的值與程式計數器等CPU的執行狀態
  3. C該行程在實體記憶體中的全部內容
查看答案與解析

正確答案：B. 暫存器的值與程式計數器等CPU的執行狀態

在環境切換時，為了之後能從相同狀態繼續執行，會儲存通用暫存器、程式計數器、堆疊指標、運作模式等CPU的狀態，並載入接下來要執行行程的狀態。切換行程時，也會一併切換指示頁表位置的暫存器。記憶體與檔案的內容原本就保留著，因此不必在每次切換時儲存。

行程的環境切換有時造成的效能下降，實際上比儲存與還原暫存器所花的時間更大，其主要理由為何？

  1. A因為每次切換，CPU的時脈頻率都會下降
  2. B因為每次切換，都要重新從磁碟讀取程式
  3. C因為切換之後，快取與TLB的未命中會增加
查看答案與解析

正確答案：C. 因為切換之後，快取與TLB的未命中會增加

儲存與還原暫存器本身只需很短的時間，但對切換後的行程而言，快取與TLB裡的內容是前一個行程的，在重新載入所需的資料與轉換結果之前，未命中會持續發生。在沒有ASID的CPU上，切換位址空間時還必須清空TLB。這種間接的成本，有時會比直接的切換時間更大。時脈並不會下降，也不會從磁碟重新讀取程式。

常見問題

環境切換時會儲存什麼？

即將讓出的執行緒的 CPU 狀態：暫存器、程式計數器、堆疊指標與狀態資訊；切換行程時還包括頁表指標。記憶體本身不會被儲存，因為它留在原處。

為什麼環境切換的成本很高？

除了核心本身的工作之外，切入的行程一開始面對的快取與 TLB 都存放著另一個行程的內容，因此在重新填入之前會發生許多失誤。

系統呼叫算是環境切換嗎？

不算。系統呼叫是同一行程內的模式切換；只有當核心決定在返回前改為執行其他執行緒或行程時，才會發生環境切換。

解析中的「環境切換」

  • 在環境切換時，為了之後能從相同狀態繼續執行，會儲存通用暫存器、程式計數器、堆疊指標、運作模式等CPU的狀態，並載入接下來要執行行程的狀態。

    在環境切換（context switch）時，必須儲存切換前行程的哪些內容？

  • 環境切換是切換要執行的行程，需求分頁則是在需要時才載入分頁的方式。

    應用程式請求作業系統進行檔案讀寫等操作的機制稱為什麼？

  • 一旦發生中斷，CPU必定會轉移到核心的中斷處理常式，因此即使程式陷入無限迴圈，作業系統也能取回控制權，並環境切換到其他行程。

    作業系統即使面對不主動釋出CPU的程式，仍能每隔一段時間取回CPU並切換到其他行程，主要是靠什麼機制？

出現「環境切換」的題目（4題）

  1. 在環境切換（context switch）時，必須儲存切換前行程的哪些內容？
  2. 行程的環境切換有時造成的效能下降，實際上比儲存與還原暫存器所花的時間更大，其主要理由為何？
  3. 應用程式請求作業系統進行檔案讀寫等操作的機制稱為什麼？
  4. 作業系統即使面對不主動釋出CPU的程式，仍能每隔一段時間取回CPU並切換到其他行程，主要是靠什麼機制？

出現這個名詞的比較

  • 行程與執行緒的差異：比較記憶體、切換與使用時機以記憶體、建立成本、情境切換、通訊、隔離、同步與用途等面向，用表格比較行程與執行緒。
  • 使用者模式與核心模式的差異：指令、記憶體、切換、成本、保護比較從可執行的指令、可存取的記憶體、切換的觸發條件、切換的成本、錯誤的影響、保護的目的等面向，以表格比較使用者模式與核心模式。
  • 自旋鎖與互斥鎖的差異：等待方式、CPU 使用、持有時間、核心中的用法比較從等待方式（忙碌等待與睡眠）、CPU 使用、適合的持有時間、核心中的用法（中斷內文）、優先權反轉與實作範例（futex）等面向，比較自旋鎖與互斥鎖。
