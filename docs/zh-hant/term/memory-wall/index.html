什麼是記憶體牆

記憶體頻寬與延遲的改善跟不上處理器運算性能的提升，使整體性能受限的問題。以 HBM、快取容量增大、先進封裝等來因應。

日文名稱: メモリウォール

「記憶體牆」出現在2領域的2道練習題中（DRAM, 先進技術（3D構裝與小晶片）等）。

這個名詞所屬的領域: DRAM

差距從何而來

數十年來處理器效能快速成長，起初靠時脈速度，後來靠更多核心與更寬的向量單元，而 DRAM 主要針對密度與每位元成本最佳化。DRAM 的存取延遲一直停留在數十奈秒，因此在數 GHz 的時脈下，存取主記憶體的一次未命中要花上數百個週期。「記憶體牆」一詞在 1990 年代中期廣為流傳，用以警告最終限制系統效能的將是這個不斷擴大的差距，而不是處理器核心。

延遲牆與頻寬牆

這個問題有兩個面向。延遲會傷害具有相依存取的程式碼，例如沿著鏈結結構追蹤指標，每次載入都必須完成後才知道下一個位址。頻寬則會傷害每次運算都存取大量資料的串流式程式碼。Roofline 模型描述了頻寬這一面：可達到的效能是峰值運算能力與「記憶體頻寬乘以運算強度」兩者中較低者，運算強度是指每搬移一個位元組所執行的運算數。運算強度低的程式碼，無論有多少核心都達不到峰值運算能力。

為什麼 AI 工作負載受到重擊

大型神經網路擁有數十億個權重，在小批次下產生一個 token，基本上要將每個權重讀取一次，而每個權重只進行一次乘法與一次加法。以 16 位元權重而言，大約是每位元組一次運算，而現代加速器對其記憶體提供的每個位元組可執行數百次運算。因此運算單元都在等待記憶體。將請求批次化、將權重量化為較少位元，以及將資料保留在晶片上，都能提高運算強度或減少搬移的位元組數。

設計者如何反擊

多層快取利用局部性，使大多數存取永遠不會到達 DRAM，硬體預取器則在資料被請求之前就先取來。亂序執行核心與擁有數千個執行緒的 GPU 讓許多未命中同時進行，以隱藏延遲。以先進封裝放在處理器旁的高頻寬記憶體（HBM），以及堆疊在晶粒上的大型快取，可直接提高頻寬。記憶體內運算與近記憶體運算則走相反的路線，將部分運算移到資料所在之處，而不是搬移資料。

練習記憶體牆的題目

相較於處理器效能的提升，記憶體的頻寬與延遲的改善跟不上，因而產生的效能限制稱為什麼？

  1. A摩爾定律
  2. B矽週期
  3. C記憶體牆（memory wall）
查看答案與解析

正確答案：C. 記憶體牆（memory wall）

處理器的運算效能曾有一段時期以每年50%以上的速度成長，但DRAM的存取延遲自數十ns起幾乎沒有改善，使CPU得等待資料長達數百個週期。這就是記憶體牆。作為對策，正持續推進多層快取、記憶體的平行存取、預取、HBM這類高頻寬記憶體，以及在記憶體附近進行運算的記憶體內處理（processing-in-memory）等。

相較於處理器運算效能的提升，從記憶體供應資料的速度跟不上，進而限制整體效能的問題稱為什麼？

  1. A熱牆
  2. B記憶體牆（memory wall）
  3. C摩爾定律
查看答案與解析

正確答案：B. 記憶體牆（memory wall）

處理器的運算效能快速提升，但與記憶體之間資料傳輸的速度（頻寬）成長較為緩慢，運算單元等待資料的時間因此增加。這稱為記憶體牆。大型AI模型每次運算都要讀取大量權重，因此特別嚴重，將HBM安裝在處理器附近的先進封裝，以及大容量快取的堆疊，就是因應的對策。

常見問題

記憶體牆指的是延遲還是頻寬？

兩者都是。延遲限制進行相依記憶體存取的程式，頻寬則限制相對於其運算量而串流大量資料的程式。

HBM 如何幫助解決記憶體牆？

HBM 將 DRAM 晶粒堆疊在處理器旁邊，並使用非常寬的介面，提供比傳統 DIMM 高得多的頻寬。它主要針對頻寬這一面；延遲仍停留在相同的數十奈秒範圍。

為什麼大型語言模型受記憶體限制？

在小批次生成時，每個權重從記憶體取出後只用於少數幾次運算。加速器的運算速度遠快於記憶體提供權重的速度。
