什麼是目的檔（Object file）

編譯器從單一原始碼檔案輸出的檔案。包含機器碼、資料的初始值、符號表與重定位資訊，但其他檔案的位址尚未確定，不經連結就無法執行。

日文名稱: オブジェクトファイル

「目的檔（Object file）」出現在2領域的9道練習題中（連結器與載入器與執行檔格式, 編譯器等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

練習目的檔（Object file）的題目

關於編譯器從單一原始檔輸出的目的檔（.o），下列何者正確？

  1. A是可直接在作業系統上執行的完整程式
  2. B只是將原始碼壓縮而成，不含機器碼
  3. C含有機器碼，但其他檔案中的函式與變數的位址尚未決定
查看答案與解析

正確答案：C. 含有機器碼，但其他檔案中的函式與變數的位址尚未決定

目的檔中包含該檔案內函式經翻譯後的機器碼、變數的初始值、所定義與所參照的名稱清單（符號表），以及事後要填入位址的位置清單（重定位資訊）。像printf這樣呼叫其他檔案中函式的指令，由於不知道位址，仍保留暫時的值。連結器會將多個目的檔整合起來決定位址，進而產生執行檔。

使用GNU連結器時，若像「gcc -lmylib main.o」這樣，將靜態函式庫寫在使用它的目的檔之前，有時會出現未定義參照的錯誤。下列關於其原因的敘述何者正確？

  1. A因為連結器從左到右依序處理，讀取函式庫的時點上尚未被參照的函式不會被取出
  2. B因為規定函式庫必須且只能寫在指令的最後一個
  3. C因為將函式庫寫在前面，函式庫的內容會被清除
查看答案與解析

正確答案：A. 因為連結器從左到右依序處理，讀取函式庫的時點上尚未被參照的函式不會被取出

GNU連結器依命令列上所寫的順序處理檔案，遇到靜態函式庫時，只會取出能解決「尚未找到定義的參照」的目的檔。若先寫函式庫，在那個時點main.o的參照還不存在，所以什麼都不會取出，之後再讀取main.o也不會回頭尋找。因此原則上函式庫要寫在使用它的一方之後。

解析中的「目的檔（Object file）」

  • C語言的原始檔，首先由編譯器轉換為接近機器碼的組合語言（或直接轉成目的檔），再由組譯器變成機器碼的目的檔。

    從C語言的程式到產生執行檔的一般流程，下列何者正確？

  • 連結器會將各目的檔中所參照的名稱（符號），對應到其他地方所定義的實體（符號解析），並排列各檔案的程式碼與資料以決定最終位址，再將指令中的暫時位址改寫為正確的值（重定位）。

    關於連結器的主要功能，下列何者正確？

  • 連結器會蒐集所有目的檔的符號表，為每個參照找出一個對應的定義。
