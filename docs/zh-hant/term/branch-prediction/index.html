什麼是分支預測

在執行前預測條件分支的結果，不使管線停頓而處理後續指令的技術。預測錯誤時會重新處理。

日文名稱: 分岐予測

「分支預測」出現在6領域的20道練習題中（硬體安全, CPU與架構, 效能評估與效能剖析等）。

這個名詞所屬的領域: CPU與架構

管線為什麼需要分支預測

管線化 CPU 每個週期都會擷取新指令，但條件分支是否成立、要跳到哪裡，要到幾個階段之後執行時才會知道。若等待結果，管線就會閒置，而大約每五道指令就有一道是分支。分支預測則在擷取時就猜測結果，並沿著預測的路徑繼續推測執行。猜對時不會損失任何時間；猜錯時，推測執行的指令會被清除而不影響架構狀態，並從正確路徑重新擷取，在深管線中要付出十幾到約二十個週期的代價。

預測器如何猜測

靜態方案使用固定規則，例如預測往回跳的分支（迴圈）會成立、往前跳的分支不成立。動態預測器則從歷史中學習：以分支位址為索引的 2 位元飽和計數器表，需要連續兩次猜錯才會翻轉預測，因此迴圈結束時只會造成一次預測失誤。更好的預測器會把位址與最近結果的全域歷史結合，以捕捉分支之間的相關性。預測方向只是工作的一半；分支目標緩衝區（BTB）提供目標位址，返回位址堆疊則用來預測函式返回。

預測失誤的代價

其影響可以用增加的每指令週期數（CPI）來估算：分支頻率 × 預測失誤率 × 懲罰週期。在分支佔 20%、準確率 95%、懲罰 20 個週期時，就是 0.2 × 0.05 × 20 = 0.2 的額外 CPI，佔了現代核心預算的一大部分。這就是為什麼一、兩個百分點的準確率提升也很重要。對於取決於隨機資料而無法預測的分支，編譯器與程式設計師有時會使用條件搬移等無分支程式碼，以多一點工作換取保證不會發生清除。

推測執行與安全性

預測錯誤的指令在架構層面上會被捨棄，但仍可能在快取等微架構狀態中留下痕跡。Spectre 類攻擊會訓練預測器，使受害程式推測性地讀取機密資料，並透過快取時序洩漏出去。防禦方法包括在敏感的邊界檢查後加入推測屏障（例如 x86 的 lfence）、遮罩陣列索引、針對間接分支的 retpoline 序列，以及透過微碼控制預測器。每一項限制都會犧牲效能，因此會選擇性地套用。MIPS 等較舊的指令集架構使用分支延遲槽而非預測，這條規則後來成為後續設計的負擔。

練習分支預測的題目

關於 CPU 分支預測的目的，下列何者正確？

  1. A預測分支指令的結果並提前執行後續指令，以減少管線停頓
  2. B預測功耗並控制電源
  3. C預測主記憶體的容量
查看答案與解析

正確答案：A. 預測分支指令的結果並提前執行後續指令，以減少管線停頓

在管線中，必須等到分支指令的結果確定，下一道指令才能決定，處理因而會停住。分支預測會根據過去的歷史等資訊預測分支目的地並繼續向前執行，只有在預測錯誤時才重做。程式中約每 5 道指令就有 1 道是分支，因此影響很大，現今的高效能 CPU 預測準確率超過 95%。一次預測失誤會損失十幾〜二十個時脈左右，因此即使準確率只提升一點點，也會影響效能。

以效能計數器發現分支預測錯誤非常多。下列何者是適用的改善方法？

  1. A在迴圈中再增加分支
  2. B將資料排序，使分支的結果更容易預測，或是以條件選擇或運算來消除分支本身
  3. C減少快取的容量
查看答案與解析

正確答案：B. 將資料排序，使分支的結果更容易預測，或是以條件選擇或運算來消除分支本身

一旦分支預測錯誤，CPU就必須丟棄推測性執行的指令並重新來過，每次會損失十幾個週期以上。若資料是隨機的，像「值在128以上的話」這類分支的結果就無法預測。若事先將資料排序，結果會趨於一致而使預測容易命中；若改用條件選擇指令或位元運算來撰寫，分支本身就會消失。也可以促使編譯器進行這類轉換。

常見問題

分支預測失誤時會發生什麼事？

CPU 會捨棄沿錯誤路徑推測擷取與執行的指令，並從正確的目標重新開始，在典型的深管線中約損失 10 到 20 個週期。

現代 CPU 的分支預測準確率有多高？

高效能預測器在一般程式碼上的準確率通常超過 95%，不過取決於隨機資料的分支可能難預測得多。

分支預測和推測執行有什麼差別？

分支預測是猜測分支會往哪個方向走；推測執行則是在猜測被確認之前，實際沿著所猜測的路徑執行指令。
