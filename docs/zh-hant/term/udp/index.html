什麼是UDP（使用者資料包協定）

User Datagram Protocol的縮寫。傳輸層的非連線型協定。標頭為8位元組，只有連接埠號碼、長度與檢查和。不建立連線，也不做確認應答、重傳與順序控制，因此延遲小。用於DNS查詢、語音與視訊通話、線上遊戲、DHCP、QUIC等。

日文名稱: UDP

「UDP（使用者資料包協定）」出現在2領域的4道練習題中（電腦網路基礎, Web技術基礎等）。

這個名詞所屬的領域: 電腦網路基礎

標頭與資料包

UDP標頭由來源連接埠號碼、目的地連接埠號碼、長度、檢查和4個欄位（各16位元）組成，合計8位元組。應用程式一次送出的資料就是一個資料包，接收端也能以相同的分隔收到（不像TCP是位元組流）。檢查和在IPv4中可以省略，在IPv6中則是必須的。大的資料包會在IP層被分割而容易遺失，因此一般會讓大小收在MTU之內。

選擇UDP的場合

在通話與直播中，延遲送達的資料已經沒有用處，等待重傳反而會讓聲音與影像斷斷續續。像DNS查詢這樣一問一答就結束的通訊，省略建立連線的程序可以減少等待時間。UDP也能用於一對多的廣播與多播，因此還沒有IP位址的終端所使用的DHCP也是UDP。需要可靠性的應用程式，會像QUIC那樣在UDP之上自行實作重傳與順序控制。

使用時的注意事項

UDP資料包可能遺失、重複或順序錯亂，因此應用程式要自行處理，例如替資料加上編號。UDP本身沒有壅塞控制，大量傳送時也要由應用程式調整傳送速度。NAT的對應關係在一段時間沒有通訊後就會消失，因此有時會定期送出小封包加以維持。由於沒有建立連線的程序、來源位址容易偽造，UDP也被用於反射與放大型的DDoS攻擊，例如濫用會對小查詢回傳大回應的DNS。

練習UDP（使用者資料包協定）的題目

在TCP/IP的四層模型中，TCP與UDP屬於哪一層？

  1. A應用層
  2. B網際網路層
  3. C傳輸層
查看答案與解析

正確答案：C. 傳輸層

TCP/IP模型由下而上分為連結層（網路介面層）、網際網路層、傳輸層、應用層4層。TCP與UDP是傳輸層的協定，使用連接埠號碼區分通訊是要送給終端上的哪一個應用程式。網際網路層的IP負責把封包從一台終端送到另一台終端。HTTP與DNS則是應用層的協定。若與OSI參考模型對應，傳輸層相當於第4層，網際網路層相當於第3層。

下列關於UDP特徵的敘述，何者正確？

  1. A不建立連線，也不控制重傳與順序，因此標頭小，傳送前也不需等待
  2. B會建立連線，重傳未送達的資料，並在接收端整理順序
  3. C不使用IP位址，只用MAC位址把資料送到目的地終端
查看答案與解析

正確答案：A. 不建立連線，也不控制重傳與順序，因此標頭小，傳送前也不需等待

UDP是在IP之上只加入連接埠號碼與簡單錯誤偵測（檢查碼）的輕量協定，標頭為8位元組（TCP在無選項時為20位元組）。它沒有建立連線的程序，也不確認是否送達、不重傳，因此用於寧可少量遺失也不要延遲的語音通話與直播影像，以及只需一次查詢與回應的DNS等。若需要可靠性，則由應用程式端補足。例如HTTP/3使用的QUIC，就是在UDP之上實作重傳與加密。建立連線、重傳、控制順序是TCP的工作。

常見問題

UDP沒有可靠性，為什麼還要使用？

因為不必等待建立連線或重傳，延遲小、標頭也小。適合比起少量資料缺漏、更重視低延遲的通話與遊戲，以及一個往返就結束的DNS查詢。需要可靠性時，可以像QUIC那樣在UDP之上實作重傳等功能。

以UDP送出的資料會依順序送達嗎？

沒有保證。可能因路徑不同而順序錯亂，也可能遺失或重複送達。如果順序很重要，應用程式要替資料加上編號再重新排序。
