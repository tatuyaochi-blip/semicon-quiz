什麼是FMA(融合乘加運算)

以一個指令計算 a × b + c，中間的乘積不捨入，只在最後捨入一次的運算。比分開進行乘法與加法更快，誤差也更小。大量用於矩陣計算等。

日文名稱: FMA(融合積和演算)

「FMA(融合乘加運算)」出現在2領域的2道練習題中（電腦算術, 編譯器等）。

這個名詞所屬的領域: 電腦算術

捨入一次而非兩次

兩個 p 位元有效數相乘，會產生最多 2p 位元的精確乘積。分開的乘法指令會把乘積捨入到 p 位元，接下來的加法再捨入一次。FMA（融合乘加）單元則保留全寬度的乘積，將 c 與其對齊後相加，只捨入一次，因此結果是 a × b + c 的精確值經正確捨入後的值。IEEE 754-2008 將此運算標準化，C 語言以 fma 函式提供，而目前大多數 CPU 與 GPU 指令集都包含它，例如 RISC-V F 與 D 擴充中的 fmadd.s 與 fmadd.d。

FMA 發揮效益之處

內積、矩陣乘法與卷積都是一長串的乘積累加步驟，因此 FMA 既能讓指令數減半，又能改善精度。以 Horner 法求多項式值時，每一步都是 r = r × x + c 的形式，完美契合。迭代式的除法與平方根演算法仰賴 FMA 精確計算殘差。一個巧妙的技巧是：若 p 是 a 與 b 捨入後的乘積，則 fma(a, b, -p) 會給出該乘積的精確捨入誤差，這是延伸精度算術的基本構件。依慣例，浮點峰值效能數字會把每次 FMA 算作兩次運算。

可重現性的陷阱

由於 FMA 的捨入方式不同，啟用它可能使結果的最後幾個位元與分開的乘法和加法不同。編譯器可能依語言規則與編譯旗標，自動把 a * b + c 縮合成 FMA（在 GCC 與 Clang 中由 -ffp-contract 控制），因此同一份原始碼在不同目標平台或最佳化等級下，可能得到些微不同的答案。FMA 也可能破壞預期的對稱性：當 a 等於 b 時，把 a * a - b * b 計算成 fma(a, a, -(b * b))，傳回的是 b * b 的捨入誤差，而不是精確的零。

FMA 與整數乘積累加的比較

整數乘積累加指令同樣計算 a × b + c，但整數運算沒有捨入，因此融合兩者只能節省時間與暫存器。精度方面的論點是浮點數特有的。在數位訊號處理器與 AI 加速器中，寬位元累加器扮演類似的角色：窄位元值的乘積在較寬的暫存器中加總，使精度不會在每一步流失，只有最終總和才被捨入或縮放。

練習FMA(融合乘加運算)的題目

以FMA（融合乘加運算）指令計算 a × b + c 的優點，下列何者正確？

  1. A中間的乘積不做捨入，只在最後捨入1次，因此誤差小且快速
  2. B乘法的結果必定先轉為整數再相加，因此完全不會產生誤差
  3. C省略加法而只做乘法，因此計算減半
查看答案與解析

正確答案：A. 中間的乘積不做捨入，只在最後捨入1次，因此誤差小且快速

若以乘法與加法各別的指令進行，會先將 a × b 的結果捨入一次，再將加上 c 的結果捨入一次，因此發生2次捨入。FMA則是將乘積不經捨入而保留在內部，再加上 c，最後只捨入1次，所以誤差較小。由於1個指令即可完成，速度很快，廣泛用於矩陣乘法、多項式的計算以及AI的運算等。它並不會把乘積轉為整數，也不會省略加法。不過由於捨入次數不同，結果可能與分開計算的結果有些許差異。

常見問題

啟用 FMA 後，浮點運算結果為什麼會改變？

FMA 對 a × b + c 只捨入一次而非兩次，因此其結果的最後幾個位元可能與分開的乘法和加法不同。FMA 的結果通常較精確，但並非逐位元相同。

一次 FMA 算一個還是兩個 FLOP？

依慣例算兩個：一次乘法與一次加法。這就是為什麼具備 FMA 單元之硬體的峰值吞吐量數字，是每秒 FMA 指令數的兩倍。

C 語言的 fma 函式做什麼？

math.h 中的 fma(x, y, z) 傳回以如同無限精度計算的 x × y + z，並對結果型別捨入一次。在沒有 FMA 指令的硬體上，它以軟體模擬，可能很慢。
