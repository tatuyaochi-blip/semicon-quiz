什麼是推測執行（Speculative execution）

在分支結果等確定之前，依預測先執行後面指令的 CPU 機制。預測錯誤時會取消結果，但快取等處可能會留下痕跡。

日文名稱: 投機的実行

「推測執行（Speculative execution）」出現在1領域的6道練習題中（硬體安全等）。

這個名詞所屬的領域: 硬體安全

CPU 為何要提前執行

高效能 CPU 具有很深的管線，並以亂序方式執行指令，因此若等待每個分支都確定，就會閒置許多週期。實際上，分支預測器會猜測結果，核心則沿著預測的路徑持續擷取並執行指令。這些推測性的結果保存在內部緩衝區中，只有在猜測被確認後才會提交（retire）。若預測錯誤，核心會捨棄推測執行的工作並從正確的路徑重新開始，因此程式可見的結果永遠是正確的。

架構狀態與微架構狀態

回復預測錯誤時，會還原架構狀態，也就是程式能直接觀察到的暫存器與記憶體。但它不會撤銷微架構狀態的變化，例如哪些快取行在快取中、TLB 的內容或預測器的歷史。這些變化通常無害，因為程式無法直接讀取它們，但時間可能會洩漏它們：存取已在快取中的快取行，明顯比存取主記憶體快。這種「哪些會回復、哪些不會」之間的落差，正是推測執行漏洞的根源。

Spectre 與 Meltdown 如何利用它

在 2018 年與 Meltdown 一同公開的 Spectre 中，攻擊者訓練分支預測器，使一條本不應執行的路徑（例如越過邊界檢查的程式碼）被推測執行、讀取機密，並以該值存取某個特定的快取行。結果雖被捨棄，但量測哪個快取行已在快取中的時間，就能透過快取旁通道洩漏機密。Meltdown 則濫用了某些 CPU 的特性：推測性載入在權限檢查生效之前就能傳回核心記憶體中的資料。幾乎所有高效能 CPU 都受到至少一種變體的影響。

對策及其代價

緩解措施遍及各個層級：作業系統將核心與使用者的分頁表分開，編譯器插入推測屏障或使用能避免被汙染之預測的間接分支序列，微碼更新加入了對預測器行為的控制，較新的 CPU 則內建硬體修正。對推測、預測或共享快取的每一項限制都能減少洩漏，但也可能犧牲效能，因此設計者會依據所涉及的資料決定要做到什麼程度。這起事件顯示，即使軟體本身沒有錯誤，效能功能也可能成為安全弱點。

練習推測執行（Speculative execution）的題目

下列關於稱為Spectre的推測執行漏洞的原理，何者正確？

  1. A因CPU的運算錯誤，加法的結果會改變
  2. B依分支預測而推測執行的指令，即使結果被取消，載入快取的痕跡仍會殘留，並能以時間測量讀取出來
  3. C因推測執行而使CPU溫度過度上升
查看答案與解析

正確答案：B. 依分支預測而推測執行的指令，即使結果被取消，載入快取的痕跡仍會殘留，並能以時間測量讀取出來

CPU在分支結果確定之前，會先執行預測那一側的指令，預測錯誤時再捨棄結果。在Spectre中，攻擊者讓分支預測出錯，在原本不會執行的路徑上讀取機密資料，並使對應該值的位置被載入快取。即使結果被取消，快取的狀態也不會復原，因此可藉由快取旁路推測出該值。

下列關於為何即使推測執行的指令結果被取消，Spectre這類攻擊仍會洩漏資訊的原因，何者正確？

  1. A因為取消處理失敗，暫存器中殘留機密的值
  2. B因為推測執行的結果會被儲存到磁碟
  3. C因為被取消的只有暫存器等架構（architectural）狀態，快取等微架構（microarchitectural）狀態不會復原
查看答案與解析

正確答案：C. 因為被取消的只有暫存器等架構（architectural）狀態，快取等微架構（microarchitectural）狀態不會復原

CPU被設計成，對於程式可見的狀態（暫存器與記憶體的內容），預測錯誤時會完全復原。然而快取的內容與分支預測器的狀態等微架構狀態，屬於為了提升效能的內部狀態，不會被復原。即使遵守了ISA的約定，內部狀態仍會以時間差異的形式被外界看見，這正是此類漏洞的本質。

常見問題

推測執行和亂序執行是一樣的嗎？

兩者相關但不同。亂序執行是將輸入已就緒的指令重新排序執行，而推測執行是在還不知道指令是否該執行時就先執行它們，例如位於尚未確定之分支後的指令；現代核心兩者都會做。

Spectre 和 Meltdown 有什麼不同？

Spectre 誘使分支預測器推測執行合法的程式路徑，洩漏受害程式可存取的資料。Meltdown 則利用了推測性載入能在權限檢查生效前讀取核心記憶體的 CPU，大致已透過核心分頁表隔離及後來的硬體變更修正。

為什麼被捨棄的推測結果仍會洩漏資料？

CPU 會捨棄暫存器中的結果，但不會還原快取，因此推測期間載入的資料會留下痕跡，可藉由量測存取時間偵測出來。

解析中的「推測執行（Speculative execution）」
