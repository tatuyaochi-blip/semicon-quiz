什麼是捨入至最接近偶數

捨入到可表示的值中最接近的值，恰好在中間時則捨入到最低位元為偶數(0)的一方的方法。是IEEE 754的預設捨入，捨入誤差不會偏向單一方向。

日文名稱: 最近接偶数丸め

「捨入至最接近偶數」出現在1領域的2道練習題中（電腦算術等）。

這個名詞所屬的領域: 電腦算術

硬體如何偵測「恰好在中間」

精確的運算結果，其有效數位元數通常多於目標格式所能容納的位數。除了保留的位元之外，硬體還會追蹤第一個被捨棄的位元，稱為捨入（round，或 guard）位元，以及一個黏著（sticky）位元，它是其下所有位元的 OR。若捨入位元為 0，結果直接截斷；若捨入位元為 1 且黏著位元為 1，則結果的絕對值進位。只有在捨入位元為 1、黏著位元為 0 時，數值才恰好在中間，此時由最後一個保留位元決定：若為 1，就進位使其變成 0。

平局為何要取偶數

若每次平局都向上捨入，每次都會加上一點正誤差，經過大量運算後，這些誤差就會朝同一方向累積。把平局送往偶數的一方，大約一半向上、一半向下，因此誤差傾向互相抵消。以十進位而言，2.5 變成 2、3.5 變成 4，兩者總和 6 得以保持，而總是向上捨入則會得到 7。此方法也稱為銀行家捨入（banker's rounding）；在二進位浮點數中，偶數的一方是有效數最低位元為 0 的那一個。

IEEE 754 的其他捨入模式

IEEE 754 也定義了定向捨入：朝零（截斷）、朝正無限大與朝負無限大。這些模式是為了特殊用途而明確選用的；例如區間運算以向下捨入計算下界、以向上捨入計算上界，保證真正的結果一定落在兩者之間。2008 年的修訂版新增了平局時遠離零捨入（round half away from zero），主要是十進位格式所要求。捨入至最接近偶數仍是算術運算與轉換的預設模式，而正確捨入的運算定義為以目前模式捨入的精確結果。

讓程式設計師意外之處

Python 3 內建的 round 遵循平局取偶，因此 round(2.5) 傳回 2，對期待學校教的四捨五入的人來說，看起來像是錯誤。第二個意外來自數值表示：像 2.675 這樣的十進位值無法以二進位精確儲存，最接近的 double 略小於它，因此不論平局規則為何，捨入到小數點後兩位都會得到 2.67。當結果必須遵循特定的十進位捨入慣例時，例如財務計算，通常的解法是使用可明確指定捨入模式的十進位算術型別。

兩者都剛好在正中間，因此捨入至偶數的那一邊。2.5位於2與3的正中間，捨入至偶數的2。3.5位於3與4的正中間，捨入至偶數的4。若採用正中間一律進位的四捨五入，會得到3與4，合計為7，比原本的合計6大了1；而捨入至偶數則是 2 + 4 = 6，合計得以維持。2與3是正中間一律捨去時的結果。這種方式的優點在於可以避免捨入誤差的偏向。

常見問題

Python 的 round(2.5) 為什麼傳回 2？

Python 3 把恰好在中間的值捨入到最接近的偶數，這與 IEEE 754 預設使用的規則相同，因此 2.5 變成 2、3.5 變成 4。這能避免大量數值捨入時產生系統性的向上偏差。

銀行家捨入和捨入至最接近偶數是一樣的嗎？

是的。兩個名稱都指捨入到最接近的值，並在恰好平局時選擇最後一位數字或位元為偶數的一方。

IEEE 754 的預設捨入模式是什麼？

捨入至最接近值、平局取偶數。朝零、朝正無限大與朝負無限大的定向模式也可使用，但必須明確選擇。
