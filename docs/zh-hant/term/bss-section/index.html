什麼是BSS 區段（BSS section）

沒有初始值（或為 0）的全域變數與靜態變數的區域。檔案中只記錄大小，載入時以 0 填滿，因此不會讓可執行檔變大。

日文名稱: BSSセクション

「BSS 區段（BSS section）」出現在1領域的2道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

哪些變數會放進 .bss

C 語言規定，所有具有靜態儲存期間的物件，也就是全域變數與 static 變數，若沒有給定初始值，就必須從 0 開始。編譯器會將這類變數放在 .bss 區段，通常明確初始化為 0 的變數也一樣。具有非零初始值的全域變數放在 .data，以 const 修飾的常數則放在唯讀的 .rodata。static 關鍵字並不決定區段，它只是把可見範圍限制在單一檔案內。區域自動變數絕不會出現在 .bss，因為它們位於堆疊上，且沒有定義的初始值。

為什麼 .bss 不佔檔案空間

在可執行檔中儲存一長串 0 只會浪費磁碟空間與載入時間，因此 .bss 區段只記錄其大小與對齊。在 ELF 中，它被標記為不佔用任何檔案位元組。載入器映射包含 .data 與 .bss 的可讀寫節段，當節段的記憶體大小超過其檔案大小時，多出來的部分就以填零的分頁提供。因此，static char buf[1000000]; 這樣的宣告會讓記憶體用量增加約 1 MB，檔案卻幾乎沒有變大。

嵌入式系統中的 BSS

在沒有作業系統的微控制器上，沒有其他人會幫忙把記憶體填零，因此由啟動程式碼來做。在呼叫 main 之前，重置處理常式通常會將 .data 的初始值從快閃記憶體複製到 RAM，並清除 RAM 中的 .bss 範圍，所用的起始與結束位址是由連結器指令檔匯出為符號的。漏掉其中任何一步，全域變數就會帶有垃圾值。size 命令等工具會分別回報 text、data 與 bss，有助於估計快閃記憶體與 RAM 的用量。

名稱的由來

BSS 一般展開為 block started by symbol，這個名稱沿襲自早期 IBM 大型主機上的一個組譯器指令，用來在某個標籤下保留一塊未初始化的儲存區。即使該指令本身早已不復存在，這個意義仍延續到 Unix 的目的檔格式以及後來的 ELF。如今這個名稱單純指零初始化資料區段，與程式碼的 .text、已初始化資料的 .data 以及常數的 .rodata 並列。

練習BSS 區段（BSS section）的題目

關於.bss區段的特徵，下列何者正確？

  1. A是每次函式被呼叫時放置其區域變數的區域
  2. B是沒有初始值（或為0）的變數區域，檔案中只記錄大小，載入時以0填滿
  3. C是放置常數字串、無法寫入的區域
查看答案與解析

正確答案：B. 是沒有初始值（或為0）的變數區域，檔案中只記錄大小，載入時以0填滿

未寫初始值的全域變數與靜態變數，依C語言的規定從0開始。若內容全部為0，將一長串0存入檔案是浪費，因此.bss區段只記錄大小，由載入器配置記憶體並以0填滿。例如即使有「static char buf[1000000];」，執行檔也不會因此增大1 MB。

常見問題

BSS 是什麼的縮寫？

BSS 通常展開為 block started by symbol，源自一個古老的組譯器指令。在現代工具鏈中，它單純是存放零初始化全域變數與 static 變數的區段名稱。

很大的未初始化陣列會讓執行檔變大嗎？

不會。沒有初始值的全域或 static 陣列會放在 .bss，檔案中只記錄其大小；記憶體是在程式載入時才配置並填零。

.data 和 .bss 有什麼差別？

.data 區段存放具有非零初始值的全域變數與 static 變數，這些值必須儲存在檔案中。.bss 區段存放從 0 開始的變數，因此執行時會佔用記憶體，但在檔案中不需要存放內容。
