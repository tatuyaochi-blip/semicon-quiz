什麼是動態連結器（Dynamic linker）

在動態連結的程式啟動時，尋找並載入共享函式庫，進行重定位與符號結合之後再啟動程式的軟體。例如 Linux 的 ld.so。

日文名稱: 動的リンカ

「動態連結器（Dynamic linker）」出現在1領域的10道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

程式啟動時發生什麼事

動態連結的 ELF 執行檔會在其程式標頭中指定一個直譯器，例如 Linux 上的 ld-linux。execve 對應程式之後，核心也會對應該動態連結器，並把控制權交給它而不是程式本身。動態連結器讀取所需函式庫的清單，在設定的路徑與其快取中搜尋，把它們對應到位址空間，套用重定位、繫結符號、執行函式庫的初始化函式（列在 .init_array 等區段中），最後跳到程式的進入點。之後以 dlopen 開啟的函式庫也會經過相同的機制。

GOT、PLT 與延遲繫結

共享函式庫以位置無關程式碼建置，因此其程式碼分頁中不含其他模組的絕對位址。程式碼改為從全域偏移表（GOT）讀取位址，GOT 是由動態連結器填入的可寫入資料表。函式呼叫則經由程序連結表（PLT）的跳板進行。在延遲繫結下，第一次經由跳板的呼叫會進入連結器的解析程式，由它把真正的位址寫入 GOT，之後的呼叫就直接跳到該處。許多系統則改為在啟動時就繫結所有符號，然後把 GOT 設為唯讀（full RELRO），以阻擋 GOT 覆寫攻擊。

動態連結器與靜態連結器

靜態連結器（ld）在建置時執行：它合併目的檔、解析符號並套用大部分的重定位，產生執行檔。動態連結器則在每次程式啟動時執行，為共享函式庫完成剩下的工作。正是這種分工，讓函式庫程式碼的一份實體副本能被許多行程共用，也讓安全修補只需替換一個檔案就能套用到所有程式。代價是啟動時要多做一些工作，而且必須依賴目標機器上存在正確版本的函式庫。

控制與除錯

動態連結程式的啟動失敗，大多是因為缺少函式庫或函式庫不相容；ldd 命令可列出相依項，並顯示哪些找不到。在 Linux 上，LD_LIBRARY_PATH 等環境變數可增加搜尋目錄，LD_PRELOAD 則可把某個函式庫注入到其他函式庫之前，對除錯與插樁很有用。函式庫作者可以只匯出公開函式、並把內部符號標記為 hidden 來加快載入，這能減少動態連結器必須處理的符號，並讓內部呼叫略過 PLT。

練習動態連結器（Dynamic linker）的題目

在Linux等系統中啟動動態連結的程式時，動態連結器（ld.so等）的功用，下列何者正確？

  1. A編譯原始碼以產生機器碼
  2. B尋找所需的共用函式庫並載入記憶體，結合符號後再讓程式開始執行
  3. C程式結束後，整理磁碟的空閒區域
查看答案與解析

正確答案：B. 尋找所需的共用函式庫並載入記憶體，結合符號後再讓程式開始執行

動態連結的執行檔中記載了要使用的動態連結器的位置，作業系統載入程式後，會先把處理交給動態連結器。動態連結器會尋找並載入所需的共用函式庫，進行重定位與符號的結合，然後將控制權移交給程式的入口。使用dlopen在執行中額外載入函式庫的處理，也是由動態連結器負責。

常見問題

Linux 上的 ld.so 是什麼？

它是動態連結器/載入器：核心對動態連結執行檔最先執行的程式，負責載入共享函式庫、解析符號，然後啟動程式。

程式顯示找不到共享函式庫是怎麼回事？

動態連結器在其搜尋路徑中找不到所需的函式庫，或只找到不相容的版本。對程式執行 ldd 即可看出缺少哪個相依項。

GOT 和 PLT 有什麼差別？

GOT 是由動態連結器填入已解析位址的資料表；PLT 則是一組小型程式碼跳板，外部函式呼叫會經由它們跳躍，並從 GOT 讀取跳躍目標。
