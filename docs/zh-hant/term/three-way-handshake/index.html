什麼是三向交握

建立TCP連線的程序。以用戶端的SYN、伺服器的SYN+ACK、用戶端的ACK三次交換，彼此確認對方的初始序號。

日文名稱: 3ウェイハンドシェイク

「三向交握」出現在1領域的2道練習題中（電腦網路基礎等）。

這個名詞所屬的領域: 電腦網路基礎

三次交換的意義

用戶端以SYN請求連線，並告知自己的初始序號。伺服器以SYN+ACK確認已收到該序號，同時告知自己的初始序號。用戶端以ACK確認後，雙方向都確認了「對方知道我的序號」，便可以傳送資料。透過確認序號，可以防止網路中殘留的舊封包造成錯誤的連線。

建立連線所需的時間

開始傳送資料之前，至少需要一個往返時間（RTT）。HTTPS之後還需要TLS的交握，TLS 1.3合計2個往返、TLS 1.2合計3個往返之後，才能送出請求。伺服器越遠RTT越大，因此會以重複使用連線（持續連線），或像HTTP/3的QUIC那樣合併交握等方式，減少往返的次數。

結束連線與SYN洪泛

結束連線時，兩個方向各自以FIN與ACK關閉，因此一般需要4次交換。另外，大量送出偽造來源位址的SYN，讓伺服器累積建立中的連線而耗盡資源的攻擊，稱為SYN洪泛。對策包括不需保存狀態即可回應的SYN cookie等。

練習三向交握的題目

在建立TCP連線的三向交握中，交換封包的順序下列何者正確？

  1. ASYN → ACK → FIN
  2. BACK → SYN → SYN+ACK
  3. CSYN → SYN+ACK → ACK
查看答案與解析

正確答案：C. SYN → SYN+ACK → ACK

三向交握中，首先由用戶端以SYN請求連線，並告知自己要傳送之資料的起始編號（初始序號）。伺服器以SYN+ACK確認（ACK）已收到，同時告知自己的初始序號。最後用戶端回傳ACK，雙向通訊便準備就緒。透過三次交換確認雙方向的序號，可防止延遲抵達的舊封包等造成錯誤的連線。因此，TCP在開始傳送資料之前至少需要一個往返時間（RTT）。FIN用於結束連線。

常見問題

為什麼需要三次而不是兩次交換？

因為必須確認雙方向的初始序號都已被對方收到。只有兩次的話，伺服器無法確認自己的序號已送達用戶端。

UDP也有三向交握嗎？

沒有。UDP不建立連線，因此可以立即傳送資料。在UDP之上運作的QUIC，則進行與加密金鑰交換結合的獨自交握。
