什麼是返回位址

函式處理結束時要返回的位址。在RISC-V中由jal指令將下一個指令的位址放入ra(x1)，在x86中由call指令推入堆疊。

日文名稱: リターンアドレス

「返回位址」出現在3領域的8道練習題中（指令集與組合語言, CPU與架構, 連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 指令集與組合語言

呼叫時如何保存返回位址

函式呼叫必須記錄執行應從哪裡恢復，也就是呼叫指令之後那一道指令的位址。在 RISC-V 中，jal（jump and link）會把 PC + 4 寫入暫存器（慣例上為 ra，即 x1）並跳躍；返回則是 ret，它是 jalr x0, 0(ra) 的虛擬指令。透過函式指標、虛擬函式與共享函式庫跳板（stub）的呼叫，則使用以暫存器為目標的 jalr。在 x86 中，call 把返回位址推入堆疊，ret 再把它彈出到指令指標，因此返回位址一定存放在堆疊上。

葉函式與非葉函式

由於每次 jal 都會覆寫 ra，會呼叫其他函式的 RISC-V 函式必須先保存自己的返回位址。典型的開頭程式碼（prologue）是 addi sp, sp, -16，在往下成長的堆疊上配置一個框架，接著以 sw ra, 12(sp) 與 sw s0, 8(sp) 保存 ra 與一個被呼叫者保存的暫存器。結尾程式碼（epilogue）重新載入它們、恢復 sp 並執行 ret。不呼叫任何函式的葉函式可以把 ra 留在暫存器中，甚至可能完全不需要堆疊框架，使小型函式的成本很低。

攻擊者為何以它為目標

存放在堆疊上的返回位址緊鄰區域緩衝區，因此緩衝區溢位可以覆寫它，在函式返回時改變執行流程。傳統的攻擊會把機器碼寫到堆疊上再跳過去執行；搭配分頁表不可執行位元的 W^X 政策可以阻擋這種攻擊。於是攻擊者轉向返回導向程式設計（ROP），把既有的程式碼片段串接起來。進一步的防禦包括在返回前檢查的堆疊金絲雀（stack canary）、位址空間配置隨機化，以及為每個返回位址保存一份受保護副本的硬體影子堆疊。

硬體中的返回位址

亂序執行 CPU 會在讀取 ra 或堆疊之前很久，就預測返回會跳到哪裡。分支預測器中的返回位址堆疊（RAS）在每次呼叫時推入下一道指令的位址，在每次返回時彈出，對巢狀結構良好的程式碼能做出非常準確的預測。例外與中斷則不同：CPU 會把被中斷的 PC 保存在專用暫存器中（例如 RISC-V 的 mepc 或 sepc），連同先前的特權模式一起保存，並以 mret 或 sret 一次全部恢復，而不是使用一般的 ret。

練習返回位址的題目

在程式中呼叫副程式（函式）時，一般用來暫時保存返回位址等的區域是下列何者？

  1. A堆疊（stack）
  2. B快取的標籤（tag）
  3. CROM 的固定區域
查看答案與解析

正確答案：A. 堆疊（stack）

呼叫副程式時，返回位址、應保存的暫存器值、區域變數等會被推入堆疊。堆疊是後放入的先取出（LIFO）的結構，即使呼叫形成巢狀或遞迴，也能依正確的順序返回。頂端位置由堆疊指標指示。遞迴過深而用盡區域時會發生堆疊溢位，也有藉由陣列越界改寫返回位址的攻擊。

常見問題

RISC-V 的返回位址存在哪裡？

存放在暫存器 ra（x1）中，由呼叫時的 jal 或 jalr 寫入。非葉函式在自己發出呼叫之前會把它複製到堆疊框架，並在 ret 之前恢復。

x86 的 call/ret 和 RISC-V 的 jal/ret 有什麼差別？

x86 的 call 一定會把返回位址推入堆疊，再由 ret 彈出；RISC-V 的 jal 則把它放在暫存器中，只有在函式選擇保存時才會存取記憶體。

返回位址被覆寫為什麼很危險？

函式返回時，CPU 會跳到那裡存放的任何位址，因此透過緩衝區溢位覆寫它的攻擊者就能奪取程式的控制權。
