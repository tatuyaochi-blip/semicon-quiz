什麼是靜態函式庫（Static library）

將多個目的檔彙整為一個的封存檔（在 Linux 為 .a）。進行靜態連結時，連結器只取出需要的目的檔並組入可執行檔。

日文名稱: 静的ライブラリ

「靜態函式庫（Static library）」出現在1領域的3道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

.a 檔裡面有什麼

在類 Unix 系統上，靜態函式庫是以 ar 工具建立的封存檔，例如 ar rcs libfoo.a a.o b.o。它基本上只是把目的檔加上標頭串接起來，再加上一個索引，將每個已定義的全域符號對應到定義它的成員，讓連結器不必掃描每個成員就能找到定義。命令列選項 -lfoo 會讓連結器在函式庫搜尋路徑中尋找 libfoo.so 或 libfoo.a；兩者都存在時，除非要求靜態連結，否則 GNU ld 會優先使用共用版本。Windows 工具鏈則使用 .lib 檔達到相同目的。

取出的單位是目的檔

當需要某個成員時，連結器會納入整個目的檔，而不只是被參照的那一個函式。如果函式庫的某個原始檔定義了二十個函式，而程式只呼叫其中一個，這二十個函式都會進入執行檔，連同它們所參照的其他東西。因此 C 標準函式庫等函式庫常由許多小原始檔建置而成，有時一個檔案只有一個函式。另一種做法是以 -ffunction-sections 與 -fdata-sections 編譯，並以 --gc-sections 連結，讓連結器能丟棄成員內未被參照的函式。

連結順序與循環相依

GNU 連結器由左至右掃描輸入，遇到封存檔時，只取出能解析當下未定義參照的成員，之後便不再回頭。因此函式庫必須放在使用它們的目的檔之後，而相依於另一個函式庫的函式庫必須放在那個函式庫之前。當兩個函式庫互相相依時，常見的解法是把其中一個列出兩次，或以 --start-group 與 --end-group 包住兩者，讓連結器反覆掃描直到沒有新的符號被解析為止。有些連結器，例如 LLVM 的 lld，會記住所有封存檔的符號，不需要這種順序安排。

靜態函式庫與共用函式庫的比較

靜態函式庫只在建置時使用：其程式碼被複製到每個執行檔中，程式執行時不需要 .a 檔。共用函式庫（Linux 上為 .so，Windows 上為 .dll）則是以位置無關程式碼建置、已連結好的單一檔案，在執行時載入，其分頁由所有使用它的行程共用。靜態函式庫適合自給自足的部署與嵌入式韌體，共用函式庫則能節省磁碟與記憶體，並且只需替換一個檔案就能讓修正套用到所有程式。

練習靜態函式庫（Static library）的題目

與靜態函式庫（.a檔）一起連結時，連結器會嵌入執行檔的是下列何者？

  1. A函式庫中的所有目的檔
  2. B只有函式庫的檔名，不嵌入程式碼
  3. C函式庫中的目的檔裡，只有解決未定義參照所需的那些
查看答案與解析

正確答案：C. 函式庫中的目的檔裡，只有解決未定義參照所需的那些

靜態函式庫是將許多目的檔整合成一個的封存檔。連結器只會從封存檔中取出定義了尚未找到定義之符號的目的檔，並將其嵌入。因此即使是像標準函式庫這樣包含許多函式的函式庫，執行檔也只會增加所用函式的份量。

使用GNU連結器時，若像「gcc -lmylib main.o」這樣，將靜態函式庫寫在使用它的目的檔之前，有時會出現未定義參照的錯誤。下列關於其原因的敘述何者正確？

  1. A因為連結器從左到右依序處理，讀取函式庫的時點上尚未被參照的函式不會被取出
  2. B因為規定函式庫必須且只能寫在指令的最後一個
  3. C因為將函式庫寫在前面，函式庫的內容會被清除
查看答案與解析

正確答案：A. 因為連結器從左到右依序處理，讀取函式庫的時點上尚未被參照的函式不會被取出

GNU連結器依命令列上所寫的順序處理檔案，遇到靜態函式庫時，只會取出能解決「尚未找到定義的參照」的目的檔。若先寫函式庫，在那個時點main.o的參照還不存在，所以什麼都不會取出，之後再讀取main.o也不會回頭尋找。因此原則上函式庫要寫在使用它的一方之後。

常見問題

如何在 Linux 中建立靜態函式庫？

以 gcc -c 將原始檔編譯成目的檔，再以 ar rcs libname.a file1.o file2.o 打包。連結時以 -L 指向其所在目錄，並加上 -lname。

.a 檔和 .so 檔有什麼差別？

.a 檔是目的檔的封存檔，所需的成員會在連結時複製到執行檔中。.so 檔則是在執行時載入、由多個行程共用的共用函式庫。

明明有連結函式庫，為什麼還出現 undefined reference 錯誤？

使用 GNU 連結器時，最常見的原因是順序：函式庫在命令列上出現在使用它的目的檔之前。把 -lname 移到目的檔之後，並用 nm 確認函式庫確實定義了該符號。
