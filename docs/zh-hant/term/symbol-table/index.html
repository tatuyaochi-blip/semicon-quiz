什麼是符號表（Symbol table）

包含於目的檔或可執行檔中，記錄函式與變數的名稱和位址等的清單。用於連結與除錯，可用 strip 移除。

日文名稱: シンボルテーブル

「符號表（Symbol table）」出現在1領域的3道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

一個項目包含什麼

符號表的每個項目描述一個具名的實體。在 Linux 所用的 ELF（可執行與可連結格式）中，一個項目記錄名稱（以字串表中的偏移表示）、值（位址，或在目的檔中為區段內的偏移）、大小、函式或資料物件等型別、繫結（local、global 或 weak），以及定義該符號的區段。在此檔案中被參照但未定義的符號會標記為未定義；這些就是連結器必須從其他目的檔或函式庫中滿足的參照。

連結器如何使用它

連結從符號解析開始：連結器收集所有輸入檔案的符號表，並將每個未定義的參照與恰好一個定義配對。同名的兩個強全域定義會產生重複定義錯誤，弱定義會讓位給強定義，而沒有定義的參照則會產生未定義參照錯誤。每個符號都有了最終位址之後，連結器處理重定位項目，修補每一個參照到符號的指令與資料字組。區域符號，例如 C 語言中的 static 函式，從不參與跨檔案的配對。

靜態符號、動態符號與 strip

ELF 檔案帶有兩個符號表。完整的表（.symtab）供靜態連結器與除錯器使用；動態表（.dynsym）只列出執行檔與其共用函式庫之間在載入時必須解析的符號。執行 strip 會移除 .symtab 以及 DWARF 行號資訊等除錯區段，使檔案變小，但會保留 .dynsym，因為沒有它程式就無法執行。開發者常在 strip 之前把除錯資訊另存成獨立檔案，以便在已發行的二進位檔當機時仍能進行符號化。nm 與 readelf -s 等工具可列出檔案的符號。

編譯器的符號表

同一個詞也指編譯器內部的另一種結構。在語意分析期間，編譯器維護一張表——通常是依巢狀範圍組織的雜湊表——將每個識別字對應到其宣告、型別與儲存方式。它回答諸如「此處的 x 指的是哪個變數」以及「函式宣告的引數是否相符」等問題。這張表只在編譯期間存在。目的檔的符號表則是它持久保存的產出，只包含對連結、重定位與除錯有意義的名稱。

練習符號表（Symbol table）的題目

關於編譯器從單一原始檔輸出的目的檔（.o），下列何者正確？

  1. A是可直接在作業系統上執行的完整程式
  2. B只是將原始碼壓縮而成，不含機器碼
  3. C含有機器碼，但其他檔案中的函式與變數的位址尚未決定
查看答案與解析

正確答案：C. 含有機器碼，但其他檔案中的函式與變數的位址尚未決定

目的檔中包含該檔案內函式經翻譯後的機器碼、變數的初始值、所定義與所參照的名稱清單（符號表），以及事後要填入位址的位置清單（重定位資訊）。像printf這樣呼叫其他檔案中函式的指令，由於不知道位址，仍保留暫時的值。連結器會將多個目的檔整合起來決定位址，進而產生執行檔。

關於連結器所進行的符號解析，下列說明何者正確？

  1. A將某檔案中使用的函式或變數名稱，對應到另一個檔案中的該定義
  2. B將原始碼的變數名稱換成較短的名稱，使其難以閱讀
  3. C將含有數學符號的算式重新計算成數值
查看答案與解析

正確答案：A. 將某檔案中使用的函式或變數名稱，對應到另一個檔案中的該定義

若在main.c中呼叫sum函式，並在sum.c中定義其內容，則main.o會記錄「參照sum」，sum.o會記錄「定義sum」。連結器會蒐集所有目的檔的符號表，為每個參照找出一個對應的定義。若找不到定義，就會出現「未定義的參照」錯誤；若有兩個以上，則會出現「重複定義」錯誤。

常見問題

如何查看執行檔或目的檔的符號表？

在 Linux 上，nm 會以單一字母的型別列出符號，readelf -s 則顯示完整的 ELF 符號表，包括大小、型別與繫結。objdump -t 也是一個選擇。

nm 輸出中的 T 和 U 是什麼意思？

T 表示定義在 text（程式碼）區段中的符號，通常是全域函式；U 表示此檔案參照但未定義的未定義符號。小寫字母表示區域符號。

經過 strip 的二進位檔還能除錯嗎？

可以，但除非除錯器能取得另存的除錯資訊或符號檔，否則堆疊追蹤只會顯示位址，而不是函式名稱。
