什麼是連結器指令檔（Linker script）

指示連結器將各區段配置於記憶體哪個位址的檔案。在嵌入式開發中，用於決定在快閃記憶體與 RAM 中的配置以及中斷向量的位址。

日文名稱: リンカスクリプト

「連結器指令檔（Linker script）」出現在1領域的1道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

連結器指令檔描述什麼

編譯器產生的目的檔中，程式碼與資料被歸類到 .text（指令）、.rodata（常數）、.data（已初始化變數）與 .bss（零初始化變數）等區段，但尚未有最終位址。連結器指令檔告訴連結器如何將它們組合起來。在 GNU ld 語法中，MEMORY 區塊以起始位址與長度宣告記憶體區域，例如快閃記憶體在某個位址、RAM 在另一個位址；SECTIONS 區塊則將輸入區段對應到輸出區段，並將每個輸出區段指派到某個區域。若區域容量溢出，連結器會回報錯誤。

嵌入式系統為何需要它

在 PC 上，由作業系統的載入器決定程式在記憶體中的位置，預設的連結器指令檔幾乎適用於所有情況。沒有作業系統的微控制器在上電時從固定位址開始執行，因此程式必須依照其確切的記憶體映射來建置。中斷向量表必須位於硬體預期的位置，程式碼與常數應放在非揮發性的快閃記憶體中，而可寫變數、堆積與堆疊則必須位於 RAM。同一系列中的不同晶片，往往只因記憶體大小不同而需要換一份連結器指令檔。

載入位址與執行位址

已初始化變數帶來一個特殊問題：它們的初始值必須在斷電後保留，所以儲存在快閃記憶體中；但程式會寫入它們，所以執行時必須位於 RAM。因此連結器指令檔為 .data 指定兩個位址：快閃記憶體中的載入位址，以及 RAM 中的執行位址。它也會定義標示 .data 與 .bss 起訖的符號，通常還有堆疊頂端。啟動程式碼利用這些符號，在呼叫 main 之前把 .data 從快閃記憶體複製到 RAM，並將 .bss 填零，使 C 語言承諾的初始狀態得以成立。

常見的陷阱

裸機（bare-metal）專案中的許多問題都可追溯到連結器指令檔。啟用未使用區段移除功能時，中斷向量表或其他只被硬體參照的區段，若沒有標記為保留就可能被丟棄。堆疊區域設得太小並不會造成連結錯誤，而是在執行時悄悄覆寫其他資料。區段放錯載入位址，會讓變數帶有垃圾初始值。查看連結器可產生的映射檔（map file），其中列出每個符號的位址與各區域的使用量，是檢查結果的標準方法。

練習連結器指令檔（Linker script）的題目

關於嵌入式開發中使用的連結器腳本（linker script）的功用，下列何者正確？

  1. A指示連結器要將各區段配置在快閃記憶體或RAM等的哪個位址
  2. B撰寫自動執行程式測試的步驟
  3. C規定原始碼的寫法規則，並通知違規之處
查看答案與解析

正確答案：A. 指示連結器要將各區段配置在快閃記憶體或RAM等的哪個位址

在個人電腦的作業系統中，位址是由載入器決定的，但在微控制器上，通電那一刻的位址就是直接使用的位址。連結器腳本中會寫下快閃記憶體與RAM的起始位址與大小，並指定配置方式，例如.text與常數放在快閃記憶體，.data、.bss與堆疊放在RAM。像中斷向量這類必須放在固定位址的東西，也在此指定。

常見問題

連結器指令檔（linker script）是做什麼用的？

連結器指令檔告訴連結器有哪些記憶體區域，以及每個程式碼與資料區段要放在哪個位址。嵌入式專案用它把程式碼放進快閃記憶體、變數放進 RAM，並將中斷向量表放在規定的位址。

.data 和 .bss 有什麼不同？

.data 存放具有非零初始值的變數，這些值儲存在快閃記憶體中，啟動時複製到 RAM。.bss 存放從 0 開始的變數，因此不佔快閃記憶體空間，只需在 main 執行前於 RAM 中清除即可。

為什麼連結器指令檔裡 .data 有兩個位址？

它的初始值必須儲存在非揮發性的快閃記憶體中，但變數在執行時會被修改，因此必須位於 RAM。載入位址指向快閃記憶體中的副本，執行位址則指向程式碼實際使用的 RAM 位置。
