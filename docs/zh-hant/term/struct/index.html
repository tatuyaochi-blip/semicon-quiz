什麼是結構（struct）

C語言中，把多個（可為不同型別的）值（成員）整合成一個型別來處理的機制。以 struct sensor { int id; float value; }; 的方式定義，變數 s 的成員以 s.id 使用，透過指向結構的指標 p 則以 p->id 使用。成員依宣告順序排列在記憶體中，但為了對齊，成員之間可能加入填充（padding），整體大小可能大於成員大小的總和。

日文名稱: 構造体

「結構（struct）」出現在1領域的2道練習題中（C語言基礎等）。

這個名詞所屬的領域: C語言基礎

定義與使用方式

定義 struct point { int x; int y; }; 之後，就能以 struct point p = {1, 2}; 建立變數，並以 p.x、p.y 使用各成員。以 typedef 取別名，如 typedef struct { … } Point;，就能不寫 struct 而以 Point p; 宣告。結構之間可以用 = 整個指派，也能作為函式的引數或回傳值，但大型結構一般以指標傳遞。

在記憶體中的排列

成員依宣告順序，從位址小的一方開始放置。像 int 這種必須對齊到4位元組邊界的型別之前會加入填充，整個結構的大小也會進位到最嚴格對齊值的倍數。因此依 char、int、char 順序排列的結構，在 int 為4位元組的一般環境中是12位元組，把 int 放在前面則減為8位元組。

嵌入式與通訊上的注意事項

以結構表示周邊電路暫存器的排列很常見，但填充與位元欄位的位元順序可以因處理系統而異，未經確認就使用可能使位址錯開。若把通訊資料或儲存檔案的格式直接當作結構的記憶體內容處理，會因填充與端序的差異而與其他環境不相容，因此常改為逐位元組組合資料。

常見問題

結構與陣列有什麼不同？

陣列是排列相同型別的元素，以索引選取元素。結構是整合可為不同型別的成員，以名稱選取成員。也能組合使用，例如結構的陣列，或以陣列作為成員的結構。

為什麼需要用 sizeof 確認結構的大小？

成員之間或最後加入的填充量，會依型別大小與對齊規則（ABI）而變，只把成員大小相加並不能得到正確的大小。用 malloc 配置結構的區域或寫入檔案時，要以 sizeof(struct 名稱) 求出實際大小。

出現這個名詞的比較

  • DRAM 與 SRAM 的差異：結構、速度、成本、用途比較從單元結構、更新、速度、積體度、成本、耗電量與用途等面向，以表格比較 DRAM 與 SRAM，並說明各自適用的時機。
  • FinFET 與 GAA 電晶體的差異：結構、控制性、製造比較從閘極結構、通道、靜電控制、寬度調整、製造與採用現況等面向，以表格比較 FinFET 與環繞式閘極（GAA）奈米片電晶體。
  • CPU 與 GPU 的差異：結構、擅長的運算、用途比較從設計目的、核心數、執行模型、快取、記憶體頻寬、分支、資料傳輸與擅長的運算等面向，以表格比較 CPU 與 GPU。
  • JFET與MOSFET的差異：比較閘極結構與使用時機以閘極的結構、常開或常關、閘極電流、雜訊、抗靜電能力、整合度與用途等面向，用表格比較JFET與MOSFET。
  • DDR4 與 DDR5 的差異：速度、結構與升級的判斷依據以速度、電壓、通道結構、突發長度、記憶庫、晶粒內 ECC、電源管理、延遲、頻寬與相容性等面向，用表格比較 DDR4 與 DDR5。
  • 前照式、背照式與堆疊式影像感測器的差異：結構、感度、速度比較從光的入射面、結構、開口率與感度、導線與周邊電路、晶片面積、速度、製造難度、課題與用途等面向，以表格比較前照式（FSI）、背照式（BSI）與堆疊式 CMOS 影像感測器，並說明各自適用的時機。
  • PN 接面二極體與蕭特基二極體的差異：結構、順向電壓、逆向恢復、漏電流比較從結構、傳導電流的載子、順向電壓、逆向恢復、逆向漏電流、耐壓、溫度特性與用途等面向，以表格比較 PN 接面二極體與蕭特基能障二極體。
  • 直接能隙與間接能隙半導體的差異：能帶結構、發光效率、光吸收、材料比較從能帶結構、聲子的參與、發光效率、載子壽命、光的吸收深度、代表性材料與用途等面向，以表格比較直接能隙與間接能隙半導體。
  • 開汲極與推挽輸出的差異：結構、上升時間、線及、用途比較從輸出級結構、輸出 H 的機制、上升速度、線及（wired-AND）、與不同電壓電路的連接、消耗電流與用途等面向，以表格比較開汲極輸出與推挽輸出。
  • NPN 電晶體與 PNP 電晶體的差異：結構、電流方向、電路符號、使用方式比較從半導體的排列、主要載子、偏壓方式、電流方向、電路符號的箭頭、作為開關的接法與性能等面向，以表格比較雙極性電晶體的 NPN 型與 PNP 型。
