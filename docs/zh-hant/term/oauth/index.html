什麼是OAuth

讓使用者不必交出自己的密碼，就能允許其他應用程式（用戶端）在有限範圍內存取自己資源（委派授權）的機制。廣泛使用的是OAuth 2.0。由資源擁有者（使用者）、用戶端、取得使用者同意後發行存取權杖的授權伺服器，以及確認權杖後回傳資源的資源伺服器四種角色組成。OAuth本身是授權的機制，用於登入（身分驗證）時，要使用加入了ID權杖的OpenID Connect。

日文名稱: OAuth

練習OAuth的題目

相片沖印服務的應用程式，取得使用者的許可後，讀取使用者存放在另一家公司相片儲存服務中的相片。在OAuth 2.0中，向使用者顯示請求許可的畫面，並在使用者同意後對應用程式發行存取權杖的角色，為下列何者？

  1. A資源伺服器
  2. B授權伺服器
  3. C用戶端
查看答案與解析

正確答案：B. 授權伺服器

OAuth 2.0有資源擁有者（使用者）、用戶端（相片沖印服務的應用程式）、授權伺服器、資源伺服器（回傳相片的API）四種角色。授權伺服器確認使用者並取得同意後，對用戶端發行限定範圍（scope）與期限的存取權杖。用戶端附上權杖呼叫資源伺服器的API，資源伺服器確認權杖後回傳相片。使用者不必把相片儲存服務的密碼交給應用程式，之後也能撤銷許可。

關於OAuth 2.0與OpenID Connect的關係，下列說明何者正確？

  1. AOAuth 2.0是委派資源存取許可（授權）的機制，OpenID Connect則在其上加入傳達身分驗證結果的ID權杖，使其能用於登入
  2. BOAuth 2.0是傳達使用者身分驗證結果的機制，OpenID Connect則不使用它，而是把使用者的密碼直接送到各個連結的服務加以確認
  3. COpenID Connect是加密HTTP通訊的協定，在傳送登入畫面時代替TLS使用
查看答案與解析

正確答案：A. OAuth 2.0是委派資源存取許可（授權）的機制，OpenID Connect則在其上加入傳達身分驗證結果的ID權杖，使其能用於登入

OAuth 2.0的存取權杖表示「可以使用這個範圍的資源」的許可，並不是為了確認誰登入而設計的。OpenID Connect在OAuth 2.0的流程中，加入帶簽章之JWT形式的ID權杖。ID權杖包含發行者、使用者識別碼、對象用戶端、有效期限等，用戶端確認簽章與內容，得知使用者是誰。這個機制用於以其他服務的帳號登入的功能，以及單一登入。
