什麼是JIT編譯(即時編譯)

在程式執行中，將經常執行的部分編譯成機器碼的方式。可進行利用執行時資訊的最佳化。用於Java與JavaScript的執行環境等。

日文名稱: JITコンパイル

「JIT編譯(即時編譯)」出現在3領域的5道練習題中（編譯器, 效能評估與效能剖析, 連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 編譯器

分層執行

典型的 JIT（即時）執行環境一開始先直譯位元組碼，這不需要事前成本，但執行速度慢。直譯時，它會計數每個方法被呼叫、每個迴圈迭代的次數。超過門檻的程式碼會交給快速的基線編譯器，持續熱門的程式碼之後再由最佳化編譯器重新編譯，後者對每個函式花費多得多的時間。長時間執行的迴圈可以在執行途中切換到已編譯的程式碼，這種技術稱為堆疊上替換（on-stack replacement）。編譯通常在背景執行緒進行，讓程式同時繼續執行。

推測與去最佳化

直譯器與基線程式碼會收集剖析資料（profile）：哪些分支被採用、每個呼叫點出現哪些物件型別、整數是否曾經溢位。最佳化編譯器就押注在這些觀察上，例如把某個虛擬呼叫一直以來都只呼叫到的那個方法內嵌（inline），並捨棄從未出現之型別的程式碼。每一個押注都由一個低成本的防護（guard）保護。若防護失敗，執行環境就會去最佳化（deoptimize）：重建目前堆疊框在直譯器中的視圖，以較慢的程式碼繼續執行，之後可能再根據新資訊重新編譯。預先編譯器無法如此自由地進行這類押注。

JIT、AOT 與直譯器的比較

純直譯器可立即啟動，執行時不需要編譯器，但每個運算都執行得很慢。AOT（預先）編譯在程式執行之前就產生機器碼，帶來快速啟動、可預測的效能，且記憶體中不需要編譯器；但除非有剖析導向最佳化（PGO）提供訓練執行的資料，否則它必須在不知道實際輸入的情況下進行最佳化。JIT 要付出暖機時間、編譯所耗的 CPU 時間與程式碼快取的記憶體，換來在長時間執行的程式上達到很高的峰值速度。許多執行環境會結合多種方法，例如快取啟動程式碼或以 AOT 編譯它。

實務上的限制

JIT 會把機器碼寫入記憶體再執行，這與「記憶體不應同時可寫入又可執行」的安全規則相衝突。執行環境的處理方式是在產生程式碼後切換分頁權限，或以不同權限將同一塊實體記憶體對映兩次；有些受嚴格管控的平台則完全禁止執行時期產生程式碼。由於編譯後的程式碼取決於執行時期的剖析資料，每次執行的效能可能不同，並可能在發生去最佳化時突然下降，因此對以 JIT 為基礎的系統做效能評測時，需要充分的暖機。

練習JIT編譯(即時編譯)的題目

  1. A在執行程式之前，先全部翻譯成機器碼再發布
  2. B在執行中將經常使用的部分轉為機器碼，且能利用執行期的資訊
  3. C完全不使用機器碼，永遠逐條指令地解釋位元組碼
查看答案與解析

正確答案：B. 在執行中將經常使用的部分轉為機器碼，且能利用執行期的資訊

在JIT編譯中，一開始是邊解釋位元組碼邊執行，一旦找到被反覆執行的部分（熱點，hotspot），就在執行中把那裡編譯成機器碼。可以利用實際通過的分支與傳入的型別等執行期資訊，進行事前編譯難以做到的大膽最佳化。若假設落空，也具備退回解釋執行的機制。事先全部翻譯的是事前（AOT）編譯，只持續解釋的則是純粹的直譯器。

常見問題

JIT 編譯比 AOT 編譯快嗎？

視工作負載而定。由於 JIT 利用真實的剖析資料進行最佳化，在長時間執行的程式上，其程式碼可追平甚至勝過 AOT 程式碼；但在啟動時間、記憶體用量與可預測性方面，AOT 較佔優勢。

JIT 暖機（warm-up）是什麼？

是指程式碼在直譯器或基線層中執行、而執行環境一邊剖析一邊編譯熱門部分的初期階段。在暖機期間量測的效能，會低估穩態下的速度。

JIT 中的去最佳化是什麼？

是指當最佳化程式碼所依據的假設被證明不成立時，放棄該程式碼，並從對應的位置改以直譯器或最佳化程度較低的程式碼繼續執行。之後執行環境可能以更新的剖析資料重新編譯。
