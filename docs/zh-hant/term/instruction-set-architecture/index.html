什麼是指令集架構(ISA)

處理器可執行的指令與暫存器等，從軟體角度看到的處理器規格。例如 x86、Arm、RISC-V 等。

日文名稱: 命令セットアーキテクチャ(ISA)

「指令集架構(ISA)」出現在4領域的12道練習題中（指令集與組合語言, CPU與架構, 效能評估與效能剖析等）。

這個名詞所屬的領域: CPU與架構

ISA 規範了什麼

指令集架構（ISA）是軟體與處理器硬體之間的契約。它定義了指令及其位元編碼、程式可見的暫存器、資料型別與定址模式、記憶體存取的順序規則、特權等級，以及中斷與例外的行為。ISA 所定義的一切都是機器碼可觀察並依賴的架構狀態。組譯器將組合語言助憶符幾乎一對一地轉換為這些編碼，因此每種 ISA 都有自己的組合語言。

ISA 與微架構

微架構是特定處理器實作 ISA 的方式：管線深度、快取大小、分支預測器、每個週期發出的指令數等。同一個 ISA 可以由極小的低功耗核心實作，也可以由大型亂序執行核心實作，兩者執行相同的機器碼，速度卻差異極大。在效能方程式「執行時間 = 指令數 × 每指令週期數（CPI）× 週期時間」中，ISA 與編譯器主要決定指令數，微架構決定 CPI，電路與製程技術決定週期時間。Spectre 類攻擊正是利用這個邊界：錯誤推測的架構狀態會被回復，但快取內容不會。

影響硬體的設計選擇

ISA 的細節會對硬體造成長遠影響。RISC-V 的基本指令固定為 32 位元（只有在壓縮 C 擴充中才有 16 位元格式），因此指令邊界一目了然；x86 指令長度則從 1 到 15 位元組不等，必須先部分解碼才能找出下一個指令的起點，使寬解碼器變得複雜。x86 的分支會檢查先前比較指令所設定的旗標；RISC-V 則在分支指令中直接比較兩個暫存器，沒有需要追蹤的隱含旗標狀態。MIPS 的分支延遲槽說明了將某一代管線的特性寫進 ISA 的風險，因為 ISA 的壽命比那條管線長。

模組化與開放式 ISA

RISC-V 是開放式 ISA，任何人都可以實作其規格而無須支付授權費。它結合了小型的基本整數指令集（RV32I 或 RV64I，約 40 個指令）與可選擇的擴充：M 為乘除法，A 為原子操作，F 與 D 為浮點運算，C 為壓縮指令，V 為向量，另外還可加入自訂指令。省略某個擴充可以節省面積，但會犧牲速度：沒有 M 時，編譯器會將 C 語言的乘法轉換為呼叫以移位與加法進行乘法的函式庫常式。Arm 與 x86 則是專有架構，由其擁有者授權或自行實作。

ISA是規定指令的種類、指令的位元排列、暫存器數量等的軟體與硬體之間的約定。管線的級數、快取的大小、分支預測的方式等內部構造稱為微架構，與ISA分開決定。因此即使是相同的ISA，也有小型低功耗核心與大型高效能核心，效能與耗電量各不相同，但相同的機器語言程式都能執行。製造的工廠與製程也與ISA無關。

常見問題

ISA 和微架構有什麼不同？

ISA 是軟體看到的規格：指令、暫存器與行為。微架構則是實作該規格的特定硬體設計，因此兩個微架構不同的處理器，只要 ISA 相同，就能執行相同的程式。

x86、Arm 和 RISC-V 都是指令集架構嗎？

是的。它們是三種不同的 ISA，因此為其中一種編譯的機器碼無法直接在另一種上執行，儘管每一種都由許多不同的處理器設計所實作。

ISA 和 ABI 有什麼差別？

ISA 定義處理器執行什麼，而 ABI 是建立在其上的軟體慣例，涵蓋呼叫慣例、資料型別大小與系統呼叫。同一個 ISA 可以有多種 ABI，例如針對不同的作業系統。
