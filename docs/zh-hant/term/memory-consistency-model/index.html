什麼是記憶體一致性模型（Memory consistency model）

規定某個核心對多個位址所做的讀寫，在其他核心看來可能呈現何種順序的約定。有循序一致性、x86 的 TSO、ARM 與 RISC-V 的弱模型等。

日文名稱: メモリ一貫性モデル

「記憶體一致性模型（Memory consistency model）」出現在1領域的5道練習題中（多核心與同步等）。

這個名詞所屬的領域: 多核心與同步

硬體為何重新排序記憶體操作

現代核心並不嚴格依照程式順序執行載入與儲存。儲存常被暫放在儲存緩衝區中，核心則繼續往下執行；載入也可能提早或亂序發出，以隱藏快取延遲。這些最佳化在單一執行緒內是看不到的，因為核心總會轉送自己尚未完成的寫入，並保持自己的結果正確。然而，另一個核心可能以不同的順序看到同樣的操作。記憶體一致性模型就是明確規定這些重新排序中哪些可能被看見的契約，讓程式設計者與編譯器知道何時需要同步。

循序一致性、TSO 與弱模型

循序一致性（SC）是最嚴格的模型：所有操作看起來都發生在單一的全域順序中，且符合各核心的程式順序。x86 採用總儲存順序（TSO），強度幾乎相當：唯一可見的重新排序是較晚的、對不同位址的載入先於較早的儲存完成，而這正是 FIFO 儲存緩衝區會產生的結果。Arm 與 RISC-V 採用弱模型，允許對不同位址的載入與儲存在大多數組合下重新排序。此時必須以 fence 或屏障指令，或以 acquire 與 release 操作明確要求順序。

經典範例：儲存緩衝區測試

設核心 0 執行 x = 1 後讀取 y，核心 1 執行 y = 1 後讀取 x，x 與 y 的初始值皆為 0。在循序一致性下，至少有一個核心必定讀到 1。在 TSO 下兩者都可能讀到 0，因為當另一個核心的載入執行時，各自的儲存可能仍留在自己核心的儲存緩衝區中。Dekker 與 Peterson 等鎖演算法正是以這種方式失效，除非在儲存與載入之間放置完整的 fence。在弱模型上，即使是以旗標傳遞資料也可能失敗，除非以屏障規範存取的順序。

一致性模型與快取一致性

快取一致性（cache coherence）是針對單一位址的保證：所有核心對該位置的寫入順序有共識，最終都會看到最新的值。一致性模型（consistency model）則涵蓋不同位址之間的順序，例如對 x 的寫入是否會比之後對 y 的寫入先被看見。系統即使完全滿足快取一致性，仍可能出現這類重新排序，這也是屏障與一致性協定並存的原因。高階語言會定義自己的模型，例如 C11 與 C++11 的原子操作，再由編譯器將其轉譯為硬體模型所需的屏障指令。

查看答案與解析

正確答案：C. 某個核心所進行的對多個位址的讀寫，從其他核心看來可能以什麼順序出現

CPU為了提升效能，會把寫入暫存在儲存緩衝區（store buffer），或先行執行讀取，因此有時會改變記憶體操作的順序。在單一核心內雖然設計成結果不會改變，但從其他核心看來，順序可能顯得被調換了。記憶體一致性模型規定了哪些調換有可能發生，是讓程式設計師能寫出正確同步的一種約定。

關於x86的記憶體一致性模型（TSO，Total Store Order，全域儲存順序）的特徵，下列何者正確？

  1. A允許讀寫的任何組合被調換的、最弱的模型
  2. B完全不允許調換的循序一致性本身
  3. C只允許寫入之後對其他位址的讀取，比該寫入更早被看到的、相對較強的模型
查看答案與解析

正確答案：C. 只允許寫入之後對其他位址的讀取，比該寫入更早被看到的、相對較強的模型

在TSO中，寫入之間的順序、讀取之間的順序、讀取之後寫入的順序都會被保持，只有寫入之後對其他位址的讀取可以超前。這是直接反映儲存緩衝區存在的模型。多數程式在這個範圍內都能依直覺運作，所以在x86上需要屏障的場合相對較少。

常見問題

快取一致性和記憶體一致性有什麼差別？

快取一致性確保所有核心以相同順序看到對同一位址的寫入，並最終讀到最新值。記憶體一致性則定義對不同位址的存取可能以何種順序被其他核心觀察到。

TSO 是什麼的縮寫？

TSO 是 total store order（總儲存順序）的縮寫，是 x86 處理器採用的記憶體模型。它只允許較晚的、對不同位址的載入先於較早的儲存被觀察到，這是儲存緩衝區造成的效果。

為什麼 Arm 和 RISC-V 的程式比 x86 需要更多記憶體屏障？

Arm 與 RISC-V 採用弱記憶體模型，允許對不同位址的載入與儲存進行大部分的重新排序，因此必須明確要求順序。x86 的 TSO 已保留大多數順序，只有在儲存之後接著對另一位址的載入等情況才需要屏障。
