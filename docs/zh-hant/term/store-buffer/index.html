什麼是儲存緩衝區（Store buffer）

核心暫時累積寫入的小型緩衝區。不必等待寫入完成即可前進到下一個指令，但從其他核心看來寫入會延遲。

日文名稱: ストアバッファ

「儲存緩衝區（Store buffer）」出現在1領域的4道練習題中（多核心與同步等）。

這個名詞所屬的領域: 多核心與同步

為什麼核心要緩衝其儲存

核心執行儲存時，目標快取線可能不在快取中，或被另一個核心持有，而透過一致性協定取得寫入所有權可能需要許多週期。核心不會停頓，而是將位址與資料放入儲存緩衝區並繼續執行。這些項目之後才會寫入 L1 快取，在 x86 上通常依程式順序進行。在亂序執行處理器中，儲存緩衝區也保存推測性的儲存，這些儲存在指令提交並確定不會被撤銷之前，不能寫入快取。

儲存到載入的轉送

由於最近的儲存可能仍留在緩衝區中，每個載入都會檢查緩衝區中是否有相符的位址。若找到，載入就從最新的相符項目取得資料，而非從快取取得，這種機制稱為儲存到載入的轉送（store-to-load forwarding）。這維持了單執行緒的行為：核心總是能依程式順序立即看到自己的寫入。當載入所讀取的位元組正好是先前單一儲存所寫入的位元組時，轉送效果最好；載入與緩衝中的儲存部分重疊時，常會迫使載入等到那些儲存寫出為止。

為什麼其他核心較晚看到寫入

其他核心無法查看某個核心的儲存緩衝區，因此被緩衝的寫入在寫出之前對它們是不可見的。考慮 x 與 y 皆為 0，核心 1 執行 x = 1 再執行 r1 = y，核心 2 執行 y = 1 再執行 r2 = x。在循序一致性下，至少一個載入必須看到 1。有了儲存緩衝區，兩個儲存可能都在各自的緩衝區中等待，而兩個載入都從快取讀到 0，因此在實際的 x86 機器上會出現 r1 = r2 = 0。在儲存與載入之間加入記憶體屏障，等待緩衝區清空，即可禁止此結果。

儲存緩衝區與記憶體一致性模型

x86 的模型，即總儲存順序（TSO），基本上描述的就是先進先出的儲存緩衝區：儲存與儲存之間、載入與載入之間保持順序，只有後面對不同位址的載入可能看起來超越前面的儲存。Arm 與 RISC-V 等較弱的模型，除了其他重排之外，也允許儲存以亂序方式變為可見，因此更常需要屏障（fence）或 acquire/release 指令。程式設計者通常仰賴語言層級的原子操作，由編譯器將其對應到正確的屏障。

練習儲存緩衝區（Store buffer）的題目

記憶體一致性模型（memory consistency model）所規定的是下列何者？

  1. A快取列的大小與組（set）的數量
  2. B主記憶體DRAM所使用的電晶體種類
  3. C某個核心所進行的對多個位址的讀寫，從其他核心看來可能以什麼順序出現
查看答案與解析

正確答案：C. 某個核心所進行的對多個位址的讀寫，從其他核心看來可能以什麼順序出現

CPU為了提升效能，會把寫入暫存在儲存緩衝區（store buffer），或先行執行讀取，因此有時會改變記憶體操作的順序。在單一核心內雖然設計成結果不會改變，但從其他核心看來，順序可能顯得被調換了。記憶體一致性模型規定了哪些調換有可能發生，是讓程式設計師能寫出正確同步的一種約定。

關於循序一致性（sequential consistency），下列說明何者正確？

  1. A各核心的操作每次都以隨機的順序執行
  2. B所有核心的操作被排成某一個順序，且各核心的操作看起來會依程式所寫的順序出現
  3. C所有操作都只在一個核心上執行
查看答案與解析

正確答案：B. 所有核心的操作被排成某一個順序，且各核心的操作看起來會依程式所寫的順序出現

在循序一致性中，多個核心的操作就像洗牌一樣被排成一列，而各核心的操作在其中看起來維持程式的順序。對程式設計師而言這是最容易理解的模型，但它會大幅限制硬體以儲存緩衝區等方式調換順序的最佳化，所以實際上許多CPU採用更寬鬆的模型。

常見問題

什麼是儲存到載入的轉送？

就是載入在儲存緩衝區中找到仍在等待的相符先前儲存，並直接從那裡取得資料，使核心不必等待寫入到達快取，就能看到自己尚未完成的寫入。

為什麼在儲存緩衝 litmus 測試中兩個執行緒都可能讀到 0？

每個核心的寫入都停留在自己的儲存緩衝區中，對另一個核心不可見，而其後續的載入從快取讀到舊值；在儲存與載入之間加入記憶體屏障即可防止這種情況。

儲存緩衝區和 TSO 有什麼關係？

總儲存順序基本上就是 FIFO 儲存緩衝區的行為：它唯一允許的重排，是後面對不同位址的載入在前面的儲存變為可見之前就完成。
