什麼是共享函式庫（Shared library）

在動態連結時於執行期載入的函式庫。在 Linux 為 .so，在 Windows 為 .dll。以位置無關程式碼建置，程式碼的分頁可由多個行程共用。

日文名稱: 共有ライブラリ

「共享函式庫（Shared library）」出現在3領域的16道練習題中（連結器與載入器與執行檔格式, 指令集與組合語言, 雲端與容器基礎等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

動態連結如何運作

當程式與共享函式庫連結時，執行檔只記錄它需要哪些函式庫（以 soname 識別）以及要匯入哪些符號。啟動時，動態連結器（Linux 上為 ld.so）會找到每個函式庫，將其對應到行程的位址空間，解析符號參照並套用重定位。呼叫函式庫函式通常會經過程序連結表（PLT），它可以在每個函式第一次被呼叫時才延遲解析。ldd 指令會顯示每個所需函式庫解析到哪個檔案，並將找不到的標示為「not found」；不應對不受信任的二進位檔執行 ldd，因為這可能會執行其程式碼。

位置無關程式碼與分頁共用

共享函式庫在每個行程中都可能被載入到不同的位址，因此會編譯成位置無關程式碼（PIC）。程式碼以 PC 相對定址存取自己的函式與資料，並透過全域偏移表（GOT）存取外部符號；GOT 是每個行程各自擁有的資料區，由動態連結器填入。因此程式碼分頁永遠不需要修補，可以對應為唯讀且可執行。作業系統讓每個行程的對應都指向相同的實體分頁，所以 100 個使用同一函式庫的行程只需保存一份程式碼，而可寫入的資料分頁則由各行程分別保有，通常採用寫入時複製。

以 soname 進行版本管理

在 Linux 上，像 libfoo.so.1.2.3 這樣的函式庫檔案帶有 libfoo.so.1 這樣的 soname，程式記錄的是 soname。維持 ABI（應用程式二進位介面）相容的錯誤修正或安全性修補會保留 soname，因此只要替換一個檔案，就能更新所有使用它的程式。若改變引數型別、結構配置或移除函式，舊的二進位檔就會失效，因此要提高 soname 的編號，並將新函式庫與舊函式庫並存安裝。

共享函式庫與靜態函式庫

靜態函式庫是目的檔的封存檔，連結時會將需要的部分複製到執行檔中，產生不需要啟動時綁定的獨立二進位檔，但每個程式都帶有自己的副本，修正時也必須重新連結。共享函式庫可節省記憶體與磁碟空間，並允許就地更新，代價是啟動時的綁定工作、跨模組呼叫的間接層，以及缺少相依函式庫時的失敗。將內部函式設為隱藏可見性、只匯出公開 API，可以減少動態連結器需要處理的符號，讓內部呼叫略過 PLT，避免名稱衝突，並讓 ABI 保持精簡。

正確答案：B. 多個程式可在記憶體上共用一個函式庫，更新函式庫後不必重新建置即可反映修正

在動態連結中，執行檔只記錄「要使用哪個共用函式庫的哪個函式」，執行時由動態連結器載入函式庫並加以結合。共用函式庫的程式碼不會被改寫，因此實體記憶體上的同一份副本可由許多行程共用。錯誤與漏洞的修正，也只要替換函式庫即可。不過啟動時需要花費結合的功夫。

位置獨立程式碼無法將位於其他函式庫中的變數位址直接寫入指令。因此每個模組會準備一張排列位址的表（GOT），程式碼以與PC的距離讀取GOT的項目，並使用其中的位址。動態連結器在載入時，會將實際位址寫入GOT。被改寫的只有可寫入的資料GOT，因此程式碼的分頁可維持共用。

常見問題

靜態函式庫和共享函式庫有什麼差別？

靜態函式庫（.a 或 .lib）在連結時被複製到執行檔中。共享函式庫（.so 或 .dll）則維持為獨立檔案，在執行期載入，並可在記憶體中由多個行程共用。

為什麼共享函式庫需要 -fPIC？

函式庫可能被載入到任意位址，因此其程式碼必須避免使用絕對位址。PIC 使用 PC 相對定址與 GOT，讓程式碼分頁不需修改即可共用。

ldd 輸出中的「not found」是什麼意思？

動態連結器在其搜尋路徑中找不到該共享函式庫，因此在安裝該函式庫或修正路徑之前，程式都無法啟動。
