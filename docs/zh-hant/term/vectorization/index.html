什麼是向量化

將迴圈中逐元素進行的相同計算，改為使用SIMD指令一次對多個元素進行的最佳化。條件是重複之間沒有資料相依。

日文名稱: ベクトル化

「向量化」出現在2領域的4道練習題中（編譯器, 記憶體階層與效能等）。

這個名詞所屬的領域: 編譯器

迴圈如何變成SIMD程式碼

SIMD（單一指令多重資料）指令會對打包在一個寬暫存器中的多個值進行運算。一個128位元暫存器可容納四個32位元數值，因此一道SIMD加法可取代四道純量加法，而256位元或512位元單元則可一次處理八個或十六個。向量化編譯器會改寫迴圈，使新迴圈的每次迭代處理一個暫存器容量的元素。當迭代次數在編譯時未知或不是向量寬度的整數倍時，編譯器會加入純量的剩餘迴圈，或使用遮罩運算來處理剩下的元素。

什麼會阻礙向量化

關鍵條件是各次迭代彼此獨立。像a[i] = a[i-1] + b[i]這樣的迴圈具有迴圈攜帶相依性，因為每個元素都需要前一個結果，所以無法同時計算多個元素。可能的別名是另一個障礙：若兩個指標可能指向重疊的記憶體，編譯器就必須加入執行時期的重疊檢查，否則只能放棄；C語言的restrict限定詞則保證不重疊。非連續或間接的存取、編譯器無法內嵌的函式呼叫，以及複雜的控制流程，也會降低或阻止向量化。

歸約與浮點運算順序

將陣列加總到單一變數本身就是一種相依性，但編譯器會在各向量通道中保留多個部分和，最後再合併，以此將其向量化。對整數而言結果完全相同。對浮點數則無法保證，因為每次加法都會捨入，(a + b) + c可能與a + (b + c)略有不同。因此在嚴格設定下，編譯器會維持原本的順序，可能不會將這類歸約向量化；fast-math等選項則允許重新結合，代價是極小的數值差異。

資料配置：AoS與SoA

記憶體配置常決定向量化程式碼是否快速。在結構陣列（AoS）中，每筆記錄將x、y、z與質量存在一起，因此只讀取x的迴圈只會用到每條所抓取64位元組快取行的四分之一。在陣列結構（SoA）中，所有x值是連續的：每條抓取的快取行都被完整使用，記憶體流量降到約四分之一，而且一次向量載入就能取得連續的x值，無需收集（gather）指令。改變配置並不會改變數值結果。

練習向量化的題目

編譯器的自動向量化所使用的指令種類，下列何者正確？

  1. A引發中斷的指令
  2. B同時處理多筆資料的SIMD指令
  3. C一次清除快取全部內容的指令
查看答案與解析

正確答案：B. 同時處理多筆資料的SIMD指令

自動向量化是一種最佳化，會找出對陣列的每個元素進行相同計算的迴圈，並替換為一次處理多個元素的SIMD指令。例如若是128位元的SIMD暫存器，可以同時將4個32位元的數相加，順利的話迴圈的運算次數可減為四分之一。其條件包括重複之間沒有相依、資料排列連續等，若可能有指標重疊，也會放棄向量化。這與中斷或快取操作的指令無關。

常見問題

向量化和多執行緒有什麼差別？

向量化是利用每道指令處理多個資料元素的SIMD指令，加快單一執行緒的速度。多執行緒則是在不同核心上執行各自的指令串流，兩者經常結合使用。

為什麼編譯器不幫我的迴圈做向量化？

常見原因包括迭代之間有相依性、可能的指標別名、非連續的記憶體存取、呼叫無法內嵌的函式，或是在嚴格設定下需要重排加法順序的浮點歸約。大多數編譯器都能輸出向量化報告，說明其判斷原因。

向量化會改變浮點運算結果嗎？

逐元素運算的結果相同，但向量化的歸約會以不同順序相加數值，而浮點加法不具結合性，因此最終總和可能在最後幾個位元上有所不同。
