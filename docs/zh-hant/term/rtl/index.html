什麼是RTL(暫存器傳輸層級)

以資料如何在暫存器之間傳輸與處理來描述電路的設計抽象層級。以Verilog或VHDL撰寫，是邏輯合成的輸入。

日文名稱: RTL(レジスタ転送レベル)

「RTL(暫存器傳輸層級)」出現在3領域的9道練習題中（LSI設計流程與EDA, 硬體描述語言與驗證, 時序分析與CDC等）。

這個名詞所屬的領域: LSI設計流程與EDA

RTL 描述在表達什麼

RTL 模型把同步電路分成兩類元素：在時脈邊緣擷取新值的暫存器，以及根據目前暫存器內容與輸入計算出這些新值的組合邏輯。在這個層級撰寫設計，就是逐個週期地指定每個暫存器下一步要保存的值，而不必選定具體的邏輯閘。在 Verilog 中，正反器以搭配非阻塞指定的時脈 always 區塊表示，組合邏輯則寫成獨立的組合區塊或 assign 敘述。所有區塊描述的都是同時運作的硬體，這對習慣循序式軟體的程式設計師來說是最大的思維轉換。

從 RTL 到邏輯閘

RTL 介於演算法層級描述與閘級網表之間。在其上層，高階合成（HLS）可將運算排程到各個時脈週期，從 C 或 C++ 產生 RTL。在其下層，邏輯合成會把 RTL 對應到標準元件庫中的正反器與邏輯閘，並依時序、面積與功耗限制進行最佳化，接著由佈局繞線產生佈局。有些設計意圖會刻意放在 RTL 之外：統一功率格式（UPF，IEEE 1801）以獨立檔案描述電源域、斷電、隔離與電位轉換器，讓電源架構可以在不修改 RTL 的情況下變更。

可合成程式碼與僅供模擬的程式碼

HDL 中只有一部分能對應到硬體。像 #10 這類延遲敘述會推進模擬時間，但合成時會被忽略，因為實際延遲來自邏輯閘與導線。$display 等系統任務、檔案 I/O 以及 case 相等運算子 === 都是測試平台用的工具。典型的撰寫陷阱會改變硬體本身：組合區塊若沒有在每條路徑上都指定輸出，就會推論出非預期的閂鎖器；而隨意混用阻塞與非阻塞指定，可能使模擬結果與合成後的電路不一致。良好的 RTL 寫法會讓模擬行為與硬體行為完全相同。

RTL 驗證

大部分驗證工作都在 RTL 進行，因為此層級的模擬速度足以跑上數百萬個週期。進度以程式碼覆蓋率與功能覆蓋率衡量：前者追蹤已執行的程式行與分支，後者追蹤規格中指定的情境；光是程式碼覆蓋率達到百分之百，並不能證明每一種規定的組合都已測試過。有些錯誤在 RTL 模擬中是看不見的。由於模擬中的正反器永遠不會進入亞穩態，因此需要時脈域跨越（CDC）工具來找出缺少的同步器。形式等價性檢查可確認網表與 RTL 一致，而搭配 SDF 延遲資料的閘級模擬則能揭露重置、未知值與時序方面的問題。

練習RTL(暫存器傳輸層級)的題目

RTL設計主要使用的硬體描述語言為下列何者？

  1. AVerilog HDL或VHDL
  2. BHTML
  3. CSQL
查看答案與解析

正確答案：A. Verilog HDL或VHDL

RTL設計是以Verilog HDL（及其擴充版SystemVerilog）或VHDL等硬體描述語言，描述每個時脈下資料如何在暫存器之間流動。與軟體語言不同，所描述的處理會以電路形式同時並行運作。HTML是網頁的描述語言，SQL是資料庫的查詢語言，都無法描述電路。

從以C語言或C++等撰寫的演算法描述，自動產生RTL的技術稱為什麼？

  1. A高階合成（HLS）
  2. B邏輯合成
  3. C佈局繞線
查看答案與解析

正確答案：A. 高階合成（HLS）

高階合成是從以C/C++等撰寫的行為描述，自動決定運算器與暫存器的分配、各運算在哪個時脈週期執行（排程），並產生RTL的技術。由於可從同一份描述試驗不同管線化或平行度的多種架構，能提高設計的抽象程度並縮短開發時間。用於訊號處理或AI用電路設計等。邏輯合成則是從RTL產生邏輯閘的製程。

常見問題

RTL 和閘級網表有什麼差別？

RTL 是以硬體描述語言描述暫存器及其間的邏輯，不選定具體的邏輯閘；閘級網表則是合成後的結果，是實際元件庫單元及其連接關係的清單。

RTL 就是 Verilog 嗎？

不是。RTL 是一種抽象層級；Verilog、SystemVerilog 與 VHDL 則是語言，除了 RTL 之外也能撰寫測試平台與更低階的閘級描述。

為什麼 RTL 模擬正確，合成後卻出錯？

常見原因包括延遲等僅供模擬的語法、指定不完整而推論出的閂鎖器、不完整的敏感度列表，以及阻塞／非阻塞指定的誤用，這些都會使模擬行為與產生的邏輯閘不同。
