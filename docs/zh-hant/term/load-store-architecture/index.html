什麼是載入儲存架構

將讀寫記憶體的指令限定為載入與儲存，加法等運算只在暫存器之間進行的ISA方式。RISC-V與ARM採用，指令形式整齊，容易以管線處理。

日文名稱: ロード・ストア・アーキテクチャ

「載入儲存架構」出現在1領域的1道練習題中（指令集與組合語言等）。

這個名詞所屬的領域: 指令集與組合語言

將存取記憶體的指令分開的概念

在載入／儲存架構中，只有載入指令與儲存指令能讀寫記憶體，加法、比較等運算都在暫存器之間進行。例如將記憶體中的變數b與c相加並寫入a，在RISC-V中需要4個指令：以lw指令將b與c載入暫存器，以add指令相加，再以sw指令寫回a。相對地，像x86的「add eax, [mem]」這種運算指令能直接讀取記憶體的方式，稱為暫存器-記憶體型，與載入／儲存型形成對比。

與管線相容性佳的原因

由於運算指令不碰觸記憶體，每個指令最多只存取記憶體1次，指令格式與處理流程都很整齊。在經典的5級管線（指令擷取、解碼、執行、記憶體存取、寫回）中，只有載入與儲存會使用記憶體存取級，其他指令直接通過。位址轉換失敗或頁面錯誤等與記憶體相關的例外，也只會由載入與儲存引起，因此例外處理變得單純。指令長度也較容易固定，解碼因而簡單。

暫存器數量與程式碼大小

由於值要先放進暫存器才能運算，載入／儲存型ISA一般具有較多的通用暫存器：RISC-V的整數暫存器有32個，ARM的64位元指令集（AArch64）的通用暫存器有31個。編譯器會把常用的值分配到暫存器，以減少載入與儲存的次數。另一方面，指令數會增加、程式碼容易變大，因此有RISC-V的C擴充（壓縮指令）或ARM的Thumb等，提供較短的指令格式以提高程式碼密度。

與CISC的關係及例外的指令

載入／儲存型是RISC的代表性特徵，RISC-V、ARM、MIPS、Power等都採用。屬於暫存器-記憶體型的x86，現今的CPU在內部也會把讀取記憶體的運算指令拆成載入與運算的微運算來執行，在執行階段已接近載入／儲存型。不過載入／儲存型ISA也有讀取記憶體上的值、運算後再寫回的原子指令（例如RISC-V A擴充的AMO指令），作為多核心同步之用的例外。

練習載入儲存架構的題目

下列何者是RISC-V這類載入／儲存架構（load-store architecture）的特徵？

  1. A加法等運算指令直接讀取記憶體上的值進行計算，並將結果寫回記憶體
  2. B只有載入指令與儲存指令能讀寫記憶體，運算在暫存器之間進行
  3. C不具備暫存器，所有的值都堆入堆疊來計算
查看答案與解析

正確答案：B. 只有載入指令與儲存指令能讀寫記憶體，運算在暫存器之間進行

在載入／儲存架構中，記憶體的值先以載入指令讀入暫存器，加法或比較等運算在暫存器之間進行，需要時再以儲存指令將結果寫回記憶體。由於運算指令不直接處理記憶體，指令的格式整齊，也更容易以管線處理。這與x86的「add eax, [mem]」這種運算指令可以讀取記憶體的方式形成對比。

常見問題

載入／儲存架構是什麼？

是將存取記憶體的指令限定為載入與儲存，所有運算都在暫存器之間進行的指令集方式。代表例有RISC-V與ARM，由於指令格式整齊，容易以管線處理。

載入／儲存架構和RISC是同樣的意思嗎？

不一樣。載入／儲存型描述的是存取記憶體的方式，RISC則是包含單純指令、固定長度指令等的更廣泛設計理念。不過許多RISC都採用載入／儲存型，因此兩者常被一起討論。

x86是載入／儲存架構嗎？

就指令集而言不是，它屬於運算指令能直接讀寫記憶體的暫存器-記憶體型。不過現今的x86 CPU在內部會把這類指令拆成載入、運算、儲存的微運算來執行。
