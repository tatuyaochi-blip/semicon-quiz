什麼是多週期路徑

告知 STA 某路徑的資料傳遞可使用多個時脈週期的時序例外。設定檢查設為 N 週期時，保持檢查通常也指定 N − 1，使檢查的邊緣回到原來的位置。

日文名稱: マルチサイクルパス

「多週期路徑」出現在1領域的3道練習題中（時序分析與CDC等）。

這個名詞所屬的領域: 時序分析與CDC

路徑確實擁有更多時間的情況

有些路徑不必在一個時脈週期內傳遞資料，因為目的端每 N 個週期才擷取一次，例如透過每隔一個週期才致能的 enable 載入的暫存器，或在輸入改變兩個週期後才取樣其結果的低速運算區塊。STA 預設假設單週期傳輸，並回報違規。多週期路徑例外（SDC 中的 set_multicycle_path）會告訴工具，擷取邊緣是在發送之後 N 個週期，而不是一個。

setup 的計算

若時脈為 2.0 ns、資料到達時間為 3.3 ns、setup 時間為 0.1 ns，預設的單週期檢查得到要求時間 1.9 ns、slack −1.4 ns。設定 setup multicycle 為 2 後，擷取移到 4.0 ns，要求時間變為 3.9 ns，slack 為 +0.6 ns。此例外只有在邏輯確實保證每隔一個週期才擷取時才有效；否則它會掩蓋將在實際晶片上出現的真正故障。

為什麼 hold 需要 N − 1

STA 是以 setup 擷取邊緣前一個週期的邊緣來檢查 hold。因此將 setup 擷取移到 N 個週期，也會把 hold 檢查拖到發送後 N − 1 個週期，這等於要求新資料至少要那麼晚才到達，是一個荒謬且嚴苛、通常會失敗的要求。加上 N − 1 的 hold multicycle，會將 hold 檢查移回時間零的發送邊緣，恢復一般的 hold 條件。它並不會移除 hold 檢查。

多週期路徑與 false path

多週期路徑仍會進行時序分析，只是時間預算較長。以 set_false_path 設定的 false path 則完全排除在分析之外，用於結構上有連接、但絕不會傳遞有意義轉態的路徑，例如經過兩個選擇條件互斥之多工器的路徑。只因路徑難以收斂就宣告為 false，會掩蓋真正的錯誤；而將真正的多週期路徑宣告為 false，則會移除它仍需要的檢查。

練習多週期路徑的題目

在以週期 2.0 ns 的時脈運作的電路中，有一條資料到達時間（時脈→輸出延遲與組合電路延遲的總和）為 3.3 ns、建立時間為 0.1 ns 的路徑。此路徑只需每2個週期取入一次，因此將建立時間的多週期路徑設為2。建立時間的餘裕是多少？

  1. A−1.4 ns
  2. B+2.6 ns
  3. C+0.6 ns
查看答案與解析

正確答案：C. +0.6 ns

多週期路徑設為2時，取入的邊緣不是1個週期後，而是2個週期後。要求時間為 2 × 2.0 − 0.1 = 3.9 ns，到達時間為 3.3 ns，因此餘裕為 +0.6 ns。−1.4 ns 是仍以一般的1個週期計算的值，+2.6 ns 是給予3個週期時間的值。多週期路徑必須由設計者確認該電路確實透過致能訊號等只每2個週期取入一次之後，才能設定。

將建立時間的多週期路徑設為 N（N ≥ 2）時，保持時間通常也要將多週期路徑設為 N − 1。其理由何者正確？

  1. A保持時間的檢查邊緣也會隨建立時間一起往後移而變得過於嚴苛，因此要將其移回原位
  2. B將保持時間的檢查邊緣再往後移，以增加保持時間的餘裕
  3. C將該路徑的保持時間檢查排除於分析之外
查看答案與解析

正確答案：A. 保持時間的檢查邊緣也會隨建立時間一起往後移而變得過於嚴苛，因此要將其移回原位

STA預設是在建立時間取入邊緣的前一個邊緣檢查保持時間。將建立時間設為2個週期後，保持時間的檢查邊緣也會從時刻0移到1個週期後；若週期為 2.0 ns，資料不延遲 2.0 ns 以上才到達就會違規。將保持時間的多週期路徑指定為 N − 1 = 1，檢查邊緣便回到時刻0，與一般路徑的條件相同。這並不是取消保持時間的檢查。

常見問題

為什麼 setup multicycle 設為 N 時，hold multicycle 要設為 N − 1？

移動 setup 擷取邊緣也會使預設的 hold 檢查往後移，讓 hold 幾乎不可能滿足。N − 1 的 hold 設定會讓 hold 檢查回到原本的邊緣。

多週期路徑和 false path 有什麼差別？

多週期路徑仍會被分析，只是給予多個時脈週期。false path 則完全不分析，只應用於功能上絕不會傳遞的路徑。

什麼時候設定多週期路徑是安全的？

只有在設計保證目的端每 N 個週期取樣一次資料（例如透過 enable），且驗證已確認該行為時才安全。否則放寬的檢查可能掩蓋真正的時序故障。
