什麼是飛地（Secure enclave）

在 CPU 對記憶體加密保護的區域中執行應用程式的一部分，使連作業系統與虛擬機器監視器都無法讀取其內容的 TEE 方式。

日文名稱: エンクレーブ

「飛地（Secure enclave）」出現在1領域的1道練習題中（硬體安全等）。

這個名詞所屬的領域: 硬體安全

飛地的運作方式

飛地是只把應用程式中處理金鑰或個人資料等機密的部分，放在CPU保護的特殊記憶體區域中執行的方式。以代表例Intel SGX來說，飛地的分頁在CPU外部的主記憶體中是加密的，只有在CPU內部才會解密。CPU會拒絕飛地以外的程式碼對其讀寫，視實作而定也會偵測記憶體遭竄改。作業系統與虛擬機器監視器（hypervisor）仍負責記憶體配置與排程，但無法讀取或改寫飛地的內容。

縮小需要信任的範圍

一般的應用程式必須信任作業系統、虛擬機器監視器、驅動程式、管理者等所有對象，才能保護機密。使用飛地時，必須信任的範圍（TCB：Trusted Computing Base）縮小到CPU的硬體與韌體，以及飛地本身的程式碼。飛地的程式碼在啟動時會被量測，並透過以CPU內部金鑰簽署該量測值的遠端證明，讓使用者在確認正確的程式碼確實在真正的飛地中執行後，再交付機密資料。

限制與旁通道攻擊

飛地並非萬能。飛地內部無法直接呼叫系統呼叫，因此檔案與通訊的處理必須交給外部的程式碼，每次進出都會產生處理負擔。有些實作對受保護記憶體的容量設有上限，處理大量資料時效能可能下降。此外，研究中也陸續報告了利用快取時序、分頁錯誤的模式、推測執行等旁通道攻擊（也稱旁路攻擊）洩漏飛地機密的例子。因此，讓分支與記憶體存取不隨機密而改變的寫法，以及微碼的更新都很重要。

與TrustZone及機密虛擬機的差異

TEE有幾種形式。Arm的TrustZone將CPU分為安全世界與一般世界，在安全世界中執行專用的小型作業系統與應用程式，與只切出應用程式一部分的飛地，保護的單位不同。AMD SEV或Intel TDX這類機密虛擬機，是將整個虛擬機的記憶體加密，以防範虛擬機器監視器的方式；既有的作業系統與應用程式幾乎可以直接執行，但整個客體作業系統都納入信任範圍。另外，截至2020年代前半，Intel已不在用戶端CPU提供SGX，主要在伺服器用CPU上提供。

練習飛地（Secure enclave）的題目

下列關於Intel SGX這類「飛地（enclave）」型TEE的特徵，何者正確？

  1. A在外接硬碟上執行整個作業系統核心
  2. B在由CPU將記憶體加密保護的區域中執行應用程式的一部分，連作業系統或超管理器（hypervisor）也無法讀取其內容
  3. C飛地內的資料任何人都能自由改寫
查看答案與解析

正確答案：B. 在由CPU將記憶體加密保護的區域中執行應用程式的一部分，連作業系統或超管理器（hypervisor）也無法讀取其內容

在飛地中，只有應用程式處理機密的部分在特殊的記憶體區域中執行，該區域在CPU內經過加密與竄改偵測後才放到主記憶體。連作業系統、超管理器，以及以物理方式讀取記憶體的攻擊者都看不到內容。需要信任的只有CPU及其程式碼。不過也有報告指出其對旁路攻擊的脆弱性，使用時需要留意。

常見問題

簡單來說，飛地是什麼？

將應用程式處理機密的部分，放在由CPU加密保護記憶體的區域中執行，使連作業系統與虛擬機器監視器都無法讀取其內容的機制。Intel SGX是代表例，屬於TEE（可信執行環境）的一種方式。

飛地與TrustZone有什麼不同？

TrustZone將CPU分為安全與一般兩個世界，在安全側執行專用的作業系統與應用程式。飛地則是將在一般作業系統上執行的應用程式的一部分，切出成為專用的受保護區域。兩者保護的單位，以及必須信任的軟體範圍都不同。

Apple的Secure Enclave也是同樣的東西嗎？

名稱相似，但架構不同。Apple的Secure Enclave是在SoC內與主CPU分開設置的安全用子系統，負責金鑰管理與生物辨識資料的處理等。SGX這類飛地，則是由主CPU本身保護並執行應用程式一部分的方式。
