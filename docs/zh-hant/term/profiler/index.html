什麼是效能剖析器（Profiler）

量測程式中哪些函式或部分花費較多執行時間的工具。有取樣方式與插碼（instrumentation）方式。

日文名稱: プロファイラ

「效能剖析器（Profiler）」出現在2領域的3道練習題中（效能評估與效能剖析, GPU程式設計等）。

這個名詞所屬的領域: 效能評估與效能剖析

取樣式與插碼式

取樣式效能剖析器利用計時器或硬體效能計數器的溢位，定期中斷執行中的程式，記錄當下的指令位址，通常也會記錄呼叫堆疊，每秒可能達數千次。耗時越多的函式越常被捕捉到，因此取樣次數能以統計方式估計時間花在哪裡，額外負擔小，也不需修改程式。插碼式效能剖析器則在函式的進入與離開點或基本區塊中插入程式碼，可取得精確的呼叫次數，但增加的額外負擔可能扭曲時序，對於小而頻繁呼叫的函式尤其明顯。

如何解讀剖析結果

效能剖析器通常會報告自身時間（花在函式本身程式碼上的時間）與包含時間（也計入其所呼叫函式的時間）。平面剖析依自身時間為函式排名，呼叫圖或火焰圖則顯示哪些呼叫路徑造成了這些成本。典型的發現是熱點：少數百分比的程式碼（通常是內層迴圈）占用了大部分的執行時間。許多效能剖析器也會讀取快取失誤或分支預測錯誤等硬體效能計數器，有助於解釋熱點為什麼慢，而不只是它在哪裡。

效能剖析與 Amdahl 定律

Amdahl 定律指出，若執行時間中的比例 f 被加速 s 倍，整體加速為 1 / ((1 − f) + f/s)。讓只占 1% 時間的程式碼變得無限快，也只能獲得約 1% 的改善，而讓占 80% 時間的程式碼速度加倍，整體約可快 1.7 倍。由於對時間花在哪裡的直覺經常是錯的，可靠的流程是：先量測，最佳化最大的貢獻者，然後在相同條件下再次量測，以確認改善幅度並檢查其他部分沒有退化。

GPU 效能剖析，以及名稱上的注意事項

對 GPU 程式而言，首先要用時間軸檢視總時間如何分配在核心執行、CPU–GPU 資料傳輸與 CPU 端工作上，以及傳輸是否與運算重疊。只有在核心執行占主導時，才值得檢視記憶體存取模式或占用率，而占用率較高也不一定比較快。在半導體量測領域，「profiler」可能指完全不同的東西：探針式輪廓儀（stylus profiler）以細探針劃過晶圓，量測毫米級範圍內的階差高度、蝕刻深度與平坦度，解析度比原子力顯微鏡（AFM）粗。

練習效能剖析器（Profiler）的題目

改善程式效能時使用剖析器（profiler）的目的，下列何者正確？

  1. A找出程式的語法錯誤
  2. B計算程式的使用者人數
  3. C調查程式的哪些函式或部分花費了大部分的執行時間
查看答案與解析

正確答案：C. 調查程式的哪些函式或部分花費了大部分的執行時間

在許多程式中，大部分的執行時間是由極少部分的程式碼所使用。然而，由人來推測哪裡慢，常常會猜錯。剖析器會測量並顯示每個函式的執行時間與被呼叫的次數，甚至是每一行、每個指令的時間。如同阿姆達爾定律所述，改善花費大量時間的部分才有效，所以先測量就是改善效能的第一步。

常見問題

取樣式和插碼式效能剖析器有什麼差別？

取樣式效能剖析器定期記錄程式正在執行的位置，以較低的額外負擔進行統計估計。插碼式效能剖析器在函式或區塊中加入量測程式碼，可取得精確次數，但會拖慢程式，也可能使其行為失真。

效能剖析中的熱點是什麼？

熱點是占用大部分執行時間的一小段程式碼，通常是一個迴圈或少數幾個函式。最佳化熱點能以最少的投入獲得最大的效益。

使用效能剖析器會拖慢程式嗎？

會有一些影響。取樣式效能剖析器通常只增加很少的額外負擔，而插碼可能增加很多，尤其是包覆大量短函式的時候。
