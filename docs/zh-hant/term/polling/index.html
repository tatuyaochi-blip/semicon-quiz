什麼是輪詢（Polling）

CPU 反覆去檢查周邊電路的狀態，藉以發現變化的方式。雖然單純，但即使什麼都沒發生也持續檢查，因此耗費時間與電力。

日文名稱: ポーリング

「輪詢（Polling）」出現在3領域的3道練習題中（作業系統與硬體, 嵌入式與韌體, CPU與架構等）。

這個名詞所屬的領域: 嵌入式與韌體

輪詢的運作方式

使用輪詢時，CPU 在迴圈中讀取周邊的狀態暫存器來得知其狀況，例如反覆檢查 UART 的「接收資料就緒」旗標，直到它被設定後再讀取該位元組。檢查可以是緊密的忙碌等待，也可以是在主迴圈或計時器常式中的定期檢查。輪詢容易撰寫與除錯，而且時序可預測，因為檢查恰好發生在程式安排的位置。在 C 語言中，暫存器指標必須宣告為 volatile，編譯器才會在每一輪實際重新讀取硬體，而不是沿用快取的值。

輪詢與中斷的比較

使用中斷時，周邊在發生事件時通知 CPU；CPU 暫停目前的工作、保存狀態、執行處理常式後再恢復。如此一來 CPU 在等待期間可以做其他工作或進入休眠，這對電池供電的裝置很重要。輪詢即使在沒有任何變化時也會耗費 CPU 時間與能量，其最壞情況的反應時間由輪詢間隔決定。另一方面，每次中斷都帶有進入與離開處理常式的固定額外負擔，而輪詢可以避免這一點。

輪詢較佳的情況

當事件頻繁到每次中斷的額外負擔會成為主導時，輪詢就更有優勢。高速網路處理是經典案例：在高負載下，驅動程式會從每個封包一次中斷，切換成以批次輪詢封包，有些封包處理框架甚至會指派專用核心持續輪詢。輪詢也適合非常短的等待，例如幾個週期內就會就緒的狀態旗標、中斷尚未設定好的簡單開機程式碼，以及必須在嚴格固定的時刻取樣的控制迴圈。

混合做法

實際系統常將兩者結合。由中斷將 CPU 從休眠中喚醒，處理常式再以輪詢方式取完所有待處理的資料後才重新啟用中斷，如此一連串事件只需一次中斷而非多次。DMA（直接記憶體存取）可在不需 CPU 介入的情況下搬移資料，只在整個區塊完成時才發出通知，從而減少對兩者的需求。對於讀取動作本身就會清除旗標的狀態暫存器要特別小心，因為多讀一次就可能在不知不覺中丟失一個事件。

練習輪詢（Polling）的題目

  1. A處理的發生頻率非常高，每次中斷所需的切換負擔很大時
  2. B處理的發生極為罕見，且希望把CPU用在其他工作時
  3. C為了盡量降低耗電量，希望讓CPU長時間休眠時
查看答案與解析

正確答案：A. 處理的發生頻率非常高，每次中斷所需的切換負擔很大時

當處理很罕見時，中斷可以讓CPU不被浪費，但每一次都有儲存狀態與跳到處理常式的負擔。若像高速網路那樣處理極為頻繁，中斷的負擔會累積而來不及處理，因此集中輪詢反而更有效率。處理罕見的情況，或想讓CPU休眠以降低功耗時，空轉持續檢查的輪詢十分浪費，較適合使用中斷。

  3. C中斷是CPU反覆去檢查狀態的方式

輪詢的結構簡單，檢查的間隔固定，因此動作容易預測；但即使什麼都沒發生，CPU也持續檢查，會浪費時間與電力。中斷只在有變化時CPU才回應，因此等待期間可以做其他處理或進入睡眠。不過若中斷過於頻繁，反而會使處理的負擔變大，所以區分使用很重要。

常見問題

輪詢和中斷有什麼差別？

輪詢是由 CPU 反覆檢查裝置的狀態；中斷則是裝置在狀態改變時通知 CPU。輪詢較簡單且可預測，而中斷讓 CPU 在等待期間能做其他工作或休眠。

為什麼 C 語言中被輪詢的暫存器要宣告為 volatile？

若沒有 volatile，編譯器可能假設該值不會改變而只讀取一次，使輪詢迴圈變成無窮迴圈。volatile 會強制每次迭代都重新讀取硬體暫存器。

輪詢一定沒效率嗎？

不一定。當事件以極高的頻率到達時，輪詢可避免每次中斷的保存與還原負擔，並能批次處理事件，因此比中斷更有效率。
