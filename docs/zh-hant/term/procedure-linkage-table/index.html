什麼是PLT（程序連結表）

排列了呼叫共享函式庫函式所用的小型入口的表。在延遲繫結中，第一次呼叫時由動態連結器解析位址並寫入 GOT。

日文名稱: PLT(プロシージャリンケージテーブル)

「PLT（程序連結表）」出現在1領域的3道練習題中（連結器與載入器與執行檔格式等）。

這個名詞所屬的領域: 連結器與載入器與執行檔格式

為什麼呼叫要經過樁程式

共享函式庫在每個行程中可能被載入到不同的位址，因此在程式連結時，像 printf 這樣的函式位址是未知的。在載入時修補每一條呼叫指令，會使程式碼頁面變成可寫入，且無法在行程之間共享。因此，連結器將每個外部呼叫指向程序連結表（PLT）中的一個小型樁程式（stub）。樁程式會透過全域偏移表（GOT）中的一個槽位進行間接跳躍，GOT 是一個可寫入的資料區域，由動態連結器填入實際位址。

延遲繫結的逐步流程

在延遲繫結下，每個 GOT 槽位一開始都指回其自身的 PLT 樁程式。第一次呼叫時，樁程式推入一個識別該函式重定位項目的索引，並跳到共同的 PLT 標頭，由此進入動態連結器的解析器。解析器在已載入的函式庫中查找該符號，將其位址寫入 GOT 槽位，然後跳到該函式。之後的每次呼叫都依樁程式、GOT、函式的順序進行，不再查找。從未被呼叫的函式永遠不會被解析，這縮短了程式的啟動時間。

立即繫結與唯讀 GOT

由於 GOT 可寫入且保存程式碼位址，能夠覆寫記憶體的攻擊者可能將某個 GOT 項目重新導向，以劫持控制流程。因此許多系統在啟動時就解析所有符號，例如在 Linux 上以 -z now 連結或設定 LD_BIND_NOW，然後將 GOT 標記為唯讀，這種強化稱為 full RELRO（重定位唯讀）。取捨在於：匯入許多函式的程式啟動較慢，換來的是移除一個常見的攻擊目標。

符號可見性與內部呼叫

共享函式庫中匯出的函式可能被另一個模組中同名的定義覆蓋，即插入（interpose），因此即使是函式庫內部的呼叫，通常也必須經過 PLT。將內部函式設為隱藏（hidden）可見性，會將其從動態符號表中移除，於是對它們的呼叫變成直接的 PC 相對呼叫，動態連結器需要處理的符號變少，也能避免與其他函式庫的名稱衝突。GOT 也保存外部資料的位址，但資料存取是直接讀取 GOT，不經過 PLT 樁程式。

練習PLT（程序連結表）的題目

在動態連結中，使用PLT（程序連結表，Procedure Linkage Table）進行延遲繫結（lazy binding）時，下列說明何者正確？

  1. A共用函式庫函式的位址，在該函式第一次被呼叫時才解析，第二次起直接跳到已解析的位址
  2. B在程式啟動前，一定會先解析所有函式的位址
  3. C每次呼叫函式時，都會從磁碟重新讀取函式庫的檔案
查看答案與解析

正確答案：A. 共用函式庫函式的位址，在該函式第一次被呼叫時才解析，第二次起直接跳到已解析的位址

程式是透過PLT的小入口來呼叫外部函式。在延遲繫結中，第一次呼叫時入口會跳到動態連結器的解析處理，尋找真正的位址並寫入GOT。第二次起則直接跳到GOT中的位址。可省去對未使用函式的解析，因此啟動較快。不過基於安全考量，在啟動時全部解析並將GOT設為唯讀的設定也被廣泛使用。

常見問題

PLT 和 GOT 有什麼不同？

PLT 包含外部呼叫所跳往的小型可執行樁程式，而 GOT 是保存已解析位址的資料表；每個 PLT 樁程式都透過其 GOT 項目進行間接跳躍。

動態連結中的延遲繫結是什麼？

延遲繫結是將共享函式庫函式位址的解析延後到第一次呼叫時，屆時動態連結器會查找該位址並存入 GOT，供之後所有呼叫使用。

full RELRO 有什麼作用？

它讓動態連結器在啟動時解析所有符號，然後將 GOT 重新映射為唯讀，使攻擊者無法覆寫 GOT 項目來重新導向函式呼叫。
