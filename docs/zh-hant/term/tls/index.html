什麼是TLS

Transport Layer Security（傳輸層安全性協定）。進行通訊加密、竄改偵測，以及以憑證驗證伺服器的協定。HTTPS是以TLS保護的HTTP。

日文名稱: TLS

「TLS」出現在2領域的6道練習題中（電腦網路基礎, 資訊安全基礎等）。

這個名詞所屬的領域: 電腦網路基礎

練習TLS的題目

以HTTPS（在TCP之上的TLS 1.3）重新連線到RTT（往返時間）為100 ms的Web伺服器，從送出第一個請求到開始收到回應，所需時間最接近下列何者？假設DNS名稱解析已完成，並忽略伺服器的處理時間與資料的傳輸時間。

  1. A約100 ms
  2. B約300 ms
  3. C約200 ms
查看答案與解析

正確答案：B. 約300 ms

首先，TCP的三向交握需要1個往返（用戶端可以把TLS的第一則訊息與最後的ACK一起送出）。接著TLS 1.3的交握需要1個往返，之後HTTP的請求與回應再需要1個往返，合計3個往返，即 3 × 100 = 300 ms。TLS 1.2的金鑰交換需要2個往返，因此共4個往返，為400 ms。這段等待時間取決於RTT的次數，而RTT由距離決定，因此即使增加線路頻寬也不會縮短。HTTP/3使用的QUIC把傳輸層與加密的交握合併為1個往返，重新連線時還提供在第一次往返就傳送資料的方法（0-RTT）。

HTTPS（以TLS保護的HTTP通訊）能保護的是下列何者？

  1. A所連線網站的營運者是沒有惡意、值得信賴的個人或組織
  2. B正在通訊這件事本身，以及所連線伺服器的IP位址，在途中的路徑上都看不到
  3. C通訊內容在途中不會被竊看或竄改，以及所連線的伺服器是憑證上網域名稱的正當擁有者
查看答案與解析

正確答案：C. 通訊內容在途中不會被竊看或竄改，以及所連線的伺服器是憑證上網域名稱的正當擁有者

TLS提供三項功能：通訊加密（機密性）、竄改偵測（完整性）與伺服器驗證。伺服器出示憑證，瀏覽器沿著所信任之憑證機構（CA）的簽章確認憑證是否正確，並確認是否與URL的網域名稱一致。不過，能確認的只是「正在與該網域名稱的擁有者通訊」，並無法得知網站的營運者是否善良。即使是詐騙網站，也能取得自己網域名稱的憑證。此外，IP標頭不會被加密，因此與哪個IP位址、在何時、通訊了多少量，在途中的路徑上都看得到。
