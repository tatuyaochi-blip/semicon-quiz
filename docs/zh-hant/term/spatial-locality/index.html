什麼是空間局部性

存取某個位址後，其附近的位址也容易在不久後被存取的性質。例如依序讀取陣列的處理，是以快取行為單位一併載入的原因。

日文名稱: 空間的局所性

「空間局部性」出現在2領域的4道練習題中（CPU與架構, 記憶體階層與效能等）。

這個名詞所屬的領域: 記憶體階層與效能

程式為何具有空間局部性

在遇到分支之前，指令會從連續的位址依序擷取；陣列通常逐個元素走訪；結構的欄位或堆疊框中的區域變數彼此相鄰。因此，存取某個位址之後，往往很快就會存取鄰近的位址。空間局部性指的就是這種傾向，它是程式存取模式的性質，而非硬體的性質。

硬體如何利用它

快取以快取行為單位搬移資料，現今 CPU 通常為 64 位元組，因此一次失誤就會帶入接下來很可能使用的鄰近資料。這也與 DRAM 的突發傳輸相符：在 DDR4 中，8 次 8 位元組的傳輸剛好提供 64 位元組。硬體預取器會偵測循序或固定步距的資料流，並提前擷取接下來的快取行；保持開啟的 DRAM 列也能更快地服務鄰近存取。分頁與 TLB 同樣受益，因為一次位址轉換即可涵蓋許多鄰近位址。

空間局部性與時間局部性的比較

時間局部性指不久後再次使用相同的資料，例如迴圈計數器或累加值；空間局部性則指不久後使用鄰近的資料，例如下一個陣列元素。單次走訪大型陣列具有很強的空間局部性，但沒有時間局部性；反覆更新同一個變數則具有時間局部性，但幾乎沒有空間局部性。對大型資料集的隨機存取，例如某些雜湊表或圖形走訪，兩者都很少，因此經常失誤。

撰寫具有空間局部性的程式

在 C 語言中，二維陣列以列為主序儲存，因此讓內層迴圈走訪各行會存取連續的位址，而將兩層迴圈對調則每一步都會跳過整整一列。若只處理其中一個欄位，選擇陣列結構（structure-of-arrays）的配置可避免載入用不到的欄位。較大的快取行能更充分利用空間局部性，但會提高失誤代價，並可能載入不需要的資料；在多執行緒程式中，不相關的變數共用同一快取行則會造成偽共享。

練習空間局部性的題目

設置快取記憶體的主要目的，下列何者正確？

  1. A為了在切斷電源後仍能保存資料
  2. B為了將常用資料放在 CPU 附近，縮小與主記憶體之間的速度差距
  3. C為了修正運算結果的錯誤
查看答案與解析

正確答案：B. 為了將常用資料放在 CPU 附近，縮小與主記憶體之間的速度差距

CPU 處理一個時脈只需 0.2〜0.3 ns，但存取 DRAM 需要數十〜100 ns，也就是數百個時脈。因此將常用的資料與指令放在高速 SRAM 的快取中，以減少等待時間。快取利用的是短時間內會再次使用相同資料的時間局部性，以及會連續使用相鄰位址的空間局部性；L1 只需數個時脈即可存取，即使是 L3 也只需數十個時脈。

目前許多 CPU 所使用之快取列（快取區塊）的大小，下列何者為一般情況？

  1. A1 位元組
  2. B64 位元組
  3. C64 MB
查看答案與解析

正確答案：B. 64 位元組

許多 CPU 在快取與主記憶體之間，是以 64 位元組的快取列為單位交換資料。相鄰位址的資料經常會被連續使用（空間局部性），所以一併取入較有效率，也與 DRAM 的突發傳輸（DDR4 為 8 次 × 8 位元組 = 64 位元組）相符。在多執行緒程式中，必須注意若不同的變數位於同一條快取列，會發生互相爭奪的「偽共享」（false sharing）。

常見問題

空間局部性有什麼例子？

從頭到尾讀取一個陣列：使用元素 i 之後，接著使用位於下一個位址的元素 i+1，而它很可能已在同一次快取行填入時被帶入快取。

快取如何利用空間局部性？

每次失誤時，快取會傳輸整條快取行（通常為 64 位元組），並經常預取後續的快取行，因此當程式要求時，鄰近資料早已在快取中。

為什麼以行方向走訪 C 陣列很慢？

C 以列為單位儲存陣列，因此沿著一行往下走，每次存取都會跳過整整一列，每條擷取進來的快取行只用到一小部分。

解析中的「空間局部性」

  • 快取利用的是短時間內會再次使用相同資料的時間局部性，以及會連續使用相鄰位址的空間局部性；L1 只需數個時脈即可存取，即使是 L3 也只需數十個時脈。
