什麼是IPC

為 Instructions Per Cycle 的縮寫，指每個時脈可執行的指令數。表示 CPU 設計上的效率，性能大致為 IPC 與時脈頻率的乘積。其倒數是 CPI。

日文名稱: IPC

「IPC」出現在3領域的6道練習題中（CPU與架構, 效能評估與效能剖析, 規格書的閱讀方法等）。

這個名詞所屬的領域: CPU與架構

效能公式中的 IPC

程式執行時間等於指令數乘以每指令週期數（CPI），再除以時脈頻率。IPC（每週期指令數）是 CPI 的倒數，因此對同一個程式而言，效能與 IPC 乘以頻率成正比。3 GHz 核心的週期時間約為 0.33 ns，但兩顆 3 GHz 處理器的速度可能因 IPC 不同而相差甚遠。IPC 的比較只有在相同程式與相同指令集下才有意義，因為不同指令集完成相同工作所需的指令數並不相同。

提升 IPC 的因素

簡單的管線以每週期一條指令為目標。超純量核心每週期可發出多條彼此獨立的指令，近年的高效能設計寬度約為 6 到 10。亂序執行讓較早的指令等待時先執行後面獨立的指令，使這些執行單元保持忙碌；分支預測可避免管線清空；大型快取搭配預取則可隱藏記憶體延遲。寬度無法無限制擴大：相依性檢查邏輯大致隨發出寬度的平方成長，而實際程式可提供的指令層級平行度有限，因此實際達到的 IPC 會遠低於峰值寬度。

拖累 IPC 的因素

最大的損失來自停頓。末級快取未命中而需存取 DRAM 時，可能耗費數百個週期；分支預測錯誤會丟棄已進入深管線的工作；相依指令串則會讓執行序列化。寬核心上的 IPC 遠低於 1（例如 0.3）時，通常代表核心大部分時間都在等待記憶體；為提高區域性而重新安排資料、調整迴圈順序或以分塊方式提升快取重用，通常比任何編譯器選項都更有效。提高時脈頻率並不會縮短以奈秒計的記憶體延遲，因此受記憶體限制的程式碼，其 IPC 會隨頻率上升而下降。

量測 IPC

處理器內含效能監控單元（PMU），提供硬體計數器，可計算週期數、退役指令數、各級快取未命中、TLB 未命中以及分支預測錯誤。將退役指令數除以週期數即可直接得到 IPC。Linux perf 等工具可在程式執行時讀取這些計數器，將 IPC 與未命中率、預測錯誤率對照，就能看出時間是花在記憶體、分支還是運算上。由於現代 CPU 會隨負載與溫度不斷改變頻率，以週期數而非實際經過時間來計算，更能清楚看出微架構的效率。

練習IPC的題目

以效能計數器測量後，發現某程式的IPC（每個週期的指令數）非常低，為0.3，且最後一級快取的失誤很多。下列何者是最可能的狀況與對策的組合？

  1. A因等待記憶體，CPU停滯的時間很長。改變資料的排列方式或進行分塊（blocking），以有效利用快取
  2. B運算太快了。提高頻率
  3. C分支太少了。增加分支
查看答案與解析

正確答案：A. 因等待記憶體，CPU停滯的時間很長。改變資料的排列方式或進行分塊（blocking），以有效利用快取

現今的CPU每個週期可執行數個指令，所以IPC為0.3表示大部分時間都在等待某些東西。若最後一級快取的失誤很多，就可以認為是在長時間等待來自主記憶體的資料。將資料排在連續的位址、改變迴圈的順序、藉由分塊重複使用同樣的資料等，來減少快取失誤是有效的。

常見問題

時脈較高和 IPC 較高，哪個比較好？

效能取決於兩者的乘積，因此單看任何一項都無法決定速度。在同一個程式上，時脈較低但 IPC 高出許多的核心，可能勝過時脈較高的核心。

如何量測自己程式的 IPC？

使用硬體效能計數器（例如透過 Linux perf）計算退役指令數與週期數；IPC 就是指令數除以週期數。再參考快取未命中與分支預測錯誤的次數，即可解釋 IPC 偏低的原因。

IPC 偏低代表什麼？

代表核心有許多週期處於閒置，最常見的原因是快取未命中後等待記憶體的資料，或是從分支預測錯誤與長相依鏈中恢復。
