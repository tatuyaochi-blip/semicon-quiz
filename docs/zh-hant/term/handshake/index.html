什麼是交握(Handshake)

透過交換發送端的請求(req)與接收端的回應(ack)，確實傳遞資料的方式。在時脈域之間只同步 req 與 ack，期間資料保持不變，因此安全，但每次傳輸需要數個週期以上。

日文名稱: ハンドシェイク

「交握(Handshake)」出現在3領域的8道練習題中（時序分析與CDC, 介面與匯流排規格, 邏輯電路等）。

這個名詞所屬的領域: 時序分析與CDC

四相交握的順序

在四相（歸零式）交握中，發送端先將資料放到匯流排上並保持，接著拉高 req。接收端看到同步後的 req，擷取資料並拉高 ack。發送端看到同步後的 ack 後拉低 req，接收端看到 req 下降後再拉低 ack。每個訊號各上升、下降一次，每次傳輸共四次轉態。關鍵規則在於順序：資料必須在 req 上升之前就已穩定，並且在 ack 確認擷取之前不得改變，否則接收端可能抓到正在轉態中的值。

為什麼跨時脈域也安全

只有 req 和 ack 會在時脈域之間傳遞，而且各自都是單一位元，經過一般的雙正反器同步器即可。多位元資料從不經過同步；當接收端看到 req 時，資料已經穩定了好幾個週期，可以直接擷取。這消除了逐位元同步匯流排時會出問題的位元偏移，適用於任何頻率比，而且由於發送端會等待確認，事件永遠不會遺失。這種等待正是它與翻轉同步（toggle synchronization）的區別，後者要求事件之間必須保證有最小間隔。

代價是延遲

每次轉態都必須經過同步器，通常單向各需 2 個週期，而四相訊號需要兩次來回，因此一次傳輸在兩個時脈域合計要花 8 個以上週期。兩相變體將 req 或 ack 的每次翻轉視為一個事件，轉態次數減半，代價是需要邊緣偵測邏輯。無論哪一種，吞吐量都遠低於每週期一個字組，因此交握適合像寫入控制暫存器這類偶發性傳輸，串流資料則走非同步 FIFO。

單一時脈內的交握：VALID/READY

同樣的請求–回應概念也出現在同步匯流排中，只是不需要同步器。在 AXI 中，每個通道都使用發送端的 VALID 與接收端的 READY，在兩者皆為 1 的任何時脈邊緣上完成傳輸。將 READY 保持為低即可施加反壓（backpressure），讓速度不同的區塊能夠連接而不遺失資料。為避免死結，發送端不得等待 READY 之後才拉高 VALID。AXI 有讀取位址、讀取資料、寫入位址、寫入資料與寫入回應五個獨立通道；AXI4-Stream 則省略位址，用於單向資料流。

練習交握(Handshake)的題目

在使用req與ack的4相交握中，傳遞1筆資料時訊號的順序何者正確？

  1. A將req設為1的同時開始改變資料 → 接收端將ack設為1 → 將req與ack同時設為0
  2. B接收端先將ack設為1 → 發送端確定資料並將req設為1 → 接收端取入資料 → 將req與ack同時設為0
  3. C確定資料並將req設為1 → 接收端取入資料並將ack設為1 → 將req設為0 → 將ack設為0
查看答案與解析

正確答案：C. 確定資料並將req設為1 → 接收端取入資料並將ack設為1 → 將req設為0 → 將ack設為0

在4相交握中，req與ack各上升、下降1次，共4次變化完成1次傳遞。發送端確定資料後拉高req，接收端看到同步化後的req就取入資料並拉高ack。發送端看到同步化後的ack就拉低req，接收端看到req下降後拉低ack。req與ack都是1位元，因此可用2級同步器安全傳遞。若一邊改變資料一邊拉高req，接收端可能取入變化中的值。

以交握進行時脈域間資料傳輸的缺點，何者正確？

  1. Areq與ack的同步化需要往返，1次傳輸需花費許多週期，不適合連續大量傳輸
  2. B傳遞多位元資料時，各位元同步化的錯開會使資料損壞
  3. C發送端與接收端的時脈頻率不相同就無法使用
查看答案與解析

正確答案：A. req與ack的同步化需要往返，1次傳輸需花費許多週期，不適合連續大量傳輸

在4相交握中，req傳到接收端需要同步化的2個週期，ack傳回發送端需要2個週期，各自回到0也需要同樣的時間，因此1次傳輸在兩個時脈域合計需要8個週期以上。所以適合用於如控制暫存器設定值這類偶爾才傳遞的資料。資料在傳輸期間一直保持穩定，因此不會發生位元錯開造成的錯誤，也不受頻率比限制。若要幾乎每個週期都傳送資料，則使用非同步FIFO。

常見問題

兩相交握和四相交握有什麼差別？

在四相訊號中，req 與 ack 各自上升後再歸零，因此一次傳輸使用四次轉態。在兩相訊號中，每次翻轉都是一個事件，一次傳輸只需兩次轉態，延遲大約減半，但需要邊緣偵測。

AXI 的 VALID/READY 交握需要同步器嗎？

不需要，VALID/READY 在單一時脈域內運作，在兩者皆為高的任何邊緣上完成傳輸。當 AXI 流量必須跨時脈域時，會插入非同步橋接器，通常由非同步 FIFO 構成。

為什麼 req/ack 交握用於跨時脈域會很慢？

每次 req 和 ack 轉態都要經過多週期的同步器，而且發送端必須等待回應，因此一次完整傳輸需要 8 個以上週期。對偶發性資料而言可以接受，但不適合連續資料流。
