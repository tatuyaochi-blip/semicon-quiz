什麼是佇列

最先放入的元素最先取出的先進先出（FIFO）資料結構。放入尾端的操作稱為 enqueue，從前端取出的操作稱為 dequeue。用於等待處理的隊列、工作之間的資料傳遞、廣度優先搜尋等。

日文名稱: キュー

「佇列」出現在11領域的17道練習題中（資料結構與演算法, 嵌入式與韌體, 網路設計與維運等）。

練習佇列的題目

對空的佇列依序放入 A、B、C，取出1個，放入 D 後取出1個，再放入 E 後取出1個。依序排列取出的元素，下列何者正確？

  1. AA, B, C
  2. BC, D, E
  3. CC, B, A
查看答案與解析

正確答案：A. A, B, C

佇列是依先放入的順序取出的先進先出（FIFO）結構。放入 A、B、C 後第一次取出的是 A。之後即使在尾端加入 D 或 E，位於前端的 B、C 也會先取出，因此取出順序為 A、B、C，最後留下 D 與 E。C、D、E 是當作每次取出最後放入者的堆疊（LIFO）時的順序。佇列用於印表機的列印等待、在工作之間傳遞資料的訊息佇列、廣度優先搜尋等。

以條件變數（condition variable）「等到佇列不為空」時，被喚醒後之所以用while敘述而非if敘述重新確認條件，其理由下列何者正確？

  1. A因為while敘述比if敘述執行得更快
  2. B因為規定if敘述不能使用條件變數
  3. C因為即使被喚醒，也可能被其他執行緒搶先取走，或無緣無故醒來，導致條件並未滿足
查看答案與解析

正確答案：C. 因為即使被喚醒，也可能被其他執行緒搶先取走，或無緣無故醒來，導致條件並未滿足

條件變數的等待，是先放開鎖並休眠，收到通知醒來後再重新取得鎖才返回。然而在醒來之前，其他執行緒可能先取得鎖並取走佇列的元素。此外，因實作上的考量，也允許在沒有通知的情況下醒來（虛假喚醒，spurious wakeup）。因此，醒來後要確認條件，若不滿足就再次等待，所以要寫成while敘述。
