什麼是硬體木馬（Hardware Trojan）

在設計或製造途中被惡意植入、會洩漏資訊或使動作停止的不正當電路。僅在罕見條件下才動作，所以難以發現。

日文名稱: ハードウェアトロイ

「硬體木馬（Hardware Trojan）」出現在1領域的3道練習題中（硬體安全等）。

這個名詞所屬的領域: 硬體安全

觸發條件與酬載

硬體木馬通常分成兩部分來描述。觸發條件是使其啟動的條件，例如罕見的 32 位元輸入值、特定的指令序列，或計數器達到數十億個週期。酬載則是啟動後發生的事：透過輸出接腳或功耗等旁通道洩漏密鑰、破壞運算結果，或讓晶片失效。有些木馬完全沒有觸發條件，會以難以察覺的方式持續洩漏資訊。

可能在哪裡被植入

現代晶片會經過許多組織之手：第三方 IP 供應商、EDA 工具、設計承包商、外部晶圓代工廠，以及封裝與測試廠。惡意邏輯可能在 RTL 中、在合成或佈局期間、透過修改光罩被加入，或如研究所示，在不增加可見邏輯閘的情況下微妙地改變電晶體的摻雜。由於這種變更在物理上是電路的一部分，出貨後無法以軟體更新修補或移除，因此預防遠比修復重要。

為什麼一般測試會漏掉它

量產測試檢查的是規格中的功能能否運作、是否沒有結構性缺陷；它不會去搜尋額外的行為。以功能測試與隨機測試圖樣幾乎不會產生的條件建構的觸發器會保持休眠，因此晶片看起來很正常。木馬可能只需要數十億個電晶體中的少數幾個，因此它對面積、功耗與延遲的影響可能隱藏在正常的製程變異中，使目視檢查與旁通道偵測都變得困難。

貫穿整個流程的對策

防禦分散在整個設計與製造鏈：使用可信任的工具、IP 與晶圓代工廠；控管並獨立審查設計資料的變更；在設計階段之間進行形式等價性檢查；將樣品晶片逐層剝除，並將各層影像與佈局比對；將功耗、延遲或電磁特徵與已知良品晶片比較；以及分割製造，使任何單一晶圓廠都看不到完整設計。晶片上的監視器還能在執行時偵測異常行為。

正確答案：A. 在設計或製造過程中被惡意植入、會洩漏資訊或使運作停止的不正當電路

現今的晶片多半是組合許多公司的IP來設計，再交由其他公司的工廠製造，牽涉的公司與人員眾多。在這過程中，恐怕會被加入在特定條件下將金鑰洩漏到外部，或在特定日期時間使運作停止之類的不正當電路。這稱為硬體木馬。製造後無法藉由軟體更新移除，因此需要在整個設計與製造流程中採取對策。

  2. B因為硬體木馬會弄壞測試裝置
  3. C因為它被設計成只有在極罕見的輸入或條件（觸發條件）下才會動作，平常的行為與正常電路相同

正確答案：C. 因為它被設計成只有在極罕見的輸入或條件（觸發條件）下才會動作，平常的行為與正常電路相同

製造測試是確認依設計的功能是否正確運作。硬體木馬被設計成只有在輸入特定的32位元值、某個計數器達到數十億次等，測試中幾乎不會發生的條件下才會動作，所以平常看起來正常。而且電路規模相對於整體數十億個電晶體只需極少，因此以目視發現也很困難。

常見問題

硬體木馬可以用韌體更新移除嗎？

不行。它是實體電路的一部分，軟體無法刪除它；韌體頂多只能避開或監視已知的觸發條件。對策必須在設計與製造階段實施。

為什麼硬體木馬很難被偵測？

它們只在測試不會產生的極罕見條件下啟動，而且相對於晶片其餘部分可能非常微小，因此對功耗與時序的影響會混在正常變異中。

硬體木馬和仿冒晶片有什麼不同？

仿冒晶片是以真品名義販售的假貨、回收品或重新標記的零件，通常是可靠度風險。硬體木馬則是在設計內部蓄意加入的惡意功能；兩者都是供應鏈威脅。
