雲端與容器基礎

FROM alpine
COPY data.tar.gz /tmp/
RUN tar -xzf /tmp/data.tar.gz -C /opt && rm /tmp/data.tar.gz

為了解開500 MB的封存檔 data.tar.gz，以上面的 Dockerfile 建置映像檔。雖然解開後在同一個 RUN 中刪除了封存檔，映像檔仍然大了一個封存檔的大小。原因與對策的組合，下列何者最適當？

  1. A&& 之後的 rm 在建置時不會執行。把 rm 寫成另一個 RUN 指令
  2. B刪除的檔案會作為建置快取留在映像檔中。在 docker build 加上 --no-cache 重新建置
  3. C封存檔留在 COPY 指令建立的層中。以多階段建置，只把解開後的檔案複製到最終映像檔
查看答案與解析

正確答案：C. 封存檔留在 COPY 指令建立的層中。以多階段建置，只把解開後的檔案複製到最終映像檔

Dockerfile 的指令中，會改變檔案系統的指令（COPY、RUN 等）各自成為1層，映像檔就是這些層的疊加。即使在後面的層刪除檔案，也只是在上層記錄一個已刪除的標記，進入 COPY 層的500 MB封存檔仍留在映像檔中。若以多階段建置在另一個階段解開，再用 COPY --from 只把解開後的檔案帶到最後階段，最終映像檔就不含封存檔。在1個 RUN 中完成下載、解開與刪除也是一種方法，但無法用於以 COPY 帶入的檔案。

  • A. && 之後的 rm 也會在同一個 RUN 中執行。分成另一個 RUN 只會多一層刪除標記，大小不會減少。
  • B. --no-cache 只是不重複使用先前建置的結果，層的內容相同，因此大小不變。
  • C. 正確。即使刪除，下層的內容仍會保留，所以要讓它不進入最終映像檔。
