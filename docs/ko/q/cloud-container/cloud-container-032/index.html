클라우드와 컨테이너의 기초

어떤 가상 머신은 사용한 시간만큼 지불하는 온디맨드로는 1시간당 50엔, 1년분의 이용을 미리 약정하는 예약으로는 사용한 시간과 관계없이 1년에 262,800엔이 든다(둘 다 가상의 가격). 1년을 8,760시간이라고 하면, 1년간의 이용 시간이 어떤 시간을 넘었을 때 예약 쪽이 저렴해진다. 그 시간으로 올바른 것은?

  1. A3,504시간(1년의 40%)
  2. B5,256시간(1년의 60%)
  3. C8,760시간(1년의 100%)
정답과 해설 보기

정답: B. 5,256시간(1년의 60%)

예약 요금은 이용 시간과 관계없이 262,800엔이고 온디맨드 요금은 50엔 × 이용 시간이므로, 둘이 같아지는 것은 262,800 ÷ 50 = 5,256시간입니다. 이는 5,256 ÷ 8,760 = 60%에 해당하며, 1년의 60%보다 길게 사용한다면 예약 쪽이 저렴해집니다. 예약을 1시간당으로 환산하면 262,800 ÷ 8,760 = 30엔으로, 온디맨드보다 40% 저렴한 셈입니다. 항상 가동하는 서버는 예약, 부하에 맞추어 늘리는 분량은 온디맨드처럼 나누어 쓰는 경우가 많습니다.

클라우드와 컨테이너의 기초의 다른 문제

  1. 많은 퍼블릭 클라우드의 데이터 전송 요금의 사고방식으로 일반적으로 들어맞는 것은?
  2. 선언적인 IaC(Infrastructure as Code) 도구로, 네트워크와 가상 머신 2대의 구성을 정의한 파일을 적용하여 환경을 만들었다. 그 직후에 아무것도 바꾸지 않고 같은 파일을 한 번 더 적용했을 때 일어나는 일로 적절한 것은?
  3. 이뮤터블 인프라스트럭처의 사고방식에 따른, 운영 서버의 소프트웨어 업데이트 방법으로 적절한 것은?
  4. 운영 환경과 같은 구성의 환경을 두 개 준비하여, 한쪽에서 현재 버전을 실행한 채로 다른 쪽에 새 버전을 넣어 확인한 다음, 로드 밸런서가 향하는 곳을 한 번에 전환한다. 문제가 있으면 향하는 곳을 되돌려 즉시 원래 버전으로 돌아간다. 이 릴리스 방법은?
  5. 1시간에 12,000건의 요청을 받는 서비스에서 새 버전을 카나리 릴리스하여, 요청의 5%만 새 버전으로 보냈다. 새 버전에는 받은 요청의 3%가 실패하는 결함이 있었고, 1시간 뒤에 알아차려 모든 요청을 원래 버전으로 되돌렸다. 이 1시간 동안 결함으로 실패한 요청의 건수로 올바른 것은?
