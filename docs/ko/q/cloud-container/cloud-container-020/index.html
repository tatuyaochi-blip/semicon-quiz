클라우드와 컨테이너의 기초

Kubernetes의 Secret에 데이터베이스의 비밀번호를 저장한다. Secret의 설명으로 올바른 것은?

  1. ASecret에 넣은 값은 자동으로 강력한 암호로 암호화되므로, 클러스터 안의 누가 읽어 내도 원래 비밀번호는 알 수 없다
  2. BSecret의 값은 컨테이너에서 참조할 수 없으므로, 비밀번호는 이미지 안의 설정 파일에 써 두어야 한다
  3. C값은 기본적으로 Base64로 표현되어 있을 뿐 암호화가 아니므로, 읽을 수 있는 이용자의 제한이나 저장할 때의 암호화를 함께 사용한다
정답과 해설 보기

정답: C. 값은 기본적으로 Base64로 표현되어 있을 뿐 암호화가 아니므로, 읽을 수 있는 이용자의 제한이나 저장할 때의 암호화를 함께 사용한다

Secret은 비밀번호나 API 키 같은 기밀 값을 이미지나 Pod의 정의와 분리하여 관리하고, 환경 변수나 파일로 컨테이너에 전달하기 위한 리소스입니다. 다만 매니페스트에 쓰는 값은 Base64로 표현했을 뿐이어서 누구나 원래대로 되돌릴 수 있습니다. 또한 기본적으로는 클러스터의 정보를 저장하는 etcd에 암호화되지 않은 채 저장됩니다. 따라서 RBAC로 Secret을 읽을 수 있는 이용자를 좁히고, etcd에 저장할 때의 암호화를 활성화하는 등의 대책을 함께 시행합니다.

클라우드와 컨테이너의 기초의 다른 문제

  1. 어떤 웹 애플리케이션은 시작한 뒤 캐시를 읽어 들일 때까지의 약 60초 동안은 요청을 처리할 수 없고, 그동안은 /ready에 503을 반환한다. Pod의 컨테이너에 위의 설정을 추가했을 때의 효과로 올바른 것은?
  2. Kubernetes의 웹 애플리케이션에서, liveness 프로브의 확인 처리 안에서 의존 대상인 데이터베이스에 접속할 수 있는지까지 조사하도록 했다. 이 설정으로 일어날 수 있는 문제로 가장 적절한 것은?
  3. Kubernetes의 HorizontalPodAutoscaler에서 Pod의 CPU 사용률 목표를 70%, Pod 수의 범위를 1~10으로 했다. 현재 5개 Pod의 평균 CPU 사용률이 30%이다. 필요한 Pod의 수를 ⌈현재 수 × 현재 사용률 ÷ 목표 사용률⌉(⌈ ⌉은 올림)로 구할 때, 필요한 Pod의 수로 올바른 것은?
  4. Pod의 컨테이너에 위의 설정을 한 Deployment에서 Pod가 4개 동작하고 있으며, 모든 Pod가 CPU를 400m(0.4코어)씩 사용하고 있다. HorizontalPodAutoscaler의 CPU 사용률 목표를 60%로 하고, 필요한 Pod의 수는 ⌈현재 수 × 현재 사용률 ÷ 목표 사용률⌉로 구한다고 하자. 필요한 Pod의 수로 올바른 것은?
  5. Kubernetes에서 컨테이너에 설정하는 자원의 requests와 limits의 설명으로 올바른 것은?
