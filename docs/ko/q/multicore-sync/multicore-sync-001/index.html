멀티코어와 동기화

두 개의 코어가 각자의 캐시에 변수 x의 사본을 가지고 있다. 코어 0이 x에 쓴 뒤 코어 1이 x를 읽을 때, 캐시 일관성 메커니즘이 없다면 일어날 수 있는 문제는 무엇입니까?

  1. A코어 1이 자신의 캐시에 남아 있는 오래된 값을 읽어 버린다
  2. B코어 1의 읽기가 코어 0의 쓰기보다 반드시 빨라진다
  3. Cx의 값이 2배로 읽힌다
정답과 해설 보기

정답: A. 코어 1이 자신의 캐시에 남아 있는 오래된 값을 읽어 버린다

멀티코어 CPU에서는 코어마다 있는 캐시에 같은 주소의 데이터 사본이 만들어집니다. 코어 0이 자신의 캐시 안에서만 x를 갱신하면 코어 1의 캐시에는 오래된 값이 남아 있어, 코어 1은 그것을 읽게 됩니다. 캐시 일관성(코히런시) 메커니즘은 쓰기 시에 다른 코어의 사본을 무효화하는 등의 방법으로, 어느 코어에서 읽어도 최신 값이 보이도록 합니다.

멀티코어와 동기화의 다른 문제

  1. 캐시 코히런시 프로토콜인 MESI의 네 가지 상태의 조합으로 올바른 것은 무엇입니까?
  2. MESI 프로토콜에서 캐시 라인이 Modified(M) 상태일 때의 의미로 올바른 것은 무엇입니까?
  3. MESI 프로토콜에서 Exclusive(E) 상태의 라인에 해당 코어가 쓸 때의 동작으로 올바른 것은 무엇입니까?
  4. 무효화형 코히런시 프로토콜에서 어떤 코어가 Shared(S) 상태의 라인에 쓸 때 수행되는 것은 무엇입니까?
  5. MESI 프로토콜에서 코어 0이 Modified(M) 상태로 가진 라인을 코어 1이 읽으려 할 때의 일반적인 동작은 무엇입니까?

이 분야의 비교

  • 뮤텍스 vs 세마포어: 차이점 설명뮤텍스와 세마포어를 표로 비교합니다: 목적, 값, 소유권, 연산, 시그널링, 우선순위 역전, 주요 용도, 흔한 함정.
  • MSI, MESI, MOESI 프로토콜의 차이점 정리캐시 일관성 프로토콜 MSI, MESI, MOESI를 표로 비교합니다. 상태 수와 의미, Exclusive·Owned 상태의 이점, 메모리 라이트백, 회로 복잡도를 안내합니다.
  • 스핀락과 뮤텍스의 차이점 정리스핀락과 뮤텍스를 표로 비교합니다. 대기 방식(바쁜 대기와 슬립), CPU 사용, 적합한 보유 시간, 커널 안에서의 사용, 우선순위 역전, futex를 안내합니다.
