멀티코어와 동기화

CAS를 사용한 락프리 자료 구조에서 문제가 되는 ABA 문제에 대한 설명으로 올바른 것은 무엇입니까?

  1. AA와 B 두 스레드가 번갈아서만 실행될 수 있게 되는 것
  2. B값이 A에서 B로 바뀌었다가 다시 A로 돌아왔을 때, CAS가 변화를 알아차리지 못하고 성공해 버리는 것
  3. CA와 B 두 락을 반대 순서로 획득해 버리는 것
정답과 해설 보기

정답: B. 값이 A에서 B로 바뀌었다가 다시 A로 돌아왔을 때, CAS가 변화를 알아차리지 못하고 성공해 버리는 것

연결 리스트의 선두 포인터가 A일 때, 어떤 스레드가 A를 읽고 CAS를 준비하는 사이에 다른 스레드가 A를 제거하고 B에 대한 조작을 한 뒤, 다시 같은 주소 A의 노드를 넣는 경우가 있습니다. CAS는 값이 A 그대로이므로 성공하지만 리스트의 내용은 이미 바뀌어 있어 구조가 망가집니다. 포인터에 갱신 횟수를 붙여 함께 비교하는 방법이나 LR/SC를 사용하는 방법으로 방지합니다.

멀티코어와 동기화의 다른 문제

  1. RISC-V의 amoadd.w 명령이나 x86의 lock xadd 명령과 같은 fetch-and-add 명령의 동작으로 올바른 것은 무엇입니까?
  2. 스핀락에 대한 설명으로 올바른 것은 무엇입니까?
  3. 스핀락이 적합하지 않은 상황으로 가장 적절한 것은 무엇입니까?
  4. 스핀락에서 락 변수를 곧바로 원자적 명령으로 갱신하려 하지 않고, 평소에는 일반 읽기로 풀리기를 기다리다가 풀린 것으로 보일 때만 원자적 명령을 사용하는(test-and-test-and-set) 이유로 올바른 것은 무엇입니까?
  5. 뮤텍스(재워서 기다리는 락)와 스핀락을 비교한 설명으로 올바른 것은 무엇입니까?
