HDL과 검증

위 기술에서 sel이 X(불정)일 때 Verilog 시뮬레이션에서는 y에 b가 선택된다. 이 성질이 검증에서 문제가 되는 이유로 올바른 것은?

always @(*)
    if (sel) y = a;
    else     y = b;
  1. Ay가 반드시 X가 되어 시뮬레이션이 멈추기 때문
  2. Bsel이 X일 때는 실제 칩에서도 반드시 b가 선택되기 때문
  3. CX가 '거짓'으로 취급되어 b라는 확정된 값이 나오므로, sel이 불정이라는 오류가 시뮬레이션에서 보이지 않게 되기 때문
정답과 해설 보기

정답: C. X가 '거짓'으로 취급되어 b라는 확정된 값이 나오므로, sel이 불정이라는 오류가 시뮬레이션에서 보이지 않게 되기 때문

Verilog의 if문은 조건이 X일 때 거짓으로 취급하고 else 쪽을 실행합니다. 그래서 y에는 b라는 확정된 값이 나오고, sel이 불정이라는 오류가 시뮬레이션에서 가려집니다. 실제 회로에서 sel은 0이나 1 중 하나이며 a가 선택될 수도 있습니다. 이를 X 낙관주의(X-optimism)라고 하며, X를 전파하도록 기술하거나 X를 검출하는 어서션을 넣는 등으로 대처합니다.

HDL과 검증의 다른 문제

  1. HDL에서 Z(하이 임피던스)를 출력하는 트라이스테이트 기술에 대해 일반적으로 올바른 것은?
  2. HDL 검증에서 사용하는 테스트벤치에 대한 설명으로 올바른 것은?
  3. 테스트벤치의 위 기술로 만들어지는 클럭의 주기는 얼마입니까?(시간 단위는 1 ns로 한다)
  4. 테스트벤치에서 회로에 대한 입력을 클럭 상승과 같은 시각에 블로킹 대입으로 바꾸면 문제가 생길 수 있다. 주된 이유와 대책의 조합으로 올바른 것은?
  5. 자체 검사형(self-checking) 테스트벤치의 특징으로 올바른 것은?

이 분야의 비교

  • Verilog와 VHDL: 두 HDL의 차이점Verilog와 VHDL을 표로 비교합니다. 기원, 문법, 타입 체계, 대소문자 구분, 검증 기능, 사용층, 선택 방법을 다룹니다.
  • 블로킹 할당 vs 논블로킹 할당: 평가 타이밍·순서·사용 위치 비교Verilog의 블로킹 할당(=)과 논블로킹 할당(<=)을 표로 비교합니다: 좌변을 갱신하는 타이밍, 기술 순서에 대한 의존성, 사용 위치(조합 회로와 순차 회로), 시뮬레이션과 합성의 불일치.
  • 동기 리셋 vs 비동기 리셋: 타이밍·클럭·해제 시 주의점 비교동기 리셋과 비동기 리셋을 표로 비교합니다: 적용되는 타이밍, 클럭 필요 여부, 글리치에 대한 강도, 타이밍 분석, 리셋 해제 시 동기화, 면적, Verilog 작성법. 각각에 적합한 회로도 설명…
