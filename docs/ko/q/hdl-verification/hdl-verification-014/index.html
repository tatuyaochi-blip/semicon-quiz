HDL과 검증

조합 회로의 always 블록에서 의도하지 않은 래치를 방지하기 위해 자주 사용되는 작성 방식은?

  1. A조건 분기를 가능한 한 많이 쓰고 else는 생략한다
  2. B블록 맨 앞에서 출력의 모든 신호에 기본값을 대입한 뒤 조건 분기를 작성한다
  3. C출력 신호를 모두 wire로 하고 always 안에서 대입한다
정답과 해설 보기

정답: B. 블록 맨 앞에서 출력의 모든 신호에 기본값을 대입한 뒤 조건 분기를 작성한다

블록 맨 앞에서 'y = 0; valid = 0;'처럼 출력에 기본값을 넣어 두면, 이후 조건 분기에서 어떤 경로를 지나도 최소한 기본값이 대입되어 있으므로 값을 유지할 필요가 없어져 래치가 만들어지지 않습니다. 조건이 많은 상태 머신의 출력 기술 등에서 특히 유용합니다. SystemVerilog의 always_comb를 사용하면 래치가 만들어졌을 때 툴이 경고를 출력해 줍니다.

  3. 위 기술의 리셋 종류와 동작으로 올바른 것은?
  4. 동기 리셋과 비동기 리셋의 차이로 올바른 것은?
  5. 비동기 리셋을 사용하는 회로에서 리셋 해제(0에서 1로의 변화)를 2단 플립플롭으로 클럭에 동기시킨 뒤 각 회로에 분배하는 이유로 올바른 것은?

이 분야의 비교

  • Verilog와 VHDL: 두 HDL의 차이점Verilog와 VHDL을 표로 비교합니다. 기원, 문법, 타입 체계, 대소문자 구분, 검증 기능, 사용층, 선택 방법을 다룹니다.
  • 블로킹 할당 vs 논블로킹 할당: 평가 타이밍·순서·사용 위치 비교Verilog의 블로킹 할당(=)과 논블로킹 할당(<=)을 표로 비교합니다: 좌변을 갱신하는 타이밍, 기술 순서에 대한 의존성, 사용 위치(조합 회로와 순차 회로), 시뮬레이션과 합성의 불일치.
  • 동기 리셋 vs 비동기 리셋: 타이밍·클럭·해제 시 주의점 비교동기 리셋과 비동기 리셋을 표로 비교합니다: 적용되는 타이밍, 클럭 필요 여부, 글리치에 대한 강도, 타이밍 분석, 리셋 해제 시 동기화, 면적, Verilog 작성법. 각각에 적합한 회로도 설명…
