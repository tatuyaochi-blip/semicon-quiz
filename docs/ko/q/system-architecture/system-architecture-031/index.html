시스템 구성과 신뢰성 설계

부하에 따라 서버 대수를 자동으로 늘리고 줄이는 오토 스케일링을 사용하는 시스템의 설계로 일반적으로 바람직한 것은?

  1. A각 서버의 로컬 디스크에 그 서버만 가지는 업무 데이터를 저장해 둔다
  2. B이용자의 세션 정보를 각 서버의 메모리가 아니라 공유 데이터 스토어에 저장하여, 어느 서버가 요청을 처리해도 같은 결과가 되게 한다
  3. C대수를 줄일 때는 처리 중인 요청이 있어도 즉시 서버를 정지한다
정답과 해설 보기

정답: B. 이용자의 세션 정보를 각 서버의 메모리가 아니라 공유 데이터 스토어에 저장하여, 어느 서버가 요청을 처리해도 같은 결과가 되게 한다

오토 스케일링에서는 서버가 언제 추가되거나 삭제되어도 문제가 없도록, 각 서버에 고유한 상태를 갖게 하지 않는(스테이트리스로 하는) 설계가 바람직합니다. 세션 정보나 업무 데이터를 공유 데이터 스토어에 두면 어느 서버가 요청을 받아도 똑같이 처리할 수 있고, 대수를 줄여도 데이터는 사라지지 않습니다. 대수를 줄일 때는 새 요청의 분배를 멈추고, 처리 중인 요청이 끝나기를 기다린 후에 정지합니다.

시스템 구성과 신뢰성 설계의 다른 문제

  2. CDN(콘텐츠 전송 네트워크)에 대한 설명으로 적절한 것은?
  3. 반도체 공장에서 다수의 제조 장비로부터 높은 빈도로 모이는 센서 데이터를 사용하여 이상을 즉시 감지하고 싶다. 데이터를 모두 먼 클라우드로 보내 처리하는 것이 아니라, 장비 가까이에 둔 컴퓨터로 처리하는 엣지 컴퓨팅을 사용하는 주된 이점으로 적절한 것은?
  4. 스토리지 접속 방식 중 SAN(스토리지 영역 네트워크)에 대한 설명으로 적절한 것은?
  5. 물리 용량이 100 TB인 스토리지 풀에서 씬 프로비저닝으로 논리 용량 5 TB의 볼륨을 30개 만들었다. 현재 각 볼륨에는 평균하여 논리 용량의 40%의 데이터가 기록되어 있고, 데이터는 매주 합계 2 TB씩 늘고 있다. 데이터의 삭제나 압축은 고려하지 않을 때, 풀의 사용률이 80%에 도달하는 시기로 올바른 것은?
