하드웨어 보안

캐시 사이드 채널에 대한 대책으로, 공유 캐시를 분할(파티셔닝)하는 개념으로 올바른 것은 무엇입니까?

  1. A캐시를 물리적으로 둘로 쪼개어 버린다
  2. B캐시 용량을 2배로 한다
  3. C프로세스나 가상 머신별로 사용할 수 있는 캐시 범위를 나누어 서로의 데이터를 밀어낼 수 없게 하고, 흔적을 관찰할 수 없게 한다
정답과 해설 보기

정답: C. 프로세스나 가상 머신별로 사용할 수 있는 캐시 범위를 나누어 서로의 데이터를 밀어낼 수 없게 하고, 흔적을 관찰할 수 없게 한다

캐시 사이드 채널은 공격자와 피해자가 같은 캐시 위치를 두고 다투는 것으로 성립합니다. 캐시의 일부 웨이(way)나 세트를 프로세스나 가상 머신별로 할당하여 나누면 서로의 데이터를 밀어낼 수 없게 되어, 상대의 접근 흔적을 관찰할 수 없게 됩니다. CPU에는 캐시 할당을 제어하는 기능을 가진 것이 있습니다. 다만 각자가 쓸 수 있는 용량이 줄어드므로 성능과의 절충이 됩니다.

하드웨어 보안의 다른 문제

  1. 기밀 처리를 하는 시스템에서 CPU의 동시 멀티스레딩(SMT)을 비활성화하는 경우가 있는 이유로 올바른 것은 무엇입니까?
  2. PC에 연결한 외부 기기가 DMA를 사용하여 메인 메모리 내용을 멋대로 읽고 쓰는 공격에 대한 대책으로 올바른 것은 무엇입니까?
  3. 하드웨어와 소프트웨어 보안에서 중시되는 '다층 방어'의 개념으로 올바른 것은 무엇입니까?
  4. 다수의 기기를 제조할 때 모든 기기에 같은 키를 넣지 않고 기기마다 다른 키를 갖게 하는 이유로 올바른 것은 무엇입니까?
  5. CPU의 하드웨어 취약점이 발견되었을 때 출하된 CPU에서 이루어지는 대책의 하나로 올바른 것은 무엇입니까?
