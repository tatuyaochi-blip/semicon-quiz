암호 기술의 기초와 응용

시스템 설계에서 암호 민첩성(암호 방식을 교체하기 쉽게 해 두는 성질)을 높이는 대처로 적절한 것은?

  1. A암호 알고리즘과 키 길이를 프로그램 안에 직접 써넣어 두고, 운용 중에 누구도 설정을 변경할 수 없게 해 둔다
  2. B사용하고 있는 암호 방식과 위치의 목록을 만들고, 알고리즘을 설정이나 프로토콜 협상으로 교체할 수 있게 해 둔다
  3. C새로운 암호 방식은 결함의 우려가 있으므로, 20년 이상 전부터 사용되어 온 방식만 계속 사용한다
정답과 해설 보기

정답: B. 사용하고 있는 암호 방식과 위치의 목록을 만들고, 알고리즘을 설정이나 프로토콜 협상으로 교체할 수 있게 해 둔다

암호 방식은 MD5나 SHA-1, 짧은 키의 RSA 암호처럼 공격의 발전으로 안전하지 않게 되는 경우가 있으며, 양자 내성 암호로의 이행도 그중 하나입니다. 방식이 프로그램 깊숙이 직접 쓰여 있으면 어디에서 사용하고 있는지를 찾는 것만으로도 수고가 들어, 교체에 오랜 세월이 걸립니다. 어디에서 어떤 암호를 사용하고 있는지의 목록(인벤토리)을 가지고, 알고리즘 식별자를 통신이나 데이터 형식에 포함하며, 설정으로 교체할 수 있게 해 둠으로써 이행을 빠르고 안전하게 진행할 수 있습니다.

암호 기술의 기초와 응용의 다른 문제

  2. 현재 널리 쓰이는 블록 암호 AES의 블록 길이와 키 길이의 조합으로 올바른 것은?
  3. 이미지 데이터를 AES의 ECB 모드로 암호화했더니, 암호화한 후의 이미지에서도 원래 그림의 윤곽을 알아볼 수 있었다. 이 원인으로 올바른 것은?
  4. AES를 CBC 모드로 사용할 때 초기화 벡터(IV)의 취급으로 적절한 것은?
  5. AES(블록 길이 16바이트)를 CBC 모드로 사용하고, 패딩에는 PKCS#7 방식을 사용한다. PKCS#7 방식에서는 부족한 바이트 수를 n이라 할 때 값이 n인 바이트를 n개 덧붙이며, 평문의 길이가 정확히 16의 배수일 때도 값이 16인 바이트를 16개 덧붙인다. 96바이트의 평문을 암호화했을 때 암호문의 길이(IV는 포함하지 않음)는?
