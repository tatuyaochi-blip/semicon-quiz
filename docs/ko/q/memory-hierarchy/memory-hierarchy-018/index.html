메모리 계층 구조

행렬 곱 등에서 사용되는 루프 블로킹(타일링)의 주된 목적은?

  1. A캐시에 들어가는 작은 블록 단위로 계산하여 데이터의 재사용을 늘리기 위해
  2. B루프 횟수를 줄여 루프 끝에서 실행하는 분기 명령의 수를 줄이기 위해
  3. C계산 순서를 바꾸지 않고 사용하는 메모리 총량을 절반으로 하기 위해
정답과 해설 보기

정답: A. 캐시에 들어가는 작은 블록 단위로 계산하여 데이터의 재사용을 늘리기 위해

큰 행렬의 곱을 그대로 계산하면 한 번 읽어 온 요소가 다시 사용되기 전에 캐시에서 쫓겨나 주기억장치에서 여러 번 다시 읽게 됩니다. 루프 블로킹에서는 행렬을 캐시에 들어가는 작은 블록으로 나누어 블록 안에서 계산을 마치므로, 읽어 온 데이터를 여러 번 재사용하여 용량 미스를 크게 줄입니다. 분기 명령을 줄이는 것은 루프 언롤링의 목적이며, 사용하는 메모리 총량은 변하지 않습니다.

관련 계산 도구

캐시 주소 분할과 평균 메모리 접근 시간캐시 크기, 라인 크기, 연관도로 태그·인덱스·오프셋 비트 수와 평균 메모리 접근 시간 계산메모리 대역폭 계산기전송 속도와 버스 폭으로 DDR, LPDDR, GDDR, HBM의 피크 및 실효 대역폭 계산

메모리 계층 구조의 다른 문제

  1. 위와 같이 x 좌표만 합산하는 처리를 배열의 구조체(각 성분을 별도의 배열로 만드는 형태)로 바꾸면 빨라지기 쉬운 이유는?
  2. 캐시를 명령용(I 캐시)과 데이터용(D 캐시)으로 나눈 L1 캐시의 주된 이점은?
  3. 페이지 크기 4 KB, 라인 크기 64바이트인 시스템에서 L1 캐시를 가상 인덱스·물리 태그(VIPT) 방식으로 하고, 인덱스와 오프셋을 페이지 내 비트만으로 구성하고 싶다. 8웨이 세트 어소시에이티브라면 캐시 용량은 최대 얼마까지 가능한가?
  4. L1 캐시에 가상 인덱스·물리 태그(VIPT) 방식이 자주 사용되는 주된 이유는?
  5. 캐시의 히트 시간이 2사이클, 미스율이 4%, 미스 페널티가 150사이클일 때, 평균 메모리 접근 시간은 몇 사이클인가?

이 분야의 비교

  • 라이트스루 vs 라이트백 캐시: 차이점 설명라이트스루와 라이트백 캐시를 표로 비교합니다: 쓰기 정책, 메모리 트래픽, 속도, 일관성, 복잡도, 축출 비용, 대표 용도.
  • 직접 사상 vs 세트 연관 vs 완전 연관 캐시직접 사상, 세트 연관, 완전 연관 캐시를 표로 비교합니다: 블록 배치 위치, 태그 비교, 속도, 비용, 충돌 미스, 용도.
  • L1, L2, L3 캐시의 차이점 정리L1, L2, L3 캐시를 일반적인 PC·서버 CPU를 예로 표로 비교합니다. 용량과 레이턴시, 코어별 또는 공유, 명령어와 데이터의 분리, 포함 관계, 설계에서 중시하는 점을 다룹니다.
