메모리 계층 구조

8웨이 세트 어소시에이티브 방식 캐시에서 한 번 접근할 때마다 병렬로 비교하는 태그의 수는 몇 개인가?

  1. A캐시 전체의 라인 수와 같은 수
  2. B8개
  3. C1개
정답과 해설 보기

정답: B. 8개

세트 어소시에이티브 방식에서는 먼저 주소의 인덱스로 하나의 세트를 선택하고, 그 세트에 있는 모든 웨이의 태그를 병렬로 비교합니다. 8웨이라면 한 세트에 8라인이 있으므로 비교하는 태그는 8개이고 그를 위한 비교기도 8개 필요합니다. 캐시 전체의 라인 수만큼 비교하는 것은 풀 어소시에이티브 방식, 1개만 비교하는 것은 다이렉트 매핑 방식입니다. 웨이를 늘리면 비교기와 소비 전력이 늘어나므로 L1의 연관도는 보수적으로 잡는 경우가 많습니다.

메모리 계층 구조의 다른 문제

  1. 라인 크기 64바이트, 세트 수 64인 캐시에서 주소 0x1234의 데이터가 들어가는 세트 번호는?
  2. 같은 라인에 여러 번 쓰는 처리에서 라이트 스루 방식보다 라이트 백 방식이 유리해지는 주된 이유는?
  3. 가장 오랫동안 사용되지 않은 것을 쫓아내는 LRU에 대해, 앞으로 가장 오랫동안 사용되지 않을 것을 쫓아내는 방식(최적 교체, OPT)에 대한 설명으로 올바른 것은?
  4. 캐시 용량을 크게 하면 일반적으로 히트 시간은 어떻게 되는가? 그 이유와 함께 올바른 것은?
  5. 위 연결 리스트를 따라가는 처리가 같은 수의 요소를 가진 배열을 차례로 읽는 것보다 크게 느려지기 쉬운 이유는?

이 분야의 비교

  • 라이트스루 vs 라이트백 캐시: 차이점 설명라이트스루와 라이트백 캐시를 표로 비교합니다: 쓰기 정책, 메모리 트래픽, 속도, 일관성, 복잡도, 축출 비용, 대표 용도.
  • 직접 사상 vs 세트 연관 vs 완전 연관 캐시직접 사상, 세트 연관, 완전 연관 캐시를 표로 비교합니다: 블록 배치 위치, 태그 비교, 속도, 비용, 충돌 미스, 용도.
  • L1, L2, L3 캐시의 차이점 정리L1, L2, L3 캐시를 일반적인 PC·서버 CPU를 예로 표로 비교합니다. 용량과 레이턴시, 코어별 또는 공유, 명령어와 데이터의 분리, 포함 관계, 설계에서 중시하는 점을 다룹니다.
