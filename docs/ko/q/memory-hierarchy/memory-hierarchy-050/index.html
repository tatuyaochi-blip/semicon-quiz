메모리 계층 구조

두 프로그램을 같은 코어에서 번갈아 실행하면 각각을 단독으로 실행하는 것보다 느려지는 경우가 있다. 캐시 관점에서 가장 적절한 설명은?

  1. A번갈아 실행하면 각각이 실행하는 명령 수 자체가 2배로 늘어나기 때문
  2. B번갈아 실행하면 캐시 용량이 절반으로 재설정되기 때문
  3. C상대의 데이터에 자신의 데이터가 쫓겨나 다시 읽는 일이 늘어나기 때문
정답과 해설 보기

정답: C. 상대의 데이터에 자신의 데이터가 쫓겨나 다시 읽는 일이 늘어나기 때문

프로그램을 전환하면 상대 프로그램이 사용한 데이터로 캐시와 TLB가 채워지고, 자신의 차례가 돌아왔을 때는 필요한 데이터가 쫓겨나 있습니다. 그래서 단독이라면 히트했을 접근에서 미스가 일어나 데이터를 주기억장치에서 다시 읽는 시간이 걸립니다. 전환 간격이 짧을수록 이 영향은 커집니다. 실행하는 명령 수는 변하지 않으며 캐시 용량이 재설정되는 것도 아닙니다. 캐시를 나누어 쓰는 영향 때문입니다.

  3. 주소가 32비트, 용량 32 KB, 라인 크기 64바이트인 다이렉트 매핑 방식 캐시에서 태그는 몇 비트인가?
  4. 주소가 32비트, 용량 32 KB, 라인 크기 64바이트인 4웨이 세트 어소시에이티브 방식 캐시의 세트 수는 얼마인가?
  5. 풀 어소시에이티브 방식 캐시에서 주소 중 인덱스(세트를 선택하는 부분)에 사용하는 비트 수는?

  • 라이트스루 vs 라이트백 캐시: 차이점 설명라이트스루와 라이트백 캐시를 표로 비교합니다: 쓰기 정책, 메모리 트래픽, 속도, 일관성, 복잡도, 축출 비용, 대표 용도.
