메모리 계층 구조

C 언어의 2차원 배열 a[i][j]를 위와 같이 안쪽 루프를 j로 하여 순회하면, 안쪽을 i로 하는 것보다 빨라지기 쉽다. 그 이유는?

for (i = 0; i < N; i++)
    for (j = 0; j < N; j++)
        sum += a[i][j];
  1. A행 우선으로 저장되어 있어 연속된 주소를 차례로 읽으므로 캐시 라인을 효과적으로 사용할 수 있기 때문
  2. B컴파일러가 루프 안의 덧셈을 한데 모아 제거하여 계산 자체를 실행 시에 생략해 버리기 때문
  3. C안쪽을 j로 하면 TLB를 전혀 참조하지 않게 되어 가상 주소에서 물리 주소로의 변환이 필요 없어지기 때문
정답과 해설 보기

정답: A. 행 우선으로 저장되어 있어 연속된 주소를 차례로 읽으므로 캐시 라인을 효과적으로 사용할 수 있기 때문

C 언어의 2차원 배열은 행 우선(row-major)으로 저장되어 a[i][0], a[i][1]…이 메모리 상에서 이웃합니다. 안쪽을 j로 하면 연속된 주소를 차례로 읽으므로, 한 번의 미스로 읽어 온 64바이트 캐시 라인의 나머지 부분도 곧바로 사용됩니다. 안쪽을 i로 하면 한 행 크기만큼 떨어진 주소를 띄엄띄엄 읽게 되어 라인의 극히 일부만 사용한 채 쫓겨나기 쉽습니다. TLB는 계속 사용되며 주소 변환이 불필요해지는 것은 아닙니다.

  2. 주소가 32비트, 용량 32 KB, 라인 크기 64바이트인 4웨이 세트 어소시에이티브 방식 캐시의 세트 수는 얼마인가?
  3. 풀 어소시에이티브 방식 캐시에서 주소 중 인덱스(세트를 선택하는 부분)에 사용하는 비트 수는?
  4. L1 캐시의 히트 시간이 1 ns, 미스율이 5%, L2 캐시의 히트 시간이 10 ns, L2의 로컬 미스율이 20%, 주기억장치의 접근 시간이 100 ns일 때, 평균 메모리 접근 시간은 얼마인가?
  5. 다이렉트 매핑 방식 캐시에서 두 배열의 요소가 같은 캐시 위치에 대응하여, 번갈아 접근할 때마다 서로를 쫓아내고 있다. 이 미스의 분류는?
