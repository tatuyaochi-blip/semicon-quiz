성능 분석

start = now();
for (i = 0; i < N; i++)
    x = a * b + i;
end = now();

위와 같은 작은 루프로 계산 속도를 측정했더니 N을 크게 해도 시간이 거의 0이었다. 가장 가능성이 높은 원인은?

  1. ACPU가 계산을 한순간에 끝내는 특별한 명령어를 가지고 있기 때문
  2. Bx의 값이 나중에 사용되지 않으므로 컴파일러가 루프 계산을 불필요한 것으로 보고 제거했기 때문
  3. C시계 함수가 고장 났기 때문
정답과 해설 보기

정답: B. x의 값이 나중에 사용되지 않으므로 컴파일러가 루프 계산을 불필요한 것으로 보고 제거했기 때문

최적화를 활성화한 컴파일러는 결과가 사용되지 않는 계산을 불필요한 코드(데드 코드)로 제거하거나, 루프의 결과를 계산하여 상수로 치환합니다. 그래서 작은 부분만 떼어 낸 마이크로벤치마크에서는 측정하려는 계산이 실제로는 수행되지 않는 경우가 있습니다. 결과를 출력하거나, volatile이나 컴파일러 최적화를 막는 기법을 사용하거나, 생성된 기계어를 확인하는 등으로 대처합니다.

관련 계산 도구

암달의 법칙과 병렬 속도 향상병렬화 비율과 프로세서 수로 암달의 법칙과 구스타프슨의 법칙에 따른 속도 향상률과 병렬 효율 계산

성능 분석의 다른 문제

  1. 프로그램의 실행 시간을 측정할 때 같은 측정을 여러 번 반복하고 처음 몇 번의 결과를 제외하는 경우가 많은 이유로 올바른 것은?
  2. 매우 짧은 처리의 시간을 한 번만 측정하려 할 때의 문제와 대책의 조합으로 올바른 것은?
  3. 실행 시간 측정 방법 중 '벽시계 시간'과 'CPU 시간'의 차이로 올바른 것은?
  4. 서버 성능을 나타내는 처리량(스루풋)과 지연 시간(레이턴시)에 대한 설명으로 올바른 것은?
  5. 웹 서비스의 응답 시간을 평가할 때 평균값뿐 아니라 99퍼센타일 값(느린 쪽 1%의 경계)을 보는 경우가 많은 이유로 올바른 것은?

이 분야의 비교

  • 암달의 법칙과 구스타프슨의 법칙의 차이: 전제·식·스케일링·예 비교병렬화에 의한 속도 향상을 추정하는 암달의 법칙과 구스타프슨의 법칙을 전제, 식, 비율의 측정 방법, 상한, 강한 스케일링과 약한 스케일링, 계산 예 관점에서 표로 비교합니다.
