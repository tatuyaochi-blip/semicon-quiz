사이버 공격과 방어의 실무

공격자가 직원의 비밀번호를 입수하고 로그인을 수십 번 반복하여, 직원의 스마트폰에 승인을 요구하는 알림을 대량으로 보냈다. 직원은 귀찮아져서 그만 '승인'을 눌러 버렸다. 이 공격에 대한 대책으로 가장 적절한 것은?

  1. A알림 소리를 작게 하여, 승인을 요구하는 알림이 대량으로 와도 직원이 신경 쓰지 않고 업무를 계속할 수 있게 한다
  2. B비밀번호의 최소 글자 수를 늘리면, 공격자로부터 승인을 요구하는 알림이 와도 직원이 승인해 버릴 위험은 없어진다
  3. C화면에 표시된 번호를 앱에 입력하게 하는 방식이나 대량 요청의 제한을 도입하고, 기억에 없는 알림을 보고하게 한다
정답과 해설 보기

정답: C. 화면에 표시된 번호를 앱에 입력하게 하는 방식이나 대량 요청의 제한을 도입하고, 기억에 없는 알림을 보고하게 한다

이러한 공격은 MFA 피로 공격(푸시 폭탄)이라고 불리며, 알림의 '승인'을 누르기만 하면 인증이 끝나는 방식의 약점을 파고듭니다. 번호를 대조하는 방식에서는 로그인 화면에 표시된 번호를 입력하지 않으면 승인할 수 없으므로, 스스로 로그인하지 않은 사용자는 승인할 수 없습니다. 짧은 시간에 대량의 요청이 오면 멈추기, 알림에 위치나 앱 정보를 표시하기, 기억에 없는 알림을 보고하게 하기 같은 대책을 조합합니다. 보다 근본적으로는 FIDO2의 패스키처럼 가짜 사이트나 타인의 로그인에는 사용할 수 없는, 피싱에 강한 방식으로 옮겨 갑니다.

사이버 공격과 방어의 실무의 다른 문제

  1. FIDO2(WebAuthn)의 패스키에 의한 인증이 일회용 비밀번호(OTP)와 비교하여 피싱에 강하다고 여겨지는 이유로 올바른 것은?
  2. 어떤 웹 서비스에서 서로 다른 많은 IP 주소로부터, 각각 다른 사용자의 ID와 비밀번호 쌍으로 로그인이 대량으로 시도되었고 일부가 성공했다. 시도된 쌍의 대부분은 다른 서비스에서 유출된 것과 일치했다. 이 공격의 이름은?
  3. 다요소 인증을 사용하는 클라우드 메일 서비스에서, 직원이 진짜와 똑같은 로그인 화면으로 유도되어 비밀번호와 일회용 비밀번호를 입력했다. 공격자는 그 화면을 진짜 서비스와의 중계에 사용하여, 로그인 후에 발급된 세션 쿠키를 훔쳐 직원으로 사칭했다. 이 공격과 대책에 대한 설명으로 가장 적절한 것은?
  4. 서버의 관리자 계정을 지키기 위한 특권 접근 관리(PAM)의 사고방식으로 가장 적절한 것은?
  5. 개발자가 클라우드 서비스의 API 키를 포함한 설정 파일을 실수로 공개 Git 리포지토리에 커밋해 버렸다. 알아챈 즉시 그 파일을 삭제하는 변경을 커밋했다. 이후에 해야 할 대응으로 가장 적절한 것은?
