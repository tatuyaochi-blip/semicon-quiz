사이버 공격과 방어의 실무

침입 조사에서 서버 2대의 로그를 대조한다. 웹 서버의 로그는 협정 세계시(UTC)로 기록되었고, 시계는 NTP로 정확하게 맞춰져 있었다. 파일 서버의 로그는 일본 시간(UTC+9시간)으로 기록되었고, 시계는 정확한 시각보다 4분 빨랐다. 웹 서버의 로그에는 수상한 로그인이 01:52(UTC), 파일 서버의 로그에는 대량의 파일 읽기가 10:58(일본 시간)로 기록되어 있었다. 파일 읽기가 실제로 일어난 것은 수상한 로그인의 몇 분 후인가?

  1. A2분 후
  2. B6분 후
  3. C10분 후
정답과 해설 보기

정답: A. 2분 후

파일 서버의 시계는 4분 빨랐으므로, 기록된 10:58에서 4분을 빼면 정확한 일본 시간은 10:54입니다. 일본 시간은 UTC보다 9시간 빠르므로 UTC로 고치면 01:54가 되며, 수상한 로그인 01:52의 2분 후입니다. 시계의 차이를 보정하지 않으면 10:58 − 9시간 = 01:58로 6분 후, 차이를 보정하는 방향을 반대로 하면 11:02 − 9시간 = 02:02로 10분 후가 되어 사건 사이의 간격을 잘못 판단합니다. 이러한 오류를 막기 위해 모든 기기의 시계를 NTP로 맞추고, 로그에는 시차를 알 수 있는 형태(UTC 등)로 시각을 기록하며, 변조되기 어려운 별도의 장소에 모아 보관해 둡니다.

사이버 공격과 방어의 실무의 다른 문제

  1. 같은 주에 취약점 3개의 수정이 공개되었다. 운영 담당자는 하루에 하나씩만 수정을 적용할 수 있다. 가장 먼저 수정을 적용해야 할 것과 그 이유의 조합으로 가장 적절한 것은?
  2. 조직의 방어를 확인하는 방법 중 취약점 스캔, 침투 테스트, 레드팀 훈련의 차이에 대한 설명으로 올바른 것은?
  3. 외부 보안 연구자가 어떤 기업의 제품에서 공표되지 않은 취약점을 발견했다. 조정된 취약점 공개(Coordinated Vulnerability Disclosure)의 사고방식에 따른 진행 방법으로 가장 적절한 것은?
  4. SBOM(소프트웨어 자재 명세서)을 만들어 관리하는 주된 목적으로 올바른 것은?
  5. 어떤 기업은 사내 패키지 저장소(프라이빗 레지스트리)에 사내 전용 라이브러리 acme-utils를 두고 사용하고 있다. 공격자가 공개 패키지 저장소에 같은 이름 acme-utils로 더 큰 버전 번호의 패키지를 등록했더니, 빌드 설정에 따라서는 사내 빌드 환경이 공격자의 패키지를 가져와 버린다는 것이 밝혀졌다. 이 '의존성 혼동(dependency confusion)'에 대한 대책으로 가장 적절한 것은?
