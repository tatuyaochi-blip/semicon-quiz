네트워크 설계와 운용

MAC 주소가 00-1A-2B-3C-4D-5E인 인터페이스가 프리픽스 2001:db8:1:1::/64와 EUI-64 형식의 인터페이스 ID로 SLAAC에 의해 주소를 만든다. 만들어지는 주소는?

  1. A2001:db8:1:1:21a:2bff:fe3c:4d5e
  2. B2001:db8:1:1:1a:2bff:fe3c:4d5e
  3. C2001:db8:1:1:21a:2bfe:ff3c:4d5e
정답과 해설 보기

정답: A. 2001:db8:1:1:21a:2bff:fe3c:4d5e

EUI-64 형식에서는 48비트 MAC 주소를 상위 24비트와 하위 24비트로 나누고, 사이에 FF-FE를 넣어 64비트로 만듭니다. 00-1A-2B와 3C-4D-5E 사이에 넣으면 00-1A-2B-FF-FE-3C-4D-5E입니다. 또한 첫 바이트의 하위에서 두 번째 비트(U/L 비트)를 반전시키므로 00은 02가 되어 02-1A-2B-FF-FE-3C-4D-5E가 됩니다. 16비트씩 구분하여 각 구분의 앞쪽 0을 생략하면 21a:2bff:fe3c:4d5e이고, 프리픽스와 합치면 2001:db8:1:1:21a:2bff:fe3c:4d5e입니다. MAC 주소가 주소에 드러나면 단말이 추적되기 쉬우므로, 요즘 많은 OS는 난수를 바탕으로 한 인터페이스 ID를 사용합니다.

네트워크 설계와 운용의 다른 문제

  1. IPv6로만 동작하는 두 거점을 IPv4로만 동작하는 네트워크를 통해 연결하고, 거점 사이를 IPv6 패킷 그대로 통신시키고 싶다. 사용할 방법으로 적절한 것은?
  2. traceroute에서 출발지로부터 세어 4번째 라우터가 ICMP 시간 초과(Time Exceeded) 메시지를 돌려보내게 하려고 보내는 패킷의 IP 헤더 TTL 값은?
  3. 어떤 단말에서 웹 서버 198.51.100.80까지 traceroute를 실행했더니, 1~5번째 줄에 192.168.1.1, 10.0.0.1, '* * *'(응답 없음), 203.0.113.1, 198.51.100.80 순으로 표시되었고, 웹 서버도 문제없이 쓸 수 있었다. 3번째 줄의 해석으로 가장 적절한 것은?
  4. IPv4에서 전체 길이 4000바이트(헤더 20바이트, 데이터 3980바이트)의 패킷이 MTU가 1500바이트인 링크에서 분할(프래그먼트화)된다. 분할된 패킷의 헤더도 20바이트이며, 분할해도 되는 설정이라고 한다. 마지막 프래그먼트의 프래그먼트 오프셋 필드 값은?
  5. 거점 간 VPN 터널을 통해 먼 곳의 웹 서버와 통신하고 있다. TCP 연결은 확립되고 작은 페이지는 표시되지만, 큰 파일의 다운로드만 도중에 멈춰 버린다. 터널 안의 MTU는 1400바이트이며, 서버는 1500바이트의 패킷을 분할 금지(DF 비트를 1)로 하여 보내고 있다. 또한 서버 앞단의 방화벽은 ICMP를 모두 버리는 설정으로 되어 있다. 원인으로 가장 적절한 것은?
