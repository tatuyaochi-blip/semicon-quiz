I/O 인터페이스와 버스

PCI Express에서 사용되는 크레딧 방식 흐름 제어에 대한 설명으로 올바른 것은?

  1. A수신 측이 버퍼의 빈 용량을 크레딧으로 송신 측에 알리고, 송신 측은 크레딧 범위 안에서만 패킷을 보낸다
  2. B송신 측은 수신 측 상태와 무관하게 보내고, 넘친 패킷은 버린다
  3. C보내는 데이터 양에 따라 이용자에게 요금을 청구한다
정답과 해설 보기

정답: A. 수신 측이 버퍼의 빈 용량을 크레딧으로 송신 측에 알리고, 송신 측은 크레딧 범위 안에서만 패킷을 보낸다

수신 측 버퍼가 가득 찼을 때 패킷을 보내면 버리고 다시 보내는 낭비가 생깁니다. 크레딧 방식에서는 수신 측이 "앞으로 이만큼 받을 수 있다"는 양을 송신 측에 알리고, 송신 측은 그 범위 안에서만 보내며, 수신 측은 처리하여 버퍼가 빌 때마다 크레딧을 반환합니다. 넘침이 발생하지 않으므로 버리고 재전송하는 수고가 없습니다.

I/O 인터페이스와 버스의 다른 문제

  1. AI용 GPU를 다수 연결하는 시스템에서 PCI Express와는 별도로 GPU끼리를 잇는 전용 고속 접속(NVIDIA의 NVLink 등)이 사용되는 주된 이유는?
  2. PCI Express에서 64바이트의 작은 데이터를 쓰는 패킷을 다수 보내면 실효 대역폭이 이론값보다 상당히 작아진다. 그 주된 이유는?
  3. 네트워크 카드나 NVMe SSD 등에서 널리 사용되는, 메모리 상 디스크립터(기술자)의 링 구조를 이용한 DMA 방식에 대해 올바른 것은?
  4. PCI Express 링크의 절전 기능(ASPM에 의한 L0s나 L1 상태)에 대해 올바른 것은?
  5. 칩이나 보드 간의 고속 접속이 많은 선을 나란히 배치하는 병렬 전송에서 적은 선에 빠른 신호를 흘리는 직렬 전송으로 옮겨 온 주된 이유는?

이 분야의 비교

  • NVMe와 SATA SSD: 속도, 인터페이스, 선택 기준NVMe와 SATA SSD를 표로 비교합니다. 인터페이스, 속도, 지연 시간, 명령 큐, 폼팩터, 전력, 호환성, 가격, 각각에 알맞은 사용자를 다룹니다.
  • DMA vs 프로그램 방식 I/O: 차이점 설명DMA와 프로그램 방식 I/O(PIO)를 표로 비교합니다: 데이터를 옮기는 주체, CPU 부하, 처리량, 설정 비용, 복잡도, 버스 사용, 주요 용도.
  • PCIe 3.0 vs 4.0 vs 5.0 vs 6.0: 속도와 차이점PCIe 3.0, 4.0, 5.0, 6.0을 표로 비교합니다: 전송률, 레인당 및 x4, x16 링크 대역폭, 인코딩, 시그널링, 주요 장치.
