I/O 인터페이스와 버스

PCI Express에서 64바이트의 작은 데이터를 쓰는 패킷을 다수 보내면 실효 대역폭이 이론값보다 상당히 작아진다. 그 주된 이유는?

  1. A64바이트 데이터는 PCI Express에서 보낼 수 없기 때문
  2. B패킷마다 헤더나 오류 검출 부호 등이 붙어 데이터에 비해 그 비율이 커지기 때문
  3. C작은 패킷은 반드시 오류가 나서 매번 재전송되기 때문
정답과 해설 보기

정답: B. 패킷마다 헤더나 오류 검출 부호 등이 붙어 데이터에 비해 그 비율이 커지기 때문

PCI Express 패킷에는 데이터 외에 주소와 종류를 나타내는 헤더, 데이터 링크 계층의 일련번호와 CRC, 물리 계층의 구분자 등이 붙어 합쳐서 20~30바이트 정도가 됩니다. 데이터가 64바이트라면 보내는 비트의 3할 안팎이 데이터 이외가 됩니다. 256바이트 이상의 묶음 전송으로 하면 낭비 비율이 작아집니다. 이 또한 대역폭뿐 아니라 패킷 크기에도 주의해야 하는 이유입니다.

I/O 인터페이스와 버스의 다른 문제

  1. 네트워크 카드나 NVMe SSD 등에서 널리 사용되는, 메모리 상 디스크립터(기술자)의 링 구조를 이용한 DMA 방식에 대해 올바른 것은?
  2. PCI Express 링크의 절전 기능(ASPM에 의한 L0s나 L1 상태)에 대해 올바른 것은?
  3. 칩이나 보드 간의 고속 접속이 많은 선을 나란히 배치하는 병렬 전송에서 적은 선에 빠른 신호를 흘리는 직렬 전송으로 옮겨 온 주된 이유는?
  4. 고속 직렬 전송에서 사용되는 SerDes(시리얼라이저/디시리얼라이저)의 역할로 올바른 것은?
  5. 고속 직렬 전송에서 2개의 선에 반대 방향의 신호를 흘리는 차동 신호가 사용되는 주된 이유는?

이 분야의 비교

  • NVMe와 SATA SSD: 속도, 인터페이스, 선택 기준NVMe와 SATA SSD를 표로 비교합니다. 인터페이스, 속도, 지연 시간, 명령 큐, 폼팩터, 전력, 호환성, 가격, 각각에 알맞은 사용자를 다룹니다.
  • DMA vs 프로그램 방식 I/O: 차이점 설명DMA와 프로그램 방식 I/O(PIO)를 표로 비교합니다: 데이터를 옮기는 주체, CPU 부하, 처리량, 설정 비용, 복잡도, 버스 사용, 주요 용도.
  • PCIe 3.0 vs 4.0 vs 5.0 vs 6.0: 속도와 차이점PCIe 3.0, 4.0, 5.0, 6.0을 표로 비교합니다: 전송률, 레인당 및 x4, x16 링크 대역폭, 인코딩, 시그널링, 주요 장치.
