OS와 하드웨어

컨테이너와 가상 머신의 차이로 올바른 것은 무엇입니까?

  1. A컨테이너는 각각 독자적인 OS 커널을 가지고, 가상 머신은 커널을 공유한다
  2. B컨테이너는 하이퍼바이저 위에서 동작하고, 가상 머신은 OS의 기능만으로 동작한다
  3. C컨테이너는 커널을 공유하고, 가상 머신은 독자적인 OS를 실행한다
정답과 해설 보기

정답: C. 컨테이너는 커널을 공유하고, 가상 머신은 독자적인 OS를 실행한다

컨테이너는 하나의 OS 커널을 공유하면서 파일 시스템의 보이는 모습, 프로세스, 네트워크, 사용할 수 있는 자원 등을 그룹별로 나누어 격리하는 방식입니다. OS를 통째로 부팅하지 않으므로 가볍고 시작도 빠릅니다. 가상 머신은 하이퍼바이저 위에서 각각 독자적인 커널을 포함한 OS를 실행하므로 무거운 대신 격리가 강하고 다른 종류의 OS도 실행할 수 있습니다. 커널을 공유하는 쪽은 컨테이너이며, 설명이 반대로 된 선택지에 주의해야 합니다.

  • A. 커널을 공유하는 쪽은 컨테이너이며, 설명이 반대입니다.
  • B. 하이퍼바이저 위에서 동작하는 쪽은 가상 머신입니다.
  • C. 올바릅니다. 컨테이너는 커널을 공유하고, 가상 머신은 독자적인 OS를 실행합니다.

OS와 하드웨어의 다른 문제

  1. 많은 OS에서 커널 영역을 각 프로세스의 주소 공간 일부(예를 들어 상위 범위)에 할당해 두고, 페이지 테이블의 보호 비트로 사용자 모드에서의 접근을 금지합니다. 이 배치의 주된 이점은 무엇입니까?
  2. 페이지 크기가 4 KB일 때, 가상 주소 중 페이지 내 위치(오프셋)를 나타내는 것은 몇 비트입니까?
  3. 페이지 크기가 4 KB일 때, 32비트 가상 주소 0x00403ABC의 페이지 번호와 페이지 내 오프셋의 조합으로 올바른 것은 무엇입니까?
  4. RISC-V 특권 아키텍처에서 정해진 주요 동작 모드의 조합으로 올바른 것은 무엇입니까?
  5. 인터럽트나 예외 처리를 마치고 원래 프로그램으로 돌아갈 때, 일반 함수의 복귀 명령이 아니라 전용 복귀 명령(RISC-V의 sret, mret 등)을 사용하는 이유는 무엇입니까?
