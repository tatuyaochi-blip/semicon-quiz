OS와 하드웨어

위와 같이 장치의 상태 레지스터를 메모리 맵 I/O로 읽을 때, volatile을 붙이고 그 영역을 캐시하지 않도록 설정하는 이유로 올바른 것은?

#define STATUS (*(volatile unsigned int *)0x40001000)
while ((STATUS & 1) == 0)
    ;   /* 装置の準備ができるまで待つ */
  1. Avolatile을 붙이면 읽기 명령이 한 번으로 합쳐져 빨라지기 때문에
  2. B캐시에 넣으면 장치 레지스터의 값이 자동으로 0으로 돌아가기 때문에
  3. C값은 장치가 바꾸므로 매번 실제로 다시 읽지 않으면 변화를 놓치기 때문에
정답과 해설 보기

정답: C. 값은 장치가 바꾸므로 매번 실제로 다시 읽지 않으면 변화를 놓치기 때문에

장치 레지스터의 값은 프로그램과 무관하게 장치가 바꿉니다. volatile이 없으면 컴파일러는 루프 안에서 값이 바뀌지 않는다고 판단하여 한 번만 읽고 영원히 기다리는 코드를 만들기도 합니다. 또한 그 영역을 캐시하면 CPU는 캐시에 있는 오래된 값을 계속 읽어 장치의 변화가 보이지 않습니다. volatile은 읽기를 생략하지 못하게 하는 지정이며, 한 번으로 합치는 것과는 반대 작용입니다. 캐시로 인해 값이 0이 되지도 않습니다.
