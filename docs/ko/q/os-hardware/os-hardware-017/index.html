OS와 하드웨어

프로세스를 복제할 때 카피 온 라이트(copy-on-write)를 사용하는 이점으로 올바른 것은 무엇입니까?

  1. A복제한 프로세스와 원래 프로세스가 쓴 내용을 항상 공유할 수 있다
  2. B쓰기가 이루어진 페이지만 나중에 복제하므로 빠르고 메모리를 절약한다
  3. C쓰기 때마다 모든 페이지를 복제하므로 데이터의 안전성이 높아진다
정답과 해설 보기

정답: B. 쓰기가 이루어진 페이지만 나중에 복제하므로 빠르고 메모리를 절약한다

프로세스를 복제할 때 전체 메모리를 즉시 복사하면 시간도 메모리도 많이 들고, 직후에 다른 프로그램을 읽어 들인다면 그 복사는 낭비가 됩니다. 카피 온 라이트에서는 양쪽 페이지 테이블이 같은 물리 페이지를 읽기 전용으로 가리키게 해 두고, 어느 한쪽이 쓰면 페이지 폴트가 발생하여 OS가 그 페이지만 복제합니다. 쓴 내용은 공유되지 않고 각 프로세스에 따로 유지됩니다. 모든 페이지를 복제하는 것도 아닙니다.

  • A. 쓰기 후에는 각각 별도의 페이지가 되며 공유되지 않습니다.
  • B. 올바릅니다. 쓰기가 이루어진 페이지만 복제하므로 빠르고 메모리를 절약합니다.
  • C. 복제하는 것은 쓰기가 이루어진 페이지뿐입니다.

OS와 하드웨어의 다른 문제

  1. 디맨드 페이징에 대한 설명으로 올바른 것은 무엇입니까?
  2. 페이지 교체의 클락(clock) 방식(세컨드 찬스 방식)에서 각 페이지의 참조 비트를 사용하는 목적은 무엇입니까?
  3. 페이지 교체에서 FIFO 방식을 사용하면 물리 메모리의 페이지 수를 늘렸는데도 페이지 폴트가 늘어나는 경우가 있습니다. 이 현상을 무엇이라고 합니까?
  4. 물리 메모리가 부족하여 페이지를 내보내고 읽어 들이는 일만 계속되어 처리가 거의 진행되지 않는 상태를 무엇이라고 합니까?
  5. 메모리 접근 시간이 100 ns, 페이지 폴트 처리에 8 ms가 걸리고, 100만 번에 한 번 페이지 폴트가 발생할 때 평균 접근 시간은 대략 얼마입니까?
