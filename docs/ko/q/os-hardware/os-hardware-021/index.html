OS와 하드웨어

물리 메모리가 부족하여 페이지를 내보내고 읽어 들이는 일만 계속되어 처리가 거의 진행되지 않는 상태를 무엇이라고 합니까?

  1. A데드락
  2. B캐시 일관성
  3. C스래싱
정답과 해설 보기

정답: C. 스래싱

동시에 동작하는 프로세스가 사용하는 페이지의 합계(워킹 셋)가 물리 메모리보다 커지면, 필요한 페이지를 읽어 들일 때마다 다른 프로세스가 사용하는 페이지를 내보내고 곧바로 그것이 다시 필요해지는 일이 반복됩니다. 디스크 읽기·쓰기를 기다리는 시간만 늘어나고 CPU 이용률도 떨어집니다. 이것이 스래싱이며, 실행하는 프로세스를 줄이거나 메모리를 늘리면 해소됩니다. 데드락은 서로의 자원을 기다리며 멈추는 상태입니다.

OS와 하드웨어의 다른 문제

  1. 메모리 접근 시간이 100 ns, 페이지 폴트 처리에 8 ms가 걸릴 때, 100만 번에 한 번 페이지 폴트가 일어나면 평균 접근 시간은 대략 얼마입니까?
  2. 컨텍스트 스위치에서 전환 전 프로세스에 대해 저장해 두어야 하는 것은?
  3. 프로세스의 컨텍스트 스위치가 레지스터 저장·복원에 걸리는 시간보다 실제로는 더 큰 성능 저하를 초래하는 경우가 있는 주된 이유는?
  4. TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 장점으로 올바른 것은?
  5. OS가 스스로 CPU를 내놓지 않는 프로그램으로부터도 일정 시간마다 CPU를 되찾아 다른 프로세스로 전환할 수 있는 것은 주로 어떤 구조 덕분입니까?
