링커, 로더, 실행 파일

동적 링크(공유 라이브러리)의 이점으로 올바른 것은 무엇입니까?

  1. A실행 환경에 라이브러리가 없어도 반드시 동작한다
  2. B여러 프로그램이 하나의 라이브러리를 메모리에서 공유할 수 있고, 라이브러리를 갱신하면 다시 만들지 않아도 수정이 반영된다
  3. C기동 시 처리가 전혀 필요 없어져 정적 링크보다 반드시 빠르게 기동한다
정답과 해설 보기

정답: B. 여러 프로그램이 하나의 라이브러리를 메모리에서 공유할 수 있고, 라이브러리를 갱신하면 다시 만들지 않아도 수정이 반영된다

동적 링크에서는 실행 파일에 '어느 공유 라이브러리의 어느 함수를 사용하는지'만 기록해 두고, 실행 시에 동적 링커가 라이브러리를 읽어 들여 연결합니다. 공유 라이브러리의 코드는 바뀌지 않으므로 물리 메모리 상의 하나의 사본을 많은 프로세스가 공유할 수 있습니다. 버그나 취약점 수정도 라이브러리를 교체하기만 하면 됩니다. 다만 기동 시에 결합 작업이 필요합니다.

링커, 로더, 실행 파일의 다른 문제

  1. 동적 링크를 사용한 프로그램을 다른 컴퓨터에 복사하여 실행했더니 기동하지 않았습니다. 가장 가능성이 높은 원인은 무엇입니까?
  2. 정적 라이브러리(.a 파일)와 함께 링크할 때 링커가 실행 파일에 포함시키는 것으로 올바른 것은 무엇입니까?
  3. GNU 링커에서 'gcc -lmylib main.o'처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 앞에 쓰면 정의되지 않은 참조 오류가 나는 경우가 있습니다. 그 이유로 올바른 것은 무엇입니까?
  4. 위치 독립 코드(PIC)의 설명으로 올바른 것은 무엇입니까?
  5. 공유 라이브러리에서 사용되는 GOT(Global Offset Table)의 역할로 올바른 것은 무엇입니까?

이 분야의 비교

  • 정적 링킹 vs 동적 링킹: 차이점 설명정적 링킹과 동적 링킹을 표로 비교합니다: 링킹 시점, 실행 파일 크기, 메모리 사용, 업데이트, 시작 시간, 배포, 성능, 주요 용도.
  • 스택 vs 힙 메모리: 차이점 설명스택과 힙 메모리를 표로 비교합니다: 용도, 할당, 속도, 수명, 크기 제한, 배치, 단편화, 흔한 오류.
