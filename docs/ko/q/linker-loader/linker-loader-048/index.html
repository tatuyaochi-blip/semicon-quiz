링커, 로더, 실행 파일

malloc과 free를 반복하는 동안, 빈 메모리의 합계는 충분한데도 큰 영역을 한꺼번에 확보할 수 없게 되는 경우가 있습니다. 이 현상을 무엇이라고 합니까?

  1. A메모리 누수
  2. B단편화(프래그멘테이션)
  3. C스택 오버플로
정답과 해설 보기

정답: B. 단편화(프래그멘테이션)

크기가 다른 영역의 확보와 해제를 반복하면 사용 중인 영역 사이에 작은 빈 공간이 흩어집니다. 빈 공간의 합계가 크더라도 이어진 큰 빈 공간이 없으면 큰 확보에 실패합니다. 이를 단편화라고 부릅니다. 메모리 할당기는 크기별로 나누어 관리하거나 이웃한 빈 공간을 합쳐 단편화를 줄입니다. 오래 계속 동작하는 임베디드 기기에서는 특히 주의가 필요합니다.

링커, 로더, 실행 파일의 다른 문제

  1. 공유 라이브러리를 만들 때 외부에서 사용할 함수만 공개하고 내부 함수는 심볼 가시성(visibility)을 'hidden'으로 하는 이점으로 올바른 것은 무엇입니까?
  2. C++에서 전역 오브젝트의 생성자가 main보다 먼저 실행되는 구조로 올바른 것은 무엇입니까?
  3. 컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?
  4. 링커의 주된 역할로 올바른 것은 무엇입니까?
  5. 링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?

이 분야의 비교

  • 정적 링킹 vs 동적 링킹: 차이점 설명정적 링킹과 동적 링킹을 표로 비교합니다: 링킹 시점, 실행 파일 크기, 메모리 사용, 업데이트, 시작 시간, 배포, 성능, 주요 용도.
  • 스택 vs 힙 메모리: 차이점 설명스택과 힙 메모리를 표로 비교합니다: 용도, 할당, 속도, 수명, 크기 제한, 배치, 단편화, 흔한 오류.
