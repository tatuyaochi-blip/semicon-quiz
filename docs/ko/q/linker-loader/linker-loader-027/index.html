링커, 로더, 실행 파일

Linux에서 동적 링크 프로그램을 기동할 때 동작하는 동적 링커(ld.so 등)의 역할로 올바른 것은 무엇입니까?

  1. A소스 코드를 컴파일하여 기계어를 만든다
  2. B필요한 공유 라이브러리를 찾아 메모리에 읽어 들이고, 심볼을 연결한 뒤 프로그램을 시작시킨다
  3. C프로그램이 종료된 뒤 디스크의 빈 공간을 정리한다
정답과 해설 보기

정답: B. 필요한 공유 라이브러리를 찾아 메모리에 읽어 들이고, 심볼을 연결한 뒤 프로그램을 시작시킨다

동적 링크 실행 파일에는 사용할 동적 링커의 위치가 적혀 있으며, OS는 프로그램을 읽어 들이면 먼저 동적 링커에 처리를 넘깁니다. 동적 링커는 필요한 공유 라이브러리를 찾아 읽어 들이고, 재배치와 심볼 결합을 수행한 뒤 프로그램의 입구로 제어를 옮깁니다. dlopen으로 실행 중에 라이브러리를 추가로 읽어 들이는 처리도 동적 링커가 맡습니다.

링커, 로더, 실행 파일의 다른 문제

  1. ASLR(주소 공간 배치 무작위화)의 목적으로 올바른 것은 무엇입니까?
  2. 실행 파일을 PIE(위치 독립 실행 파일)로 만드는 주된 이유는 무엇입니까?
  3. 프로그램을 기동할 때(Linux의 execve 등) OS 로더가 수행하는 일로 올바른 것은 무엇입니까?
  4. C 언어 프로그램에서 OS가 처음 실행을 시작하는 주소(엔트리 포인트)에 대해 올바른 것은 무엇입니까?
  5. C 언어의 main 함수가 'return 3;'으로 끝났을 때, 그 값 3은 일반적으로 어떻게 됩니까?

이 분야의 비교

  • 정적 링킹 vs 동적 링킹: 차이점 설명정적 링킹과 동적 링킹을 표로 비교합니다: 링킹 시점, 실행 파일 크기, 메모리 사용, 업데이트, 시작 시간, 배포, 성능, 주요 용도.
  • 스택 vs 힙 메모리: 차이점 설명스택과 힙 메모리를 표로 비교합니다: 용도, 할당, 속도, 수명, 크기 제한, 배치, 단편화, 흔한 오류.
