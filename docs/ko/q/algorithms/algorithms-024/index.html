자료 구조와 알고리즘

빈 이진 탐색 트리에 50, 30, 70, 20, 40, 60, 80의 순서로 값을 삽입했다. 이 트리를 후위 순회(왼쪽 서브트리, 오른쪽 서브트리, 그 노드 순으로 방문한다)로 따라갔을 때의 순서는?

  1. A50, 30, 20, 40, 70, 60, 80
  2. B20, 40, 30, 60, 80, 70, 50
  3. C20, 30, 40, 50, 60, 70, 80
정답과 해설 보기

정답: B. 20, 40, 30, 60, 80, 70, 50

루트는 50이고, 왼쪽 자식은 30(그 자식이 20과 40), 오른쪽 자식은 70(그 자식이 60과 80)이 됩니다. 후위 순회에서는 왼쪽 서브트리의 20, 40, 30, 오른쪽 서브트리의 60, 80, 70을 방문한 다음, 마지막으로 루트 50을 방문합니다. 50, 30, 20, 40, 70, 60, 80은 노드를 먼저 방문하는 전위 순회, 20, 30, 40, …은 중위 순회의 결과입니다. 후위 순회는 자식을 먼저 처리해야 하는 트리의 삭제나, 수식 트리로부터 후위 표기법을 만들 때 쓰입니다.

자료 구조와 알고리즘의 다른 문제

  1. 빈 이진 탐색 트리에 1, 2, 3, …, 1000의 순서로 값을 삽입했다(균형을 잡는 조작은 하지 않는다). 이 트리에서 1000을 찾을 때, 루트부터 비교하기 시작하여 찾을 때까지 비교하는 노드의 수는?
  2. 데이터베이스나 파일 시스템의 인덱스에 이진 탐색 트리가 아니라 B 트리(B+ 트리 포함)가 자주 쓰이는 주된 이유는?
  3. 정점이 100만 개, 간선이 300만 개 정도인 도로망처럼 정점 수에 비해 간선이 적은(희소한) 그래프를 메모리에 저장하는 방법으로 적절한 것은?
  4. 간선에 가중치가 없는 그래프에서, 출발점에서 각 정점까지의 최소 간선 수를 구하고 싶다. 적합한 탐색 방법과 그때 사용하는 자료 구조의 조합은?
  5. 간선에 방향이 없는 그래프에서 각 정점의 이웃 정점이 다음과 같다. A: B, C / B: A, D, E / C: A, F / D: B / E: B, F / F: C, E. 정점 A부터 재귀적인 깊이 우선 탐색을 수행한다. 이웃 정점은 여기에 쓴 순서로 조사하고, 아직 방문하지 않은 정점이 발견되면 바로 그 정점으로 나아간다. 정점을 방문하는 순서는?
