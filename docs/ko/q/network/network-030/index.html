네트워크 기초

캐시에 아무것도 들어 있지 않은 풀 서비스 리졸버(캐시 DNS 서버)가 www.example.com의 IP 주소를 알아낼 때 질의하는 순서로 올바른 것은?

  1. A루트 서버 → .com의 DNS 서버 → example.com의 권한 있는 DNS 서버
  2. Bexample.com의 권한 있는 DNS 서버 → .com의 DNS 서버 → 루트 서버
  3. C.com의 DNS 서버 → 루트 서버 → www.example.com의 웹 서버
정답과 해설 보기

정답: A. 루트 서버 → .com의 DNS 서버 → example.com의 권한 있는 DNS 서버

단말은 인터넷 서비스 제공자나 사내 등에 있는 리졸버에 질의하고, 리졸버가 단말을 대신해 도메인 이름의 계층을 위에서부터 따라갑니다. 먼저 루트 서버에 물어 .com을 관리하는 서버(TLD 서버)를 안내받고, 다음으로 그곳에서 example.com의 권한 있는 DNS 서버를 안내받으며, 마지막으로 권한 있는 DNS 서버로부터 www.example.com의 주소를 얻습니다. 얻은 답은 레코드에 붙은 유효 기간(TTL. IP 헤더의 TTL과는 다른 것) 동안 캐시되어, 두 번째부터는 바로 답할 수 있습니다. 그래서 DNS 설정을 바꿔도 오래된 답의 캐시가 만료될 때까지는 이전 주소가 사용될 수 있습니다.

  2. HTTPS(HTTP를 TLS로 보호한 통신)로 보호되는 것으로 올바른 것은?
  3. TLS에서 브라우저가 접속한 서버를 '위장이 아니다'라고 판단할 수 있는 이유로 올바른 것은?
  4. 100 MB 파일을 100 Mbps 회선으로 보내는 데 걸리는 시간에 가장 가까운 것은? 헤더 등의 오버헤드와 지연은 무시하고, 1 MB = 10^6바이트로 한다.
  5. 1 Gbps 이더넷에서 IP 패킷의 크기가 MTU를 꽉 채운 1500바이트가 되도록 하여 TCP 데이터를 계속 보낸다. IPv4 헤더를 20바이트, TCP 헤더를 20바이트, 이더넷 헤더와 FCS를 합쳐 18바이트, 프리앰블과 프레임 사이의 빈 시간(프레임 간 갭)을 합쳐 20바이트라고 할 때, 애플리케이션 데이터의 처리량 상한에 가장 가까운 것은?
