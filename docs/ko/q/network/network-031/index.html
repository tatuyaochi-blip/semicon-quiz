네트워크 기초

DHCP로 단말이 IP 주소를 얻을 때의 메시지 순서로 올바른 것은?

  1. ARequest → Offer → Discover → Ack
  2. BDiscover → Offer → Request → Ack
  3. COffer → Discover → Ack → Request
정답과 해설 보기

정답: B. Discover → Offer → Request → Ack

아직 주소가 없는 단말은 DHCP 서버의 위치도 모르므로 먼저 Discover를 브로드캐스트로 보냅니다. 서버는 빌려줄 수 있는 주소 등을 Offer로 제시하고, 단말은 어느 서버의 제시를 받아들일지를 Request로 알리며, 서버가 Ack로 확정합니다. 머리글자를 따서 DORA라고 부릅니다. 단말은 IP 주소 외에 서브넷 마스크, 기본 게이트웨이, DNS 서버의 주소 등도 받습니다. 주소는 기한(임대 기간)이 있는 대여이며, 단말은 기한이 되기 전에 갱신을 요청합니다. 라우터 너머에 있는 DHCP 서버를 사용하려면 라우터에 DHCP 릴레이를 설정합니다.

네트워크 기초의 다른 문제

  1. HTTPS(HTTP를 TLS로 보호한 통신)로 보호되는 것으로 올바른 것은?
  2. TLS에서 브라우저가 접속한 서버를 '위장이 아니다'라고 판단할 수 있는 이유로 올바른 것은?
  3. 100 MB 파일을 100 Mbps 회선으로 보내는 데 걸리는 시간에 가장 가까운 것은? 헤더 등의 오버헤드와 지연은 무시하고, 1 MB = 10^6바이트로 한다.
  4. 1 Gbps 이더넷에서 IP 패킷의 크기가 MTU를 꽉 채운 1500바이트가 되도록 하여 TCP 데이터를 계속 보낸다. IPv4 헤더를 20바이트, TCP 헤더를 20바이트, 이더넷 헤더와 FCS를 합쳐 18바이트, 프리앰블과 프레임 사이의 빈 시간(프레임 간 갭)을 합쳐 20바이트라고 할 때, 애플리케이션 데이터의 처리량 상한에 가장 가까운 것은?
  5. RTT가 50 ms, 대역폭이 100 Mbps인 회선에서 10 KB의 응답을 받는 요청을, 이전 응답을 다 받은 뒤 다음 요청을 보내는 방식으로 100회 반복한다. 걸리는 시간에 가장 가까운 것은? 1회당 시간은 RTT에 응답의 전송 시간(데이터량÷대역폭)을 더한 것으로 하고, 1 KB = 1000바이트, 서버의 처리 시간은 무시한다.
