CPU와 아키텍처

명령어의 의존 관계를 조사해, 실행할 수 있는 명령어부터 프로그램 순서와 다른 순서로 실행하여 성능을 높이는 방식은?

  1. A순차 실행(인오더)
  2. B비순차 실행(아웃오브오더)
  3. C싱글 사이클 실행
정답과 해설 보기

정답: B. 비순차 실행(아웃오브오더)

비순차 실행에서는 앞선 명령어의 결과나 메모리의 데이터를 기다리는 명령어를 뒤로 미루고, 준비된 뒤쪽 명령어를 먼저 실행합니다. 특히 캐시 미스의 대기 시간에 다른 일을 진행할 수 있다는 것이 큰 이점입니다. 수백 명령어 분량의 윈도우에서 실행 가능한 명령어를 찾는 회로, 레지스터 리네이밍, 결과를 순서대로 확정하는 리오더 버퍼 등이 필요하여 회로와 전력이 커집니다.

CPU와 아키텍처의 다른 문제

  1. 실행 중인 처리를 일시적으로 중단하고 외부 기기의 요청 등에 따른 처리를 우선 수행하는 CPU의 구조는?
  2. CPU를 거치지 않고 주변 장치와 메모리 사이에서 직접 데이터를 전송하는 구조는?
  3. CPU, 메모리, 타이머나 ADC 등의 주변 기능을 1칩에 담아 가전이나 기기 제어에 사용되는 LSI는?
  4. 멀티코어 CPU에서 각 코어의 캐시에 같은 주소의 데이터가 있을 때, 그 내용의 일관성을 유지하는 구조는?
  5. CPU의 소비 전력을 줄이기 위해 부하에 따라 동작 주파수와 전원 전압을 동적으로 바꾸는 기술은?
