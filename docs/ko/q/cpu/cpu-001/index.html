CPU와 아키텍처

CPU의 파이프라인 처리의 주된 목적으로 올바른 것은?

  1. A명령어 처리를 여러 단계로 나누고 서로 다른 명령어의 단계를 겹쳐 실행함으로써 처리량(스루풋)을 높인다
  2. B하나의 명령어 실행 시간(레이턴시)을 반드시 단축한다
  3. C명령어 수를 줄여 프로그램을 작게 만든다
정답과 해설 보기

정답: A. 명령어 처리를 여러 단계로 나누고 서로 다른 명령어의 단계를 겹쳐 실행함으로써 처리량(스루풋)을 높인다

파이프라인은 명령어의 인출, 해독, 실행, 메모리 접근, 쓰기 등의 단계를 조립 라인처럼 겹쳐서 매 클록 1개의 명령어를 완료시켜 처리량을 높입니다. 5단이라면 이상적으로는 약 5배입니다. 명령어 하나의 처리 시간(레이턴시)은 오히려 조금 늘어납니다. 데이터 의존, 분기, 자원 경합으로 흐름이 흐트러지는 것(해저드)이 있으며, 포워딩과 분기 예측으로 대처합니다.

  4. RISC(축소 명령어 세트 컴퓨터)의 특징으로 올바른 것은?
  5. 클록 주파수 1 GHz인 클록의 주기는 얼마인가?

이 분야의 비교

  • RISC와 CISC의 차이와 대표 예시RISC와 CISC 명령어 집합 구조를 표로 비교합니다. 명령어 길이, 메모리 접근, 레지스터, 디코딩, 코드 크기, ARM, RISC-V, x86 같은 예시를 다룹니다.
  • ARM vs RISC-V vs x86: 명령어 집합 구조 비교ARM, RISC-V, x86을 표로 비교합니다: 설계 방식, 명령어 길이, 라이선스, 레지스터, 생태계, 강점, 주요 용도.
  • 폰 노이만 vs 하버드 아키텍처: 차이점 설명폰 노이만과 하버드 아키텍처를 표로 비교합니다: 메모리, 버스, 처리량, 유연성, 복잡도, 주요 장치, 수정된 하버드 설계.
