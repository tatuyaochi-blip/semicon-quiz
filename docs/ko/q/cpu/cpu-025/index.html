정답: C. 캐시 코히런시(일관성) 제어

어떤 코어가 캐시 상의 데이터를 고쳐 쓸 때 다른 코어의 캐시에 오래된 데이터가 남아 있으면 잘못된 값을 쓰게 됩니다. 코히런시 제어는 각 캐시 라인에 「수정됨·공유·무효」 등의 상태를 두고(MESI 프로토콜 등), 쓰기 시 다른 코어의 사본을 무효화하여 일관성을 유지합니다. 코어 수가 많으면 통신량이 늘어나므로 디렉터리 방식 등으로 효율화합니다.

CPU와 아키텍처의 다른 문제

  1. CPU의 소비 전력을 줄이기 위해 부하에 따라 동작 주파수와 전원 전압을 동적으로 바꾸는 기술은?
  2. 투기적 실행의 흔적이 캐시에 남는 것을 악용하여, 본래 접근할 수 없는 데이터를 추측하는 공격이 밝혀진 취약점의 예는?
  3. CPU의 냉각 설계 기준이 되는, 표준적인 고부하 시 발생하는 열량을 나타내는 지표는?
  4. 1클록당 실행할 수 있는 명령어 수를 나타내는 지표는?
  5. 소비 전력과 발열의 제약 때문에 칩 위의 모든 회로를 동시에 최대 성능으로 동작시킬 수 없게 되는 문제를 무엇이라 하는가?

이 분야의 비교

  • RISC와 CISC의 차이와 대표 예시RISC와 CISC 명령어 집합 구조를 표로 비교합니다. 명령어 길이, 메모리 접근, 레지스터, 디코딩, 코드 크기, ARM, RISC-V, x86 같은 예시를 다룹니다.
  • ARM vs RISC-V vs x86: 명령어 집합 구조 비교ARM, RISC-V, x86을 표로 비교합니다: 설계 방식, 명령어 길이, 라이선스, 레지스터, 생태계, 강점, 주요 용도.
  • 폰 노이만 vs 하버드 아키텍처: 차이점 설명폰 노이만과 하버드 아키텍처를 표로 비교합니다: 메모리, 버스, 처리량, 유연성, 복잡도, 주요 장치, 수정된 하버드 설계.
