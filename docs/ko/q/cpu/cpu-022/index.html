CPU와 아키텍처

실행 중인 처리를 일시적으로 중단하고 외부 기기의 요청 등에 따른 처리를 우선 수행하는 CPU의 구조는?

  1. A인터럽트
  2. B파이프라인
  3. C캐시
정답과 해설 보기

정답: A. 인터럽트

인터럽트는 키보드 입력, 타이머, 통신 수신 등의 이벤트가 발생했을 때 CPU가 실행 중인 처리를 중단하고 레지스터 등의 상태를 저장한 뒤 해당 처리(인터럽트 핸들러)를 수행하고, 끝나면 원래대로 돌아가는 구조입니다. CPU가 주변기기의 상태를 계속 확인하는 방식(폴링)보다 낭비가 적고 응답도 빠릅니다. 우선순위를 매겨 중요한 요청을 먼저 처리합니다.

CPU와 아키텍처의 다른 문제

  1. CPU를 거치지 않고 주변 장치와 메모리 사이에서 직접 데이터를 전송하는 구조는?
  2. CPU, 메모리, 타이머나 ADC 등의 주변 기능을 1칩에 담아 가전이나 기기 제어에 사용되는 LSI는?
  3. 멀티코어 CPU에서 각 코어의 캐시에 같은 주소의 데이터가 있을 때, 그 내용의 일관성을 유지하는 구조는?
  4. CPU의 소비 전력을 줄이기 위해 부하에 따라 동작 주파수와 전원 전압을 동적으로 바꾸는 기술은?
  5. 투기적 실행의 흔적이 캐시에 남는 것을 악용하여, 본래 접근할 수 없는 데이터를 추측하는 공격이 밝혀진 취약점의 예는?

  • RISC와 CISC의 차이와 대표 예시RISC와 CISC 명령어 집합 구조를 표로 비교합니다. 명령어 길이, 메모리 접근, 레지스터, 디코딩, 코드 크기, ARM, RISC-V, x86 같은 예시를 다룹니다.

  • 폰 노이만 vs 하버드 아키텍처: 차이점 설명폰 노이만과 하버드 아키텍처를 표로 비교합니다: 메모리, 버스, 처리량, 유연성, 복잡도, 주요 장치, 수정된 하버드 설계.
