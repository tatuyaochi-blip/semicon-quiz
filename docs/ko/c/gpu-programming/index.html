GPU 프로그래밍: 핵심 정리

GPU는 수천에서 수만 개의 스레드를 동시에 실행하여 대량의 데이터에 같은 연산을 적용하는 데 뛰어난 프로세서입니다. 프로그램은 그리드, 블록, 스레드의 계층으로 병렬성을 표현하며, 하드웨어는 워프라 불리는 약 32개 스레드 묶음을 동기화된 상태로 실행합니다.

성능을 내려면 이웃한 스레드가 이웃한 주소를 읽는 병합(coalesced) 메모리 접근, 블록 안에서 사용하는 온칩 공유 메모리, 워프 내 다이버전스 회피, 메모리 지연을 숨길 수 있을 만큼의 충분한 점유율이 필요합니다. 이 주제는 제품 세대에 의존하지 않는 원리에 초점을 맞춥니다.

GPU 프로그래밍 전체 문제 (50)
  1. CPU와 GPU의 설계 사고방식의 차이로 올바른 것은?
  2. GPU에서 빠르게 처리할 수 있는 작업의 특징으로 가장 적절한 것은?
  3. GPU에서 실행하면 효율이 떨어지기 쉬운 처리는?
  4. CUDA 등 GPU 프로그래밍에서 말하는 '커널'에 대한 설명으로 올바른 것은?
  5. CUDA 스레드 계층의 조합으로 올바른 것은? (큰 순서)
  6. CUDA 커널에서 위의 식으로 각 스레드의 번호 i를 구한다. blockIdx.x=2, blockDim.x=256, threadIdx.x=5인 스레드의 i는 얼마인가?
  7. 요소 수 1000인 배열을 블록당 256스레드, 스레드당 1요소씩 처리하려 한다. 실행할 블록 수로 올바른 것은?
  8. 위 CUDA 커널에 "if (i < n)"을 넣은 이유로 올바른 것은?
  9. NVIDIA GPU에서 32개의 스레드를 하나의 묶음으로 하여 같은 명령을 일제히 실행하는 단위를 무엇이라 하는가?
  10. GPU의 SIMT(단일 명령·다중 스레드) 방식과 CPU의 SIMD 명령의 차이로 올바른 것은?
  11. 하나의 워프 안에서 조건 분기에 의해 스레드의 절반이 if 쪽, 나머지 절반이 else 쪽으로 갈라졌다(워프 다이버전스). 일반적으로 어떻게 실행되는가?
  12. 위의 (1)과 (2)는 모두 스레드의 절반에 A, 나머지에 B를 실행시킨다. 워프 효율 측면에서 올바른 설명은? (1워프=32스레드로 한다)
  13. GPU의 메모리 병합 접근(코얼레싱)에 대한 설명으로 올바른 것은?
  14. 각 스레드의 번호를 i로 하여, 위와 같이 32요소 간격으로 배열을 읽으면 a[i]를 읽는 경우보다 느려진다. 주된 이유는?
  15. 입자의 위치 x, y, z를 가진 데이터를 GPU에서 처리할 때, 메모리 병합 접근 측면에서 유리한 배치는?
  16. CUDA 공유 메모리(shared memory)의 특징으로 올바른 것은?
  17. CUDA의 __syncthreads()의 역할로 올바른 것은?
  18. CUDA에서 __syncthreads()를 "if (threadIdx.x < 16)" 안에 써서 일부 스레드만 통과하도록 했다. 일어날 수 있는 일로 올바른 것은?
  19. CUDA 공유 메모리의 뱅크 충돌에 대한 설명으로 올바른 것은?
  20. 32×32 float 표를 공유 메모리에 두고 워프의 32개 스레드로 열 방향(세로)으로 읽으면 뱅크 충돌이 발생한다. 자주 사용되는 대책은?
  21. GPU에서 큰 행렬의 곱을 계산할 때, 행렬을 작은 타일로 나누어 공유 메모리에 읽어 들이는 이유로 올바른 것은?
  22. GPU 커널에서 스레드당 레지스터 사용량이 너무 많을 때 일어날 수 있는 일로 올바른 것은?
  23. GPU의 점유율(occupancy)에 대한 설명으로 올바른 것은?
  24. GPU가 메모리의 긴 지연(수백 클럭)을 숨기는 주된 방법으로 올바른 것은?
  25. GPU의 점유율에 대해 올바른 것은?
  26. CUDA에서 블록과 SM(스트리밍 멀티프로세서)의 관계로 올바른 것은?
  27. CUDA에서 커널 도중에 다른 모든 블록의 계산이 끝나기를 기다린 뒤 다음 단계로 진행하고 싶다. 일반적인 방법은?
  28. GPU에서 픽셀 값의 히스토그램을 만들 때, 모든 스레드가 글로벌 메모리의 256개 빈(bin)에 atomicAdd로 직접 더하면 느린 경우가 있다. 개선 방법으로 올바른 것은?
  29. GPU에서 다수 값의 총합을 구할 때, 트리 형태의 리덕션(이웃끼리 더해 절반으로 줄이는 것을 반복)을 사용하는 이유로 올바른 것은?
  30. 1024개의 값을 트리 형태의 리덕션으로 합산할 때 필요한 단계 수는 몇 개인가?
  31. 외장 GPU를 사용하는 프로그램에서 CPU 측 메모리와 GPU 측 메모리에 대해 일반적으로 올바른 것은?
  32. 배열 요소를 한 번만 더하는 가벼운 처리를 위해 데이터를 GPU로 보내면 CPU에서 계산하는 것보다 느려지는 경우가 있다. 주된 이유는?
  33. CPU 메모리를 핀 고정(페이지 락)한 뒤 GPU로 전송하면 빨라지는 이유로 올바른 것은?
  34. CUDA 스트림을 여러 개 사용하는 주된 목적은?
  35. 매우 작은 커널을 수천 번 연속으로 실행하는 프로그램이 느릴 때, 개선 방법으로 가장 적절한 것은?
  36. CUDA 유니파이드 메모리(통합 메모리)에 대한 설명으로 올바른 것은?
  37. GPU에서 두 개의 큰 배열의 요소별 덧셈(c[i] = a[i] + b[i])을 수행할 때, 성능을 주로 결정하는 것은?
  38. 가정용 게임 GPU 대부분에서 배정밀도(FP64) 연산 성능이 단정밀도(FP32)보다 훨씬 낮은(수십 분의 일 등) 이유로 가장 적절한 것은?
  39. 최근 GPU에 탑재된 텐서 코어(행렬 연산 유닛)의 특징으로 올바른 것은?
  40. GPU의 혼합 정밀도 계산에서 곱셈은 FP16 등 낮은 정밀도로, 합산(누적)은 FP32로 하는 경우가 많은 이유로 올바른 것은?
  41. GPU에서 같은 데이터의 부동소수점수 총합을 구했더니, 실행할 때마다 결과의 마지막 자릿수가 미세하게 달랐다. 가장 가능성이 높은 원인은?
  42. CUDA에서 블록당 스레드 수를 정할 때의 일반적인 기준으로 올바른 것은?
  43. 위와 같은 루프(그리드 스트라이드 루프)로 커널을 작성할 때의 이점으로 올바른 것은?
  44. CUDA 상수 메모리(constant memory)가 특히 빠르게 동작하는 것은 어떤 접근일 때인가?
  45. GPU 캐시에 대해 CPU와 비교한 일반적인 특징으로 올바른 것은?
  46. NVIDIA 이외의 GPU에서도 사용할 수 있는, GPU 등의 병렬 계산을 위한 프로그래밍 체계의 예로 올바른 것은?
  47. GPU에서 조건에 맞는 요소만 배열에서 골라 다른 배열에 채워 넣어 출력하고 싶다(각 스레드의 출력 수는 0 또는 1). 각 스레드의 쓰기 위치 주소를 정하는 데 자주 사용되는 병렬 계산은?
  48. GPU 커널을 작성할 때 지켜야 할 전제로 올바른 것은?
  49. GPU에서 큰 행렬을 전치(b[j][i] = a[i][j])할 때, 공유 메모리를 경유시키는 주된 목적은?
  50. CUDA에서 CPU 측 프로그램이 커널을 실행한 직후의 동작으로 일반적으로 올바른 것은?

이 분야의 비교

  • CPU와 GPU의 구조와 용도 차이CPU와 GPU를 표로 비교합니다. 설계 목표, 코어 수, 실행 모델, 캐시, 메모리 대역폭, 분기 처리, 데이터 전송, 대표 워크로드를 다룹니다.
