성능 분석: 핵심 정리

프로그램의 속도는 실행된 명령어 수, 명령어당 평균 사이클 수(CPI), 사이클 시간의 곱입니다. 한 요소를 개선해도 다른 요소가 나빠지면 프로그램은 빨라지지 않습니다. 암달의 법칙에 따르면 프로그램의 일부만 빠르게 해서는 나머지 부분이 전체 속도 향상의 상한을 결정합니다.

성능을 올바르게 비교하려면 벤치마크를 고르고, 측정하고, 결과를 평균하는 방법에 주의해야 합니다. 이 주제는 CPU 성능 카운터로 캐시 미스와 분기 예측 실패를 세거나, 루프라인 모델로 연산과 메모리 중 어느 쪽이 한계인지 판별하는 등 병목을 분리하는 방법을 다룹니다.

성능 분석 전체 문제 (50)
  1. 프로그램의 CPU 실행 시간을 나타내는 기본 식으로 올바른 것은?
  2. 10억 개의 명령어를 실행하는 프로그램을 평균 CPI 2, 클럭 주파수 2 GHz인 CPU에서 실행했다. 실행 시간은 얼마입니까?
  3. CPU 설계 변경으로 클럭 주파수는 1.5배가 되었지만 CPI도 1.2배로 늘었다(명령어 수는 동일). 실행 속도는 원래의 몇 배가 됩니까?
  4. 컴파일러의 새로운 최적화로 실행하는 명령어 수는 20% 줄었지만 평균 CPI가 10% 늘었다(주파수는 동일). 이 최적화의 효과로 올바른 것은?
  5. 어떤 프로그램의 명령어 비율이 정수 연산 50%(CPI 1), 로드와 스토어 30%(CPI 2), 분기 20%(CPI 5)였다. 평균 CPI는 얼마입니까?
  6. CPU 성능을 '1초당 실행할 수 있는 명령어 수(MIPS)'로 비교할 때의 주의점으로 올바른 것은?
  7. 성능 개선을 나타내는 '속도 향상률(스피드업)'을 구하는 방법으로 올바른 것은?
  8. 전체 처리의 50%를 차지하는 부분을 4배 빠르게 했다. 전체의 속도 향상률은 얼마입니까?(암달의 법칙)
  9. 전체 처리의 60%를 차지하는 부분만 빠르게 하여 전체를 2배 빠르게 하고 싶다. 그 부분을 몇 배 빠르게 해야 합니까?
  10. 암달의 법칙에서 얻을 수 있는 성능 개선 방법에 대한 교훈으로 가장 적절한 것은?
  11. 구스타프슨의 법칙이 나타내는 사고방식으로 올바른 것은?
  12. 병렬 계산 평가에서 말하는 '강한 스케일링'과 '약한 스케일링'의 차이로 올바른 것은?
  13. 컴퓨터 성능을 벤치마크로 평가할 때의 사고방식으로 가장 적절한 것은?
  14. SPEC CPU와 같은 표준 벤치마크에 대한 설명으로 올바른 것은?
  15. 여러 벤치마크의 기준 컴퓨터 대비 속도 비를 종합할 때 기하 평균이 자주 사용되는 이유로 올바른 것은?
  16. 같은 수의 명령어를 가진 두 프로그램을 하나는 초당 1000 MIPS, 다른 하나는 500 MIPS의 속도로 연속해서 실행했다. 전체 평균 속도는 얼마입니까?
  17. 위와 같은 작은 루프로 계산 속도를 측정했더니 N을 크게 해도 시간이 거의 0이었다. 가장 가능성이 높은 원인은?
  18. 프로그램의 실행 시간을 측정할 때 같은 측정을 여러 번 반복하고 처음 몇 번의 결과를 제외하는 경우가 많은 이유로 올바른 것은?
  19. 매우 짧은 처리의 시간을 한 번만 측정하려 할 때의 문제와 대책의 조합으로 올바른 것은?
  20. 실행 시간 측정 방법 중 '벽시계 시간'과 'CPU 시간'의 차이로 올바른 것은?
  21. 서버 성능을 나타내는 처리량(스루풋)과 지연 시간(레이턴시)에 대한 설명으로 올바른 것은?
  22. 웹 서비스의 응답 시간을 평가할 때 평균값뿐 아니라 99퍼센타일 값(느린 쪽 1%의 경계)을 보는 경우가 많은 이유로 올바른 것은?
  23. 어떤 서버에 초당 100건의 요청이 도착하고, 1건의 처리에 평균 0.2초가 걸린다(정상 상태로 한다). 서버 안에서 동시에 처리 중인 요청은 평균 몇 건입니까?(리틀의 법칙)
  24. 서버의 사용률(바쁜 시간의 비율)이 100%에 가까워지면 요청의 대기 시간은 어떻게 됩니까?
  25. 프로그램 성능을 개선할 때 프로파일러를 사용하는 목적으로 올바른 것은?
  26. 샘플링 방식 프로파일러의 특징으로 올바른 것은?
  27. 함수의 입구와 출구에 시간을 측정하는 코드를 넣어 기록하는 계측(인스트루멘테이션) 방식 프로파일러에 대해 올바른 것은?
  28. 프로그램 성능 분석에서 말하는 핫스팟에 대한 설명으로 올바른 것은?
  29. 프로파일 결과를 나타내는 플레임 그래프의 읽는 법으로 올바른 것은?
  30. CPU에 내장된 성능 카운터(PMU)로 셀 수 있는 것의 예로 올바른 것은?
  31. 성능 카운터로 측정했더니 어떤 프로그램의 IPC(1사이클당 명령어 수)가 0.3으로 매우 낮고 최종 단계 캐시 미스가 많았다. 가장 가능성이 높은 상황과 대책의 조합은?
  32. 성능 카운터로 분기 예측 실패가 매우 많다는 것을 알았다. 개선 방법에 해당하는 것은?
  33. 성능 카운터를 사용한 톱다운 분석(Top-down Microarchitecture Analysis)에서 CPU의 명령어 처리 슬롯 사용 방식을 나누는 큰 분류로 올바른 것은?
  34. 프로그램이 느린데 CPU 사용률이 20% 정도로 낮았다. 가장 가능성이 높은 원인은?
  35. 어떤 프로그램이 연산 바운드인지 메모리 바운드인지 확인하는 방법으로 CPU 주파수를 바꿔 실행 시간을 측정했다. 메모리 바운드라면 일반적으로 어떤 결과가 나옵니까?
  36. 루프라인(Roofline) 모델에서 어떤 처리가 메모리 대역폭으로 제한되는 영역에 있음을 알았을 때, 성능을 높이는 방향으로 올바른 것은?
  37. STREAM 벤치마크로 주로 측정하는 것은?
  38. 병렬 프로그램의 확장성(스케일러빌리티)을 조사하는 방법으로 가장 적절한 것은?
  39. 8코어로 병렬 실행했더니 1코어일 때보다 6배 빨라졌다. 병렬 효율은 얼마입니까?
  40. 성능을 측정하기 위한 장치를 넣은 탓에 측정하려는 프로그램의 동작 자체가 바뀌어 버리는 현상을 무엇이라고 합니까?
  41. 프로그램 성능을 개선할 때의 진행 방식으로 가장 적절한 것은?
  42. 대량의 데이터를 처리하는 프로그램에서 가장 큰 속도 향상을 얻을 가능성이 높은 개선은?
  43. 소프트웨어 개발에서 변경할 때마다 벤치마크를 자동으로 실행하여 결과를 기록해 두는 목적으로 올바른 것은?
  44. 노트북에서 벤치마크를 측정했더니 같은 프로그램인데도 결과가 매번 크게 흔들렸다. CPU 측의 원인으로 생각할 수 있는 것과 그 대책의 조합으로 올바른 것은?
  45. 멀티코어나 NUMA 시스템에서 성능을 측정할 때 스레드를 특정 코어에 고정하는(어피니티를 설정하는) 경우가 있는 이유로 올바른 것은?
  46. GPU를 사용하는 프로그램의 성능을 분석할 때 가장 먼저 확인해야 할 것으로 가장 적절한 것은?
  47. 데이터센터에서 서버를 선택할 때 피크 성능 외에 고려해야 할 관점이 아닌 것은?
  48. '새로운 방법으로 100배 빨라졌다'는 주장을 평가할 때 확인해야 할 점으로 가장 적절한 것은?
  49. SSD 성능을 연속 읽기 대역폭(MB/s)뿐 아니라 4 KB 랜덤 읽기의 IOPS(초당 입출력 횟수)로도 나타내는 경우가 많은 이유로 올바른 것은?
  50. 배열 크기를 조금씩 키우면서 배열을 반복해서 읽는 처리의 요소당 시간을 측정하면, 어떤 크기마다 시간이 단계적으로 늘어난다. 그 이유로 올바른 것은?
