암호 기술의 기초와 응용: 핵심 정리

암호는 알고리즘이 안전한 것만으로는 쓸모가 없습니다. 같은 논스를 두 번 사용하거나, ECB 모드로 암호화하거나, 인증서의 호스트 이름을 확인하지 않는 등의 사용상 실수로 강한 암호도 쉽게 뚫립니다. 여기서는 암호가 실제 시스템과 프로토콜 안에서 어떻게 조합되어 쓰이는지를 한 단계 깊이 학습합니다.

먼저 대칭 키 암호로서 블록 암호와 스트림 암호, AES의 블록 길이와 키 길이, 블록 암호 운용 모드(ECB·CBC·CTR·GCM)와 초기화 벡터·논스의 조건, 패딩과 패딩 오라클 공격, 인증 암호화(AEAD)를 다루고, CTR 모드에서 논스를 재사용했을 때 평문이 새어 나가는 모습을 계산으로 확인합니다. 이어서 SHA-2와 SHA-3, 길이 확장 공격과 HMAC, 생일 공격에 의한 블록 길이 64비트의 한계, 키 유도 함수를 학습하고, RSA 암호와 디피-헬먼 키 교환을 작은 수로 계산하여 이산 로그 문제, 중간자 공격, 타원 곡선 암호의 키 길이 기준, 전방향 안전성, ECDSA의 난수 취급을 확인합니다. 후반에서는 인증 기관과 인증서 체인, 호스트 이름 확인, 인증서 투명성, TLS 1.3의 변경점과 암호 스위트, 0-RTT의 리플레이, 상호 TLS를 다루고, 양자 내성 암호로서 그로버 알고리즘과 키 길이, 2024년 8월에 표준화된 ML-KEM·ML-DSA·SLH-DSA, 키 캡슐화 메커니즘, 하이브리드 키 교환, 이행 시기에 대한 사고방식을 학습합니다. 마지막으로 HSM, 봉투 암호화, 키 로테이션, 암호 민첩성 같은 키 관리를 확인합니다. IT 자격시험의 보안 분야 학습에도 도움이 됩니다. 계산 문제의 값은 오답 선택지의 값도 포함하여 Python으로 계산해 확인했습니다. 대칭 키 암호와 공개 키 암호의 기본, 키 개수 계산, 해시 함수의 성질과 비밀번호 저장, 디지털 서명과 MAC의 차이는 '정보 보안 기초', 사이드 채널 공격과 상수 시간 구현, AES-NI, TPM, 진성 난수 생성기는 '하드웨어 보안', 쇼어 알고리즘과 양자 컴퓨터의 규모는 '양자 컴퓨터의 하드웨어', TLS의 왕복 횟수와 HTTPS로 보호되는 것은 '네트워크 기초', JWT와 OAuth는 '웹 기술 기초', 엔트로피는 '정보 이론과 부호의 기초' 분야에서 다룹니다.

  1. 대칭 키 암호 중 블록 암호와 스트림 암호의 차이에 대한 설명으로 올바른 것은?

  3. 이미지 데이터를 AES의 ECB 모드로 암호화했더니, 암호화한 후의 이미지에서도 원래 그림의 윤곽을 알아볼 수 있었다. 이 원인으로 올바른 것은?
  4. AES를 CBC 모드로 사용할 때 초기화 벡터(IV)의 취급으로 적절한 것은?

  6. CBC 모드로 암호화한 데이터를 받는 서버가, 복호화한 후의 패딩이 올바르지 않을 때와 패딩은 올바르지만 내용 검사에 실패했을 때 서로 다른 오류를 돌려주고 있었다. 이 상황에 대한 설명으로 올바른 것은?
  7. 블록 암호의 CTR 모드(카운터 모드)의 특징으로 올바른 것은?
  8. CTR 모드에서 실수로 같은 키와 같은 논스를 사용해 두 메시지를 암호화했다. 어떤 위치의 바이트에 대해 첫 번째 평문 P₁은 01001000(ASCII의 'H'), 그 암호문 C₁은 01110100, 두 번째 암호문 C₂는 01010101이다. 공격자가 P₁을 알고 있을 때, 같은 위치의 두 번째 평문 P₂는?
  9. AES-GCM 같은 인증 암호화(AEAD)가 하나의 처리로 제공하는 것으로 올바른 것은?
  10. AES-GCM에서 사용하는 96비트 논스(IV)에 대한 설명으로 올바른 것은?
  11. 어떤 장치에서 56비트 키를 모두 시도하는 무차별 대입에 약 20시간이 걸린다. 같은 장치에서 64비트 키를 모두 시도하는 데 걸리는 시간에 가장 가까운 것은?
  12. 해시 함수 SHA-2와 SHA-3에 대한 설명으로 올바른 것은?
  13. 비밀 키 K와 메시지 m을 이은 값의 해시값 SHA-256(K ‖ m)을 변조 검출용 태그로 사용하는 것은 위험하다고 여겨진다. 그 이유로 올바른 것은?
  14. 1 GiB = 2³⁰바이트, 1 EiB = 2⁶⁰바이트로 한다. 블록 길이가 64비트인 블록 암호(3DES 등)를 CBC 모드로 사용하여, 하나의 키로 대량의 데이터를 암호화한다. 암호문 블록을 무작위 64비트 값으로 간주할 때, 생일 역설에 의해 같은 암호문 블록 쌍이 나타날 확률을 무시할 수 없게 되는 데이터양의 기준은?
  15. TLS 1.3 등의 프로토콜에서 ECDHE 키 교환으로 얻은 공유 비밀을 그대로 암호 키로 사용하지 않고, HKDF 같은 키 유도 함수(KDF)를 거쳐 키를 만드는 이유로 적절한 것은?
  16. RSA 암호의 구조를 작은 수로 확인한다. 소수 p = 5, q = 11로부터 n = pq를 만들고, 공개 지수를 e = 3으로 한다. φ(n) = (p − 1)(q − 1)이라 할 때, e × d ≡ 1 (mod φ(n))을 만족하는 비밀 지수 d(0 < d < φ(n))는?
  17. RSA 암호에서 공개 키를 n = 55, e = 3으로 한다. 평문 m = 7을 c = m^e mod n으로 암호화했을 때의 암호문 c는?
  18. 교과서 그대로의 RSA 암호(평문 m을 그대로 c = m^e mod n으로 하는 방식)를 패딩을 붙이지 않고 실제 통신에 사용하는 것의 문제점으로 올바른 것은?
  19. 디피-헬먼 키 교환에서는 소수 p와 생성원 g를 공개하고, A 씨와 B 씨가 각각 비밀 값 a, b를 골라 g^a mod p와 g^b mod p를 서로 보낸다. 도청자가 이렇게 공개된 값을 모두 보더라도 공유 비밀 g^(ab) mod p를 구할 수 없다고 생각되는 이유로 올바른 것은?
  20. 디피-헬먼 키 교환을 작은 수로 확인한다. p = 23, g = 5로 하고, A 씨는 비밀 값 a = 6, B 씨는 비밀 값 b = 15를 고른다. A 씨는 A = g^a mod p를, B 씨는 B = g^b mod p를 서로 보낸다. 두 사람이 얻는 공유 비밀은?
  21. 인증을 하지 않는 디피-헬먼 키 교환의 약점과 그 대책의 조합으로 올바른 것은?
  22. NIST SP 800-57의 표에서 128비트 대칭 키 암호(AES-128)와 같은 정도의 안전성 기준으로 여겨지는 RSA 암호의 키 길이(n의 비트 수)와 타원 곡선 암호의 키 길이의 조합은?
  23. TLS에서 서버 인증서의 개인 키가 나중에 유출되더라도 그 이전에 기록된 통신은 복호화되지 않는 성질(전방향 안전성)을 얻을 수 있는 키 교환 방법은?
