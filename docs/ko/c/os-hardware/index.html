OS와 하드웨어: 핵심 정리

운영체제(OS)는 여러 프로그램이 CPU, 메모리, I/O 장치 같은 하드웨어를 안전하게 공유할 수 있게 하는 소프트웨어입니다. 이를 지원하기 위해 CPU는 OS만 사용할 수 있는 특권 모드, 인터럽트와 예외 메커니즘, 가상 메모리를 위해 페이지 테이블을 탐색하는 하드웨어를 제공합니다.

애플리케이션은 시스템 콜로 OS에 서비스를 요청하고, OS는 타이머 인터럽트로 프로그램을 전환하며(컨텍스트 스위치), 페이지 폴트가 발생하면 필요한 페이지를 메모리로 가져옵니다. 디바이스 드라이버와 메모리 맵 I/O부터 하이퍼바이저에 의한 가상화까지, 이 주제는 하드웨어와 소프트웨어가 협력하는 방식을 다룹니다.

OS와 하드웨어 전체 문제 (50)

  1. CPU에 특권 모드(커널 모드)와 사용자 모드를 두는 주된 목적은 무엇입니까?
  2. 애플리케이션이 파일 읽기/쓰기 등을 OS에 요청하는 구조를 무엇이라고 합니까?
  3. 위의 RISC-V 코드에서 마지막 ecall 명령이 실행되었을 때 일어나는 일로 올바른 것은 무엇입니까?
  4. 인터럽트와 예외의 차이에 대한 일반적인 설명은 무엇입니까?
  5. 다음 중 명령 실행과 무관하게 언제 발생할지 정해져 있지 않은 비동기 요인은 무엇입니까?
  6. CPU가 인터럽트를 받아들였을 때의 일반적인 처리 흐름으로 올바른 것은 무엇입니까?
  7. 인터럽트 벡터 테이블의 역할로 올바른 것은 무엇입니까?
  8. 중요한 처리 도중에 일시적으로 인터럽트를 금지(마스크)할 때의 주의점으로 올바른 것은 무엇입니까?
  9. 인터럽트 핸들러의 처리를 곧바로 수행하는 짧은 부분과 나중에 일반 컨텍스트에서 수행하는 나머지 부분으로 나누는 이유로 올바른 것은 무엇입니까?
  10. 페이지 테이블의 역할로 올바른 것은 무엇입니까?
  11. 페이지 폴트가 발생하는 경우로 올바른 것은 무엇입니까?
  12. 내보내져 디스크에 있는 페이지에 접근하여 페이지 폴트가 발생했을 때 OS가 수행하는 처리 흐름으로 올바른 것은 무엇입니까?
  13. 페이지 테이블을 1단이 아닌 다단(계층형)으로 만드는 주된 이유는 무엇입니까?
  14. 가상 주소가 32비트, 페이지 크기가 4 KB, 페이지 테이블의 한 항목이 4바이트일 때, 1단 페이지 테이블의 크기는 얼마입니까?
  15. 가상 주소 중 48비트를 사용하고, 페이지 크기 4 KB, 각 단의 표가 512개 항목(9비트)인 다단 페이지 테이블에서는 몇 단의 표를 따라가야 합니까?
  16. 페이지 테이블의 각 항목에 보통 포함되는 정보의 조합으로 올바른 것은 무엇입니까?
  17. 프로세스를 복제할 때 카피 온 라이트(copy-on-write)를 사용하는 이점으로 올바른 것은 무엇입니까?
  18. 디맨드 페이징에 대한 설명으로 올바른 것은 무엇입니까?
  19. 페이지 교체의 클락(clock) 방식(세컨드 찬스 방식)에서 각 페이지의 참조 비트를 사용하는 목적은 무엇입니까?
  20. 페이지 교체에서 FIFO 방식을 사용하면 물리 메모리의 페이지 수를 늘렸는데도 페이지 폴트가 늘어나는 경우가 있습니다. 이 현상을 무엇이라고 합니까?
  21. 물리 메모리가 부족하여 페이지를 내보내고 읽어 들이는 일만 계속되어 처리가 거의 진행되지 않는 상태를 무엇이라고 합니까?
  22. 메모리 접근 시간이 100 ns, 페이지 폴트 처리에 8 ms가 걸리고, 100만 번에 한 번 페이지 폴트가 발생할 때 평균 접근 시간은 대략 얼마입니까?
  23. 컨텍스트 스위치에서 전환하기 전의 프로세스에 대해 저장해 두어야 하는 것은 무엇입니까?
  24. 프로세스의 컨텍스트 스위치가 레지스터를 저장하고 복원하는 시간보다 실제로는 더 큰 성능 저하를 일으키는 경우가 있습니다. 그 주된 이유는 무엇입니까?
  25. TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 이점으로 올바른 것은 무엇입니까?
  26. OS가 스스로 CPU를 내놓지 않는 프로그램에서도 일정 시간마다 CPU를 되찾아 다른 프로세스로 전환할 수 있는 것은 주로 어떤 구조 덕분입니까?
  27. 위와 같이 장치의 상태 레지스터를 메모리 맵 I/O로 읽을 때 volatile을 붙이고 그 영역을 캐시하지 않도록 설정하는 이유로 올바른 것은 무엇입니까?
  28. 장치의 상태를 인터럽트를 쓰지 않고 CPU가 반복해서 조사하는 방식(폴링)이 유리한 경우는 무엇입니까?
  29. 캐시 일관성을 하드웨어가 유지하지 않는(비코히런트) 시스템에서, 장치가 DMA로 주기억장치에 쓴 데이터를 CPU가 읽기 전에 소프트웨어가 해야 하는 처리는 무엇입니까?
  30. IOMMU의 주된 역할로 올바른 것은 무엇입니까?
  31. 디바이스 드라이버의 역할로 올바른 것은 무엇입니까?
  32. 일반적인 OS에서 애플리케이션이 장치의 레지스터를 직접 읽고 쓰지 못하게 하는 주된 이유는 무엇입니까?
  33. 한 대의 컴퓨터 위에서 여러 OS를 각각 독립된 가상 머신으로 동시에 실행하기 위한 소프트웨어를 무엇이라고 합니까?
  34. 하이퍼바이저의 유형에 대한 설명으로 올바른 것은 무엇입니까?
  35. 중첩 페이징(2단 주소 변환)을 사용한 가상화에서 하드웨어가 수행하는 주소 변환에 대한 설명으로 올바른 것은 무엇입니까?
  36. 게스트도 호스트도 4단 페이지 테이블을 사용하는 중첩 페이징에서 TLB 미스가 발생했을 때, 최악의 경우 몇 번의 메모리 접근이 필요합니까?
  37. 가상 머신의 OS가 특권이 필요한 명령을 실행했을 때 하이퍼바이저로 처리가 넘어가고, 하이퍼바이저가 그 명령의 효과를 대신 재현하는 방식을 무엇이라고 합니까?
  38. 준가상화(paravirtualization)에 대한 설명으로 올바른 것은 무엇입니까?
  39. 컨테이너와 가상 머신의 차이로 올바른 것은 무엇입니까?
  40. 많은 OS에서 커널 영역을 각 프로세스의 주소 공간 일부(예를 들어 상위 범위)에 할당해 두고, 페이지 테이블의 보호 비트로 사용자 모드에서의 접근을 금지합니다. 이 배치의 주된 이점은 무엇입니까?
  41. 페이지 크기가 4 KB일 때, 가상 주소 중 페이지 내 위치(오프셋)를 나타내는 것은 몇 비트입니까?
  42. 페이지 크기가 4 KB일 때, 32비트 가상 주소 0x00403ABC의 페이지 번호와 페이지 내 오프셋의 조합으로 올바른 것은 무엇입니까?
  43. RISC-V 특권 아키텍처에서 정해진 주요 동작 모드의 조합으로 올바른 것은 무엇입니까?
  44. 인터럽트나 예외 처리를 마치고 원래 프로그램으로 돌아갈 때, 일반 함수의 복귀 명령이 아니라 전용 복귀 명령(RISC-V의 sret, mret 등)을 사용하는 이유는 무엇입니까?
  45. 실시간성이 요구되는 시스템에서, 인터럽트가 발생하고 나서 핸들러가 동작하기 시작할 때까지의 시간(인터럽트 지연)을 크게 만드는 요인으로 가장 적절한 것은 무엇입니까?
  46. NMI(마스크 불가능 인터럽트, non-maskable interrupt)에 대한 설명으로 올바른 것은 무엇입니까?
  47. 여러 코어를 가진 시스템에서 OS가 어떤 페이지의 페이지 테이블 항목을 고쳐 써서 대응을 취소했을 때 필요한 처리로 올바른 것은 무엇입니까?
  48. 프로그램이 OS가 할당하지 않은 주소에 접근했을 때 일반적으로 일어나는 일은 무엇입니까?
  49. 파일을 메모리에 대응시키는(mmap과 같은) 구조에서 파일 내용을 읽을 때 일어나는 일에 대한 설명으로 올바른 것은 무엇입니까?
  50. 작은 데이터를 1바이트씩 쓸 때, 매번 시스템 콜을 호출하는 것보다 사용자 공간의 버퍼에 모았다가 한꺼번에 쓰는 편이 빠른 주된 이유는 무엇입니까?
