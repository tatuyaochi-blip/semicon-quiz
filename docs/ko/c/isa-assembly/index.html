ISA와 어셈블리: 핵심 정리

명령어 집합 구조(ISA)는 소프트웨어와 하드웨어 사이의 약속입니다. 어떤 명령어가 있는지, 비트로 어떻게 인코딩되는지, 레지스터와 메모리를 어떻게 지정하는지를 정의합니다. 같은 ISA를 따르는 CPU라면 내부 구조가 아무리 달라도 같은 프로그램을 실행할 수 있습니다.

어셈블리 언어는 기계어 명령어를 사람이 읽을 수 있는 형태로 쓴 것입니다. RISC-V의 핵심 명령어, 레지스터 사용법, 함수 간에 인자와 반환값을 전달하는 방법(호출 규약), 스택 프레임의 구성을 알면 컴파일러가 무엇을 생성하는지, 프로그램이 CPU에서 실제로 어떻게 실행되는지 알 수 있습니다.

ISA와 어셈블리 전체 문제 (50)

  1. 동일한 명령어 집합 아키텍처(ISA)를 채택한 두 CPU에 대해 올바른 것은?
  2. RISC-V와 같은 로드-스토어 아키텍처의 특징으로 올바른 것은?
  3. RISC-V의 레지스터 x0(zero)의 성질로 올바른 것은?
  4. RISC-V의 RV32I(32비트 기본 정수 명령어 집합)가 가진 범용 정수 레지스터로 올바른 것은?
  5. 어셈블리 언어와 기계어의 관계로 올바른 것은?
  6. RISC-V의 의사 명령어 'nop'(아무것도 하지 않음)은 어셈블러에 의해 실제로 어떤 명령어로 치환되는가?
  7. RISC-V의 'add' 명령어와 'addi' 명령어의 차이로 올바른 것은?
  8. 위의 RISC-V 코드를 실행한 후 레지스터 a2의 값은 얼마인가?
  9. RISC-V 명령어 'lw t0, 8(sp)'의 동작으로 올바른 것은?
  10. RISC-V의 조건 분기 명령어 'beq a0, a1, label'에서 분기 대상 label의 주소는 어떻게 표현되는가?
  11. 분기나 점프에 PC 상대 주소 지정을 사용하는 것의 이점으로 올바른 것은?
  12. RISC-V의 기본 명령어와 x86 명령어의 길이에 대해 올바른 것은?
  13. 명령어 길이를 고정 길이로 하는 것의 이점으로 가장 적절한 것은?
  14. RISC-V 명령어에서는 레지스터를 지정하는 필드(rd, rs1, rs2)가 각각 5비트이다. 그 이유로 올바른 것은?
  15. RISC-V addi 명령어의 즉치값은 12비트 부호 있는 정수이다. 이 즉치값으로 나타낼 수 있는 범위는?
  16. RISC-V에서 12비트 즉치값에 들어가지 않는 32비트 상수(예: 0x12345678)를 레지스터에 넣는 일반적인 방법은?
  17. RISC-V에서 상수 0x12345FFF를 lui와 addi의 2개 명령어로 만들 때 올바른 조합은?
  18. RISC-V의 auipc 명령어(add upper immediate to PC)의 동작으로 올바른 것은?
  19. RISC-V(RV32I)에서 'addi t0, zero, -1'을 실행한 후 t0에 들어 있는 32비트 값은?
  20. 메모리 상의 1바이트에 0x80이 들어 있다. RISC-V의 lb 명령어와 lbu 명령어로 이 바이트를 32비트 레지스터에 읽어 들였을 때의 값의 조합으로 올바른 것은?
  21. 조건 분기 구조에 대해 RISC-V와 x86의 차이로 올바른 것은?
  22. RISC-V 명령어 'slt t0, a0, a1'의 동작으로 올바른 것은?
  23. 위의 RISC-V 코드를 실행 완료했을 때 t0의 값은 얼마인가?
  24. RISC-V의 조건 분기 명령어(B 형식)는 분기 대상까지의 거리를 13비트 부호 있는 바이트 수로 나타내며, 그 최하위 비트는 항상 0이므로 명령어에 넣지 않는다. 분기 명령어가 직접 닿는 범위로 대략 올바른 것은?
  25. RISC-V 명령어 'jal ra, func'의 동작으로 올바른 것은?
  26. RISC-V의 의사 명령어 'ret'은 실제로 어떤 명령어로 실행되는가?
  27. 호출 규약(콜링 컨벤션)이 정해져 있는 주된 목적은?
  28. RISC-V의 표준 호출 규약에서 정수 인자와 반환값을 전달하는 데 사용하는 레지스터로 올바른 것은?
  29. RISC-V의 표준 호출 규약에서 정수 인자가 10개인 함수를 호출할 때 9번째와 10번째 인자는 어디로 전달되는가?
  30. RISC-V 호출 규약에서 s0~s11이 '호출 대상 저장(callee-saved)' 레지스터라는 의미로 올바른 것은?
  31. RISC-V 호출 규약에서 t0~t6은 '호출 원본 저장(caller-saved)' 레지스터이다. 어떤 함수가 t0에 넣은 값을 다른 함수를 호출한 뒤에도 사용하고 싶을 때 올바른 대응은?
  32. 다른 함수를 호출하지 않는 함수(리프 함수)에서는 ra를 스택에 저장하지 않아도 되는 경우가 많다. 그 이유로 올바른 것은?
  33. RISC-V 함수의 시작 부분에서 'addi sp, sp, -16'을 실행하는 목적으로 올바른 것은?
  34. RISC-V의 표준 호출 규약에서는 함수에 진입할 때의 스택 포인터 sp를 16바이트의 배수로 맞추게 되어 있다. 그 이유로 가장 적절한 것은?
  35. 위의 코드는 어떤 함수의 시작 부분(프롤로그)이다. 이 부분이 하고 있는 일로 올바른 것은?
  36. 함수 안에서 프레임 포인터(RISC-V에서는 s0/fp)를 사용하는 이점으로 올바른 것은?
  37. RISC-V에서 자기 자신을 호출하는 재귀 함수를 작성할 때 ra를 스택에 저장하는 것을 잊으면 어떻게 되는가?
  38. 리틀 엔디안 RISC-V에서 0x12345678이 들어 있는 레지스터를 'sw'로 주소 0x100에 썼다. 그 후 'lbu'로 주소 0x101의 1바이트를 읽으면 값은 얼마인가?
  39. RISC-V에서 4바이트를 읽는 lw 명령어의 주소가 4의 배수가 아닐 때(경계가 맞지 않을 때) 일어날 수 있는 일로 올바른 것은?
  40. RISC-V 명령어 'slli t0, a0, 3'의 결과 t0는 a0 값의 몇 배가 되는가? (오버플로는 고려하지 않음)
  41. a0에 int형(4바이트) 배열 a의 시작 주소, a1에 첨자 i가 들어 있다. 위의 코드가 a2에 읽어 들이는 것으로 올바른 것은?
  42. x86의 명령어 'add eax, [rbx]'처럼 연산 명령어가 메모리 상의 값을 직접 사용할 수 있는 방식에 대해 올바른 것은?
  43. 현재의 고성능 x86 CPU가 복잡한 명령어를 내부에서 어떻게 실행하는지에 대한 설명으로 올바른 것은?
  44. RISC-V의 M 확장이 기본 정수 명령어 집합에 추가하는 명령어는?
  45. RISC-V의 C 확장(압축 명령어)의 주된 목적은?
  46. M 확장이 없는 RV32I CPU용으로 C 언어의 'a * b'(int끼리의 곱셈)를 컴파일하면 일반적으로 어떻게 되는가?
  47. 예전 MIPS 등에 있었던 분기 지연 슬롯(분기 명령어 직후의 1개 명령어는 분기 여부와 관계없이 실행되는 규칙)에 대해 올바른 것은?
  48. 64비트 RV64I에서 lw 명령어를 실행하면 읽어 들인 32비트 값은 64비트 레지스터에 어떻게 들어가는가?
  49. ABI(애플리케이션 바이너리 인터페이스)에 대한 설명으로 올바른 것은?
  50. C 언어의 함수 포인터를 사용한 호출 '(*fp)(x)'는 RISC-V에서 일반적으로 어떤 명령어로 이루어지는가?
