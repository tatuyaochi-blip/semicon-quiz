클라우드와 컨테이너의 기초

컨테이너를 실현하는 네임스페이스와 cgroups, 이미지와 레이어와 카피 온 라이트, Dockerfile의 명령(RUN·CMD·ENTRYPOINT·COPY), 빌드 캐시와 명령의 순서, 포트 공개, 볼륨과 바인드 마운트, 태그와 다이제스트, 멀티 스테이지 빌드, Kubernetes의 Pod·Deployment·Service·Ingress·Secret, 조정(reconcile)과 롤링 업데이트, readiness/liveness 프로브, 오토 스케일링 계산, requests와 limits, 공동 책임 모델, 가용 영역, 서버리스, 스토리지의 종류, 종량 과금과 예약의 손익분기점, 데이터 전송 요금, IaC, 이뮤터블 인프라스트럭처, 블루-그린과 카나리, 관측 가능성을 객관식 문제로 학습합니다.

클라우드와 컨테이너의 기초: 핵심 정리

웹 서비스나 사내 시스템의 상당수는 이제 클라우드 위에서, 컨테이너로 묶은 애플리케이션으로 동작합니다. 컨테이너는 호스트 OS의 커널을 공유하면서 프로세스를 격리하는 구조로, Docker로 이미지를 만들고 Kubernetes 같은 기반으로 다수의 머신에 배치하여 개수를 유지하고 업데이트합니다.

여기서는 네임스페이스와 cgroups, 이미지의 레이어와 카피 온 라이트, Dockerfile의 명령과 빌드 캐시, 포트 공개, 볼륨과 바인드 마운트, 태그와 다이제스트, 멀티 스테이지 빌드에서 시작하여 Kubernetes의 Pod·Deployment·Service·Ingress·Secret, 바람직한 상태의 선언과 조정(reconcile), 롤링 업데이트의 계산, readiness 프로브와 liveness 프로브, HorizontalPodAutoscaler의 계산, requests와 limits와 Pod의 배치를 다룹니다. 이어서 클라우드의 공동 책임 모델, 리전과 가용 영역, 서버리스와 콜드 스타트, 블록·파일·오브젝트 스토리지, 종량 과금 요금과 예약의 손익분기점, 데이터 전송 요금, IaC와 이뮤터블 인프라스트럭처, 블루-그린 배포와 카나리 릴리스, 산출물을 한 번만 빌드하는 사고방식, 환경 변수에 의한 설정, 관측 가능성을 확인합니다. 계산 문제의 값은 오답 선택지의 값까지 포함하여 Python으로 계산해 확인했습니다. 가격은 모두 가상의 값입니다. 하이퍼바이저와 컨테이너와 가상 머신의 차이는 'OS와 하드웨어', IaaS·PaaS·SaaS, 스케일 아웃, 이중화, 라이브 마이그레이션, CDN은 '시스템 구성과 신뢰성 설계', 로드 밸런서와 세션은 '웹 기술 기초', CI/CD는 '소프트웨어 개발과 프로젝트 관리', SLA는 '서비스 관리와 시스템 감사', 셸과 환경 변수는 'Linux와 커맨드 라인 기초' 분야에서 다룹니다.

  8. 위의 Dockerfile로 만든 이미지 pinger를 docker run pinger example.com으로 시작했다. 컨테이너 안에서 실행되는 명령으로 올바른 것은?

  10. 위의 Dockerfile(B)은 COPY . . 뒤에 RUN npm ci를 두었던 Dockerfile(A)을, 의존성 파일만 먼저 복사하는 순서로 바꾼 것이다. npm ci에는 120초, npm run build에는 30초, COPY . .에는 2초가 걸리고, 다른 명령의 시간은 무시할 수 있다고 하자. 하루에 20회, src 아래의 소스 코드만 바꾸어(package.json과 package-lock.json은 바꾸지 않고) 이미지를 다시 만든다. 이전 빌드의 캐시를 사용할 수 있을 때, 하루 빌드 시간의 합계에서 B가 A보다 짧아지는 시간으로 올바른 것은?
  11. Docker에서 컨테이너가 쓴 데이터를 남기기 위한 명명된 볼륨과 바인드 마운트의 설명으로 올바른 것은?

  14. Kubernetes에서 배포하고 관리하는 최소 단위로, 하나 이상의 컨테이너를 묶어 같은 IP 주소와 볼륨을 공유하게 하는 것은?
  15. Kubernetes에서 replicas: 3을 지정한 Deployment의 Pod가 3개 동작하고 있다. 이 중 하나의 Pod를 kubectl delete pod로 삭제했을 때 일어나는 일로 올바른 것은?
