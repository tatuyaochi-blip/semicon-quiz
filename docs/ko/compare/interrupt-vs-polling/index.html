인터럽트 vs 폴링: 차이점과 사용 시기

프로세서가 장치에 처리가 필요하다는 것을 알아내는 방법은 두 가지입니다. 폴링에서는 CPU가 루프를 돌며 장치 상태를 계속 확인합니다. 인터럽트에서는 장치가 CPU에 신호를 보내고, CPU는 하던 일을 잠시 멈추고 작은 핸들러를 실행한 뒤 다시 재개합니다. 폴링은 단순하고 예측 가능하지만 시간을 낭비하고, 인터럽트는 효율적이고 응답이 빠르지만 오버헤드가 있고 프로그램의 동작을 파악하기가 더 어렵습니다.

비교 항목폴링인터럽트
동작 방식CPU가 상태 레지스터를 반복해서 읽어 장치가 준비되었는지 확인장치가 신호를 올리면 CPU가 작업을 중단하고 인터럽트 핸들러(ISR)를 실행
대기 중 CPU 사용바쁨: CPU가 확인하는 데 사이클을 소모여유: CPU가 다른 작업을 하거나 슬립할 수 있음
응답 시간루프의 확인 주기에 따라 결정되며 예측 가능빠름(마이크로초 단위)이지만 마스킹, 우선순위, 컨텍스트 저장에 따라 달라짐
오버헤드아무 일이 없어도 일정하게 발생이벤트마다 비용 발생; 이벤트 발생률이 매우 높으면 CPU가 감당하지 못할 수 있음(인터럽트 폭주)
복잡도작성과 디버깅이 간단더 복잡함: 핸들러는 짧아야 하고, 메인 코드와 공유하는 데이터는 주의가 필요함(volatile, 원자적 접근)
전력CPU를 계속 깨워 둠이벤트가 CPU를 깨울 때까지 저전력 슬립 가능
타이밍 특성파악하기 쉬움핸들러와 메인 코드 사이에 동시성 버그가 생길 수 있음
주요 용도매우 빠르거나 연속적인 이벤트, 단순한 프로그램, 고속 네트워크 드라이버타이머, 버튼, 통신 이벤트, 센서 알림, 슬립에서 깨우기

수치는 대략적인 자릿수 기준이며, 공정 세대와 제품에 따라 달라져요.

상황별 선택 기준

폴링
이벤트가 빈번하거나 루프가 단순하며, 핸들러의 복잡성 없이 예측 가능한 타이밍을 원할 때.
인터럽트
이벤트가 드물거나 예측할 수 없고, 빠른 응답과 저전력이 필요하며, CPU가 다른 일을 할 수 있을 때.
혼합
일부 시스템은 둘을 결합합니다. 인터럽트로 첫 이벤트를 알리고, 트래픽이 많은 동안에는 드라이버가 폴링하는 방식으로, 고속 네트워크 드라이버가 그 예입니다.

자주 묻는 질문

인터럽트와 폴링 중 어느 쪽이 더 좋은가요?

항상 한쪽이 좋은 것은 아닙니다. 인터럽트는 빠른 응답을 주고 CPU를 슬립시킬 수 있으며, 폴링은 단순하고 예측 가능합니다. 드문 이벤트에는 인터럽트를, 매우 빈번한 이벤트에는 폴링을 쓰세요.

인터럽트 핸들러는 무엇을 해야 하나요?

짧아야 합니다. 최소한의 일만 하고, 플래그를 설정하거나 작업을 큐에 넣은 뒤 반환하세요. 핸들러 안의 긴 작업이나 블로킹 호출은 응답성을 해칩니다.

인터럽트 폭주란 무엇인가요?

이벤트가 너무 빨리 도착해서 CPU가 핸들러에 진입하고 나오는 데 모든 시간을 쓰는 상황입니다. 이럴 때 고속 네트워크 드라이버는 폴링으로 전환합니다.

인터럽트가 전력을 절약하는 이유는 무엇인가요?

CPU가 계속 깨어 확인하는 대신, 이벤트가 깨울 때까지 슬립할 수 있기 때문입니다.

이해도 확인

주변 회로의 상태를 파악하는 방법 중 폴링과 인터럽트의 차이로 올바른 것은 무엇입니까?

  1. A폴링은 CPU가 상태를 반복해서 확인하러 가고, 인터럽트는 상태가 바뀌었을 때 주변 회로가 CPU에 알린다
  2. B폴링과 인터럽트는 같은 것이다
  3. C인터럽트는 CPU가 상태를 반복해서 확인하러 가는 방식이다
정답과 해설 보기

정답: A. 폴링은 CPU가 상태를 반복해서 확인하러 가고, 인터럽트는 상태가 바뀌었을 때 주변 회로가 CPU에 알린다

폴링은 구조가 단순하고 확인하는 간격이 정해져 있어 동작을 예측하기 쉬운 반면, 아무 일이 없어도 CPU가 계속 확인하므로 시간과 전력을 낭비합니다. 인터럽트는 변화가 있을 때만 CPU가 응답하므로, 기다리는 동안 다른 처리를 하거나 잠들 수 있습니다. 다만 인터럽트가 매우 빈번하면 오히려 처리 오버헤드가 커지므로 적절히 구분해서 사용하는 것이 중요합니다.

인터럽트 핸들러 안에서 피해야 할 것으로 가장 적절한 것은 무엇입니까?

  1. A플래그 변수에 1을 써서 메인 처리에 알리는 것
  2. B인터럽트 원인을 나타내는 비트를 지우는 것
  3. Cprintf로 긴 문자열을 출력하거나 무언가가 일어날 때까지 계속 기다리는 루프와 같은 시간이 오래 걸리는 처리
정답과 해설 보기

정답: C. printf로 긴 문자열을 출력하거나 무언가가 일어날 때까지 계속 기다리는 루프와 같은 시간이 오래 걸리는 처리

인터럽트 핸들러가 오래 동작하면 그동안 다른 인터럽트에 응답하지 못하고 메인 처리도 멈춥니다. printf는 출력이 끝날 때까지 시간이 걸리고 내부에서 인터럽트를 사용하기도 하므로 특히 위험합니다. 핸들러에서는 데이터를 받아 버퍼에 넣거나 플래그를 세우는 등 최소한의 처리만 하고, 무거운 처리는 메인 처리나 태스크에 맡깁니다. 원인 비트를 지우는 것도 잊어서는 안 됩니다.

인터럽트에 우선순위를 줄 수 있는 마이크로컨트롤러에서, 우선순위가 낮은 인터럽트의 핸들러를 실행 중에 우선순위가 높은 인터럽트가 발생했습니다. 일반적으로 어떻게 됩니까? (인터럽트 중첩을 허용하는 설정으로 가정)

  1. A낮은 핸들러를 중단하고 높은 핸들러를 실행한 뒤, 끝나면 낮은 핸들러의 이어지는 부분으로 돌아간다
  2. B낮은 핸들러가 끝날 때까지 높은 인터럽트는 버려진다
  3. C두 핸들러가 동시에 같은 CPU에서 병렬로 실행된다
정답과 해설 보기

정답: A. 낮은 핸들러를 중단하고 높은 핸들러를 실행한 뒤, 끝나면 낮은 핸들러의 이어지는 부분으로 돌아간다

인터럽트에 우선순위를 주면 급한 인터럽트는 다른 핸들러를 실행하는 도중에도 끼어들어 처리됩니다. 예를 들어 모터의 과전류 검출을 높은 우선순위로, 통신 수신을 낮은 우선순위로 해 두면 수신 처리 중에도 과전류에 즉시 대응할 수 있습니다. Arm Cortex-M의 NVIC 등이 이 구조를 가지고 있습니다. 같거나 낮은 우선순위의 인터럽트는 현재 핸들러가 끝날 때까지 기다리게 됩니다.

  1. 인터럽트 핸들러의 처리를 즉시 수행하는 짧은 부분과 나중에 일반 컨텍스트에서 수행하는 나머지 부분으로 나누는 이유로 올바른 것은?
  2. 메인 처리에서 레지스터 비트를 'reg |= mask;'(읽기-수정-쓰기)로 조작하는 도중에 인터럽트 핸들러가 같은 레지스터의 다른 비트를 바꾸면 발생할 수 있는 문제와 대책의 조합으로 올바른 것은 무엇입니까?
  3. 16 MHz 클럭을 프리스케일러로 16분주한 것으로 타이머를 세고, 1000카운트마다 인터럽트가 발생하도록 설정했습니다. 인터럽트 간격은 얼마입니까?

임베디드 시스템과 펌웨어 문제 풀기

주요 용어 설명

인터럽트(Interrupt)
외부 기기의 요청 등에 따라 실행 중인 처리를 일시 중단하고 해당 처리를 우선 수행하는 CPU의 메커니즘. 끝나면 원래 처리로 돌아간다.
폴링(polling)
CPU가 주변 회로의 상태를 반복해서 확인하며 변화를 찾아내는 방식. 단순하지만 아무 일이 없어도 계속 확인하므로 시간과 전력을 소모한다.
인터럽트 핸들러
인터럽트나 예외가 발생했을 때 CPU가 실행하는 처리. 중단된 처리의 상태를 저장하고 원인에 맞는 처리를 한 뒤 원래 처리로 돌아간다. 처리는 가능한 한 짧게 하는 것이 원칙.

  • MCU vs MPU: 마이크로컨트롤러와 마이크로프로세서 비교MCU와 MPU를 표로 비교합니다: 집적도, 클록 속도, 메모리, 운영체제, 실시간성, 전력, 부팅 시간, 비용, 대표 용도.
  • I2C, SPI, UART의 차이와 선택 기준I2C, SPI, UART를 표로 비교합니다. 배선 수, 클록, 속도, 토폴로지, 주소 지정, 오류 검사, 마이크로컨트롤러 프로젝트에서의 대표 용도를 다룹니다.
  • DMA vs 프로그램 방식 I/O: 차이점 설명DMA와 프로그램 방식 I/O(PIO)를 표로 비교합니다: 데이터를 옮기는 주체, CPU 부하, 처리량, 설정 비용, 복잡도, 버스 사용, 주요 용도.
  • CPU와 GPU의 구조와 용도 차이CPU와 GPU를 표로 비교합니다. 설계 목표, 코어 수, 실행 모델, 캐시, 메모리 대역폭, 분기 처리, 데이터 전송, 대표 워크로드를 다룹니다.
  • Verilog와 VHDL: 두 HDL의 차이점Verilog와 VHDL을 표로 비교합니다. 기원, 문법, 타입 체계, 대소문자 구분, 검증 기능, 사용층, 선택 방법을 다룹니다.
  • NVMe와 SATA SSD: 속도, 인터페이스, 선택 기준NVMe와 SATA SSD를 표로 비교합니다. 인터페이스, 속도, 지연 시간, 명령 큐, 폼팩터, 전력, 호환성, 가격, 각각에 알맞은 사용자를 다룹니다.
