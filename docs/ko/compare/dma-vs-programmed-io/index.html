DMA vs 프로그램 방식 I/O: 차이점 설명

장치와 메모리 사이에서 데이터를 옮기는 방법은 두 가지입니다. 프로그램 방식 I/O(PIO)에서는 CPU가 직접 레지스터를 통해 모든 워드를 읽고 씁니다. 직접 메모리 접근(DMA)에서는 DMA 컨트롤러가 스스로 데이터를 옮기고, CPU는 전송을 설정하기만 하며 완료되면 통지를 받습니다. DMA는 CPU를 해방하고 대용량 전송을 훨씬 빠르게 처리하지만, 더 많은 설정과 주의가 필요합니다.

비교 항목프로그램 방식 I/O(PIO)DMA
데이터를 옮기는 주체CPU가 load와 store 명령으로 워드 단위로 옮김DMA 컨트롤러 또는 장치 자체가 메모리와 직접 주고받음
CPU 부하높음: 전송하는 내내 CPU가 바쁨낮음: CPU는 전송을 설정하고 다른 작업을 함
대용량 전송 처리량CPU 속도에 제한됨높음
설정 오버헤드없음주소, 길이 또는 디스크립터, 완료 처리가 필요
소량 전송설정이 없어서 더 빠른 경우가 많음설정 비용이 이점보다 클 수 있음
복잡도단순더 복잡함: 디스크립터 링, 버퍼 정렬, 캐시 일관성, IOMMU 설정
메모리 버스 사용CPU를 거침DMA 엔진이 CPU와 메모리 대역폭을 두고 경쟁
주요 용도작은 제어 레지스터, 단순한 센서, 레거시 PIO 모드SSD와 NVMe, 네트워크 카드, 오디오 버퍼, ADC 샘플 스트림, GPU 전송

수치는 대략적인 자릿수 기준이며, 공정 세대와 제품에 따라 달라져요.

상황별 선택 기준

PIO
전송이 아주 작거나 드물고, CPU 시간보다 단순함이 중요할 때.
DMA
전송이 크거나 연속적이어서 CPU를 묶어 두고 싶지 않을 때: 스토리지, 네트워킹, 스트리밍 데이터.
주의
DMA에서는 장치가 읽기 전이나 쓴 후에 CPU 캐시와 메모리가 일치하도록 해야 합니다(캐시를 flush 또는 invalidate하거나 일관성 있는 메모리를 사용).

자주 묻는 질문

DMA가 CPU 부하를 줄이는 이유는 무엇인가요?

DMA 컨트롤러가 데이터를 직접 옮기므로, CPU는 전송을 설정하기만 하고 완료되면 통지를 받기 때문입니다.

DMA가 항상 더 빠른가요?

아닙니다. 아주 작은 전송에서는 설정 비용이 이점보다 클 수 있어 프로그램 방식 I/O가 더 빠를 수 있습니다.

DMA 디스크립터 링이란 무엇인가요?

메모리에 있는 디스크립터의 링으로, 각 디스크립터가 하나의 버퍼를 기술합니다. 네트워크 카드와 NVMe 드라이브처럼 장치와 드라이버가 이 링을 통해 버퍼를 주고받습니다.

DMA에서 캐시 일관성이 중요한 이유는 무엇인가요?

장치가 메모리를 직접 읽고 쓰기 때문에 CPU 캐시에 오래된 데이터가 남아 있을 수 있습니다. 소프트웨어가 캐시를 flush 또는 invalidate하거나 일관성 있는 메모리를 사용해야 합니다.

이해도 확인

네트워크 카드나 NVMe SSD 등에서 널리 사용되는, 메모리 상 디스크립터(기술자)의 링 구조를 이용한 DMA 방식에 대해 올바른 것은?

  1. ACPU가 데이터를 1바이트씩 기기의 레지스터에 써서 전송한다
  2. BCPU는 전송 주소와 길이를 디스크립터에 써서 기기에 알리기만 하고, 기기가 디스크립터를 읽어 스스로 전송을 진행한다
  3. C디스크립터는 기기 내부에만 있고 CPU에서는 보이지 않는다
정답과 해설 보기

정답: B. CPU는 전송 주소와 길이를 디스크립터에 써서 기기에 알리기만 하고, 기기가 디스크립터를 읽어 스스로 전송을 진행한다

디스크립터 링은 메인 메모리 상에 늘어놓은 "어느 주소에서 몇 바이트를 보낼 것인가"를 적은 표를 고리처럼 사용하는 구조입니다. CPU는 비어 있는 디스크립터에 전송 내용을 쓰고, 기기 레지스터에 "여기까지 썼다"고 한 번 알립니다. 기기는 DMA로 디스크립터를 읽고 데이터를 전송하며, 끝난 디스크립터에 완료 표시를 합니다. CPU와 기기가 서로 기다리지 않고 많은 전송을 진행할 수 있습니다.

마이크로컨트롤러에서 AD 컨버터의 변환 결과를 일정한 간격으로 대량으로 가져올 때 DMA를 사용하는 이점으로 올바른 것은 무엇입니까?

  1. AAD 컨버터의 분해능이 자동으로 올라간다
  2. B입력 전압이 자동으로 커진다
  3. C변환이 끝날 때마다 CPU가 인터럽트로 읽을 필요 없이 DMA가 메모리에 나열해 주므로 CPU의 부담이 줄어든다
정답과 해설 보기

정답: C. 변환이 끝날 때마다 CPU가 인터럽트로 읽을 필요 없이 DMA가 메모리에 나열해 주므로 CPU의 부담이 줄어든다

변환할 때마다 인터럽트로 CPU가 결과를 읽으면, 1초에 수만 번 가져오는 경우 인터럽트 오버헤드만으로 CPU 시간의 상당 부분이 쓰입니다. DMA를 사용하면 변환이 끝날 때마다 DMA가 결과를 메모리 배열에 차례로 쓰고, 배열이 가득 찼을 때만 CPU에 알립니다. 타이머로 변환을 시작하도록 설정하는 것과 조합하면, 정확한 간격으로 데이터를 CPU 없이 계속 가져올 수 있습니다.

캐시 일관성을 하드웨어가 유지하지 않는(비코히런트) 시스템에서, 장치가 DMA로 주기억장치에 쓴 데이터를 CPU가 읽기 전에 소프트웨어가 수행해야 하는 처리는?

  1. ACPU의 클록 주파수를 일시적으로 낮춘다
  2. B해당 범위의 캐시 내용을 무효화하여 주기억장치에서 다시 읽도록 한다
  3. C캐시 내용을 모두 주기억장치에 되쓴 후 DMA로 도착한 결과를 폐기한다
정답과 해설 보기

정답: B. 해당 범위의 캐시 내용을 무효화하여 주기억장치에서 다시 읽도록 한다

DMA는 CPU를 거치지 않고 장치와 주기억장치 사이에서 데이터를 전송하므로, 하드웨어가 일관성을 유지하지 않는 시스템에서는 CPU 캐시에 그 범위의 오래된 데이터가 남아 있을 수 있습니다. 그대로 읽으면 DMA로 도착한 새 데이터가 아니라 오래된 값을 읽게 됩니다. 그래서 드라이버는 읽기 전에 그 범위의 캐시를 무효화하여 주기억장치에서 새 값을 읽게 합니다. 반대로 장치로 보낼 데이터는 DMA를 시작하기 전에 캐시에서 되써 둡니다.

주요 용어 설명

DMA(직접 메모리 접근)
CPU를 거치지 않고 주변 장치와 메모리 사이에서 직접 데이터를 전송하는 구조. 대량의 데이터 전송 중에도 CPU가 다른 처리를 진행할 수 있다.
인터럽트(Interrupt)
외부 기기의 요청 등에 따라 실행 중인 처리를 일시 중단하고 해당 처리를 우선 수행하는 CPU의 메커니즘. 끝나면 원래 처리로 돌아간다.

관련 비교

  • NVMe와 SATA SSD: 속도, 인터페이스, 선택 기준NVMe와 SATA SSD를 표로 비교합니다. 인터페이스, 속도, 지연 시간, 명령 큐, 폼팩터, 전력, 호환성, 가격, 각각에 알맞은 사용자를 다룹니다.
  • PCIe 3.0 vs 4.0 vs 5.0 vs 6.0: 속도와 차이점PCIe 3.0, 4.0, 5.0, 6.0을 표로 비교합니다: 전송률, 레인당 및 x4, x16 링크 대역폭, 인코딩, 시그널링, 주요 장치.
  • NRZ와 PAM4의 차이점 정리NRZ와 PAM4를 표로 비교합니다. 심볼당 비트 수, 같은 비트레이트에서의 보 레이트, 아이 개구와 SNR, FEC의 필요성, 회로, 사용되는 규격의 세대를 다룹니다.
  • 싱글엔드 신호와 차동 신호의 차이점 정리싱글엔드 신호와 차동 신호를 표로 비교합니다. 배선 수, 기준 전압, 노이즈 내성, 방사 노이즈, 진폭과 속도, 배선 설계, 대표 규격을 안내합니다.
  • MCU vs MPU: 마이크로컨트롤러와 마이크로프로세서 비교MCU와 MPU를 표로 비교합니다: 집적도, 클록 속도, 메모리, 운영체제, 실시간성, 전력, 부팅 시간, 비용, 대표 용도.
  • 인터럽트 vs 폴링: 차이점과 사용 시기인터럽트와 폴링을 표로 비교합니다: 동작 방식, CPU 사용, 지연 시간, 오버헤드, 복잡도, 전력, 임베디드 및 운영체제에서의 주요 용도.
