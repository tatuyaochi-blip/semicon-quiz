프로세스 vs 스레드: 차이점 설명

프로세스는 자체 전용 주소 공간과 자원을 가진 실행 중인 프로그램입니다. 스레드는 프로세스 안의 실행 단위입니다. 한 프로세스의 모든 스레드는 메모리를 공유하므로 생성 비용이 낮고 통신이 빠르지만, 버그나 크래시 하나가 프로세스 전체에 영향을 줄 수 있습니다. 별개의 프로세스끼리는 서로 격리되어 더 안전하지만, 생성과 프로세스 간 통신에 더 많은 비용이 듭니다.

비교 항목프로세스스레드
정의자체 주소 공간, 파일, 기타 자원을 가진 실행 중인 프로그램프로세스 내부의 실행 경로로, 자체 스택과 레지스터를 가짐
메모리다른 프로세스와 격리된 독립적인 가상 주소 공간프로세스의 코드, 힙, 전역 데이터를 공유하며 스택만 전용
생성 비용더 무거움: 새 주소 공간을 구성해야 함(copy-on-write로 비용 감소)더 가벼움: 새 주소 공간이 필요 없음
컨텍스트 스위칭더 비쌈: 주소 공간이 바뀌고 캐시된 변환 정보(TLB)가 사라질 수 있음더 저렴함: 주소 공간과 캐시가 그대로 유지됨
통신파이프, 소켓, 공유 메모리 같은 프로세스 간 통신(IPC)이 필요공유 메모리를 직접 읽고 쓰므로 빠름
격리와 장애크래시가 보통 해당 프로세스 안에 머묾한 스레드의 크래시가 프로세스 전체를 중단시킬 수 있음
동기화프로세스가 메모리나 파일을 공유할 때 필요공유 데이터에는 항상 필요: 뮤텍스와 원자적 연산이 없으면 데이터 레이스와 데드락이 발생
스케줄링하나 이상의 스레드를 포함운영체제가 실제로 CPU 코어에 스케줄링하는 단위
대표 용도격리와 보안: 브라우저 탭, 서비스, 셸 파이프라인한 프로그램 내부의 병렬 작업: 다수의 연결을 처리하는 서버, 백그라운드 작업, 병렬 연산

수치는 대략적인 자릿수 기준이며, 공정 세대와 제품에 따라 달라져요.

상황별 선택 기준

프로세스
격리, 견고성, 보안이 필요하거나, 서로 다른 주체가 작성한 소프트웨어가 메모리를 공유하면 안 될 때.
스레드
작업끼리 데이터를 빠르게 공유해야 하고 한 프로그램 안에서 여러 CPU 코어를 활용하고 싶을 때.
주의 필요
스레드가 메모리를 공유한다는 점은 강점이자 위험입니다. 공유 데이터는 락이나 원자적 연산으로 보호하고 데드락에 유의하세요.

자주 묻는 질문

스레드는 메모리를 공유하나요?

네. 한 프로세스의 스레드는 코드, 힙, 전역 데이터를 공유합니다. 각 스레드는 자체 스택과 레지스터를 가집니다.

스레드가 프로세스보다 생성 비용이 낮은 이유는 무엇인가요?

새 프로세스는 자체 주소 공간이 필요하지만 스레드는 소속 프로세스의 주소 공간을 재사용합니다. 스레드 간 전환도 주소 공간을 바꾸지 않으므로 비용이 적게 듭니다.

스레드 하나가 크래시하면 어떻게 되나요?

스레드들이 메모리를 공유하므로 프로세스 전체가 중단될 수 있습니다. 한 프로세스의 크래시는 보통 다른 프로세스에 영향을 주지 않습니다.

스레드 대신 프로세스를 써야 하는 경우는 언제인가요?

브라우저 탭이나 독립 서비스처럼 격리와 견고성이 필요하거나, 서로 다른 부분이 다른 부분의 메모리를 손상시키지 못해야 할 때입니다.

이해도 확인

프로세스를 복제할 때 카피 온 라이트를 사용하는 장점으로 올바른 것은?

  1. A복제된 프로세스와 원래 프로세스가 기록한 내용을 항상 공유할 수 있다
  2. B기록된 페이지만 나중에 복제하므로 빠르고 메모리를 절약한다
  3. C기록할 때마다 모든 페이지를 복제하므로 데이터의 안전성이 높아진다
정답과 해설 보기

정답: B. 기록된 페이지만 나중에 복제하므로 빠르고 메모리를 절약한다

프로세스를 복제할 때 전체 메모리를 곧바로 복사하면 시간도 메모리도 많이 들고, 직후에 다른 프로그램을 읽어 들인다면 그 복사는 낭비가 됩니다. 카피 온 라이트에서는 양쪽 페이지 테이블이 같은 물리 페이지를 읽기 전용으로 가리키게 해 두고, 어느 한쪽이 쓰기를 하면 페이지 폴트가 일어나 OS가 그 페이지만 복제합니다. 기록한 내용은 공유되지 않고 각 프로세스에 따로 유지됩니다. 모든 페이지를 복제하는 것도 아닙니다.

컨텍스트 스위치에서 전환 전 프로세스에 대해 저장해 두어야 하는 것은?

  1. A그 프로세스가 사용하는 디스크 파일의 내용
  2. B레지스터 값이나 프로그램 카운터 등 CPU의 실행 상태
  3. C그 프로세스의 물리 메모리 전체 내용
정답과 해설 보기

정답: B. 레지스터 값이나 프로그램 카운터 등 CPU의 실행 상태

컨텍스트 스위치에서는 나중에 같은 상태에서 재개할 수 있도록 범용 레지스터, 프로그램 카운터, 스택 포인터, 동작 모드 등 CPU의 상태를 저장하고, 다음에 실행할 프로세스의 상태를 읽어 들입니다. 프로세스를 전환하는 경우에는 페이지 테이블의 위치를 나타내는 레지스터도 전환합니다. 메모리나 파일의 내용은 그대로 남아 있으므로 전환할 때마다 저장할 필요가 없습니다.

프로세스의 컨텍스트 스위치가 레지스터 저장·복원에 걸리는 시간보다 실제로는 더 큰 성능 저하를 초래하는 경우가 있는 주된 이유는?

  1. A전환할 때마다 CPU의 클록 주파수가 내려가기 때문에
  2. B전환할 때마다 프로그램을 디스크에서 다시 읽기 때문에
  3. C전환 후 캐시나 TLB의 미스가 늘어나기 때문에
정답과 해설 보기

정답: C. 전환 후 캐시나 TLB의 미스가 늘어나기 때문에

레지스터의 저장과 복원 자체는 짧은 시간에 끝나지만, 전환된 프로세스에게 캐시나 TLB의 내용은 이전 프로세스의 것이므로 필요한 데이터나 변환 결과를 다시 읽어 들일 때까지 미스가 계속됩니다. ASID가 없는 CPU에서는 주소 공간을 전환할 때 TLB를 비워야 하기도 합니다. 이러한 간접 비용이 직접적인 전환 시간보다 커지는 경우가 있습니다. 클록이 내려가거나 프로그램을 디스크에서 다시 읽지는 않습니다.

  1. TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 장점으로 올바른 것은?
  2. 뮤텍스(재워서 기다리는 락)와 스핀락을 비교한 설명으로 올바른 것은 무엇입니까?
  3. 데드락의 예로 올바른 것은 무엇입니까?

OS와 하드웨어 문제 풀기

주요 용어 설명

컨텍스트 스위치(context switch)
CPU에서 실행할 프로세스나 스레드를 전환하는 것. 레지스터와 프로그램 카운터 등의 상태를 저장·복원하며 프로세스 전환에서는 주소 공간도 바뀐다.
뮤텍스(Mutex)
동시에 하나의 스레드만 가질 수 있는 락. 얻지 못하면 스레드를 재워 CPU를 양보하고, 해제되면 OS가 깨우는 구현이 일반적이다.
데드락(Deadlock)
여러 스레드가 각자 자원을 쥔 채 다른 스레드가 쥔 자원을 서로 기다리며 아무도 진행하지 못하게 되는 상태. 락을 잡는 순서를 전체적으로 정하여 방지한다.

  • I2C, SPI, UART의 차이와 선택 기준I2C, SPI, UART를 표로 비교합니다. 배선 수, 클록, 속도, 토폴로지, 주소 지정, 오류 검사, 마이크로컨트롤러 프로젝트에서의 대표 용도를 다룹니다.
