스택 vs 힙 메모리: 차이점 설명

실행 중인 프로그램은 데이터를 위해 두 가지 주요 메모리 영역을 사용합니다. 스택은 함수 호출 프레임, 즉 지역 변수, 인자, 반환 주소를 담습니다. 자동으로 관리되고 매우 빠르지만 크기가 작고 각 함수 호출의 수명에 묶여 있습니다. 힙은 malloc이나 new처럼 프로그램이 명시적으로 요청한 메모리를 담으며, 해제될 때까지 유지됩니다. 힙은 유연하고 크지만 더 느리고, 메모리 누수와 단편화가 발생하는 곳입니다.

비교 항목스택힙
용도함수 호출 프레임: 지역 변수, 인자, 반환 주소함수보다 오래 살아야 하거나 크기를 미리 알 수 없는 동적 할당 데이터
할당자동: 호출과 반환 때마다 스택 포인터가 이동명시적: malloc과 free, new와 delete, 또는 가비지 컬렉터
속도매우 빠름: 포인터만 조정더 느림: 할당자가 빈 블록을 찾고 기록을 유지해야 함
수명함수가 반환될 때까지메모리가 해제(또는 가비지 컬렉션)될 때까지
크기제한적(보통 스레드당 수 메가바이트)사용 가능한 메모리에 의해서만 제한
배치보통 높은 주소에서 아래로 자람보통 낮은 주소에서 위로 자라서, 둘이 서로를 향해 자람
단편화없음가능: 할당과 해제를 반복하면 쓸 수 없는 빈틈이 남을 수 있음
스레드각 스레드가 자신만의 스택을 가짐모든 스레드가 공유하므로 할당자가 스레드 안전해야 함
흔한 오류깊은 재귀나 큰 지역 배열로 인한 스택 오버플로메모리 누수, 해제 후 사용, 이중 해제, 메모리 부족

수치는 대략적인 자릿수 기준이며, 공정 세대와 제품에 따라 달라져요.

상황별 선택 기준

스택
일반적인 지역 변수처럼 크기를 컴파일 시점에 알 수 있는 작고 수명이 짧은 데이터.
힙
큰 데이터, 실행 시점에 크기가 바뀌는 데이터, 생성한 함수보다 오래 살아야 하는 데이터.

자주 묻는 질문

스택 할당이 힙 할당보다 빠른 이유는 무엇인가요?

스택 할당은 스택 포인터만 이동하면 되지만, 힙 할당은 빈 블록을 찾고 할당자의 기록을 갱신해야 하기 때문입니다.

스택 오버플로의 원인은 무엇인가요?

깊거나 무한한 재귀, 매우 큰 지역 배열 등으로 스택을 너무 많이 사용해 스택 크기 제한을 넘기면 프로그램이 비정상 종료됩니다.

메모리 누수란 무엇인가요?

할당되었지만 해제되지 않아 재사용할 수 없는 힙 메모리입니다. 누수가 반복되면 프로그램이 점점 더 많은 메모리를 사용합니다.

스레드가 스택을 공유하나요?

아니요. 각 스레드는 자신만의 스택을 가지며, 힙은 모든 스레드가 공유합니다.

이해도 확인

프로세스의 힙과 스택을 사이에 넓은 빈 공간을 두고 반대 방향으로 늘어나는 배치로 하는 이점으로 올바른 것은 무엇입니까?

  1. A어느 쪽이 얼마나 쓸지 미리 알 수 없어도 빈 공간을 양쪽이 유연하게 나눠 쓸 수 있다
  2. B힙과 스택이 같은 주소를 동시에 사용할 수 있으므로 메모리가 2배가 된다
  3. C스택이 넘치는 일이 절대 없어진다
정답과 해설 보기

정답: A. 어느 쪽이 얼마나 쓸지 미리 알 수 없어도 빈 공간을 양쪽이 유연하게 나눠 쓸 수 있다

힙은 주소가 큰 쪽으로, 스택은 작은 쪽으로 늘어나므로 사이의 빈 공간은 힙을 많이 쓰는 프로그램에도 스택을 많이 쓰는 프로그램에도 사용할 수 있습니다. 각각에 고정된 크기를 할당하면 한쪽이 남아도 다른 쪽이 넘칠 수 있습니다. 다만 스택에는 상한이 설정되어 있는 경우가 많아, 너무 깊은 재귀는 상한을 넘어 스택 오버플로가 됩니다.

C 언어의 malloc으로 확보한 메모리는 일반적으로 프로세스의 어느 영역에서 가져옵니까?

  1. A.text 섹션
  2. B힙
  3. C.rodata 섹션
정답과 해설 보기

정답: B. 힙

힙은 프로그램 실행 중에 필요한 크기의 메모리를 확보하고, 필요 없어지면 free로 반환하는 영역입니다. 확보하는 크기나 수명을 실행 시에 정할 수 있는 것이 특징입니다. malloc은 스스로 빈 영역을 관리하고, 부족해지면 OS에 요청하여 영역을 넓힙니다(Linux에서는 brk나 mmap 시스템 콜). free를 잊으면 쓰지 않는 메모리가 계속 남는 메모리 누수가 됩니다.

Linux 등의 일반적인 프로세스 메모리 배치를 주소가 작은 쪽부터 나열한 것으로 올바른 것은 무엇입니까?

  1. A텍스트 → 데이터 → BSS → 힙 → (빈 공간) → 스택
  2. B스택 → 텍스트 → 힙 → 데이터 → BSS
  3. C힙 → 스택 → BSS → 데이터 → 텍스트
정답과 해설 보기

정답: A. 텍스트 → 데이터 → BSS → 힙 → (빈 공간) → 스택

전형적인 배치에서는 주소가 작은 쪽부터 기계어인 텍스트, 초기값이 있는 데이터, 0에서 시작하는 BSS가 놓이고, 그 위에 힙이 주소가 큰 쪽으로 늘어납니다. 스택은 주소가 큰 쪽에서 작은 쪽으로 늘어나며, 둘 사이의 넓은 빈 영역에 공유 라이브러리나 mmap 영역이 놓입니다. 실제 주소는 보안을 위해 ASLR에 의해 실행할 때마다 달라집니다.

  1. 재귀가 너무 깊어져 스택 상한을 넘었을 때 Linux 등에서 일반적으로 일어나는 일로 올바른 것은 무엇입니까?
  2. malloc과 free를 반복하는 동안, 빈 메모리의 합계는 충분한데도 큰 영역을 한꺼번에 확보할 수 없게 되는 경우가 있습니다. 이 현상을 무엇이라고 합니까?
  3. RISC-V에서 자기 자신을 호출하는 재귀 함수를 작성할 때 ra를 스택에 저장하는 것을 잊으면 어떻게 되는가?

링커, 로더, 실행 파일 문제 풀기

주요 용어 설명

스택 프레임(Stack Frame)
함수가 호출될 때마다 스택 위에 확보하는 영역. 복귀 주소, 저장한 레지스터, 지역 변수 등을 두며 함수에서 복귀할 때 해제한다.
스택 포인터(stack pointer)
스택의 현재 맨 위 번지를 가리키는 레지스터. RISC-V에서는 sp(x2). 많은 ISA에서 스택은 번지가 작은 쪽으로 자란다.
힙(Heap)
프로그램 실행 중 malloc 등으로 필요한 크기의 메모리를 확보하고 free로 반환하는 영역. 확보와 해제를 반복하면 단편화가 일어날 수 있다.
