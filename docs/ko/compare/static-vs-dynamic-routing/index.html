정적 라우팅과 동적 라우팅의 차이: 설정·장애 시 전환·부하·규모·선택 기준 비교

라우터는 라우팅 테이블을 찾아 각 패킷을 다음에 어디로 보낼지 정합니다. 경로가 테이블에 들어가는 방법은 두 가지로, 관리자가 직접 설정하는 정적 라우팅과, 라우터끼리 라우팅 프로토콜로 정보를 교환해 테이블을 자동으로 만드는 동적 라우팅이 있습니다. 정적 라우팅은 단순하고 라우터에 추가 부하가 없으며 동작을 예측하기 쉽지만, 장애 후 자동으로 전환하지 않고 네트워크가 커질수록 설정과 관리가 늘어납니다. 동적 라우팅은 OSPF나 BGP 같은 프로토콜로 경로를 자동으로 구하고, 장애 후에는 다른 경로로 전환합니다. 실제 네트워크는 출구가 하나뿐인 거점에는 정적 기본 경로를, 경로가 이중화된 곳에는 동적 라우팅을 쓰는 식으로 둘을 조합하는 경우가 대부분입니다.

경로를 정하는 방법관리자가 각 라우터에 목적지 네트워크와 다음 홉을 설정합니다라우터끼리 라우팅 프로토콜(OSPF, BGP, RIP 등)로 정보를 교환해 경로를 자동으로 구합니다
장애 시 동작자동으로 전환하지 않습니다. 이웃 라우터 너머의 장애는 알아채지 못하고, 이미 쓸 수 없는 경로를 계속 쓸 수 있습니다장애를 감지하면 다시 계산해 다른 경로로 전환합니다
라우터의 부하와 대역폭경로 정보를 교환하지 않으므로 그 때문에 CPU, 메모리, 회선 대역을 쓰지 않습니다경로 정보의 교환과 경로 계산에 CPU, 메모리, 대역을 씁니다
설정의 수고와 규모네트워크와 경로의 수에 따라 설정량과 실수의 위험이 늘어납니다. 변경할 때마다 관련된 모든 라우터를 고쳐야 합니다추가와 변경이 자동으로 퍼지므로 대규모 네트워크도 관리하기 쉽습니다. 다만 프로토콜의 설계와 설정에는 지식이 필요합니다
예측 가능성설정한 그대로 동작하므로 예측하기 쉽습니다프로토콜의 계산 결과에 따라 쓰이는 경로가 바뀔 수 있습니다
보안경로 정보를 받지 않으므로 거짓 경로를 주입당할 위험이 없습니다거짓 경로를 받아들이지 않도록 이웃 인증과 받아들일 경로의 제한(필터)이 필요합니다
관리 거리일반적으로 작은 값으로, 동적 경로보다 우선됩니다(값은 기기마다 다르며, 예: 1)프로토콜마다 정해집니다(예를 들어 OSPF에 110, RIP에 120을 쓰는 기기가 있습니다)
적합한 곳소규모 네트워크, 출구가 하나인 거점의 기본 경로, 서비스 제공자로 나가는 출구경로가 이중화된 네트워크, 거점이 많은 기업 네트워크, 인터넷의 AS 사이(BGP)

수치는 대략적인 자릿수 기준이며, 공정 세대와 제품에 따라 달라져요.

상황별 선택 기준

정적 라우팅
라우터가 적고 구성이 거의 고정된 네트워크나, 지사처럼 출구가 하나뿐이라 0.0.0.0/0 기본 경로 하나만 설정하면 충분한 거점.
동적 라우팅
라우터가 많은 네트워크나, 장애 후 자동으로 전환해야 하는 이중화된 경로가 있는 네트워크. 경로의 추가나 변경이 잦은 네트워크에도 적합합니다.

자주 묻는 질문

정적 라우팅으로도 장애 후 예비 경로로 전환할 수 있나요?

어느 정도는 가능합니다. 일반 경로보다 관리 거리를 크게 한 예비 정적 경로(플로팅 정적 경로)를 설정하면, 일반 경로가 라우팅 테이블에서 사라졌을 때만 쓰입니다. 다만 일반 경로가 사라지는 것은 라우터가 자신의 링크 다운을 알아챈 경우 등에 한정되므로, 더 먼 곳의 장애는 알아채지 못합니다. 그래서 도달 가능성을 주기적으로 확인해 경로를 지우는 기능과 조합하기도 합니다.

기본 경로(디폴트 경로)란 무엇인가요?

모든 목적지에 일치하는 0.0.0.0/0(IPv6에서는 ::/0) 같은 경로입니다. 라우터는 일치하는 경로 가운데 프리픽스가 가장 긴 것을 고르므로(롱기스트 매치), 기본 경로는 다른 경로가 일치하지 않을 때만 쓰입니다. 출구가 하나뿐인 거점에서는 목적지마다 경로를 설정하는 대신 정적 기본 경로 하나를 설정하는 것이 일반적입니다.

같은 목적지로 가는 정적 경로와 동적 경로가 있으면 어느 쪽이 쓰이나요?

프리픽스 길이가 다른 경로는 서로 다른 경로로 다루며, 전달할 때는 롱기스트 매치로 가장 긴 쪽을 고릅니다. 둘 다 같은 목적지, 같은 프리픽스 길이의 경로를 가지고 있으면 관리 거리가 작은 쪽이 라우팅 테이블에 들어갑니다. 정적 경로는 일반적으로 동적 경로보다 값이 작으므로 정적 경로가 이깁니다. 실제 값은 장비 업체마다 다릅니다.

정적 라우팅과 동적 라우팅을 함께 쓸 수 있나요?

네, 많은 네트워크가 둘을 조합합니다. 예를 들어 본사와 지사 사이는 OSPF로 경로를 교환하고, 인터넷 출구에는 정적 기본 경로를 설정한 뒤 그 기본 경로를 OSPF로 다른 라우터에 알립니다.

동적 라우팅에 대한 설명으로 올바른 것은?

  1. A관리자가 각 라우터에 경로를 수동으로 설정하며, 장애가 발생해도 설정을 바꿀 때까지 같은 경로를 계속 사용한다
  2. B라우터끼리 라우팅 프로토콜로 경로 정보를 교환하고, 장애로 경로를 쓸 수 없게 되면 자동으로 다른 경로로 전환한다
  3. C패킷마다 경로를 무작위로 선택하여 여러 경로에 부하를 균등하게 분산한다
정답과 해설 보기

정답: B. 라우터끼리 라우팅 프로토콜로 경로 정보를 교환하고, 장애로 경로를 쓸 수 없게 되면 자동으로 다른 경로로 전환한다

정적 라우팅은 관리자가 경로를 수동으로 설정하는 방법입니다. 설정이 단순하고 동작을 예측하기 쉬워 작은 네트워크나 출구가 하나뿐인 거점의 기본 경로에 적합하지만, 장애가 발생해도 자동으로는 전환되지 않습니다. 동적 라우팅에서는 라우터가 OSPF나 BGP 등의 라우팅 프로토콜로 정보를 교환하여 라우팅 테이블을 자동으로 만들고, 링크가 끊어지면 다른 경로를 다시 계산합니다. 인터넷에서는 조직의 네트워크(자율 시스템) 사이의 경로를 BGP로 교환합니다. 실제 네트워크에서는 두 가지를 조합해 사용하는 것이 일반적입니다.

지사의 라우터 R2는 본사의 라우터 R1과 10.255.0.0/30 링크로 연결되어 있으며, R1 쪽 주소는 10.255.0.1, R2 쪽은 10.255.0.2이다. R2에 본사 네트워크 192.168.1.0/24로 가는 정적 경로를 설정할 때, 다음 전달 대상(넥스트 홉)으로 지정할 주소로 적절한 것은?

  1. A10.255.0.1
  2. B10.255.0.2
  3. C192.168.1.1(R1의 본사 LAN 쪽 주소)
정답과 해설 보기

정답: A. 10.255.0.1

정적 경로에서는 목적지 네트워크와, 그곳으로 보내기 위해 다음에 넘길 라우터의 주소(넥스트 홉)를 설정합니다. 넥스트 홉은 자신이 직접 연결된 네트워크 위에 있는 이웃 라우터의 주소로 하는 것이 기본입니다. 여기서는 링크 건너편에 있는 R1의 10.255.0.1이며, R2는 ARP로 이 주소의 MAC 주소를 알아내 프레임을 보냅니다. 지사에 출구가 하나뿐인 경우에는 목적지마다 경로를 쓰는 대신 0.0.0.0/0의 기본 경로 하나만 설정하는 방법도 자주 쓰입니다.

어떤 라우터가 같은 목적지 192.168.50.0/24로 가는 경로를 OSPF와 RIP 양쪽에서 배웠다. 이 라우터에서 경로 정보원별 우선도를 나타내는 관리 거리(값이 작을수록 우선)는 OSPF가 110, RIP가 120이다. 라우팅 테이블에 들어가는 경로로 올바른 것은?

  1. A두 경로를 모두 라우팅 테이블에 넣고, 패킷마다 번갈아 사용한다
  2. BRIP의 경로만 넣는다
  3. COSPF의 경로만 넣는다
정답과 해설 보기

정답: C. OSPF의 경로만 넣는다

OSPF의 비용과 RIP의 홉 수처럼, 라우팅 프로토콜에 따라 경로의 좋고 나쁨을 나타내는 값(메트릭)의 의미가 다르므로 그대로는 비교할 수 없습니다. 그래서 같은 목적지·같은 프리픽스 길이의 경로를 여러 정보원에서 얻었을 때는, 정보원별 신뢰도인 관리 거리가 작은 쪽을 채택합니다. 여기서는 OSPF의 110이 RIP의 120보다 작으므로 OSPF의 경로가 라우팅 테이블에 들어갑니다. 직접 연결된 네트워크는 0, 정적 경로는 1처럼 사람이 설정한 것일수록 작은 값으로 하는 것이 일반적이지만, 명칭과 기본값은 기기 제조사에 따라 다릅니다.

  1. 라우터의 라우팅 테이블에 정적 경로 10.0.0.0/8(다음 전달 대상은 라우터 A, 관리 거리 1), OSPF로 배운 10.1.0.0/16(라우터 B, 110), RIP로 배운 10.1.1.0/24(라우터 C, 120)의 3개가 들어 있다. 목적지가 10.1.1.5인 패킷이 보내지는 라우터는?
  2. 라우터의 라우팅 테이블에 0.0.0.0/0(다음 전달 대상은 라우터 A), 10.0.0.0/8(라우터 B), 10.1.0.0/16(라우터 C), 10.1.2.0/24(라우터 D)의 4개 경로가 있다. 목적지가 10.1.5.9인 패킷은 어느 라우터로 보내지는가?

네트워크 설계와 운용 문제 풀기

주요 용어 설명

라우팅(경로 제어)
IP 네트워크에서 패킷을 목적지까지 전달하기 위해 어느 경로로 보낼지 정하는 것. 각 라우터는 라우팅 테이블을 가지며, 목적지 IP 주소와 가장 길게 일치하는 경로(최장 일치)를 골라 다음 라우터로 넘긴다. 라우팅 테이블은 사람이 설정하는 정적 라우팅이나, OSPF, RIP, BGP 등의 라우팅 프로토콜로 자동으로 만드는 동적 라우팅으로 만든다.
라우터(Router)
서로 다른 네트워크 사이에서 패킷을 중계하는 네트워크 계층(3계층)의 기기. 받은 패킷의 목적지 IP 주소를 라우팅 테이블과 대조하여, 다음에 넘길 라우터(넥스트 홉)와 출구 인터페이스를 정해 내보낸다. 가정용 라우터는 NAPT나 DHCP 서버, 방화벽 기능도 함께 가진다.
관리 거리(Administrative Distance)
같은 목적지·같은 프리픽스 길이의 경로를 정적 경로나 OSPF, RIP 등 여러 정보원에서 얻었을 때, 어느 것을 라우팅 테이블에 넣을지 정하기 위한 정보원별 우선도 값. 값이 작을수록 우선된다. 프리픽스 길이가 다른 경로끼리의 선택에는 쓰이지 않으며, 그쪽은 롱기스트 매치로 정해진다. 명칭과 기본값은 기기 제조사에 따라 다르다.
롱기스트 매치(최장 일치)
라우터가, 목적지 IP 주소와 일치하는 경로가 라우팅 테이블에 여러 개 있을 때 프리픽스가 가장 긴(가장 구체적인) 경로를 고르는 규칙. 예를 들어 10.0.0.0/8과 10.1.0.0/16 모두에 일치하는 목적지에는 /16 경로를 쓴다. 어디에도 일치하지 않을 때 쓰는 기본 경로(0.0.0.0/0)는 길이 0인 가장 짧은 경로에 해당한다.
OSPF(Open Shortest Path First)
Open Shortest Path First의 약자. 조직 안에서 쓰는 링크 상태형 라우팅 프로토콜. 각 라우터가 자신의 링크 상태를 퍼뜨려 네트워크의 구성을 공유하고, 다익스트라 알고리즘으로 비용 합계가 가장 작은 경로를 계산한다. 비용은 일반적으로 링크의 대역폭으로 정하며, 네트워크를 여러 에어리어로 나누어 규모가 큰 네트워크에도 대응할 수 있다.
BGP(Border Gateway Protocol)
Border Gateway Protocol의 약자. 인터넷에서 AS(자율 시스템. 인터넷 서비스 제공자 등의 조직이 관리하는 네트워크 단위) 사이에서 경로 정보를 교환하는 라우팅 프로토콜. 경로에 붙은, 거쳐 온 AS의 나열(AS_PATH) 등의 속성과 조직별 방침(정책)에 따라 경로를 고른다. 라우터끼리는 TCP 179번 포트로 접속하여 정보를 주고받는다.

  • OSPF와 BGP의 차이: IGP와 EGP·경로 선택 방식·이웃 라우터와의 연결 방식·규모 비교OSPF와 BGP를 한 장의 표로 비교합니다. 분류와 범위(IGP와 EGP), 프로토콜 방식, 경로 선택, 루프 방지, 이웃과의 연결 방식, 갱신 방식, 수렴 속도, 다루는 경로 수를 정리합니다.
  • SNMP·syslog·NetFlow의 차이: 감시로 알 수 있는 것·수집 방식·데이터 형식·프로토콜 비교네트워크 감시에 쓰는 SNMP, syslog, NetFlow(IPFIX)를 한 장의 표로 비교합니다. 알 수 있는 것, 수집 방식, 데이터 형식, 시간 단위, 알 수 없는 것, 기기와 회선의 부하…
  • STP와 RSTP의 차이: 포트의 상태와 역할·전환 속도·BPDU·호환성 비교STP(IEEE 802.1D)와 RSTP(IEEE 802.1w)를 한 장의 표로 비교합니다. 규격, 포트 상태, 포트 역할, 장애 후 복구 시간, 빠른 전환의 구조, BPDU 송신과 장애 감지, …
  • DHCPv6와 SLAAC의 차이: IPv6 주소 결정 방식·상태 관리·게이트웨이와 DNS·선택 기준 비교IPv6 주소를 자동으로 설정하는 두 방식인 DHCPv6와 SLAAC(상태 비저장 주소 자동 설정)를 한 장의 표로 비교합니다. 주소를 정하는 주체, 상태, 필요한 것, 쓰는 메시지, 기본 게이트…
  • 보안 부팅과 측정 부팅의 차이: 서명 검증·TPM 기록·증명 비교보안 부팅과 측정 부팅을 한 장의 표로 비교합니다. 무엇을 확인하는지, 멈추는지 기록하는지, 신뢰의 근간, 변조되었을 때의 동작, 필요한 것, 결과의 활용, 한계와 조합 방법을 정리합니다.
