컴파일러 vs 인터프리터 vs JIT: 차이점 설명

소스 코드를 실행하는 주요 방법은 세 가지입니다. 컴파일러(AOT, 사전 컴파일)는 실행 전에 프로그램 전체를 기계어 코드로 변환합니다. 인터프리터는 별도의 기계어 파일을 만들지 않고 프로그램을 실행하면서 읽고 수행합니다. JIT(just-in-time) 컴파일러는 처음에는 인터프리트하다가 프로그램이 실행되는 동안 자주 쓰이는 부분을 기계어 코드로 컴파일합니다. 많은 언어가 이 방식들을 혼합합니다.

비교 항목컴파일러(AOT)인터프리터JIT 컴파일러
코드 변환 시점실행 전: 프로그램 전체가 기계어 코드가 됨실행 중: 프로그램을 한 단계씩 읽고 실행실행 중: 자주 쓰이는 코드를 기계어 코드로 컴파일
시작빠르게 시작(단, 먼저 빌드 단계 필요)빌드 단계 없이 빠르게 시작처음에는 느리며 코드가 워밍업될 때까지 지속
실행 속도가장 빠르고 가장 예측 가능가장 느리며 컴파일된 코드보다 몇 배나 느린 경우가 많음워밍업 후에는 컴파일 속도에 근접하며, 실행 시점 정보를 활용해 더 빠를 때도 있음
이식성플랫폼마다 바이너리 필요이식 가능: 인터프리터가 있는 곳 어디서나 실행이식 가능한 바이트코드와 플랫폼별 런타임
오류 검출많은 오류를 컴파일 시점에 잡음문제의 줄이 실행될 때 오류가 나타남언어에 따라 다름
메모리 사용실행 시점 오버헤드가 낮음인터프리터 자체가 메모리에 상주컴파일러와 컴파일된 코드 캐시를 위한 추가 메모리
개발 사이클편집, 빌드, 실행편집 후 즉시 실행보통 편집 후 실행, 또는 바이트코드로 빌드
예시 언어C, C++, Rust, Go기본 Python(CPython), Ruby, 셸 스크립트Java(HotSpot), JavaScript(V8), C#(.NET), PyPy

수치는 대략적인 자릿수 기준이며, 공정 세대와 제품에 따라 달라져요.

상황별 선택 기준

컴파일러
운영체제, 게임, 임베디드 펌웨어처럼 성능, 작은 크기, 예측 가능한 동작이 중요할 때.
인터프리터
빠른 실험, 스크립팅, 학습처럼 속도보다 빠른 개발이 중요할 때.
JIT
웹 브라우저와 서버 애플리케이션처럼 이식 가능한 플랫폼에서 속도가 필요한 장시간 실행 프로그램.

자주 묻는 질문

Python은 컴파일 언어인가요, 인터프리터 언어인가요?

표준 구현인 CPython은 소스 코드를 바이트코드로 컴파일한 뒤 이를 인터프리트합니다. PyPy 같은 다른 구현은 더 빠른 속도를 위해 JIT 컴파일러를 추가합니다.

Java는 컴파일 언어인가요, 인터프리터 언어인가요?

둘 다입니다. Java는 사전에 바이트코드로 컴파일되고, JVM이 프로그램 실행 중에 이를 인터프리트하고 기계어 코드로 JIT 컴파일합니다.

컴파일된 코드가 더 빠른 이유는 무엇인가요?

프로그램 전체가 실행 전에 최적화된 기계어 코드로 변환되므로, 실행 시점에 인터프리트할 것이 없기 때문입니다.

JIT 컴파일러의 워밍업이란 무엇인가요?

처음에는 프로그램이 인터프리터에서 실행되고, JIT는 코드가 자주 실행되는 것을 확인한 뒤 그 핫 코드를 컴파일합니다. 그때까지는 속도가 낮습니다.

이해도 확인

컴파일러와 인터프리터의 차이로 올바른 것은?

  1. A컴파일러는 실행 전에 번역하고, 인터프리터는 읽으면서 실행한다
  2. B컴파일러는 실행하면서 한 줄씩 번역하고, 인터프리터는 실행 전에 한꺼번에 번역한다
  3. C컴파일러는 수치 계산만, 인터프리터는 문자 처리만 다룬다
정답과 해설 보기

정답: A. 컴파일러는 실행 전에 번역하고, 인터프리터는 읽으면서 실행한다

컴파일러는 프로그램 전체를 실행하기 전에 기계어 등으로 번역하고, 번역한 결과를 실행합니다. 번역에 시간이 걸리는 대신 실행은 빨라지고 최적화에도 시간을 들일 수 있습니다. 인터프리터는 프로그램을 읽으면서 해석하여 실행하므로 바로 시험해 볼 수 있는 반면 실행은 느려지기 쉽습니다. 실제로는 바이트코드로 번역한 뒤 해석하고, 자주 쓰는 부분을 JIT 컴파일하는 등 둘을 조합한 방식도 많이 사용됩니다. 다룰 수 있는 처리의 종류로 나누는 것은 아닙니다.

JIT 컴파일을 사용하는 실행 환경의 특징으로 올바른 것은?

  1. A프로그램을 실행하기 전에 모든 것을 기계어로 번역한 뒤 배포한다
  2. B실행 중에 자주 쓰는 부분을 기계어로 만들고 실행 시의 정보도 활용할 수 있다
  3. C기계어를 전혀 사용하지 않고 언제까지나 바이트코드를 한 명령씩 해석한다
정답과 해설 보기

정답: B. 실행 중에 자주 쓰는 부분을 기계어로 만들고 실행 시의 정보도 활용할 수 있다

JIT 컴파일에서는 처음에는 바이트코드를 해석하면서 실행하다가, 여러 번 실행되는 부분(핫스폿)을 발견하면 실행 중에 그 부분을 기계어로 컴파일합니다. 실제로 지나가는 분기나 전달되는 타입 같은 실행 시의 정보를 활용하여, 사전에 하는 컴파일로는 어려운 과감한 최적화를 할 수 있습니다. 가정이 빗나가면 해석 실행으로 되돌아가는 구조도 갖추고 있습니다. 사전에 모든 것을 번역하는 것은 사전(AOT) 컴파일, 해석만 계속하는 것은 순수한 인터프리터입니다.

컴파일러 내부에서 소스 언어에도 CPU에도 의존하지 않는 중간 표현(IR)을 사용하는 주된 이점은?

  1. A중간 표현을 사용하면 소스 코드를 읽지 않고도 컴파일할 수 있게 되기 때문에
  2. B중간 표현은 CPU가 그대로 실행할 수 있으므로 기계어 생성이 필요 없어지기 때문에
  3. C언어별 전단부와 CPU별 후단부를 분리할 수 있고 최적화도 공통으로 사용할 수 있기 때문에
정답과 해설 보기

정답: C. 언어별 전단부와 CPU별 후단부를 분리할 수 있고 최적화도 공통으로 사용할 수 있기 때문에

M종류의 언어와 N종류의 CPU를 지원할 때 조합마다 컴파일러를 만들면 M×N개가 필요하지만, 공통 중간 표현을 거치면 언어에서 중간 표현까지의 전단부(프런트엔드) M개와 중간 표현에서 CPU까지의 후단부(백엔드) N개로 충분합니다. 최적화의 상당 부분도 중간 표현 위에서 한 번 만들면 모든 언어와 CPU에서 사용할 수 있습니다. 중간 표현은 CPU가 그대로 실행할 수 있는 것이 아니며, 마지막에 기계어로 변환해야 합니다.

컴파일러 문제 풀기

주요 용어 설명

JIT 컴파일
프로그램 실행 중에 자주 실행되는 부분을 기계어로 컴파일하는 방식. 실행 시 정보를 이용한 최적화가 가능하다. Java와 JavaScript의 실행 환경 등에서 쓰인다.

관련 비교

  • CPU와 GPU의 구조와 용도 차이CPU와 GPU를 표로 비교합니다. 설계 목표, 코어 수, 실행 모델, 캐시, 메모리 대역폭, 분기 처리, 데이터 전송, 대표 워크로드를 다룹니다.
  • I2C, SPI, UART의 차이와 선택 기준I2C, SPI, UART를 표로 비교합니다. 배선 수, 클록, 속도, 토폴로지, 주소 지정, 오류 검사, 마이크로컨트롤러 프로젝트에서의 대표 용도를 다룹니다.
  • Verilog와 VHDL: 두 HDL의 차이점Verilog와 VHDL을 표로 비교합니다. 기원, 문법, 타입 체계, 대소문자 구분, 검증 기능, 사용층, 선택 방법을 다룹니다.
  • NVMe와 SATA SSD: 속도, 인터페이스, 선택 기준NVMe와 SATA SSD를 표로 비교합니다. 인터페이스, 속도, 지연 시간, 명령 큐, 폼팩터, 전력, 호환성, 가격, 각각에 알맞은 사용자를 다룹니다.
  • MCU vs MPU: 마이크로컨트롤러와 마이크로프로세서 비교MCU와 MPU를 표로 비교합니다: 집적도, 클록 속도, 메모리, 운영체제, 실시간성, 전력, 부팅 시간, 비용, 대표 용도.
  • 프로세스 vs 스레드: 차이점 설명프로세스와 스레드를 표로 비교합니다: 메모리, 생성 비용, 컨텍스트 스위칭, 통신, 격리, 동기화, 대표 용도.
