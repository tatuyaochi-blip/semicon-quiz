심볼 테이블(symbol table)란?

오브젝트 파일이나 실행 파일에 포함된, 함수와 변수의 이름과 번지 등의 목록. 링크와 디버깅에 쓰이며 strip으로 제거할 수 있다.

일본어 명칭: シンボルテーブル

심볼 테이블(symbol table)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 3개에 나와요.

분야: 링커, 로더, 실행 파일

엔트리에 담기는 정보

심볼 테이블의 각 엔트리는 이름이 있는 개체 하나를 기술합니다. Linux에서 쓰는 ELF(Executable and Linkable Format)에서 엔트리는 이름(문자열 테이블에 대한 오프셋), 값(주소, 또는 오브젝트 파일에서는 섹션 내 오프셋), 크기, 함수나 데이터 객체 같은 타입, 바인딩(local, global, weak), 그리고 심볼이 정의된 섹션을 기록합니다. 이 파일에서 참조되지만 정의되지 않은 심볼은 undefined로 표시되며, 링커는 다른 오브젝트 파일이나 라이브러리에서 이 참조들을 해결해야 합니다.

링커가 사용하는 방식

링크는 심볼 해석(symbol resolution)에서 시작합니다. 링커는 모든 입력 파일의 심볼 테이블을 모아, 정의되지 않은 각 참조를 정확히 하나의 정의와 대응시킵니다. 같은 이름의 강한 전역 정의가 두 개 있으면 다중 정의 오류가 나고, 약한 정의는 강한 정의에 양보하며, 정의가 없는 참조는 undefined reference 오류를 냅니다. 각 심볼의 최종 주소가 정해지면 링커는 재배치 엔트리를 처리하여, 심볼을 참조하는 모든 명령과 데이터 워드를 수정합니다. C의 static 함수 같은 로컬 심볼은 파일 간 대응에 참여하지 않습니다.

정적 심볼, 동적 심볼, strip

ELF 파일에는 두 개의 심볼 테이블이 있습니다. 전체 테이블(.symtab)은 정적 링커와 디버거가 사용하고, 동적 테이블(.dynsym)은 실행 파일과 공유 라이브러리 사이에서 적재 시 해석해야 하는 심볼만 나열합니다. strip을 실행하면 .symtab과 DWARF 줄 정보 같은 디버그 섹션이 제거되어 파일이 작아지지만, 프로그램이 .dynsym 없이는 실행될 수 없으므로 .dynsym은 남습니다. 개발자는 출시된 바이너리의 크래시도 심볼화할 수 있도록 strip 전에 디버그 정보를 별도 파일로 저장해 두는 경우가 많습니다. nm이나 readelf -s 같은 도구로 파일의 심볼을 나열할 수 있습니다.

컴파일러의 심볼 테이블

같은 용어가 컴파일러 내부의 다른 구조를 가리키기도 합니다. 의미 분석 중에 컴파일러는 각 식별자를 그 선언, 타입, 저장 위치에 대응시키는 테이블을 유지하며, 보통 중첩된 스코프별로 구성된 해시 테이블입니다. 이 지점에서 x가 어느 변수를 뜻하는지, 함수가 일치하는 인수로 선언되었는지 같은 질문에 답합니다. 이 테이블은 컴파일하는 동안에만 존재합니다. 오브젝트 파일의 심볼 테이블은 그 영속적인 출력물로, 링크, 재배치, 디버깅에 필요한 이름만 담고 있습니다.

컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?

  1. A그대로 OS에서 실행할 수 있는 완성된 프로그램이다
  2. B소스 코드를 압축한 것일 뿐이며 기계어는 포함하지 않는다
  3. C기계어를 포함하지만, 다른 파일에 있는 함수나 변수의 주소는 아직 정해지지 않았다
정답과 해설 보기

정답: C. 기계어를 포함하지만, 다른 파일에 있는 함수나 변수의 주소는 아직 정해지지 않았다

오브젝트 파일에는 그 파일의 함수를 번역한 기계어, 변수의 초기값, 정의하거나 참조하는 이름의 목록(심볼 테이블), 나중에 주소를 채울 위치의 목록(재배치 정보)이 들어 있습니다. printf처럼 다른 파일에 있는 함수를 호출하는 명령은 주소를 알 수 없으므로 임시 값인 채로 있습니다. 링커가 여러 오브젝트 파일을 모아 주소를 정하고 실행 파일을 만듭니다.

링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?

  1. A어떤 파일에서 사용되는 함수나 변수의 이름을 다른 파일에 있는 그 정의와 대응시킨다
  2. B소스 코드의 변수 이름을 짧은 이름으로 바꾸어 읽기 어렵게 한다
  3. C수학 기호를 포함한 식을 수치로 다시 계산한다
정답과 해설 보기

정답: A. 어떤 파일에서 사용되는 함수나 변수의 이름을 다른 파일에 있는 그 정의와 대응시킨다

main.c에서 sum 함수를 호출하고 sum.c에서 그 내용을 정의하면, main.o에는 'sum을 참조한다', sum.o에는 'sum을 정의한다'라는 정보가 들어갑니다. 링커는 모든 오브젝트 파일의 심볼 테이블을 모아 참조마다 대응하는 정의를 하나 찾습니다. 정의를 찾지 못하면 '정의되지 않은 참조', 둘 이상이면 '다중 정의' 오류가 됩니다.

자주 묻는 질문

실행 파일이나 오브젝트 파일의 심볼 테이블은 어떻게 보나요?

Linux에서는 nm이 한 글자 타입과 함께 심볼을 나열하고, readelf -s는 크기, 타입, 바인딩을 포함한 전체 ELF 심볼 테이블을 보여 줍니다. objdump -t도 사용할 수 있습니다.

nm 출력의 T와 U는 무슨 뜻인가요?

T는 텍스트(코드) 섹션에 정의된 심볼로 보통 전역 함수를 나타내고, U는 이 파일이 참조하지만 정의하지 않은 undefined 심볼을 나타냅니다. 소문자는 로컬 심볼을 뜻합니다.

strip한 바이너리도 디버깅할 수 있나요?

가능합니다. 다만 별도로 저장해 둔 디버그 정보나 심볼 파일을 디버거가 사용할 수 없으면, 스택 트레이스에 함수 이름 대신 주소가 표시됩니다.

해설 속 심볼 테이블(symbol table)

  • 오브젝트 파일에는 그 파일의 함수를 번역한 기계어, 변수의 초기값, 정의하거나 참조하는 이름의 목록(심볼 테이블), 나중에 주소를 채울 위치의 목록(재배치 정보)이 들어 있습니다.

    컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?

  • 링커는 모든 오브젝트 파일의 심볼 테이블을 모아 참조마다 대응하는 정의를 하나 찾습니다.

    링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?

  • 실행 파일에는 함수나 변수의 이름을 나열한 심볼 테이블이나 소스 코드 행과의 대응을 나타내는 디버그 정보가 포함되어 있는 경우가 있습니다.

    실행 파일에 strip 명령을 사용했을 때 일어나는 일로 올바른 것은 무엇입니까?
