상수 폴딩(constant folding)란?

컴파일 시점에 값이 정해지는 식을 미리 계산해 결과 상수로 바꾸는 최적화. 예를 들어 3 * 4를 12로 만든다. 실행 시 계산을 줄일 수 있다.

일본어 명칭: 定数畳み込み

상수 폴딩(constant folding)은(는) 컴파일러 등 1개 분야의 연습 문제 6개에 나와요.

분야: 컴파일러

컴파일러가 실제로 하는 일

최적화 과정에서 컴파일러는 중간 표현(IR)을 탐색해 피연산자가 모두 상수인 연산을 찾아 계산하고, 그 연산을 결과 리터럴로 대체합니다. 산술 연산, 비트 연산, 시프트, 캐스트, 비교를 모두 폴딩할 수 있습니다. 특히 비교의 폴딩은 강력합니다. 10 > 100 같은 조건이 거짓으로 확정되면 그 조건이 지키는 분기는 결코 실행되지 않습니다. 컴파일러는 보통 폴딩과 함께 대수적 단순화를 수행해 x * 1이나 x + 0 같은 식을 x로 바꾸지만, 엄밀히는 x 자체가 상수가 아니므로 이는 별개의 변환입니다.

전파, 인라이닝, 데드 코드 제거와의 연계

상수 폴딩은 단독으로 작동하는 경우가 드뭅니다. 상수 전파는 상수를 갖는 것으로 알려진 변수의 사용처를 그 상수로 대체해 폴딩의 새로운 기회를 만들고, 폴딩 결과는 다시 전파될 수 있습니다. 예를 들어 n = 8; m = n * 2; return m + 1은 return 17로 축약되고, 그 후 데드 코드 제거가 사용되지 않는 대입을 제거합니다. 인라이닝도 이 순환에 기여합니다. 호출 sq(6)이 본체로 대체되면 6 * 6 + 1이 37로 폴딩됩니다. SSA 형식 기반 컴파일러는 전파, 폴딩, 도달 불가능한 분기 제거를 희소 조건부 상수 전파(sparse conditional constant propagation)라는 하나의 알고리즘으로 결합하는 경우가 많습니다.

프로그램의 의미 보존

폴딩한 결과는 타깃 머신이 실행 시 계산했을 값과 정확히 같아야 합니다. 따라서 컴파일러는 타깃의 정수 폭과 랩어라운드를 에뮬레이션해야 하며, 이는 64비트 호스트에서 32비트 타깃으로 크로스 컴파일할 때 중요합니다. 부동소수점 폴딩은 각 연산에 대해 소스 순서대로 IEEE 754 반올림을 재현해야 하므로, 컴파일러는 fast-math 같은 옵션이 허용하지 않는 한 부동소수점 식의 결합 순서를 바꾸지 않습니다. 정수 0 나누기처럼 폴트를 일으킬 연산은 그 코드가 확실히 실행되는 경우가 아니라면 컴파일 오류로 바꿔서는 안 됩니다.

상수 폴딩과 언어 수준의 상수식

컴파일 시점 계산 중 일부는 최적화기가 선택하는 것이 아니라 언어가 요구하는 것입니다. C에서는 배열 크기, case 레이블, 정적 변수의 초기화식이 상수식이어야 하며, C++의 constexpr 함수는 요청에 따라 컴파일 시점에 평가될 수 있습니다. 최적화 수준의 상수 폴딩은 더 넓고 선택적입니다. 전파나 인라이닝 후에 비로소 상수가 된 값을 포함해 프로그램 어디에든 적용되며, 프런트엔드에서 중간 표현을 거쳐 명령어 선택에 이르기까지 여러 단계에서 일어날 수 있습니다. 명령어 선택 단계에서는 주소 오프셋과 상수를 하나의 즉치값으로 합치기도 합니다.

컴파일러의 상수 폴딩의 예로 올바른 것은?

  1. A같은 함수를 여러 번 호출하는 부분을 1번의 호출로 합친다
  2. Bx = 3 * 4를 컴파일 시에 계산하여 x = 12로 만든다
  3. C루프의 본체를 4번 분량 나열하여 반복 횟수를 줄인다
정답과 해설 보기

정답: B. x = 3 * 4를 컴파일 시에 계산하여 x = 12로 만든다

상수 폴딩은 컴파일 시점에 값이 정해지는 식을 미리 계산하여 결과 상수로 치환하는 최적화입니다. 3 * 4는 실행할 때마다 같은 12가 되므로 실행 시에 곱셈을 할 필요가 없습니다. 상수 전파와 조합하면 변수를 거친 계산도 한꺼번에 폴딩할 수 있습니다. 부동소수점에서는 반올림 방식을 맞춰야 하는 등 주의할 점도 있습니다. 루프의 본체를 나열하는 것은 루프 전개이고, 함수 호출을 합치는 것은 다른 최적화입니다.

자주 묻는 질문

상수 폴딩과 상수 전파의 차이

상수 폴딩은 3 * 4를 12로 바꾸는 것처럼 피연산자가 모두 상수인 식을 계산합니다. 상수 전파는 변수의 알려진 상수 값을 그 사용처에 대입하며, 이로 인해 폴딩할 수 있는 새로운 식이 생기는 경우가 많습니다.

최적화를 끄면 상수 폴딩은 안 되나요?

단순한 리터럴 식은 프런트엔드가 파싱 중에 계산하므로 최적화 없이도 폴딩되는 경우가 많습니다. 변수를 거친 폴딩, 함수 인라이닝, 분기 제거는 일반적으로 최적화를 켜야 합니다.

상수 폴딩으로 부동소수점 결과가 달라질 수 있나요?

표준을 준수하는 컴파일러는 하드웨어와 같은 IEEE 754 반올림으로 부동소수점 연산을 폴딩하므로 결과가 바뀌지 않습니다. fast-math처럼 부동소수점 규칙을 완화하는 옵션은 결합 순서 변경을 허용하므로 결과의 마지막 비트가 달라질 수 있습니다.

해설 속 상수 폴딩(constant folding)

  • 상수 폴딩은 컴파일 시점에 값이 정해지는 식을 미리 계산하여 결과 상수로 치환하는 최적화입니다.

    컴파일러의 상수 폴딩의 예로 올바른 것은?

  • 상수 폴딩으로 8 * 2를 16으로 계산하면 m = 16이 되고, 다시 전파와 폴딩으로 m + 1은 16 + 1 = 17이 됩니다.

    위의 코드에 상수 전파와 상수 폴딩을 반복해서 적용하면 최종적으로 어떤 코드가 되는가?

  • 상수 전파나 상수 폴딩 뒤에는 사용되지 않게 된 대입이 많이 생기므로 함께 사용됩니다.

    불필요한 코드의 삭제(데드 코드 제거)로 제거되는 것으로 올바른 것은?

  • 또한 호출하는 쪽의 상수 등이 본체에 전달되어 상수 폴딩이나 불필요한 코드의 삭제가 효과를 발휘하게 되는 것이 큰 장점입니다.

    함수 인라인 전개의 장점과 단점의 조합으로 올바른 것은?

  • 이어서 상수 폴딩을 하면 6 * 6 = 36, 36 + 1 = 37로 계산할 수 있어 g는 37을 반환하기만 하는 코드가 됩니다.

    위의 코드에서 sq를 인라인 전개한 뒤 이어서 효과를 내는 최적화와 그 결과로 올바른 것은 무엇인가?

  3. 위의 함수에 상수 전파·상수 폴딩·불필요한 코드 제거를 충분히 적용했을 때, 함수가 반환하는 값과 남는 코드로 올바른 것은 무엇인가?
  4. 불필요한 코드의 삭제(데드 코드 제거)로 제거되는 것으로 올바른 것은?
