성능 카운터(Performance Counter)란?

CPU 내부에서 일어난 명령 실행, 캐시 미스, 분기 예측 실패 등의 사건을 세는 하드웨어 카운터. PMU.

일본어 명칭: 性能カウンタ

성능 카운터(Performance Counter)은(는) 성능 분석, 메모리 계층 구조 등 2개 분야의 연습 문제 9개에 나와요.

분야: 성능 분석

도전해 보기: 성능 카운터(Performance Counter) 관련 문제

CPU에 내장된 성능 카운터(PMU)로 셀 수 있는 것의 예로 올바른 것은?

  1. A실행한 명령어 수, 캐시 미스 횟수, 분기 예측 실패 횟수 등
  2. B프로그램을 작성한 사람의 수
  3. C키보드 키의 수
정답과 해설 보기

정답: A. 실행한 명령어 수, 캐시 미스 횟수, 분기 예측 실패 횟수 등

성능 카운터는 CPU 안에서 일어나는 다양한 사건을 세는 하드웨어 카운터입니다. 사이클 수와 명령어 수로 IPC를 구할 수 있고, 각 단계의 캐시 미스, TLB 미스, 분기 예측 실패 등의 횟수도 알 수 있습니다. Linux의 perf 같은 도구로 프로그램을 실행하면서 셀 수 있으며, 시간이 걸리는 원인이 메모리인지, 분기인지, 연산 자체인지 구분하는 단서가 됩니다.

성능 카운터로 측정했더니 어떤 프로그램의 IPC(1사이클당 명령어 수)가 0.3으로 매우 낮고 최종 단계 캐시 미스가 많았다. 가장 가능성이 높은 상황과 대책의 조합은?

  1. A메모리 대기로 CPU가 멈춰 있는 시간이 길다. 데이터 배치를 바꾸거나 블로킹을 수행하여 캐시를 효과적으로 사용한다
  2. B연산이 너무 빠르다. 주파수를 올린다
  3. C분기가 너무 적다. 분기를 늘린다
정답과 해설 보기

정답: A. 메모리 대기로 CPU가 멈춰 있는 시간이 길다. 데이터 배치를 바꾸거나 블로킹을 수행하여 캐시를 효과적으로 사용한다

현재의 CPU는 1사이클에 수 개의 명령어를 실행할 수 있으므로, IPC가 0.3이라는 것은 대부분의 시간 무언가를 기다리고 있음을 나타냅니다. 최종 단계 캐시 미스가 많다면 주기억장치로부터의 데이터를 기다리는 시간이 길다고 생각할 수 있습니다. 데이터를 연속된 주소에 배치하거나, 루프 순서를 바꾸거나, 블로킹으로 같은 데이터를 여러 번 사용하는 등으로 캐시 미스를 줄이는 것이 효과적입니다.

해설 속 성능 카운터(Performance Counter)

  • 성능 카운터는 CPU 안에서 일어나는 다양한 사건을 세는 하드웨어 카운터입니다.

    CPU에 내장된 성능 카운터(PMU)로 셀 수 있는 것의 예로 올바른 것은?

  • 미스율은 성능 카운터 등으로 측정할 수 있습니다.

    캐시 성능을 평가할 때 미스율뿐 아니라 평균 메모리 접근 시간으로 비교해야 하는 이유로 올바른 것은?

  • 샘플링 방식에서는 타이머나 성능 카운터의 인터럽트로, 예를 들어 1초에 수천 번 실행 중인 명령어의 위치(와 호출 연쇄)를 기록합니다.

    샘플링 방식 프로파일러의 특징으로 올바른 것은?

  • 성능 카운터와 함께 이 성질을 사용하면 어느 쪽 개선에 힘을 쏟아야 하는지 알 수 있습니다.

    어떤 프로그램이 연산 바운드인지 메모리 바운드인지 확인하는 방법으로 CPU 주파수를 바꿔 실행 시간을 측정…

  • 샘플링이나 성능 카운터처럼 영향이 작은 방법을 선택하고, 측정의 영향이 어느 정도인지도 확인하는 것이 중요합니다.

성능 카운터(Performance Counter)이(가) 나오는 문제 (9)

  1. CPU에 내장된 성능 카운터(PMU)로 셀 수 있는 것의 예로 올바른 것은?
  2. 성능 카운터로 측정했더니 어떤 프로그램의 IPC(1사이클당 명령어 수)가 0.3으로 매우 낮고 최종 단계 캐시 미스가 많았다. 가장 가능성이 높은 상황과 대책의 조합은?
  3. 성능 카운터로 분기 예측 실패가 매우 많다는 것을 알았다. 개선 방법에 해당하는 것은?
  4. 성능 카운터를 사용한 톱다운 분석(Top-down Microarchitecture Analysis)에서 CPU의 명령어 처리 슬롯 사용 방식을 나누는 큰 분류로 올바른 것은?
  5. 캐시 성능을 평가할 때 미스율뿐 아니라 평균 메모리 접근 시간으로 비교해야 하는 이유로 올바른 것은?
  6. 샘플링 방식 프로파일러의 특징으로 올바른 것은?
  7. 어떤 프로그램이 연산 바운드인지 메모리 바운드인지 확인하는 방법으로 CPU 주파수를 바꿔 실행 시간을 측정했다. 메모리 바운드라면 일반적으로 어떤 결과가 나옵니까?
  8. 성능을 측정하기 위한 장치를 넣은 탓에 측정하려는 프로그램의 동작 자체가 바뀌어 버리는 현상을 무엇이라고 합니까?
  9. 프로그램 성능을 개선할 때의 진행 방식으로 가장 적절한 것은?

관련 용어
