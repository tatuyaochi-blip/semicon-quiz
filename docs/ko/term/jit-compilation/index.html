JIT 컴파일란?

프로그램 실행 중에 자주 실행되는 부분을 기계어로 컴파일하는 방식. 실행 시 정보를 이용한 최적화가 가능하다. Java와 JavaScript의 실행 환경 등에서 쓰인다.

일본어 명칭: JITコンパイル

JIT 컴파일은(는) 컴파일러, 링커, 로더, 실행 파일, 성능 분석 등 3개 분야의 연습 문제 5개에 나와요.

분야: 컴파일러

계층형 실행

일반적인 JIT(just-in-time) 런타임은 바이트코드를 인터프리트하는 것에서 시작하며, 이는 초기 비용이 없지만 느리게 실행됩니다. 인터프리트하는 동안 각 메서드가 몇 번 호출되고 각 루프가 몇 번 반복되는지 셉니다. 임곗값을 넘은 코드는 빠른 베이스라인 컴파일러에 넘겨지고, 계속 자주 실행되는 코드는 나중에 함수당 훨씬 많은 시간을 들이는 최적화 컴파일러로 다시 컴파일됩니다. 오래 도는 루프는 실행 도중에 컴파일된 코드로 전환할 수 있는데, 이를 OSR(on-stack replacement)이라고 합니다. 컴파일은 보통 백그라운드 스레드에서 이루어지므로 그동안에도 프로그램은 계속 실행됩니다.

투기적 최적화와 역최적화

인터프리터와 베이스라인 코드는 어떤 분기가 선택되는지, 각 호출 지점에 어떤 객체 타입이 나타나는지, 정수 오버플로가 발생한 적이 있는지 같은 프로파일을 수집합니다. 최적화 컴파일러는 이 관찰에 베팅합니다. 예를 들어 가상 호출이 항상 도달했던 유일한 메서드를 인라인하고, 한 번도 본 적 없는 타입을 위한 코드는 버립니다. 각 베팅은 비용이 낮은 가드로 보호됩니다. 가드가 실패하면 런타임은 역최적화(deoptimization)를 수행합니다. 현재 프레임에 대한 인터프리터의 관점을 재구성하고, 더 느린 코드에서 실행을 이어 가며, 나중에 새 정보로 다시 컴파일할 수 있습니다. AOT 컴파일러는 이런 베팅을 그렇게 자유롭게 할 수 없습니다.

JIT, AOT, 인터프리터의 비교

순수 인터프리터는 즉시 시작하고 실행 시 컴파일러가 필요 없지만, 각 연산을 느리게 실행합니다. AOT(ahead-of-time) 컴파일은 프로그램 실행 전에 기계어를 생성하므로 시작이 빠르고 성능이 예측 가능하며 메모리에 컴파일러가 없지만, 프로파일 기반 최적화(PGO)가 학습 실행 데이터를 제공하지 않는 한 실제 입력을 모른 채 최적화해야 합니다. JIT는 워밍업 시간, 컴파일에 쓰는 CPU 시간, 코드 캐시용 메모리를 대가로 치르는 대신, 오래 실행되는 프로그램에서 높은 최고 속도에 도달할 수 있습니다. 많은 런타임은 시작 코드를 캐시하거나 AOT 컴파일하는 등 여러 방식을 결합합니다.

실무상의 제약

JIT는 기계어를 메모리에 쓴 뒤 실행하므로, 메모리를 동시에 쓰기 가능하고 실행 가능하게 두어서는 안 된다는 보안 규칙과 충돌합니다. 런타임은 코드를 생성한 뒤 페이지 권한을 전환하거나, 같은 물리 메모리를 서로 다른 권한으로 두 번 매핑하는 방식으로 이를 처리하며, 일부 엄격하게 제한된 플랫폼은 실행 시 코드 생성을 아예 금지합니다. 컴파일된 코드가 실행 시 프로파일에 의존하므로 성능이 실행마다 다를 수 있고 역최적화가 일어나면 갑자기 떨어질 수 있어, JIT 기반 시스템을 벤치마크할 때는 적절한 워밍업이 필요합니다.

정답과 해설 보기

정답: B. 실행 중에 자주 쓰는 부분을 기계어로 만들고 실행 시의 정보도 활용할 수 있다

JIT 컴파일에서는 처음에는 바이트코드를 해석하면서 실행하다가, 여러 번 실행되는 부분(핫스폿)을 발견하면 실행 중에 그 부분을 기계어로 컴파일합니다. 실제로 지나가는 분기나 전달되는 타입 같은 실행 시의 정보를 활용하여, 사전에 하는 컴파일로는 어려운 과감한 최적화를 할 수 있습니다. 가정이 빗나가면 해석 실행으로 되돌아가는 구조도 갖추고 있습니다. 사전에 모든 것을 번역하는 것은 사전(AOT) 컴파일, 해석만 계속하는 것은 순수한 인터프리터입니다.

자주 묻는 질문

JIT 컴파일이 AOT 컴파일보다 빠른가요?

워크로드에 따라 다릅니다. JIT 코드는 실제 프로파일을 이용해 최적화하므로 오래 실행되는 프로그램에서 AOT 코드와 대등하거나 더 빠를 수 있지만, 시작 시간, 메모리 사용량, 예측 가능성에서는 AOT가 유리합니다.

JIT 워밍업이란 무엇인가요?

런타임이 코드를 프로파일링하고 자주 실행되는 부분을 컴파일하는 동안, 코드가 인터프리터나 베이스라인 계층에서 실행되는 초기 구간입니다. 워밍업 중에 측정한 성능은 정상 상태의 속도를 과소평가합니다.

JIT에서 역최적화란 무엇인가요?

최적화된 코드가 바탕으로 삼은 가정이 틀린 것으로 드러났을 때 그 코드를 버리고, 대응하는 지점부터 인터프리터나 덜 최적화된 코드에서 실행을 이어 가는 것입니다. 이후 런타임은 갱신된 프로파일 정보로 다시 컴파일할 수 있습니다.
