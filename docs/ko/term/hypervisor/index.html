하이퍼바이저(Hypervisor)란?

한 대의 컴퓨터 위에서 여러 가상 머신을 동작시키기 위한 소프트웨어. 각 가상 머신의 OS에 CPU, 메모리, 장치를 나누어 주고 서로 격리한다. 가상 머신 모니터라고도 한다.

일본어 명칭: ハイパーバイザ

하이퍼바이저(Hypervisor)은(는) OS와 하드웨어, 하드웨어 보안의 최신 동향, 하드웨어 보안 등 4개 분야의 연습 문제 14개에 나와요.

분야: OS와 하드웨어

CPU 제어권을 유지하는 방법

하이퍼바이저, 즉 가상 머신 모니터는 게스트 운영체제보다 높은 특권 레벨에서 실행됩니다. 게스트 커널은 자신이 하드웨어를 제어한다고 믿지만, 특권 명령을 실행하거나 보호된 자원에 접근하면 CPU가 하이퍼바이저로 트랩하고, 하이퍼바이저는 그 효과를 해당 가상 머신의 상태에 재현한 뒤 게스트를 재개합니다. 이것이 트랩 앤 에뮬레이트입니다. 하드웨어 가상화 확장은 전용 모드를 추가하고 전환할 때마다 게스트 상태를 빠르게 저장·복원합니다. 예를 들어 RISC-V는 머신, 슈퍼바이저, 사용자 모드에 하이퍼바이저 모드를 추가합니다.

메모리 가상화

각 게스트는 게스트 가상 주소를 자신이 물리 주소라고 믿는 주소로 매핑하는 페이지 테이블을 관리합니다. 이 게스트 물리 주소는 다시 실제 호스트 메모리로 매핑되어야 합니다. 중첩 페이징(nested paging)에서는 하드웨어가 두 단계를 자동으로 수행합니다. 게스트의 테이블로 게스트 가상 주소에서 게스트 물리 주소로, 이어서 하이퍼바이저의 테이블로 호스트 물리 주소로 변환합니다. 초기 시스템은 소프트웨어로 관리하는 섀도 페이지 테이블을 사용했기 때문에, 게스트가 테이블을 수정할 때마다 하이퍼바이저가 개입해야 했습니다. 2단계 변환의 비용은 TLB 미스 시 페이지 테이블 워크가 길어지는 것이며, 큰 페이지를 쓰면 이를 줄일 수 있습니다.

I/O 가상화

실제 장치를 레지스터 하나하나까지 에뮬레이션하면 완전히 투명하지만, 레지스터에 접근할 때마다 하이퍼바이저로 빠져나가므로 느립니다. 반가상화(paravirtualization)는 대신 게스트에 가상화를 인식하는 드라이버를 설치하여 공유 메모리의 큐를 통해 하이퍼바이저와 일괄 요청을 주고받으며, 가상 디스크와 네트워크 카드에서 흔히 쓰이는 방식입니다. 최고 성능이 필요하면 물리 장치를 하나의 게스트에 직접 할당할 수 있으며, 이때 IOMMU(I/O memory management unit)가 그 장치의 DMA를 해당 게스트의 메모리로 제한하여 격리를 유지합니다.

하이퍼바이저, 컨테이너, 신뢰

타입 1 하이퍼바이저는 클라우드 서버처럼 하드웨어 위에서 직접 실행되고, 타입 2 하이퍼바이저는 호스트 OS 위의 애플리케이션으로 실행됩니다. 컨테이너는 또 다릅니다. 하나의 커널을 공유하고 프로세스, 파일 시스템, 자원만 분할하므로, 각자 자신의 커널을 부팅하는 가상 머신보다 가볍지만 격리는 약합니다. 하이퍼바이저는 차량용 SoC에서 서로 다른 중요도의 소프트웨어를 분할하는 데도 쓰입니다. 일반적으로 하이퍼바이저는 게스트 메모리를 모두 읽을 수 있지만, 컨피덴셜 컴퓨팅 기능은 VM 메모리를 암호화하여 호스트조차 읽을 수 없게 합니다.

  2. B반드시 일반 OS 위에서 애플리케이션으로 동작하며 하드웨어 위에서 직접 동작하지는 않는다
  3. C유형에 따른 차이는 없으며 모두 하드웨어를 사용하지 않고 소프트웨어만으로 동작한다
정답과 해설 보기

정답: A. 하드웨어 위에서 직접 동작하는 유형과 일반 OS 위에서 애플리케이션으로 동작하는 유형이 있다

하이퍼바이저에는 하드웨어 위에서 직접 동작하며 OS를 관리하는 유형(타입 1, 베어메탈형)과 Windows나 Linux 같은 일반 OS 위에서 애플리케이션으로 동작하는 유형(타입 2, 호스트형)이 있습니다. 타입 1은 불필요한 계층이 없어 성능과 격리가 뛰어나 서버와 클라우드에서, 타입 2는 손쉽게 쓸 수 있어 PC에서의 개발이나 시험에 자주 사용됩니다. 둘 다 CPU의 가상화 지원 기능 등 하드웨어를 이용합니다.

  2. B카피 온 라이트
  3. C디맨드 페이징
정답과 해설 보기

정답: A. 트랩 앤 에뮬레이트

가상 머신의 OS는 하드웨어를 직접 조작하는 것으로 알고 특권 명령을 실행하지만, 실제로는 특권이 낮은 모드에서 실행되고 있으므로 예외(트랩)가 발생합니다. 하이퍼바이저는 그것을 받아 그 가상 머신에게 올바른 결과가 되도록 명령의 효과를 재현(에뮬레이트)하고 가상 머신으로 돌려보냅니다. CPU의 가상화 지원 기능은 이러한 전환을 빠르고 확실하게 수행할 수 있게 합니다. 카피 온 라이트와 디맨드 페이징은 메모리 관리 방식입니다.

자주 묻는 질문

하이퍼바이저와 가상 머신 차이

하이퍼바이저는 가상 머신을 생성·실행하고 하드웨어를 나누어 주는 소프트웨어 계층이며, 각 가상 머신은 자체 OS를 실행하는 격리된 게스트 환경 하나입니다.

타입 1 하이퍼바이저와 타입 2 하이퍼바이저 차이

타입 1(베어메탈) 하이퍼바이저는 하드웨어 위에서 직접 실행되고, 타입 2(호스티드) 하이퍼바이저는 일반 운영체제 위의 애플리케이션으로 실행됩니다.

컨테이너와 가상 머신은 같은 건가요?

아닙니다. 컨테이너는 호스트 커널을 공유하여 가볍고, 가상 머신은 하이퍼바이저 위에서 각자 자신의 커널을 실행하므로 격리가 더 강하고 서로 다른 운영체제를 실행할 수 있습니다.

이 용어가 포함된 비교

  • TrustZone·SGX·SEV/TDX의 차이: 격리 단위·신뢰 범위·메모리 암호화 비교Arm TrustZone, Intel SGX 엔클레이브, AMD SEV와 Intel TDX의 기밀 VM을 한 장의 표로 비교합니다. 격리 단위, 무엇으로부터 지키는지, 신뢰해야 하는 범위(TCB)…
  • 가상 머신과 컨테이너의 차이: 가상화하는 계층·커널·시작 속도·격리 강도·용도 비교가상 머신과 컨테이너를 가상화하는 계층, OS 커널, 실행할 수 있는 OS, 이미지 크기, 시작 속도, 격리 강도, 자원 효율, 주요 용도의 관점에서 표로 비교합니다.
  • IaaS·PaaS·SaaS의 차이: 제공 범위·사용자가 관리하는 것·자유도·운영 부담 비교IaaS·PaaS·SaaS를 사업자가 제공하는 것, 사용자가 관리하는 것, 자유도, 운영 부담, 주요 사용자, 요금 방식, 공동 책임 모델에서의 분담, 대표적인 예의 관점에서 표로 비교합니다.
