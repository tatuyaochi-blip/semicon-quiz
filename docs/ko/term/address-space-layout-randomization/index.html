ASLR란?

Address Space Layout Randomization의 약어. 스택, 힙, 공유 라이브러리, 실행 파일의 번지를 실행할 때마다 바꿔 공격자가 번지를 예측하기 어렵게 하는 대책.

일본어 명칭: ASLR

ASLR은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 3개에 나와요.

분야: 링커, 로더, 실행 파일

ASLR이 프로세스를 옮기는 방식

프로그램이 시작되면 커널과 동적 로더는 주소 공간의 주요 영역마다 페이지 정렬된 무작위 기준 오프셋을 선택합니다. 대상은 스택, 힙, 공유 라이브러리가 매핑되는 mmap 영역, 그리고 위치 독립 실행 파일(PIE)로 빌드된 경우의 실행 파일 자체입니다. 영역의 상대적 순서는 평소와 같지만(낮은 주소에 text, data, BSS, 힙이 있고 맨 위에 스택), 절대 주소는 실행할 때마다 달라집니다. 즉 주소 공간 배치 무작위화(ASLR)는 무엇이 어디에 있는지를 바꿀 뿐, 프로그램이 하는 일은 바꾸지 않습니다.

공격자에게 주소가 필요한 이유

스택 버퍼 오버플로 같은 메모리 손상 익스플로잇은 보통 복귀 주소나 함수 포인터를 쓸모 있는 무언가의 주소로 덮어씁니다. 스택에 올린 셸코드, return-to-libc 공격에서의 system() 같은 라이브러리 함수, 또는 리턴 지향 프로그래밍(ROP)에서의 명령어 조각 체인이 그 대상입니다. 이들 모두 정확한 주소가 필요합니다. ASLR이 있으면 공격자는 주소를 추측해야 하고, 추측이 틀리면 제어권을 넘겨주는 대신 대개 프로세스가 크래시합니다. 보호는 확률적이므로 강도는 사용 가능한 무작위 비트 수에 달려 있으며, 32비트 주소 공간에서는 64비트보다 훨씬 제한적입니다.

PIE와 위치 독립 코드

ASLR은 고정 로드 주소를 전제로 하지 않는 코드만 옮길 수 있습니다. 공유 라이브러리는 오래전부터 위치 독립 코드(PIC)로 컴파일되어 PC 상대 주소 지정과 전역 오프셋 테이블(GOT)로 데이터에 접근해 왔습니다. 그러나 예전 실행 파일은 고정 주소로 링크되었기 때문에 메인 프로그램의 코드가 알려진 위치에 머물러, 공격자에게 신뢰할 수 있는 ROP 가젯 공급원이 되었습니다. -fPIE와 -pie로 빌드하면 실행 파일도 재배치 가능해져 로더가 이를 무작위화할 수 있습니다. x86-64에서는 PC 상대 데이터 접근이 기본 지원되므로 비용이 작습니다.

한계와 함께 쓰는 방어 기법

무작위화는 영역 단위로 적용되므로, 라이브러리의 포인터 하나만 유출되어도 그 라이브러리 전체의 오프셋, 나아가 그 안의 모든 함수 주소가 드러납니다. fork()로 생성된 자식 프로세스는 부모의 배치를 그대로 물려받으므로, 공격자는 fork하는 서버를 반복해서 탐색할 수 있습니다. 이런 이유로 ASLR은 쓰기 가능 메모리의 실행 금지(W^X 또는 NX), 스택 카나리, 제어 흐름 보호와 함께 사용됩니다. 운영체제 커널도 무작위화할 수 있으며 이를 KASLR이라고 합니다. Linux에서는 /proc/sys/kernel/randomize_va_space에서 설정을 확인할 수 있습니다.

ASLR(주소 공간 배치 무작위화)의 목적으로 올바른 것은 무엇입니까?

  1. A스택, 힙, 라이브러리 등의 주소를 실행할 때마다 바꾸어, 공격자가 노리는 주소를 예측하기 어렵게 한다
  2. B메모리 주소를 무작위로 골라 캐시 히트율을 높인다
  3. C사용하지 않는 메모리를 무작위로 해제하여 빈 용량을 늘린다
정답과 해설 보기

정답: A. 스택, 힙, 라이브러리 등의 주소를 실행할 때마다 바꾸어, 공격자가 노리는 주소를 예측하기 어렵게 한다

버퍼 오버플로 등을 악용하는 공격에서는 라이브러리 함수나 스택 위 데이터의 주소를 아는 것이 중요합니다. ASLR은 프로세스를 기동할 때마다 스택, 힙, 공유 라이브러리, 실행 파일을 놓는 주소를 바꾸어 공격자가 주소를 단정할 수 없게 합니다. 단독으로 완전히 막을 수 있는 것은 아니며, 쓰기와 실행의 분리 등 다른 대책과 조합하여 사용합니다.

자주 묻는 질문

ASLR로 버퍼 오버플로 공격을 막을 수 있나요?

아닙니다. ASLR은 오버플로 자체를 막지 못하며, 어느 주소로 점프해야 하는지 알기 어렵게 만들어 대부분의 시도가 성공 대신 크래시로 끝나게 할 뿐입니다. 실제 주소 하나를 드러내는 정보 유출이 있으면 무력화될 수 있으므로 NX 메모리, 스택 카나리와 함께 사용합니다.

ASLR과 PIE의 차이는 무엇인가요?

ASLR은 실행할 때마다 메모리 영역을 무작위 주소에 로드하는 운영체제의 메커니즘입니다. PIE는 실행 파일의 코드가 어느 주소에서든 동작하도록 컴파일·링크하는 방식으로, ASLR이 라이브러리, 스택, 힙뿐 아니라 메인 프로그램까지 무작위화할 수 있게 해 줍니다.

Linux에서 ASLR이 켜져 있는지 확인하는 방법은?

/proc/sys/kernel/randomize_va_space를 읽습니다. 0은 비활성, 1은 스택, mmap 영역, 공유 라이브러리를 무작위화하며, 2는 여기에 brk 기반 힙까지 무작위화합니다. 대부분의 배포판은 기본값이 2입니다.

  • 실제 주소는 보안을 위해 ASLR에 의해 실행할 때마다 달라집니다.

    Linux 등의 일반적인 프로세스 메모리 배치를 주소가 작은 쪽부터 나열한 것으로 올바른 것은 무엇입니까?

  • 예전 실행 파일은 정해진 주소에 읽힌다는 전제로 만들어졌으므로, ASLR을 사용해도 라이브러리나 스택만 옮길 수 있었고 본체 코드의 주소는 공격자에게 알려져 있었습니다.
