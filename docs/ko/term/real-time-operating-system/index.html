RTOS(실시간 OS)란?

여러 태스크를 우선순위에 따라 전환하여 정해진 시간 내에 응답할 수 있게 하는 임베디드용 OS. FreeRTOS, Zephyr 등.

일본어 명칭: RTOS(リアルタイムOS)

RTOS(실시간 OS)은(는) 임베디드 시스템과 펌웨어 등 1개 분야의 연습 문제 7개에 나와요.

분야: 임베디드 시스템과 펌웨어

RTOS가 태스크를 스케줄링하는 방식

실시간 운영체제(RTOS)는 펌웨어를 태스크로 구성하며, 각 태스크는 우선순위와 준비(ready), 실행(running), 대기(blocked) 같은 상태를 가집니다. 대부분의 RTOS는 선점형 우선순위 스케줄링을 사용합니다. 인터럽트나 메시지로 더 높은 우선순위의 태스크가 준비 상태가 되면, 커널은 실행 중인 태스크의 컨텍스트를 저장하고 즉시 전환하며, 중단된 태스크는 나중에 멈춘 곳에서 재개합니다. 하드웨어 타이머에서 오는 주기적인 틱, 흔히 1 ms가 타임아웃과 지연을 구동합니다. 예를 들어 16 MHz를 프리스케일러 16으로 나누면 1 µs 카운트가 되고, 1000카운트마다 인터럽트를 걸면 1 ms 틱이 됩니다.

실시간이란 단지 빠른 것이 아니라 예측 가능한 것

목표는 평균 처리량의 최대화가 아니라, 모터 제어나 통신 프로토콜 같은 중요한 작업에 대해 상한이 있고 예측 가능한 응답 시간을 보장하는 것입니다. 범용 OS는 공정성과 처리량을 최적화하므로 태스크를 예측할 수 없게 지연시킬 수 있지만, RTOS는 커널을 작게 유지하고 스케줄링 판단을 결정적으로 하므로 메모리가 적은 마이크로컨트롤러에서도 동작할 수 있습니다. OS가 없으면 펌웨어는 흔히 슈퍼 루프를 씁니다. while (1) 루프가 각 작업을 차례로 호출하고, 인터럽트가 긴급한 이벤트를 처리하며 플래그를 세웁니다. 단순하고 가볍지만 느린 작업 하나가 전체를 지연시키며, 바로 이때 RTOS가 가치를 발휘합니다.

태스크 간 통신

RTOS는 태스크가 바쁜 대기(busy-waiting) 없이 협력할 수 있도록 기본 기능을 제공합니다. 메시지 큐를 쓰면 센서 태스크가 측정값을 보내는 동안 디스플레이 태스크는 데이터가 도착할 때까지 CPU를 쓰지 않고 대기 상태로 잠들어 있으며, 여러 항목을 버퍼링하여 일시적인 속도 차이를 흡수하므로 데이터가 유실되지 않습니다. 뮤텍스는 버스나 버퍼 같은 공유 자원을 보호하고, 세마포어는 흔히 인터럽트 핸들러에서 이벤트를 알리며, 시간 제한 대기는 태스크가 타임아웃을 두고 대기할 수 있게 합니다. 공유 변수와 폴링 플래그 대신 이들을 사용하면 데이터 경합과 사이클 낭비를 피할 수 있습니다.

우선순위 역전과 상속

우선순위 역전은 높은 우선순위 태스크가 낮은 우선순위 태스크가 가진 뮤텍스를 기다리고 있을 때, 관계없는 중간 우선순위 태스크가 낮은 태스크를 선점하면 발생합니다. 낮은 태스크가 끝나서 뮤텍스를 해제할 수 없으므로, 높은 태스크는 사실상 중간 태스크에 의해 무제한으로 막히게 됩니다. 이것이 1997년 화성 탐사선 마스 패스파인더 착륙선에서 반복적인 시스템 리셋을 일으켰습니다. 우선순위 상속은 뮤텍스 보유자가 자원을 해제할 때까지 일시적으로 그 우선순위를 대기 중인 태스크의 우선순위로 올려 이를 해결하며, 많은 RTOS의 뮤텍스가 이를 내장 옵션으로 제공합니다.

  2. B처리의 평균 속도를 PC의 OS보다 반드시 빠르게 한다
  3. C여러 처리(태스크)를 우선순위에 따라 전환하여 정해진 시간 안에 응답할 수 있게 한다
정답과 해설 보기

정답: C. 여러 처리(태스크)를 우선순위에 따라 전환하여 정해진 시간 안에 응답할 수 있게 한다

RTOS는 처리를 태스크로 나누고, 우선순위가 높은 태스크가 실행 가능해지면 즉시 전환하여 실행합니다. 모터 제어나 통신 응답처럼 지연되면 곤란한 처리를 정해진 시간 안에 확실하게 수행할 수 있게 하는 것이 목적입니다. 태스크 간에 데이터를 전달하는 큐, 자원을 보호하는 뮤텍스, 시간을 기다리는 기능 등도 제공됩니다. FreeRTOS, Zephyr, μITRON 등이 있습니다.

선점형 RTOS에서 우선순위가 낮은 태스크가 실행 중일 때, 우선순위가 높은 태스크가 기다리던 데이터를 받아 실행 가능한 상태가 되었습니다. 일반적으로 어떻게 됩니까?

  1. A낮은 태스크가 스스로 끝날 때까지 높은 태스크는 기다린다
  2. B두 태스크가 모두 멈추고 마이크로컨트롤러가 재시작한다
  3. C낮은 태스크를 도중에 멈추고 즉시 높은 태스크로 전환한다
정답과 해설 보기

정답: C. 낮은 태스크를 도중에 멈추고 즉시 높은 태스크로 전환한다

선점형 RTOS에서는 인터럽트 등을 계기로 우선순위가 높은 태스크가 실행 가능한 상태가 되면, 커널이 실행 중인 낮은 태스크의 상태를 저장하고 멈춘 뒤 높은 태스크로 전환합니다. 높은 태스크가 끝나거나 대기 상태가 되면 낮은 태스크가 이어서 재개합니다. 그래서 높은 우선순위 처리의 응답 시간을 짧고 예측하기 쉽게 할 수 있습니다.

자주 묻는 질문

RTOS와 Linux 같은 범용 OS 차이

RTOS는 엄격한 우선순위 기반 선점과 작은 메모리 사용량으로 최악의 경우 응답 시간을 예측할 수 있도록 설계됩니다. 범용 OS는 평균 처리량과 공정성을 최적화하며, 더 풍부한 서비스를 제공하지만 타이밍의 결정성은 떨어집니다.

RTOS 우선순위 역전이란?

높은 우선순위 태스크가 낮은 우선순위 태스크가 가진 자원을 기다리며 멈춰 있는데, 그 낮은 태스크 자체가 중간 우선순위 태스크 때문에 실행되지 못하는 상황입니다. 우선순위 상속은 보유자의 우선순위를 일시적으로 올려 이를 방지합니다.

슈퍼 루프 대신 RTOS를 써야 하는 경우

타이밍 요구가 서로 다른 여러 활동이 있고, 슈퍼 루프 안의 긴 작업이 시간이 중요한 작업을 지연시킬 때입니다. 단순하고 부하가 가벼운 펌웨어라면 슈퍼 루프와 인터럽트만으로 충분한 경우가 많습니다.

RTOS(실시간 OS)이(가) 나오는 문제 (7)

  1. 임베디드 기기에서 RTOS(실시간 OS)를 사용하는 주된 목적은 무엇입니까?
  2. 선점형 RTOS에서 우선순위가 낮은 태스크가 실행 중일 때, 우선순위가 높은 태스크가 기다리던 데이터를 받아 실행 가능한 상태가 되었습니다. 일반적으로 어떻게 됩니까?
  3. RTOS에서 발생하는 우선순위 역전의 설명으로 올바른 것은 무엇입니까?
  4. RTOS에서 센서를 읽는 태스크에서 표시하는 태스크로 데이터를 전달할 때 큐(메시지 큐)를 사용하는 이점으로 올바른 것은 무엇입니까?
  5. 16 MHz 클럭을 프리스케일러로 16분주한 것으로 타이머를 세고, 1000카운트마다 인터럽트가 발생하도록 설정했습니다. 인터럽트 간격은 얼마입니까?
  6. OS를 사용하지 않는 마이크로컨트롤러 프로그램에서 흔히 볼 수 있는 '슈퍼 루프' 구성의 설명으로 올바른 것은 무엇입니까?
  7. 우선순위 역전을 막기 위해 사용되는 '우선순위 상속'의 개념으로 올바른 것은 무엇입니까?
