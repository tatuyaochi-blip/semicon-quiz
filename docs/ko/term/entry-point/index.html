진입점(entry point)란?

프로그램이 실행을 시작하는 주소로 ELF 헤더에 기록됩니다. C에서는 보통 _start 같은 시동 코드이며, 초기화한 뒤 main을 호출합니다.

일본어 명칭: エントリポイント

진입점(entry point)은(는) 링커, 로더, 실행 파일, OS와 하드웨어 등 2개 분야의 연습 문제 4개에 나와요.

분야: 링커, 로더, 실행 파일

도전해 보기: 진입점(entry point) 관련 문제

Linux에서 동적 링크 프로그램을 시작할 때 동작하는 동적 링커(ld.so 등)의 역할로 올바른 것은?

  1. A소스 코드를 컴파일하여 기계어를 만든다
  2. B필요한 공유 라이브러리를 찾아 메모리에 읽어 들이고, 심볼을 연결한 다음 프로그램을 시작시킨다
  3. C프로그램이 종료된 뒤 디스크의 빈 공간을 정리한다
정답과 해설 보기

정답: B. 필요한 공유 라이브러리를 찾아 메모리에 읽어 들이고, 심볼을 연결한 다음 프로그램을 시작시킨다

동적 링크 실행 파일에는 사용할 동적 링커의 위치가 적혀 있으며, OS는 프로그램을 읽어 들이면 먼저 동적 링커에 처리를 넘깁니다. 동적 링커는 필요한 공유 라이브러리를 찾아 읽어 들이고, 재배치와 심볼 결합을 수행한 다음 프로그램의 진입점으로 제어를 옮깁니다. dlopen으로 실행 중에 라이브러리를 추가로 읽어 들이는 처리도 동적 링커가 담당합니다.

프로그램을 시작할 때(Linux의 execve 등) OS의 로더가 하는 일로 올바른 것은?

  1. A소스 코드를 읽어 들여 그 자리에서 컴파일한 다음 실행한다
  2. B실행 파일의 프로그램 헤더에 따라 각 부분을 메모리에 배치하고, 스택에 인수 등을 준비한 뒤 진입점 주소부터 실행을 시작한다
  3. C실행 파일의 모든 심볼 이름을 화면에 표시한 다음 실행한다
정답과 해설 보기

정답: B. 실행 파일의 프로그램 헤더에 따라 각 부분을 메모리에 배치하고, 스택에 인수 등을 준비한 뒤 진입점 주소부터 실행을 시작한다

로더는 실행 파일의 헤더를 읽고, 프로그램 헤더에 적힌 각 부분(세그먼트)을 읽기, 쓰기, 실행 권한을 붙여 가상 주소 공간에 대응시킵니다. BSS를 위한 0 영역과 스택을 준비하고, 명령줄 인수와 환경 변수를 스택에 쌓습니다. 동적 링크라면 동적 링커를, 그렇지 않으면 실행 파일의 진입점 주소부터 실행을 시작합니다.

해설 속 진입점(entry point)

  • 동적 링커는 필요한 공유 라이브러리를 찾아 읽어 들이고, 재배치와 심볼 결합을 수행한 다음 프로그램의 진입점으로 제어를 옮깁니다.

    Linux에서 동적 링크 프로그램을 시작할 때 동작하는 동적 링커(ld.so 등)의 역할로 올바른 것은?

  • 동적 링크라면 동적 링커를, 그렇지 않으면 실행 파일의 진입점 주소부터 실행을 시작합니다.

    프로그램을 시작할 때(Linux의 execve 등) OS의 로더가 하는 일로 올바른 것은?

  • 링커는 C 런타임이 준비한 시작용 오브젝트(crt1.o 등)를 프로그램에 포함시키고, 그 안의 _start를 진입점으로 삼습니다.

    C 언어 프로그램에서 OS가 가장 먼저 실행을 시작하는 주소(엔트리 포인트)에 대한 설명으로 올바른 것은?

  • CPU는 현재 명령의 주소를 저장하고 권한이 높은 모드로 전환하여 OS가 설정한 예외 처리의 진입점으로 이동합니다.

    위의 RISC-V 코드에서 마지막 ecall 명령이 실행되었을 때 일어나는 일로 올바른 것은 무엇입니까?

  1. Linux에서 동적 링크 프로그램을 시작할 때 동작하는 동적 링커(ld.so 등)의 역할로 올바른 것은?
  2. 프로그램을 시작할 때(Linux의 execve 등) OS의 로더가 하는 일로 올바른 것은?
  3. C 언어 프로그램에서 OS가 가장 먼저 실행을 시작하는 주소(엔트리 포인트)에 대한 설명으로 올바른 것은?
  4. 위의 RISC-V 코드에서 마지막 ecall 명령이 실행되었을 때 일어나는 일로 올바른 것은 무엇입니까?
