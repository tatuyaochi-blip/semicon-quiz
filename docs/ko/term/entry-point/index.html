엔트리 포인트(Entry Point)란?

프로그램 실행을 시작하는 주소. ELF 헤더에 기록된다. C 언어에서는 보통 main이 아니라 _start 등의 시작 코드가 초기화를 한 뒤 main을 호출한다.

일본어 명칭: エントリポイント

엔트리 포인트(Entry Point)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 1개에 나와요.

분야: 링커, 로더, 실행 파일

엔트리 포인트와 main

엔트리 포인트는 로더가 제어를 넘기는 첫 명령어의 주소로, ELF 파일의 e_entry 필드처럼 실행 파일의 헤더에 저장됩니다. C 프로그램에서는 보통 main이 아닙니다. 링커가 crt1.o 같은 C 런타임의 시작 오브젝트를 추가하고, 그 안의 _start 심볼을 엔트리 포인트로 삼습니다. C 코드 입장에서는 main이 시작처럼 보이지만, 실제로는 이 시작 코드가 호출하는 평범한 함수일 뿐입니다. 필요하면 링커에서 다른 엔트리 심볼을 지정할 수 있습니다.

시작 코드가 하는 일

Linux에서 커널은 argc, argv 포인터, 환경 변수 포인터, 보조 벡터(auxiliary vector)를 스택에 배치한 상태로 새 프로세스를 시작합니다. _start 루틴은 이들을 모으고 스택을 정렬한 뒤 C 라이브러리의 초기화를 호출하며, 초기화는 표준 라이브러리를 설정하고 전역 객체의 생성자와 초기화 함수를 실행한 다음 main을 호출합니다. main이 반환하면 그 반환값이 exit에 전달되고, exit는 등록된 atexit 핸들러를 실행하고 버퍼된 출력을 플러시한 뒤 마지막으로 커널에 프로세스 종료를 요청합니다.

동적 링크된 프로그램

동적 링크된 실행 파일은 프로그램 헤더에 Linux의 ld.so 같은 동적 링커를 지정합니다. 커널은 프로그램과 동적 링커를 모두 매핑하고, 프로그램이 아니라 동적 링커 자신의 엔트리 포인트에서 실행을 시작합니다. 동적 링커는 필요한 공유 라이브러리를 로드하고, 재배치를 적용하고, 심볼을 바인딩하고, 라이브러리의 초기화 함수를 실행한 뒤 프로그램의 엔트리 포인트인 _start로 점프합니다. 따라서 동적 링크된 프로세스에서는 프로그램 자신의 첫 명령어 이전에 상당한 양의 코드가 실행됩니다.

커널과 마이크로컨트롤러의 엔트리 포인트

이 용어는 실행이 시작되는 다른 곳에도 쓰입니다. 운영체제는 예외와 인터럽트의 엔트리 포인트를 CPU에 등록합니다. 예를 들어 RISC-V에서는 ecall 명령어가 예외를 발생시켜 더 높은 특권 모드로 전환하고 OS가 설정한 트랩 벡터로 점프합니다. 베어메탈 마이크로컨트롤러에서는 리셋 벡터가 시작 코드를 가리키며, 시작 코드는 스택을 준비하고, 초기화된 데이터를 플래시에서 RAM으로 복사하고, 초기화되지 않은 .bss 섹션을 0으로 채운 뒤에야 main을 호출합니다.

링커는 C 런타임이 제공하는 기동용 오브젝트(crt1.o 등)를 프로그램에 포함시키고, 그 안의 _start를 입구로 삼습니다. _start는 스택에서 커맨드라인 인수를 꺼내고, 표준 라이브러리나 전역 오브젝트의 초기화를 수행한 뒤 main을 호출합니다. main이 돌아오면 그 반환값으로 exit를 호출하여 종료 처리를 합니다.

자주 묻는 질문

C 프로그램의 엔트리 포인트는 main인가요?

보통은 아닙니다. 실행 파일의 엔트리 포인트는 _start 같은 시작 코드로, 인수와 런타임을 준비하고 main을 호출한 뒤 main의 반환값을 exit에 전달합니다.

ELF 파일에서 엔트리 포인트는 어디에 저장되나요?

ELF 헤더의 e_entry 필드에 저장되며, 프로그램이 로드된 후 실행이 시작되는 가상 주소를 담고 있습니다.

C 프로그램에서 main 전에 무엇이 실행되나요?

C 런타임 시작 코드, 라이브러리 초기화, 전역 객체의 생성자가 실행됩니다. 동적 링크된 프로그램에서는 그보다 먼저 동적 링커가 공유 라이브러리를 로드하고 재배치합니다.
