스택 포인터(stack pointer)란?

스택의 현재 맨 위 번지를 가리키는 레지스터. RISC-V에서는 sp(x2). 많은 ISA에서 스택은 번지가 작은 쪽으로 자란다.

일본어 명칭: スタックポインタ

스택 포인터(stack pointer)은(는) ISA와 어셈블리, CPU와 아키텍처, 링커, 로더, 실행 파일 등 4개 분야의 연습 문제 5개에 나와요.

도전해 보기: 스택 포인터(stack pointer) 관련 문제

RISC-V의 표준 호출 규약에서는 함수에 진입할 때의 스택 포인터 sp를 16바이트의 배수로 맞추게 되어 있다. 그 이유로 가장 적절한 것은?

  1. A스택 용량이 16바이트의 배수가 아니면 OS가 부팅하지 않기 때문
  2. Bsp의 하위 4비트에 함수 번호를 기록하기 때문
  3. C16바이트까지의 큰 데이터를 스택에 두어도 경계를 넘지 않고 효율적으로 읽고 쓸 수 있기 때문
정답과 해설 보기

정답: C. 16바이트까지의 큰 데이터를 스택에 두어도 경계를 넘지 않고 효율적으로 읽고 쓸 수 있기 때문

데이터는 크기의 배수 주소에 두면(정렬하면) 경계를 넘지 않고 한 번에 읽고 쓸 수 있습니다. sp를 항상 16의 배수로 해 두면 8바이트의 double이나 16바이트의 long double 등을 스택에 두어도 정렬이 유지됩니다. 그래서 함수는 프레임 크기를 16의 배수로 확보하며, 저장할 레지스터가 하나뿐이어도 'addi sp, sp, -16'으로 합니다.

해설 속 스택 포인터(stack pointer)

  • 맨 위 위치는 스택 포인터가 가리킵니다.

    프로그램에서 서브루틴(함수)을 호출할 때 복귀 주소 등을 일시적으로 저장하기 위해 일반적으로 사용되는 영역…

  • 인자용 레지스터는 a0~a7의 8개이므로 9번째 이후는 호출하는 쪽이 스택에 쌓고, 호출받은 쪽은 스택 포인터로부터 정해진 위치에서 읽습니다.

    RISC-V의 표준 호출 규약에서 정수 인자가 10개인 함수를 호출할 때 9번째와 10번째 인자는 어디로 …

  • 실행 파일 안에 지역 변수를 위한 섹션은 없으며, 함수 시작 부분에서 스택 포인터를 움직여 영역을 확보합니다.

    C 언어 함수 안에서 선언한, static이 붙지 않은 지역 변수(자동 변수)는 실행 중 어디에 놓입니까?

  • 컨텍스트 스위치에서는 나중에 같은 상태에서 재개할 수 있도록 범용 레지스터, 프로그램 카운터, 스택 포인터, 동작 모드 등 CPU의 상태를 저장하고, 다음에 실행할 프로세스의 상태를 읽어 들입니다.

    컨텍스트 스위치에서 전환 전 프로세스에 대해 저장해 두어야 하는 것은?

스택 포인터(stack pointer)이(가) 나오는 문제 (5)

  1. RISC-V의 표준 호출 규약에서는 함수에 진입할 때의 스택 포인터 sp를 16바이트의 배수로 맞추게 되어 있다. 그 이유로 가장 적절한 것은?
  2. 프로그램에서 서브루틴(함수)을 호출할 때 복귀 주소 등을 일시적으로 저장하기 위해 일반적으로 사용되는 영역은?
  3. RISC-V의 표준 호출 규약에서 정수 인자가 10개인 함수를 호출할 때 9번째와 10번째 인자는 어디로 전달되는가?
  4. C 언어 함수 안에서 선언한, static이 붙지 않은 지역 변수(자동 변수)는 실행 중 어디에 놓입니까?
  5. 컨텍스트 스위치에서 전환 전 프로세스에 대해 저장해 두어야 하는 것은?
