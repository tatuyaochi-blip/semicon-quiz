추상 구문 트리(AST)란?

프로그램의 구조를 연산이나 문을 노드로 한 트리로 나타낸 것. 괄호나 구분 기호 등 의미 없는 정보는 생략하고, 연산자 우선순위는 트리의 형태로 나타낸다.

일본어 명칭: 抽象構文木(AST)

추상 구문 트리(AST)은(는) 컴파일러 등 1개 분야의 연습 문제 2개에 나와요.

분야: 컴파일러

파스 트리에서 AST로

문법을 글자 그대로 따르는 파서는 구체 구문 트리(파스 트리)를 만들며, 적용된 모든 문법 규칙마다 노드가, 괄호, 쉼표, 세미콜론을 포함한 모든 토큰마다 잎이 생깁니다. 식, 항, 인자(factor)에 대한 별도 규칙으로 우선순위를 표현하는 문법은 자식이 하나뿐인 노드의 긴 사슬도 만듭니다. AST(추상 구문 트리)는 이 모든 것을 버립니다. 각 노드는 이항 연산, 함수 호출, if 문, 변수 참조처럼 의미 있는 구문 요소이며, 그 요소에 필요한 자식만 정확히 가집니다.

트리 모양이 우선순위와 결합성을 표현하는 방식

먼저 계산되는 연산일수록 트리의 더 깊은 곳에 위치합니다. 2 + 3 * 4에서는 루트가 +이고 자식이 2와, 3과 4를 거느린 * 노드입니다. (2 + 3) * 4에서는 루트가 *가 되며, 괄호는 역할을 다하고 사라집니다. 결합성도 같은 방식으로 표현됩니다. a - b - c는 (a - b) - c를 뜻하므로 루트의 왼쪽 자식이 또 하나의 뺄셈이 되어 왼쪽으로 기운 트리가 됩니다. 따라서 자식을 부모보다 먼저 방문하는 후위 순회로 식을 올바른 순서로 계산할 수 있습니다.

컴파일러가 AST로 하는 일

파싱 후 의미 분석 단계는 AST를 순회하면서 각 이름을 그 선언에 연결하고, 타입을 검사하고 추론하며, 암시적 변환을 삽입하고, 선언되지 않은 변수 사용 같은 오류를 보고합니다. 노드에는 보통 이러한 정보가 주석으로 붙습니다. 주석이 붙은 트리는 이후 3주소 코드나 SSA 형식 같은 중간 표현(IR)으로 변환(lowering)되며, 여기서 제어 흐름은 기본 블록 사이의 명시적 분기가 됩니다. 단순한 트리 순회 인터프리터는 AST를 직접 실행하며, 포매터, 린터, 리팩터링 엔진 같은 도구도 AST를 대상으로 동작합니다.

AST와 IR의 차이

AST는 소스 언어를 그대로 반영합니다. 중첩된 루프, 구조화된 if 문, 소스 수준의 식을 여전히 가지고 있어, 작성된 그대로의 프로그램을 참조하는 검사와 변환에 이상적입니다. IR은 기계에 더 가까워, 단순한 연산의 평평한 나열과 명시적인 점프로 이루어지며 데이터 흐름 분석과 최적화에 적합합니다. 둘을 혼동하는 경우가 많지만, 경계는 대략 이렇습니다. AST는 프로그래머가 무엇을 작성했는지에 답하고, IR은 무엇을 계산해야 하는지에 답합니다.

추상 구문 트리(AST)의 특징으로 올바른 것은?

  1. A소스 코드의 괄호나 구분 기호까지 모두 노드로 남겨 둔다
  2. B의미와 관계없는 기호를 생략하고 연산자의 우선순위를 트리 형태로 나타낸다
  3. CCPU의 명령과 1대1로 대응하며 그대로 실행할 수 있다
정답과 해설 보기

정답: B. 의미와 관계없는 기호를 생략하고 연산자의 우선순위를 트리 형태로 나타낸다

구문 분석에서는 문법 규칙대로 괄호나 구분 기호까지 포함한 트리(구체 구문 트리)가 만들어지지만, 이후의 처리에는 불필요한 정보가 많이 들어 있습니다. 추상 구문 트리는 프로그램의 의미에 필요한 연산과 문장만을 노드로 한 트리로, 예를 들어 (a + b) * c에서는 곱셈 노드 아래에 덧셈 노드가 오므로 괄호가 없어도 계산 순서를 알 수 있습니다. CPU의 명령에 대응하는 것은 더 뒤의 단계에서 생성하는 코드입니다.

식 2 + 3 * 4의 추상 구문 트리의 형태로 올바른 것은?

  1. A루트는 + 노드이고, 그 오른쪽 자식이 3 * 4를 나타내는 * 노드가 된다
  2. B루트는 * 노드이고, 그 왼쪽 자식이 2 + 3을 나타내는 + 노드가 된다
  3. C2, 3, 4, +, * 의 5개 노드가 모두 루트의 직접 자식으로 나란히 놓인다
정답과 해설 보기

정답: A. 루트는 + 노드이고, 그 오른쪽 자식이 3 * 4를 나타내는 * 노드가 된다

곱셈은 덧셈보다 우선순위가 높으므로 이 식은 2 + (3 * 4)로 해석됩니다. 추상 구문 트리에서는 먼저 계산하는 연산일수록 아래에 놓이므로, 루트는 +이고 그 왼쪽 자식이 2, 오른쪽 자식이 3과 4를 자식으로 갖는 * 노드가 됩니다. 트리를 아래에서부터 평가하면 3 * 4 = 12를 먼저 계산하고 2 + 12 = 14를 얻습니다. 루트가 *가 되는 것은 (2 + 3) * 4라고 쓴 경우이며, 모두를 루트의 자식으로 나열하면 계산 순서를 나타낼 수 없습니다.

자주 묻는 질문

파스 트리와 추상 구문 트리의 차이는 무엇인가요?

파스 트리는 구두점을 포함한 모든 문법 규칙과 토큰을 기록하고, AST는 의미를 가진 구문 요소만 남깁니다. 파스 트리가 규칙의 사슬로 나타내는 우선순위를 AST는 어느 노드가 부모인지만으로 나타냅니다.

AST에서 괄호는 어떻게 표현되나요?

노드로 저장되지 않습니다. 괄호의 효과는 트리 구조에 반영되어, 괄호로 묶인 부분식은 부모 연산보다 먼저 계산되는 하위 트리가 됩니다.

인터프리터도 AST를 사용하나요?

많이 사용합니다. 트리 순회 인터프리터는 AST를 직접 평가하고, 더 빠른 인터프리터는 보통 AST를 먼저 바이트코드로 컴파일한 뒤 그것을 실행합니다.
