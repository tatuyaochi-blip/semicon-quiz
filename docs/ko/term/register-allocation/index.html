레지스터 할당(Register Allocation)란?

프로그램의 변수와 중간 값을 한정된 수의 CPU 레지스터에 배정하는 컴파일러 처리. 동시에 쓰이는 값끼리 같은 레지스터가 되지 않도록 간섭 그래프의 채색 등으로 정한다.

일본어 명칭: レジスタ割り当て

레지스터 할당(Register Allocation)은(는) 컴파일러 등 1개 분야의 연습 문제 3개에 나와요.

분야: 컴파일러

도전해 보기: 레지스터 할당(Register Allocation) 관련 문제

컴파일러의 레지스터 할당에서 간섭 그래프를 색칠하는(채색하는) 방법을 사용할 때, 그래프의 노드와 간선이 나타내는 것의 조합으로 올바른 것은?

  1. A노드는 명령, 간선은 명령의 실행 순서
  2. B노드는 레지스터, 간선은 레지스터끼리의 배선
  3. C노드는 값, 간선은 동시에 살아 있는 관계
정답과 해설 보기

정답: C. 노드는 값, 간선은 동시에 살아 있는 관계

간섭 그래프에서는 변수나 중간 값을 노드로 하고, 어느 시점에 둘 다 아직 사용되는(살아 있는) 두 값을 간선으로 연결합니다. 간선으로 이어진 값은 동시에 필요하므로 같은 레지스터에 넣을 수 없습니다. 레지스터 수를 k개로 하여 이웃끼리 같은 색이 되지 않도록 k색으로 칠할 수 있다면, 색을 그대로 레지스터에 대응시켜 할당할 수 있습니다. 칠할 수 없는 경우에는 일부 값을 메모리로 내보냅니다(스필). 명령의 순서나 레지스터의 배선을 나타내는 그래프가 아닙니다.

레지스터 할당에서 「스필」이 일어나면 생성되는 코드는 어떻게 되는가?

  1. A값을 스택에 내보내고 다시 읽어 들이는 명령이 늘어 느려지기 쉽다
  2. B레지스터의 수가 자동으로 늘어나 모든 값을 레지스터에 둘 수 있게 된다
  3. C사용되지 않는 값이 삭제되어 명령의 수가 줄어든다
정답과 해설 보기

정답: A. 값을 스택에 내보내고 다시 읽어 들이는 명령이 늘어 느려지기 쉽다

스필은 동시에 살아 있는 값이 레지스터 수보다 많을 때 일부 값을 메모리(스택)에 두는 것입니다. 그 값을 사용할 때마다 읽기 명령, 바꿀 때마다 쓰기 명령이 필요해 명령이 늘고 메모리 접근만큼 느려지기 쉽습니다. 그래서 컴파일러는 루프 안 등 자주 사용되는 값을 레지스터에 남기고, 별로 사용되지 않는 값을 골라 스필시킵니다. 레지스터의 수는 CPU로 정해져 있어 늘어나지 않으며, 불필요한 값의 삭제와도 다른 이야기입니다.

레지스터 할당(Register Allocation)이(가) 나오는 문제 (3)

  1. 컴파일러의 레지스터 할당에서 간섭 그래프를 색칠하는(채색하는) 방법을 사용할 때, 그래프의 노드와 간선이 나타내는 것의 조합으로 올바른 것은?
  2. 레지스터 할당에서 「스필」이 일어나면 생성되는 코드는 어떻게 되는가?
  3. 레지스터 할당의 준비로 수행하는 생존 구간(라이브니스) 분석에서 구하는 것은?

관련 용어

스필(Spill) 제어 흐름 그래프(Control Flow Graph) 강도 감소(Strength Reduction) 공통 부분식 제거(CSE) 구문 분석(Parsing) 기본 블록(Basic Block) 루프 언롤링(Loop Unrolling) 명령어 스케줄링(instruction scheduling) 벡터화(vectorization) 상수 폴딩(constant folding)
