SIMD란?

Single Instruction, Multiple Data의 약어. 하나의 명령으로 여러 데이터에 같은 연산을 동시에 수행하는 방식. 영상 처리와 AI 연산을 고속화한다.

일본어 명칭: SIMD

SIMD은(는) 컴파일러, GPU 프로그래밍, CPU와 아키텍처 등 5개 분야의 연습 문제 7개에 나와요.

분야: CPU와 아키텍처

SIMD의 원리

SIMD(single instruction, multiple data) 유닛은 넓은 레지스터를 독립적인 레인의 집합으로 취급합니다. 128비트 레지스터에는 32비트 값 4개, 512비트 레지스터에는 16개가 들어가며, 덧셈 명령어 하나로 모든 레인을 병렬로 더합니다. x86의 SSE와 AVX, Arm의 NEON과 SVE 같은 명령어 집합 확장은 정수 및 부동소수점 레인 연산과 함께 로드, 셔플, 비교 명령어를 제공합니다. 플린의 분류에서 SIMD는 일반적인 순차 프로세서인 SISD, 그리고 여러 코어가 독립적인 명령어 흐름을 실행하는 MIMD와 나란히 놓입니다. 이미지 필터, 비디오 코덱, 행렬 연산은 보통 몇 배 이상 빨라집니다.

루프를 벡터화할 수 있는 조건

컴파일러는 배열의 각 요소에 같은 연산을 적용하는 루프를 자동 벡터화합니다. 핵심 조건은 루프 전달 의존성이 없는 것입니다. a[i] = a[i-1] + b[i]에서는 각 요소가 이전 결과를 필요로 하므로 레인을 동시에 실행할 수 없습니다. 데이터는 연속적이어야 하며, 포인터가 겹칠 가능성(에일리어싱)이 있으면 컴파일러가 벡터화를 포기할 수 있습니다. 컴파일 시점에 반복 횟수를 모르는 것은 장애가 되지 않습니다. 벡터 루프가 꽉 찬 덩어리를 처리하고 짧은 나머지 루프가 남은 부분을 처리합니다. 미디어 코드는 포화 연산도 사용하는데, 8비트 부호 있는 127 + 1은 −128로 순환하지 않고 127로 고정됩니다.

데이터 배치: AoS와 SoA

구조체 배열(AoS)은 x, y, z, 질량처럼 각 레코드의 필드를 함께 저장합니다. 그러면 x만 읽는 루프는 각 캐시 라인의 대부분을 낭비하고, 벡터 레인을 채우기 위해 개더나 셔플 작업이 필요합니다. 배열 구조체(SoA)는 모든 x 값을 연속으로 두므로 가져온 라인이 모두 사용되고, 메모리 트래픽이 크게 줄 수 있으며, 벡터 로드 하나로 레인을 직접 채울 수 있습니다. 같은 배치는 인접한 GPU 스레드가 인접한 주소를 읽게 하여 메모리 접근을 병합(coalescing)할 수 있게 합니다.

SIMD와 SIMT

CPU SIMD에서는 프로그래머나 컴파일러가 고정 폭 벡터 명령어를 명시적으로 사용하므로, 코드를 벡터 폭을 염두에 두고 작성합니다. GPU SIMT(single instruction, multiple threads)는 프로그래머가 스레드 하나에 대한 일반 코드를 작성하게 하고, 하드웨어가 보통 32개의 스레드를 묶어 공통 명령어 발행으로 보조를 맞춰 실행합니다. 그룹 안의 스레드가 서로 다르게 분기하면, 하드웨어는 비활성 스레드를 마스킹한 채 각 경로를 차례로 실행하므로 코드는 여전히 동작하지만 효율이 떨어집니다. 근본적으로 둘 다 하나의 명령어를 많은 데이터 요소에 분산시킨다는 같은 원리에 기반합니다.

도전해 보기: SIMD 관련 문제

GPU의 SIMT(단일 명령·다중 스레드) 방식과 CPU의 SIMD 명령의 차이로 올바른 것은?

  1. ASIMT는 하나의 데이터에 여러 명령을 동시에 수행하고, SIMD는 하나의 명령을 하나의 데이터에 수행한다
  2. BSIMT와 SIMD는 완전히 같은 것이며 이름만 다르다
  3. CSIMT에서는 각 스레드를 독립된 프로그램으로 작성할 수 있고 분기도 하드웨어가 처리하지만, SIMD에서는 프로그래머나 컴파일러가 폭이 정해진 벡터 명령을 명시적으로 사용한다
정답과 해설 보기

정답: C. SIMT에서는 각 스레드를 독립된 프로그램으로 작성할 수 있고 분기도 하드웨어가 처리하지만, SIMD에서는 프로그래머나 컴파일러가 폭이 정해진 벡터 명령을 명시적으로 사용한다

CPU의 SIMD에서는 4개나 8개의 데이터를 묶은 벡터 레지스터에 하나의 명령을 적용하므로, 프로그램은 벡터 폭을 의식하여 작성합니다. GPU의 SIMT에서는 프로그래머가 하나의 스레드 처리를 평범하게 작성하면 하드웨어가 32개씩 묶어 같은 명령으로 실행합니다. 스레드별로 분기해도 되며 하드웨어가 갈라진 경로를 차례로 실행하지만, 이때는 효율이 떨어집니다.

자주 묻는 질문

SIMD는 무엇의 약자이고 무엇을 하나요?

Single instruction, multiple data의 약자로, 하나의 명령어가 128비트 레지스터에 담긴 32비트 수 4개처럼 넓은 레지스터에 묶인 여러 데이터 요소를 처리합니다.

루프가 자동 벡터화되지 않는 이유

흔한 이유는 반복이 이전 반복의 결과를 필요로 하는 루프 전달 의존성, 연속적이지 않은 메모리 접근, 또는 컴파일러가 배제할 수 없는 포인터 에일리어싱 가능성입니다.

SIMD와 SIMT 차이

SIMD는 CPU에서 명시적인 고정 폭 벡터 명령어를 사용합니다. GPU에서 쓰이는 SIMT는 스레드별 스칼라 코드를 스레드 그룹에서 보조를 맞춰 실행하며, 분기 발산은 하드웨어가 처리합니다.

해설 속 SIMD

  • 벡터화에서는 예를 들어 4개 요소의 계산을 하나의 SIMD 명령으로 동시에 수행합니다.

    위의 루프를 SIMD 명령으로 벡터화하기 어려운 주된 이유는?

  • CPU의 SIMD에서는 4개나 8개의 데이터를 묶은 벡터 레지스터에 하나의 명령을 적용하므로, 프로그램은 벡터 폭을 의식하여 작성합니다.

    GPU의 SIMT(단일 명령·다중 스레드) 방식과 CPU의 SIMD 명령의 차이로 올바른 것은?

  • SIMD는 하나의 명령어로 여러 데이터에 같은 연산을 병렬로 수행하는 방식으로, 예를 들어 512비트 레지스터라면 32비트 수치 16개를 한 번에 계산할 수 있습니다.

    하나의 명령어로 여러 데이터에 같은 연산을 동시에 수행하는 방식은?

  • DSP나 SIMD 명령에 마련되어 있습니다.

    신호 처리에서 사용되는 포화 연산의 설명으로 올바른 것은 무엇입니까?

  • 자동 벡터화는 배열의 요소마다 같은 계산을 하는 루프를 찾아 여러 요소를 한꺼번에 처리하는 SIMD 명령으로 대체하는 최적화입니다.

    컴파일러의 자동 벡터화에서 사용되는 명령의 종류로 올바른 것은 무엇인가?
