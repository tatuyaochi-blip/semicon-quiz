시스템 콜(system call)란?

애플리케이션이 파일 읽기·쓰기나 메모리 할당 등을 OS에 요청하는 구조. 전용 명령으로 예외를 일으켜 특권 모드로 전환하고 커널 처리를 호출한다.

일본어 명칭: システムコール

시스템 콜(system call)은(는) OS와 하드웨어, ISA와 어셈블리, 링커, 로더, 실행 파일 등 4개 분야의 연습 문제 11개에 나와요.

시스템 콜에서는 사용자 모드에서 특권 모드로의 전환, 레지스터 저장, 인수 확인, 복귀 처리 등이 매번 필요하며, 처리하는 양이 1바이트여도 이 고정 부담이 듭니다. 또한 커널에 진입하면 캐시나 TLB의 내용도 흐트러집니다. 버퍼에 모아 수 KB씩 한꺼번에 쓰면 시스템 콜 횟수가 크게 줄어 전체가 빨라집니다. 기록하는 데이터의 총량은 변하지 않으며, 결국에는 디스크에 기록됩니다.

  • ABI는 컴파일된 프로그램이나 라이브러리가 함께 동작하기 위한 기계어 수준의 약속으로, 호출 규약, int·long·포인터의 크기, 구조체 정렬, 시스템 콜 호출 방법 등을 포함합니다.

    ABI(애플리케이션 바이너리 인터페이스)에 대한 설명으로 올바른 것은?

  • malloc은 스스로 빈 영역을 관리하고, 부족해지면 OS에 요청하여 영역을 넓힙니다(Linux에서는 brk나 mmap 시스템 콜).

    C 언어의 malloc으로 확보한 메모리는 일반적으로 프로세스의 어느 영역에서 가져옵니까?

  • 그래서 시스템 콜을 사용하여 전용 명령으로 특권 모드로 전환하고 커널의 처리를 호출해 파일 읽기·쓰기, 메모리 할당, 프로세스 생성 등을 요청합니다.

    애플리케이션이 파일 읽기·쓰기 등을 OS에 요청하는 구조를 무엇이라고 합니까?

  • 커널은 a7의 번호로 어떤 시스템 콜인지 판단하고 a0~a2를 인수로 처리한 뒤 결과를 돌려주고 사용자 모드로 돌아갑니다.
