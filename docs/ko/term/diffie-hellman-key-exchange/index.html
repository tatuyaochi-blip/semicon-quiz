디피-헬먼 키 교환(Diffie-Hellman Key Exchange)란?

공개된 통신로만 사용하여 두 당사자가 공유 비밀을 만드는 방법. 1976년에 디피와 헬먼이 발표했다. 소수 p와 생성원 g를 공개하고, A 씨와 B 씨가 비밀 값 a, b로부터 g^a mod p, g^b mod p를 만들어 서로 보낸 뒤, 각자 상대의 값을 자신의 비밀 값으로 거듭제곱하여 같은 g^(ab) mod p를 얻는다. 안전성은 이산 로그 문제의 어려움에 기반한다. 타원 곡선 위에서 수행하는 것을 ECDH, 연결마다 일회용 값을 사용하는 것을 DHE·ECDHE라고 부르며, 후자에서는 전방향 안전성을 얻을 수 있다. 상대를 확인하는 기능은 없으므로, 서명이나 인증서와 조합하여 중간자 공격을 막는다.

일본어 명칭: ディフィー・ヘルマン鍵交換

키 교환으로 얻어지는 공유 비밀은 타원 곡선 위의 점의 좌표 등으로, 모든 비트가 균일하게 무작위라고는 할 수 없습니다. HKDF는 HMAC을 사용해 먼저 공유 비밀로부터 치우침 없는 의사 난수 키를 추출하고(Extract), 다음으로 이를 '클라이언트에서 서버로의 암호화용' 같은 레이블과 함께 확장하여(Expand) 필요한 개수와 길이의 키를 만듭니다. 용도별로 독립된 키를 사용하면 하나의 키에 생긴 문제가 다른 용도로 번지기 어려워집니다. 비밀번호로부터 키를 만드는 PBKDF2나 Argon2는 일부러 계산을 무겁게 하지만, HKDF는 엔트로피가 충분히 큰 입력을 전제로 한 가벼운 처리입니다.

디피-헬먼 키 교환에서는 소수 p와 생성원 g를 공개하고, A 씨와 B 씨가 각각 비밀 값 a, b를 골라 g^a mod p와 g^b mod p를 서로 보낸다. 도청자가 이렇게 공개된 값을 모두 보더라도 공유 비밀 g^(ab) mod p를 구할 수 없다고 생각되는 이유로 올바른 것은?

  1. Ag^a mod p로부터 a를 구하는 문제(이산 로그 문제)는 p가 크면 효율적으로 풀 수 없다고 생각되기 때문에
  2. Bg^a mod p와 g^b mod p는 보내기 전에 상대의 공개 키로 다시 암호화되므로 도청자는 읽을 수 없기 때문에
  3. C공유 비밀은 두 사람이 미리 만나서 정한 암호 문구로부터 만들기 때문에

정답: A. g^a mod p로부터 a를 구하는 문제(이산 로그 문제)는 p가 크면 효율적으로 풀 수 없다고 생각되기 때문에

g^a mod p를 계산하는 것은 빠른 데 비해, 결과로부터 a를 구하는 것은 p가 충분히 크면 현실적인 시간 안에는 할 수 없다고 생각됩니다(이산 로그 문제). 도청자는 g^a mod p와 g^b mod p를 볼 수 있어도 a나 b를 모르면 g^(ab) mod p를 만들 수 없습니다. 한편 A 씨는 B 씨의 값을 a제곱하고, B 씨는 A 씨의 값을 b제곱하기만 하면 둘 다 같은 g^(ab) mod p를 얻습니다. 타원 곡선 위에서 같은 일을 하는 것이 ECDH이며, 타원 곡선 위의 이산 로그 문제의 어려움에 기반합니다.
