IPC란?

Instructions Per Cycle의 약자로, 1클록당 실행할 수 있는 명령 수. CPU 설계상의 효율을 나타내며 성능은 대체로 IPC와 클록 주파수의 곱이 된다. 역수는 CPI.

일본어 명칭: IPC

IPC은(는) CPU와 아키텍처, 성능 분석, 데이터시트 읽는 법 등 3개 분야의 연습 문제 6개에 나와요.

분야: CPU와 아키텍처

성능 방정식에서의 IPC

프로그램 실행 시간은 명령어 수에 명령어당 사이클 수(CPI, cycles per instruction)를 곱하고 클록 주파수로 나눈 값입니다. IPC(instructions per cycle)는 CPI의 역수이므로, 같은 프로그램에서 성능은 IPC와 주파수의 곱에 비례합니다. 3 GHz 코어의 사이클 시간은 약 0.33 ns이지만, 같은 3 GHz 프로세서 두 개라도 IPC가 다르면 속도가 크게 달라질 수 있습니다. 명령어 세트가 다르면 같은 작업에 필요한 명령어 수가 다르므로, IPC 비교는 같은 프로그램과 같은 명령어 세트에서만 의미가 있습니다.

IPC를 높이는 요소

단순한 파이프라인은 사이클당 1명령을 목표로 합니다. 슈퍼스칼라 코어는 사이클당 여러 개의 독립된 명령을 발행하며, 최근 고성능 설계는 약 6~10폭입니다. 비순차(out-of-order) 실행은 앞선 명령이 대기하는 동안 뒤의 독립된 명령을 실행해 이 유닛들을 계속 가동시키고, 분기 예측은 파이프라인 플러시를 피하며, 대용량 캐시와 프리페치는 메모리 지연을 숨깁니다. 다만 폭을 무한정 늘릴 수는 없습니다. 의존성 검사 로직은 발행 폭의 대략 제곱에 비례해 커지고, 실제 프로그램이 제공하는 명령어 수준 병렬성에는 한계가 있으므로 실제 IPC는 최대 폭보다 훨씬 낮게 머뭅니다.

IPC를 떨어뜨리는 요소

가장 큰 손실은 스톨입니다. DRAM까지 가는 최종 레벨 캐시 미스는 수백 사이클이 걸릴 수 있고, 분기 예측 실패는 깊은 파이프라인에 이미 들어간 작업을 버리게 하며, 의존 관계가 있는 명령의 연쇄는 실행을 직렬화합니다. 폭이 넓은 코어에서 IPC가 0.3처럼 1보다 훨씬 낮다면 대개 코어가 대부분의 시간을 메모리 대기에 쓰고 있다는 뜻입니다. 이 경우 지역성을 고려한 데이터 재구성, 루프 순서 변경, 캐시 재사용을 위한 블로킹이 어떤 컴파일러 플래그보다도 효과적인 경우가 많습니다. 클록 주파수를 높여도 나노초 단위의 메모리 지연은 짧아지지 않으므로, 메모리 바운드 코드는 주파수가 올라갈수록 IPC가 떨어집니다.

IPC 측정

프로세서에는 사이클, 리타이어된 명령, 각 레벨의 캐시 미스, TLB 미스, 분기 예측 실패를 세는 하드웨어 카운터를 갖춘 성능 모니터링 유닛(PMU)이 있습니다. 리타이어된 명령 수를 사이클 수로 나누면 바로 IPC가 됩니다. Linux perf 같은 도구는 프로그램 실행 중에 이 카운터를 읽으며, IPC를 미스율이나 예측 실패율과 비교하면 시간이 메모리, 분기, 연산 중 어디에 쓰이는지 알 수 있습니다. 최신 CPU는 부하와 온도에 따라 주파수를 끊임없이 바꾸므로, 실제 경과 시간보다 사이클 수를 세는 편이 마이크로아키텍처 효율을 더 명확하게 보여 줍니다.

도전해 보기: IPC 관련 문제

성능 카운터로 측정했더니 어떤 프로그램의 IPC(1사이클당 명령어 수)가 0.3으로 매우 낮고 최종 단계 캐시 미스가 많았다. 가장 가능성이 높은 상황과 대책의 조합은?

  1. A메모리 대기로 CPU가 멈춰 있는 시간이 길다. 데이터 배치를 바꾸거나 블로킹을 수행하여 캐시를 효과적으로 사용한다
  2. B연산이 너무 빠르다. 주파수를 올린다
  3. C분기가 너무 적다. 분기를 늘린다
정답과 해설 보기

정답: A. 메모리 대기로 CPU가 멈춰 있는 시간이 길다. 데이터 배치를 바꾸거나 블로킹을 수행하여 캐시를 효과적으로 사용한다

현재의 CPU는 1사이클에 수 개의 명령어를 실행할 수 있으므로, IPC가 0.3이라는 것은 대부분의 시간 무언가를 기다리고 있음을 나타냅니다. 최종 단계 캐시 미스가 많다면 주기억장치로부터의 데이터를 기다리는 시간이 길다고 생각할 수 있습니다. 데이터를 연속된 주소에 배치하거나, 루프 순서를 바꾸거나, 블로킹으로 같은 데이터를 여러 번 사용하는 등으로 캐시 미스를 줄이는 것이 효과적입니다.

자주 묻는 질문

클록 속도와 IPC 중 어느 쪽이 높은 게 더 좋나요?

성능은 둘의 곱으로 결정되므로 어느 한쪽만으로 속도가 정해지지 않습니다. 같은 프로그램이라면 클록이 낮더라도 IPC가 훨씬 높은 코어가 클록이 더 높은 코어보다 빠를 수 있습니다.

내 프로그램의 IPC 측정 방법

Linux perf 등으로 하드웨어 성능 카운터를 사용해 리타이어된 명령 수와 사이클 수를 셉니다. IPC는 명령 수를 사이클 수로 나눈 값입니다. 값이 낮다면 캐시 미스 수와 분기 예측 실패 수가 그 원인을 설명하는 데 도움이 됩니다.

IPC가 낮다는 것은 무슨 뜻인가요?

코어가 많은 사이클 동안 놀고 있다는 뜻입니다. 가장 흔한 원인은 캐시 미스 후 메모리에서 데이터를 기다리는 것이며, 분기 예측 실패로부터의 복구나 긴 의존성 체인도 원인이 됩니다.

해설 속 IPC

  • 현재의 CPU는 1사이클에 수 개의 명령어를 실행할 수 있으므로, IPC가 0.3이라는 것은 대부분의 시간 무언가를 기다리고 있음을 나타냅니다.

    성능 카운터로 측정했더니 어떤 프로그램의 IPC(1사이클당 명령어 수)가 0.3으로 매우 낮고 최종 단계 …

  • 슈퍼스칼라는 여러 연산기를 갖추고 서로 의존하지 않는 명령어를 1클록에 여러 개 발행하여 IPC를 1보다 크게 만드는 방식입니다.

    1클록 사이클에 여러 명령어를 동시에 발행·실행하는 프로세서 방식을 무엇이라 하는가?

  • IPC(Instructions Per Clock)는 1클록당 평균 실행 명령어 수로 CPI의 역수입니다.

    1클록당 실행할 수 있는 명령어 수를 나타내는 지표는?

  • 다만 1클록에 실행할 수 있는 명령어 수(IPC)는 설계에 따라 크게 다르므로 주파수만으로는 성능을 비교할 수 없습니다.

    클록 주파수 3 GHz인 CPU에 대한 설명으로 올바른 것은?

  • MSL은 IPC와 JEDEC의 공동 규격(분류는 J-STD-020, 취급은 J-STD-033)에서 정한 습기 민감도 등급으로, 방습 봉투를 개봉한 후 리플로까지 허용되는 시간(플로어 라이프)을 나타냅니다.

    MSL 3(습기 민감도 레벨 3)으로 표시된 표면 실장 부품의 취급으로 올바른 것은 무엇입니까?

  2. 1클록 사이클에 여러 명령어를 동시에 발행·실행하는 프로세서 방식을 무엇이라 하는가?
  3. 1클록당 실행할 수 있는 명령어 수를 나타내는 지표는?
  4. 클록 주파수 3 GHz인 CPU에 대한 설명으로 올바른 것은?
  5. MSL 3(습기 민감도 레벨 3)으로 표시된 표면 실장 부품의 취급으로 올바른 것은 무엇입니까?
  6. CPU에 내장된 성능 카운터(PMU)로 셀 수 있는 것의 예로 올바른 것은?
