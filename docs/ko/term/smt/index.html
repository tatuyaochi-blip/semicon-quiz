SMT(동시 멀티스레딩)란?

하나의 CPU 코어에서 여러 스레드의 명령을 동시에 처리해 코어 안의 연산기를 효율적으로 쓰는 기술. Intel은 하이퍼스레딩이라 부른다.

일본어 명칭: SMT(同時マルチスレッディング)

SMT(동시 멀티스레딩)은(는) 하드웨어 보안, CPU와 아키텍처 등 2개 분야의 연습 문제 2개에 나와요.

분야: CPU와 아키텍처

SMT가 하나의 코어를 공유하는 방식

최신 비순차(out-of-order) 실행 코어는 사이클당 여러 명령을 발행할 수 있지만, 단일 스레드는 의존성, 분기 예측 실패, 캐시 미스 때문에 모든 실행 유닛을 바쁘게 유지하는 경우가 드뭅니다. 동시 멀티스레딩(SMT)은 하드웨어 스레드마다 프로그램 카운터와 아키텍처 레지스터 같은 별도의 아키텍처 상태를 코어에 제공하고, 실행 유닛, 캐시, 분기 예측기, 내부 버퍼는 스레드들이 공유합니다. 같은 사이클에 서로 다른 스레드의 명령을 서로 다른 유닛으로 발행할 수 있습니다. 운영 체제는 각 하드웨어 스레드를 논리 프로세서로 인식하며, 보통 코어당 두 개입니다.

기대할 수 있는 성능 향상

스레드들이 같은 실행 자원을 두고 경쟁하므로, SMT는 두 번째 코어처럼 성능을 두 배로 만들지 못합니다. 일반적인 향상 폭은 약 0–30%입니다. 메모리를 기다리는 작업처럼 자주 멈추는 작업이 가장 큰 이득을 얻습니다. 한 스레드가 캐시 미스를 기다리는 동안 다른 스레드가 유닛을 계속 사용하기 때문입니다. 이미 부동소수점 유닛이나 메모리 대역폭을 포화시키는 작업은 이득이 적고, 공유 캐시에서의 경합으로 개별 스레드가 오히려 느려질 수도 있으며, 이는 레이턴시에 민감한 애플리케이션에서 중요합니다.

SMT와 다른 멀티스레딩 방식

거친 단위(coarse-grained) 멀티스레딩은 캐시 미스 같은 긴 정지가 있을 때에만 다른 스레드로 전환합니다. 세밀한 단위(fine-grained) 멀티스레딩은 사이클마다 스레드를 번갈아 실행하지만 사이클당 한 스레드에서만 발행하며, GPU와 일부 네트워크 프로세서에서 흔히 쓰입니다. SMT는 한 걸음 더 나아가 같은 사이클에 여러 스레드에서 발행하므로, 폭이 넓은 슈퍼스칼라 코어에 적합합니다. 반면 멀티코어는 코어 전체를 복제합니다. Intel은 2-way SMT를 하이퍼스레딩이라는 브랜드로 부르며, 일부 서버 프로세서는 코어당 4개나 8개의 스레드를 지원합니다.

보안과 스케줄링 문제

두 SMT 스레드는 L1 캐시, 분기 예측기, 실행 포트, 버퍼를 매우 세밀한 단위로 공유하므로, 한 스레드가 자신의 실행 시간을 측정하여 다른 스레드가 무엇을 하는지 추론할 수 있습니다. 여러 사이드 채널 취약점이 바로 이 구조에 의존합니다. 따라서 서로 다른 고객의 신뢰할 수 없는 코드를 같은 하드웨어에서 실행하는 시스템은 SMT를 비활성화하거나, 같은 신뢰 도메인의 스레드만 형제 논리 프로세서에 배치하는 코어 스케줄링을 사용할 수 있습니다. 둘 다 처리량을 줄이므로, 성능과 격리 사이에서 판단해야 합니다.

SMT에서는 하나의 코어 안에서 두 스레드가 동시에 동작하며, L1 캐시, 분기 예측기, 연산기, 버퍼 등을 세밀하게 공유합니다. 그래서 한쪽 스레드가 다른 쪽이 사용하는 자원을 시간 측정으로 관찰하기 쉬우며, 몇몇 취약점에서는 이것이 공격 조건이 되었습니다. 신뢰할 수 없는 상대와 같은 코어를 공유하지 않도록 SMT를 끄거나, 같은 코어에는 같은 이용자의 스레드만 배치합니다.

자주 묻는 질문

하이퍼스레딩과 SMT는 같은 것인가요?

네. 하이퍼스레딩은 Intel이 구현한 동시 멀티스레딩의 브랜드 이름으로, 각 물리 코어가 운영 체제에 두 개의 논리 프로세서로 보입니다.

SMT를 쓰면 CPU 성능이 두 배가 되나요?

아닙니다. 두 스레드가 한 코어의 실행 유닛과 캐시를 공유하므로, 일반적인 처리량 향상은 작업에 따라 약 0–30%로, 두 번째 코어를 추가하는 것보다 훨씬 작습니다.

일부 시스템에서 SMT를 비활성화하는 이유는 무엇인가요?

같은 코어의 스레드들은 캐시와 실행 자원을 밀접하게 공유하므로, 한 스레드가 타이밍 사이드 채널을 통해 다른 스레드를 관찰할 수 있습니다. SMT를 비활성화하거나 서로 신뢰하는 스레드끼리만 함께 스케줄링하면, 처리량은 다소 줄지만 이러한 노출을 없앨 수 있습니다.
