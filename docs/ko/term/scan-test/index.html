스캔 테스트(scan test)란?

회로 안의 플립플롭을 사슬 모양으로 이은 스캔 체인을 사용해 내부 상태를 설정·관측하며 테스트하는 방법.

일본어 명칭: スキャンテスト

스캔 테스트(scan test)은(는) 테스트와 검사 등 1개 분야의 연습 문제 3개에 나와요.

분야: 테스트와 검사

스캔 체인의 동작 원리

스캔 설계에서는 각 플립플롭을 입력단에 멀티플렉서가 달린 스캔 플립플롭으로 교체합니다. 스캔 인에이블 신호가 활성화되면 플립플롭들이 스캔 체인이라 불리는 시프트 레지스터로 연결되므로, 테스터는 원하는 상태를 모든 플립플롭에 시프트 인할 수 있습니다. 이어서 기능 클록을 한 번(캡처) 인가하면 조합 논리가 연산을 수행하고, 그 결과가 다시 플립플롭에 래치됩니다. 체인을 시프트 아웃하면 이 결과를 읽어 내는 동시에 다음 패턴을 시프트 인할 수 있습니다. 이를 통해 깊은 순차 논리를 테스트하는 어려운 문제가, 제어와 관측이 가능한 레지스터 사이의 조합 논리를 테스트하는 문제로 바뀝니다.

테스트 패턴, 고장 모델과 ATPG

스캔 패턴은 ATPG(자동 테스트 패턴 생성) 도구로 만듭니다. ATPG는 노드가 0 또는 1에 고정되었다고 가정하는 고착 고장(stuck-at fault), 그리고 노드의 전환이 너무 느린 경우를 모델링하여 실제 동작 속도의 캡처 클록(at-speed)으로 테스트하는 천이 고장(transition fault) 같은 고장 모델을 대상으로 합니다. 패턴 세트의 품질은 고장 검출률(fault coverage)로 나타냅니다. 스캔의 비용으로는 멀티플렉서와 배선에 따른 면적 증가, 플립플롭 입력에 더해지는 약간의 지연, 그리고 테스트 중 클록과 리셋을 제어 가능하게 유지하는 등의 DFT(테스트 용이화 설계) 규칙을 지키기 위한 설계 노력이 있습니다.

테스트 압축과 미지값(X)

대규모 칩에서는 플립플롭 수가 많아 압축하지 않은 스캔 데이터량과 시프트 시간이 막대해집니다. 테스트 압축은 논리를 다수의 짧은 체인으로 나누고, 온칩 디컴프레서로 데이터를 공급하며 출력은 컴팩터로 모읍니다. 패턴의 비트 대부분은 돈 케어(don't care)이므로 데이터량과 테스트 시간을 수십 분의 1 이하로 줄일 수 있습니다. 다만 컴팩션에는 약점이 있어, 초기화되지 않은 메모리, 아날로그 블록, 클록 도메인 크로싱에서 나오는 미지값(X)이 압축된 시그니처를 오염시킵니다. 따라서 설계 단계에서 X의 발생원을 피하고, X 마스킹으로 영향을 받는 스캔 셀을 차단합니다.

스캔 테스트와 바운더리 스캔의 차이

내부 스캔은 칩 내부의 플립플롭을 체인으로 연결하여 칩 안의 논리를 대상으로 합니다. IEEE 1149.1(JTAG)로 표준화된 바운더리 스캔은 칩의 I/O 핀에 스캔 셀을 배치하여, 보드 수준의 상호 연결과 솔더 접합부를 테스트하고 물리적 프로브 없이 핀을 구동하거나 관측할 수 있게 합니다. 두 방식은 상호 보완적이며, JTAG 포트는 내부 테스트 기능을 제어하는 데에도 자주 재사용됩니다. 스캔 패턴은 칩의 실제 사용 사례가 아니라 구조를 검사하므로, 어느 쪽도 기능 테스트를 완전히 대체하지는 못합니다.

스캔 테스트의 데이터 양과 테스트 시간을 줄이기 위해 칩 안에서 테스트 패턴을 전개하고 응답을 압축하는 기술을 무엇이라고 합니까?

  1. A테스트 압축(스캔 압축)
  2. B번인
  3. CIDDQ 테스트
정답과 해설 보기

정답: A. 테스트 압축(스캔 압축)

대규모 LSI에서는 스캔 테스트의 패턴 양이 방대해져 테스터의 메모리와 테스트 시간이 문제가 됩니다. 테스트 압축에서는 적은 입력 데이터를 칩 안의 전개 회로가 다수의 짧은 스캔 체인으로 배분하고, 출력도 압축 회로로 모아서 비교합니다. 패턴의 대부분의 비트는 어느 쪽이든 상관없는 값이므로, 데이터 양과 테스트 시간을 수십 분의 1 이하로 줄일 수 있습니다.

스캔 테스트에서 출력을 압축할 때, 시뮬레이션에서 값이 0인지 1인지 정해지지 않는 신호(불정값 X)를 제거하는 처리가 필요한 이유는 무엇입니까?

  1. A불정값이 압축된 결과에 섞이면 기대값과 비교할 수 없어 고장을 검출할 수 없게 되기 때문
  2. B불정값이 있으면 칩이 발열하기 때문
  3. C불정값이 있으면 클록이 멈추기 때문
정답과 해설 보기

정답: A. 불정값이 압축된 결과에 섞이면 기대값과 비교할 수 없어 고장을 검출할 수 없게 되기 때문

초기화되지 않은 메모리, 아날로그 회로, 서로 다른 클록의 경계 등에서 오는 불정값(X)은 압축 회로에서 다른 비트와 섞이면 압축 후 값 전체가 불정이 되어 올바른 기대값과 비교할 수 없게 됩니다. 그래서 X가 나오는 스캔 셀의 출력을 차단하는 X 마스킹이나, X가 생기기 어렵게 하는 설계상의 고안을 수행합니다. 발열이나 클록 정지와는 관계가 없습니다.

자주 묻는 질문

스캔 체인을 사용하는 목적은 무엇인가요?

스캔 체인은 테스트 중에 칩의 플립플롭을 시프트 레지스터로 연결하여 모든 내부 상태를 직접 설정하고 읽을 수 있게 합니다. 이를 통해 자동 생성된 패턴으로 높은 고장 검출률을 달성할 수 있습니다.

스캔 테스트와 JTAG 바운더리 스캔의 차이는 무엇인가요?

내부 스캔은 코어의 플립플롭을 체인으로 연결해 칩 내부 논리를 테스트하고, 바운더리 스캔(IEEE 1149.1)은 I/O 핀의 셀을 체인으로 연결해 보드 위 칩 간의 연결을 테스트합니다. 둘 다 직렬 시프트를 사용하지만 시스템의 서로 다른 부분을 담당합니다.

스캔 압축에서 미지값(X)이 왜 문제가 되나요?

출력 컴팩터에 들어간 X는 다른 비트와 섞여 압축 결과를 예측할 수 없게 만들므로, 기댓값과 비교할 수 없게 되고 고장을 놓칠 수 있습니다. X 마스킹과 X가 발생하지 않도록 하는 설계 기법으로 이를 방지합니다.
