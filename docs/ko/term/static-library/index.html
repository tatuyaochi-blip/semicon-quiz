정적 라이브러리(Static Library)란?

여러 오브젝트 파일을 하나로 모은 아카이브(Linux에서는 .a). 정적 링크 시 링커는 필요한 오브젝트만 꺼내 실행 파일에 포함시킨다.

일본어 명칭: 静的ライブラリ

정적 라이브러리(Static Library)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 3개에 나와요.

분야: 링커, 로더, 실행 파일

.a 파일의 내부

유닉스 계열 시스템에서 정적 라이브러리는 ar 도구로 만든 아카이브로, 예를 들어 ar rcs libfoo.a a.o b.o로 생성합니다. 오브젝트 파일을 헤더와 함께 이어 붙인 것에 불과하며, 여기에 정의된 각 전역 심볼을 그것을 정의한 멤버에 대응시키는 인덱스가 더해져 있어 링커가 모든 멤버를 훑지 않고도 정의를 찾을 수 있습니다. 명령줄 옵션 -lfoo를 주면 링커는 라이브러리 검색 경로에서 libfoo.so나 libfoo.a를 찾으며, GNU ld는 정적 링크를 요청하지 않는 한 둘 다 있으면 공유 버전을 우선합니다. Windows 툴체인은 같은 목적으로 .lib 파일을 사용합니다.

추출 단위는 오브젝트 파일

멤버가 필요하면 링커는 참조된 함수 하나만이 아니라 오브젝트 파일 전체를 포함시킵니다. 라이브러리의 소스 파일 하나가 함수 20개를 정의하고 프로그램이 그중 하나만 호출해도, 20개 모두와 그 함수들이 다시 참조하는 것까지 실행 파일에 들어갑니다. 그래서 C 표준 라이브러리 같은 라이브러리는 흔히 작은 소스 파일 여러 개로, 때로는 파일당 함수 하나로 빌드됩니다. 또는 -ffunction-sections와 -fdata-sections로 컴파일하고 --gc-sections로 링크하면, 링커가 멤버 안에서 참조되지 않는 함수를 버릴 수 있습니다.

링크 순서와 순환 의존

GNU 링커는 입력을 왼쪽에서 오른쪽으로 훑으며, 아카이브에 도달하면 그 시점에 정의되지 않은 참조를 해결하는 멤버만 추출하고 그 아카이브를 다시 방문하지 않습니다. 따라서 라이브러리는 그것을 사용하는 오브젝트보다 뒤에 와야 하며, 다른 라이브러리에 의존하는 라이브러리는 그 라이브러리보다 앞에 와야 합니다. 두 라이브러리가 서로 의존할 때의 일반적인 해결책은 하나를 두 번 나열하거나, 둘을 --start-group과 --end-group으로 감싸 새로 해결되는 것이 없을 때까지 링커가 다시 훑게 하는 것입니다. LLVM의 lld 같은 일부 링커는 모든 아카이브 심볼을 기억하므로 이런 순서가 필요 없습니다.

정적 라이브러리와 공유 라이브러리

정적 라이브러리는 빌드 시에만 쓰입니다. 그 코드는 각 실행 파일에 복사되며, 프로그램 실행 시에는 .a 파일이 필요 없습니다. 공유 라이브러리(Linux의 .so, Windows의 .dll)는 위치 독립 코드로 빌드된 하나의 링크된 파일로, 실행 시 적재되며 그 페이지는 이를 사용하는 모든 프로세스가 공유합니다. 정적 라이브러리는 자기 완결적인 배포와 임베디드 펌웨어에 적합하고, 공유 라이브러리는 디스크와 메모리를 절약하며 파일 하나만 교체하면 모든 프로그램에 수정이 반영됩니다.

정답: C. 라이브러리 안의 오브젝트 파일 중 정의되지 않은 참조를 해결하는 데 필요한 것만

정적 라이브러리는 많은 오브젝트 파일을 하나로 모은 아카이브입니다. 링커는 아직 정의를 찾지 못한 심볼을 정의하고 있는 오브젝트 파일만 아카이브에서 꺼내 포함시킵니다. 그래서 표준 라이브러리처럼 많은 함수를 포함한 라이브러리라도 사용한 함수만큼만 실행 파일이 커집니다.

GNU 링커에서 'gcc -lmylib main.o'처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 앞에 쓰면 정의되지 않은 참조 오류가 나는 경우가 있습니다. 그 이유로 올바른 것은 무엇입니까?

  1. A링커는 왼쪽부터 순서대로 처리하며, 라이브러리를 읽는 시점에 아직 참조되지 않은 함수는 꺼내지 않기 때문에
  2. B라이브러리는 반드시 명령의 맨 끝에 하나만 쓸 수 있는 규칙이기 때문에
  3. C라이브러리를 앞에 쓰면 라이브러리 내용이 지워지기 때문에
정답과 해설 보기

정답: A. 링커는 왼쪽부터 순서대로 처리하며, 라이브러리를 읽는 시점에 아직 참조되지 않은 함수는 꺼내지 않기 때문에

GNU 링커는 명령줄에 쓰인 순서대로 파일을 처리하며, 정적 라이브러리를 만난 시점에 '아직 정의를 찾지 못한 참조'를 해결하는 오브젝트만 꺼냅니다. 라이브러리를 먼저 쓰면 그 시점에는 main.o의 참조가 아직 없으므로 아무것도 꺼내지 않고, 나중에 main.o를 읽어도 되돌아가서 찾지 않습니다. 그래서 라이브러리는 사용하는 쪽 뒤에 쓰는 것이 원칙입니다.

자주 묻는 질문

리눅스에서 정적 라이브러리는 어떻게 만드나요?

gcc -c로 소스를 오브젝트 파일로 컴파일한 뒤, ar rcs libname.a file1.o file2.o로 묶습니다. 링크할 때는 -L로 그 디렉터리를 지정하고 -lname을 붙입니다.

.a 파일과 .so 파일의 차이는 무엇인가요?

.a 파일은 오브젝트 파일의 아카이브로, 필요한 멤버가 링크 시 실행 파일에 복사됩니다. .so 파일은 실행 시 적재되어 프로세스 간에 공유되는 공유 라이브러리입니다.

라이브러리를 링크했는데도 undefined reference 오류가 나는 이유는 무엇인가요?

GNU 링커에서 가장 흔한 원인은 순서입니다. 명령줄에서 라이브러리가 그것을 사용하는 오브젝트 파일보다 앞에 있는 경우입니다. -lname을 오브젝트 뒤로 옮기고, nm으로 라이브러리가 실제로 그 심볼을 정의하는지 확인하세요.
