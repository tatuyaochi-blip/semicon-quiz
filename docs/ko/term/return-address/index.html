복귀 주소(return address)란?

함수 처리를 마쳤을 때 돌아갈 번지. RISC-V에서는 jal 명령이 다음 명령의 번지를 ra(x1)에 넣고, x86에서는 call 명령이 스택에 쌓는다.

일본어 명칭: リターンアドレス

복귀 주소(return address)은(는) ISA와 어셈블리, CPU와 아키텍처, 링커, 로더, 실행 파일 등 4개 분야의 연습 문제 10개에 나와요.

분야: ISA와 어셈블리

호출 시 복귀 주소를 저장하는 방식

호출은 실행을 재개할 위치, 즉 호출 다음 명령어의 주소를 기록해야 합니다. RISC-V에서 jal(jump and link)은 PC + 4를 레지스터(관례상 ra(x1))에 쓰고 점프하며, 복귀는 jalr x0, 0(ra)의 의사 명령어인 ret입니다. 함수 포인터, 가상 함수, 공유 라이브러리 스텁을 통한 호출은 레지스터를 목적지로 하는 jalr을 씁니다. x86에서는 call이 복귀 주소를 스택에 푸시하고 ret이 이를 명령어 포인터로 팝하므로, 복귀 주소는 항상 스택에 있습니다.

리프 함수와 비리프 함수

jal은 매번 ra를 덮어쓰므로, 다른 함수를 호출하는 RISC-V 함수는 먼저 자기 복귀 주소를 저장해야 합니다. 전형적인 프롤로그는 addi sp, sp, -16으로 아래 방향으로 자라는 스택에 프레임을 할당한 뒤, sw ra, 12(sp)와 sw s0, 8(sp)로 ra와 피호출자 저장 레지스터를 저장합니다. 에필로그는 이를 다시 읽어 들이고 sp를 복원한 뒤 ret을 실행합니다. 아무것도 호출하지 않는 리프 함수는 ra를 레지스터에 그대로 둘 수 있고 스택 프레임이 전혀 필요 없을 수도 있어, 작은 함수의 비용이 낮아집니다.

공격자가 노리는 이유

스택에 저장된 복귀 주소는 지역 버퍼 바로 옆에 있으므로, 버퍼 오버플로가 이를 덮어써 함수가 복귀할 때 실행 흐름을 바꿀 수 있습니다. 고전적인 공격은 스택에 기계어를 써 넣고 그곳으로 점프했는데, 페이지 테이블의 실행 금지 비트를 이용한 W^X 정책이 이를 막습니다. 그러자 공격자는 기존 코드 조각을 연결하는 리턴 지향 프로그래밍(ROP)으로 옮겨 갔습니다. 추가 방어책으로는 복귀 전에 검사하는 스택 카나리, 주소 공간 배치 무작위화(ASLR), 그리고 각 복귀 주소의 보호된 사본을 따로 유지하는 하드웨어 섀도 스택이 있습니다.

하드웨어 속의 복귀 주소

비순차 실행 CPU는 ra나 스택을 읽기 훨씬 전에 복귀가 어디로 갈지 예측합니다. 분기 예측기 안의 리턴 어드레스 스택(RAS)은 호출마다 다음 명령어 주소를 푸시하고 복귀마다 팝하므로, 중첩이 잘 된 코드에서 매우 정확한 예측을 제공합니다. 예외와 인터럽트는 다릅니다. CPU는 중단된 PC를 RISC-V의 mepc나 sepc 같은 전용 레지스터에 이전 특권 모드와 함께 저장하며, 일반 ret이 아니라 mret이나 sret이 이를 한 번에 모두 복원합니다.

자주 묻는 질문

RISC-V에서 복귀 주소는 어디에 저장되나요?

호출 시 jal이나 jalr이 쓰는 레지스터 ra(x1)에 저장됩니다. 비리프 함수는 자신이 다른 함수를 호출하기 전에 이를 스택 프레임에 복사해 두고, ret 전에 복원합니다.

x86의 call/ret과 RISC-V의 jal/ret의 차이

x86의 call은 항상 복귀 주소를 스택에 푸시하고 ret이 이를 팝하는 반면, RISC-V의 jal은 복귀 주소를 레지스터에 두며 함수가 저장하기로 할 때만 메모리에 접근합니다.

복귀 주소를 덮어쓰면 왜 위험한가요?

함수가 복귀할 때 CPU는 그곳에 있는 주소로 점프하므로, 버퍼 오버플로로 이를 덮어쓴 공격자가 프로그램의 제어권을 빼앗을 수 있습니다.
