동적 링커(Dynamic Linker)란?

동적 링크 프로그램의 시작 시 공유 라이브러리를 찾아 읽어 들이고, 재배치와 심볼 결합을 수행한 뒤 프로그램을 시작시키는 소프트웨어. Linux의 ld.so 등이 있다.

일본어 명칭: 動的リンカ

동적 링커(Dynamic Linker)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 10개에 나와요.

분야: 링커, 로더, 실행 파일

프로그램 시작 시 일어나는 일

동적으로 링크된 ELF 실행 파일은 프로그램 헤더에 인터프리터(Linux의 ld-linux 등)를 지정합니다. execve가 프로그램을 매핑한 뒤, 커널은 그 동적 링커도 매핑하고 프로그램이 아니라 동적 링커에 제어를 넘깁니다. 동적 링커는 필요한 라이브러리 목록을 읽고, 설정된 경로와 자체 캐시에서 이를 찾아 주소 공간에 매핑하고, 재배치를 적용하고, 심볼을 결합하고, 라이브러리의 초기화 함수(.init_array 같은 섹션에 나열됨)를 실행한 뒤, 마지막으로 프로그램의 엔트리 포인트로 점프합니다. 나중에 dlopen으로 연 라이브러리도 같은 메커니즘을 거칩니다.

GOT, PLT, 지연 바인딩

공유 라이브러리는 위치 독립 코드로 빌드되므로, 코드 페이지에 다른 모듈의 절대 주소가 들어 있지 않습니다. 대신 코드는 동적 링커가 채우는 쓰기 가능한 데이터 테이블인 전역 오프셋 테이블(GOT)에서 주소를 읽습니다. 함수 호출은 프로시저 링키지 테이블(PLT) 스텁을 거칩니다. 지연 바인딩에서는 스텁을 통한 첫 호출이 링커의 리졸버로 들어가 실제 주소를 GOT에 써 넣고, 이후 호출은 곧바로 그곳으로 점프합니다. 많은 시스템은 대신 시작 시 모든 것을 바인딩한 뒤 GOT를 읽기 전용으로 만들어(full RELRO) GOT 덮어쓰기 공격을 막습니다.

동적 링커와 정적 링커

정적 링커(ld)는 빌드 시에 동작합니다. 오브젝트 파일을 결합하고, 심볼을 해석하고, 대부분의 재배치를 적용해 실행 파일을 만듭니다. 동적 링커는 프로그램이 시작될 때마다 동작하며 공유 라이브러리에 대한 작업을 마무리합니다. 이러한 분담 덕분에 라이브러리 코드의 물리적 사본 하나를 많은 프로세스가 공유할 수 있고, 파일 하나를 교체하는 것으로 보안 수정이 모든 프로그램에 적용됩니다. 그 대가는 추가적인 시작 작업과, 대상 머신에 올바른 버전의 라이브러리가 있어야 한다는 의존성입니다.

제어와 디버깅

동적으로 링크된 프로그램의 시작 실패는 대부분 라이브러리가 없거나 호환되지 않아서 일어납니다. ldd 명령은 의존성을 나열하고 어떤 것을 찾을 수 없는지 보여 줍니다. Linux에서는 LD_LIBRARY_PATH 같은 환경 변수가 검색 디렉터리를 추가하고, LD_PRELOAD는 다른 라이브러리보다 먼저 라이브러리를 주입하므로 디버깅과 계측에 유용합니다. 라이브러리 작성자는 공개 함수만 익스포트하고 내부 심볼을 hidden으로 지정해 로딩을 빠르게 할 수 있습니다. 이렇게 하면 동적 링커가 처리할 심볼이 줄고 내부 호출이 PLT를 건너뛸 수 있습니다.

정답과 해설 보기

정답: B. 필요한 공유 라이브러리를 찾아 메모리에 읽어 들이고, 심볼을 연결한 뒤 프로그램을 시작시킨다

동적 링크 실행 파일에는 사용할 동적 링커의 위치가 적혀 있으며, OS는 프로그램을 읽어 들이면 먼저 동적 링커에 처리를 넘깁니다. 동적 링커는 필요한 공유 라이브러리를 찾아 읽어 들이고, 재배치와 심볼 결합을 수행한 뒤 프로그램의 입구로 제어를 옮깁니다. dlopen으로 실행 중에 라이브러리를 추가로 읽어 들이는 처리도 동적 링커가 맡습니다.

자주 묻는 질문

Linux의 ld.so란 무엇인가요?

동적 링커/로더입니다. 동적으로 링크된 실행 파일에 대해 커널이 가장 먼저 실행하는 프로그램으로, 공유 라이브러리를 로드하고 심볼을 해석한 뒤 프로그램을 시작합니다.

공유 라이브러리를 찾을 수 없다는 오류가 나는 이유는?

동적 링커가 검색 경로에서 필요한 라이브러리를 찾지 못했거나, 호환되지 않는 버전만 찾았기 때문입니다. 프로그램에 ldd를 실행하면 어떤 의존성이 빠졌는지 알 수 있습니다.

GOT와 PLT의 차이점

GOT는 동적 링커가 해석된 주소를 채워 넣는 데이터 테이블이고, PLT는 외부 함수 호출이 거쳐 가는 작은 코드 스텁의 집합으로, 점프할 대상을 GOT에서 읽습니다.
