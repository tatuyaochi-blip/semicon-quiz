KPTI란?

커널 페이지 테이블 격리. 사용자 프로그램이 실행되는 동안 커널 메모리 대부분을 페이지 테이블에서 제외하여 Meltdown을 막는 OS의 대책.

일본어 명칭: KPTI

KPTI은(는) 하드웨어 보안의 최신 동향, 하드웨어 보안 등 2개 분야의 연습 문제 3개에 나와요.

분야: 하드웨어 보안

도전해 보기: KPTI 관련 문제

Meltdown에 대한 소프트웨어 대책으로 도입된 KPTI(커널 페이지 테이블 격리)의 개념으로 올바른 것은 무엇입니까?

  1. A사용자 프로그램이 실행되는 동안에는 커널 메모리 대부분을 페이지 테이블에서 제외하여 투기적으로도 읽을 수 없게 한다
  2. B커널을 모두 암호화하여 디스크에 둔다
  3. C사용자 프로그램의 실행을 금지한다
정답과 해설 보기

정답: A. 사용자 프로그램이 실행되는 동안에는 커널 메모리 대부분을 페이지 테이블에서 제외하여 투기적으로도 읽을 수 없게 한다

기존 OS는 전환을 빠르게 하기 위해 사용자 프로세스의 페이지 테이블에도 커널 메모리를 (접근 금지 표시를 붙여) 올려 두었습니다. Meltdown에서는 그 표시를 확인하기 전에 투기적으로 읽을 수 있었으므로, KPTI에서는 사용자 프로그램이 실행되는 동안 커널 페이지를 매핑 자체에서 제외했습니다. 주소 변환이 불가능하면 투기적으로도 읽을 수 없습니다. 다만 시스템 콜마다 페이지 테이블을 전환하므로 성능이 떨어집니다.

해설 속 KPTI

  • Meltdown에서는 그 표시를 확인하기 전에 투기적으로 읽을 수 있었으므로, KPTI에서는 사용자 프로그램이 실행되는 동안 커널 페이지를 매핑 자체에서 제외했습니다.

    Meltdown에 대한 소프트웨어 대책으로 도입된 KPTI(커널 페이지 테이블 격리)의 개념으로 올바른 것…

  • KPTI는 Meltdown에 대한 대책, IOMMU는 기기의 DMA를 제한하는 구조로, 제어 흐름은 보호하지 않습니다.

    제어 흐름 무결성을 하드웨어로 지원하는 기능에 대해, 함수에서의 복귀를 보호하는 것과 함수 포인터 등에 의…

  • 이 때문에 KPTI 같은 대책에서는 시스템 콜이나 인터럽트가 많은 데이터베이스나 입출력 처리일수록 성능 저하가 커집니다.

    어떤 처리는 투기적 실행에 대한 대책을 넣기 전에 10초가 걸렸고, 그동안 시스템 콜을 500만 회 호출했…

KPTI이(가) 나오는 문제 (3)

  1. Meltdown에 대한 소프트웨어 대책으로 도입된 KPTI(커널 페이지 테이블 격리)의 개념으로 올바른 것은 무엇입니까?
  2. 제어 흐름 무결성을 하드웨어로 지원하는 기능에 대해, 함수에서의 복귀를 보호하는 것과 함수 포인터 등에 의한 간접 호출이나 점프를 보호하는 것의 조합으로 올바른 것은?
  3. 어떤 처리는 투기적 실행에 대한 대책을 넣기 전에 10초가 걸렸고, 그동안 시스템 콜을 500만 회 호출했다. 대책을 넣으면 시스템 콜 1회당 처리 시간이 0.4 µs에서 0.6 µs로 늘어나고, 그 이외 부분의 시간은 변하지 않는다고 한다. 처리 전체 시간의 증가 비율은?

관련 용어

Meltdown 시스템 콜(system call) 페이지 테이블(Page Table) 제어 흐름 무결성(Control-Flow Integrity) 함수 포인터(Function Pointer) 섀도 스택(Shadow Stack) 복귀 주소(return address) 포인터 인증(PAC) IOMMU DMA(직접 메모리 접근)
