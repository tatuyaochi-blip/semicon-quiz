KV 캐시(KV Cache)란?

대규모 언어 모델의 추론에서 이미 처리한 토큰의 어텐션 Key와 Value를 저장해 두는 메모리. 재계산을 피하지만 문장 길이와 배치에 비례하여 커진다.

일본어 명칭: KVキャッシュ

KV 캐시(KV Cache)은(는) AI 하드웨어·소프트웨어 스택 등 1개 분야의 연습 문제 4개에 나와요.

LLM 추론에서 키와 값을 보관하는 이유

트랜스포머 언어 모델은 텍스트를 한 번에 토큰 하나씩 생성합니다. 각 어텐션 레이어에서는 새 토큰의 쿼리를 이전 모든 토큰의 키와 비교하고, 그 결과로 각 토큰의 값에 가중치를 줍니다. 어텐션은 인과적이므로 이전 토큰의 키와 값은 한 번 계산되면 다시 바뀌지 않습니다. KV 캐시는 이를 레이어별로 저장하므로, 각 디코딩 단계에서는 시퀀스 전체를 다시 처리하는 대신 새 토큰의 쿼리, 키, 값만 계산하고 키와 값을 캐시에 추가하면 됩니다. 이로써 반복적인 전체 재계산이 토큰당 적당한 비용으로 바뀝니다.

KV 캐시의 크기

캐시 크기는 2(키와 값) × 레이어 수 × 레이어당 키/값 차원 × 토큰 수 × 배치 크기 × 요소당 바이트 수입니다. 예를 들어 32개 레이어, 은닉 크기 4096, 표준 멀티헤드 어텐션을 사용하는 모델은 FP16에서 토큰당 약 0.5 MB가 필요합니다. 그러면 4096토큰 컨텍스트는 시퀀스당 약 2 GB를 차지하고, 이런 시퀀스 8개의 배치는 약 16 GB가 필요해, FP16 70억 파라미터 모델의 가중치가 차지하는 약 14 GB보다 커집니다.

프리필, 디코드와 메모리 대역폭

추론은 두 단계로 이루어집니다. 프리필은 프롬프트 전체를 병렬로 처리해 그 키와 값을 캐시에 기록하며, 주로 연산 성능에 의해 제한됩니다. 이어서 디코드는 단계마다 토큰 하나를 생성하는데, 각 단계에서 모델 가중치와 해당 시퀀스의 KV 캐시 전체를 읽어야 하므로 보통 메모리 대역폭에 의해 제한됩니다. 배치를 키우면 가중치 읽기를 더 많은 요청이 나눠 쓰므로 처리량이 올라가지만, KV 캐시가 커지고 각 단계가 길어져 개별 요청의 지연 시간이 늘어납니다.

KV 캐시를 줄이거나 관리하는 방법

KV 캐시 부담을 줄이는 기법이 여러 가지 있습니다. 그룹 쿼리 어텐션과 멀티 쿼리 어텐션은 여러 쿼리 헤드가 하나의 키·값 헤드 세트를 공유하게 해 그 비율만큼 캐시 크기를 줄입니다. 캐시를 8비트 이하의 정밀도로 저장하면 FP16 대비 메모리가 절반 이하로 줄어듭니다. 시퀀스마다 최대 길이에 맞춘 하나의 연속 영역 대신 작은 고정 크기 블록 단위로 캐시를 할당하면 단편화를 피하고 더 많은 요청을 수용할 수 있으며, 공통 프롬프트 접두부를 가진 시퀀스끼리 블록을 공유할 수도 있습니다. 일부 모델은 어텐션을 최근 토큰의 슬라이딩 윈도로 제한하기도 합니다.

정답과 해설 보기

정답: C. 이미 처리한 토큰의 어텐션 Key와 Value를 저장해 두고, 새 토큰이 나올 때마다 다시 계산하는 것을 피한다

어텐션 계산에서는 새 토큰이 그때까지의 모든 토큰의 Key와 Value를 참조합니다. 이전 토큰의 Key와 Value는 변하지 않으므로, 매번 다시 계산하지 않고 저장해 두면 새 토큰 몫만 계산하면 됩니다. 이것이 KV 캐시입니다. 계산은 크게 줄지만, 저장하는 Key와 Value의 양은 문장 길이와 배치 크기에 비례하여 늘어납니다.

자주 묻는 질문

대규모 언어 모델(LLM)의 KV 캐시란 무엇인가요?

이미 처리한 토큰의 어텐션 키와 값을 보관하는 메모리로, 새로 생성되는 토큰마다 시퀀스 전체를 재계산하지 않고 자신의 키와 값만 계산하면 되게 해 줍니다.

KV 캐시가 메모리를 많이 쓰는 이유는?

크기가 레이어 수, 어텐션 폭, 컨텍스트 길이, 배치 크기에 선형으로 비례해 커지므로, 긴 컨텍스트나 많은 동시 요청이 있으면 모델 가중치보다 커질 수 있습니다.

KV 캐시가 출력 품질에 영향을 주나요?

정확한 키와 값을 캐싱하는 것은 이를 재계산하는 것과 수학적으로 동등합니다. 저정밀도 캐시 저장이나 오래된 토큰 삭제 같은 근사를 적용할 때만 출력이 바뀔 수 있습니다.
