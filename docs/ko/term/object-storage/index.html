오브젝트 스토리지(Object Storage)란?

데이터를 키(이름)와 메타데이터가 붙은 오브젝트로 저장하고, HTTP의 API로 통째로 읽고 쓰는 스토리지. 용량을 미리 정하지 않고 거의 무제한으로 늘릴 수 있으며, 데이터는 일반적으로 여러 장치나 장소에 복제되어 높은 내구성을 가진다. 이미지나 동영상, 백업, 로그, 정적 웹사이트의 파일 저장에 적합하다. 파일 시스템처럼 일부만 수정하는 사용 방식이나 데이터베이스의 데이터 파일을 두는 용도에는 적합하지 않으며, 그런 용도에는 가상 디스크를 제공하는 블록 스토리지나 공유 파일 시스템을 제공하는 파일 스토리지를 사용한다.

일본어 명칭: オブジェクトストレージ

오브젝트 스토리지(Object Storage)은(는) 사이버 공격과 방어의 실무, 클라우드와 컨테이너의 기초 등 2개 분야의 연습 문제 2개에 나와요.

분야: 클라우드와 컨테이너의 기초

도전해 보기: 오브젝트 스토리지(Object Storage) 관련 문제

클라우드의 오브젝트 스토리지에 둔 고객 정보 파일이 인터넷의 누구나 읽을 수 있는 상태였다는 것이 밝혀졌다. 이러한 정보 유출의 전형적인 원인과 재발을 막는 대책의 조합으로 적절한 것은?

  1. A사용자의 설정 오류로 공개되어 있었다. 계정 전체에서 공개를 금지하는 설정으로 하고, 설정 오류를 자동으로 검사한다
  2. B클라우드 사업자의 암호 방식이 약해서 파일이 해독되었다. 파일을 압축한 후 저장하도록 한다
  3. C클라우드 사업자 데이터 센터의 물리적 경비가 불충분했다. 자사 직원을 데이터 센터에 상주시켜 감시하게 한다
정답과 해설 보기

정답: A. 사용자의 설정 오류로 공개되어 있었다. 계정 전체에서 공개를 금지하는 설정으로 하고, 설정 오류를 자동으로 검사한다

클라우드의 공동 책임 모델에서는 스토리지의 접근 설정은 사용자의 책임이며, 공개 설정 오류로 인한 정보 유출은 되풀이하여 일어나고 있습니다. 테스트를 위해 일시적으로 공개한 설정을 되돌리는 것을 잊거나, 허가 대상의 의미를 오해하여 넓게 허가해 버리는 오류가 전형적입니다. 대책으로서 계정이나 조직 전체에서 공개를 금지하는 설정을 기본으로 하고, 설정 상태를 자동으로 검사하는 구조(CSPM: 클라우드 보안 태세 관리)로 공개 설정이나 암호화 설정 누락 등을 지속적으로 찾아내어 고칩니다.

해설 속 오브젝트 스토리지(Object Storage)

  • 오브젝트 스토리지는 데이터를 키로 식별하는 오브젝트로서 HTTP의 API로 통째로 읽고 쓰는 것으로, 용량을 거의 신경 쓰지 않고 늘릴 수 있어 이미지나 백업, 로그의 저장에 적합합니다.

오브젝트 스토리지(Object Storage)이(가) 나오는 문제 (2)

  1. 클라우드의 오브젝트 스토리지에 둔 고객 정보 파일이 인터넷의 누구나 읽을 수 있는 상태였다는 것이 밝혀졌다. 이러한 정보 유출의 전형적인 원인과 재발을 막는 대책의 조합으로 적절한 것은?
  2. 클라우드 스토리지를 ① 가상 머신에 디스크로 연결하여 파일 시스템을 만들고 데이터베이스의 데이터 파일을 둔다, ② 여러 서버에서 동시에 마운트하여 공유 디렉터리로 사용한다, ③ HTTP의 API로 키(이름)를 지정하여 대량의 이미지를 읽고 쓰며, 용량을 미리 정하지 않고 늘린다는 세 가지 용도로 사용한다. ①~③에 적합한 스토리지 종류의 조합으로 적절한 것은?

공동 책임 모델(Shared Responsibility Model) HTTP(하이퍼텍스트 전송 프로토콜) API(애플리케이션 프로그래밍 인터페이스) 가용 영역(Availability Zone) 관측 가능성(Observability) 블루-그린 배포(Blue-Green Deployment) 서버리스(Serverless) 오토 스케일링(Autoscaling) 이뮤터블 인프라스트럭처(Immutable Infrastructure) 카나리 릴리스(Canary Release)
