심볼 해결(Symbol Resolution)란?

어떤 파일에서 참조하는 함수나 변수의 이름을 어딘가에 있는 그 정의와 대응시키는 링커의 처리. 정의가 없으면 미정의 참조, 둘 이상이면 다중 정의 오류가 된다.

일본어 명칭: シンボル解決

분야: 링커, 로더, 실행 파일

심볼 해결이 하는 일

각 오브젝트 파일에는 함수나 전역 변수처럼 자신이 정의하는 이름과, 참조하지만 정의하지 않는 이름을 나열한 심볼 테이블이 들어 있습니다. main.c가 sum을 호출하고 sum.c가 이를 정의한다면, main.o에는 sum에 대한 미정의 참조가, sum.o에는 그 정의가 기록됩니다. 심볼 해결은 모든 심볼 테이블을 모아 각 참조를 정확히 하나의 정의에 연결하는 링커 단계입니다. 이 단계는 재배치보다 먼저 수행되며, 재배치는 이어서 그 정의들의 최종 주소를 이를 참조하는 명령어와 데이터에 기록합니다.

미정의 참조와 다중 정의

참조에 대한 정의가 없으면 링커는 미정의 참조(undefined reference)를 보고합니다. 대개 소스 파일이나 라이브러리가 링크되지 않았거나 이름의 철자가 틀린 경우입니다. static이 아닌 전역 정의 두 개가 같은 이름을 가지면, 참조를 어느 쪽에 연결할지 결정할 수 없으므로 다중 정의 오류를 보고합니다. 함수를 static으로 선언하면 내부 링키지를 가져 다른 파일에서 보이지 않으므로 같은 이름을 다시 쓸 수 있습니다. extern int count; 같은 선언은 저장 공간을 확보하지 않고, 정의가 다른 곳에 있다는 것만 약속합니다.

약한 심볼과 라이브러리 순서

약한 심볼(weak symbol)은 같은 이름의 일반(강한) 정의가 없을 때만 사용되는 대체 정의로, 임베디드 코드에서 기본 인터럽트 핸들러에 쓰이는 패턴입니다. 정적 라이브러리는 오브젝트 파일의 아카이브이며, GNU 링커는 입력을 왼쪽에서 오른쪽으로 처리하면서 그 시점에 미정의 상태인 심볼을 정의하는 라이브러리 멤버만 꺼냅니다. 따라서 gcc -lmylib main.o 같은 명령은 실패합니다. 라이브러리를 훑는 시점에는 main.o에 아직 미해결 심볼이 없기 때문입니다. 라이브러리는 그것을 사용하는 파일 뒤에 둡니다.

C++ 이름과 동적 링킹

링커는 오직 이름 문자열로만 심볼을 대조합니다. C++는 print(int)와 print(double) 같은 함수 오버로드를 허용하므로, 컴파일러는 인수 타입과 네임스페이스를 심볼 이름에 인코딩하며 이를 이름 맹글링이라고 합니다. C는 이름을 맹글링하지 않으므로, C++ 코드는 C 함수를 extern "C"로 선언해 이름을 일치시킵니다. 공유 라이브러리를 사용하면 심볼 해결의 일부가 뒤로 미뤄집니다. 동적 링커가 로드 시점이나 첫 호출 시점에 라이브러리 함수에 대한 참조를 바인딩하며, 보통 PLT 스텁과 GOT 엔트리를 거칩니다.

자주 묻는 질문

undefined reference 오류의 원인은 무엇인가요?

링커가 함수나 변수에 대한 참조를 찾았지만, 링크된 어떤 오브젝트 파일이나 라이브러리에서도 정의를 찾지 못한 것입니다. 링크 명령에 파일이나 라이브러리가 빠졌거나, 나열 순서가 잘못되었거나, 이름이 일치하지 않는 경우가 많습니다.

심볼 해결과 재배치의 차이는 무엇인가요?

심볼 해결은 참조된 각 이름이 어느 정의를 가리키는지 결정합니다. 그런 다음 재배치가 그 정의들의 실제 주소를 이를 사용하는 기계어 코드와 데이터에 패치합니다.

multiple definition 오류는 어떻게 해결하나요?

static이 아닌 전역 함수와 변수가 각각 정확히 하나의 소스 파일에서만 정의되도록 하고, 헤더에는 extern 선언을 사용하며, 파일 안에서만 쓰는 항목은 static으로 지정해 이름이 충돌하지 않게 합니다.
