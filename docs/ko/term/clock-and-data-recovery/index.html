클록 데이터 복원(CDR)란?

수신한 데이터 신호의 변화로부터 클록 타이밍을 추출하여 비트를 판정하는 수신 회로. CDR. 클록 전용선이 필요 없어진다.

일본어 명칭: クロック・データ・リカバリ

클록 데이터 복원(CDR)은(는) I/O 인터페이스와 버스 등 1개 분야의 연습 문제 3개에 나와요.

분야: I/O 인터페이스와 버스

데이터에서 클록을 복원하는 이유

초당 수십 기가비트의 속도에서는 1비트가 수십 피코초에 불과하며, 별도로 배선한 클록은 데이터 레인에 대해 스큐를 가지고 도착하여 그 비트 시간의 큰 부분을 소모합니다. 그래서 고속 직렬 링크는 클록을 아예 보내지 않습니다. 각 수신 레인에는 데이터 전이 자체로부터 타이밍을 얻는 클록 데이터 복원(CDR) 회로가 있어, 모든 레인이 독립적으로 정렬됩니다. DDR 메모리 같은 소스 동기 인터페이스는 반대 방식을 택해 데이터와 함께 스트로브를 전달합니다.

CDR 루프의 동작

CDR은 피드백 루프입니다. 위상 검출기는 데이터 전이가 일어나는 위치를 로컬 샘플링 클록과 비교하여 클록이 빠른지 늦은지를 판정합니다. 이런 방식의 뱅뱅(bang-bang) 검출기는 비트 중심과 에지에서 취한 샘플을 사용합니다. 루프 필터는 이 판정을 평활화하여, PLL 기반 CDR처럼 전압 제어 발진기를 조정하거나 기준 클록의 위상을 회전시키는 위상 보간기를 조정합니다. 목표는 여유가 가장 큰 데이터 아이의 중심 부근에서 각 비트를 샘플링하는 것입니다.

전이와 라인 코딩

위상 검출기는 데이터가 바뀔 때만 정보를 얻으므로, 같은 비트가 길게 이어지면 클록이 드리프트하고 AC 결합 링크에서는 평균 전압도 이동합니다. 라인 코딩은 충분한 전이를 보장합니다. 8b/10b 코딩은 8개의 데이터 비트를 1과 0의 균형이 맞고 연속 길이가 짧은 10비트 심볼로 대응시키며, 25%의 추가 비트로 효율은 80%가 됩니다. PCI Express 1세대와 2세대, USB 3.0에서 사용되었습니다. 이후 링크는 128b/130b처럼 가벼운 프레이밍과 스크램블링을 사용하여 훨씬 적은 오버헤드로 통계적으로 전이를 제공합니다.

주파수 오프셋, SSC, 지터 추종

송신기와 수신기의 기준 클록은 결코 정확히 같지 않으므로, CDR은 위상뿐 아니라 작은 주파수 오프셋도 추종해야 합니다. 스펙트럼 확산 클로킹(SSC)에서는 전자기 방사 피크를 낮추기 위해 송신 클록을 약 0.5% 천천히 스윕하며, CDR은 이 스윕도 따라가야 합니다. 루프 대역폭은 트레이드오프입니다. 루프 대역폭보다 느린 지터는 추종하여 제거되고, 더 빠른 지터는 아이 여유 안에 들어가야 합니다. 표준은 수신기가 주파수 전반에 걸쳐 만족해야 하는 지터 내성 마스크를 규정합니다.

정답과 해설 보기

정답: B. 수신한 데이터 신호의 변화에서 클록 타이밍을 추출하고, 그 타이밍에 비트를 판정한다

클록을 별도의 선으로 보내면 데이터 선과의 사이에 어긋남이 생깁니다. 그래서 고속 직렬 전송에서는 CDR 회로가 데이터의 0과 1이 전환되는 타이밍을 보고, PLL 등으로 같은 주파수·위상의 클록을 만들어 비트의 한가운데에서 데이터를 판정합니다. 따라서 데이터에는 어느 정도 빈도로 전환이 포함되어야 하며, 부호화로 이를 보장합니다.

자주 묻는 질문

SerDes 수신기에서 CDR은 무슨 역할을 하나요?

데이터 전이로부터 수신 비트열에 정렬된 클록을 추출하고, 이를 이용해 각 비트를 아이 중심 부근에서 샘플링하므로 별도의 클록 선이 필요 없습니다.

직렬 링크에 8b/10b나 128b/130b 인코딩이 필요한 이유는?

코딩이 잦은 전이와 DC 균형을 보장하여 수신기의 CDR이 록을 유지하고 AC 결합 신호가 중심에 머물게 하기 때문입니다. 128b/130b는 스크램블링을 이용해 8b/10b보다 훨씬 낮은 오버헤드로 이를 달성합니다.

CDR과 PLL의 차이는?

PLL은 발진기를 깨끗한 주기적 기준 클록에 록하고, CDR은 전이가 불규칙하게 일어나는 랜덤 데이터에 록합니다. 많은 CDR은 데이터용으로 설계한 위상 검출기를 갖춘 PLL을 기반으로 만들어집니다.
