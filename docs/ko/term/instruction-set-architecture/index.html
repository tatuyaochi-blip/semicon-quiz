명령어 집합 구조(ISA)란?

프로세서가 실행할 수 있는 명령어와 레지스터 등 소프트웨어 관점에서의 프로세서 사양. x86, Arm, RISC-V 등이 있다.

일본어 명칭: 命令セットアーキテクチャ(ISA)

명령어 집합 구조(ISA)은(는) ISA와 어셈블리, CPU와 아키텍처, 성능 분석 등 4개 분야의 연습 문제 12개에 나와요.

분야: CPU와 아키텍처

ISA가 규정하는 것

명령어 집합 구조(ISA)는 소프트웨어와 프로세서 하드웨어 사이의 계약입니다. 명령어와 그 비트 인코딩, 프로그램이 볼 수 있는 레지스터, 데이터 타입과 주소 지정 방식, 메모리 접근의 순서, 특권 레벨, 인터럽트와 예외의 동작을 정의합니다. ISA가 정의하는 모든 것은 기계어 코드가 관찰하고 의존할 수 있는 아키텍처 상태입니다. 어셈블러는 어셈블리 니모닉을 이 인코딩으로 거의 일대일 변환하므로, ISA마다 고유한 어셈블리 언어가 있습니다.

ISA와 마이크로아키텍처

마이크로아키텍처는 특정 프로세서가 ISA를 구현하는 방식으로, 파이프라인 깊이, 캐시 크기, 분기 예측기, 사이클당 발행 명령어 수 등을 말합니다. 하나의 ISA를 작은 저전력 코어와 대형 비순차 실행 코어로 모두 구현할 수 있으며, 이들은 같은 기계어 코드를 매우 다른 속도로 실행합니다. 성능 방정식 실행 시간 = 명령어 수 × 명령어당 사이클 수(CPI) × 사이클 시간에서, ISA와 컴파일러는 주로 명령어 수를, 마이크로아키텍처는 CPI를, 회로와 공정 기술은 사이클 시간을 결정합니다. Spectre 계열 공격은 이 경계를 악용합니다. 잘못 투기 실행된 아키텍처 상태는 되돌려지지만 캐시 내용은 그렇지 않기 때문입니다.

하드웨어를 좌우하는 설계 선택

ISA의 세부 사항은 하드웨어에 오래 지속되는 영향을 미칩니다. RISC-V 기본 명령어는 32비트 고정 길이이므로(16비트 형식은 압축 C 확장에서만) 명령어 경계가 명확하지만, x86 명령어는 1–15바이트로 다양해 다음 명령어의 시작 위치를 찾으려면 일부를 디코딩해야 하므로 넓은 디코더가 복잡해집니다. x86 분기는 앞선 비교 명령어가 설정한 플래그를 검사하지만, RISC-V는 분기 명령어 안에서 두 레지스터를 비교하므로 추적해야 할 암묵적 플래그 상태가 없습니다. MIPS의 분기 지연 슬롯은 특정 파이프라인의 특성을 그 파이프라인보다 오래 사는 ISA에 새겨 넣는 위험을 보여 주었습니다.

모듈형 오픈 ISA

RISC-V는 누구나 라이선스 비용 없이 사양을 구현할 수 있는 오픈 ISA입니다. 작은 기본 정수 명령어 집합(RV32I 또는 RV64I, 약 40개 명령어)에 선택적 확장을 조합합니다. 곱셈·나눗셈용 M, 원자적 연산용 A, 부동소수점용 F와 D, 압축 명령어용 C, 벡터용 V, 그리고 커스텀 명령어가 있습니다. 확장을 빼면 면적은 줄지만 속도가 떨어집니다. M이 없으면 컴파일러는 C 언어의 곱셈을 시프트와 덧셈으로 곱하는 라이브러리 루틴 호출로 바꿉니다. Arm과 x86은 독점 ISA로, 소유자가 라이선스하거나 직접 구현합니다.

  3. C같은 반도체 공장에서 같은 제조 공정을 사용해 만들어야 한다
정답과 해설 보기

정답: B. 내부 회로 구성이 달라도 같은 기계어 프로그램을 실행할 수 있다

ISA는 명령어의 종류, 명령어의 비트 배열, 레지스터의 수 등을 정한 소프트웨어와 하드웨어 사이의 약속입니다. 파이프라인 단수, 캐시 크기, 분기 예측 방식 같은 내부 구조는 마이크로아키텍처라고 하며 ISA와 별도로 결정됩니다. 그래서 같은 ISA라도 작은 저전력 코어와 큰 고성능 코어가 있어 성능도 전력도 다르지만 같은 기계어 프로그램이 동작합니다. 제조 공장이나 공정도 ISA와는 관계가 없습니다.

자주 묻는 질문

ISA와 마이크로아키텍처의 차이는 무엇인가요?

ISA는 명령어, 레지스터, 동작 등 소프트웨어가 보는 사양입니다. 마이크로아키텍처는 그 사양을 구현하는 구체적인 하드웨어 설계이므로, 마이크로아키텍처가 다른 두 프로세서도 ISA가 같다면 같은 프로그램을 실행할 수 있습니다.

x86, Arm, RISC-V는 명령어 집합 구조인가요?

네. 세 가지는 서로 다른 ISA이므로, 각각을 구현한 프로세서 설계가 많더라도 한 ISA용으로 컴파일된 기계어 코드는 다른 ISA에서 직접 실행할 수 없습니다.

ISA와 ABI의 차이는 무엇인가요?

ISA는 프로세서가 실행하는 것을 정의하고, ABI는 그 위의 소프트웨어 규약으로 호출 규약, 데이터 타입 크기, 시스템 호출 등을 다룹니다. 하나의 ISA에 예를 들어 운영체제별로 여러 ABI가 있을 수 있습니다.
