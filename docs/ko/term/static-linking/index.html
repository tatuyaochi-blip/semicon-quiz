정적 링크(static linking)란?

사용하는 라이브러리의 코드를 실행 파일 안에 복사해 결합하는 방식. 실행 환경에 라이브러리가 없어도 동작하지만 파일이 커지고, 라이브러리 수정은 다시 빌드해야 반영된다.

일본어 명칭: 静的リンク

정적 링크(static linking)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 2개에 나와요.

분야: 링커, 로더, 실행 파일

링커가 하는 일

정적 링크에서 링커는 프로그램의 오브젝트 파일과 명령줄에 지정된 정적 라이브러리를 읽어, 정의되지 않은 심볼을 해결하는 데 필요한 아카이브 멤버를 가져오고, 같은 종류의 섹션을 합칩니다. 모든 코드는 하나의 텍스트 섹션으로, 초기화된 모든 데이터는 하나의 데이터 섹션으로 모으는 식입니다. 그런 다음 최종 주소를 배정하고, 재배치 엔트리를 이용해 모든 참조를 수정하여 하나의 실행 파일을 씁니다. GCC에서는 -static 옵션을 주면 C 표준 라이브러리를 포함한 모든 라이브러리를 이렇게 링크하며, 단 해당 라이브러리의 정적 버전이 설치되어 있어야 합니다.

정적 링크와 동적 링크의 비교

정적으로 링크된 실행 파일은 자기 완결적입니다. 시작 시 찾아야 할 것이 없고, 동적 링커에 의한 심볼 바인딩도 없으며, 라이브러리 코드 호출이 직접 호출입니다. 비용은 크기와 유지 보수입니다. 각 프로그램이 사용하는 모든 라이브러리 루틴의 사본을 가지므로, 공유 라이브러리 페이지처럼 프로세스 간에 메모리를 공유하지 못하며, 라이브러리의 보안 수정은 프로그램을 다시 링크해야만 반영됩니다. 동적 링크는 이러한 절충을 뒤집는 대신, 프로그램이 실행되는 모든 기계에 호환되는 라이브러리 버전이 있어야 한다는 의존성을 대가로 치릅니다.

자기 완결성의 한계

정적 실행 파일도 여전히 CPU 아키텍처와 운영체제의 시스템 콜 인터페이스에 의존하므로, 다른 OS에서 그대로 실행할 수는 없습니다. 일부 라이브러리 기능은 내부적으로 동적 적재를 전제하기도 합니다. 예를 들어 GNU libc는 정적으로 링크된 프로그램에서 getaddrinfo 같은 함수를 쓰면 이름 서비스 조회를 위해 실행 시 여전히 공유 라이브러리가 필요하다고 경고합니다. 또한 정적 링크를 하면 dlopen 방식의 플러그인을 쉽게 쓸 수 없는데, 플러그인은 동적 링커를 전제로 하는 공유 오브젝트이기 때문입니다.

활용처

마이크로컨트롤러용 펌웨어는 실행 시 라이브러리를 공급할 로더나 파일 시스템이 없기 때문에 거의 항상 하나의 이미지로 정적 링크됩니다. 서버와 최소 컨테이너 이미지에서는 호환되는 커널만 있으면 파일 하나를 어디로든 복사해 쓸 수 있다는 점에서 정적 실행 파일이 높이 평가됩니다. 개발자들은 라이브러리 버전을 신경 쓰지 않고 여러 배포판에서 실행해야 하는 명령줄 도구에도 정적 링크를 사용하며, 공유 라이브러리가 없거나 호환되지 않는 문제를 피하는 대가로 파일이 커지는 것을 감수합니다.

  2. B프로그램을 실행할 때마다 라이브러리를 읽어 들여 결합한다

정답과 해설 보기

정답: A. 사용하는 라이브러리 코드를 실행 파일 안에 복사하여 결합한다

정적 링크에서는 링커가 정적 라이브러리(Linux에서는 .a 파일)에서 필요한 함수를 꺼내 실행 파일에 포함시킵니다. 실행 환경에 라이브러리가 없어도 동작하고 기동 시 결합 작업도 없지만, 실행 파일이 커지고 같은 라이브러리를 사용하는 프로그램마다 사본을 가집니다. 라이브러리의 버그 수정이 있어도 다시 만들지 않으면 반영되지 않습니다.

자주 묻는 질문

gcc로 C 프로그램을 정적 링크하려면 어떻게 하나요?

링크 명령에 -static을 추가합니다. 예를 들어 gcc -static main.c -o main입니다. 성공하려면 C 라이브러리를 포함해 관련된 모든 라이브러리의 정적(.a) 버전이 설치되어 있어야 합니다.

정적 링크한 실행 파일이 훨씬 큰 이유는 무엇인가요?

시스템에 이미 있는 공유 라이브러리를 참조하는 대신, C 런타임의 일부를 포함해 사용하는 모든 라이브러리 코드의 사본을 담고 있기 때문입니다. 심볼을 strip하고 섹션 가비지 컬렉션을 적용해 링크하면 크기를 줄일 수 있습니다.

정적 링크한 프로그램이 더 빠른가요?

공유 라이브러리를 적재하고 바인딩할 필요가 없고 호출에 간접 참조가 없으므로 보통 시작은 더 빠릅니다. 오래 실행되는 대부분의 프로그램에서는 정상 상태 속도의 차이가 작습니다.
