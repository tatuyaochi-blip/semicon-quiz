컨텍스트 스위치(context switch)란?

CPU에서 실행할 프로세스나 스레드를 전환하는 것. 레지스터와 프로그램 카운터 등의 상태를 저장·복원하며 프로세스 전환에서는 주소 공간도 바뀐다.

일본어 명칭: コンテキストスイッチ

컨텍스트 스위치(context switch)은(는) OS와 하드웨어, 멀티코어와 동기화 등 2개 분야의 연습 문제 5개에 나와요.

분야: OS와 하드웨어

저장하고 복원하는 것

커널은 나가는 스레드의 CPU 상태, 즉 범용 레지스터, 프로그램 카운터, 스택 포인터, 이전 모드 같은 상태 비트를 저장하고, 나중에 이를 다시 불러와 스레드가 멈춘 지점에서 정확히 재개되게 합니다. 부동소수점 레지스터와 벡터 레지스터도 상태에 포함되며, 일부 커널은 다음 스레드가 실제로 사용할 때만 이를 지연 저장합니다. 프로세스 간 전환에서는 페이지 테이블을 가리키는 레지스터도 바뀌어 새 프로세스에 고유한 주소 공간이 주어집니다. 메모리 내용과 열린 파일은 그 자리에 남아 있으며 복사되지 않습니다.

전환이 일어나는 시점

전환은 실행 중인 스레드가 디스크 I/O나 락을 기다리며 블록될 때, 자발적으로 양보할 때, 또는 타이머 인터럽트가 스케줄러에 타임 슬라이스 만료를 알려 다른 스레드를 실행해야 할 때 일어납니다. 어느 경우든 CPU는 이미 시스템 콜이나 인터럽트를 처리하며 커널 안에 있고, 스케줄러가 다음 스레드를 고릅니다. 같은 프로세스 내 스레드 간 전환은 주소 공간이 바뀌지 않으므로 더 저렴합니다.

직접 비용과 간접 비용

레지스터 저장과 로드에는 시간이 거의 들지 않으며, 스케줄링을 포함한 커널 경로 전체는 보통 마이크로초 단위입니다. 더 큰 비용은 간접 비용인 경우가 많습니다. 새 프로세스는 이전 프로세스의 데이터와 변환으로 채워진 캐시와 TLB를 만나므로, 이들이 다시 채워질 때까지 미스를 반복합니다. TLB 엔트리에 주소 공간 식별자(ASID)를 붙이는 CPU는 전환할 때마다 TLB를 비우지 않아도 되지만, 캐시 워밍업 비용은 남습니다. 따라서 잦은 전환은 전환 시간만으로 예상되는 것보다 처리량을 더 많이 떨어뜨립니다.

컨텍스트 스위치와 모드 스위치의 차이

시스템 콜이나 인터럽트는 CPU를 사용자 모드에서 특권 모드로 옮겼다가 되돌리지만, 이후에도 같은 프로세스가 계속 실행됩니다. 이것은 모드 스위치이지 컨텍스트 스위치가 아닙니다. 컨텍스트 스위치는 CPU를 차지하는 스레드나 프로세스가 바뀌는 것입니다. 전환은 항상 커널 안에서 일어나므로 두 가지가 함께 일어나는 경우가 많지만, 호출자에게 그대로 돌아가는 시스템 콜에는 컨텍스트 스위치가 전혀 수반되지 않습니다.

정답: B. 레지스터 값이나 프로그램 카운터 등 CPU의 실행 상태

컨텍스트 스위치에서는 나중에 같은 상태에서 재개할 수 있도록 범용 레지스터, 프로그램 카운터, 스택 포인터, 동작 모드 등 CPU의 상태를 저장하고, 다음에 실행할 프로세스의 상태를 읽어 들입니다. 프로세스를 전환하는 경우에는 페이지 테이블의 위치를 나타내는 레지스터도 전환합니다. 메모리나 파일의 내용은 그대로 남아 있으므로 전환할 때마다 저장할 필요가 없습니다.

프로세스의 컨텍스트 스위치가 레지스터 저장·복원에 걸리는 시간보다 실제로는 더 큰 성능 저하를 초래하는 경우가 있는 주된 이유는?

  1. A전환할 때마다 CPU의 클록 주파수가 내려가기 때문에
  2. B전환할 때마다 프로그램을 디스크에서 다시 읽기 때문에
  3. C전환 후 캐시나 TLB의 미스가 늘어나기 때문에
정답과 해설 보기

정답: C. 전환 후 캐시나 TLB의 미스가 늘어나기 때문에

레지스터의 저장과 복원 자체는 짧은 시간에 끝나지만, 전환된 프로세스에게 캐시나 TLB의 내용은 이전 프로세스의 것이므로 필요한 데이터나 변환 결과를 다시 읽어 들일 때까지 미스가 계속됩니다. ASID가 없는 CPU에서는 주소 공간을 전환할 때 TLB를 비워야 하기도 합니다. 이러한 간접 비용이 직접적인 전환 시간보다 커지는 경우가 있습니다. 클록이 내려가거나 프로그램을 디스크에서 다시 읽지는 않습니다.

자주 묻는 질문

컨텍스트 스위치 때 저장되는 것

나가는 스레드의 CPU 상태, 즉 레지스터, 프로그램 카운터, 스택 포인터, 상태 정보이며, 프로세스 전환 시에는 페이지 테이블 포인터도 포함됩니다. 메모리 자체는 그 자리에 남아 있으므로 저장하지 않습니다.

컨텍스트 스위치 비용이 큰 이유

커널 작업 자체 외에도, 들어오는 프로세스가 다른 프로세스의 내용을 담은 캐시와 TLB로 시작하므로 다시 채워질 때까지 많은 미스를 겪기 때문입니다.

시스템 콜은 컨텍스트 스위치인가요

아닙니다. 시스템 콜은 같은 프로세스 안에서의 모드 스위치이며, 커널이 복귀 전에 다른 스레드나 프로세스를 실행하기로 결정한 경우에만 컨텍스트 스위치가 일어납니다.

해설 속 컨텍스트 스위치(context switch)

  • 컨텍스트 스위치에서는 나중에 같은 상태에서 재개할 수 있도록 범용 레지스터, 프로그램 카운터, 스택 포인터, 동작 모드 등 CPU의 상태를 저장하고, 다음에 실행할 프로세스의 상태를 읽어 들입니다.

    컨텍스트 스위치에서 전환 전 프로세스에 대해 저장해 두어야 하는 것은?

  • 기다리는 동안 CPU를 낭비하지 않으므로 긴 대기에 적합하지만, 재우고 깨우는 처리와 컨텍스트 스위치에 수 마이크로초 정도가 걸립니다.

    뮤텍스(재워서 기다리는 락)와 스핀락을 비교한 설명으로 올바른 것은 무엇입니까?

  • 컨텍스트 스위치는 실행할 프로세스를 전환하는 것, 디맨드 페이징은 페이지를 필요할 때 읽어 들이는 방식입니다.

  • 인터럽트가 발생하면 CPU는 반드시 커널의 인터럽트 핸들러로 이동하므로, 프로그램이 무한 루프에 빠져 있어도 OS는 제어를 되찾아 다른 프로세스로 컨텍스트 스위치를 할 수 있습니다.
