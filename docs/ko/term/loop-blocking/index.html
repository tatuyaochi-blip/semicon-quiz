루프 블로킹(Loop Blocking)란?

큰 배열을 캐시에 들어가는 작은 블록으로 나누어 처리하여 읽어 들인 데이터가 밀려나기 전에 여러 번 사용하도록 하는 최적화. 행렬 곱 등에서 효과가 크다.

일본어 명칭: ループブロッキング

루프 블로킹(Loop Blocking)은(는) 메모리 계층 구조 등 1개 분야의 연습 문제 2개에 나와요.

분야: 메모리 계층 구조

단순한 행렬 곱에서 미스가 나는 이유

교과서식 3중 루프로 double형 N × N 행렬의 C = A × B를 계산한다고 생각해 봅시다. C의 각 원소에는 A의 한 행 전체와 B의 한 열 전체가 필요한데, 행 우선(row-major) 저장에서 B의 열을 따라 내려가면 원소마다 다른 캐시 라인에 접근하게 됩니다. N이 크면 B의 열과 A의 행이 재사용될 만큼 오래 캐시에 머물지 못하므로, 같은 데이터를 주 메모리에서 계속 다시 읽어 오게 됩니다. 이것이 용량 미스(capacity miss)로, 워킹 세트가 단순히 너무 크기 때문에 캐시의 연관도를 높여도 도움이 되지 않습니다.

블로킹의 동작 방식

루프 블로킹 또는 타일링은 각 행렬을 b × b 타일로 나누고 루프 순서를 바꾸어, 세 타일이 모두 캐시에 상주하는 동안 하나의 타일 곱 C 타일 += A 타일 × B 타일을 완료합니다. 그러면 적재된 각 원소가 쫓겨나기 전에 약 b번 재사용되어, 메모리 트래픽이 N³ 원소 수준에서 약 N³/b로 줄어듭니다. 연산량과 전체 메모리 사용량은 변하지 않고 연산 순서만 바뀝니다. 이동한 바이트당 연산 수인 산술 강도(arithmetic intensity)는 대략 타일 크기에 비례하여 높아집니다.

타일 크기 선택

첫 번째 추정은 세 타일이 대상 캐시에 들어가야 한다는 것으로, double형이면 3 × b² × 8바이트입니다. 32 KB L1 캐시라면 b는 약 36이므로, 다른 데이터를 위한 여유를 남겨 약 32의 타일이 자연스러운 선택입니다. 실제로는 2의 거듭제곱 스트라이드로 인한 충돌 미스, TLB 커버 범위, 하드웨어 프리페치도 영향을 주므로 타일 크기는 실험적으로 조정하며, 타일을 연속된 버퍼로 복사하기도 합니다. 고성능 라이브러리는 레지스터, L1, L2, L3의 여러 수준에서 동시에 블로킹합니다.

블로킹과 다른 루프 변환

루프 언롤링은 루프 본체를 복제하여 루프 오버헤드를 줄이고 명령어 수준 병렬성을 드러내지만, 그 자체로 캐시 재사용을 개선하지는 않습니다. 루프 교환(interchange)은 중첩 순서를 바꾸어 가장 안쪽 루프가 메모리를 연속적으로 훑도록 하여 공간 지역성을 개선합니다. 블로킹은 대규모 데이터 전반의 시간 지역성을 겨냥하며, 흔히 이 두 기법과 함께 사용됩니다. 같은 아이디어가 타일을 온칩 공유 메모리에 올려 두는 GPU에서도, 스텐실 코드, 합성곱, 많은 밀집 선형대수 커널에서도 나타납니다.

  2. B루프 횟수를 줄여 루프 끝에서 실행하는 분기 명령의 수를 줄이기 위해

정답과 해설 보기

정답: A. 캐시에 들어가는 작은 블록 단위로 계산하여 데이터의 재사용을 늘리기 위해

큰 행렬의 곱을 그대로 계산하면 한 번 읽어 온 요소가 다시 사용되기 전에 캐시에서 쫓겨나 주기억장치에서 여러 번 다시 읽게 됩니다. 루프 블로킹에서는 행렬을 캐시에 들어가는 작은 블록으로 나누어 블록 안에서 계산을 마치므로, 읽어 온 데이터를 여러 번 재사용하여 용량 미스를 크게 줄입니다. 분기 명령을 줄이는 것은 루프 언롤링의 목적이며, 사용하는 메모리 총량은 변하지 않습니다.

자주 묻는 질문

루프 타일링은 어디에 쓰나요?

루프를 재구성하여 캐시 크기의 데이터 블록 단위로 작업하게 함으로써, 적재된 각 원소가 쫓겨나기 전에 여러 번 재사용되도록 합니다. 이로써 용량 미스와 메모리 트래픽이 크게 줄어듭니다.

행렬 곱의 블록 크기는 어떻게 정하나요?

작업 중인 타일들이 대상 캐시에 들어가는 크기에서 시작합니다. 예를 들어 32 KB L1에 double형 b × b 타일 3개를 넣으면 b는 약 32가 되며, 이후 충돌, TLB, 프리페치를 고려해 실험적으로 조정합니다.

루프 블로킹과 루프 언롤링은 같은 것인가요?

아닙니다. 언롤링은 루프 오버헤드와 분기를 줄이는 것이고, 블로킹은 반복 순서를 바꾸어 캐시 재사용을 개선하는 것입니다.
