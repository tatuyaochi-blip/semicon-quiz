블랙박스 테스트(Black-box Testing)란?

프로그램의 내부 구조를 보지 않고, 사양만으로 입력과 기대하는 출력을 정하여 확인하는 테스트 방법. 동치 분할, 경계값 분석, 결정 테이블 등의 기법이 있다.

블랙박스 테스트의 설명으로 적절한 것은?

  1. A프로그램의 내부 구조를 보지 않고, 사양에 기반하여 입력과 기대하는 출력을 정하고 올바르게 동작하는지를 확인한다
  2. B프로그램의 내부 구조에 주목하여, 명령이나 분기가 실행되었는지를 기준으로 테스트 케이스를 만든다
  3. C사용자가 실제 업무 환경에서 시스템을 요구사항대로 쓸 수 있는지를 최종적으로 확인한다
정답과 해설 보기

정답: A. 프로그램의 내부 구조를 보지 않고, 사양에 기반하여 입력과 기대하는 출력을 정하고 올바르게 동작하는지를 확인한다

블랙박스 테스트는 테스트 대상을 속이 보이지 않는 상자로 간주하고, 사양만으로 테스트 케이스를 만드는 방법으로, 동치 분할, 경계값 분석, 원인-결과 그래프, 결정 테이블 등의 기법이 있습니다. 사양에는 있는데 구현되지 않은 기능 등을 찾기 쉬운 반면, 구현 안의 특정 경로를 지나갔는지는 알 수 없습니다. 내부 구조에 주목하여 커버리지를 기준으로 하는 것은 화이트박스 테스트입니다. 사용자에 의한 최종 확인은 인수 테스트로, 이는 테스트 단계의 이름입니다.
