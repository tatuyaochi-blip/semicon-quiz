패킷(Packet)란?

통신으로 보낼 데이터를 일정 크기 이하로 나누고, 목적지 등의 제어 정보를 적은 헤더를 붙인 것. 1개의 회선을 많은 통신이 나눠 쓸 수 있고(패킷 교환), 오류가 있어도 그 부분만 다시 보낼 수 있다. 계층에 따라 IP에서는 패킷, TCP에서는 세그먼트, 이더넷에서는 프레임으로 구분해 부르는 경우가 많다. PCI Express나 온칩 네트워크에서도 데이터를 패킷으로 만들어 보낸다.

일본어 명칭: パケット

패킷(Packet)은(는) 네트워크 기초, I/O 인터페이스와 버스, 웹 기술 기초 등 4개 분야의 연습 문제 24개에 나와요.

분야: 네트워크 기초

도전해 보기: 패킷(Packet) 관련 문제

PCI Express에서 64바이트의 작은 데이터를 쓰는 패킷을 다수 보내면 실효 대역폭이 이론값보다 상당히 작아진다. 그 주된 이유는?

  1. A64바이트 데이터는 PCI Express에서 보낼 수 없기 때문
  2. B패킷마다 헤더나 오류 검출 부호 등이 붙어 데이터에 비해 그 비율이 커지기 때문
  3. C작은 패킷은 반드시 오류가 나서 매번 재전송되기 때문
정답과 해설 보기

정답: B. 패킷마다 헤더나 오류 검출 부호 등이 붙어 데이터에 비해 그 비율이 커지기 때문

PCI Express 패킷에는 데이터 외에 주소와 종류를 나타내는 헤더, 데이터 링크 계층의 일련번호와 CRC, 물리 계층의 구분자 등이 붙어 합쳐서 20~30바이트 정도가 됩니다. 데이터가 64바이트라면 보내는 비트의 3할 안팎이 데이터 이외가 됩니다. 256바이트 이상의 묶음 전송으로 하면 낭비 비율이 작아집니다. 이 또한 대역폭뿐 아니라 패킷 크기에도 주의해야 하는 이유입니다.

OSI 참조 모델에서 IP 주소 같은 논리 주소를 사용하여 서로 다른 네트워크 사이에서 패킷을 중계해 목적지까지 전달하는 역할을 하는 계층은?

  1. A데이터 링크 계층(2계층)
  2. B네트워크 계층(3계층)
  3. C전송 계층(4계층)
정답과 해설 보기

정답: B. 네트워크 계층(3계층)

OSI 참조 모델은 통신 기능을 물리 계층부터 응용 계층까지 7개 계층으로 나누어 정리한 모델입니다. 네트워크 계층(3계층)은 IP 주소 같은 논리 주소를 사용하여 여러 네트워크에 걸쳐 목적지까지의 경로를 선택하고 패킷을 중계합니다. 그 아래의 데이터 링크 계층은 같은 네트워크 안에서 MAC 주소를 사용해 이웃한 기기에 프레임을 전달하는 데까지를 담당합니다. 전송 계층은 단말의 애플리케이션 간 통신을 다루며, TCP라면 재전송과 순서 관리를 수행합니다. 기기로 말하면 라우터는 3계층, L2 스위치는 2계층에서 동작합니다.

패킷(Packet)이(가) 나오는 문제 (24)

  1. PCI Express에서 64바이트의 작은 데이터를 쓰는 패킷을 다수 보내면 실효 대역폭이 이론값보다 상당히 작아진다. 그 주된 이유는?
  2. OSI 참조 모델에서 IP 주소 같은 논리 주소를 사용하여 서로 다른 네트워크 사이에서 패킷을 중계해 목적지까지 전달하는 역할을 하는 계층은?
  3. NAPT를 수행하는 라우터(외부 공인 주소는 198.51.100.7) 안쪽에 있는 단말 A(192.168.1.10)가 출발지 포트 50000으로 웹 서버 203.0.113.5의 443번 포트에 접속했다. 라우터는 출발지를 198.51.100.7의 포트 61000으로 변환했다. 웹 서버가 돌려보내는 응답 패킷의 목적지는?
  4. 단말(192.168.1.10/24, 기본 게이트웨이 192.168.1.1)이 다른 네트워크에 있는 서버 203.0.113.80으로 패킷을 보낸다. ARP 캐시가 비어 있을 때, 단말이 ARP로 MAC 주소를 알아내는 상대는?
  5. 라우터의 라우팅 테이블에 0.0.0.0/0(다음 전달 대상은 라우터 A), 10.0.0.0/8(라우터 B), 10.1.0.0/16(라우터 C), 10.1.2.0/24(라우터 D)의 4개 경로가 있다. 목적지가 10.1.5.9인 패킷은 어느 라우터로 보내지는가?
  6. TCP에서 연결을 설정하는 3-way 핸드셰이크에서 주고받는 패킷의 순서로 올바른 것은?
  7. 1 Gbps 이더넷에서 IP 패킷의 크기가 MTU를 꽉 채운 1500바이트가 되도록 하여 TCP 데이터를 계속 보낸다. IPv4 헤더를 20바이트, TCP 헤더를 20바이트, 이더넷 헤더와 FCS를 합쳐 18바이트, 프리앰블과 프레임 사이의 빈 시간(프레임 간 갭)을 합쳐 20바이트라고 할 때, 애플리케이션 데이터의 처리량 상한에 가장 가까운 것은?
  8. 방화벽(패킷 필터링형)의 기본적인 기능으로 올바른 것은?
  9. PCI Express 3.0(1레인당 8 GT/s, 128b/130b 부호화)의 x16 접속에서 단방향 실효 대역폭에 가장 가까운 것은?

  13. 대형 SoC에서 1개의 공유 버스 대신 네트워크 온 칩(NoC)이 사용되게 된 이유로 올바른 것은?
