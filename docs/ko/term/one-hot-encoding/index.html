원핫 인코딩(One-hot Encoding)란?

상태 기계의 상태마다 하나의 플립플롭을 할당하고 항상 하나만 1로 하는 부호화. 논리가 간단하고 빨라지기 쉬워 FPGA에서 자주 사용된다.

일본어 명칭: ワンホット符号化

분야: HDL과 검증

원핫 상태 인코딩의 동작 방식

유한 상태 기계에서 원핫 인코딩은 각 상태에 고유한 플립플롭을 할당하며, 언제나 정확히 하나의 플립플롭만 1을 가집니다. 상태 4개는 0001, 0010, 0100, 1000이 됩니다. 기계가 특정 상태에 있는지 확인하려면 비트 하나만 보면 되므로, 상태에 의존하는 출력은 흔히 플립플롭 하나이거나 몇 개의 작은 OR입니다. 각 플립플롭의 다음 상태 입력은 그 상태로 들어오는 천이 조건들을 각각 출발 상태의 비트와 AND한 뒤 OR한 것이므로, 논리 단수가 얕고 기계가 빠르게 동작합니다.

원핫 인코딩과 바이너리 인코딩

바이너리 인코딩은 상태에 번호를 매기며 log2 N을 올림한 개수의 플립플롭만 필요합니다. 상태 3개는 플립플롭 2개에 들어가지만 원핫은 3개가 필요하고, 상태 16개는 4개 대 16개입니다. 바이너리 인코딩의 대가는 더 넓은 디코드 논리로, 상태를 인식하려면 모든 상태 비트를 비교해야 하기 때문입니다. 세 번째 선택지인 그레이 코드 인코딩은 자주 일어나는 천이에서 1비트만 바뀌도록 코드를 할당해 스위칭 활동을 줄입니다. 바이너리는 플립플롭이 부족하거나 상태 수가 많은 설계에, 원핫은 플립플롭이 넉넉할 때 속도와 단순함을 원하는 설계에 적합합니다.

FPGA가 원핫을 선호하는 이유

FPGA 로직 블록은 작은 룩업 테이블(LUT)마다 하나 이상의 플립플롭을 짝지어 두므로, 레지스터는 풍부한 반면 넓은 논리 함수는 여러 단의 LUT로 나눠야 합니다. 원핫 인코딩은 이 구조에 잘 맞습니다. 각 상태 비트의 다음 상태 함수는 보통 입력이 몇 개뿐이라 LUT 하나에 들어가므로 크리티컬 패스가 짧아집니다. 합성 도구는 흔히 상태 기계를 검출해 인코딩을 자동으로 선택하며, 소·중규모 기계에는 원핫을 고르는 경우가 많지만 설계자가 이를 바꿀 수 있습니다. 플립플롭의 면적 비용이 더 큰 ASIC에서는 바이너리나 다른 압축된 인코딩이 더 일반적입니다.

허용되지 않는 상태와 복구

플립플롭이 N개일 때 원핫은 가능한 2^N개의 패턴 중 N개만 사용하므로, 모두 0인 패턴과 여러 비트가 1인 패턴은 허용되지 않는 상태입니다. 노이즈, 글리치, 방사선에 의한 비트 반전으로 기계가 이런 상태에 빠지면 멈추거나 예측할 수 없게 동작할 수 있습니다. 바이너리 인코딩에도 상태 3개짜리 기계의 11처럼 사용하지 않는 코드에 대해 같은 문제가 있습니다. 따라서 견고한 설계는 예상치 못한 상태를 알려진 상태로 되돌리는 default 분기를 정의하며, 합성 도구는 이 복구 논리를 최적화로 제거하지 않고 유지하는 안전한 상태 기계 옵션을 제공합니다.

자주 묻는 질문

원핫 인코딩에는 플립플롭이 몇 개 필요한가요?

상태마다 플립플롭 하나가 필요하므로, 상태가 N개인 기계에는 N개가 필요합니다. 같은 기계를 바이너리로 인코딩하면 log2 N을 올림한 개수만 필요합니다.

원핫 인코딩과 바이너리 상태 인코딩의 차이는?

원핫은 상태마다 플립플롭 하나를 쓰고 비트 하나만 세트하므로 레지스터가 더 많이 드는 대신 디코드 논리가 단순하고 빠릅니다. 바이너리 인코딩은 상태 번호를 가장 적은 플립플롭에 저장하지만 각 상태를 디코드하는 데 더 넓은 논리가 필요합니다.

디지털 설계의 원핫 인코딩과 머신러닝의 원핫 인코딩은 같은 것인가요?

개념은 같습니다. 정확히 하나의 요소만 1인 벡터로 집합에서 항목 하나를 식별합니다. 하드웨어에서는 상태 기계의 현재 상태나 선택 신호를 인코딩하고, 머신러닝에서는 범주형 값을 수치 벡터로 표현합니다.
