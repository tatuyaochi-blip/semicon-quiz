DNS(도메인 네임 시스템)란?

Domain Name System의 약자. www.example.com 같은 도메인 이름과 통신에 사용하는 IP 주소를 대응시키는, 전 세계의 서버에서 분산 관리되는 구조.

일본어 명칭: DNS

DNS(도메인 네임 시스템)은(는) 네트워크 기초, 네트워크 설계와 운용, 클라우드와 컨테이너의 기초 등 3개 분야의 연습 문제 13개에 나와요.

분야: 네트워크 기초

이름 해석의 흐름

단말은 인터넷 서비스 제공자나 사내 등에 있는 풀 서비스 리졸버(캐시 DNS 서버)에 질의합니다. 리졸버는 캐시에 답이 없으면 루트 서버, .com 등의 TLD 서버, 그 도메인의 권한 있는 DNS 서버 순서로 질의하여 답을 얻고 단말에 돌려줍니다. 각 서버는 '다음은 이 서버에 물어보세요'라고 알려 줄 뿐이므로, 어느 서버도 전체 데이터를 가질 필요가 없습니다.

캐시와 TTL

리졸버는 얻은 답을 레코드에 붙은 유효 기간(TTL) 동안 캐시하고, 같은 질의에는 바로 답합니다. 이로써 질의 수와 대기 시간을 줄일 수 있지만, DNS 설정을 바꿔도 오래된 답의 캐시가 만료될 때까지는 이전 값이 사용될 수 있습니다. 서버를 이전하기 전에 TTL을 짧게 해 두는 것은 이 때문입니다.

주요 레코드와 통신 방식

레코드에는 IPv4 주소를 나타내는 A, IPv6 주소를 나타내는 AAAA, 별칭을 나타내는 CNAME, 메일 배송처를 나타내는 MX, 그 도메인의 권한 있는 DNS 서버를 나타내는 NS 등이 있습니다. 질의에는 주로 UDP 53번 포트가 사용되며, 응답이 클 때 등에는 TCP도 사용됩니다. 엿보기나 가짜 응답에 대한 대책으로 DNSSEC에 의한 서명이나 DNS over HTTPS(DoH) 등의 암호화도 사용되고 있습니다.

도전해 보기: DNS(도메인 네임 시스템) 관련 문제

RTT(왕복 시간)가 100 ms인 웹 서버에 HTTPS(TCP 위의 TLS 1.3)로 새로 접속하여, 첫 요청을 보내고 응답을 받기 시작할 때까지 걸리는 시간에 가장 가까운 것은? DNS 이름 해석은 끝났으며, 서버의 처리 시간과 데이터 전송 시간은 무시한다.

  1. A약 100 ms
  2. B약 300 ms
  3. C약 200 ms
정답과 해설 보기

정답: B. 약 300 ms

먼저 TCP의 3-way 핸드셰이크에 1왕복이 걸립니다(클라이언트는 마지막 ACK와 함께 TLS의 첫 메시지를 보낼 수 있습니다). 다음으로 TLS 1.3 핸드셰이크에 1왕복, 그 후 HTTP 요청과 응답에 1왕복이 걸려 합계 3왕복, 3 × 100 = 300 ms입니다. TLS 1.2에서는 키 교환에 2왕복이 걸리므로 4왕복인 400 ms가 됩니다. 이 대기 시간은 거리로 정해지는 RTT의 횟수로 결정되므로 회선의 대역폭을 늘려도 짧아지지 않습니다. HTTP/3에서 사용되는 QUIC은 전송 계층과 암호의 핸드셰이크를 1왕복으로 합치고, 재접속할 때는 첫 왕복에서 데이터를 보내는 방법(0-RTT)도 제공합니다.

DNS의 주된 역할로 올바른 것은?

  1. AIP 주소를 바탕으로 같은 네트워크에 있는 기기의 MAC 주소를 알아낸다
  2. Bwww.example.com 같은 도메인 이름을 통신에 사용하는 IP 주소로 변환한다(이름 해석)
  3. C통신을 암호화하고 접속한 웹사이트가 진짜인지 확인한다
정답과 해설 보기

정답: B. www.example.com 같은 도메인 이름을 통신에 사용하는 IP 주소로 변환한다(이름 해석)

사람이 기억하기 쉬운 도메인 이름과 통신에 사용하는 IP 주소를 대응시키는 구조가 DNS(Domain Name System)입니다. 브라우저에서 URL을 열면 단말은 먼저 DNS에 질의하여 서버의 IP 주소를 얻은 뒤 그 주소로 접속합니다. DNS의 데이터는 한 대의 서버에 모여 있는 것이 아니라 도메인 이름의 계층별로 나뉘어 전 세계의 서버에서 분산 관리됩니다. 질의에는 주로 UDP 53번 포트가 사용되며, 응답이 클 때 등에는 TCP도 사용됩니다.

자주 묻는 질문

DNS는 몇 번 포트를 사용하나요?

표준으로는 53번 포트입니다. 일반적인 질의는 주로 UDP로 하며, 응답이 큰 경우나 서버 사이에서 존 데이터를 전송하는 경우 등에는 TCP도 사용합니다.

DNS 설정을 바꿨는데 바로 반영되지 않는 이유는 무엇인가요?

리졸버나 단말이 이전 답을 레코드의 TTL 동안 캐시하고 있기 때문입니다. 캐시가 만료되어 새로 다시 질의할 때까지는 오래된 주소가 사용될 수 있습니다.

  • 재귀적 질의는 '최종 답을 돌려 달라'는 요청이며, 단말은 보통 인터넷 서비스 제공자나 사내의 풀 서비스 리졸버(캐시 DNS 서버)에 이 형태로 질의합니다.

이 용어가 포함된 비교

  • TCP와 UDP의 차이: 연결·신뢰성·순서·혼잡 제어·헤더·지연·용도 비교TCP와 UDP를 한 장의 표로 비교합니다. 연결 수립, 확인 응답과 재전송, 순서, 데이터 경계, 흐름 제어와 혼잡 제어, 헤더 크기, 지연, 전송 대상의 종류와 대표 용도를 정리합니다.
  • IPv4와 IPv6의 차이: 주소 길이·헤더·프래그먼테이션·주소 설정·NAT 비교IPv4와 IPv6를 한 장의 표로 비교합니다. 주소 길이와 개수, 표기법, 헤더, 단편화(프래그먼테이션), 주소 자동 설정, MAC 주소 확인, NAT, 전송 대상의 종류와 IPsec을 정리합니…
  • DHCPv6와 SLAAC의 차이: IPv6 주소 결정 방식·상태 관리·게이트웨이와 DNS·선택 기준 비교IPv6 주소를 자동으로 설정하는 두 방식인 DHCPv6와 SLAAC(상태 비저장 주소 자동 설정)를 한 장의 표로 비교합니다. 주소를 정하는 주체, 상태, 필요한 것, 쓰는 메시지, 기본 게이트…
