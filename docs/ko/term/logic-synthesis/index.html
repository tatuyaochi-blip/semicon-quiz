논리 합성란?

RTL로 기술된 회로를 셀 라이브러리의 게이트를 사용한 넷리스트로 변환하는 설계 공정.

일본어 명칭: 論理合成

논리 합성은(는) IC 설계 흐름과 EDA, HDL과 검증, 논리 회로 등 3개 분야의 연습 문제 23개에 나와요.

분야: IC 설계 흐름과 EDA

합성 도구가 하는 일

합성은 세 가지 입력을 받습니다. 하드웨어 기술 언어로 쓴 RTL, 각 게이트의 기능, 타이밍, 면적, 전력을 기술한 셀 라이브러리, 그리고 보통 SDC 형식으로 쓴 클록 주기와 I/O 지연 같은 제약 조건입니다. 도구는 먼저 RTL을 범용 로직으로 변환하면서 레지스터, 멀티플렉서, 산술 연산기를 추론합니다. 이어서 기술과 무관하게 불 논리를 최적화하고, 라이브러리 셀에 매핑한 뒤, 마지막으로 제약을 만족하도록 셀 크기 조정, 버퍼 삽입, 경로 재구성을 합니다. 출력은 게이트 수준 넷리스트와 타이밍, 면적, 전력 리포트입니다.

RTL이 하드웨어가 되는 방식

합성은 코드를 명령어가 아니라 회로로 바꾸므로 모든 블록이 동시에 동작합니다. always @(posedge clk) 블록은 에지 트리거 플립플롭이 됩니다. else 없는 if처럼 모든 분기에서 출력을 할당하지 않는 조합 블록은 이전 값을 유지하기 위해 도구가 래치를 추론하게 만듭니다. 합성은 감도 리스트를 무시하므로, 리스트가 불완전하면 시뮬레이션과 게이트의 동작이 어긋나며, @(*)를 쓰면 이를 피할 수 있습니다. #10 같은 지연과 $display 같은 테스트벤치용 태스크는 시뮬레이션 전용이라 무시됩니다.

제약 조건이 결과를 좌우한다

같은 RTL에서도 전혀 다른 넷리스트가 나올 수 있습니다. 클록이 빡빡하면 도구는 더 크고 빠른 셀, 저문턱 전압 셀, 그리고 리플 캐리 가산기 대신 캐리 룩어헤드 가산기 같은 병렬 구조를 택해 면적과 누설이 늘어나며, 클록이 여유로우면 면적을 최소화할 수 있습니다. 폴스 패스와 멀티사이클 패스는 도구가 노력을 들이지 않아도 되는 곳을 알려 줍니다. 잘못된 제약은 위험합니다. 설계가 모든 도구 검사를 통과하고도 실리콘에서 실패할 수 있습니다. 레이아웃 전에는 배선 지연을 추정할 수밖에 없으므로, 물리 인식 합성은 배치 정보를 활용해 상관성을 높입니다.

설계 흐름 속의 합성

일반적인 흐름은 테이프아웃 전에 사양, RTL 설계, 논리 합성, 배치 배선, 기생 성분 추출, 사인오프 타이밍 분석 순으로 진행됩니다. 그 위에는 고위 합성(HLS)이 있어, 연산을 클록 사이클에 스케줄링하며 C나 C++로부터 RTL을 생성하고, 논리 합성이 그 RTL을 게이트로 바꿉니다. 형식 등가성 검사는 시뮬레이션 없이 넷리스트가 RTL과 같은 로직을 구현함을 증명합니다. 테스트용 스캔 삽입은 보통 합성 중이나 직후에 합니다. FPGA에서는 합성이 로직을 표준 셀 대신 룩업 테이블과 플립플롭에 매핑합니다.

논리 합성에 대한 설명으로 올바른 것은?

  1. A칩 위에 셀을 배치하고 배선을 연결하는 공정
  2. BRTL 기술을 셀 라이브러리의 게이트로 구성한 넷리스트로 변환하는 공정
  3. C웨이퍼 위에 회로 패턴을 전사하는 공정
정답과 해설 보기

정답: B. RTL 기술을 셀 라이브러리의 게이트로 구성한 넷리스트로 변환하는 공정

논리 합성은 RTL로 작성된 회로의 동작 기술을 셀 라이브러리에 있는 논리 게이트와 플립플롭의 연결 정보(넷리스트)로 변환하는 공정입니다. 타이밍·면적·소비 전력 제약을 주면 툴이 논리식을 단순화하고 적절한 구동력의 셀을 골라 제약을 만족하도록 최적화합니다. 셀을 늘어놓고 배선하는 것은 배치 배선, 웨이퍼에 전사하는 것은 리소그래피입니다.

논리 합성 전후로 회로의 논리가 바뀌지 않았음을 시뮬레이션 없이 수학적으로 확인하는 기법은?

  1. A형식적 등가성 검증(포멀 검증)
  2. BDRC
  3. C다이싱
정답과 해설 보기

정답: A. 형식적 등가성 검증(포멀 검증)

형식적 등가성 검증은 두 회로가 같은 논리 함수를 구현하는지를 수학적 기법으로 빠짐없이 확인하는 검증입니다. 테스트 패턴을 준비할 필요가 없고 모든 입력 조합에 대해 등가성을 보증할 수 있으므로, 논리 합성, 배치 배선, ECO 전후의 확인에 사용됩니다. 시뮬레이션으로 모든 조합을 시험하는 것은 입력이 수십 비트만 되어도 현실적으로 불가능합니다. DRC는 도형 규칙의 검사입니다.

자주 묻는 질문

논리 합성과 고위 합성의 차이점

고위 합성은 C나 C++ 알고리즘 기술을 RTL로 변환하며, 각 연산을 어느 클록 사이클에 실행할지 결정합니다. 논리 합성은 RTL을 받아 라이브러리 셀로 이루어진 게이트 수준 넷리스트로 변환합니다.

합성에서 의도치 않은 래치가 생기는 이유는?

조합 블록이 어떤 경로에서 출력을 할당하지 않으면 출력이 이전 값을 기억해야 하는데, 그렇게 할 방법은 래치뿐입니다. 기본값을 할당하거나 모든 경우를 다루면 래치가 사라집니다.

논리 합성의 입력과 출력은 무엇인가요?

입력은 RTL, 셀 라이브러리, 타이밍 제약(보통 SDC)입니다. 출력은 게이트 수준 넷리스트와 타이밍, 면적, 전력에 관한 리포트입니다.

해설 속 논리 합성

  • 논리 합성은 RTL로 작성된 회로의 동작 기술을 셀 라이브러리에 있는 논리 게이트와 플립플롭의 연결 정보(넷리스트)로 변환하는 공정입니다.

    논리 합성에 대한 설명으로 올바른 것은?

  • 테스트 패턴을 준비할 필요가 없고 모든 입력 조합에 대해 등가성을 보증할 수 있으므로, 논리 합성, 배치 배선, ECO 전후의 확인에 사용됩니다.

    논리 합성 전후로 회로의 논리가 바뀌지 않았음을 시뮬레이션 없이 수학적으로 확인하는 기법은?

  • 'always @(posedge clk)'는 클럭이 상승하는 순간에만 안의 대입을 수행한다는 의미이며, 논리 합성은 이를 에지에서 동작하는 플립플롭으로 만듭니다.

    위의 Verilog 기술이 논리 합성으로 만드는 회로로 올바른 것은?

  • 조합 회로에는 기억 기능이 없으므로 논리 합성은 값을 유지하기 위한 래치를 만듭니다.

    조합 회로를 의도하여 위와 같이 작성하면 논리 합성에서 무엇이 만들어집니까?

  • '#10'은 시뮬레이션 안에서 시간을 10단위 진행시킨다는 의미이지만, 논리 합성은 지연을 만들 수 없으므로 무시합니다.
