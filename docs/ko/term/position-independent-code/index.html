위치 독립 코드(PIC)란?

메모리의 어느 번지에 적재해도 코드를 고치지 않고 동작하는 기계어. PIC라고도 한다. PC 상대 참조나 GOT를 이용하며 공유 라이브러리와 PIE에서 쓰인다.

일본어 명칭: 位置独立コード

위치 독립 코드(PIC)은(는) 링커, 로더, 실행 파일, ISA와 어셈블리 등 2개 분야의 연습 문제 5개에 나와요.

분야: 링커, 로더, 실행 파일

PIC가 코드와 데이터를 참조하는 방법

위치 독립 코드(PIC)는 명령어에 절대 주소를 절대 넣지 않습니다. 분기와 호출은 대상을 프로그램 카운터로부터의 거리로 지정하며, 이 거리는 모듈 전체가 어디에 놓이든 변하지 않습니다. 분기 필드로 닿을 수 없는 먼 대상에 대해서 RISC-V는 20비트 즉치값을 12비트 왼쪽으로 시프트해 PC에 더하는 auipc와, 하위 12비트를 제공하는 jalr 또는 로드 명령을 조합해 현재 명령으로부터 약 ±2 GiB 범위를 커버합니다. x86-64는 같은 목적으로 RIP 상대 주소 지정을 제공하므로, 위치 독립 코드가 고정 주소 코드와 거의 같은 속도로 동작합니다.

GOT와 PLT

PC 상대 거리는 한 모듈 안에서는 통하지만, 다른 공유 라이브러리에 있는 변수나 함수의 주소는 실행 시까지 알 수 없습니다. 그래서 PIC는 이런 심볼에 전역 오프셋 테이블(GOT)을 통해 접근합니다. GOT는 코드로부터 고정된 거리에 놓이는 모듈별 주소 테이블입니다. 코드는 필요한 주소를 GOT에서 로드하고, 동적 링커가 로드 시점에 실제 주소를 채워 넣습니다. ELF 시스템에서는 외부 함수 호출이 추가로 프로시저 링키지 테이블(PLT)의 작은 스텁을 거치며, 이를 통해 각 함수를 첫 호출 시에 지연 해결할 수 있습니다.

공유 라이브러리에 필요한 이유

공유 라이브러리는 이를 사용하는 프로세스마다 서로 다른 가상 주소에 매핑될 수 있습니다. 코드에 절대 주소가 들어 있으면 로더가 주소마다 명령어를 패치해야 하므로, 공유되던 읽기 전용 페이지가 프로세스별 쓰기 가능 사본으로 바뀌어 공유의 의미가 사라집니다. PIC를 사용하면 프로세스마다 다른 것은 작은 쓰기 가능 GOT뿐이므로, 코드 페이지는 수정할 필요가 없고 하나의 물리적 사본을 모든 프로세스에 매핑할 수 있습니다. 덕분에 메모리를 절약하고, 라이브러리가 어디에 놓이든 빠르게 로드할 수 있습니다.

PIC와 PIE, 그리고 보안과의 관계

위치 독립 실행 파일(PIE)은 같은 기법을 메인 프로그램에 적용한 것으로, 보통 GCC나 Clang에서 -fPIE와 -pie 옵션으로 빌드하며, 공유 라이브러리는 -fPIC를 사용합니다. 예전 실행 파일은 고정 로드 주소를 전제로 했기 때문에, 주소 공간 배치 무작위화(ASLR)가 라이브러리와 스택은 옮길 수 있어도 메인 프로그램의 코드는 옮길 수 없어 공격자가 그 주소를 예측할 수 있었습니다. PIE는 어디에나 로드할 수 있으므로 코드도 무작위화되며, 현재 많은 Linux 배포판은 기본적으로 PIE로 빌드합니다. 대가는 GOT 간접 참조로 인한 작은 오버헤드이며, 32비트 x86에서는 이 오버헤드가 눈에 띄게 컸습니다.

정답: C. 메모리의 어느 주소에 읽어 들여도 코드를 고쳐 쓰지 않고 올바르게 동작하도록 만들어진 기계어

공유 라이브러리는 프로세스마다 다른 주소에 읽혀질 수 있습니다. 위치 독립 코드에서는 함수나 데이터를 고정 주소가 아니라 PC로부터의 거리나 주소를 모아 둔 테이블(GOT)을 통해 참조합니다. 이렇게 하면 읽어 들이는 주소가 바뀌어도 코드 페이지를 고쳐 쓰지 않아도 되므로, 물리 메모리 상의 하나의 사본을 많은 프로세스가 공유할 수 있습니다.

자주 묻는 질문

PIC는 무엇의 약자인가요?

PIC는 position-independent code(위치 독립 코드)의 약자로, 어떤 로드 주소에서도 수정 없이 올바르게 동작하는 기계어 코드입니다. PC 상대 주소 지정과 전역 오프셋 테이블을 이용합니다.

-fPIC와 -fPIE의 차이는 무엇인가요?

둘 다 위치 독립 코드를 생성합니다. -fPIC는 심볼이 다른 모듈에 의해 대체될 수 있는 공유 라이브러리용이고, -fPIE는 메인 실행 파일용으로 자신의 심볼에 대해 약간 더 저렴한 직접 참조를 사용할 수 있습니다. -fPIE로 빌드한 실행 파일은 -pie로 링크해 PIE를 만듭니다.

전역 오프셋 테이블(GOT)은 왜 필요한가요?

다른 모듈에 있는 심볼의 주소는 로드한 뒤에야 알 수 있으므로 코드에 넣을 수 없습니다. GOT는 동적 링커가 채워 넣는 그 주소들을 보관하며, 코드는 PC 상대 참조로 GOT에 접근합니다.

    분기나 점프에 PC 상대 주소 지정을 사용하는 것의 이점으로 올바른 것은?

  • 이에 따라 프로그램을 어디에 로드해도 동작하는 위치 독립 코드에서 먼 함수를 호출하거나 전역 변수를 읽을 수 있습니다.

    RISC-V의 auipc 명령어(add upper immediate to PC)의 동작으로 올바른 것은?

  • 위치 독립 코드는 다른 라이브러리에 있는 변수의 주소를 명령에 직접 쓸 수 없습니다.

    공유 라이브러리에서 사용되는 GOT(Global Offset Table)의 역할로 올바른 것은 무엇입니까?

  • PIE는 본체도 위치 독립 코드로 만들어 어디에 읽혀도 동작하게 한 것으로, 본체의 주소도 무작위로 할 수 있습니다.
