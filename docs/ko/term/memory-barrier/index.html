메모리 배리어(Memory Barrier)란?

배리어 이전의 메모리 연산이 이후의 연산보다 먼저 다른 코어에서 보이는 것을 보장하는 명령. 펜스라고도 한다. RISC-V의 fence 등.

일본어 명칭: メモリバリア

메모리 배리어(Memory Barrier)은(는) 멀티코어와 동기화 등 1개 분야의 연습 문제 2개에 나와요.

분야: 멀티코어와 동기화

메모리 배리어가 보장하는 것

펜스라고도 하는 메모리 배리어는 스레드의 메모리 연산을 그 앞과 뒤로 나누고, 앞쪽 연산이 뒤쪽 연산보다 먼저 다른 코어에 보이도록 보장하는 명령입니다. 배리어가 없으면 프로세서는 예를 들어 저장을 스토어 버퍼에 두고 나중의 로드를 먼저 진행하는 식으로, 서로 다른 주소에 대한 로드와 저장을 순서와 다르게 완료할 수 있습니다. 명령을 실행한 스레드 자신이 보는 결과는 결코 바뀌지 않으므로, 배리어는 코어 간이나 DMA 엔진 같은 장치와 데이터를 공유할 때만 의미가 있습니다.

스토어 버퍼 예제

x와 y가 0에서 시작할 때, 코어 0은 x = 1 다음에 r1 = y를, 코어 1은 y = 1 다음에 r2 = x를 실행한다고 합시다. 순차 일관성에서는 한쪽 저장이 먼저 일어나므로 적어도 한 로드는 1을 반환해야 합니다. x86을 포함한 실제 프로세서에서는 각 저장이 자기 코어의 스토어 버퍼에서 기다리는 동안 뒤따르는 로드가 캐시에서 이전 값을 읽을 수 있으므로, r1과 r2가 모두 0이 될 수 있습니다. 각 스레드에서 저장과 로드 사이에 완전한 배리어를 두면 로드가 실행되기 전에 저장이 보이도록 강제되어 그런 결과가 배제됩니다.

실제 ISA의 배리어 명령

RISC-V는 fence를 제공하며, 피연산자로 어떤 앞선 접근을 어떤 나중 접근보다 먼저 정렬할지 지정합니다. 따라서 fence rw, rw는 모든 읽기와 쓰기의 순서를 정합니다. 원자적 명령과 load-reserved/store-conditional 명령에는 acquire·release 비트가 있습니다. Arm은 순서 지정을 위한 dmb(data memory barrier), 완료를 기다려야 할 때 쓰는 dsb, 그리고 load-acquire·store-release 명령을 갖추고 있습니다. 이미 대부분의 순서를 지키는 TSO(total store order)의 x86에서는, 주로 저장을 나중의 로드보다 앞에 정렬할 때 mfence나 lock 접두 명령이 필요합니다. 배리어는 대기 중인 저장이 모두 빠져나갈 때까지 코어를 멈추게 할 수 있으므로 공짜가 아닙니다.

락과 컴파일러에서의 배리어

대부분의 프로그래머는 배리어를 직접 작성하지 않습니다. 락 획득에는 acquire 의미론이 있어 나중의 접근이 그 앞으로 이동할 수 없고, 해제에는 release 의미론이 있어 락이 풀리기 전에 앞선 쓰기가 보이게 됩니다. 락으로 보호되는 데이터가 스레드 간에 올바르게 전달되는 이유가 이것입니다. 언어는 C11과 C++11처럼 메모리 오더를 지정한 atomic을 통해 같은 개념을 제공합니다. 컴파일러 배리어는 다른 것입니다. 컴파일러가 특정 지점을 넘어 접근 순서를 바꾸지 못하게 할 뿐 명령을 생성하지 않으므로 하드웨어를 제약하지는 않습니다.

정답과 해설 보기

정답: A. 배리어 이전의 메모리 연산이 배리어 이후의 연산보다 먼저 다른 코어에서 보이는 것을 보장한다

CPU는 메모리 연산의 순서를 바꾸는 경우가 있으므로, 다른 코어와 정해진 순서로 데이터를 주고받으려면 이를 막는 지시가 필요합니다. 메모리 배리어는 그 이전의 읽기와 쓰기를 모두 끝낸 뒤(다른 코어에 보이게 한 뒤) 이후의 읽기와 쓰기를 수행하게 합니다. 락의 획득과 해제 안에도 배리어의 역할이 포함되어 있어, 락으로 보호한 변수가 올바르게 전달됩니다.

자주 묻는 질문

메모리 배리어와 펜스는 어떻게 다른가요?

같은 개념을 부르는 두 이름입니다. 둘 다 다른 코어가 관측할 때 그 앞의 메모리 연산이 뒤의 연산보다 먼저 정렬되도록 하는 명령을 가리키며, RISC-V는 이 명령을 fence라 부르고 Arm은 배리어라고 부릅니다.

x86에도 메모리 배리어가 필요한가요?

약한 순서의 아키텍처보다는 덜 필요합니다. x86의 TSO(total store order)는 대부분의 로드와 저장을 프로그램 순서대로 유지하기 때문입니다. 그래도 저장이 다른 주소에 대한 나중의 로드보다 먼저 보여야 할 때는 mfence 같은 배리어나 lock 접두 명령이 필요합니다.

컴파일러 배리어와 메모리 배리어의 차이는 무엇인가요?

컴파일러 배리어는 컴파일러가 메모리 접근을 그 지점 너머로 옮기지 못하게 할 뿐 기계어 명령을 생성하지 않습니다. 메모리 배리어는 프로세서가 접근을 다른 코어에 보이게 하는 순서를 제약하는 하드웨어 명령입니다.
