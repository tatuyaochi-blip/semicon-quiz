DMA(직접 메모리 접근)란?

CPU를 거치지 않고 주변 장치와 메모리 사이에서 직접 데이터를 전송하는 구조. 대량의 데이터 전송 중에도 CPU가 다른 처리를 진행할 수 있다.

일본어 명칭: DMA(ダイレクトメモリアクセス)

DMA(직접 메모리 접근)은(는) OS와 하드웨어, CPU와 아키텍처, 임베디드 시스템과 펌웨어 등 6개 분야의 연습 문제 10개에 나와요.

분야: CPU와 아키텍처

DMA 전송의 동작 방식

프로그램 I/O(PIO)에서는 CPU가 로드·스토어 명령으로 모든 워드를 직접 옮깁니다. 반면 직접 메모리 접근(DMA)에서는 CPU가 DMA 컨트롤러나 장치 자체의 DMA 엔진에 소스, 목적지, 길이, 트리거를 설정한 뒤 다른 작업으로 돌아갑니다. 컨트롤러는 버스 제어권을 얻어 데이터를 옮기고 완료 인터럽트를 발생시킵니다. 예를 들어 마이크로컨트롤러에서는 타이머가 일정 간격으로 ADC 변환을 트리거하고, DMA가 각 결과를 배열에 저장하여 버퍼가 가득 찼을 때만 CPU를 깨울 수 있습니다.

고속 장치의 디스크립터 링

네트워크 카드와 NVMe SSD는 디스크립터 링을 사용합니다. 디스크립터 링은 메인 메모리에 있는 원형 테이블로, 각 항목에는 버퍼 주소와 길이가 들어 있습니다. CPU는 빈 디스크립터를 채우고, 흔히 도어벨이라 불리는 장치 레지스터에 한 번 써서 어디까지 기록했는지 알립니다. 장치는 DMA로 디스크립터를 읽어 직접 전송을 수행하고 끝난 항목을 완료로 표시합니다. 이렇게 CPU와 장치는 서로를 기다리지 않고 많은 전송을 진행하며, 흩어진 버퍼 목록도 한 번의 동작으로 처리할 수 있는데 이를 스캐터-개더라고 합니다.

캐시와 고정(pinned) 메모리

DMA는 CPU 캐시를 거치지 않으므로 메모리에 대한 두 관점이 어긋날 수 있습니다. 하드웨어가 일관성(coherence)을 유지하지 않는 경우, 드라이버는 장치가 버퍼를 읽기 전에 더티 캐시 라인을 메모리에 기록하고, 장치가 쓴 데이터를 CPU가 읽기 전에 해당 캐시 범위를 무효화하여 오래된 값이 쓰이지 않게 합니다. 또한 운영 체제는 일반 페이지를 언제든 이동하거나 스왑 아웃할 수 있으므로, DMA용 버퍼는 제자리에 고정(pin)합니다. 고정된 호스트 메모리를 쓰면 GPU가 중간 복사 없이 데이터를 전송하고 전송과 연산을 겹쳐 수행할 수 있습니다.

IOMMU로 메모리 보호하기

DMA는 메모리에 직접 쓰므로, 결함이 있거나 악의적인 장치가 커널 데이터를 덮어쓰거나 암호화 키를 읽을 수 있으며, 특히 고속 외부 포트로 연결되는 장치에서 우려됩니다. IOMMU(입출력 메모리 관리 장치)는 MMU가 CPU에 대해 하는 일을 장치에 대해 수행합니다. 장치가 사용하는 주소를 물리 주소로 변환하고, 운영 체제가 허용한 영역 밖으로의 접근을 차단합니다. 또한 흩어진 물리 페이지를 장치에는 연속된 것처럼 보이게 하며, 장치를 가상 머신에 직접 할당하는 것을 안전하게 만듭니다.

캐시 일관성을 하드웨어가 유지하지 않는(비코히런트) 시스템에서, 장치가 DMA로 주기억장치에 쓴 데이터를 CPU가 읽기 전에 소프트웨어가 수행해야 하는 처리는?

  2. B해당 범위의 캐시 내용을 무효화하여 주기억장치에서 다시 읽도록 한다
  3. C캐시 내용을 모두 주기억장치에 되쓴 후 DMA로 도착한 결과를 폐기한다
정답과 해설 보기

정답: B. 해당 범위의 캐시 내용을 무효화하여 주기억장치에서 다시 읽도록 한다

DMA는 CPU를 거치지 않고 장치와 주기억장치 사이에서 데이터를 전송하므로, 하드웨어가 일관성을 유지하지 않는 시스템에서는 CPU 캐시에 그 범위의 오래된 데이터가 남아 있을 수 있습니다. 그대로 읽으면 DMA로 도착한 새 데이터가 아니라 오래된 값을 읽게 됩니다. 그래서 드라이버는 읽기 전에 그 범위의 캐시를 무효화하여 주기억장치에서 새 값을 읽게 합니다. 반대로 장치로 보낼 데이터는 DMA를 시작하기 전에 캐시에서 되써 둡니다.

마이크로컨트롤러에서 AD 컨버터의 변환 결과를 일정한 간격으로 대량으로 가져올 때 DMA를 사용하는 이점으로 올바른 것은 무엇입니까?

  1. AAD 컨버터의 분해능이 자동으로 올라간다
  2. B입력 전압이 자동으로 커진다
  3. C변환이 끝날 때마다 CPU가 인터럽트로 읽을 필요 없이 DMA가 메모리에 나열해 주므로 CPU의 부담이 줄어든다
정답과 해설 보기

정답: C. 변환이 끝날 때마다 CPU가 인터럽트로 읽을 필요 없이 DMA가 메모리에 나열해 주므로 CPU의 부담이 줄어든다

변환할 때마다 인터럽트로 CPU가 결과를 읽으면, 1초에 수만 번 가져오는 경우 인터럽트 오버헤드만으로 CPU 시간의 상당 부분이 쓰입니다. DMA를 사용하면 변환이 끝날 때마다 DMA가 결과를 메모리 배열에 차례로 쓰고, 배열이 가득 찼을 때만 CPU에 알립니다. 타이머로 변환을 시작하도록 설정하는 것과 조합하면, 정확한 간격으로 데이터를 CPU 없이 계속 가져올 수 있습니다.

자주 묻는 질문

DMA는 무엇의 약자인가요?

DMA는 direct memory access(직접 메모리 접근)의 약자로, CPU가 워드마다 복사하지 않아도 주변 장치가 메인 메모리와 데이터를 주고받을 수 있게 하는 메커니즘입니다. 그동안 CPU는 다른 작업을 할 수 있습니다.

DMA와 프로그램 I/O의 차이는 무엇인가요?

프로그램 I/O에서는 CPU가 모든 데이터 워드를 직접 장치에 읽고 씁니다. DMA에서는 CPU가 전송을 설정하기만 하고 완료되면 통지를 받으므로, 대량이거나 빈번한 전송에서 CPU 시간을 절약할 수 있습니다.

메모리로 DMA 전송한 뒤 캐시를 무효화해야 하는 이유는 무엇인가요?

하드웨어 캐시 일관성이 없는 시스템에서는 CPU 캐시에 해당 메모리 범위의 오래된 복사본이 남아 있을 수 있습니다. 캐시를 무효화하면 CPU가 장치가 새로 쓴 데이터를 읽게 됩니다.
