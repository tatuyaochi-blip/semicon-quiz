중간 표현(intermediate representation)란?

컴파일러 내부에서 쓰는 프로그램 형태로, 원시 언어에도 대상 CPU에도 의존하지 않습니다. 대부분의 최적화가 이 위에서 이루어지며, 언어별 프런트엔드와 CPU별 백엔드를 분리해 줍니다.

일본어 명칭: 中間表現

중간 표현(intermediate representation)은(는) 컴파일러 등 1개 분야의 연습 문제 6개에 나와요.

분야: 컴파일러

도전해 보기: 중간 표현(intermediate representation) 관련 문제

컴파일러 내부에서 소스 언어에도 CPU에도 의존하지 않는 중간 표현(IR)을 사용하는 주된 이점은?

  1. A중간 표현을 사용하면 소스 코드를 읽지 않고도 컴파일할 수 있게 되기 때문에
  2. B중간 표현은 CPU가 그대로 실행할 수 있으므로 기계어 생성이 필요 없어지기 때문에
  3. C언어별 전단부와 CPU별 후단부를 분리할 수 있고 최적화도 공통으로 사용할 수 있기 때문에
정답과 해설 보기

정답: C. 언어별 전단부와 CPU별 후단부를 분리할 수 있고 최적화도 공통으로 사용할 수 있기 때문에

M종류의 언어와 N종류의 CPU를 지원할 때 조합마다 컴파일러를 만들면 M×N개가 필요하지만, 공통 중간 표현을 거치면 언어에서 중간 표현까지의 전단부(프런트엔드) M개와 중간 표현에서 CPU까지의 후단부(백엔드) N개로 충분합니다. 최적화의 상당 부분도 중간 표현 위에서 한 번 만들면 모든 언어와 CPU에서 사용할 수 있습니다. 중간 표현은 CPU가 그대로 실행할 수 있는 것이 아니며, 마지막에 기계어로 변환해야 합니다.

SSA 형식 중간 표현의 특징으로 올바른 것은?

  1. A각 변수에 대한 대입이 프로그램 안에서 정확히 1번이 된다
  2. B모든 변수가 레지스터가 아니라 메모리 위에 놓인다
  3. C조건 분기 명령을 전혀 포함하지 않는 형태로 다시 쓰인다
정답과 해설 보기

정답: A. 각 변수에 대한 대입이 프로그램 안에서 정확히 1번이 된다

SSA 형식에서는 변수에 대한 대입이 1번이 되도록 이름을 바꾸어 붙이고, 합류 지점에서는 φ 함수로 값을 선택합니다. 예를 들어 x를 2번 대입한다면 x1과 x2로 나누어 어느 쪽이 사용되는지를 명확히 합니다. 정의와 사용의 관계가 분명해지므로 상수 전파나 불필요한 코드의 삭제 같은 최적화가 쉬워집니다. 분기는 φ 함수로 다루므로 분기 명령이 없어지는 것은 아닙니다. 변수가 메모리에 놓이는 형태도 아니며, 대부분은 레지스터 후보로 취급됩니다.
