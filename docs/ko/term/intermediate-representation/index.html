중간 표현(IR)란?

컴파일러 내부에서 소스 언어에도 CPU에도 의존하지 않는 형태로 프로그램을 나타낸 것. 최적화 대부분이 이 위에서 이루어지며 언어별 프런트엔드와 CPU별 백엔드를 분리할 수 있다.

일본어 명칭: 中間表現

중간 표현(IR)은(는) 컴파일러 등 1개 분야의 연습 문제 6개에 나와요.

분야: 컴파일러

컴파일러가 IR을 쓰는 이유

M개의 소스 언어를 N개의 프로세서에서 지원하려면 개별 컴파일러가 M × N개 필요합니다. 공통 중간 표현(IR)이 있으면 언어마다 IR로 번역하는 프런트엔드 하나, 프로세서마다 IR에서 번역하는 백엔드 하나만 있으면 되므로 총 M + N개로 충분합니다. IR 위에 한 번 작성한 최적화는 모든 언어와 타깃에 적용됩니다. 가장 잘 알려진 예가 LLVM으로, Clang 같은 프런트엔드가 LLVM IR을 출력하고 백엔드가 x86, Arm, RISC-V 등의 타깃용 코드를 생성합니다.

대표적인 형태

컴파일러는 여러 수준의 IR을 쓰는 경우가 많습니다. 소스에 가까운 쪽에는 추상 구문 트리가 있습니다. 더 낮은 수준에서는 3번지 코드가 식을 t1 = a + b; x = t1 * c 처럼 단순한 단계로 나누고, 중간값에는 임시 변수를 씁니다. 이 명령어들은 기본 블록으로 묶이고, 기본 블록은 제어 흐름 그래프로 연결됩니다. LLVM IR을 포함한 많은 현대 IR은 정적 단일 할당(SSA) 형식을 사용합니다. SSA에서는 각 변수가 정확히 한 번만 대입되며, 제어 경로가 합류하는 곳에서는 특별한 phi 노드가 값을 합칩니다.

IR 위에서 이루어지는 일

대부분의 최적화 패스는 IR 위에서 실행됩니다. 상수 전파, 죽은 코드 제거, 공통 부분식 제거, 루프 불변 계산의 루프 밖 이동, 함수 인라이닝 등입니다. SSA 형식에서는 모든 사용이 정확히 하나의 정의를 가리키므로 이들 중 상당수가 단순해집니다. 링크 타임 최적화(LTO)는 오브젝트 파일에 기계어 대신 IR을 저장해 프로그램 전체를 함께 최적화할 수 있게 하며, 소스 파일을 넘나드는 인라이닝과 사용되지 않는 함수 제거가 가능해집니다.

IR과 바이트코드, 기계어의 차이

컴파일러 내부 IR은 분석과 변환을 위한 작업용 형식이며 CPU가 실행할 수 없습니다. 백엔드가 여전히 명령어 선택, 레지스터 할당, 코드 스케줄링을 해야 합니다. Java 바이트코드나 WebAssembly 같은 이식 가능한 바이트코드는 관련이 있지만 목적이 다릅니다. 이들은 가상 머신이 인터프리트하거나 JIT 컴파일하는 안정적인 배포 형식인 반면, 내부 IR은 컴파일러 버전에 따라 바뀔 수 있습니다.

  3. C언어별 전단부와 CPU별 후단부를 분리할 수 있고 최적화도 공통으로 사용할 수 있기 때문에

정답: C. 언어별 전단부와 CPU별 후단부를 분리할 수 있고 최적화도 공통으로 사용할 수 있기 때문에

M종류의 언어와 N종류의 CPU를 지원할 때 조합마다 컴파일러를 만들면 M×N개가 필요하지만, 공통 중간 표현을 거치면 언어에서 중간 표현까지의 전단부(프런트엔드) M개와 중간 표현에서 CPU까지의 후단부(백엔드) N개로 충분합니다. 최적화의 상당 부분도 중간 표현 위에서 한 번 만들면 모든 언어와 CPU에서 사용할 수 있습니다. 중간 표현은 CPU가 그대로 실행할 수 있는 것이 아니며, 마지막에 기계어로 변환해야 합니다.

SSA 형식 중간 표현의 특징으로 올바른 것은?

  1. A각 변수에 대한 대입이 프로그램 안에서 정확히 1번이 된다
  2. B모든 변수가 레지스터가 아니라 메모리 위에 놓인다
  3. C조건 분기 명령을 전혀 포함하지 않는 형태로 다시 쓰인다
정답과 해설 보기

정답: A. 각 변수에 대한 대입이 프로그램 안에서 정확히 1번이 된다

SSA 형식에서는 변수에 대한 대입이 1번이 되도록 이름을 바꾸어 붙이고, 합류 지점에서는 φ 함수로 값을 선택합니다. 예를 들어 x를 2번 대입한다면 x1과 x2로 나누어 어느 쪽이 사용되는지를 명확히 합니다. 정의와 사용의 관계가 분명해지므로 상수 전파나 불필요한 코드의 삭제 같은 최적화가 쉬워집니다. 분기는 φ 함수로 다루므로 분기 명령이 없어지는 것은 아닙니다. 변수가 메모리에 놓이는 형태도 아니며, 대부분은 레지스터 후보로 취급됩니다.

자주 묻는 질문

컴파일러의 중간 표현이란

컴파일러가 기계어를 생성하기 전에 소스 코드를 번역해 두는 형태로, 소스 언어와 타깃 CPU 모두에 독립적이어서 최적화를 공유할 수 있습니다.

SSA 형식이란

정적 단일 할당은 모든 변수가 정확히 한 번만 대입되고, 제어 흐름이 합류하는 곳에서 phi 노드가 값을 선택하는 IR 형식으로, 많은 최적화를 단순하게 만듭니다.

LLVM IR은 기계어인가요

아닙니다. LLVM IR은 타깃에 독립적인 중간 표현이며, 백엔드가 이를 특정 프로세서용 기계어로 번역해야 합니다.
