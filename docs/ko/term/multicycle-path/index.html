멀티사이클 패스(Multicycle Path)란?

데이터 전달에 여러 클록 사이클을 사용해도 되는 경로를 STA에 알리는 타이밍 예외. 셋업을 N사이클로 했을 때는 홀드도 보통 N − 1을 지정하여 확인하는 에지를 원래 위치로 되돌린다.

일본어 명칭: マルチサイクルパス

멀티사이클 패스(Multicycle Path)은(는) 타이밍 분석과 CDC 등 1개 분야의 연습 문제 3개에 나와요.

분야: 타이밍 분석과 CDC

경로에 실제로 시간이 더 있는 경우

목적지가 N 사이클마다 한 번만 캡처하기 때문에 한 클록 주기 안에 데이터를 전달할 필요가 없는 경로가 있습니다. 예를 들어 한 사이클 걸러 어서트되는 인에이블을 통해 로드되는 레지스터나, 입력이 바뀐 지 두 사이클 후에 결과를 샘플링하는 느린 연산 블록이 그렇습니다. STA는 기본적으로 단일 사이클 전송을 가정하므로 위반을 보고합니다. SDC의 set_multicycle_path인 멀티사이클 패스 예외는 캡처 에지가 런치 후 1주기가 아니라 N주기 뒤에 있다고 툴에 알려 줍니다.

셋업 계산

클록이 2.0 ns, 데이터 도착 시간이 3.3 ns, 셋업 타임이 0.1 ns이면, 기본 단일 사이클 검사에서는 요구 시간이 1.9 ns, 슬랙이 −1.4 ns가 됩니다. 셋업 멀티사이클을 2로 하면 캡처가 4.0 ns로 이동하여 요구 시간은 3.9 ns, 슬랙은 +0.6 ns가 됩니다. 이 예외는 로직이 두 사이클마다 캡처하는 것을 실제로 보장하는 경우에만 유효하며, 그렇지 않으면 실리콘에서 드러날 실제 불량을 숨기게 됩니다.

홀드에 N − 1이 필요한 이유

STA는 셋업 캡처 에지보다 1주기 앞선 에지에 대해 홀드를 검사합니다. 따라서 셋업 캡처를 N주기로 옮기면 홀드 검사도 런치 후 N − 1주기로 끌려가며, 이는 새 데이터가 적어도 그만큼 늦게 도착할 것을 요구하는 터무니없이 엄격한 조건이라 대개 위반이 됩니다. 홀드 멀티사이클을 N − 1로 추가하면 홀드 검사가 시각 0의 런치 에지로 되돌아가 일반적인 홀드 조건이 복원됩니다. 이 설정은 홀드 검사를 없애는 것이 아닙니다.

멀티사이클 패스와 폴스 패스

멀티사이클 패스는 더 긴 예산이 주어질 뿐 타이밍 해석 대상으로 남습니다. set_false_path로 설정하는 폴스 패스는 해석에서 완전히 제외되며, 선택 조건이 상호 배타적인 두 멀티플렉서를 통과하는 경로처럼 구조적으로는 연결되어 있지만 의미 있는 천이를 결코 전달할 수 없는 경로를 위한 것입니다. 타이밍을 맞추기 어렵다는 이유만으로 경로를 폴스 패스로 선언하면 실제 버그가 숨겨지고, 진짜 멀티사이클 패스를 폴스 패스로 선언하면 여전히 필요한 검사가 사라집니다.

도전해 보기: 멀티사이클 패스(Multicycle Path) 관련 문제

주기 2.0 ns인 클럭으로 동작하는 회로에서 데이터의 도착 시각(클럭→출력 지연과 조합 회로 지연의 합)이 3.3 ns, 셋업 타임이 0.1 ns인 경로가 있습니다. 이 경로는 2사이클에 한 번만 캡처하면 되므로 셋업 멀티사이클 패스를 2로 설정했습니다. 셋업 슬랙은 얼마입니까?

  1. A−1.4 ns
  2. B+2.6 ns
  3. C+0.6 ns
정답과 해설 보기

정답: C. +0.6 ns

멀티사이클 패스를 2로 하면 캡처 에지가 1주기 후가 아니라 2주기 후가 됩니다. 요구 시각은 2 × 2.0 − 0.1 = 3.9 ns, 도착 시각은 3.3 ns이므로 슬랙은 +0.6 ns입니다. −1.4 ns는 일반적인 1사이클 그대로 계산한 값, +2.6 ns는 3사이클분의 시간을 준 값입니다. 멀티사이클 패스는 인에이블 신호 등으로 실제로 2사이클마다만 캡처하는 회로임을 설계자가 확인한 후에 설정해야 합니다.

셋업 멀티사이클 패스를 N(N ≥ 2)으로 설정했을 때, 홀드에 대해서도 보통 멀티사이클 패스를 N − 1로 설정합니다. 그 이유로 올바른 것은?

  2. B홀드의 확인 에지를 더 뒤로 밀어 홀드의 여유를 늘리기 위해
  3. C그 경로의 홀드 체크를 분석에서 제외하기 위해
정답과 해설 보기

정답: A. 홀드의 확인 에지도 셋업과 함께 뒤로 밀려 지나치게 엄격해지므로 원래 위치로 되돌리기 위해

STA의 기본 설정에서는 홀드를 셋업 캡처 에지의 하나 앞 에지에서 확인합니다. 셋업을 2사이클로 하면 홀드의 확인 에지도 시각 0에서 1주기 후로 옮겨 가므로, 주기가 2.0 ns라면 데이터가 2.0 ns 이상 늦게 도착하지 않으면 위반이 되어 버립니다. 홀드 멀티사이클 패스를 N − 1 = 1로 지정하면 확인 에지가 시각 0으로 돌아와 일반 경로와 같은 조건이 됩니다. 홀드 체크를 제외하는 것은 아닙니다.

자주 묻는 질문

셋업 멀티사이클 N과 함께 홀드 멀티사이클 N − 1을 설정하는 이유는?

셋업 캡처 에지를 옮기면 기본 홀드 검사도 뒤로 이동하여 홀드를 만족시키기가 거의 불가능해지기 때문입니다. 홀드를 N − 1로 설정하면 홀드 검사가 원래 에지로 돌아갑니다.

멀티사이클 패스와 폴스 패스의 차이는?

멀티사이클 패스는 여러 클록 주기가 주어질 뿐 여전히 해석됩니다. 폴스 패스는 전혀 해석되지 않으므로, 기능적으로 결코 전파될 수 없는 경로에만 사용해야 합니다.

멀티사이클 패스는 언제 설정해도 안전한가요?

인에이블 등을 통해 목적지가 N 사이클마다 데이터를 샘플링하는 것을 설계가 보장하고, 검증으로 그 동작이 확인된 경우에만 안전합니다. 그렇지 않으면 완화된 검사가 실제 타이밍 불량을 가릴 수 있습니다.
