프로파일러(profiler)란?

프로그램의 어느 함수나 부분이 실행 시간을 많이 쓰는지 측정하는 도구. 샘플링 방식과 계측(인스트루멘테이션) 방식이 있다.

일본어 명칭: プロファイラ

프로파일러(profiler)은(는) 성능 분석, GPU 프로그래밍 등 2개 분야의 연습 문제 8개에 나와요.

분야: 성능 분석

샘플링 방식과 계측 방식

샘플링 프로파일러는 타이머나 하드웨어 성능 카운터의 오버플로를 이용해 실행 중인 프로그램을 일정 간격으로 인터럽트하고, 현재 명령어 주소와 흔히 호출 스택을 초당 수천 번 정도 기록합니다. 시간을 많이 쓰는 함수일수록 더 자주 잡히므로, 샘플 수로 시간이 어디에 쓰이는지를 통계적으로 추정할 수 있으며, 오버헤드가 작고 프로그램을 수정할 필요도 없습니다. 반면 계측(인스트루멘테이션) 프로파일러는 함수의 진입과 종료 지점이나 기본 블록에 코드를 삽입하여 정확한 호출 횟수를 주지만, 특히 작고 자주 호출되는 함수에서 타이밍을 왜곡할 수 있는 오버헤드를 더합니다.

프로파일 읽는 법

프로파일러는 보통 함수 자체 코드에서 소비한 셀프 시간과, 호출하는 함수까지 포함한 포괄 시간을 보고합니다. 플랫 프로파일은 셀프 시간으로 함수 순위를 매기고, 콜 그래프나 플레임 그래프는 어떤 호출 경로가 비용으로 이어지는지 보여 줍니다. 전형적인 발견은 핫스팟입니다. 코드의 몇 퍼센트, 흔히 안쪽 루프 하나가 실행 시간의 대부분을 차지합니다. 많은 프로파일러는 캐시 미스나 분기 예측 실패 같은 하드웨어 성능 카운터도 읽는데, 이는 핫스팟이 어디에 있는지뿐 아니라 왜 느린지를 설명하는 데 도움이 됩니다.

프로파일링과 암달의 법칙

암달의 법칙에 따르면 실행 시간의 비율 f를 s배 빠르게 하면 전체 속도 향상은 1 / ((1 − f) + f/s)입니다. 시간의 1%를 차지하는 코드를 무한히 빠르게 해도 이득은 약 1%뿐이지만, 80%를 차지하는 코드를 2배 빠르게 하면 전체적으로 약 1.7배가 됩니다. 시간이 어디에 쓰이는지에 대한 직관은 자주 틀리므로, 믿을 만한 작업 흐름은 측정하고, 가장 큰 요인을 최적화하고, 같은 조건에서 다시 측정하여 개선을 확인하고 다른 곳이 퇴보하지 않았는지 점검하는 것입니다.

GPU 프로파일링, 그리고 이름에 관한 주의

GPU 프로그램에서는 먼저 타임라인 뷰로 전체 시간이 커널 실행, CPU-GPU 데이터 전송, CPU 측 작업으로 어떻게 나뉘는지, 그리고 전송이 계산과 겹치는지를 봅니다. 커널이 지배적일 때만 메모리 접근 패턴이나 점유율(occupancy)을 살펴볼 가치가 있으며, 점유율이 높다고 자동으로 빨라지는 것은 아닙니다. 반도체 계측에서 '프로파일러'는 전혀 다른 것을 뜻할 수 있습니다. 촉침식 프로파일러는 가는 촉침을 웨이퍼 위로 끌어 mm 단위 거리에 걸쳐 단차 높이, 식각 깊이, 평탄도를 측정하며, 분해능은 원자간력 현미경(AFM)보다 거칩니다.

프로그램 성능을 개선할 때 프로파일러를 사용하는 목적으로 올바른 것은?

  1. A프로그램의 문법 오류를 찾는다
  2. B프로그램 사용자 수를 센다
  3. C프로그램의 어느 함수나 부분이 실행 시간의 많은 부분을 사용하는지 조사한다
정답과 해설 보기

정답: C. 프로그램의 어느 함수나 부분이 실행 시간의 많은 부분을 사용하는지 조사한다

많은 프로그램에서 실행 시간의 대부분은 극히 일부 코드에서 소비됩니다. 그러나 어디가 느린지 사람이 추측하면 빗나가는 경우가 많습니다. 프로파일러는 함수별 실행 시간이나 호출 횟수, 나아가 행별·명령어별 시간을 측정하여 보여 줍니다. 암달의 법칙대로 시간을 많이 쓰는 부분을 개선하는 것이 효과적이므로, 먼저 측정하는 것이 성능 개선의 첫걸음입니다.

샘플링 방식 프로파일러의 특징으로 올바른 것은?

  1. A모든 함수의 진입과 종료를 한 번도 빠뜨리지 않고 기록한다
  2. B일정 간격으로 프로그램을 인터럽트하여 그때 실행 중이던 위치를 기록하고, 많이 기록된 위치를 시간을 쓰는 곳으로 간주한다
  3. C프로그램의 소스 코드를 읽기만 하고 실행은 하지 않는다
정답과 해설 보기

정답: B. 일정 간격으로 프로그램을 인터럽트하여 그때 실행 중이던 위치를 기록하고, 많이 기록된 위치를 시간을 쓰는 곳으로 간주한다

샘플링 방식에서는 타이머나 성능 카운터의 인터럽트로, 예를 들어 1초에 수천 번 실행 중인 명령어의 위치(와 호출 연쇄)를 기록합니다. 시간을 많이 쓰는 곳일수록 기록되는 횟수가 많아지므로 통계적으로 어디가 무거운지 알 수 있습니다. 프로그램을 고쳐 쓰지 않으므로 측정에 따른 지연이 작고 실제에 가까운 상태에서 측정할 수 있지만, 극히 짧은 처리의 정확한 횟수 등은 알 수 없습니다.

자주 묻는 질문

샘플링 프로파일러와 인스트루멘테이션 프로파일러 차이

샘플링 프로파일러는 프로그램이 실행 중인 위치를 주기적으로 기록하여 낮은 오버헤드로 시간을 통계적으로 추정합니다. 인스트루멘테이션 프로파일러는 함수나 블록에 측정 코드를 추가하여 정확한 횟수를 주지만, 프로그램을 느리게 하고 왜곡할 수 있습니다.

프로파일링에서 핫스팟이란?

핫스팟은 실행 시간의 큰 몫을 차지하는 작은 코드 영역으로, 흔히 루프 하나나 몇 개의 함수입니다. 핫스팟을 최적화하면 노력 대비 효과가 가장 큽니다.

프로파일러를 쓰면 프로그램이 느려지나요?

어느 정도는 그렇습니다. 샘플링 프로파일러는 보통 오버헤드가 작지만, 인스트루멘테이션은 특히 짧은 함수를 많이 감쌀 때 오버헤드가 클 수 있습니다.

해설 속 프로파일러(profiler)

  • 프로파일러는 함수별 실행 시간이나 호출 횟수, 나아가 행별·명령어별 시간을 측정하여 보여 줍니다.

    프로그램 성능을 개선할 때 프로파일러를 사용하는 목적으로 올바른 것은?

  • 성능은 프로파일러로 실제로 측정하여 판단하는 것이 확실합니다.

    GPU의 점유율에 대해 올바른 것은?

  • 따라서 먼저 프로파일러 등으로 시간을 많이 쓰는 부분을 찾아 거기서부터 개선하는 것이 기본입니다.

    암달의 법칙에서 얻을 수 있는 성능 개선 방법에 대한 교훈으로 가장 적절한 것은?

  • 프로파일러로 핫스팟을 찾아 거기에 알고리즘 개선이나 메모리 사용 방식의 개선을 집중하면 적은 노력으로 큰 효과를 얻을 수 있습니다.

    프로그램 성능 분석에서 말하는 핫스팟에 대한 설명으로 올바른 것은?

  • 먼저 프로파일러나 성능 카운터로 측정하여 시간을 많이 쓰는 곳과 그 원인(연산, 메모리, 분기, 입출력 등)을 파악합니다.

    프로그램 성능을 개선할 때의 진행 방식으로 가장 적절한 것은?
