재배치(Relocation)란?

코드와 데이터의 최종 주소가 정해진 뒤 명령이나 데이터 안의 임시 주소를 올바른 값으로 고쳐 쓰는 처리. 링커가 수행하며, 동적 링크에서는 일부를 실행 시 동적 링커가 수행한다.

일본어 명칭: 再配置

재배치(Relocation)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 8개에 나와요.

분야: 링커, 로더, 실행 파일

재배치가 필요한 이유

분할 컴파일에서는 각 소스 파일이 자신의 코드와 데이터가 최종적으로 메모리의 어디에 놓일지, 그리고 다른 파일에서 정의된 함수와 변수가 어디에 있을지 모른 채 번역됩니다. 따라서 컴파일러는 각 섹션이 주소 0에서 시작한다고 가정하고, 명령이나 데이터 워드에 알 수 없는 주소가 필요한 곳마다 자리 표시자를 쓰고 재배치 엔트리를 기록합니다. 링커는 모든 오브젝트 파일의 모든 섹션을 배치하고 최종 주소를 정한 뒤, 이 엔트리들을 순회하며 올바른 값을 기록합니다. 이 단계가 없다면 독립적으로 컴파일된 조각들을 하나의 프로그램으로 결합할 수 없습니다.

재배치 엔트리에 기록되는 정보

각 엔트리는 섹션 내 오프셋으로 표시한 패치할 위치, 주소가 필요한 심볼, 가산값(addend), 그리고 타입을 지정합니다. 타입은 링커에게 값을 계산하는 방법과 인코딩하는 방법을 알려 줍니다. 32비트 또는 64비트 절대 주소, 분기와 호출을 위한 PC 상대 거리, 또는 두 명령에 나뉘어 들어가는 값 등이 있습니다. 예를 들어 RISC-V는 lui와 addi, 또는 auipc와 jalr 같은 명령 쌍으로 주소를 만들므로, 상위 20비트와 하위 12비트를 서로 다른 재배치 타입으로 채웁니다.

정적 재배치와 동적 재배치

완전한 정적 링크에서는 링커가 모든 재배치를 해결하므로 실행 파일을 그대로 실행할 수 있습니다. 공유 라이브러리는 로드 주소가 실행 시까지 정해지지 않으므로 사정이 달라집니다. 위치 독립 코드는 전역 오프셋 테이블(GOT)이라는 주소 테이블을 통해 전역 데이터에 접근하고, 프로시저 링키지 테이블(PLT)의 작은 스텁을 통해 라이브러리 함수를 호출합니다. 동적 링커는 프로그램 로드 시, 또는 첫 호출 시 지연(lazy) 방식으로 GOT를 채웁니다. 무작위 주소에 로드되는 위치 독립 실행 파일(PIE)도 단순한 상대 재배치를 가지고 있으며, 로더가 실제 베이스 주소를 더해 이를 적용합니다.

재배치와 심볼 해결의 차이

두 단계는 혼동하기 쉽습니다. 심볼 해결은 참조된 각 이름을 정확히 하나의 정의와 대응시키며, 실패하면 undefined reference나 multiple definition 오류로 나타납니다. 재배치는 그다음에 이루어지며 순전히 비트를 패치하는 작업입니다. 모든 심볼의 주소가 정해지면 기록된 필드에 올바른 숫자를 써 넣습니다. 재배치에도 고유한 실패가 있습니다. 예를 들어 분기 대상이 도달 범위를 벗어나는 등 계산된 값이 명령 필드에 들어가지 않으면 GNU 링커는 relocation truncated to fit을 보고하며, 대개 다른 코드 모델이나 더 긴 명령 시퀀스가 필요합니다.

정답: A. 코드와 데이터의 최종 주소가 정해진 뒤, 명령이나 데이터 안의 주소를 올바른 값으로 고쳐 쓴다

컴파일러는 각 파일을 주소 0부터 시작하는 것으로 간주하여 만들고, 다른 파일의 함수나 자신의 변수 주소를 사용하는 위치를 재배치 정보로 기록합니다. 링커는 모든 파일을 나열하여 실제 주소를 정한 뒤, 기록된 위치마다 올바른 주소(또는 PC로부터의 거리)를 계산하여 명령에 씁니다. 동적 링크에서는 비슷한 고쳐 쓰기의 일부를 실행 시에 동적 링커가 수행합니다.

자주 묻는 질문

심볼 해결과 재배치의 차이

심볼 해결은 참조된 각 이름이 어느 정의를 가리키는지 결정합니다. 재배치는 그 후 해당 심볼의 최종 주소나 거리를 그것을 사용하는 명령과 데이터에 써 넣습니다.

링커 오류 relocation truncated to fit의 의미

링커가 계산한 주소나 오프셋이, 대상이 범위를 벗어난 분기처럼 들어가야 할 명령 필드에 비해 너무 크다는 뜻입니다. 코드 모델이나 메모리 레이아웃을 바꾸거나 더 긴 명령 시퀀스를 사용하면 대개 해결됩니다.

재배치는 실행 시에도 일어나나요?

일부는 그렇습니다. 대부분은 정적 링커가 수행하지만, 공유 라이브러리와 위치 독립 실행 파일에서는 동적 링커가 프로그램 로드 시나 라이브러리 함수의 첫 호출 시 나머지 재배치를 적용합니다.

    링커가 수행하는 재배치(relocation)의 설명으로 올바른 것은 무엇입니까?

  • 오브젝트 파일에는 그 파일의 함수를 번역한 기계어, 변수의 초기값, 정의하거나 참조하는 이름의 목록(심볼 테이블), 나중에 주소를 채울 위치의 목록(재배치 정보)이 들어 있습니다.

    컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?

  • 링커는 각 오브젝트 파일에서 참조되는 이름(심볼)을 어딘가에서 정의된 실체와 대응시키고(심볼 해석), 각 파일의 코드와 데이터를 배치하여 최종 주소를 정하며, 명령 안의 임시 주소를 올바른 값으로 고쳐 씁니다(재배치).

    링커의 주된 역할로 올바른 것은 무엇입니까?

  • 컴파일러는 count의 주소를 모른 채 참조하는 명령을 만들고 그 위치를 재배치 정보에 기록합니다.

    C 언어에서 'extern int count;'라고 썼을 때의 의미로 올바른 것은 무엇입니까?

  • 동적 링커는 필요한 공유 라이브러리를 찾아 읽어 들이고, 재배치와 심볼 결합을 수행한 뒤 프로그램의 입구로 제어를 옮깁니다.
