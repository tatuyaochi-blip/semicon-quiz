메모리 월(Memory Wall)란?

프로세서의 연산 성능 향상을 메모리의 대역폭과 지연 개선이 따라가지 못해 전체 성능이 제한되는 문제. HBM, 캐시 대용량화, 첨단 패키징 등으로 대응한다.

일본어 명칭: メモリウォール

메모리 월(Memory Wall)은(는) DRAM, 첨단 패키징(3D와 칩렛) 등 2개 분야의 연습 문제 2개에 나와요.

분야: DRAM

격차가 생기는 이유

프로세서 성능은 수십 년 동안 처음에는 클록 속도로, 나중에는 코어 수 증가와 더 넓은 벡터 유닛으로 빠르게 향상되었지만, DRAM은 주로 밀도와 비트당 비용에 최적화되었습니다. DRAM 액세스 지연 시간은 수십 ns에 머물러 있으므로, 수 GHz의 클록에서 메인 메모리로의 미스는 수백 사이클의 비용이 듭니다. 메모리 월이라는 말은 1990년대 중반에 널리 쓰이게 되었으며, 프로세서 코어가 아니라 점점 벌어지는 이 격차가 결국 시스템 성능을 제한할 것이라고 경고한 것입니다.

지연 시간의 벽과 대역폭의 벽

이 문제에는 두 가지 측면이 있습니다. 지연 시간은 연결 구조를 따라 포인터를 추적하는 것처럼 의존적인 액세스를 하는 코드에 피해를 줍니다. 각 로드가 끝나야 다음 주소를 알 수 있기 때문입니다. 대역폭은 연산당 많은 데이터를 다루는 스트리밍 코드에 피해를 줍니다. 루프라인(roofline) 모델은 대역폭 측면을 나타냅니다. 달성 가능한 성능은 피크 연산 성능과, 메모리 대역폭 × 산술 강도(이동한 바이트당 수행하는 연산 수) 중 낮은 쪽입니다. 산술 강도가 낮은 코드는 코어가 아무리 많아도 피크 연산 성능에 도달하지 못합니다.

AI 워크로드가 크게 타격을 받는 이유

대형 신경망은 수십억 개의 가중치를 가지며, 작은 배치 크기에서 토큰 하나를 생성하려면 사실상 모든 가중치를 한 번씩 읽으면서 각각에 대해 곱셈과 덧셈 하나만 수행합니다. 16비트 가중치라면 바이트당 약 1회의 연산인 반면, 최신 가속기는 메모리가 공급하는 바이트당 수백 회의 연산을 수행할 수 있습니다. 따라서 연산 유닛은 메모리를 기다리게 됩니다. 요청 배칭, 가중치를 더 적은 비트로 양자화, 데이터를 온칩에 유지하는 것은 모두 산술 강도를 높이거나 이동하는 바이트를 줄입니다.

설계자들의 대응 방법

다단계 캐시는 국부성을 활용하여 대부분의 액세스가 DRAM에 도달하지 않게 하고, 하드웨어 프리페처는 요청되기 전에 데이터를 가져옵니다. 비순차 실행 코어와 수천 개의 스레드를 가진 GPU는 많은 미스를 동시에 처리하여 지연 시간을 숨깁니다. 첨단 패키징으로 프로세서 옆에 배치한 고대역폭 메모리(HBM)와 다이 위에 적층한 대용량 캐시는 대역폭을 직접 높입니다. 프로세싱 인 메모리(PIM)와 니어 메모리 컴퓨팅은 반대 방향을 택하여, 데이터를 옮기는 대신 일부 연산을 데이터가 이미 있는 곳으로 옮깁니다.

정답과 해설 보기

정답: C. 메모리 월

프로세서의 연산 성능은 연평균 50% 이상으로 성장한 시기가 있었지만, DRAM의 액세스 지연은 수십 ns에서 거의 개선되지 않아 CPU가 수백 사이클이나 데이터를 기다리게 되었습니다. 이것이 메모리 월입니다. 대책으로 다단 캐시, 메모리 병렬 액세스, 프리페치, HBM과 같은 광대역 메모리, 연산을 메모리 가까이에서 수행하는 PIM(프로세싱 인 메모리) 등이 추진되고 있습니다.

프로세서의 연산 성능 향상에 비해 메모리에서 데이터를 공급하는 속도가 따라가지 못해 전체 성능을 제한해 버리는 문제를 무엇이라 하는가?

  1. A열의 벽
  2. B메모리 월(메모리의 벽)
  3. C무어의 법칙
정답과 해설 보기

정답: B. 메모리 월(메모리의 벽)

프로세서의 연산 성능은 빠르게 향상되어 왔지만 메모리와의 데이터 전송 속도(대역폭)의 증가는 그보다 완만하여, 연산기가 데이터를 기다리는 시간이 늘고 있습니다. 이를 메모리 월이라 합니다. 대규모 AI 모델은 계산할 때마다 방대한 가중치를 읽어 들이므로 특히 심각하며, HBM을 프로세서 가까이에 실장하는 첨단 패키지나 대용량 캐시의 적층이 대책이 되고 있습니다.

자주 묻는 질문

메모리 월은 지연 시간 문제인가요, 대역폭 문제인가요?

둘 다입니다. 지연 시간은 의존적인 메모리 액세스를 하는 프로그램을 제한하고, 대역폭은 수행하는 연산에 비해 많은 양의 데이터를 스트리밍하는 프로그램을 제한합니다.

HBM은 메모리 월 해결에 어떻게 도움이 되나요?

HBM은 DRAM 다이를 프로세서 옆에 적층하고 매우 넓은 인터페이스를 사용하여, 기존 DIMM보다 훨씬 높은 대역폭을 제공합니다. 주로 대역폭 측면을 공략하며, 지연 시간은 같은 수십 ns 범위에 머뭅니다.

대규모 언어 모델(LLM)이 메모리 바운드인 이유는?

작은 배치 크기로 생성할 때 각 가중치를 메모리에서 가져와 두어 번의 연산에만 사용하기 때문입니다. 가속기는 메모리가 가중치를 공급할 수 있는 것보다 훨씬 빠르게 연산할 수 있습니다.
