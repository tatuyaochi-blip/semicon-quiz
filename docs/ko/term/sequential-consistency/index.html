순차 일관성(sequential consistency)란?

모든 코어의 동작이 하나의 순서로 나열되고 각 코어의 동작은 프로그램 순서대로 보인다는, 가장 직관적인 메모리 일관성 모델.

일본어 명칭: 逐次一貫性

순차 일관성(sequential consistency)은(는) 멀티코어와 동기화 등 1개 분야의 연습 문제 3개에 나와요.

분야: 멀티코어와 동기화

순차 일관성이 보장하는 것

1979년 Leslie Lamport가 정의한 순차 일관성은, 어떤 실행 결과든 모든 코어의 메모리 연산을 하나의 전역 시퀀스로 교차 배치하고 각 코어의 연산이 그 시퀀스 안에서 프로그램 순서대로 나타나는 경우와 같아야 한다고 요구합니다. 여러 벌의 카드를 각 벌의 순서는 바꾸지 않고 섞는 것처럼, 교차 배치는 어떤 형태든 될 수 있지만 모든 코어가 같은 순서를 봅니다. 프로그래머는 스레드들이 번갈아 실행된다고 상상하며 동시성 코드의 동작을 따져 볼 수 있으므로, 가장 직관적인 메모리 일관성 모델로 여겨집니다.

실제 CPU가 이를 완화하는 이유

모든 메모리 접근에 걸쳐 프로그램 순서를 엄격하게 지키면 많은 하드웨어 최적화를 쓸 수 없습니다. 스토어 버퍼는 쓰기가 캐시에 도달하기를 기다리지 않고 코어가 계속 실행하게 해 주고, 비순차 실행은 나중의 로드가 앞선 저장보다 먼저 완료되게 합니다. 둘 다 순차 일관성을 깨뜨립니다. 따라서 대부분의 프로세서는 더 약한 모델을 구현합니다. x86은 다른 주소에 대한 앞선 저장을 나중의 로드가 앞지를 수 있는 TSO(total store order)를 사용하고, Arm과 RISC-V는 프로그램이 펜스를 넣지 않는 한 더 많은 순서 변경을 허용하는 더 약한 모델을 사용합니다.

스토어 버퍼 리트머스 테스트

x와 y가 처음에 0일 때, 코어 0은 x = 1 다음에 r1 = y를, 코어 1은 y = 1 다음에 r2 = x를 실행한다고 합시다. 순차 일관성에서는 두 쓰기 중 하나가 전역 순서에서 먼저 와야 하므로 적어도 한 읽기는 1을 보며, r1 = r2 = 0은 불가능합니다. x86에서는 각 쓰기가 자기 코어의 스토어 버퍼에 머무는 동안 뒤따르는 읽기가 캐시에서 이전 값을 가져올 수 있으므로 두 읽기 모두 0을 반환할 수 있습니다. 각 코어에서 쓰기와 읽기 사이에 완전한 메모리 배리어를 두면 순차 일관적인 결과가 회복됩니다.

순차 일관성과 캐시 코히런스

캐시 코히런스는 단일 메모리 위치에 관한 것으로, 모든 코어가 그 주소에 대한 쓰기 순서에 합의하고 결국 최신 값을 보게 합니다. 순차 일관성 같은 메모리 일관성 모델은 서로 다른 주소에 대한 접근 순서를 다루며, 이는 코히런스만으로는 제약되지 않습니다. 언어가 그 간극을 메웁니다. C11과 C++11의 atomic은 기본값이 memory_order_seq_cst이며, 데이터 레이스가 없는 프로그램은 순차 일관적인 것처럼 동작합니다. acquire/release나 relaxed 같은 더 약한 오더를 사용하면, 완전한 순서가 필요 없을 때 컴파일러가 배리어를 더 적게 생성할 수 있습니다.

정답: B. 모든 코어의 연산이 하나의 순서로 나열되고, 각 코어의 연산은 프로그램에 쓴 순서대로 나타나는 것처럼 보인다

순차 일관성에서는 여러 코어의 연산이 카드를 섞듯이 한 줄로 나열되고, 각 코어의 연산은 그 안에서 프로그램 순서를 유지하는 것처럼 보입니다. 프로그래머에게 가장 이해하기 쉬운 모델이지만, 하드웨어가 스토어 버퍼 등으로 순서를 바꾸는 최적화를 크게 제한하므로, 실제 많은 CPU는 더 느슨한 모델을 채택하고 있습니다.

자주 묻는 질문

x86은 순차 일관성을 보장하나요?

아닙니다. x86은 TSO(total store order)를 구현하며, 다른 주소에 대한 앞선 저장이 다른 코어에 보이기 전에 로드가 완료될 수 있으므로 스토어 버퍼 리트머스 테스트의 r1 = r2 = 0이라는 결과가 나올 수 있습니다. MFENCE 같은 펜스나 lock 접두 명령으로 이를 막을 수 있습니다.

순차 일관성과 캐시 코히런스의 차이는 무엇인가요?

코히런스는 개별 주소마다 합의된 하나의 쓰기 순서를 보장합니다. 순차 일관성은 더 강한 조건으로, 모든 주소에 대한 연산의 상대 순서를 모든 코어의 프로그램 순서를 지키는 하나의 전역 교차 배열로 다룹니다.

C++의 memory_order_seq_cst는 무슨 뜻인가요?

std::atomic 연산의 기본 메모리 오더로, 모든 seq_cst 연산이 각 스레드의 프로그램 순서와 일치하는 하나의 전체 순서로 나타나게 합니다. 가장 추론하기 쉽지만 가장 비싼 배리어 명령이 필요할 수 있습니다.
