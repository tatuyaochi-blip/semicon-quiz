동적 링크(Dynamic Linking)란?

실행 시에 공유 라이브러리를 읽어 들여 연결하는 방식. 라이브러리를 프로세스 간에 공유할 수 있고 교체로 수정이 반영되지만 실행 환경에 맞는 라이브러리가 필요하다.

일본어 명칭: 動的リンク

동적 링크(Dynamic Linking)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 12개에 나와요.

분야: 링커, 로더, 실행 파일

프로그램 시작 시 일어나는 일

동적 링크된 실행 파일에는 라이브러리 코드가 들어 있지 않습니다. 실행 파일은 필요한 공유 라이브러리와 그 라이브러리에서 사용하는 심볼을 기록하며, Linux에서는 프로그램 인터프리터인 동적 링커를 지정합니다. 프로그램이 시작되면 커널이 실행 파일과 동적 링커를 매핑하고, 동적 링커는 검색 경로를 따라 각 라이브러리를 찾아 메모리에 매핑하고, 심볼 참조를 해석하고, 남은 재배치를 적용하고, 라이브러리 초기화 루틴을 실행한 다음 프로그램의 엔트리 포인트로 점프합니다. Windows는 각 실행 파일의 임포트 테이블을 사용해 DLL에 대해 같은 일을 합니다.

위치 독립 코드, GOT와 PLT

라이브러리 코드의 물리적 사본 하나가 여러 프로세스에 쓰이려면, 라이브러리가 프로세스마다 다른 주소에 로드되더라도 코드 페이지는 절대 수정되어서는 안 됩니다. 그래서 공유 라이브러리는 위치 독립 코드(PIC)로 컴파일되며, 달라지는 주소는 데이터 테이블인 전역 오프셋 테이블(GOT)에 들어갑니다. 외부 함수 호출은 GOT를 거쳐 점프하는 작은 프로시저 링키지 테이블(PLT) 스텁을 통합니다. 지연 바인딩(lazy binding)에서는 첫 호출 때 GOT 엔트리가 채워지며, 시작 시점에 모두 해석한 뒤 GOT를 읽기 전용으로 만드는 것이 일반적인 보안 강화 선택지입니다.

동적 링크와 정적 링크

정적 링크는 빌드 시점에 필요한 오브젝트 코드를 실행 파일에 복사합니다. 결과물은 자체 완결적이고 런타임 심볼 탐색이 없지만, 크기가 크고 라이브러리 수정 사항을 반영하려면 다시 빌드해야 합니다. 동적 링크는 라이브러리 페이지를 프로세스 간에 공유하고 디스크 공간을 절약하며, 파일 하나만 교체해도 보안 수정이 모든 프로그램에 적용됩니다. 비용은 시작 시의 작업과 대상 시스템에 대한 의존성입니다. 라이브러리가 없거나 호환되지 않으면 프로그램이 실행되지 않으며, 그래서 라이브러리에는 버전 이름과 버전이 붙은 심볼이 있습니다.

필요할 때 라이브러리 로드하기

시작 시 정해진 라이브러리 외에도, 실행 중인 프로그램은 POSIX 시스템에서는 dlopen, Windows에서는 LoadLibrary로 라이브러리를 명시적으로 로드한 뒤 dlsym이나 GetProcAddress로 이름을 통해 함수를 찾을 수 있습니다. 플러그인 아키텍처와 선택적 기능이 이렇게 동작합니다. 심볼 바인딩이 런타임에 일어나므로, 미리 로드한 라이브러리가 함수의 자체 버전을 끼워 넣을 수도 있으며, 프로파일러와 메모리 디버거가 이 메커니즘을 사용합니다. ldd 같은 도구는 실행 파일이 로드할 공유 라이브러리와 그 위치를 보여 줍니다.

동적 링크에서는 실행 파일에 '어느 공유 라이브러리의 어느 함수를 사용하는지'만 기록해 두고, 실행 시에 동적 링커가 라이브러리를 읽어 들여 연결합니다. 공유 라이브러리의 코드는 바뀌지 않으므로 물리 메모리 상의 하나의 사본을 많은 프로세스가 공유할 수 있습니다. 버그나 취약점 수정도 라이브러리를 교체하기만 하면 됩니다. 다만 기동 시에 결합 작업이 필요합니다.

  2. B동적 링크 프로그램은 만든 컴퓨터에서만 동작하는 규칙이기 때문에
  3. C필요한 공유 라이브러리가 설치되어 있지 않거나, 호환되지 않는 버전만 있기 때문에
정답과 해설 보기

정답: C. 필요한 공유 라이브러리가 설치되어 있지 않거나, 호환되지 않는 버전만 있기 때문에

동적 링크 프로그램은 실행하는 컴퓨터에 있는 공유 라이브러리를 사용합니다. 필요한 라이브러리가 없거나 함수가 부족한 오래된 버전밖에 없으면 동적 링커가 결합하지 못하고 기동에 실패합니다. Linux에서는 ldd 명령으로 프로그램이 필요로 하는 공유 라이브러리와 그것이 발견되는지를 확인할 수 있습니다. 배포하기 쉽도록 일부러 정적 링크로 하기도 합니다.

자주 묻는 질문

정적 링크와 동적 링크의 차이는 무엇인가요?

정적 링크는 빌드 시점에 라이브러리 코드를 실행 파일에 복사하므로 외부 라이브러리 없이 실행됩니다. 동적 링크는 동적 링커가 런타임에 해석하는 참조를 남겨 두므로, 프로세스들이 라이브러리 사본 하나를 공유하고 그것을 교체해 수정 사항을 받을 수 있습니다.

PLT와 GOT는 무엇인가요?

전역 오프셋 테이블(GOT)은 외부 함수와 변수의 런타임 주소를 담는 쓰기 가능한 데이터 테이블입니다. 프로시저 링키지 테이블(PLT)에는 코드가 호출하는 작은 스텁이 들어 있으며, 이 스텁이 GOT를 거쳐 실제 라이브러리 함수로 점프합니다.

error while loading shared libraries: cannot open shared object file 오류는 무슨 뜻인가요?

동적 링커가 프로그램이 의존하는 라이브러리를 검색 경로에서 찾지 못했다는 뜻입니다. 라이브러리를 설치하거나, 예를 들어 시스템 링커 설정이나 rpath를 통해 그 위치를 검색 경로에 추가하면 해결됩니다.
