동적 링크(Dynamic Linking)란?

실행 시에 공유 라이브러리를 읽어 들여 연결하는 방식. 라이브러리를 프로세스 간에 공유할 수 있고 교체로 수정이 반영되지만 실행 환경에 맞는 라이브러리가 필요하다.

일본어 명칭: 動的リンク

동적 링크(Dynamic Linking)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 12개에 나와요.

분야: 링커, 로더, 실행 파일

도전해 보기: 동적 링크(Dynamic Linking) 관련 문제

동적 링크(공유 라이브러리)의 이점으로 올바른 것은 무엇입니까?

  1. A실행 환경에 라이브러리가 없어도 반드시 동작한다
  2. B여러 프로그램이 하나의 라이브러리를 메모리에서 공유할 수 있고, 라이브러리를 갱신하면 다시 만들지 않아도 수정이 반영된다
  3. C기동 시 처리가 전혀 필요 없어져 정적 링크보다 반드시 빠르게 기동한다
정답과 해설 보기

정답: B. 여러 프로그램이 하나의 라이브러리를 메모리에서 공유할 수 있고, 라이브러리를 갱신하면 다시 만들지 않아도 수정이 반영된다

동적 링크에서는 실행 파일에 '어느 공유 라이브러리의 어느 함수를 사용하는지'만 기록해 두고, 실행 시에 동적 링커가 라이브러리를 읽어 들여 연결합니다. 공유 라이브러리의 코드는 바뀌지 않으므로 물리 메모리 상의 하나의 사본을 많은 프로세스가 공유할 수 있습니다. 버그나 취약점 수정도 라이브러리를 교체하기만 하면 됩니다. 다만 기동 시에 결합 작업이 필요합니다.

동적 링크를 사용한 프로그램을 다른 컴퓨터에 복사하여 실행했더니 기동하지 않았습니다. 가장 가능성이 높은 원인은 무엇입니까?

  1. A실행 파일 안에 라이브러리 코드가 모두 들어 있어 너무 컸기 때문에
  2. B동적 링크 프로그램은 만든 컴퓨터에서만 동작하는 규칙이기 때문에
  3. C필요한 공유 라이브러리가 설치되어 있지 않거나, 호환되지 않는 버전만 있기 때문에
정답과 해설 보기

정답: C. 필요한 공유 라이브러리가 설치되어 있지 않거나, 호환되지 않는 버전만 있기 때문에

동적 링크 프로그램은 실행하는 컴퓨터에 있는 공유 라이브러리를 사용합니다. 필요한 라이브러리가 없거나 함수가 부족한 오래된 버전밖에 없으면 동적 링커가 결합하지 못하고 기동에 실패합니다. Linux에서는 ldd 명령으로 프로그램이 필요로 하는 공유 라이브러리와 그것이 발견되는지를 확인할 수 있습니다. 배포하기 쉽도록 일부러 정적 링크로 하기도 합니다.

  1. 동적 링크(공유 라이브러리)의 이점으로 올바른 것은 무엇입니까?
  2. 동적 링크를 사용한 프로그램을 다른 컴퓨터에 복사하여 실행했더니 기동하지 않았습니다. 가장 가능성이 높은 원인은 무엇입니까?
  3. 동적 링크에서 PLT(Procedure Linkage Table)를 사용한 지연 바인딩(lazy binding)을 수행하는 경우의 설명으로 올바른 것은 무엇입니까?
  4. Linux에서 동적 링크 프로그램을 기동할 때 동작하는 동적 링커(ld.so 등)의 역할로 올바른 것은 무엇입니까?
  5. 링커가 수행하는 재배치(relocation)의 설명으로 올바른 것은 무엇입니까?
  6. 프로그램을 기동할 때(Linux의 execve 등) OS 로더가 수행하는 일로 올바른 것은 무엇입니까?
  7. 실행 파일에 strip 명령을 사용했을 때 일어나는 일로 올바른 것은 무엇입니까?
  8. Linux의 dlopen 함수(Windows의 LoadLibrary에 해당)의 용도로 가장 적절한 것은 무엇입니까?

  10. Linux 공유 라이브러리에서 libfoo.so.1의 '.1'과 같은 soname 버전 번호를 올리는 것은 일반적으로 어떤 경우입니까?
  11. Linux에서 ldd 명령을 실행 파일에 사용하면 알 수 있는 것은 무엇입니까?
