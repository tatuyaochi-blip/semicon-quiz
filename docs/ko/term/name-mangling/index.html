네임 맹글링(Name Mangling)란?

C++ 컴파일러가 함수 이름에 인수 타입이나 네임스페이스 정보를 삽입하여 심볼 이름을 만드는 것. 오버로드된 함수를 링커가 구별할 수 있다.

일본어 명칭: 名前修飾

네임 맹글링(Name Mangling)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 2개에 나와요.

분야: 링커, 로더, 실행 파일

인코딩되는 정보

맹글링된 이름은 소스 수준에서 이름이 같은 C++ 개체들을 구별하는 모든 정보를 하나의 링커 심볼에 담습니다. 감싸고 있는 네임스페이스와 클래스, 함수 이름, 매개변수 타입, 멤버 함수의 const 또는 volatile 한정자, 템플릿 인수입니다. 오버로드는 반환 타입만으로 구별될 수 없으므로 반환 타입은 보통 생략되지만, 함수 템플릿 인스턴스는 반환 타입도 포함합니다. Linux를 비롯한 많은 플랫폼에서 GCC와 Clang이 사용하는 Itanium C++ ABI에서는 print(int)가 _Z5printi가 되고 ns::f(double)가 _ZN2ns1fEd가 되는데, 각 이름 앞에 길이가 붙고 내장 타입은 한 글자로 인코딩됩니다.

extern "C"와 언어 혼용

C에는 오버로딩이 없으므로 C 컴파일러는 함수 이름을 그대로 내보냅니다. C++ 코드가 C 라이브러리를 호출할 때는 C++ 컴파일러가 맹글링되지 않은 이름을 찾도록 선언을 extern "C"로 감싸야 합니다. 그렇지 않으면 _Z3fooi 같은 이름을 찾다가 foo만 발견하여 undefined reference로 링크가 실패합니다. 두 언어가 공유하는 헤더는 보통 __cplusplus 매크로 검사로 보호한 extern "C"로 선언을 감쌉니다. extern "C"로 선언한 함수는 오버로드할 수 없는데, 두 함수가 같은 심볼로 대응되기 때문입니다.

맹글링된 이름 읽기

맹글링된 이름은 nm 출력, 디스어셈블리, 크래시 보고서, 링커 오류에 나타납니다. c++filt 도구는 이를 읽을 수 있는 선언으로 되돌리고, nm -C는 목록에서 같은 일을 하며, 대부분의 디버거와 링커는 진단을 출력할 때 자동으로 디맹글링합니다. 그래도 원래 형태를 읽을 줄 알면 도움이 됩니다. 디맹글링하면 똑같아 보이는 두 심볼이 const 한정자나 매개변수 타입에서 다를 수 있으며, 이는 헤더의 선언이 실제로 컴파일된 정의와 일치하지 않는다는 것을 드러냅니다.

맹글링은 ABI의 일부

컴파일러 계열마다 자체 방식을 정의하며, Microsoft 컴파일러는 Itanium ABI와 완전히 다른 인코딩을 사용합니다. 이 방식은 ABI(application binary interface)의 일부이므로, 방식이 다른 컴파일러의 오브젝트 파일은 소스가 같더라도 직접 링크할 수 없습니다. 매개변수 타입 변경처럼 라이브러리의 C++ 인터페이스를 바꾸면 맹글링된 이름이 바뀌어, 이전 버전으로 빌드된 프로그램과의 바이너리 호환성이 깨집니다. Rust처럼 오버로딩이나 모듈이 있는 다른 언어도 같은 이유로 이름을 맹글링합니다.

  2. B함수 이름을 짧게 하여 실행 파일을 작게 하기 위해
  3. C같은 이름이면서 인수 타입이 다른 함수(오버로드)나 네임스페이스를 링커가 구별할 수 있게 하기 위해
정답과 해설 보기

정답: C. 같은 이름이면서 인수 타입이 다른 함수(오버로드)나 네임스페이스를 링커가 구별할 수 있게 하기 위해

링커는 심볼을 이름 문자열만으로 대조합니다. C++에서는 'print(int)'와 'print(double)'처럼 같은 이름의 함수를 만들 수 있으므로 그대로는 구별할 수 없습니다. 그래서 컴파일러는 '_Z5printi'처럼 인수 타입 등을 이름에 넣습니다. C 언어 함수는 맹글링되지 않으므로, C++에서 C 함수를 호출할 때는 'extern "C"'를 붙여 맹글링을 하지 않게 합니다.

자주 묻는 질문

C++ 심볼 이름은 어떻게 디맹글링하나요?

c++filt에 파이프로 넘깁니다. 예를 들어 echo _Z5printi | c++filt는 print(int)를 출력합니다. nm -C와 objdump -C는 심볼을 나열하면서 디맹글링합니다.

C++에서 extern "C"는 무슨 역할을 하나요?

선언된 함수에 C 링키지를 부여하여, 컴파일러가 맹글링되지 않은 이름을 그대로 쓰게 합니다. 이를 통해 C++ 코드가 C 라이브러리를 호출할 수 있고, C 코드가 이렇게 내보낸 C++ 함수를 호출할 수 있습니다.

반환 타입이 맹글링된 함수 이름에 포함되지 않는 이유는 무엇인가요?

C++ 오버로드는 매개변수가 달라야 하므로 매개변수만으로 함수를 식별할 수 있기 때문입니다. 함수 템플릿 인스턴스는 예외로, 반환 타입도 인코딩합니다.
