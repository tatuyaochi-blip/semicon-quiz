벡터화(vectorization)란?

루프 안에서 요소마다 하는 같은 계산을 SIMD 명령을 사용해 여러 요소를 한꺼번에 처리하는 형태로 바꾸는 최적화. 반복 간에 데이터 의존이 없어야 한다.

일본어 명칭: ベクトル化

벡터화(vectorization)은(는) 컴파일러, 메모리 계층 구조 등 2개 분야의 연습 문제 4개에 나와요.

분야: 컴파일러

루프가 SIMD 코드로 바뀌는 과정

SIMD(single instruction, multiple data) 명령어는 하나의 넓은 레지스터에 담긴 여러 값에 대해 동작합니다. 128비트 레지스터에는 32비트 숫자 4개가 들어가므로 SIMD 덧셈 하나가 스칼라 덧셈 4개를 대신하며, 256비트나 512비트 유닛은 8개나 16개를 처리합니다. 벡터화 컴파일러는 새 루프의 각 반복이 레지스터 하나 분량의 요소를 처리하도록 루프를 다시 씁니다. 반복 횟수를 컴파일 시점에 알 수 없거나 벡터 폭의 배수가 아니면, 남은 요소를 위해 스칼라 나머지 루프를 추가하거나 마스크 연산을 사용합니다.

벡터화를 막는 요인

핵심 요건은 반복들이 서로 독립적이어야 한다는 것입니다. a[i] = a[i-1] + b[i] 같은 루프는 각 요소가 이전 결과를 필요로 하는 루프 간 의존성(loop-carried dependence)이 있어 여러 요소를 한꺼번에 계산할 수 없습니다. 에일리어싱 가능성도 장애물입니다. 두 포인터가 겹치는 메모리를 가리킬 수 있다면 컴파일러는 실행 시 겹침 검사를 추가하거나 벡터화를 포기해야 하며, C의 restrict 한정자는 겹치지 않음을 약속합니다. 연속적이지 않거나 간접적인 접근, 컴파일러가 인라인할 수 없는 함수 호출, 복잡한 제어 흐름도 벡터화를 줄이거나 막습니다.

리덕션과 부동소수점 연산 순서

배열을 하나의 변수로 합산하는 것 자체가 의존성이지만, 컴파일러는 벡터 레인에 여러 개의 부분합을 유지하다가 마지막에 합치는 방식으로 이를 벡터화합니다. 정수에서는 결과가 동일합니다. 부동소수점에서는 덧셈마다 반올림이 일어나 (a + b) + c가 a + (b + c)와 약간 다를 수 있으므로 동일함이 보장되지 않습니다. 그래서 엄격한 설정에서는 컴파일러가 원래 순서를 유지하며 이러한 리덕션을 벡터화하지 않을 수 있고, fast-math 같은 옵션은 미세한 수치 차이를 감수하는 대신 재결합을 허용합니다.

데이터 배치: AoS와 SoA

벡터화된 코드가 빠른지는 메모리 배치에 따라 결정되는 경우가 많습니다. 구조체 배열(AoS)에서는 각 레코드가 x, y, z, 질량을 함께 저장하므로, x만 읽는 루프는 가져온 64바이트 캐시 라인의 4분의 1만 사용합니다. 배열 구조체(SoA)에서는 모든 x 값이 연속해 있어 가져온 라인이 모두 사용되고, 메모리 트래픽이 약 4분의 1로 줄며, 한 번의 벡터 로드로 gather 명령어 없이 연속된 x 값을 가져올 수 있습니다. 배치를 바꿔도 수치 결과는 달라지지 않습니다.

정답과 해설 보기

정답: B. 여러 데이터를 동시에 다루는 SIMD 명령

자동 벡터화는 배열의 요소마다 같은 계산을 하는 루프를 찾아 여러 요소를 한꺼번에 처리하는 SIMD 명령으로 대체하는 최적화입니다. 예를 들어 128비트 SIMD 레지스터라면 32비트 수를 4개 동시에 더할 수 있으므로, 잘 되면 루프의 연산 횟수가 4분의 1이 됩니다. 반복 사이에 의존이 없을 것, 데이터의 배열이 연속일 것 등이 조건이 되며, 포인터가 겹칠 가능성이 있으면 보류되기도 합니다. 인터럽트나 캐시 조작 명령과는 관계가 없습니다.

자주 묻는 질문

벡터화와 멀티스레딩의 차이는 무엇인가요?

벡터화는 명령어 하나로 여러 데이터 요소를 처리하는 SIMD 명령어를 사용해 단일 스레드를 빠르게 합니다. 멀티스레딩은 서로 다른 코어에서 별도의 명령어 흐름을 실행하며, 둘은 일상적으로 함께 사용됩니다.

컴파일러가 루프를 벡터화하지 않는 이유는 무엇인가요?

흔한 이유로는 반복 간 의존성, 포인터 에일리어싱 가능성, 연속적이지 않은 메모리 접근, 인라인할 수 없는 함수 호출, 엄격한 설정에서 덧셈 순서를 바꿔야 하는 부동소수점 리덕션 등이 있습니다. 대부분의 컴파일러는 판단 근거를 설명하는 벡터화 리포트를 출력할 수 있습니다.

벡터화하면 부동소수점 결과가 달라질 수 있나요?

요소별 연산은 같은 결과를 내지만, 벡터화된 리덕션은 다른 순서로 숫자를 더하며, 부동소수점 덧셈은 결합 법칙이 성립하지 않으므로 최종 합계의 마지막 비트가 달라질 수 있습니다.
