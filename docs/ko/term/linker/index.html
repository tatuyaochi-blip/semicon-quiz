링커(linker)란?

여러 오브젝트 파일과 라이브러리를 결합하고 심볼 해결과 재배치를 수행해 실행 파일이나 공유 라이브러리를 만드는 소프트웨어.

일본어 명칭: リンカ

링커(linker)은(는) 링커, 로더, 실행 파일, ISA와 어셈블리, 컴파일러 등 3개 분야의 연습 문제 17개에 나와요.

분야: 링커, 로더, 실행 파일

도전해 보기: 링커(linker) 관련 문제

링커의 주된 역할로 올바른 것은 무엇입니까?

  1. A여러 오브젝트 파일이나 라이브러리를 결합하고, 이름을 주소에 연결하여 실행 파일을 만든다
  2. B소스 코드의 문법 오류를 찾아 알린다
  3. C실행 중인 프로그램의 메모리를 다 쓰고 나면 자동으로 해제한다
정답과 해설 보기

정답: A. 여러 오브젝트 파일이나 라이브러리를 결합하고, 이름을 주소에 연결하여 실행 파일을 만든다

링커는 각 오브젝트 파일에서 참조되는 이름(심볼)을 어딘가에서 정의된 실체와 대응시키고(심볼 해석), 각 파일의 코드와 데이터를 배열하여 최종 주소를 정하며, 명령 안의 임시 주소를 올바른 값으로 고쳐 씁니다(재배치). 필요하면 라이브러리에서 함수를 꺼내 추가합니다. 이렇게 해서 OS가 읽어 들여 실행할 수 있는 실행 파일이 완성됩니다.

링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?

  1. A어떤 파일에서 사용되는 함수나 변수의 이름을 다른 파일에 있는 그 정의와 대응시킨다
  2. B소스 코드의 변수 이름을 짧은 이름으로 바꾸어 읽기 어렵게 한다
  3. C수학 기호를 포함한 식을 수치로 다시 계산한다
정답과 해설 보기

정답: A. 어떤 파일에서 사용되는 함수나 변수의 이름을 다른 파일에 있는 그 정의와 대응시킨다

main.c에서 sum 함수를 호출하고 sum.c에서 그 내용을 정의하면, main.o에는 'sum을 참조한다', sum.o에는 'sum을 정의한다'라는 정보가 들어갑니다. 링커는 모든 오브젝트 파일의 심볼 테이블을 모아 참조마다 대응하는 정의를 하나 찾습니다. 정의를 찾지 못하면 '정의되지 않은 참조', 둘 이상이면 '다중 정의' 오류가 됩니다.

해설 속 링커(linker)

  • 링커는 각 오브젝트 파일에서 참조되는 이름(심볼)을 어딘가에서 정의된 실체와 대응시키고(심볼 해석), 각 파일의 코드와 데이터를 배열하여 최종 주소를 정하며, 명령 안의 임시 주소를 올바른 값으로 고쳐 씁니다(재배치).

    링커의 주된 역할로 올바른 것은 무엇입니까?

  • 링커는 모든 오브젝트 파일의 심볼 테이블을 모아 참조마다 대응하는 정의를 하나 찾습니다.

    링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?

  • 링커는 모든 파일을 나열하여 실제 주소를 정한 뒤, 기록된 위치마다 올바른 주소(또는 PC로부터의 거리)를 계산하여 명령에 씁니다.

    링커가 수행하는 재배치(relocation)의 설명으로 올바른 것은 무엇입니까?

  • 링커는 아직 정의를 찾지 못한 심볼을 정의하고 있는 오브젝트 파일만 아카이브에서 꺼내 포함시킵니다.

    정적 라이브러리(.a 파일)와 함께 링크할 때 링커가 실행 파일에 포함시키는 것으로 올바른 것은 무엇입니까?

  • GNU 링커는 명령줄에 쓰인 순서대로 파일을 처리하며, 정적 라이브러리를 만난 시점에 '아직 정의를 찾지 못한 참조'를 해결하는 오브젝트만 꺼냅니다.

    GNU 링커에서 'gcc -lmylib main.o'처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보…

링커(linker)이(가) 나오는 문제 (17)

  1. 링커의 주된 역할로 올바른 것은 무엇입니까?
  2. 링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?
  3. 링커가 수행하는 재배치(relocation)의 설명으로 올바른 것은 무엇입니까?
  4. 정적 라이브러리(.a 파일)와 함께 링크할 때 링커가 실행 파일에 포함시키는 것으로 올바른 것은 무엇입니까?
  5. GNU 링커에서 'gcc -lmylib main.o'처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 앞에 쓰면 정의되지 않은 참조 오류가 나는 경우가 있습니다. 그 이유로 올바른 것은 무엇입니까?
  6. 링커에서 약한 심볼(weak symbol)의 취급으로 올바른 것은 무엇입니까?
  7. RISC-V에서 상수 0x12345FFF를 lui와 addi의 2개 명령어로 만들 때 올바른 조합은?
  8. C 언어 프로그램에서 실행 파일이 만들어지기까지의 일반적인 흐름으로 올바른 것은 무엇인가?
  9. 컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?
  10. a.c와 b.c 양쪽에서 static을 붙이지 않은 같은 이름의 전역 함수 void init(void)를 정의하고 링크했습니다. 일어나는 일로 올바른 것은 무엇입니까?
  11. C 언어에서 'extern int count;'라고 썼을 때의 의미로 올바른 것은 무엇입니까?
  12. 정적 링크의 설명으로 올바른 것은 무엇입니까?
  13. C 언어 프로그램에서 OS가 처음 실행을 시작하는 주소(엔트리 포인트)에 대해 올바른 것은 무엇입니까?
  14. C++ 컴파일러가 함수 이름에 인수 타입 등의 정보를 덧붙여 심볼 이름을 만드는 '네임 맹글링(name mangling)'의 주된 목적은 무엇입니까?
  15. 오브젝트 파일을 역어셈블했더니 외부 함수 printf를 호출하는 명령의 점프 대상이 0 같은 임시 값이었습니다. 이 값은 언제 올바르게 채워집니까?
