메모리 맵 I/O(Memory-mapped I/O)란?

주변 장치의 레지스터를 메모리와 같은 주소 공간의 특정 주소에 할당하여 일반 읽기·쓰기 명령으로 조작하는 방식. 해당 영역은 캐시하지 않도록 설정한다.

일본어 명칭: メモリマップドI/O

메모리 맵 I/O(Memory-mapped I/O)은(는) OS와 하드웨어, CPU와 아키텍처 등 2개 분야의 연습 문제 2개에 나와요.

분야: OS와 하드웨어

동작 방식

프로세서의 주소 디코더는 특정 주소 범위를 RAM이 아닌 주변 장치로 보냅니다. 타이머의 제어 레지스터, UART의 데이터 레지스터, GPIO 포트가 각각 고정된 주소에 나타나며, 일반적인 load/store 명령이 해당 장치에 대한 읽기 및 쓰기 트랜잭션이 됩니다. 메모리와 달리 이러한 접근에는 부작용이 있을 수 있습니다. 상태나 데이터 레지스터를 읽으면 플래그가 지워지거나 FIFO에서 값이 꺼내질 수 있고, 1을 쓰면 인터럽트가 해제될 수 있으며, 하드웨어가 프로그램과 무관하게 값을 갱신하므로 값이 언제든 바뀔 수 있습니다.

메모리 맵 I/O와 포트 맵 I/O

포트 맵 I/O는 장치에 별도의 주소 공간을 주며, x86의 IN과 OUT 같은 전용 명령으로만 접근합니다. 메모리 맵 I/O는 특별한 명령이 필요 없으므로 모든 주소 지정 방식, 포인터, C 구조체를 레지스터 접근에 쓸 수 있어 명령어 집합을 단순하게 유지할 수 있습니다. ARM과 RISC-V 마이크로컨트롤러에서는 이것이 표준이며, x86 시스템에서도 PCI Express 장치는 대부분의 레지스터를 메모리 맵 영역으로 노출하고, 레거시 포트 I/O는 주로 호환성을 위해 남아 있습니다.

캐시, volatile, 순서 보장

장치 영역은 캐시하지 않도록 설정해야 합니다. 그렇지 않으면 CPU가 오래된 캐시 사본을 계속 다시 읽어 장치의 변화를 끝내 보지 못하거나, 쓰기를 캐시에 붙잡아 둘 수 있습니다. C에서는 레지스터 포인터를 volatile로 선언하여, 컴파일러가 한 번만 읽고 무한 루프에 빠지거나 반복된 쓰기를 생략하는 대신 모든 접근을 작성된 그대로 수행하게 합니다. 다만 volatile은 하드웨어의 재정렬이나 쓰기 버퍼링까지 제어하지는 않습니다. 프로세서와 버스는 쓰기를 포스팅할 수 있으므로, 드라이버는 메모리 배리어나 디바이스 메모리 속성, 때로는 다시 읽기(read-back)를 사용하여 순서와 완료를 보장합니다.

운영체제에서의 MMIO

가상 메모리를 쓰는 시스템에서는 드라이버가 장치를 사용하기 전에 장치의 물리 레지스터 주소를 캐시하지 않는 속성으로 커널의 가상 주소 공간에 매핑하며, 사용자 공간 드라이버를 위해 사용자 프로세스에 매핑하는 경우도 있습니다. MMIO는 보통 장치 설정, 동작 시작, 인터럽트 확인 같은 제어와 상태 관리에 쓰입니다. 대량 데이터는 대개 CPU가 레지스터를 통해 복사하는 대신, 장치 자체가 주 메모리를 읽고 쓰는 DMA(direct memory access)로 이동합니다.

정답과 해설 보기

정답: B. 메모리 맵 I/O

메모리 맵 I/O에서는 타이머나 UART 등 주변기기의 제어 레지스터에 특정 주소를 할당하고 일반적인 로드/스토어 명령어로 조작합니다. 입출력 전용 명령어를 마련하는 방식(x86의 IN/OUT 등 포트 맵 I/O)에 비해 명령어 세트를 단순하게 할 수 있어 ARM과 RISC-V 마이컴에서 표준적입니다. 주변 레지스터는 캐시하지 않고, 컴파일러가 최적화하지 못하게 하는(volatile) 등의 주의가 필요합니다.

자주 묻는 질문

메모리 맵 I/O와 포트 맵 I/O의 차이는 무엇인가요?

메모리 맵 I/O는 장치 레지스터를 일반 메모리 주소 공간에 배치하여 일반 load/store로 접근하고, 포트 맵 I/O는 별도의 주소 공간과 x86의 IN, OUT 같은 전용 명령을 사용합니다.

메모리 맵 레지스터를 volatile로 선언해야 하는 이유는 무엇인가요?

장치가 프로그램과 무관하게 레지스터 값을 바꿀 수 있으므로, volatile로 컴파일러가 값을 레지스터에 캐시하거나 겉보기에 중복된 접근을 제거하지 않고 모든 읽기와 쓰기를 수행하도록 강제하기 위해서입니다.

메모리 맵 I/O 영역을 캐시하지 않는 이유는 무엇인가요?

캐시는 장치의 현재 상태 대신 오래된 값을 돌려줄 수 있고 쓰기를 지연시키거나 합칠 수 있으므로, 장치 영역은 uncached 또는 device 속성으로 매핑합니다.
