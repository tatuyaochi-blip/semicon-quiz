GOT(Global Offset Table)란?

외부 변수와 함수의 실제 주소를 모아 둔 표. 동적 링커가 실행 시에 채우며 위치 독립 코드는 이 표를 통해 참조하므로 코드 페이지를 고쳐 쓰지 않아도 된다.

일본어 명칭: GOT(グローバルオフセットテーブル)

GOT(Global Offset Table)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 5개에 나와요.

  3. C외부 변수나 함수의 실제 주소를 모아 둔 테이블로, 실행 시에 동적 링커가 채우며 코드는 이 테이블을 통해 참조한다
정답과 해설 보기

정답: C. 외부 변수나 함수의 실제 주소를 모아 둔 테이블로, 실행 시에 동적 링커가 채우며 코드는 이 테이블을 통해 참조한다

위치 독립 코드는 다른 라이브러리에 있는 변수의 주소를 명령에 직접 쓸 수 없습니다. 그래서 각 모듈에 주소를 나열한 테이블(GOT)을 두고, 코드는 PC로부터의 거리로 GOT 항목을 읽어 거기에 들어 있는 주소를 사용합니다. 동적 링커는 읽어 들일 때 GOT에 실제 주소를 씁니다. 고쳐 쓰는 것은 쓰기 가능한 데이터인 GOT뿐이므로 코드 페이지는 공유한 채로 둘 수 있습니다.

해설 속 GOT(Global Offset Table)

  • 그래서 각 모듈에 주소를 나열한 테이블(GOT)을 두고, 코드는 PC로부터의 거리로 GOT 항목을 읽어 거기에 들어 있는 주소를 사용합니다.

    공유 라이브러리에서 사용되는 GOT(Global Offset Table)의 역할로 올바른 것은 무엇입니까?

  • 위치 독립 코드에서는 함수나 데이터를 고정 주소가 아니라 PC로부터의 거리나 주소를 모아 둔 테이블(GOT)을 통해 참조합니다.

    위치 독립 코드(PIC)의 설명으로 올바른 것은 무엇입니까?

  • 지연 바인딩에서는 첫 호출 때 입구가 동적 링커의 해석 처리로 점프하여 진짜 주소를 찾아 GOT에 씁니다.

GOT(Global Offset Table)이(가) 나오는 문제 (5)

  1. 공유 라이브러리에서 사용되는 GOT(Global Offset Table)의 역할로 올바른 것은 무엇입니까?
  2. 위치 독립 코드(PIC)의 설명으로 올바른 것은 무엇입니까?
  3. 동적 링크에서 PLT(Procedure Linkage Table)를 사용한 지연 바인딩(lazy binding)을 수행하는 경우의 설명으로 올바른 것은 무엇입니까?
  4. 오브젝트 파일을 역어셈블했더니 외부 함수 printf를 호출하는 명령의 점프 대상이 0 같은 임시 값이었습니다. 이 값은 언제 올바르게 채워집니까?
  5. 공유 라이브러리를 만들 때 외부에서 사용할 함수만 공개하고 내부 함수는 심볼 가시성(visibility)을 'hidden'으로 하는 이점으로 올바른 것은 무엇입니까?
