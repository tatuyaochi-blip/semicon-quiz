인터럽트 벡터 테이블(Interrupt Vector Table)란?

인터럽트와 예외의 종류별로 해당 인터럽트 핸들러의 시작 주소를 나열한 표. CPU는 원인 번호로 이 표를 참조하여 처리 시작 위치를 정한다.

일본어 명칭: 割り込みベクタテーブル

인터럽트 벡터 테이블(Interrupt Vector Table)은(는) OS와 하드웨어 등 1개 분야의 연습 문제 2개에 나와요.

분야: OS와 하드웨어

CPU가 테이블을 사용하는 방법

인터럽트나 예외가 받아들여지면 하드웨어는 그 원인을 식별하는 번호, 즉 벡터를 정합니다. 원인은 타이머, 특정 주변 장치, 페이지 폴트, 잘못된 명령어, 시스템 콜 등입니다. CPU는 다음 명령어의 주소와 동작 모드 같은 상태를 저장한 뒤, 벡터를 인덱스로 삼아 인터럽트 벡터 테이블을 참조하며, 일반적으로 베이스 + 벡터 × 엔트리 크기 위치의 엔트리를 읽습니다. 그 엔트리에 핸들러의 시작 주소가 들어 있습니다. 핸들러는 사용할 레지스터를 저장하고, 사건을 처리한 뒤 인터럽트 복귀 명령을 실행합니다.

테이블이 위치하는 곳

세부 사항은 아키텍처마다 다릅니다. Arm Cortex-M 마이크로컨트롤러에서는 테이블이 코드 메모리의 시작 부분에 있으며, 첫 번째 워드는 초기 스택 포인터, 두 번째 워드는 리셋 핸들러 주소이고, 그 뒤의 워드들은 폴트 및 주변 장치 핸들러를 가리킵니다. 대부분의 코어에서는 벡터 테이블 오프셋 레지스터(VTOR)로 소프트웨어가 테이블을 옮길 수 있습니다. x86 리얼 모드에서는 테이블이 메모리의 처음 1 KB를 차지하며 4바이트 엔트리 256개로 구성되고, 보호 모드와 롱 모드에서는 IDTR 레지스터로 위치를 지정하는 인터럽트 디스크립터 테이블(IDT)을 사용합니다. RISC-V는 mtvec 레지스터를 사용하며, 모든 트랩을 하나의 핸들러로 보내거나 인터럽트를 각각의 주소로 벡터링할 수 있습니다.

임베디드 펌웨어에서의 설정

운영 체제가 없는 마이크로컨트롤러에서는 리셋 순간부터 벡터 테이블이 하드웨어가 기대하는 주소에 있어야 합니다. 스타트업 코드는 테이블을 자체 섹션에 함수 포인터 배열로 정의하고, 링커 스크립트가 그 섹션을 필요한 플래시 주소에 배치합니다. 일반적인 스타트업 파일은 모든 엔트리에 약한(weak) 기본 핸들러, 흔히 무한 루프를 지정해 두므로, 애플리케이션은 이름이 같은 함수를 정의해 사용하는 인터럽트만 재정의합니다. 그래서 핸들러 이름의 철자가 틀리면 문제없이 컴파일되지만, 인터럽트는 조용히 기본 루프로 보내집니다.

벡터 테이블과 폴링 방식의 비교

벡터 방식은 각 원인을 곧바로 전용 핸들러로 보내므로, CPU가 무슨 일이 일어났는지 알아내기 위해 상태 레지스터를 읽을 필요가 없어 인터럽트 지연이 짧아집니다. 대안은 하나의 진입점만 두고 핸들러가 원인 레지스터를 읽어 소프트웨어로 분기하는 방식으로, RISC-V의 다이렉트 모드가 이에 해당합니다. 범용 운영 체제에서는 커널이 부팅 시 테이블을 채워, 타이머 틱, 장치 인터럽트, 페이지 폴트, 시스템 콜이 각각 올바른 커널 루틴에 도달하도록 합니다.

정답: B. 인터럽트나 예외의 종류별로 처리를 시작할 주소를 정해 둔다

인터럽트나 예외가 발생하면 CPU는 그 원인에 대응하는 번호(벡터 번호)를 얻어 인터럽트 벡터 테이블에서 핸들러의 시작 주소를 읽고 그곳으로 처리를 옮깁니다. 표의 내용은 OS가 부팅 시 설정하며, 타이머, 각 장치, 페이지 폴트, 시스템 콜 등에서 서로 다른 핸들러를 호출할 수 있게 합니다. 횟수를 세는 것은 통계를 위한 별도의 구조이고, 실행할 프로세스의 순서는 OS의 스케줄러가 관리합니다.

자주 묻는 질문

인터럽트 벡터란 무엇인가요?

인터럽트 벡터는 인터럽트나 예외의 발생원에 할당된 번호로, 벡터 테이블의 인덱스로 사용됩니다. 넓게는 핸들러 주소를 담고 있는 테이블 엔트리 자체를 가리키기도 합니다.

ARM Cortex-M 마이크로컨트롤러의 벡터 테이블은 어디에 있나요?

기본적으로 부트 메모리, 보통 플래시의 시작 부분에 있습니다. 첫 번째 엔트리는 초기 스택 포인터 값이고 두 번째는 리셋 핸들러이며, 대부분의 코어에서는 벡터 테이블 오프셋 레지스터(VTOR)로 RAM 등으로 옮길 수 있습니다.

x86의 IVT와 IDT의 차이는 무엇인가요?

인터럽트 벡터 테이블(IVT)은 메모리 맨 아래에 있는 256개의 세그먼트:오프셋 주소로 이루어진 리얼 모드용 테이블입니다. 인터럽트 디스크립터 테이블(IDT)은 보호 모드와 롱 모드에서 이를 대체하며, 권한 정보를 포함한 디스크립터를 담고, IDTR 레지스터로 어디에든 배치할 수 있습니다.

해설 속 인터럽트 벡터 테이블(Interrupt Vector Table)

  • 인터럽트나 예외가 발생하면 CPU는 그 원인에 대응하는 번호(벡터 번호)를 얻어 인터럽트 벡터 테이블에서 핸들러의 시작 주소를 읽고 그곳으로 처리를 옮깁니다.

    인터럽트 벡터 테이블의 역할로 올바른 것은?

  • 인터럽트를 받아들이면 CPU는 다음에 실행할 예정이던 명령의 주소와 동작 모드 등의 상태를 저장하고, 인터럽트 벡터 테이블 등으로 정해진 인터럽트 핸들러로 이동합니다.
