인터럽트 벡터 테이블(interrupt vector table)란?

인터럽트나 예외의 종류별로 핸들러의 시작 주소를 모아 둔 표입니다. CPU는 원인 번호로 이 표를 찾아 어디서 처리를 시작할지 알아냅니다.

일본어 명칭: 割り込みベクタテーブル

인터럽트 벡터 테이블(interrupt vector table)은(는) OS와 하드웨어 등 1개 분야의 연습 문제 2개에 나와요.

정답과 해설 보기

정답: B. 인터럽트나 예외의 종류별로 처리를 시작할 주소를 정해 둔다

인터럽트나 예외가 발생하면 CPU는 그 원인에 대응하는 번호(벡터 번호)를 얻고, 인터럽트 벡터 테이블에서 핸들러의 시작 주소를 읽어 그곳으로 처리를 옮깁니다. 표의 내용은 OS가 부팅 시 설정하며, 타이머, 각 장치, 페이지 폴트, 시스템 콜 등에서 서로 다른 핸들러를 호출할 수 있게 합니다. 횟수를 세는 것은 통계를 위한 다른 구조이고, 실행할 프로세스의 순서는 OS의 스케줄러가 관리합니다.

해설 속 인터럽트 벡터 테이블(interrupt vector table)

  • 인터럽트나 예외가 발생하면 CPU는 그 원인에 대응하는 번호(벡터 번호)를 얻고, 인터럽트 벡터 테이블에서 핸들러의 시작 주소를 읽어 그곳으로 처리를 옮깁니다.

    인터럽트 벡터 테이블의 역할로 올바른 것은 무엇입니까?

  • 인터럽트를 받아들이면 CPU는 다음에 실행할 예정이었던 명령의 주소와 동작 모드 등의 상태를 저장하고, 인터럽트 벡터 테이블 등으로 정해진 인터럽트 핸들러로 이동합니다.

    CPU가 인터럽트를 받아들였을 때의 일반적인 처리 흐름으로 올바른 것은 무엇입니까?
