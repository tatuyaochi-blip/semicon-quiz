특권 모드(Privileged Mode)란?

OS 커널만 사용할 수 있는 CPU 동작 모드. 페이지 테이블 설정이나 입출력 조작 등 위험한 명령을 실행할 수 있으며, 애플리케이션이 동작하는 사용자 모드와 구별된다.

일본어 명칭: 特権モード

특권 모드(Privileged Mode)은(는) OS와 하드웨어 등 1개 분야의 연습 문제 5개에 나와요.

  2. B애플리케이션이 페이지 테이블이나 장치를 마음대로 조작하지 못하도록 보호하기 위해
  3. C하나의 CPU에서 동시에 두 개의 명령을 실행할 수 있게 하기 위해

정답: B. 애플리케이션이 페이지 테이블이나 장치를 마음대로 조작하지 못하도록 보호하기 위해

페이지 테이블 재작성, 입출력 장치 조작, 인터럽트 금지 등을 애플리케이션이 마음대로 할 수 있다면 다른 프로그램의 메모리를 망가뜨리거나 시스템 전체를 멈출 수 있습니다. 그래서 CPU는 이러한 명령을 특권 모드에서만 실행할 수 있게 하여 OS 커널만 사용할 수 있도록 합니다. 사용자 모드에서 실행하려 하면 예외가 발생합니다. 속도나 동시 실행을 위한 구조가 아닙니다.

해설 속 특권 모드(Privileged Mode)

  • 그래서 CPU는 이러한 명령을 특권 모드에서만 실행할 수 있게 하여 OS 커널만 사용할 수 있도록 합니다.

    CPU에 특권 모드(커널 모드)와 사용자 모드를 두는 주된 목적은?

  • 그래서 시스템 콜을 사용하여 전용 명령으로 특권 모드로 전환하고 커널의 처리를 호출해 파일 읽기·쓰기, 메모리 할당, 프로세스 생성 등을 요청합니다.

    애플리케이션이 파일 읽기·쓰기 등을 OS에 요청하는 구조를 무엇이라고 합니까?

  • CPU는 현재 명령의 주소를 저장하고 더 높은 특권 모드로 전환하여 OS가 설정한 예외 처리 입구로 진행합니다.

  • 시스템 콜에서는 사용자 모드에서 특권 모드로의 전환, 레지스터 저장, 인수 확인, 복귀 처리 등이 매번 필요하며, 처리하는 양이 1바이트여도 이 고정 부담이 듭니다.

특권 모드(Privileged Mode)이(가) 나오는 문제 (5)

  1. CPU에 특권 모드(커널 모드)와 사용자 모드를 두는 주된 목적은?
  2. 애플리케이션이 파일 읽기·쓰기 등을 OS에 요청하는 구조를 무엇이라고 합니까?
  3. 위 RISC-V 코드의 마지막 ecall 명령이 실행되었을 때 일어나는 일로 올바른 것은?
  4. 인터럽트나 예외 처리를 마치고 원래 프로그램으로 돌아갈 때, 일반 함수의 리턴 명령이 아니라 전용 복귀 명령(RISC-V의 sret, mret 등)을 사용하는 이유는?
  5. 작은 데이터를 1바이트씩 쓸 때, 매번 시스템 콜을 호출하는 것보다 사용자 공간의 버퍼에 모았다가 한꺼번에 쓰는 편이 빠른 주된 이유는?
