스누핑(snooping)란?

각 캐시가 공유 버스 등에 흐르는 다른 코어의 읽기·쓰기를 감시하며 자신의 라인 상태를 바꾸는 코히어런시 방식. 코어 수가 적을 때 적합하다.

일본어 명칭: スヌーピング

스누핑(snooping)은(는) 멀티코어와 동기화 등 1개 분야의 연습 문제 2개에 나와요.

분야: 멀티코어와 동기화

도전해 보기: 스누핑(snooping) 관련 문제

캐시 코히런시의 스누핑 방식에 대한 설명으로 올바른 것은 무엇입니까?

  1. AOS가 일정 시간마다 모든 캐시를 조사하여 불일치를 수정한다
  2. B각 코어의 캐시가 공유 버스 등에 흐르는 다른 코어의 읽기와 쓰기를 감시하고 자신의 라인 상태를 바꾼다
  3. C프로그래머가 쓸 때마다 다른 코어에 값을 수동으로 보낸다
정답과 해설 보기

정답: B. 각 코어의 캐시가 공유 버스 등에 흐르는 다른 코어의 읽기와 쓰기를 감시하고 자신의 라인 상태를 바꾼다

스누핑 방식에서는 코어의 읽기와 쓰기 요청이 모든 캐시에 전달되고, 각 캐시는 자신이 같은 라인을 가지고 있는지 조사하여 무효화하거나 데이터를 전달합니다. 구조가 단순하여 코어 수가 적을 때 적합합니다. 그러나 코어 수가 늘어나면 모든 요청을 모든 캐시에 전달하는 통신이 지나치게 많아지므로, 대규모 시스템에서는 디렉터리 방식이 사용됩니다.

코어 수가 많은 시스템에서 스누핑 방식 대신 디렉터리 방식의 코히런시가 사용되는 이유로 올바른 것은 무엇입니까?

  1. A각 라인을 어느 코어가 가지고 있는지 기록해 두고, 관련된 코어에만 통지함으로써 통신을 줄일 수 있기 때문
  2. B디렉터리 방식에서는 캐시가 필요 없어지기 때문
  3. C디렉터리 방식에서는 쓸 때마다 모든 코어에 통지할 수 있기 때문
정답과 해설 보기

정답: A. 각 라인을 어느 코어가 가지고 있는지 기록해 두고, 관련된 코어에만 통지함으로써 통신을 줄일 수 있기 때문

디렉터리 방식에서는 각 라인에 대해 어느 코어가 사본을 가지고 있고 어떤 상태인지를 기록한 표(디렉터리)를 가집니다. 쓰기가 있으면 디렉터리를 보고 사본을 가진 코어에만 무효화 요청을 보냅니다. 모든 캐시에 일제히 알리는 스누핑에 비해 통신이 적으므로, 코어가 수십 개 이상인 서버용 CPU 등에서 사용됩니다.
