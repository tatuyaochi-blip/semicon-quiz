NUMA란?

Non-Uniform Memory Access의 약어. 코어에서 가까운 메모리와 먼 메모리가 있어 먼 메모리 접근에 시간이 더 걸리는 구성. 데이터와 스레드를 같은 쪽에 두면 빠르다.

일본어 명칭: NUMA

NUMA은(는) 멀티코어와 동기화, 성능 분석, DRAM 등 3개 분야의 연습 문제 4개에 나와요.

분야: 멀티코어와 동기화

메모리 접근이 불균일해지는 이유

현대 프로세서는 메모리 컨트롤러를 내장하므로, 멀티 소켓 서버에서는 각 소켓이 직접 연결된 자체 DRAM을 갖습니다. 코어가 자기 소켓의 메모리에 접근할 때는 로컬 컨트롤러를 바로 거치지만, 다른 소켓의 메모리에 접근하려면 소켓 간 링크를 건너 원격 컨트롤러를 거쳐야 합니다. 코어 그룹과 그 로컬 메모리를 묶어 NUMA 노드라고 합니다. 원격 접근은 보통 지연 시간이 눈에 띄게 길어 흔히 로컬의 약 1.3~2배 범위이고 대역폭도 낮으며, 정확한 비율은 플랫폼과 링크 부하에 따라 다릅니다.

NUMA와 UMA, 클러스터의 비교

균일 메모리 접근(UMA) 시스템은 흔히 하나의 메모리 컨트롤러 복합체를 가진 단일 소켓 머신으로, 모든 코어가 모든 주소를 거의 같은 비용으로 봅니다. 캐시 일관성 NUMA(ccNUMA) 시스템은 하나의 공유 주소 공간과 하드웨어 캐시 일관성을 유지하므로, 수정하지 않은 프로그램도 올바르게 동작하며 속도만 데이터 위치에 따라 달라집니다. 이 점에서 각 노드가 개별 주소 공간을 가져 메시지 전달로 데이터를 명시적으로 주고받아야 하는 독립 컴퓨터 클러스터와 구별됩니다. 칩렛 기반의 대형 프로세서는 하나의 소켓 안에서도 둘 이상의 NUMA 노드를 노출할 수 있습니다.

퍼스트 터치 배치와 그 함정

malloc은 가상 주소만 예약하므로, Linux는 보통 페이지를 할당한 스레드가 아니라 처음 쓴 스레드의 노드에 배치합니다. 하나의 스레드가 큰 배열을 0으로 초기화하면 모든 페이지가 그 스레드의 노드에 놓이고, 이후 다른 노드에서 실행되는 병렬 루프는 거의 전부 원격 메모리에서 실행되며, 메모리 컨트롤러 하나는 포화되고 나머지는 놀게 됩니다. 해결책은 계산과 같은 작업 분할로 데이터를 병렬 초기화해, 각 스레드의 담당 부분이 그 스레드에 로컬로 놓이게 하는 것입니다.

도구와 모범 사례

Linux에서 numactl --hardware는 노드, 노드별 메모리, 그리고 로컬 접근을 관례상 10으로 하고 원격은 그보다 큰 값으로 나타내는 거리 표를 보여 줍니다. 같은 도구로 프로세스를 특정 노드의 CPU와 메모리에 바인딩하거나, 모든 스레드가 고르게 읽는 데이터에 적합하도록 페이지를 노드에 인터리브할 수 있습니다. 스레드를 고정(CPU 어피니티 설정)하면 스케줄러가 스레드를 데이터에서 먼 곳으로 옮기는 것을 막고 벤치마크의 재현성도 높아집니다. 커널이 페이지를 사용하는 스레드 쪽으로 자동 이동시킬 수도 있지만, 성능이 중요한 코드에서는 명시적 배치가 더 예측 가능합니다.

도전해 보기: NUMA 관련 문제

NUMA(비균일 메모리 접근) 시스템에 대한 설명으로 올바른 것은 무엇입니까?

  1. A모든 코어에서 모든 메모리에 같은 시간으로 접근할 수 있다
  2. B코어에서 가까운 메모리와 먼 메모리가 있으며, 먼 메모리에 대한 접근은 시간이 걸린다
  3. C각 코어는 자신의 메모리만 읽을 수 있고 다른 코어의 메모리는 사용할 수 없다
정답과 해설 보기

정답: B. 코어에서 가까운 메모리와 먼 메모리가 있으며, 먼 메모리에 대한 접근은 시간이 걸린다

여러 CPU 소켓을 가진 서버 등에서는 각 소켓에 직접 연결된 메모리가 있고, 다른 소켓의 메모리에는 소켓 간 연결을 통해 접근합니다. 그래서 가까운 메모리보다 먼 메모리가 느리고 대역폭도 작습니다. 모든 메모리가 하나의 주소 공간으로 보이므로 프로그램은 그대로 동작하지만, 데이터와 스레드를 같은 쪽에 두면 성능이 올라갑니다.

Linux의 NUMA 시스템에서 흔히 쓰이는 퍼스트 터치 정책(처음 페이지에 쓴 스레드가 실행 중인 노드의 메모리에 그 페이지를 배치)에서 주의할 점으로 올바른 것은 무엇입니까?

  1. A퍼스트 터치에서는 페이지가 무작위 노드에 배치된다
  2. Bmalloc을 호출한 시점에 모든 페이지의 배치 위치가 정해진다
  3. C큰 배열을 하나의 스레드만으로 0으로 초기화하면 전부 하나의 노드에 배치되어, 다른 노드의 스레드가 먼 메모리를 사용하게 된다
정답과 해설 보기

정답: C. 큰 배열을 하나의 스레드만으로 0으로 초기화하면 전부 하나의 노드에 배치되어, 다른 노드의 스레드가 먼 메모리를 사용하게 된다

malloc으로 확보했을 뿐으로는 물리 페이지가 할당되지 않고, 처음 쓸 때의 페이지 폴트로 그 스레드가 있는 노드의 메모리에 배치됩니다. 그래서 초기화를 하나의 스레드로 수행하면 배열 전체가 그 노드에 모이고, 병렬 계산에서 각 스레드가 담당하는 부분의 상당수가 먼 메모리가 됩니다. 초기화도 계산과 같은 분담으로 병렬로 수행하면 각 부분이 담당 스레드 가까이에 배치됩니다.

자주 묻는 질문

내 컴퓨터가 NUMA인지 확인하는 방법

Linux에서 lscpu나 numactl --hardware를 실행합니다. NUMA 노드가 둘 이상 나오면 메모리 접근 비용이 위치에 따라 달라집니다. 대부분의 듀얼 소켓 서버는 노드가 최소 두 개 표시됩니다.

NUMA를 위해 프로그램을 다시 작성해야 하나요

아닙니다. ccNUMA 머신은 하나의 일관된 주소 공간을 제공하므로 프로그램은 그대로도 올바르게 동작합니다. 다시 작성하는 것은 성능을 위해서일 뿐이며, 주로 각 스레드의 데이터를 자기 노드에 두는 것이 핵심입니다.

퍼스트 터치 정책이란

물리 페이지를 그 페이지에 처음 쓰는 스레드의 NUMA 노드에 할당하는 일반적인 규칙입니다. NUMA 시스템에서 배열의 병렬 초기화가 중요한 이유가 이것입니다.

해설 속 NUMA

  • 옮겨 간 코어의 캐시에는 필요한 데이터가 없고, NUMA 시스템에서는 데이터가 놓인 메모리에서 먼 소켓으로 옮겨질 수도 있습니다.

    멀티코어나 NUMA 시스템에서 성능을 측정할 때 스레드를 특정 코어에 고정하는(어피니티를 설정하는) 경우가…

  • 여러 CPU를 가진 서버에서는 각 CPU에 직결된 메모리가 더 빠른 NUMA 구성이 됩니다.

    현재 대부분의 PC용 프로세서에서 DRAM을 제어하는 메모리 컨트롤러가 놓여 있는 곳은?

  3. 멀티코어나 NUMA 시스템에서 성능을 측정할 때 스레드를 특정 코어에 고정하는(어피니티를 설정하는) 경우가 있는 이유로 올바른 것은?
