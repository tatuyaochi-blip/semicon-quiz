가상 메모리(virtual memory)란?

프로그램이 쓰는 주소(가상 주소)를 OS와 하드웨어가 실제 메모리 번지(물리 주소)에 대응시키는 구조. 각 프로그램이 넓고 독립된 메모리 공간을 쓸 수 있다.

일본어 명칭: 仮想記憶

가상 메모리(virtual memory)은(는) CPU와 아키텍처, OS와 하드웨어 등 2개 분야의 연습 문제 2개에 나와요.

분야: CPU와 아키텍처

주소 변환의 동작 방식

메모리는 고정 크기의 페이지로 나뉘며, 흔히 4 KB를 사용합니다. 가상 주소는 가상 페이지 번호와 페이지 내 오프셋으로 나뉘고, 4 KB 페이지의 오프셋은 12비트입니다. 메모리 관리 장치(MMU)는 페이지 테이블에서 가상 페이지 번호를 찾아 물리 프레임 번호와 함께 present, writable, executable, user-accessible 같은 권한 비트를 얻습니다. 오프셋은 그대로 복사됩니다. 테이블을 작게 유지하기 위해 트리 구조로 구성하며, 48비트 가상 주소를 쓰는 x86-64는 각 단계를 주소 9비트로 인덱싱하는 4단계 구조를 사용합니다.

TLB와 대형 페이지

4단계 테이블을 탐색하면 로드 한 번에 메모리 접근이 네 번 필요할 수 있으므로, TLB(translation lookaside buffer)가 최근 변환 결과를 캐시하며 대부분의 접근은 여기에서 적중합니다. TLB의 엔트리는 수십 개에서 수천 개 정도이고, 커버 범위는 엔트리 수와 페이지 크기의 곱입니다. 4 KB 엔트리 약 1,000개는 4 MB밖에 커버하지 못합니다. 워킹 세트가 더 큰 프로그램은 미스가 잦기 때문에 운영체제는 2 MB 같은 대형 페이지(huge page)를 제공하여 같은 엔트리 수로 기가바이트 단위를 커버할 수 있게 합니다. 주소 공간 식별자(ASID)를 사용하면 TLB가 여러 프로세스의 엔트리를 동시에 보유할 수 있습니다.

페이지 폴트와 요구 페이징

엔트리가 not present로 표시되어 있으면 접근 시 페이지 폴트가 발생하고 운영체제가 제어를 넘겨받습니다. 운영체제는 0으로 초기화된 새 페이지를 할당하거나, 파일이나 스왑 공간에서 페이지를 읽어 오거나, 불법 접근을 감지하면 세그멘테이션 폴트로 프로그램을 종료합니다. 이를 통해 페이지에 접근할 때 비로소 적재하는 요구 페이징(demand paging), 메모리 맵 파일, 그리고 어느 한 프로세스가 쓰기 전까지 페이지를 공유하는 copy-on-write가 가능해집니다. 워킹 세트가 물리 메모리를 크게 넘으면 끊임없는 스와핑, 즉 스래싱이 일어나 시스템이 극도로 느려집니다.

가상 메모리와 캐시의 차이

캐시와 가상 메모리는 둘 다 메모리 계층과 관련되어 있어 자주 혼동되지만, 역할이 다릅니다. 캐시는 최근 사용한 데이터를 하드웨어가 관리하는 복사본으로, 오직 속도를 위해 존재하며 소프트웨어에서는 보이지 않습니다. 가상 메모리는 운영체제가 관리하는 매핑으로, 각 프로세스에 고유한 주소 공간을 제공하고, 프로세스 간 및 커널과의 보호를 강제하며, 공통 라이브러리처럼 물리 페이지를 공유할 수 있게 합니다. 일상적으로는 가상 메모리가 스왑 파일만을 가리키기도 하지만, 이는 가상 메모리로 가능해지는 기능 중 하나일 뿐입니다.

정답과 해설 보기

정답: B. TLB(변환 색인 버퍼)

가상 메모리에서는 프로그램이 쓰는 가상 주소를 물리 주소로 변환해야 하는데, 변환 표(페이지 테이블)가 메모리 위에 있어 매번 참조하면 메모리에 여러 번 접근하게 됩니다. 그래서 최근 사용한 변환 결과를 TLB에 보관합니다. TLB는 수십~수천 항목으로 작고 다루는 메모리가 넓으면 미스가 늘어나므로, 2 MB 같은 큰 페이지(Huge Page)로 TLB가 담당하는 범위를 넓히기도 합니다.

페이지 테이블의 역할로 올바른 것은?

  1. A가상 주소의 페이지 번호를 물리 주소의 페이지 번호에 대응시킨다
  2. B물리 메모리에 있는 데이터의 내용을 페이지별로 복제하여 저장한다
  3. C실행 중인 프로세스의 우선순위를 페이지 순서대로 정렬하여 관리한다
정답과 해설 보기

정답: A. 가상 주소의 페이지 번호를 물리 주소의 페이지 번호에 대응시킨다

가상 메모리에서는 프로그램이 사용하는 가상 주소를 실제 물리 메모리의 주소로 변환하여 사용합니다. 페이지 테이블은 가상 페이지 번호마다 대응하는 물리 페이지 번호와 읽기·쓰기 허가 등의 보호 정보를 기록한 표로, OS가 프로세스마다 만들고 CPU의 MMU가 참조합니다. 자주 쓰는 변환 결과는 TLB에 보관됩니다. 데이터 내용 자체를 복제하거나 프로세스 우선순위를 관리하는 표가 아닙니다.

자주 묻는 질문

페이지 테이블과 TLB의 차이는 무엇인가요?

페이지 테이블은 가상 페이지에서 물리 페이지로의 전체 매핑으로, 메모리에 저장되고 OS가 관리합니다. TLB는 CPU 내부의 작은 하드웨어 캐시로, 최근 사용한 엔트리를 보관하여 대부분의 변환이 테이블 탐색 없이 이루어지게 합니다.

페이지 폴트가 발생하면 어떻게 되나요?

CPU는 폴트를 일으킨 명령을 멈추고 운영체제에 제어를 넘깁니다. 운영체제는 디스크에서 적재하는 등의 방법으로 유효한 페이지를 매핑한 뒤 명령을 재실행하거나, 불법 접근이었다면 프로세스를 종료합니다.

대형 페이지는 왜 사용하나요?

TLB 엔트리 하나가 훨씬 넓은 메모리를 커버하게 되므로, 워킹 세트가 큰 프로그램에서 TLB 미스와 테이블 탐색이 줄어듭니다. 데이터베이스와 가상 머신에서 흔히 사용합니다.
