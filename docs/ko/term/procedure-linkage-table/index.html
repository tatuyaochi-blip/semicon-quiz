PLT(프로시저 링키지 테이블)란?

공유 라이브러리 함수를 호출하기 위한 작은 입구를 나열한 표. 지연 바인딩에서는 첫 호출 시 동적 링커가 주소를 해결하여 GOT에 기록한다.

일본어 명칭: PLT(プロシージャリンケージテーブル)

PLT(프로시저 링키지 테이블)은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 3개에 나와요.

분야: 링커, 로더, 실행 파일

호출이 스텁을 거치는 이유

공유 라이브러리는 프로세스마다 다른 주소에 로드될 수 있으므로, printf 같은 함수의 주소는 프로그램을 링크할 때 알 수 없습니다. 로드 시 모든 호출 명령어를 패치하면 코드 페이지를 쓰기 가능하게 만들어야 하고 프로세스 간에 공유할 수 없게 됩니다. 대신 링커는 각 외부 호출이 프로시저 링키지 테이블(PLT)의 작은 스텁을 가리키게 합니다. 스텁은 전역 오프셋 테이블(GOT)의 슬롯을 통해 간접 점프하며, GOT는 동적 링커가 실제 주소를 채우는 쓰기 가능한 데이터 영역입니다.

지연 바인딩의 단계

지연 바인딩에서 각 GOT 슬롯은 처음에 자신의 PLT 스텁 안쪽을 다시 가리킵니다. 첫 호출 시 스텁은 함수의 재배치 엔트리를 식별하는 인덱스를 푸시하고 공통 PLT 헤더로 점프하며, 헤더는 동적 링커의 리졸버로 진입합니다. 리졸버는 로드된 라이브러리에서 심볼을 찾아 그 주소를 GOT 슬롯에 쓰고 함수로 점프합니다. 이후의 모든 호출은 추가 조회 없이 스텁, GOT, 함수 순으로 진행됩니다. 한 번도 호출되지 않는 함수는 해결되지 않으므로 프로그램 시작이 빨라집니다.

즉시 바인딩과 읽기 전용 GOT

GOT는 쓰기 가능하고 코드 주소를 담고 있으므로, 메모리를 덮어쓸 수 있는 공격자는 GOT 엔트리를 바꿔 제어 흐름을 탈취할 수 있습니다. 그래서 많은 시스템은 Linux에서 -z relro와 -z now로 링크하는 등의 방법으로 시작 시 모든 심볼을 해결한 뒤 GOT를 읽기 전용으로 표시하며, 이 보안 강화를 full RELRO(relocation read-only)라고 합니다. 대가로 많은 함수를 임포트하는 프로그램은 시작이 느려지지만, 흔한 공격 대상을 없앨 수 있습니다.

심볼 가시성과 내부 호출

공유 라이브러리에서 익스포트된 함수는 다른 모듈의 같은 이름 정의로 재정의, 즉 인터포즈될 수 있으므로, 라이브러리 내부에서의 호출도 보통 PLT를 거쳐야 합니다. 내부 함수에 hidden 가시성을 주면 동적 심볼 테이블에서 제거되므로, 그 함수에 대한 호출은 직접 PC 상대 호출이 되고, 동적 링커가 처리할 심볼이 줄며, 다른 라이브러리와의 이름 충돌도 피할 수 있습니다. GOT는 외부 데이터의 주소도 담지만, 데이터 접근은 PLT 스텁 없이 GOT를 직접 읽습니다.

정답과 해설 보기

정답: A. 공유 라이브러리 함수의 주소는 그 함수가 처음 호출될 때 해석되고, 두 번째부터는 해석된 주소로 직접 점프한다

프로그램은 외부 함수를 PLT의 작은 입구를 통해 호출합니다. 지연 바인딩에서는 첫 호출 때 입구가 동적 링커의 해석 처리로 점프하여 진짜 주소를 찾아 GOT에 씁니다. 두 번째부터는 GOT의 주소로 곧바로 점프합니다. 사용되지 않는 함수의 해석을 생략할 수 있어 기동이 빨라집니다. 다만 안전을 위해 기동 시에 모두 해석하고 GOT를 읽기 전용으로 하는 설정도 널리 사용됩니다.

자주 묻는 질문

PLT와 GOT의 차이는 무엇인가요?

PLT에는 외부 호출이 점프하는 작은 실행 가능 스텁이 들어 있고, GOT는 해결된 주소를 담는 데이터 테이블입니다. 각 PLT 스텁은 자신의 GOT 엔트리를 통해 간접 점프합니다.

동적 링킹의 지연 바인딩이란?

공유 라이브러리 함수의 주소 해결을 처음 호출될 때까지 미루는 것으로, 그때 동적 링커가 주소를 찾아 이후 모든 호출을 위해 GOT에 저장합니다.

full RELRO는 무엇을 하나요?

동적 링커가 시작 시 모든 심볼을 해결한 뒤 GOT를 읽기 전용으로 다시 매핑하게 하여, 공격자가 GOT 엔트리를 덮어써 함수 호출을 다른 곳으로 돌리지 못하게 합니다.
