페이지 폴트(page fault)란?

접근한 페이지가 물리 메모리에 할당되어 있지 않거나 허용되지 않는 종류의 접근을 했을 때 CPU가 일으키는 예외. OS가 페이지를 준비해 명령을 다시 실행하거나 부정 접근으로 처리한다.

일본어 명칭: ページフォルト

페이지 폴트(page fault)은(는) OS와 하드웨어, 링커, 로더, 실행 파일, 메모리 계층 구조 등 5개 분야의 연습 문제 15개에 나와요.

분야: OS와 하드웨어

페이지 폴트가 일어날 때의 흐름

메모리 관리 장치(MMU)는 가상 주소를 변환할 때 페이지 테이블 엔트리를 확인합니다. 엔트리가 유효하지 않거나 접근 종류가 허용되지 않으면 MMU는 페이지 폴트를 일으키는데, 이는 폴트를 낸 명령어에 묶인 동기 예외입니다. OS 핸들러는 그 주소가 프로세스가 쓸 수 있는 영역에 속하는지 확인합니다. 속한다면 빈 물리 프레임을 찾고(필요하면 다른 페이지를 내보내고), 디스크의 내용이나 0으로 채운 뒤, 엔트리를 유효로 표시하고 폴트를 낸 명령어를 다시 실행합니다. 속하지 않는다면 프로세스는 세그멘테이션 폴트를 받습니다.

마이너 폴트와 메이저 폴트

모든 페이지 폴트가 디스크에 접근하는 것은 아닙니다. 마이너(소프트) 폴트는 I/O 없이 해결됩니다. 예를 들어 페이지가 이미 파일 캐시로 메모리에 있거나, 0으로 채운 새 프레임만 있으면 되거나, copy-on-write를 위해 복사만 하면 되는 경우입니다. 메이저(하드) 폴트는 스토리지에서 페이지를 읽어야 하며 밀리초 단위의 비용이 듭니다. 그 차이는 엄청납니다. 메모리 접근이 100 ns, 폴트 처리 시간이 8 ms라면, 메이저 폴트가 100만 회 접근당 한 번만 일어나도 평균 접근 시간이 100 ns에서 약 108 ns로 늘어납니다.

의도적으로 쓰이는 페이지 폴트

운영체제는 폴트를 지연 평가 도구로 활용합니다. 디맨드 페이징은 프로그램을 로드하지 않고 매핑만 해 두었다가 각 페이지를 처음 접근할 때 로드합니다. 메모리 매핑 파일(mmap)도 같은 방식으로 파일 내용을 읽습니다. copy-on-write는 fork가 페이지를 읽기 전용으로 공유하게 하고, 나중에 쓰기가 일어난 페이지만 복사합니다. 접근 권한이 없는 가드 페이지를 스택 너머에 두면, 폭주하는 재귀가 데이터를 손상시키는 대신 폴트를 일으킵니다. NUMA 시스템에서 Linux는 페이지를 처음 쓰는 스레드의 노드에 배치하므로, 초기화 순서가 성능에 영향을 줍니다.

페이지 폴트, TLB 미스, 캐시 미스의 차이

이 세 가지는 자주 혼동됩니다. 캐시 미스는 하드웨어가 전부 처리하며, 하위 메모리 계층에서 라인을 가져옵니다. TLB 미스는 변환이 TLB(변환 색인 버퍼)에 캐시되어 있지 않다는 뜻으로, 대부분의 최신 CPU에서는 하드웨어 페이지 테이블 워커가 이를 가져오며, 엔트리가 유효하면 예외가 발생하지 않습니다. 페이지 테이블 엔트리 자체가 무효이거나 접근을 금지할 때에만 페이지 폴트가 OS에 도달합니다. 폴트가 너무 잦아져 시스템이 대부분의 시간을 페이징에 쓰는 상태를 스래싱이라고 합니다.

페이지 폴트가 일어나는 경우로 올바른 것은?

  1. A캐시에 데이터가 없어 주기억장치에서 읽어 들였을 때
  2. B접근한 페이지가 물리 메모리에 할당되어 있지 않을 때
  3. CTLB에 변환 결과가 있어 곧바로 물리 주소를 알 수 있을 때
정답과 해설 보기

정답: B. 접근한 페이지가 물리 메모리에 할당되어 있지 않을 때

페이지 폴트는 접근한 페이지의 페이지 테이블 항목이 무효일 때, 즉 물리 메모리에 할당되어 있지 않을 때(디스크로 내보내졌거나 아직 읽어 들이지 않은 경우 등)나, 읽기 전용 페이지에 쓰기를 하는 것처럼 허용되지 않은 접근을 했을 때 발생하는 예외입니다. OS가 페이지를 준비한 뒤 명령을 다시 실행합니다. 캐시 미스는 하드웨어만으로 처리되며 예외가 되지 않습니다. TLB에 있으면 곧바로 변환할 수 있으므로 폴트는 일어나지 않습니다.

내보내져 디스크에 있는 페이지에 접근하여 페이지 폴트가 일어났을 때 OS가 수행하는 처리 흐름으로 올바른 것은?

  1. A프로그램을 즉시 비정상 종료시키고 페이지는 읽어 들이지 않는다
  2. B페이지를 읽어 들인 뒤 폴트를 일으킨 명령을 건너뛰고 다음 명령부터 재개한다
  3. C페이지를 준비하여 디스크에서 읽어 들이고, 표를 갱신한 뒤 명령을 다시 실행한다
정답과 해설 보기

정답: C. 페이지를 준비하여 디스크에서 읽어 들이고, 표를 갱신한 뒤 명령을 다시 실행한다

정당한 접근에 의한 페이지 폴트에서는 OS가 빈 물리 페이지를 찾고(없으면 다른 페이지를 내보내고) 디스크에서 내용을 읽어 페이지 테이블 항목을 유효하게 만듭니다. 그런 다음 폴트를 일으킨 명령을 처음부터 다시 실행하므로, 프로그램은 아무 일도 없었던 것처럼 계속됩니다. 명령을 건너뛰면 그 접근이 실행되지 않아 결과가 잘못됩니다. 비정상 종료시키는 것은 할당되지 않은 주소에 대한 부정 접근의 경우입니다.

자주 묻는 질문

페이지 폴트는 오류인가요?

꼭 그렇지는 않습니다. 대부분의 페이지 폴트는 디맨드 페이징, copy-on-write, 메모리 매핑 파일에 쓰이는 정상적인 사건이며, 프로세스가 접근해서는 안 되는 주소에 대한 폴트만 세그멘테이션 폴트 같은 오류가 됩니다.

마이너 페이지 폴트와 메이저 페이지 폴트의 차이

마이너 폴트는 이미 메모리에 있는 페이지를 매핑하는 식으로 디스크 I/O 없이 해결되고, 메이저 폴트는 스토리지에서 페이지를 읽어야 하므로 수천 배 느립니다.

페이지 폴트 후 명령어를 건너뛰지 않고 다시 실행하는 이유는?

폴트를 낸 접근은 완료되지 않았으므로, OS가 매핑을 고친 뒤 명령어를 처음부터 다시 실행해 프로그램이 아무 일도 없었던 것처럼 계속 진행하게 합니다.
