데이터 레이스(Data Race)란?

여러 스레드가 같은 변수에 동기화 없이 동시에 접근하며 적어도 하나가 쓰기인 상태. 결과가 실행마다 달라진다. C 언어와 C++에서는 정의되지 않은 동작이다.

일본어 명칭: データ競合

데이터 레이스(Data Race)은(는) 멀티코어와 동기화 등 1개 분야의 연습 문제 1개에 나와요.

분야: 멀티코어와 동기화

갱신 손실이 일어나는 과정

counter++라는 문장은 원자적으로 보이지만, 실제로는 값을 로드하고, 1을 더하고, 다시 저장하는 세 단계로 컴파일됩니다. 두 스레드가 공유 카운터를 각각 100,000번 증가시킨다고 해 봅시다. 스레드 A가 100을 로드하고, A가 저장하기 전에 스레드 B도 100을 로드하면, 둘 다 101을 저장해 증가 한 번이 사라집니다. 스레드가 어떻게 교차 실행되느냐에 따라 최종값은 200,000 미만의 어떤 값이든 될 수 있고 실행할 때마다 달라집니다. 크래시가 발생하지 않으므로 버그를 놓치기 쉽고, 디버거나 로깅으로 프로그램이 느려지면 증상이 사라지기도 합니다.

데이터 레이스와 경쟁 조건

데이터 레이스는 엄밀하게 정의됩니다. 두 스레드가 같은 메모리 위치에 동시에 접근하고, 그중 적어도 하나가 쓰기이며, 이들의 순서를 정하는 동기화가 없는 경우입니다. 경쟁 조건(race condition)은 더 넓은 개념으로, 결과가 타이밍에 따라 달라지는 모든 버그를 가리킵니다. 둘은 겹치지만 같지는 않습니다. 개별적으로 원자적인 연산들로 만든 확인 후 실행(check-then-act) 순서에는 데이터 레이스가 없어도, 확인과 실행 사이에 다른 스레드가 끼어들 수 있으므로 경쟁 조건이 될 수 있습니다. 언어마다 데이터 레이스를 다르게 취급합니다. C와 C++에서는 데이터 레이스를 포함한 프로그램이 정의되지 않은 동작을 일으키고, Java는 레이스가 있는 프로그램에도 정의되어 있지만 약한 의미론을 부여합니다.

해결책: 락과 원자적 연산

해결책은 충돌하는 접근에 순서를 부여하는 것입니다. 락(뮤텍스)은 갱신을 한 번에 한 스레드만 실행하는 임계 구역으로 만들며, 임계 구역을 짧게 유지하면 대기가 줄어듭니다. 단순한 연산에는 원자적 명령이 더 빠릅니다. x86의 lock xadd나 RISC-V의 amoadd.w 같은 fetch-and-add는 읽기, 덧셈, 쓰기를 분할 불가능하게 수행하고 이전 값을 반환하므로 재시도가 필요 없습니다. 더 복잡한 갱신에는 compare-and-swap 루프를 사용합니다. C나 C++에서 변수를 volatile로 선언해도 원자성이나 스레드 간 순서를 제공하지 않으므로 데이터 레이스를 막지 못합니다.

컴파일러와 하드웨어가 레이스를 악화시키는 이유

C와 C++는 레이스가 없는 프로그램을 전제로 하므로, 컴파일러는 공유 변수를 레지스터에 유지하거나, 로드를 루프 밖으로 끌어내거나, 저장을 병합하는 것이 합법적으로 허용됩니다. 그래서 다른 스레드가 동기화 없이 쓰는 플래그를 기다리며 스핀하는 스레드는 그 변화를 영영 보지 못할 수도 있습니다. 하드웨어도 스토어 버퍼와 캐시를 통해 자체적으로 순서를 바꿉니다. 락 획득이나 적절한 메모리 오더를 지정한 원자적 연산 같은 동기화 연산이 컴파일러와 하드웨어 양쪽에 순서를 지켜야 할 지점을 알려 줍니다. ThreadSanitizer 같은 동적 레이스 검출기는 테스트만으로는 좀처럼 드러나지 않는 레이스를 찾는 데 도움이 됩니다.

정답과 해설 보기

정답: C. 여러 스레드가 같은 변수에 동기화 없이 동시에 접근하고, 적어도 하나가 쓰기인 상태

데이터 경쟁은 같은 위치에 대한 읽기와 쓰기의 순서가 동기화로 정해져 있지 않아, 어떤 순서로 실행되었는지에 따라 결과가 달라지는 상태입니다. 타이밍에 따라 발생하기도 하고 하지 않기도 하므로 테스트에서 찾기 어려운 버그가 됩니다. C 언어나 C++에서는 데이터 경쟁이 있는 프로그램의 동작은 미정의로 간주됩니다. 락이나 원자적(atomic) 변수로 순서를 정해야 합니다.

자주 묻는 질문

데이터 레이스와 경쟁 조건(레이스 컨디션)의 차이는 무엇인가요?

데이터 레이스는 같은 메모리 위치에 대한 동시적이고 동기화되지 않은 접근으로, 그중 적어도 하나가 쓰기인 경우입니다. 경쟁 조건은 타이밍에 의존하는 모든 버그를 말하며, 개별 접근이 모두 올바르게 동기화되어 있어도 존재할 수 있습니다.

싱글 코어 CPU에서도 데이터 레이스가 발생하나요?

발생합니다. 운영체제가 로드와 저장 사이에서 스레드를 선점하면 다른 스레드가 실행되어 같은 변수를 갱신할 수 있으므로, 실제 병렬성이 없어도 증가 연산이 사라질 수 있습니다.

C/C++에서 volatile로 데이터 레이스를 막을 수 있나요?

아닙니다. volatile은 컴파일러가 각 접근을 실제로 수행하도록 강제할 뿐, 읽기-수정-쓰기 시퀀스를 원자적으로 만들거나 스레드 간 순서를 보장하지 않습니다. 대신 원자적 연산이나 락을 사용해야 합니다.
