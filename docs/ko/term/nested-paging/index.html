중첩 페이징(Nested Paging)란?

가상 머신의 OS가 관리하는 변환과 하이퍼바이저가 관리하는 변환의 2단 페이지 테이블을 하드웨어가 연속으로 탐색하는 방식. 하이퍼바이저의 개입을 줄여 가상화를 빠르게 한다.

일본어 명칭: 入れ子ページング

중첩 페이징(Nested Paging)은(는) OS와 하드웨어 등 1개 분야의 연습 문제 3개에 나와요.

분야: OS와 하드웨어

한 번의 하드웨어 탐색으로 두 단계 변환

가상 머신 안의 게스트 운영 체제는 게스트 가상 주소를 자신이 물리 주소라고 믿는 주소, 즉 게스트 물리 주소로 매핑하는 페이지 테이블을 관리합니다. 그 메모리는 실제로는 하이퍼바이저가 배치한 곳에 있습니다. 2단계 변환이라고도 하는 중첩 페이징에서는 하드웨어가 게스트의 페이지 테이블을 탐색한 뒤 하이퍼바이저 자신의 테이블을 탐색하여, 게스트 가상 주소에서 게스트 물리 주소, 다시 호스트 물리 주소로 자동 변환합니다. 대표적인 구현으로는 Intel의 EPT(Extended Page Tables), AMD의 NPT(Nested Page Tables), Arm의 스테이지 2 변환이 있습니다.

중첩 페이징이 대체한 것: 섀도 페이지 테이블

하드웨어 지원 이전에 하이퍼바이저는 섀도 페이지 테이블을 사용했습니다. 이는 게스트 가상 주소를 호스트 물리 주소로 직접 매핑하도록 소프트웨어가 관리하는 테이블로, 실제 MMU가 이를 사용했습니다. 이를 올바르게 유지하려면 하이퍼바이저가 게스트의 페이지 테이블 쓰기와 주소 공간 전환을 트랩해야 했으므로, 가상 머신에서 빠져나오는 비싼 VM 종료(exit)가 빈번하게 일어났습니다. 중첩 페이징은 게스트가 자기 테이블을 자유롭게 수정할 수 있게 하여 이러한 종료의 대부분을 없애고 하이퍼바이저를 단순하게 만듭니다. 그 대가는 TLB 미스의 비용으로 옮겨 갑니다.

TLB 미스에 메모리 접근이 24회 필요할 수 있는 이유

게스트 탐색기가 필요로 하는 각 엔트리는 게스트 물리 주소로 위치가 지정되며, 이를 읽으려면 먼저 그 주소 자체를 호스트의 테이블로 변환해야 합니다. 양쪽 모두 4단계 테이블이면 게스트의 각 단계마다 호스트 읽기 4회와 게스트 테이블 읽기 1회, 합계 5회가 들어 4단계에 걸쳐 20회가 되고, 최종 데이터 주소를 호스트에서 변환하는 데 4회가 더해집니다. (4 + 1) × (4 + 1) − 1 = 24회로, 비가상화 환경의 탐색이 4회인 것과 대비됩니다. 페이지 워크 캐시, 최종 결합 변환을 캐시하는 TLB, 호스트 측의 대형 페이지가 평균 비용을 훨씬 낮게 유지해 줍니다.

도전해 보기: 중첩 페이징(Nested Paging) 관련 문제

중첩 페이징(2단 주소 변환)을 사용한 가상화에서 하드웨어가 수행하는 주소 변환에 대한 설명으로 올바른 것은?

  1. A가상 머신 OS의 페이지 테이블만 거치고 하이퍼바이저의 표는 사용하지 않는다
  2. B게스트 가상 → 게스트 물리 → 호스트 물리의 2단으로 변환한다
  3. C하이퍼바이저가 모든 메모리 접근을 가로채 소프트웨어로 한 번씩 변환한다
정답과 해설 보기

정답: B. 게스트 가상 → 게스트 물리 → 호스트 물리의 2단으로 변환한다

가상 머신의 OS는 자신이 관리하는 물리 주소(게스트 물리 주소)가 실제 메모리라고 생각하지만, 실제로는 하이퍼바이저가 할당한 다른 위치에 있습니다. 중첩 페이징에서는 하드웨어가 게스트의 페이지 테이블로 게스트 물리 주소까지 변환하고, 다시 하이퍼바이저의 표로 호스트의 물리 주소까지 변환합니다. 게스트가 페이지 테이블을 재작성할 때마다 하이퍼바이저가 개입할 필요가 없어집니다. 모든 접근을 소프트웨어로 변환하면 너무 느립니다.

게스트도 호스트도 4단 페이지 테이블을 사용하는 중첩 페이징에서 TLB 미스가 일어났을 때 최악의 경우 몇 번의 메모리 접근이 필요합니까?

  1. A8번
  2. B16번
  3. C24번
정답과 해설 보기

정답: C. 24번

게스트 페이지 테이블 4단의 각 표 위치는 게스트 물리 주소로 쓰여 있으므로, 각각을 읽기 전에 호스트의 4단 표로 변환해야 합니다. 게스트의 각 단에서 '호스트 4번 + 게스트 표 1번'의 5번, 4단이면 20번이 되고, 마지막에 얻은 게스트 물리 주소의 데이터 자체를 호스트 4단으로 변환하는 4번을 더하면 24번입니다. 식으로는 (4 + 1) × (4 + 1) − 1 = 24입니다. 8번은 4단을 2번 거치는 것으로 생각한 값이며, 표 위치의 변환을 빠뜨린 것입니다.

자주 묻는 질문

중첩 페이징과 섀도 페이징의 차이는 무엇인가요?

섀도 페이징에서는 하이퍼바이저가 게스트 가상 주소에서 호스트 물리 주소로 가는 결합 테이블을 소프트웨어로 관리하고 게스트의 페이지 테이블 갱신을 트랩합니다. 중첩 페이징에서는 하드웨어가 게스트와 호스트의 테이블을 연달아 탐색하므로, 게스트는 하이퍼바이저의 개입 없이 자기 테이블을 갱신합니다.

중첩 페이지 탐색에는 메모리 접근이 몇 번 필요한가요?

게스트와 호스트 모두 4단계 페이지 테이블을 쓰는 경우, TLB 미스 한 번에 최악의 경우 최대 24회의 메모리 접근이 필요하며, 이는 비가상화 환경의 탐색이 4회인 것과 대비됩니다.

중첩 페이징은 중첩 가상화와 같은 것인가요?

아닙니다. 중첩 페이징은 일반적인 가상 머신을 위한 2단계 주소 변환이고, 중첩 가상화는 가상 머신 안에서 하이퍼바이저를 실행하는 것을 말합니다.
