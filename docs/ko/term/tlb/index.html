TLB(변환 색인 버퍼)란?

가상 주소에서 물리 주소로의 변환 결과를 보관하는 작은 캐시. 메모리상의 페이지 테이블을 매번 탐색하지 않아도 되므로 주소 변환이 빨라진다.

일본어 명칭: TLB(変換索引バッファ)

TLB(변환 색인 버퍼)은(는) OS와 하드웨어, 메모리 계층 구조, 성능 분석 등 4개 분야의 연습 문제 20개에 나와요.

분야: CPU와 아키텍처

도전해 보기: TLB(변환 색인 버퍼) 관련 문제

TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 장점으로 올바른 것은?

  1. A전환 시 TLB를 전부 지우지 않고 변환을 구분할 수 있다
  2. B하나의 프로세스가 사용할 수 있는 가상 주소의 범위를 2배로 할 수 있다
  3. C페이지 테이블이 불필요해져 모든 변환을 TLB만으로 수행할 수 있다
정답과 해설 보기

정답: A. 전환 시 TLB를 전부 지우지 않고 변환을 구분할 수 있다

ASID가 없으면 프로세스마다 같은 가상 주소가 다른 물리 주소를 가리키므로, 프로세스를 전환할 때마다 TLB를 비워야 하고 전환 후 TLB 미스가 계속됩니다. 각 항목에 ASID를 붙이면 어느 프로세스의 변환인지 구분할 수 있으므로 TLB를 지우지 않고 남겨 둘 수 있고, 원래 프로세스로 돌아왔을 때도 재사용할 수 있습니다. 가상 주소의 범위는 바뀌지 않으며, TLB에 다 들어가지 않는 변환을 위해 페이지 테이블은 여전히 필요합니다.

게스트도 호스트도 4단 페이지 테이블을 사용하는 중첩 페이징에서 TLB 미스가 일어났을 때 최악의 경우 몇 번의 메모리 접근이 필요합니까?

  1. A8번
  2. B16번
  3. C24번
정답과 해설 보기

정답: C. 24번

게스트 페이지 테이블 4단의 각 표 위치는 게스트 물리 주소로 쓰여 있으므로, 각각을 읽기 전에 호스트의 4단 표로 변환해야 합니다. 게스트의 각 단에서 '호스트 4번 + 게스트 표 1번'의 5번, 4단이면 20번이 되고, 마지막에 얻은 게스트 물리 주소의 데이터 자체를 호스트 4단으로 변환하는 4번을 더하면 24번입니다. 식으로는 (4 + 1) × (4 + 1) − 1 = 24입니다. 8번은 4단을 2번 거치는 것으로 생각한 값이며, 표 위치의 변환을 빠뜨린 것입니다.
