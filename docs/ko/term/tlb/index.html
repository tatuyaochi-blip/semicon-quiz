TLB(변환 색인 버퍼)란?

최근 사용한 가상 주소에서 물리 주소로의 변환 결과를 보관하는 소형 캐시입니다. 접근할 때마다 메모리의 페이지 테이블을 탐색하지 않아도 되므로 주소 변환이 빨라집니다.

일본어 명칭: TLB(変換索引バッファ)

TLB(변환 색인 버퍼)은(는) OS와 하드웨어, 성능 분석, CPU와 아키텍처 등 3개 분야의 연습 문제 14개에 나와요.

분야: CPU와 아키텍처

도전해 보기: TLB(변환 색인 버퍼) 관련 문제

TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 이점으로 올바른 것은 무엇입니까?

  1. A전환할 때 TLB를 전부 비우지 않고도 변환을 구별할 수 있다
  2. B하나의 프로세스가 사용할 수 있는 가상 주소의 범위를 두 배로 할 수 있다
  3. C페이지 테이블이 필요 없어져 모든 변환을 TLB만으로 수행할 수 있다
정답과 해설 보기

정답: A. 전환할 때 TLB를 전부 비우지 않고도 변환을 구별할 수 있다

ASID가 없으면 프로세스마다 같은 가상 주소가 다른 물리 주소를 가리키므로 프로세스를 전환할 때마다 TLB를 비워야 하고, 전환 후 TLB 미스가 이어집니다. 각 항목에 ASID를 붙이면 어느 프로세스의 변환인지 구별할 수 있으므로 TLB를 비우지 않고 남겨 둘 수 있고, 원래 프로세스로 돌아왔을 때도 재사용할 수 있습니다. 가상 주소의 범위는 달라지지 않으며, TLB에 다 들어가지 못하는 변환을 위해 페이지 테이블은 계속 필요합니다.

게스트도 호스트도 4단 페이지 테이블을 사용하는 중첩 페이징에서 TLB 미스가 발생했을 때, 최악의 경우 몇 번의 메모리 접근이 필요합니까?

  1. A8회
  2. B16회
  3. C24회
정답과 해설 보기

정답: C. 24회

게스트 페이지 테이블 4단의 각 표 위치는 게스트 물리 주소로 적혀 있으므로, 각각을 읽기 전에 호스트의 4단 표로 변환해야 합니다. 게스트의 각 단마다 '호스트 4회 + 게스트 표 1회'로 5회, 4단이면 20회이고, 마지막으로 얻은 게스트 물리 주소의 데이터 자체를 호스트의 4단으로 변환하는 4회를 더하면 24회입니다. 식으로는 (4 + 1) × (4 + 1) − 1 = 24입니다. 8회는 4단을 두 번 따라가기만 한다고 생각한 값으로, 표 위치의 변환을 놓친 것입니다.

해설 속 TLB(변환 색인 버퍼)

  • ASID가 없으면 프로세스마다 같은 가상 주소가 다른 물리 주소를 가리키므로 프로세스를 전환할 때마다 TLB를 비워야 하고, 전환 후 TLB 미스가 이어집니다.

    TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 이점으로 올바른 것은 무엇입니까?

  • 그래서 최근 사용한 변환 결과를 TLB에 보관합니다.

    가상 주소에서 물리 주소로의 변환 결과를 보관하여 주소 변환을 고속화하는 캐시는?

  • 자주 쓰는 변환 결과는 TLB에 보관됩니다.

    페이지 테이블의 역할로 올바른 것은 무엇입니까?

  • TLB에 있으면 곧바로 변환할 수 있으므로 폴트는 일어나지 않습니다.

    페이지 폴트가 발생하는 경우로 올바른 것은 무엇입니까?

  • 그 대신 TLB 미스 때 따라가는 표의 수가 단 수만큼 늘어 느려집니다.

    페이지 테이블을 1단이 아닌 다단(계층형)으로 만드는 주된 이유는 무엇입니까?

TLB(변환 색인 버퍼)이(가) 나오는 문제 (14)

  1. TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 이점으로 올바른 것은 무엇입니까?
  2. 게스트도 호스트도 4단 페이지 테이블을 사용하는 중첩 페이징에서 TLB 미스가 발생했을 때, 최악의 경우 몇 번의 메모리 접근이 필요합니까?
  3. 가상 주소에서 물리 주소로의 변환 결과를 보관하여 주소 변환을 고속화하는 캐시는?
  4. 페이지 테이블의 역할로 올바른 것은 무엇입니까?
  5. 페이지 폴트가 발생하는 경우로 올바른 것은 무엇입니까?
  6. 페이지 테이블을 1단이 아닌 다단(계층형)으로 만드는 주된 이유는 무엇입니까?
  7. 가상 주소 중 48비트를 사용하고, 페이지 크기 4 KB, 각 단의 표가 512개 항목(9비트)인 다단 페이지 테이블에서는 몇 단의 표를 따라가야 합니까?
  8. 프로세스의 컨텍스트 스위치가 레지스터를 저장하고 복원하는 시간보다 실제로는 더 큰 성능 저하를 일으키는 경우가 있습니다. 그 주된 이유는 무엇입니까?
  9. 많은 OS에서 커널 영역을 각 프로세스의 주소 공간 일부(예를 들어 상위 범위)에 할당해 두고, 페이지 테이블의 보호 비트로 사용자 모드에서의 접근을 금지합니다. 이 배치의 주된 이점은 무엇입니까?
  10. 페이지 크기가 4 KB일 때, 가상 주소 중 페이지 내 위치(오프셋)를 나타내는 것은 몇 비트입니까?
  11. 여러 코어를 가진 시스템에서 OS가 어떤 페이지의 페이지 테이블 항목을 고쳐 써서 대응을 취소했을 때 필요한 처리로 올바른 것은 무엇입니까?
  12. 작은 데이터를 1바이트씩 쓸 때, 매번 시스템 콜을 호출하는 것보다 사용자 공간의 버퍼에 모았다가 한꺼번에 쓰는 편이 빠른 주된 이유는 무엇입니까?
  13. 프로그램의 실행 시간을 측정할 때 같은 측정을 여러 번 반복하고 처음 몇 번의 결과를 제외하는 경우가 많은 이유로 올바른 것은?
  14. CPU에 내장된 성능 카운터(PMU)로 셀 수 있는 것의 예로 올바른 것은?
