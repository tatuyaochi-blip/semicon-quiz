TLB(변환 색인 버퍼)란?

가상 주소에서 물리 주소로의 변환 결과를 보관하는 작은 캐시. 메모리상의 페이지 테이블을 매번 탐색하지 않아도 되므로 주소 변환이 빨라진다.

일본어 명칭: TLB(変換索引バッファ)

TLB(변환 색인 버퍼)은(는) OS와 하드웨어, 메모리 계층 구조, 성능 분석 등 4개 분야의 연습 문제 20개에 나와요.

분야: CPU와 아키텍처

TLB 조회의 동작

명령어 인출, 로드, 스토어가 일어날 때마다 메모리 관리 장치(MMU)는 가상 주소를 가상 페이지 번호와 페이지 오프셋으로 나눕니다. 4 KB 페이지에서는 하위 12비트가 오프셋이며 변환 없이 그대로 전달됩니다. TLB 히트이면 저장된 물리 페이지 번호를 오프셋에 붙이고, 같은 단계에서 접근 권한도 검사합니다. 미스이면 페이지 테이블 워크가 메모리의 테이블을 읽어(4 KB 페이지의 48비트 주소에서 최대 4단계) 엔트리를 다시 채웁니다. 페이지 폴트는 페이지 테이블 엔트리가 무효이거나 그 접근을 금지할 때에만 발생합니다.

TLB 리치와 휴지 페이지

TLB 리치는 엔트리 수 × 페이지 크기입니다. 4 KB 엔트리 64개는 256 KB만 덮지만, 같은 64개 엔트리가 2 MB 휴지 페이지를 담으면 128 MB를 덮습니다. TLB에는 수십에서 수천 개의 엔트리만 있으므로, 데이터베이스나 가상 머신처럼 작업 집합이 크거나 흩어진 프로그램은 페이지 테이블 워크에 눈에 띄는 비율의 시간을 쓸 수 있습니다. 대책으로는 휴지 페이지, 작은 1차 TLB 뒤에 두는 더 큰 2차 TLB, 페이지 테이블 엔트리를 데이터 캐시에 유지하기, 지역성 개선이 있습니다.

TLB, 페이지 테이블, 데이터 캐시의 차이

페이지 테이블은 운영체제가 프로세스마다 만들어 메모리에 저장하는 정식 매핑이며, TLB는 그중 최근에 쓰인 엔트리를 캐시하므로 데이터가 아니라 변환을 담습니다. 데이터 캐시는 별개이지만 긴밀하게 협력합니다. 많은 L1 캐시는 가상 인덱스·물리 태그(VIPT) 방식으로, 변환되지 않는 오프셋 비트로 세트를 선택하므로 세트 읽기와 TLB 조회를 병렬로 수행한 뒤 물리 태그를 비교합니다. 캐시 미스는 하드웨어가 처리하지만, 페이지 폴트는 OS가 처리하는 예외입니다.

컨텍스트 스위치, ASID, 가상화

프로세스들은 같은 가상 주소를 재사용하므로, 주소 공간이 바뀐 뒤에 오래된 변환이 남아 있으면 안 됩니다. 태그가 없으면 스위치할 때마다 TLB를 비워야 하므로 미스가 한꺼번에 발생합니다. 엔트리에 주소 공간 식별자(ASID)를 붙이면 프로세스가 돌아왔을 때 엔트리를 재사용할 수 있습니다. 커널을 모든 주소 공간에 매핑해 두면 시스템 콜에 스위치가 필요 없습니다. OS가 매핑을 변경하면 해당 엔트리를 가지고 있을 수 있는 모든 코어에서 그 엔트리를 무효화해야 합니다. 게스트와 호스트 모두 4단계 테이블을 쓰는 중첩 페이징에서는 미스 한 번에 최대 24회의 메모리 접근이 들 수 있습니다.

도전해 보기: TLB(변환 색인 버퍼) 관련 문제

TLB의 각 항목에 ASID(주소 공간 식별자)를 붙이는 장점으로 올바른 것은?

  1. A전환 시 TLB를 전부 지우지 않고 변환을 구분할 수 있다
  2. B하나의 프로세스가 사용할 수 있는 가상 주소의 범위를 2배로 할 수 있다
  3. C페이지 테이블이 불필요해져 모든 변환을 TLB만으로 수행할 수 있다
정답과 해설 보기

정답: A. 전환 시 TLB를 전부 지우지 않고 변환을 구분할 수 있다

ASID가 없으면 프로세스마다 같은 가상 주소가 다른 물리 주소를 가리키므로, 프로세스를 전환할 때마다 TLB를 비워야 하고 전환 후 TLB 미스가 계속됩니다. 각 항목에 ASID를 붙이면 어느 프로세스의 변환인지 구분할 수 있으므로 TLB를 지우지 않고 남겨 둘 수 있고, 원래 프로세스로 돌아왔을 때도 재사용할 수 있습니다. 가상 주소의 범위는 바뀌지 않으며, TLB에 다 들어가지 않는 변환을 위해 페이지 테이블은 여전히 필요합니다.

게스트도 호스트도 4단 페이지 테이블을 사용하는 중첩 페이징에서 TLB 미스가 일어났을 때 최악의 경우 몇 번의 메모리 접근이 필요합니까?

  1. A8번
  2. B16번
  3. C24번
정답과 해설 보기

정답: C. 24번

게스트 페이지 테이블 4단의 각 표 위치는 게스트 물리 주소로 쓰여 있으므로, 각각을 읽기 전에 호스트의 4단 표로 변환해야 합니다. 게스트의 각 단에서 '호스트 4번 + 게스트 표 1번'의 5번, 4단이면 20번이 되고, 마지막에 얻은 게스트 물리 주소의 데이터 자체를 호스트 4단으로 변환하는 4번을 더하면 24번입니다. 식으로는 (4 + 1) × (4 + 1) − 1 = 24입니다. 8번은 4단을 2번 거치는 것으로 생각한 값이며, 표 위치의 변환을 빠뜨린 것입니다.

자주 묻는 질문

TLB 미스가 나면 어떻게 되나요?

MMU(일부 아키텍처에서는 OS 핸들러)가 메모리의 페이지 테이블을 워크해 변환을 찾고, TLB에 설치한 뒤 접근을 다시 시도합니다. 페이지 테이블 엔트리가 무효이거나 접근이 허용되지 않으면 대신 페이지 폴트가 발생하고 OS가 처리를 넘겨받습니다.

TLB 리치 계산 방법

TLB 엔트리 수에 페이지 크기를 곱합니다. 예를 들어 64 엔트리 × 4 KB = 256 KB이지만 64 엔트리 × 2 MB = 128 MB이며, 이것이 휴지 페이지가 TLB 미스를 줄이는 이유입니다.

TLB는 CPU 캐시의 일부인가요?

캐시이긴 하지만 데이터가 아니라 주소 변환을 담습니다. L1 캐시 옆에 있으며 보통 L1과 병렬로 조회되지만, 메모리 내용 자체를 담지는 않습니다.
