TLB(変換索引バッファ)란?

てぃーえるびー

仮想アドレスから物理アドレスへの変換結果を保持する小さなキャッシュ。メモリ上のページテーブルを毎回たどらずに済むため、アドレス変換が速くなる。

일본어 명칭: TLB(変換索引バッファ)

TLB(変換索引バッファ)은(는) 성능 분석, CPU와 아키텍처 등 2개 분야의 연습 문제 3개에 나와요.

분야: CPU와 아키텍처

도전해 보기: TLB(変換索引バッファ) 관련 문제

가상 주소에서 물리 주소로의 변환 결과를 보관하여 주소 변환을 고속화하는 캐시는?

  1. AL3 캐시
  2. BTLB(변환 색인 버퍼)
  3. C레지스터 파일
정답과 해설 보기

정답: B. TLB(변환 색인 버퍼)

가상 메모리에서는 프로그램이 쓰는 가상 주소를 물리 주소로 변환해야 하는데, 변환 표(페이지 테이블)가 메모리 위에 있어 매번 참조하면 메모리에 여러 번 접근하게 됩니다. 그래서 최근 사용한 변환 결과를 TLB에 보관합니다. TLB는 수십~수천 항목으로 작고 다루는 메모리가 넓으면 미스가 늘어나므로, 2 MB 같은 큰 페이지(Huge Page)로 TLB가 담당하는 범위를 넓히기도 합니다.

프로그램의 실행 시간을 측정할 때 같은 측정을 여러 번 반복하고 처음 몇 번의 결과를 제외하는 경우가 많은 이유로 올바른 것은?

  1. A처음 몇 번은 계산 결과가 반드시 틀리기 때문에
  2. B처음에는 캐시가 비어 있거나 파일 읽기나 실행 시 컴파일이 이루어져 느리고, 측정의 편차도 있기 때문에
  3. C같은 측정을 반복하면 CPU가 빨라지는 회로를 만들기 때문에
정답과 해설 보기

정답: B. 처음에는 캐시가 비어 있거나 파일 읽기나 실행 시 컴파일이 이루어져 느리고, 측정의 편차도 있기 때문에

처음 실행에서는 캐시, TLB, 분기 예측기가 빈 상태에서 시작하고, 파일이 OS 캐시에 없어 디스크에서 읽어야 하며, JIT 컴파일러를 쓰는 언어에서는 기계어로의 변환도 이루어집니다. 그래서 처음 몇 번은 느려집니다. 또한 다른 프로그램, 인터럽트, 온도에 따른 주파수 변화 등으로 측정은 편차가 생기므로, 여러 번 측정하여 평균이나 중앙값, 편차의 크기를 제시하는 것이 중요합니다.
