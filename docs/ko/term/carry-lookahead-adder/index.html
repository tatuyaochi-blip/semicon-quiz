캐리 룩어헤드 가산기(Carry-Lookahead Adder)란?

각 자리의 생성 신호 g = a·b와 전파 신호 p = a ⊕ b로부터 자리올림을 하위로부터의 전파를 기다리지 않고 병렬로 구하는 가산기. 비트 수가 많아도 지연이 작다.

일본어 명칭: 桁上げ先見加算器

캐리 룩어헤드 가산기(Carry-Lookahead Adder)은(는) 컴퓨터 산술, 논리 회로 등 2개 분야의 연습 문제 3개에 나와요.

분야: 컴퓨터 산술

생성 신호와 전파 신호

입력이 a와 b인 각 비트에서 생성 신호 g = a·b는 들어오는 캐리와 관계없이 그 비트가 캐리를 만들어 낼 때 1이 되고, 전파 신호 p = a ⊕ b는 들어오는 캐리가 그대로 통과할 때 1이 됩니다. 캐리 출력은 c(i+1) = g(i) + p(i)·c(i), 합은 s(i) = p(i) ⊕ c(i)입니다. 이 점화식을 전개하면 c1 = g0 + p0·c0, c2 = g1 + p1·g0 + p1·p0·c0이 되므로, 모든 캐리를 g·p 신호와 입력 캐리 c0만으로 2단 논리로 표현할 수 있습니다.

리플 캐리 가산이 느린 이유

리플 캐리 가산기에서는 각 전가산기가 아래 비트에서 오는 캐리를 기다려야 합니다. 모든 비트가 1인 워드에 1을 더하는 경우처럼 최악의 경우 캐리가 모든 비트를 거쳐 가므로 지연이 비트 폭에 선형으로 증가합니다. 64비트 리플 캐리 가산기는 기가헤르츠급 클록으로 동작하는 프로세서에는 너무 느립니다. 캐리 룩어헤드 가산기(CLA)는 입력으로부터 캐리를 직접 병렬로 계산하며, 계층적 룩어헤드를 적용하면 지연이 비트 폭의 로그에 비례해서만 증가합니다.

넓은 가산기의 계층적 구성

캐리 식을 완전히 전개하면 곧 입력 수가 너무 많은 게이트가 필요해지므로, 실제 설계에서는 약 4비트 단위의 블록을 사용합니다. 각 블록은 그룹 생성 신호 G = g3 + p3·g2 + p3·p2·g1 + p3·p2·p1·g0과 그룹 전파 신호 P = p3·p2·p1·p0을 만듭니다. 2단 룩어헤드 유닛은 이 신호들을 단일 비트의 g, p 신호와 똑같이 다루어 각 블록으로 들어가는 캐리를 계산하고, 3단을 추가하면 64비트까지 확장할 수 있습니다. Kogge-Stone, Brent-Kung 같은 병렬 프리픽스 가산기는 같은 아이디어를 일반화한 것으로, 배선과 면적을 대가로 논리 단수를 줄입니다.

캐리 룩어헤드 가산기의 용도

고속 가산기는 ALU, 주소 생성기, 부동 소수점 연산 장치, 그리고 곱셈기의 마지막 단에 사용됩니다. 곱셈기는 먼저 많은 부분곱을 캐리 세이브 가산기로 줄입니다. 캐리 세이브 가산기는 독립된 전가산기들로 이루어져 캐리 전파 없이 전가산기 1단의 지연만으로 세 수를 두 수로 바꿉니다. 캐리 전파 덧셈이 필요한 것은 마지막 두 수뿐이며, 이를 캐리 룩어헤드 가산기나 프리픽스 가산기로 한 번에 계산합니다. 캐리 선택 가산기, 캐리 스킵 가산기 같은 절충안은 속도와 면적 면에서 리플 캐리와 완전 룩어헤드의 중간에 위치합니다.

캐리 룩어헤드 가산기가 빠른 이유로 올바른 것은?

  1. A덧셈의 비트 수를 줄이기 위해
  2. B클록 주파수를 2배로 하기 위해
  3. C각 비트의 올림수를 하위에서의 전파를 기다리지 않고 입력으로부터 병렬로 계산하기 때문에
정답과 해설 보기

정답: C. 각 비트의 올림수를 하위에서의 전파를 기다리지 않고 입력으로부터 병렬로 계산하기 때문에

캐리 룩어헤드 가산기는 각 비트의 생성 G = A・B(반드시 올림수를 냄)와 전파 P = A⊕B(하위 올림수를 통과시킴)를 사용하여, C1 = G0 + P0・C0, C2 = G1 + P1・G0 + P1・P0・C0 … 처럼 각 자리의 올림수를 입력으로부터 병렬로 계산합니다. 지연은 비트 수의 로그에 비례해 늘어날 뿐입니다. 다만 식이 길어지므로 4비트 정도의 블록을 계층적으로 조합하여 사용합니다.

캐리 룩어헤드 가산기에서 사용하는 각 자리의 생성 신호 g와 전파 신호 p의 정의(a, b는 그 자리의 입력)와, 윗자리로의 올림 c(i+1)의 식의 조합으로 올바른 것은 무엇입니까?

  1. Ag = a + b, p = a・b, c(i+1) = p + g・c(i)
  2. Bg = a・b, p = a ⊕ b, c(i+1) = g + p・c(i)
  3. Cg = a ⊕ b, p = a・b, c(i+1) = g・p・c(i)
정답과 해설 보기

정답: B. g = a・b, p = a ⊕ b, c(i+1) = g + p・c(i)

그 자리에서 a와 b가 모두 1이면 아래에서의 올림과 관계없이 반드시 올림이 발생하므로 생성 신호는 g = a・b입니다. a와 b 중 한쪽만 1이면 아래에서의 올림을 그대로 위로 전달하므로 전파 신호는 p = a ⊕ b(OR로 하기도 함)입니다. 따라서 c(i+1) = g(i) + p(i)・c(i)가 되며, 이를 전개하면 각 자리의 올림을 입력의 g・p와 최하위 올림만으로 2단의 논리로 병렬 계산할 수 있습니다. 생성과 전파를 바꾼 식으로는 올바르게 계산할 수 없습니다.

자주 묻는 질문

캐리 룩어헤드 가산기가 리플 캐리 가산기보다 빠른 이유는?

리플 캐리 가산기는 캐리가 모든 비트를 차례로 통과하기를 기다리므로 지연이 비트 폭에 선형으로 증가합니다. 캐리 룩어헤드 가산기는 생성·전파 신호로부터 모든 캐리를 병렬로 계산하므로 지연이 대략 비트 폭의 로그에 비례해 증가합니다.

전파 신호에 XOR 대신 OR을 써도 되나요?

캐리 체인에 한해서는 가능합니다. 두 입력이 모두 1이면 생성 항이 이미 캐리를 만들어 내므로 p = a + b로도 같은 캐리가 얻어집니다. 다만 합 비트에는 여전히 a ⊕ b가 필요하므로, 많은 설계에서는 p를 XOR로 계산해 두 용도에 함께 사용합니다.

그룹 생성 신호와 그룹 전파 신호란 무엇인가요?

여러 비트로 이루어진 블록을 요약하는 신호입니다. 그룹 생성 신호는 블록이 스스로 캐리 출력을 만들어 낼 때 1이 되고, 그룹 전파 신호는 블록으로 들어온 캐리가 블록 전체를 통과할 때 1이 됩니다. 상위 룩어헤드 단은 이 신호들을 이용해 블록 캐리를 빠르게 계산합니다.

해설 속 캐리 룩어헤드 가산기(Carry-Lookahead Adder)

  • 캐리 룩어헤드 가산기는 각 비트의 생성 G = A・B(반드시 올림수를 냄)와 전파 P = A⊕B(하위 올림수를 통과시킴)를 사용하여, C1 = G0 + P0・C0, C2 = G1 + P1・G0 + P1・P0・C0 … 처럼 각 자리의 올림수를 입력으로부터 병렬로 계산합니다.
