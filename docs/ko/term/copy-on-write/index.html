카피 온 라이트(Copy-on-Write)란?

복제한 메모리를 처음에는 원본과 공유하다가, 어느 한쪽이 쓰기를 시도할 때 비로소 그 페이지만 복제하는 방식. 프로세스 생성을 빠르게 하고 메모리를 절약할 수 있다.

일본어 명칭: コピーオンライト

카피 온 라이트(Copy-on-Write)은(는) OS와 하드웨어, 링커, 로더, 실행 파일 등 2개 분야의 연습 문제 5개에 나와요.

분야: OS와 하드웨어

카피 온 라이트의 동작 원리

프로세스를 복제할 때 커널은 페이지 테이블만 복사합니다. 부모와 자식의 엔트리는 같은 물리 프레임을 가리키며, 쓰기 가능한 모든 사적(private) 페이지는 일시적으로 읽기 전용으로 표시되고, 커널은 프레임마다 참조 카운트를 유지합니다. 읽기는 최고 속도로 진행됩니다. 어느 한 프로세스가 처음 쓰기를 하면 보호 폴트가 발생하며, 커널은 이것이 카피 온 라이트 페이지임을 인식해 새 프레임을 할당하고, 페이지를 복사하고, 그 복사본을 쓰기 측에 쓰기 가능으로 매핑한 뒤 폴트를 일으킨 명령을 재실행합니다. 참조 카운트상 페이지가 더 이상 공유되지 않는다면 복사 없이 다시 쓰기 가능으로 바꾸기만 하면 됩니다.

프로세스 생성에서 효과가 큰 이유

Unix 계열 시스템에서는 셸이 명령을 시작할 때처럼 fork 직후 거의 바로 exec를 호출하는 패턴이 흔합니다. exec는 주소 공간 전체를 버리고 새 프로그램을 로드하므로, 부모의 메모리를 미리 복사하는 것은 순전한 낭비입니다. 카피 온 라이트를 사용하면 fork의 비용은 대략 페이지 테이블을 복제하는 시간 정도이며, exec 전에 실제로 수정되는 페이지, 일반적으로 스택과 데이터 페이지 몇 개만 복사됩니다. 코드나 읽기 전용 데이터처럼 어느 쪽도 쓰지 않는 페이지는 두 프로세스가 존재하는 동안 계속 공유되므로 메모리도 절약됩니다.

그 밖에 볼 수 있는 곳

같은 아이디어는 데이터가 논리적으로 복제되지만 대개 수정되지 않는 상황이면 어디서나 등장합니다. 사적 파일 매핑이 이를 사용합니다. 공유 라이브러리의 쓰기 가능한 데이터 섹션은 처음에는 파일 캐시와 공유되고, 각 프로세스는 쓰기를 할 때에만 해당 페이지의 자체 복사본을 얻습니다. 많은 커널은 새로 할당된 익명 메모리를 쓰기가 일어날 때까지 하나의 공유 제로 페이지에 매핑합니다. 카피 온 라이트 파일 시스템과 스토리지 스냅숏은 수정된 블록을 덮어쓰는 대신 새 위치에 쓰며, 가상 머신 스냅숏과 일부 언어 런타임은 이 원리를 디스크 이미지와 문자열에 적용합니다.

비용과 함정

카피 온 라이트는 비용을 없애는 것이 아니라 옮기는 것입니다. 공유 페이지에 대한 각 첫 쓰기에는 폴트, 커널로의 트랩, 페이지 복사가 따르며, 이는 일반적인 저장 명령보다 훨씬 느립니다. 대규모 프로세스가 fork한 뒤 부모가 메모리 대부분에 계속 쓰면 결국 거의 모든 페이지가 복사되어 메모리 사용량이 2배에 가까워질 수 있습니다. 또한 fork 시 페이지를 읽기 전용으로 표시하려면 다른 코어의 오래된 TLB 엔트리를 무효화해야 합니다. 카피 온 라이트를 공유 메모리와 혼동해서는 안 됩니다. 공유 메모리에서는 두 프로세스가 서로의 쓰기를 볼 수 있지만, 카피 온 라이트는 쓰는 쪽에 사적인 복사본을 제공합니다.

  2. B기록된 페이지만 나중에 복제하므로 빠르고 메모리를 절약한다
  3. C기록할 때마다 모든 페이지를 복제하므로 데이터의 안전성이 높아진다
정답과 해설 보기

정답: B. 기록된 페이지만 나중에 복제하므로 빠르고 메모리를 절약한다

프로세스를 복제할 때 전체 메모리를 곧바로 복사하면 시간도 메모리도 많이 들고, 직후에 다른 프로그램을 읽어 들인다면 그 복사는 낭비가 됩니다. 카피 온 라이트에서는 양쪽 페이지 테이블이 같은 물리 페이지를 읽기 전용으로 가리키게 해 두고, 어느 한쪽이 쓰기를 하면 페이지 폴트가 일어나 OS가 그 페이지만 복제합니다. 기록한 내용은 공유되지 않고 각 프로세스에 따로 유지됩니다. 모든 페이지를 복제하는 것도 아닙니다.

자주 묻는 질문

fork는 부모의 메모리를 전부 복사하나요?

최신 시스템에서는 그렇지 않습니다. fork는 페이지 테이블을 복제하고 물리 페이지를 읽기 전용으로 표시해 공유하며, 페이지는 어느 한 프로세스가 처음 쓸 때에만 복사됩니다.

fork 후 자식 프로세스가 메모리에 쓰면 어떻게 되나요?

쓰기가 페이지 폴트를 일으키고, 커널이 그 페이지 하나만 새 프레임에 복사해 자식에 쓰기 가능으로 매핑합니다. 부모는 원본을 유지하므로 어느 프로세스도 상대의 변경을 보지 않습니다.

카피 온 라이트와 공유 메모리 차이

공유 메모리는 쓰기 후에도 두 프로세스 모두가 볼 수 있도록 의도된 것이지만, 카피 온 라이트는 누군가 쓰기 전까지만 페이지를 공유하고 쓰는 시점에 쓰는 쪽이 사적인 복사본을 얻습니다.
