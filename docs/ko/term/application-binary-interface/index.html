ABI(애플리케이션 바이너리 인터페이스)란?

컴파일된 프로그램과 라이브러리가 함께 동작하기 위한 기계어 수준의 약속. 호출 규약, 데이터형의 크기와 정렬, 시스템 콜 호출 방식 등을 포함한다.

일본어 명칭: ABI(アプリケーションバイナリインターフェース)

ABI(애플리케이션 바이너리 인터페이스)은(는) ISA와 어셈블리, 링커, 로더, 실행 파일 등 2개 분야의 연습 문제 3개에 나와요.

분야: ISA와 어셈블리

ABI가 고정하는 것

애플리케이션 바이너리 인터페이스(ABI)는 컴파일된 두 코드가 다시 빌드하지 않고 서로를 호출하기 위해 합의해야 하는 모든 것을 정합니다. 여기에는 호출 규약(인수와 반환값을 전달하는 레지스터, 피호출자가 보존해야 하는 레지스터, 스택의 정렬과 배치), int·long·포인터 같은 기본형의 크기와 정렬, 구조체의 레이아웃과 패딩, C++ 이름 맹글링 방식, 예외 발생 시의 스택 되감기 방식, 오브젝트 파일 형식, 그리고 운영체제에 시스템 콜을 호출하는 명령 시퀀스가 포함됩니다.

API와 ABI

애플리케이션 프로그래밍 인터페이스(API)는 프로그래머가 보는 함수 이름, 매개변수 타입, 동작을 정한 소스 수준의 계약입니다. ABI는 그 계약을 컴파일한 뒤의 모습입니다. 라이브러리는 API를 그대로 유지하면서도 ABI를 깨뜨릴 수 있습니다. 예를 들어 공개 구조체에 필드를 추가하면 구조체 크기와 뒤쪽 필드의 오프셋이 바뀝니다. 이 경우 새 헤더로는 문제없이 컴파일되지만, 이전 버전으로 빌드된 바이너리는 다시 컴파일하지 않으면 메모리를 잘못 읽게 됩니다. 공유 라이브러리의 버전 번호는 주로 이런 ABI 변경을 알리기 위해 존재합니다.

하나의 ISA, 여러 ABI

명령어 집합 구조(ISA)는 프로세서가 실행하는 것을 정의하고, ABI는 그 위에 얹힌 소프트웨어 규약이므로 하나의 ISA에 여러 ABI가 있을 수 있습니다. x86-64에서 Linux가 사용하는 System V ABI는 처음 6개의 정수 인수를 RDI, RSI, RDX, RCX, R8, R9로 전달하고 long을 64비트로 정하는 반면, Windows x64 ABI는 RCX, RDX, R8, R9를 사용하고 long을 32비트로 유지합니다. RISC-V는 ilp32, lp64, lp64d 같은 ABI를 정의하며, lp64d는 부동 소수점 인수를 부동 소수점 레지스터로 전달합니다.

라이브러리 ABI를 작게 유지하기

공유 라이브러리가 익스포트하는 모든 심볼은 ABI의 일부가 되어 호환성을 유지해야 합니다. 또한 익스포트된 함수는 다른 모듈의 같은 이름 심볼로 대체될 수 있으므로, 라이브러리 내부 호출조차 프로시저 링키지 테이블(PLT)이나 전역 오프셋 테이블(GOT)을 거쳐야 합니다. 내부 함수에 hidden 가시성을 지정하면 공개 인터페이스에서 제외됩니다. 그러면 동적 링커가 해결할 심볼이 줄고, 내부 호출이 직접 PC 상대 호출이 되며, 다른 라이브러리와의 이름 충돌을 피할 수 있고, 나중에 해당 함수를 자유롭게 변경할 수 있습니다.

정답: C. 호출 규약이나 데이터형의 크기·정렬 등, 기계어 수준에서 프로그램끼리 연결하기 위한 약속

ABI는 컴파일된 프로그램이나 라이브러리가 함께 동작하기 위한 기계어 수준의 약속으로, 호출 규약, int·long·포인터의 크기, 구조체 정렬, 시스템 콜 호출 방법 등을 포함합니다. API는 소스 코드에서 함수 사용법을 정하는 것이며, API가 같아도 ABI가 다르면 다시 빌드하지 않는 한 라이브러리를 사용할 수 없습니다. 같은 RISC-V ISA라도 OS나 용도에 따라 ABI가 다를 수 있습니다.

자주 묻는 질문

API와 ABI의 차이는 무엇인가요?

API는 프로그래머가 코드를 작성할 때 기준으로 삼는 소스 코드 인터페이스이고, ABI는 컴파일된 코드가 의존하는 레지스터, 데이터 레이아웃, 호출 순서에 관한 바이너리 수준의 약속입니다. API를 유지하더라도 ABI가 바뀌면 이에 의존하는 프로그램을 다시 컴파일해야 합니다.

프로그램을 바꾸지 않았는데 라이브러리 업데이트로 동작하지 않는 이유는?

업데이트로 구조체 크기나 함수 인수 타입 같은 ABI가 바뀌면, 기존 바이너리는 여전히 이전 레이아웃을 사용해 잘못된 형태로 데이터를 전달합니다. 소스는 수정 없이 컴파일될 수 있지만, 이미 빌드된 프로그램은 다시 빌드할 때까지 오류를 일으킵니다.

호출 규약은 ABI에 포함되나요?

그렇습니다. 인수와 반환값을 어디에 두는지, 양쪽이 어떤 레지스터를 보존해야 하는지를 정하는 호출 규약은 ABI의 핵심 부분 중 하나입니다.
