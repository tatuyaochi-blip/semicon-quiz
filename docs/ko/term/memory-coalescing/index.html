메모리 코얼레싱(Memory Coalescing)란?

워프 안의 인접한 스레드가 인접한 주소에 접근할 때 이를 묶어 적은 횟수의 메모리 접근으로 처리하는 것. 병합 접근.

일본어 명칭: メモリコアレッシング

분야: GPU 프로그래밍

코얼레싱의 동작 방식

GPU 글로벌 메모리는 개별 워드가 아니라 고정 크기 청크 단위로 접근되며, 보통 128바이트 캐시 라인 안의 32바이트 섹터 단위입니다. 스레드는 워프라는 그룹으로 실행되며, 보통 32개 스레드가 같은 로드 명령을 함께 발행합니다. 워프의 스레드 i가 base + 4i 위치의 4바이트 요소를 읽으면 32개의 요청이 연속된 128바이트 안에 들어가고, 하드웨어는 이를 하나 또는 몇 개의 메모리 트랜잭션으로 합칩니다. 이렇게 합치는 것이 메모리 코얼레싱이며, GPU가 옮기는 바이트를 거의 모두 활용할 수 있게 해 줍니다.

코얼레싱을 깨뜨리는 요인

스레드가 예를 들어 네 번째 요소마다 접근하는 식으로 스트라이드를 두고 주소에 접근하면, 워프는 네 배나 많은 섹터를 건드리고 가져온 각 섹터의 대부분은 버려집니다. 무작위 접근이나 간접 접근은 스레드마다 별도의 트랜잭션이 필요할 수 있습니다. 시작 주소가 정렬되지 않으면 세그먼트가 하나 더 늘어날 수 있습니다. 어느 경우든 실효 대역폭은 피크의 일부로 떨어지며, 많은 GPU 커널이 연산이 아니라 메모리 대역폭에 의해 제한되므로, 코얼레싱되지 않은 접근은 흔히 커널을 몇 배나 느리게 만듭니다.

구조체 배열과 배열 구조체

접근이 코얼레싱되는지는 데이터 레이아웃이 크게 좌우합니다. 입자 위치를 구조체 배열(AoS)로 저장하면 입자 0의 x, y, z 다음에 입자 1의 x, y, z가 오므로, 각 스레드가 x를 읽을 때 주소가 12바이트씩 떨어집니다. 배열 구조체(SoA)에서는 모든 x 값이 연속되므로 이웃한 스레드가 이웃한 주소를 읽고 워프의 로드가 코얼레싱됩니다. 같은 이유로, 즉 이웃한 레인이 이웃한 요소를 원하기 때문에 SoA는 대개 CPU의 SIMD 벡터화에도 더 유리합니다.

기법과 흔한 혼동

일반적인 해결책으로는 가장 빠르게 변하는 스레드 인덱스(CUDA의 threadIdx.x)를 배열의 연속된 차원에 대응시키기, AoS 데이터를 SoA로 변환하기, 온칩 공유 메모리를 경유하기 등이 있습니다. 마지막 방법의 예로, 행렬 타일을 코얼레싱된 행 읽기로 로드한 뒤 전치해서 써 내는 방식이 있습니다. 코얼레싱은 글로벌 메모리 트랜잭션에 관한 것입니다. 이를 공유 메모리 뱅크 충돌과 혼동해서는 안 됩니다. 뱅크 충돌은 워프의 여러 스레드가 같은 공유 메모리 뱅크의 서로 다른 주소에 접근해 접근이 직렬화될 때 발생합니다.

자주 묻는 질문

CUDA에서 메모리 코얼레싱이란 무엇인가요?

워프 스레드들의 글로벌 메모리 접근을 하드웨어가 가능한 한 적은 트랜잭션으로 합치는 것으로, 이웃한 스레드가 이웃하고 정렬된 주소에 접근할 때 일어납니다.

GPU 메모리 접근에 배열 구조체(SoA)가 더 좋은 이유는?

배열 구조체에서는 각 필드가 연속으로 저장되므로, 같은 필드를 읽는 이웃 스레드가 연속된 주소에 접근해 로드가 코얼레싱됩니다. 구조체 배열에서는 그 사이에 스트라이드가 생깁니다.

메모리 코얼레싱과 뱅크 충돌의 차이는 무엇인가요?

코얼레싱은 워프의 글로벌 메모리 접근이 메모리 트랜잭션에 어떻게 대응되는지에 관한 것이고, 뱅크 충돌은 여러 스레드가 온칩 공유 메모리의 같은 뱅크에 접근해 직렬화가 강제되는 현상에 관한 것입니다.

이 용어가 포함된 비교
