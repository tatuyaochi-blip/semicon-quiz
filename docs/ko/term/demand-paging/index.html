요구 페이징(Demand Paging)란?

프로그램의 페이지를 처음부터 모두 읽어 들이지 않고 처음 접근되어 페이지 폴트가 발생했을 때 물리 메모리로 읽어 들이는 방식. 시작이 빠르고 쓰지 않는 부분의 메모리를 절약할 수 있다.

일본어 명칭: デマンドページング

분야: OS와 하드웨어

페이지 폴트 시 일어나는 일

프로그램이 시작될 때 OS는 주소 공간을 기술하는 페이지 테이블을 구성하지만, 대부분의 페이지를 존재하지 않음(not present)으로 표시합니다. 그런 페이지에 처음 접근하면 메모리 관리 장치(MMU)가 페이지 폴트를 발생시킵니다. 커널은 주소가 유효한 영역에 속하는지 확인하고(아니면 프로그램에 세그멘테이션 폴트가 발생), 빈 물리 프레임을 찾아 실행 파일이나 파일의 내용 또는 0으로 채운 뒤, 페이지 테이블 엔트리를 갱신하고 폴트를 일으킨 명령어를 다시 실행합니다. 이번에는 접근이 성공합니다.

마이너 폴트와 메이저 폴트

필요한 데이터가 이미 메모리에 있는 경우, 예를 들어 OS 파일 캐시에 있거나 다른 프로세스가 로드한 공유 라이브러리 페이지인 경우에는 커널이 매핑만 하면 됩니다. 이것이 마이너 폴트이며 비용은 약 1마이크로초입니다. 메이저 폴트는 스토리지에서 읽어야 하므로 훨씬 비싸며, 빠른 플래시에서 수십 마이크로초, 하드 디스크에서는 밀리초 단위가 걸립니다. 커널은 순차 접근을 감지하면 파일의 인접 페이지를 미리 읽어(리드어헤드) 메이저 폴트를 줄입니다.

요구 페이징과 전체 로드의 비교

시작 시 프로그램 전체를 로드하면 오류 핸들러나 선택 기능처럼 한 번도 쓰이지 않는 코드 경로와 데이터에 시간과 메모리를 낭비합니다. 요구 페이징은 접근된 부분만 로드하므로 프로그램이 빨리 시작되고 더 많은 프로세스가 메모리에 들어갑니다. 단점은 첫 접근 시 지연을 예측하기 어렵다는 것이며, 그래서 실시간 시스템은 페이지를 고정(lock)하거나 미리 접근해 두는 경우가 많습니다. 활성 워킹 세트가 물리 메모리를 넘어서면 시스템은 대부분의 시간을 페이징에 쓰는 스래싱 상태에 빠집니다.

관련 기법

메모리 매핑 파일도 같은 메커니즘을 씁니다. mmap은 매핑만 기록하고, 각 페이지를 처음 읽을 때 폴트가 발생해 파일 데이터를 읽어 들입니다. 카피 온 라이트(copy-on-write)는 새로 생성된 프로세스가 어느 한쪽이 쓰기 전까지 부모의 페이지를 공유하게 하며, 쓰는 시점에 폴트가 발생해 개별 사본을 만듭니다. 대용량 메모리 할당은 처음 접근할 때에야 물리 페이지를 받는 경우가 많으므로, 메모리를 할당하는 것과 실제로 사용하는 것은 별개의 사건입니다.

자주 묻는 질문

요구 페이징과 스와핑 차이

요구 페이징은 개별 페이지를 처음 사용할 때 메모리로 가져옵니다. 원래 의미의 스와핑은 프로세스 전체를 메모리와 디스크 사이에서 옮기는 것이며, 현대 시스템은 그 대신 개별 페이지를 페이지 아웃, 페이지 인합니다.

페이지 폴트는 오류인가요

대개는 아닙니다. 요구 페이징에서 페이지 폴트는 페이지를 로드하는 정상적인 방법이며, 어떤 유효 영역에도 속하지 않는 주소에 접근한 경우에만 세그멘테이션 폴트 같은 오류로 처리됩니다.

요구 페이징으로 프로그램 시작이 빨라지는 이유

OS는 시작 시 페이지 테이블만 구성하고 페이지는 접근될 때 로드하므로, 프로그램에서 쓰이지 않는 부분은 스토리지에서 아예 읽지 않기 때문입니다.

관련 용어

디바이스 드라이버(device driver) 메모리 맵 I/O(Memory-mapped I/O) 스래싱(Thrashing) 시스템 콜(system call) 인터럽트 벡터 테이블(Interrupt Vector Table) 인터럽트 핸들러 중첩 페이징(Nested Paging) 카피 온 라이트(Copy-on-Write) 컨텍스트 스위치(context switch) 특권 모드(Privileged Mode)
