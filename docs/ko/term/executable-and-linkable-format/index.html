ELF란?

Executable and Linkable Format의 약어. Linux 등 UNIX 계열 OS와 임베디드 기기에서 오브젝트 파일·실행 파일·공유 라이브러리에 사용되는 파일 형식.

일본어 명칭: ELF

ELF은(는) 링커, 로더, 실행 파일 등 1개 분야의 연습 문제 3개에 나와요.

분야: 링커, 로더, 실행 파일

ELF 파일의 내부 구조

Executable and Linkable Format(ELF) 파일은 매직 바이트 0x7F 뒤에 문자 E, L, F가 이어지는 ELF 헤더로 시작합니다. 헤더에는 32비트인지 64비트인지, 바이트 순서, 대상 CPU, 파일 유형, 실행이 시작되는 엔트리 포인트 주소가 기록됩니다. 같은 형식이 컴파일러가 만드는 재배치 가능 오브젝트 파일, 실행 파일, 공유 라이브러리, 코어 덤프에 모두 쓰입니다. 헤더 다음에는 프로그램 헤더 테이블, 실제 내용, 그리고 각 섹션을 기술하는 섹션 헤더 테이블이 옵니다.

섹션과 세그먼트

ELF는 같은 바이트를 두 가지 관점으로 제공합니다. 링커는 코드용 .text, 상수용 .rodata, 초기화된 변수용 .data, 0으로 초기화되는 변수용 .bss 같은 세분화된 섹션을 다룹니다. .bss는 파일에서 공간을 차지하지 않고 로드 시 0으로 채워집니다. 로더는 프로그램 헤더에 나열된 세그먼트를 다루며, 세그먼트는 섹션을 권한별로 묶은 것입니다. 보통 .text와 .rodata는 읽기·실행 세그먼트에, .data와 .bss는 읽기·쓰기 세그먼트에 들어갑니다. 권한별로 묶으면 페이지 단위의 메모리 보호를 간단히 설정할 수 있습니다.

ELF의 링크·로드 지원

오브젝트 파일에는 코드와 데이터를 결합할 때 링커가 어떤 주소를 패치해야 하는지 알려 주는 심볼 테이블과 재배치 엔트리가 들어 있습니다. 동적 링크된 실행 파일은 프로그램 헤더에 인터프리터, 즉 동적 로더를 지정하고, 필요한 공유 라이브러리를 나열한 dynamic 섹션을 포함합니다. 이들 라이브러리에 대한 호출은 주소를 실행 시에 해결할 수 있도록 보통 프로시저 링키지 테이블(PLT)과 전역 오프셋 테이블(GOT)을 거칩니다. 디버그 정보는 별도의 섹션에 저장되며 도구로 제거(strip)할 수 있습니다. 임베디드 툴체인은 흔히 ELF를 출력한 뒤 이를 플래시 기록용 raw 바이너리나 hex 파일로 변환합니다.

ELF와 PE, Mach-O 비교

Linux, BSD 계열, 그리고 많은 임베디드 시스템은 ELF를 사용하고, Windows는 .exe와 .dll 파일에 Portable Executable(PE) 형식을, macOS와 iOS는 Mach-O를 사용합니다. 코드·데이터 영역, 심볼, 재배치, 동적 링크 정보라는 기본 개념은 비슷하지만 형식이 다르고, 프로그램이 기대하는 시스템 콜 인터페이스와 라이브러리도 다릅니다. 그래서 같은 CPU라도 컴파일된 프로그램은 다른 운영체제에서 그대로 실행되지 않습니다.

  3. C이미지를 저장하기 위한 형식이다

ELF(Executable and Linkable Format)는 Linux를 비롯한 많은 UNIX 계열 OS와 임베디드 기기에서 사용되는 프로그램 파일 형식입니다. 맨 앞의 ELF 헤더에 대상 CPU, 64비트 여부, 실행을 시작할 주소 등이 적혀 있고, 그 뒤에 .text, .data 등의 섹션과 로더가 메모리에 읽어 들이는 단위를 나타내는 프로그램 헤더가 이어집니다. Windows에서는 PE 형식, macOS에서는 Mach-O 형식이 사용됩니다.

ELF 파일에서 '섹션'과 '세그먼트'의 차이로 올바른 것은 무엇입니까?

  1. A섹션은 Windows용, 세그먼트는 Linux용 호칭이며 내용은 같다
  2. B섹션은 링커가 다루는 세밀한 단위이고, 세그먼트는 로더가 메모리에 읽어 들이는 단위로서 권한이 같은 섹션을 모은 것이다
  3. C세그먼트는 디스크 상에만 있고 메모리에는 읽히지 않는다
정답과 해설 보기

정답: B. 섹션은 링커가 다루는 세밀한 단위이고, 세그먼트는 로더가 메모리에 읽어 들이는 단위로서 권한이 같은 섹션을 모은 것이다

ELF에는 두 가지 관점이 있습니다. 링커는 .text, .rodata, .data, .bss 등 세밀한 섹션을 단위로 결합과 재배치를 수행합니다. 로더는 프로그램 헤더에 적힌 세그먼트를 단위로 메모리에 대응시키며, 예를 들어 읽기·실행 세그먼트에 .text와 .rodata를, 읽기·쓰기 세그먼트에 .data와 .bss를 모읍니다. 권한별로 모으면 페이지 단위 보호를 설정하기 쉬워집니다.

자주 묻는 질문

ELF는 무엇의 약자인가요?

ELF는 Executable and Linkable Format의 약자로, Linux를 비롯한 여러 UNIX 계열 시스템과 임베디드 시스템에서 오브젝트 파일, 실행 파일, 공유 라이브러리에 쓰이는 표준 파일 형식입니다.

ELF의 섹션과 세그먼트는 어떻게 다른가요?

섹션은 링커가 결합하고 재배치하는 .text, .data 같은 세분화된 단위입니다. 세그먼트는 프로그램 헤더로 기술되며, 같은 권한을 가진 섹션들을 로더가 메모리에 매핑하는 단위로 묶은 것입니다.

ELF 실행 파일을 Windows에서 실행할 수 있나요?

기본적으로는 불가능합니다. Windows는 PE 형식과 자체 시스템 인터페이스를 전제로 하므로, ELF 프로그램을 실행하려면 호환 계층이나 Linux를 실행하는 가상 머신이 필요하거나 Windows용으로 다시 컴파일해야 합니다.
