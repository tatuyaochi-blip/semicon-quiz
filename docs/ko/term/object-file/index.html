오브젝트 파일(Object File)란?

컴파일러가 하나의 소스 파일로부터 출력하는 파일. 기계어, 데이터 초깃값, 심볼 테이블, 재배치 정보를 포함하지만 다른 파일의 주소는 미확정이며 링크하지 않으면 실행할 수 없다.

일본어 명칭: オブジェクトファイル

오브젝트 파일(Object File)은(는) 링커, 로더, 실행 파일, 컴파일러 등 2개 분야의 연습 문제 8개에 나와요.

분야: 링커, 로더, 실행 파일

오브젝트 파일의 내용

오브젝트 파일은 섹션으로 구성됩니다. text 섹션은 기계어를, data 섹션은 초깃값이 있는 쓰기 가능한 변수를, 읽기 전용 데이터 섹션은 상수와 문자열 리터럴을 담으며, bss 섹션은 0으로 초기화되는 변수의 크기만 기록하므로 파일에서 공간을 차지하지 않습니다. 이와 함께 심볼 테이블은 파일이 정의하는 모든 이름과, 사용하지만 정의하지 않는 모든 이름을 나열하고, 재배치 엔트리는 나중에 주소를 채워 넣어야 하는 각 위치를 나열합니다. 디버그 정보는 선택 사항입니다. 일반적인 포맷은 Linux의 ELF, macOS의 Mach-O, Windows의 COFF/PE입니다.

단독으로 실행할 수 없는 이유

컴파일러나 어셈블러는 각 오브젝트 파일을 독립적으로 생성하며, 섹션이 주소 0에서 시작하는 것처럼 배치합니다. 코드가 printf 같은 다른 파일의 함수를 호출하면 그 주소를 알 수 없으므로, 명령에는 자리 표시자(흔히 0)와 그 자리에 무엇이 들어가야 하는지 기술한 재배치 엔트리가 들어갑니다. 모든 오브젝트 파일과 라이브러리를 함께 보는 것은 링커뿐입니다. 링커는 정의되지 않은 각 심볼을 정의와 대응시키고, 각 섹션이 메모리의 어디에 놓일지 정하고, 자리 표시자를 패치하며, 운영체제가 프로그램을 로드하는 데 필요한 시작 코드와 헤더를 추가합니다.

전형적인 링크 오류와 그 의미

undefined reference to foo 같은 오류는 어떤 오브젝트 파일이 foo를 사용하지만 링크 대상 어디에도 그 정의가 없다는 뜻입니다. 흔한 원인은 정의가 들어 있는 파일을 링크하지 않은 것, -lm 같은 라이브러리 옵션을 빠뜨린 것, 이름의 철자 오류, 또는 extern "C" 없이 C++에서 C 코드를 호출해 C++ 네임 맹글링 후 이름이 달라진 것입니다. 반대로 multiple definition은 대개 여러 소스 파일이 포함하는 헤더에서 변수를 정의했을 때 발생합니다. GNU 링커에서는 명령줄에서 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 뒤에 두어야 합니다.

오브젝트 파일, 정적 라이브러리, 공유 라이브러리

정적 라이브러리는 단순히 오브젝트 파일의 아카이브입니다. 링커는 그 시점에 정의되지 않은 심볼을 해결하는 멤버만 추출하므로 명령줄 순서가 중요합니다. 공유 라이브러리는 다릅니다. 위치 독립 코드로 빌드된, 이미 링크를 거친 출력물이며, 실행 시 메모리에 매핑되고 남은 주소는 동적 링커가 채웁니다. nm, objdump, readelf 같은 도구는 오브젝트 파일의 섹션, 심볼, 재배치 엔트리를 표시하며, 링크가 실패하는 이유를 확인하는 가장 빠른 방법입니다.

컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?

  1. A그대로 OS에서 실행할 수 있는 완성된 프로그램이다
  2. B소스 코드를 압축한 것일 뿐이며 기계어는 포함하지 않는다
  3. C기계어를 포함하지만, 다른 파일에 있는 함수나 변수의 주소는 아직 정해지지 않았다
정답과 해설 보기

정답: C. 기계어를 포함하지만, 다른 파일에 있는 함수나 변수의 주소는 아직 정해지지 않았다

오브젝트 파일에는 그 파일의 함수를 번역한 기계어, 변수의 초기값, 정의하거나 참조하는 이름의 목록(심볼 테이블), 나중에 주소를 채울 위치의 목록(재배치 정보)이 들어 있습니다. printf처럼 다른 파일에 있는 함수를 호출하는 명령은 주소를 알 수 없으므로 임시 값인 채로 있습니다. 링커가 여러 오브젝트 파일을 모아 주소를 정하고 실행 파일을 만듭니다.

GNU 링커에서 'gcc -lmylib main.o'처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 앞에 쓰면 정의되지 않은 참조 오류가 나는 경우가 있습니다. 그 이유로 올바른 것은 무엇입니까?

  1. A링커는 왼쪽부터 순서대로 처리하며, 라이브러리를 읽는 시점에 아직 참조되지 않은 함수는 꺼내지 않기 때문에
  2. B라이브러리는 반드시 명령의 맨 끝에 하나만 쓸 수 있는 규칙이기 때문에
  3. C라이브러리를 앞에 쓰면 라이브러리 내용이 지워지기 때문에
정답과 해설 보기

정답: A. 링커는 왼쪽부터 순서대로 처리하며, 라이브러리를 읽는 시점에 아직 참조되지 않은 함수는 꺼내지 않기 때문에

GNU 링커는 명령줄에 쓰인 순서대로 파일을 처리하며, 정적 라이브러리를 만난 시점에 '아직 정의를 찾지 못한 참조'를 해결하는 오브젝트만 꺼냅니다. 라이브러리를 먼저 쓰면 그 시점에는 main.o의 참조가 아직 없으므로 아무것도 꺼내지 않고, 나중에 main.o를 읽어도 되돌아가서 찾지 않습니다. 그래서 라이브러리는 사용하는 쪽 뒤에 쓰는 것이 원칙입니다.

자주 묻는 질문

오브젝트 파일과 실행 파일의 차이

오브젝트 파일은 소스 파일 하나에 대한 기계어를 담고 있지만, 다른 파일에 대한 참조는 미해결 상태이고 최종 주소도 없습니다. 실행 파일은 링커의 출력물로, 모든 심볼이 해결되고 주소가 확정되었으며 운영체제에 로드 방법을 알려 주는 헤더가 있습니다.

오브젝트 파일의 심볼 목록을 보는 방법

nm, objdump -t, readelf -s를 사용합니다. nm 출력에서 U로 표시된 심볼은 정의되지 않은 심볼로, 파일이 참조하면서 다른 오브젝트 파일이나 라이브러리가 정의해 주기를 기대하는 것입니다.

bss 섹션이란?

0으로 시작하는 전역 변수와 정적 변수를 담는 섹션입니다. 오브젝트 파일에는 그 크기만 기록되고, 프로그램이 시작될 때 로더가 메모리를 할당해 0으로 채웁니다.

해설 속 오브젝트 파일(Object File)

  • 오브젝트 파일에는 그 파일의 함수를 번역한 기계어, 변수의 초기값, 정의하거나 참조하는 이름의 목록(심볼 테이블), 나중에 주소를 채울 위치의 목록(재배치 정보)이 들어 있습니다.

    컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?

  • C 언어 소스 파일은 먼저 컴파일러에서 기계어에 가까운 어셈블리 언어(또는 직접 오브젝트 파일)로 변환되고, 어셈블러에서 기계어 오브젝트 파일이 됩니다.

    C 언어 프로그램에서 실행 파일이 만들어지기까지의 일반적인 흐름으로 올바른 것은 무엇인가?

  • 링커는 각 오브젝트 파일에서 참조되는 이름(심볼)을 어딘가에서 정의된 실체와 대응시키고(심볼 해석), 각 파일의 코드와 데이터를 배열하여 최종 주소를 정하며, 명령 안의 임시 주소를 올바른 값으로 고쳐 씁니다(재배치).

    링커의 주된 역할로 올바른 것은 무엇입니까?

  • 링커는 모든 오브젝트 파일의 심볼 테이블을 모아 참조마다 대응하는 정의를 하나 찾습니다.

    링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?

  • 그러나 링크할 때 foo를 정의한 오브젝트 파일이나 라이브러리를 찾지 못하면 호출 명령에 넣을 주소가 정해지지 않아 이 오류가 납니다.

오브젝트 파일(Object File)이(가) 나오는 문제 (8)

  1. 컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대해 올바른 것은 무엇입니까?
  2. GNU 링커에서 'gcc -lmylib main.o'처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 앞에 쓰면 정의되지 않은 참조 오류가 나는 경우가 있습니다. 그 이유로 올바른 것은 무엇입니까?
  3. 오브젝트 파일을 역어셈블했더니 외부 함수 printf를 호출하는 명령의 점프 대상이 0 같은 임시 값이었습니다. 이 값은 언제 올바르게 채워집니까?
  4. C 언어 프로그램에서 실행 파일이 만들어지기까지의 일반적인 흐름으로 올바른 것은 무엇인가?
  5. 링커의 주된 역할로 올바른 것은 무엇입니까?
  6. 링커가 수행하는 심볼 해석의 설명으로 올바른 것은 무엇입니까?
  7. C 언어 프로그램을 링크했을 때 "undefined reference to `foo'"(foo에 대한 정의되지 않은 참조) 오류가 나왔습니다. 가장 가능성이 높은 원인은 무엇입니까?
  8. 정적 라이브러리(.a 파일)와 함께 링크할 때 링커가 실행 파일에 포함시키는 것으로 올바른 것은 무엇입니까?
