오브젝트 파일(object file)란?

컴파일러가 소스 파일 하나로부터 만들어 내는 파일입니다. 기계어, 초기 데이터, 심볼 테이블, 재배치 항목을 담고 있지만 다른 파일의 주소는 미해결 상태이므로 링크하기 전에는 실행할 수 없습니다.

일본어 명칭: オブジェクトファイル

오브젝트 파일(object file)은(는) 링커, 로더, 실행 파일, 컴파일러 등 2개 분야의 연습 문제 8개에 나와요.

분야: 링커, 로더, 실행 파일

도전해 보기: 오브젝트 파일(object file) 관련 문제

컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대한 설명으로 올바른 것은?

  1. A그대로 OS에서 실행할 수 있는 완성된 프로그램이다
  2. B소스 코드를 압축한 것일 뿐 기계어는 포함하지 않는다
  3. C기계어를 포함하지만, 다른 파일에 있는 함수나 변수의 주소는 아직 정해지지 않았다
정답과 해설 보기

정답: C. 기계어를 포함하지만, 다른 파일에 있는 함수나 변수의 주소는 아직 정해지지 않았다

오브젝트 파일에는 해당 파일의 함수를 번역한 기계어, 변수의 초깃값, 정의하거나 참조하는 이름의 목록(심볼 테이블), 나중에 주소를 채워 넣을 위치의 목록(재배치 정보)이 들어 있습니다. printf처럼 다른 파일에 있는 함수를 호출하는 명령은 주소를 알 수 없으므로 임시 값인 채로 남아 있습니다. 링커가 여러 오브젝트 파일을 합쳐 주소를 정하고 실행 파일을 만듭니다.

GNU 링커에서 「gcc -lmylib main.o」처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 앞에 쓰면 미정의 참조 오류가 나는 경우가 있다. 그 이유로 올바른 것은?

  1. A링커는 왼쪽부터 차례로 처리하며, 라이브러리를 읽는 시점에 아직 참조되지 않은 함수는 꺼내지 않기 때문
  2. B라이브러리는 반드시 명령의 맨 끝에 하나만 쓸 수 있다는 규칙이 있기 때문
  3. C라이브러리를 앞에 쓰면 라이브러리의 내용이 지워지기 때문
정답과 해설 보기

정답: A. 링커는 왼쪽부터 차례로 처리하며, 라이브러리를 읽는 시점에 아직 참조되지 않은 함수는 꺼내지 않기 때문

GNU 링커는 명령줄에 쓰인 순서대로 파일을 처리하며, 정적 라이브러리를 만난 시점에 「아직 정의를 찾지 못한 참조」를 해결하는 오브젝트만 꺼냅니다. 라이브러리를 먼저 쓰면 그 시점에는 main.o의 참조가 아직 없으므로 아무것도 꺼내지 않고, 나중에 main.o를 읽어도 되돌아가서 찾지 않습니다. 그래서 라이브러리는 사용하는 쪽의 뒤에 쓰는 것이 원칙입니다.

해설 속 오브젝트 파일(object file)

  • 오브젝트 파일에는 해당 파일의 함수를 번역한 기계어, 변수의 초깃값, 정의하거나 참조하는 이름의 목록(심볼 테이블), 나중에 주소를 채워 넣을 위치의 목록(재배치 정보)이 들어 있습니다.

    컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대한 설명으로 올바른 것은?

  • C 언어 소스 파일은 먼저 컴파일러에서 기계어에 가까운 어셈블리 언어(또는 직접 오브젝트 파일)로 변환되고, 어셈블러에서 기계어 오브젝트 파일이 됩니다.

    C 언어 프로그램에서 실행 파일이 만들어지기까지의 일반적인 흐름으로 올바른 것은 무엇인가?

  • 링커는 각 오브젝트 파일에서 참조하는 이름(심볼)을 어딘가에서 정의된 실체와 대응시키고(심볼 해석), 각 파일의 코드와 데이터를 나열해 최종 주소를 정한 다음, 명령 안의 임시 주소를 올바른 값으로 고쳐 씁니다(재배치).

    링커의 주된 역할로 올바른 것은?

  • 링커는 모든 오브젝트 파일의 심볼 테이블을 모아 참조마다 대응하는 정의를 하나 찾습니다.

    링커가 수행하는 심볼 해석에 대한 설명으로 올바른 것은?

오브젝트 파일(object file)이(가) 나오는 문제 (8)

  1. 컴파일러가 하나의 소스 파일에서 출력하는 오브젝트 파일(.o)에 대한 설명으로 올바른 것은?
  2. GNU 링커에서 「gcc -lmylib main.o」처럼 정적 라이브러리를 그것을 사용하는 오브젝트 파일보다 앞에 쓰면 미정의 참조 오류가 나는 경우가 있다. 그 이유로 올바른 것은?
  3. 오브젝트 파일을 역어셈블했더니 외부 함수 printf를 호출하는 명령의 분기 대상이 0 같은 임시 값으로 되어 있었다. 이 값은 언제 올바르게 채워지는가?
  4. C 언어 프로그램에서 실행 파일이 만들어지기까지의 일반적인 흐름으로 올바른 것은 무엇인가?
  5. 링커의 주된 역할로 올바른 것은?
  6. 링커가 수행하는 심볼 해석에 대한 설명으로 올바른 것은?
  7. C 언어 프로그램을 링크했더니 「undefined reference to `foo'」(foo에 대한 미정의 참조)라는 오류가 나왔다. 가장 가능성이 높은 원인은?
  8. 정적 라이브러리(.a 파일)와 함께 링크할 때 링커가 실행 파일에 포함시키는 것으로 올바른 것은?
