공유 라이브러리(Shared Library)란?

동적 링크로 실행 시 로드되는 라이브러리. Linux에서는 .so, Windows에서는 .dll. 위치 독립 코드로 만들어지며 코드 페이지를 여러 프로세스가 공유할 수 있다.

일본어 명칭: 共有ライブラリ

공유 라이브러리(Shared Library)은(는) 링커, 로더, 실행 파일, ISA와 어셈블리 등 2개 분야의 연습 문제 15개에 나와요.

분야: 링커, 로더, 실행 파일

도전해 보기: 공유 라이브러리(Shared Library) 관련 문제

동적 링크(공유 라이브러리)의 이점으로 올바른 것은 무엇입니까?

  1. A실행 환경에 라이브러리가 없어도 반드시 동작한다
  2. B여러 프로그램이 하나의 라이브러리를 메모리에서 공유할 수 있고, 라이브러리를 갱신하면 다시 만들지 않아도 수정이 반영된다
  3. C기동 시 처리가 전혀 필요 없어져 정적 링크보다 반드시 빠르게 기동한다
정답과 해설 보기

정답: B. 여러 프로그램이 하나의 라이브러리를 메모리에서 공유할 수 있고, 라이브러리를 갱신하면 다시 만들지 않아도 수정이 반영된다

동적 링크에서는 실행 파일에 '어느 공유 라이브러리의 어느 함수를 사용하는지'만 기록해 두고, 실행 시에 동적 링커가 라이브러리를 읽어 들여 연결합니다. 공유 라이브러리의 코드는 바뀌지 않으므로 물리 메모리 상의 하나의 사본을 많은 프로세스가 공유할 수 있습니다. 버그나 취약점 수정도 라이브러리를 교체하기만 하면 됩니다. 다만 기동 시에 결합 작업이 필요합니다.

공유 라이브러리에서 사용되는 GOT(Global Offset Table)의 역할로 올바른 것은 무엇입니까?

  1. A라이브러리 함수의 이름을 알파벳 순으로 나열한 목차이다
  2. B캐시에 다 들어가지 못한 데이터를 일시적으로 두는 테이블이다
  3. C외부 변수나 함수의 실제 주소를 모아 둔 테이블로, 실행 시에 동적 링커가 채우며 코드는 이 테이블을 통해 참조한다
정답과 해설 보기

정답: C. 외부 변수나 함수의 실제 주소를 모아 둔 테이블로, 실행 시에 동적 링커가 채우며 코드는 이 테이블을 통해 참조한다

위치 독립 코드는 다른 라이브러리에 있는 변수의 주소를 명령에 직접 쓸 수 없습니다. 그래서 각 모듈에 주소를 나열한 테이블(GOT)을 두고, 코드는 PC로부터의 거리로 GOT 항목을 읽어 거기에 들어 있는 주소를 사용합니다. 동적 링커는 읽어 들일 때 GOT에 실제 주소를 씁니다. 고쳐 쓰는 것은 쓰기 가능한 데이터인 GOT뿐이므로 코드 페이지는 공유한 채로 둘 수 있습니다.

  3. 100개의 프로세스가 같은 공유 라이브러리를 사용하고 있을 때 물리 메모리 사용 방식으로 올바른 것은 무엇입니까?

  5. 공유 라이브러리를 만들 때 외부에서 사용할 함수만 공개하고 내부 함수는 심볼 가시성(visibility)을 'hidden'으로 하는 이점으로 올바른 것은 무엇입니까?

  7. C 언어의 함수 포인터를 사용한 호출 '(*fp)(x)'는 RISC-V에서 일반적으로 어떤 명령어로 이루어지는가?
  8. 실행 파일의 .text 섹션에 들어 있는 것은 무엇입니까?
  9. Linux 등의 일반적인 프로세스 메모리 배치를 주소가 작은 쪽부터 나열한 것으로 올바른 것은 무엇입니까?
  10. 동적 링크를 사용한 프로그램을 다른 컴퓨터에 복사하여 실행했더니 기동하지 않았습니다. 가장 가능성이 높은 원인은 무엇입니까?
  11. 위치 독립 코드(PIC)의 설명으로 올바른 것은 무엇입니까?
  12. Linux에서 동적 링크 프로그램을 기동할 때 동작하는 동적 링커(ld.so 등)의 역할로 올바른 것은 무엇입니까?
  13. ASLR(주소 공간 배치 무작위화)의 목적으로 올바른 것은 무엇입니까?
  14. Linux의 dlopen 함수(Windows의 LoadLibrary에 해당)의 용도로 가장 적절한 것은 무엇입니까?
