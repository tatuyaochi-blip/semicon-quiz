공유 라이브러리(Shared Library)란?

동적 링크로 실행 시 로드되는 라이브러리. Linux에서는 .so, Windows에서는 .dll. 위치 독립 코드로 만들어지며 코드 페이지를 여러 프로세스가 공유할 수 있다.

일본어 명칭: 共有ライブラリ

공유 라이브러리(Shared Library)은(는) 링커, 로더, 실행 파일, ISA와 어셈블리 등 2개 분야의 연습 문제 15개에 나와요.

분야: 링커, 로더, 실행 파일

동적 링크의 원리

프로그램을 공유 라이브러리와 링크하면, 실행 파일에는 soname으로 식별되는 필요한 라이브러리와 가져올 심볼만 기록됩니다. 시작 시 동적 링커(Linux에서는 ld.so)가 각 라이브러리를 찾아 프로세스의 주소 공간에 매핑하고, 심볼 참조를 해결하고, 재배치를 적용합니다. 라이브러리 함수 호출은 보통 프로시저 링키지 테이블(PLT)을 거치며, PLT는 각 함수를 처음 호출할 때 지연 해결할 수 있습니다. ldd 명령은 필요한 각 라이브러리가 어느 파일로 해결되는지 보여 주고, 없는 것은 'not found'로 표시합니다. 다만 신뢰할 수 없는 바이너리에 ldd를 실행하면 그 코드가 실행될 수 있으므로 해서는 안 됩니다.

위치 독립 코드와 페이지 공유

공유 라이브러리는 프로세스마다 다른 주소에 로드될 수 있으므로 위치 독립 코드(PIC)로 컴파일됩니다. 코드는 자신의 함수와 데이터에는 PC 상대 주소 지정으로 접근하고, 외부 심볼에는 동적 링커가 채워 넣는 프로세스별 데이터 영역인 글로벌 오프셋 테이블(GOT)을 통해 접근합니다. 따라서 코드 페이지는 수정할 필요가 없고, 읽기 전용이자 실행 가능으로 매핑할 수 있습니다. OS는 모든 프로세스의 매핑이 같은 물리 페이지를 가리키게 하므로, 하나의 라이브러리를 사용하는 프로세스가 100개라도 코드는 한 벌만 존재하며, 쓰기 가능한 데이터 페이지는 보통 카피 온 라이트로 프로세스별로 유지됩니다.

soname을 이용한 버전 관리

Linux에서 libfoo.so.1.2.3 같은 라이브러리 파일은 libfoo.so.1 같은 soname을 가지며, 프로그램은 soname을 기록합니다. ABI(application binary interface) 호환성을 유지하는 버그 수정이나 보안 패치는 soname을 유지하므로, 파일 하나를 교체하면 그것을 쓰는 모든 프로그램이 갱신됩니다. 인수 타입이나 구조체 배치를 바꾸거나 함수를 제거하면 기존 바이너리가 깨지므로, soname의 번호를 올리고 새 라이브러리를 기존 라이브러리와 나란히 설치합니다.

공유 라이브러리와 정적 라이브러리

정적 라이브러리는 오브젝트 파일의 아카이브로, 필요한 부분이 링크 시점에 실행 파일에 복사되어 시작 시 바인딩이 없는 자기 완결적인 바이너리가 되지만, 모든 프로그램이 각자 복사본을 가지며 수정하려면 다시 링크해야 합니다. 공유 라이브러리는 메모리와 디스크를 절약하고 그 자리에서 업데이트할 수 있지만, 시작 시 바인딩 작업, 모듈 간 호출의 간접 참조, 의존성 누락으로 인한 실패라는 대가가 따릅니다. 내부 함수의 가시성을 hidden으로 하고 공개 API만 내보내면, 동적 링커가 처리해야 할 심볼이 줄고, 내부 호출이 PLT를 건너뛸 수 있으며, 이름 충돌을 피하고 ABI를 작게 유지할 수 있습니다.

  3. C기동 시 처리가 전혀 필요 없어져 정적 링크보다 반드시 빠르게 기동한다
정답과 해설 보기

정답: B. 여러 프로그램이 하나의 라이브러리를 메모리에서 공유할 수 있고, 라이브러리를 갱신하면 다시 만들지 않아도 수정이 반영된다

동적 링크에서는 실행 파일에 '어느 공유 라이브러리의 어느 함수를 사용하는지'만 기록해 두고, 실행 시에 동적 링커가 라이브러리를 읽어 들여 연결합니다. 공유 라이브러리의 코드는 바뀌지 않으므로 물리 메모리 상의 하나의 사본을 많은 프로세스가 공유할 수 있습니다. 버그나 취약점 수정도 라이브러리를 교체하기만 하면 됩니다. 다만 기동 시에 결합 작업이 필요합니다.

공유 라이브러리에서 사용되는 GOT(Global Offset Table)의 역할로 올바른 것은 무엇입니까?

  1. A라이브러리 함수의 이름을 알파벳 순으로 나열한 목차이다
  2. B캐시에 다 들어가지 못한 데이터를 일시적으로 두는 테이블이다
  3. C외부 변수나 함수의 실제 주소를 모아 둔 테이블로, 실행 시에 동적 링커가 채우며 코드는 이 테이블을 통해 참조한다
정답과 해설 보기

정답: C. 외부 변수나 함수의 실제 주소를 모아 둔 테이블로, 실행 시에 동적 링커가 채우며 코드는 이 테이블을 통해 참조한다

위치 독립 코드는 다른 라이브러리에 있는 변수의 주소를 명령에 직접 쓸 수 없습니다. 그래서 각 모듈에 주소를 나열한 테이블(GOT)을 두고, 코드는 PC로부터의 거리로 GOT 항목을 읽어 거기에 들어 있는 주소를 사용합니다. 동적 링커는 읽어 들일 때 GOT에 실제 주소를 씁니다. 고쳐 쓰는 것은 쓰기 가능한 데이터인 GOT뿐이므로 코드 페이지는 공유한 채로 둘 수 있습니다.

자주 묻는 질문

정적 라이브러리와 공유 라이브러리 차이

정적 라이브러리(.a 또는 .lib)는 링크 시점에 실행 파일에 복사됩니다. 공유 라이브러리(.so 또는 .dll)는 실행 시 로드되는 별도 파일로 남으며, 여러 프로세스가 메모리에서 공유할 수 있습니다.

공유 라이브러리에 -fPIC가 필요한 이유

라이브러리는 임의의 주소에 로드될 수 있으므로 코드가 절대 주소를 피해야 합니다. PIC는 PC 상대 주소 지정과 GOT를 사용하므로 코드 페이지를 수정할 필요가 없고 공유할 수 있습니다.

ldd 출력의 not found는 무슨 뜻인가요?

동적 링커가 검색 경로에서 그 공유 라이브러리를 찾을 수 없다는 뜻이며, 라이브러리를 설치하거나 경로를 고칠 때까지 프로그램은 시작되지 않습니다.
