그레이 코드(Gray Code)란?

인접한 값 사이에서 1비트만 변하는 부호. 로터리 인코더나 서로 다른 클록 간의 카운터 값 전달에서 읽기 오류를 방지하는 데 쓰인다.

일본어 명칭: グレイコード

그레이 코드(Gray Code)은(는) 타이밍 분석과 CDC, 논리 회로, 정보 이론과 부호의 기초 등 4개 분야의 연습 문제 12개에 나와요.

분야: 논리 회로

2진 코드와 그레이 코드 사이의 변환

일반적인 그레이 코드는 반사 2진 코드(reflected binary code)로, n비트 수열을 나열한 뒤 그 거울상을 이어 붙이고 앞쪽 절반에는 0, 뒤쪽 절반에는 1을 앞에 붙여 만듭니다. 2진수 B로부터의 변환은 G = B XOR (B >> 1)이라는 한 줄의 식으로 표현되며, 최상위 비트를 제외한 각 그레이 비트는 인접한 두 2진 비트의 XOR입니다. 역변환은 최상위 비트부터 아래로 누적 XOR을 취합니다. 최상위 비트는 그대로 복사하고, 그 아래 각 2진 비트는 바로 위의 2진 비트와 현재 그레이 비트의 XOR입니다. 3비트의 경우 수열은 000, 001, 011, 010, 110, 111, 101, 100입니다.

인코더에서 1비트 변화가 중요한 이유

일반 2진 코드에서 0111에서 1000으로 넘어가면 네 비트가 동시에 바뀝니다. 회전형이나 직선형 앱솔루트 인코더는 각 비트를 별도의 트랙에서 읽는데, 트랙들의 전환 위치가 완벽하게 일치하지는 않으므로 경계에서 읽으면 이전 비트와 새 비트가 섞여 두 위치 모두와 동떨어진 값이 나올 수 있습니다. 그레이 코드에서는 한 단계마다 하나의 트랙만 바뀌므로, 경계에서 읽은 값은 이전 값이나 새 값 중 하나일 뿐이고 둘 다 한 단계 이내의 오차로 정확합니다.

비동기 FIFO의 그레이 코드 포인터

비동기 FIFO는 두 클록 도메인 사이에서 데이터를 전달하며, full과 empty 플래그를 계산하려면 각 쪽이 상대편의 읽기 또는 쓰기 포인터를 알아야 합니다. 2진 포인터를 동기화 플립플롭으로 전달하는 것은 안전하지 않습니다. 여러 비트가 동시에 바뀌어 서로 다른 클록 에지에서 캡처되면 존재한 적 없는 포인터 값이 만들어질 수 있기 때문입니다. 그레이 코드 포인터는 증가할 때마다 한 비트만 바뀌므로, 그 비트가 전환 도중에 캡처되더라도 수신 측은 이전 포인터나 새 포인터 중 하나를 얻습니다. 이 방식은 포인터가 클록당 1씩 증가하고 카운터가 2의 거듭제곱에서 순환할 때에만 성립합니다.

플래시 메모리와 카르노 맵의 그레이 코드

MLC(멀티 레벨 셀)와 TLC(트리플 레벨 셀) NAND 플래시는 2비트 또는 3비트를 4개 또는 8개의 문턱 전압 상태 중 하나로 저장합니다. 마모와 간섭으로 상태 분포가 넓어지며, 오독은 거의 항상 이웃한 상태로 일어납니다. TLC의 111, 110, 100, 101, 001, 000, 010, 011처럼 비트 패턴을 그레이 순서로 할당하면, 이러한 오독은 모두 1비트 오류가 되어 오류 정정 부호로 적은 비용으로 처리할 수 있습니다. 카르노 맵도 축에 같은 순서를 사용하여, 물리적으로 인접한 칸이 한 변수만 다르게 되어 묶을 수 있게 합니다.

정답과 해설 보기

정답: C. 이웃한 값 사이에서 1비트만 변화하는 부호

그레이 코드는 이웃한 값 사이에서 반드시 1비트만 변화하는 부호로, 2진수 B에서 B XOR (B >> 1)로 구할 수 있습니다. 여러 비트가 동시에 바뀌지 않으므로 로터리 인코더의 위치 검출이나, 서로 다른 클록으로 동작하는 회로 사이에서 FIFO 포인터를 주고받을 때 중간의 잘못된 값을 읽을 위험이 없습니다. 카르노 맵 칸의 배열도 그레이 코드 순입니다. 10진의 각 자리를 4비트로 나타내는 것은 BCD입니다.

비동기 FIFO에서 쓰기 포인터와 읽기 포인터를 그레이 코드로 변환한 후 상대 도메인으로 동기화하는 이유로 올바른 것은?

  1. A그레이 코드로 하면 비트 수가 절반이 되어 동기화기가 적게 들기 때문에
  2. B하나 증가할 때마다 1비트만 바뀌므로, 변화 도중에 캡처하더라도 증가 전이나 후의 올바른 값이 되기 때문에
  3. C그레이 코드 신호는 메타스테이블 상태가 되지 않으므로 동기화가 필요 없어지기 때문에
정답과 해설 보기

정답: B. 하나 증가할 때마다 1비트만 바뀌므로, 변화 도중에 캡처하더라도 증가 전이나 후의 올바른 값이 되기 때문에

바이너리 포인터는 예를 들어 0111에서 1000처럼 여러 비트가 동시에 바뀌므로, 각 비트를 따로 동기화하면 전혀 관계없는 값을 받는 경우가 있습니다. 그레이 코드라면 한 번 증가할 때 바뀌는 것은 1비트뿐이므로, 그 비트가 메타스테이블 상태가 되어 새 값과 이전 값 중 어느 쪽으로 정해지더라도 결과는 증가 전이나 증가 후의 값이 됩니다. 약간 오래된 값을 볼 뿐이므로 FIFO가 망가지지는 않습니다. 비트 수는 변하지 않으며, 메타스테빌리티 자체도 일어날 수 있으므로 동기화기는 필요합니다.

자주 묻는 질문

2진수를 그레이 코드로 어떻게 변환하나요?

2진수와 그것을 오른쪽으로 1비트 시프트한 값을 XOR합니다. 즉 G = B XOR (B >> 1)입니다. 최상위 비트는 그대로이고, 나머지 각 그레이 비트는 인접한 두 2진 비트의 XOR입니다.

클록 도메인 크로싱에서 FIFO 포인터를 그레이 코드로 하는 이유는 무엇인가요?

그레이 코드 포인터는 증가할 때마다 한 비트만 바뀌므로, 동기화기가 전환 도중에 샘플링해도 이전 값이나 새 값 중 하나를 얻습니다. 2진 포인터는 여러 비트가 한꺼번에 바뀔 수 있어 완전히 잘못된 값으로 캡처될 수 있습니다.

그레이 코드와 BCD의 차이는 무엇인가요?

그레이 코드는 연속한 값이 1비트만 다르도록 2진 패턴을 배열한 것입니다. BCD(2진화 10진수)는 10진수의 각 자릿수를 4비트로 따로 부호화한 것으로, 1비트만 변하는 성질이 없습니다.
