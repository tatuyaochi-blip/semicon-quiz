라이트 스루 방식(write-through)란?

캐시에 쓰는 동시에 하위 계층(주기억장치 등)에도 쓰는 방식. 하위 계층이 항상 최신으로 유지되지만 쓰기 통신량이 많아 쓰기 버퍼와 함께 쓴다.

일본어 명칭: ライトスルー方式

라이트 스루 방식(write-through)은(는) 메모리 계층 구조 등 1개 분야의 연습 문제 3개에 나와요.

분야: 메모리 계층 구조

라이트 스루 캐시의 스토어 처리

스토어 히트 시 라이트 스루 캐시는 자신의 사본을 갱신하는 동시에 L2 캐시나 주기억장치 같은 하위 계층에도 쓰기를 보냅니다. 따라서 라인이 더티 상태가 되는 일이 없어 더티 비트가 필요 없고, 하위 계층이 이미 같은 데이터를 갖고 있으므로 축출되는 라인은 그냥 버리면 됩니다. 스토어 미스 시 라이트 스루 캐시는 보통 노 라이트 얼로케이트를 사용해 라인을 읽어 들이지 않고 쓰기를 그대로 하위로 보냅니다. 어차피 나중에 라이트백할 필요가 없기 때문입니다.

쓰기 버퍼

모든 스토어가 메모리에 도달하기를 기다리면 CPU가 계속 정지하게 되므로, 쓰기는 쓰기 버퍼에 들어가고 CPU가 실행을 계속하는 동안 백그라운드에서 하위 계층으로 배출됩니다. CPU는 버퍼가 가득 찼을 때만 정지하며, 이는 메모리가 흡수할 수 있는 속도보다 빠르게 스토어가 도착할 때 발생합니다. 미스가 난 로드는 메모리에서 오래된 데이터를 읽지 않도록 버퍼를 확인하거나 버퍼가 비워질 때까지 기다려야 합니다. 버퍼는 같은 라인에 대한 여러 쓰기를 하나의 전송으로 병합하는 경우가 많습니다.

라이트 스루와 라이트백 비교

라이트백은 캐시만 갱신하고, 더티 라인은 축출될 때 한 번만 메모리에 씁니다. 따라서 같은 라인에 대한 반복 쓰기가 한 번의 전송으로 줄어듭니다. 이는 대역폭과 전력을 절약하므로 대부분의 CPU L1~L3 캐시는 라이트백입니다. 라이트 스루는 스토어마다 트래픽을 발생시키지만 하위 계층을 항상 최신으로 유지하므로, 다른 코어나 DMA와의 일관성 유지가 단순해지고 복구도 쉽습니다. 라이트 스루 L1은 간단한 패리티로 데이터를 보호하고 오류 시 깨끗한 사본을 다시 가져올 수 있습니다.

사용되는 곳

라이트 스루는 라이트백 L2가 뒤를 받치는 소형 1차 캐시, 단순한 임베디드 프로세서, 그리고 하위 계층이 모든 쓰기를 즉시 볼 필요가 있는 메모리 영역에 쓰입니다. 많은 아키텍처에서는 운영체제가 메모리 타입 속성을 통해 페이지 단위로 이를 선택할 수 있습니다. DRAM 앞의 마지막 캐시 계층에는 덜 적합한데, 라이트백 정책이라면 절약할 수 있는 메모리 대역폭을 스토어 트래픽이 소비하기 때문입니다.

라이트 스루 방식에서는 쓰기마다 주기억장치에도 쓰므로 그대로 완료를 기다리면 CPU가 자주 멈춥니다. 쓰기 버퍼에 쓰기를 임시로 모아 두면 CPU는 바로 다음 명령으로 넘어가고, 버퍼가 뒤에서 주기억장치로 내보냅니다. 캐시를 주기억장치보다 최신으로 유지하는 것은 라이트 백 방식의 성질이며, 라이트 스루에서는 오히려 양쪽이 일치합니다. 미스한 라인을 읽어 올지 여부는 라이트 얼로케이트의 선택이며 쓰기 버퍼와는 별개의 이야기입니다.

같은 라인에 여러 번 쓰는 처리에서 라이트 스루 방식보다 라이트 백 방식이 유리해지는 주된 이유는?

  1. A쓰기가 캐시 안에서 처리되고 주기억장치에는 쫓아낼 때 한 번만 쓰면 되기 때문
  2. B쓰기마다 주기억장치도 최신이 되므로 쫓아낼 때의 처리가 필요 없기 때문
  3. C캐시와 주기억장치의 내용이 항상 일치하므로 일관성 관리가 필요 없기 때문

정답: A. 쓰기가 캐시 안에서 처리되고 주기억장치에는 쫓아낼 때 한 번만 쓰면 되기 때문

라이트 백 방식에서는 같은 라인에 대한 여러 번의 쓰기를 캐시 안에서만 처리하고, 쫓아낼 때 더티인 라인을 한 번 되쓰기만 하면 됩니다. 따라서 주기억장치로의 통신량과 전력을 크게 줄일 수 있습니다. 쓰기마다 주기억장치도 최신으로 만드는 것은 라이트 스루 방식의 성질이며, 같은 라인에 여러 번 쓰면 그때마다 통신이 발생합니다. 캐시와 주기억장치가 항상 일치하는 것도 라이트 스루의 성질이며, 라이트 백에서는 일치하지 않는 기간이 있습니다.

자주 묻는 질문

라이트 스루와 라이트백 캐시 차이

라이트 스루는 스토어마다 하위 계층에 써서 하위 계층을 항상 최신으로 유지합니다. 라이트백은 캐시에만 쓰고, 수정된 라인이 축출될 때 한 번만 하위 계층을 갱신하므로 트래픽이 줄어듭니다.

라이트 스루 캐시에 쓰기 버퍼가 필요한 이유

쓰기 버퍼가 없으면 CPU는 느린 메모리에서 모든 스토어가 완료되기를 기다려야 합니다. 버퍼가 쓰기를 대기열에 넣어 두므로 백그라운드에서 배출되는 동안 CPU는 실행을 계속할 수 있습니다.

라이트 스루 캐시에 더티 비트가 필요한가요

필요 없습니다. 모든 쓰기가 즉시 전파되므로 라인이 하위 계층과 달라지는 일이 없어, 아무것도 되쓰지 않고 축출할 수 있습니다.
