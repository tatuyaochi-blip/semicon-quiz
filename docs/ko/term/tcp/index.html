TCP(전송 제어 프로토콜)란?

Transmission Control Protocol의 약자. 전송 계층의 연결형 프로토콜. 3-way 핸드셰이크로 연결을 설정하고, 시퀀스 번호, 확인 응답(ACK), 재전송을 통해 데이터를 빠짐이나 중복 없이 보낸 순서대로 전달한다. 흐름 제어와 혼잡 제어로 보내는 양도 조절한다. 웹 접속(HTTP/1.1·HTTP/2), 메일, SSH 등이 사용한다.

일본어 명칭: TCP

TCP(전송 제어 프로토콜)은(는) 네트워크 기초, 네트워크 설계와 운용, 웹 기술 기초 등 3개 분야의 연습 문제 21개에 나와요.

분야: 네트워크 기초

확실하게 전달하는 원리

TCP는 보내는 데이터의 1바이트마다 일련번호(시퀀스 번호)를 붙입니다. 수신 측은 '다음에는 이 번호부터 보내 주세요'라는 확인 응답(ACK)을 돌려보내고, 송신 측은 정해진 시간 안에 ACK가 오지 않으면 그 데이터를 다시 보냅니다(재전송 타임아웃). 같은 번호의 ACK(중복 ACK)를 3개 받았을 때는 타임아웃을 기다리지 않고 재전송합니다(빠른 재전송). 수신 측은 순서가 바뀌어 도착한 데이터를 다시 정렬하고, 중복을 버리며, 체크섬으로 손상된 데이터를 찾아냅니다. 애플리케이션에서는 구분이 없는 바이트의 흐름(스트림)으로 보입니다.

윈도로 보내는 양을 정한다

송신 측은 ACK를 기다리지 않고 보내도 되는 양(윈도)만큼 데이터를 연이어 보냅니다. 수신 측이 알려 주는 빈 버퍼의 크기(수신 윈도)에 맞추는 것이 흐름 제어, 네트워크의 혼잡 정도에 맞춰 송신 측이 가진 혼잡 윈도를 늘리고 줄이는 것이 혼잡 제어이며, 실제로는 둘 중 작은 쪽까지 보냅니다. 1왕복 시간(RTT)에 보낼 수 있는 것은 윈도만큼이므로 처리량은 대략 윈도÷RTT가 됩니다. 예를 들어 윈도 64 KB, RTT 100 ms에서는 약 5 Mbit/s가 상한이며, 빠른 회선을 살리려면 윈도 스케일 옵션으로 윈도를 크게 합니다.

헤더와 연결 관리

TCP 헤더는 옵션 없이 20바이트입니다. 출발지와 목적지의 포트 번호, 시퀀스 번호, 확인 응답 번호, SYN·ACK·FIN·RST 등의 플래그, 윈도 크기, 체크섬이 들어갑니다. 하나의 연결은 출발지와 목적지의 IP 주소와 포트 번호 4개의 조합으로 구별됩니다. 연결은 3-way 핸드셰이크로 시작하고, 양방향이 각각 FIN을 보내 닫습니다. 세그먼트 하나가 손실되면 뒤의 데이터가 도착해 있어도 애플리케이션에 넘기지 못하고 기다리게 되므로(HOL 블로킹, head-of-line blocking), HTTP/3에서는 UDP 위의 QUIC가 쓰입니다.

정답: C. 전송 계층

TCP/IP 모델은 아래에서부터 링크 계층(네트워크 인터페이스 계층), 인터넷 계층, 전송 계층, 응용 계층의 4개 계층으로 나타냅니다. TCP와 UDP는 전송 계층의 프로토콜로, 포트 번호를 사용하여 단말 안의 어느 애플리케이션으로 가는 통신인지를 구별합니다. 인터넷 계층의 IP는 단말에서 단말까지 패킷을 전달하는 일을 담당합니다. HTTP와 DNS는 응용 계층의 프로토콜입니다. OSI 참조 모델에 대응시키면 전송 계층은 4계층, 인터넷 계층은 3계층에 해당합니다.

TCP에서 연결을 설정하는 3-way 핸드셰이크에서 주고받는 패킷의 순서로 올바른 것은?

  1. ASYN → ACK → FIN
  2. BACK → SYN → SYN+ACK
  3. CSYN → SYN+ACK → ACK
정답과 해설 보기

정답: C. SYN → SYN+ACK → ACK

3-way 핸드셰이크에서는 먼저 클라이언트가 SYN으로 연결을 요청하면서 자신이 보낼 데이터의 첫 번호(초기 시퀀스 번호)를 알립니다. 서버는 SYN+ACK로 그것을 받았음을 확인(ACK)하는 동시에 자신의 초기 시퀀스 번호를 알립니다. 마지막으로 클라이언트가 ACK를 돌려보내면 양방향 통신의 준비가 갖추어집니다. 세 번의 교환으로 양쪽 방향의 번호를 서로 확인함으로써, 늦게 도착한 오래된 패킷으로 인한 잘못된 연결 등을 막습니다. 이 때문에 TCP에서는 데이터를 보내기 시작할 때까지 적어도 1왕복 시간(RTT)이 걸립니다. FIN은 연결을 종료할 때 사용합니다.

자주 묻는 질문

TCP와 UDP의 차이는 무엇인가요?

TCP는 연결을 설정하고, 확인 응답과 재전송, 순서 제어로 데이터를 확실하게 전달합니다. UDP는 연결 절차도 재전송도 없이 데이터그램을 보내기만 하므로 헤더가 작고 지연도 적습니다. 확실성이 필요한 웹이나 파일 전송에는 TCP, 약간의 손실보다 지연이 적은 것이 중요한 통화나 질의가 짧은 DNS에는 UDP가 쓰입니다.

TCP의 재전송은 언제 일어나나요?

두 가지 계기가 있습니다. 하나는 보낸 뒤 재전송 타임아웃 시간(RTT 측정으로 계산)이 지나도 ACK가 오지 않을 때, 또 하나는 같은 확인 응답 번호의 ACK를 3개 연속으로 받았을 때이며, 후자를 빠른 재전송이라고 부릅니다. 재전송이 계속되면 타임아웃 시간을 2배씩 늘립니다.

TCP의 처리량이 회선 속도보다 낮은 이유는 무엇인가요?

1왕복 시간(RTT)에 보낼 수 있는 것은 윈도 크기까지이므로, 상대가 멀수록, 윈도가 작을수록 처리량이 떨어집니다. 패킷 손실로 혼잡 제어가 윈도를 줄였을 때나 수신 측 애플리케이션의 읽기가 느릴 때도 떨어집니다.

이 용어가 포함된 비교

  • TCP와 UDP의 차이: 연결·신뢰성·순서·혼잡 제어·헤더·지연·용도 비교TCP와 UDP를 한 장의 표로 비교합니다. 연결 수립, 확인 응답과 재전송, 순서, 데이터 경계, 흐름 제어와 혼잡 제어, 헤더 크기, 지연, 전송 대상의 종류와 대표 용도를 정리합니다.
  • OSPF와 BGP의 차이: IGP와 EGP·경로 선택 방식·이웃 라우터와의 연결 방식·규모 비교OSPF와 BGP를 한 장의 표로 비교합니다. 분류와 범위(IGP와 EGP), 프로토콜 방식, 경로 선택, 루프 방지, 이웃과의 연결 방식, 갱신 방식, 수렴 속도, 다루는 경로 수를 정리합니다.
