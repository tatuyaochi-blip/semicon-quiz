어셈블러(Assembler)란?

어셈블리 언어로 작성한 프로그램을 기계어 명령의 비트열로 변환하는 소프트웨어. 레이블을 주소로 바꾸고 의사 명령을 실제 명령으로 치환한다.

일본어 명칭: アセンブラ

어셈블러(Assembler)은(는) ISA와 어셈블리, 컴파일러 등 2개 분야의 연습 문제 6개에 나와요.

분야: ISA와 어셈블리

니모닉에서 비트 패턴으로

어셈블러는 어셈블리 소스를 한 줄씩 읽습니다. 각 명령에 대해 니모닉을 찾고, 피연산자를 검사하고, 오피코드, 레지스터 번호, 즉치값을 명령어 포맷의 고정된 필드에 채워 넣습니다. 예를 들어 32비트 RISC-V 워드가 그렇습니다. .text, .data, .word, .globl 같은 지시어(디렉티브)는 어느 섹션에 출력할지, 어떤 데이터를 배치할지, 어떤 심볼을 외부에 공개할지를 지정합니다. 어셈블리는 기계어 명령과 거의 일대일로 대응하므로, 명령어 세트 아키텍처(ISA)마다 고유한 어셈블리 언어가 있습니다.

레이블, 심볼, 2패스

레이블을 사용하면 프로그래머는 숫자 주소 대신 분기 대상과 데이터 이름을 쓸 수 있습니다. 레이블은 정의되기 전에 사용될 수 있으므로, 전통적인 어셈블러는 2패스로 동작합니다. 첫 번째 패스에서 소스를 훑으며 모든 레이블에 주소를 할당하고 심볼 테이블을 만들고, 두 번째 패스에서 그 주소를 사용해 각 명령을 인코딩합니다. 같은 섹션 내 레이블까지의 거리는 바로 채워 넣습니다. 다른 파일의 심볼이나 최종 배치에 따라 달라지는 주소에 대한 참조는 아직 해결할 수 없으므로, 어셈블러는 자리 표시자를 남기고 출력 오브젝트 파일에 링커를 위한 재배치 엔트리를 기록합니다.

의사 명령과 확장

어셈블러는 하드웨어에 존재하지 않는 편리한 의사 명령을 받아들입니다. RISC-V에서 nop은 addi x0, x0, 0으로, mv rd, rs는 addi rd, rs, 0으로, j label은 jal x0, label로, ret은 jalr x0, 0(ra)로 바뀝니다. li는 임의의 상수를 로드합니다. 작은 값은 addi 하나로 충분하지만, 32비트 전체 값은 상위 20비트용 lui와 하위 12비트용 addi가 되며, addi는 즉치값을 부호 확장하므로 하위 부분이 음수이면 상위 부분을 1만큼 조정합니다. 어셈블러는 또한 대상이 약 4 KiB의 도달 범위를 벗어난 조건 분기를, jal을 건너뛰는 반전된 분기로 다시 쓰기도 합니다.

어셈블러와 컴파일러, 링커, 디스어셈블러

컴파일러는 고급 언어를 번역하며, 한 문장이 여러 명령이 될 수 있고 레지스터와 최적화에 관한 실질적인 결정이 대응 과정에 포함됩니다. 어셈블러는 그런 선택을 거의 하지 않으며, 그 역할은 인코딩, 레이블 해결, 의사 명령 확장입니다. 출력은 실행 가능한 프로그램이 아니라 오브젝트 파일이며, 링커가 여전히 오브젝트 파일과 라이브러리를 결합하고 최종 주소를 확정해야 합니다. 디스어셈블러는 비트 패턴을 니모닉으로 되돌리는 역변환을 수행하지만, 주석은 복원할 수 없고 심볼 테이블이 없으면 원래 레이블 이름도 복원할 수 없습니다.

도전해 보기: 어셈블러(Assembler) 관련 문제

RISC-V의 의사 명령어 'nop'(아무것도 하지 않음)은 어셈블러에 의해 실제로 어떤 명령어로 치환되는가?

  1. Aaddi x0, x0, 0
  2. Bjal ra, 0
  3. Clw x0, 0(sp)
정답과 해설 보기

정답: A. addi x0, x0, 0

RISC-V에는 '아무것도 하지 않는' 전용 명령어가 없으며, nop은 'addi x0, x0, 0'으로 표현됩니다. x0에 대한 쓰기는 버려지므로 레지스터도 메모리도 아무것도 바뀌지 않습니다. 마찬가지로 'mv rd, rs'는 'addi rd, rs, 0', 'j label'은 'jal x0, label', 'ret'은 'jalr x0, 0(ra)'입니다. x0을 활용해 명령어의 종류를 적게 유지하는 것이 RISC-V의 설계 사상입니다.

자주 묻는 질문

어셈블러와 컴파일러의 차이

컴파일러는 C 같은 고급 언어를 어셈블리나 기계어로 번역하며 레지스터 사용과 최적화에 관한 결정을 내립니다. 어셈블러는 어셈블리 언어를 거의 일대일로 기계어로 번역하며, 주로 명령을 인코딩하고 레이블을 주소로 바꿉니다.

어셈블리 언어의 의사 명령이란?

하드웨어가 직접 구현하지 않는 편리한 니모닉으로, 어셈블러가 하나 이상의 실제 명령으로 대체합니다. 예를 들어 RISC-V에서 nop은 addi x0, x0, 0으로 어셈블되고, li는 lui 다음에 addi가 오는 형태가 될 수 있습니다.

어셈블러가 실행 파일을 만드나요?

보통은 아닙니다. 어셈블러는 기계어, 심볼 테이블, 재배치 엔트리를 담은 오브젝트 파일을 만들고, 링커가 하나 이상의 오브젝트 파일을 실행 파일로 만듭니다.

해설 속 어셈블러(Assembler)

  • 어셈블리 언어는 기계어 명령어를 'add a0, a0, a1'과 같은 사람이 읽을 수 있는 기호(니모닉)로 쓴 것이며, 어셈블러가 명령어의 비트열로 변환합니다.

    어셈블리 언어와 기계어의 관계로 올바른 것은?

  • 어셈블리에서 'li a0, 0x12345678'이라고 쓰면 어셈블러가 필요에 따라 이 2개의 명령어로 전개합니다.

    RISC-V에서 12비트 즉치값에 들어가지 않는 32비트 상수(예: 0x12345678)를 레지스터에 넣는…

  • 하위 12비트의 비트 11이 1일 때 상위에 1을 더해 둔다는 이 보정은 어셈블러나 링커가 자동으로 수행합니다.

    RISC-V에서 상수 0x12345FFF를 lui와 addi의 2개 명령어로 만들 때 올바른 조합은?

  • 이보다 먼 분기는 조건을 반전시킨 짧은 분기로, 멀리 닿는 jal(약 ±1MiB)을 건너뛰는 형태로 어셈블러가 고쳐 씁니다.

    RISC-V의 조건 분기 명령어(B 형식)는 분기 대상까지의 거리를 13비트 부호 있는 바이트 수로 나타내…

  • C 언어 소스 파일은 먼저 컴파일러에서 기계어에 가까운 어셈블리 언어(또는 직접 오브젝트 파일)로 변환되고, 어셈블러에서 기계어 오브젝트 파일이 됩니다.

    C 언어 프로그램에서 실행 파일이 만들어지기까지의 일반적인 흐름으로 올바른 것은 무엇인가?

  2. 어셈블리 언어와 기계어의 관계로 올바른 것은?

  4. RISC-V에서 상수 0x12345FFF를 lui와 addi의 2개 명령어로 만들 때 올바른 조합은?
  5. RISC-V의 조건 분기 명령어(B 형식)는 분기 대상까지의 거리를 13비트 부호 있는 바이트 수로 나타내며, 그 최하위 비트는 항상 0이므로 명령어에 넣지 않는다. 분기 명령어가 직접 닿는 범위로 대략 올바른 것은?
