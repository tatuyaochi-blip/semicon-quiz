풀 연관 방식(Fully Associative)란?

어떤 데이터든 캐시 내 어느 위치에나 둘 수 있는 캐시 구성. 충돌 미스는 일어나지 않지만 모든 태그와 비교해야 하므로 큰 캐시에는 적합하지 않다. TLB 등에 쓰인다.

일본어 명칭: フルアソシアティブ方式

분야: 메모리 계층 구조

인덱스 없이 태그와 오프셋만

풀 연관 캐시에서는 캐시 전체가 하나의 세트이므로 어떤 블록이든 어느 라인에나 저장할 수 있습니다. 세트를 선택하는 비트가 필요 없어 인덱스는 0비트이고, 주소는 라인 안의 오프셋과 나머지 모든 비트로 이루어진 태그로만 나뉩니다. 접근할 때마다 요청한 태그를 모든 유효 라인의 태그와 동시에 비교해야 하며, 이는 보통 각 엔트리가 자체 비교기를 가진 내용 주소화 메모리(CAM)로 구현합니다.

작은 구조에만 쓰이는 이유

엔트리가 N개인 CAM은 조회할 때마다 동작하는 넓은 비교기 N개와 일치한 데이터를 내보내는 큰 멀티플렉서가 필요합니다. 엔트리 수에 따라 면적, 전력, 히트 시간이 빠르게 증가하므로 큰 데이터 캐시는 대신 세트 연관 방식을 사용합니다. 풀 연관은 사용 빈도가 높고 미스 하나하나의 비용이 큰 작은 구조에서 감당할 만하고 가치가 있습니다. 예를 들어 페이지 테이블 엔트리를 캐시하는 변환 색인 버퍼(TLB)나, 다이렉트 매핑 캐시에서 최근 축출된 라인을 담는 작은 희생 캐시가 있습니다.

성능을 좌우하는 교체 정책

어떤 라인이든 축출될 수 있으므로 캐시에는 교체 정책이 필요합니다. LRU(least recently used)는 가장 오랫동안 접근되지 않은 라인을 축출합니다. 라인이 2개이고 참조열이 A, B, A, C, B, A일 때 LRU는 미스 5회를 냅니다. A의 히트로 C가 들어올 때 B가 희생되고, 이어서 A와 C가 차례로 축출됩니다. 엔트리가 많으면 진정한 LRU를 추적하는 비용이 커지므로 하드웨어는 흔히 의사 LRU(pseudo-LRU)나 랜덤 교체를 사용합니다. LRU는 캐시보다 약간 큰 순환 패턴에서도 성능이 나쁘며, 이때는 랜덤이 더 나을 수 있습니다.

풀 연관으로도 해결되지 않는 것

풀 연관은 블록이 특정 세트를 두고 경쟁하지 않으므로 충돌 미스를 없앱니다. 일반적인 3분류 모델에서 충돌 미스는 사실 같은 크기의 풀 연관 캐시라면 피할 수 있는 미스로 정의됩니다. 첫 접근 시의 강제 미스와, 작업 집합이 캐시 전체보다 클 때의 용량 미스는 남습니다. 이를 해결하려면 더 큰 캐시, 프리페치, 또는 루프 블로킹(타일링)처럼 데이터를 더 빨리 재사용하도록 코드를 재구성해야 합니다.

자주 묻는 질문

풀 연관 캐시의 인덱스 비트는 몇 비트인가요?

0비트입니다. 캐시 전체가 하나의 세트이므로 주소는 태그와 오프셋으로만 이루어지며, 태그를 모든 라인과 비교합니다.

TLB가 풀 연관 방식인 경우가 많은 이유는?

TLB는 작고 미스가 날 때마다 비용이 큰 페이지 테이블 워크가 필요하므로, 충돌 미스를 완전히 피하기 위해 추가 비교기를 둘 가치가 있기 때문입니다.

풀 연관 캐시는 모든 미스를 없애나요?

아닙니다. 충돌 미스는 없애지만, 첫 사용 시의 강제 미스와 작업 집합이 캐시보다 클 때의 용량 미스는 여전히 발생합니다.
