비순차 실행(Out-of-Order Execution)란?

명령의 의존 관계를 조사하여 실행 가능한 명령부터 프로그램 순서와 다른 순서로 실행해 성능을 높이는 방식. 결과는 리오더 버퍼에서 본래 순서대로 확정한다.

일본어 명칭: アウトオブオーダー実行

비순차 실행(Out-of-Order Execution)은(는) CPU와 아키텍처, ISA와 어셈블리, 메모리 계층 구조 등 3개 분야의 연습 문제 7개에 나와요.

분야: CPU와 아키텍처

비순차 실행의 원리

프런트엔드는 여전히 프로그램 순서대로 명령어를 인출하고 해독합니다. 그 후 각 명령어는 리네이밍되고, 리오더 버퍼(ROB)에 항목을 할당받아 이슈 큐에 놓입니다. 스케줄링 로직은 소스 피연산자가 준비된 명령어를 감시하다가, 프로그램 내 위치와 관계없이 비어 있는 실행 유닛으로 보냅니다. 느린 로드를 기다리는 명령어는 옆에 대기하고, 그동안 뒤쪽의 독립적인 명령어가 실행됩니다. 결과는 ROB가 명령어를 원래 순서대로 리타이어할 때까지 보관되므로, 소프트웨어에서는 순차 머신과 똑같은 동작으로 보입니다. 고성능 코어에서 이 윈도우는 수백 개의 명령어에 걸칩니다.

레지스터 리네이밍과 순차 커밋

프로그램은 적은 수의 아키텍처 레지스터를 재사용하므로 거짓 의존이 생깁니다. 뒤의 쓰기가 같은 레지스터에 대한 앞의 읽기나 쓰기를 앞지르면 안 되기 때문입니다. 레지스터 리네이밍은 새 값마다 새로운 물리 레지스터를 할당하여, 명령어가 실제로 다른 명령어가 계산한 값을 필요로 하는 진짜 데이터 의존만 남깁니다. ROB를 통한 순차 커밋은 정확한 예외를 보장하고, 코어가 예측된 분기 너머까지 실행하다가 예측 실패 시 잘못된 경로의 작업을 버릴 수 있게 합니다. 여기서는 ISA의 세부 사항이 중요합니다. RV64I가 lw 결과를 레지스터 전체로 부호 확장하는 것은 바로 상위 비트가 레지스터의 이전 값에 결코 의존하지 않도록 하기 위해서입니다.

메모리 지연 숨기기

가장 큰 효과는 캐시 미스 동안 나타납니다. 순차 실행 코어는 미스가 난 로드 뒤에서 멈추지만, 비순차 실행 코어는 계속 독립적인 작업을 찾아내고, 첫 번째 미스와 겹치는 추가 로드를 발행할 수 있습니다. 이를 위해서는 미처리 미스를 MSHR(miss status holding register)로 추적하면서 그동안 히트를 계속 처리하는 논블로킹 캐시가 필요합니다. 미스 횟수와 각 미스의 지연은 변하지 않지만, 겹치게 함으로써 비용의 상당 부분을 숨깁니다. 슈퍼스칼라 발행, 분기 예측, 대용량 캐시와 함께 이것이 IPC(클록당 명령어 수)를 높이며, 성능은 IPC와 주파수의 곱에 비례합니다.

비순차 실행과 슈퍼스칼라, 그리고 비용

슈퍼스칼라는 사이클당 여러 명령어를 발행하는 폭을 말하고, 비순차 실행은 명령어가 실행되는 순서를 말합니다. 코어는 순차 실행 슈퍼스칼라일 수도 있으며, 최근의 고성능 코어는 약 6~10 명령어 폭으로 둘을 결합합니다. 비용은 큽니다. 의존성 검사는 대략 폭의 제곱에 비례해 늘어나고, 리네이밍 테이블, 웨이크업 로직, ROB가 모든 명령어에 면적과 에너지를 더합니다. 그래서 스마트폰 SoC의 효율 코어는 더 작고 단순하며, GPU는 그 실리콘을 대신 처리량을 위한 다수의 단순한 연산 유닛에 씁니다.

정답: A. 리오더 버퍼

리오더 버퍼는 순서를 바꿔 실행된 명령어의 결과를 일시적으로 보관했다가 프로그램 순서대로 확정(리타이어)시키는 구조이며, 최근 고성능 코어에서는 수백 명령어 분량의 크기입니다. 분기 예측 실패나 예외가 발생했을 때 그 이후 명령어의 결과를 버리고 올바른 상태로 되돌릴 수 있어, 외부에서 보면 프로그램대로 실행된 것처럼 보입니다(정확한 예외).

비순차 실행 CPU에서 사용되는 레지스터 리네이밍의 주된 목적은?

  1. A레지스터 수를 줄여 회로를 작게 한다
  2. B프로그램이 쓰는 레지스터 이름은 바꾸지 않고 물리 레지스터를 다시 할당하여 겉보기 의존(WAR, WAW)을 제거한다
  3. C레지스터 값을 암호화한다
정답과 해설 보기

정답: B. 프로그램이 쓰는 레지스터 이름은 바꾸지 않고 물리 레지스터를 다시 할당하여 겉보기 의존(WAR, WAW)을 제거한다

명령어 세트의 레지스터 수는 16~32개 정도로 한정되어 있어 같은 레지스터 이름이 재사용되고, 실제 데이터 흐름과는 무관한 의존(역의존 WAR, 출력 의존 WAW)이 생깁니다. 레지스터 리네이밍은 수백 개의 물리 레지스터를 동적으로 할당하여 쓰기마다 새로운 물리 레지스터를 사용함으로써 이를 제거하고 병렬로 실행할 수 있는 명령어를 늘립니다. 진짜 의존(RAW)은 제거할 수 없습니다.

자주 묻는 질문

비순차 실행과 슈퍼스칼라 차이

슈퍼스칼라는 클록당 여러 명령어를 발행하는 것이고, 비순차 실행은 의존 관계가 허락할 때 프로그램 순서와 다른 순서로 실행하는 것입니다. 둘은 독립적인 개념이며, 고성능 코어는 보통 둘을 결합합니다.

비순차 실행 CPU에 리오더 버퍼가 필요한 이유

명령어는 순서와 다르게 끝나지만, 예외를 정확하게 처리하고 예측이 빗나간 작업을 버릴 수 있도록 아키텍처 상태는 프로그램 순서대로 갱신되어야 합니다. 리오더 버퍼는 각 명령어가 순서대로 리타이어할 수 있을 때까지 결과를 보관합니다.

비순차 실행으로 캐시 미스가 줄어드나요?

아닙니다. 미스를 처리하는 동안 다른 미스를 병렬로 발행하는 것을 포함한 독립적인 작업을 수행하여 미스 지연을 숨길 뿐이며, 미스 횟수는 그대로입니다.
