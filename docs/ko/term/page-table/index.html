페이지 테이블(Page Table)란?

가상 주소의 페이지 번호에서 물리 주소의 페이지 번호로의 대응을 기록한 표. OS가 프로세스마다 만들고 CPU의 MMU가 참조하여 주소를 변환한다. 각 항목에는 보호를 위한 비트도 포함된다.

페이지 테이블의 역할로 올바른 것은?

  1. A가상 주소의 페이지 번호를 물리 주소의 페이지 번호에 대응시킨다
  2. B물리 메모리에 있는 데이터의 내용을 페이지별로 복제하여 저장한다
  3. C실행 중인 프로세스의 우선순위를 페이지 순서대로 정렬하여 관리한다
정답과 해설 보기

정답: A. 가상 주소의 페이지 번호를 물리 주소의 페이지 번호에 대응시킨다

가상 메모리에서는 프로그램이 사용하는 가상 주소를 실제 물리 메모리의 주소로 변환하여 사용합니다. 페이지 테이블은 가상 페이지 번호마다 대응하는 물리 페이지 번호와 읽기·쓰기 허가 등의 보호 정보를 기록한 표로, OS가 프로세스마다 만들고 CPU의 MMU가 참조합니다. 자주 쓰는 변환 결과는 TLB에 보관됩니다. 데이터 내용 자체를 복제하거나 프로세스 우선순위를 관리하는 표가 아닙니다.

페이지 테이블을 1단이 아니라 다단(계층형)으로 하는 주된 이유는?

  1. A사용하지 않는 범위의 표를 생략할 수 있어 페이지 테이블의 메모리를 절약할 수 있기 때문에
  2. B주소 변환 시마다 읽는 표의 수가 줄어 TLB 미스 처리가 빨라지기 때문에
  3. C물리 메모리 용량을 가상 주소 공간보다 크게 할 수 있기 때문에
정답과 해설 보기

정답: A. 사용하지 않는 범위의 표를 생략할 수 있어 페이지 테이블의 메모리를 절약할 수 있기 때문에

1단 페이지 테이블에서는 사용 여부와 관계없이 가상 주소 공간의 모든 페이지 몫의 항목이 필요하여, 64비트 환경에서는 표가 거대해집니다. 다단으로 하면 사용 중인 범위의 하위 표만 만들고 사용하지 않는 범위는 상위 표의 항목을 무효로 해 둘 수 있어, 프로그램이 사용하는 양에 맞는 메모리로 충분합니다. 그 대신 TLB 미스 때 거치는 표의 수가 단수만큼 늘어 느려집니다. 물리 메모리의 크기와는 관계가 없습니다.

  2. 페이지 테이블을 1단이 아니라 다단(계층형)으로 하는 주된 이유는?
  3. 가상 주소가 32비트, 페이지 크기가 4 KB, 페이지 테이블 1항목이 4바이트일 때 1단 페이지 테이블의 크기는 얼마입니까?
  4. 가상 주소 중 48비트를 사용하고, 페이지 크기 4 KB, 각 단의 표가 512항목(9비트)인 다단 페이지 테이블에서는 몇 단의 표를 거쳐야 합니까?
  5. 페이지 테이블의 각 항목에 보통 포함되는 정보의 조합으로 올바른 것은?
  6. 게스트도 호스트도 4단 페이지 테이블을 사용하는 중첩 페이징에서 TLB 미스가 일어났을 때 최악의 경우 몇 번의 메모리 접근이 필요합니까?
  7. 많은 OS에서 커널 영역을 각 프로세스 주소 공간의 일부(예를 들어 상위 범위)에 할당해 두고 페이지 테이블의 보호 비트로 사용자 모드로부터의 접근을 금지합니다. 이 배치의 주된 장점은?
  8. 여러 코어를 가진 시스템에서 OS가 어떤 페이지의 페이지 테이블 항목을 재작성하여 대응을 취소했을 때 필요한 처리로 올바른 것은?
  9. Meltdown에 대한 소프트웨어 대책으로 도입된 KPTI(커널 페이지 테이블 격리)의 개념으로 올바른 것은 무엇입니까?
  10. 가상 주소에서 물리 주소로의 변환 결과를 보관하여 주소 변환을 고속화하는 캐시는?
  11. 메모리 페이지에 '쓰기 가능'과 '실행 가능'을 동시에 허용하지 않는 것(W^X, 쓰기와 실행의 분리)으로 막기 쉬워지는 공격은 무엇입니까?
  12. CPU에 특권 모드(커널 모드)와 사용자 모드를 두는 주된 목적은?
  13. 페이지 폴트가 일어나는 경우로 올바른 것은?
  14. 내보내져 디스크에 있는 페이지에 접근하여 페이지 폴트가 일어났을 때 OS가 수행하는 처리 흐름으로 올바른 것은?
  15. 프로세스를 복제할 때 카피 온 라이트를 사용하는 장점으로 올바른 것은?
