클록 스큐(Clock Skew)란?

같은 클록 신호가 플립플롭마다 도착하는 시각의 차이. 셋업·홀드 여유를 바꾸므로 클록 트리 합성에서 작게 억제한다.

일본어 명칭: クロックスキュー

클록 스큐(Clock Skew)은(는) 논리 회로 등 1개 분야의 연습 문제 1개에 나와요.

분야: 논리 회로

스큐가 생기는 원인

동기 회로에서는 하나의 클록 소스가 배선과 버퍼로 이루어진 네트워크를 통해 수천에서 수백만 개의 플립플롭에 공급됩니다. 배선 길이, 배선 저항과 커패시턴스, 버퍼 부하의 차이, 그리고 공정·전압·온도의 국소적 변동 때문에 같은 클록 에지가 플립플롭마다 조금씩 다른 시각에 도착합니다. 이러한 도착 시각의 공간적 차이가 클록 스큐입니다. 한 지점에서 사이클마다 클록 에지 타이밍이 변동하는 지터(jitter)와 혼동해서는 안 됩니다. 타이밍에서 중요한 것은 서로 데이터를 주고받는 플립플롭 쌍 각각의 스큐입니다.

셋업과 홀드에 미치는 영향

스큐를 캡처 클록의 도착 시각에서 런치 클록의 도착 시각을 뺀 값으로 정의합니다. 캡처 클록이 늦으면 데이터에 시간이 더 주어지므로 셋업에 유리하며, 조건은 주기 + 스큐 ≥ 클록-출력 지연 + 로직 지연 + 셋업 시간이 됩니다. 주기 2.0 ns, 클록-출력 지연 0.2 ns, 로직 1.4 ns, 셋업 0.1 ns이면 슬랙은 스큐 0에서 0.3 ns, 양의 스큐 0.1 ns에서 0.4 ns입니다. 그러나 같은 늦은 캡처는 홀드에 불리합니다. 캡처 플립플롭이 이전 데이터를 래치하기 전에 새 데이터가 덮어쓸 수 있기 때문입니다. 최소 클록-출력 지연과 최소 로직 지연의 합이 홀드 시간과 스큐의 합보다 커야 합니다.

클록 트리 합성으로 스큐 제어

클록 트리 합성(CTS)은 칩 전체의 분배 네트워크를 구성하며, 버퍼 위치를 정하고 배선 길이와 부하를 균형 있게 맞춰 스큐를 수십 피코초 이내로 유지합니다. 대표적인 구조로는 대칭형 H-트리, 버퍼 트리, 많은 분기를 서로 단락시키는 격자형 클록 메시가 있습니다. 이후 정적 타이밍 분석이 실제 계산된 클록 도착 시각으로 모든 경로를 검사하고, 온칩 변동에 대한 디레이팅을 추가합니다. 설계자는 때때로 의도적인 스큐, 즉 유용한 스큐(useful skew)를 도입하여 크리티컬 경로의 캡처 클록을 지연시키고, 여유가 있는 인접 경로에서 시간을 빌려오기도 합니다.

홀드 위반이 위험한 이유

셋업 위반은 제조 후에도 클록 주파수를 낮춰 해결할 수 있습니다. 주기가 길어지면 데이터에 시간이 더 주어지기 때문입니다. 홀드 위반은 그렇게 할 수 없습니다. 홀드 조건에는 클록 주기가 전혀 포함되지 않으며, 같은 사이클 안에서 새 데이터와 클록 에지 사이의 경쟁이기 때문입니다. 그래서 스큐로 인한 홀드 문제는 테이프아웃 전에 짧은 경로에 지연 버퍼를 삽입하여 해결합니다. 보드 수준에서도 칩 간 인터페이스에 같은 계산이 적용되며, 클록 스큐와 지터를 타이밍 예산에서 빼야 합니다.

정답: B. 클록 신호가 플립플롭마다 도착하는 시각의 차이

클록 스큐는 같은 클록이 배선 길이나 부하의 차이로 플립플롭마다 서로 다른 시각에 도착하는 차이입니다. 수신 측 클록이 늦어지면 셋업에는 유리하지만 홀드에는 불리하며, 반대의 경우도 마찬가지입니다. 칩 전체에 도달하는 클록 트리를 CTS(클록 트리 합성)로 설계하고, 버퍼 배치와 배선 길이를 맞추어 스큐를 수십 ps 이하로 억제합니다. 주기의 시간적 흔들림은 지터입니다.

자주 묻는 질문

클록 스큐와 클록 지터의 차이는 무엇인가요?

스큐는 같은 사이클에서 서로 다른 위치 간 클록 도착 시각의 차이이고, 지터는 한 위치에서 사이클마다 클록 에지 시각이 변동하는 것입니다.

클록 스큐는 항상 나쁜가요?

아닙니다. 양의 스큐는 경로에 셋업 시간을 더 주며, 설계자는 타이밍 균형을 위해 의도적인 유용한 스큐를 추가하기도 합니다. 다만 셋업에 도움이 되는 스큐는 같은 경로의 홀드 여유를 줄입니다.

홀드 위반을 클록을 느리게 해서 고칠 수 있나요?

아닙니다. 홀드 타이밍은 클록 주기에 의존하지 않으므로, 짧은 데이터 경로에 지연을 추가하거나 스큐를 줄여서 해결해야 합니다.
