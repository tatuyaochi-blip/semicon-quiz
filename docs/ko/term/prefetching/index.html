프리페치(Prefetch)란?

가까운 시일 안에 필요할 것 같은 데이터를 요청되기 전에 캐시로 읽어 들여 두는 것. 하드웨어가 접근의 규칙성을 찾아 수행하는 방식과 명령으로 지시하는 소프트웨어 방식이 있다.

일본어 명칭: プリフェッチ

프리페치(Prefetch)은(는) 메모리 계층 구조, DRAM, 자료 구조와 알고리즘 등 4개 분야의 연습 문제 11개에 나와요.

분야: 메모리 계층 구조

프리페치가 필요한 이유

L1 캐시 히트는 몇 사이클, 약 1 ns가 걸리지만 DRAM 접근은 수십~약 100 ns가 걸리므로, 수 GHz 코어는 미스 한 번에 수백 사이클을 기다릴 수 있습니다. 이 격차를 메모리 월이라고 합니다. 데이터에 처음 접근할 때 생기는 강제 미스(compulsory miss)는 데이터가 한 번도 캐시된 적이 없으므로 용량이나 연관도를 늘려도 줄지 않습니다. 프리페치는 프로그램이 필요로 하기 전에 라인을 요청하여 메모리 지연을 유용한 작업과 겹치게 함으로써 이 문제에 대처합니다. 큰 캐시 라인도 미스할 때마다 이웃 데이터를 가져오므로 비슷하게 도움이 됩니다.

하드웨어 프리페처의 동작

하드웨어 프리페처는 미스 또는 접근 주소의 흐름을 감시하며 규칙성을 찾습니다. 가장 단순한 것은 다음 순차 라인을 가져오는 방식입니다. 스트라이드 프리페처는 연속된 접근 사이의 주소 차이를 흔히 로드 명령어별로 추적하고, 일정한 스트라이드가 반복되면 몇 스트라이드 앞을 요청합니다. 64바이트 라인에서 int 배열을 순차적으로 읽으면 원래 16개 요소당 한 번, 즉 미스율 6.25%로 미스가 나는데, 좋은 프리페처는 그 미스 대부분을 숨깁니다. 포인터 추적은 이를 무력화합니다. 연결 리스트에서는 현재 노드가 도착할 때까지 다음 주소를 알 수 없으므로 미스가 직렬화됩니다.

소프트웨어 프리페치와 프리페치 거리

소프트웨어 프리페치는 인덱스 배열을 통한 간접 접근처럼 하드웨어가 예측할 수 없는 패턴을 위해 명시적인 프리페치 명령어를 수작업이나 컴파일러로 삽입합니다. 이 명령어들은 힌트이며, 일반적으로 예외를 일으키거나 프로그램 결과를 바꾸지 않습니다. 핵심 파라미터는 프리페치 거리입니다. 사용 시점에 너무 가깝게 가져오면 지연이 그대로 드러나고, 너무 앞서 가져오면 사용 전에 축출될 위험이 있습니다. 흔한 경험칙은 미스 지연을 루프 1회 반복 시간으로 나눈 만큼 앞서서 프리페치하고, 측정으로 조정하는 것입니다.

정확도, 커버리지, 적시성

프리페치는 공짜가 아닙니다. 쓸모없는 프리페치는 메모리 대역폭을 소비하고 유용한 라인을 축출할 수 있는데, 이를 캐시 오염이라 하며 프로그램을 더 느리게 만들 수 있습니다. 따라서 프리페처는 프리페치한 라인 중 실제로 사용된 비율인 정확도, 원래 미스 중 제거된 비율인 커버리지, 데이터가 필요하기 전에 도착하는지인 적시성으로 평가됩니다. 프리페치는 제한된 명령어 윈도우 안에서만 미스를 겹치게 하는 비순차 실행과도 다릅니다. 데이터 구조가 예측에 불리할 때는 연속된 배열로 재구성하는 것이 어떤 프리페처보다 도움이 되는 경우가 많습니다.

DDR4 SDRAM 등에서 사용되는 '8n 프리페치'의 개념으로 올바른 것은?

  1. A내부 셀 어레이에서 한 번에 8배 폭의 데이터를 꺼내 외부 핀에서 고속으로 차례로 출력한다
  2. B8회분의 리프레시를 한꺼번에 수행한다
  3. C8개의 칩에 같은 데이터를 쓴다
정답과 해설 보기

정답: A. 내부 셀 어레이에서 한 번에 8배 폭의 데이터를 꺼내 외부 핀에서 고속으로 차례로 출력한다

셀 어레이 자체의 동작 속도는 세대가 바뀌어도 거의 변하지 않으므로, DDR4에서는 내부에서 한 번의 액세스로 핀 폭의 8배(8n) 데이터를 한꺼번에 읽어 외부의 고속 인터페이스로 차례로 내보냅니다. 그래서 버스트 길이는 8이 됩니다. 프리페치는 DDR(2n), DDR2(4n), DDR3(8n)로 두 배씩 늘었고, DDR4는 8n 그대로 뱅크 그룹으로 고속화했습니다. DDR5는 16n 프리페치로, 내부 속도를 높이지 않고 외부 전송 속도를 높이고 있습니다.

하드웨어 프리페치가 특히 효과를 발휘하기 쉬운 접근은?

  1. A배열을 일정한 간격(스트라이드)으로 차례로 읽어 가는 접근
  2. B연결 리스트를 처음부터 한 요소씩 따라가는 접근
  3. C해시 테이블을 무작위 키로 조회하는 접근
정답과 해설 보기

정답: A. 배열을 일정한 간격(스트라이드)으로 차례로 읽어 가는 접근

하드웨어 프리페처는 직전 접근 주소의 규칙성(연속 또는 일정한 간격)을 찾아 다음에 올 주소를 예측하여 미리 읽어 둡니다. 배열을 일정한 스트라이드로 읽는 접근은 예측하기 쉬워 효과가 큽니다. 연결 리스트는 다음 요소의 주소를 현재 요소를 읽을 때까지 알 수 없으므로 규칙성이 없어 예측할 수 없습니다. 무작위 키로 해시 테이블을 참조하는 것도 주소에 규칙성이 없으므로 효과가 작습니다.

자주 묻는 질문

하드웨어 프리페치와 소프트웨어 프리페치 차이

하드웨어 프리페처는 순차 접근이나 일정 스트라이드 접근 같은 패턴을 실행 중에 자동으로 검출합니다. 소프트웨어 프리페치는 프로그래머나 컴파일러가 배치한 명시적 명령어에 의존하며, 불규칙하지만 계산 가능한 주소에 도움이 됩니다.

연결 리스트에 프리페치가 별로 효과 없는 이유

각 노드의 주소는 이전 노드를 로드한 뒤에야 알 수 있으므로 예측 가능한 패턴이 없고 미스를 겹칠 수 없습니다. 보통 데이터를 연속으로 저장하거나 점프 포인터를 추가해야 합니다.

프리페치 때문에 성능이 나빠질 수 있나요?

네. 부정확하거나 너무 이른 프리페치는 대역폭을 낭비하고 아직 필요한 데이터를 축출하므로, 공격적인 프리페치는 메모리 병목인 프로그램을 느리게 할 수 있습니다.

해설 속 프리페치(Prefetch)

  • 프리페치는 DDR(2n), DDR2(4n), DDR3(8n)로 두 배씩 늘었고, DDR4는 8n 그대로 뱅크 그룹으로 고속화했습니다.

    DDR4 SDRAM 등에서 사용되는 '8n 프리페치'의 개념으로 올바른 것은?

  • 프리페치는 데이터가 필요해질 때까지 메모리에서의 읽기가 끝나 있지 않으면 의미가 없습니다.

    소프트웨어 프리페치 명령을 넣을 때, 얼마나 앞의 데이터를 읽을지(프리페치 거리)에 대한 설명으로 올바른 …

  • 대책으로 다단 캐시, 메모리 병렬 액세스, 프리페치, HBM과 같은 광대역 메모리, 연산을 메모리 가까이에서 수행하는 PIM(프로세싱 인 메모리) 등이 추진되고 있습니다.

    프로세서의 성능 향상에 비해 메모리의 대역폭이나 지연의 개선이 따라가지 못해 생기는 성능의 제약을 무엇이라…

  • 대책은 초기 참조 미스에는 라인을 키우거나 프리페치로 미리 읽고, 용량 미스에는 캐시를 키우고, 충돌 미스에는 연관도를 높이는 등 원인별로 다릅니다.

    캐시 미스 분류인 「3C」에 포함되는 것의 조합으로 올바른 것은?

  • 필요해지기 전에 프리페치로 읽어 두거나, 라인을 크게 하여 근처 데이터를 한꺼번에 가져오면 줄일 수 있습니다.

    프로그램이 어떤 데이터에 처음 접근했을 때 일어나는 캐시 미스를 줄이는 방법으로 효과가 있는 것은?

  4. 위 루프에서 int가 4바이트, 캐시 라인이 64바이트이고, 배열은 캐시에 들어 있지 않으며 시작 주소가 라인 경계에 정렬되어 있을 때, 프리페치가 없다면 배열 읽기의 미스율은 얼마인가?
  5. 프로세서의 성능 향상에 비해 메모리의 대역폭이나 지연의 개선이 따라가지 못해 생기는 성능의 제약을 무엇이라 하는가?
