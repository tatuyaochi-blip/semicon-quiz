프리페치(prefetching)란?

곧 필요할 것으로 예상되는 데이터를 요청되기 전에 미리 캐시로 가져오는 것입니다. 하드웨어 프리페처는 접근 패턴을 감지하고, 소프트웨어 프리페치는 명시적인 명령어를 사용합니다.

일본어 명칭: プリフェッチ

프리페치(prefetching)은(는) 메모리 계층 구조, DRAM, CPU와 아키텍처 등 3개 분야의 연습 문제 9개에 나와요.

분야: 메모리 계층 구조

도전해 보기: 프리페치(prefetching) 관련 문제

DDR4 SDRAM 등에서 사용되는 「8n 프리페치」의 개념으로 올바른 것은?

  1. A내부 셀 어레이에서 한 번에 8배 폭의 데이터를 꺼내, 외부 단자에서 고속으로 차례로 출력한다
  2. B8회 분량의 리프레시를 한꺼번에 수행한다
  3. C8개의 칩에 같은 데이터를 쓴다
정답과 해설 보기

정답: A. 내부 셀 어레이에서 한 번에 8배 폭의 데이터를 꺼내, 외부 단자에서 고속으로 차례로 출력한다

셀 어레이 자체의 동작 속도는 세대가 바뀌어도 거의 변하지 않으므로, DDR4에서는 내부에서 1회 접근으로 단자 폭의 8배(8n) 데이터를 한꺼번에 읽어 내고, 외부의 고속 인터페이스로 차례로 내보냅니다. 그래서 버스트 길이는 8이 됩니다. DDR5는 16n 프리페치로, 내부 속도를 올리지 않고 외부 전송 속도를 2배로 했습니다. DDR(2n), DDR2(4n)와 세대마다 배로 늘려 온 구조입니다.

하드웨어 프리페치가 특히 효과를 발휘하기 쉬운 접근은 무엇입니까?

  1. A배열을 일정한 간격(스트라이드)으로 차례로 읽어 나가는 접근
  2. B연결 리스트를 처음부터 한 요소씩 따라가는 접근
  3. C해시 테이블을 임의의 키로 조회하는 접근
정답과 해설 보기

정답: A. 배열을 일정한 간격(스트라이드)으로 차례로 읽어 나가는 접근

하드웨어 프리페처는 직전 접근 주소의 규칙성(연속이나 일정한 간격)을 찾아내어 다음에 올 주소를 예측해 미리 읽어 옵니다. 배열을 일정한 스트라이드로 읽는 접근은 예측하기 쉬워 효과가 큽니다. 연결 리스트는 다음 요소의 주소를 현재 요소를 읽기 전까지 알 수 없으므로 규칙성이 없어 예측할 수 없습니다. 임의의 키로 해시 테이블을 참조하는 것도 주소에 규칙성이 없어 효과가 작습니다.

프리페치(prefetching)이(가) 나오는 문제 (9)

  1. DDR4 SDRAM 등에서 사용되는 「8n 프리페치」의 개념으로 올바른 것은?
  2. 하드웨어 프리페치가 특히 효과를 발휘하기 쉬운 접근은 무엇입니까?
  3. 소프트웨어 프리페치 명령을 넣을 때, 얼마나 앞의 데이터를 읽을 것인가(프리페치 거리)에 대한 설명으로 올바른 것은 무엇입니까?
  4. 위의 루프에서 int가 4바이트, 캐시 라인이 64바이트이고, 배열은 캐시에 들어 있지 않으며 시작이 라인 경계에 정렬되어 있을 때, 프리페치가 없다면 배열 읽기의 미스율은 얼마입니까?
  5. 프로세서의 성능 향상에 비해 메모리의 대역이나 지연의 개선이 따라가지 못해 생기는 성능 제약을 무엇이라 하는가?
  6. 캐시 미스 분류인 「3C」에 포함되는 것의 조합으로 올바른 것은?
  7. 프로그램이 어떤 데이터에 처음 접근했을 때 일어나는 캐시 미스를 줄이는 방법으로 효과가 있는 것은 무엇입니까?
  8. 주기억장치 DRAM에 접근하는 데 걸리는 시간은 L1 캐시의 히트 시간의 대략 몇 배입니까? (일반적인 PC나 서버의 CPU의 경우)
  9. 위의 연결 리스트를 따라가는 처리가, 같은 수의 요소를 가진 배열을 차례로 읽는 것보다 훨씬 느려지기 쉬운 이유는 무엇입니까?
