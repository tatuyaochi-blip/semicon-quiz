연산 강도(Arithmetic Intensity)란?

처리의 연산 횟수를 메모리에서 읽고 쓰는 바이트 수로 나눈 값. 클수록 연산 바운드(compute-bound), 작을수록 메모리 바운드(memory-bound)이 되기 쉽다.

일본어 명칭: 演算強度

연산 강도(Arithmetic Intensity)은(는) AI 하드웨어·소프트웨어 스택, CPU와 아키텍처, 성능 분석 등 3개 분야의 연습 문제 8개에 나와요.

분야: AI 하드웨어·소프트웨어 스택

계산 방법

연산 강도는 수행한 연산 횟수를 메모리와 프로세서 사이에서 옮긴 바이트 수로 나눈 값으로, 보통 DRAM 트래픽 1바이트당 FLOP 수로 셉니다. 두 N × N FP16 행렬의 곱에서 각각을 한 번 읽고 결과를 한 번 쓴다면, 연산량은 2N^3이고 트래픽은 3N^2 요소, 즉 6N^2 바이트이므로 N/3이 되며, N = 1024이면 약 340입니다. 행렬-벡터 곱은 각 가중치를 한 번만 사용하므로 FP16에서 약 1 FLOP/byte이며, ReLU 같은 요소별 연산은 1 미만입니다. 연산 강도는 알고리즘, 데이터 타입, 그리고 구현이 데이터를 얼마나 잘 재사용하는지에 따라 달라집니다.

루프라인 모델

operational intensity라는 용어를 쓰기도 하는 루프라인 모델은 달성 가능한 성능을 연산 강도에 대해 플롯합니다. 성능은 피크 연산 성능과, 메모리 대역폭 × 연산 강도 중 작은 쪽이므로, 그래프에는 기울어진 대역폭 천장과 평평한 연산 천장이 생깁니다. 둘은 피크 성능을 대역폭으로 나눈 릿지 포인트에서 만납니다. 100 TFLOPS와 2 TB/s라면 릿지는 50 FLOP/byte이므로, 10 FLOP/byte인 워크로드는 메모리 바운드이며 2 TB/s × 10 = 20 TFLOPS에 머뭅니다. 릿지 아래에서는 연산 유닛을 늘려도 도움이 되지 않고, 그 위에서는 더 이상 메모리 대역폭이 제약이 아닙니다.

연산 강도를 높이는 방법

워크로드가 기울어진 지붕 아래에 있다면, 바이트당 더 많은 작업을 하거나 옮기는 바이트를 줄이는 것이 해결책입니다. 블로킹(타일링)은 부분 행렬을 캐시나 온칩 메모리에 유지하여, DRAM에서 가져온 각 값을 여러 번 사용합니다. 연산자 융합은 활성화나 정규화 같은 요소별 단계를 데이터를 내보냈다가 다시 읽는 대신 데이터가 아직 칩 안에 있을 때 적용합니다. 배칭은 가중치를 한 번 읽어 여러 입력에 쓰게 합니다. 더 낮은 정밀도의 데이터 타입은 값당 바이트 수를 줄이므로, 같은 계산에서 바이트당 연산 횟수가 올라갑니다.

연산 강도를 만나는 곳

연산 강도는 AI 가속기의 동작을 상당 부분 설명합니다. 큰 행렬 곱은 연산 바운드여서 피크 처리량에 근접할 수 있는 반면, 요소별 층은 연산 횟수가 적은데도 실행 시간의 눈에 띄는 몫을 차지할 수 있습니다. 배치 크기 1의 추론은 연산 강도가 1 근처인 행렬-벡터 워크로드이므로, 메모리에서 가중치를 얼마나 빨리 흘려보낼 수 있는지에 제약되며, 이것이 배칭과 가중치 양자화가 도움이 되는 이유입니다. 하드웨어의 릿지 포인트와 비교해 보십시오. 연산 강도는 워크로드의 속성이고 릿지 포인트는 머신의 속성이며, 둘의 비가 어느 자원을 최적화해야 할지 알려 줍니다.

정답과 해설 보기

정답: B. 루프라인 모델

루프라인 모델에서는 가로축에 연산 강도(메모리에서 1바이트를 읽을 때의 연산 수), 세로축에 성능을 잡습니다. 연산 강도가 낮은 처리는 메모리 대역폭에서 한계에 부딪히고(비스듬한 선), 높은 처리는 최대 연산 성능에서 한계에 부딪힙니다(수평선). 예를 들어 대역폭 1 TB/s, 연산 성능 100 TFLOPS라면 연산 강도 100 FLOP/바이트 미만인 처리는 메모리 율속입니다. 개선 방침(데이터 재사용인지 연산 효율화인지)을 판단하는 데 쓰입니다.

N×N의 FP16(2바이트) 행렬끼리의 곱에서, 두 입력을 한 번씩 읽고 결과를 한 번 쓴다고 하자. 연산 강도(1바이트당 연산 수)는 대략 얼마인가?

  1. A1/3
  2. BN/3
  3. C3N
정답과 해설 보기

정답: B. N/3

연산 수는 2N³, 메모리 읽기/쓰기는 세 행렬로 3N² 요소이며 FP16이므로 6N² 바이트입니다. 연산 강도는 2N³ ÷ 6N² = N/3이고, N=1024이면 약 340이 됩니다. 행렬 곱은 클수록 1바이트당 계산이 늘어나므로 연산기의 성능을 끌어내기 쉬운 처리입니다. 반면 요소별 덧셈 같은 처리는 연산 강도가 1 미만이며 메모리 대역폭으로 속도가 결정됩니다.

자주 묻는 질문

연산 강도 계산 방법

연산 횟수(보통 FLOP)를 메모리와 주고받은 바이트 수로 나눕니다. N × N FP16 행렬 곱이라면 2N^3 / 6N^2 = N/3입니다.

루프라인 모델의 릿지 포인트란?

피크 연산 성능을 메모리 대역폭으로 나눈 값으로, 워크로드가 메모리 바운드에서 연산 바운드로 바뀌는 연산 강도입니다. 100 TFLOPS와 2 TB/s라면 50 FLOP/byte입니다.

배치 크기 1 추론이 메모리 바운드인 이유

각 가중치를 메모리에서 읽어 단 한 번의 곱셈-덧셈에만 쓰므로 연산 강도가 FP16에서 약 1 FLOP/byte로, 일반적인 가속기의 릿지 포인트보다 훨씬 낮기 때문입니다.
