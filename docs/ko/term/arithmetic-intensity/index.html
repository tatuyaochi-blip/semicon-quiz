연산 강도(Arithmetic Intensity)란?

처리의 연산 횟수를 메모리에서 읽고 쓰는 바이트 수로 나눈 값. 클수록 연산 바운드(compute-bound), 작을수록 메모리 바운드(memory-bound)이 되기 쉽다.

일본어 명칭: 演算強度

연산 강도(Arithmetic Intensity)은(는) AI 하드웨어·소프트웨어 스택, CPU와 아키텍처, 성능 분석 등 3개 분야의 연습 문제 8개에 나와요.

도전해 보기: 연산 강도(Arithmetic Intensity) 관련 문제

프로그램의 성능이 연산 성능과 메모리 대역폭 중 어느 쪽에 의해 제한되는지를 연산 강도(1바이트당 연산 수)를 가로축으로 하여 도시하는 모델은?

  1. A암달의 법칙
  2. B루프라인 모델
  3. C푸아송 모델
정답과 해설 보기

정답: B. 루프라인 모델

루프라인 모델에서는 가로축에 연산 강도(메모리에서 1바이트를 읽을 때의 연산 수), 세로축에 성능을 잡습니다. 연산 강도가 낮은 처리는 메모리 대역폭에서 한계에 부딪히고(비스듬한 선), 높은 처리는 최대 연산 성능에서 한계에 부딪힙니다(수평선). 예를 들어 대역폭 1 TB/s, 연산 성능 100 TFLOPS라면 연산 강도 100 FLOP/바이트 미만인 처리는 메모리 율속입니다. 개선 방침(데이터 재사용인지 연산 효율화인지)을 판단하는 데 쓰입니다.

N×N의 FP16(2바이트) 행렬끼리의 곱에서, 두 입력을 한 번씩 읽고 결과를 한 번 쓴다고 하자. 연산 강도(1바이트당 연산 수)는 대략 얼마인가?

  1. A1/3
  2. BN/3
  3. C3N
정답과 해설 보기

정답: B. N/3

연산 수는 2N³, 메모리 읽기/쓰기는 세 행렬로 3N² 요소이며 FP16이므로 6N² 바이트입니다. 연산 강도는 2N³ ÷ 6N² = N/3이고, N=1024이면 약 340이 됩니다. 행렬 곱은 클수록 1바이트당 계산이 늘어나므로 연산기의 성능을 끌어내기 쉬운 처리입니다. 반면 요소별 덧셈 같은 처리는 연산 강도가 1 미만이며 메모리 대역폭으로 속도가 결정됩니다.

  1. 프로그램의 성능이 연산 성능과 메모리 대역폭 중 어느 쪽에 의해 제한되는지를 연산 강도(1바이트당 연산 수)를 가로축으로 하여 도시하는 모델은?
  2. N×N의 FP16(2바이트) 행렬끼리의 곱에서, 두 입력을 한 번씩 읽고 결과를 한 번 쓴다고 하자. 연산 강도(1바이트당 연산 수)는 대략 얼마인가?
  3. 피크 성능 100 TFLOPS, 메모리 대역폭 2 TB/s의 가속기에서 연산 강도가 10 FLOP/바이트인 처리를 실행한다. Roofline 모델로 어림한 달성 가능한 성능은 얼마인가?
  4. 입력이 하나뿐일 때(배치 크기 1), 완전 연결층의 계산(가중치 행렬과 벡터의 곱)이 메모리 율속이 되기 쉬운 이유로 올바른 것은 무엇인가?
  5. 추론에서 배치 크기(한꺼번에 처리하는 입력의 수)를 키우면 전체 처리 효율이 올라가기 쉬운 이유는 무엇인가?
  6. 대규모 언어 모델의 추론은 입력 문장을 한꺼번에 처리하는 단계(프리필)와 토큰을 하나씩 출력으로 만드는 단계(디코드)로 나뉜다. 각각의 성능을 주로 결정하는 것의 조합으로 올바른 것은 무엇인가(배치가 작은 경우)?
  7. ReLU나 레이어 정규화와 같은 요소별 연산이 AI 계산 중에서 연산 횟수에 비해 시간이 걸리기 쉬운 이유로 올바른 것은 무엇인가?
  8. 루프라인(Roofline) 모델에서 어떤 처리가 메모리 대역폭으로 제한되는 영역에 있음을 알았을 때, 성능을 높이는 방향으로 올바른 것은?
