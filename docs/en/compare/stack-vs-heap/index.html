Stack vs Heap Memory: Differences Explained

A running program uses two main regions of memory for its data. The stack holds function call frames: local variables, arguments and return addresses. It is managed automatically and is very fast, but small and tied to the lifetime of each function call. The heap holds memory that the program requests explicitly, such as with malloc or new, and it lives until it is freed. The heap is flexible and large but slower, and it is where leaks and fragmentation happen.

AspectStackHeap
Used forFunction call frames: local variables, arguments, return addressesDynamically allocated data that must outlive a function or whose size is not known in advance
AllocationAutomatic: the stack pointer moves on each call and returnExplicit: malloc and free, new and delete, or a garbage collector
SpeedVery fast: just adjusting a pointerSlower: the allocator must find a free block and keep records
LifetimeUntil the function returnsUntil the memory is freed (or garbage collected)
SizeLimited (typically a few megabytes per thread)Limited only by the available memory
LayoutUsually grows downward from high addressesUsually grows upward from lower addresses, so the two grow toward each other
FragmentationNonePossible: repeated allocation and freeing can leave unusable gaps
ThreadsEach thread has its own private stackShared by all threads, so the allocator must be thread-safe
Typical errorsStack overflow from deep recursion or large local arraysMemory leaks, use after free, double free and running out of memory

Figures are typical orders of magnitude and vary by process generation and product.

When to use which

Stack
For small, short-lived data whose size is known at compile time: ordinary local variables.
Heap
For large data, data whose size changes at run time, and data that must outlive the function that created it.
