I2C vs SPI vs UART: Differences and When to Use Each

These are the three serial interfaces you meet first in embedded systems. UART is a simple point-to-point link with no shared clock. SPI is a fast, four-wire bus where one master selects each device with a chip-select line. I2C is a two-wire bus where many devices share the same lines and are picked by address. The trade-off is mostly between speed (SPI), pin count (I2C) and simplicity (UART).

AspectUARTSPII2C
WiresTwo signal wires (TX and RX) plus groundFour signal wires (SCLK, MOSI, MISO) plus one chip-select (CS) per deviceTwo shared wires (SDA and SCL) plus ground, with pull-up resistors
ClockAsynchronous: no clock line, so both sides must agree on the baud rateSynchronous: the master drives a clockSynchronous: the master drives a clock
TopologyPoint to point between two devicesOne master and several slaves, each slave needing its own CS lineSeveral masters and slaves share one bus
AddressingNoneChip-select line selects the device7-bit address (10-bit optional) sent at the start of each transfer
Typical speedFrom 9,600 to 115,200 bit/s up to a few Mbit/sOften 1 to 50 MHz, and higher on some parts100 kHz (standard), 400 kHz (fast), 1 MHz (fast-mode plus), 3.4 MHz (high-speed)
DirectionFull duplexFull duplexHalf duplex
Error checkingOptional parity bit and framing checkNone built inAcknowledge (ACK/NACK) after every byte
Pins as devices increaseTwo more pins for every additional linkOne more CS pin for every additional deviceNo additional pins
DistanceCan run longer with RS-232 or RS-485 driversShort, on the same boardShort, on the same board
Typical usesDebug console, GPS and Bluetooth modules, board-to-board linksFlash memory, SD cards, displays, fast ADCs and sensorsLow-speed sensors, EEPROM, real-time clocks, chip configuration

Figures are typical orders of magnitude and vary by process generation and product.

When to use which

UART
When you need the simplest possible link between two devices, a debug console or a module with a serial interface.
SPI
When you need speed: memory, displays, fast converters. The price is more pins as you add devices.
I2C
When you have many slow devices and few pins: sensors, small memories, configuration registers. Speed is limited and pull-up resistors are required.
