NAND vs NOR Flash: Differences and Uses

Both are non-volatile flash memories, but they are wired differently. NOR flash connects its cells in parallel, so it offers fast random reads and can run code in place, but it is expensive per bit. NAND flash connects its cells in series, so it packs far more bits into the same area and is cheap, but it reads and writes in pages and needs error correction. That is why NAND stores your data and NOR stores firmware.

AspectNAND flashNOR flash
Cell connectionCells are connected in series in strings, with select transistors at both endsCells are connected in parallel to the bit line, so each cell can be accessed directly
Read accessRead in pages (several KB at a time). The first access takes tens of microseconds, so random reads are slowFast random access at the byte or word level, in the range of tens of nanoseconds
Write (program)Programmed one page at a time; high throughput for sequential writesProgrammed in small units; slower for large amounts of data
Erase unitBlock (a few MB or more)Sector (typically 64 to 128 KB)
Programming mechanismFowler-Nordheim tunneling for both program and eraseChannel hot-electron injection to program, tunneling to erase
Density and cost per bitHigh density and low cost; 3D NAND stacks hundreds of layers, and TLC/QLC store 3 to 4 bits per cellLower density (usually up to a few gigabits per chip) and higher cost per bit
Execute in place (XIP)No. Code must be copied to RAM firstYes. A processor can run code directly from the chip
ReliabilityBad blocks and bit errors are normal, so strong ECC, bad-block management and wear leveling are requiredFew bit errors, so only light error correction is needed
EnduranceFrom about 100,000 program/erase cycles (SLC) down to roughly 1,000 or fewer (QLC)Typically around 100,000 program/erase cycles
Typical usesSSDs, USB drives, memory cards, smartphone storage (eMMC, UFS)Boot code and firmware: BIOS/UEFI chips, microcontroller code, automotive and industrial devices

Figures are typical orders of magnitude and vary by process generation and product.

When to use which

NAND flash
When you need a large amount of cheap, non-volatile storage and can read and write in pages: SSDs, phones, cameras, memory cards.
NOR flash
When you need to store program code that a processor reads directly and reliably, and the capacity is modest: boot ROM, firmware, small embedded systems.
Together
Many devices use both: a small NOR chip holds the boot code, which then loads the operating system from a large NAND device.
