DMA vs Programmed I/O: Differences Explained

There are two ways to move data between a device and memory. In programmed I/O (PIO), the CPU itself reads or writes every word through registers. In direct memory access (DMA), a DMA controller moves the data on its own, and the CPU only sets up the transfer and is notified when it is done. DMA frees the CPU and handles large transfers much faster, but it needs more setup and care.

AspectProgrammed I/O (PIO)DMA
Who moves the dataThe CPU, word by word, with load and store instructionsA DMA controller or the device itself, directly to or from memory
CPU loadHigh: the CPU is busy during the whole transferLow: the CPU sets up the transfer and does other work
Throughput for large transfersLimited by the CPU speedHigh
Setup overheadNoneNeeds an address, a length or descriptors, and completion handling
Small transfersOften faster, because there is no setupThe setup cost can outweigh the benefit
ComplexitySimpleMore complex: descriptor rings, buffer alignment, cache coherency and IOMMU settings
Memory bus useThrough the CPUThe DMA engine competes with the CPU for memory bandwidth
Typical usesSmall control registers, simple sensors, legacy PIO modesSSDs and NVMe, network cards, audio buffers, ADC sample streams, GPU transfers

Figures are typical orders of magnitude and vary by process generation and product.

When to use which

PIO
When transfers are tiny or rare, and simplicity matters more than CPU time.
DMA
When transfers are large or continuous and you do not want the CPU tied up: storage, networking, streaming data.
Watch out
With DMA, make sure the CPU cache and memory agree before the device reads or after it writes (flush or invalidate the cache, or use coherent memory).
