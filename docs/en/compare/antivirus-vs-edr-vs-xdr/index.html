Antivirus vs EDR vs XDR: Prevention or Detection, Telemetry, Response and Scope

All three protect endpoints from attacks, but they differ in purpose and scope. Antivirus software (an EPP, endpoint protection platform) aims to stop malware before it runs, using known malware patterns and suspicious characteristics. EDR assumes that intrusions cannot be completely prevented: it keeps recording processes, files and network activity on the endpoint, finds suspicious behavior, and helps investigate and respond, for example by isolating the endpoint. XDR correlates records not only from endpoints but also from the network, email, cloud services and identity authentication, to find the course of an attack across the whole organization. Most organizations combine a mechanism that stops attacks with one that finds and responds to what slips through.

When to use which

Antivirus (EPP)
The basic measure to install on every endpoint. It stops much known malware without waiting for a human decision.
EDR
When you assume intrusions can get through and want to find them early and limit the damage. It is also used in incident response investigations to trace back what happened on an endpoint.
XDR
When endpoints, email, cloud and so on are monitored on separate consoles and you want to follow the course of an attack in one place. Its role overlaps with a SIEM, so decide how it divides the work with the systems you already have.

FAQ

If I install EDR, do I still need antivirus?

Their roles differ, so in most cases both are used. Antivirus is strong at automatically stopping known malware before it runs; EDR is strong at finding, investigating and responding to the activity of attacks that slipped through. Many products provide both functions together.

Why does EDR need human response?

Because EDR alerts include legitimate administration work and business tools judged as suspicious. Deciding whether it is really an attack, investigating the scope and choosing actions such as isolation require operation by staff, a SOC or an external monitoring service. If no one looks at the alerts, the records alone cannot limit the damage.

What is the difference between XDR and a SIEM?

Both collect and correlate records from several sources, but a SIEM is usually described as a platform that collects, analyzes and stores logs broadly from many kinds of devices, while XDR focuses on deeply integrating a defined set of sources, such as endpoints and email, and handling everything from detection to response in one system. The boundary differs by product, so check what is collected and how much response can be automated.

Check your understanding

Which of the following correctly describes EDR (endpoint detection and response) compared with traditional antivirus software?

  1. AIt continuously records behavior on endpoints, such as process launches and network connections, detects suspicious activity and supports responses such as isolating the device
  2. BIt only checks whether files match the characteristics of known malware and deletes the files that match, without recording behavior
  3. CIt is placed at the network perimeter rather than on endpoints and blocks packets arriving from outside based on IP addresses and port numbers
Show answer and explanation

Answer: A. It continuously records behavior on endpoints, such as process launches and network connections, detects suspicious activity and supports responses such as isolating the device

Traditional antivirus software mainly compares files against the characteristics of known malware and aims to stop intrusion at the point of entry. EDR assumes that intrusion cannot be prevented completely and continuously records process launches, changes to files and settings, network connections and so on at the endpoint to detect suspicious behavior. Its features include going back through the records to investigate the intrusion path and the extent of the impact, remotely isolating the device from the network and stopping suspicious processes. Many products today provide antivirus functions and EDR in one.

The technique in which an intruder avoids using custom malware as far as possible and works with legitimate tools already present in the OS, such as PowerShell, WMI and the standard remote administration features, is called "living off the land". Which of the following is the most appropriate way of thinking about countermeasures to this technique?

  1. AThe executables of legitimate tools are digitally signed, so installing antivirus software that checks signatures is enough to detect it
  2. BAttacks using legitimate tools cannot be detected, so give up on post-intrusion measures and invest only in defenses at the entry point
  3. CRecord who ran the legitimate tools, with which arguments and from which parent process, detect unusual use, and limit the people and devices that can use administration tools
Show answer and explanation

Answer: C. Record who ran the legitimate tools, with which arguments and from which parent process, detect unusual use, and limit the people and devices that can use administration tools

In a living-off-the-land attack the programs themselves are legitimate and signed, so methods that recognize known malware by file characteristics cannot detect it. Instead, command arguments and parent-child relationships are collected with EDR and OS logs (such as PowerShell script logging and process creation records), and detection relies on use that differs from normal work, such as "PowerShell launched by an application that opened a document" or "a long encoded command was run". In addition, limiting the users and devices that can use administration tools and allowing only approved applications to run reduce the tools available to the attacker.

Which of the following correctly matches SIEM, SOAR and SOC with their roles in security monitoring?

  1. ASIEM is software that records endpoint behavior, SOAR is a device that encrypts traffic, and SOC is an identifier given to vulnerabilities
  2. BSIEM automatically runs response procedures, SOAR collects and analyzes logs from each device, and SOC is the development team that handles product vulnerabilities
  3. CSIEM collects and correlates logs from many devices, SOAR automatically runs response procedures (playbooks), and SOC is the team that uses them for monitoring
Show answer and explanation

Answer: C. SIEM collects and correlates logs from many devices, SOAR automatically runs response procedures (playbooks), and SOC is the team that uses them for monitoring

SIEM (security information and event management) collects logs from firewalls, servers, EDR, cloud services and so on in one place, aligns their timestamps and presents suspected attacks as alerts using rules that combine several events (correlation analysis). SOAR (security orchestration, automation and response) automatically runs set procedures such as gathering information, isolating devices and disabling accounts as playbooks in response to alerts, reducing analysts' workload. The SOC (security operations center) is the team that uses these to monitor, analyze alerts and determine and report whether something is an incident, and it often operates around the clock. Response to the incidents identified by the SOC is usually led by the CSIRT.

Practice Cyber Attacks and Defense in Practice questions

Key terms explained

EDR (endpoint detection and response)
A security product that continuously records activity on endpoints such as PCs and servers, including process launches, changes to files and settings and network connections, detects suspicious behavior and supports investigation and response (isolating the device, stopping processes and so on). Unlike traditional antivirus software, which recognizes known malware files, it assumes that intrusions cannot be prevented completely and aims to find activity after an intrusion.
SIEM (security information and event management)
A system that collects logs from firewalls, servers, EDR, cloud services, authentication infrastructure and more in one place, normalizes their formats and timestamps, detects suspected attacks with rules that combine several events (correlation analysis) and presents them as alerts. It is also used to search logs during investigations and to retain logs for long periods as regulations require. It is one of the central tools that analysts in a security operations center (SOC) use for monitoring.
Security operations center
A team or facility that continuously monitors an organization's networks, endpoints and cloud services, analyzes alerts from SIEM and EDR, determines whether they are incidents and reports them to those who respond. It is abbreviated SOC (a different term from SoC, system on chip). It often operates around the clock, and many organizations outsource it to an external provider rather than running it themselves. Response to the incidents it identifies proceeds in cooperation with the CSIRT.
Indicator of compromise (IoC)
A concrete trace showing that a system has been compromised, such as the hash value of a malware file, the IP address or domain name of a C2 server, or a characteristic file name. IoCs are shared between organizations and through threat intelligence and are matched against an organization's own logs and endpoints to check whether it has been hit by the same attack. Since attackers can easily change hash values and IP addresses, IoCs are combined with indicators of attack (IoA), which focus on attacker behavior, and with detection based on techniques.
Incident response
The series of activities carried out when a security incident such as a cyber attack occurs: finding the damage and stopping it from spreading, removing the cause and restoring operations, and applying the lessons learned. The second revision of the US NIST SP 800-61 (2012) presents it in four phases (preparation; detection and analysis; containment, eradication and recovery; and post-incident activity), and the third revision (2025) reorganized it in line with the Cybersecurity Framework (CSF) 2.0. Within an organization the CSIRT leads it, in cooperation with the SOC, system owners, legal, public relations and management.
Lateral movement
The spreading of a compromise by an attacker who has got into an organization's network, using the first hijacked endpoint as a foothold and moving to other endpoints and servers one after another with stolen credentials and legitimate administration tools. It is done to get closer to the target data or to systems with administrator privileges. It is prevented and detected with a different administrator password on each endpoint, blocking unnecessary traffic between endpoints (micro-segmentation), management of privileged accounts and monitoring of authentication logs.
MITRE ATT&CK
A knowledge base, published by the US non-profit research organization MITRE, of attacker techniques observed in real attacks. It organizes them into "tactics", which represent the attacker's goals (initial access, persistence, privilege escalation, lateral movement, exfiltration and so on), and "techniques", which represent the concrete methods for achieving them, and gives each technique an identifier. Defenders use it to check which techniques their detections and controls cover and to describe techniques in common terms in threat intelligence reports.
Zero-day attack
An attack that exploits a software vulnerability in the period after it is discovered but before a fix (patch) is provided. Since patches cannot prevent it, damage is limited with multiple layers of defense.
