2-Flop Synchronizer vs Toggle Synchronizer vs Handshake vs Asynchronous FIFO: Clock Domain Crossing Methods

Between asynchronous clock domains there will always be moments when the receiving flip-flop cannot meet its setup or hold time, so signals are passed through circuits designed on the assumption that metastability will occur. The basic one is the synchronizer, which receives a 1-bit level signal through two flip-flops. A toggle synchronizer carries short pulses, a handshake carries occasional multi-bit data, and an asynchronous FIFO carries continuous, high-volume data. All of them share one idea: only a 1-bit signal, or a Gray code that changes by only one bit per step, is ever synchronized.

When to use which

2-flop synchronizer
For a 1-bit level signal that stays stable much longer than the receiving clock period. It is the building block of every other method; use 3 stages when the clock is fast or a longer MTBF is needed.
Toggle synchronizer
When a short pulse in a fast domain must reach a slower domain without being lost, provided that consecutive pulses are spaced by more than a few receiving cycles.
Handshake
When multi-bit data such as configuration values must be passed reliably from time to time. It is safe for any frequency ratio, but each transfer takes many cycles.
Asynchronous FIFO
When data must be passed continuously or at a high rate. It absorbs rate differences and bursts, but it is the largest circuit of the four.

FAQ

Why not put a 2-flop synchronizer on each bit of multi-bit data?

Because for each bit it is undetermined whether a change is captured at this edge or the next. For example, when the value changes from 0111 to 1000, the receiver can see 1111 or 0000 for one cycle, with only some bits updated. Instead, keep the data itself unsynchronized and stable and synchronize only a 1-bit control signal (a handshake), or use an asynchronous FIFO. For counter values, another option is to convert them to Gray code so that only one bit changes at a time.

What changes when a synchronizer goes from 2 to 3 stages?

The time available for metastability to resolve grows by about one clock period, and the mean time between failures (MTBF) grows exponentially. MTBF is roughly e^(t_r/τ) ÷ (T_0 × f_clk × f_data); with τ = 20 ps, adding 1 ns to t_r multiplies the MTBF by e^50 (more than 10 to the 21st power). The cost is one more cycle of latency.

Why are asynchronous FIFO pointers converted to Gray code?

Because a binary pointer can change several bits at once, as from 0111 to 1000, and synchronizing the bits separately can produce a completely unrelated value. In Gray code only one bit changes per step, so even if that bit goes metastable and resolves either way, the result is the value before or after the step. The receiver only sees a slightly old value, so the full and empty decisions err on the safe side.

How is the depth of an asynchronous FIFO chosen?

From the largest amount that piles up during a write burst because reading cannot keep up. With a 100 MHz write side and an 80 MHz read side, writing a 100-word burst one word per cycle and reading one word per cycle, the depth is 100 × (1 − 80/100) = 20 words. Real designs add margin for the pointer synchronization delay.

Check your understanding

How does the mean time between failures (MTBF) due to metastability change when a two-flip-flop synchronizer is extended to three stages?

  1. AThe time available for metastability to resolve increases by about one period, and MTBF grows exponentially
  2. BMTBF increases 1.5 times, in proportion to the number of stages
  3. CHow likely metastability is depends on the input side, so MTBF does not change
Show answer and explanation

Answer: A. The time available for metastability to resolve increases by about one period, and MTBF grows exponentially

Synchronizer MTBF is approximately MTBF = e^(t_r/τ) ÷ (T_0 × f_clk × f_data), where t_r is the time available for metastability to resolve and τ and T_0 are constants determined by the flip-flop's characteristics. Adding a stage extends t_r by about one period (precisely, one period minus the flip-flop's clock-to-output delay and setup time). For example, with τ = 20 ps, increasing t_r by 1 ns multiplies MTBF by e^50, more than 10^21 times. The probability of the first stage going metastable is unchanged, but the probability that it resolves before propagating further rises sharply.

Each bit of 4-bit data is passed to another clock domain through its own two-stage synchronizer. What problem can occur when the data changes from 0111 to 1000?

  1. AThe bits may be captured in different cycles, so an intermediate value such as 1111 or 0000 may be received
  2. BPassing through the synchronizers aligns all bits to the same cycle, so no problem occurs
  3. CAll four bits become metastable and never return to either 0 or 1
Show answer and explanation

Answer: A. The bits may be captured in different cycles, so an intermediate value such as 1111 or 0000 may be received

For each bit, a two-stage synchronizer does not determine whether a change is captured at the current edge or the next one. In a change from 0111 to 1000 all four bits change, so for one cycle the receiver may get a value in which only some bits have their new value, such as 1111, 0000 or 0100. If the receiver uses that value, it malfunctions. Metastability resolves to 0 or 1 over time. For counter values, convert to Gray code so that only one bit changes; for arbitrary data, use a handshake or an asynchronous FIFO.

In toggle synchronization (a scheme in which the sending side generates and passes a level signal that inverts each time a pulse arrives), how is the original pulse recovered on the receiving side?

  1. AUse the synchronized toggle signal directly as the pulse
  2. BAND the synchronized toggle signal with the receiving clock to make a one-cycle-wide pulse
  3. CXOR the synchronized toggle signal with a version of it delayed by one more stage
Show answer and explanation

Answer: C. XOR the synchronized toggle signal with a version of it delayed by one more stage

In toggle synchronization, the sending side inverts a flip-flop each time a pulse arrives, representing each event as a 0-to-1 or 1-to-0 transition. Being a level signal, it is not lost even if the pulse is shorter than the receiving period. On the receiving side, after two-stage synchronization, XORing with the value delayed by one more stage gives a one-cycle-wide pulse that is 1 only in the cycle where a change occurred. Using the toggle signal directly misses the second event, when it returns to 0. Logic operations with the clock cause glitches.

Key terms explained

Synchronizer
A circuit that aligns an asynchronous signal to the receiving clock. The basic form is two flip-flops in series, which raises the probability that metastability in the first stage resolves before the next edge.
Toggle synchronizer
A scheme that turns each pulse on the sending side into a toggle of a level signal, synchronizes it, and recovers a pulse on the receiving side by XORing it with its value one cycle earlier. Pulses shorter than the receiving clock period are not lost, but pulses must be spaced several receiving cycles apart.
Handshake
A scheme that transfers data reliably by exchanging a request (req) from the sender and an acknowledgment (ack) from the receiver. Across clock domains only req and ack are synchronized while the data is held stable, which is safe but takes several cycles or more per transfer.
Asynchronous FIFO
A FIFO written and read on separate clocks, used to pass multi-bit data between clock domains. Its pointers are converted to Gray code before being synchronized into the other domain to decide full and empty. The pointers have one more bit than the address to distinguish wrap-around.
Clock domain
A group of flip-flops driven by the same clock, or by clocks with a fixed frequency and phase relationship. Passing a signal between clock domains that are asynchronous to each other requires a synchronizer.
Metastability
A state in which a flip-flop's output stays between 0 and 1 for a while when setup or hold time is violated. Asynchronous signals are passed through two flip-flops (a synchronizer) to guard against it.
Gray code
A code in which successive values differ in only one bit. It prevents read errors in rotary encoders and when passing counter values between different clock domains.
MTBF (mean time between failures)
The average interval between failures. For a synchronizer it is the average time between metastable events that fail to resolve and propagate onward, given by MTBF = e^(t_r/τ) ÷ (T_0 × f_clk × f_data). Adding stages lengthens the resolution time t_r and increases it exponentially.
