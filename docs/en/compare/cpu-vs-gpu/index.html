CPU vs GPU: Differences in Architecture and Use

A CPU is built to finish one task as fast as possible, so it has a few powerful cores with large caches and smart control logic. A GPU is built to finish many similar tasks at once, so it has thousands of simple arithmetic units and hides memory delays by switching between huge numbers of threads. CPUs are good at complex, branching, serial work; GPUs are good at massively parallel math such as graphics and deep learning.

AspectCPUGPU
Design goalLow latency: finish a single thread as fast as possibleHigh throughput: finish as much total work as possible
Core countA few to a few hundred complex coresThousands of simple arithmetic units, grouped into larger blocks
Execution modelOut-of-order execution and branch prediction in each core, plus SIMD instructionsSIMT: groups of threads (for example 32) run the same instruction together
Control logic and cacheLarge caches and sophisticated control logic take much of the chip areaMore area goes to arithmetic units; caches are smaller per thread
Hiding memory latencyMostly with caches and prefetchingMostly by switching to other ready threads while one waits
MemoryDDR or LPDDR, typically tens to a few hundred GB/s of bandwidthGDDR or HBM, typically hundreds of GB/s to several TB/s of bandwidth
BranchingHandles branches and irregular code wellSlows down when threads in a group take different branches (divergence)
Data locationWorks directly on main memoryA discrete GPU has its own memory, so data must be copied over a bus such as PCIe
ProgrammingAlmost any language and toolSpecialized models such as CUDA, HIP, OpenCL and graphics shader languages
Typical workloadsOperating systems, databases, control logic, general applicationsGraphics, matrix and vector math, deep learning, simulation

Figures are typical orders of magnitude and vary by process generation and product.

When to use which

CPU
When the work is serial, branchy or needs fast response from one thread: running the operating system, application logic, databases.
GPU
When the same operation is applied to a huge amount of data: rendering images, training and running neural networks, scientific simulation.
Together
Most systems use both. The CPU runs the program and prepares the data, and the GPU does the heavy parallel math. Sending too little work to a GPU can be slower than staying on the CPU, because of the cost of copying data.
