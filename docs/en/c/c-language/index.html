C Programming Basics: key points

C is still widely used for software close to the hardware, such as operating systems, device drivers and microcontroller firmware. It lets you handle memory addresses directly and write fast code, but it also has many rules whose mistakes are hard to notice unless you know them: the size of int differs between implementations, types change in the middle of a calculation, and nothing stops a program that writes past the end of an array.

This topic centers on questions that trace the output of short code when it is actually run. It covers integer type sizes and the fixed-width integer types of stdint.h, integer division, integer promotion and signed/unsigned comparison, operator precedence, bitwise operations, short-circuit evaluation, fall-through in switch statements, pass by value and passing pointers, static variables and lifetimes, pointer arithmetic and arrays, the layout of two-dimensional arrays, strings with strlen and sizeof, where to put const, and function pointers. It then deals with malloc and free, memory leaks, dangling pointers, buffer overflows, null pointers, struct padding, unions and endianness, bit-fields, macros and include guards, conditional compilation, volatile in embedded code, and undefined behavior and compiler optimization. The program outputs have been checked by actually compiling the code with gcc on x86-64 Linux. Pseudocode tracing is covered in "Programming Basics (Pseudocode Tracing)", interrupts and register access with volatile in "Embedded Systems & Firmware", compiler optimizations in detail in "Compilers", and memory layout and linking in "Linkers, Loaders & Executables".
