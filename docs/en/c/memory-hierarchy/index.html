Memory Hierarchy: key points

A CPU operation takes well under a nanosecond, yet reading data from DRAM main memory takes tens to a hundred nanoseconds. To bridge this gap, computers stack a hierarchy from small, fast caches to large, slow main memory and storage, keeping frequently used data in the fast levels.

Caches work because programs exhibit temporal and spatial locality. Understanding direct-mapped and set-associative organizations, splitting addresses into tag, index and offset, the three types of misses and how to compute average memory access time explains why data layout and loop order can change performance several times over.
