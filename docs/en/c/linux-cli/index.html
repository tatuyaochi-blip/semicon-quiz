Linux and Command-Line Basics: key points

Most servers and clouds run Linux, and EDA tools for logic synthesis, circuit simulation and the like are also normally used on Linux servers. There, daily work means typing commands into a shell rather than clicking buttons: inspecting files, filtering logs, and leaving long jobs running after disconnecting.

This topic covers the directory layout, absolute and relative paths, hidden files, hard and symbolic links, wildcards, rwx permissions and their octal notation, umask, execute permission on directories, and sudo and setuid. It then deals with redirection and pipes, grep and regular expressions, counting with sort and uniq, tail -f, cut, sed, awk, find, kill and signals, Ctrl+Z with bg and fg, nohup, exit status with && and ||, quoting and variable expansion, script arguments, conditions and loops, and PATH and export, and finally checks package management, systemctl, cron, df and du, SSH keys, tar, and Git add, commit and push with .gitignore. Command behavior follows bash and the GNU commands (coreutils, grep, sed, findutils, tar), and the outputs in the questions have been checked by actually running them on Linux. How processes and virtual memory work is covered in "OS & Hardware", port numbers and DNS in "Computer Networking Basics", access-control principles in "Information Security Basics", and Git merges and development practices in "Software Development and Project Management".
