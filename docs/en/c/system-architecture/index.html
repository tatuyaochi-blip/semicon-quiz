System Architecture and Reliability: key points

How usable and how hard to stop an information system is depends not only on the performance of one computer but on how equipment is combined and how processing continues when something fails. This design matters especially for systems whose stopping directly affects production, such as a semiconductor fab's manufacturing execution system (MES) and the servers that collect equipment data.

This topic covers system configurations such as client-server, three-tier client-server, peer-to-peer, and batch and online processing, and redundancy concepts such as dual and duplex systems, hot standby, clusters and single points of failure. It also covers, with calculation questions, RAID capacity and the number of failures each level tolerates, backup restore procedures, RPO and RTO, reliability design such as fail-safe, IaaS, PaaS and SaaS, live migration, SAN and NAS, PUE and UPS, and estimating the number of servers needed. It also helps with the system components sections of IT certification exams such as Japan's Fundamental and Applied Information Technology Engineer Examinations.
