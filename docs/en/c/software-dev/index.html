Software Development and Project Management: key points

The quality and delivery of software depend less on how much code is written than on what is built in what order, how it is checked, and how its schedule and cost are managed. In development close to semiconductors and hardware, such as firmware, drivers, EDA scripts and verification environments, how well this is done also shapes the final product.

This topic covers ways of developing software such as the waterfall model and the V-model, Scrum, test-driven development and CI/CD; design ideas such as non-functional requirements, UML, and module cohesion and coupling; and test techniques such as equivalence partitioning, boundary value analysis and branch coverage. It also covers the basics of project and service management, mainly through calculation questions: critical paths in arrow diagrams, three-point estimates, earned value management, risk responses, SLAs and problem management. It also helps with the software development and management sections of IT certification exams such as Japan's Fundamental and Applied Information Technology Engineer Examinations.
