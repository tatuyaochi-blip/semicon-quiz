Cloud and Container Basics: key points

Many web services and corporate systems now run in the cloud as applications packaged in containers. A container isolates processes while sharing the host OS kernel; images are built with Docker, and platforms such as Kubernetes place containers on many machines, keep their number and update them.

This topic starts with namespaces and cgroups, image layers and copy-on-write, Dockerfile instructions and the build cache, publishing ports, volumes and bind mounts, tags and digests, and multi-stage builds, and then deals with Kubernetes Pods, Deployments, Services, Ingress and Secrets, declaring a desired state and reconciliation, rolling update calculations, readiness and liveness probes, HorizontalPodAutoscaler calculations, and requests, limits and Pod placement. It goes on to check the shared responsibility model of the cloud, regions and availability zones, serverless computing and cold starts, block, file and object storage, pay-as-you-go charges and the break-even point of reservations, data transfer charges, IaC and immutable infrastructure, blue-green deployment and canary releases, building artifacts only once, configuration through environment variables, and observability. The values in the calculation questions, including those of the wrong choices, have been checked by computing them in Python. All prices are made-up values. The differences between hypervisors, containers and virtual machines are covered in "OS & Hardware"; IaaS, PaaS and SaaS, scale-out, redundancy, live migration and CDNs in "System Architecture and Reliability"; load balancers and sessions in "Web Technology Basics"; CI/CD in "Software Development and Project Management"; SLAs in "IT Service Management and Systems Audit"; and the shell and environment variables in "Linux and Command-Line Basics".
