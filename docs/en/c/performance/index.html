Performance Analysis: key points

A program's speed is the product of the number of instructions executed, the average cycles per instruction (CPI) and the cycle time. Improving one factor does not make the program faster if another gets worse. Amdahl's law adds that speeding up only part of a program leaves the rest to cap the overall speedup.

Comparing performance correctly requires care in choosing benchmarks, measuring them and averaging results. This topic covers ways to isolate bottlenecks, such as counting cache misses and branch mispredictions with CPU performance counters and using the roofline model to tell whether computation or memory is the limit.
