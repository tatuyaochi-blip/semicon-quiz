Database Basics: key points

From an online shop's inventory to bank accounts, most information systems entrust their data to a database. A relational database holds data as tables, links tables with primary keys and foreign keys, and retrieves and updates the data it needs with a language called SQL.

This topic covers searching with SQL SELECT statements, aggregation with GROUP BY and HAVING, inner and outer joins, and subqueries, counting the results on small example tables. It also covers normalization and E-R diagrams for splitting tables correctly, the ACID properties of transactions, concurrency problems such as lost updates and dirty reads and the isolation levels that prevent them, locks and deadlocks, recovery from failures using logs, how indexes work, and the ideas behind NoSQL, which helps with the database section of IT certification exams such as Japan's Fundamental and Applied Information Technology Engineer Examinations.

If they run without locks in the order T1 reads, T2 reads, T1 writes, T2 writes, what is the final stock count?
  29. Among the problems that occur when transactions run concurrently, which correctly describes a dirty read?

T4 and T5 started after the checkpoint; T4 committed before the failure, and T5 had not committed. In recovery after the failure, which transactions must be rolled forward using the log?
