What is Forward secrecy?

The property that even if a long-term private key leaks later, previously recorded communications cannot be decrypted. Also called perfect forward secrecy (PFS). It is achieved with DHE or ECDHE, which run the key exchange with throwaway values for each connection; because those values are discarded after use, the keys of past sessions cannot be recomputed later. The method of encrypting key material with the server's RSA public key lacks this property, and TLS 1.3 removed it.

Japanese name: 前方秘匿性

In TLS, which of the following key exchange methods provides the property that previously recorded communications cannot be decrypted even if the private key of the server certificate leaks later (forward secrecy)?

  1. AKey exchange such as ECDHE, which uses throwaway values created for each connection
  2. BA method in which the client encrypts the key material it created with the RSA public key of the server certificate and sends it
  3. CA method in which the server and client keep using the same symmetric key, agreed in advance, for every connection
Show answer and explanation

Answer: A. Key exchange such as ECDHE, which uses throwaway values created for each connection

The final E in ECDHE stands for ephemeral (throwaway): a new secret value is used for the key exchange of each connection and discarded afterwards. The private key of the certificate is used only for signing, so even if it leaks later, the shared secrets of past connections cannot be computed. By contrast, with the method of sending key material encrypted with the server's RSA public key, the recorded traffic plus a later-leaked private key allows all past communications to be decrypted. TLS 1.3 removed that method, and key exchange is now based on (EC)DHE with forward secrecy (except when a connection is resumed with a pre-shared key alone).
