What is Secure boot?

A mechanism that verifies the digital signature of the next software at each boot stage and starts only authentic software, forming a chain of trust.

Japanese name: セキュアブート

How the chain of trust works

At power-on, boot code in the chip's ROM loads the first bootloader and checks its digital signature: it hashes the image and verifies the vendor's signature over that hash. Only if the check passes does it run the bootloader, which in turn verifies the next stage or the OS kernel before handing over control. Each link vouches for the next, forming a chain of trust. If any signature fails, boot stops, so malware that rewrites the bootloader or OS boot code cannot run. Smartphones, PCs and many embedded devices use this scheme.

The root of trust in silicon

The chain is only as strong as its first check, so the root of trust must be immutable: boot code in mask ROM, fixed at manufacture, plus the public key used to verify signatures, often stored as a hash in eFuses (one-time programmable fuses) to save space. Public-key cryptography matters here. With a symmetric scheme, the key that verifies could also sign, so extracting it from one device would allow fake firmware for all devices. With public-key signatures, devices hold only a verification key and the signing private key never leaves the vendor's secure facility.

Anti-rollback and locked debug ports

Signature checks alone still accept old firmware, because the vendor legitimately signed it. After a vulnerability is fixed, an attacker could reinstall the vulnerable version, so images carry a version number and the chip stores a minimum allowed version in write-once storage such as eFuses, advancing it with each update. Debug ports such as JTAG and SWD can read and write memory and halt the processor, which would bypass secure boot entirely, so shipped products disable them with fuses or open them only after cryptographic authentication.

Secure boot vs. measured boot

Secure boot enforces: unverified code does not start. Measured boot records: each stage hashes the next and extends the result into TPM (trusted platform module) platform configuration registers, where a new value can only be formed by combining the old value with a new hash. Boot continues regardless, but the record lets software or a remote server later verify exactly what ran. Note also that a signature proves authenticity, not confidentiality; keeping firmware secret needs encryption. Secure boot protects only the start-up path, so it is one layer in defense in depth alongside memory protection, trusted execution environments and tamper resistance.

FAQ

What is the root of trust in secure boot?

Immutable code in the chip's mask ROM together with the public key, or its hash in eFuses, used to verify the first bootloader. Everything later in the chain depends on it being unchangeable.

What is the difference between secure boot and measured boot?

Secure boot refuses to run software whose signature fails. Measured boot lets everything run but records hashes in a TPM so the boot state can be checked or attested later.

Why does secure boot need anti-rollback protection?

Older firmware versions carry valid signatures too, so without a minimum-version counter an attacker could reinstall a version with a known vulnerability.
