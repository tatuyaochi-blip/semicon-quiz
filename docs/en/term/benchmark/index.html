What is Benchmark?

A representative program run under fixed conditions to compare computer or program performance. Choosing ones close to actual use is important.

Japanese name: ベンチマーク

Benchmark appears in 3 practice questions across 2 topics, including Performance Analysis, Automotive Semiconductors and Functional Safety.

Field: Performance Analysis

Why the workload matters

Performance has no single value; it depends on what is run. Integer-heavy code, floating-point kernels, memory-bound processing and I/O-bound tasks stress different parts of a system, so a machine that wins on one may lose on another. A meaningful benchmark is therefore the real application or a program close to it, run with identical inputs, compiler settings and system conditions on every machine being compared. Execution time of the actual workload remains the most trustworthy measure.

How SPEC CPU reports results

Standard suites such as SPEC CPU bundle many programs derived from real applications, for example compilers, compression and physics simulation. For each program, the reference machine's execution time is divided by the measured time to give a ratio, where higher means faster, and the ratios are combined with a geometric mean into a single score. The geometric mean makes relative comparisons independent of which machine serves as the reference. Run rules fix compiler options and procedures, and published results list full hardware and software details.

Microbenchmarks and common pitfalls

Synthetic benchmarks and microbenchmarks isolate one feature, such as memory bandwidth or a single loop, and are useful for diagnosis but poor predictors of overall performance. Typical pitfalls include tuning compilers specifically for a benchmark, comparing runs with different input sizes or settings, ignoring warm-up and caching effects, and reporting one run without checking run-to-run variation. A kernel whose data fits entirely in cache can make a system look much faster than it will be on real data sets.

Benchmark vs. metric

A benchmark is the workload; the metric is what you report from it, such as execution time, throughput in operations per second, latency percentiles or energy per task. MIPS and peak FLOPS are not benchmarks at all: they ignore how much useful work each instruction does and how often peak rates are actually reached. A fair comparison states the benchmark, the metric and the conditions together.

FAQ

Why does SPEC use the geometric mean?

Because the ratios are normalized to a reference machine, the geometric mean gives the same relative ranking whichever reference is chosen, and no single program dominates the score just because its ratio is large.

What is the difference between a synthetic benchmark and an application benchmark?

A synthetic benchmark is an artificial program targeting one feature, while an application benchmark runs real or realistic software. The latter predicts real-world performance better but is harder to standardize.

Does a higher benchmark score mean my program will run faster?

Only if the benchmark resembles your workload. A system tuned for compute-heavy tests may gain little on memory-bound or I/O-bound programs, so test with code close to your actual use.
