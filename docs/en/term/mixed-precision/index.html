What is Mixed precision?

Using different numeric precisions for different parts of a computation, such as multiplying in FP16 and accumulating in FP32, to balance speed and accuracy.

Japanese name: 混合精度

In mixed-precision AI training, why are master weights kept in FP32 while most computation is done in FP16 or bfloat16?

  1. AWhen small updates are added to weights, a low-precision format would lose them to absorption
  2. BFP32 computes faster than FP16, so all weight calculations are left to FP32
  3. CFP16 and bfloat16 values are not allowed to be stored in memory
Show answer and explanation

Answer: A. When small updates are added to weights, a low-precision format would lose them to absorption

Training repeatedly adds very small amounts, learning rate × gradient, to the weights. FP16 and bfloat16 have short significands, so if an update is too small relative to the weight, the rounded sum equals the old weight and the update vanishes (absorption). Weights are therefore kept in FP32 so updates accumulate correctly, while lower-precision copies are used for the forward and backward passes. Lower precision computes faster, and low-precision values can certainly be stored.

In GPU mixed-precision computation, why are multiplications often done in a low precision such as FP16 while accumulation is done in FP32?

  1. AMultiplication cannot be done in FP32
  2. BSumming many products in low precision accumulates rounding error and loses small values, so accumulation alone uses higher precision
  3. CAddition cannot be done in FP16
Show answer and explanation

Answer: B. Summing many products in low precision accumulates rounding error and loses small values, so accumulation alone uses higher precision

FP16 has only a 10-bit significand, so adding a small product to a large running sum can round the product away. A matrix product sums thousands of products, so such errors accumulate and skew the result. So the multiplications, which dominate memory and arithmetic cost, are done in low precision, and only the accumulation uses FP32. Most tensor cores perform this kind of multiply-accumulate in a single instruction.
