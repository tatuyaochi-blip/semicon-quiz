What is Load balancer?

A device or software that distributes users' requests among several servers to spread the load. It checks the state of each server regularly (health checks) and removes failed servers from distribution, so it also serves a redundancy role. Unless it is itself made redundant, the load balancer becomes a single point of failure.

Japanese name: ロードバランサ

A system has two redundant load balancers, three web servers behind them, and a single database server used by all the web servers. Among the devices listed here, which is a single point of failure (a point whose stopping stops the whole system)?

  1. AThe load balancers
  2. BThe web servers
  3. CThe database server
Show answer and explanation

Answer: C. The database server

A single point of failure (SPOF) is a point where a stop in just that one place stops the whole system. The load balancers are made redundant with two units, and there are three web servers and the load balancers can remove a failed server from distribution, so processing continues even if any one of them stops. There is only one database server and every web server uses it, so if it stops, the whole system stops. Making the database server redundant too, for example with a cluster configuration, removes this single point of failure.

Two environments with the same configuration as production are prepared; the current version keeps running in one while the new version is installed and checked in the other, and then the load balancer is switched over to it all at once. If there is a problem, switching back quickly returns to the old version. Which of the following is this release method?

  1. ABlue-green deployment
  2. BCanary release
  3. CRolling update
Show answer and explanation

Answer: A. Blue-green deployment

Blue-green deployment prepares two environments (blue and green) and switches user traffic to the new environment all at once. The old environment is left as it is for a while, so if a problem occurs, simply switching back restores the old version. On the other hand, resources for two environments are needed around the switch, and database schema changes must be made in a form that both the old and new versions can use. A canary release exposes the new version to only some of the requests, and a rolling update replaces servers a few at a time.
