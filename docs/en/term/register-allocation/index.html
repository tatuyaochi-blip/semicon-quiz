What is Register allocation?

Assigning program variables and temporaries to the CPU's limited registers, ensuring values in use at the same time get different registers, often via coloring an interference graph.

Japanese name: レジスタ割り当て

Try it: questions about Register allocation

In register allocation by coloring an interference graph, what do the nodes and edges represent?

  1. ANodes are instructions, and edges are their execution order
  2. BNodes are registers, and edges are the wiring between registers
  3. CNodes are values; edges join values live at the same time
Show answer and explanation

Answer: C. Nodes are values; edges join values live at the same time

In an interference graph, variables and temporaries are nodes, and two values that are both still in use (live) at some point are joined by an edge. Connected values are needed simultaneously, so they cannot share a register. With k registers, if the graph can be colored with k colors so that no neighbors share a color, each color maps directly to a register. If not, some values are spilled to memory. The graph does not represent instruction order or register wiring.

What happens to generated code when register allocation causes a "spill"?

  1. AStores and reloads to the stack are added, tending to slow the code
  2. BThe number of registers grows automatically so every value fits in a register
  3. CUnused values are deleted, reducing the number of instructions
Show answer and explanation

Answer: A. Stores and reloads to the stack are added, tending to slow the code

A spill places some values in memory (the stack) when more values are live than there are registers. Each use of such a value needs a load and each update a store, adding instructions and memory-access delays. Compilers therefore keep heavily used values, such as those in loops, in registers and choose rarely used values to spill. The register count is fixed by the CPU and does not grow, and deleting unused values is a separate matter.
