What is Register allocation?

Assigning program variables and temporaries to the CPU's limited registers, ensuring values in use at the same time get different registers, often via coloring an interference graph.

Japanese name: レジスタ割り当て

Register allocation appears in 3 practice questions across 1 topic, including Compilers.

Field: Compilers

Virtual registers to physical registers

Compilers generate intermediate code using an unlimited supply of virtual registers or temporaries, but a real CPU has only a small fixed set, typically 16 to 32 general-purpose registers. Register allocation decides which values live in which physical registers at each point and which must be kept in memory instead. Because registers are far faster than even an L1 cache access, good allocation has a large effect on speed, especially inside loops. The hard rule is that two values needed at the same time cannot share a register.

Liveness and the interference graph

The allocator first runs liveness analysis over the control-flow graph to find, at every point, which values may still be read later. It then builds an interference graph: each value is a node, and an edge joins two values that are live at the same time. Assigning registers becomes coloring the graph with k colors, where k is the number of available registers, so that no neighbors share a color. Optimal coloring is NP-complete in general, so compilers use heuristics such as Chaitin-style simplification, repeatedly removing nodes with fewer than k neighbors.

Spilling and its cost

When the graph cannot be colored with k colors, some values are spilled: they are kept in a stack slot, with a store after each definition and a load before each use. Spills add instructions and memory traffic, so the allocator estimates a spill cost for each candidate, weighting uses by loop nesting depth, and prefers to spill values that are used rarely but interfere with many others. Splitting a long live range into shorter pieces can also let a value stay in a register where it matters most.

Calling conventions, coalescing and linear scan

Real allocators must respect the calling convention: arguments and return values use specific registers, caller-saved registers are clobbered by calls, and callee-saved registers must be restored before returning. Coalescing assigns the same register to the source and destination of a copy when they do not interfere, deleting the move instruction. Just-in-time (JIT) compilers often use linear-scan allocation instead of graph coloring, walking sorted live intervals in a single pass, which is much faster to run at the cost of somewhat lower code quality.

  2. BNodes are registers, and edges are the wiring between registers
  3. CNodes are values; edges join values live at the same time
Show answer and explanation

Answer: C. Nodes are values; edges join values live at the same time

In an interference graph, variables and temporaries are nodes, and two values that are both still in use (live) at some point are joined by an edge. Connected values are needed simultaneously, so they cannot share a register. With k registers, if the graph can be colored with k colors so that no neighbors share a color, each color maps directly to a register. If not, some values are spilled to memory. The graph does not represent instruction order or register wiring.

What happens to generated code when register allocation causes a "spill"?

  1. AStores and reloads to the stack are added, tending to slow the code
  2. BThe number of registers grows automatically so every value fits in a register
  3. CUnused values are deleted, reducing the number of instructions

Answer: A. Stores and reloads to the stack are added, tending to slow the code

A spill places some values in memory (the stack) when more values are live than there are registers. Each use of such a value needs a load and each update a store, adding instructions and memory-access delays. Compilers therefore keep heavily used values, such as those in loops, in registers and choose rarely used values to spill. The register count is fixed by the CPU and does not grow, and deleting unused values is a separate matter.

FAQ

What is register spilling?

Spilling is keeping a value in memory, usually a stack slot, because there are not enough registers for everything live at that point; the compiler inserts stores and loads around its uses, which slows the code.

Why is register allocation a graph coloring problem?

Values live at the same time interfere and need different registers, so if values are nodes and interferences are edges, giving each node one of k colors with no neighbors alike is exactly assigning k registers.

What is the difference between graph coloring and linear scan register allocation?

Graph coloring builds a full interference graph and usually produces better code but takes longer; linear scan allocates in one pass over sorted live intervals, trading some code quality for much faster compilation.
