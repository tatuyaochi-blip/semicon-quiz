What is ML-KEM?

A lattice-based key encapsulation mechanism (KEM) standardized by the US NIST in August 2024 as FIPS 203. The name stands for Module-Lattice-Based Key-Encapsulation Mechanism, and it is based on CRYSTALS-Kyber. Its security rests on the difficulty of the Module-LWE problem, recovering a secret from a system of linear equations with small errors added, which is believed to be hard even for quantum computers. There are three parameter sets: ML-KEM-512, ML-KEM-768 and ML-KEM-1024. It is used in protocols such as TLS to replace, or be combined with, ECDHE key exchange.

Japanese name: ML-KEM

What a key encapsulation mechanism is

A KEM consists of three operations: key generation, encapsulation and decapsulation. The sender encapsulates with the recipient's public key, obtaining a random shared secret together with a ciphertext that wraps it, and sends the ciphertext. The recipient decapsulates with the private key and obtains the same shared secret. Unlike Diffie–Hellman key exchange, the sender does not need a long-term key pair of its own.

Typical sizes

For ML-KEM-768 the public key (encapsulation key) is 1,184 bytes, the ciphertext 1,088 bytes and the shared secret 32 bytes. The public value of the elliptic-curve key exchange X25519 is 32 bytes, so much more data is sent. The computation itself, on the other hand, is light and is said to be no slower than elliptic-curve key exchange.

Hybrid use

As a hedge against concerns about a new scheme, hybrid key exchange that feeds both the X25519 and the ML-KEM-768 shared secrets into key derivation (such as X25519MLKEM768) has started to be used in TLS 1.3 as of 2025. As long as either one is secure, the resulting key is protected.

A KEM consists of three operations: key generation, encapsulation and decapsulation. The sender encapsulates with the receiver's public key, obtaining a random shared secret together with a ciphertext that wraps it, and sends only the ciphertext. The receiver decapsulates with its private key to obtain the same shared secret, after which they use symmetric-key encryption with keys based on it. A KEM is a mechanism for sharing keys, so a separate signature such as ML-DSA is used to authenticate the other party.

ML-KEM is a new scheme, and the possibility of implementation errors or new attacks being found cannot yet be fully ruled out. X25519, on the other hand, is weak against quantum computers but has a long track record of security against classical computers. In hybrid key exchange both shared secrets are concatenated and fed into a key derivation function, so an attacker must break both to obtain the key, and communications recorded today are also protected against decryption by future quantum computers. As of 2025, this combination (such as X25519MLKEM768) has started to be used in TLS 1.3.

FAQ

Can ML-KEM be used for signatures?

No. ML-KEM is a mechanism for sharing keys. For post-quantum signatures, ML-DSA (FIPS 204) and SLH-DSA (FIPS 205), standardized together with it in August 2024, are used.

Is it the same as quantum key distribution (QKD)?

No. ML-KEM rests on the difficulty of a mathematical problem and runs unchanged on ordinary computers and networks. Quantum key distribution shares keys by using quantum properties of photons and the like, and needs dedicated equipment and channels.
