What is Weak scaling?

Parallel performance evaluation that fixes problem size per processor while growing the total and checks whether time stays constant.

Japanese name: 弱いスケーリング

Weak scaling appears in 1 practice question across 1 topic, including Performance Analysis.

Field: Performance Analysis

What weak scaling measures

Weak scaling is an evaluation that keeps the amount of work per processor constant, grows the number of processors and the total problem size in the same proportion, and checks how well the run time stays constant. If one processor solves a simulation with a million grid cells, for example, 100 processors solve one with 100 million cells. Ideally the time does not change, and the ratio T1/TN of the time on one processor to the time on N processors is taken as the weak-scaling efficiency. It is the right view when more processors are meant to solve larger problems or finer calculations in the same time.

How it differs from strong scaling

Strong scaling fixes the problem size, adds processors and measures how much the time drops. It follows Amdahl's law, under which the fraction that cannot be parallelized caps the speedup. In weak scaling, a larger problem has more parallel work and a smaller serial fraction, so, as Gustafson's law indicates, the work done grows almost in proportion to the number of processors. The same program may plateau under strong scaling yet scale well under weak scaling, so results cannot be compared without stating which was measured.

Estimates from Gustafson's law

If s is the serial fraction of the run time on N processors, the scaled speedup relative to doing the same work on one processor is S = N − s × (N − 1). With s = 0.05 and N = 100, for example, S is about 95. By contrast, if a program whose serial part is 5% of its single-processor run time is run on 100 processors at a fixed problem size, Amdahl's law limits the speedup to about 17. Gustafson's formula, however, assumes that the serial time does not depend on problem size and that communication costs are negligible.

Why the time does not stay constant

In real weak-scaling runs the time usually creeps up as processors are added. Exchanging boundary data between neighboring domains stays roughly constant as the count grows, but collective operations that compute global sums or maxima, such as all-reduce, add steps and waiting time as processors increase. Load imbalance, network congestion and concentrated file I/O also reduce efficiency. Adding GPUs while keeping the per-GPU batch size fixed in distributed AI training is also a form of weak scaling, but because the global batch grows, its effect on training convergence must be checked separately.

FAQ

What is the difference between strong and weak scaling?

Strong scaling fixes the total problem size, adds processors and measures how much the time drops. Weak scaling fixes the work per processor, grows the total and checks whether the time stays constant. The former corresponds to Amdahl's law and the latter to Gustafson's law.

How is weak-scaling efficiency calculated?

It is the ratio T1/TN of the time T1 to solve a base-size problem on one processor to the time TN to solve an N-times-larger problem on N processors. If the time does not change the efficiency is 100%; for example, T1 = 100 s and TN = 125 s give 80%.

Why can weak scaling look good when strong scaling looks poor?

Making the problem larger adds parallel work, so communication and serial parts become relatively smaller. Adding processors to a fixed problem shrinks the computation per processor while communication and serial parts do not shrink, so their share grows and efficiency falls.
