What is Symbol resolution?

The linker step that matches each function or variable name referenced in a file with its definition. No definition gives an undefined-reference error; more than one gives a multiple-definition error.

Japanese name: シンボル解決

What symbol resolution does

Each object file carries a symbol table listing the names it defines, such as functions and global variables, and the names it references but does not define. If main.c calls sum and sum.c defines it, main.o records an undefined reference to sum and sum.o records a definition. Symbol resolution is the linker step that gathers all symbol tables and binds every reference to exactly one definition. It comes before relocation, which then writes the final addresses of those definitions into the instructions and data that refer to them.

Undefined and multiple definitions

If no definition exists for a reference, the linker reports an undefined reference, typically because a source file or library was not linked or a name is misspelled. If two non-static global definitions share a name, it reports a multiple-definition error, because it cannot decide which one references should bind to. Declaring a function static gives it internal linkage, hiding it from other files so the same name can be reused. A declaration such as extern int count; reserves no storage and simply promises that a definition exists elsewhere.

Weak symbols and library order

A weak symbol is a fallback definition that is used only if no ordinary (strong) definition with the same name exists, a pattern embedded code uses for default interrupt handlers. Static libraries are archives of object files, and the GNU linker processes its inputs from left to right, extracting a library member only if it defines a symbol that is undefined at that moment. A command such as gcc -lmylib main.o therefore fails, because nothing in main.o is unresolved yet when the library is scanned. Libraries go after the files that use them.

C++ names and dynamic linking

The linker matches symbols purely by name strings. C++ allows overloaded functions such as print(int) and print(double), so the compiler encodes argument types and namespaces into the symbol name, which is called name mangling. C does not mangle names, so C++ code declares C functions with extern "C" to make the names match. With shared libraries, part of symbol resolution is postponed: the dynamic linker binds references to library functions at load time or on first call, typically through PLT stubs and GOT entries.

FAQ

What causes an undefined reference error?

The linker found a reference to a function or variable but no definition in any linked object file or library, often because a file or library is missing from the link command, is listed in the wrong order, or a name does not match.

What is the difference between symbol resolution and relocation?

Symbol resolution decides which definition each referenced name refers to. Relocation then patches the actual addresses of those definitions into the machine code and data that use them.

How do I fix a multiple definition error?

Make sure each non-static global function or variable is defined in exactly one source file, use extern declarations in headers, and mark file-local items static so their names do not collide.
