What is RTL (register-transfer level)?

A design abstraction that describes circuits by how data moves and is processed between registers. It is written in Verilog or VHDL and serves as the input to logic synthesis.

Japanese name: RTL(レジスタ転送レベル)

Field: IC design flow and EDA

What an RTL description says

An RTL model divides a synchronous circuit into two kinds of things: registers, which capture new values on a clock edge, and the combinational logic that computes those values from current register contents and inputs. Writing at this level means stating, cycle by cycle, what each register will hold next, without choosing specific gates. In Verilog this appears as clocked always blocks with nonblocking assignments for flip-flops and separate combinational blocks or assign statements. All blocks describe hardware that operates concurrently, which is the biggest mental shift for programmers coming from sequential software.

From RTL to gates

RTL sits between algorithm-level descriptions and the gate-level netlist. Above it, high-level synthesis (HLS) can generate RTL from C or C++ by scheduling operations into clock cycles. Below it, logic synthesis maps RTL onto flip-flops and gates from a standard-cell library, optimizing against timing, area and power constraints, and place and route then produces the layout. Some intent is deliberately kept outside the RTL: the Unified Power Format (UPF, IEEE 1801) describes power domains, shutoff, isolation and level shifters in separate files so the power architecture can change without editing the RTL.

Synthesizable vs. simulation-only code

Only part of an HDL maps to hardware. Delay statements such as #10 advance simulation time but are ignored by synthesis, because real delay comes from gates and wires. System tasks like $display, file I/O and the case-equality operator === are testbench tools. Classic coding pitfalls change the hardware itself: a combinational block that does not assign an output on every path infers an unintended latch, and mixing blocking and nonblocking assignments carelessly can make simulation disagree with the synthesized circuit. Good RTL style keeps simulation and hardware behavior identical.

Verifying RTL

Most verification effort happens at RTL, where simulation is fast enough for millions of cycles. Progress is measured by code coverage, which tracks executed lines and branches, and functional coverage, which tracks specified scenarios; full code coverage alone does not prove every specified combination was tested. Some bugs are invisible to RTL simulation. Clock-domain-crossing (CDC) tools catch missing synchronizers, because simulated flip-flops never go metastable. Formal equivalence checking confirms the netlist matches the RTL, and gate-level simulation with SDF delay data exposes reset, unknown-value and timing problems.

Answer: A. Verilog HDL and VHDL

RTL design uses hardware description languages such as Verilog HDL (and its extension SystemVerilog) or VHDL to describe how data flows between registers each clock cycle. Unlike software languages, the described operations run concurrently as hardware. HTML describes web pages and SQL queries databases; neither can describe circuits.

  2. BLogic synthesis
  3. CPlace and route
Show answer and explanation

Answer: A. High-level synthesis (HLS)

High-level synthesis automatically allocates functional units and registers and schedules which clock cycle each operation occurs in, generating RTL from behavioral descriptions in C/C++ and similar languages. Different pipelining and parallelism options can be explored from the same source, raising abstraction and shortening development. It is used for signal-processing and AI accelerator design. Logic synthesis turns RTL into gates.

FAQ

What is the difference between RTL and a gate-level netlist?

RTL describes registers and the logic between them in a hardware description language without choosing specific gates, while a gate-level netlist is the synthesized result, a list of actual library cells and their connections.

Is RTL the same as Verilog?

No. RTL is an abstraction level; Verilog, SystemVerilog and VHDL are languages that can express RTL as well as testbenches and lower-level gate descriptions.

Why does my RTL simulate correctly but fail after synthesis?

Common causes are simulation-only constructs such as delays, inferred latches from incomplete assignments, incomplete sensitivity lists and blocking/nonblocking assignment misuse, which make simulated behavior differ from the generated gates.
