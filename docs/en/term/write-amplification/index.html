What is Write amplification?

The amount of data actually written to flash exceeding what the host wrote, because of garbage collection and similar operations. The larger it is, the shorter the SSD's life.

Field: SRAM and flash memory

Where the extra writes come from

NAND flash is programmed in pages but erased only in much larger blocks containing hundreds or more pages, and a page cannot be overwritten in place. When the host updates data, the SSD writes the new version to a fresh page and marks the old one invalid. To reclaim space, garbage collection picks a block with many invalid pages, copies its remaining valid pages elsewhere, and erases it. Those copies are writes the host never asked for. Wear leveling, which moves rarely changed data off lightly worn blocks, and the drive's own mapping-table updates add more.

Defining and estimating WAF

The write amplification factor (WAF) is the amount of data written to flash divided by the amount written by the host. Large sequential writes tend to invalidate whole blocks at once, so garbage collection has little to copy and WAF stays near 1. Small random writes scatter invalid pages across many blocks, so each reclaimed block still holds much valid data and WAF can reach several. The fuller the drive and the less spare area it has, the fewer mostly-empty blocks are available, and write amplification and performance loss both grow.

Effect on lifetime

Each flash block survives only a limited number of program/erase cycles, so write amplification directly consumes endurance. As a simple illustration, if a 1 TB drive's flash could withstand 1,000 cycles, its raw budget would be about 1 PB of flash writes; at a WAF of 3, the host could write only about a third of that. Drive endurance ratings in terabytes written already assume some typical workload WAF, so a workload dominated by small random writes can wear a drive out faster than its rating suggests.

How to reduce it

TRIM tells the drive which data is obsolete so garbage collection does not copy it. Over-provisioning, spare flash capacity hidden from the host, gives garbage collection more free blocks to work with, so victim blocks contain fewer valid pages; enterprise drives reserve a larger share for this reason. Controllers that compress data before writing can push the effective WAF below 1 for compressible data. Writing in large, aligned, sequential chunks and separating short-lived from long-lived data in different blocks also help, which is the idea behind zoned storage interfaces that let the host place data deliberately.

Answer: C. The amount of data actually written to flash exceeding the amount written by the host

Because flash cannot overwrite and erases by block, garbage collection adds extra writes such as copying valid data to new blocks, so the flash receives more data than the host wrote. The ratio is the write amplification factor (WAF), which can reach several times under small random writes. TRIM, spare area and data compression reduce it, protecting lifespan and performance.

FAQ

What is a good write amplification factor?

A WAF near 1 is ideal and typical for sequential workloads; small random writes on a nearly full drive can push it to several. Lower is better for both endurance and sustained write speed.

Can write amplification be less than 1?

Yes, if the controller compresses or deduplicates data, it can write less to flash than the host sent, giving an effective WAF below 1 for compressible data.

Does over-provisioning reduce write amplification?

Yes. Extra spare area means garbage collection can choose blocks with fewer valid pages to copy, which lowers WAF, especially under random write workloads.
