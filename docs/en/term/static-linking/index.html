What is Static linking?

Linking that copies the code of the libraries used into the executable. It runs without the libraries present, but the file is larger and library fixes require rebuilding.

Japanese name: 静的リンク

What the linker does

In static linking the linker reads the program's object files and the static libraries named on the command line, pulls in the archive members needed to resolve undefined symbols, and merges like sections together: all code into one text section, all initialized data into one data section, and so on. It then assigns final addresses, patches every reference using the relocation entries and writes a single executable. With GCC, the -static option requests this for all libraries, including the C standard library, provided static versions of them are installed.

Static vs. dynamic linking

A statically linked executable is self-contained: nothing has to be found at start-up, there is no symbol binding by a dynamic linker and calls into library code are direct. The costs are size and maintenance. Each program carries its own copy of every library routine it uses, so copies are not shared in memory across processes as shared-library pages are, and a security fix in a library reaches the program only when it is relinked. Dynamic linking reverses these trade-offs, at the price of depending on compatible library versions on every machine where the program runs.

Limits of self-containment

A static executable still depends on the CPU architecture and on the operating system's system-call interface, so it cannot simply run on another OS. Some library features also assume dynamic loading behind the scenes. GNU libc, for example, warns that functions such as getaddrinfo, used in statically linked programs, still require shared libraries at run time for name-service lookups. Static linking also means the program cannot use dlopen-style plug-ins as easily, since those are shared objects expecting a dynamic linker.

Where you will meet it

Firmware for microcontrollers is almost always statically linked into one image, because there is no loader or file system to supply libraries at run time. On servers and in minimal container images, static executables are valued because a single file can be copied anywhere with a compatible kernel. Developers also use static linking for command-line tools that must run on many distributions without worrying about library versions, accepting a larger file in exchange for avoiding problems such as a missing or incompatible shared library.

Answer: A. The code of the libraries used is copied into the executable

With static linking, the linker extracts the needed functions from static libraries (.a files on Linux) and builds them into the executable. It runs even where the library is absent and needs no binding at start-up, but the executable grows and every program using the library carries its own copy. Fixes to the library are not picked up unless the program is rebuilt.

FAQ

How do I statically link a C program with gcc?

Add -static to the link command, for example gcc -static main.c -o main. Static (.a) versions of every library involved, including the C library, must be installed for this to succeed.

Why is my statically linked executable so much bigger?

It contains copies of all library code it uses, including parts of the C runtime, instead of referring to shared libraries already on the system. Stripping symbols and linking with section garbage collection can reduce the size.

Is a statically linked program faster?

Start-up is usually faster because no shared libraries need loading and binding, and calls avoid an indirection. For most long-running programs the difference in steady-state speed is small.
