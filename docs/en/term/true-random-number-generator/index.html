What is True random number generator (TRNG)?

A circuit generating random numbers from unpredictable physical phenomena such as thermal noise or oscillator jitter, serving as the source for cryptographic keys.

Japanese name: 真性乱数生成器

How it differs from a pseudorandom generator

The pseudorandom number generators computers normally use produce a sequence by fixed calculations from an initial value called a seed, so the same seed gives the same sequence. Random numbers for cryptographic keys and nonces must above all be impossible for an attacker to guess, which means the seed itself must be unpredictable. A true random number generator (TRNG) is a circuit that produces random bits from physically unpredictable phenomena such as thermal noise or jitter in oscillator periods, and it serves as that source of unpredictability. One built into a chip is called a hardware TRNG, and many microcontrollers, SoCs and security chips include one.

Examples of entropy sources

The source of unpredictability is called the entropy source. A common on-chip approach samples the output of free-running ring oscillators with another clock, extracting bits from the accumulated tiny variations in their periods (jitter). Other approaches amplify the thermal noise of a resistor and turn it into 0s and 1s with a comparator, or release a latch from an unstable state and use which way it settles. Discrete sources include noise from diode breakdown and quantum phenomena such as photon detection. Whatever the method, estimating how much unpredictability the bits actually carry is central to the design.

Post-processing and health tests

Raw bits taken from a physical process may have more 0s than 1s or correlation between successive bits. A conditioning step, such as compressing many bits with a hash function, raises the unpredictability per bit. In real products the result is usually used to seed a cryptographic deterministic random bit generator (DRBG), which produces large amounts of random data quickly. Health tests built into the design continuously check that the same value does not repeat too often and that no value appears too frequently, and stop output if the noise source fails. NIST's SP 800-90 series in the US and AIS 31 from Germany's Federal Office for Information Security set out how such generators are evaluated.

Attacks and design cautions

A TRNG's output characteristics change with temperature, supply voltage, manufacturing variation and aging. If an attacker injects noise into the supply or uses external electromagnetic signals to pull ring oscillators onto a common frequency, jitter can drop and the output can become easier to predict. Output that looks random after post-processing is not secure if the underlying entropy is insufficient. Designs therefore combine worst-case entropy estimates, health tests at startup and during operation, and mechanisms that stop output on failure. Passing statistical randomness tests is necessary, but on its own it does not prove the output is unpredictable.

A pseudo-random sequence can be regenerated if its seed is known, so guessing the seed means guessing the keys. A TRNG generates bits from unpredictable physical phenomena such as resistor thermal noise or ring-oscillator period jitter. In practice, TRNG output often seeds a cryptographic pseudo-random generator, combining speed with unpredictability.

FAQ

What does TRNG stand for?

True random number generator. It is a circuit that produces random numbers from physical phenomena such as thermal noise and oscillator jitter, used to generate cryptographic keys and seeds for pseudorandom generators.

Why isn't raw TRNG output used directly as a key?

Raw bits often have bias and correlation, so each bit carries less than one bit of unpredictability. The output is therefore compressed by post-processing and then usually used to seed a cryptographic deterministic random bit generator (DRBG), which can produce large amounts of random data quickly.

Do CPUs contain a TRNG?

Many CPUs and SoCs do. For example, x86 CPUs provide the RDRAND instruction for reading hardware random numbers and the RDSEED instruction for reading values intended as seeds, and Armv8.5-A added instructions such as RNDR. Operating systems mix such sources with other inputs to seed their random number generators.
