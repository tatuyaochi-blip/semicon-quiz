What is Stack?

A last-in, first-out (LIFO) data structure in which the element added last is removed first. Adding an element is called push and removing one is called pop. Stacks are used to manage return addresses and local variables in function calls (the call stack), to evaluate expressions in Reverse Polish notation and for depth-first search.

Japanese name: スタック

Try it: questions about Stack

A function that calls no other functions (a leaf function) often does not need to save ra on the stack. Why?

  1. ABecause leaf functions do not use the ret instruction
  2. BBecause the CPU automatically pushes the return address of leaf functions
  3. CBecause it calls no one, ra is never overwritten and the return address stays intact
Show answer and explanation

Answer: C. Because it calls no one, ra is never overwritten and the return address stays intact

Every jal overwrites ra, so a function that calls others must first save its own return address on the stack. A leaf function never executes jal, so ra stays intact and it can ret without saving it. If it also avoids callee-saved registers, it does not even need a stack frame. x86's call instruction always pushes the return address on the stack, which is a difference from RISC-V.

In RISC-V, what happens if a recursive function (one that calls itself) forgets to save ra on the stack?

  1. AThe inner call overwrites ra, so the outer invocation cannot return to its real caller
  2. BNothing goes wrong, because the CPU saves ra automatically
  3. CThe result is doubled regardless of recursion depth
Show answer and explanation

Answer: A. The inner call overwrites ra, so the outer invocation cannot return to its real caller

The recursive jal overwrites ra with "the instruction after my own call". If ra was not saved, when the outer invocation executes ret it returns into itself instead of to its original caller, looping or misbehaving. That is why any function that calls another must save ra on the stack in its prologue and restore it in its epilogue.
