What is Trusted Platform Module (TPM)?

A security chip or function that generates and stores keys, records measurements of booted software and attests to platform state.

Japanese name: TPM

Trusted Platform Module (TPM) appears in 5 practice questions across 3 topics, including Hardware Security, Applied Cryptography, Hardware Security: Advanced Topics and Trends.

Field: Hardware Security

What is inside a TPM

A Trusted Platform Module is a tamper-resistant security chip, or an equivalent function implemented in firmware on the main processor, often called fTPM. It contains a random-number generator, engines for hashing, signing and encryption, protected non-volatile storage and a set of platform configuration registers (PCRs). Keys can be generated inside the TPM and used there without the private part ever leaving in the clear. The interface is defined by the Trusted Computing Group, and current PCs use version 2.0.

Measured boot and PCRs

In measured boot, each stage hashes the next piece of software before running it and extends the hash into a PCR. Extending means the new PCR value is the hash of the old value concatenated with the new measurement; software cannot write a PCR directly, and the boot-measurement PCRs are cleared only by a platform reset. The final values therefore summarize the whole boot sequence in order, and any change produces different values. Unlike secure boot, measured boot does not stop anything from running; it produces evidence for later checks.

Sealing and remote attestation

Two uses follow from PCRs. Sealing binds data, such as a disk-encryption key, to specific PCR values, so the TPM releases it only when the platform booted the expected software; a removed disk or a modified bootloader gets nothing. In remote attestation, the TPM signs a report of its PCR values with a key that cannot be extracted, and a server checks the signature and measurements before granting secrets, services or network access. A fresh random challenge from the server prevents replaying an old report.

TPM vs. secure element and TEE

A TPM is a standardized platform-trust component focused on measurement, key protection and attestation, and it is relatively slow; bulk encryption runs on the CPU using keys the TPM has released. A secure element is a smart-card-class chip for payment or identity credentials, and a trusted execution environment (TEE) is an isolated mode of the main processor that runs trusted code. Systems often combine them, and attestation can be rooted in either a TPM or a TEE.

FAQ

What is the difference between TPM and secure boot?

Secure boot blocks unsigned or altered boot software from running. A TPM records measurements of what booted, protects keys and can prove the platform state to others; the two are often used together.

What is a PCR in a TPM?

A platform configuration register holds a running hash of measured software. It can only be extended by hashing in new measurements, so its value reflects the exact sequence of what was loaded since reset.

What is a firmware TPM (fTPM)?

It is TPM functionality implemented in firmware running in an isolated environment of the main processor instead of a separate chip. It offers the same interface but different physical-attack resistance from a discrete TPM.
