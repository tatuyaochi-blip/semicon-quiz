What is Constant folding?

An optimization that evaluates expressions whose values are known at compile time and replaces them with the resulting constant, such as turning 3 * 4 into 12. It removes run-time computation.

Japanese name: 定数畳み込み

Field: Compilers

What the compiler actually does

During optimization the compiler scans its intermediate representation for operations whose operands are all constants, evaluates them, and replaces the operation with the resulting literal. Arithmetic, bit operations, shifts, casts and comparisons can all be folded. Folding a comparison is especially powerful: if a condition such as 10 > 100 becomes a known false, the branch it guards can never run. Compilers usually fold together with algebraic simplification, rewriting expressions like x * 1 or x + 0 into x, although strictly that is a separate transformation because x itself is not constant.

Working with propagation, inlining and dead-code elimination

Constant folding rarely acts alone. Constant propagation replaces uses of a variable known to hold a constant with that constant, which creates new opportunities for folding, whose results can be propagated again. For example, n = 8; m = n * 2; return m + 1 collapses to return 17, after which dead-code elimination removes the unused assignments. Inlining feeds the loop: once a call sq(6) is replaced by its body, 6 * 6 + 1 folds to 37. Compilers based on SSA form often combine propagation, folding and unreachable-branch removal in one algorithm called sparse conditional constant propagation.

Preserving the program's meaning

A folded result must be exactly what the target machine would have computed at run time. The compiler must therefore emulate the target's integer widths and wraparound, which matters when cross-compiling from a 64-bit host to a 32-bit target. Floating-point folding must reproduce IEEE 754 rounding for each operation in source order, which is why compilers do not reassociate floating-point expressions unless options such as fast-math permit it. Operations that would fault, such as integer division by zero, must not be turned into a compile-time error unless the code is certain to execute.

Constant folding versus language-level constant expressions

Some evaluation at compile time is required by the language rather than chosen by the optimizer. In C, array sizes, case labels and initializers of static variables must be constant expressions, and C++ constexpr functions can be evaluated at compile time on request. Optimization-level constant folding is broader and optional: it applies anywhere in the program, including values that only became constant after propagation or inlining, and it can happen at several stages, from the front end through the intermediate representation to instruction selection, where an address offset plus a constant may be merged into one immediate.

Answer: B. Computing x = 3 * 4 at compile time to produce x = 12

Constant folding evaluates expressions whose values are fixed at compile time and replaces them with the resulting constants. 3 * 4 always yields 12, so there is no need to multiply at run time. Combined with constant propagation, computations through variables can be folded as well. There are caveats, such as matching rounding behavior for floating point. Replicating a loop body is loop unrolling, and merging function calls is a different optimization.

FAQ

What is the difference between constant folding and constant propagation?

Constant folding evaluates an expression whose operands are all constants, such as 3 * 4 becoming 12. Constant propagation substitutes a variable's known constant value into its uses, which often creates new expressions that can then be folded.

Does constant folding happen with optimization turned off?

Simple literal expressions are often folded even without optimization, because front ends evaluate them while parsing. Folding through variables, function inlining and branch removal generally require optimization to be enabled.

Can constant folding change floating-point results?

A conforming compiler folds floating-point operations with the same IEEE 754 rounding the hardware would use, so results do not change. Options that relax floating-point rules, such as fast-math, allow reassociation and can change the last bits of results.
