What is Bus snooping?

A coherence approach in which each cache watches other cores' reads and writes on a shared bus or similar and updates its own line states. It suits small core counts.

Japanese name: スヌーピング

Try it: questions about Bus snooping

Which describes the snooping approach to cache coherence?

  1. AThe OS periodically inspects every cache and fixes discrepancies
  2. BEach core's cache watches other cores' reads and writes on a shared bus or similar and updates its own line states
  3. CThe programmer manually sends values to other cores on each write
Show answer and explanation

Answer: B. Each core's cache watches other cores' reads and writes on a shared bus or similar and updates its own line states

In snooping, every core's read and write requests reach all caches, and each cache checks whether it holds the same line and invalidates it or supplies data. It is simple and suits a small number of cores. As cores increase, broadcasting every request to every cache generates too much traffic, so large systems use directory-based coherence.

Why do systems with many cores use directory-based coherence instead of snooping?

  1. ARecording which cores hold each line lets notices go only to the cores involved, reducing traffic
  2. BDirectory-based coherence makes caches unnecessary
  3. CDirectory-based coherence can notify all cores on every write
Show answer and explanation

Answer: A. Recording which cores hold each line lets notices go only to the cores involved, reducing traffic

Directory-based coherence keeps a table (the directory) recording, for each line, which cores hold copies and in what state. On a write, it consults the directory and sends invalidations only to the cores holding copies. With less traffic than snooping, which notifies all caches at once, it is used in CPUs with dozens of cores or more, such as server processors.
