What is Page fault?

An exception raised when an accessed page is not mapped to physical memory or the access type is not permitted. The OS either supplies the page and retries the instruction or treats it as an illegal access.

Japanese name: ページフォルト

Field: OS & Hardware

What happens during a page fault

When the memory management unit (MMU) translates a virtual address, it checks the page-table entry. If the entry is not valid or the access type is not allowed, the MMU raises a page fault, a synchronous exception tied to the faulting instruction. The OS handler checks whether the address belongs to a region the process may use. If so, it finds a free physical frame, evicting another page if necessary, fills it from disk or with zeros, marks the entry valid and restarts the faulting instruction. If not, the process receives a segmentation fault.

Minor vs. major faults

Not every page fault touches the disk. A minor (soft) fault is resolved without I/O, for example when a page is already in memory in the file cache, needs only a fresh zero-filled frame, or must be copied for copy-on-write. A major (hard) fault must read the page from storage and costs tens of microseconds on a fast SSD to milliseconds on a hard disk. The difference matters enormously: with a 100 ns memory access and an 8 ms fault service time, a major fault rate of just one per million accesses raises the average access time from 100 ns to about 108 ns.

Page faults used on purpose

Operating systems rely on faults as a lazy-evaluation tool. Demand paging maps a program without loading it, then loads each page on first touch. Memory-mapped files (mmap) read file contents in the same way. Copy-on-write lets fork share pages read-only and copy only the pages that are later written. Guard pages with no access rights sit beyond the stack so runaway recursion faults instead of corrupting data. On NUMA systems, Linux places a page on the node of the thread that first writes it, so initialization order affects performance.

Page fault vs. TLB miss vs. cache miss

These three are often confused. A cache miss is handled entirely by hardware, which fetches the line from a lower memory level. A TLB miss means the translation is not cached in the translation lookaside buffer; on most modern CPUs a hardware page-table walker fetches it, and if the entry is valid, no exception occurs. Only when the page-table entry itself is invalid or forbids the access does a page fault reach the OS. When faults become so frequent that the system spends most of its time paging, the condition is called thrashing.

When does a page fault occur?

  1. AWhen data is not in the cache and is fetched from main memory
  2. BWhen the accessed page is not mapped to physical memory
  3. CWhen the TLB holds the translation and the physical address is found immediately

Answer: B. When the accessed page is not mapped to physical memory

A page fault is an exception raised when the accessed page's page-table entry is invalid, meaning it is not mapped to physical memory (it was paged out or never loaded), or when the access is not permitted, such as writing a read-only page. The OS supplies the page and retries the instruction. A cache miss is handled entirely in hardware and is not an exception. If the TLB has the translation, it completes at once and no fault occurs.

When a page fault occurs on a page that was evicted to disk, what does the OS do?

  1. AIt immediately terminates the program abnormally without loading the page
  2. BAfter loading the page, it skips the faulting instruction and resumes at the next one
  3. CIt loads the page from disk, updates the table and retries the instruction
Show answer and explanation

Answer: C. It loads the page from disk, updates the table and retries the instruction

For a page fault from a legitimate access, the OS finds a free physical page (evicting another if needed), reads the contents from disk and marks the page-table entry valid. It then re-executes the faulting instruction from the start, so the program continues as if nothing happened. Skipping the instruction would leave the access undone and produce wrong results. Abnormal termination is for illegal accesses to unmapped addresses.

FAQ

Is a page fault an error?

Not necessarily. Most page faults are normal events used for demand paging, copy-on-write and memory-mapped files; only a fault on an address the process is not allowed to access becomes an error such as a segmentation fault.

What is the difference between a minor and a major page fault?

A minor fault is resolved without disk I/O, for example by mapping a page already in memory, while a major fault must read the page from storage and, depending on the storage, is tens of times (fast SSD) to thousands of times (hard disk) slower.

Why does a page fault restart the instruction instead of skipping it?

The faulting access never completed, so the OS fixes the mapping and re-executes the instruction from the start, letting the program continue as if nothing had happened.
