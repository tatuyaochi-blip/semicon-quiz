What is Page fault?

An exception raised when an accessed page is not mapped to physical memory or the access type is not permitted. The OS either supplies the page and retries the instruction or treats it as an illegal access.

Japanese name: ページフォルト

Try it: questions about Page fault

When does a page fault occur?

  1. AWhen data is not in the cache and is fetched from main memory
  2. BWhen the accessed page is not mapped to physical memory
  3. CWhen the TLB holds the translation and the physical address is found immediately
Show answer and explanation

Answer: B. When the accessed page is not mapped to physical memory

A page fault is an exception raised when the accessed page's page-table entry is invalid, meaning it is not mapped to physical memory (it was paged out or never loaded), or when the access is not permitted, such as writing a read-only page. The OS supplies the page and retries the instruction. A cache miss is handled entirely in hardware and is not an exception. If the TLB has the translation, it completes at once and no fault occurs.

When a page fault occurs on a page that was evicted to disk, what does the OS do?

  1. AIt immediately terminates the program abnormally without loading the page
  2. BAfter loading the page, it skips the faulting instruction and resumes at the next one
  3. CIt loads the page from disk, updates the table and retries the instruction
Show answer and explanation

Answer: C. It loads the page from disk, updates the table and retries the instruction

For a page fault from a legitimate access, the OS finds a free physical page (evicting another if needed), reads the contents from disk and marks the page-table entry valid. It then re-executes the faulting instruction from the start, so the program continues as if nothing happened. Skipping the instruction would leave the access undone and produce wrong results. Abnormal termination is for illegal accesses to unmapped addresses.
