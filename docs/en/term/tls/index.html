What is TLS?

Transport Layer Security. A protocol that encrypts communication, detects tampering and authenticates servers with certificates. HTTPS is HTTP protected by TLS.

Japanese name: TLS

TLS appears in 6 practice questions across 2 topics, including Computer Networking Basics, Information Security Basics.

Try it: questions about TLS

A client makes a new HTTPS connection (TLS 1.3 over TCP) to a web server with a round-trip time (RTT) of 100 ms. Roughly how long does it take until the response to the first request starts to arrive? Assume DNS resolution is already done, and ignore server processing time and data transfer time.

  1. AAbout 100 ms
  2. BAbout 300 ms
  3. CAbout 200 ms
Show answer and explanation

Answer: B. About 300 ms

First, the TCP three-way handshake takes one round trip (the client can send its first TLS message together with the final ACK). Next, the TLS 1.3 handshake takes one round trip, and then the HTTP request and response take one more, for three round trips in total: 3 × 100 = 300 ms. With TLS 1.2 the key exchange takes two round trips, giving four round trips, or 400 ms. This waiting time depends on the number of RTTs, which is set by distance, so adding link bandwidth does not shorten it. QUIC, used by HTTP/3, combines the transport and cryptographic handshakes into one round trip and also offers a way to send data in the first flight when reconnecting (0-RTT).

Which of the following does HTTPS (HTTP protected by TLS) protect?

  1. AThat the operator of the website you connect to is a trustworthy person or organization without malicious intent
  2. BThat the fact you are communicating, and the IP address of the server you connect to, cannot be seen along the path
  3. CThat the content cannot be read or altered in transit, and that the server you connect to is the legitimate holder of the domain name in its certificate
Show answer and explanation

Answer: C. That the content cannot be read or altered in transit, and that the server you connect to is the legitimate holder of the domain name in its certificate

TLS provides three things: encryption of the communication (confidentiality), detection of tampering (integrity) and authentication of the server. The server presents a certificate, and the browser checks it by following signatures back to a certificate authority (CA) it trusts and confirms that it matches the domain name in the URL. What this proves, however, is only that you are talking to the holder of that domain name; it says nothing about whether the site's operator is honest. Even a scam site can obtain a certificate for its own domain. Also, the IP header is not encrypted, so which IP address you talk to, when and how much can be seen along the path.
