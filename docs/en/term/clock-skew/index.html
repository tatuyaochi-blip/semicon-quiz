What is Clock skew?

The difference in arrival time of the same clock signal at different flip-flops. Because it changes setup and hold margins, clock tree synthesis keeps it small.

Japanese name: クロックスキュー

Clock skew appears in 3 practice questions across 3 topics, including Logic circuits, Timing analysis and CDC, How to read datasheets.

Field: Logic circuits

Where skew comes from

In a synchronous circuit one clock source feeds thousands to millions of flip-flops through a network of wires and buffers. Differences in wire length, wire resistance and capacitance, buffer load, and local variations in process, voltage and temperature make the same clock edge arrive at slightly different times at different flip-flops. That spatial difference in arrival time is clock skew. It should not be confused with jitter, which is the variation of the clock edge's timing from cycle to cycle at a single point. What matters for timing is the skew between each pair of flip-flops that pass data to each other.

Effect on setup and hold

Define skew as the capture clock's arrival minus the launch clock's arrival. A late capture clock gives data more time, helping setup: the condition becomes period + skew ≥ clock-to-output + logic delay + setup time. For a 2.0 ns period, 0.2 ns clock-to-output, 1.4 ns logic and 0.1 ns setup, slack is 0.3 ns at zero skew and 0.4 ns with 0.1 ns positive skew. The same late capture hurts hold, because new data can overwrite the old before the capture flip-flop has latched it: minimum clock-to-output plus minimum logic delay must exceed hold time plus skew.

Controlling skew with clock tree synthesis

Clock tree synthesis (CTS) builds the chip-wide distribution network, choosing buffer locations and balancing wire lengths and loads so that skew stays within tens of picoseconds. Common structures include symmetric H-trees, buffered trees and grid-like clock meshes that short many branches together. Static timing analysis then checks every path with the actual computed clock arrivals and adds derating for on-chip variation. Designers sometimes introduce intentional, or useful, skew, delaying the capture clock of a critical path to borrow time from a neighboring path that has slack to spare.

Why hold violations are dangerous

A setup violation can be fixed after fabrication by lowering the clock frequency, since a longer period gives data more time. A hold violation cannot, because the hold condition does not include the clock period at all; it is a race between the new data and the clock edge in the same cycle. That is why skew-induced hold problems are fixed before tape-out by inserting delay buffers on short paths. At board level the same arithmetic applies to chip-to-chip interfaces, where clock skew and jitter must be subtracted from the timing budget.

In a synchronous circuit with a clock period of 2.0 ns, the launching flip-flop's clock-to-output delay is 0.2 ns, the combinational logic delay is 1.4 ns and the capturing flip-flop's setup time is 0.1 ns. With zero clock skew, what is the setup slack?

  1. A0.3 ns
  2. B0.4 ns
  3. C0.5 ns
Show answer and explanation

Answer: A. 0.3 ns

Setup slack is calculated as "required time − arrival time." The data arrival time is 0.2 + 1.4 = 1.6 ns and the required time is the next clock edge minus the setup time, 2.0 − 0.1 = 1.9 ns, so the slack is 1.9 − 1.6 = 0.3 ns. Being positive, it meets the constraint. 0.4 ns is the value obtained by forgetting to subtract the setup time, and 0.5 ns by adding the setup time instead. A negative slack means a violation.

FAQ

What is the difference between clock skew and clock jitter?

Skew is a difference in clock arrival time between different locations in the same cycle, while jitter is the variation of the clock edge time from cycle to cycle at one location.

Is clock skew always bad?

No. Positive skew gives a path more setup time, and designers sometimes add intentional useful skew to balance timing, but any skew that helps setup reduces hold margin on the same path.

Can a hold violation be fixed by slowing the clock?

No. Hold timing does not depend on the clock period, so it must be fixed by adding delay to the short data path or reducing skew.
