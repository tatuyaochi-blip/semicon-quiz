What is UART?

A circuit for asynchronous serial communication without a clock wire, in which both sides agree on a baud rate and characters are framed by start and stop bits.

Japanese name: UART

UART appears in 7 practice questions across 3 topics, including Embedded Systems & Firmware, CPUs and architecture, Automotive Semiconductors and Functional Safety.

Field: Embedded Systems & Firmware

How a UART frame works

A UART (universal asynchronous receiver-transmitter) sends bytes one bit at a time over a transmit line and receives on a separate line, sharing only a ground with the other device. No clock is sent. The line idles at logic 1; a character begins with a start bit of 0, followed by usually eight data bits sent least significant bit first, an optional parity bit and one or more stop bits at 1. The most common format is written 8N1: eight data bits, no parity, one stop bit. Both ends must be configured to the same baud rate in advance, such as 9600 or 115200 bits per second.

Throughput and timing tolerance

Framing costs bandwidth: an 8N1 character takes ten bit times for eight bits of data. At 115200 bps that gives 115200 / 10 = 11,520 bytes per second, about 87 µs per byte, so heavy logging can stall a program. The receiver synchronizes on the falling edge of each start bit, typically by sampling the line at 16 times the baud rate, and then samples each bit near its center using its own clock. Any rate mismatch accumulates, and once the drift reaches half a bit by the stop bit the character is corrupted, so the combined error of both ends must stay within a few percent.

UART vs. SPI and I2C

UART is the simplest of the common on-board serial links: two signal wires, point to point, with no clock and little protocol. SPI (serial peripheral interface) is synchronous, with a shared clock, data in each direction and a chip-select line per device, which allows clock rates of tens of megahertz but adds a wire for each additional device. I2C (inter-integrated circuit) connects many devices on two open-drain wires using addresses, at a few hundred kilohertz to a few megahertz. Choose UART to link two devices simply, SPI for speed and I2C for many devices on few wires.

Where you will meet it

Almost every microcontroller includes one or more UARTs, alongside SPI, I2C and often CAN. They provide debug consoles, connect GPS receivers, cellular and wireless modules, and serve as a recovery path through which a bootloader receives new firmware. The UART itself works at logic levels; standards such as RS-232 and RS-485 add line drivers with different voltage levels or differential signaling for longer cables. Because characters can arrive at any time, practical drivers use receive FIFOs with interrupts or DMA so that no byte is lost while the processor is busy.

Answer: B. About 11,500 bytes

In 8N1 format, sending one byte of data takes 10 bits: 1 start bit, 8 data bits and 1 stop bit. 115200 ÷ 10 = 11,520, so about 11,500 bytes per second, or roughly 87 µs per byte. Heavy logging can take longer than expected and delay other processing, so the amount of output and the use of buffers need attention.

FAQ

What does UART stand for?

UART stands for universal asynchronous receiver-transmitter. It is the hardware block that converts bytes to and from a serial bit stream framed by start and stop bits, without a shared clock.

How many bytes per second can a 115200 baud UART send?

With 8N1 framing each byte takes 10 bits, so 115200 bps carries about 11,520 bytes per second, roughly 87 µs per byte. Adding parity or a second stop bit lowers this further.

Why do both sides of a UART link need the same baud rate?

No clock is transmitted, so the receiver times each bit with its own clock after the start bit. If the rates differ by more than a few percent, the sampling point drifts by half a bit or more before the end of the frame and bits are misread.
