What is Pod?

The smallest unit that Kubernetes places and runs. It groups one or more containers, which share a network namespace, including the IP address, and volumes, and can talk to each other over localhost. Usually it holds one application container, with helper containers added as needed. Pods are disposable and generally get a new name and IP address when recreated, so their number is kept by a Deployment or similar and a Service provides a stable endpoint for them.

Try it: questions about Pod

In Kubernetes, a Deployment with replicas: 3 is running three Pods. Which of the following correctly describes what happens when one of these Pods is deleted with kubectl delete pod?

  1. AThe Deployment's setting is also rewritten to replicas: 2, and two Pods keep running
  2. BA controller detects that the actual number has fallen below the specified 3 and creates one new Pod
  3. CThe other two Pods of the Deployment are also deleted, and the whole Deployment stops
Show answer and explanation

Answer: B. A controller detects that the actual number has fallen below the specified 3 and creates one new Pod

In Kubernetes, users declare a desired state such as "run three Pods", and controllers repeatedly observe the actual state and act to bring it closer to the declaration when they differ (reconciliation). Deleting one Pod makes the actual number 2, so the ReplicaSet controller creates a new Pod to return to 3. When a Pod is lost because a node fails, the same mechanism recreates it on another node. To really reduce the number of Pods, change the Deployment's replicas instead of deleting Pods.

In a Kubernetes Deployment, the container image in the Pod template is changed to a new version. Which of the following correctly describes what happens with the default update strategy (RollingUpdate)?

  1. AA new ReplicaSet is created, and Pods of the new version are added while Pods of the old version are removed. The old ReplicaSet stays with 0 Pods for rollback
  2. BThe container image inside the running Pods is replaced with the new version in place without recreating the Pods, so neither the Pods' IP addresses nor their names change
  3. CAll Pods of the old version are deleted at once and then the Pods of the new version are created together, so the service stops temporarily during the update
Show answer and explanation

Answer: A. A new ReplicaSet is created, and Pods of the new version are added while Pods of the old version are removed. The old ReplicaSet stays with 0 Pods for rollback

When the Pod template changes, a Deployment creates a ReplicaSet for the new template and, while confirming that new Pods have become ready, gradually reduces the Pods of the old ReplicaSet. A certain number of Pods therefore keep handling requests during the update. The old ReplicaSet is kept with 0 Pods, so kubectl rollout undo can return to the previous version. The strategy that deletes all Pods first and then recreates them is Recreate, which is used only when specified explicitly.
