What is Loop unrolling?

Replicating a loop body several times to reduce the number of iterations. It cuts branch and counter overhead and gives more freedom to reorder instructions, at the cost of larger code.

Japanese name: ループ展開

Field: Compilers

What unrolling does to a loop

A loop that adds two arrays element by element normally performs, for every element, a counter increment, a comparison and a conditional branch in addition to the useful work. Unrolling by four writes the body four times, handling elements i through i+3 in one pass and incrementing i by 4, so the loop runs a quarter as many iterations and the overhead is paid once per four elements. When the trip count is not a multiple of the unroll factor, a short remainder loop handles the leftover elements. Small loops with a known constant trip count can be unrolled completely.

Why it speeds code up

Besides cutting branch and counter overhead, unrolling places several independent copies of the work in one basic block, giving the compiler's instruction scheduler freedom to interleave them. A load from one copy can be issued while arithmetic from another proceeds, hiding latencies. For reductions such as sums, unrolling with several separate accumulators breaks a single long dependency chain; for floating point this changes the rounding order, so compilers do it only when allowed. Unrolling also exposes groups of operations that can be combined into SIMD vector instructions.

Costs and diminishing returns

Each extra copy enlarges the code, which can push hot loops out of the instruction cache, and more simultaneous values raise register pressure, which can force spills to memory that undo the gain. Modern out-of-order processors with accurate branch prediction already hide much loop overhead, so heavy unrolling often brings little benefit. Compilers therefore choose unroll factors heuristically, and programmers can request specific behavior through compiler options or pragmas when measurements justify it.

Unrolling vs. related loop optimizations

Loop unrolling targets control overhead and scheduling freedom. Strength reduction is different: it replaces an expensive operation with a cheaper one, such as computing i * 4 by adding 4 to a separate variable each iteration or by a shift. Loop blocking, or tiling, restructures loops such as matrix multiplication to work on cache-sized blocks and increase data reuse, attacking memory misses rather than branches. Compilers often apply several of these together to the same loop.

Answer: A. Fewer counter checks and branches, and easier reordering

Loop unrolling writes, say, four copies of the loop body and runs a quarter as many iterations. Counter checks and branches shrink, and instructions from the copies can be interleaved, making it easier to hide operation latencies. Code grows in exchange and can strain the instruction cache. A single copy with smaller code is the reverse, and extracting a loop into a function is a different transformation.

FAQ

What is loop unrolling?

Loop unrolling is a compiler or manual optimization that replicates the loop body several times and reduces the number of iterations accordingly, cutting counter updates and branches and exposing more instructions for scheduling.

Does loop unrolling always improve performance?

No. It increases code size and register usage, which can cause instruction cache misses or register spills, and on modern CPUs the remaining loop overhead is often small, so the benefit must be measured.

What is the difference between loop unrolling and loop tiling?

Unrolling replicates the loop body to reduce branch overhead and increase instruction-level parallelism. Tiling splits the iteration space into cache-sized blocks to improve data reuse and reduce cache misses.
