What is Sensitivity list?

The list in @( ) after a Verilog always that names the signals triggering the block. Omissions in combinational logic make simulation and hardware disagree.

Japanese name: センシティビティリスト

Sensitivity list appears in 3 practice questions across 1 topic, including HDL & Verification.

Field: HDL & Verification

How the simulator uses it

An event-driven simulator does not evaluate an always block continuously. It waits at the @( ) event control and wakes the block only when a listed signal changes, or, for posedge and negedge entries, only on that particular edge. Everything follows from this: if a signal that affects the outputs is missing from the list, the block simply does not run when that signal changes, and the outputs keep stale values until some listed signal moves.

Incomplete lists and simulation-synthesis mismatch

Synthesis tools largely ignore the list for combinational logic and build gates from the block's statements, typically with only a warning. So "always @(a) y = a & b;" synthesizes to an AND gate in which y follows both inputs, while the simulator updates y only when a changes. Tests that happen to toggle a will pass, yet the hardware behaves differently from the RTL simulation. The mismatch is dangerous because it survives RTL verification and appears only in gate-level simulation or silicon.

@(*) and always_comb

Verilog-2001 introduced always @(*), which automatically includes every signal read inside the block and removes the risk of omissions. SystemVerilog's always_comb goes further: it also executes once at time zero so outputs start consistent, is sensitive to signals read inside called functions, and lets tools flag blocks that would infer a latch. Hand-written sensitivity lists for combinational logic are now a legacy style best avoided.

Edges in sequential blocks

For flip-flops the list names edges rather than levels. "always @(posedge clk)" describes a register that samples on the rising clock edge. Adding "or negedge rst_n" gives an asynchronous active-low reset: the block also runs the instant rst_n falls, so the output clears without waiting for a clock, even when the clock is stopped. The "_n" suffix is a common convention for active-low signals. The reset's release still needs care, usually by synchronizing it to the clock to meet recovery and removal timing.

The list inside @( ) after always is called the sensitivity list and specifies which signal changes trigger the block. Writing "*" automatically includes every signal read in the block, correctly describing combinational logic. Listing signals by hand invites omissions, so "@(*)" or SystemVerilog's always_comb is the safe choice for combinational logic.

FAQ

What does always @(*) mean in Verilog?

The block runs whenever any signal it reads changes, which is the correct behavior for combinational logic. The asterisk saves you from listing signals by hand and missing one.

Does synthesis use the sensitivity list?

For combinational logic, synthesis tools essentially ignore it and build logic from the statements, so an incomplete list causes simulation to disagree with the hardware. Edge keywords in clocked blocks are used to infer flip-flops and asynchronous resets.

Does VHDL have a sensitivity list too?

Yes. A VHDL process lists its triggering signals in parentheses after the process keyword, and VHDL-2008 adds process(all), the counterpart of Verilog's @(*).
