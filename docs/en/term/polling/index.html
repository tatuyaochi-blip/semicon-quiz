What is Polling?

A method in which the CPU repeatedly checks a peripheral's status to detect changes. Simple, but it consumes time and power even when nothing happens.

Japanese name: ポーリング

Polling appears in 3 practice questions across 3 topics, including OS & Hardware, Embedded Systems & Firmware, CPUs and architecture.

Field: Embedded Systems & Firmware

Try it: questions about Polling

When is polling, in which the CPU repeatedly checks device status instead of using interrupts, advantageous?

  1. AWhen events occur at a very high rate and the per-interrupt switching overhead is large
  2. BWhen events are very rare and the CPU should be used for other work
  3. CWhen the CPU should sleep as long as possible to minimize power
Show answer and explanation

Answer: A. When events occur at a very high rate and the per-interrupt switching overhead is large

Interrupts avoid wasting the CPU when events are rare, but each one costs state saving and a jump to the handler. When events are extremely frequent, as with high-speed networking, interrupt overhead piles up until processing cannot keep pace, so polling in batches becomes more efficient. For rare events or when the CPU should sleep to save power, spinning on polls is wasteful and interrupts are better.

What is the difference between polling and interrupts as ways to learn a peripheral's status?

  1. AWith polling the CPU checks the status repeatedly; with interrupts the peripheral notifies the CPU when the status changes
  2. BPolling and interrupts are the same thing
  3. CInterrupts are the method where the CPU repeatedly checks the status
Show answer and explanation

Answer: A. With polling the CPU checks the status repeatedly; with interrupts the peripheral notifies the CPU when the status changes

Polling is simple and predictable because checks happen at fixed intervals, but the CPU keeps checking even when nothing happens, wasting time and power. With interrupts the CPU responds only when something changes, so it can do other work or sleep while waiting. If interrupts are extremely frequent, though, their overhead becomes large, so the choice matters.
