What is Memory-mapped I/O?

Assigning peripheral registers to specific addresses in the same address space as memory and accessing them with ordinary load and store instructions. That region is configured as uncached.

Japanese name: メモリマップドI/O

Field: OS & Hardware

How it works

The processor's address decoder routes certain address ranges not to RAM but to peripheral devices. A timer's control register, a UART's data register or a GPIO port each appears at a fixed address, and ordinary load and store instructions become read and write transactions to that device. Unlike memory, these accesses can have side effects: reading a status or data register may clear a flag or pop a FIFO, writing a 1 may clear an interrupt, and the value can change at any moment because the hardware updates it independently of the program.

Memory-mapped vs. port-mapped I/O

Port-mapped I/O gives devices a separate address space reached only through dedicated instructions, such as IN and OUT on x86. Memory-mapped I/O needs no special instructions, so every addressing mode, pointer and C struct can be used to reach registers, keeping the instruction set simple. It is the standard on ARM and RISC-V microcontrollers, and even on x86 systems PCI Express devices expose most of their registers through memory-mapped regions, while legacy port I/O remains mainly for compatibility.

Caching, volatile and ordering

Device regions must be configured as uncached; otherwise the CPU might keep rereading a stale cached copy and never see the device change, or hold writes in the cache. In C, register pointers are declared volatile so the compiler performs every access exactly as written, rather than reading once and looping forever or dropping repeated writes. volatile does not, however, control hardware reordering or write buffering. Processors and buses may post writes, so drivers use memory barriers or device memory attributes, and sometimes a read-back, to guarantee ordering and completion.

MMIO in operating systems

On systems with virtual memory, a device's physical register addresses are mapped into the kernel's virtual address space with uncached attributes before a driver can use them, and occasionally into a user process for user-space drivers. MMIO is typically used for control and status: configuring a device, starting operations and acknowledging interrupts. Bulk data usually moves by DMA (direct memory access), where the device itself reads and writes main memory, rather than by the CPU copying through registers.

Answer: B. Memory-mapped I/O

Memory-mapped I/O assigns addresses to peripheral control registers, such as timers and UARTs, so ordinary load and store instructions control them. Compared with port-mapped I/O using dedicated instructions (like x86 IN/OUT), it keeps the instruction set simple and is standard on ARM and RISC-V microcontrollers. Peripheral registers must not be cached and must be accessed as volatile so the compiler does not optimize accesses away.

FAQ

What is the difference between memory-mapped I/O and port-mapped I/O?

Memory-mapped I/O places device registers in the normal memory address space and accesses them with ordinary loads and stores, while port-mapped I/O uses a separate address space and special instructions such as x86 IN and OUT.

Why must memory-mapped registers be declared volatile?

The device can change register values independently of the program, so volatile forces the compiler to perform every read and write rather than caching values in registers or removing apparently redundant accesses.

Why is memory-mapped I/O space uncached?

A cache would return stale values instead of the device's current state and could delay or merge writes, so device regions are mapped with uncached or device attributes.
