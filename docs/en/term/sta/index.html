What is STA (static timing analysis)?

A method that calculates the delay of every path in a circuit without test patterns and checks that timing constraints are met.

Japanese name: STA(静的タイミング解析)

STA (static timing analysis) appears in 21 practice questions across 4 topics, including Timing analysis and CDC, IC design flow and EDA, HDL & Verification.

Field: IC design flow and EDA

How STA works

Static timing analysis breaks a synchronous design into timing paths, mainly from one flip-flop to the next. For each path it adds cell delays, interpolated from characterized library tables indexed by input transition time and output load, and wire delays, giving the data arrival time. It compares this with the required time set by the clock edge and the capturing flip-flop's setup or hold requirement. Slack is required minus arrival; negative slack is a violation. No test vectors are needed, so every path is covered, but logical correctness must still be verified by simulation.

Constraints tell STA what to check

The tool needs timing constraints, typically in SDC format: clock periods and waveforms, input and output delays, and exceptions. A false path excludes a connection that can never be exercised, such as one blocked by mutually exclusive select signals. A multicycle path gives a path N cycles for setup, and normally a hold multicycle of N − 1 to move the hold check back to its usual edge. Wrong constraints are dangerous: a chip can pass every tool check yet fail in silicon. Reports summarize results as worst negative slack (WNS) and total negative slack (TNS).

Corners and on-chip variation

Delays change with process, voltage and temperature (PVT), so analysis is repeated at multiple corners. Setup is usually worst at the slow corner with slow transistors and low voltage; hold is worst at the fast corner. In advanced processes temperature inversion, where low-voltage circuits slow down as they get colder, adds corners. Within one die, on-chip variation (OCV) derating makes the data and launch clock paths slower and the capture clock faster for setup checks. Common path pessimism removal (CRPR) then credits back the impossible slow-and-fast treatment of clock buffers shared by both paths.

Fixing violations

A setup violation means a path is too slow: remedies include reducing logic levels, upsizing cells or using faster low-threshold cells, and placing cells closer to shorten wires, or, as a last resort, lowering the clock frequency. A hold violation means a path is too fast, and since the check does not involve the clock period, it is fixed by inserting delay buffers. Graph-based analysis takes the worst transition at every node and can be pessimistic, so path-based analysis (PBA) recomputes failing paths with their real transitions to avoid unnecessary fixes.

Which correctly describes static timing analysis (STA)?

  1. AFabricating a prototype chip and measuring its operating speed
  2. BApplying many test patterns and checking operation by simulation
  3. CCalculating the delay of each path in the circuit without test patterns and verifying whether timing constraints are met
Show answer and explanation

Answer: C. Calculating the delay of each path in the circuit without test patterns and verifying whether timing constraints are met

STA sums cell and wire delays along every signal path and exhaustively checks timing constraints such as setup and hold times. It needs no test patterns and covers paths that patterns might miss, so it is central to timing verification of large ICs. It does not check logical correctness, however, so functionality is verified separately by simulation and other means.

In static timing analysis, which timing violation occurs when a signal changes too soon after the clock edge, so a flip-flop cannot correctly hold the previous data?

  1. ASetup violation
  2. BHold violation
  3. CDRC violation
Show answer and explanation

Answer: B. Hold violation

A hold violation occurs when a data path is so short that data is not held long enough after the clock edge, letting new data be captured on the same edge. The hold check compares the same edge and does not involve the clock period, so lowering frequency does not fix it; delay buffers are inserted instead. A path too long to arrive in time is a setup violation, and a DRC violation is a layout rule violation.

FAQ

What is the difference between static timing analysis and timing simulation?

STA computes worst-case delays for every path from the circuit structure without input vectors, so its coverage is exhaustive and fast. Timing simulation applies specific vectors and checks behavior, so it only covers the paths those vectors exercise but also verifies function.

What is slack in STA?

Slack is the required time minus the arrival time for a path. Positive slack means the constraint is met with margin, and negative slack means a violation that must be fixed.

What are WNS and TNS in timing reports?

WNS (worst negative slack) is the slack of the single worst path, and TNS (total negative slack) is the sum of negative slacks over all violating endpoints. A small WNS with a large TNS means many paths fail by a little.
