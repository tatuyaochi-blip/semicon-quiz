What is Symbol table?

The list of function and variable names, with their addresses and attributes, contained in object files and executables. Used for linking and debugging; strip can remove it.

Japanese name: シンボルテーブル

What an entry holds

Each symbol table entry describes one named entity. In the ELF (Executable and Linkable Format) used on Linux, an entry records the name (as an offset into a string table), the value (an address, or an offset within a section in an object file), the size, the type such as function or data object, the binding (local, global or weak) and the section where the symbol is defined. A symbol that is referenced but not defined in this file is marked undefined; these are the references the linker must satisfy from other object files or libraries.

How the linker uses it

Linking starts with symbol resolution: the linker collects the symbol tables of all input files and matches every undefined reference with exactly one definition. Two strong global definitions of the same name produce a multiple-definition error, a weak definition yields to a strong one, and a reference with no definition produces an undefined-reference error. Once each symbol has a final address, the linker processes relocation entries, patching every instruction and data word that refers to a symbol. Local symbols, such as static functions in C, never take part in cross-file matching.

Static symbols, dynamic symbols and strip

ELF files carry two symbol tables. The full table (.symtab) serves the static linker and debuggers; the dynamic table (.dynsym) lists only the symbols that must be resolved at load time between an executable and its shared libraries. Running strip removes .symtab and debug sections such as DWARF line information, shrinking the file, but leaves .dynsym because the program cannot run without it. Developers often save the debug information to a separate file before stripping so that crashes in shipped binaries can still be symbolized. Tools such as nm and readelf -s list a file's symbols.

The compiler's symbol table

The same term also names a different structure inside the compiler. During semantic analysis, the compiler keeps a table, typically hash tables organized by nested scope, that maps each identifier to its declaration, type and storage. It answers questions such as which variable x means at this point and whether a function was declared with matching arguments. That table exists only while compiling. The object-file symbol table is its persistent output, containing just the names that matter for linking, relocation and debugging.

  2. BIt is just compressed source code and contains no machine code
  3. CIt contains machine code, but the addresses of functions and variables in other files are not yet fixed

Answer: C. It contains machine code, but the addresses of functions and variables in other files are not yet fixed

An object file holds the machine code translated from that file's functions, initial values of variables, a list of names it defines and references (the symbol table) and a list of places whose addresses must be filled in later (relocation entries). An instruction calling a function in another file, such as printf, keeps a placeholder because the address is unknown. The linker combines several object files, fixes the addresses and produces an executable.

Answer: C. Symbol tables and debug information are removed; the file shrinks, but debuggers can no longer show function names and the like easily

An executable may contain a symbol table listing function and variable names, and debug information mapping code to source lines. These are not needed to run, so removing them with strip makes the file smaller. Function names and line numbers are then unavailable when investigating bugs, so the information is sometimes kept separately before stripping. Symbols needed for dynamic linking remain.

FAQ

How do I view the symbol table of an executable or object file?

On Linux, nm lists symbols with a one-letter type, and readelf -s shows the full ELF symbol tables including size, type and binding. objdump -t is another option.

What do T and U mean in nm output?

T marks a symbol defined in the text (code) section, typically a global function, and U marks an undefined symbol that this file references but does not define. Lowercase letters indicate local symbols.

Can a stripped binary still be debugged?

Yes, but stack traces show addresses instead of function names unless separately saved debug information or symbol files are available to the debugger.
