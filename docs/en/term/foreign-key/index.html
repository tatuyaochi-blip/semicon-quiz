What is Foreign key?

A column that refers to the primary key (or a unique column) of another table. Through the referential integrity constraint, which allows only values that exist in the referenced table or NULL, it prevents data that points to nonexistent rows. The behavior when a referenced row is deleted or updated (rejection, cascading deletion and so on) can also be specified.

Japanese name: 外部キー

Try it: questions about Foreign key

The primary key of a customer table (cust_id, name) is cust_id, and cust_id in an orders table (order_id, cust_id) is defined as a foreign key referring to cust_id in the customer table. The customer table contains only the rows with cust_id 'C1' and 'C2'. What happens when INSERT INTO orders VALUES ('O9', 'C5') is executed in this state?

  1. AThe row is not added and an error occurs, because it violates the referential integrity constraint
  2. BThe row is added, and a row with cust_id 'C5' is automatically added to the customer table as well
  3. CThe row is added, but its cust_id value is replaced with NULL
Show answer and explanation

Answer: A. The row is not added and an error occurs, because it violates the referential integrity constraint

A foreign key is a column that refers to the primary key (or similar) of another table, here the customer table, and it enforces the referential integrity constraint: only values that exist in the referenced table, or NULL, may be stored. The customer table has no customer 'C5', so the DBMS rejects the attempt to add an order for a nonexistent customer, and an error occurs. This prevents orders that belong to no known customer. Conversely, an attempt to delete a customer row that still has orders is also rejected under the default behavior (NO ACTION). Adding ON DELETE CASCADE to the foreign key definition makes deleting a customer also delete that customer's orders in a cascade.
