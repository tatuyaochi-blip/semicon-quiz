What is Linker?

Software that combines object files and libraries, performs symbol resolution and relocation, and produces an executable or shared library.

Japanese name: リンカ

Field: Linkers, Loaders & Executables

Where the linker fits in the build

Building a C program normally runs the compiler, which produces assembly or object code, the assembler, which produces a machine-code object file, and finally the linker. Each object file is compiled in isolation, so it contains machine code and data, a symbol table of names it defines and references, and relocation entries marking every place where an address is still unknown, such as a call to printf in another file. The linker combines many such object files and libraries into one executable or shared library that the operating system can load.

Resolution, layout and relocation

The linker's core work has three parts. Symbol resolution binds every referenced name to exactly one definition, reporting undefined-reference or multiple-definition errors otherwise. Layout merges like sections from all inputs, such as .text for code, .rodata for constants, .data for initialized variables and .bss for zero-initialized ones, and assigns their final addresses, often under the control of a linker script. Relocation then visits each relocation entry and writes the correct absolute address or PC-relative distance into the instruction or data word.

Static vs. dynamic linking

A static library (.a on Linux) is an archive of object files, and the linker copies in only the members needed to resolve references that are still undefined, scanning inputs left to right; that is why libraries are listed after the files that use them. Static linking produces a self-contained executable but duplicates library code in every program, and library fixes require relinking. With shared libraries (.so), the linker records dependencies and the dynamic linker binds library functions at load or run time through PLT stubs and the GOT.

What runs before main

The linker also adds start-up objects from the C runtime, such as crt1.o, and makes their _start symbol the entry point. _start sets up arguments, initializes the library and global objects, then calls main and passes its return value to exit. C++ global constructors are collected into an .init_array table that start-up code calls before main. C++ compilers mangle names to encode argument types so overloaded functions get distinct symbols, and extern "C" disables mangling for functions shared with C code.

Answer: A. To combine object files and libraries, bind names to addresses and produce an executable

The linker matches each name (symbol) referenced in the object files with a definition somewhere (symbol resolution), lays out every file's code and data to decide final addresses, and rewrites placeholder addresses in instructions with the right values (relocation). It also pulls in functions from libraries as needed. The result is an executable that the OS can load and run.

Answer: A. Matching a function or variable name used in one file with its definition in another file

If main.c calls sum and sum.c defines it, main.o records "references sum" and sum.o records "defines sum". The linker collects the symbol tables of all object files and finds exactly one definition for each reference. If no definition is found it reports an undefined reference; if there are two or more it reports a multiple-definition error.

FAQ

What is the difference between a compiler and a linker?

A compiler translates one source file into an object file with unresolved addresses, while a linker combines many object files and libraries, resolves names between them and fixes final addresses to produce an executable.

Why does library order matter when linking with GCC?

The GNU linker scans inputs left to right and extracts members from a static library only for symbols that are already undefined, so a library listed before the objects that use it contributes nothing.

What is the difference between static and dynamic linking?

Static linking copies the needed library code into the executable at build time, while dynamic linking leaves references to shared libraries that the dynamic linker binds when the program is loaded or run.
