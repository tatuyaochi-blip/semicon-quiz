What is MESI protocol?

A coherence protocol that tracks each cache line in one of four states: Modified, Exclusive, Shared or Invalid. On a write it invalidates other cores' copies.

Japanese name: MESIプロトコル

Try it: questions about MESI protocol

In the MESI protocol, what does it mean when a cache line is in the Modified (M) state?

  1. AOnly this core holds the line, and its contents differ from main memory (it must be written back)
  2. BSeveral cores hold the same contents, which also match main memory
  3. CThe line's contents are unusable and must be fetched again to read
Show answer and explanation

Answer: A. Only this core holds the line, and its contents differ from main memory (it must be written back)

The M state means this core has written the line and alone holds the latest value. Main memory is stale, so when the line is evicted or another core wants to read it, the latest value must be written back or supplied directly. A line in M can be written again any number of times without notifying other cores, so repeated writes by the same core are fast.

In the MESI protocol, what happens when a core writes to a line it holds in the Exclusive (E) state?

  1. AIt sends invalidation requests to all other cores before writing
  2. BIt cannot write, so it writes to main memory and reads the line back
  3. CNo other core needs to be notified, and the line simply becomes M
Show answer and explanation

Answer: C. No other core needs to be notified, and the line simply becomes M

The E state means only this core holds the line and its contents match main memory. Since there are known to be no other copies, the core can move to M on a write without sending invalidations. The benefit of having E is saving that communication in the common pattern of reading and then writing data used by a single core. Writing from S, by contrast, requires invalidating other copies.
