What is Variable?

A named container that holds a value in a program. It is declared with a type such as integer or real and changed by assignment. Assigning a new value discards the previous one.

Japanese name: 変数

In embedded programs, variables that hold the value of a 32-bit peripheral register are often declared with uint32_t from stdint.h rather than unsigned int. Which of the following is the main reason?

  1. Auint32_t does not wrap to 0 when a value exceeds the maximum but stops at the maximum (saturates)
  2. BReads and writes of a variable declared as uint32_t are no longer removed by compiler optimization
  3. CThe size of unsigned int differs between implementations, whereas uint32_t is defined as an unsigned integer of exactly 32 bits
Show answer and explanation

Answer: C. The size of unsigned int differs between implementations, whereas uint32_t is defined as an unsigned integer of exactly 32 bits

uint8_t, uint16_t, uint32_t, int32_t and the like from stdint.h are integer types whose bit widths are fixed as their names say (exact-width integer types). unsigned int may be 16 or 32 bits, so using exact-width types where the width must match a register or where a communication data format is defined keeps the meaning unchanged when the code moves to another CPU. Like other unsigned integer types, uint32_t wraps to the remainder modulo 2³² when it overflows. To keep reads and writes from being removed, volatile is added separately from the type.

In C, which of the following correctly pairs the lifetimes of (1) a local variable declared inside a function without static, (2) a region allocated with malloc, and (3) a variable declared outside any function?

  1. A(1) until the program ends, (2) until the function that allocated it returns, (3) until the program ends
  2. B(1) until execution leaves the block where it is declared, (2) until it is released with free, (3) until the program ends
  3. C(1) until execution leaves the block where it is declared, (2) until the program ends (it cannot be released earlier), (3) until the function that first used it returns
Show answer and explanation

Answer: B. (1) until execution leaves the block where it is declared, (2) until it is released with free, (3) until the program ends

The automatic variable in (1) is generally placed on the stack; it is created on entry to the block where it is declared and disappears when execution leaves it. The region allocated with malloc in (2) is in the heap; it survives function returns and can be used until it is released with free. The variable outside any function in (3) (and any variable declared static) exists throughout the execution of the program and is placed in a static area such as .data or .bss. Using a pointer to a region whose lifetime has ended, and forgetting free so that regions keep piling up, are common causes of bugs.
