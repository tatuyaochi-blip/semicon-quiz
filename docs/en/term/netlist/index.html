What is Netlist?

Data describing the elements (cells) of a circuit and how they are connected. It is the output of logic synthesis and the input to place-and-route and timing analysis.

Japanese name: ネットリスト

Netlist appears in 6 practice questions across 3 topics, including IC design flow and EDA, Testing and inspection, HDL & Verification.

Field: IC design flow and EDA

What a netlist contains

A netlist lists instances, the cells or transistors in a circuit, and nets, the electrical connections between their pins, plus the ports that connect the circuit to the outside. It is pure connectivity: it says that the output pin of one NAND gate drives the inputs of two flip-flops, but nothing about where those cells sit or how the wires are drawn. A gate-level netlist references cells from a standard-cell library and is usually written as structural Verilog, while a transistor-level SPICE netlist lists individual MOSFETs, resistors and capacitors with their parameters for circuit simulation.

Where netlists appear in the design flow

Logic synthesis converts register-transfer level (RTL) code into a gate-level netlist that meets timing, area and power constraints. Place-and-route reads that netlist, then adds buffers and a synthesized clock tree, producing an updated post-layout netlist. Parasitic resistance and capacitance extracted from the layout are attached for static timing analysis. Formal equivalence checking compares the netlist against the RTL, automatic test pattern generation (ATPG) works on the netlist to target faults such as stuck-at faults, and layout-versus-schematic (LVS) checking compares a netlist extracted from the layout with the reference netlist.

Gate-level simulation

RTL simulation is fast but abstract, so some bugs only appear after synthesis. Simulating the gate-level netlist exercises the actual gates and flip-flops, exposing reset and initialization problems that X-optimism hides in RTL, and cases where the synthesized logic differs from the designer's intent. When gate and wire delays from the layout are back-annotated in SDF (Standard Delay Format), timing-related problems also show up. Because gate-level simulation is far slower than RTL simulation, it is usually run on a limited set of tests.

Netlist versus layout data

The netlist and the layout describe the same chip in different ways. The netlist captures what is connected to what, while layout data in GDSII or OASIS format holds the polygons on each mask layer that will actually be printed on the wafer. Verification ties them together: LVS proves that the drawn shapes implement exactly the connections in the netlist, and design rule checking (DRC) separately confirms that the shapes obey manufacturing rules. Only layout data goes to mask making after tape-out.

Answer: B. ATPG (automatic test pattern generation)

ATPG automatically generates, from the netlist, input patterns that activate each modeled fault (such as stuck-at faults) and propagate its effect to an output. Combined with scan design, it efficiently produces high-coverage patterns even for circuits of hundreds of millions of gates. DRC checks layout design rules and CTS synthesizes clock trees; both are design steps.

Answer: A. Data describing the devices (cells) that make up a circuit and how they are connected

A netlist describes which devices (transistors or cells) a circuit contains and which wires (nets) connect their pins. It carries connectivity only, no geometry. It is the output of synthesis and the input to place-and-route, and LVS compares a netlist extracted from the layout with the schematic netlist. Mask shapes reside in layout data such as GDSII.

FAQ

What is the difference between RTL and a netlist?

RTL describes behavior as registers and the logic operations between them in a language like Verilog or VHDL. A netlist is the structural result after synthesis, listing specific library cells and the wires connecting them.

What is a SPICE netlist?

It is a transistor-level netlist in the input format of SPICE circuit simulators, listing devices such as MOSFETs, resistors and capacitors with their node connections and model parameters, used for analog and cell-level simulation.

Does a netlist contain physical layout information?

No. A netlist contains only components and connectivity. Cell positions and wire shapes live in the layout database and in GDSII or OASIS files, although parasitics extracted from the layout can be attached to the netlist for timing analysis.
