What is Clock domain?

A group of flip-flops driven by the same clock, or by clocks with a fixed frequency and phase relationship. Passing a signal between clock domains that are asynchronous to each other requires a synchronizer.

Japanese name: クロックドメイン

Field: Timing analysis and CDC

What makes two clocks the same domain

Flip-flops belong to one domain when they share a clock, or clocks whose frequency and phase relationship is fixed, such as divided clocks from the same PLL. Static timing analysis (STA) can then check every path for setup and hold. Clocks from independent sources, or with no known phase relationship, are asynchronous: a data edge can arrive at any point relative to the capturing edge, so timing cannot be guaranteed. Such paths are excluded from normal timing checks, for example by declaring the clocks as asynchronous groups in the constraints, and must instead be made safe by design.

Metastability and the two-flop synchronizer

If data changes inside a flip-flop's setup and hold window, the output can hover between 0 and 1, a metastable state, before resolving. The standard single-bit synchronizer adds a second flip-flop in the receiving domain, giving the first one a full cycle to settle. The probability of failure falls exponentially with that settling time, so two stages usually give a mean time between failures far beyond the product lifetime, and three are used at high frequencies. A synchronizer lowers the probability; it does not remove it, and it decides only when a change is seen, not whether it was valid.

Crossing with multi-bit data and pulses

Synchronizing each bit of a bus separately fails because different bits may be captured on different edges: a change from 0111 to 1000 can arrive as 1111 or 0000 for a cycle. Counters crossing domains are therefore Gray-coded so only one bit changes at a time, and arbitrary data is held stable while a single valid or request bit is synchronized, through a handshake or an asynchronous FIFO. Pulses also need care: a 2 ns pulse from a 500 MHz domain can fall between 10 ns edges of a 100 MHz clock and vanish, so it is stretched or converted to a toggle.

Design rules and verification

Signals entering a synchronizer must come straight from a flip-flop in the sending domain, because combinational logic can glitch and an asynchronous edge may capture the glitch. Toggle synchronizers need a minimum spacing between events, several receiving cycles, or two toggles can cancel out. Ordinary RTL simulation does not model metastability and rarely exposes these bugs, so dedicated clock domain crossing (CDC) tools check structurally for missing synchronizers, logic in front of them and unsafe multi-bit crossings. Resets crossing domains need the same care, typically asserted asynchronously and released synchronously.

  1. ABecause the receiving side may capture a momentary glitch on the combinational output as a valid value
  2. BBecause combinational outputs have a low voltage and the receiving flip-flop does not respond
  3. CBecause capturing a combinational output always causes metastability
Show answer and explanation

Answer: A. Because the receiving side may capture a momentary glitch on the combinational output as a valid value

Within the same clock domain, glitches settle before the next clock edge and cause no problem. When captured by an asynchronous clock, however, the edge can come at any time, so a momentary 1 pulse on a signal that should be 0 can be captured. The rule is therefore that signals crossing domains come directly from a flip-flop output in the sending domain. Metastability does not occur every time, and CDC verification tools also flag combinational logic in front of synchronizers.

Each bit of 4-bit data is passed to another clock domain through its own two-stage synchronizer. What problem can occur when the data changes from 0111 to 1000?

  1. AThe bits may be captured in different cycles, so an intermediate value such as 1111 or 0000 may be received
  2. BPassing through the synchronizers aligns all bits to the same cycle, so no problem occurs
  3. CAll four bits become metastable and never return to either 0 or 1
Show answer and explanation

Answer: A. The bits may be captured in different cycles, so an intermediate value such as 1111 or 0000 may be received

For each bit, a two-stage synchronizer does not determine whether a change is captured at the current edge or the next one. In a change from 0111 to 1000 all four bits change, so for one cycle the receiver may get a value in which only some bits have their new value, such as 1111, 0000 or 0100. If the receiver uses that value, it malfunctions. Metastability resolves to 0 or 1 over time. For counter values, convert to Gray code so that only one bit changes; for arbitrary data, use a handshake or an asynchronous FIFO.

FAQ

What is a clock domain crossing?

A clock domain crossing is any path where a signal launched by one clock is captured by another clock that is asynchronous to it. Such paths need synchronizers, handshakes or asynchronous FIFOs because timing analysis cannot guarantee them.

Why does a synchronizer use two flip-flops?

The first flip-flop may go metastable when its input changes near the clock edge; the second gives it a full clock period to settle before the value is used. This makes the failure probability extremely small, though never zero.

Are clocks with different frequencies always in different clock domains?

No. If they are derived from the same source with a fixed ratio and phase, such as a clock and its divide-by-two, timing analysis can check paths between them, so they can be treated as synchronous.
