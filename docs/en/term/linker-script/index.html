What is Linker script?

A file telling the linker at which memory addresses to place each section. Embedded development uses it to lay out flash and RAM and to fix the interrupt vector address.

Japanese name: リンカスクリプト

Field: Linkers, Loaders & Executables

What a linker script describes

The compiler produces object files whose code and data are grouped into sections such as .text (instructions), .rodata (constants), .data (initialized variables) and .bss (zero-initialized variables), but without final addresses. A linker script tells the linker how to combine them. In GNU ld syntax, a MEMORY block declares regions with an origin and length, for example flash at one address and RAM at another, and a SECTIONS block maps input sections into output sections and assigns each to a region. The linker reports an error if a region overflows.

Why embedded systems need one

On a PC the operating system's loader decides where a program sits in memory, and a default linker script works for nearly everything. A microcontroller without an OS starts executing from fixed addresses at power-on, so the program must be built for its exact memory map. The interrupt vector table has to sit where the hardware expects it, code and constants belong in non-volatile flash, and writable variables, the heap and the stack must be in RAM. Different chips in the same family often need only a different linker script because their memory sizes differ.

Load address vs. run address

Initialized variables pose a special problem: their initial values must survive power-off, so they are stored in flash, yet the program writes to them, so they must live in RAM at run time. The linker script therefore gives .data two addresses: a load address in flash and a run address in RAM. It also defines symbols marking the start and end of .data and .bss and often the top of the stack. Start-up code uses those symbols to copy .data from flash to RAM and fill .bss with zeros before calling main, giving C its promised initial state.

Common pitfalls

Many problems in bare-metal projects trace back to the linker script. When unused-section removal is enabled, the vector table or other sections referenced only by hardware can be discarded unless marked to be kept. A stack region sized too small does not cause a link error but silently overwrites other data at run time. Placing a section at the wrong load address leaves variables with garbage initial values. Reading the map file the linker can produce, which lists every symbol's address and each region's usage, is the standard way to check the result.

Answer: A. To tell the linker at which addresses, in flash or RAM, to place each section

On a PC the OS loader chooses addresses, but on a microcontroller the addresses at power-on are used as they are. A linker script gives the start addresses and sizes of flash and RAM and specifies placement, such as .text and constants in flash and .data, .bss and the stack in RAM. Items that must sit at fixed addresses, such as the interrupt vector table, are also placed here.

FAQ

What is a linker script used for?

A linker script tells the linker which memory regions exist and at which addresses to place each code and data section. Embedded projects use it to put code in flash, variables in RAM and the interrupt vector table at its required address.

What is the difference between .data and .bss?

.data holds variables with nonzero initial values, which are stored in flash and copied to RAM at start-up. .bss holds variables that start at zero, so it takes no space in flash and is simply cleared in RAM before main runs.

Why does .data have two addresses in a linker script?

Its initial values must be stored in non-volatile flash, but the variables are modified at run time and so must live in RAM. The load address points to the flash copy and the run address to the RAM location the code actually uses.
