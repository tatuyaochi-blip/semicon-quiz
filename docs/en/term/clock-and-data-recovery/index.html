What is Clock and data recovery (CDR)?

A receiver circuit that extracts clock timing from transitions in the received data and decides each bit, removing the need for a dedicated clock wire.

Japanese name: クロック・データ・リカバリ

Field: I/O Interfaces & Buses

Why recover the clock from the data

At rates of tens of gigabits per second a bit lasts only tens of picoseconds, and a separately routed clock would arrive with skew relative to the data lanes that consumes a large part of that bit time. High-speed serial links therefore send no clock at all. Each receiver lane includes a clock and data recovery (CDR) circuit that derives timing from the data transitions themselves, so every lane aligns independently. Source-synchronous interfaces such as DDR memory take the other approach and forward a strobe alongside the data.

How a CDR loop works

A CDR is a feedback loop. A phase detector compares where data transitions occur with the local sampling clock and decides whether the clock is early or late; a bang-bang detector of this kind uses samples taken at the bit centers and at the edges. A loop filter smooths these decisions and steers either a voltage-controlled oscillator, as in a PLL-based CDR, or a phase interpolator that rotates the phase of a reference clock. The goal is to sample each bit near the center of the data eye, where the margin is largest.

Transitions and line coding

The phase detector gets information only when the data changes, so long runs of identical bits let the clock drift and also shift the average voltage on AC-coupled links. Line coding guarantees enough transitions. 8b/10b coding maps 8 data bits to 10-bit symbols with balanced ones and zeros and short run lengths, costing 25% extra bits for 80% efficiency; it was used in PCI Express generations 1 and 2 and USB 3.0. Later links use scrambling with lighter framing, such as 128b/130b, which provides transitions statistically with far less overhead.

Tracking offset, SSC and jitter

Transmitter and receiver reference clocks are never exactly equal, so a CDR must track a small frequency offset as well as phase. With spread-spectrum clocking (SSC), the transmit clock is swept slowly by about 0.5% to lower electromagnetic emission peaks, and the CDR must follow that sweep too. Loop bandwidth is a trade-off: jitter slower than the loop bandwidth is tracked out, while faster jitter must fit inside the eye margin. Standards specify jitter tolerance masks that a receiver must meet across frequency.

Answer: B. It extracts clock timing from the transitions of the received data and decides each bit at that timing

Sending the clock on a separate wire would introduce skew relative to the data. So in high-speed serial links, a CDR circuit watches where the data switches between 0 and 1, generates a clock of matching frequency and phase with a PLL or similar, and samples the data in the middle of each bit. This requires the data to contain transitions often enough, which line coding guarantees.

FAQ

What does a CDR do in a SerDes receiver?

It extracts a clock aligned to the incoming bit stream from the data transitions and uses it to sample each bit near the center of the eye, so no separate clock wire is needed.

Why do serial links need 8b/10b or 128b/130b encoding?

The coding guarantees frequent transitions and DC balance so the receiver's CDR can stay locked and AC-coupled signals stay centered; 128b/130b achieves this with scrambling at much lower overhead than 8b/10b.

What is the difference between a CDR and a PLL?

A PLL locks an oscillator to a clean periodic reference clock, while a CDR locks to random data, whose transitions occur irregularly; many CDRs are built around a PLL with a phase detector designed for data.
