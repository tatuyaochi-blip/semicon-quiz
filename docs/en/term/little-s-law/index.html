What is Little's law?

The relationship that the average number in a system equals the arrival rate times the average time each spends there: L = λW.

Japanese name: リトルの法則

Little's law appears in 3 practice questions across 3 topics, including Yield and quality control, Performance Analysis, Memory Hierarchy.

Field: Performance Analysis

What L = λW says

Little's law relates three long-run averages of any stable system: L, the average number of items inside; λ, the average rate at which items arrive, which equals throughput in steady state; and W, the average time each item spends inside. Its power is its generality: it holds regardless of the arrival distribution, the service-time distribution or the order in which items are served, as long as the system is stable and units are consistent. It needs no assumption of Poisson arrivals, which is why it applies equally to factories, servers and memory systems.

Work in progress and cycle time in a fab

In manufacturing the law reads WIP = throughput × cycle time. A fab completing 50,000 wafers a month with a three-month cycle time always holds about 150,000 wafers in process. At fixed throughput, shortening cycle time requires holding less WIP, and releasing more wafers than the line can process only lengthens cycle time without raising output. Little's law does not by itself explain why cycle time explodes as tools approach full utilization; queueing models that account for variability address that part.

Memory-level parallelism

Applied to memory, the law says bandwidth equals data in flight divided by latency. If each cache miss fetches a 64-byte line and memory latency is 100 ns, one outstanding miss at a time yields 64 B ÷ 100 ns = 0.64 GB/s, while ten concurrent misses yield 6.4 GB/s. Saturating a memory system therefore requires many outstanding requests, not just lower latency. This is why cores track multiple pending misses, why hardware prefetchers issue requests early, and why the same reasoning sets network window sizes as the bandwidth-delay product.

Sizing servers and buffers

A server receiving 100 requests per second, each taking 0.2 seconds on average, holds 100 × 0.2 = 20 requests in progress on average. That figure sizes thread pools, connection limits and queue buffers. The law also works backward as a sanity check: if measured concurrency and throughput imply a response time different from the one observed, the measurements or the assumption of steady state are wrong. Averages are all it gives, though; tail latency needs a fuller model of the system.

FAQ

What do L, λ and W mean in Little's law?

L is the average number of items in the system, λ is the average arrival rate (equal to throughput in steady state) and W is the average time an item spends in the system. The law states L = λW.

Does Little's law require Poisson arrivals?

No. It holds for any stable system in steady state, whatever the arrival and service time distributions or the queueing discipline.

How does Little's law relate to memory bandwidth?

Bandwidth equals the number of bytes in flight divided by latency, so reaching high bandwidth with a fixed latency requires many outstanding memory requests at once.
