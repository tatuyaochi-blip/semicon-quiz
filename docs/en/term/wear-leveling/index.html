What is Wear leveling?

A technique that spreads writes so rewrites do not concentrate on particular flash blocks, extending the memory's life.

Japanese name: ウェアレベリング

Field: SRAM and flash memory

Why flash needs it

NAND flash cannot overwrite data in place: pages are programmed individually, but erasing works only on whole blocks containing many pages, and every program/erase (P/E) cycle slightly damages the tunnel oxide. Endurance therefore depends on cell type: roughly 50,000 to 100,000 cycles for single-level cells (SLC), several thousand to 10,000 for multi-level cells (MLC), a few thousand for triple-level cells (TLC) and around 1,000 for quad-level cells (QLC). If one frequently updated logical address, such as a log or file-system metadata, always hit the same block, that block would wear out long before the rest.

How it works through the FTL

The controller runs a flash translation layer (FTL) that maps logical block addresses from the host to physical pages. Each update of a logical address is written to a freshly erased page elsewhere, and the old page is merely marked invalid; garbage collection later copies remaining valid pages out of a block and erases it. Dynamic wear leveling directs new writes to free blocks with low erase counts. Static wear leveling also relocates cold data that rarely changes, so the barely worn blocks it occupies rejoin the rotation and all blocks age at a similar rate.

Write amplification and spare area

Garbage collection and static wear leveling write data the host never asked to write. The ratio of NAND writes to host writes, the write amplification factor, directly reduces usable endurance. Reserving spare capacity, called over-provisioning, and the host's TRIM commands, which tell the drive which data are deleted, give the controller room to work and lower the factor. Drive endurance is rated as total bytes written (TBW) or drive writes per day (DWPD), roughly capacity times rated P/E cycles divided by write amplification.

Related mechanisms and where it runs

Wear leveling only evens out wear; it works alongside other controller functions. Error-correcting codes (ECC), from BCH to low-density parity-check (LDPC) codes in modern SSDs, correct the raw bit errors that increase as cells age, and bad block management retires blocks that fail. SSDs, USB drives, SD cards and embedded eMMC devices do all of this inside their controllers, though inexpensive cards may implement it simply. When raw NAND is attached directly to a processor, flash-aware file systems or the host software must provide wear leveling instead.

Answer: C. To spread writes across the whole device instead of concentrating them on certain blocks, extending its life

Each block tolerates a limited number of erase cycles, so writing the same logical address repeatedly would wear one spot out early. With wear leveling, the controller maintains a logical-to-physical mapping (the FTL) and steers writes to blocks with fewer erases. It also occasionally relocates rarely changed static data, evening out wear across all blocks and extending product life.

FAQ

What is the difference between static and dynamic wear leveling?

Dynamic wear leveling chooses lightly worn free blocks for new writes, while static wear leveling also moves rarely changed data out of lightly worn blocks so those blocks can share the write load.

Does wear leveling increase write amplification?

Static wear leveling adds some internal writes because it moves data the host did not change, but the gain in evenly distributed wear far outweighs that cost.

How many write cycles can NAND flash handle?

Roughly 50,000 to 100,000 for SLC, several thousand to 10,000 for MLC, a few thousand for TLC and about 1,000 for QLC, depending on process and conditions.
