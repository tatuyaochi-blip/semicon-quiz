What is Function pointer?

A pointer whose value is the address of a function. It is declared including the argument and return types, as in int (*fp)(int, int) = add; and the function it points to is called with fp(1, 2) or (*fp)(1, 2). An array of function pointers forms a table that selects processing by number. Function pointers are used for callbacks such as the comparison function passed to qsort, interrupt vector tables, and the handlers of each state in a state machine. In machine code, the call becomes an indirect call that jumps to an address held in a register.

Japanese name: 関数ポインタ

How is a call through a C function pointer, "(*fp)(x)", generally performed in RISC-V?

  1. AThe function address is placed in a register, and jalr jumps to that register's address
  2. Bjal jumps with the function address written as an immediate
  3. Cbeq compares with the function address and jumps if equal
Show answer and explanation

Answer: A. The function address is placed in a register, and jalr jumps to that register's address

The target of a function pointer is not known until run time, so jal, whose target is written in the instruction, cannot be used. Instead the pointer value is loaded into a register and the code jumps to it with, for example, "jalr ra, 0(t0)", leaving the return address in ra. Calls to C++ virtual functions and shared-library functions are similar indirect calls. Because the target can change, CPUs predict it with an indirect branch predictor.

Regarding hardware features that support control-flow integrity, which correctly pairs what protects returns from functions with what protects indirect calls and jumps such as those through function pointers?

  1. AReturns are protected by shadow stacks or pointer authentication; indirect calls and jumps by mechanisms requiring a designated marker instruction at the start of the target
  2. BReturns are protected by mechanisms requiring a designated marker instruction at the start of the target; indirect calls and jumps by shadow stacks
  3. CReturns are protected by KPTI (kernel page-table isolation); indirect calls and jumps by address translation in the IOMMU
Show answer and explanation

Answer: A. Returns are protected by shadow stacks or pointer authentication; indirect calls and jumps by mechanisms requiring a designated marker instruction at the start of the target

A shadow stack compares the return address with its copy, and pointer authentication checks the authentication code attached to the return address, so both protect returns from functions. For indirect calls and jumps, Intel IBT and Arm Branch Target Identification require a marker instruction at the start of the target (ENDBR64 on x86) and turn branches into the middle of functions and the like into exceptions. However, any place with a marker can still be reached from any indirect branch, so these features are sometimes combined with finer checks by the compiler that restrict targets to functions of a matching type. KPTI is a countermeasure against Meltdown and the IOMMU restricts device DMA; neither protects control flow.
