What is Nested paging?

Hardware that walks two levels of page tables in succession, one managed by the guest OS and one by the hypervisor. It reduces hypervisor intervention and speeds up virtualization.

Japanese name: 入れ子ページング

Nested paging appears in 3 practice questions across 1 topic, including OS & Hardware.

Field: OS & Hardware

Two translations in one hardware walk

A guest operating system inside a virtual machine manages page tables that map guest virtual addresses to what it believes are physical addresses, called guest physical addresses. That memory actually lives wherever the hypervisor placed it. With nested paging, also known as two-stage translation, the hardware walks the guest's page tables and then the hypervisor's own tables, translating guest virtual to guest physical to host physical automatically. The common implementations are Intel's Extended Page Tables (EPT), AMD's Nested Page Tables (NPT) and Arm's stage-2 translation.

What it replaced: shadow page tables

Before hardware support, hypervisors used shadow page tables: software-maintained tables mapping guest virtual addresses directly to host physical addresses, which the real MMU used. To keep them correct, the hypervisor had to trap the guest's page-table writes and address-space switches, causing frequent and expensive exits from the virtual machine. Nested paging lets the guest edit its own tables freely, removing most of those exits and simplifying the hypervisor. The trade-off moves to the cost of a TLB miss.

Why a TLB miss can cost 24 memory accesses

Each entry the guest walker needs is located by a guest physical address, which must itself be translated through the host's tables before it can be read. With four-level tables on both sides, each guest level costs four host reads plus one guest-table read, five in all, for 20 across four levels, and translating the final data address through the host adds four more: (4 + 1) × (4 + 1) − 1 = 24, versus four for a native walk. Page-walk caches, TLBs that cache the final combined translation and large pages on the host side keep the average cost far lower.

In virtualization with nested paging (two-stage address translation), which describes what the hardware does?

  1. AIt walks only the guest OS's page tables and does not use the hypervisor's tables
  2. BIt translates guest virtual → guest physical → host physical
  3. CThe hypervisor intercepts every memory access and translates each one in software
Show answer and explanation

Answer: B. It translates guest virtual → guest physical → host physical

A guest OS believes its physical addresses (guest physical addresses) are real memory, but the memory actually lives elsewhere as assigned by the hypervisor. With nested paging, hardware translates through the guest's page tables to a guest physical address and then through the hypervisor's tables to a host physical address. The hypervisor no longer needs to intervene every time the guest edits its page tables. Translating every access in software would be far too slow.

In nested paging where both guest and host use 4-level page tables, how many memory accesses can a TLB miss require in the worst case?

  1. A8
  2. B16
  3. C24
Show answer and explanation

Answer: C. 24

Each of the guest's four table locations is a guest physical address, so it must be translated through the host's four levels before it can be read. Each guest level costs four host reads plus one guest-table read, five in all, giving 20 for four levels; translating the final guest physical address of the data itself through the host's four levels adds four more, for 24. As a formula, (4 + 1) × (4 + 1) − 1 = 24. Eight assumes simply walking four levels twice, overlooking translation of the table locations.

FAQ

What is the difference between nested paging and shadow paging?

Shadow paging has the hypervisor maintain combined guest-virtual-to-host-physical tables in software and trap guest page-table updates. Nested paging lets the hardware walk the guest and host tables in succession, so the guest updates its own tables without hypervisor intervention.

How many memory accesses does a nested page walk need?

With four-level page tables in both guest and host, a TLB miss can require up to 24 memory accesses in the worst case, compared with four for a non-virtualized walk.

Is nested paging the same as nested virtualization?

No. Nested paging is two-stage address translation for ordinary virtual machines, while nested virtualization means running a hypervisor inside a virtual machine.
