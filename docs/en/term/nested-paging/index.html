What is Nested paging?

Hardware that walks two levels of page tables in succession, one managed by the guest OS and one by the hypervisor. It reduces hypervisor intervention and speeds up virtualization.

Japanese name: 入れ子ページング

Try it: questions about Nested paging

In virtualization with nested paging (two-stage address translation), which describes what the hardware does?

  1. AIt walks only the guest OS's page tables and does not use the hypervisor's tables
  2. BIt translates guest virtual → guest physical → host physical
  3. CThe hypervisor intercepts every memory access and translates each one in software
Show answer and explanation

Answer: B. It translates guest virtual → guest physical → host physical

A guest OS believes its physical addresses (guest physical addresses) are real memory, but the memory actually lives elsewhere as assigned by the hypervisor. With nested paging, hardware translates through the guest's page tables to a guest physical address and then through the hypervisor's tables to a host physical address. The hypervisor no longer needs to intervene every time the guest edits its page tables. Translating every access in software would be far too slow.

In nested paging where both guest and host use 4-level page tables, how many memory accesses can a TLB miss require in the worst case?

  1. A8
  2. B16
  3. C24
Show answer and explanation

Answer: C. 24

Each of the guest's four table locations is a guest physical address, so it must be translated through the host's four levels before it can be read. Each guest level costs four host reads plus one guest-table read, five in all, giving 20 for four levels; translating the final guest physical address of the data itself through the host's four levels adds four more, for 24. As a formula, (4 + 1) × (4 + 1) − 1 = 24. Eight assumes simply walking four levels twice, overlooking translation of the table locations.
