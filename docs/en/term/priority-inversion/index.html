What is Priority inversion?

A situation in which a high-priority task waiting for a resource held by a low-priority task is held up because a medium-priority task preempts the low one.

Japanese name: 優先度逆転

Which describes priority inversion in an RTOS?

  1. AWhile a high-priority task waits for a resource held by a low-priority task, a medium-priority task preempts the low one and keeps running, so the high task waits a long time
  2. BA bug where priority numbers are interpreted backwards
  3. CA rule that high-priority tasks always run after low-priority ones
Show answer and explanation

Answer: A. While a high-priority task waits for a resource held by a low-priority task, a medium-priority task preempts the low one and keeps running, so the high task waits a long time

If a high-priority task waits for a mutex held by a low-priority task, it must wait until the low task releases it. If an unrelated medium-priority task then starts running, it preempts the low task, which cannot release the resource, so in effect the high task is held up by the medium task. On the Mars Pathfinder lander in 1997, this caused repeated system resets.

Which describes priority inheritance, used to prevent priority inversion?

  1. ALower the high-priority task to the low task's priority
  2. BGive all tasks the same priority
  3. CTemporarily raise the low-priority task holding a resource to the priority of the high-priority task waiting for it
Show answer and explanation

Answer: C. Temporarily raise the low-priority task holding a resource to the priority of the high-priority task waiting for it

With priority inheritance, when a high-priority task starts waiting for a mutex held by a low-priority task, the low task temporarily gets the high task's priority. It then proceeds without being preempted by medium tasks and returns to its original priority on releasing the resource. The high task waits only for the short time the low task uses the resource. Many RTOS mutexes provide this feature.
