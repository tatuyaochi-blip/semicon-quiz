What is Intermediate representation?

A form of the program inside a compiler that depends on neither the source language nor the target CPU. Most optimizations operate on it, separating language-specific front ends from CPU-specific back ends.

Japanese name: 中間表現

Field: Compilers

Why compilers use an IR

Supporting M source languages on N processors with separate compilers would require M × N of them. With a shared intermediate representation (IR), each language needs only a front end that translates into the IR and each processor only a back end that translates out of it, M + N pieces in total. Optimizations written once on the IR then benefit every language and target. LLVM is the best-known example: front ends such as Clang emit LLVM IR, and back ends generate code for x86, Arm, RISC-V and other targets.

Common forms

Compilers often use several IR levels. Close to the source sits an abstract syntax tree. Lower down, three-address code breaks expressions into simple steps such as t1 = a + b; x = t1 * c, with temporaries for intermediate values. These instructions are grouped into basic blocks connected by a control-flow graph. Many modern IRs, including LLVM IR, use static single assignment (SSA) form, where each variable is assigned exactly once and special phi nodes merge values where control paths join.

What happens on the IR

Most optimization passes run on the IR: constant propagation, dead code elimination, common subexpression elimination, moving loop-invariant computations out of loops, and function inlining. SSA form makes many of these simpler because every use points to exactly one definition. Link-time optimization (LTO) stores IR instead of machine code in object files so that the whole program can be optimized together, enabling inlining and dead-function removal across source files.

IR vs. bytecode and machine code

A compiler's internal IR is a working form for analysis and transformation; the CPU cannot execute it, and the back end must still select instructions, allocate registers and schedule code. Portable bytecodes, such as Java bytecode or WebAssembly, are related but serve a different purpose: they are stable distribution formats that a virtual machine interprets or compiles just in time, whereas internal IRs may change between compiler versions.

Answer: C. Language-specific front ends and CPU-specific back ends can be separated, and optimizations shared

Supporting M languages and N CPUs with a compiler per combination needs M × N compilers, but with a common IR it takes only M front ends (language to IR) and N back ends (IR to CPU). Most optimizations, written once on the IR, then serve every language and CPU. The IR cannot be executed directly by the CPU and must finally be converted to machine code.

Which describes three-address code, a kind of intermediate representation?

  1. AA single instruction can contain any number of operations and parentheses
  2. BEach instruction has at most three addresses and one operation
  3. CAddresses must always be physical memory addresses
Show answer and explanation

Answer: B. Each instruction has at most three addresses and one operation

Three-address code breaks complex expressions into a sequence of simple instructions with one operation each. For example, x = (a + b) * c becomes t1 = a + b and x = t1 * c, and each instruction mentions at most three addresses: the result and two operands. Intermediate values get temporary names such as t1. This makes evaluation order explicit and eases optimization and translation to CPU instructions. Addresses are variables or temporaries, not physical addresses.

FAQ

What is an intermediate representation in a compiler?

It is the form a compiler translates source code into before generating machine code, independent of both the source language and the target CPU, so optimizations can be shared.

What is SSA form?

Static single assignment is an IR form in which every variable is assigned exactly once, with phi nodes selecting values where control flow merges, which simplifies many optimizations.

Is LLVM IR machine code?

No. LLVM IR is a target-independent intermediate representation; a back end must translate it into machine code for a specific processor.
