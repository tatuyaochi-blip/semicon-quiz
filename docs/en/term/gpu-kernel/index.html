What is GPU kernel?

A function that many threads execute simultaneously on a GPU. It is launched from the CPU-side program, and each thread uses its index to choose its data. Distinct from an OS kernel.

Japanese name: GPUカーネル

What can happen if a GPU kernel uses too many registers per thread?

  1. ARegisters grow automatically and performance always improves
  2. BResults are always wrong
  3. CEach SM has a fixed register file, so fewer threads fit at once and memory latency becomes harder to hide
Show answer and explanation

Answer: C. Each SM has a fixed register file, so fewer threads fit at once and memory latency becomes harder to hide

GPUs keep the registers of every active thread on chip so that switching warps is instantaneous. So if each thread uses many registers, fewer threads fit on an SM at once. Registers that do not fit are spilled to memory, which can also slow things down. Compiler options can cap register usage to balance it against thread count.

In CUDA, how does the CPU-side program receive the results computed by a GPU kernel (a function marked __global__)?

  1. AThrough the kernel's return value, which sends the results of all threads back to the CPU together
  2. BThe kernel writes its results to an array in GPU memory, and after the kernel finishes the CPU side copies that array to CPU memory (or reads unified memory)
  3. CThe CPU-side program reads the values each thread printed with printf as variables
Show answer and explanation

Answer: B. The kernel writes its results to an array in GPU memory, and after the kernel finishes the CPU side copies that array to CPU memory (or reads unified memory)

A GPU kernel is executed by many threads at once, so it cannot return its results as a single value, and in CUDA a __global__ function must have a void return type. The CPU side allocates an array in GPU memory and passes its pointer as an argument, and each thread writes its result to the element it handles. Because kernel launches are asynchronous, the CPU side copies the array back with cudaMemcpy or similar after the kernel has finished (in the same stream, the copy waits for the preceding kernel to finish). printf inside a kernel is a debugging aid for displaying output, and the program cannot read those values back.
