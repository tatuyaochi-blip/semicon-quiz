What is Interrupt handler?

The routine a CPU runs when an interrupt or exception occurs. It saves the interrupted state, handles the cause and returns. Handlers should be kept as short as possible.

Japanese name: 割り込みハンドラ

Field: OS & Hardware

What happens when an interrupt is accepted

When a device signals an interrupt, the CPU finishes the current instruction, saves the address it would have executed next along with state such as the operating mode and flags, and jumps to the interrupt handler, also called an interrupt service routine (ISR), usually found through an interrupt vector table. The handler saves any registers it uses, services the cause, clears the device's interrupt flag, restores state and executes a return-from-interrupt instruction. The interrupted program then resumes exactly where it stopped; it is neither discarded nor restarted.

Why handlers must be short

While a handler runs, other interrupts of the same or lower priority are typically held off and the main code is stalled, so a long handler increases latency for everything else. Slow calls such as printf are especially risky because they take time and may themselves depend on interrupts. A good handler does the minimum, such as moving received data into a buffer or setting a flag, and leaves heavy processing to the main loop or a task. Operating system kernels formalize this by splitting work into an immediate part and a deferred part.

Sharing data with main code

Variables shared between a handler and the main program cause classic bugs. If main spins on a flag that only the handler sets, an optimizing compiler may load it into a register once and never see the update; declaring it volatile forces every access to go to memory. A read-modify-write such as reg |= mask can be interrupted between the read and the write, wiping out a change the handler made to another bit. Briefly disabling interrupts or using hardware set and clear registers avoids this, and multi-byte variables need protection against torn reads.

Interrupts in scheduling and watchdogs

A periodic timer interrupt is what lets an operating system take back the CPU from a program that never yields, enabling preemptive scheduling and context switches. Interrupts are asynchronous events from hardware, whereas exceptions such as page faults or divide-by-zero arise synchronously from the instruction being executed, though both enter the kernel through similar handlers. One common mistake is kicking a watchdog timer unconditionally inside a timer interrupt: the interrupt keeps firing even if the main loop has hung, so the watchdog never detects the failure.

  3. CNothing happens; no fix is needed
Show answer and explanation

Answer: A. The handler's change is lost when main writes back; disable interrupts during the update or use dedicated per-bit set/clear registers

"reg |= mask" is three operations: read the register, OR, and write back. If an interrupt arrives right after the read and the handler changes another bit, main writes back a value based on the stale read, wiping out the handler's change. Disabling interrupts during the operation, or using set and clear registers where only the bits written as 1 change, makes it a single write and avoids the problem.

What should be avoided inside an interrupt handler?

  1. AWriting 1 to a flag variable to notify the main code
  2. BClearing the bit that indicates the interrupt source
  3. CTime-consuming work such as printing long strings with printf or loops that wait for something to happen

Answer: C. Time-consuming work such as printing long strings with printf or loops that wait for something to happen

While an interrupt handler runs long, other interrupts cannot be serviced and the main code stalls. printf takes time to finish and may itself rely on interrupts, so it is especially risky. A handler should do only the minimum, such as moving received data into a buffer or setting a flag, and leave heavy work to the main loop or a task. It must also remember to clear the interrupt source bit.

FAQ

What is the difference between an interrupt handler and an ISR?

There is no real difference: interrupt service routine (ISR) is another name for the interrupt handler, the code the CPU runs in response to an interrupt.

Why should a variable shared with an interrupt handler be declared volatile?

Without volatile, the compiler may assume the variable cannot change inside a loop and keep it in a register, so the main code never sees the handler's update. Volatile forces each access to read or write memory.

What is the difference between an interrupt and an exception?

An interrupt is an asynchronous signal from hardware such as a timer or peripheral, unrelated to the current instruction. An exception is raised synchronously by the instruction being executed, for example a page fault or an illegal operation.
