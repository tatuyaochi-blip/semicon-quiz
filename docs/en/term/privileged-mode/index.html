What is Privileged mode?

A CPU operating mode reserved for the OS kernel, in which dangerous operations such as setting page tables and controlling I/O are allowed. It is distinguished from user mode, where applications run.

Japanese name: 特権モード

Field: OS & Hardware

What privileged mode protects

Certain operations would let one program take over the whole machine: changing page tables or the register that points to them, accessing I/O devices directly, disabling interrupts, reprogramming the timer that lets the OS regain control, or halting the CPU. The processor allows these only in privileged mode, also called kernel or supervisor mode. If code running in user mode attempts one, the CPU raises an exception and the OS decides what to do, typically terminating the program.

Entering and leaving it

User code cannot simply jump into privileged mode. The only ways in are exceptions, interrupts and deliberate traps such as system calls, and each one transfers control to an entry point the OS configured in advance. The CPU saves the return address, previous mode and interrupt-enable state in dedicated registers. A special return instruction, such as sret or mret on RISC-V, restores all of these at once, so execution never resumes in user code while still holding privileges.

Levels on real CPUs

Many architectures have more than two levels. RISC-V defines machine, supervisor and user modes; x86 has rings 0 to 3, with operating systems mainly using ring 0 for the kernel and ring 3 for applications; Arm uses exception levels EL0 to EL3. A hypervisor runs above guest kernels, and when a guest executes a privileged instruction it traps to the hypervisor, which emulates the effect. This trap-and-emulate scheme reuses the same protection idea one level higher.

Privileged mode vs. administrator rights

Privileged mode is a hardware state of the CPU, not a user account. A process run by an administrator or root user still executes in user mode; its extra rights are permissions the kernel checks when it handles that process's system calls. Only kernel code, and in some systems firmware or a hypervisor, runs in privileged mode. Memory protection complements the mode bit: page-table entries mark which pages user mode may access.

  2. BTo prevent applications from tampering with page tables and devices
  3. CTo let one CPU execute two instructions at the same time

Answer: B. To prevent applications from tampering with page tables and devices

If applications could freely rewrite page tables, operate I/O devices or disable interrupts, they could corrupt other programs' memory or halt the whole system. CPUs therefore allow these operations only in privileged mode, reserving them for the OS kernel; attempting them in user mode raises an exception. The modes are not about speed or simultaneous execution.

What is the mechanism by which applications ask the OS to perform tasks such as file I/O?

  1. ASystem call
  2. BContext switch
  3. CDemand paging
Show answer and explanation

Answer: A. System call

Applications run in user mode and cannot operate disks or devices directly. They use system calls: a dedicated instruction switches to privileged mode and invokes the kernel to read or write files, allocate memory, create processes and so on, then returns to user mode. A context switch changes which process runs, and demand paging loads pages only when needed.

FAQ

What is the difference between kernel mode and user mode?

In kernel (privileged) mode the CPU allows operations such as changing page tables, controlling devices and disabling interrupts. In user mode these raise an exception, so applications must ask the kernel through system calls.

Does running as root mean running in kernel mode?

No. Root is an operating-system permission level, and root processes still run in user mode; only the kernel executes in privileged mode.

How does a program switch to kernel mode?

Only through a trap, such as executing a system call instruction, or through an exception or interrupt, all of which enter the kernel at entry points the OS has set up.
