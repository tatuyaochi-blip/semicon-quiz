What is Queue?

A first-in, first-out (FIFO) data structure in which the element added first is removed first. Adding to the back is called enqueue and removing from the front is called dequeue. Queues are used for waiting lines of work, passing data between tasks and breadth-first search.

Japanese name: キュー

When waiting on a condition variable until a queue becomes non-empty, why is the condition rechecked in a while loop rather than an if after waking?

  1. AA while loop runs faster than an if statement
  2. BCondition variables cannot be used with if statements
  3. CEven after waking, another thread may have taken the item first or the wake-up may be spurious, so the condition may not hold
Show answer and explanation

Answer: C. Even after waking, another thread may have taken the item first or the wake-up may be spurious, so the condition may not hold

Waiting on a condition variable releases the lock and sleeps; when signaled, the thread reacquires the lock and returns. But before it does, another thread may grab the lock and take the queue element. Implementations are also allowed to wake a thread with no signal at all (a spurious wake-up). So the code checks the condition after waking and waits again if it does not hold, using a while loop.

In an RTOS, what is the advantage of using a queue (message queue) to pass data from a sensor-reading task to a display task?

  1. AData passing through a queue is encrypted automatically
  2. BThe receiver can sleep until data arrives, and differences in speed between sender and receiver are absorbed by the queue
  3. CUsing a queue makes task priorities unnecessary
Show answer and explanation

Answer: B. The receiver can sleep until data arrives, and differences in speed between sender and receiver are absorbed by the queue

Passing data through a shared variable and flag requires guarding against data races and having the receiver check repeatedly. With an RTOS queue, the sender simply puts data in and the receiver waits in a blocked state without using CPU until data arrives. Because several items can be buffered, no data is lost even if the sender is temporarily faster.
