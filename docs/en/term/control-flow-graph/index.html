What is Control-flow graph?

A graph representing a program's execution flow, with basic blocks as nodes and branches between them as edges. It is used to detect loops and analyze data flow.

Japanese name: 制御フローグラフ

Control-flow graph appears in 3 practice questions across 1 topic, including Compilers.

Field: Compilers

Basic blocks as nodes

A control-flow graph (CFG) is built from basic blocks: maximal runs of instructions entered only at the first instruction and left only at the last. To form them, a compiler marks leaders, namely the first instruction of a function, every branch target and every instruction immediately following a branch. Each block runs from a leader up to the next leader. Since instructions inside a block always execute in order, local optimizations such as common subexpression elimination are easy to apply within one block.

Edges and what the shape reveals

Edges represent possible transfers of control: a conditional branch gives a block two successors, the taken target and the fall-through block, while an unconditional jump gives one. Many analyses add a single entry and exit node. The graph's shape exposes structure. A block d dominates block n if every path from entry to n passes through d, and an edge whose target dominates its source is a back edge that identifies a loop. Blocks unreachable from the entry are dead code that can be removed.

Data-flow analysis on the CFG

Many optimizations rely on data-flow analyses that propagate facts along CFG edges and iterate until nothing changes. Liveness analysis works backward to find, at each point, which values may still be read later, and its result builds the interference graph used for register allocation. Reaching definitions works forward to find which assignments may supply a variable's value. Static single assignment (SSA) form, used by most modern compilers, is also constructed on the CFG, inserting phi functions where control-flow paths merge.

CFG vs. call graph

A CFG describes flow inside a single function, whereas a call graph has whole functions as nodes and calls as edges; interprocedural analysis uses both. CFGs also appear outside compilers. Branch coverage in testing asks whether every CFG edge has been executed, binary analysis tools reconstruct CFGs from machine code, and control-flow integrity defenses restrict indirect jumps to edges the CFG allows, blocking attacks that redirect execution to unintended code.

Answer: B. Nodes are basic blocks, and edges are branches or transitions between blocks

A control-flow graph has basic blocks as nodes and, as edges, the possible transitions from one block to the next: both targets of a conditional branch, or falling through to the following block. Back edges reveal loops, and the graph supports analyses of where variable values flow. Calls between functions are shown in a separate call graph, and file include relationships are unrelated.

FAQ

What is a basic block in a control-flow graph?

A straight-line sequence of instructions with one entry at the top and one exit at the bottom, so that if its first instruction runs, all of them run in order.

How do you find loops in a control-flow graph?

Compute dominators and look for back edges, edges whose target dominates their source; each back edge defines a natural loop headed by its target block.

What is the difference between a control-flow graph and a call graph?

A control-flow graph shows the possible paths between basic blocks within one function, while a call graph shows which functions call which other functions.
