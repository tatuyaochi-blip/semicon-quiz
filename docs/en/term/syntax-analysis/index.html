What is Syntax analysis (parsing)?

The compiler phase that checks whether the token sequence follows the language grammar and builds the program's structure as a tree. Grammar errors are detected here.

Japanese name: 構文解析

Syntax analysis (parsing) appears in 4 practice questions across 1 topic, including Compilers.

Field: Compilers

Where parsing sits in a compiler

A compiler front end works in stages. Lexical analysis turns the character stream into tokens such as identifiers, numbers and symbols, discarding whitespace and comments. Syntax analysis, or parsing, then checks whether that token sequence forms a valid program according to the language grammar and records how the pieces nest: which statements form a loop body, which operands belong to which operator. Errors such as a missing semicolon or unbalanced parentheses are reported here. Semantic analysis follows, checking types and whether names are declared, before the program is lowered to an intermediate representation for optimization and code generation.

Why context-free grammars are needed

Token rules are simple enough for regular expressions and fast finite automata, but program structure is not. Nested parentheses and if statements inside if statements require counting to unlimited depth, which no regular expression can do. Programming languages are therefore described with context-free grammars, sets of rewriting rules such as expr → expr + term, often written in Backus-Naur form. A well-designed grammar also encodes operator precedence and associativity, so that a + b * c groups the multiplication first. Ambiguous grammars, where one input has two possible trees, must be avoided or resolved with extra rules.

Top-down LL vs. bottom-up LR parsing

LL parsers work top-down: starting from the start symbol, they predict which rule to apply by looking at the next token or few tokens. Hand-written recursive-descent parsers, with one function per grammar rule, are LL in style and are widely used for their clarity and good error messages, but they require left-recursive rules to be rewritten. LR parsers work bottom-up: they shift tokens onto a stack and reduce them to rules once a complete right-hand side is recognized. LR handles a wider class of grammars, and parser generators such as yacc and Bison build LALR tables automatically.

Parse trees vs. abstract syntax trees

Following the grammar literally yields a concrete syntax tree, or parse tree, containing every parenthesis, separator and intermediate rule. Later phases need far less, so parsers usually build an abstract syntax tree (AST) instead. In the AST for (a + b) * c, the addition node simply sits beneath the multiplication node; the tree shape now carries the evaluation order, and the parentheses disappear. The AST is the data structure that semantic analysis annotates with types and scopes and that the compiler later translates into intermediate code.

Answer: C. Checking the token sequence against the grammar and building the program structure as a tree

Parsing checks whether the token sequence produced by lexical analysis follows the language grammar and builds structures, such as an if statement's condition and body or the operations inside an expression, into a tree (a syntax tree). Grammar errors such as a missing semicolon or mismatched parentheses are found here. Splitting into words while removing whitespace is lexical analysis, and converting to machine code at run time is JIT compilation.

Answer: C. Context-free grammars

Nested parentheses and if statements inside if statements cannot be expressed with regular expressions. Most programming-language grammars are written as context-free grammars, collections of rewriting rules such as "expr → expr + term", and parsing is based on them. Parsing methods include LL, which applies rules top-down, and LR, which builds bottom-up, and tools can generate parsers from grammars automatically. Regular grammars suit lexical analysis and cannot handle nesting.

FAQ

What is the difference between lexical analysis and syntax analysis?

Lexical analysis splits source text into tokens and discards whitespace and comments. Syntax analysis takes those tokens, checks them against the grammar and builds a tree describing the program structure.

What is an abstract syntax tree?

An abstract syntax tree is a tree representation of a program that keeps only the operations and statements needed for meaning. Grouping symbols like parentheses are dropped because the tree shape itself expresses precedence and nesting.

What is the difference between LL and LR parsers?

LL parsers build the tree top-down, predicting rules from upcoming tokens, and include hand-written recursive-descent parsers. LR parsers build bottom-up by shifting tokens onto a stack and reducing them to rules, and accept a broader class of grammars.
