What is Throughput?

The amount of work, requests or data processed per unit time, a different metric from latency, which describes how fast one task completes.

Japanese name: スループット

Throughput appears in 20 practice questions across 16 topics, including CPUs and architecture, Computer Networking Basics, DRAM.

Field: Performance Analysis

Throughput vs. latency

Throughput counts how much work finishes per unit time; latency measures how long one piece of work takes from start to finish. The two often trade against each other. A five-stage CPU pipeline ideally completes one instruction per clock, raising throughput about fivefold, even though each instruction's latency grows slightly. Batching requests in a server or AI inference engine raises throughput but makes each request wait. CPUs spend circuitry on making one thread fast, while GPUs run thousands of simpler threads to maximize total throughput.

Throughput in memory and I/O

Peak memory throughput is transfer rate times bus width. DDR memory transfers on both clock edges, so DDR4-3200 runs a 1600 MHz clock at 3200 MT/s, and a 64-bit channel peaks at 25.6 GB/s. Multiple DRAM banks overlap activate and precharge operations to keep data flowing. Link encoding also matters: PCI Express 3.0 moved from 8b/10b (80% efficient) to 128b/130b (about 98.5%), nearly doubling effective throughput while the signaling rate rose only from 5 to 8 GT/s.

Compute-bound or memory-bound

The roofline model shows which kind of throughput limits a program. Plotting performance against arithmetic intensity, in operations per byte moved from memory, gives a slanted ceiling set by memory bandwidth and a flat ceiling set by peak compute. With 1 TB/s of bandwidth and 100 TFLOPS of compute, any kernel below 100 FLOP per byte is memory-bound, so improving data reuse helps more than adding arithmetic units.

Throughput in a fab

Manufacturing uses the same idea. Tool throughput is quoted in wafers per hour, and choices often trade it against other goals: batch cleaning of about 50 wafers per bath is fast but risks cross-contamination, higher EUV dose reduces stochastic defects but lowers scanner throughput, and thermocompression bonding is slower than mass reflow. At factory level, Little's law states WIP = throughput × cycle time, so a fab shipping 50,000 wafers a month with a three-month cycle time holds about 150,000 wafers in process.

  2. BWIP = throughput ÷ cycle time
  3. CWIP is unrelated to cycle time

Answer: A. WIP = throughput × cycle time

Little's law states that average WIP equals throughput (output per unit time) times cycle time. A fab completing 50,000 wafers a month with a three-month cycle time always holds about 150,000 wafers in process. Shortening cycle time at the same throughput requires less WIP, and piling on too much WIP lengthens cycle time.

Answer: B. The roofline model

The roofline model plots performance against arithmetic intensity (operations per byte read from memory). Low-intensity workloads hit a slanted ceiling set by memory bandwidth; high-intensity workloads hit a flat ceiling at peak compute. With 1 TB/s of bandwidth and 100 TFLOPS of compute, for example, anything below 100 FLOP/byte is memory-bound. The model guides whether to improve data reuse or compute efficiency.

FAQ

What is the difference between throughput and latency?

Throughput is the amount of work completed per unit time, such as requests per second or GB/s. Latency is the time a single request takes to complete; a system can have high throughput and still high latency, for example when it batches work.

How do you calculate memory bandwidth?

Multiply the transfer rate by the bus width in bytes. For example, DDR4-3200 on a 64-bit (8-byte) channel gives 3200 MT/s × 8 B = 25.6 GB/s peak; sustained throughput is lower because of refresh, bank conflicts and turnarounds.

What is Little's law?

Little's law says average work in progress equals throughput multiplied by average time in the system. It applies to fabs, queues and processors alike, so cutting cycle time at constant throughput requires less WIP.
