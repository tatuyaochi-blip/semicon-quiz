What is Object file?

The file a compiler produces from one source file. It contains machine code, initial data, a symbol table and relocation entries, but addresses in other files are unresolved, so it cannot run until linked.

Japanese name: オブジェクトファイル

Field: Linkers, Loaders & Executables

What is inside an object file

An object file is organized into sections. The text section holds machine code; the data section holds initialized writable variables; a read-only data section holds constants and string literals; and the bss section records only the size of zero-initialized variables, so it takes no space in the file. Alongside these, the symbol table lists every name the file defines and every name it uses but does not define, and the relocation entries list each place whose address must be filled in later. Debug information is optional. Common formats are ELF on Linux, Mach-O on macOS and COFF/PE on Windows.

Why it cannot run by itself

The compiler or assembler builds each object file in isolation, laying out its sections as if they began at address 0. When code calls a function in another file, such as printf, its address is unknown, so the instruction contains a placeholder, often 0, plus a relocation entry describing what must go there. Only the linker sees all object files and libraries together. It matches every undefined symbol with a definition, decides where each section will live in memory, patches the placeholders and adds the startup code and headers the operating system needs to load a program.

Typical link errors and what they mean

An error such as undefined reference to foo means some object file uses foo but nothing in the link defines it. Common causes are forgetting to link the file that defines it, omitting a library option such as -lm, a misspelled name, or calling C code from C++ without extern "C", which makes the names differ after C++ name mangling. The reverse, multiple definition, usually comes from defining a variable in a header included by several source files. With the GNU linker, static libraries should appear after the object files that use them on the command line.

Object files, static libraries and shared libraries

A static library is simply an archive of object files. The linker extracts only the members that resolve currently undefined symbols, which is why command-line order matters. A shared library is different: it is already the output of a link, built from position-independent code, and it is mapped into memory at run time, with remaining addresses filled in by the dynamic linker. Tools such as nm, objdump and readelf display an object file's sections, symbols and relocation entries, and are the quickest way to see why a link fails.

  2. BIt is just compressed source code and contains no machine code
  3. CIt contains machine code, but the addresses of functions and variables in other files are not yet fixed

Answer: C. It contains machine code, but the addresses of functions and variables in other files are not yet fixed

An object file holds the machine code translated from that file's functions, initial values of variables, a list of names it defines and references (the symbol table) and a list of places whose addresses must be filled in later (relocation entries). An instruction calling a function in another file, such as printf, keeps a placeholder because the address is unknown. The linker combines several object files, fixes the addresses and produces an executable.

With the GNU linker, writing a static library before the object file that uses it, as in "gcc -lmylib main.o", can cause undefined-reference errors. Why?

  1. AThe linker works left to right and does not extract functions not yet referenced when it reads the library
  2. BOnly one library may be written, and only at the end of the command
  3. CWriting the library first erases its contents
Show answer and explanation

Answer: A. The linker works left to right and does not extract functions not yet referenced when it reads the library

The GNU linker processes files in command-line order, and when it meets a static library it extracts only the objects that resolve references still undefined at that moment. If the library comes first, main.o's references do not exist yet, so nothing is extracted, and the linker does not go back after reading main.o. That is why libraries are normally written after the files that use them.

FAQ

What is the difference between an object file and an executable?

An object file contains machine code for one source file but leaves references to other files unresolved and has no final addresses. An executable is the linker's output, with all symbols resolved, addresses fixed and headers that tell the operating system how to load it.

How can I list the symbols in an object file?

Use nm, objdump -t or readelf -s. In nm output, symbols marked U are undefined, meaning the file references them and expects another object file or library to define them.

What is the bss section?

It holds global and static variables that start at zero. The object file records only its size, and the loader allocates and zero-fills the memory when the program starts.
