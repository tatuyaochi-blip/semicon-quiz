What is Value change dump (VCD)?

A standard file format recording signal value changes during simulation, viewed in waveform tools for debugging.

Japanese name: VCD

Value change dump (VCD) appears in 1 practice question across 1 topic, including HDL & Verification.

Field: HDL & Verification

What a VCD file records

VCD (value change dump) is a text file format that records when and how each signal's value changed during a logic simulation. Defined in the Verilog standard IEEE 1364, it can be written by most simulators and opened in waveform viewers such as GTKWave for debugging. Because it records only the times at which values changed and the new values, it is smaller than writing every value at every clock. Values use four states, 0, 1, x (unknown) and z (high impedance), and multi-bit signals are recorded together as vectors.

File structure

A VCD file consists of a header followed by a list of value changes. The header gives the creation date ($date), time unit ($timescale), module hierarchy ($scope, $upscope) and signal definitions ($var), and ends with $enddefinitions. Each $var assigns the signal a short identifier such as ! or %. The body then gives times such as #100, followed by the signals that changed at that time as a value and identifier, such as 1! for a single bit or b1010 % for a vector. The format is simple enough to read and write with homemade scripts.

Dumping from Verilog, and caveats

In Verilog, the testbench names the output file with $dumpfile and selects what to record with $dumpvars; $dumpvars(0, top) records every signal in all levels of the hierarchy below the top module. $dumpoff and $dumpon pause and resume recording, so only the time window of interest is kept. Because VCD is text, recording every signal of a large design for a long time produces very large files, and writing them also slows the simulation. Designers therefore limit the hierarchy or time span recorded, or use another, compressed format.

Other waveform formats and SAIF

Because VCD is a common format defined by a standard, it is convenient for passing data between simulators and waveform viewers from different vendors. Large designs, however, often use proprietary formats that are compressed and load quickly, such as FST, FSDB and WLF. Counting signal transitions from the value changes in a VCD also allows power analysis. The SAIF format, which summarizes only quantities such as transition counts, is smaller than VCD and widely used for power estimation. IEEE 1364-2001 also defined extended VCD, which additionally records port directions and signal strengths.

Answer: A. To view signal changes over time in a waveform viewer and investigate bugs

VCD (Value Change Dump) is a standard file format recording when and how each signal changed during simulation. Opening it in a waveform viewer shows signal changes clock by clock along a time axis, so you can trace where a value first deviated from expectation. Recording every signal produces huge files, so the dump is sometimes limited to the time range or signals of interest.

FAQ

What do you use to view a VCD file?

Opening it in a waveform viewer such as GTKWave shows signal changes as waveforms along a time axis. Most waveform viewers bundled with simulators can also load VCD, and since it is text it can be inspected directly in an editor.

What can you do when VCD files get too large?

Reduce the data by narrowing the hierarchy recorded with $dumpvars and limiting the time span with $dumpoff and $dumpon. If the simulator supports it, writing a compressed format such as FST or FSDB makes files smaller and faster to load.

What is the difference between VCD and SAIF?

VCD records every change of every signal's value with its time. SAIF summarizes only quantities such as each signal's transition count and the time spent at 0 and 1; it cannot reproduce waveforms, but its files are small and well suited to power analysis.
