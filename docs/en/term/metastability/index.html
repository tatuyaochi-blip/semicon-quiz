What is Metastability?

A state in which a flip-flop's output stays between 0 and 1 for a while when setup or hold time is violated. Asynchronous signals are passed through two flip-flops (a synchronizer) to guard against it.

Japanese name: メタステーブル

Field: Logic circuits

Why a flip-flop can hang between 0 and 1

A flip-flop stores its state in cross-coupled inverters, which have two stable points and one unstable balance point in between. If the data input changes inside the window defined by the setup time (before the clock edge) and hold time (after it), the latch can be left near that balance point. Positive feedback then amplifies the small imbalance with a time constant τ, but the closer it starts to balance, the longer resolution takes, with no hard upper bound. The output may sit at an intermediate voltage or switch late, and the final value is unpredictable.

Synchronizers and MTBF

With an asynchronous input, metastability can only be made rare, not prevented. A two-flip-flop synchronizer gives the first stage almost one clock period to resolve before the second stage samples it. Mean time between failures is approximately MTBF = e^(t_r/τ) / (T_0 × f_clk × f_data), where t_r is the available resolution time and τ and T_0 depend on the flip-flop. Because t_r sits in an exponent, a third stage adds about one period and multiplies MTBF enormously: with τ = 20 ps, an extra 1 ns gives a factor of e^50, over 10^21.

What a synchronizer does not fix

Each synchronized bit may capture a change one cycle early or late, so a multi-bit value such as 0111 to 1000 can arrive as 1111 or 0000. Counters therefore cross in Gray code, where only one bit changes per step, as with asynchronous FIFO pointers; arbitrary data uses a handshake or an asynchronous FIFO. A short pulse from a fast domain can fall between slow-clock edges and vanish, so it must be stretched or converted to a toggle. Crossing signals should come straight from a flip-flop, because a combinational glitch can be captured as a valid value.

Metastability vs. ordinary timing violations

In a single synchronous clock domain, a setup violation means the data path is too slow, and static timing analysis finds it; slowing the clock or speeding the path fixes it. Across asynchronous clocks there is no fixed phase relationship, so violations happen eventually no matter how fast the logic is, and timing analysis cannot close them. That is why designs rely on CDC (clock domain crossing) verification, where tools find every crossing and check for a proper synchronizer, Gray-coded pointer or handshake. Such bugs are rare, so ordinary simulation seldom catches them.

  3. CHow likely metastability is depends on the input side, so MTBF does not change

Answer: A. The time available for metastability to resolve increases by about one period, and MTBF grows exponentially

Synchronizer MTBF is approximately MTBF = e^(t_r/τ) ÷ (T_0 × f_clk × f_data), where t_r is the time available for metastability to resolve and τ and T_0 are constants determined by the flip-flop's characteristics. Adding a stage extends t_r by about one period (precisely, one period minus the flip-flop's clock-to-output delay and setup time). For example, with τ = 20 ps, increasing t_r by 1 ns multiplies MTBF by e^50, more than 10^21 times. The probability of the first stage going metastable is unchanged, but the probability that it resolves before propagating further rises sharply.

FAQ

What causes metastability in a flip-flop?

Data changing within the setup-and-hold window around the clock edge, which leaves the internal latch near its unstable balance point. It is unavoidable when the input is asynchronous to the clock.

Why are two flip-flops used to synchronize an asynchronous signal?

The first flip-flop may go metastable, and the second samples it a full clock period later, by which time it has almost certainly resolved. This raises MTBF exponentially but does not make failure impossible.

Can a synchronizer be used for a multi-bit bus?

Not bit by bit, because different bits can be captured on different cycles and produce an invalid intermediate value. Use Gray code for counters, or a handshake or asynchronous FIFO for general data.
