What is TCP (Transmission Control Protocol)?

A connection-oriented transport-layer protocol. It sets up a connection with a three-way handshake and uses sequence numbers, acknowledgments (ACKs) and retransmission to deliver data in order, without gaps or duplicates. Flow control and congestion control adjust how much it sends. It carries web traffic over HTTP/1.1 and HTTP/2, email, SSH and more.

How TCP guarantees delivery

TCP gives every byte it sends a running number, the sequence number. The receiver returns an acknowledgment (ACK) that says, in effect, send me the data starting from this number next. If no ACK arrives within a set time, the sender sends the data again (retransmission timeout). If it receives three ACKs with the same number (duplicate ACKs), it retransmits without waiting for the timeout (fast retransmit). The receiver puts data that arrived out of order back in order, discards duplicates and uses a checksum to detect corrupted data. To the application, the data looks like a continuous stream of bytes with no message boundaries.

Windows decide how much to send

The sender may send up to a window's worth of data before it has to wait for ACKs. Matching the free buffer space the receiver advertises (the receive window) is flow control; growing and shrinking the sender's congestion window to match how busy the network is, is congestion control. The sender uses whichever of the two is smaller. Because only one window of data can be sent per round-trip time (RTT), throughput is roughly window ÷ RTT. With a 64 KB window and a 100 ms RTT, for example, the ceiling is about 5 Mbit/s, so fast long-distance links rely on the window scale option to allow larger windows.

Header and connection management

A TCP header is 20 bytes without options. It holds the source and destination port numbers, the sequence number, the acknowledgment number, flags such as SYN, ACK, FIN and RST, the window size and a checksum. A connection is identified by four values: the source and destination IP addresses and port numbers. It opens with a three-way handshake and closes when each direction sends a FIN. If one segment is lost, later data cannot be passed to the application even if it has arrived (head-of-line blocking), which is one reason HTTP/3 uses QUIC over UDP instead.

Try it: questions about TCP (Transmission Control Protocol)

In the four-layer TCP/IP model, which layer do TCP and UDP belong to?

  1. AApplication layer
  2. BInternet layer
  3. CTransport layer
Show answer and explanation

Answer: C. Transport layer

The TCP/IP model is described with four layers, from the bottom: the link layer (network interface layer), the internet layer, the transport layer and the application layer. TCP and UDP are transport-layer protocols, and they use port numbers to tell which application on a host the traffic is for. IP, in the internet layer, is responsible for delivering packets from one host to another. HTTP and DNS are application-layer protocols. Mapped onto the OSI reference model, the transport layer corresponds to layer 4 and the internet layer to layer 3.

In the three-way handshake that establishes a TCP connection, what is the correct order of the packets exchanged?

  1. ASYN → ACK → FIN
  2. BACK → SYN → SYN+ACK
  3. CSYN → SYN+ACK → ACK
Show answer and explanation

Answer: C. SYN → SYN+ACK → ACK

In the three-way handshake, the client first requests a connection with a SYN and announces the first number of the data it will send (its initial sequence number). The server replies with a SYN+ACK, acknowledging (ACK) that and announcing its own initial sequence number. Finally the client returns an ACK, and both directions are ready. Confirming the numbers in both directions in three exchanges prevents mistaken connections, for example from old packets that arrive late. As a result, TCP needs at least one round-trip time (RTT) before data can start flowing. FIN is used to close a connection.

FAQ

What is the difference between TCP and UDP?

TCP sets up a connection and delivers data reliably with acknowledgments, retransmission and ordering. UDP has no setup and no retransmission and simply sends datagrams, so its header is smaller and it adds less delay. TCP is used where completeness matters, such as the web and file transfer; UDP is used where low delay matters more than an occasional loss, such as voice calls, and for short exchanges such as DNS queries.

When does TCP retransmit?

There are two triggers: no ACK arriving before the retransmission timeout, which is calculated from measured RTTs, and three duplicate ACKs with the same acknowledgment number in a row, which triggers fast retransmit. If retransmissions keep failing, the timeout is doubled each time.

Why is TCP throughput lower than the link speed?

At most one window of data can be sent per round-trip time, so throughput falls as the distance to the other end grows or as the window shrinks. It also drops when packet loss makes congestion control cut the window, or when the receiving application reads data slowly.
