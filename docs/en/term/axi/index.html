What is AXI?

An on-chip bus from Arm's AMBA specifications that connects blocks in an SoC, with five independent channels and a VALID/READY handshake. Variants include AXI4-Lite and AXI4-Stream.

Japanese name: AXI

Channels and the handshake

The Advanced eXtensible Interface (AXI) splits each connection into five one-directional channels: read address, read data, write address, write data and write response. Every channel transfers information with the same VALID/READY handshake, completing a transfer on a clock edge where both signals are high. A sender must not wait for READY before asserting VALID, which avoids deadlock, while a receiver may hold READY low to apply backpressure. Because each channel is a simple handshake, pipeline register slices can be inserted on any of them to ease timing closure without changing behaviour.

Bursts and transactions

A single address handshake can start a burst of many data beats. The address channel carries the start address, burst length, beat size and burst type: fixed for a FIFO-like address, incrementing for ordinary memory blocks, or wrapping for cache-line fills that start at the critical word. In AXI4 an incrementing burst can be up to 256 beats, and a burst must not cross a 4 KB address boundary, so an interconnect never has to split one burst between two targets. Each read beat and each write burst returns a response code indicating success or an error.

IDs, outstanding requests and interconnects

Each transaction carries an ID. A manager can issue many requests before earlier ones complete, keeping the bus busy through long memory latency. Transactions with the same ID must complete in order, while different IDs may complete out of order, so a fast peripheral need not wait behind slow DRAM. In an SoC, an interconnect or crossbar decodes addresses, arbitrates between managers such as CPUs and DMA engines, and routes requests to subordinates such as memory controllers, often adding width, clock-domain and protocol converters.

AXI4-Lite, AXI4-Stream and APB

AXI4-Lite keeps the five channels but drops bursts and most transaction options, moving one data word per transaction; it suits control and status registers. AXI4-Stream has no addresses at all: a single TVALID/TREADY channel carries continuous data, with TLAST marking packet ends, and it suits video, signal-processing and network data paths. The Advanced Peripheral Bus (APB), another member of the Arm AMBA specifications, is simpler still and non-pipelined, typically used behind a bridge for slow peripherals. Coherent extensions of AXI add snooping for cache coherency.

What is a characteristic of the AXI bus?

  1. AIt has five independent channels (read address, read data, write address, write data and write response) that can operate simultaneously
  2. BIt sends addresses and data alternately on a single wire
  3. CReads and writes can never occur at the same time
Show answer and explanation

Answer: A. It has five independent channels (read address, read data, write address, write data and write response) that can operate simultaneously

AXI has five channels: read address (AR), read data (R), write address (AW), write data (W) and write response (B). Because they are independent, reads and writes can proceed at the same time, and addresses can be sent ahead of their data. Every channel uses the same VALID/READY handshake, giving a uniform design.

In the VALID/READY handshake used on each AXI channel, when is data transferred?

  1. AAt a clock edge when both the sender's VALID and the receiver's READY are 1
  2. BThe instant the sender sets VALID to 1, regardless of READY
  3. CThe instant the receiver sets READY to 1, regardless of VALID
Show answer and explanation

Answer: A. At a clock edge when both the sender's VALID and the receiver's READY are 1

The sender raises VALID when it has valid data, and the receiver raises READY when it can accept it; a transfer happens at a clock edge where both are 1. A busy receiver can hold READY low to make the sender wait (backpressure), so blocks of different speeds can connect without losing data. The rule that the sender must not wait for READY before asserting VALID prevents the two sides from waiting on each other forever.

FAQ

What is the difference between AXI4, AXI4-Lite and AXI4-Stream?

Full AXI4 supports bursts, IDs and multiple outstanding transactions for high-throughput memory traffic. AXI4-Lite handles one word per transaction for register access, and AXI4-Stream drops addresses entirely to carry continuous data flows.

Can VALID depend on READY in AXI?

No. A sender must assert VALID when it has data, without waiting for READY, otherwise both sides could wait forever. A receiver is allowed to wait for VALID before asserting READY.

What is the difference between AXI and APB?

AXI is a high-performance, pipelined interface with independent read and write channels and bursts. APB is a simple, low-speed bus for peripheral registers, usually connected to AXI through a bridge.
