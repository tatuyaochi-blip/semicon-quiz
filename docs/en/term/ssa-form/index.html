What is SSA form?

An IR form in which variables are renamed so each is assigned exactly once, with φ functions selecting values at join points. Clear definition-use relationships make optimization easier.

Japanese name: SSA形式

Field: Compilers

Renaming: one definition per name

SSA (static single assignment) form gives every assignment its own variable name. In straight-line code this is just renaming: x = 1; x = x + 2 becomes x1 = 1; x2 = x1 + 2, and each later use refers to whichever version reaches it. The word static matters: each name has exactly one assignment in the program text, even if that assignment executes many times in a loop. Because every use has exactly one definition, the definition-use relationships that optimizers need are explicit in the names themselves rather than computed by separate analysis.

φ functions at join points

Renaming alone fails where control flow merges, because the value of x after an if-else depends on which branch ran. SSA inserts a φ (phi) function at the start of the join block, x3 = φ(x1, x2), with one argument per incoming edge; it yields the argument for the edge actually taken. Loops need the same thing at the loop header, merging the initial value with the value from the previous iteration. Standard construction algorithms place φ functions only where definitions from different paths actually meet, using the control-flow graph's dominance information.

Why optimizers like SSA

With a single definition per name, many optimizations become simple and fast. Constant propagation just follows each definition to its uses; dead-code elimination removes definitions with no uses; global value numbering detects redundant computations by comparing operations on the same named values. Analyses can be sparse, working along definition-use edges instead of iterating over every program point. For these reasons the IRs of many production compilers, LLVM IR among them, are in SSA form, usually for scalar values held in virtual registers while memory is accessed through explicit loads and stores.

Leaving SSA

Processors have no φ instruction, so before or during register allocation the compiler converts out of SSA. Each φ is replaced by copy instructions at the end of the predecessor blocks, so every incoming path writes the chosen value into a common location. Edges that leave a block with several successors and enter one with several predecessors may need to be split to have a place for those copies. Register allocation then tries to coalesce the copies, assigning both sides the same register so that most of them disappear.

Answer: A. Each variable is assigned exactly once in the program

In SSA form, variables are renamed so each is assigned only once, and φ functions select values at join points. If x is assigned twice, for example, it is split into x1 and x2, making clear which one each use refers to. The clear definition-use relationships make optimizations such as constant propagation and dead-code elimination easier. Branches are handled with φ functions, so branch instructions do not disappear. Variables are not forced into memory; most are treated as register candidates.

FAQ

What does SSA stand for in compilers?

Static single assignment. Each variable in the IR is assigned in exactly one place in the program text, and φ functions merge values where control-flow paths join.

How can SSA work with loops if a variable can only be assigned once?

The single assignment is static, not dynamic. A φ function at the loop header merges the value entering the loop with the value computed in the previous iteration, and that one definition executes on every iteration.

Where are φ functions placed?

At the beginning of blocks where different definitions of the same original variable can arrive along different incoming edges. Algorithms based on dominance frontiers find these points without inserting unnecessary φs.
