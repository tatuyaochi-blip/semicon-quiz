What is Pointer authentication (PAC)?

A mechanism added in Armv8.3-A. A short authentication code (PAC) is computed from the pointer value and a context value with a key held inside the CPU, placed in the unused upper bits of the pointer, and checked with a dedicated instruction just before the pointer is used. On a mismatch the pointer is turned into an unusable address, which makes attacks that overwrite return addresses or function pointers harder. The length of the code depends on settings such as the virtual address width.

Japanese name: ポインタ認証(PAC)

  2. BA short authentication code is computed from the pointer value and a context value with a key inside the CPU, placed in the pointer's upper bits and checked before use
  3. CAll bits of the pointer are encrypted with a key inside the CPU before being stored in memory and decrypted inside the CPU before each use
Show answer and explanation

Answer: B. A short authentication code is computed from the pointer value and a context value with a key inside the CPU, placed in the pointer's upper bits and checked before use

In the upper bits of a 64-bit pointer that are not used for the virtual address, an authentication code computed with a key inside the CPU from the pointer value and a context value (for example the stack pointer) is inserted. Just before a function's return address or similar is used, a dedicated instruction recomputes and compares it and, on a mismatch, turns the pointer into an unusable address, which makes attacks that overwrite return addresses on the stack (such as ROP) harder. Software cannot read the key, so an attacker cannot produce an authentication code that matches a modified pointer. However, the length of the code depends on settings such as the virtual address width and is often a dozen or so bits or fewer, so where many guesses are possible, the probability of a chance match has to be considered.
