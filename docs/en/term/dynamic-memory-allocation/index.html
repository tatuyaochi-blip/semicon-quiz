What is Dynamic memory allocation?

Obtaining memory of the needed size while a program is running, and releasing it when it is no longer used. In C, malloc(size) allocates it and returns the address of its start, and free(address) releases it. calloc returns a zero-initialized region and realloc returns a resized one. On failure, NULL is returned, so the result must be checked. The region lies in the heap and survives function returns until it is released. On small microcontrollers it is often avoided because of fragmentation and allocation times that are hard to predict.

Japanese name: 動的メモリ確保

Try it: questions about Dynamic memory allocation

In C, which of the following correctly pairs the lifetimes of (1) a local variable declared inside a function without static, (2) a region allocated with malloc, and (3) a variable declared outside any function?

  1. A(1) until the program ends, (2) until the function that allocated it returns, (3) until the program ends
  2. B(1) until execution leaves the block where it is declared, (2) until it is released with free, (3) until the program ends
  3. C(1) until execution leaves the block where it is declared, (2) until the program ends (it cannot be released earlier), (3) until the function that first used it returns
Show answer and explanation

Answer: B. (1) until execution leaves the block where it is declared, (2) until it is released with free, (3) until the program ends

The automatic variable in (1) is generally placed on the stack; it is created on entry to the block where it is declared and disappears when execution leaves it. The region allocated with malloc in (2) is in the heap; it survives function returns and can be used until it is released with free. The variable outside any function in (3) (and any variable declared static) exists throughout the execution of the program and is placed in a static area such as .data or .bss. Using a pointer to a region whose lifetime has ended, and forgetting free so that regions keep piling up, are common causes of bugs.

Why does firmware on small microcontrollers often avoid dynamic memory allocation such as malloc?

  1. AMicrocontrollers cannot use any C functions
  2. BRAM is small, fragmentation can make allocations fail, and allocation time is hard to predict
  3. CDynamically allocated memory survives power-off
Show answer and explanation

Answer: B. RAM is small, fragmentation can make allocations fail, and allocation time is hard to predict

On a microcontroller with only a few KB to a few hundred KB of RAM, repeated allocation and release fragments free space, so a large allocation can fail even though the total is sufficient. In devices running for months, it may eventually fail. Allocation time is also not constant, which suits real-time work poorly. So designs often reserve all needed memory statically at the start.
