What is Write-through?

A write policy that writes to the level below (such as main memory) at the same time as the cache. The lower level stays up to date, but write traffic is heavy, so it is paired with a write buffer.

Japanese name: ライトスルー方式

Field: Memory Hierarchy

How a write-through cache handles a store

On a store hit, a write-through cache updates its own copy and also sends the write to the next level, such as an L2 cache or main memory. Lines are therefore never dirty: no dirty bit is needed, and an evicted line can simply be discarded because the level below already holds the same data. On a store miss, write-through caches usually use no-write-allocate, sending the write straight down without loading the line, since a later write-back is not needed anyway.

The write buffer

Waiting for every store to reach memory would stall the CPU constantly, so writes go into a write buffer that drains to the lower level in the background while the CPU continues. The CPU stalls only when the buffer fills, which happens if stores arrive faster than memory can absorb them. Loads that miss must check the buffer, or wait for it to drain, so they do not read stale data from memory. Buffers often merge several writes to the same line into one transfer.

Write-through vs. write-back

Write-back updates only the cache and writes a dirty line to memory once, when it is evicted, so repeated writes to the same line collapse into one transfer. That saves bandwidth and power, which is why most CPU L1 to L3 caches are write-back. Write-through generates traffic on every store but keeps the lower level always current, which simplifies coherence with other cores and with DMA, and makes recovery easy: an L1 that is write-through can protect its data with simple parity and refetch a clean copy on an error.

Where it is used

Write-through appears in small first-level caches backed by a write-back L2, in simple embedded processors, and in memory regions where the lower level must see every write promptly, which many architectures let the operating system select per page through memory-type attributes. It is less suited to the last cache level before DRAM, where store traffic would consume memory bandwidth that a write-back policy would save.

FAQ

What is the difference between write-through and write-back cache?

Write-through writes to the lower level on every store, keeping it always up to date. Write-back writes only the cache and updates the lower level once when the modified line is evicted, cutting traffic.

Why does a write-through cache need a write buffer?

Without one, the CPU would have to wait for every store to complete in slower memory. The buffer queues writes so the CPU can continue while they drain in the background.

Does a write-through cache need a dirty bit?

No. Since every write is propagated immediately, a line never differs from the lower level, so it can be evicted without writing anything back.
