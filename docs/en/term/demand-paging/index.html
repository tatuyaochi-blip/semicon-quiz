What is Demand paging?

Loading a program's pages into physical memory only when first accessed and a page fault occurs, rather than all at once. It speeds startup and saves memory for unused parts.

Japanese name: デマンドページング

What happens on a page fault

When a program starts, the OS sets up page tables describing its address space but marks most pages as not present. The first access to such a page makes the memory management unit (MMU) raise a page fault. The kernel checks that the address belongs to a valid region (if not, the program gets a segmentation fault), finds a free physical frame, fills it from the executable, a file or with zeros, updates the page-table entry and re-executes the faulting instruction, which now succeeds.

Minor and major faults

If the needed data is already in memory, for example in the OS file cache or as a shared library page another process loaded, the kernel only has to map it: a minor fault costing roughly a microsecond. A major fault must read from storage and costs far more, from tens of microseconds on fast flash to milliseconds on a hard disk. Kernels reduce major faults by reading ahead neighboring pages of a file when sequential access is detected.

Demand paging vs. loading everything

Loading a whole program at startup wastes time and memory on code paths and data that are never used, such as error handlers or optional features. Demand paging loads only what is touched, so programs start quickly and more processes fit in memory. The downside is unpredictable latency on first touch, which is why real-time systems often lock or pre-touch their pages. If the active working sets exceed physical memory, the system thrashes, spending most of its time paging.

Related techniques

Memory-mapped files use the same machinery: mmap only records the mapping, and the first read of each page faults the file data in. Copy-on-write lets a newly created process share its parent's pages until one side writes, at which point a fault creates a private copy. Large memory allocations often receive physical pages only when first touched, so allocating memory and actually using it are different events.

Answer: C. A page fault occurs on a page's first use, and the page is loaded into physical memory then

Under demand paging, starting a program only sets up page tables without loading actual pages. The first access to a page causes a page fault, and the OS loads just that page from disk. Startup is faster and no memory is spent on code or data that is never used. It is the opposite of loading everything up front and has nothing to do with pinning pages in the cache.

FAQ

What is the difference between demand paging and swapping?

Demand paging brings individual pages into memory when they are first used. Swapping, in its original sense, moves whole processes between memory and disk; modern systems page individual pages out and in instead.

Is a page fault an error?

Usually not. Under demand paging a page fault is the normal way a page gets loaded; only an access to an address outside any valid region is turned into an error such as a segmentation fault.

Why does demand paging make programs start faster?

The OS only builds page tables at startup and loads pages as they are touched, so parts of the program that are never used are never read from storage.
