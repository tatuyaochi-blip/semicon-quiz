What is Environment variable?

One of the "name=value" pairs held by a process, used to configure a program's behavior from outside. When a process is started, a copy of the parent's environment variables is inherited by the child. In the shell, only variables exported, as in export X=1, become environment variables and are passed to child processes; a variable that is only assigned is used only inside that shell. Besides PATH (directories searched for commands), HOME (the home directory) and LD_LIBRARY_PATH (where shared libraries are searched), they are also used, for example, to specify the license server of EDA tools. env or printenv lists them.

An executable script run.sh in the current directory gives "command not found" when run by typing "run.sh", but runs when typed as "./run.sh". Which of the following is the reason?

  1. Arun.sh has no execute permission, and only when ./ is put in front can it be run without permission
  2. BA command name without a slash is searched for only in the directories of the PATH environment variable, which generally does not include the current directory
  3. CThe #!/bin/bash on the first line of run.sh (the shebang) is read only when it is run with ./ in front
Show answer and explanation

Answer: B. A command name without a slash is searched for only in the directories of the PATH environment variable, which generally does not include the current directory

When the shell receives a command name without a slash, it searches in order through the directories listed, separated by colons, in the PATH environment variable (/usr/local/bin:/usr/bin and so on) and runs what it finds. The current directory is generally not put in PATH, so that a malicious program with the same name placed elsewhere is not run by mistake. Writing a path containing a slash, such as ./run.sh, runs that file directly without searching PATH. The #!/bin/bash on the first line (the shebang) specifies the interpreter that runs the script, whichever way it is started.

The line "30 2 * * 1 /home/alice/backup.sh" was registered in cron. Which of the following is when backup.sh is run?

  1. AAt 2:30 on the 1st of every month
  2. BAt 2:30 every Monday
  3. CAt 2:30 every Sunday
Show answer and explanation

Answer: B. At 2:30 every Monday

In a cron configuration (crontab), each line starts with five fields that are, from the left, "minute, hour, day of month, month, day of week", followed by the command to run. In this line the minute is 30, the hour 2, the day of month and month * (every), and the day of week 1, so it runs at 2:30 every Monday. For the day of week, 0 is Sunday and 1 is Monday, and in many implementations 7 also means Sunday. Commands run from cron work with a limited set of environment variables, unlike a login session, so care is needed, such as writing commands in scripts with absolute paths.
