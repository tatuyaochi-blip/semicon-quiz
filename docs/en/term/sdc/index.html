What is SDC?

A format for timing constraints that describes clock periods and waveforms, input and output delays, timing exceptions and so on. Written as Tcl commands, it is shared by logic synthesis, place-and-route and STA tools.

Field: Timing analysis and CDC

What an SDC file contains

SDC (Synopsys Design Constraints) is a Tcl-based format that originated at Synopsys and is now read by most synthesis, place-and-route and static timing analysis tools. Typical commands define clocks (create_clock with period and waveform), derived clocks (create_generated_clock), external timing at the ports (set_input_delay, set_output_delay), the electrical environment (set_load, set_driving_cell), clock quality (set_clock_uncertainty, set_clock_latency) and timing exceptions (set_false_path, set_multicycle_path, set_max_delay, set_clock_groups).

Clock uncertainty and generated clocks

set_clock_uncertainty subtracts margin for jitter and, before clock-tree synthesis (CTS), for expected skew: with a 1 ns period and 50 ps of uncertainty, data must arrive within 0.95 ns. After CTS the tool computes the real skew from the built tree, so the uncertainty is reduced to jitter plus any deliberate margin. A divided clock must be declared with create_generated_clock relative to its source, for example divide-by-2 turning 500 MHz into 250 MHz, so the flip-flops it drives are analyzed with the correct period and phase relationship.

Why constraints are a sign-off risk

Tools optimize and verify only what the constraints describe. A missing clock leaves flip-flops unanalyzed, an over-broad false path silences real violations, and declaring synchronous clocks asynchronous drops paths that must be checked. Such a design can pass every tool report and still fail in silicon. Constraints are therefore reviewed as carefully as RTL, checked with constraint-linting tools for unclocked registers and unconstrained ports, and kept consistent between synthesis, implementation and sign-off.

SDC vs. related formats

SDC states requirements, not results. Calculated delays are exchanged in SDF (Standard Delay Format) for back-annotated gate-level simulation, and extracted parasitics in SPEF (Standard Parasitic Exchange Format). FPGA tools use SDC or close derivatives that add physical constraints such as pin assignments. Because SDC is Tcl, variables and loops can generate constraints compactly, though heavily scripted files become harder to review.

  1. AClock uncertainty
  2. BDose
  3. CAspect ratio
Show answer and explanation

Answer: A. Clock uncertainty

Clock uncertainty is a setting that subtracts margin in timing analysis for clock jitter and, before place-and-route, expected skew. With a 1 ns period and 50 ps of uncertainty, the usable time is 0.95 ns, and data must arrive by that time minus the setup time of the capturing flip-flop. The value is adjusted by design stage; after CTS, skew is calculated from the actual clock tree and only the jitter allowance remains. Dose and aspect ratio are manufacturing terms.

  2. BDefine the divider output as a generated clock, specifying its relationship to the source clock (divide-by-2)
  3. CDefine the divided clock as a new asynchronous clock unrelated to the source clock
Show answer and explanation

Answer: B. Define the divider output as a generated clock, specifying its relationship to the source clock (divide-by-2)

SDC is the timing constraint description that tells the tool the clock periods and waveforms, input/output delays, exception paths and so on. If nothing is defined, the divider output is not treated as a clock and the flip-flops beyond it are not analyzed correctly. Defined as a generated clock, it is analyzed as 250 MHz when the source clock is 500 MHz, including its phase relationship to the source clock. The two are synchronous, so treating them as asynchronous drops paths that should be checked from the analysis.

FAQ

What does SDC stand for in VLSI?

Synopsys Design Constraints, a Tcl-based format for timing constraints such as clocks, input and output delays and timing exceptions, shared by synthesis, place-and-route and STA tools.

What is the difference between SDC and SDF?

SDC describes the timing requirements the design must meet, while SDF carries calculated cell and interconnect delays, mainly for back-annotated gate-level simulation.

When do I need create_generated_clock?

Whenever a clock is derived inside the design, for example by a divider or clock multiplexer. Without it, the derived net is not treated as a clock and the logic it drives is not timed correctly.
