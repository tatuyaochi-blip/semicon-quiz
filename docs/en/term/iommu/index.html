What is IOMMU?

A unit that translates and protects the addresses peripherals use for DMA. It keeps devices from writing to unauthorized memory and is also used when assigning devices to virtual machines.

Japanese name: IOMMU

Field: OS & Hardware

How an IOMMU translates DMA

With an IOMMU (input-output memory management unit), a device no longer issues raw physical addresses. Its DMA requests carry I/O virtual addresses, and the IOMMU looks them up in page tables that the OS has set up for that device or group of devices, identified on PCIe by the requester's bus, device and function numbers. Recent translations are cached in an IOTLB (I/O translation lookaside buffer). An access to an address with no valid mapping, or with the wrong read/write permission, is blocked and reported to the OS as a fault instead of reaching memory.

IOMMU vs. MMU

Both translate addresses through page tables, but they serve different masters. The CPU's MMU translates virtual addresses for each process so that programs are isolated from one another. The IOMMU translates addresses for each device, so that DMA engines are confined to the buffers their driver mapped. Because the mappings are independent, the OS can hand a device a buffer that is scattered across many physical pages but appears contiguous in the device's address space, which simplifies devices that cannot do scatter-gather transfers themselves.

Blocking DMA attacks

DMA bypasses the CPU and its memory protection, so without an IOMMU any device that can master the bus can read keys or patch kernel code. This is a practical risk with external ports that expose PCIe-style DMA to plugged-in hardware. With the IOMMU enabled, the OS maps only the specific buffers each driver uses, typically for the duration of each transfer, and everything else is unreachable from that device. Many platforms also use the IOMMU to remap device interrupts so that a device cannot forge arbitrary interrupt messages.

Device assignment to virtual machines

A guest OS programs a device with what it believes are physical addresses, but they are really guest-physical addresses. When a hypervisor passes a real device such as a GPU or network card straight through to a virtual machine, it configures the IOMMU to translate those guest-physical addresses to the host-physical pages backing that VM. The device can then use DMA at full speed without the hypervisor intercepting each transfer, while remaining unable to touch other VMs' memory. The price is some translation overhead, mainly IOTLB misses and the cost of mapping and unmapping buffers.

Answer: C. Translating device DMA addresses and blocking illegal access

Devices using DMA can read and write main memory directly, so a malfunctioning or malicious device could overwrite OS memory. Like an MMU for the CPU, an IOMMU translates device addresses into physical addresses and blocks access outside permitted ranges. It can also present scattered physical memory as contiguous to a device and is used when assigning devices directly to virtual machines. It neither translates instructions nor controls power.

FAQ

Do I need an IOMMU for GPU passthrough?

Yes. Passing a physical device to a virtual machine relies on the IOMMU to translate the guest's DMA addresses and to keep the device from reaching memory outside that VM, so it must be supported and enabled in firmware and the OS.

Does enabling the IOMMU slow down I/O?

It adds some cost for translation misses and for creating and removing mappings, which can matter for very high-rate devices. Caching in the IOTLB and longer-lived mappings keep the overhead modest in most workloads.

What is the difference between an IOMMU and an MMU?

The MMU translates addresses issued by the CPU on behalf of processes, while the IOMMU translates addresses issued by devices doing DMA. Both use page tables and permission bits, but the IOMMU's tables are per device or device group.
