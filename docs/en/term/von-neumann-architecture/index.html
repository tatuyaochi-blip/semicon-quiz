What is Von Neumann architecture?

A computer organization that keeps programs and data in the same main memory and fetches and executes instructions in sequence.

Japanese name: ノイマン型アーキテクチャ

Field: CPUs and architecture

The stored-program concept

The von Neumann architecture is a computer organization that keeps programs (instructions) and data in the same main memory, with the CPU repeatedly fetching, decoding and executing instructions one at a time. It is named after John von Neumann because a 1945 report he wrote on the design of the EDVAC made the approach widely known, though other developers, including Eckert and Mauchly, also contributed to the stored-program concept. Since programs can be written into memory just like data, a machine can switch to a different task without rewiring, and an operating system can load and run programs.

Components and instruction execution

A von Neumann computer consists of an arithmetic unit that performs calculations, a control unit that directs overall operation, a memory that holds instructions and data, and input/output devices. The control unit reads an instruction from the address held by the program counter (fetch), interprets it (decode), executes it in the arithmetic unit, and writes the result to a register or memory. The program counter normally advances to the next instruction's address and is overwritten with a different address for a branch. This cycle is the basic operation of a von Neumann machine, and CPUs that use pipelining or out-of-order execution are still built so that the results, as seen by the program, follow this order.

The von Neumann bottleneck

Because instructions and data share the same memory and the same path, the speed of transfers to and from memory caps performance no matter how fast the CPU is. This is called the von Neumann bottleneck. Since memory speed has not kept pace with gains in CPU speed, the problem has grown. The standard remedy is a memory hierarchy that places small, fast caches near the CPU to keep frequently used instructions and data close at hand. In workloads that read and write huge amounts of data, such as AI computation, the energy spent moving data is also a concern, and research on in-memory and near-memory computing, which computes inside or next to memory, is advancing.

Versus the Harvard architecture

The Harvard architecture separates instruction memory from data memory and connects them through separate paths. Because instruction fetches and data accesses can happen at the same time, it has a bandwidth advantage, and many DSPs and small microcontrollers such as AVR and PIC use it. It is less flexible than the von Neumann design, however, since programs are harder to read and write as data. Most of today's high-performance CPUs use what is called a modified Harvard architecture: main memory is shared by instructions and data as in von Neumann, while the L1 cache is split into instruction and data caches that can be accessed simultaneously.

FAQ

What is the difference between the von Neumann and Harvard architectures?

A von Neumann machine keeps instructions and data in the same memory and accesses them over the same path, while a Harvard machine gives instructions and data separate memories and paths. Harvard allows simultaneous access to instructions and data and is faster; von Neumann is simpler and more flexible. Most CPUs use a modified Harvard design in which only the L1 cache is split.

What is the von Neumann bottleneck?

It is the problem that, because instructions and data compete for the same memory and path, the speed of transfers between CPU and memory limits overall performance. It is eased by memory hierarchies such as caches.

Why is it called the von Neumann architecture?

Because the approach became widely known through a 1945 report on the design of the EDVAC by the mathematician John von Neumann. Other developers, including Eckert and Mauchly, also contributed to the stored-program concept.
