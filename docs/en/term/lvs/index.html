What is LVS?

Short for layout versus schematic: checking that the connectivity extracted from the layout matches the schematic or netlist. It is always run before tape-out, along with DRC.

Japanese name: LVS

Field: IC design flow and EDA

How LVS works

Layout versus schematic (LVS) checks that the drawn layout implements exactly the intended circuit. The tool first extracts devices from the layout polygons: overlapping polysilicon and diffusion form a transistor, specific marker layers identify resistors and capacitors, and contacts and vias connect metal shapes into nets. This produces a layout netlist. It is then compared with the reference netlist from the schematic or from place and route, essentially a graph-matching problem. Besides connectivity, LVS also compares device parameters such as transistor width and length and resistor values against the reference.

Typical errors LVS finds

The most common LVS errors are shorts, where two nets that should be separate touch, and opens, where a net is broken. A short between supply nets is especially serious. Other reports include missing or extra devices, swapped pins, transistors with wrong dimensions, and pin labels that are misplaced or misspelled, which make nets appear unconnected even if the geometry is correct. Debugging is often harder than the check itself, because a single short merges two large nets and the tool must help locate the exact polygon where they meet.

LVS vs. DRC vs. ERC

Three checks are usually run together at sign-off. Design rule checking (DRC) looks only at geometry: minimum width, spacing, enclosure, density and similar manufacturing rules, which number in the thousands in advanced processes. LVS looks at connectivity and device identity. Electrical rule checking (ERC) looks for electrically suspicious connections, such as floating inputs, outputs driven by multiple sources, shorts between different supplies and unconnected wells. A layout can be DRC-clean but fail LVS, and vice versa, so all must pass before mask data is released.

Where LVS fits in sign-off

The LVS rule deck comes from the foundry's process design kit (PDK), and the same device-recognition rules underpin parasitic extraction, so a clean LVS is also a prerequisite for accurate post-layout simulation and timing. In digital flows, LVS compares the routed layout with the gate-level netlist, with standard cells treated as verified building blocks. Sign-off additionally includes static timing analysis and power-grid checks such as IR drop and electromigration. Only when all of these pass is the layout released as GDSII or OASIS data for mask making, the step called tape-out.

Answer: B. Verifying that the layout satisfies manufacturing rules such as minimum width and spacing

DRC checks whether layout shapes violate design rules derived from manufacturing, such as minimum width, spacing, overlap and density. Advanced processes have thousands of rules, verified automatically by tools. Checking that layout connectivity matches the schematic is LVS (layout versus schematic), and checking logic function is simulation. DRC and LVS are always run before mask data is released.

  1. APDK (process design kit)
  2. BIP core
  3. CHDL

Answer: A. PDK (process design kit)

A PDK contains a process's design rules, SPICE models for transistors and other devices, rule decks for DRC and LVS, parasitic extraction data, and layouts of basic devices. Using it, designers create circuits that the foundry can manufacture. Standard-cell libraries are sometimes supplied separately. An IP core is a circuit block and an HDL is a description language.

FAQ

What does LVS stand for?

LVS stands for layout versus schematic, a verification step that confirms the devices and connections extracted from a chip layout match the intended schematic or netlist.

What is the difference between DRC and LVS?

DRC checks whether layout shapes obey the foundry's geometric manufacturing rules, while LVS checks whether the layout's devices and connectivity match the circuit netlist. Both must pass before tape-out.

What causes an LVS short error?

An LVS short means two nets that should be separate are electrically connected in the layout, typically through overlapping metal, a misplaced via or contact, or an incorrect label that merges net names.
