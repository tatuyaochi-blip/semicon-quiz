What is Anti-rollback protection?

A mechanism recording a minimum version number in unchangeable storage so software cannot be reverted to older vulnerable versions.

Japanese name: ロールバック防止

Try it: questions about Anti-rollback protection

In devices with secure boot, why is an anti-rollback mechanism needed?

  1. ANew software versions have no signature
  2. BOlder versions take longer to boot
  3. COlder vulnerable software versions also carry valid signatures, so reverting to them enables attacks
Show answer and explanation

Answer: C. Older vulnerable software versions also carry valid signatures, so reverting to them enables attacks

The vendor has signed older releases legitimately too, so signature checks alone would still boot an old version reinstalled after a vulnerability was found. Software therefore carries a version number, and the chip records in write-once storage such as eFuses a minimum version below which it refuses to boot. Advancing this number with each update prevents rollback to old versions.

In a device that updates firmware using two areas, side A and side B, when is the most appropriate time to advance the minimum version number recorded in eFuses for anti-rollback to the new version number?

  1. AAdvance the minimum version number to the new version number immediately, as soon as the download of the new firmware begins
  2. BAdvance it after the new firmware's signature has been verified and it has been confirmed to boot and run normally from its side
  3. CKeep the minimum version number written at manufacturing and never advance it, even when the firmware is updated
Show answer and explanation

Answer: B. Advance it after the new firmware's signature has been verified and it has been confirmed to boot and run normally from its side

If the number is advanced first and the new firmware turns out to be corrupted or fails to boot, the old version remaining on the original side is also rejected as "older than the minimum version", and the device can no longer boot. So the new version is written to the free side, its signature is verified, and only after it has been confirmed to boot and run normally from that side (commit) is the minimum version number advanced. After that, the device is protected from being rolled back to an old vulnerable version. Conversely, if the number is never advanced, attacks that write back an old, correctly signed version cannot be prevented.
