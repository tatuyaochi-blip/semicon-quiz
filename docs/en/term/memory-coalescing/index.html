What is Memory coalescing?

Combining accesses into a few memory transactions when adjacent threads in a warp access adjacent addresses.

Japanese name: メモリコアレッシング

Memory coalescing appears in 2 practice questions across 1 topics, including GPU Programming.

Field: GPU Programming

Try it: questions about Memory coalescing

Which describes memory coalescing on a GPU?

  1. ACombining two GPUs' memories into one to double capacity
  2. BCompressing memory data to increase capacity
  3. CWhen adjacent threads in a warp read adjacent addresses, the reads are combined into a few memory accesses
Show answer and explanation

Answer: C. When adjacent threads in a warp read adjacent addresses, the reads are combined into a few memory accesses

GPU memory is read and written in chunks such as 32 or 128 bytes. If the 32 threads of a warp each read 4 consecutive bytes, the 128 bytes together are fetched in one or a few accesses. With scattered addresses, each thread needs a separate chunk and unused data is carried along, cutting effective bandwidth to a fraction.

When processing particle data with positions x, y and z on a GPU, which layout is better for memory coalescing?

  1. AAn array of structures with x, y and z per particle
  2. BArrange all values in random order
  3. CSeparate arrays for x, y and z (a structure of arrays rather than an array of structures)
Show answer and explanation

Answer: C. Separate arrays for x, y and z (a structure of arrays rather than an array of structures)

In an array of structures (AoS), the layout is x, y, z of particle 0, then x, y, z of particle 1 and so on, so when each thread reads x the addresses are 12 bytes apart. In a structure of arrays (SoA), all x values are contiguous, so adjacent threads read adjacent x values and the accesses coalesce. SoA is often better for CPU SIMD for the same reason.
