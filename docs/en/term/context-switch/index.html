What is Context switch?

Switching the process or thread running on a CPU. Registers, the program counter and other state are saved and restored, and switching processes also switches address spaces.

Japanese name: コンテキストスイッチ

Context switch appears in 4 practice questions across 2 topics, including OS & Hardware, Multicore & Synchronization.

Field: OS & Hardware

What is saved and restored

The kernel saves the outgoing thread's CPU state, meaning its general-purpose registers, program counter, stack pointer and status bits such as the previous mode, and later reloads it so the thread resumes exactly where it stopped. Floating-point and vector registers are part of the state too, and some kernels save them lazily only when the next thread actually uses them. When the switch is between processes, the register pointing to the page table is also changed, giving the new process its own address space. Memory contents and open files stay in place and are not copied.

When switches happen

A switch is triggered when the running thread blocks, for example waiting for disk I/O or a lock, when it voluntarily yields, or when a timer interrupt tells the scheduler its time slice has expired and another thread should run. In each case the CPU is already in the kernel, handling a system call or interrupt, and the scheduler picks the next thread. Switching between threads of the same process is cheaper because the address space does not change.

Direct and indirect cost

Saving and loading registers takes little time; the whole kernel path, including scheduling, typically costs on the order of microseconds. The larger cost is often indirect: the new process finds caches and the TLB filled with the previous process's data and translations, so it misses repeatedly until they warm up. CPUs that tag TLB entries with an address-space identifier (ASID) avoid flushing the TLB on each switch, but cache warm-up remains. Frequent switching therefore lowers throughput more than the switch time alone suggests.

Context switch vs. mode switch

A system call or interrupt moves the CPU from user mode to privileged mode and back, but the same process continues afterward; that is a mode switch, not a context switch. A context switch changes which thread or process owns the CPU. The two often happen together, since a switch always takes place inside the kernel, but a system call that returns to its caller involves no context switch at all.

During a context switch, what must be saved for the process being switched out?

  2. BCPU execution state such as register values and the program counter
  3. CThe entire contents of the process's physical memory

Answer: B. CPU execution state such as register values and the program counter

A context switch saves CPU state, such as general registers, the program counter, the stack pointer and the operating mode, so the process can later resume exactly where it left off, and loads the state of the next process. When switching processes, the register pointing to the page table is also switched. Memory and file contents remain in place, so they need not be saved on each switch.

Why can a process context switch degrade performance more than the time spent saving and restoring registers would suggest?

  1. AThe CPU clock frequency drops on every switch
  2. BThe program is reloaded from disk on every switch
  3. CCache and TLB misses rise after the switch
Show answer and explanation

Answer: C. Cache and TLB misses rise after the switch

Saving and restoring registers is quick, but after the switch the caches and TLB hold the previous process's contents, so the new process misses until its data and translations are reloaded. On CPUs without ASIDs, the TLB must also be flushed when changing address spaces. This indirect cost can exceed the direct switching time. The clock does not slow down, and programs are not reloaded from disk.

FAQ

What is saved during a context switch?

The CPU state of the outgoing thread: registers, program counter, stack pointer and status information, plus the page-table pointer when switching processes. Memory itself is not saved because it stays in place.

Why are context switches expensive?

Beyond the kernel work itself, the incoming process starts with caches and the TLB holding another process's contents, so it suffers many misses until they are refilled.

Is a system call a context switch?

No. A system call is a mode switch within the same process; a context switch occurs only if the kernel decides to run a different thread or process before returning.
