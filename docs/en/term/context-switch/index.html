What is Context switch?

Switching the process or thread running on a CPU. Registers, the program counter and other state are saved and restored, and switching processes also switches address spaces.

Japanese name: コンテキストスイッチ

Try it: questions about Context switch

During a context switch, what must be saved for the process being switched out?

  1. AThe contents of the disk files the process is using
  2. BCPU execution state such as register values and the program counter
  3. CThe entire contents of the process's physical memory
Show answer and explanation

Answer: B. CPU execution state such as register values and the program counter

A context switch saves CPU state, such as general registers, the program counter, the stack pointer and the operating mode, so the process can later resume exactly where it left off, and loads the state of the next process. When switching processes, the register pointing to the page table is also switched. Memory and file contents remain in place, so they need not be saved on each switch.

Why can a process context switch degrade performance more than the time spent saving and restoring registers would suggest?

  1. AThe CPU clock frequency drops on every switch
  2. BThe program is reloaded from disk on every switch
  3. CCache and TLB misses rise after the switch
Show answer and explanation

Answer: C. Cache and TLB misses rise after the switch

Saving and restoring registers is quick, but after the switch the caches and TLB hold the previous process's contents, so the new process misses until its data and translations are reloaded. On CPUs without ASIDs, the TLB must also be flushed when changing address spaces. This indirect cost can exceed the direct switching time. The clock does not slow down, and programs are not reloaded from disk.
