What is Superscalar?

A processor design that issues and executes several instructions per clock cycle. It has multiple execution units and processes independent instructions in parallel.

Japanese name: スーパースカラ

Superscalar appears in 4 practice questions across 2 topics, including CPUs and architecture, ISA & Assembly.

Field: CPUs and architecture

How a superscalar core works

A superscalar processor fetches and decodes several instructions per clock, checks which of them depend on one another, and dispatches the independent ones to multiple execution units such as integer ALUs, load/store units, floating-point units and branch units. Its throughput can therefore exceed one instruction per clock, meaning instructions per clock (IPC) above 1 or clocks per instruction (CPI) below 1. A 2 GHz core averaging a CPI of 0.5 executes 4 billion instructions per second. Recent high-performance cores are roughly 6 to 10 instructions wide.

Superscalar vs. pipelining and VLIW

Pipelining overlaps the stages of successive instructions and at best completes one per clock; a superscalar core effectively runs several pipelines side by side. Very long instruction word (VLIW) machines also execute several operations per cycle, but the compiler finds the parallelism and packs it into each instruction, whereas a superscalar core finds it in hardware at run time, so existing binaries benefit without recompilation. Superscalar issue can be in-order or, in most high-performance cores, combined with out-of-order execution and register renaming.

Why width cannot grow forever

Real programs offer limited instruction-level parallelism: data dependencies, branches and cache misses stall issue slots, so branch prediction, out-of-order windows and large caches are needed to keep wide machines busy. The hardware cost also rises steeply. Dependency checks and result-forwarding paths among simultaneously issued instructions grow roughly with the square of the width, and register files need more ports. Beyond a point, each extra slot adds little IPC for considerable area, power and timing difficulty.

The front end matters

Issuing many instructions per cycle requires decoding many per cycle. Fixed-length instruction sets make this easy because instruction boundaries are known in advance. Variable-length sets such as x86 must first find the boundaries, then split complex instructions into simpler micro-operations; many cores keep a micro-op cache so frequently executed code can skip decoding. Superscalar execution is also distinct from multicore and SIMD, which exploit parallelism across threads and across data elements rather than among neighboring instructions.

Approximately how many instructions per second can a processor with a 2 GHz clock and an average CPI (clocks per instruction) of 0.5 execute?

  1. A1 billion instructions
  2. B4 billion instructions
  3. C100 million instructions
Show answer and explanation

Answer: B. 4 billion instructions

There are 2×10⁹ clocks per second and each instruction averages 0.5 clocks, so 2×10⁹ ÷ 0.5 = 4×10⁹—4 billion instructions. CPI below 1 reflects superscalar execution of multiple instructions per clock. Performance is execution time = instruction count × CPI ÷ frequency, so no single one of the three factors suffices for comparison.

FAQ

What is the difference between superscalar and pipelined processors?

A pipelined processor overlaps the stages of consecutive instructions and completes at most about one per clock. A superscalar processor has multiple pipelines and execution units, so it can issue and complete several instructions per clock.

What is IPC in a CPU?

IPC means instructions per clock, the average number of instructions completed per cycle and the inverse of CPI. Performance is proportional to IPC times clock frequency for a given instruction count.

Is superscalar the same as multicore?

No. Superscalar execution runs several instructions from one thread in parallel inside a single core, while multicore puts several cores on a chip to run separate threads.
