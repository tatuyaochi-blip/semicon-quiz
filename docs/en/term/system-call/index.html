What is System call?

The mechanism by which applications ask the OS for services such as file I/O or memory allocation. A dedicated instruction raises an exception that switches to privileged mode and invokes the kernel.

A system call step by step

On RISC-V Linux, a program places the system call number in register a7 and its arguments in a0 onward, then executes ecall. The instruction deliberately raises an exception: the CPU records the address of the ecall, switches to supervisor mode and jumps to the kernel's trap entry. The kernel saves user registers, looks up the handler by number, checks the arguments, does the work and puts the result in a0. It then advances the saved address past the ecall and returns to user mode with sret. Other architectures use instructions such as syscall on x86-64 and svc on Arm.

System call vs. library function

Programs usually reach system calls through library wrappers, so the boundary is easy to miss. A function such as printf runs entirely in user space, formatting text into a buffer, and only occasionally calls the write system call to pass that buffer to the kernel. Many library functions, such as string handling or math routines, never enter the kernel at all. A system call is defined by the switch into privileged mode, not by how the function is named.

Why system calls cost time

Each call pays a fixed overhead: the mode switch, saving and restoring registers, argument validation and the return. Entering the kernel also disturbs caches and the TLB, and countermeasures for speculative-execution attacks, such as kernel page-table isolation (KPTI), add a page-table switch on every entry. Writing one byte per call therefore runs far slower than buffering several kilobytes in user space and writing them in one call.

Ways to avoid calls

Besides buffering, programs can map a file into memory with mmap, after which reads are ordinary loads served by page faults on first touch rather than a call per read. Interfaces that submit several operations in one call reduce crossings further. Some operating systems also map read-only kernel data, such as the current time, into user space so frequent queries need no trap at all.

  3. CBuffering lets the data be kept without ever being written to the disk

Answer: B. Fewer calls cut the fixed per-call overhead

Every system call requires switching from user to privileged mode, saving registers, checking arguments and returning, a fixed cost paid even for a single byte. Entering the kernel also disturbs cache and TLB contents. Buffering and writing several kilobytes at a time drastically cuts the number of system calls and speeds up the whole process. The total data written is unchanged, and it still ends up on disk.

A task took 10 seconds before mitigations for speculative execution were applied and made 5 million system calls during that time. Assume that the mitigations increase the processing time per system call from 0.4 µs to 0.6 µs and leave the time of everything else unchanged. By what proportion does the total time of the task increase?

  1. Aabout 10%
  2. Babout 30%
  3. Cabout 50%
Show answer and explanation

Answer: A. about 10%

The time spent in system calls is 5 million × 0.4 µs = 2 s before the mitigations and 5 million × 0.6 µs = 3 s after. The increase is 1 s, so the total goes from 10 s to 11 s, an increase of 1 ÷ 10 = 10%. Even though each system call becomes 1.5 times slower (50% more), the effect on the whole is determined by the share of time that part takes (20% here). For this reason, with mitigations such as KPTI, the performance loss is larger for databases and I/O-heavy processing that make many system calls and interrupts.

FAQ

What is the difference between a system call and an interrupt?

A system call is a synchronous trap the program triggers on purpose with a dedicated instruction. An interrupt is an asynchronous signal from hardware, such as a timer or device, that arrives regardless of what the program is doing.

Is printf a system call?

No. printf is a C library function that formats output in user space; it eventually calls the write system call to hand the buffered data to the kernel.

Why are system calls slow?

Each one switches into privileged mode, saves state, validates arguments and returns, and it disturbs caches and the TLB. The cost is fixed per call, so many tiny calls add up.
