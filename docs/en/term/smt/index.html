What is SMT (simultaneous multithreading)?

A technique in which one CPU core processes instructions from several threads at once, making better use of its execution units. Intel calls it Hyper-Threading.

Japanese name: SMT(同時マルチスレッディング)

How SMT shares one core

A modern out-of-order core can issue several instructions per cycle, but a single thread rarely keeps all its execution units busy because of dependencies, branch mispredictions and cache misses. Simultaneous multithreading (SMT) gives the core a separate architectural state, such as program counter and architectural registers, for each hardware thread, while the threads share execution units, caches, branch predictors and internal buffers. In the same cycle, instructions from different threads can be issued to different units. The operating system sees each hardware thread as a logical processor, typically two per core.

How much speedup to expect

Because the threads compete for the same execution resources, SMT does not double performance the way a second core can. Typical gains range from about 0 to 30 percent. Workloads that stall often, such as those waiting on memory, benefit most: while one thread waits for a cache miss, the other keeps the units busy. Workloads that already saturate the floating-point units or memory bandwidth gain little, and contention in shared caches can even make individual threads slower, which matters for latency-sensitive applications.

SMT versus other kinds of multithreading

Coarse-grained multithreading switches to another thread only on a long stall such as a cache miss. Fine-grained multithreading interleaves threads cycle by cycle but issues from only one thread per cycle, an approach common in GPUs and some network processors. SMT goes further by issuing from multiple threads in the same cycle, which suits wide superscalar cores. Multicore, by contrast, duplicates the entire core. Intel brands its two-way SMT as Hyper-Threading, and some server processors support four or eight threads per core.

Security and scheduling concerns

Two SMT threads share the L1 caches, branch predictor, execution ports and buffers at very fine granularity, so one thread can infer what the other is doing by measuring its own timing. Several side-channel vulnerabilities depend on exactly this arrangement. Systems that run untrusted code from different customers on the same hardware therefore may disable SMT or use core scheduling, which only places threads from the same trust domain on sibling logical processors. Both reduce throughput, so the decision weighs performance against isolation.

Answer: A. Two threads on the same core share the L1 cache, execution units and more, so one thread can closely observe the other's activity

With SMT, two threads run simultaneously in one core, finely sharing the L1 cache, branch predictor, execution units, buffers and more. One thread can therefore observe the resources the other uses through timing measurements, and several vulnerabilities required exactly this condition. To avoid sharing a core with untrusted parties, SMT is turned off or only threads of the same tenant are scheduled on the same core.

FAQ

Is Hyper-Threading the same as SMT?

Yes. Hyper-Threading is Intel's brand name for its implementation of simultaneous multithreading, in which each physical core appears to the operating system as two logical processors.

Does SMT double CPU performance?

No. The two threads share one core's execution units and caches, so typical throughput gains are about 0 to 30 percent depending on the workload, far less than adding a second core.

Why do some systems disable SMT?

Threads on the same core share caches and execution resources closely enough for one to observe the other through timing side channels. Disabling SMT, or scheduling only mutually trusted threads together, removes that exposure at some cost in throughput.
