What is Remote attestation?

A mechanism in which a device signs the state of its running software with an on-chip key and presents it to a remote server for trust verification.

Japanese name: リモートアテステーション

Remote attestation appears in 2 practice questions across 1 topic, including Hardware Security.

Field: Hardware Security

What it proves

Remote attestation lets a device across a network show a remote server, in a trustworthy way, what software it booted on what hardware. Software inside the device simply answering 'I am fine' proves nothing, since compromised software can give the same answer. Instead, the device sends the measurements it recorded at boot (hashes of the software) signed with a key that cannot be extracted from the chip. It is common to separate the roles: the device that produces the evidence, the verifier that checks it, and the party that uses the result to decide whether to release data or services.

The procedure with a TPM

On PCs and similar systems, each boot stage extends the hash of the next software it runs into the TPM's PCRs in turn (measured boot). The verifying server sends a fresh random number (nonce) to prevent reuse, and the TPM signs the PCR values together with the nonce using a non-exportable attestation key (a quote). The device returns this with the boot record (event log). The server checks the signature, recomputes the PCR values from the event log to confirm they match, and compares each measurement with known-good values. That the key belongs to a genuine TPM is confirmed through a certificate chain starting from the TPM manufacturer.

Confidential computing and embedded devices

In cloud confidential computing, features such as AMD SEV-SNP and Intel TDX have the CPU measure the initial state of an encrypted virtual machine and issue a report signed with a key inside the CPU. The user verifies the report to confirm the VM is what was expected before handing over the keys that decrypt the data. On smartphones, attestation shows that a key was created inside secure hardware and reports the device's boot state. Small microcontrollers can use lightweight schemes such as the TCG's DICE, in which each layer derives keys from that layer's measurement. Attestation is also used to check the health of devices joining a corporate network.

Limits of what it proves

Attestation shows what was loaded at the moment of measurement. If running software is attacked in memory after boot, the boot-time measurements may not change. Unless the list of known-good values is maintained as software is updated, healthy devices may be rejected or old vulnerable versions accepted. Per-device keys could be used to track individual devices, so privacy needs consideration. The trustworthiness of the evidence ultimately rests on trusting the hardware that protects the keys and its manufacturer.

FAQ

What is remote attestation?

It is a mechanism in which a device signs measurements of the software it booted with a non-extractable on-chip key and sends them to a remote server, which checks whether the device is in a trustworthy state. The server releases secret data, services or network access only to devices that pass.

How does it differ from secure boot?

Secure boot stops software whose signature check fails from running on the device itself. Remote attestation presents a record of what booted to an outside party and leaves the decision to that server. The two are used together.

What is the nonce for?

The verifier sends a new random number each time, and the device includes it in what it signs, proving the report was produced just now. Without a nonce, an attacker could record an old report from when the device was healthy and send it again (a replay attack).
