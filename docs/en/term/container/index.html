What is Container?

A unit of execution that bundles an application with the libraries and settings it needs and runs it isolated from other processes while sharing the host OS kernel. On Linux it is built from namespaces, which separate the view of process IDs, the network, mounts and so on, and cgroups, which limit the use of CPU and memory. It is lighter and faster to start than a virtual machine that boots a whole OS, but because it shares the kernel it cannot run a kernel of a different kind of OS from the host. Containers are created from container images and are created and managed with tools such as Docker and Kubernetes.

How it differs from a virtual machine

Virtual machines each run an OS, kernel included, on a hypervisor. A container does not boot an OS; it runs as an isolated process on the host kernel, so it often starts in under a second, and many can be packed onto one machine. On the other hand, its isolation relies on kernel features and is not as strong as that of a virtual machine. Where strong isolation is needed, containers are sometimes run inside lightweight virtual machines.

A container's file system

A container's file system is a writable layer for that container stacked on the read-only image layers. When a file from the image is modified, it is first copied into the writable layer and then changed (copy-on-write). The writable layer disappears when the container is removed, so data that must be kept is placed in external storage such as a volume.

Designing for disposability

Containers are designed on the assumption that a broken one is not repaired but recreated from the image and replaced. Configuration is supplied from outside, for example through environment variables, logs are written to standard output for the platform to collect, and state is kept in databases or storage. This makes it easy to change the number of containers or to swap in a new version.

Which correctly distinguishes containers from virtual machines?

  1. AEach container has its own OS kernel, while virtual machines share a kernel
  2. BContainers run on a hypervisor, while virtual machines run using only OS features
  3. CContainers share the kernel; each VM runs its own OS
Show answer and explanation

Answer: C. Containers share the kernel; each VM runs its own OS

Containers share a single OS kernel while partitioning file-system views, processes, networking and resource limits by group. Since no whole OS is booted, they are lightweight and start quickly. Virtual machines run on a hypervisor, each with its own OS including a kernel, which is heavier but gives stronger isolation and allows different OS types. Kernel sharing belongs to containers; watch for options that reverse the two.

Among the Linux kernel features that make containers possible, which of the following correctly pairs namespaces and cgroups (control groups) with their roles?

  1. ANamespaces: separate what a process can see (process IDs, network, mounts, etc.); cgroups: limit and account for the use of resources such as CPU and memory
  2. BNamespaces: limit and account for the use of resources such as CPU and memory; cgroups: separate what a process can see (process IDs, network, mounts, etc.)
  3. CNamespaces: boot a separate kernel for each container to isolate them; cgroups: create a virtual CPU for each container and emulate the hardware
Show answer and explanation

Answer: A. Namespaces: separate what a process can see (process IDs, network, mounts, etc.); cgroups: limit and account for the use of resources such as CPU and memory

A container is an ordinary process running on the host kernel, isolated by two mechanisms. Namespaces split process IDs, the network, mounts (the view of the file system), the host name and so on into groups, so that the processes in a container see only their own share. Cgroups limit the CPU time and amount of memory a group of processes can use and account for their usage. Both are kernel features, so a container neither boots another kernel nor emulates hardware.

FAQ

Can a container use a different Linux distribution from the host?

Yes. An image contains user-space files such as commands and libraries, so they can come from another distribution. The kernel, however, is shared with the host, so uname -r shows the host kernel and features the host kernel lacks are unavailable.

Why can Linux containers run on Windows or macOS?

Tools such as Docker Desktop run a small Linux virtual machine and execute the Linux containers in it. Linux containers always need a Linux kernel somewhere.
