What is TLB shootdown?

On a multiprocessor, the procedure for making other cores discard stale translations from their TLBs after a page table is modified. It uses inter-processor interrupts or instructions that broadcast the invalidation to all cores, and is costly.

Japanese name: TLBシュートダウン

Why a shootdown is needed

A TLB is a cache in which each core keeps virtual-to-physical address translations close at hand. On many CPUs, unlike data caches, TLB contents are not kept coherent with the page tables by hardware. Even after the OS revokes a mapping or removes write permission, the old translation can remain in other cores' TLBs, letting those cores write to a physical page that should already have been freed. So when the page tables change, for example through munmap, mprotect, page migration or eviction, the OS has the other cores discard their stale entries and confirms that all of them have finished before reusing the page.

The inter-processor interrupt procedure

A typical x86 procedure goes as follows. The OS first updates the page-table entry and removes the entry from its own TLB with an instruction such as INVLPG. It then sends inter-processor interrupts (IPIs) to the cores that may be using the address space. Each receiving core, in its interrupt handler, removes the relevant entry or flushes its whole TLB and reports completion. The initiating core waits for every response before continuing. Because this requires sending and receiving interrupts, interrupting running work and waiting for acknowledgments, it becomes a major source of slowdown on systems with many cores and in programs that free memory frequently.

Hardware broadcast methods

Some instruction sets have instructions that propagate TLB invalidation to other cores. In the Arm architecture, issuing the form of the TLBI instruction that broadcasts to all cores in the shareability domain (the Inner Shareable variants) and waiting with a DSB instruction performs a shootdown without IPIs. Some AMD x86 CPUs have also added an INVLPGB instruction that broadcasts invalidation to all cores and a TLBSYNC instruction that waits for it to complete. RISC-V's SFENCE.VMA, by contrast, affects only the executing core, so other cores are asked through IPIs (such as SBI remote fence calls).

Reducing the cost

Operating systems try to reduce the number and scope of shootdowns: batching changes to several pages into one shootdown, sending requests only to cores that have actually used the address space, and flushing the entire TLB instead of page by page when many pages change. Changes that only widen permissions, such as allowing writes, can sometimes skip the shootdown, because a fault caused by the stale entry can simply be handled later. In virtual machines, IPIs sent by the guest OS are expensive, so paravirtualized methods in which the hypervisor performs the invalidation on the guest's behalf are also used.

Answer: B. Making sure the stale translation is removed from other cores' TLBs too

On many CPUs, unlike caches, TLBs are not kept coherent by hardware, so other cores' TLBs may still hold the translation from before the page table was changed. Left alone, other cores could still access the revoked page. The OS therefore removes the stale entry from other cores, either by sending inter-processor interrupts or by using instructions that broadcast the invalidation, and waits for completion. This is a TLB shootdown, and it gets more expensive as core counts rise.

FAQ

What is a TLB shootdown?

On a multiprocessor system, it is the procedure for making other cores discard stale address translations left in their TLBs after the page tables are modified. It is done either by asking each core with inter-processor interrupts or by using instructions that broadcast the invalidation to all cores.

Why aren't TLBs kept coherent by hardware like data caches?

Monitoring every write to the page tables and updating every core's TLB would cost circuitry and inter-core communication. Many instruction sets are instead designed so that the OS explicitly specifies when and which translations to invalidate, and some, such as Arm, assist only by broadcasting the invalidation in hardware.

When do TLB shootdowns hurt performance?

When memory is allocated and freed frequently, when many threads share the same address space, or when there is a lot of page migration or reclamation. The more cores there are, the more responses must be awaited and the larger the impact.
