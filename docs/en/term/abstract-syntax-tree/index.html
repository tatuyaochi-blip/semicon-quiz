What is Abstract syntax tree?

A tree representing program structure with operations and statements as nodes. Meaningless details such as parentheses and separators are omitted, and operator precedence is expressed by the tree's shape.

Japanese name: 抽象構文木(AST)

Field: Compilers

From parse tree to AST

A parser that follows the grammar literally produces a concrete syntax tree (parse tree), with a node for every grammar rule applied and a leaf for every token, including parentheses, commas and semicolons. Grammars that encode precedence with separate rules for expressions, terms and factors also create long chains of single-child nodes. An AST (abstract syntax tree) discards all of this. Each node is a meaningful construct, such as a binary operation, a function call, an if statement or a variable reference, with exactly the children that construct needs.

How the shape encodes precedence and associativity

Operations evaluated first sit deeper in the tree. For 2 + 3 * 4 the root is + with children 2 and a * node over 3 and 4; for (2 + 3) * 4 the root is * instead, and the parentheses have done their job and vanish. Associativity is encoded the same way: a - b - c means (a - b) - c, so the left child of the root is another subtraction, giving a left-leaning tree. A post-order walk, children before parent, therefore evaluates the expression in the correct order.

What compilers do with an AST

After parsing, semantic analysis walks the AST to resolve each name to its declaration, check and infer types, insert implicit conversions and report errors such as using an undeclared variable. Nodes are typically annotated with this information. The annotated tree is then lowered into an intermediate representation (IR), such as three-address code or SSA form, where control flow becomes explicit branches between basic blocks. Simple tree-walking interpreters execute the AST directly, and tools such as formatters, linters and refactoring engines also operate on ASTs.

AST vs. IR

An AST mirrors the source language: it still has nested loops, structured if statements and source-level expressions, which makes it ideal for checks and transformations that refer to the program as written. An IR is closer to the machine, with flat sequences of simple operations and explicit jumps, which suits data-flow analysis and optimization. Confusing the two is common, but the dividing line is roughly this: the AST answers what the programmer wrote, the IR answers what must be computed.

Try it: questions about Abstract syntax tree

Which describes an abstract syntax tree (AST)?

  1. AIt keeps everything from the source, including parentheses and separators, as nodes
  2. BIt omits symbols irrelevant to meaning and expresses operator precedence through its shape
  3. CIt corresponds one-to-one with CPU instructions and can be executed directly
Show answer and explanation

Answer: B. It omits symbols irrelevant to meaning and expresses operator precedence through its shape

Parsing following the grammar rules yields a tree that includes parentheses and separators (a concrete syntax tree), which carries much information later phases do not need. An AST keeps only the operations and statements needed for meaning; in (a + b) * c, for example, the addition node sits under the multiplication node, so the order of evaluation is clear without parentheses. Code corresponding to CPU instructions is generated in later phases.

What does the abstract syntax tree for the expression 2 + 3 * 4 look like?

  1. AThe root is a + node whose right child is a * node representing 3 * 4
  2. BThe root is a * node whose left child is a + node representing 2 + 3
  3. CThe five nodes 2, 3, 4, + and * all sit directly under the root
Show answer and explanation

Answer: A. The root is a + node whose right child is a * node representing 3 * 4

Multiplication has higher precedence than addition, so the expression means 2 + (3 * 4). In an AST, operations computed first sit lower, so the root is +, its left child is 2 and its right child is a * node with children 3 and 4. Evaluating bottom-up computes 3 * 4 = 12 first, then 2 + 12 = 14. A * root corresponds to (2 + 3) * 4, and a flat list cannot express evaluation order.

FAQ

What is the difference between a parse tree and an abstract syntax tree?

A parse tree records every grammar rule and token, including punctuation, while an AST keeps only the constructs that carry meaning. Precedence that the parse tree shows through rule chains is shown in the AST simply by which node is the parent.

How are parentheses represented in an AST?

They are not stored as nodes. Their effect is captured by the tree structure: a parenthesized subexpression becomes a subtree that is evaluated before its parent operation.

Do interpreters use an AST?

Many do. A tree-walking interpreter evaluates the AST directly, while faster interpreters usually compile the AST into bytecode first and execute that.
