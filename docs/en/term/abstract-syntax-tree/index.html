What is Abstract syntax tree?

A tree representing program structure with operations and statements as nodes. Meaningless details such as parentheses and separators are omitted, and operator precedence is expressed by the tree's shape.

Japanese name: 抽象構文木(AST)

Try it: questions about Abstract syntax tree

Which describes an abstract syntax tree (AST)?

  1. AIt keeps everything from the source, including parentheses and separators, as nodes
  2. BIt omits symbols irrelevant to meaning and expresses operator precedence through its shape
  3. CIt corresponds one-to-one with CPU instructions and can be executed directly
Show answer and explanation

Answer: B. It omits symbols irrelevant to meaning and expresses operator precedence through its shape

Parsing following the grammar rules yields a tree that includes parentheses and separators (a concrete syntax tree), which carries much information later phases do not need. An AST keeps only the operations and statements needed for meaning; in (a + b) * c, for example, the addition node sits under the multiplication node, so the order of evaluation is clear without parentheses. Code corresponding to CPU instructions is generated in later phases.

What does the abstract syntax tree for the expression 2 + 3 * 4 look like?

  1. AThe root is a + node whose right child is a * node representing 3 * 4
  2. BThe root is a * node whose left child is a + node representing 2 + 3
  3. CThe five nodes 2, 3, 4, + and * all sit directly under the root
Show answer and explanation

Answer: A. The root is a + node whose right child is a * node representing 3 * 4

Multiplication has higher precedence than addition, so the expression means 2 + (3 * 4). In an AST, operations computed first sit lower, so the root is +, its left child is 2 and its right child is a * node with children 3 and 4. Evaluating bottom-up computes 3 * 4 = 12 first, then 2 + 12 = 14. A * root corresponds to (2 + 3) * 4, and a flat list cannot express evaluation order.
