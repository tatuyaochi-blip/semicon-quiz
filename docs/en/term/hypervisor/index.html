What is Hypervisor?

Software that runs multiple virtual machines on one computer, allocating CPU, memory and devices to each guest OS and isolating them from one another. Also called a virtual machine monitor.

How it keeps control of the CPU

A hypervisor, or virtual machine monitor, runs at a higher privilege level than the guest operating systems. Guest kernels believe they control the hardware, but when one executes a privileged instruction or touches a protected resource, the CPU traps to the hypervisor, which reproduces the effect on that virtual machine's state and resumes the guest. This is trap-and-emulate. Hardware virtualization extensions add a dedicated mode and save and restore guest state quickly on each transition; RISC-V, for example, adds hypervisor modes to its machine, supervisor and user modes.

Virtualizing memory

Each guest manages page tables that map guest virtual addresses to what it believes are physical addresses. Those guest physical addresses must in turn map to real host memory. With nested paging, hardware performs both stages automatically: guest virtual to guest physical through the guest's tables, then to host physical through the hypervisor's tables. Earlier systems used shadow page tables maintained in software, forcing the hypervisor to intervene whenever a guest edited its tables. The cost of two-stage translation is a longer page-table walk on TLB misses, which larger pages help reduce.

Virtualizing I/O

Emulating a real device register by register is fully transparent but slow, since every register access exits to the hypervisor. Paravirtualization instead installs virtualization-aware drivers in the guest that exchange batched requests with the hypervisor through queues in shared memory, which is the common choice for virtual disks and network cards. For the highest performance, a physical device can be assigned directly to one guest, with an I/O memory management unit (IOMMU) restricting its DMA to that guest's memory so isolation is preserved.

Hypervisors, containers and trust

A type 1 hypervisor runs directly on the hardware, as in cloud servers, while a type 2 hypervisor runs as an application on a host OS. Containers are different again: they share one kernel and only partition processes, file systems and resources, so they are lighter but isolate less strongly than virtual machines, each of which boots its own kernel. Hypervisors also partition mixed-criticality software on automotive SoCs. Normally the hypervisor can read all guest memory; confidential-computing features encrypt VM memory so even the host cannot.

Answer: A. Trap-and-emulate

A guest OS executes privileged instructions believing it controls the hardware, but it actually runs in a lower-privilege mode, so an exception (trap) occurs. The hypervisor catches it, reproduces (emulates) the instruction's effect so the result is correct for that virtual machine, and returns to the guest. CPU virtualization support makes these transitions fast and reliable. Copy-on-write and demand paging are memory-management techniques.

FAQ

What is the difference between a hypervisor and a virtual machine?

The hypervisor is the software layer that creates and runs virtual machines and divides hardware among them; each virtual machine is one isolated guest environment running its own OS.

What is the difference between type 1 and type 2 hypervisors?

A type 1 (bare-metal) hypervisor runs directly on hardware, while a type 2 (hosted) hypervisor runs as an application on top of an ordinary operating system.

Are containers the same as virtual machines?

No. Containers share the host kernel and are lightweight, while virtual machines each run their own kernel on a hypervisor, giving stronger isolation and the ability to run different operating systems.
