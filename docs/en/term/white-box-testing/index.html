What is White-box testing?

A testing approach that creates test cases based on the internal structure of a program (statements, branches and conditions) and checks how much of it has been executed using coverage criteria such as statement coverage and branch coverage. It is used mainly in unit testing.

Japanese name: ホワイトボックステスト

Which describes black-box testing?

  1. AWithout looking at the internal structure of the program, inputs and expected outputs are determined from the specification to check that it works correctly
  2. BTest cases are created based on the internal structure of the program, using whether statements and branches have been executed as the criterion
  3. CUsers finally confirm, in their actual business environment, that the system can be used as required
Show answer and explanation

Answer: A. Without looking at the internal structure of the program, inputs and expected outputs are determined from the specification to check that it works correctly

Black-box testing treats the test object as a box whose contents cannot be seen and creates test cases from the specification alone; its techniques include equivalence partitioning, boundary value analysis, cause-effect graphs and decision tables. It is good at finding functions that are in the specification but not implemented, but it cannot tell whether a particular path in the implementation has been exercised. Creating tests based on internal structure and using coverage as the criterion is white-box testing. The final confirmation by users is acceptance testing, which is the name of a test level.
