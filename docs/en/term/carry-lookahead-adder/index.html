What is Carry-lookahead adder?

An adder that computes carries in parallel from each bit's generate signal g = a·b and propagate signal p = a ⊕ b, without waiting for carries to ripple. Delay stays small even for wide operands.

Japanese name: 桁上げ先見加算器

Carry-lookahead adder appears in 3 practice questions across 2 topics, including Computer Arithmetic, Logic circuits.

Field: Computer Arithmetic

Generate and propagate signals

For each bit with inputs a and b, the generate signal g = a·b is 1 when the bit produces a carry regardless of the carry coming in, and the propagate signal p = a ⊕ b is 1 when an incoming carry will pass through. The carry out is c(i+1) = g(i) + p(i)·c(i), and the sum is s(i) = p(i) ⊕ c(i). Expanding the recurrence gives c1 = g0 + p0·c0 and c2 = g1 + p1·g0 + p1·p0·c0, so every carry can be written in two-level logic using only the g and p signals and the input carry c0.

Why ripple-carry addition is slow

In a ripple-carry adder, each full adder must wait for the carry from the bit below. In the worst case, such as adding 1 to a word of all ones, the carry travels through every bit, so delay grows linearly with width; a 64-bit ripple-carry adder is far too slow for a processor clocked at gigahertz rates. A carry-lookahead adder (CLA) computes the carries directly from the inputs in parallel, and with hierarchical lookahead its delay grows only with the logarithm of the width.

Building wide adders hierarchically

Fully expanded carry equations quickly need gates with too many inputs, so practical designs use blocks of about 4 bits. Each block produces a group generate, G = g3 + p3·g2 + p3·p2·g1 + p3·p2·p1·g0, and a group propagate, P = p3·p2·p1·p0. A second-level lookahead unit treats these exactly like single-bit g and p signals to compute the carries into each block, and a third level extends the scheme to 64 bits. Parallel prefix adders such as Kogge-Stone and Brent-Kung generalize the same idea, trading wiring and area for logic depth.

Where carry-lookahead adders are used

Fast adders sit in ALUs, address generators and floating-point units, and in the last stage of multipliers. A multiplier first reduces its many partial products with carry-save adders, which are independent full adders that turn three numbers into two with only one full-adder delay and no carry propagation. Only the final two numbers need a carry-propagating addition, which is done once by a carry-lookahead or prefix adder. Other compromises, such as carry-select and carry-skip adders, sit between ripple-carry and full lookahead in speed and area.

Answer: C. It computes the carry for each bit in parallel from the inputs without waiting for propagation from the lower bits

A carry-lookahead adder uses per-bit generate G = A·B (always produces a carry) and propagate P = A⊕B (passes a lower carry) to compute each carry directly from the inputs in parallel: C1 = G0 + P0·C0, C2 = G1 + P1·G0 + P1·P0·C0, and so on. Delay then grows only with the logarithm of the width. Because the expressions grow long, about 4-bit blocks are combined hierarchically.

In a carry-lookahead adder, which gives the definitions of each bit's generate signal g and propagate signal p (a and b are that bit's inputs) and the carry into the next bit, c(i+1)?

  1. Ag = a + b, p = a·b, c(i+1) = p + g·c(i)
  2. Bg = a·b, p = a ⊕ b, c(i+1) = g + p·c(i)
  3. Cg = a ⊕ b, p = a·b, c(i+1) = g·p·c(i)
Show answer and explanation

Answer: B. g = a·b, p = a ⊕ b, c(i+1) = g + p·c(i)

If a and b are both 1, a carry is produced regardless of the incoming carry, so the generate signal is g = a·b. If exactly one of them is 1, the incoming carry passes upward, so the propagate signal is p = a ⊕ b (OR is also used). Hence c(i+1) = g(i) + p(i)·c(i); expanding this lets every carry be computed in parallel with two-level logic from the g and p signals and the lowest carry alone. Formulas that swap generate and propagate do not compute correctly.

FAQ

Why is a carry-lookahead adder faster than a ripple-carry adder?

A ripple-carry adder waits for the carry to pass through every bit in turn, so delay grows linearly with width. A carry-lookahead adder computes all carries in parallel from generate and propagate signals, so delay grows roughly with the logarithm of the width.

Can the propagate signal use OR instead of XOR?

Yes, for the carry chain: p = a + b gives the same carries because when both inputs are 1 the generate term already produces the carry. The sum bit still needs a ⊕ b, so many designs compute XOR for p and use it for both.

What is group generate and group propagate?

They summarize a block of bits: group generate is 1 if the block produces a carry out by itself, and group propagate is 1 if a carry entering the block will pass all the way through. Higher lookahead levels use them to compute block carries quickly.
