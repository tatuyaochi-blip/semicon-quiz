What is ATPG (automatic test pattern generation)?

Automatically generating test patterns that detect faults from a circuit's netlist. It is used together with scan design.

Japanese name: ATPG(自動テストパターン生成)

ATPG (automatic test pattern generation) appears in 7 practice questions across 4 topics, including Testing and inspection, Metrology and analysis, Yield and quality control.

Field: Testing and inspection

How ATPG finds a test

Automatic test pattern generation (ATPG) works from the gate-level netlist and a fault model. For each target fault it must activate the fault, driving the faulty line to the opposite of its stuck value, and propagate the difference along a sensitized path to an observable output, while finding primary-input values that justify both. Classic algorithms such as the D-algorithm and PODEM search this space. Each new pattern is fault-simulated to mark every other fault it happens to detect, and patterns are compacted, because test time and tester memory grow with pattern count.

Fault models and coverage

The stuck-at model assumes a line is permanently 0 or 1, giving 2n faults for n lines. It is abstract, yet patterns that detect stuck-at faults also catch many real shorts and opens, and it remains the baseline for measuring fault coverage, the fraction of modeled faults the pattern set detects. Defects that only slow a signal are invisible to static tests, so delay fault models such as transition faults add at-speed patterns that launch a transition and capture the result one clock later. Coverage is always relative to a model, not to every possible physical defect.

Why scan design is essential

Generating tests for a deep sequential circuit is very hard, because internal states can be reached only through many clock cycles. Scan design, a design-for-testability (DFT) technique, adds a multiplexer at each flip-flop input so that in test mode the flip-flops link into shift-register chains. The tester shifts a state in, applies one functional capture clock and shifts the result out. ATPG then only has to solve combinational logic between scan cells, which is what makes high coverage practical for chips with hundreds of millions of gates.

ATPG vs. functional verification

Functional verification asks whether the design is correct; ATPG assumes the design is correct and asks whether each manufactured chip matches it. Its output is test patterns, also called test vectors: input values per time step plus the expected responses, which automatic test equipment applies and compares. Other screens complement it. Part average testing (PAT) rejects chips whose measurements are statistical outliers even though they pass, a practice common for automotive parts, while automatic defect classification (ADC) belongs to wafer inspection, not to electrical test.

Answer: C. Connecting the flip-flops in a circuit like a shift register to make it easy to set and observe internal states

Scan design adds a multiplexer at each flip-flop input; in test mode the flip-flops are chained into scan chains so arbitrary values can be shifted in and internal values shifted out. This turns sequential-circuit testing into combinational-circuit testing, letting ATPG automatically generate patterns with high fault coverage. Answer: B. A fault in which a signal line's value is fixed at 0 or 1

The stuck-at model assumes a signal line is permanently fixed at 0 (stuck-at-0) or 1 (stuck-at-1), giving 2n faults for n lines. Simple as it is, it represents many physical defects such as shorts and opens, and it underpins ATPG and fault-coverage evaluation. Slow signals are handled by delay fault models, and temperature rise is not a fault model.

FAQ

What is ATPG in VLSI testing?

It is software that automatically generates input patterns and expected outputs that detect modeled manufacturing faults, such as stuck-at faults, from a circuit's netlist.

Why does ATPG need scan chains?

Scan chains let the tester set and read every flip-flop directly, turning a hard sequential test problem into a combinational one that ATPG can solve efficiently with high coverage.

What is the difference between stuck-at and transition fault models?

Stuck-at faults model a line fixed at 0 or 1 and are found with static tests. Transition faults model a line that switches too slowly and need at-speed launch-and-capture patterns.
