What is Measured boot?

A mechanism that cumulatively records hashes of each boot stage's software in a TPM or similar so the boot state can be verified later.

Japanese name: 測定ブート

Measured boot appears in 1 practice question across 1 topic, including Hardware Security.

Field: Hardware Security

How measured boot works

In measured boot, a small piece of code that runs first at startup and serves as the root of trust computes (measures) the hash of the firmware to be run next, records it in the TPM and only then hands over control. Each subsequent stage, such as the bootloader and then the OS kernel, continues the measurement chain in the same way. The records go into the TPM's PCRs (platform configuration registers), where each new value is computed as the hash of the previous PCR value concatenated with the new hash (an extend operation). The PCRs that hold boot measurements cannot be reset without a reboot, so the record cannot later be rewritten to a convenient value.

Measured boot vs. secure boot

Secure boot verifies the signature of the software to be started next and halts the boot if it is not properly signed. Measured boot, by contrast, does not stop the boot but records what started in a tamper-evident way. Secure boot only tells you whether something was signed with a trusted key, so it cannot distinguish an old, correctly signed but vulnerable version, or a configuration change. Measured boot keeps the values of what actually ran. The two are not in conflict and are used together: secure boot prevents unauthorized boot, and measured boot proves the boot state.

How the recorded values are used

PCR values are used in two main ways. One is remote attestation: the device sends a server the PCR values signed with a key inside the TPM (a quote) along with the record of each stage (the event log). The server checks that the PCR values computed from the event log match, and grants access only to devices that booted the expected software. The other is sealing: secrets such as disk-encryption keys are made releasable by the TPM only when the PCRs hold specific values. If any part of the boot is altered, the key cannot be released, protecting the data.

Limitations and related technologies

Measured boot only records, so it does not prevent malicious code from running, and it is meaningful only once someone checks the records. It also assumes that the code doing the first measurement is trustworthy; if that is compromised, the whole record becomes unreliable. Updating software changes the expected PCR values, so reference values must be managed too. Related technologies include the dynamic root of trust for measurement (DRTM), which restarts measurement from a trusted state partway through boot, and DICE, which derives keys from a hardware secret and measurements for small devices without a TPM.

FAQ

What is measured boot?

It is a mechanism that computes the hash of the software to run next at each boot stage and records it cumulatively in a TPM or similar. It does not stop the boot, but the records let you later confirm which software started, or prove it to a remote server.

What is the difference between secure boot and measured boot?

Secure boot verifies signatures and stops incorrect software from starting. Measured boot does not stop the boot; it records hashes of the software that started in a tamper-evident way. Secure boot prevents, measured boot proves, and in many cases they are used together.

Does measured boot require a TPM?

Measurements are generally recorded in a TPM's PCRs. Besides a discrete chip, a TPM can be implemented as firmware inside a CPU or SoC. Microcontrollers and other devices without a TPM can serve the same purpose with schemes such as DICE that derive keys from measurements.
