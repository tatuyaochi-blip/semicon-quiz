What is Non-uniform memory access (NUMA)?

An organization in which each core has near and far memory, and far accesses take longer. Placing data and threads on the same side is faster.

Japanese name: NUMA

Try it: questions about Non-uniform memory access (NUMA)

Which describes a NUMA (non-uniform memory access) system?

  1. AEvery core reaches all memory in the same time
  2. BEach core has near and far memory, and accessing far memory takes longer
  3. CEach core can read only its own memory and cannot use other cores' memory
Show answer and explanation

Answer: B. Each core has near and far memory, and accessing far memory takes longer

In servers with multiple CPU sockets, for example, each socket has memory attached directly, and other sockets' memory is reached over inter-socket links. Far memory is therefore slower and has less bandwidth than near memory. All memory appears in one address space, so programs run unchanged, but placing data and threads on the same side improves performance.

Under the first-touch policy common on Linux NUMA systems (a page is placed in the memory of the node where the thread first writing it runs), what should programmers watch out for?

  1. AUnder first touch pages are placed on random nodes
  2. BAll page placements are fixed when malloc is called
  3. CIf one thread zero-initializes a large array, all of it lands on one node, and threads on other nodes end up using far memory
Show answer and explanation

Answer: C. If one thread zero-initializes a large array, all of it lands on one node, and threads on other nodes end up using far memory

malloc alone assigns no physical pages; the page fault on first write places each page in the memory of the node where the writing thread runs. So if one thread does the initialization, the whole array gathers on that node, and in the parallel computation much of each thread's portion is in far memory. Initializing in parallel with the same division of work as the computation puts each portion near its thread.
