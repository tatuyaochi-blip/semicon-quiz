What is Multicycle path?

A timing exception telling STA that a path may take several clock cycles to transfer data. When setup is set to N cycles, hold is usually set to N − 1 to move the hold check edge back to its original position.

Japanese name: マルチサイクルパス

Field: Timing analysis and CDC

When a path really has more time

Some paths need not deliver data within one clock period because the destination captures only every N cycles, for example a register loaded through an enable that is asserted every other cycle, or a slow arithmetic block whose result is sampled two cycles after its inputs change. By default STA assumes single-cycle transfer and reports a violation. A multicycle path exception, set_multicycle_path in SDC, tells the tool that the capture edge is N periods after launch instead of one.

Setup arithmetic

With a 2.0 ns clock, a data arrival time of 3.3 ns and a 0.1 ns setup time, the default single-cycle check gives a required time of 1.9 ns and a slack of −1.4 ns. A setup multicycle of 2 moves capture to 4.0 ns, so the required time becomes 3.9 ns and the slack +0.6 ns. The exception is valid only if the logic truly guarantees capture every second cycle; otherwise it hides a real failure that will appear in silicon.

Why hold needs N − 1

STA checks hold against the edge one period before the setup capture edge. Moving setup capture to N periods therefore also drags the hold check to N − 1 periods after launch, which would demand that new data arrive at least that late, an absurdly strict requirement that usually fails. Adding a hold multicycle of N − 1 moves the hold check back to the launch edge at time zero, restoring the ordinary hold condition. It does not remove the hold check.

Multicycle path vs. false path

A multicycle path stays timed, just with a longer budget. A false path, set with set_false_path, is excluded from analysis entirely and is meant for paths that are structurally connected but can never carry a meaningful transition, for example through two multiplexers whose select conditions are mutually exclusive. Declaring a path false merely because it is hard to close hides real bugs, and declaring a genuine multicycle path false removes a check it still needs.

  1. A−1.4 ns
  2. B+2.6 ns
  3. C+0.6 ns
Show answer and explanation

Answer: C. +0.6 ns

A multicycle path of 2 moves the capturing edge from one period later to two periods later. The required time is 2 × 2.0 − 0.1 = 3.9 ns and the arrival time is 3.3 ns, so the slack is +0.6 ns. −1.4 ns is calculated with the normal single cycle, and +2.6 ns allows three cycles' worth of time. A multicycle path must be set only after the designer has confirmed that the circuit actually captures only every two cycles, for example via an enable signal.

When a setup multicycle path of N (N ≥ 2) is set, a hold multicycle path of N − 1 is normally set as well. Why?

  1. ABecause the hold check edge also shifts later along with setup and becomes far too strict, so it must be moved back to its original position
  2. BTo shift the hold check edge even later and increase hold margin
  3. CTo exclude the path's hold check from the analysis
Show answer and explanation

Answer: A. Because the hold check edge also shifts later along with setup and becomes far too strict, so it must be moved back to its original position

By default, STA checks hold at the edge one before the setup capture edge. Making setup two cycles moves the hold check edge from time 0 to one period later, so with a 2.0 ns period the data would violate hold unless it arrived 2.0 ns or more late. Specifying a hold multicycle path of N − 1 = 1 moves the check edge back to time 0, giving the same conditions as an ordinary path. It does not remove the hold check.

FAQ

Why is a hold multicycle of N − 1 set with a setup multicycle of N?

Moving the setup capture edge also moves the default hold check later, making hold nearly impossible to meet. The N − 1 hold setting returns the hold check to its original edge.

What is the difference between a multicycle path and a false path?

A multicycle path is still analyzed but given several clock periods. A false path is not analyzed at all and should be used only for paths that can never functionally propagate.

When is it safe to set a multicycle path?

Only when the design guarantees the destination samples the data every N cycles, for example through an enable, and verification confirms that behavior. Otherwise the relaxed check can mask a real timing failure.
