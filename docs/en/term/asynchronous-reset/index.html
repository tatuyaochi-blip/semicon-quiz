What is Asynchronous reset?

A reset that initializes flip-flops as soon as the reset signal is asserted, regardless of the clock. Release should be synchronized to the clock.

Japanese name: 非同期リセット

Field: HDL & Verification

How an asynchronous reset is written

In Verilog an asynchronous reset appears in the sensitivity list together with the clock, as in always @(posedge clk or negedge rst_n) followed by if (!rst_n) q <= 0; else q <= d;. Because the falling edge of rst_n also triggers the block, q clears the instant reset is asserted, without waiting for a clock edge. The _n suffix is a common naming convention for active-low signals. Synthesis maps this pattern onto flip-flops that have a dedicated reset or clear pin, so the reset does not pass through the data path logic.

Asynchronous vs. synchronous reset

A synchronous reset is just another input sampled at the clock edge: it passes through logic in front of the flip-flop's D input and takes effect only when the clock is running. That makes timing analysis simple, but it cannot initialize a block whose clock is stopped and adds logic to the data path. An asynchronous reset uses the flip-flop's reset pin, acting immediately even without a clock, which is useful at power-up or when clocks are gated. Its weakness is the moment of release, which has timing requirements of its own.

The problem with reset release

Flip-flops specify recovery and removal times, which play the role of setup and hold times for the deassertion of an asynchronous reset. If reset is released too close to a clock edge, a flip-flop may become metastable, or flip-flops at different points of the reset network may leave reset in different clock cycles. A state machine whose bits start one cycle apart can begin in an illegal state. Because the external reset source is not related to the clock, this situation cannot be ruled out without synchronizing the release.

Asynchronous assert, synchronous release

The usual remedy is a reset synchronizer: two flip-flops in series, clocked by the destination clock, whose asynchronous reset pins are driven by the external reset, with the first stage's data input tied to the inactive level. Asserting reset clears both stages at once, so reset still acts immediately. On release, the inactive level must ripple through the two flip-flops, so the distributed reset deasserts in step with the clock, and the second stage gives the first time to resolve metastability. Each clock domain needs its own synchronizer.

  1. AClock gating check
  2. BRecovery and removal checks
  3. CMaximum transition (max transition) check
Show answer and explanation

Answer: B. Recovery and removal checks

Like a data input, deassertion of an asynchronous reset must be a certain time away from the clock edge. The recovery check (equivalent to setup) looks at whether deassertion comes too soon before the edge, and the removal check (equivalent to hold) at whether it comes too soon after the edge. A violation makes it uncertain whether reset is released in that cycle, so different flip-flops may start operating in different cycles. The transition check looks at the slew of signal waveforms and serves a different purpose.

In circuits using asynchronous reset, why is reset release (the 0-to-1 transition) synchronized to the clock through two flip-flops before distribution?

  1. ATo delay asserting reset by two clocks for safety
  2. BTo make the reset signal twice as fast
  3. CIf release lands near a clock edge, flip-flops may leave reset on different cycles or become unstable, so release is aligned to the clock
Show answer and explanation

Answer: C. If release lands near a clock edge, flip-flops may leave reset on different cycles or become unstable, so release is aligned to the clock

If an asynchronous reset is released just before or after a clock edge, the timing requirements for release are violated, and one flip-flop may start in this cycle while another starts in the next. This can start a state machine in an illegal state. A reset synchronizer applies reset immediately but aligns only its release to the clock through two flip-flops before distributing it.

FAQ

What is the difference between synchronous and asynchronous reset?

A synchronous reset takes effect only at an active clock edge and needs a running clock, while an asynchronous reset acts immediately through the flip-flop's reset pin regardless of the clock.

Why do we synchronize the release of an asynchronous reset?

If reset is released near a clock edge, flip-flops can violate recovery or removal timing, become metastable or leave reset in different cycles; a two-flip-flop synchronizer aligns the release to the clock.

What are recovery and removal times?

They are the minimum times by which an asynchronous reset must be deasserted before (recovery) or held after (removal) an active clock edge, analogous to setup and hold times for data.
