What is SystemVerilog?

An extension of Verilog adding design features such as the logic type and always_ff/always_comb, and verification features such as classes, constrained random and assertions.

Japanese name: SystemVerilog

Field: HDL & Verification

What SystemVerilog adds for design

SystemVerilog, standardized as IEEE 1800, is a superset of Verilog that adds features for both writing hardware and verifying it. On the design side, the logic type replaces Verilog's confusing wire and reg split for single-driver signals; always_ff, always_comb and always_latch state the intended hardware; and enums, structs, packages and interfaces make RTL more readable and less error-prone. In Verilog, reg merely means a signal assigned in an always block, not necessarily a flip-flop. Signals with multiple drivers, such as tri-state buses, still use wire, and logic is a four-state type that can hold X and Z.

Catching RTL mistakes early

A frequent Verilog bug is an unintended latch: a combinational always block that leaves an output unassigned on some path forces the tool to remember the old value. The standard cure is to assign default values to every output at the top of the block. With always_comb, tools also know combinational logic was intended and warn or error when a latch is inferred, and the sensitivity list is derived automatically from the signals read, avoiding the missing-signal mistakes of hand-written lists. always_ff similarly flags code that does not map to edge-triggered flip-flops.

Verification features

Most of SystemVerilog's additions are for testbenches. Classes bring object-oriented programming; constrained random generation produces legal stimulus such as word-aligned addresses or lengths from 1 to 256; covergroups measure functional coverage to show which cases were exercised; and SystemVerilog Assertions (SVA) express temporal properties, such as a response within three cycles of a request, that are checked in simulation or proven by formal tools. Clocking blocks define when testbench signals are driven and sampled, preventing races with the design. The Universal Verification Methodology (UVM, IEEE 1800.2) builds reusable testbenches on these features.

Synthesizable versus testbench-only code

Only part of SystemVerilog describes hardware. The synthesizable subset, including logic, always_ff, always_comb, enums, structs, packages and interfaces, is accepted by synthesis tools and becomes gates. Classes, randomization, coverage and most dynamic data types exist only in simulation, where they describe the environment around the design. Assertions can be bound to RTL and used in simulation, formal verification and sometimes emulation, but they are not turned into functional logic. VHDL remains the main alternative language, especially in some FPGA and aerospace teams.

Answer: C. UVM (Universal Verification Methodology)

UVM is a standard methodology and class library for building SystemVerilog testbenches from components such as drivers that apply stimulus, monitors that observe outputs and scoreboards that check against expected values. Components can be reused across projects, and constrained-random stimulus and coverage collection are easy to integrate. It is standardized as IEEE 1800.2. OPC and CMP are manufacturing technologies.

Which describes constrained random verification in SystemVerilog?

  1. AInput values are generated randomly within constraints allowed by the specification, broadly exercising cases people might not think of
  2. BInput values are generated completely at random, including many values outside the specification
  3. CPeople write every input value by hand
Show answer and explanation

Answer: A. Input values are generated randomly within constraints allowed by the specification, broadly exercising cases people might not think of

Tests people devise (directed tests) tend to miss bugs in combinations the designer did not anticipate. Constrained random verification states constraints such as "addresses are multiples of 4" or "length is 1 to 256" and generates random inputs within them, exercising many cases with only meaningful inputs. Coverage measures which cases were hit, and gaps are filled by adjusting constraints or adding directed tests.

FAQ

What is the difference between Verilog and SystemVerilog?

SystemVerilog is a superset of Verilog that adds safer design constructs such as logic, always_ff and always_comb, plus verification features such as classes, constrained random stimulus, functional coverage and assertions. Existing Verilog code is generally valid SystemVerilog.

Is SystemVerilog synthesizable?

Its design subset is, including logic, always_ff, always_comb, structs, enums and interfaces. Verification constructs such as classes, randomization and covergroups are for simulation only.

Should I use logic instead of wire and reg?

For signals with a single driver, logic works whether it is driven by an assign statement or an always block, so it replaces both in most code. Use wire for nets with multiple drivers, such as tri-state buses.
