What is Pipelining?

A method that splits instruction processing into stages such as fetch, decode and execute, and processes several instructions at once, each offset by a stage.

Japanese name: パイプライン処理

Pipelining appears in 7 practice questions across 5 topics, including CPUs and architecture, Compilers, Logic circuits.

Field: CPUs and architecture

How a pipeline raises throughput

A pipeline splits instruction processing into stages separated by registers, like an assembly line. The classic five-stage RISC pipeline uses instruction fetch, decode and register read, execute, memory access and write-back. While one instruction executes, the next is being decoded and a third fetched, so ideally one instruction completes every clock and throughput approaches five times that of an unpipelined design. The latency of an individual instruction does not shrink and actually grows slightly, because every instruction now passes through all the pipeline registers.

Why the speedup falls short

The clock period must cover the slowest stage plus register overhead: clock-to-Q delay, setup time and clock skew. If logic cannot be divided evenly, the longest stage sets the frequency and the others idle for part of each cycle. Deeper pipelines shorten each stage, but the fixed register overhead becomes a larger fraction of the period, and the penalty for mispredicted branches grows because more partially processed instructions must be discarded. Beyond a point, adding stages lowers performance and raises power, which is why pipeline depth is a balanced design choice.

Hazards and how they are handled

Three kinds of hazard interrupt the ideal flow. Structural hazards arise when two instructions need the same resource in the same cycle. Data hazards arise when an instruction needs a result that has not yet been written; forwarding, or bypassing, routes results directly from later stages, though a load followed immediately by its use still typically costs a stall cycle in the classic pipeline. Control hazards come from branches, whose outcome is known only several stages after fetch; branch prediction guesses the path and flushes the wrong instructions when it misses.

Pipelining beyond the CPU

RISC instruction sets, with uniform instruction lengths and load/store architectures, were designed to pipeline cleanly; x86 processors reach similar behavior by splitting complex instructions into simple micro-operations. The same idea applies to any synchronous datapath: inserting registers to split a long critical path raises the maximum clock frequency at the cost of latency, and high-level synthesis tools expose this as a pipelining option. Software pipelining is the compiler counterpart, overlapping different loop iterations so loads, computation and stores proceed in parallel, with prologue and epilogue code around the loop.

Answer: A. To divide instruction processing into stages and overlap the stages of different instructions, increasing throughput

Pipelining overlaps stages such as fetch, decode, execute, memory access and write-back like an assembly line, completing one instruction per clock to raise throughput—ideally about 5× for five stages. Each instruction's latency actually grows slightly. Data dependences, branches and resource conflicts disrupt the flow (hazards), handled with forwarding and branch prediction.

  1. AA technique that increases the number of CPU pipeline stages in software
  2. BA technique that splits a loop into functions and runs them in parallel on multiple threads
  3. COverlapping different iterations to fill latency

Answer: C. Overlapping different iterations to fill latency

Software pipelining divides one loop iteration into stages such as load, compute and store, then arranges instructions so that, for example, the store for iteration i, the computation for i+1 and the load for i+2 happen within the same loop body. Computation from other iterations proceeds during load latency, keeping functional units busy. Prologue and epilogue code are needed around the loop. It neither changes the CPU's pipeline depth nor parallelizes across threads.

FAQ

Does pipelining reduce the latency of an instruction?

No. Pipelining increases throughput by overlapping instructions, but each instruction still passes through every stage and usually takes slightly longer because of register overhead.

What are the three types of pipeline hazards?

Structural hazards from resource conflicts, data hazards from dependences on results not yet available, and control hazards from branches. Typical remedies are duplicated resources, forwarding and branch prediction.

Why not make the pipeline as deep as possible?

Register overhead stays fixed while stage logic shrinks, so gains diminish, and branch mispredictions waste more work in a deeper pipeline. Power and design complexity also increase.
