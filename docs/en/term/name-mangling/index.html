What is Name mangling?

A C++ compiler's encoding of argument types and namespaces into a function's symbol name, so the linker can tell overloaded functions apart.

Japanese name: 名前修飾

What gets encoded

A mangled name packs into one linker symbol everything that distinguishes C++ entities sharing a source-level name: enclosing namespaces and classes, the function name, the parameter types, const or volatile qualification of member functions and template arguments. The return type is normally omitted, since overloads cannot differ only by return type, although function template instances do include it. Under the Itanium C++ ABI, used by GCC and Clang on Linux and many other platforms, print(int) becomes _Z5printi and ns::f(double) becomes _ZN2ns1fEd, where lengths prefix each name and single letters encode built-in types.

extern "C" and mixing languages

C has no overloading, so C compilers emit plain function names. When C++ code calls a C library, its declarations must be wrapped in extern "C" so that the C++ compiler looks for the unmangled name; otherwise it looks for something like _Z3fooi, finds only foo, and the link fails with an undefined reference. Headers shared between the languages usually wrap their declarations in extern "C" guarded by a check for the __cplusplus macro. Functions declared extern "C" cannot be overloaded, because two of them would map to the same symbol.

Reading mangled names

Mangled names show up in nm output, disassembly, crash reports and linker errors. The c++filt tool converts them back to readable declarations, nm -C does the same in its listing, and most debuggers and linkers demangle automatically when printing diagnostics. Being able to read the raw form still helps: two symbols that look identical once demangled may differ in a const qualifier or a parameter type, which reveals that a declaration in a header does not match the definition that was actually compiled.

Mangling is part of the ABI

Each compiler family defines its own scheme, and Microsoft's compiler uses a completely different encoding from the Itanium ABI. The scheme is part of the application binary interface (ABI), so object files from compilers with different schemes cannot be linked directly even if the source is identical. Changes to a library's C++ interface, such as altering a parameter type, change the mangled names and break binary compatibility with programs built against the old version. Other languages with overloading or modules, such as Rust, mangle names for the same reasons.

Answer: C. To let the linker distinguish overloaded functions with the same name but different argument types, and namespaces

The linker matches symbols purely by their name strings. C++ allows functions with the same name, such as print(int) and print(double), which would otherwise be indistinguishable. So the compiler embeds the argument types and more into the name, as in "_Z5printi". C functions are not mangled, so when C++ calls a C function, it is declared extern "C" to turn mangling off.

FAQ

How do I demangle a C++ symbol name?

Pipe it through c++filt, for example echo _Z5printi | c++filt prints print(int). nm -C and objdump -C demangle while listing symbols.

What does extern "C" do in C++?

It gives the declared functions C linkage, so the compiler uses the plain unmangled name. This lets C++ code call C libraries and lets C code call C++ functions exported this way.

Why is the return type not part of a mangled function name?

C++ overloads must differ in their parameters, so the parameters alone identify the function. Function template instances are the exception and do encode the return type.
