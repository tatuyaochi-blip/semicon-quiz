What is Lexical analysis?

The first compiler phase, which splits the characters of source code into tokens such as identifiers, numbers, operators and keywords. Whitespace and comments are removed here.

Japanese name: 字句解析

Answer: B. Splitting the characters of source code into tokens such as identifiers and operators

Lexical analysis is the first phase of a compiler. It splits, for example, "count = count + 1;" into the tokens identifier count, symbol =, identifier count, symbol +, number 1 and symbol ;. Whitespace and comments are discarded here. Token rules can be written as regular expressions, so a finite automaton processes them quickly. Checking grammar in tree form is the next phase, parsing, and checking types and names is semantic analysis.

What is commonly used to express the rules for recognizing tokens in lexical analysis?

  2. BRegular expressions, processed by finite automata
  3. CCache replacement policies

Answer: B. Regular expressions, processed by finite automata

Token types can be written concisely as regular expressions, such as "a letter followed by letters or digits" for identifiers and "one or more digits" for numbers. Regular expressions convert to finite automata, machines with a finite number of states that change state with each character read, so tokens are extracted in time proportional to input length. Lexers are therefore often generated automatically from regular expressions by tools. Rounding and cache rules have nothing to do with lexical analysis.
