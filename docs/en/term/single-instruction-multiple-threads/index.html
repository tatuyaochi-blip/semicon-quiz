What is Single instruction, multiple threads (SIMT)?

An execution model in which programs are written per thread while hardware bundles threads into warps (32 on NVIDIA) that execute the same instruction in lockstep.

Japanese name: SIMT

Field: GPU Programming

How SIMT executes threads

In the single instruction, multiple threads (SIMT) model, the programmer writes a kernel as ordinary code for one thread, and thousands of threads run it on different data. The hardware groups threads into fixed bundles, called warps of 32 threads on NVIDIA GPUs and wavefronts of 64 or 32 on AMD GPUs. One instruction is fetched and decoded for the whole bundle and executed by all its threads in lockstep, each with its own registers and data. This amortizes control logic over many arithmetic lanes, so most of the chip area goes to computation.

Branch divergence

Because each thread is written independently, threads in one warp may take different branches. The hardware handles this by executing each path in turn, with the threads not on that path masked off, and then reconverging. Correctness is preserved, but if half the threads take each side of an if-else, the warp spends time on both and its throughput roughly halves. Performance-aware code arranges data so that threads in the same warp follow the same path, for example by making branch conditions depend on the warp index rather than on each thread's data.

SIMT vs. CPU SIMD

CPU single instruction, multiple data (SIMD) extensions apply one instruction to a vector register holding a fixed number of elements, such as 4 or 8. The program or the compiler must be written around that width, with explicit vector instructions and masks for edge cases. SIMT hides the width: the code describes a scalar thread, and the hardware forms the vectors from many threads and manages masking on divergence. Underneath, the execution is similar, which is why SIMT performance still depends on keeping threads in a warp in step.

Practical consequences

Several common GPU programming rules follow from SIMT. Thread-block sizes are normally multiples of 32 so no warp runs partly empty. Memory accesses are fastest when neighboring threads in a warp access neighboring addresses, letting the hardware combine them into a few wide transactions, a pattern called coalescing. And GPUs hide long memory latency by keeping many warps resident and switching to another ready warp whenever one stalls, which is why high occupancy, enough active warps per core, often matters for performance.

FAQ

What is a warp in GPU computing?

A warp is a group of 32 threads on NVIDIA GPUs that execute the same instruction together in lockstep. It is the basic unit of instruction issue in the SIMT model; AMD's equivalent is called a wavefront.

What is the difference between SIMT and SIMD?

SIMD exposes fixed-width vector instructions that the programmer or compiler must use explicitly. SIMT lets each thread be written as independent scalar code while the hardware groups threads into warps and handles divergent branches.

What is warp divergence?

Warp divergence occurs when threads in the same warp take different branch paths. The hardware executes each path serially with inactive threads masked, which lowers efficiency until the paths reconverge.
