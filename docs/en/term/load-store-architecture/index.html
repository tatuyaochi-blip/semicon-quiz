What is Load-store architecture?

An ISA style in which only load and store instructions access memory and arithmetic works only on registers. Used by RISC-V and Arm, it gives instructions a uniform shape that is easy to pipeline.

Japanese name: ロード・ストア・アーキテクチャ

Separating memory access from computation

In a load-store architecture, only load and store instructions can read or write memory, and operations such as add and compare work between registers. For example, adding variables b and c in memory and writing the result to a takes four instructions in RISC-V: lw to load b and c into registers, add to sum them, and sw to store the result to a. By contrast, designs such as x86, where an arithmetic instruction like "add eax, [mem]" can read memory directly, are called register-memory architectures, the opposite approach.

Why it suits pipelining

Because arithmetic instructions never touch memory, every instruction accesses memory at most once, and instruction formats and processing flow are uniform. In the classic five-stage pipeline (fetch, decode, execute, memory access, write-back), only loads and stores use the memory-access stage; other instructions pass straight through it. Apart from instruction fetch, memory-related exceptions such as translation failures and page faults can arise only from loads and stores, which simplifies exception handling. Fixed-length instructions are also easier to adopt, making decoding simple.

Register count and code size

Because values are placed in registers before being operated on, load-store ISAs generally have many general-purpose registers: RISC-V has 32 integer registers and Arm's 64-bit instruction set (AArch64) has 31 general-purpose registers. Compilers allocate frequently used values to registers to reduce loads and stores. On the other hand, instruction counts rise and code tends to grow, so there are short instruction formats to improve code density, such as RISC-V's C extension (compressed instructions) and Arm's Thumb.

Relation to CISC and exceptional instructions

Load-store design is a hallmark of RISC, adopted by RISC-V, Arm, MIPS, Power and others. Even register-memory x86 CPUs today internally split arithmetic instructions that read memory into load and compute micro-operations, so at the execution level they look much like a load-store machine. Load-store ISAs do, however, include atomic instructions that read a memory value, operate on it and write it back (such as the AMO instructions of RISC-V's A extension), provided as an exception for multicore synchronization.

Answer: B. Only load and store instructions access memory; arithmetic is done between registers

In a load-store architecture, a memory value is first loaded into a register, arithmetic such as add or compare is done between registers, and results are written back to memory with a store if needed. Because arithmetic instructions never touch memory, instructions have a uniform shape and are easy to pipeline. This contrasts with designs like x86, where an arithmetic instruction such as "add eax, [mem]" can read memory.

FAQ

What is a load-store architecture?

It is an instruction-set style in which only load and store instructions access memory and all arithmetic is done between registers. RISC-V and Arm are leading examples, and the uniform instruction shape makes pipelining easier.

Does load-store architecture mean the same as RISC?

No. Load-store describes how memory is accessed, while RISC is a broader design philosophy that also includes simple instructions, fixed-length encoding and more. Because many RISC designs adopt the load-store approach, however, the two are often discussed together.

Is x86 a load-store architecture?

Not as an instruction set: it is a register-memory architecture in which arithmetic instructions can read and write memory directly. Today's x86 CPUs, however, internally split such instructions into load, compute and store micro-operations.
