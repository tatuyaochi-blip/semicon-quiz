What is Stack frame?

The area reserved on the stack each time a function is called. It holds the return address, saved registers and local variables and is freed when the function returns.

Japanese name: スタックフレーム

Try it: questions about Stack frame

A function that calls no other functions (a leaf function) often does not need to save ra on the stack. Why?

  1. ABecause leaf functions do not use the ret instruction
  2. BBecause the CPU automatically pushes the return address of leaf functions
  3. CBecause it calls no one, ra is never overwritten and the return address stays intact
Show answer and explanation

Answer: C. Because it calls no one, ra is never overwritten and the return address stays intact

Every jal overwrites ra, so a function that calls others must first save its own return address on the stack. A leaf function never executes jal, so ra stays intact and it can ret without saving it. If it also avoids callee-saved registers, it does not even need a stack frame. x86's call instruction always pushes the return address on the stack, which is a difference from RISC-V.

What is the purpose of executing "addi sp, sp, -16" at the start of a RISC-V function?

  1. ATo grow the stack toward lower addresses and reserve a 16-byte work area
  2. BTo free 16 bytes on the stack
  3. CTo subtract 16 from sp and return it as the result
Show answer and explanation

Answer: A. To grow the stack toward lower addresses and reserve a 16-byte work area

By the convention of many ISAs, RISC-V included, the stack grows from higher toward lower addresses. Subtracting 16 from sp makes the 16 bytes between the new sp and the old one this function's stack frame, where the return address, saved registers and local variables can be kept. At the end, "addi sp, sp, 16" restores sp and frees the area, returning to the state before the call.
