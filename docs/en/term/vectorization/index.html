What is Vectorization?

Transforming a loop that performs the same computation on each element so that SIMD instructions process several elements at once. It requires no data dependence between iterations.

Japanese name: ベクトル化

Vectorization appears in 4 practice questions across 2 topics, including Compilers, Memory Hierarchy.

Field: Compilers

How a loop becomes SIMD code

SIMD (single instruction, multiple data) instructions operate on several values packed into one wide register. A 128-bit register holds four 32-bit numbers, so one SIMD add replaces four scalar adds, and 256-bit or 512-bit units do eight or sixteen. A vectorizing compiler rewrites a loop so each iteration of the new loop handles one register's worth of elements. When the trip count is unknown at compile time or not a multiple of the vector width, it adds a scalar remainder loop, or uses masked operations, for the leftover elements.

What blocks vectorization

The key requirement is that iterations be independent. A loop such as a[i] = a[i-1] + b[i] has a loop-carried dependence, because each element needs the previous result, so several elements cannot be computed at once. Possible aliasing is another obstacle: if two pointers might refer to overlapping memory, the compiler must either add a run-time overlap check or give up; C's restrict qualifier promises no overlap. Non-contiguous or indirect accesses, function calls the compiler cannot inline, and complex control flow also reduce or prevent vectorization.

Reductions and floating-point order

Summing an array into one variable is itself a dependence, yet compilers vectorize it by keeping several partial sums in the vector lanes and combining them at the end. For integers the result is identical. For floating-point numbers it is not guaranteed, because every addition rounds, so (a + b) + c can differ slightly from a + (b + c). Under strict settings the compiler therefore keeps the original order and may not vectorize such reductions; options such as fast-math allow reassociation in exchange for tiny numerical differences.

Data layout: AoS vs. SoA

Memory layout often decides whether vectorized code is fast. In an array of structures (AoS), each record stores x, y, z and mass together, so a loop that reads only x uses a quarter of every 64-byte cache line it fetches. In a structure of arrays (SoA), all x values are contiguous: every fetched line is fully used, memory traffic drops to about a quarter, and a single vector load picks up consecutive x values without gather instructions. Changing the layout does not change numerical results.

Answer: B. SIMD instructions handling multiple data at once

Automatic vectorization finds loops that perform the same computation on each array element and replaces them with SIMD instructions that process several elements at once. A 128-bit SIMD register can add four 32-bit numbers simultaneously, potentially cutting the loop's operation count to a quarter. Conditions include no dependences between iterations and contiguous data, and possible pointer overlap can cause the compiler to give up. Interrupt or cache-management instructions are unrelated.

FAQ

What is the difference between vectorization and multithreading?

Vectorization speeds up a single thread by using SIMD instructions that process several data elements per instruction. Multithreading runs separate instruction streams on different cores, and the two are routinely combined.

Why won't my compiler vectorize a loop?

Common reasons are a dependence between iterations, possible pointer aliasing, non-contiguous memory access, calls to functions that cannot be inlined, or a floating-point reduction that would require reordering additions under strict settings. Most compilers can print a vectorization report explaining their decision.

Can vectorization change floating-point results?

Element-wise operations give the same results, but vectorized reductions add numbers in a different order, and because floating-point addition is not associative the final sum can differ in the last bits.
