What is Asynchronous FIFO?

A FIFO written and read on separate clocks, used to pass multi-bit data between clock domains. Its pointers are converted to Gray code before being synchronized into the other domain to decide full and empty. The pointers have one more bit than the address to distinguish wrap-around.

Japanese name: 非同期FIFO

How an asynchronous FIFO is built

An asynchronous FIFO is a dual-port memory written on the sender's clock and read on the receiver's clock. The write pointer lives in the write domain and the read pointer in the read domain. Each pointer is passed through a synchronizer into the opposite domain: the write side compares its own pointer with the synchronized read pointer to generate full, and the read side compares its pointer with the synchronized write pointer to generate empty. The data itself is never synchronized; it sits stable in memory until the pointers say it may be read.

Why pointers are Gray coded

A binary counter can flip many bits at once, such as 0111 to 1000, and bits synchronized separately may resolve in different cycles, producing a value unrelated to either. In Gray code only one bit changes per increment, so even if that bit is caught mid-change the receiver sees either the old or the new pointer, just possibly one step stale. Depth is normally a power of two so the sequence wraps cleanly. The pointer bits should not simply be declared false paths: a maximum-delay constraint keeps their skew within one sending period.

Telling full from empty

With 16 entries, a 4-bit address cannot distinguish an empty FIFO from one that has wrapped all the way round, because both show equal addresses. Adding a fifth lap bit solves this. In binary, all five bits equal means empty, and only the MSB differing means full. In Gray code the full condition becomes the top two bits inverted and the lower three equal; for a read pointer of 00000, full is 11000. Because each side sees a stale copy of the other pointer, full and empty may be held slightly too long but are never released too early, so it errs safe.

Sizing the depth

Depth must absorb the rate mismatch during a burst. If the writer sends 100 words at 100 MHz and the reader drains one word per cycle at 80 MHz, the burst lasts 1000 ns, the reader removes 80 words, and 20 remain, which follows from burst × (1 − read rate / write rate). Real designs add a few entries for the two-to-three-cycle pointer synchronization latency. Compared with a req/ack handshake, which needs eight or more cycles per item, an asynchronous FIFO sustains one word per cycle and is the standard choice for streaming data.

  3. CBecause Gray-coded signals do not go metastable, so synchronization becomes unnecessary

Answer: B. Because only one bit changes per increment, so even if captured mid-change the result is the correct value from before or after the increment

A binary pointer can change multiple bits at once, as in 0111 to 1000, so synchronizing each bit separately can yield a completely unrelated value. With Gray code only one bit changes per increment, so even if that bit goes metastable and resolves to either the old or new value, the result is the value from before or after the increment. The receiver merely sees a slightly stale value, so the FIFO does not break. The number of bits does not change, and metastability itself can still occur, so synchronizers are still required.

In a 16-word-deep asynchronous FIFO, why are the write and read pointers made 5 bits, one bit more than the address?

  1. ABecause 5 bits are needed to represent the addresses of 16 words
  2. BSo that when the pointers match, empty (same lap) can be distinguished from full (one lap apart)
  3. CTo use the extra bit as parity for detecting pointer errors
Show answer and explanation

Answer: B. So that when the pointers match, empty (same lap) can be distinguished from full (one lap apart)

The addresses of 16 words fit in 4 bits, but with 4-bit pointers alone, when the read and write addresses match it is impossible to tell whether the FIFO is empty because everything has been read, or full because writing has gone a full lap and caught up. Adding a fifth bit that indicates the lap means that, comparing in binary, the FIFO is empty when all 5 bits match and full when only the MSB differs. With Gray code pointers, the comparison for full is slightly different. The bit is not used as parity.

FAQ

Why does an asynchronous FIFO use Gray code pointers?

Only one bit changes per increment, so a pointer sampled mid-change by the other clock still resolves to a valid value from just before or after the increment. A binary pointer could be captured as a completely wrong value and corrupt full or empty.

Why is the FIFO pointer one bit wider than the address?

The extra bit counts laps. When the addresses match, equal lap bits mean empty and different lap bits mean the writer has gone a full lap ahead, which means full.

Asynchronous FIFO or handshake for clock domain crossing?

Use a handshake for occasional transfers such as configuration registers, where a cost of eight or more cycles per item is acceptable. Use an asynchronous FIFO when data must flow continuously at up to one word per cycle.
