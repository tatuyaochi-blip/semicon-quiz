What is Testbench?

Simulation-only code that drives inputs to the design under test and checks its outputs. Since it is never synthesized, delays, display statements and similar can be used freely.

Japanese name: テストベンチ

Try it: questions about Testbench

Which describes a testbench used in HDL verification?

  1. AFactory equipment for manufacturing circuits
  2. BA simulation-only description that drives inputs to the circuit under test and checks whether outputs are correct; it is not synthesized
  3. CAn instrument for measuring circuit power
Show answer and explanation

Answer: B. A simulation-only description that drives inputs to the circuit under test and checks whether outputs are correct; it is not synthesized

A testbench is HDL code that instantiates the design under test (DUT), generates clocks, resets and input signals, and observes outputs. Because it is never synthesized, it can freely use simulation-only features such as delays, file I/O and display statements. It sometimes takes as much effort as the design itself, or more.

In a testbench, changing a design input with a blocking assignment at the same instant as the rising clock edge can cause problems. Which pairs the reason with a fix correctly?

  1. AWhether the design captures the old or new value depends on execution order (a race); change inputs away from the clock edge or with nonblocking assignments
  2. BThe clock frequency automatically drops; make the clock faster
  3. CBlocking assignments are not allowed in testbenches; use assign everywhere
Show answer and explanation

Answer: A. Whether the design captures the old or new value depends on execution order (a race); change inputs away from the clock edge or with nonblocking assignments

When the testbench updates an input at the same instant the design's flip-flops sample it, the captured value can be old or new depending on which the simulator executes first. This is a simulation race, and results may even differ between simulators. It is prevented by changing inputs on the falling edge or slightly after the edge, or by using nonblocking assignments or SystemVerilog clocking blocks.
