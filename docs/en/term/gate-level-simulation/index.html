What is Gate-level simulation?

Simulation of the post-synthesis or post-layout netlist, optionally with delay information, to catch problems invisible at RTL.

Japanese name: ゲートレベルシミュレーション

Gate-level simulation appears in 1 practice question across 1 topic, including HDL & Verification.

Field: HDL & Verification

How it differs from RTL simulation

Gate-level simulation (GLS) runs the netlist produced by logic synthesis or place-and-route together with simulation models of the standard cells. RTL simulation checks the behavior as written, whereas GLS checks how the gates and flip-flops actually created are connected and how they behave. It can therefore reveal cases where the synthesis tool interpreted the description differently from the designer's intent, and verify circuitry that did not exist in the RTL, such as scan chains and clock-gating cells.

Zero-delay and timing GLS

There are two broad kinds of GLS. Zero-delay GLS, which treats all delays as zero, mainly checks logical behavior, reset and initialization, and how unknown values (X) propagate. Timing GLS back-annotates each cell's and wire's delay onto the netlist using an SDF (Standard Delay Format) file output by a static timing analysis (STA) tool or similar. The cell models contain built-in setup and hold checks, so a violation produces a warning and drives the flip-flop output to X. Delays are generally checked at several corners, such as slow and fast conditions.

Typical problems GLS finds

In RTL simulation, unknown values can be treated optimistically, for example an if statement taking one branch when its condition is X, hiding problems with uninitialized registers (X-optimism). GLS tends to expose such missing resets and power-up unknowns. It is also used to check mismatches between simulation and synthesis caused by incomplete sensitivity lists or synthesis directives, the connections of test circuitry such as scan chains, the behavior of asynchronous paths, and errors in timing constraints (such as a path that must work in one cycle being declared an exception).

Division of labor with STA and formal verification

Timing is checked exhaustively across all paths by static timing analysis, and logical equivalence between RTL and netlist by equivalence checking (formal verification), so GLS is not the only safeguard. GLS is far slower than RTL simulation, and the larger the circuit the longer it takes, so it is generally limited to selected tests such as reset and boot sequences, test patterns and representative functional tests. Cell models may also propagate unknowns pessimistically, spreading X where there is no real problem (X-pessimism), so results need careful interpretation.

Answer: B. To check issues invisible in RTL simulation, such as initialization or reset bugs, synthesis differences and delay-related problems

RTL simulation is fast but cannot reveal unknown-value problems hidden by X-optimism, or cases where synthesis produced a circuit different from the description. Gate-level simulation exercises the actual gates and flip-flops, and with each gate's and wire's delay supplied in SDF format, delay-related problems also show up. It is very slow, so it is generally run on a limited set of tests.

FAQ

What is gate-level simulation?

It is simulation of the gate-level netlist produced after logic synthesis or place-and-route. With delays supplied through SDF as needed, it checks for problems invisible in RTL simulation, such as initialization bugs, differences introduced by synthesis and timing-related issues.

Why is GLS needed when there is STA?

STA computes delays and exhaustively checks them against constraints, but it does not check how the circuit actually behaves. Constraint mistakes, asynchronous paths, reset and initialization problems, and test-circuit behavior can be caught by GLS, which actually exercises the circuit.

What is SDF?

SDF stands for Standard Delay Format, a file format describing cell and wire delays, timing-check values and the like. It is output by STA tools and similar and back-annotated onto the netlist in gate-level simulation to run timing simulation.
