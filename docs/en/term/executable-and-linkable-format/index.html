What is Executable and Linkable Format (ELF)?

The file format used for object files, executables and shared libraries on Linux and other UNIX-like systems and in embedded devices.

Japanese name: ELF

What is inside an ELF file

An Executable and Linkable Format (ELF) file starts with an ELF header beginning with the magic bytes 0x7F followed by the letters E, L and F. The header records whether the file is 32- or 64-bit, its byte order, the target CPU, the file type and the entry point address where execution begins. The same format covers relocatable object files produced by the compiler, executables, shared libraries and core dumps. After the header come a program header table, the contents themselves and a section header table describing each section.

Sections vs. segments

ELF offers two views of the same bytes. The linker works with fine-grained sections such as .text for code, .rodata for constants, .data for initialized variables and .bss for zero-initialized variables, which takes no space in the file and is zero-filled at load time. The loader works with segments listed in the program headers, which group sections by permission: .text and .rodata typically go into a read-execute segment, .data and .bss into a read-write one. Grouping by permission makes it simple to set page-level memory protection.

How ELF supports linking and loading

Object files carry symbol tables and relocation entries that tell the linker which addresses to patch when code and data are combined. Dynamically linked executables name an interpreter, the dynamic loader, in a program header, and include a dynamic section listing required shared libraries; calls into those libraries usually go through a procedure linkage table (PLT) and global offset table (GOT) so addresses can be resolved at run time. Debug information is stored in additional sections that tools can strip. Embedded toolchains often output ELF and then convert it to a raw binary or hex file for flashing.

ELF vs. PE and Mach-O

Linux, the BSDs and many embedded systems use ELF, Windows uses the Portable Executable (PE) format for .exe and .dll files, and macOS and iOS use Mach-O. The underlying ideas of code and data regions, symbols, relocations and dynamic-linking information are similar, but the formats differ, and so do the system call interfaces and libraries the programs expect. That is why a compiled program does not run unchanged on a different operating system even on the same CPU.

ELF has two views. The linker combines and relocates in units of fine-grained sections such as .text, .rodata, .data and .bss. The loader maps memory in units of segments described by the program headers, grouping, for example, .text and .rodata into a read-execute segment and .data and .bss into a read-write segment. Grouping by permission makes page-level protection easy to set up.

FAQ

What does ELF stand for?

ELF stands for Executable and Linkable Format, the standard file format for object files, executables and shared libraries on Linux and many other UNIX-like and embedded systems.

What is the difference between sections and segments in ELF?

Sections are fine-grained units such as .text and .data that the linker combines and relocates. Segments, described by program headers, group sections with the same permissions into the units the loader maps into memory.

Can an ELF executable run on Windows?

Not natively. Windows expects the PE format and its own system interfaces, so an ELF program needs a compatibility layer, a virtual machine running Linux, or recompilation for Windows.
