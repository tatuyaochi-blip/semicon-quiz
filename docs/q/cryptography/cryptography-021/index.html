暗号技術の基礎と応用

認証を行わないディフィー・ヘルマン鍵交換の弱点と、その対策の組み合わせとして正しいものはどれか。

  1. A盗聴者が公開値を見るだけで、共有の秘密を計算できてしまう。対策は、p と g を秘密にして、送る値を通信路で盗聴されないようにすること
  2. B途中にいる攻撃者が、それぞれの相手と別々に鍵交換をする中間者攻撃を防げない。対策は、公開値に証明書の鍵で署名して相手を確かめること
  3. C秘密の値 a と b が毎回同じになり、共有の秘密も変わらない。対策は、鍵交換を1回だけにして、同じ秘密を長く使い続けること
答えと解説を見る

正解：B. 途中にいる攻撃者が、それぞれの相手と別々に鍵交換をする中間者攻撃を防げない。対策は、公開値に証明書の鍵で署名して相手を確かめること

この鍵交換は、受け取った公開値が本当に相手から来たものかを確かめません。そのため、途中にいる攻撃者は、Aさんとは自分の値で、Bさんとも自分の値で別々に鍵交換をして、両方の通信を復号しながら中継できます(中間者攻撃)。TLSでは、サーバが鍵交換の内容に証明書の秘密鍵で署名し、クライアントがそれを証明書で確かめることで、この攻撃を防いでいます。p と g は公開してよい値で、秘密にする必要はありません。

  • A. 公開値だけから共有の秘密を求めるには、離散対数問題を解く必要があります。p と g は公開してよい値です。
  • B. 正しい。鍵交換そのものは相手を確かめないので、署名と証明書による認証を組み合わせます。
  • C. a と b は毎回新しく選べます。同じ秘密を長く使い続けると、漏えいしたときの影響がむしろ大きくなります。

暗号技術の基礎と応用のほかの問題

  1. NIST SP 800-57 の表で、128ビットの共通鍵暗号(AES-128)と同程度の安全性の目安とされる、RSA暗号の鍵長(n のビット数)と楕円曲線暗号の鍵長の組み合わせはどれか。
  2. TLSで、サーバの証明書の秘密鍵が後で漏えいしても、それ以前に記録された通信は復号されないという性質(前方秘匿性)が得られる鍵交換の方法はどれか。
  3. ECDSAのデジタル署名では、署名ごとに秘密の乱数 k を使う。k の扱いについての説明として、正しいものはどれか。
  4. ブラウザがWebサーバの証明書を検証するときの、証明書チェーンについての説明として正しいものはどれか。
  5. TLSの証明書の検証では、署名のチェーンと有効期間を確かめるだけでなく、接続しようとしたホスト名が証明書のSAN(サブジェクト代替名)に含まれるかも確かめる。この確認が欠かせない理由として、正しいものはどれか。
