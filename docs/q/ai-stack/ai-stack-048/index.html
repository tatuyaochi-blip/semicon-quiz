AIハードウェアとソフトウェアスタック

大規模言語モデルの推論を速くする「投機的デコーディング」の考え方として正しいものはどれか。

  1. A答えをランダムに推測して、そのまま出力する
  2. B小さなモデルで数トークン先まで下書きし、大きなモデルでそれらをまとめて1回で検証して、合っている分を一度に採用する
  3. C大きなモデルの層を半分に減らして使う
答えと解説を見る

正解：B. 小さなモデルで数トークン先まで下書きし、大きなモデルでそれらをまとめて1回で検証して、合っている分を一度に採用する

デコードはメモリ律速なので、大きなモデルで1トークンを計算しても数トークンをまとめて計算しても、重みを読む時間はほとんど同じです。そこで、軽い小さなモデルで次の数トークンを予想し、大きなモデルはそれらを1回の順伝播でまとめて確かめ、合っていた分を一度に採用します。予想がよく当たれば、大きなモデルの呼び出しの回数が減って、出力の質を変えずに速くなります。

  • A. 推測した答えは必ず大きなモデルで確かめます。
  • B. 正しい。結果は大きなモデル単独の場合と同じにできます。
  • C. 大きなモデルはそのまま使います。

AIハードウェアとソフトウェアスタックのほかの問題

  1. 推薦システムのモデルなどで使われる大きな埋め込み表(エンベディングテーブル)の表引きが、AIのハードウェアで扱いにくい理由として正しいものはどれか。
  2. AIのソフトウェアスタックを、利用者に近い上の層からハードウェアに近い下の層へ並べたものとして正しいものはどれか。
  3. ニューラルネットワークの「学習」と「推論」の違いとして正しいものはどれか。
  4. 学習に必要なメモリが、同じモデルの推論よりずっと大きくなる理由として当てはまらないものはどれか。
  5. パラメータ数70億(7B)のモデルを、重み・勾配・Adamの2つの状態をすべてFP32(4バイト)で持って学習する。活性化を除いて必要なメモリに最も近いものはどれか。
