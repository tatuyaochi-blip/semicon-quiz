サイバー攻撃と防御の実務

外部のセキュリティの研究者が、ある企業の製品に未公表の脆弱性を見つけた。協調された脆弱性の開示(Coordinated Vulnerability Disclosure)の考え方に沿った進め方として、最も適切なものはどれか。

  1. A利用者に早く知らせるため、見つけた日のうちに、攻撃の方法も含めて詳しくインターネットで公表する
  2. B開発元に報告すれば十分なので、修正が出た後も、脆弱性があったことは利用者に知らせずにおく
  3. C開発元(または調整を行う機関)に非公開で報告し、修正を準備する期間を調整したうえで、修正の公開と合わせて脆弱性の情報を公表する
答えと解説を見る

正解：C. 開発元(または調整を行う機関)に非公開で報告し、修正を準備する期間を調整したうえで、修正の公開と合わせて脆弱性の情報を公表する

修正が出る前に詳しい情報を公表すると、攻撃者が先に悪用でき、利用者は守る手段がないまま危険にさらされます。協調された開示では、発見者が開発元に非公開で報告し、開発元が修正を用意するまでの期間を両者で調整して、修正の公開と合わせて情報を公表します(90日などの期限を決めて進めることが多くあります)。日本では、IPAとJPCERT/CCが調整する「情報セキュリティ早期警戒パートナーシップ」の制度があり、調整した脆弱性の情報はJVNで公表されます。企業が報告者に報奨金を払うバグバウンティの制度も、報告の窓口と規則をあらかじめ示すことで、協調された開示を促します。

  • A. 修正の前に攻撃の方法まで公表すると、利用者が守る手段のないまま、攻撃者に悪用されます。
  • B. 利用者が修正を適用すべきかを判断できるよう、修正と合わせて脆弱性の情報も公表します。
  • C. 正しい。非公開での報告、期間の調整、修正と合わせた公表が基本の流れです。

サイバー攻撃と防御の実務のほかの問題

  1. SBOM(ソフトウェア部品表)を作って管理する主な目的として、正しいものはどれか。
  2. ある企業は、社内のパッケージの置き場(プライベートレジストリ)に、社内専用のライブラリ acme-utils を置いて使っている。攻撃者が、公開のパッケージの置き場に、同じ名前 acme-utils でより大きな版番号のパッケージを登録したところ、ビルドの設定によっては、社内のビルドの環境が攻撃者のパッケージを取り込んでしまうことが分かった。この「依存関係の混乱(dependency confusion)」への対策として、最も適切なものはどれか。
  3. 2020年12月に発覚したSolarWinds社の事件では、IT管理用のソフトウェアのビルドの環境に攻撃者が入り込み、正規の更新プログラムに不正なコードが混ぜられた。この更新は、開発元の正規のコード署名が付いた状態で配布された。この事件から得られる教訓として、最も適切なものはどれか。
  4. クラウドのオブジェクトストレージに置いた顧客の情報のファイルが、インターネットの誰からでも読み出せる状態になっていたことが分かった。このような情報の漏えいの典型的な原因と、再発を防ぐ対策の組み合わせとして、適切なものはどれか。
  5. クラウドの上で動くバッチの処理に、すべての操作を許可した管理者の権限のアクセスキー(長期間有効な認証情報)を、設定ファイルに書いて渡していた。このキーが漏えいしたときの被害を小さくするための見直しとして、最も適切なものはどれか。
