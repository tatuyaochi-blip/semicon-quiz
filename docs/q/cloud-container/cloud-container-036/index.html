クラウドとコンテナの基礎

本番と同じ構成の環境を2つ用意し、一方で現在の版を動かしたまま、もう一方に新しい版を入れて確かめてから、ロードバランサの向き先を一度に切り替える。問題があれば、向き先を戻してすぐに元の版に戻す。このリリースの方法はどれか。

  1. Aブルーグリーンデプロイメント
  2. Bカナリアリリース
  3. Cローリングアップデート
答えと解説を見る

正解：A. ブルーグリーンデプロイメント

ブルーグリーンデプロイメントは、2つの環境(ブルーとグリーン)を用意し、利用者の通信を一度に新しい環境へ切り替える方法です。古い環境はしばらくそのまま残すので、問題が起きても切り替えを戻すだけで元の版に戻せます。一方、切り替えの前後は2つの環境の分の資源が必要で、データベースの構造の変更は、新旧どちらの版からも使える形にしておく必要があります。カナリアリリースは一部の要求にだけ新しい版を出す方法、ローリングアップデートはサーバを少しずつ入れ替える方法です。

  • A. 正しい。2つの環境を用意し、向き先を一度に切り替えます。
  • B. カナリアリリースは、まず一部の要求だけを新しい版に送り、様子を見ながら割合を増やす方法です。
  • C. ローリングアップデートは、1つの環境の中のサーバやPodを、少しずつ新しい版に入れ替える方法です。

クラウドとコンテナの基礎のほかの問題

  1. 1時間に12,000件の要求を受けるサービスで、新しい版をカナリアリリースし、要求の5%だけを新しい版に送った。新しい版には、受けた要求の3%が失敗する不具合があり、1時間後に気づいて、すべての要求を元の版に戻した。この1時間に不具合で失敗した要求の件数として、正しいものはどれか。
  2. CI/CDのパイプラインで作ったコンテナイメージを、ステージング環境で試験し、合格した。このイメージを本番環境に出す方法として、最も適切なものはどれか。
  3. 上のように、データベースの接続先をイメージに書き込まず、コンテナを起動するときに環境変数で渡すようにした。この設計の主な利点として、最も適切なものはどれか。
  4. 複数のサービスが連携して動くシステムで、利用者の1つの要求が、どのサービスをどの順に通り、それぞれでどれだけ時間がかかったかを調べたい。オブザーバビリティのためのデータのうち、最も適したものはどれか。
  5. Linuxのコンテナを実現するカーネルの機能のうち、名前空間(namespaces)とcgroups(コントロールグループ)の役割の組み合わせとして、正しいものはどれか。
