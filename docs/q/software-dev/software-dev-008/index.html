ソフトウェア開発とプロジェクト管理

継続的デリバリーと継続的デプロイの違いの説明として、適切なものはどれか。

  1. A継続的デリバリーはソースコードの変更を共有のブランチに統合することだけを指し、ビルドやテストは含まない
  2. B継続的デプロイでは、本番環境に公開する前に必ず人が承認する
  3. C継続的デリバリーではいつでも本番環境に公開できる状態を保ち、公開は人が判断して行う。継続的デプロイでは、テストに合格した変更を自動で本番環境に公開する
答えと解説を見る

正解：C. 継続的デリバリーではいつでも本番環境に公開できる状態を保ち、公開は人が判断して行う。継続的デプロイでは、テストに合格した変更を自動で本番環境に公開する

どちらも、CIで統合してテストした変更を、ステージング環境での確認などを含む自動化されたパイプラインに流します。継続的デリバリーでは公開できる状態までを自動で用意し、本番環境に出すかどうかは人が決めます。継続的デプロイでは、その最後の公開も自動で行います。開発と運用が協力し、こうした自動化と運用からのフィードバックで、速く安全にリリースを繰り返す考え方や文化をDevOpsと呼びます。

  • A. 共有のブランチへの統合と自動のビルド・テストはCIの範囲で、継続的デリバリーはその先の公開の準備までを含みます。
  • B. 人の承認を挟むのは継続的デリバリーの方で、継続的デプロイは自動で公開します。
  • C. 正しい。違いは、本番環境への公開を人が判断するか、自動で行うかです。

ソフトウェア開発とプロジェクト管理のほかの問題

  1. ある業務システムの要件のうち、非機能要件に当たるものはどれか。
  2. UMLで、炊飯器の制御ソフトウェアのように、イベント(ボタンの押下、タイマの満了、温度の到達など)によってオブジェクトの状態がどのように変わるかを表すのに適した図はどれか。
  3. UMLで、複数のオブジェクトの間でやり取りされるメッセージ(呼出しや応答)を、時間の順に上から下へ並べて表す図はどれか。
  4. モジュールの独立性を評価するモジュール強度(凝集度)のうち、最も強度が高く、望ましいとされるものはどれか。
  5. モジュール間の結合度のうち、最も結合度が弱く、モジュールの独立性が高いものはどれか。
