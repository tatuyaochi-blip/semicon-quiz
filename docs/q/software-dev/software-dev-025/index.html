ソフトウェア開発とプロジェクト管理

規模が25 kステップ(2万5,000行)のファームウェアの結合テストで、不具合が30件見つかった。組織の過去の実績から、この工程で見つかる不具合の目安は1 kステップ当たり2〜4件とされている。この結果の評価として、最も適切なものはどれか。

  1. A不具合の密度は目安の範囲内なので、品質は計画どおりと判断する
  2. B不具合の密度は1 kステップ当たり1.2件で目安より少ないので、品質が良いと決めつけず、テストの不足(テストケースの漏れ)がないかを確かめる
  3. C不具合の密度は1 kステップ当たり1.2件で目安より少ないので、品質が非常に良いと判断し、残りのテストを省略する
答えと解説を見る

正解：B. 不具合の密度は1 kステップ当たり1.2件で目安より少ないので、品質が良いと決めつけず、テストの不足(テストケースの漏れ)がないかを確かめる

不具合の密度は 30件 ÷ 25 kステップ = 1 kステップ当たり1.2件で、目安の2〜4件を下回っています。目安より少ないときは、作りが良かった可能性もありますが、テストケースが仕様を十分に網羅していない、テストの観点が偏っているなど、テストの不足で不具合を見つけきれていない可能性があります。そのため、テストの網羅の状況や不具合の内容を分析してから評価します。目安より多いときは、設計や実装の品質に問題がないかを調べます。

  • A. 1 kステップ当たり1.2件で、目安の2〜4件の範囲外です。
  • B. 正しい。目安より少ないときは、テストの不足を疑って確かめます。
  • C. 少ない理由がテストの不足かもしれないので、確かめずにテストを省くのは危険です。

ソフトウェア開発とプロジェクト管理のほかの問題

  1. Gitで、2人の開発者が同じファイルの同じ行をそれぞれ別のブランチで書き換え、一方のブランチをもう一方にマージした。このとき起こることとして、適切なものはどれか。
  2. 設計書やソースコードのレビューの方法のうち、モデレータ(進行役)が主導し、参加者の役割を決め、チェックリストなどを使って公式に行い、見つけた欠陥を記録して修正まで確認するものはどれか。
  3. 正しく動くことが分かっているファームウェアの版の後に1,000個のコミットがあり、最新のコミットでは不具合が起こる。不具合はある1つのコミットで入り、それ以降のコミットではすべて起こるとする。git bisect のように二分探索で原因のコミットを特定するとき、ビルドしてテストする回数の最大値はどれか。
  4. プロジェクトの成果物と作業を階層的に分解したWBSで、最も下の階層にあり、所要期間やコストを見積もって担当者を割り当てる単位はどれか。
  5. 結合点を①〜⑥とし、作業を「名前: 始点→終点、所要日数」で示すと、A: ①→②、6日、B: ①→③、4日、C: ②→④、4日、D: ③→⑤、4日、E: ④→⑥、2日、F: ⑤→⑥、3日、ダミー作業: ②→③(所要日数0)となるアローダイアグラムがある。プロジェクト全体の最短の所要日数はどれか。
