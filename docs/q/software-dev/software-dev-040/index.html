ソフトウェア開発とプロジェクト管理

ITサービスマネジメントで、繰り返し起こる障害について根本原因を調べ、恒久的な対策によって再発を防ぐことを主な目的とするプロセスはどれか。

  1. Aインシデント管理
  2. B変更管理
  3. C問題管理
答えと解説を見る

正解：C. 問題管理

インシデント管理は、障害などでサービスが止まったり品質が下がったりしたときに、回避策なども使って、できるだけ早くサービスを元に戻すことを目的とします。問題管理は、インシデントの根本原因(問題)を突き止め、恒久的な対策を検討して再発を防ぐことを目的とします。対策としてシステムを変更するときは、変更管理で影響やリスクを評価し、承認してから実施します。

  • A. サービスをできるだけ早く元に戻すことが目的で、根本原因の解決は問題管理が担います。
  • B. システムへの変更を、影響やリスクを評価して承認し、管理して実施するプロセスです。
  • C. 正しい。根本原因を突き止め、恒久的な対策で再発を防ぎます。

ソフトウェア開発とプロジェクト管理のほかの問題

  1. ソフトウェア開発のウォーターフォールモデルの特徴として、適切なものはどれか。
  2. ソフトウェア開発のV字モデルで、要件定義の工程に対応し、その工程で決めた内容を満たしているかを確かめるテストはどれか。
  3. スクラムで、プロダクトバックログの項目の内容と並び順(優先順位)に責任をもち、プロダクトの価値を最大にする役割はどれか。
  4. スクラムで、スプリントの終わりに、できあがったインクリメント(動く成果物)を利害関係者に見せてフィードバックを受け、今後の方針やプロダクトバックログを見直すイベントはどれか。
  5. エクストリームプログラミング(XP)などのアジャイル開発で行われる、プログラムの外部から見た振る舞いを変えずに、内部の構造を分かりやすく変更しやすいものに整理する作業はどれか。
