OSとハードウェア

ページ置き換えのクロック方式(セカンドチャンス方式)で、各ページの参照ビットを使う目的はどれか。

  1. A最近使われたページを見分け、LRUに近い追い出しを少ない手間で行うため
  2. Bページが書き換えられたかどうかを調べ、書き戻しの要否を決めるため
  3. Cページを使っているプロセスの数を数え、多いものから追い出すため
答えと解説を見る

正解：A. 最近使われたページを見分け、LRUに近い追い出しを少ない手間で行うため

正確なLRUはアクセスのたびに順番を更新する必要があり、ページの数が多いと手間がかかります。クロック方式では、アクセスされるとハードウェアが参照ビットを1にし、OSは時計の針のようにページを順に調べて、1なら0に戻して見逃し(もう一度の機会)、0のページを追い出します。こうして最近使われたページを残す、LRUに近い置き換えを安く実現します。書き戻しの要否を決めるのはダーティビットです。

  • A. 正しい。最近の使用を参照ビットで見分け、LRUに近い置き換えをします。
  • B. 書き戻しの要否はダーティビットで判断します。
  • C. プロセスの数で追い出す方式ではありません。

OSとハードウェアのほかの問題

  1. ページ置き換えでFIFO方式を使うと、物理メモリのページ数を増やしたのにページフォルトが増える場合がある。この現象を何と呼ぶか。
  2. 物理メモリが足りず、ページの追い出しと読み込みばかりが続いて処理がほとんど進まなくなる状態を何と呼ぶか。
  3. メモリのアクセス時間が100 ns、ページフォルトの処理に8 msかかるとき、100万回に1回ページフォルトが起こると、平均のアクセス時間はおよそいくらになるか。
  4. コンテキストスイッチで、切り替える前のプロセスについて保存しておく必要があるものはどれか。
  5. プロセスのコンテキストスイッチが、レジスタの保存と復元にかかる時間よりも、実際には大きな性能の低下を招くことがある主な理由はどれか。
