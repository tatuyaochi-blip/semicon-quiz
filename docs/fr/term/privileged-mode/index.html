Qu'est-ce que Mode privilégié ?

Mode de fonctionnement du CPU réservé au noyau de l'OS. Il permet d'exécuter des instructions sensibles comme la configuration des tables de pages ou les entrées-sorties, et se distingue du mode utilisateur où tournent les applications.

Nom japonais: 特権モード

« Mode privilégié » apparaît dans 4 questions d'entraînement réparties sur 1 thèmes, dont Système d'exploitation et matériel.

Domaine: Système d'exploitation et matériel

Ce que protège le mode privilégié

Certaines opérations permettraient à un programme de prendre le contrôle de toute la machine : modifier les tables de pages ou le registre qui pointe vers elles, accéder directement aux périphériques d'entrée-sortie, désactiver les interruptions, reprogrammer le temporisateur qui permet à l'OS de reprendre la main, ou arrêter le CPU. Le processeur ne les autorise qu'en mode privilégié, aussi appelé mode noyau ou mode superviseur. Si du code exécuté en mode utilisateur en tente une, le CPU lève une exception et l'OS décide de la suite, généralement en terminant le programme.

Y entrer et en sortir

Le code utilisateur ne peut pas simplement sauter en mode privilégié. Les seules voies d'entrée sont les exceptions, les interruptions et les déroutements volontaires (traps) comme les appels système, et chacune transfère le contrôle à un point d'entrée configuré à l'avance par l'OS. Le CPU sauvegarde l'adresse de retour, le mode précédent et l'état d'activation des interruptions dans des registres dédiés. Une instruction de retour spéciale, comme sret ou mret sur RISC-V, restaure tout cela d'un coup, de sorte que l'exécution ne reprend jamais dans le code utilisateur avec les privilèges encore actifs.

Les niveaux sur les CPU réels

De nombreuses architectures ont plus de deux niveaux. RISC-V définit les modes machine, superviseur et utilisateur ; x86 a les anneaux 0 à 3, les systèmes d'exploitation utilisant principalement l'anneau 0 pour le noyau et l'anneau 3 pour les applications ; Arm utilise les niveaux d'exception EL0 à EL3. Un hyperviseur s'exécute au-dessus des noyaux invités, et lorsqu'un invité exécute une instruction privilégiée, il est dérouté vers l'hyperviseur, qui en émule l'effet. Ce schéma trap-and-emulate reprend la même idée de protection un niveau plus haut.

Mode privilégié et droits administrateur

Le mode privilégié est un état matériel du CPU, pas un compte utilisateur. Un processus lancé par un administrateur ou par l'utilisateur root s'exécute toujours en mode utilisateur ; ses droits supplémentaires sont des permissions que le noyau vérifie lorsqu'il traite les appels système de ce processus. Seul le code du noyau, et dans certains systèmes le firmware ou un hyperviseur, s'exécute en mode privilégié. La protection mémoire complète le bit de mode : les entrées des tables de pages indiquent quelles pages le mode utilisateur peut accéder.

  2. BEmpêcher les applications de manipuler arbitrairement les tables de pages et les périphériques
  3. CPermettre à un CPU d’exécuter deux instructions simultanément
Afficher la réponse et l'explication

Réponse : B. Empêcher les applications de manipuler arbitrairement les tables de pages et les périphériques

Si les applications pouvaient librement modifier les tables de pages, manipuler les périphériques d’entrée/sortie ou désactiver les interruptions, elles pourraient corrompre la mémoire d’autres programmes ou bloquer tout le système. Le CPU n’autorise donc ces instructions qu’en mode privilégié, réservé au noyau de l’OS. Toute tentative de les exécuter en mode utilisateur provoque une exception. Ce n’est pas un mécanisme de vitesse ni d’exécution simultanée.

Questions fréquentes

Quelle différence entre mode noyau et mode utilisateur ?

En mode noyau (privilégié), le CPU autorise des opérations comme la modification des tables de pages, le contrôle des périphériques et la désactivation des interruptions. En mode utilisateur, celles-ci lèvent une exception : les applications doivent donc passer par le noyau via des appels système.

Exécuter en tant que root signifie-t-il exécuter en mode noyau ?

Non. Root est un niveau de permission du système d'exploitation, et les processus root s'exécutent toujours en mode utilisateur ; seul le noyau s'exécute en mode privilégié.

Comment un programme passe-t-il en mode noyau ?

Uniquement par un déroutement, comme l'exécution d'une instruction d'appel système, ou par une exception ou une interruption, qui entrent toutes dans le noyau par des points d'entrée mis en place par l'OS.
