Qu'est-ce que ABI (interface binaire d'application) ?

Conventions au niveau du code machine permettant à des programmes et bibliothèques compilés de fonctionner ensemble : convention d'appel, taille et alignement des types de données, mode d'appel système, etc.

Nom japonais: ABI(アプリケーションバイナリインターフェース)

« ABI (interface binaire d'application) » apparaît dans 3 questions d'entraînement réparties sur 2 thèmes, dont ISA et assembleur, Éditeurs de liens, chargeurs et exécutables.

Domaine: ISA et assembleur

Ce que fixe une ABI

Une interface binaire d'application (ABI) fixe tout ce sur quoi deux morceaux de code compilé doivent s'accorder pour s'appeler sans être recompilés. Cela comprend la convention d'appel (quels registres transportent arguments et valeurs de retour, quels registres un appelé doit préserver, comment la pile est alignée et organisée), la taille et l'alignement des types de base comme int, long et les pointeurs, la disposition et le remplissage (padding) des structures, la décoration des noms C++ (name mangling), le déroulement des exceptions, le format des fichiers objets et la séquence d'instructions utilisée pour effectuer un appel système vers le système d'exploitation.

API et ABI

Une interface de programmation (API) est un contrat au niveau du source : noms de fonctions, types des paramètres et comportement tels que les voit le programmeur. Une ABI est ce même contrat après compilation. Une bibliothèque peut conserver son API tout en cassant son ABI, par exemple en ajoutant un champ à une structure publique, ce qui modifie la taille de la structure et les décalages des champs suivants. Les programmes compilent alors sans problème avec le nouvel en-tête, mais les binaires construits avec l'ancienne version lisent la mémoire de travers tant qu'ils ne sont pas recompilés. Les numéros de version des bibliothèques partagées existent en grande partie pour signaler ces ruptures d'ABI.

Une ISA, plusieurs ABI

L'architecture du jeu d'instructions (ISA) définit ce qu'exécute le processeur ; l'ABI est une convention logicielle superposée, si bien qu'une même ISA peut en avoir plusieurs. Sur x86-64, l'ABI System V utilisée par Linux passe les six premiers arguments entiers dans RDI, RSI, RDX, RCX, R8 et R9 et donne à long 64 bits, tandis que l'ABI Windows x64 utilise RCX, RDX, R8 et R9 et garde long sur 32 bits. RISC-V définit des ABI telles que ilp32, lp64 et lp64d, cette dernière passant les arguments flottants dans les registres flottants.

Garder une ABI de bibliothèque réduite

Chaque symbole exporté par une bibliothèque partagée fait partie de son ABI et doit rester compatible. Les fonctions exportées peuvent aussi être remplacées par un symbole de même nom dans un autre module ; même les appels internes à la bibliothèque doivent donc passer par la table de liaison des procédures (PLT) ou la table globale des décalages (GOT). Marquer les fonctions internes avec une visibilité cachée (hidden) les retire de l'interface publique : l'éditeur de liens dynamique a moins de symboles à résoudre, les appels internes deviennent des appels directs relatifs au PC, les collisions de noms avec d'autres bibliothèques sont évitées, et la bibliothèque reste libre de modifier ces fonctions plus tard.

Réponse : C. Un contrat au niveau du langage machine permettant de lier des programmes entre eux, couvrant la convention d'appel, la taille et l'alignement des types de données, etc.

L'ABI est un contrat au niveau du langage machine permettant à des programmes et bibliothèques compilés de fonctionner ensemble ; il comprend la convention d'appel, la taille de int, long et des pointeurs, l'alignement des structures, la manière d'invoquer les appels système, etc. L'API définit l'usage des fonctions au niveau du code source ; même avec la même API, si l'ABI diffère, une bibliothèque ne peut être utilisée sans recompilation. Pour une même ISA RISC-V, l'ABI peut différer selon l'OS ou l'usage.

Questions fréquentes

Quelle est la différence entre une API et une ABI ?

Une API est l'interface au niveau du code source avec laquelle le programmeur écrit son code, tandis qu'une ABI est l'accord au niveau binaire sur les registres, la disposition des données et la séquence d'appel dont dépend le code compilé. Conserver l'API mais changer l'ABI oblige à recompiler les programmes dépendants.

Pourquoi une mise à jour de bibliothèque peut-elle casser des programmes non modifiés ?

Si la mise à jour change l'ABI, par exemple la taille d'une structure ou les types des arguments d'une fonction, les binaires existants utilisent toujours l'ancienne disposition et transmettent les données sous une forme erronée. Le source peut compiler sans changement, mais les programmes déjà construits échouent tant qu'ils ne sont pas recompilés.

La convention d'appel fait-elle partie de l'ABI ?

Oui. La convention d'appel, qui précise où vont les arguments et les valeurs de retour et quels registres chaque partie doit préserver, est l'un des éléments centraux d'une ABI.
