Qu'est-ce que Temps CPU ?

Durée totale pendant laquelle le CPU a exécuté les instructions du programme. Elle exclut les temps d'attente et peut dépasser le temps écoulé (horloge murale) en cas d'exécution parallèle.

Nom japonais: CPU時間

« Temps CPU » apparaît dans 3 questions d'entraînement réparties sur 3 thèmes, dont Analyse des performances, Semi-conducteurs automobiles et sécurité fonctionnelle, Multicœur et synchronisation.

Domaine: Analyse des performances

Temps CPU et temps écoulé

Le temps écoulé (horloge murale), aussi appelé temps réel, est ce qu'un utilisateur attend du début à la fin, y compris le temps passé à attendre le disque, le réseau ou des verrous et les tranches de temps accordées à d'autres programmes. Le temps CPU ne compte que le temps pendant lequel un processeur a effectivement exécuté le programme. Sur les systèmes de type Unix, la commande time affiche les deux : real est le temps écoulé, tandis que user et sys répartissent le temps CPU entre le code propre du programme et le travail du noyau effectué pour son compte, comme les appels système.

Interpréter le rapport

Comparer les deux valeurs montre où passe le temps. Si le temps écoulé est bien supérieur au temps CPU pour un programme monothread, celui-ci passe surtout son temps à attendre, typiquement des E/S ou des verrous, et un processeur plus rapide n'aidera guère. Si le temps CPU est proche du temps écoulé, le programme est limité par le calcul. Avec plusieurs threads s'exécutant en parallèle, le temps CPU total peut dépasser le temps écoulé : quatre threads occupés chacun pendant 10 s donnent environ 40 s de temps CPU pour environ 10 s de temps écoulé.

L'équation de performance du CPU

En architecture des ordinateurs, le temps CPU d'un programme s'écrit nombre d'instructions × CPI (nombre moyen de cycles d'horloge par instruction) × période d'horloge, ou de manière équivalente nombre d'instructions × CPI ÷ fréquence d'horloge. L'équation sépare les contributions du compilateur et du jeu d'instructions (nombre d'instructions), de la microarchitecture (CPI) et de la technologie des circuits (fréquence d'horloge). Elle montre aussi pourquoi améliorer un facteur au détriment d'un autre, par exemple augmenter la fréquence alors que le CPI se dégrade, peut ne pas rendre un programme plus rapide.

Le temps CPU comme budget

Du temps CPU occupé n'est pas toujours du travail utile. Un thread qui boucle en attente active sur un verrou détenu longtemps brûle du temps CPU sans rien faire et, sur un seul cœur, il peut même retarder le détenteur du verrou jusqu'à la fin de sa tranche de temps ; les longues attentes appellent un mutex qui met le thread en sommeil. Dans les systèmes temps réel et automobiles, le temps CPU est alloué et surveillé par tâche, et le partitionnement temporel garantit qu'une tâche défaillante de criticité inférieure ne peut pas consommer le temps d'exécution dont le logiciel critique pour la sécurité a besoin.

Questions fréquentes

Pourquoi le temps CPU est-il supérieur au temps réel ?

Le programme a utilisé plusieurs threads ou processus s'exécutant simultanément sur différents cœurs, et le temps CPU additionne le temps passé sur chacun d'eux. Quatre threads pleinement occupés, par exemple, accumulent environ quatre secondes de temps CPU par seconde de temps écoulé.

Que signifient real, user et sys dans la commande time ?

real est le temps écoulé (horloge murale), user est le temps CPU passé dans le code propre du programme, et sys est le temps CPU que le noyau a consacré pour son compte, par exemple au traitement des appels système.

Le temps CPU inclut-il l'attente des E/S ?

Non. Pendant qu'un programme attend le disque ou le réseau, il ne s'exécute pas ; ce temps apparaît donc dans le temps écoulé mais pas dans le temps CPU.
