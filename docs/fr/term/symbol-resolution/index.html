Qu'est-ce que Résolution des symboles ?

Traitement de l'éditeur de liens qui associe les noms de fonctions et de variables référencés dans un fichier à leur définition située ailleurs. En l'absence de définition, on obtient une erreur de référence indéfinie ; avec plusieurs définitions, une erreur de définition multiple.

Nom japonais: シンボル解決

« Résolution des symboles » apparaît dans 2 questions d'entraînement réparties sur 1 thèmes, dont Éditeurs de liens, chargeurs et exécutables.

Domaine: Éditeurs de liens, chargeurs et exécutables

Ce que fait la résolution des symboles

Chaque fichier objet contient une table des symboles qui recense les noms qu'il définit, comme les fonctions et les variables globales, et les noms qu'il référence sans les définir. Si main.c appelle sum et que sum.c la définit, main.o enregistre une référence indéfinie à sum et sum.o une définition. La résolution des symboles est l'étape de l'éditeur de liens qui rassemble toutes les tables des symboles et associe chaque référence à exactement une définition. Elle précède la relocalisation, qui écrit ensuite les adresses finales de ces définitions dans les instructions et les données qui y font référence.

Définitions manquantes et multiples

S'il n'existe aucune définition pour une référence, l'éditeur de liens signale une référence indéfinie (undefined reference), généralement parce qu'un fichier source ou une bibliothèque n'a pas été lié ou qu'un nom est mal orthographié. Si deux définitions globales non static portent le même nom, il signale une erreur de définition multiple, car il ne peut pas décider à laquelle lier les références. Déclarer une fonction static lui donne une liaison interne, ce qui la masque aux autres fichiers et permet de réutiliser le même nom. Une déclaration comme extern int count; ne réserve aucun stockage et promet simplement qu'une définition existe ailleurs.

Symboles faibles et ordre des bibliothèques

Un symbole faible (weak) est une définition de repli, utilisée uniquement s'il n'existe aucune définition ordinaire (forte) de même nom ; le code embarqué emploie ce procédé pour les gestionnaires d'interruption par défaut. Les bibliothèques statiques sont des archives de fichiers objets, et l'éditeur de liens GNU traite ses entrées de gauche à droite, n'extrayant un membre de bibliothèque que s'il définit un symbole indéfini à cet instant. Une commande comme gcc -lmylib main.o échoue donc, car rien dans main.o n'est encore non résolu au moment où la bibliothèque est parcourue. Les bibliothèques se placent après les fichiers qui les utilisent.

Noms C++ et édition de liens dynamique

L'éditeur de liens associe les symboles uniquement par leurs chaînes de noms. C++ autorise les fonctions surchargées comme print(int) et print(double) ; le compilateur encode donc les types des arguments et les espaces de noms dans le nom du symbole, ce qu'on appelle la décoration des noms (name mangling). C ne décore pas les noms, si bien que le code C++ déclare les fonctions C avec extern "C" pour que les noms correspondent. Avec les bibliothèques partagées, une partie de la résolution des symboles est différée : l'éditeur de liens dynamique lie les références aux fonctions de bibliothèque au chargement ou au premier appel, généralement via des stubs PLT et des entrées de la GOT.

Si main.c appelle la fonction sum et que sum.c en définit le contenu, main.o contient l'information « référence sum » et sum.o l'information « définit sum ». L'éditeur de liens rassemble les tables des symboles de tous les fichiers objets et trouve, pour chaque référence, une définition correspondante unique. Si aucune définition n'est trouvée, l'erreur « référence non définie » survient ; s'il y en a deux ou plus, l'erreur « définition multiple ».

Questions fréquentes

Qu'est-ce qui provoque une erreur undefined reference ?

L'éditeur de liens a trouvé une référence à une fonction ou une variable, mais aucune définition dans les fichiers objets ou bibliothèques liés, souvent parce qu'un fichier ou une bibliothèque manque dans la commande d'édition de liens, est listé dans le mauvais ordre, ou qu'un nom ne correspond pas.

Quelle est la différence entre résolution des symboles et relocalisation ?

La résolution des symboles détermine à quelle définition renvoie chaque nom référencé. La relocalisation inscrit ensuite les adresses réelles de ces définitions dans le code machine et les données qui les utilisent.

Comment corriger une erreur de définition multiple ?

Assurez-vous que chaque fonction ou variable globale non static est définie dans un seul fichier source, utilisez des déclarations extern dans les en-têtes et marquez static les éléments propres à un fichier pour que leurs noms n'entrent pas en collision.

« Résolution des symboles » dans les explications

  • L'éditeur de liens associe chaque nom (symbole) référencé dans les fichiers objets à l'entité qui le définit quelque part (résolution des symboles), dispose le code et les données de chaque fichier pour fixer les adresses définitives, et remplace les adresses provisoires dans les instructions par les valeurs correctes (relocalisation).
