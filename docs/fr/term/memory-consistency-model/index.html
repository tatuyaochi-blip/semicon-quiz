Qu'est-ce que Modèle de cohérence mémoire ?

Ensemble de règles définissant dans quel ordre les lectures et écritures d'un cœur à plusieurs adresses peuvent être observées par les autres cœurs. Exemples : cohérence séquentielle, TSO de x86, modèles faibles d'ARM et de RISC-V.

Nom japonais: メモリ一貫性モデル

« Modèle de cohérence mémoire » apparaît dans 3 questions d'entraînement réparties sur 1 thèmes, dont Multicœur et synchronisation.

Domaine: Multicœur et synchronisation

S'entraîner : questions sur Modèle de cohérence mémoire

Que définit un modèle de cohérence mémoire (memory consistency model) ?

  1. ALa taille des lignes et le nombre d’ensembles du cache
  2. BLe type de transistor utilisé pour la DRAM de la mémoire principale
  3. CDans quel ordre les lectures et écritures d’un cœur sur plusieurs adresses peuvent être vues par les autres cœurs
Afficher la réponse et l'explication

Réponse : C. Dans quel ordre les lectures et écritures d’un cœur sur plusieurs adresses peuvent être vues par les autres cœurs

Pour les performances, le CPU peut réordonner les opérations mémoire, par exemple en accumulant les écritures dans un tampon d’écriture (store buffer) ou en anticipant les lectures. Il est conçu pour que le résultat ne change pas au sein d’un cœur, mais les autres cœurs peuvent voir l’ordre modifié. Le modèle de cohérence mémoire définit quels réordonnancements peuvent survenir et constitue le contrat qui permet au programmeur d’écrire une synchronisation correcte.

Quelle est la caractéristique du modèle de cohérence mémoire de x86 (TSO, Total Store Order) ?

  1. AC’est le modèle le plus faible, qui autorise tous les réordonnancements de lectures et écritures
  2. BC’est la cohérence séquentielle elle-même, qui n’autorise aucun réordonnancement
  3. CC’est un modèle relativement fort, qui autorise uniquement qu’une lecture d’une autre adresse suivant une écriture soit vue avant celle-ci
Afficher la réponse et l'explication

Réponse : C. C’est un modèle relativement fort, qui autorise uniquement qu’une lecture d’une autre adresse suivant une écriture soit vue avant celle-ci

En TSO, l’ordre entre écritures, l’ordre entre lectures et l’ordre d’une écriture suivant une lecture sont préservés ; seule une lecture d’une autre adresse suivant une écriture peut la devancer. Ce modèle traduit directement l’existence du tampon d’écriture. Dans ce cadre, la plupart des programmes se comportent de façon intuitive, si bien que les barrières sont relativement rarement nécessaires sur x86.
