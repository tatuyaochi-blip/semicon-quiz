Qu'est-ce que Fichier objet ?

Fichier produit par le compilateur à partir d'un fichier source. Il contient le code machine, les valeurs initiales des données, la table des symboles et les informations de relocalisation, mais les adresses des autres fichiers n'y sont pas résolues : il n'est exécutable qu'après édition de liens.

Nom japonais: オブジェクトファイル

« Fichier objet » apparaît dans 5 questions d'entraînement réparties sur 2 thèmes, dont Éditeurs de liens, chargeurs et exécutables, Compilateurs.

Domaine: Éditeurs de liens, chargeurs et exécutables

Ce que contient un fichier objet

Un fichier objet est organisé en sections. La section text contient le code machine ; la section data contient les variables inscriptibles initialisées ; une section de données en lecture seule contient les constantes et les littéraux de chaînes ; et la section bss n'enregistre que la taille des variables initialisées à zéro, si bien qu'elle n'occupe aucune place dans le fichier. À côté de ces sections, la table des symboles recense chaque nom que le fichier définit et chaque nom qu'il utilise sans le définir, et les entrées de relocalisation recensent chaque emplacement dont l'adresse devra être renseignée plus tard. Les informations de débogage sont facultatives. Les formats courants sont ELF sous Linux, Mach-O sous macOS et COFF/PE sous Windows.

Pourquoi il ne peut pas s'exécuter seul

Le compilateur ou l'assembleur construit chaque fichier objet isolément, en disposant ses sections comme si elles commençaient à l'adresse 0. Lorsque le code appelle une fonction d'un autre fichier, comme printf, son adresse est inconnue : l'instruction contient donc une valeur provisoire, souvent 0, accompagnée d'une entrée de relocalisation décrivant ce qui doit y figurer. Seul l'éditeur de liens voit ensemble tous les fichiers objets et toutes les bibliothèques. Il associe chaque symbole non défini à une définition, décide où chaque section résidera en mémoire, corrige les valeurs provisoires et ajoute le code de démarrage et les en-têtes dont le système d'exploitation a besoin pour charger un programme.

Erreurs d'édition de liens typiques et leur signification

Une erreur comme undefined reference to foo signifie qu'un fichier objet utilise foo mais que rien dans l'édition de liens ne le définit. Les causes courantes sont l'oubli de lier le fichier qui le définit, l'omission d'une option de bibliothèque comme -lm, une faute de frappe dans le nom, ou l'appel de code C depuis du C++ sans extern "C", ce qui rend les noms différents après la décoration de noms (name mangling) du C++. L'erreur inverse, multiple definition, vient généralement de la définition d'une variable dans un en-tête inclus par plusieurs fichiers source. Avec l'éditeur de liens GNU, les bibliothèques statiques doivent apparaître sur la ligne de commande après les fichiers objets qui les utilisent.

Fichiers objets, bibliothèques statiques et bibliothèques partagées

Une bibliothèque statique n'est qu'une archive de fichiers objets. L'éditeur de liens n'en extrait que les membres qui résolvent des symboles encore non définis, ce qui explique l'importance de l'ordre sur la ligne de commande. Une bibliothèque partagée est différente : c'est déjà le résultat d'une édition de liens, construite à partir de code indépendant de la position, et elle est projetée en mémoire à l'exécution, les adresses restantes étant renseignées par l'éditeur de liens dynamique. Des outils comme nm, objdump et readelf affichent les sections, les symboles et les entrées de relocalisation d'un fichier objet, et constituent le moyen le plus rapide de comprendre pourquoi une édition de liens échoue.

  3. CÉcrire la bibliothèque en premier efface son contenu

Réponse : A. L'éditeur de liens traite de gauche à droite et n'extrait pas les fonctions qui ne sont pas encore référencées au moment où il lit la bibliothèque

L'éditeur de liens GNU traite les fichiers dans l'ordre de la ligne de commande et, lorsqu'il rencontre une bibliothèque statique, n'en extrait que les objets résolvant « des références dont la définition n'a pas encore été trouvée ». Si la bibliothèque vient en premier, les références de main.o n'existent pas encore à ce moment, rien n'est extrait, et il ne revient pas en arrière après avoir lu main.o. Le principe est donc d'écrire les bibliothèques après ceux qui les utilisent.

Questions fréquentes

Quelle différence entre un fichier objet et un exécutable ?

Un fichier objet contient le code machine d'un seul fichier source, mais laisse non résolues les références aux autres fichiers et n'a pas d'adresses définitives. Un exécutable est le produit de l'éditeur de liens : tous les symboles y sont résolus, les adresses fixées, et des en-têtes indiquent au système d'exploitation comment le charger.

Comment lister les symboles d'un fichier objet ?

Utilisez nm, objdump -t ou readelf -s. Dans la sortie de nm, les symboles marqués U sont non définis : le fichier y fait référence et s'attend à ce qu'un autre fichier objet ou une bibliothèque les définisse.

Qu'est-ce que la section bss ?

Elle contient les variables globales et statiques dont la valeur initiale est zéro. Le fichier objet n'enregistre que sa taille, et le chargeur alloue la mémoire et la remplit de zéros au démarrage du programme.
