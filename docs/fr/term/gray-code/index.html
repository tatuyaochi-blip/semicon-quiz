Qu'est-ce que Code de Gray ?

Code dans lequel un seul bit change entre deux valeurs consécutives. Utilisé dans les codeurs rotatifs et pour transférer des valeurs de compteur entre domaines d'horloge, afin d'éviter les erreurs de lecture.

Nom japonais: グレイコード

« Code de Gray » apparaît dans 12 questions d'entraînement réparties sur 4 thèmes, dont Analyse temporelle et CDC, Circuits logiques, Bases de la théorie de l'information et du codage.

Domaine: Circuits logiques

Conversion entre binaire et code de Gray

Le code de Gray usuel est le code binaire réfléchi, construit en écrivant la séquence sur n bits, en y ajoutant son image miroir, puis en préfixant 0 à la première moitié et 1 à la seconde. La conversion depuis un binaire B tient en une seule expression : G = B XOR (B >> 1), si bien que chaque bit de Gray sous le bit de poids fort est le XOR de deux bits binaires voisins. La conversion inverse se fait par un XOR cumulatif depuis le bit de poids fort : le bit de tête est recopié, et chaque bit binaire inférieur est le XOR du bit binaire précédent et du bit de Gray courant. Sur trois bits, la séquence est 000, 001, 011, 010, 110, 111, 101, 100.

Pourquoi un seul bit qui change compte dans les codeurs

En binaire naturel, passer de 0111 à 1000 fait basculer quatre bits à la fois. Un codeur absolu rotatif ou linéaire lit chaque bit sur sa propre piste, et les transitions de ces pistes ne sont jamais parfaitement alignées : une lecture prise à la frontière peut mélanger anciens et nouveaux bits et indiquer une valeur éloignée des deux positions. Avec le code de Gray, une seule piste change à chaque pas : une lecture à la frontière ne peut donner que l'ancienne ou la nouvelle valeur, toutes deux exactes à un pas près.

Pointeurs en code de Gray dans les FIFO asynchrones

Une FIFO asynchrone transfère des données entre deux domaines d'horloge, et chaque côté doit voir le pointeur de lecture ou d'écriture de l'autre pour calculer les indicateurs plein et vide. Faire passer un pointeur binaire par des bascules de synchronisation est risqué, car plusieurs bits peuvent changer ensemble et être capturés sur des fronts d'horloge différents, produisant une valeur de pointeur qui n'a jamais existé. Un pointeur en code de Gray change d'un seul bit par incrément : même si ce bit est capturé en pleine transition, le côté récepteur obtient soit l'ancien, soit le nouveau pointeur. Cela ne fonctionne que si le pointeur avance d'une unité par cycle d'horloge et si le compteur reboucle sur une puissance de deux.

Code de Gray en mémoire flash et tableaux de Karnaugh

Les mémoires flash NAND MLC (multi-level cell) et TLC (triple-level cell) stockent deux ou trois bits sous la forme de l'un de quatre ou huit états de tension de seuil. L'usure et les interférences élargissent les distributions des états, et une erreur de lecture tombe presque toujours dans un état voisin. Attribuer les combinaisons de bits dans l'ordre de Gray, par exemple 111, 110, 100, 101, 001, 000, 010, 011 pour la TLC, transforme chacune de ces erreurs en une erreur sur un seul bit, que le code correcteur d'erreurs traite à faible coût. Les tableaux de Karnaugh utilisent le même ordre sur leurs axes, afin que des cases physiquement adjacentes ne diffèrent que d'une variable et puissent être regroupées.

Réponse : C. Un code où un seul bit change entre deux valeurs adjacentes

Le code de Gray est un code où un seul bit change toujours entre deux valeurs adjacentes ; on l'obtient à partir du binaire B par B XOR (B >> 1). Plusieurs bits ne changeant jamais simultanément, il n'y a pas de risque de lire une valeur intermédiaire erronée, que ce soit pour la détection de position par codeur rotatif ou pour le transfert des pointeurs de FIFO entre circuits cadencés par des horloges différentes. Les cases du tableau de Karnaugh sont aussi disposées dans l'ordre du code de Gray. Représenter chaque chiffre décimal sur 4 bits correspond au BCD.

Dans une FIFO asynchrone, quelle est la raison correcte pour laquelle on convertit les pointeurs d'écriture et de lecture en code de Gray avant de les synchroniser vers l'autre domaine ?

  1. AParce que le code de Gray divise par deux le nombre de bits et réduit le nombre de synchroniseurs
  2. BParce qu'un seul bit change à chaque incrément, si bien que même une capture en plein changement donne une valeur correcte, celle d'avant ou celle d'après l'incrément
  3. CParce que les signaux en code de Gray ne deviennent pas métastables, ce qui rend la synchronisation inutile
Afficher la réponse et l'explication

Réponse : B. Parce qu'un seul bit change à chaque incrément, si bien que même une capture en plein changement donne une valeur correcte, celle d'avant ou celle d'après l'incrément

Avec un pointeur binaire, plusieurs bits changent en même temps, comme de 0111 à 1000 ; si chaque bit est synchronisé séparément, on peut recevoir une valeur sans aucun rapport. En code de Gray, un seul bit change par incrément : même si ce bit devient métastable et se résout vers l'ancienne ou la nouvelle valeur, le résultat est la valeur d'avant ou d'après l'incrément. On voit simplement une valeur un peu ancienne, et la FIFO n'est pas corrompue. Le nombre de bits ne change pas, et la métastabilité elle-même peut toujours survenir : les synchroniseurs restent nécessaires.

Questions fréquentes

Comment convertir un nombre binaire en code de Gray ?

Faites le XOR du nombre binaire avec lui-même décalé d'un bit vers la droite : G = B XOR (B >> 1). Le bit de poids fort reste inchangé, et chaque autre bit de Gray est le XOR de deux bits binaires adjacents.

Pourquoi les pointeurs de FIFO sont-ils codés en Gray pour le passage entre domaines d'horloge ?

Un pointeur en code de Gray ne change que d'un bit par incrément : un synchroniseur qui l'échantillonne pendant une transition fournit quand même l'ancienne ou la nouvelle valeur. Un pointeur binaire peut changer de nombreux bits à la fois et être capturé avec une valeur complètement fausse.

Quelle est la différence entre le code de Gray et le BCD ?

Le code de Gray est un ordonnancement de motifs binaires dans lequel deux valeurs successives ne diffèrent que d'un bit. Le BCD (décimal codé binaire) code chaque chiffre décimal séparément sur quatre bits et ne possède pas cette propriété de changement d'un seul bit.
