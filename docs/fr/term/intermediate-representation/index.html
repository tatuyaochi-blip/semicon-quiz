Qu'est-ce que Représentation intermédiaire ?

Forme interne au compilateur représentant le programme indépendamment du langage source et du CPU. La plupart des optimisations s'y effectuent, ce qui sépare le front-end propre au langage du back-end propre au CPU.

Nom japonais: 中間表現

Domaine: Compilateurs

Pourquoi les compilateurs utilisent une RI

Prendre en charge M langages source sur N processeurs avec des compilateurs séparés en nécessiterait M × N. Avec une représentation intermédiaire (RI, ou IR) partagée, chaque langage n'a besoin que d'un front-end qui traduit vers la RI, et chaque processeur que d'un back-end qui traduit depuis elle, soit M + N éléments au total. Les optimisations écrites une seule fois sur la RI profitent alors à tous les langages et à toutes les cibles. LLVM en est l'exemple le plus connu : des front-ends comme Clang émettent de la LLVM IR, et des back-ends génèrent du code pour x86, Arm, RISC-V et d'autres cibles.

Les formes courantes

Les compilateurs utilisent souvent plusieurs niveaux de RI. Près du source se trouve un arbre syntaxique abstrait. Plus bas, le code à trois adresses décompose les expressions en étapes simples comme t1 = a + b; x = t1 * c, avec des temporaires pour les valeurs intermédiaires. Ces instructions sont regroupées en blocs de base reliés par un graphe de flot de contrôle. De nombreuses RI modernes, dont la LLVM IR, utilisent la forme SSA (static single assignment), où chaque variable est affectée exactement une fois et où des nœuds phi spéciaux fusionnent les valeurs là où les chemins de contrôle se rejoignent.

Ce qui se passe sur la RI

La plupart des passes d'optimisation s'exécutent sur la RI : propagation de constantes, élimination du code mort, élimination des sous-expressions communes, sortie des calculs invariants hors des boucles et inlining de fonctions. La forme SSA simplifie beaucoup d'entre elles, car chaque utilisation renvoie à exactement une définition. L'optimisation à l'édition de liens (LTO) stocke de la RI au lieu du code machine dans les fichiers objets afin que l'ensemble du programme puisse être optimisé globalement, ce qui permet l'inlining et la suppression des fonctions mortes entre fichiers source.

RI, bytecode et code machine

La RI interne d'un compilateur est une forme de travail destinée à l'analyse et à la transformation ; le CPU ne peut pas l'exécuter, et le back-end doit encore sélectionner les instructions, allouer les registres et ordonnancer le code. Les bytecodes portables, comme le bytecode Java ou WebAssembly, sont apparentés mais servent un autre but : ce sont des formats de distribution stables qu'une machine virtuelle interprète ou compile à la volée (JIT), alors que les RI internes peuvent changer d'une version de compilateur à l'autre.

  2. BLe CPU pouvant l'exécuter telle quelle, la génération de code machine devient inutile
  3. CElle sépare la partie avant propre à chaque langage de la partie arrière propre à chaque CPU, et les optimisations peuvent être partagées

Réponse : C. Elle sépare la partie avant propre à chaque langage de la partie arrière propre à chaque CPU, et les optimisations peuvent être partagées

Pour prendre en charge M langages et N CPU, un compilateur par combinaison en exigerait M×N ; avec une représentation intermédiaire commune, M parties avant (frontend) du langage vers l'IR et N parties arrière (backend) de l'IR vers le CPU suffisent. La plupart des optimisations, réalisées une fois sur l'IR, profitent à tous les langages et CPU. L'IR n'est pas directement exécutable par le CPU et doit finalement être convertie en code machine.

Quelle caractéristique d'une représentation intermédiaire en forme SSA est correcte ?

  1. AChaque variable n'est affectée qu'exactement une fois dans le programme
  2. BToutes les variables sont placées en mémoire et non en registres
  3. CLe programme est réécrit sans aucune instruction de branchement conditionnel
Afficher la réponse et l'explication

Réponse : A. Chaque variable n'est affectée qu'exactement une fois dans le programme

En forme SSA, les variables sont renommées pour n'être affectées qu'une fois, et aux points de jonction une fonction φ choisit la valeur. Par exemple, une variable x affectée deux fois est scindée en x1 et x2, ce qui rend explicite laquelle est utilisée. Les relations définition-utilisation étant claires, les optimisations comme la propagation de constantes ou l'élimination de code mort sont facilitées. Les branchements étant traités par les fonctions φ, les instructions de branchement ne disparaissent pas. Les variables ne sont pas non plus placées en mémoire ; elles sont le plus souvent traitées comme candidates aux registres.

Questions fréquentes

Qu'est-ce qu'une représentation intermédiaire dans un compilateur ?

C'est la forme dans laquelle un compilateur traduit le code source avant de générer le code machine, indépendante à la fois du langage source et du CPU cible, afin que les optimisations puissent être partagées.

Qu'est-ce que la forme SSA ?

La forme SSA (static single assignment) est une forme de RI dans laquelle chaque variable est affectée exactement une fois, des nœuds phi sélectionnant les valeurs là où le flot de contrôle se rejoint, ce qui simplifie de nombreuses optimisations.

La LLVM IR est-elle du code machine ?

Non. La LLVM IR est une représentation intermédiaire indépendante de la cible ; un back-end doit la traduire en code machine pour un processeur donné.
