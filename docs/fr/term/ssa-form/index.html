Qu'est-ce que Forme SSA ?

Forme de représentation intermédiaire où les variables sont renommées pour que chacune ne soit affectée qu'une seule fois dans le programme. Aux points de jonction, une fonction φ choisit la valeur. Les relations définition-utilisation deviennent explicites, ce qui facilite l'optimisation.

Nom japonais: SSA形式

Domaine: Compilateurs

Renommage : une définition par nom

La forme SSA (static single assignment, affectation unique statique) donne à chaque affectation son propre nom de variable. Dans du code linéaire, il s'agit simplement de renommer : x = 1; x = x + 2 devient x1 = 1; x2 = x1 + 2, et chaque utilisation ultérieure se réfère à la version qui l'atteint. Le mot statique compte : chaque nom a exactement une affectation dans le texte du programme, même si cette affectation s'exécute de nombreuses fois dans une boucle. Comme chaque utilisation a exactement une définition, les relations définition-utilisation dont les optimiseurs ont besoin sont explicites dans les noms eux-mêmes au lieu d'être calculées par une analyse séparée.

Les fonctions φ aux points de jonction

Le renommage seul échoue là où le flot de contrôle se rejoint, car la valeur de x après un if-else dépend de la branche exécutée. La SSA insère une fonction φ (phi) au début du bloc de jonction, x3 = φ(x1, x2), avec un argument par arc entrant ; elle renvoie l'argument correspondant à l'arc effectivement emprunté. Les boucles ont besoin de la même chose dans l'en-tête de boucle, pour fusionner la valeur initiale avec la valeur de l'itération précédente. Les algorithmes de construction standard ne placent des fonctions φ que là où des définitions provenant de chemins différents se rencontrent réellement, en utilisant les informations de dominance du graphe de flot de contrôle.

Pourquoi les optimiseurs apprécient la SSA

Avec une seule définition par nom, de nombreuses optimisations deviennent simples et rapides. La propagation de constantes suit simplement chaque définition jusqu'à ses utilisations ; l'élimination de code mort supprime les définitions sans utilisation ; la numérotation globale des valeurs détecte les calculs redondants en comparant les opérations portant sur les mêmes valeurs nommées. Les analyses peuvent être creuses, en suivant les arcs définition-utilisation au lieu d'itérer sur chaque point du programme. Pour ces raisons, les IR de nombreux compilateurs de production, dont LLVM IR, sont en forme SSA, généralement pour les valeurs scalaires conservées dans des registres virtuels, tandis que la mémoire est accédée par des chargements et rangements explicites.

Sortir de la SSA

Les processeurs n'ont pas d'instruction φ ; avant ou pendant l'allocation de registres, le compilateur sort donc de la forme SSA. Chaque φ est remplacée par des instructions de copie à la fin des blocs prédécesseurs, si bien que chaque chemin entrant écrit la valeur choisie dans un emplacement commun. Les arcs qui quittent un bloc à plusieurs successeurs et entrent dans un bloc à plusieurs prédécesseurs peuvent devoir être scindés pour ménager une place à ces copies. L'allocation de registres tente ensuite de fusionner les copies (coalescing), en attribuant le même registre aux deux côtés afin que la plupart d'entre elles disparaissent.

S'entraîner : questions sur Forme SSA

Quelle caractéristique d'une représentation intermédiaire en forme SSA est correcte ?

  1. AChaque variable n'est affectée qu'exactement une fois dans le programme
  2. BToutes les variables sont placées en mémoire et non en registres
  3. CLe programme est réécrit sans aucune instruction de branchement conditionnel
Afficher la réponse et l'explication

Réponse : A. Chaque variable n'est affectée qu'exactement une fois dans le programme

En forme SSA, les variables sont renommées pour n'être affectées qu'une fois, et aux points de jonction une fonction φ choisit la valeur. Par exemple, une variable x affectée deux fois est scindée en x1 et x2, ce qui rend explicite laquelle est utilisée. Les relations définition-utilisation étant claires, les optimisations comme la propagation de constantes ou l'élimination de code mort sont facilitées. Les branchements étant traités par les fonctions φ, les instructions de branchement ne disparaissent pas. Les variables ne sont pas non plus placées en mémoire ; elles sont le plus souvent traitées comme candidates aux registres.

Questions fréquentes

Que signifie SSA en compilation ?

Static single assignment, affectation unique statique. Chaque variable de l'IR est affectée en exactement un endroit du texte du programme, et des fonctions φ fusionnent les valeurs là où les chemins du flot de contrôle se rejoignent.

Comment la SSA fonctionne-t-elle avec les boucles si une variable ne peut être affectée qu'une fois ?

L'affectation unique est statique, et non dynamique. Une fonction φ dans l'en-tête de boucle fusionne la valeur qui entre dans la boucle avec la valeur calculée à l'itération précédente, et cette unique définition s'exécute à chaque itération.

Où place-t-on les fonctions φ ?

Au début des blocs où différentes définitions d'une même variable d'origine peuvent arriver par différents arcs entrants. Les algorithmes fondés sur les frontières de dominance trouvent ces points sans insérer de φ inutiles.
