Qu'est-ce que Décoration de noms (name mangling) ?

Construction par le compilateur C++ de noms de symboles intégrant les types des arguments et l'espace de noms. Elle permet à l'éditeur de liens de distinguer les fonctions surchargées.

Nom japonais: 名前修飾

« Décoration de noms (name mangling) » apparaît dans 2 questions d'entraînement réparties sur 1 thèmes, dont Éditeurs de liens, chargeurs et exécutables.

Domaine: Éditeurs de liens, chargeurs et exécutables

Ce qui est encodé

Un nom décoré regroupe dans un seul symbole d'édition de liens tout ce qui distingue des entités C++ partageant un même nom au niveau source : espaces de noms et classes englobants, nom de la fonction, types des paramètres, qualification const ou volatile des fonctions membres et arguments de template. Le type de retour est normalement omis, puisque des surcharges ne peuvent pas différer uniquement par leur type de retour, bien que les instances de templates de fonction l'incluent. Selon l'ABI C++ Itanium, utilisée par GCC et Clang sous Linux et sur de nombreuses autres plateformes, print(int) devient _Z5printi et ns::f(double) devient _ZN2ns1fEd, où chaque nom est préfixé par sa longueur et où des lettres uniques codent les types intégrés.

extern "C" et le mélange de langages

C n'a pas de surcharge ; les compilateurs C émettent donc des noms de fonctions simples. Lorsque du code C++ appelle une bibliothèque C, ses déclarations doivent être entourées d'extern "C" pour que le compilateur C++ cherche le nom non décoré ; sinon, il cherche quelque chose comme _Z3fooi, ne trouve que foo, et l'édition de liens échoue avec une référence indéfinie. Les en-têtes partagés entre les deux langages entourent généralement leurs déclarations d'extern "C", protégé par un test de la macro __cplusplus. Les fonctions déclarées extern "C" ne peuvent pas être surchargées, car deux d'entre elles correspondraient au même symbole.

Lire les noms décorés

Les noms décorés apparaissent dans la sortie de nm, le désassemblage, les rapports de plantage et les erreurs d'édition de liens. L'outil c++filt les reconvertit en déclarations lisibles, nm -C fait de même dans sa liste, et la plupart des débogueurs et éditeurs de liens les décodent automatiquement lorsqu'ils affichent des diagnostics. Savoir lire la forme brute reste utile : deux symboles qui paraissent identiques une fois décodés peuvent différer par un qualificatif const ou un type de paramètre, ce qui révèle qu'une déclaration dans un en-tête ne correspond pas à la définition réellement compilée.

La décoration fait partie de l'ABI

Chaque famille de compilateurs définit son propre schéma, et le compilateur de Microsoft utilise un codage complètement différent de celui de l'ABI Itanium. Le schéma fait partie de l'interface binaire d'application (ABI) ; les fichiers objets issus de compilateurs aux schémas différents ne peuvent donc pas être liés directement, même si le source est identique. Les modifications de l'interface C++ d'une bibliothèque, comme le changement d'un type de paramètre, modifient les noms décorés et rompent la compatibilité binaire avec les programmes construits pour l'ancienne version. D'autres langages dotés de surcharge ou de modules, comme Rust, décorent les noms pour les mêmes raisons.

S'entraîner : questions sur Décoration de noms (name mangling)

Quel est le principal objectif de la décoration de noms (mangling), par laquelle le compilateur C++ ajoute au nom d'une fonction des informations comme le type de ses arguments pour former le nom de symbole ?

  1. ARendre les noms de fonctions illisibles pour empêcher le vol du programme
  2. BRaccourcir les noms de fonctions pour réduire la taille de l'exécutable
  3. CPermettre à l'éditeur de liens de distinguer les fonctions de même nom aux types d'arguments différents (surcharge) et les espaces de noms
Afficher la réponse et l'explication

Réponse : C. Permettre à l'éditeur de liens de distinguer les fonctions de même nom aux types d'arguments différents (surcharge) et les espaces de noms

L'éditeur de liens compare les symboles uniquement par leur chaîne de nom. En C++, on peut créer des fonctions de même nom comme « print(int) » et « print(double) », impossibles à distinguer telles quelles. Le compilateur intègre donc au nom le type des arguments, etc., comme « _Z5printi ». Les fonctions C n'étant pas décorées, pour appeler une fonction C depuis C++, on ajoute « extern "C" » afin de supprimer la décoration.

Questions fréquentes

Comment décoder (demangle) un nom de symbole C++ ?

Passez-le à c++filt, par exemple echo _Z5printi | c++filt affiche print(int). nm -C et objdump -C décodent les noms lors du listage des symboles.

À quoi sert extern "C" en C++ ?

Il donne aux fonctions déclarées une liaison C, si bien que le compilateur utilise le nom simple non décoré. Cela permet au code C++ d'appeler des bibliothèques C et au code C d'appeler des fonctions C++ exportées de cette façon.

Pourquoi le type de retour ne fait-il pas partie du nom décoré d'une fonction ?

Les surcharges C++ doivent différer par leurs paramètres ; les paramètres suffisent donc à identifier la fonction. Les instances de templates de fonction font exception et codent le type de retour.
