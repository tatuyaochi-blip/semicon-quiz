Qu'est-ce que Code indépendant de la position ?

Code machine qui fonctionne sans modification quelle que soit l'adresse de chargement en mémoire. Aussi appelé PIC. Il utilise des références relatives au PC et la GOT ; employé pour les bibliothèques partagées et les PIE.

Nom japonais: 位置独立コード

Domaine: Éditeurs de liens, chargeurs et exécutables

Comment le PIC adresse le code et les données

Le code indépendant de la position (PIC) n'intègre jamais d'adresses absolues dans ses instructions. Les branchements et les appels désignent leurs cibles sous forme de distances par rapport au compteur ordinal, qui restent identiques où que soit placé le module entier. Pour les cibles plus éloignées que ce que permet le champ de branchement, RISC-V associe auipc, qui ajoute au PC un immédiat de 20 bits décalé de 12 bits vers la gauche, à jalr ou à un chargement qui fournit les 12 bits de poids faible, couvrant environ ±2 Gio autour de l'instruction courante. x86-64 offre l'adressage relatif à RIP dans le même but, ce qui rend le code indépendant de la position presque aussi rapide que du code à adresse fixe.

La GOT et la PLT

Les distances relatives au PC fonctionnent au sein d'un module, mais l'adresse d'une variable ou d'une fonction d'une autre bibliothèque partagée n'est connue qu'à l'exécution. Le PIC atteint donc ces symboles via la table globale des décalages (GOT), une table d'adresses propre à chaque module placée à une distance fixe du code. Le code charge l'adresse requise depuis la GOT, et l'éditeur de liens dynamique y inscrit les adresses réelles au chargement. Sur les systèmes ELF, les appels aux fonctions externes passent en outre par de petits stubs de la table de liaison des procédures (PLT), qui peuvent résoudre chaque fonction de façon paresseuse lors de son premier appel.

Pourquoi les bibliothèques partagées en ont besoin

Une bibliothèque partagée peut être projetée à une adresse virtuelle différente dans chaque processus qui l'utilise. Si son code contenait des adresses absolues, le chargeur devrait corriger les instructions pour chaque adresse, transformant des pages partagées en lecture seule en copies privées modifiables et annulant l'intérêt du partage. Avec le PIC, seule la petite GOT modifiable diffère d'un processus à l'autre ; les pages de code n'ont besoin d'aucune modification et une seule copie physique est projetée dans tous les processus. Cela économise de la mémoire et permet à la bibliothèque de se charger rapidement, quelle que soit l'adresse où elle atterrit.

PIC, PIE et lien avec la sécurité

Un exécutable indépendant de la position (PIE) applique la même technique au programme principal, généralement construit avec les options -fPIE et -pie de GCC ou Clang, tandis que les bibliothèques partagées utilisent -fPIC. Les anciens exécutables supposaient une adresse de chargement fixe ; la randomisation de l'espace d'adressage (ASLR) pouvait déplacer les bibliothèques et la pile, mais pas le code du programme principal, dont les adresses restaient prévisibles pour un attaquant. Un PIE peut être chargé n'importe où, si bien que son code est lui aussi randomisé, et de nombreuses distributions Linux actuelles construisent des PIE par défaut. Le coût est un léger surcoût dû à l'indirection par la GOT, nettement plus important sur x86 32 bits.

Une bibliothèque partagée peut être chargée à une adresse différente dans chaque processus. Le code indépendant de la position référence fonctions et données non par des adresses fixes, mais par leur distance au PC ou via une table regroupant les adresses (GOT). Ainsi, même si l'adresse de chargement change, les pages de code n'ont pas à être modifiées, et une seule copie en mémoire physique peut être partagée par de nombreux processus.

Questions fréquentes

Que signifie PIC ?

PIC signifie position-independent code, du code machine qui s'exécute correctement sans modification à n'importe quelle adresse de chargement. Il repose sur l'adressage relatif au PC et la table globale des décalages.

Quelle est la différence entre -fPIC et -fPIE ?

Les deux génèrent du code indépendant de la position ; -fPIC est destiné aux bibliothèques partagées, dont les symboles peuvent être remplacés par d'autres modules, tandis que -fPIE vise l'exécutable principal et peut utiliser des références directes un peu moins coûteuses vers ses propres symboles. Un exécutable compilé avec -fPIE est lié avec -pie pour produire un PIE.

Pourquoi la table globale des décalages est-elle nécessaire ?

Le code ne peut pas intégrer l'adresse d'un symbole d'un autre module, car cette adresse n'est connue qu'après le chargement. La GOT contient ces adresses, renseignées par l'éditeur de liens dynamique, et le code atteint la GOT via une référence relative au PC.
