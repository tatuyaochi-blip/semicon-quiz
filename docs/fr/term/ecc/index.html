Qu'est-ce que ECC (code correcteur d'erreurs) ?

Mécanisme qui ajoute des bits redondants aux données pour détecter et corriger les bits erronés à la lecture. Utilisé dans la mémoire serveur, la mémoire flash et à l'intérieur des puces DDR5.

Nom japonais: ECC(誤り訂正符号)

Domaine: DRAM

De la parité au SECDED

Un bit de parité unique détecte un nombre impair de bits inversés mais ne peut pas localiser l'erreur, et deux inversions s'annulent. Les codes de Hamming ajoutent plusieurs bits de parité, chacun couvrant un sous-ensemble de bits de données qui se chevauche avec les autres ; à la lecture, les vérifications recalculées forment un syndrome qui désigne un bit erroné unique, afin de pouvoir le réinverser. Un bit de parité global supplémentaire distingue une erreur simple corrigible d'une erreur double seulement détectée : c'est le SECDED (single error correction, double error detection). Protéger 64 bits de données demande 8 bits de contrôle, d'où le mot mémoire bien connu de 72 bits.

L'ECC dans les systèmes DRAM

Les modules ECC comportent des puces supplémentaires pour les bits de contrôle : neuf puces x8 forment un rang de 72 bits, et en DDR5 chaque sous-canal de 32 bits passe à 40 bits de large. Le contrôleur mémoire code à l'écriture et vérifie à la lecture. La DDR5 ajoute aussi un ECC intégré à la puce (on-die ECC), à raison de 8 bits de contrôle pour 128 bits de données dans chaque puce, mais il est invisible de l'extérieur et ne couvre pas les erreurs de transfert : il ne remplace donc pas l'ECC système. Les codes de type Chipkill survivent à la défaillance d'une puce entière, et les contrôleurs effectuent couramment un nettoyage (scrubbing) de la mémoire afin de corriger les erreurs sur un bit avant qu'une seconde ne s'accumule.

Contre quoi l'ECC protège

La cible classique est l'erreur logicielle (soft error) : des particules alpha issues des matériaux du boîtier ou des neutrons du rayonnement cosmique génèrent une charge qui inverse un bit sans endommager le composant, et le flux de neutrons augmente fortement avec l'altitude. L'ECC absorbe aussi les cellules à temps de rétention variable, les inversions occasionnelles dues au Rowhammer et les échecs d'écriture stochastiques de la STT-MRAM. Une erreur dépassant la capacité du code, comme une erreur sur 2 bits en SECDED, est signalée comme non corrigible, et le système rejette les données ou passe dans un état sûr. Journaliser les erreurs corrigées aide à repérer tôt les composants défaillants.

L'ECC au-delà de la DRAM

La flash NAND présente des taux d'erreurs binaires bruts bien plus élevés, qui augmentent avec l'usure par programmation/effacement et avec le nombre de bits par cellule : les contrôleurs utilisent donc des codes plus puissants comme BCH ou LDPC, qui corrigent de nombreux bits par bloc ; l'attribution des états selon un code de Gray limite à un bit l'erreur due à une lecture dans un état voisin. Les liaisons série utilisent une correction d'erreurs directe (FEC) lorsque la signalisation laisse peu de marge, comme avec le PAM4 du PCI Express 6.0. Dans les puces automobiles, la logique ECC est elle-même un mécanisme de sécurité, et un défaut dans celle-ci est un défaut latent que le BIST doit détecter.

S'entraîner : questions sur ECC (code correcteur d'erreurs)

Quelle fonction du code correcteur d'erreurs (ECC) utilisé dans les mémoires est correcte ?

  1. ACompresser les données pour augmenter la capacité
  2. BAjouter des bits redondants aux données pour détecter et corriger les erreurs de bits
  3. CChiffrer les données
Afficher la réponse et l'explication

Réponse : B. Ajouter des bits redondants aux données pour détecter et corriger les erreurs de bits

L'ECC ajoute aux données des bits de contrôle et détecte et corrige les erreurs à la lecture. Pour la mémoire de serveur jusqu'à la DDR4, le schéma de base ajoute 8 bits à 64 bits, corrige les erreurs d'un bit et détecte les erreurs de deux bits (SECDED) ; les modules DDR5 ajoutent 8 bits à chaque sous-canal de 32 bits. Les serveurs à haute fiabilité disposent en outre de Chipkill, capable de récupérer la défaillance complète d'une puce. La DDR5 intègre également un ECC à l'intérieur de la puce.

Combien de puces DRAM de largeur 8 bits (x8) faut-il par rang pour former un bus de données de 64 bits (sans ECC) ?

  1. A4 puces
  2. B64 puces
  3. C8 puces
Afficher la réponse et l'explication

Réponse : C. 8 puces

64 bits ÷ 8 bits = 8 : huit puces x8 accédées simultanément donnent une largeur de 64 bits. Avec des puces x4, il en faut 16, avec des x16, 4. Les modules avec ECC ajoutent les puces nécessaires aux 8 bits de contrôle, soit 9 puces x8 (72 bits de large). Les modules DDR5 sont divisés en deux sous-canaux de 32 bits ; avec ECC, chaque sous-canal fait 40 bits de large.

Questions fréquentes

Quelle différence entre mémoire ECC et ECC intégré (on-die) de la DDR5 ?

L'ECC intégré corrige les erreurs sur un bit à l'intérieur de chaque puce DRAM et ne fournit que des données corrigées, tandis que la mémoire ECC ajoute des puces supplémentaires pour que le contrôleur mémoire vérifie le mot entier, y compris les erreurs survenant sur le bus. Les serveurs s'appuient sur cette dernière, même avec la DDR5.

Un ECC SECDED peut-il corriger une erreur sur 2 bits ?

Non. Il corrige toute erreur sur un bit et détecte, sans pouvoir la corriger, une erreur sur 2 bits, qui est signalée comme non corrigible. Des codes plus puissants fondés sur des symboles, comme Chipkill, sont nécessaires pour survivre aux défaillances multibits d'une même puce.

Combien de bits de contrôle une mémoire ECC utilise-t-elle pour 64 bits de données ?

Le SECDED standard utilise 8 bits de contrôle pour 64 bits de données, si bien que chaque mot fait 72 bits de large. C'est pourquoi un module ECC construit avec des puces x8 comporte neuf puces par rang au lieu de huit.
