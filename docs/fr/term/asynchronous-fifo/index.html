Qu'est-ce que FIFO asynchrone ?

FIFO écrite et lue sur des horloges distinctes, utilisée pour transmettre des données multibits entre domaines d'horloge. Ses pointeurs sont convertis en code de Gray avant d'être synchronisés dans l'autre domaine pour déterminer les états plein (full) et vide (empty). Les pointeurs ont un bit de plus que l'adresse pour distinguer le rebouclage.

Nom japonais: 非同期FIFO

Domaine: Analyse temporelle et CDC

Comment est construite une FIFO asynchrone

Une FIFO asynchrone est une mémoire double port écrite sur l'horloge de l'émetteur et lue sur l'horloge du récepteur. Le pointeur d'écriture réside dans le domaine d'écriture et le pointeur de lecture dans le domaine de lecture. Chaque pointeur passe par un synchroniseur vers le domaine opposé : le côté écriture compare son propre pointeur au pointeur de lecture synchronisé pour générer full, et le côté lecture compare son pointeur au pointeur d'écriture synchronisé pour générer empty. Les données elles-mêmes ne sont jamais synchronisées ; elles restent stables en mémoire jusqu'à ce que les pointeurs indiquent qu'elles peuvent être lues.

Pourquoi les pointeurs sont en code de Gray

Un compteur binaire peut inverser de nombreux bits à la fois, par exemple de 0111 à 1000, et des bits synchronisés séparément peuvent se résoudre à des cycles différents, produisant une valeur sans rapport avec l'une ou l'autre. En code de Gray, un seul bit change à chaque incrément ; même si ce bit est capturé en plein changement, le récepteur voit soit l'ancien soit le nouveau pointeur, au pire avec un pas de retard. La profondeur est normalement une puissance de deux afin que la séquence reboucle proprement. Les bits de pointeur ne doivent pas simplement être déclarés faux chemins (false paths) : une contrainte de retard maximal maintient leur skew dans une période d'émission.

Distinguer plein et vide

Avec 16 entrées, une adresse de 4 bits ne peut pas distinguer une FIFO vide d'une FIFO qui a fait un tour complet, car les deux montrent des adresses égales. L'ajout d'un cinquième bit de tour résout ce problème. En binaire, les cinq bits égaux signifient vide, et seul le MSB différent signifie plein. En code de Gray, la condition de plein devient les deux bits de poids fort inversés et les trois bits inférieurs égaux ; pour un pointeur de lecture de 00000, plein correspond à 11000. Comme chaque côté voit une copie retardée du pointeur de l'autre, full et empty peuvent être maintenus un peu trop longtemps mais ne sont jamais relâchés trop tôt : l'erreur va dans le sens de la sécurité.

Dimensionner la profondeur

La profondeur doit absorber l'écart de débit pendant une rafale. Si l'écrivain envoie 100 mots à 100 MHz et que le lecteur en retire un mot par cycle à 80 MHz, la rafale dure 1 000 ns, le lecteur retire 80 mots et il en reste 20, ce qui découle de rafale × (1 − débit de lecture / débit d'écriture). Les conceptions réelles ajoutent quelques entrées pour la latence de synchronisation des pointeurs de deux à trois cycles. Comparée à une poignée de main req/ack, qui nécessite huit cycles ou plus par élément, une FIFO asynchrone soutient un mot par cycle et constitue le choix standard pour les flux de données.

S'entraîner : questions sur FIFO asynchrone

Dans une FIFO asynchrone, quelle est la raison correcte pour laquelle on convertit les pointeurs d'écriture et de lecture en code de Gray avant de les synchroniser vers l'autre domaine ?

  1. AParce que le code de Gray divise par deux le nombre de bits et réduit le nombre de synchroniseurs
  2. BParce qu'un seul bit change à chaque incrément, si bien que même une capture en plein changement donne une valeur correcte, celle d'avant ou celle d'après l'incrément
  3. CParce que les signaux en code de Gray ne deviennent pas métastables, ce qui rend la synchronisation inutile
Afficher la réponse et l'explication

Réponse : B. Parce qu'un seul bit change à chaque incrément, si bien que même une capture en plein changement donne une valeur correcte, celle d'avant ou celle d'après l'incrément

Avec un pointeur binaire, plusieurs bits changent en même temps, comme de 0111 à 1000 ; si chaque bit est synchronisé séparément, on peut recevoir une valeur sans aucun rapport. En code de Gray, un seul bit change par incrément : même si ce bit devient métastable et se résout vers l'ancienne ou la nouvelle valeur, le résultat est la valeur d'avant ou d'après l'incrément. On voit simplement une valeur un peu ancienne, et la FIFO n'est pas corrompue. Le nombre de bits ne change pas, et la métastabilité elle-même peut toujours survenir : les synchroniseurs restent nécessaires.

Dans une FIFO asynchrone de 16 mots de profondeur, quelle est la raison correcte pour laquelle les pointeurs d'écriture et de lecture ont 5 bits, soit 1 bit de plus que l'adresse ?

  1. AParce qu'il faut 5 bits pour représenter les adresses de 16 mots
  2. BPour pouvoir distinguer, lorsque les pointeurs sont égaux, l'état vide (même tour) de l'état plein (un tour d'écart)
  3. CPour utiliser le bit supplémentaire comme parité et détecter les erreurs de pointeur
Afficher la réponse et l'explication

Réponse : B. Pour pouvoir distinguer, lorsque les pointeurs sont égaux, l'état vide (même tour) de l'état plein (un tour d'écart)

Les adresses de 16 mots s'expriment sur 4 bits, mais avec des pointeurs de 4 bits seulement, lorsque les adresses de lecture et d'écriture coïncident, on ne peut pas distinguer l'état vide, où tout a été lu, de l'état plein, où l'écriture a fait un tour complet et rattrapé la lecture. En ajoutant un 5e bit qui indique le tour, on peut, en comparaison binaire, conclure à l'état vide si les 5 bits coïncident, et à l'état plein si seul le bit de poids fort diffère. Avec des pointeurs en code de Gray, la comparaison pour détecter l'état plein change légèrement. Le bit n'est pas utilisé comme parité.

Questions fréquentes

Pourquoi une FIFO asynchrone utilise-t-elle des pointeurs en code de Gray ?

Un seul bit change à chaque incrément ; un pointeur échantillonné en plein changement par l'autre horloge se résout donc quand même en une valeur valide, juste avant ou juste après l'incrément. Un pointeur binaire pourrait être capturé comme une valeur totalement fausse et corrompre full ou empty.

Pourquoi le pointeur de FIFO a-t-il un bit de plus que l'adresse ?

Le bit supplémentaire compte les tours. Lorsque les adresses sont égales, des bits de tour égaux signifient vide, et des bits de tour différents signifient que l'écrivain a pris un tour complet d'avance, c'est-à-dire plein.

FIFO asynchrone ou poignée de main pour le franchissement de domaines d'horloge ?

Utilisez une poignée de main pour des transferts occasionnels, comme des registres de configuration, où un coût de huit cycles ou plus par élément est acceptable. Utilisez une FIFO asynchrone lorsque les données doivent circuler en continu, jusqu'à un mot par cycle.
