Qu'est-ce que Graphe de flot de contrôle ?

Graphe représentant le flux d'exécution d'un programme, avec les blocs de base comme nœuds et les branchements entre blocs comme arcs. Utilisé pour détecter les boucles et analyser le flot de données.

Nom japonais: 制御フローグラフ

« Graphe de flot de contrôle » apparaît dans 3 questions d'entraînement réparties sur 1 thèmes, dont Compilateurs.

Domaine: Compilateurs

Les blocs de base comme nœuds

Un graphe de flot de contrôle (CFG) se construit à partir de blocs de base : des suites maximales d'instructions dans lesquelles on n'entre que par la première instruction et dont on ne sort que par la dernière. Pour les former, le compilateur marque les instructions de tête (leaders), à savoir la première instruction d'une fonction, chaque cible de branchement et chaque instruction qui suit immédiatement un branchement. Chaque bloc s'étend d'une instruction de tête jusqu'à la suivante. Comme les instructions d'un bloc s'exécutent toujours dans l'ordre, les optimisations locales comme l'élimination des sous-expressions communes s'appliquent facilement au sein d'un bloc.

Les arcs et ce que révèle la forme du graphe

Les arcs représentent les transferts de contrôle possibles : un branchement conditionnel donne à un bloc deux successeurs, la cible du saut et le bloc suivant en séquence (fall-through), tandis qu'un saut inconditionnel n'en donne qu'un. De nombreuses analyses ajoutent un nœud d'entrée et un nœud de sortie uniques. La forme du graphe révèle la structure. Un bloc d domine un bloc n si tout chemin de l'entrée à n passe par d, et un arc dont la cible domine la source est un arc arrière (back edge) qui identifie une boucle. Les blocs inaccessibles depuis l'entrée sont du code mort qui peut être supprimé.

Analyse de flot de données sur le CFG

De nombreuses optimisations reposent sur des analyses de flot de données qui propagent des informations le long des arcs du CFG et itèrent jusqu'à ce que plus rien ne change. L'analyse de vivacité (liveness) procède à rebours pour déterminer, en chaque point, quelles valeurs peuvent encore être lues plus tard, et son résultat sert à construire le graphe d'interférence utilisé pour l'allocation de registres. L'analyse des définitions atteignantes (reaching definitions) procède vers l'avant pour déterminer quelles affectations peuvent fournir la valeur d'une variable. La forme SSA (static single assignment), utilisée par la plupart des compilateurs modernes, se construit aussi sur le CFG, en insérant des fonctions phi là où des chemins de flot de contrôle se rejoignent.

CFG et graphe d'appels

Un CFG décrit le flot à l'intérieur d'une seule fonction, alors qu'un graphe d'appels a pour nœuds des fonctions entières et pour arcs les appels ; l'analyse interprocédurale utilise les deux. Les CFG apparaissent aussi hors des compilateurs. La couverture des branches en test vérifie si chaque arc du CFG a été exécuté, les outils d'analyse binaire reconstruisent les CFG à partir du code machine, et les défenses d'intégrité du flot de contrôle (CFI) restreignent les sauts indirects aux arcs autorisés par le CFG, bloquant les attaques qui redirigent l'exécution vers du code non prévu.

S'entraîner : questions sur Graphe de flot de contrôle

Dans un graphe de flot de contrôle, quelle combinaison de ce que représentent nœuds et flèches est correcte ?

  1. ALes nœuds sont les variables, les flèches l'ordre des affectations
  2. BLes nœuds sont les blocs de base, les flèches les branchements et transitions entre blocs
  3. CLes nœuds sont les fonctions, les flèches les inclusions entre fichiers
Afficher la réponse et l'explication

Réponse : B. Les nœuds sont les blocs de base, les flèches les branchements et transitions entre blocs

Le graphe de flot de contrôle a pour nœuds les blocs de base et pour flèches les transitions possibles d'un bloc vers ceux qui peuvent lui succéder (les deux destinations d'un branchement conditionnel, ou le passage direct au bloc suivant). Il sert à repérer les boucles par les flèches arrière ou à analyser d'où à où parviennent les valeurs des variables. Les relations d'appel entre fonctions sont représentées par un graphe d'appels distinct, et les inclusions de fichiers n'ont rien à voir.

Questions fréquentes

Qu'est-ce qu'un bloc de base dans un graphe de flot de contrôle ?

Une séquence linéaire d'instructions avec une seule entrée en haut et une seule sortie en bas, de sorte que si sa première instruction s'exécute, toutes s'exécutent dans l'ordre.

Comment trouver les boucles dans un graphe de flot de contrôle ?

Calculez les dominateurs et recherchez les arcs arrière, c'est-à-dire les arcs dont la cible domine la source ; chaque arc arrière définit une boucle naturelle dont l'en-tête est son bloc cible.

Quelle différence entre graphe de flot de contrôle et graphe d'appels ?

Un graphe de flot de contrôle montre les chemins possibles entre blocs de base au sein d'une fonction, tandis qu'un graphe d'appels montre quelles fonctions appellent quelles autres fonctions.
