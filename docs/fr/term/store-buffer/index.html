Qu'est-ce que Tampon d'écriture (store buffer) ?

Petit tampon dans lequel un cœur accumule temporairement ses écritures. Il permet de passer à l'instruction suivante sans attendre la fin de l'écriture, mais les autres cœurs voient les écritures avec un retard.

Nom japonais: ストアバッファ

« Tampon d'écriture (store buffer) » apparaît dans 1 questions d'entraînement réparties sur 1 thèmes, dont Multicœur et synchronisation.

Domaine: Multicœur et synchronisation

Pourquoi les cœurs mettent leurs écritures en tampon

Lorsqu'un cœur exécute une écriture, la ligne de cache visée peut être absente ou détenue par un autre cœur, et obtenir la propriété en écriture via le protocole de cohérence peut prendre de nombreux cycles. Plutôt que de se bloquer, le cœur place l'adresse et les données dans un tampon d'écriture et poursuit l'exécution. Les entrées sont vidées plus tard vers le cache L1, généralement dans l'ordre du programme sur x86. Dans les processeurs à exécution dans le désordre, le tampon d'écriture contient aussi les écritures spéculatives, qui ne peuvent pas être écrites dans le cache tant que l'instruction d'écriture n'est pas validée (commit), c'est-à-dire tant qu'on ne sait pas avec certitude qu'elle ne sera pas annulée.

Transfert d'écriture vers lecture (store-to-load forwarding)

Comme les écritures récentes peuvent encore se trouver dans le tampon, chaque lecture y recherche une adresse correspondante. Si elle en trouve une, la lecture prend les données dans l'entrée correspondante la plus récente plutôt que dans le cache, un mécanisme appelé store-to-load forwarding. Cela préserve le comportement monothread : un cœur voit toujours immédiatement ses propres écritures, dans l'ordre du programme. Le transfert fonctionne au mieux lorsque la lecture porte exactement sur les octets écrits par une seule écriture antérieure ; les chevauchements partiels entre une lecture et des écritures en tampon obligent souvent la lecture à attendre que ces écritures soient vidées.

Pourquoi les autres cœurs voient les écritures en retard

Les autres cœurs ne peuvent pas consulter le tampon d'écriture d'un cœur ; une écriture en tampon leur reste donc invisible jusqu'à ce qu'elle soit vidée. Considérons x et y valant tous deux 0, le cœur 1 exécutant x = 1 puis r1 = y, et le cœur 2 exécutant y = 1 puis r2 = x. En cohérence séquentielle, au moins une des lectures doit voir 1. Avec des tampons d'écriture, les deux écritures peuvent attendre dans leurs tampons pendant que les deux lectures lisent 0 dans les caches, si bien que r1 = r2 = 0 se produit sur de vraies machines x86. Une barrière mémoire entre l'écriture et la lecture, qui attend que le tampon soit vidé, interdit ce résultat.

Tampons d'écriture et modèles de cohérence mémoire

Le modèle x86, TSO (total store order), décrit essentiellement un tampon d'écriture FIFO : les écritures restent ordonnées entre elles et les lectures entre elles, et seule une lecture ultérieure vers une adresse différente peut sembler dépasser une écriture antérieure. Des modèles plus faibles, comme ceux d'Arm et de RISC-V, permettent aussi, entre autres réordonnancements, que les écritures deviennent visibles dans le désordre ; ils nécessitent donc plus souvent des barrières (fences) ou des instructions acquire/release. Les programmeurs s'appuient normalement sur les opérations atomiques du langage, que le compilateur traduit en barrières appropriées.

Pour les performances, le CPU peut réordonner les opérations mémoire, par exemple en accumulant les écritures dans un tampon d’écriture (store buffer) ou en anticipant les lectures. Il est conçu pour que le résultat ne change pas au sein d’un cœur, mais les autres cœurs peuvent voir l’ordre modifié. Le modèle de cohérence mémoire définit quels réordonnancements peuvent survenir et constitue le contrat qui permet au programmeur d’écrire une synchronisation correcte.

Questions fréquentes

Qu'est-ce que le store-to-load forwarding ?

C'est le cas où une lecture trouve une écriture antérieure correspondante encore en attente dans le tampon d'écriture et y prend directement ses données, de sorte que le cœur voit ses propres écritures en attente sans attendre qu'elles atteignent le cache.

Pourquoi les deux threads peuvent-ils lire 0 dans le test litmus store buffering ?

L'écriture de chaque cœur reste dans son propre tampon d'écriture, invisible pour l'autre cœur, tandis que sa lecture suivante lit l'ancienne valeur dans le cache ; une barrière mémoire entre l'écriture et la lecture l'empêche.

Quel est le lien entre le tampon d'écriture et TSO ?

TSO (total store order) correspond essentiellement au comportement d'un tampon d'écriture FIFO : le seul réordonnancement autorisé est qu'une lecture ultérieure vers une adresse différente s'achève avant qu'une écriture antérieure ne devienne visible.
