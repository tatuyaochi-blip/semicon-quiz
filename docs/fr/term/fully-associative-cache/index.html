Qu'est-ce que Cache entièrement associatif ?

Organisation de cache où toute donnée peut être placée à n'importe quel emplacement. Il n'y a pas de défauts de conflit, mais toutes les étiquettes doivent être comparées, ce qui ne convient pas aux grands caches. Utilisé notamment pour les TLB.

Nom japonais: フルアソシアティブ方式

Domaine: Hiérarchie mémoire

Pas d'index, seulement étiquette et déplacement

Dans un cache entièrement associatif, tout le cache forme un seul ensemble ; n'importe quel bloc peut donc être stocké dans n'importe quelle ligne. Aucun bit n'est nécessaire pour sélectionner un ensemble : l'index fait 0 bit, et l'adresse est divisée uniquement en un déplacement dans la ligne et une étiquette composée de tous les bits restants. À chaque accès, l'étiquette demandée doit être comparée simultanément aux étiquettes de toutes les lignes valides, ce qui se fait généralement avec une mémoire adressable par contenu (CAM), où chaque entrée possède son propre comparateur.

Pourquoi on le réserve aux petites structures

Une CAM de N entrées nécessite N comparateurs larges actifs à chaque recherche, plus un grand multiplexeur pour délivrer les données correspondantes. La surface, la consommation et le temps de succès augmentent rapidement avec le nombre d'entrées ; les grands caches de données sont donc plutôt associatifs par ensembles. L'associativité totale est abordable et intéressante dans de petites structures très sollicitées où chaque défaut coûte cher, comme les TLB (translation lookaside buffers) qui mettent en cache les entrées de table des pages, ou les petits caches de victimes qui conservent les lignes récemment évincées d'un cache à correspondance directe.

La politique de remplacement détermine les performances

Comme n'importe quelle ligne peut être évincée, le cache a besoin d'une politique de remplacement. LRU (least recently used) évince la ligne inutilisée depuis le plus longtemps. Avec deux lignes et la séquence de références A, B, A, C, B, A, LRU donne cinq défauts : le succès sur A fait de B la victime à l'arrivée de C, puis A et C sont évincés tour à tour. Un LRU exact devient coûteux à suivre pour de nombreuses entrées ; le matériel utilise donc souvent un pseudo-LRU ou un remplacement aléatoire. LRU donne aussi de mauvais résultats sur des motifs cycliques légèrement plus grands que le cache, où le remplacement aléatoire peut faire mieux.

Ce que l'associativité totale ne peut pas corriger

L'associativité totale élimine les défauts par conflit, car les blocs ne se disputent jamais un ensemble particulier. Dans le modèle habituel à trois catégories, les défauts par conflit sont d'ailleurs définis comme ceux qu'un cache entièrement associatif de même taille éviterait. Les défauts obligatoires au premier accès subsistent, de même que les défauts de capacité lorsque l'ensemble de travail dépasse la taille totale du cache. Ceux-ci exigent un cache plus grand, du préchargement (prefetching) ou une restructuration du code pour réutiliser les données plus tôt, par exemple par découpage de boucles en blocs (tiling).

Questions fréquentes

Combien de bits d'index a un cache entièrement associatif ?

Zéro. Tout le cache forme un seul ensemble ; l'adresse se compose donc uniquement d'une étiquette et d'un déplacement, et l'étiquette est comparée à chaque ligne.

Pourquoi les TLB sont-ils souvent entièrement associatifs ?

Les TLB sont petits et chaque défaut impose un parcours coûteux de la table des pages ; les comparateurs supplémentaires valent donc la peine pour éviter complètement les défauts par conflit.

Un cache entièrement associatif élimine-t-il tous les défauts ?

Non. Il supprime les défauts par conflit, mais les défauts obligatoires à la première utilisation et les défauts de capacité dus à un ensemble de travail plus grand que le cache se produisent toujours.
