Bases du cloud et des conteneurs

Une image de conteneur construite par une chaîne CI/CD a été testée dans l'environnement de préproduction (staging) et validée. Quelle est la manière la plus appropriée de mettre cette image en production ?

  1. AReconstruire l'image pour la production à partir du même code source et mettre celle-ci en production
  2. BRenommer l'image testée avec le tag latest et récupérer (pull) latest dans l'environnement de production
  3. CMettre en production l'image testée elle-même en l'indiquant par son condensé (digest), et fournir les différences entre environnements par la configuration
Afficher la réponse et l'explication

Réponse : C. Mettre en production l'image testée elle-même en l'indiquant par son condensé (digest), et fournir les différences entre environnements par la configuration

Dans une telle chaîne, l'artefact produit par la construction (ici, l'image) est traité comme non modifiable, et c'est le même artefact qui passe de la préproduction à la production. Même à partir du même code source, une reconstruction peut récupérer d'autres versions des bibliothèques ou de l'image de base dont elle dépend : ce qui arriverait en production serait alors différent de ce qui a été testé. Un tag peut plus tard être déplacé vers une autre image ; pour être sûr de désigner la même image, on utilise le condensé, qui est déterminé par le contenu. Les différences entre environnements, comme les destinations de connexion, ne sont pas intégrées à l'image, mais fournies par une configuration comme des variables d'environnement.
