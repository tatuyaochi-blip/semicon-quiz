Bases du cloud et des conteneurs

Quelle description de la relation entre une image de conteneur et un conteneur est correcte ?

  1. AQuand un conteneur est arrêté, les modifications faites à l'intérieur sont automatiquement réécrites dans l'image, ce qui écrase l'image d'origine
  2. BUne image est un modèle en lecture seule, et l'on peut démarrer à partir d'une seule image plusieurs conteneurs ayant chacun sa propre couche inscriptible
  3. COn ne peut démarrer qu'un seul conteneur à la fois à partir d'une image ; pour en démarrer un deuxième, il faut d'abord copier l'image sous un autre nom
Afficher la réponse et l'explication

Réponse : B. Une image est un modèle en lecture seule, et l'on peut démarrer à partir d'une seule image plusieurs conteneurs ayant chacun sa propre couche inscriptible

Une image est un modèle en lecture seule qui regroupe les fichiers et les réglages nécessaires pour exécuter une application, et un conteneur est une unité d'exécution créée à partir d'une image. À la création d'un conteneur, une couche inscriptible qui lui est propre est empilée sur les couches de l'image. On peut donc démarrer de nombreux conteneurs à partir d'une seule image, et les modifications faites dans l'un n'affectent ni les autres conteneurs ni l'image. Pour conserver une modification dans une image, on modifie habituellement le Dockerfile et l'on reconstruit l'image.
