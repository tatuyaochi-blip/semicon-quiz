Bases du cloud et des conteneurs

Dans un conteneur démarré à partir d'une image, on modifie le fichier de configuration /etc/app.conf, qui fait partie de l'image. Quelle description de ce qui se passe avec le mécanisme de stockage habituel de Docker (comme overlay2) est correcte ?

  1. ALe fichier est copié dans la couche inscriptible du conteneur puis modifié ; l'image et les autres conteneurs ne sont donc pas affectés
  2. BLe fichier de la couche de l'image est modifié directement ; les autres conteneurs démarrés à partir de la même image voient donc aussi le nouveau contenu
  3. CLes couches d'une image sont en lecture seule : les fichiers contenus dans l'image ne peuvent donc pas être modifiés, et l'écriture échoue avec une erreur
Afficher la réponse et l'explication

Réponse : A. Le fichier est copié dans la couche inscriptible du conteneur puis modifié ; l'image et les autres conteneurs ne sont donc pas affectés

Le système de fichiers d'un conteneur présente sous la forme d'une seule arborescence les couches de l'image, en lecture seule, surmontées d'une couche inscriptible propre au conteneur. La première fois qu'un fichier d'une couche inférieure est modifié, il est copié dans la couche inscriptible, et c'est ensuite cette copie qui est utilisée (copie sur écriture). Les couches de l'image restent donc inchangées, et les autres conteneurs qui partagent la même image ne sont pas affectés. Comme la première copie d'un gros fichier prend du temps, les données écrites fréquemment, comme celles d'une base de données, sont placées dans un volume.
