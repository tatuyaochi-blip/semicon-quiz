Bases du cloud et des conteneurs

Une image est récupérée (pull) en indiquant registry.example.com/team/web:1.4. Quelle association donnant le sens de chaque partie de cette référence est correcte ?

  1. Aregistry.example.com : dépôt ; team/web : tag ; 1.4 : condensé (digest) calculé à partir du contenu de l'image
  2. Bregistry.example.com : registre (le serveur qui stocke les images) ; team/web : dépôt ; 1.4 : tag
  3. Cregistry.example.com : registre ; team : dépôt ; web : tag ; 1.4 : nom du conteneur à démarrer
Afficher la réponse et l'explication

Réponse : B. registry.example.com : registre (le serveur qui stocke les images) ; team/web : dépôt ; 1.4 : tag

Une référence d'image a la forme « registre/dépôt:tag » : le registre est le serveur qui stocke et distribue les images, le dépôt regroupe les images d'un même type, et le tag est un nom qui désigne par exemple une version ; dans cet exemple, registry.example.com est le registre, team/web le dépôt et 1.4 le tag. Si le registre est omis, c'est le registre par défaut (Docker Hub) qui est utilisé, et si le tag est omis, c'est latest. Un tag est un nom donné par les utilisateurs, et le même tag peut plus tard être déplacé vers une autre image. L'identifiant qui change toujours quand le contenu change est le condensé (digest) commençant par sha256, que l'on indique après @.
