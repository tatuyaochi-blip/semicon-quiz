Sécurité matérielle : évolutions récentes

Parmi les TEE utilisés en informatique confidentielle, quelle affirmation décrit correctement la différence entre les TEE de type VM, qui protègent une machine virtuelle entière (comme AMD SEV-SNP et Intel TDX), et ceux de type enclave, qui protègent une partie d'une application (comme Intel SGX) ?

  1. ALe type VM ne chiffre pas la mémoire de la machine virtuelle et la protège seulement en vérifiant les droits d'accès ; seul le type enclave protège la mémoire en la chiffrant
  2. BLe type VM permet d'exécuter les OS et applications existants presque sans modification, mais tout l'OS invité entre alors dans ce qu'il faut faire confiance (la TCB)
  3. CAvec le type enclave, l'OS et l'hyperviseur font aussi partie de ce à quoi il faut faire confiance, alors qu'avec le type VM il suffit de faire confiance au CPU
Afficher la réponse et l'explication

Réponse : B. Le type VM permet d'exécuter les OS et applications existants presque sans modification, mais tout l'OS invité entre alors dans ce qu'il faut faire confiance (la TCB)

Une enclave n'exécute dans une zone protégée que la partie de l'application qui traite des secrets ; ce à quoi il faut faire confiance (la TCB : trusted computing base) se réduit donc au CPU et au code de l'enclave, mais l'application doit être découpée et réécrite. Le type VM chiffre la mémoire de toute la machine virtuelle et la protège de l'hyperviseur et des administrateurs du cloud, si bien que les logiciels existants peuvent être migrés presque sans modification. En contrepartie, l'OS invité et tous les logiciels qui s'exécutent au-dessus entrent dans la TCB, et une vulnérabilité à cet endroit peut faire fuir des secrets. Plus la TCB est petite, plus elle est facile à vérifier et plus la surface d'attaque est réduite ; le choix est donc un compromis entre facilité d'utilisation et étendue de ce à quoi il faut faire confiance.
