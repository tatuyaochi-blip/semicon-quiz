Conception et exploitation des réseaux

Un routeur qui effectue du NAPT (adresse externe 198.51.100.7) est configuré avec une redirection de port, réglage statique qui ne traduit que la destination : « transférer le trafic arrivant sur le port TCP externe 8080 vers le port 80 du serveur web interne 192.168.1.20 ». Lorsque l'hôte 203.0.113.9, sur Internet, se connecte depuis le port source 51000 au port 8080 de 198.51.100.7, quelles sont la destination et la source des paquets que reçoit le serveur web ?

  1. ADestination 198.51.100.7:8080, source 203.0.113.9:51000
  2. BDestination 192.168.1.20:80, source 203.0.113.9:51000
  3. CDestination 192.168.1.20:80, source 198.51.100.7:51000
Afficher la réponse et l'explication

Réponse : B. Destination 192.168.1.20:80, source 203.0.113.9:51000

Avec la redirection de port, le routeur réécrit la destination des paquets arrivant pour l'adresse et le port externes (198.51.100.7:8080) en l'adresse et le port internes configurés (192.168.1.20:80). La source n'est pas réécrite : pour le serveur web, les paquets semblent donc venir de 203.0.113.9:51000, et ses journaux d'accès enregistrent la véritable adresse du client. Les réponses du serveur passent par ce routeur, sa passerelle par défaut, qui consulte sa table de traduction et réécrit la source en 198.51.100.7:8080 avant de les renvoyer au client. Avec un NAPT ordinaire, les connexions initiées depuis l'extérieur n'ont pas d'entrée dans la table de traduction et n'atteignent jamais l'intérieur : ce réglage est donc nécessaire pour publier un serveur situé à l'intérieur.
