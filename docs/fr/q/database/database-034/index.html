Bases des bases de données

La transaction T1 a posé un verrou exclusif sur la ligne A puis demandé un verrou sur la ligne B, tandis que T2 a posé un verrou exclusif sur la ligne B puis demandé un verrou sur la ligne A ; aucune ne peut donc progresser. Que fait généralement un SGBD lorsqu'il détecte cette situation ?

  1. AIl les laisse attendre toutes les deux ; l'un des verrous finira par se libérer de lui-même
  2. BIl annule l'une des transactions pour libérer ses verrous et laisse l'autre progresser
  3. CIl valide telles quelles les mises à jour de T1 et de T2
Afficher la réponse et l'explication

Réponse : B. Il annule l'une des transactions pour libérer ses verrous et laisse l'autre progresser

Une situation dans laquelle 2 transactions ou plus attendent mutuellement la libération de verrous, de sorte qu'aucune ne peut progresser, s'appelle un interblocage (deadlock). Attendre ne le résout jamais ; de nombreux SGBD détectent donc l'interblocage, par exemple lorsqu'un cycle apparaît dans le graphe d'attente qui indique quelle transaction attend quelle autre, et annulent l'une d'elles (la victime) pour libérer ses verrous. La transaction annulée est relancée plus tard. Une autre approche consiste à fixer une limite (délai d'expiration, ou timeout) à l'attente d'un verrou et à annuler une transaction qui la dépasse. Comme mesure préventive, il est efficace de faire poser les verrous par toutes les transactions dans un ordre fixe, par exemple la ligne A avant la ligne B.
