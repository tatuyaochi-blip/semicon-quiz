Statisches vs. dynamisches Linken: Unterschiede im Überblick

Das Linken verbindet den kompilierten Code mit dem verwendeten Bibliothekscode. Beim statischen Linken wird der benötigte Bibliothekscode zur Build-Zeit in die ausführbare Datei kopiert, sodass das Programm in sich geschlossen ist. Beim dynamischen Linken vermerkt die ausführbare Datei nur, welche Shared Libraries sie benötigt, und das Betriebssystem lädt diese beim Programmstart, sodass sich viele Programme eine Kopie teilen können. Statisch ist einfacher zu verteilen, dynamisch spart Speicher und erleichtert Updates.

MerkmalStatisches LinkenDynamisches Linken
ZeitpunktZur Build-Zeit: Bibliothekscode wird in die ausführbare Datei kopiertBeim Laden oder zur Laufzeit: Ein dynamischer Linker findet Shared Libraries (.so, .dll) und bindet sie ein
Größe der ausführbaren DateiGrößerKleiner
SpeicherbedarfJedes Programm trägt seine eigene Kopie des BibliothekscodesEine Kopie einer Shared Library kann von vielen Prozessen gemeinsam genutzt werden
Updates und SicherheitskorrekturenDas Programm muss neu gebaut und neu verteilt werdenDie Bibliothek wird einmal aktualisiert; Programme profitieren ohne Neubau (sofern die Schnittstelle kompatibel bleibt)
StartzeitEtwas schnellerEtwas langsamer: Symbole müssen aufgelöst werden (oft verzögert)
DeploymentIn sich geschlossen: läuft, ohne dass die Bibliotheken installiert sein müssenBenötigt die richtigen Bibliotheksversionen auf dem Zielsystem, sonst startet das Programm nicht
LaufzeitkostenErmöglicht Whole-Program-Optimierung und direkte AufrufeGeringer Overhead durch indirekte Aufrufe über GOT und PLT
VersionsproblemeKeine zur LaufzeitMögliche Unstimmigkeiten zwischen Programm und installierter Bibliothek
Typische AnwendungenEingebettete Firmware, Einzeldatei-Werkzeuge, minimale ContainerDie meisten Programme auf Allzweck-Betriebssystemen, Plug-ins, Systembibliotheken wie libc

Die Zahlenwerte sind typische Größenordnungen und variieren je nach Prozessgeneration und Produkt.

Wann welche Variante?

Statisch
Wenn ein in sich geschlossenes Binary gewünscht ist, das überall läuft, oder wenn es keinen Loader des Betriebssystems gibt, wie bei eingebetteter Firmware.
Dynamisch
Wenn viele Programme dieselben Bibliotheken nutzen und Speicher gespart sowie Bibliotheken zentral gepatcht werden sollen.

Häufige Fragen

Warum startet mein Programm mit einer Fehlermeldung zu einer fehlenden Bibliothek nicht?

Es wurde dynamisch gelinkt, und die benötigte Shared Library (eine .so- oder .dll-Datei) ist auf diesem Computer nicht installiert. Die Bibliothek installieren oder das Programm statisch linken.

Spart dynamisches Linken Speicher?

Ja. Eine Kopie einer Shared Library im RAM kann von vielen Prozessen gemeinsam genutzt werden.

Ist statisches Linken schneller?

Etwas. Es vermeidet das Auflösen von Symbolen beim Start und die indirekten Aufrufe über GOT und PLT und ermöglicht Whole-Program-Optimierung.

Warum hilft dynamisches Linken bei Sicherheitsupdates?

Eine Shared Library kann einmal gepatcht werden, und jedes Programm, das sie nutzt, profitiert davon, ohne neu gebaut zu werden.

Verständnis prüfen

Welche Aussage zum statischen Linken ist richtig?

  1. ADer Code der verwendeten Bibliothek wird in die ausführbare Datei kopiert und mit ihr verbunden
  2. BBei jeder Ausführung des Programms wird die Bibliothek geladen und verbunden
  3. COhne Bibliotheken wird die gesamte Verarbeitung in einer einzigen Quelldatei geschrieben
Antwort und Erläuterung anzeigen

Antwort: A. Der Code der verwendeten Bibliothek wird in die ausführbare Datei kopiert und mit ihr verbunden

Beim statischen Linken entnimmt der Linker die benötigten Funktionen einer statischen Bibliothek (unter Linux .a-Dateien) und bindet sie in die ausführbare Datei ein. Das Programm läuft auch ohne die Bibliothek in der Ausführungsumgebung und benötigt beim Start keinen Verbindungsaufwand, doch die ausführbare Datei wird größer, und jedes Programm, das dieselbe Bibliothek nutzt, trägt eine eigene Kopie. Fehlerkorrekturen der Bibliothek wirken sich erst nach einer Neuerstellung aus.

Welcher Vorteil des dynamischen Linkens (Shared Libraries) ist richtig?

  1. ADas Programm läuft immer, auch wenn die Bibliothek in der Ausführungsumgebung fehlt
  2. BMehrere Programme können eine Bibliothek im Speicher gemeinsam nutzen, und bei einer Aktualisierung der Bibliothek wirken Korrekturen ohne Neuerstellung
  3. CVerarbeitung beim Start entfällt vollständig, sodass der Start stets schneller ist als beim statischen Linken
Antwort und Erläuterung anzeigen

Antwort: B. Mehrere Programme können eine Bibliothek im Speicher gemeinsam nutzen, und bei einer Aktualisierung der Bibliothek wirken Korrekturen ohne Neuerstellung

Beim dynamischen Linken wird in der ausführbaren Datei nur vermerkt, welche Funktion welcher Shared Library verwendet wird; zur Laufzeit lädt der dynamische Linker die Bibliothek und verbindet sie. Da der Code der Shared Library nicht überschrieben wird, kann eine einzige Kopie im physischen Speicher von vielen Prozessen gemeinsam genutzt werden. Auch die Behebung von Fehlern und Schwachstellen erfordert nur den Austausch der Bibliothek. Allerdings entsteht beim Start ein Verbindungsaufwand.

Ein dynamisch gelinktes Programm startete nicht, nachdem es auf einen anderen Computer kopiert und ausgeführt wurde. Was ist die wahrscheinlichste Ursache?

  1. AWeil die ausführbare Datei den gesamten Code der Bibliotheken enthielt und zu groß war
  2. BWeil dynamisch gelinkte Programme laut Regel nur auf dem Computer laufen, auf dem sie erstellt wurden
  3. CWeil die benötigten Shared Libraries nicht vorhanden sind oder nur Versionen vorliegen, die nicht kompatibel sind
Antwort und Erläuterung anzeigen

Antwort: C. Weil die benötigten Shared Libraries nicht vorhanden sind oder nur Versionen vorliegen, die nicht kompatibel sind

Dynamisch gelinkte Programme verwenden die auf dem ausführenden Computer vorhandenen Shared Libraries. Fehlen die benötigten Bibliotheken oder gibt es nur alte Versionen, denen Funktionen fehlen, kann der dynamische Linker nicht binden, und der Start schlägt fehl. Unter Linux lässt sich mit dem Befehl ldd prüfen, welche Shared Libraries ein Programm benötigt und ob sie gefunden werden. Im Hinblick auf die einfache Verteilung wird teils bewusst statisch gelinkt.

  1. Was bindet der Linker in die ausführbare Datei ein, wenn er mit einer statischen Bibliothek (.a-Datei) linkt?
  2. Welche Aufgabe hat die bei Shared Libraries verwendete GOT (Global Offset Table)?
  3. Wie wird der physische Speicher genutzt, wenn 100 Prozesse dieselbe Shared Library verwenden?

Übungsfragen zu Linker, Loader und ausführbare Formate

Wichtige Begriffe erklärt

Statisches Linken
Verfahren, bei dem der Code der verwendeten Bibliotheken in die ausführbare Datei kopiert und eingebunden wird. Sie läuft auch ohne Bibliotheken in der Laufzeitumgebung, die Datei wird aber größer, und Korrekturen an Bibliotheken wirken erst nach Neuerstellung.
Dynamisches Linken
Verfahren, bei dem Shared Libraries zur Laufzeit geladen und gebunden werden. Bibliotheken lassen sich zwischen Prozessen teilen, und Korrekturen wirken durch Austausch; passende Bibliotheken in der Laufumgebung sind nötig.
Shared Library (gemeinsam genutzte Bibliothek)
Bibliothek, die beim dynamischen Linken zur Laufzeit geladen wird. Unter Linux .so, unter Windows .dll. Sie wird als positionsunabhängiger Code erstellt, und die Codeseiten können von vielen Prozessen gemeinsam genutzt werden.
Statische Bibliothek
Archiv, das viele Objektdateien zusammenfasst (unter Linux .a). Beim statischen Linken entnimmt der Linker nur die benötigten Objekte und bindet sie in die ausführbare Datei ein.
