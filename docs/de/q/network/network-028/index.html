Grundlagen der Computernetzwerke

Was veranlasst einen TCP-Sender, ein Segment als verloren anzusehen und erneut zu senden?

  1. ADer Empfang einer negativen Bestätigung (NAK) vom Empfänger, die das fehlende Segment erneut anfordert
  2. BDer Empfang einer ICMP-Meldung von einem Router auf dem Weg, dass er das Paket verworfen hat
  3. CEin ACK bleibt innerhalb einer festgelegten Zeit aus (Retransmission Timeout), oder es treffen mehrere ACKs mit derselben Bestätigungsnummer hintereinander ein (doppelte ACKs)
Antwort und Erläuterung anzeigen

Antwort: C. Ein ACK bleibt innerhalb einer festgelegten Zeit aus (Retransmission Timeout), oder es treffen mehrere ACKs mit derselben Bestätigungsnummer hintereinander ein (doppelte ACKs)

Ein TCP-Empfänger gibt in seinen ACKs die Nummer zurück, die auf die bereits empfangenen Daten folgt (die nächste erwartete Sequenznummer). Geht ein Segment in der Mitte verloren, sendet er weiterhin ACKs mit derselben Nummer (doppelte ACKs), auch wenn spätere Segmente ankommen. Erhält der Sender drei doppelte ACKs, wiederholt er das Segment, ohne auf einen Timeout zu warten (Fast Retransmit). Kommt gar kein ACK zurück, wiederholt er nach einem aus RTT-Messungen bestimmten Retransmission Timeout und verdoppelt den Timeout bei jedem weiteren Fehlschlag. TCP kennt keine negative Bestätigung (NAK), und Router melden durch Überlastung verworfene Pakete im Allgemeinen nicht; Verluste werden daher aus dem Muster der ACKs erschlossen.
