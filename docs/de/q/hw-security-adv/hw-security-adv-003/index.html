Aktuelle Entwicklungen der Hardwaresicherheit

Betrachtet wird eine Schaltung, die eine Speicherverschlüsselung um Manipulationserkennung und Replay-Schutz ergänzt. Für jede 64-Byte-Cache-Zeile werden ein 8-Byte-MAC (ein Code zur Erkennung von Manipulationen) und ein 8-Byte-Zähler, der bei jedem Schreibvorgang erhöht wird, im Hauptspeicher abgelegt. Welcher zusätzliche Speicherbedarf ergibt sich im Verhältnis zur geschützten Datenmenge, wenn der Baum zum Schutz der Zähler unberücksichtigt bleibt?

  1. A12,5 %
  2. B20 %
  3. C25 %
Antwort und Erläuterung anzeigen

Antwort: C. 25 %

Die zusätzlichen Informationen pro Zeile betragen 8 + 8 = 16 Byte, also 16 ÷ 64 = 25 %. Reale Verfahren benötigen außerdem einen Baum, der die Zähler gemeinsam schützt (Integritätsbaum, Integrity Tree), damit die Zähler selbst nicht umgeschrieben werden können, was weiteren Speicher kostet. Neben der Kapazität müssen bei jedem Lesen von Daten auch MAC, Zähler und Baumknoten gelesen werden, was Latenz und Speicherbandbreite erheblich belastet. Deshalb verzichten die meisten VM-basierten TEEs, die große Speicher schützen, mit Stand Mitte der 2020er-Jahre auf einen vollständigen Replay-Schutz-Baum und schützen die Integrität auf andere Weise.

Weitere Fragen zu Aktuelle Entwicklungen der Hardwaresicherheit

  1. Im Confidential Computing prüft der Verifikationsserver des Nutzers (der Prüfer) den Attestation-Bericht, den er von einer VM-basierten TEE erhalten hat, bevor er den Schlüssel zum Entschlüsseln der Daten übergibt. Welche Kombination von Prüfpunkten des Prüfers ist am besten geeignet?
  2. Mit Stand Mitte der 2020er-Jahre bietet manche GPU für Rechenzentren Funktionen, mit denen sie sich zusammen mit der TEE einer CPU für Confidential Computing nutzen lässt. Welche Aussage beschreibt das Prinzip dieses Mechanismus richtig?
  3. Welche Beschreibung des in Arm CCA (Confidential Compute Architecture) eingeführten Realm ist richtig?
  4. Welche Beschreibung der Capabilities in der als CHERI bezeichneten Befehlssatzerweiterung ist richtig?
  5. Bei Arms MTE (Memory Tagging Extension) erhält jeder 16-Byte-Block des Speichers ein 4-Bit-Tag, auch in die oberen Bits des Zeigers wird ein 4-Bit-Tag geschrieben, und die CPU prüft bei jedem Zugriff, ob beide übereinstimmen. Betrachtet wird der Fehler, über einen alten Zeiger auf einen bereits freigegebenen Bereich zuzugreifen. Wird das neue Tag bei der erneuten Zuteilung des Bereichs gleichverteilt zufällig aus den 16 Möglichkeiten gewählt, wie groß ist dann die Wahrscheinlichkeit, dass die Tags zufällig übereinstimmen und der Fehler unentdeckt bleibt?
