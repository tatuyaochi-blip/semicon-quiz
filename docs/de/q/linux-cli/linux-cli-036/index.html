Grundlagen von Linux und der Kommandozeile

Auf dem eigenen PC wurde mit ssh-keygen ein Schlüsselpaar für die Public-Key-Authentifizierung erzeugt; nun soll die Verbindung zum Server server1 per ssh ohne Passwort möglich werden. Wie werden die Schlüssel richtig abgelegt?

  1. ADen privaten Schlüssel in ~/.ssh/authorized_keys auf dem Server eintragen und den öffentlichen Schlüssel nur auf dem eigenen PC behalten
  2. BDen öffentlichen und den privaten Schlüssel beide in ~/.ssh auf dem Server ablegen und auf dem eigenen PC nichts zurücklassen
  3. CDen öffentlichen Schlüssel in ~/.ssh/authorized_keys auf dem Server eintragen und den privaten Schlüssel nie vom eigenen PC weggeben
Antwort und Erläuterung anzeigen

Antwort: C. Den öffentlichen Schlüssel in ~/.ssh/authorized_keys auf dem Server eintragen und den privaten Schlüssel nie vom eigenen PC weggeben

Bei der Public-Key-Authentifizierung von SSH prüft der Server mit dem in authorized_keys eingetragenen öffentlichen Schlüssel, ob die verbindende Seite den zugehörigen privaten Schlüssel besitzt. Der private Schlüssel selbst wird nie übertragen; er liegt nur auf dem eigenen PC, mit Rechten wie 600, damit andere ihn nicht lesen können, und ist durch eine Passphrase geschützt. Der öffentliche Schlüssel (eine .pub-Datei wie ~/.ssh/id_ed25519.pub) darf ohne Schaden bekannt werden, und ssh-copy-id trägt ihn in authorized_keys auf dem Server ein. Derselbe Schlüssel wird auch verwendet, wenn Dateien mit scp oder rsync übertragen werden, die über ssh laufen.
