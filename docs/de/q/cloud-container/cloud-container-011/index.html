Grundlagen von Cloud und Containern

Welche Beschreibung von benannten Volumes und Bind-Mounts, mit denen in Docker die von einem Container geschriebenen Daten erhalten bleiben, ist richtig?

  1. AEin Volume liegt in einem von Docker verwalteten Bereich, ein Bind-Mount in einem angegebenen Verzeichnis des Hosts, und beide bleiben erhalten, wenn der Container entfernt wird
  2. BDie Daten eines benannten Volumes bleiben beim Entfernen des Containers erhalten, die Daten eines Bind-Mounts verschwinden dagegen beim Entfernen des Containers auch aus dem Verzeichnis des Hosts
  3. CBeide werden als Teil der beschreibbaren Schicht des Containers angelegt; wird der Container mit docker rm entfernt, verschwinden daher auch die Daten
Antwort und Erläuterung anzeigen

Antwort: A. Ein Volume liegt in einem von Docker verwalteten Bereich, ein Bind-Mount in einem angegebenen Verzeichnis des Hosts, und beide bleiben erhalten, wenn der Container entfernt wird

Daten in der beschreibbaren Schicht eines Containers verschwinden, wenn der Container entfernt wird; Daten, die erhalten bleiben sollen, legt man deshalb außerhalb des Containers ab. Ein benanntes Volume wird in einem von Docker verwalteten Bereich angelegt und bleibt bestehen, bis es ausdrücklich gelöscht wird, etwa mit docker volume rm. Ein Bind-Mount macht ein beliebiges Verzeichnis des Hosts im Container sichtbar, und die Daten bleiben einfach als Dateien auf dem Host erhalten. Bind-Mounts sind in der Entwicklung verbreitet, wenn auf dem Host bearbeiteter Quellcode sofort wirken soll, Volumes bei Daten, deren Verwaltung man besser Docker überlässt, etwa Datenbankdaten.
