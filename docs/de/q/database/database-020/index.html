Grundlagen der Datenbanken

Welche Aussage beschreibt einen View in einer relationalen Datenbank richtig?

  1. AEine durch eine SELECT-Anweisung definierte virtuelle Tabelle, die normalerweise keine eigenen Daten hält und ihr Ergebnis bei jedem Zugriff aus den zugrunde liegenden Tabellen bildet
  2. BEine Tabelle, die eine Kopie der Daten der zugrunde liegenden Tabelle speichert; Änderungen an der zugrunde liegenden Tabelle ändern den Inhalt des Views nicht
  3. CEine baumartige Datenstruktur, die angelegt wird, um Werte in einer bestimmten Spalte einer Tabelle schnell zu finden
Antwort und Erläuterung anzeigen

Antwort: A. Eine durch eine SELECT-Anweisung definierte virtuelle Tabelle, die normalerweise keine eigenen Daten hält und ihr Ergebnis bei jedem Zugriff aus den zugrunde liegenden Tabellen bildet

Ein View ist eine virtuelle Tabelle, die definiert wird, indem man einer SELECT-Anweisung einen Namen gibt, etwa CREATE VIEW Vertriebsmitarbeiter AS SELECT MitarbeiterNr, Name FROM Mitarbeiter WHERE Abteilung = 'Vertrieb'. Ein gewöhnlicher View hält keine eigenen Daten; sein Ergebnis wird bei jedem Zugriff aus den zugrunde liegenden Tabellen (Basistabellen) gebildet, sodass Änderungen an den Basistabellen unmittelbar im View erscheinen. Views dienen dazu, häufig verwendete komplexe Abfragen einfach schreibbar zu machen und den Zugriff von Nutzern einzuschränken, indem man ihnen Rechte nur auf einen View mit den erlaubten Spalten und Zeilen erteilt. Daneben gibt es Materialized Views, die das Ergebnis vorab berechnen und speichern; sie beschleunigen das Lesen, müssen aber aktualisiert werden, um den Basistabellen zu folgen. Eine Baumstruktur zum schnellen Auffinden von Werten beschreibt einen Index.

Weitere Fragen zu Grundlagen der Datenbanken

  1. Was ist der Hauptzweck der Normalisierung von Tabellen in einer relationalen Datenbank?
  2. Der Primärschlüssel einer Auftragstabelle (AuftragsNr, ArtikelNr, Menge, KundenNr, Kundenname) ist {AuftragsNr, ArtikelNr}, und ihre funktionalen Abhängigkeiten sind {AuftragsNr, ArtikelNr} → Menge, AuftragsNr → KundenNr und KundenNr → Kundenname. Welches ist das richtige Ergebnis, wenn diese Tabelle bis zur dritten Normalform normalisiert wird?
  3. Der Primärschlüssel einer Mitarbeitertabelle (MitarbeiterNr, Name, Abteilungscode, Abteilungsname) ist MitarbeiterNr, und jede Spalte enthält nur einen einzigen Wert. Die funktionalen Abhängigkeiten sind MitarbeiterNr → Name, MitarbeiterNr → Abteilungscode und Abteilungscode → Abteilungsname. Welche Aussage über die Normalform dieser Tabelle ist richtig?
