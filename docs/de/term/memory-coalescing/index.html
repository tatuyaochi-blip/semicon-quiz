Was ist Memory Coalescing?

Zusammenfassen der Speicherzugriffe benachbarter Threads eines Warps auf benachbarte Adressen zu wenigen Zugriffen. Auch „zusammengefasster Zugriff“ genannt.

Japanische Bezeichnung: メモリコアレッシング

„Memory Coalescing“ kommt in 4 Übungsfragen aus 1 Themen vor, z. B. GPU-Programmierung.

Fachgebiet: GPU-Programmierung

Jetzt üben: Fragen zu Memory Coalescing

Welche Aussage zum Memory Coalescing der GPU ist richtig?

  1. ADer Speicher zweier GPUs wird zu einem zusammengefasst und die Kapazität verdoppelt
  2. BDie Daten im Speicher werden komprimiert, um die Kapazität zu erhöhen
  3. CLesen benachbarte Threads eines Warps benachbarte Adressen, genügen wenige Speicherzugriffe für das gebündelte Lesen
Antwort und Erläuterung anzeigen

Antwort: C. Lesen benachbarte Threads eines Warps benachbarte Adressen, genügen wenige Speicherzugriffe für das gebündelte Lesen

Der Speicher der GPU wird in zusammenhängenden Einheiten wie 32 oder 128 Byte gelesen und geschrieben. Lesen die 32 Threads eines Warps jeweils 4 Byte aus aufeinanderfolgenden Adressen, können insgesamt 128 Byte in einem bis wenigen Zugriffen gelesen werden. Sind die Adressen verstreut, liest jeder Thread einen anderen Block, und es werden auch nicht benötigte Daten transportiert, sodass die effektive Bandbreite auf einen Bruchteil sinkt.

Welche Anordnung ist unter dem Gesichtspunkt des Memory Coalescing vorteilhaft, wenn Daten mit den Partikelpositionen x, y, z auf der GPU verarbeitet werden?

  1. AEin Array von Strukturen mit x, y, z je Partikel
  2. BAlle Werte in zufälliger Reihenfolge anordnen
  3. CIn ein Array nur für x, ein Array nur für y und ein Array nur für z aufteilen (Struktur von Arrays statt Array von Strukturen)
Antwort und Erläuterung anzeigen

Antwort: C. In ein Array nur für x, ein Array nur für y und ein Array nur für z aufteilen (Struktur von Arrays statt Array von Strukturen)

Bei einem Array von Strukturen (AoS) liegen x, y, z von Partikel 0, dann x, y, z von Partikel 1 usw. hintereinander, sodass die Adressen beim Lesen von x durch jeden Thread jeweils 12 Byte auseinanderliegen. Bei einer Struktur von Arrays (SoA), bei der alle x hintereinanderliegen, lesen benachbarte Threads benachbarte Adressen von x, sodass Coalescing möglich ist. Aus demselben Grund ist SoA auch bei SIMD der CPU oft vorteilhaft.
