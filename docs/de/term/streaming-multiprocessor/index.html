Was ist Streaming Multiprocessor (SM)?

Einheit in NVIDIA-GPUs, die Rechenwerke, Register, Shared Memory und die Schaltung zum Warp-Wechsel zusammenfasst. Eine GPU besteht aus vielen nebeneinander angeordneten SMs.

Japanische Bezeichnung: ストリーミングマルチプロセッサ

Welche Aussage zum Verhältnis von Block und SM (Streaming Multiprocessor) in CUDA ist richtig?

  1. ADie Threads eines Blocks werden auf alle SMs verteilt ausgeführt
  2. BDie Zahl der SMs und die Zahl der Blöcke müssen stets gleich sein
  3. CJeder Block wird einem SM zugewiesen und dort bis zum Ende ausgeführt; auf einem SM können mehrere Blöcke gleichzeitig platziert sein
Antwort und Erläuterung anzeigen

Antwort: C. Jeder Block wird einem SM zugewiesen und dort bis zum Ende ausgeführt; auf einem SM können mehrere Blöcke gleichzeitig platziert sein

Die GPU besitzt viele SMs und weist die Blöcke des Kernels der Reihe nach freien SMs zu. Ein Block wird auf einem SM ausgeführt, sodass die Threads des Blocks den Shared Memory dieses SM nutzen und sich synchronisieren können. Ist die Zahl der Blöcke deutlich größer als die Zahl der SMs, erhalten bei unterschiedlich großen GPUs alle SMs Arbeit, und einem fertigen SM wird der nächste Block zugewiesen.

Ein SM einer GPU habe eine Ausgabeeinheit, die pro Zyklus Befehle eines Warps ausgeben kann. Jeder Warp gibt wiederholt 20 Zyklen lang Befehle aus und wartet dann 400 Zyklen auf das Ergebnis eines Speicherladevorgangs. Wie viele Warps sind mindestens nötig, um Leerlauf durch Speicherwartezeiten zu vermeiden (Latenzverdeckung), wenn der Warp-Wechsel keine Zeit kostet?

  1. A21
  2. B2
  3. C420
Antwort und Erläuterung anzeigen

Antwort: A. 21

Ein Warp kann nur in 20 von je 420 Zyklen (20 + 400) Befehle ausgeben. Damit die Ausgabeeinheit ausgelastet bleibt, müssen sich 420 ÷ 20 = 21 Warps abwechseln: Während ein Warp 400 Zyklen wartet, füllen die anderen 20 Warps diese Zeit mit je 20 Zyklen Befehlsausgabe. Bei zu wenigen Warps schlägt die Wartezeit auf die Leistung durch, und die Recheneinheiten stehen still. Auf einer realen GPU hängt die nötige Zahl von der Wartezeit und dem Befehlsmix ab, und Wartezeiten lassen sich auch füllen, indem man innerhalb eines Warps mehr voneinander unabhängige Befehle bereitstellt (Parallelität auf Befehlsebene).
