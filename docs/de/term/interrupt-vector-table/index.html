Was ist Interrupt-Vektortabelle?

Tabelle, in der für jeden Typ von Interrupt oder Ausnahme die Startadresse des zugehörigen Interrupt-Handlers steht. Die CPU schlägt anhand der Ursachennummer in dieser Tabelle nach und bestimmt so den Startpunkt der Behandlung.

Japanische Bezeichnung: 割り込みベクタテーブル

Fachgebiet: Betriebssystem und Hardware

Wie die CPU die Tabelle nutzt

Wird ein Interrupt oder eine Ausnahme angenommen, ermittelt die Hardware eine Nummer, den sogenannten Vektor, der die Ursache kennzeichnet: einen Timer, ein bestimmtes Peripheriegerät, einen Seitenfehler, einen unzulässigen Befehl oder einen Systemaufruf. Die CPU sichert die Adresse des nächsten Befehls und Statusinformationen wie den Betriebsmodus und verwendet dann den Vektor als Index in die Interrupt-Vektortabelle, wobei sie typischerweise den Eintrag an Basis + Vektor × Eintragsgröße liest. Dieser Eintrag enthält die Startadresse des Handlers. Der Handler sichert die von ihm genutzten Register, behandelt das Ereignis und führt einen Return-from-Interrupt-Befehl aus.

Wo die Tabelle liegt

Die Architekturen unterscheiden sich im Detail. Bei Arm-Cortex-M-Mikrocontrollern liegt die Tabelle am Anfang des Codespeichers: Ihr erstes Wort ist der initiale Stackpointer, das zweite die Adresse des Reset-Handlers, und die folgenden Wörter verweisen auf Fehler- und Peripherie-Handler; bei den meisten Kernen kann die Software sie über das Vector Table Offset Register (VTOR) verschieben. Im Real Mode von x86 belegt die Tabelle das erste 1 KB des Speichers mit 256 Einträgen zu je vier Byte, während Protected Mode und Long Mode eine Interrupt Descriptor Table (IDT) verwenden, die über das Register IDTR gefunden wird. RISC-V nutzt das Register mtvec, das alle Traps an einen Handler leiten oder Interrupts vektoriert an getrennte Adressen verteilen kann.

Einrichtung in Embedded-Firmware

Auf einem Mikrocontroller ohne Betriebssystem muss die Vektortabelle ab dem Moment des Resets an der Adresse liegen, die die Hardware erwartet. Der Startup-Code definiert sie als Array von Funktionszeigern in einer eigenen Section, und das Linkerskript legt diese Section an die erforderliche Flash-Adresse. Typische Startup-Dateien weisen jedem Eintrag einen schwachen (weak) Default-Handler zu, oft eine Endlosschleife, sodass die Anwendung nur die genutzten Interrupts überschreibt, indem sie Funktionen mit passenden Namen definiert. Ein falsch geschriebener Handlername kompiliert daher fehlerfrei, leitet den Interrupt aber stillschweigend in die Default-Schleife.

Vektortabelle und Polling im Vergleich

Ein vektoriertes Verfahren leitet jede Ursache direkt zu ihrem eigenen Handler, sodass die CPU keine Statusregister lesen muss, um herauszufinden, was passiert ist, was die Interrupt-Latenz verkürzt. Die Alternative ist ein einziger Einsprungpunkt, dessen Handler ein Ursachenregister liest und in Software verteilt, wie im Direct Mode von RISC-V. Bei einem Universalbetriebssystem füllt der Kernel die Tabelle beim Booten, sodass Timer-Ticks, Geräte-Interrupts, Seitenfehler und Systemaufrufe jeweils die richtige Kernel-Routine erreichen.

Jetzt üben: Fragen zu Interrupt-Vektortabelle

Welche Aufgabe hat die Interrupt-Vektortabelle?

  1. ASie zeichnet die Zahl aufgetretener Interrupts nach Art auf
  2. BSie legt für jede Art von Interrupt oder Ausnahme die Adresse fest, an der die Verarbeitung beginnt
  3. CSie zeichnet die Reihenfolge auf, in der als Nächstes Prozesse ausgeführt werden
Antwort und Erläuterung anzeigen

Antwort: B. Sie legt für jede Art von Interrupt oder Ausnahme die Adresse fest, an der die Verarbeitung beginnt

Tritt ein Interrupt oder eine Ausnahme auf, erhält die CPU die zur Ursache gehörende Nummer (Vektornummer), liest aus der Interrupt-Vektortabelle die Anfangsadresse des Handlers und springt dorthin. Der Inhalt der Tabelle wird vom Betriebssystem beim Start eingerichtet, sodass für Timer, einzelne Geräte, Seitenfehler, Systemaufrufe usw. jeweils eigene Handler aufgerufen werden können. Das Zählen von Häufigkeiten ist ein anderer Mechanismus für Statistik, und die Reihenfolge der auszuführenden Prozesse verwaltet der Scheduler des Betriebssystems.

Häufige Fragen

Was ist ein Interrupt-Vektor?

Ein Interrupt-Vektor ist die Nummer, die einer Interrupt- oder Ausnahmequelle zugeordnet ist und als Index in die Vektortabelle dient. Im weiteren Sinne wird der Begriff auch für den Tabelleneintrag selbst verwendet, der die Handler-Adresse enthält.

Wo liegt die Vektortabelle bei einem ARM-Cortex-M-Mikrocontroller?

Standardmäßig am Anfang des Boot-Speichers, meist im Flash. Ihr erster Eintrag ist der Anfangswert des Stackpointers, ihr zweiter der Reset-Handler, und bei den meisten Kernen kann das Vector Table Offset Register (VTOR) sie verlagern, etwa ins RAM.

Was ist der Unterschied zwischen IVT und IDT bei x86?

Die Interrupt Vector Table (IVT) ist die Real-Mode-Tabelle mit 256 Segment:Offset-Adressen am unteren Ende des Speichers. Die Interrupt Descriptor Table (IDT) ersetzt sie im Protected Mode und Long Mode, enthält Deskriptoren mit Privilegieninformationen und kann über das Register IDTR an beliebiger Stelle liegen.
