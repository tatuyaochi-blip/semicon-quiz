Was ist Speicherwand (Memory Wall)?

Problem, dass Speicherbandbreite und -latenz nicht mit der steigenden Rechenleistung der Prozessoren Schritt halten und so die Gesamtleistung begrenzt wird. Gegenmaßnahmen sind HBM, größere Caches und fortschrittliche Gehäusetechnik.

Japanische Bezeichnung: メモリウォール

„Speicherwand (Memory Wall)“ kommt in 1 Übungsfragen aus 1 Themen vor, z. B. DRAM.

Fachgebiet: DRAM

Woher die Lücke kommt

Die Prozessorleistung wuchs jahrzehntelang schnell, zunächst über die Taktfrequenz und später über mehr Kerne und breitere Vektoreinheiten, während DRAM hauptsächlich auf Dichte und Kosten pro Bit optimiert wurde. Die DRAM-Zugriffslatenz ist im Bereich von einigen zehn Nanosekunden geblieben, sodass ein Fehlzugriff auf den Hauptspeicher bei Taktraten von mehreren Gigahertz Hunderte von Zyklen kostet. Der Begriff Memory Wall wurde Mitte der 1990er-Jahre populär, als Warnung, dass diese wachsende Lücke und nicht der Prozessorkern letztlich die Systemleistung begrenzen würde.

Latenzwand vs. Bandbreitenwand

Das Problem hat zwei Seiten. Die Latenz schadet Code mit abhängigen Zugriffen, etwa dem Verfolgen von Zeigern durch eine verkettete Struktur, bei der jeder Ladevorgang abgeschlossen sein muss, bevor die nächste Adresse bekannt ist. Die Bandbreite schadet Streaming-Code, der pro Operation viele Daten berührt. Das Roofline-Modell erfasst die Bandbreitenseite: Die erreichbare Leistung ist das Minimum aus Spitzenrechenleistung und Speicherbandbreite multipliziert mit der arithmetischen Intensität, also der Zahl der pro übertragenem Byte ausgeführten Operationen. Code mit geringer arithmetischer Intensität erreicht nie die Spitzenrechenleistung, ganz gleich, wie viele Kerne verfügbar sind.

Warum KI-Workloads besonders hart getroffen werden

Große neuronale Netze haben Milliarden von Gewichten, und das Erzeugen eines Tokens bei kleinen Batchgrößen liest im Wesentlichen jedes Gewicht einmal, während mit jedem nur eine Multiplikation und eine Addition ausgeführt werden. Bei 16-Bit-Gewichten ist das etwa eine Operation pro Byte, während moderne Beschleuniger Hunderte von Operationen pro Byte ausführen können, das ihr Speicher liefert. Die Recheneinheiten warten daher auf den Speicher. Das Bündeln von Anfragen (Batching), die Quantisierung der Gewichte auf weniger Bit und das Halten von Daten auf dem Chip erhöhen allesamt die arithmetische Intensität oder verringern die übertragenen Bytes.

Wie Entwickler gegensteuern

Mehrstufige Caches nutzen Lokalität aus, sodass die meisten Zugriffe den DRAM nie erreichen, und Hardware-Prefetcher holen Daten, bevor sie angefordert werden. Out-of-Order-Kerne und GPUs mit Tausenden von Threads halten viele Fehlzugriffe gleichzeitig in Bearbeitung, um die Latenz zu verbergen. High-Bandwidth Memory (HBM), das mit fortschrittlicher Gehäusetechnik neben dem Prozessor platziert wird, und große, auf den Die gestapelte Caches erhöhen die Bandbreite direkt. Processing-in-Memory und Near-Memory-Computing gehen den umgekehrten Weg und verlagern einen Teil der Berechnung dorthin, wo die Daten bereits liegen, statt die Daten zu bewegen.

Antwort und Erläuterung anzeigen

Antwort: C. Memory Wall

Die Rechenleistung von Prozessoren wuchs zeitweise um über 50 % pro Jahr, die Zugriffslatenz von DRAM verbesserte sich dagegen von einigen zehn ns kaum, sodass die CPU Hunderte von Zyklen auf Daten warten muss. Das ist die Memory Wall. Als Gegenmaßnahmen werden mehrstufige Caches, paralleler Speicherzugriff, Prefetching, Speicher mit hoher Bandbreite wie HBM und Processing-in-Memory vorangetrieben, bei dem Berechnungen nahe am Speicher stattfinden.

Häufige Fragen

Geht es bei der Memory Wall um Latenz oder Bandbreite?

Um beides. Die Latenz begrenzt Programme mit abhängigen Speicherzugriffen, während die Bandbreite Programme begrenzt, die im Verhältnis zu ihrer Rechenarbeit große Datenmengen streamen.

Wie hilft HBM gegen die Memory Wall?

HBM stapelt DRAM-Dies neben dem Prozessor und nutzt eine sehr breite Schnittstelle, was eine viel höhere Bandbreite als herkömmliche DIMMs ergibt. Es setzt hauptsächlich an der Bandbreitenseite an; die Latenz bleibt im selben Bereich von einigen zehn Nanosekunden.

Warum sind große Sprachmodelle speichergebunden?

Bei der Generierung mit kleinen Batchgrößen wird jedes Gewicht aus dem Speicher geholt und nur für ein paar Operationen verwendet. Der Beschleuniger kann weit schneller rechnen, als der Speicher die Gewichte liefern kann.
