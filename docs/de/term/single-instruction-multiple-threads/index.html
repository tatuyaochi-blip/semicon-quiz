Was ist SIMT?

Verfahren mit einem Befehl und mehreren Threads. Programme werden pro Thread geschrieben, die Hardware bündelt die Threads jedoch zu Warps (bei NVIDIA 32 Threads) und führt sie mit demselben Befehl aus.

Japanische Bezeichnung: SIMT

„SIMT“ kommt in 2 Übungsfragen aus 1 Themen vor, z. B. GPU-Programmierung.

Fachgebiet: GPU-Programmierung

Wie SIMT Threads ausführt

Im Modell Single Instruction, Multiple Threads (SIMT) schreibt der Programmierer einen Kernel als gewöhnlichen Code für einen Thread, und Tausende von Threads führen ihn auf unterschiedlichen Daten aus. Die Hardware fasst die Threads zu festen Bündeln zusammen, auf NVIDIA-GPUs Warps aus 32 Threads, auf AMD-GPUs Wavefronts aus 64 oder 32. Ein Befehl wird für das ganze Bündel einmal geholt und dekodiert und von allen Threads im Gleichschritt ausgeführt, jeder mit eigenen Registern und Daten. So verteilt sich die Steuerlogik auf viele Rechenspuren, und der größte Teil der Chipfläche dient der Berechnung.

Verzweigungsdivergenz

Da jeder Thread unabhängig geschrieben ist, können Threads eines Warps unterschiedliche Verzweigungen nehmen. Die Hardware führt dann jeden Pfad nacheinander aus, wobei die Threads, die nicht auf diesem Pfad sind, ausmaskiert werden, und führt die Threads danach wieder zusammen. Die Korrektheit bleibt erhalten, aber wenn je die Hälfte der Threads einen Zweig eines if-else nimmt, durchläuft der Warp beide, und sein Durchsatz halbiert sich etwa. Performancebewusster Code ordnet die Daten so an, dass Threads desselben Warps demselben Pfad folgen, etwa indem Verzweigungsbedingungen vom Warp-Index statt von den Daten jedes einzelnen Threads abhängen.

SIMT vs. SIMD auf CPUs

SIMD-Erweiterungen (Single Instruction, Multiple Data) von CPUs wenden einen Befehl auf ein Vektorregister mit einer festen Zahl von Elementen an, etwa 4 oder 8. Programm oder Compiler müssen auf diese Breite ausgerichtet sein, mit expliziten Vektorbefehlen und Masken für Randfälle. SIMT verbirgt die Breite: Der Code beschreibt einen skalaren Thread, und die Hardware bildet die Vektoren aus vielen Threads und übernimmt bei Divergenz die Maskierung. Darunter ist die Ausführung ähnlich, weshalb die SIMT-Leistung weiterhin davon abhängt, dass die Threads eines Warps im Gleichschritt bleiben.

Praktische Konsequenzen

Mehrere gängige Regeln der GPU-Programmierung folgen aus SIMT. Thread-Block-Größen sind normalerweise Vielfache von 32, damit kein Warp teilweise leer läuft. Speicherzugriffe sind am schnellsten, wenn benachbarte Threads eines Warps auf benachbarte Adressen zugreifen, sodass die Hardware sie zu wenigen breiten Transaktionen zusammenfassen kann; dieses Muster heißt Coalescing. Und GPUs verbergen lange Speicherlatenzen, indem sie viele Warps resident halten und zu einem anderen bereiten Warp wechseln, sobald einer blockiert; deshalb ist eine hohe Occupancy, also genügend aktive Warps pro Kern, oft entscheidend für die Leistung.

Bei SIMD der CPU wird eine Anweisung auf ein Vektorregister angewendet, das z. B. 4 oder 8 Daten bündelt; das Programm wird daher mit Blick auf die Vektorbreite geschrieben. Bei SIMT der GPU schreibt der Programmierer die Verarbeitung eines einzelnen Threads ganz normal, und die Hardware bündelt je 32 Threads zur Ausführung mit derselben Anweisung. Threads dürfen verzweigen, und die Hardware führt die verzweigten Pfade nacheinander aus, wobei die Effizienz sinkt.

Häufige Fragen

Was ist ein Warp bei GPUs?

Ein Warp ist auf NVIDIA-GPUs eine Gruppe von 32 Threads, die denselben Befehl gemeinsam im Gleichschritt ausführen. Er ist die grundlegende Einheit der Befehlsausgabe im SIMT-Modell; das Gegenstück bei AMD heißt Wavefront.

Was ist der Unterschied zwischen SIMT und SIMD?

SIMD stellt Vektorbefehle fester Breite bereit, die Programmierer oder Compiler explizit verwenden müssen. SIMT erlaubt, jeden Thread als unabhängigen skalaren Code zu schreiben, während die Hardware die Threads zu Warps bündelt und divergierende Verzweigungen behandelt.

Was ist Warp-Divergenz?

Warp-Divergenz tritt auf, wenn Threads desselben Warps unterschiedliche Verzweigungspfade nehmen. Die Hardware führt jeden Pfad nacheinander aus und maskiert inaktive Threads, was die Effizienz senkt, bis die Pfade wieder zusammenlaufen.
