Was ist Container?

Ausführungseinheit, die eine Anwendung mit den Bibliotheken und Einstellungen bündelt, die sie benötigt, und sie isoliert von anderen Prozessen ausführt, während sie sich den Kernel des Host-Betriebssystems teilt. Unter Linux wird sie aus Namespaces, die die Sicht auf Prozess-IDs, Netzwerk, Mounts usw. trennen, und cgroups, die den Verbrauch von CPU und Arbeitsspeicher begrenzen, aufgebaut. Ein Container ist leichter und startet schneller als eine virtuelle Maschine, die ein ganzes Betriebssystem bootet; da er sich den Kernel teilt, kann er aber keinen Kernel einer anderen Betriebssystemart als der des Hosts ausführen. Container werden aus Container-Images erzeugt und mit Werkzeugen wie Docker und Kubernetes erstellt und verwaltet.

Fachgebiet: Grundlagen von Cloud und Containern

Unterschied zur virtuellen Maschine

Virtuelle Maschinen betreiben auf einem Hypervisor jeweils ein Betriebssystem mit eigenem Kernel. Ein Container bootet kein Betriebssystem, sondern läuft als isolierter Prozess auf dem Kernel des Hosts; er startet daher oft in weniger als einer Sekunde, und viele Container lassen sich auf einer Maschine unterbringen. Dafür beruht seine Isolation auf Kernelfunktionen und ist nicht so stark wie die einer virtuellen Maschine. Wo starke Isolation nötig ist, werden Container auch in leichtgewichtigen virtuellen Maschinen ausgeführt.

Das Dateisystem eines Containers

Das Dateisystem eines Containers besteht aus einer beschreibbaren Schicht für diesen Container über den schreibgeschützten Image-Schichten. Wird eine Datei aus dem Image geändert, wird sie zuerst in die beschreibbare Schicht kopiert und dann geändert (Copy-on-Write). Die beschreibbare Schicht verschwindet, wenn der Container entfernt wird; Daten, die erhalten bleiben sollen, werden daher in externem Speicher wie einem Volume abgelegt.

Entwurf für Wegwerfbarkeit

Container werden unter der Annahme entworfen, dass ein defekter Container nicht repariert, sondern aus dem Image neu erzeugt und ersetzt wird. Die Konfiguration kommt von außen, etwa über Umgebungsvariablen, Logs werden auf die Standardausgabe geschrieben, damit die Plattform sie sammelt, und Zustand liegt in Datenbanken oder Speicherdiensten. So lässt sich die Zahl der Container leicht ändern oder eine neue Version einwechseln.

Jetzt üben: Fragen zu Container

Welche Aussage zum Unterschied zwischen Containern und virtuellen Maschinen ist richtig?

  1. AContainer haben jeweils einen eigenen Betriebssystemkern, virtuelle Maschinen teilen sich den Kern
  2. BContainer laufen auf einem Hypervisor, virtuelle Maschinen allein mit Betriebssystemfunktionen
  3. CContainer teilen sich den Kern, virtuelle Maschinen betreiben jeweils ein eigenes Betriebssystem
Antwort und Erläuterung anzeigen

Antwort: C. Container teilen sich den Kern, virtuelle Maschinen betreiben jeweils ein eigenes Betriebssystem

Container sind ein Verfahren, das sich den Kern eines Betriebssystems teilt und dabei Dateisicht, Prozesse, Netzwerk und nutzbare Ressourcen gruppenweise isoliert. Da kein ganzes Betriebssystem gestartet wird, sind sie leicht und starten schnell. Virtuelle Maschinen betreiben auf einem Hypervisor jeweils ein Betriebssystem mit eigenem Kern; sie sind schwerer, dafür stärker isoliert und können auch andere Betriebssystemarten ausführen. Den Kern teilen die Container; bei Antworten ist auf umgekehrte Beschreibungen zu achten.

Welche Kombination ordnet den Linux-Kernelfunktionen, auf denen Container beruhen, nämlich den Namespaces und den cgroups (Control Groups), ihre Aufgaben richtig zu?

  1. ANamespaces: trennen, was ein Prozess sieht (Prozess-IDs, Netzwerk, Mounts usw.); cgroups: begrenzen und erfassen den Verbrauch von Ressourcen wie CPU und Arbeitsspeicher
  2. BNamespaces: begrenzen und erfassen den Verbrauch von Ressourcen wie CPU und Arbeitsspeicher; cgroups: trennen, was ein Prozess sieht (Prozess-IDs, Netzwerk, Mounts usw.)
  3. CNamespaces: starten für jeden Container einen eigenen Kernel, um die Container voneinander zu isolieren; cgroups: erzeugen für jeden Container eine virtuelle CPU und emulieren die Hardware
Antwort und Erläuterung anzeigen

Antwort: A. Namespaces: trennen, was ein Prozess sieht (Prozess-IDs, Netzwerk, Mounts usw.); cgroups: begrenzen und erfassen den Verbrauch von Ressourcen wie CPU und Arbeitsspeicher

Ein Container ist ein gewöhnlicher Prozess, der auf dem Kernel des Hosts läuft und durch zwei Mechanismen isoliert wird. Namespaces teilen Prozess-IDs, Netzwerk, Mounts (die Sicht auf das Dateisystem), Hostnamen usw. in Gruppen auf, sodass die Prozesse in einem Container nur ihren eigenen Teil sehen. cgroups begrenzen die CPU-Zeit und die Speichermenge, die eine Gruppe von Prozessen nutzen kann, und erfassen den Verbrauch. Beides sind Kernelfunktionen; ein Container startet also weder einen eigenen Kernel, noch emuliert er Hardware.

Häufige Fragen

Kann ein Container eine andere Linux-Distribution als der Host verwenden?

Ja. Ein Image enthält Dateien des Userspace wie Befehle und Bibliotheken, und diese können aus einer anderen Distribution stammen. Den Kernel teilt sich der Container jedoch mit dem Host; uname -r zeigt daher den Kernel des Hosts, und Funktionen, die dem Kernel des Hosts fehlen, stehen nicht zur Verfügung.

Warum können Linux-Container unter Windows oder macOS laufen?

Werkzeuge wie Docker Desktop betreiben eine kleine virtuelle Linux-Maschine und führen die Linux-Container darin aus. Linux-Container brauchen immer irgendwo einen Linux-Kernel.
