Was ist Kritischer Abschnitt?

Programmteil, der gemeinsame Daten bearbeitet und daher nur von jeweils einem Thread gleichzeitig ausgeführt werden darf. Er wird z. B. durch Sperren geschützt und möglichst kurz gehalten.

Japanische Bezeichnung: クリティカルセクション

„Kritischer Abschnitt“ kommt in 1 Übungsfragen aus 1 Themen vor, z. B. Multicore und Synchronisation.

Fachgebiet: Multicore und Synchronisation

Warum es kritische Abschnitte gibt

Selbst eine einfache Anweisung wie count++ wird in Lesen, Ändern und Schreiben übersetzt. Führen zwei Threads sie gleichzeitig aus, können beide denselben alten Wert lesen, und eine Erhöhung geht verloren. Code, der gemeinsame Daten auf diese Weise liest und aktualisiert, ist ein kritischer Abschnitt, und der Fehler, der entsteht, wenn zwei Threads ihn gleichzeitig betreten, ist ein Data Race oder eine Race Condition. Eine korrekte Lösung muss gegenseitigen Ausschluss garantieren, sodass sich jeweils nur ein Thread darin befindet, und dabei wartenden Threads dennoch Fortschritt ermöglichen, statt sie ewig warten zu lassen.

Wie kritische Abschnitte geschützt werden

Das übliche Werkzeug ist ein Lock: Ein Thread erwirbt vor dem Eintritt einen Mutex und gibt ihn beim Verlassen frei; jeder andere Thread, der ihn erwerben will, blockiert oder spinnt, bis er frei ist. Locks werden aus atomaren Hardwarebefehlen wie Test-and-Set, Compare-and-Swap oder Load-Linked/Store-Conditional aufgebaut, die ein Speicherwort ohne Störung lesen und aktualisieren. Ein Spinlock wartet aktiv und eignet sich für sehr kurze Abschnitte auf Mehrkernsystemen, während ein Mutex, der den wartenden Thread schlafen legt, für längere Wartezeiten passt. Werden mehrere Locks in uneinheitlicher Reihenfolge erworben, kann ein Deadlock entstehen.

Interrupts sperren auf Mikrocontrollern

Auf einem Single-Core-Mikrocontroller ist der konkurrierende Code oft ein Interrupt-Handler statt eines anderen Threads, daher wird ein kritischer Abschnitt häufig geschützt, indem Interrupts deaktiviert und danach wieder aktiviert werden. Zwischenzeitlich eintreffende Interrupts bleiben normalerweise anhängig und werden beim Wiederaktivieren bedient, lange gesperrte Phasen verzögern jedoch Timer- und Kommunikationsverarbeitung und können Puffer überlaufen lassen. Der Abschnitt muss daher so kurz wie möglich sein. Auf einem Mehrkernsystem reicht es nicht, Interrupts auf einem Kern zu deaktivieren, weil ein anderer Kern weiterhin auf die Daten zugreifen kann; dann ist zusätzlich ein Spinlock oder eine atomare Operation nötig.

Kurze Abschnitte und Transactional Memory

Solange ein Thread ein Lock hält, warten die anderen; lange kritische Abschnitte serialisieren daher ein Programm und machen den Nutzen zusätzlicher Kerne zunichte. Entwickler verkürzen sie, teilen ein grobes Lock in feinere Locks für unabhängige Daten auf oder verwenden lockfreie atomare Operationen. Hardware-Transactional-Memory bietet einen weiteren Weg: Der kritische Abschnitt läuft spekulativ als Transaktion, deren Schreibzugriffe für andere Threads unsichtbar bleiben. Hat kein anderer Thread dieselben Daten berührt, wird alles auf einmal festgeschrieben (Commit); bei einem Konflikt wird abgebrochen, zurückgerollt und erneut versucht oder auf ein normales Lock zurückgegriffen.

Jetzt üben: Fragen zu Kritischer Abschnitt

Welche Aussage zum kritischen Abschnitt (Critical Section) ist richtig?

  1. ADer Programmteil, der gemeinsame Daten bearbeitet und daher nur von einem Thread gleichzeitig ausgeführt werden darf
  2. BDer Programmteil mit der längsten Laufzeit
  3. CDer Teil, der nur bei Fehlern ausgeführt wird
Antwort und Erläuterung anzeigen

Antwort: A. Der Programmteil, der gemeinsame Daten bearbeitet und daher nur von einem Thread gleichzeitig ausgeführt werden darf

Führen mehrere Threads gleichzeitig den Teil aus, der eine gemeinsame Variable liest und ändert, entsteht ein Data Race. Ein solcher Teil, der nur von einem Thread gleichzeitig ausgeführt werden darf, heißt kritischer Abschnitt und wird geschützt, indem vor dem Eintritt eine Sperre erworben und beim Verlassen freigegeben wird. Je länger der kritische Abschnitt, desto länger warten andere Threads; grundsätzlich wird er daher möglichst kurz gehalten.

Häufige Fragen

Was ist der Unterschied zwischen einem kritischen Abschnitt und einem Mutex?

Ein kritischer Abschnitt ist der Codebereich, der auf gemeinsame Daten zugreift und nicht nebenläufig ausgeführt werden darf. Ein Mutex ist ein Mechanismus, um das durchzusetzen, indem er nur den Thread in den Bereich lässt, der ihn hält.

Warum sollten kritische Abschnitte kurz sein?

Andere Threads müssen warten, solange sich ein Thread darin befindet, und auf Mikrocontrollern sind währenddessen möglicherweise Interrupts deaktiviert. Lange Abschnitte verringern die Parallelität und verzögern die Reaktion auf andere Ereignisse.

Reicht das Sperren von Interrupts aus, um einen kritischen Abschnitt zu schützen?

Auf einem Single-Core-System, auf dem nur ein Interrupt-Handler konkurriert, in der Regel ja. Auf einem Mehrkernsystem können andere Kerne weiterlaufen, daher ist zusätzlich ein Lock oder eine atomare Operation erforderlich.
