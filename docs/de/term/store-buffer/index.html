Was ist Store-Buffer?

Kleiner Puffer, in dem ein Kern Schreibvorgänge zwischenspeichert. Der Kern kann zum nächsten Befehl übergehen, ohne den Abschluss des Schreibens abzuwarten, aber für andere Kerne wird das Schreiben verzögert sichtbar.

Japanische Bezeichnung: ストアバッファ

Jetzt üben: Fragen zu Store-Buffer

Was legt ein Speicherkonsistenzmodell (Memory Consistency Model) fest?

  1. ADie Größe der Cache-Zeilen und die Zahl der Sets
  2. BDie Art der Transistoren im DRAM-Hauptspeicher
  3. CIn welcher Reihenfolge die von einem Kern ausgeführten Lese- und Schreibzugriffe auf mehrere Adressen für andere Kerne sichtbar sein können
Antwort und Erläuterung anzeigen

Antwort: C. In welcher Reihenfolge die von einem Kern ausgeführten Lese- und Schreibzugriffe auf mehrere Adressen für andere Kerne sichtbar sein können

Die CPU kann zugunsten der Leistung die Reihenfolge von Speicheroperationen ändern, etwa indem sie Schreibvorgänge im Store-Buffer sammelt oder Lesevorgänge vorzieht. Innerhalb eines Kerns ist dies so aufgebaut, dass sich das Ergebnis nicht ändert, doch für andere Kerne kann die Reihenfolge vertauscht erscheinen. Das Speicherkonsistenzmodell legt fest, welche Umordnungen auftreten können, und ist die Vereinbarung, auf deren Grundlage Programmierer korrekte Synchronisation schreiben.

Welche Aussage zur sequentiellen Konsistenz (Sequential Consistency) ist richtig?

  1. ADie Operationen der Kerne werden jedes Mal in zufälliger Reihenfolge ausgeführt
  2. BDie Operationen aller Kerne werden in eine einzige Reihenfolge gebracht, und die Operationen jedes Kerns erscheinen in der im Programm geschriebenen Reihenfolge
  3. CAlle Operationen werden auf nur einem Kern ausgeführt
Antwort und Erläuterung anzeigen

Antwort: B. Die Operationen aller Kerne werden in eine einzige Reihenfolge gebracht, und die Operationen jedes Kerns erscheinen in der im Programm geschriebenen Reihenfolge

Bei sequentieller Konsistenz werden die Operationen mehrerer Kerne wie beim Mischen von Spielkarten in eine einzige Reihe gebracht, wobei die Operationen jedes Kerns darin ihre Programmreihenfolge einzuhalten scheinen. Es ist das für Programmierer verständlichste Modell, schränkt aber Optimierungen stark ein, bei denen die Hardware die Reihenfolge etwa über Store-Buffer ändert; viele reale CPUs verwenden daher deutlich schwächere Modelle.
