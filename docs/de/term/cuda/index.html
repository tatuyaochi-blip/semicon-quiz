Was ist CUDA?

Programmiermodell von NVIDIA für allgemeine Berechnungen auf GPUs. Kernel werden in einer um C++ erweiterten Sprache geschrieben, und Parallelität wird über die Hierarchie aus Grid, Block und Thread ausgedrückt.

Japanische Bezeichnung: CUDA

„CUDA“ kommt in 18 Übungsfragen aus 1 Themen vor, z. B. GPU-Programmierung.

Fachgebiet: GPU-Programmierung

Kernel und die Thread-Hierarchie

In CUDA startet die CPU (Host) einen Kernel, eine Funktion, die viele GPU-Threads gleichzeitig ausführen. Ein Start erzeugt ein Grid aus Blöcken, und jeder Block enthält viele Threads. Jeder Thread berechnet einen eindeutigen globalen Index, typischerweise i = blockIdx.x × blockDim.x + threadIdx.x, um sein Datenelement auszuwählen: Thread 5 von Block 2 mit 256 Threads pro Block bearbeitet Element 517. Da Threads immer in ganzen Blöcken gestartet werden, hat der letzte Block meist überzählige Threads, daher schützen Kernel ihre Speicherzugriffe mit if (i < n), um nicht über das Array hinaus zu schreiben.

Wie Blöcke auf die GPU abgebildet werden

Jeder Block wird einem Streaming-Multiprozessor (SM) zugewiesen und läuft dort bis zum Ende, und ein SM kann mehrere Blöcke gleichzeitig aufnehmen. Intern werden die Threads in Warps zu je 32 ausgeführt. Die Occupancy, das Verhältnis der residenten Warps zum Maximum des SM, wird durch die Register pro Thread, den Shared Memory pro Block und die Blockgröße begrenzt; eine niedrige Occupancy lässt zu wenige Warps übrig, um die Speicherlatenz zu verbergen. Blöcke laufen unabhängig und in beliebiger Reihenfolge, daher kann das Warten innerhalb eines Kernels auf alle anderen Blöcke zu einem Deadlock führen; eine globale Synchronisation erreicht man normalerweise, indem man die Arbeit auf zwei Kernel-Starts aufteilt.

Speicherbereiche

Der globale Speicher ist der DRAM der GPU: hohe Bandbreite, hohe Latenz und am schnellsten, wenn benachbarte Threads auf benachbarte Adressen zugreifen. Shared Memory ist ein kleiner On-Chip-Speicher pro Block, der vom Programm explizit verwaltet wird. Er ist in 32 Bänke unterteilt, und Threads eines Warps, die auf verschiedene Adressen in derselben Bank zugreifen, werden serialisiert. __syncthreads() lässt jeden Thread eines Blocks warten, bis alle angekommen sind; steht der Aufruf in einer Verzweigung, die manche Threads überspringen, kommt es zu Hängern oder undefinierten Ergebnissen. Unified Memory erlaubt es Host und Device, einen gemeinsamen Zeiger zu nutzen, wobei Seiten bei Bedarf migriert werden.

Die GPU ausgelastet halten

Kopien vom Host zum Device laufen über PCI Express und sind oft der Engpass. Streams, geordnete Warteschlangen aus Transfers und Kerneln, erlauben es, Arbeit in verschiedenen Streams zu überlappen, sodass der nächste Datenblock kopiert werden kann, während der aktuelle berechnet wird. Jeder Kernel-Start kostet zudem einige Mikrosekunden, daher profitieren Programme, die Tausende winziger Kernel starten, davon, sie zu fusionieren, was auch das Schreiben von Zwischenergebnissen in den Speicher vermeidet, oder aufgezeichnete Startsequenzen mit CUDA Graphs auf einmal abzusenden. CUDA selbst läuft nur auf NVIDIA-GPUs; herstellerübergreifende Alternativen wie OpenCL folgen einem ähnlichen Modell aus Kerneln und Work-Groups.

Welche Aussage zum „Kernel“ in der GPU-Programmierung, etwa mit CUDA, ist richtig?

  1. ADer zentrale Teil des Betriebssystems der GPU
  2. BEine Funktion, die auf der GPU von vielen Threads gleichzeitig ausgeführt wird
  3. CEin Bauteil zur Kühlung des GPU-Chips
Antwort und Erläuterung anzeigen

Antwort: B. Eine Funktion, die auf der GPU von vielen Threads gleichzeitig ausgeführt wird

Ein Kernel in der GPU-Programmierung ist eine Funktion, die vom Programm auf der CPU-Seite gestartet wird und von vielen Threads auf der GPU mit demselben Code ausgeführt wird. Jeder Thread wählt anhand seiner Nummer das ihm zugewiesene Datenelement aus. Bei einer Array-Addition wird der Kernel z. B. so geschrieben, dass ein Thread ein Element addiert, und es werden so viele Threads gestartet, wie es Elemente gibt. Das Wort ist dasselbe wie beim Kernel eines Betriebssystems, die Bedeutung ist aber eine andere.

Welche Kombination der Thread-Hierarchie in CUDA ist richtig (von groß nach klein)?

  1. AGrid → Block → Thread
  2. BThread → Block → Grid
  3. CBlock → Thread → Grid
Antwort und Erläuterung anzeigen

Antwort: A. Grid → Block → Thread

Beim einmaligen Start eines Kernels bildet das Ganze ein Grid, das Grid gliedert sich in viele Blöcke und der Block in viele Threads. Die Threads eines Blocks werden auf demselben SM (einer Gruppe von Recheneinheiten) ausgeführt und können über den Shared Memory zusammenarbeiten und sich synchronisieren. Verschiedene Blöcke werden unabhängig ausgeführt, sodass sich die Zahl der gleichzeitig laufenden Blöcke an die Größe der GPU anpasst und dasselbe Programm auf kleinen wie großen GPUs läuft.

Häufige Fragen

Was ist der Unterschied zwischen einem CUDA-Block und einem Warp?

Ein Block ist eine vom Programmierer gewählte Gruppe von Threads, die auf einem SM läuft und Speicher teilen sowie sich synchronisieren kann. Ein Warp ist die hardwareseitige Gruppe von 32 Threads innerhalb eines Blocks, die Anweisungen gemeinsam im Gleichschritt ausführen.

Wie berechnet man den globalen Thread-Index in CUDA?

Bei einem eindimensionalen Start verwendet man i = blockIdx.x * blockDim.x + threadIdx.x. Vor dem Zugriff auf Arrays ist i < n zu prüfen, weil der letzte Block oft mehr Threads enthält als verbleibende Elemente.

Wofür wird Shared Memory in CUDA verwendet?

Es ist ein schneller On-Chip-Speicher, den sich die Threads eines Blocks teilen; er dient dazu, Daten aus dem globalen Speicher zur Wiederverwendung zwischenzuspeichern und Zwischenergebnisse auszutauschen. Anders als bei einem Cache entscheidet das Programm, was hineinkommt, und __syncthreads() ordnet die Zugriffe.
