Was ist Vektorisierung?

Optimierung, die gleiche Berechnungen je Element in einer Schleife mit SIMD-Befehlen für mehrere Elemente zusammenfasst. Voraussetzung ist, dass zwischen den Iterationen keine Datenabhängigkeit besteht.

Japanische Bezeichnung: ベクトル化

„Vektorisierung“ kommt in 4 Übungsfragen aus 2 Themen vor, z. B. Compiler, Speicherhierarchie und Leistung.

Fachgebiet: Compiler

Wie aus einer Schleife SIMD-Code wird

SIMD-Befehle (Single Instruction, Multiple Data) arbeiten auf mehreren Werten, die in ein breites Register gepackt sind. Ein 128-Bit-Register fasst vier 32-Bit-Zahlen, sodass eine SIMD-Addition vier skalare Additionen ersetzt, und 256- oder 512-Bit-Einheiten verarbeiten acht bzw. sechzehn. Ein vektorisierender Compiler schreibt eine Schleife so um, dass jede Iteration der neuen Schleife eine Registerbreite an Elementen verarbeitet. Ist die Iterationszahl zur Übersetzungszeit unbekannt oder kein Vielfaches der Vektorbreite, ergänzt er für die übrigen Elemente eine skalare Restschleife oder nutzt maskierte Operationen.

Was die Vektorisierung verhindert

Die zentrale Voraussetzung ist, dass die Iterationen unabhängig sind. Eine Schleife wie a[i] = a[i-1] + b[i] hat eine schleifenübergreifende Abhängigkeit, weil jedes Element das vorherige Ergebnis benötigt, sodass sich nicht mehrere Elemente gleichzeitig berechnen lassen. Mögliches Aliasing ist ein weiteres Hindernis: Könnten zwei Zeiger auf überlappenden Speicher verweisen, muss der Compiler entweder eine Überlappungsprüfung zur Laufzeit einfügen oder aufgeben; der Qualifizierer restrict in C sichert zu, dass keine Überlappung besteht. Nicht zusammenhängende oder indirekte Zugriffe, Funktionsaufrufe, die der Compiler nicht inlinen kann, und komplexer Kontrollfluss verringern oder verhindern die Vektorisierung ebenfalls.

Reduktionen und Gleitkommareihenfolge

Das Aufsummieren eines Arrays in eine Variable ist selbst eine Abhängigkeit, dennoch vektorisieren Compiler es, indem sie in den Vektor-Lanes mehrere Teilsummen führen und diese am Ende zusammenfassen. Bei Ganzzahlen ist das Ergebnis identisch. Bei Gleitkommazahlen ist das nicht garantiert, weil jede Addition rundet, sodass (a + b) + c geringfügig von a + (b + c) abweichen kann. Bei strengen Einstellungen behält der Compiler daher die ursprüngliche Reihenfolge bei und vektorisiert solche Reduktionen unter Umständen nicht; Optionen wie fast-math erlauben eine Umassoziierung im Tausch gegen winzige numerische Abweichungen.

Datenlayout: AoS und SoA

Das Speicherlayout entscheidet oft, ob vektorisierter Code schnell ist. In einem Array of Structures (AoS) speichert jeder Datensatz x, y, z und Masse zusammen, sodass eine Schleife, die nur x liest, ein Viertel jeder geladenen 64-Byte-Cachezeile nutzt. In einer Structure of Arrays (SoA) liegen alle x-Werte zusammenhängend: Jede geladene Zeile wird vollständig genutzt, der Speicherverkehr sinkt auf etwa ein Viertel, und ein einziger Vektor-Ladebefehl holt aufeinanderfolgende x-Werte ohne Gather-Befehle. Eine Änderung des Layouts ändert die numerischen Ergebnisse nicht.

Antwort und Erläuterung anzeigen

Antwort: B. SIMD-Befehle, die mehrere Daten gleichzeitig verarbeiten

Die automatische Vektorisierung ist eine Optimierung, die Schleifen mit gleichartiger Berechnung je Arrayelement erkennt und durch SIMD-Befehle ersetzt, die mehrere Elemente zusammen verarbeiten. Mit einem 128-Bit-SIMD-Register lassen sich z. B. vier 32-Bit-Zahlen gleichzeitig addieren, sodass im besten Fall die Zahl der Rechenoperationen in der Schleife auf ein Viertel sinkt. Voraussetzungen sind etwa fehlende Abhängigkeiten zwischen Iterationen und zusammenhängende Daten; bei möglicher Überlappung von Zeigern wird mitunter verzichtet. Mit Interrupt- oder Cache-Befehlen hat sie nichts zu tun.

Häufige Fragen

Was ist der Unterschied zwischen Vektorisierung und Multithreading?

Vektorisierung beschleunigt einen einzelnen Thread durch SIMD-Befehle, die pro Befehl mehrere Datenelemente verarbeiten. Multithreading führt getrennte Befehlsströme auf verschiedenen Kernen aus, und beides wird routinemäßig kombiniert.

Warum vektorisiert mein Compiler eine Schleife nicht?

Häufige Gründe sind eine Abhängigkeit zwischen Iterationen, mögliches Zeiger-Aliasing, nicht zusammenhängender Speicherzugriff, Aufrufe nicht inlinebarer Funktionen oder eine Gleitkommareduktion, die bei strengen Einstellungen eine Umordnung der Additionen erfordern würde. Die meisten Compiler können einen Vektorisierungsbericht ausgeben, der ihre Entscheidung erklärt.

Kann Vektorisierung Gleitkommaergebnisse verändern?

Elementweise Operationen liefern dieselben Ergebnisse, doch vektorisierte Reduktionen addieren die Zahlen in anderer Reihenfolge, und da die Gleitkommaaddition nicht assoziativ ist, kann die Endsumme in den letzten Bits abweichen.
