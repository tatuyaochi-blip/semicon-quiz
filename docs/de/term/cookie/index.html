Was ist Cookie (HTTP-Cookie)?

Kleine Daten aus Name-Wert-Paaren, die ein Webserver den Browser mit dem Header Set-Cookie speichern lässt. Der Browser hängt sie danach bei Anfragen an dieselbe Website automatisch im Header Cookie an. Cookies enthalten oft eine Sitzungs-ID, damit über das zustandslose HTTP ein Anmeldezustand gehalten werden kann. Attribute wie Secure (nur über HTTPS senden), HttpOnly (für Skripte unlesbar machen), SameSite (ob es an von anderen Websites ausgehende Anfragen angehängt wird) und Expires/Max-Age (Ablaufzeit) legen fest, wie es behandelt wird.

Fachgebiet: Grundlagen der Webtechnologien

Funktionsweise

Der Server fügt einer Antwort einen Header wie „Set-Cookie: sid=…“ hinzu, und der Browser speichert ihn. Danach hängt der Browser bei Anfragen an dieselbe Website (den durch die Attribute Domain und Path festgelegten Bereich) automatisch „Cookie: sid=…“ an. Anhand der empfangenen Sitzungs-ID sucht der Server die auf seiner Seite gespeicherten Nutzerinformationen. Ein Cookie ohne angegebene Ablaufzeit wird im Allgemeinen beim Schließen des Browsers gelöscht.

Attribute für die Sicherheit

Mit Secure wird das Cookie nur über HTTPS gesendet, sodass sein Wert nicht durch Abhören bekannt werden kann. Mit HttpOnly kann das JavaScript der Seite es nicht lesen, was den Schaden verringert, wenn sonst eine Sitzungs-ID über XSS gestohlen würde. SameSite legt mit Strict, Lax oder None fest, ob das Cookie an Anfragen angehängt wird, die von anderen Websites ausgehen; es ist eine der Gegenmaßnahmen gegen Angriffe, die einen Nutzer unbeabsichtigte Anfragen senden lassen.

Unterschied zu localStorage

Auch localStorage speichert Daten im Browser, doch werden sie nicht automatisch an Anfragen angehängt; JavaScript liest und schreibt sie. Ein Cookie ist mit im Allgemeinen höchstens etwa 4 KB klein und wird bei jeder Anfrage an seine Website mitgesendet, sodass große Daten in Cookies den Datenverkehr erhöhen. Authentifizierungsdaten wie eine Sitzungs-ID legt man im Allgemeinen in einem HttpOnly-Cookie ab, das Skripte nicht lesen können.

Jetzt üben: Fragen zu Cookie (HTTP-Cookie)

Welche Aussage über einen Unterschied zwischen localStorage im Browser und Cookies ist richtig?

  1. ADaten in localStorage werden nicht automatisch an Anfragen angehängt; das JavaScript von Seiten desselben Ursprungs liest und schreibt sie
  2. BAuch Daten in localStorage werden wie Cookies bei jeder Anfrage an dieselbe Website in einen Header gesetzt und automatisch an den Server gesendet
  3. CAuch localStorage lässt sich mit dem Attribut HttpOnly versehen; selbst wenn dort eine Sitzungs-ID liegt, können die Skripte der Seite sie nicht lesen
Antwort und Erläuterung anzeigen

Antwort: A. Daten in localStorage werden nicht automatisch an Anfragen angehängt; das JavaScript von Seiten desselben Ursprungs liest und schreibt sie

localStorage ist ein Speicherbereich im Browser, der je Ursprung Schlüssel und Werte als Zeichenketten speichert; eine Ablaufzeit lässt sich nicht festlegen, und die Daten bleiben im Allgemeinen erhalten, bis sie gelöscht werden. Sie werden nicht automatisch an den Server gesendet; soll das geschehen, setzt JavaScript sie in eine Anfrage. Cookies sind mit im Allgemeinen höchstens etwa 4 KB pro Cookie klein und werden bei jeder Anfrage automatisch gesendet, während localStorage größere Datenmengen aufnehmen kann. Allerdings kann das JavaScript der Seite es jederzeit lesen, sodass bei einer XSS-Lücke sein Inhalt gestohlen werden kann. Wer dort Werte für die Authentifizierung ablegt, muss dieses Risiko bedenken.

Bei einem Cloud-E-Mail-Dienst mit Multi-Faktor-Authentifizierung wurde ein Mitarbeiter auf eine täuschend echte Anmeldeseite gelockt und gab Passwort und Einmalpasswort ein. Der Angreifer nutzte diese Seite als Relais zum echten Dienst, stahl das nach der Anmeldung ausgestellte Session-Cookie und gab sich als der Mitarbeiter aus. Welche Beschreibung dieses Angriffs und der Gegenmaßnahmen ist am besten geeignet?

  1. ABei Multi-Faktor-Authentifizierung kann der Angreifer den Dienst nicht nutzen, selbst wenn das Session-Cookie nach der Anmeldung gestohlen wird
  2. BMit einem längeren Passwort wird bei einer weitergeleiteten Anmeldung kein Session-Cookie mehr ausgestellt
  3. CDas gestohlene Cookie steht für einen Zustand mit abgeschlossener Multi-Faktor-Authentifizierung; daher wird die Sitzung sofort ungültig gemacht, und Authentifizierung wie Passkeys, kürzere Sitzungen und die Erkennung ungewöhnlicher Nutzung werden kombiniert
Antwort und Erläuterung anzeigen

Antwort: C. Das gestohlene Cookie steht für einen Zustand mit abgeschlossener Multi-Faktor-Authentifizierung; daher wird die Sitzung sofort ungültig gemacht, und Authentifizierung wie Passkeys, kürzere Sitzungen und die Erkennung ungewöhnlicher Nutzung werden kombiniert

Nach erfolgreicher Authentifizierung stellt der Dienst ein Token wie ein Session-Cookie aus und behandelt nachfolgende Anfragen allein anhand des Tokens als vom berechtigten Benutzer stammend. Wird das Token durch Phishing mit Weiterleitung (AiTM) oder durch Malware zum Informationsdiebstahl auf dem Endgerät gestohlen, kann sich der Angreifer daher im Zustand abgeschlossener Multi-Faktor-Authentifizierung als der Benutzer ausgeben. Wird der Schaden bemerkt, genügt es nicht, das Passwort zu ändern; die bereits ausgestellten Sitzungen müssen ungültig gemacht werden. Zur Vorbeugung werden phishingresistente Authentifizierung wie Passkeys, die an die Domain des Verbindungsziels gebunden sind, kürzere Gültigkeitsdauern von Sitzungen und erneute Authentifizierung oder Nutzungsbeschränkungen bei Änderungen von Ort oder Endgerät kombiniert.

Häufige Fragen

Was passiert, wenn Cookies deaktiviert sind?

Sitzungs-IDs können nicht mehr übergeben werden, sodass viele Websites den Anmeldezustand nicht halten können. Auch Informationen, die in Cookies gespeichert sind, etwa der Inhalt eines Warenkorbs oder Anzeigeeinstellungen, bleiben nicht erhalten.

Was sind Third-Party-Cookies?

Das sind Cookies, die eine andere Website als die gerade angezeigte Seite setzt, etwa eine Website, die Werbung ausliefert. Weil sie verwendet wurden, um das Verhalten von Nutzern über viele Websites hinweg zu verfolgen, senden manche Browser sie zum Schutz der Privatsphäre standardmäßig nicht oder schränken sie ein.
