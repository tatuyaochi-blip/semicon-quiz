Was ist ABI (Application Binary Interface)?

Konventionen auf Maschinencode-Ebene, damit übersetzte Programme und Bibliotheken zusammenarbeiten. Umfasst Aufrufkonventionen, Größe und Ausrichtung von Datentypen sowie die Art von Systemaufrufen.

Japanische Bezeichnung: ABI(アプリケーションバイナリインターフェース)

„ABI (Application Binary Interface)“ kommt in 3 Übungsfragen aus 2 Themen vor, z. B. Befehlssatz und Assembler, Linker, Loader und ausführbare Formate.

Fachgebiet: Befehlssatz und Assembler

Was eine ABI festlegt

Eine Application Binary Interface (ABI) legt alles fest, worauf sich zwei Teile übersetzten Codes einigen müssen, um sich gegenseitig ohne Neuübersetzung aufzurufen. Dazu gehören die Aufrufkonvention (welche Register Argumente und Rückgabewerte übertragen, welche Register eine aufgerufene Funktion erhalten muss, wie der Stack ausgerichtet und aufgebaut ist), Größe und Ausrichtung von Grundtypen wie int, long und Zeigern, Layout und Padding von Structs, das Name Mangling von C++, das Abwickeln von Exceptions, das Objektdateiformat und die Befehlsfolge, mit der ein Systemaufruf an das Betriebssystem erfolgt.

API vs. ABI

Eine Application Programming Interface (API) ist ein Vertrag auf Quelltextebene: Funktionsnamen, Parametertypen und Verhalten, wie sie ein Programmierer sieht. Eine ABI ist derselbe Vertrag nach der Übersetzung. Eine Bibliothek kann ihre API unverändert lassen und trotzdem ihre ABI brechen, etwa indem sie einem öffentlichen Struct ein Feld hinzufügt; dadurch ändern sich die Größe des Structs und die Offsets der nachfolgenden Felder. Programme lassen sich dann mit dem neuen Header problemlos übersetzen, aber gegen die alte Version gebaute Binärdateien lesen den Speicher falsch, solange sie nicht neu übersetzt werden. Versionsnummern von Shared Libraries dienen vor allem dazu, solche ABI-Brüche anzuzeigen.

Eine ISA, mehrere ABIs

Die Befehlssatzarchitektur (ISA) definiert, was der Prozessor ausführt; die ABI ist eine darauf aufsetzende Softwarekonvention, sodass eine ISA mehrere ABIs haben kann. Auf x86-64 übergibt die von Linux verwendete System-V-ABI die ersten sechs Ganzzahlargumente in RDI, RSI, RDX, RCX, R8 und R9 und macht long 64 Bit breit, während die Windows-x64-ABI RCX, RDX, R8 und R9 nutzt und long bei 32 Bit belässt. RISC-V definiert ABIs wie ilp32, lp64 und lp64d, wobei die letzte Gleitkommaargumente in Gleitkommaregistern übergibt.

Die ABI einer Bibliothek klein halten

Jedes Symbol, das eine Shared Library exportiert, wird Teil ihrer ABI und muss kompatibel bleiben. Exportierte Funktionen können außerdem von einem gleichnamigen Symbol in einem anderen Modul überschrieben werden, daher müssen selbst Aufrufe innerhalb der Bibliothek über die Procedure Linkage Table (PLT) oder die Global Offset Table (GOT) laufen. Interne Funktionen mit Hidden Visibility zu kennzeichnen, entfernt sie aus der öffentlichen Schnittstelle: Der dynamische Linker muss weniger Symbole auflösen, interne Aufrufe werden zu direkten PC-relativen Aufrufen, Namenskollisionen mit anderen Bibliotheken werden vermieden, und die Bibliothek kann diese Funktionen später frei ändern.

Jetzt üben: Fragen zu ABI (Application Binary Interface)

Welche Beschreibung des ABI (Application Binary Interface) ist richtig?

  1. AEine Vereinbarung auf Quellcodeebene, die Funktionsnamen und Argumenttypen festlegt
  2. BEine Vereinbarung, die nur die Befehlsarten und Bitmuster der CPU festlegt
  3. CEine Vereinbarung auf Maschinenebene, die Programme untereinander verbindet, einschließlich Aufrufkonvention sowie Größe und Ausrichtung von Datentypen
Antwort und Erläuterung anzeigen

Antwort: C. Eine Vereinbarung auf Maschinenebene, die Programme untereinander verbindet, einschließlich Aufrufkonvention sowie Größe und Ausrichtung von Datentypen

Das ABI ist die Vereinbarung auf Maschinenebene, damit kompilierte Programme und Bibliotheken zusammenarbeiten; es umfasst Aufrufkonvention, Größen von int, long und Zeigern, Ausrichtung von Strukturen und die Art der Systemaufrufe. Die API legt im Quellcode fest, wie Funktionen benutzt werden; bei gleicher API, aber anderem ABI ist eine Bibliothek ohne Neuerstellung nicht verwendbar. Auch bei derselben RISC-V-ISA kann das ABI je nach Betriebssystem und Einsatzzweck unterschiedlich sein.

Häufige Fragen

Was ist der Unterschied zwischen API und ABI?

Eine API ist die Quelltextschnittstelle, gegen die ein Programmierer schreibt, während eine ABI die Vereinbarung auf Binärebene über Register, Datenlayout und Aufrufablauf ist, auf die sich übersetzter Code verlässt. Bleibt die API gleich, ändert sich aber die ABI, müssen abhängige Programme neu übersetzt werden.

Warum kann ein Bibliotheksupdate unveränderte Programme funktionsunfähig machen?

Ändert das Update die ABI, etwa die Größe eines Structs oder die Argumenttypen einer Funktion, verwenden bestehende Binärdateien weiterhin das alte Layout und übergeben Daten in falscher Form. Der Quelltext lässt sich vielleicht unverändert übersetzen, aber bereits gebaute Programme versagen, bis sie neu gebaut werden.

Ist die Aufrufkonvention Teil der ABI?

Ja. Die Aufrufkonvention, die festlegt, wohin Argumente und Rückgabewerte kommen und welche Register jede Seite erhalten muss, ist einer der zentralen Bestandteile einer ABI.
