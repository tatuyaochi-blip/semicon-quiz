Was ist Sequenzielle Konsistenz?

Intuitivstes Speicherkonsistenzmodell: Die Operationen aller Kerne lassen sich in eine einzige Reihenfolge bringen, und die Operationen jedes Kerns erscheinen in Programmreihenfolge.

Japanische Bezeichnung: 逐次一貫性

Fachgebiet: Multicore und Synchronisation

Was das Modell garantiert

Sequenzielle Konsistenz, 1979 von Leslie Lamport definiert, verlangt, dass das Ergebnis jeder Ausführung dasselbe ist, als wären die Speicheroperationen aller Kerne zu einer einzigen globalen Folge verzahnt, in der die Operationen jedes Kerns in Programmreihenfolge erscheinen. Wie beim Zusammenmischen mehrerer Kartenstapel, ohne die Reihenfolge innerhalb eines Stapels zu verändern, kann die Verzahnung beliebig sein, aber alle Kerne sehen dieselbe. Programmierer können über nebenläufigen Code nachdenken, indem sie sich vorstellen, dass die Threads abwechselnd an der Reihe sind; deshalb gilt sie als das intuitivste Speicherkonsistenzmodell.

Warum reale CPUs sie lockern

Die Programmreihenfolge über alle Speicherzugriffe strikt einzuhalten, verbietet viele Hardwareoptimierungen. Ein Store-Buffer lässt einen Kern nach einem Schreibzugriff weiterarbeiten, ohne zu warten, bis dieser den Cache erreicht, und Out-of-Order-Ausführung lässt spätere Ladebefehle vor früheren Speicherbefehlen abschließen. Beides verletzt die sequenzielle Konsistenz. Die meisten Prozessoren implementieren daher schwächere Modelle: x86 verwendet Total Store Order (TSO), das einem späteren Ladebefehl erlaubt, einen früheren Speicherbefehl auf eine andere Adresse zu überholen, und Arm und RISC-V nutzen noch schwächere Modelle, die weitere Umordnungen zulassen, sofern das Programm keine Fences einfügt.

Der Store-Buffer-Lackmustest

Angenommen, Kern 0 führt x = 1 und dann r1 = y aus, während Kern 1 y = 1 und dann r2 = x ausführt; x und y sind anfangs 0. Bei sequenzieller Konsistenz muss einer der Schreibzugriffe in der globalen Reihenfolge zuerst kommen, also sieht mindestens ein Lesezugriff 1, und r1 = r2 = 0 ist unmöglich. Auf x86 kann jeder Schreibzugriff im Store-Buffer seines Kerns stehen, während der folgende Lesezugriff den alten Wert aus dem Cache holt, sodass beide Lesezugriffe 0 liefern können. Eine vollständige Speicherbarriere zwischen Schreib- und Lesezugriff auf jedem Kern stellt das sequenziell konsistente Ergebnis wieder her.

Sequenzielle Konsistenz vs. Cache-Kohärenz

Cache-Kohärenz betrifft eine einzelne Speicherstelle: Alle Kerne sind sich über die Reihenfolge der Schreibzugriffe auf diese Adresse einig und sehen schließlich den neuesten Wert. Ein Speicherkonsistenzmodell wie die sequenzielle Konsistenz betrifft die Reihenfolge von Zugriffen auf verschiedene Adressen, die Kohärenz allein nicht einschränkt. Programmiersprachen schließen die Lücke: Atomare Operationen in C11 und C++11 verwenden standardmäßig memory_order_seq_cst, und Programme ohne Data Races verhalten sich, als wären sie sequenziell konsistent. Schwächere Ordnungen wie acquire/release oder relaxed erlauben dem Compiler, weniger Barrieren zu erzeugen, wenn keine vollständige Ordnung nötig ist.

Häufige Fragen

Ist x86 sequenziell konsistent?

Nein. x86 implementiert Total Store Order (TSO), das einen Ladebefehl abschließen lässt, bevor ein früherer Speicherbefehl auf eine andere Adresse für andere Kerne sichtbar wird; daher kann das Store-Buffer-Ergebnis r1 = r2 = 0 auftreten. Eine Fence wie MFENCE oder ein Befehl mit lock-Präfix verhindert das.

Was ist der Unterschied zwischen sequenzieller Konsistenz und Cache-Kohärenz?

Kohärenz garantiert für jede einzelne Adresse eine einheitliche Reihenfolge der Schreibzugriffe. Sequenzielle Konsistenz ist stärker und umfasst die relative Reihenfolge der Operationen auf allen Adressen, als eine einzige globale Verzahnung, die die Programmreihenfolge jedes Kerns respektiert.

Was bedeutet memory_order_seq_cst in C++?

Es ist die Standardordnung für Operationen auf std::atomic und lässt alle seq_cst-Operationen in einer einzigen Gesamtreihenfolge erscheinen, die mit der Programmreihenfolge jedes Threads übereinstimmt. Sie ist am leichtesten nachzuvollziehen, kann aber die teuersten Barrierebefehle erfordern.
