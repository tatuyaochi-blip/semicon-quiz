Was ist BSS-Segment?

Bereich für globale und statische Variablen ohne Anfangswert (oder mit 0). In der Datei wird nur die Größe vermerkt und beim Laden mit 0 gefüllt, sodass die ausführbare Datei nicht größer wird.

Japanische Bezeichnung: BSSセクション

Fachgebiet: Linker, Loader und ausführbare Formate

Was im BSS-Segment landet

Die Sprache C verlangt, dass jedes Objekt mit statischer Speicherdauer, also globale und statische Variablen, ohne Initialisierer bei null beginnt. Compiler legen solche Variablen, meist auch die explizit mit 0 initialisierten, in der Sektion .bss ab. Globale Variablen mit einem von null verschiedenen Anfangswert kommen in .data, mit const qualifizierte Konstanten in das schreibgeschützte .rodata. Das Schlüsselwort static wählt nicht die Sektion aus, sondern beschränkt nur die Sichtbarkeit auf eine Datei. Lokale automatische Variablen erscheinen nie in .bss, da sie auf dem Stack liegen und keinen definierten Anfangswert haben.

Warum .bss keinen Platz in der Datei kostet

Eine lange Folge von Nullen in der ausführbaren Datei zu speichern, würde nur Speicherplatz und Ladezeit verschwenden, daher vermerkt die Sektion .bss lediglich ihre Größe und Ausrichtung. In ELF ist sie so gekennzeichnet, dass sie keine Bytes in der Datei belegt. Der Loader bildet das Segment mit Lese- und Schreibrecht ab, das .data und .bss enthält, und wo die Speichergröße des Segments seine Dateigröße übersteigt, werden die zusätzlichen Bytes als mit Nullen gefüllte Seiten bereitgestellt. Eine Deklaration wie static char buf[1000000]; erhöht daher den Speicherbedarf um etwa 1 MB, die Datei aber fast gar nicht.

BSS in Embedded-Systemen

Auf einem Mikrocontroller ohne Betriebssystem füllt niemand sonst den Speicher mit Nullen, daher übernimmt das der Start-up-Code. Vor dem Aufruf von main kopiert der Reset-Handler typischerweise die Anfangswerte von .data aus dem Flash ins RAM und löscht den .bss-Bereich im RAM, wobei er Start- und Endadressen verwendet, die das Linker-Skript als Symbole exportiert. Fehlt einer der beiden Schritte, haben globale Variablen zufällige Werte. Werkzeuge wie der Befehl size geben text, data und bss getrennt aus, was die Abschätzung des Flash- und RAM-Bedarfs erleichtert.

Woher der Name stammt

BSS wird gewöhnlich als „block started by symbol“ aufgelöst, ein Name, der auf eine Assembler-Direktive früher IBM-Großrechner zurückgeht, die unter einem Label einen nicht initialisierten Speicherblock reservierte. Die Bedeutung überdauerte in Unix-Objektformaten und später in ELF, obwohl die Direktive selbst längst verschwunden ist. Heute bezeichnet der Name einfach die Sektion für mit null initialisierte Daten, neben .text für Code, .data für initialisierte Daten und .rodata für Konstanten.

Häufige Fragen

Wofür steht BSS?

BSS wird meist als „block started by symbol“ aufgelöst, nach einer alten Assembler-Direktive. In modernen Toolchains bezeichnet es einfach die Sektion für mit null initialisierte globale und statische Variablen.

Macht ein großes nicht initialisiertes Array die ausführbare Datei größer?

Nein. Ein globales oder statisches Array ohne Initialisierer kommt in .bss, wo nur seine Größe vermerkt wird; der Speicher wird beim Laden des Programms reserviert und mit Nullen gefüllt.

Was ist der Unterschied zwischen .data und .bss?

Die Sektion .data enthält globale und statische Variablen mit von null verschiedenen Anfangswerten, die in der Datei gespeichert werden müssen. Die Sektion .bss enthält diejenigen, die bei null beginnen; sie belegt zur Laufzeit Speicher, aber keinen Platz für Inhalte in der Datei.
