Was ist Positionsunabhängiger Code (PIC)?

Maschinencode, der unabhängig von der Ladeadresse ohne Änderung läuft. Nutzt PC-relative Zugriffe und die GOT; verwendet in Shared Libraries und PIE.

Japanische Bezeichnung: 位置独立コード

„Positionsunabhängiger Code (PIC)“ kommt in 3 Übungsfragen aus 2 Themen vor, z. B. Linker, Loader und ausführbare Formate, Befehlssatz und Assembler.

Fachgebiet: Linker, Loader und ausführbare Formate

Wie PIC Code und Daten adressiert

Positionsunabhängiger Code (PIC) bettet nie absolute Adressen in seine Befehle ein. Sprünge und Aufrufe geben ihre Ziele als Abstände vom Befehlszähler an, die gleich bleiben, egal wo das gesamte Modul platziert wird. Für Ziele außerhalb der Reichweite eines Sprungfelds kombiniert RISC-V auipc, das einen um 12 Bit nach links geschobenen 20-Bit-Immediate-Wert zum PC addiert, mit jalr oder einem Ladebefehl, der die unteren 12 Bit liefert; so werden etwa ±2 GiB um den aktuellen Befehl abgedeckt. x86-64 bietet für denselben Zweck RIP-relative Adressierung, wodurch positionsunabhängiger Code fast so schnell ist wie Code mit festen Adressen.

GOT und PLT

PC-relative Abstände funktionieren innerhalb eines Moduls, doch die Adresse einer Variablen oder Funktion in einer anderen Shared Library ist erst zur Laufzeit bekannt. PIC erreicht solche Symbole daher über die Global Offset Table (GOT), eine modulspezifische Adresstabelle in festem Abstand zum Code. Der Code lädt die benötigte Adresse aus der GOT, und der dynamische Linker trägt beim Laden die tatsächlichen Adressen ein. Auf ELF-Systemen laufen Aufrufe externer Funktionen zusätzlich über kleine Stubs in der Procedure Linkage Table (PLT), die jede Funktion bei ihrem ersten Aufruf verzögert (lazy) auflösen können.

Warum Shared Libraries PIC brauchen

Eine Shared Library kann in jedem Prozess, der sie nutzt, an einer anderen virtuellen Adresse abgebildet werden. Enthielte ihr Code absolute Adressen, müsste der Loader die Befehle für jede Adresse anpassen; aus gemeinsam genutzten schreibgeschützten Seiten würden private beschreibbare Kopien, und der Zweck des Teilens wäre verfehlt. Mit PIC unterscheidet sich zwischen den Prozessen nur die kleine beschreibbare GOT, die Codeseiten brauchen keine Änderungen, und eine einzige physische Kopie wird in alle Prozesse abgebildet. Das spart Speicher und lässt die Bibliothek schnell laden, egal wo sie landet.

PIC vs. PIE und der Bezug zur Sicherheit

Eine positionsunabhängige ausführbare Datei (PIE) wendet dieselbe Technik auf das Hauptprogramm an und wird in GCC oder Clang typischerweise mit den Optionen -fPIE und -pie gebaut, während Shared Libraries -fPIC verwenden. Ältere ausführbare Dateien setzten eine feste Ladeadresse voraus, sodass Address Space Layout Randomization (ASLR) zwar Bibliotheken und Stack verschieben konnte, nicht aber den Code des Hauptprogramms; dessen Adressen blieben für Angreifer vorhersagbar. Eine PIE kann überall geladen werden, daher wird auch ihr Code randomisiert, und viele aktuelle Linux-Distributionen bauen standardmäßig PIEs. Der Preis ist ein kleiner Overhead durch die Indirektion über die GOT, der auf 32-Bit-x86 deutlich größer war.

  1. AMaschinencode, der auf jeder CPU gleich funktioniert
  2. BMaschinencode, der sich während der Ausführung ständig an einen anderen Ort verschiebt
  3. CMaschinencode, der so gestaltet ist, dass er ohne Änderung des Codes korrekt funktioniert, an welcher Speicheradresse er auch geladen wird
Antwort und Erläuterung anzeigen

Antwort: C. Maschinencode, der so gestaltet ist, dass er ohne Änderung des Codes korrekt funktioniert, an welcher Speicheradresse er auch geladen wird

Shared Libraries können in jedem Prozess an unterschiedlichen Adressen geladen werden. Positionsunabhängiger Code referenziert Funktionen und Daten nicht über feste Adressen, sondern über den Abstand zum PC oder über eine Tabelle von Adressen (GOT). So muss auch bei geänderter Ladeadresse keine Codeseite überschrieben werden, und eine einzige Kopie im physischen Speicher kann von vielen Prozessen gemeinsam genutzt werden.

Häufige Fragen

Wofür steht PIC?

PIC steht für Position-Independent Code, also positionsunabhängigen Code: Maschinencode, der ohne Änderung an jeder Ladeadresse korrekt läuft. Er beruht auf PC-relativer Adressierung und der Global Offset Table.

Was ist der Unterschied zwischen -fPIC und -fPIE?

Beide erzeugen positionsunabhängigen Code. -fPIC ist für Shared Libraries gedacht, deren Symbole von anderen Modulen überschrieben werden können, während -fPIE auf die ausführbare Hauptdatei abzielt und für eigene Symbole etwas günstigere direkte Referenzen verwenden kann. Eine mit -fPIE gebaute ausführbare Datei wird mit -pie gelinkt, um eine PIE zu erzeugen.

Wozu wird die Global Offset Table benötigt?

Code kann die Adresse eines Symbols in einem anderen Modul nicht einbetten, weil diese erst nach dem Laden bekannt ist. Die GOT enthält diese Adressen, die der dynamische Linker einträgt, und der Code erreicht die GOT über eine PC-relative Referenz.
