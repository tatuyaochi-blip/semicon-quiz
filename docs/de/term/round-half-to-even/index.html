Was ist Runden zur nächsten geraden Zahl?

Rundungsverfahren, das auf den nächstliegenden darstellbaren Wert rundet und bei genau mittigem Wert zu dem, dessen niederwertigstes Bit gerade (0) ist. Standardrundung nach IEEE 754; der Rundungsfehler ist nicht einseitig verzerrt.

Japanische Bezeichnung: 最近接偶数丸め

Fachgebiet: Computerarithmetik

Wie die Hardware einen Gleichstand erkennt

Ein exaktes Ergebnis hat meist mehr Mantissenbits, als das Zielformat aufnehmen kann. Neben den behaltenen Bits verfolgt die Hardware das erste verworfene Bit, das Round- (oder Guard-)Bit, sowie ein Sticky-Bit, das die ODER-Verknüpfung aller darunterliegenden Bits ist. Ist das Round-Bit 0, wird das Ergebnis abgeschnitten; sind Round-Bit und Sticky-Bit beide 1, wird das Ergebnis betragsmäßig aufgerundet. Nur wenn das Round-Bit 1 und das Sticky-Bit 0 ist, liegt der Wert genau in der Mitte, und dann entscheidet das letzte behaltene Bit: Ist es 1, wird aufgerundet, sodass es 0 wird.

Warum Gleichstände zur geraden Zahl gehen

Wird jeder Gleichstand aufgerundet, kommt jedes Mal ein kleiner positiver Fehler hinzu, und über viele Operationen häufen sich diese Fehler in einer Richtung an. Werden Gleichstände zum geraden Nachbarn geschickt, wird etwa die Hälfte aufgerundet und die andere Hälfte abgerundet, sodass sich die Fehler tendenziell aufheben. Dezimal ausgedrückt wird 2,5 zu 2 und 3,5 zu 4, wobei ihre Summe von 6 erhalten bleibt, während stetiges Aufrunden 7 ergäbe. Das Verfahren heißt auch Banker's Rounding (kaufmännisch-symmetrisches Runden zur geraden Zahl), und in binärer Gleitkommadarstellung ist die gerade Wahl diejenige, deren niederwertigstes Mantissenbit 0 ist.

Die anderen Rundungsmodi nach IEEE 754

IEEE 754 definiert außerdem gerichtete Rundung: zur Null hin (Abschneiden), in Richtung plus unendlich und in Richtung minus unendlich. Diese werden für besondere Zwecke explizit gewählt; die Intervallarithmetik berechnet beispielsweise eine abgerundete Untergrenze und eine aufgerundete Obergrenze, sodass das wahre Ergebnis garantiert dazwischen liegt. Die Revision von 2008 fügte für Gleichstände das Runden von der Null weg hinzu, das vor allem für Dezimalformate erforderlich ist. Runden zur nächsten geraden Zahl bleibt der Standard sowohl für Arithmetik als auch für Konvertierungen, und korrekt gerundete Operationen sind als das exakte Ergebnis definiert, gerundet im aktuellen Modus.

Wo es Programmierer überrascht

Die eingebaute Funktion round in Python 3 rundet Gleichstände zur geraden Zahl, sodass round(2.5) den Wert 2 liefert, was für jeden, der die Schulrundung erwartet, wie ein Fehler aussieht. Eine zweite Überraschung kommt von der Darstellung: Ein Dezimalwert wie 2,675 lässt sich binär nicht exakt speichern, und das nächstgelegene Double liegt knapp darunter, sodass das Runden auf zwei Nachkommastellen unabhängig von der Gleichstandsregel 2,67 ergibt. Wenn Ergebnisse einer bestimmten dezimalen Rundungskonvention folgen müssen, etwa bei Finanzberechnungen, sind dezimale Arithmetiktypen mit explizitem Rundungsmodus die übliche Lösung.

Häufige Fragen

Warum gibt Python round(2.5) 2 zurück?

Python 3 rundet exakte Gleichstände zum nächsten geraden Wert, dieselbe Regel, die IEEE 754 standardmäßig verwendet, daher wird 2,5 zu 2 und 3,5 zu 4. Das vermeidet eine systematische Verzerrung nach oben, wenn viele Werte gerundet werden.

Ist Banker's Rounding dasselbe wie Runden zur nächsten geraden Zahl?

Ja. Beide Namen beschreiben das Runden auf den nächstgelegenen Wert, wobei bei einem exakten Gleichstand der Nachbar mit gerader letzter Ziffer bzw. geradem letztem Bit gewählt wird.

Welcher Rundungsmodus ist bei IEEE 754 Standard?

Runden zum nächsten Wert, bei Gleichstand zur geraden Zahl. Gerichtete Modi zur Null hin, in Richtung plus unendlich und in Richtung minus unendlich stehen zur Verfügung, müssen aber explizit gewählt werden.
