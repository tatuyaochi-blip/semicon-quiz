Was ist Zwischendarstellung (IR)?

Interne Darstellung eines Programms im Compiler, die weder von der Quellsprache noch von der CPU abhängt. Die meisten Optimierungen erfolgen hier, sodass sich ein sprachspezifisches Front-End und ein CPU-spezifisches Back-End trennen lassen.

Japanische Bezeichnung: 中間表現

„Zwischendarstellung (IR)“ kommt in 6 Übungsfragen aus 1 Themen vor, z. B. Compiler.

Fachgebiet: Compiler

Warum Compiler eine IR verwenden

M Quellsprachen auf N Prozessoren mit separaten Compilern zu unterstützen, würde M × N davon erfordern. Mit einer gemeinsamen Zwischendarstellung (IR) braucht jede Sprache nur ein Front-End, das in die IR übersetzt, und jeder Prozessor nur ein Back-End, das aus ihr übersetzt, insgesamt M + N Teile. Einmal auf der IR geschriebene Optimierungen kommen dann jeder Sprache und jedem Ziel zugute. LLVM ist das bekannteste Beispiel: Front-Ends wie Clang erzeugen LLVM IR, und Back-Ends generieren Code für x86, Arm, RISC-V und andere Ziele.

Gängige Formen

Compiler verwenden oft mehrere IR-Ebenen. Nahe am Quelltext liegt ein abstrakter Syntaxbaum. Weiter unten zerlegt Drei-Adress-Code Ausdrücke in einfache Schritte wie t1 = a + b; x = t1 * c, mit temporären Variablen für Zwischenwerte. Diese Befehle werden zu Basisblöcken gruppiert, die durch einen Kontrollflussgraphen verbunden sind. Viele moderne IRs, darunter LLVM IR, verwenden die Static-Single-Assignment-Form (SSA), in der jede Variable genau einmal zugewiesen wird und spezielle Phi-Knoten Werte zusammenführen, wo Kontrollpfade zusammenlaufen.

Was auf der IR passiert

Die meisten Optimierungsdurchläufe laufen auf der IR: Konstantenpropagation, Elimination toten Codes, Elimination gemeinsamer Teilausdrücke, das Herausziehen schleifeninvarianter Berechnungen aus Schleifen und Function Inlining. Die SSA-Form vereinfacht viele davon, weil jede Verwendung auf genau eine Definition zeigt. Link-Time Optimization (LTO) speichert IR statt Maschinencode in Objektdateien, damit das gesamte Programm gemeinsam optimiert werden kann, was Inlining und das Entfernen toter Funktionen über Quelldateien hinweg ermöglicht.

IR vs. Bytecode und Maschinencode

Die interne IR eines Compilers ist eine Arbeitsform für Analyse und Transformation; die CPU kann sie nicht ausführen, und das Back-End muss noch Befehle auswählen, Register zuweisen und den Code einplanen (Scheduling). Portable Bytecodes wie Java-Bytecode oder WebAssembly sind verwandt, dienen aber einem anderen Zweck: Sie sind stabile Verteilungsformate, die eine virtuelle Maschine interpretiert oder just in time kompiliert, während sich interne IRs zwischen Compilerversionen ändern können.

Was ist der Hauptvorteil einer Zwischendarstellung (IR), die im Compiler intern weder von der Quellsprache noch von der CPU abhängt?

  1. AMit einer Zwischendarstellung kann ohne Lesen des Quellcodes kompiliert werden
  2. BDie Zwischendarstellung kann von der CPU direkt ausgeführt werden, sodass keine Maschinencode-Erzeugung nötig ist
  3. CDas sprachspezifische Frontend und das CPU-spezifische Backend lassen sich trennen, und auch die Optimierungen können gemeinsam genutzt werden
Antwort und Erläuterung anzeigen

Antwort: C. Das sprachspezifische Frontend und das CPU-spezifische Backend lassen sich trennen, und auch die Optimierungen können gemeinsam genutzt werden

Sollen M Sprachen und N CPUs unterstützt werden, wären ohne gemeinsame Zwischendarstellung M×N Compiler nötig; mit ihr genügen M Frontends (Sprache zur Zwischendarstellung) und N Backends (Zwischendarstellung zur CPU). Auch ein Großteil der Optimierungen muss nur einmal auf der Zwischendarstellung implementiert werden und gilt für alle Sprachen und CPUs. Die Zwischendarstellung ist nicht direkt von der CPU ausführbar und muss am Ende in Maschinencode umgesetzt werden.

Welche Eigenschaft der Zwischendarstellung in SSA-Form ist richtig?

  1. AJeder Variablen wird im Programm genau einmal ein Wert zugewiesen
  2. BAlle Variablen liegen im Speicher statt in Registern
  3. CSie wird so umgeschrieben, dass sie keinerlei bedingte Verzweigungsbefehle enthält
Antwort und Erläuterung anzeigen

Antwort: A. Jeder Variablen wird im Programm genau einmal ein Wert zugewiesen

In der SSA-Form werden Variablen so umbenannt, dass jede nur einmal zugewiesen wird, und an Zusammenflussstellen wird der Wert per φ-Funktion ausgewählt. Wird x z. B. zweimal zugewiesen, entstehen x1 und x2, sodass klar ist, welches verwendet wird. Da Definition-Verwendung-Beziehungen eindeutig sind, lassen sich Optimierungen wie Konstantenpropagierung und Entfernung von totem Code leichter durchführen. Verzweigungen werden durch φ-Funktionen behandelt, die Verzweigungsbefehle verschwinden also nicht. Variablen liegen auch nicht im Speicher, sondern werden meist als Registerkandidaten behandelt.

Häufige Fragen

Was ist eine Zwischendarstellung im Compiler?

Es ist die Form, in die ein Compiler Quellcode übersetzt, bevor er Maschinencode erzeugt, unabhängig sowohl von der Quellsprache als auch von der Ziel-CPU, sodass Optimierungen gemeinsam genutzt werden können.

Was ist die SSA-Form?

Static Single Assignment ist eine IR-Form, in der jede Variable genau einmal zugewiesen wird, wobei Phi-Knoten Werte auswählen, wo der Kontrollfluss zusammenläuft, was viele Optimierungen vereinfacht.

Ist LLVM IR Maschinencode?

Nein. LLVM IR ist eine zielunabhängige Zwischendarstellung; ein Back-End muss sie in Maschinencode für einen bestimmten Prozessor übersetzen.
