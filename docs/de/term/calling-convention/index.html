Was ist Aufrufkonvention?

Vereinbarung beim Funktionsaufruf, über welche Register oder den Stack Argumente und Rückgabewerte übergeben werden und wer welche Register sichert. Wichtiger Teil des ABI.

Japanische Bezeichnung: 呼び出し規約

„Aufrufkonvention“ kommt in 9 Übungsfragen aus 1 Themen vor, z. B. Befehlssatz und Assembler.

Fachgebiet: Befehlssatz und Assembler

Was eine Aufrufkonvention festlegt

Eine Aufrufkonvention legt die Details eines Funktionsaufrufs auf unterster Ebene fest: welche Register die Argumente übertragen, wo der Rückgabewert abgelegt wird, wie die Rücksprungadresse gesichert wird, welche Register eine aufgerufene Funktion überschreiben darf und wie der Stack-Frame aufgebaut und ausgerichtet ist. Aufrufer und Aufgerufener werden oft getrennt übersetzt, vielleicht von verschiedenen Compilern oder von Hand in Assembler geschrieben, sodass keiner sehen kann, wie der andere erzeugt wurde. Solange beide dieselbe Konvention einhalten, kann eine C-Funktion eine Bibliotheksroutine oder eine Assemblerfunktion aufrufen, und die Werte kommen dort an, wo sie erwartet werden.

Die RISC-V-Konvention in Zahlen

RISC-V hat 32 Ganzzahlregister, x0 bis x31, und die Konvention gibt ihnen Rollennamen. Bis zu acht Ganzzahlargumente werden in a0 bis a7 (x10 bis x17) übergeben; ein neuntes oder zehntes Argument landet auf dem Stack an einem festen Offset zu sp. Das Ergebnis kommt in a0 zurück, bei einem 64-Bit-Wert auf RV32 in a0 und a1. Gleitkommaargumente nutzen fa0 bis fa7. Ein Aufruf lautet jal ra, func und schreibt die Rücksprungadresse in ra (x1). Der Stackpointer muss beim Eintritt ein Vielfaches von 16 Byte sein, daher werden Frames in 16-Byte-Schritten angelegt.

Caller-saved vs. callee-saved Register

Die Register werden in zwei Gruppen aufgeteilt. Caller-saved Temporärregister, in RISC-V t0 bis t6 sowie die Argumentregister, darf jede aufgerufene Funktion beliebig überschreiben; ein Aufrufer, der einen solchen Wert nach dem Aufruf noch braucht, muss ihn vorher sichern. Callee-saved Register, s0 bis s11, müssen nach der Rückkehr unverändert erscheinen; eine Funktion, die eines davon nutzen will, sichert es daher im Prolog und stellt es im Epilog wieder her. Durch diese Aufteilung kommen kurze Blattfunktionen ganz ohne Sichern mit Temporärregistern aus, während langlebige Werte wie Schleifenzähler sicher in s-Registern liegen.

Aufrufkonvention vs. ABI und API

Die Aufrufkonvention ist ein Teil der Application Binary Interface (ABI), die außerdem Größe und Ausrichtung von Datentypen, das Layout von Structs und die Art von Systemaufrufen festlegt. Eine API beschreibt dagegen, wie Funktionen auf Quelltextebene verwendet werden. Zwei Builds können dieselbe API teilen und dennoch auf Binärebene inkompatibel sein, weil sich ihre ABIs unterscheiden; eine Bibliothek muss dann neu übersetzt werden. Verschiedene Plattformen definieren für dieselbe ISA-Familie unterschiedliche Konventionen: Auf x86-64 übergibt Linux die ersten sechs Ganzzahlargumente in Registern, Windows dagegen vier.

Häufige Fragen

Was ist eine Aufrufkonvention?

Sie ist die Vereinbarung darüber, wie ein Funktionsaufruf Argumente und Rückgabewerte übergibt, die Rücksprungadresse sichert und die Pflicht zum Sichern von Registern zwischen Aufrufer und aufgerufener Funktion aufteilt. Sie ermöglicht es getrennt übersetztem Code, einschließlich Bibliotheken und Assemblerroutinen, sich gegenseitig korrekt aufzurufen.

Was ist der Unterschied zwischen caller-saved und callee-saved Registern?

Ein caller-saved Register darf von der aufgerufenen Funktion überschrieben werden, daher muss der Aufrufer es sichern, wenn er den Wert danach noch braucht. Ein callee-saved Register muss von der aufgerufenen Funktion erhalten werden; sie sichert es und stellt es wieder her, wenn sie es nutzt.

Wo werden Funktionsargumente in RISC-V übergeben?

Die ersten acht Ganzzahlargumente werden in den Registern a0 bis a7 übergeben, alle weiteren auf dem Stack. Der Rückgabewert kommt in a0 zurück, bei einem Wert von doppelter Registerbreite in a0 und a1.
