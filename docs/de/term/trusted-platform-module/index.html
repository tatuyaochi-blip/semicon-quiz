Was ist TPM?

Trusted Platform Module. Sicherheitschip bzw. -funktion zum Erzeugen und Speichern von Schlüsseln, Protokollieren von Messwerten gestarteter Software und Bescheinigen des Zustands.

Japanische Bezeichnung: TPM

„TPM“ kommt in 5 Übungsfragen aus 3 Themen vor, z. B. Hardwaresicherheit, Grundlagen und Anwendungen der Kryptografie, Aktuelle Entwicklungen der Hardwaresicherheit.

Fachgebiet: Hardwaresicherheit

Was in einem TPM steckt

Ein Trusted Platform Module ist ein manipulationsresistenter Sicherheitschip oder eine gleichwertige Funktion, die in Firmware auf dem Hauptprozessor implementiert ist und oft fTPM genannt wird. Es enthält einen Zufallszahlengenerator, Einheiten für Hashing, Signierung und Verschlüsselung, geschützten nichtflüchtigen Speicher und einen Satz von Platform Configuration Registers (PCRs). Schlüssel können innerhalb des TPM erzeugt und dort verwendet werden, ohne dass der private Teil es jemals im Klartext verlässt. Die Schnittstelle wird von der Trusted Computing Group definiert, aktuelle PCs nutzen Version 2.0.

Measured Boot und PCRs

Beim Measured Boot berechnet jede Stufe den Hash des nächsten Softwareteils, bevor sie es ausführt, und erweitert (extend) ein PCR mit diesem Hash. Erweitern bedeutet, dass der neue PCR-Wert der Hash aus dem alten Wert, verkettet mit der neuen Messung, ist; Software kann ein PCR nicht direkt beschreiben, und die PCRs für die Boot-Messungen werden nur durch einen Plattform-Reset gelöscht. Die Endwerte fassen daher die gesamte Bootsequenz in ihrer Reihenfolge zusammen, und jede Änderung ergibt andere Werte. Anders als Secure Boot hindert Measured Boot nichts an der Ausführung; es liefert Nachweise für spätere Prüfungen.

Sealing und Remote Attestation

Aus den PCRs ergeben sich zwei Anwendungen. Sealing bindet Daten, etwa einen Schlüssel für die Festplattenverschlüsselung, an bestimmte PCR-Werte, sodass das TPM sie nur freigibt, wenn die Plattform die erwartete Software gebootet hat; eine ausgebaute Festplatte oder ein veränderter Bootloader erhält nichts. Bei der Remote Attestation signiert das TPM einen Bericht seiner PCR-Werte mit einem nicht extrahierbaren Schlüssel, und ein Server prüft Signatur und Messwerte, bevor er Geheimnisse, Dienste oder Netzwerkzugang gewährt. Eine frische zufällige Challenge des Servers verhindert das Wiedereinspielen eines alten Berichts.

TPM vs. Secure Element und TEE

Ein TPM ist eine standardisierte Komponente für Plattformvertrauen mit Schwerpunkt auf Messung, Schlüsselschutz und Attestierung und ist relativ langsam; die Massenverschlüsselung läuft auf der CPU mit Schlüsseln, die das TPM freigegeben hat. Ein Secure Element ist ein Chip der Smartcard-Klasse für Zahlungs- oder Identitätsdaten, und eine Trusted Execution Environment (TEE) ist ein isolierter Modus des Hauptprozessors, in dem vertrauenswürdiger Code läuft. Systeme kombinieren sie oft, und die Attestierung kann entweder in einem TPM oder in einer TEE verankert sein.

Häufige Fragen

Unterschied zwischen TPM und Secure Boot

Secure Boot verhindert, dass unsignierte oder veränderte Boot-Software ausgeführt wird. Ein TPM zeichnet Messwerte dessen auf, was gebootet wurde, schützt Schlüssel und kann den Plattformzustand gegenüber anderen nachweisen; beide werden oft zusammen eingesetzt.

Was ist ein PCR im TPM?

Ein Platform Configuration Register enthält einen fortlaufenden Hash der gemessenen Software. Es kann nur erweitert werden, indem neue Messwerte eingehasht werden, sodass sein Wert die exakte Reihenfolge dessen widerspiegelt, was seit dem Reset geladen wurde.

Was ist ein Firmware-TPM (fTPM)?

Es ist TPM-Funktionalität, die statt in einem separaten Chip in Firmware implementiert ist, die in einer isolierten Umgebung des Hauptprozessors läuft. Es bietet dieselbe Schnittstelle, aber eine andere Widerstandsfähigkeit gegen physische Angriffe als ein diskretes TPM.
