Was ist NUMA (Non-Uniform Memory Access)?

Abkürzung für Non-Uniform Memory Access. Architektur mit Speicher, der für einen Kern nah oder fern liegt; Zugriffe auf fernen Speicher dauern länger. Daten und Threads auf derselben Seite zu platzieren ist schneller.

Japanische Bezeichnung: NUMA

„NUMA (Non-Uniform Memory Access)“ kommt in 4 Übungsfragen aus 3 Themen vor, z. B. Multicore und Synchronisation, Leistungsbewertung und Profiling, DRAM.

Fachgebiet: Multicore und Synchronisation

Warum der Speicherzugriff ungleichförmig wird

Moderne Prozessoren integrieren ihre Speichercontroller, sodass in einem Server mit mehreren Sockeln jeder Sockel seinen eigenen direkt angeschlossenen DRAM hat. Ein Kern, der auf Speicher seines eigenen Sockels zugreift, geht direkt über seinen lokalen Controller; der Zugriff auf Speicher eines anderen Sockels erfordert den Weg über die Verbindung zwischen den Sockeln und durch den entfernten Controller. Die Gruppe aus Kernen und ihrem lokalen Speicher heißt NUMA-Knoten. Entfernte Zugriffe zeigen typischerweise eine merklich höhere Latenz, oft etwa das 1,3- bis 2-Fache des lokalen Werts, und eine geringere Bandbreite, wobei das genaue Verhältnis von der Plattform und der Auslastung der Verbindung abhängt.

NUMA vs. UMA und vs. Cluster

In einem System mit Uniform Memory Access (UMA), oft eine Maschine mit einem Sockel und einem Speichercontroller-Komplex, sieht jeder Kern jede Adresse zu ungefähr denselben Kosten. Ein cache-kohärentes NUMA-System (ccNUMA) behält einen einzigen gemeinsamen Adressraum und hardwareseitige Cache-Kohärenz bei, sodass unveränderte Programme korrekt laufen; nur ihre Geschwindigkeit hängt davon ab, wo die Daten liegen. Das unterscheidet es von einem Cluster separater Rechner, bei dem jeder Knoten einen privaten Adressraum hat und Daten explizit per Message Passing ausgetauscht werden müssen. Große chipletbasierte Prozessoren können auch innerhalb eines einzigen Sockels mehr als einen NUMA-Knoten aufweisen.

First-Touch-Platzierung und ihre Falle

Linux legt eine Seite meist auf dem Knoten des Threads an, der sie zuerst beschreibt, nicht dem, der sie alloziert hat, da malloc nur virtuelle Adressen reserviert. Initialisiert ein einzelner Thread ein großes Array mit Nullen, landet jede Seite auf dem Knoten dieses Threads, und spätere parallele Schleifen auf anderen Knoten laufen fast vollständig aus entferntem Speicher, während ein Speichercontroller ausgelastet ist und die anderen untätig bleiben. Die Abhilfe ist, die Daten parallel mit derselben Arbeitsaufteilung wie die Berechnung zu initialisieren, sodass der Anteil jedes Threads lokal bei ihm liegt.

Werkzeuge und bewährte Praxis

Unter Linux listet numactl --hardware die Knoten, ihren Speicher und eine Distanztabelle auf, in der lokaler Zugriff konventionell 10 ist und entfernte Werte größer sind. Dasselbe Werkzeug kann einen Prozess an die CPUs und den Speicher eines Knotens binden oder Seiten über Knoten verschränken (Interleaving), was zu Daten passt, die jeder Thread gleichmäßig liest. Das Pinnen von Threads (Setzen der CPU-Affinität) hindert den Scheduler daran, einen Thread von seinen Daten wegzuverschieben, und macht Benchmarks reproduzierbar. Der Kernel kann Seiten auch automatisch zu den Threads migrieren, die sie nutzen, aber explizite Platzierung ist für leistungskritischen Code besser vorhersagbar.

Jetzt üben: Fragen zu NUMA (Non-Uniform Memory Access)

Welche Aussage zu NUMA-Systemen (Non-Uniform Memory Access) ist richtig?

  1. AVon allen Kernen aus kann auf den gesamten Speicher in gleicher Zeit zugegriffen werden
  2. BEs gibt Speicher nahe am Kern und weit entfernten Speicher, und der Zugriff auf entfernten Speicher dauert länger
  3. CJeder Kern kann nur seinen eigenen Speicher lesen und den anderer Kerne nicht nutzen
Antwort und Erläuterung anzeigen

Antwort: B. Es gibt Speicher nahe am Kern und weit entfernten Speicher, und der Zugriff auf entfernten Speicher dauert länger

Bei Servern u. Ä. mit mehreren CPU-Sockeln hat jeder Sockel direkt angebundenen Speicher, und auf den Speicher anderer Sockel wird über die Verbindung zwischen den Sockeln zugegriffen. Entfernter Speicher ist daher langsamer als naher und hat eine geringere Bandbreite. Aller Speicher erscheint als ein Adressraum, sodass Programme unverändert laufen; die Leistung steigt jedoch, wenn Daten und Threads auf derselben Seite liegen.

Was ist bei der unter Linux in NUMA-Systemen häufig verwendeten First-Touch-Strategie (die Seite wird im Speicher des Knotens abgelegt, auf dem der Thread läuft, der sie als Erster beschreibt) zu beachten?

  1. ABei First-Touch werden Seiten auf zufälligen Knoten abgelegt
  2. BMit dem Aufruf von malloc steht der Ablageort aller Seiten fest
  3. CWird ein großes Array von nur einem Thread auf 0 initialisiert, liegt alles auf einem Knoten, und Threads anderer Knoten müssen entfernten Speicher verwenden
Antwort und Erläuterung anzeigen

Antwort: C. Wird ein großes Array von nur einem Thread auf 0 initialisiert, liegt alles auf einem Knoten, und Threads anderer Knoten müssen entfernten Speicher verwenden

Mit malloc allein werden noch keine physischen Seiten zugewiesen; erst beim Seitenfehler beim ersten Schreiben werden sie im Speicher des Knotens abgelegt, auf dem der Thread läuft. Wird die Initialisierung von einem einzigen Thread ausgeführt, sammelt sich das gesamte Array auf diesem Knoten, und bei paralleler Berechnung liegt ein Großteil der von den einzelnen Threads bearbeiteten Teile im entfernten Speicher. Erfolgt die Initialisierung parallel mit derselben Aufteilung wie die Berechnung, liegen die Teile nahe beim zuständigen Thread.

Häufige Fragen

Wie prüfe ich, ob mein Rechner NUMA hat?

Unter Linux lscpu oder numactl --hardware ausführen; werden mehr als ein NUMA-Knoten aufgeführt, hängen die Kosten des Speicherzugriffs vom Ort ab. Die meisten Server mit zwei Sockeln zeigen mindestens zwei Knoten.

Müssen Programme für NUMA umgeschrieben werden?

Nein, eine ccNUMA-Maschine stellt einen kohärenten Adressraum bereit, sodass Programme unverändert korrekt laufen. Umschreiben lohnt sich nur für die Leistung, vor allem indem die Daten jedes Threads auf seinem eigenen Knoten gehalten werden.

Was ist die First-Touch-Policy?

Es ist die übliche Regel, dass eine physische Seite auf dem NUMA-Knoten des Threads angelegt wird, der zuerst in sie schreibt. Deshalb ist die parallele Initialisierung von Arrays auf NUMA-Systemen wichtig.
