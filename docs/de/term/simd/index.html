Was ist SIMD?

Abkürzung für Single Instruction, Multiple Data. Verfahren, bei dem ein einziger Befehl dieselbe Operation gleichzeitig auf mehreren Daten ausführt. Beschleunigt Bildverarbeitung und KI-Berechnungen.

Japanische Bezeichnung: SIMD

„SIMD“ kommt in 7 Übungsfragen aus 5 Themen vor, z. B. GPU-Programmierung, Compiler, Computerarithmetik.

Fachgebiet: CPU und Architektur

Wie SIMD funktioniert

Eine SIMD-Einheit (Single Instruction, Multiple Data) behandelt ein breites Register als eine Reihe unabhängiger Lanes. Ein 128-Bit-Register fasst vier 32-Bit-Werte und ein 512-Bit-Register sechzehn; ein einziger Additionsbefehl addiert alle Lanes parallel. Befehlssatzerweiterungen wie SSE und AVX bei x86 sowie NEON und SVE bei Arm bieten Ganzzahl- und Gleitkommaoperationen auf Lanes sowie Lade-, Shuffle- und Vergleichsbefehle. In Flynns Klassifikation steht SIMD neben SISD, einem gewöhnlichen sequenziellen Prozessor, und MIMD, mehreren Kernen mit unabhängigen Befehlsströmen. Bildfilter, Videocodecs und Matrixberechnungen werden typischerweise um ein Mehrfaches oder mehr beschleunigt.

Was eine Schleife vektorisierbar macht

Compiler vektorisieren Schleifen automatisch, die auf jedes Arrayelement dieselbe Operation anwenden. Die wichtigste Bedingung ist das Fehlen einer schleifenübergreifenden Abhängigkeit: Bei a[i] = a[i-1] + b[i] benötigt jedes Element das vorherige Ergebnis, sodass die Lanes nicht gleichzeitig laufen können. Die Daten sollten zusammenhängend liegen, und eine mögliche Überlappung von Zeigern (Aliasing) kann den Compiler zum Aufgeben bringen. Eine zur Übersetzungszeit unbekannte Iterationszahl ist kein Hindernis; die Vektorschleife bearbeitet volle Blöcke, und eine kurze Restschleife erledigt den Rest. Medien-Code nutzt zudem Sättigungsarithmetik, bei der die vorzeichenbehaftete 8-Bit-Rechnung 127 + 1 auf 127 begrenzt wird, statt auf −128 überzulaufen.

Datenlayout: AoS und SoA

Ein Array of Structures (AoS) speichert die Felder jedes Datensatzes zusammen, etwa x, y, z und Masse. Eine Schleife, die nur x liest, verschwendet dann den größten Teil jeder Cache-Zeile und braucht Gather- oder Shuffle-Operationen, um die Vektor-Lanes zu füllen. Eine Structure of Arrays (SoA) hält alle x-Werte zusammenhängend, sodass jede geladene Zeile vollständig genutzt wird, der Speicherverkehr stark sinken kann und ein einziger Vektorladebefehl die Lanes direkt füllt. Dasselbe Layout lässt benachbarte GPU-Threads auf benachbarte Adressen zugreifen, wodurch ihre Speicherzugriffe zusammengefasst werden (Coalescing).

SIMD und SIMT im Vergleich

Bei CPU-SIMD verwendet der Programmierer oder Compiler explizit Vektorbefehle fester Breite, sodass der Code mit Blick auf die Vektorbreite geschrieben wird. GPU-SIMT (Single Instruction, Multiple Threads) lässt den Programmierer gewöhnlichen Code für einen Thread schreiben; die Hardware gruppiert Threads, üblicherweise 32, die im Gleichschritt mit gemeinsamer Befehlsausgabe laufen. Verzweigen Threads einer Gruppe unterschiedlich, führt die Hardware jeden Pfad nacheinander aus und maskiert die inaktiven Threads, sodass der Code weiterhin funktioniert, die Effizienz aber sinkt. Im Kern beruhen beide auf demselben Prinzip, einen Befehl auf viele Datenelemente zu verteilen.

Antwort und Erläuterung anzeigen

Antwort: C. Bei SIMT lässt sich jeder Thread als unabhängiges Programm schreiben, und die Hardware übernimmt auch Verzweigungen, während bei SIMD Programmierer oder Compiler explizit Vektorbefehle fester Breite verwenden

Bei SIMD der CPU wird eine Anweisung auf ein Vektorregister angewendet, das z. B. 4 oder 8 Daten bündelt; das Programm wird daher mit Blick auf die Vektorbreite geschrieben. Bei SIMT der GPU schreibt der Programmierer die Verarbeitung eines einzelnen Threads ganz normal, und die Hardware bündelt je 32 Threads zur Ausführung mit derselben Anweisung. Threads dürfen verzweigen, und die Hardware führt die verzweigten Pfade nacheinander aus, wobei die Effizienz sinkt.

Häufige Fragen

Wofür steht SIMD und was macht es?

Single Instruction, Multiple Data: Ein Befehl arbeitet auf mehreren Datenelementen, die in ein breites Register gepackt sind, etwa vier 32-Bit-Zahlen in einem 128-Bit-Register.

Warum wird meine Schleife nicht automatisch vektorisiert?

Häufige Gründe sind eine schleifenübergreifende Abhängigkeit, bei der ein Durchlauf das Ergebnis des vorherigen benötigt, nicht zusammenhängende Speicherzugriffe oder mögliches Pointer-Aliasing, das der Compiler nicht ausschließen kann.

Unterschied zwischen SIMD und SIMT

SIMD verwendet auf einer CPU explizite Vektorbefehle fester Breite. SIMT, das GPUs nutzen, führt skalaren Code pro Thread auf Gruppen von Threads im Gleichschritt aus, wobei die Hardware divergierende Verzweigungen behandelt.
