Was ist ASLR?

Abkürzung für Address Space Layout Randomization. Schutzmaßnahme, die die Adressen von Stack, Heap, Shared Libraries und ausführbarer Datei bei jedem Start ändert, sodass Angreifer Adressen schwer vorhersagen können.

Japanische Bezeichnung: ASLR

„ASLR“ kommt in 3 Übungsfragen aus 1 Themen vor, z. B. Linker, Loader und ausführbare Formate.

Fachgebiet: Linker, Loader und ausführbare Formate

Wie ASLR einen Prozess verschiebt

Beim Start eines Programms wählen Kernel und dynamischer Loader für jeden wichtigen Bereich des Adressraums zufällige, an Seitengrenzen ausgerichtete Basis-Offsets: für den Stack, den Heap, den mmap-Bereich, in den Shared Libraries abgebildet werden, und für die ausführbare Datei selbst, sofern sie als positionsunabhängige ausführbare Datei (PIE) gebaut wurde. Die relative Reihenfolge der Bereiche bleibt die übliche (Text, Daten, BSS und Heap bei niedrigen Adressen, Stack oben), ihre absoluten Adressen sind aber bei jedem Lauf anders. Address Space Layout Randomization (ASLR) ändert also, wo etwas liegt, nicht, was das Programm tut.

Warum Angreifer Adressen brauchen

Exploits durch Speicherkorruption wie Stack-Pufferüberläufe überschreiben meist eine Rücksprungadresse oder einen Funktionszeiger mit der Adresse von etwas Nützlichem: Shellcode auf dem Stack, eine Bibliotheksfunktion wie system() bei einem Return-to-libc-Angriff oder eine Kette von Befehlsfragmenten beim Return-Oriented Programming (ROP). All das erfordert exakte Adressen. Mit ASLR muss der Angreifer sie erraten, und ein falscher Versuch bringt den Prozess typischerweise zum Absturz, statt die Kontrolle zu übergeben. Der Schutz ist probabilistisch, seine Stärke hängt also davon ab, wie viele Zufallsbits verfügbar sind; in 32-Bit-Adressräumen sind das deutlich weniger als in 64-Bit-Adressräumen.

PIE und positionsunabhängiger Code

ASLR kann nur Code verschieben, der keine feste Ladeadresse voraussetzt. Shared Libraries werden seit Langem als positionsunabhängiger Code (PIC) übersetzt und erreichen ihre Daten über PC-relative Adressierung und die Global Offset Table (GOT). Ältere ausführbare Dateien wurden dagegen für eine feste Adresse gelinkt, sodass der Code des Hauptprogramms an einer bekannten Stelle blieb und Angreifern eine zuverlässige Quelle für ROP-Gadgets bot. Mit -fPIE und -pie gebaut, wird auch die ausführbare Datei relozierbar, sodass der Loader sie ebenfalls randomisieren kann. Auf x86-64 sind die Kosten gering, da PC-relativer Datenzugriff nativ unterstützt wird.

Grenzen und ergänzende Schutzmaßnahmen

Die Randomisierung erfolgt pro Bereich; verrät ein einziger geleakter Zeiger aus einer Bibliothek deren Offset, ist damit die ganze Bibliothek und jede Funktion darin bekannt. Mit fork() erzeugte Kindprozesse erben das Layout des Elternprozesses, sodass Angreifer einen forkenden Server wiederholt abtasten können. Aus diesen Gründen wird ASLR mit nicht ausführbarem beschreibbarem Speicher (W^X oder NX), Stack Canaries und Schutzmechanismen für den Kontrollfluss kombiniert. Auch der Betriebssystemkernel kann randomisiert werden; das nennt man KASLR. Unter Linux ist die Einstellung in /proc/sys/kernel/randomize_va_space sichtbar.

Jetzt üben: Fragen zu ASLR

Welche Aussage zum Zweck von ASLR (Address Space Layout Randomization) ist richtig?

  1. ADie Adressen von Stack, Heap, Bibliotheken usw. werden bei jeder Ausführung geändert, sodass die Zieladressen von Angreifern schwer vorhersagbar sind
  2. BSpeicheradressen werden zufällig gewählt, um die Cache-Trefferrate zu erhöhen
  3. CUngenutzter Speicher wird zufällig freigegeben, um den freien Platz zu vergrößern
Antwort und Erläuterung anzeigen

Antwort: A. Die Adressen von Stack, Heap, Bibliotheken usw. werden bei jeder Ausführung geändert, sodass die Zieladressen von Angreifern schwer vorhersagbar sind

Bei Angriffen, die z. B. Pufferüberläufe ausnutzen, ist es wichtig, die Adressen von Bibliotheksfunktionen und Daten auf dem Stack zu kennen. ASLR verschiebt bei jedem Prozessstart die Adressen, an denen Stack, Heap, Shared Libraries und die ausführbare Datei liegen, sodass Angreifer die Adressen nicht fest vorgeben können. Allein bietet es keinen vollständigen Schutz und wird mit weiteren Maßnahmen wie der Trennung von Schreiben und Ausführen kombiniert.

Häufige Fragen

Verhindert ASLR Pufferüberlauf-Angriffe?

Nein. ASLR stoppt den Überlauf selbst nicht, sondern erschwert nur zu wissen, welche Adresse angesprungen werden soll, sodass die meisten Versuche abstürzen, statt zu gelingen. Ein Informationsleck, das eine einzige echte Adresse preisgibt, kann ASLR aushebeln, deshalb wird es mit NX-Speicher und Stack Canaries kombiniert.

Was ist der Unterschied zwischen ASLR und PIE?

ASLR ist der Betriebssystemmechanismus, der Speicherbereiche bei jedem Lauf an zufälligen Adressen lädt. PIE ist eine Art, die ausführbare Datei so zu übersetzen und zu linken, dass ihr Code an jeder Adresse funktioniert; damit kann ASLR neben Bibliotheken, Stack und Heap auch das Hauptprogramm randomisieren.

Wie prüft man, ob ASLR unter Linux aktiviert ist?

Man liest /proc/sys/kernel/randomize_va_space: 0 bedeutet deaktiviert, 1 randomisiert Stack, mmap-Bereich und Shared Libraries, und 2 randomisiert zusätzlich den brk-basierten Heap. Die meisten Distributionen verwenden standardmäßig 2.
