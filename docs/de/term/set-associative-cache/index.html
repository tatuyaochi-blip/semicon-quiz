Was ist Mengenassoziative Abbildung (Set-Associative)?

Cache-Organisation, bei der Daten an jeder von mehreren Positionen (Ways) innerhalb eines durch die Adresse bestimmten Sets abgelegt werden können. Bei n Ways werden pro Zugriff n Tags parallel verglichen.

Japanische Bezeichnung: セットアソシアティブ方式

„Mengenassoziative Abbildung (Set-Associative)“ kommt in 1 Übungsfragen aus 1 Themen vor, z. B. CPU und Architektur.

Fachgebiet: Speicherhierarchie und Leistung

Wie die Adresse aufgeteilt wird

Eine Cache-Adresse wird in drei Felder aufgeteilt. Die niederwertigen Offset-Bits wählen ein Byte innerhalb einer Cache-Zeile, die Index-Bits wählen ein Set, und die verbleibenden höherwertigen Bits bilden das Tag, das zusammen mit der Zeile gespeichert wird. Die Anzahl der Sets ist gleich der Kapazität geteilt durch Zeilengröße mal Anzahl der Ways. Für einen 32-KB-Cache mit 64-Byte-Zeilen und 32-Bit-Adressen gibt es 512 Zeilen: Direkt abgebildet ergibt das 512 Sets, einen 9-Bit-Index und ein 17-Bit-Tag, während 4-fach assoziativ 128 Sets, einen 7-Bit-Index und ein 19-Bit-Tag ergibt. Jede Verdopplung der Assoziativität entfernt ein Index-Bit und fügt ein Tag-Bit hinzu.

Was bei einem Zugriff passiert

Der Index wählt ein Set aus, und die Tags aller n Ways in diesem Set werden gelesen und gleichzeitig mit dem Adress-Tag verglichen, sodass ein 8-fach assoziativer Cache acht Komparatoren benötigt. Jeder Vergleich prüft zudem ein Valid-Bit. Der Way mit übereinstimmendem Tag steuert einen Multiplexer, der die Daten liefert; viele schnelle L1-Designs lesen die Daten aller Ways parallel zur Tag-Prüfung und wählen am Ende aus, wobei sie Leistung gegen Geschwindigkeit eintauschen. Bei einem Fehlzugriff wählt eine Ersetzungsstrategie wie LRU (Least Recently Used) oder eine günstigere Pseudo-LRU-Näherung aus, welcher Way im Set verdrängt wird.

Direkt abgebildet, mengenassoziativ und vollassoziativ

Dies sind Punkte auf einem Spektrum. Ein direkt abgebildeter Cache ist 1-fach assoziativ: Jede Adresse hat genau einen möglichen Platz, sodass sich zwei häufig genutzte Blöcke mit demselben Index wiederholt gegenseitig verdrängen, ein Konfliktfehlzugriff. Ein vollassoziativer Cache ist ein einziges Set, in dem jede Zeile überall abgelegt werden kann, was Konfliktfehlzugriffe beseitigt, aber einen Vergleich mit jedem Tag erfordert. Mengenassoziative Caches liegen dazwischen. Eine höhere Assoziativität verringert Konfliktfehlzugriffe, nicht aber Pflicht- (Compulsory) oder Kapazitätsfehlzugriffe, und der Nutzen nimmt jenseits von etwa 8 Ways ab, während Komparatoren, Multiplexerverzögerung, Trefferzeit und Leistungsaufnahme weiter steigen.

Typische Werte

Level-1-Caches sind üblicherweise 4- bis 12-fach assoziativ, weil die Trefferzeit kritisch und der Cache klein ist. Last-Level-Caches, bei denen ein Fehlzugriff einen Weg zum DRAM kostet, verwenden oft etwa 16 Ways, da ein etwas langsamerer Treffer im Austausch für weniger Fehlzugriffe akzeptabel ist. Translation Lookaside Buffers (TLBs) sind häufig hoch- oder vollassoziativ, weil sie wenige Einträge haben und ein Fehlzugriff teuer ist. Bei der Abschätzung der Hardwarekosten ist zu beachten, dass auch der Tag-Speicher mit der Assoziativität wächst, da bei gleicher Kapazität jede Verdopplung der Ways ein Index-Bit entfernt und jedes gespeicherte Tag um ein Bit verlängert.

Jetzt üben: Fragen zu Mengenassoziative Abbildung (Set-Associative)

Welche Aussage zu einem satzassoziativen (Set-Associative) Cache ist richtig?

  1. ADie Daten einer Adresse können an mehreren Stellen (Ways) innerhalb eines bestimmten Satzes abgelegt werden
  2. BDer Ort, an dem Daten einer Adresse abgelegt werden können, ist im Cache auf eine einzige Stelle festgelegt
  3. CDaten können an beliebiger Stelle im Cache abgelegt werden
Antwort und Erläuterung anzeigen

Antwort: A. Die Daten einer Adresse können an mehreren Stellen (Ways) innerhalb eines bestimmten Satzes abgelegt werden

Beim satzassoziativen Verfahren bestimmt ein Teil der Adresse den Satz, und die Daten können in einem von mehreren Ways darin abgelegt werden. Bei 8 Ways gibt es z. B. acht Kandidaten, und Konkurrenz um denselben Platz (Konfliktfehlzugriffe) tritt seltener auf als bei direkt abgebildeten Caches. Mehr Ways erhöhen Vergleichsschaltungen und Leistungsaufnahme; üblich sind etwa 8 bis 12 Ways bei L1 und um die 16 Ways bei L3. Beliebige Platzierung bietet das vollassoziative Verfahren.

Häufige Fragen

Wie berechnet man die Anzahl der Sets in einem mengenassoziativen Cache?

Teilen Sie die Kapazität durch die Zeilengröße, um die Anzahl der Zeilen zu erhalten, und teilen Sie dann durch die Anzahl der Ways. Ein 4-fach assoziativer 32-KB-Cache mit 64-Byte-Zeilen hat 512 Zeilen und damit 128 Sets.

Macht eine höhere Assoziativität einen Cache immer schneller?

Nein. Sie verringert Konfliktfehlzugriffe, doch jeder Zugriff muss mehr Tags vergleichen und unter mehr Ways auswählen, was tendenziell die Trefferzeit verlängert und die Leistungsaufnahme erhöht. Die beste Wahl wägt für die jeweilige Cache-Ebene die Fehlzugriffsrate gegen die Trefferzeit ab.

Unterschied zwischen Set und Way im Cache?

Ein Set ist die Gruppe von Plätzen, die ein Indexwert auswählt, und ein Way ist ein Platz innerhalb dieses Sets. Ein 8-fach assoziativer Cache hat in jedem Set acht Ways, und ein Block kann in jedem davon abgelegt werden.
