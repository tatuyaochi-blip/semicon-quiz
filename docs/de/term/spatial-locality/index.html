Was ist Räumliche Lokalität?

Eigenschaft, dass nach dem Zugriff auf eine Adresse bald auch auf benachbarte Adressen zugegriffen wird. Beispiel ist das sequenzielle Lesen eines Arrays; Grund dafür, dass Daten in Cache-Zeilen gebündelt geladen werden.

Japanische Bezeichnung: 空間的局所性

„Räumliche Lokalität“ kommt in 3 Übungsfragen aus 2 Themen vor, z. B. CPU und Architektur, Speicherhierarchie und Leistung.

Fachgebiet: Speicherhierarchie und Leistung

Warum Programme sie aufweisen

Befehle werden bis zu einer Verzweigung nacheinander von aufeinanderfolgenden Adressen geholt, Arrays werden üblicherweise Element für Element durchlaufen, und die Felder einer Struktur oder die lokalen Variablen eines Stackframes liegen nebeneinander. Daher folgen auf einen Zugriff auf eine Adresse oft bald Zugriffe auf benachbarte Adressen. Räumliche Lokalität ist diese Tendenz, und sie ist eine Eigenschaft des Zugriffsmusters des Programms, nicht der Hardware.

Wie Hardware sie ausnutzt

Caches übertragen Daten in Zeilen, bei aktuellen CPUs typischerweise 64 Byte, sodass ein Miss Nachbarn mitbringt, die wahrscheinlich als Nächstes benötigt werden. Das passt auch zu DRAM-Bursts: Bei DDR4 liefern acht Übertragungen zu 8 Byte genau 64 Byte. Hardware-Prefetcher erkennen sequenzielle Ströme oder solche mit konstantem Stride und holen kommende Zeilen im Voraus, und offen gehaltene DRAM-Zeilen bedienen benachbarte Zugriffe schneller. Auch Seiten und der TLB profitieren, da eine Übersetzung viele benachbarte Adressen abdeckt.

Räumliche vs. zeitliche Lokalität

Zeitliche Lokalität bedeutet, dieselben Daten bald wiederzuverwenden, etwa einen Schleifenzähler oder eine laufende Summe; räumliche Lokalität bedeutet, bald benachbarte Daten zu verwenden, etwa das nächste Array-Element. Ein einzelner Durchlauf über ein großes Array hat starke räumliche, aber keine zeitliche Lokalität, während das wiederholte Aktualisieren einer Variable zeitliche, aber kaum räumliche Lokalität hat. Zufällige Zugriffe auf einen großen Datenbestand, wie bei manchen Hashtabellen oder Graphtraversierungen, haben von beidem wenig und erzeugen häufig Misses.

Code schreiben, der sie besitzt

In C werden zweidimensionale Arrays zeilenweise (row-major) gespeichert, sodass eine innere Schleife über die Spalten aufeinanderfolgende Adressen berührt, während vertauschte Schleifen bei jedem Schritt eine ganze Zeile springen. Ein Structure-of-Arrays-Layout, wenn nur ein Feld verarbeitet wird, vermeidet das Laden ungenutzter Felder. Größere Cache-Zeilen nutzen räumliche Lokalität besser, erhöhen aber die Miss-Penalty und können unnötige Daten laden, und in Multithread-Code verursachen unabhängige Variablen in derselben Zeile False Sharing.

Antwort und Erläuterung anzeigen

Antwort: B. Häufig benutzte Daten nahe an der CPU abzulegen und so den Geschwindigkeitsunterschied zum Hauptspeicher zu verringern

Während die CPU einen Takt (0,2 bis 0,3 ns) verarbeitet, dauert ein DRAM-Zugriff einige zehn bis 100 ns, also einige hundert Takte. Daher werden häufig genutzte Daten und Befehle in einem schnellen SRAM-Cache abgelegt, um Wartezeiten zu verringern. Genutzt werden die zeitliche Lokalität (dieselben Daten werden bald wieder verwendet) und die räumliche Lokalität (benachbarte Adressen werden nacheinander verwendet); der Zugriff dauert bei L1 einige Takte und selbst bei L3 einige zehn Takte.

Welche Größe der Cache-Zeile (Cache-Block) wird bei den meisten heutigen CPUs verwendet?

  1. A1 Byte
  2. B64 Byte
  3. C64 MB
Antwort und Erläuterung anzeigen

Antwort: B. 64 Byte

Die meisten CPUs tauschen Daten zwischen Cache und Hauptspeicher in Zeilen von 64 Byte aus. Daten benachbarter Adressen werden oft nacheinander verwendet (räumliche Lokalität), sodass gebündeltes Laden effizient ist; es passt auch zum Burst-Transfer von DRAM (bei DDR4 8 × 8 Byte = 64 Byte). Bei Multithread-Programmen ist auf False Sharing zu achten, bei dem sich getrennte Variablen in derselben Zeile befinden und um diese konkurrieren.

Häufige Fragen

Beispiel für räumliche Lokalität

Ein Array von Anfang bis Ende lesen: Nachdem Element i verwendet wurde, wird Element i+1 an der nächsten Adresse verwendet, und es wurde wahrscheinlich durch dieselbe Zeilenfüllung in den Cache geholt.

Wie nutzen Caches räumliche Lokalität aus?

Sie übertragen bei jedem Miss ganze Cache-Zeilen, üblicherweise 64 Byte, und holen oft die folgenden Zeilen im Voraus, sodass benachbarte Daten bereits vorhanden sind, wenn das Programm sie anfordert.

Warum ist spaltenweises Durchlaufen eines C-Arrays langsam?

C speichert Arrays zeilenweise, sodass das Fortschreiten entlang einer Spalte bei jedem Zugriff eine ganze Zeile springt und nur einen kleinen Teil jeder geholten Cache-Zeile nutzt.
