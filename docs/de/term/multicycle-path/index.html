Was ist Multicycle-Pfad?

Timing-Ausnahme, die der STA mitteilt, dass ein Pfad für die Datenübertragung mehrere Taktzyklen benötigen darf. Wird Setup auf N Zyklen gesetzt, setzt man Hold meist auf N − 1, um die Prüfflanke für Hold an ihre ursprüngliche Position zurückzuschieben.

Japanische Bezeichnung: マルチサイクルパス

„Multicycle-Pfad“ kommt in 3 Übungsfragen aus 1 Themen vor, z. B. Timing-Analyse und CDC.

Fachgebiet: Timing-Analyse und CDC

Wenn ein Pfad wirklich mehr Zeit hat

Manche Pfade müssen die Daten nicht innerhalb einer Taktperiode liefern, weil das Ziel nur alle N Zyklen übernimmt, zum Beispiel ein Register, das über ein Enable geladen wird, das jeden zweiten Zyklus aktiv ist, oder ein langsamer Rechenblock, dessen Ergebnis zwei Zyklen nach der Änderung seiner Eingänge abgetastet wird. Standardmäßig geht die STA von einer Übertragung in einem Zyklus aus und meldet eine Verletzung. Eine Multicycle-Path-Ausnahme, set_multicycle_path in SDC, teilt dem Werkzeug mit, dass die Capture-Flanke N Perioden statt einer nach dem Launch liegt.

Setup-Rechnung

Bei einem 2,0-ns-Takt, einer Datenankunftszeit von 3,3 ns und einer Setup-Zeit von 0,1 ns ergibt die standardmäßige Einzyklusprüfung eine geforderte Zeit von 1,9 ns und einen Slack von −1,4 ns. Ein Setup-Multicycle von 2 verschiebt den Capture auf 4,0 ns, sodass die geforderte Zeit 3,9 ns und der Slack +0,6 ns beträgt. Die Ausnahme ist nur gültig, wenn die Logik die Übernahme in jedem zweiten Zyklus tatsächlich garantiert; andernfalls verdeckt sie einen echten Fehler, der im Silizium auftreten wird.

Warum Hold N − 1 braucht

Die STA prüft Hold gegen die Flanke eine Periode vor der Setup-Capture-Flanke. Wird der Setup-Capture auf N Perioden verschoben, wird daher auch die Hold-Prüfung auf N − 1 Perioden nach dem Launch gezogen, was verlangen würde, dass neue Daten mindestens so spät eintreffen, eine absurd strenge Anforderung, die meist verletzt wird. Ein zusätzlicher Hold-Multicycle von N − 1 verschiebt die Hold-Prüfung zurück auf die Launch-Flanke zum Zeitpunkt null und stellt die gewöhnliche Hold-Bedingung wieder her. Er entfernt die Hold-Prüfung nicht.

Multicycle-Pfad vs. False Path

Ein Multicycle-Pfad bleibt zeitlich analysiert, nur mit einem größeren Budget. Ein False Path, gesetzt mit set_false_path, wird vollständig von der Analyse ausgeschlossen und ist für Pfade gedacht, die strukturell verbunden sind, aber nie einen sinnvollen Übergang übertragen können, zum Beispiel durch zwei Multiplexer, deren Auswahlbedingungen sich gegenseitig ausschließen. Einen Pfad nur deshalb als False Path zu deklarieren, weil das Timing schwer zu schließen ist, verdeckt echte Fehler, und einen echten Multicycle-Pfad als False Path zu deklarieren, entfernt eine Prüfung, die er weiterhin braucht.

Jetzt üben: Fragen zu Multicycle-Pfad

In einer Schaltung mit einem Takt der Periode 2,0 ns gibt es einen Pfad mit einer Datenankunftszeit (Summe aus Clock-to-Q-Verzögerung und Verzögerung der kombinatorischen Logik) von 3,3 ns und einer Setup-Zeit von 0,1 ns. Da dieser Pfad nur alle 2 Zyklen einmal übernommen werden muss, wurde für Setup ein Multicycle-Pfad von 2 gesetzt. Wie groß ist der Setup-Slack?

  1. A−1,4 ns
  2. B+2,6 ns
  3. C+0,6 ns
Antwort und Erläuterung anzeigen

Antwort: C. +0,6 ns

Mit einem Multicycle-Pfad von 2 liegt die übernehmende Flanke nicht 1 Periode, sondern 2 Perioden später. Die geforderte Zeit beträgt 2 × 2,0 − 0,1 = 3,9 ns, die Ankunftszeit 3,3 ns; der Slack beträgt also +0,6 ns. −1,4 ns ist der Wert, der wie für einen normalen 1-Zyklus-Pfad berechnet wurde, +2,6 ns der Wert, bei dem die Zeit von 3 Zyklen gewährt wurde. Ein Multicycle-Pfad darf nur gesetzt werden, nachdem der Entwickler sich vergewissert hat, dass die Schaltung, etwa über ein Enable-Signal, tatsächlich nur alle 2 Zyklen übernimmt.

Wird für Setup ein Multicycle-Pfad von N (N ≥ 2) gesetzt, wird üblicherweise auch für Hold ein Multicycle-Pfad von N − 1 gesetzt. Was ist der richtige Grund dafür?

  1. AWeil sich die Prüfflanke für Hold zusammen mit der für Setup nach hinten verschiebt und die Prüfung zu streng wird; sie soll an die ursprüngliche Position zurückgesetzt werden
  2. BUm die Prüfflanke für Hold noch weiter nach hinten zu verschieben und so den Hold-Spielraum zu vergrößern
  3. CUm die Hold-Prüfung dieses Pfads von der Analyse auszuschließen
Antwort und Erläuterung anzeigen

Antwort: A. Weil sich die Prüfflanke für Hold zusammen mit der für Setup nach hinten verschiebt und die Prüfung zu streng wird; sie soll an die ursprüngliche Position zurückgesetzt werden

Standardmäßig prüft die STA Hold an der Flanke, die eine vor der Setup-Übernahmeflanke liegt. Wird Setup auf 2 Zyklen gesetzt, wandert auch die Prüfflanke für Hold von Zeitpunkt 0 um 1 Periode nach hinten; bei einer Periode von 2,0 ns entsteht dann eine Verletzung, sofern die Daten nicht mindestens 2,0 ns verspätet ankommen. Wird für Hold ein Multicycle-Pfad von N − 1 = 1 angegeben, kehrt die Prüfflanke zu Zeitpunkt 0 zurück, und es gelten dieselben Bedingungen wie für normale Pfade. Die Hold-Prüfung wird dabei nicht entfernt.

Häufige Fragen

Warum Hold-Multicycle N − 1 bei Setup-Multicycle N?

Das Verschieben der Setup-Capture-Flanke verschiebt auch die standardmäßige Hold-Prüfung nach hinten, sodass Hold kaum noch einzuhalten ist. Die Hold-Einstellung N − 1 bringt die Hold-Prüfung auf ihre ursprüngliche Flanke zurück.

Unterschied zwischen Multicycle-Pfad und False Path

Ein Multicycle-Pfad wird weiterhin analysiert, erhält aber mehrere Taktperioden. Ein False Path wird überhaupt nicht analysiert und sollte nur für Pfade verwendet werden, die funktional nie durchlaufen werden können.

Wann ist ein Multicycle-Pfad sicher?

Nur wenn das Design garantiert, dass das Ziel die Daten alle N Zyklen abtastet, zum Beispiel über ein Enable, und die Verifikation dieses Verhalten bestätigt. Andernfalls kann die gelockerte Prüfung einen echten Timing-Fehler verdecken.
