Was ist Cache-Zeile (Cache Line)?

Einheit, in der Daten zwischen Cache und der darunterliegenden Hierarchieebene gelesen und geschrieben werden. Auch Cache-Block genannt. Bei vielen CPUs 64 Byte; die niederwertigen Adressbits geben die Position (Offset) in der Zeile an.

Japanische Bezeichnung: キャッシュライン

Fachgebiet: Speicherhierarchie und Leistung

Warum Caches ganze Zeilen übertragen

Programme, die auf eine Adresse zugreifen, greifen meist kurz darauf auch auf benachbarte Adressen zu – eine Eigenschaft, die räumliche Lokalität genannt wird. Caches nutzen sie aus, indem sie Daten in festen Blöcken von typischerweise 64 Byte statt in einzelnen Wörtern übertragen, und diese Größe entspricht praktischerweise genau einem DRAM-Burst: acht Übertragungen zu je 8 Byte auf einem 64-Bit-DDR4-Kanal. Jede gecachte Zeile trägt einen Tag, der ihre Adresse kennzeichnet, ein Valid-Bit, das gültige Daten markiert, in Write-Back-Caches ein Dirty-Bit sowie Ersetzungs- und Kohärenzzustände. Eine Adresse zerfällt daher in die Felder Tag, Index und Offset; bei 64-Byte-Zeilen bilden die niedrigsten 6 Bit den Offset.

Zeilengröße und Zugriffsmuster

Die Zeilengröße übersetzt Zugriffsmuster in Fehlzugriffsraten. Wird ein Array aus 4-Byte-Ganzzahlen der Reihe nach gelesen, tritt ein Fehlzugriff pro 16 Elemente auf, also eine Fehlzugriffsrate von 6,25 %, weil jeder Fehlzugriff die nächsten 15 Elemente mitlädt. Wird nur jedes 16. Element gelesen, gibt es bei jedem Zugriff einen Fehlzugriff. C speichert zweidimensionale Arrays zeilenweise (Row-Major), sodass eine innere Schleife über den Spaltenindex aufeinanderfolgende Adressen durchläuft, während vertauschte Schleifen bei jedem Zugriff eine ganze Zeile überspringen und Zeilen verdrängen können, bevor sie wiederverwendet werden. Größere Zeilen helfen sequenziellem Code, verschwenden aber Bandbreite und Kapazität, wenn von jeder Zeile nur wenig genutzt wird.

Kohärenz arbeitet zeilenweise

In einem Mehrkernprozessor verfolgen Kohärenzprotokolle den Besitz mit der Granularität einer Zeile. Bei MESI ist jede Zeile Modified (geändert und nur hier vorhanden, der Speicher ist also veraltet), Exclusive (unverändert und nur hier vorhanden), Shared (unveränderte Kopien können anderswo existieren) oder Invalid. Ein Kern, der schreiben will, muss zunächst die Kopien in anderen Caches invalidieren; eine Zeile, die bereits im Zustand M ist, kann wiederholt beschrieben werden, ohne jemanden zu benachrichtigen. Kleine Systeme senden diese Anfragen per Broadcast, während große Systeme Verzeichnisse (Directories) nutzen, die festhalten, welche Caches jede Zeile halten, sodass der Datenverkehr mit der Zahl der Kerne skaliert.

False Sharing

Da Kohärenz zeilenweise arbeitet, invalidieren zwei Threads, die verschiedene Variablen schreiben, die zufällig in derselben 64-Byte-Zeile liegen, bei jedem Schreibvorgang gegenseitig ihre Kopien. Die Zeile springt zwischen den Kernen hin und her; die Ergebnisse bleiben korrekt, doch die Leistung kann stark einbrechen. Arrays mit Zählern oder Flags pro Thread sind der klassische Fall. Abhilfe schafft es, die Daten jedes Threads durch Auffüllen (Padding) oder Ausrichten in eine eigene Zeile zu legen, zum Beispiel mit Ausrichtungsattributen in C und C++. Davon zu unterscheiden ist True Sharing, bei dem Threads tatsächlich auf dieselbe Variable zugreifen und sich die Kommunikation nicht durch das Datenlayout vermeiden lässt.

  1. A1 Byte
  2. B64 Byte
  3. C64 MB
Antwort und Erläuterung anzeigen

Antwort: B. 64 Byte

Die meisten CPUs tauschen Daten zwischen Cache und Hauptspeicher in Zeilen von 64 Byte aus. Daten benachbarter Adressen werden oft nacheinander verwendet (räumliche Lokalität), sodass gebündeltes Laden effizient ist; es passt auch zum Burst-Transfer von DRAM (bei DDR4 8 × 8 Byte = 64 Byte). Bei Multithread-Programmen ist auf False Sharing zu achten, bei dem sich getrennte Variablen in derselben Zeile befinden und um diese konkurrieren.

Welche Rolle hat das Valid-Bit, das jeder Cache-Zeile zugeordnet ist?

  1. AEs zeigt an, ob die Zeile überschrieben wurde
  2. BEs zeigt die Reihenfolge an, in der die Zeile als Nächstes verdrängt wird
  3. CEs zeigt an, ob sinnvolle Daten enthalten sind
Antwort und Erläuterung anzeigen

Antwort: C. Es zeigt an, ob sinnvolle Daten enthalten sind

Unmittelbar nach dem Einschalten oder nach dem Ungültigmachen einer Zeile ist der Inhalt des Caches bedeutungslos. Eine Zeile mit Valid-Bit 0 gilt auch dann nicht als Treffer, wenn das Tag zufällig übereinstimmt, und das Bit wird auf 1 gesetzt, wenn korrekte Daten geladen wurden. Dadurch wird verhindert, dass eine leere Zeile fälschlich als Treffer erkannt wird. Ob überschrieben wurde, zeigt das beim Write-Back verwendete Dirty-Bit an, und die Verdrängungsreihenfolge wird durch Informationen zur Ersetzung wie LRU verwaltet.

Häufige Fragen

Wie groß ist eine Cache-Zeile?

Bei den meisten aktuellen CPUs 64 Byte, manche Prozessoren verwenden jedoch 32 oder 128 Byte; die Größe ist eine Hardwareeigenschaft, die Software abfragen kann.

Unterschied zwischen Cache-Zeile und Page

Eine Cache-Zeile, meist 64 Byte, ist die Einheit, die zwischen Cache-Ebenen und Speicher übertragen wird, während eine Page, oft 4 KB, die Einheit der virtuellen Speicherabbildung ist, die von Betriebssystem und MMU verwaltet wird.

False Sharing vermeiden – wie?

Daten, die von verschiedenen Threads geschrieben werden, in getrennte Cache-Zeilen legen, typischerweise indem man Strukturen pro Thread auf 64 Byte auffüllt oder ausrichtet.
