Was ist Shared Memory?

Kleiner, schneller Speicher in jedem SM der GPU, der von den Threads desselben Blocks gemeinsam genutzt werden kann. Was dort abgelegt wird, bestimmt das Programm.

Japanische Bezeichnung: シェアードメモリ

Fachgebiet: GPU-Programmierung

Jetzt üben: Fragen zu Shared Memory

Welche Aussage zum Shared Memory von CUDA ist richtig?

  1. AEin großer Hauptspeicher, der von allen GPUs und der CPU gemeinsam genutzt wird
  2. BEin Bereich, in dem sich der GPU-Speicher mit der Festplatte teilt
  3. CEin kleiner, schneller Speicher auf dem Chip, den sich die Threads desselben Blocks teilen können und der vom Programm explizit verwendet wird
Antwort und Erläuterung anzeigen

Antwort: C. Ein kleiner, schneller Speicher auf dem Chip, den sich die Threads desselben Blocks teilen können und der vom Programm explizit verwendet wird

Der Shared Memory ist ein schneller Speicher von einigen zehn KB pro Block in jedem SM, der um ein Vielfaches schneller gelesen und geschrieben werden kann als der Global Memory (DRAM der GPU). Da Threads desselben Blocks hier Daten ablegen und teilen können, dient er dazu, Daten nur einmal aus dem Global Memory zu laden und mehrfach zu verwenden oder Zwischenergebnisse zwischen Threads auszutauschen. Anders als bei einem Cache legt das Programm fest, was abgelegt wird.

Welche Aussage zum Bank Conflict im Shared Memory von CUDA ist richtig?

  1. AEin Problem, wenn zwei GPUs dasselbe Bankkonto verwenden
  2. BEin Problem, bei dem die Kapazität des Shared Memory nicht ausreicht und das Programm anhält
  3. CDer Shared Memory ist in 32 Bänke unterteilt; greifen mehrere Threads eines Warps gleichzeitig auf unterschiedliche Adressen in derselben Bank zu, werden die Zugriffe nacheinander ausgeführt und verlangsamt
Antwort und Erläuterung anzeigen

Antwort: C. Der Shared Memory ist in 32 Bänke unterteilt; greifen mehrere Threads eines Warps gleichzeitig auf unterschiedliche Adressen in derselben Bank zu, werden die Zugriffe nacheinander ausgeführt und verlangsamt

Der Shared Memory besteht aus 32 Bänken, denen je 4 Byte der Reihe nach zugewiesen sind, und jede Bank kann pro Zugriff nur eine Adresse lesen oder schreiben. Verwenden die 32 Threads eines Warps verschiedene Bänke, genügt ein Zugriff, nutzen zwei Threads dieselbe Bank mit unterschiedlichen Adressen, zerfällt er in zwei Zugriffe. Wird z. B. in Abständen von 32 Elementen gelesen, treffen alle auf dieselbe Bank, und der Zugriff zerfällt in 32. Lesen alle dieselbe Adresse, wird sie an alle gleichzeitig verteilt, und es gibt keinen Konflikt.
