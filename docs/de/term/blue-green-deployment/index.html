Was ist Blue-Green-Deployment?

Release-Verfahren, bei dem zwei Umgebungen (blau und grün) mit derselben Konfiguration wie die Produktion bereitgestellt werden; in der einen läuft die aktuelle Version weiter, während in der anderen die neue Version installiert und geprüft wird, und dann wird der Load Balancer o. Ä. auf einen Schlag umgeschaltet. Bei Problemen genügt es, zurückzuschalten, um die alte Version wiederherzustellen. Rund um die Umschaltung werden Ressourcen für zwei Umgebungen benötigt, und Änderungen am Datenbankschema müssen in einer Form erfolgen, die sowohl die alte als auch die neue Version nutzen kann.

Japanische Bezeichnung: ブルーグリーンデプロイメント

Antwort: A. Blue-Green-Deployment

Beim Blue-Green-Deployment werden zwei Umgebungen (blau und grün) bereitgestellt, und der Verkehr der Nutzer wird auf einen Schlag auf die neue Umgebung umgeschaltet. Die alte Umgebung bleibt eine Weile unverändert bestehen; tritt ein Problem auf, genügt es, zurückzuschalten, um die alte Version wiederherzustellen. Andererseits werden rund um die Umschaltung Ressourcen für zwei Umgebungen benötigt, und Änderungen am Datenbankschema müssen in einer Form erfolgen, die sowohl die alte als auch die neue Version nutzen kann. Ein Canary-Release gibt die neue Version nur für einen Teil der Anfragen frei, und ein Rolling Update ersetzt die Server schrittweise.
