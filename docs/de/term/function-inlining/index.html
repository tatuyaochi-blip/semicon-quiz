Was ist Inlining?

Optimierung, bei der ein Funktionsaufruf durch den Rumpf der aufgerufenen Funktion ersetzt wird. Der Aufrufaufwand entfällt und weitere Optimierungen greifen besser, der Code wird jedoch größer.

Japanische Bezeichnung: インライン展開

„Inlining“ kommt in 4 Übungsfragen aus 2 Themen vor, z. B. Compiler, Linker, Loader und ausführbare Formate.

Jetzt üben: Fragen zu Inlining

Welche Kombination aus Vor- und Nachteil des Inlinings von Funktionen ist richtig?

  1. AVorteil ist kleinerer Code, Nachteil ist mehr Aufrufaufwand
  2. BVorteil ist schnellere Kompilierung, Nachteil ist, dass sich das Ausführungsergebnis ändert
  3. CVorteil ist der entfallende Aufrufaufwand, Nachteil ist größerer Code
Antwort und Erläuterung anzeigen

Antwort: C. Vorteil ist der entfallende Aufrufaufwand, Nachteil ist größerer Code

Beim Inlining wird anstelle des Aufrufs der Funktionsrumpf eingefügt, sodass der Aufwand für die Übergabe der Argumente, den Sprung und die Rückkehr entfällt. Ein großer Vorteil ist zudem, dass Konstanten usw. der aufrufenden Seite in den Rumpf propagiert werden und Constant Folding sowie Entfernung von totem Code greifen. Andererseits entsteht bei jedem Aufruf eine Kopie des Rumpfs, der Code wächst, und es können mehr Instruktionscache-Misses auftreten; daher werden kleine oder häufig aufgerufene Funktionen ausgewählt. Bei korrekter Ausführung ändert sich das Ergebnis nicht.

Welche Optimierung wird durch Link-Time Optimization (LTO) am ehesten möglich?

  1. AAuch Funktionen in verschiedenen Dateien können z. B. inline eingesetzt werden
  2. BNur Schleifen innerhalb einer einzelnen Funktion lassen sich entfalten
  3. CDas Linken entfällt, und Objektdateien sind direkt ausführbar
Antwort und Erläuterung anzeigen

Antwort: A. Auch Funktionen in verschiedenen Dateien können z. B. inline eingesetzt werden

Bei der normalen Kompilierung wird jede Quelldatei einzeln in Maschinencode übersetzt; der Inhalt von Funktionen in anderen Dateien ist daher nicht sichtbar, und dateiübergreifendes Inlining oder Konstantenpropagierung ist nicht möglich. Bei LTO werden die einzelnen Dateien in der Zwischendarstellung belassen und das gesamte Programm wird beim Linken gemeinsam optimiert. Dadurch werden dateiübergreifendes Inlining und die Entfernung von nirgends aufgerufenen Funktionen möglich. Das Entfalten von Schleifen innerhalb einer Funktion ist auch bei der normalen Kompilierung möglich.
