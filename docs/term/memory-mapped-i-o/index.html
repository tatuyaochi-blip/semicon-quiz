メモリマップドI/Oとは

めもりまっぷどあいおー

周辺装置のレジスタを、メモリと同じアドレス空間の特定のアドレスに割り当て、通常の読み書き命令で操作する方式。その領域はキャッシュしない設定にする。

「メモリマップドI/O」は、2分野の3問の練習問題に出てきます(OSとハードウェア, CPU・アーキテクチャなど)。

この用語の分野: OSとハードウェア

メモリマップドI/Oの仕組み

プロセッサのアドレスデコーダは、特定のアドレス範囲へのアクセスをRAMではなく周辺装置に振り向けます。タイマーの制御レジスタ、UARTのデータレジスタ、GPIOポートなどはそれぞれ決まったアドレスに現れ、通常のロード命令やストア命令がその装置への読み書きになります。メモリと違って、こうしたアクセスには副作用を伴うことがあります。ステータスレジスタやデータレジスタを読むとフラグがクリアされたりFIFOからデータが取り出されたりし、1を書き込むと割り込みがクリアされることもあります。また、ハードウェアがプログラムとは無関係に値を更新するため、値はいつでも変わりえます。

メモリマップドI/OとポートマップドI/O

ポートマップドI/Oでは、装置に専用のアドレス空間を割り当て、x86のIN命令やOUT命令のような専用命令でしかアクセスできません。メモリマップドI/Oは特別な命令を必要としないため、あらゆるアドレッシングモード、ポインタ、C言語の構造体を使ってレジスタにアクセスでき、命令セットを単純に保てます。ARMやRISC-Vのマイコンでは標準的な方式で、x86システムでもPCI Expressデバイスはレジスタの大部分をメモリマップドの領域で公開しており、従来のポートI/Oは主に互換性のために残っています。

キャッシュ、volatile、アクセス順序

装置の領域はキャッシュしない設定にしなければなりません。そうしないとCPUがキャッシュ内の古いコピーを読み続けて装置の変化に気づかなかったり、書き込みをキャッシュにとどめたりするおそれがあります。C言語ではレジスタへのポインタをvolatileと宣言し、1回だけ読んで無限ループに陥ったり繰り返しの書き込みを省いたりせず、すべてのアクセスを記述どおりに実行させます。ただし、volatileはハードウェアによる並べ替えや書き込みバッファリングまでは制御しません。プロセッサやバスは書き込みを完了を待たずに先へ進める(ポステッドライト)ことがあるため、ドライバはメモリバリアやデバイスメモリ属性、場合によっては読み戻しを使って、順序と完了を保証します。

OSでのMMIO

仮想メモリを使うシステムでは、ドライバが使う前に、装置レジスタの物理アドレスをキャッシュ無効の属性付きでカーネルの仮想アドレス空間にマッピングします。ユーザー空間ドライバのために、ユーザープロセスにマッピングすることもあります。MMIOは一般に、装置の設定、動作の開始、割り込みの応答といった制御やステータスの確認に使われます。大量のデータは通常、CPUがレジスタ経由でコピーするのではなく、装置自身が主記憶を読み書きするDMA(ダイレクトメモリアクセス)で転送します。

メモリマップドI/Oの練習問題に挑戦

マイコンなどで、周辺機器のレジスタをメモリと同じアドレス空間に割り当て、通常のメモリ読み書き命令で操作する方式はどれか。

  1. A仮想記憶
  2. BメモリマップドI/O
  3. Cキャッシュコヒーレンシ
答えと解説を見る

正解：B. メモリマップドI/O

メモリマップドI/Oでは、タイマーやUARTなどの周辺機器の制御レジスタに特定のアドレスを割り当て、通常のロード・ストア命令で操作します。入出力専用の命令を用意する方式(x86のIN/OUTなどのポートマップドI/O)と比べて命令セットを単純にでき、ARMやRISC-Vのマイコンで標準的です。周辺レジスタはキャッシュさせない、コンパイラに最適化させない(volatile)などの注意が必要です。

一般的なOSで、アプリケーションが装置のレジスタを直接読み書きできないようにしている主な理由はどれか。

  1. Aアプリケーションのプログラムでは、レジスタを読み書きする命令が書けないから
  2. B複数のプログラムが勝手に装置を操作すると、装置の状態が壊れたり保護が破られたりするから
  3. C装置のレジスタは電源を入れた直後にしか読み書きできないから
答えと解説を見る

正解：B. 複数のプログラムが勝手に装置を操作すると、装置の状態が壊れたり保護が破られたりするから

装置のレジスタが置かれたアドレスは、メモリマップドI/Oならページテーブルで、x86のI/Oポートなら入出力命令の特権の設定で、ユーザモードからアクセスできないようにされ、OSのドライバだけが操作できるようにしています。複数のプログラムが同じ装置を勝手に操作すると、途中の状態が混ざって装置が誤動作し、DMAで任意のメモリを書き換えるなど保護も破られるためです。アプリケーションはシステムコールを通してOSに操作を依頼します。命令が書けないわけではなく、保護で禁止されています。

よくある質問

メモリマップドI/OとポートマップドI/Oの違いは?

メモリマップドI/Oは装置のレジスタを通常のメモリアドレス空間に置き、普通のロード・ストア命令でアクセスします。ポートマップドI/Oは別のアドレス空間を使い、x86のIN/OUTのような専用命令でアクセスします。

メモリマップドレジスタをvolatileで宣言するのはなぜ?

装置はプログラムとは無関係にレジスタの値を変えるためです。volatileを付けると、コンパイラは値をレジスタに保持したり一見冗長なアクセスを省いたりせず、すべての読み書きを実行します。

メモリマップドI/O領域をキャッシュしないのはなぜ?

キャッシュがあると装置の現在の状態ではなく古い値が返されたり、書き込みが遅れたりまとめられたりするおそれがあるためです。そのため装置の領域は、キャッシュ無効やデバイスの属性でマッピングします。
