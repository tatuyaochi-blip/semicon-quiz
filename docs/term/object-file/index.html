オブジェクトファイルとは

おぶじぇくとふぁいる

コンパイラが1つのソースファイルから出力するファイル。機械語、データの初期値、シンボルテーブル、再配置情報を含むが、ほかのファイルの番地は未確定で、リンクしないと実行できない。

「オブジェクトファイル」は、2分野の8問の練習問題に出てきます(リンカ・ローダと実行形式, コンパイラなど)。

この用語の分野: リンカ・ローダと実行形式

オブジェクトファイルの中身

オブジェクトファイルはセクションに分かれています。textセクションには機械語が、dataセクションには初期値を持つ書き込み可能な変数が、読み出し専用データのセクションには定数や文字列リテラルが入ります。bssセクションはゼロで初期化される変数のサイズだけを記録するので、ファイル内の容量を使いません。これらに加えて、ファイルが定義するすべての名前と、使っているが定義していないすべての名前を並べたシンボルテーブル、後で番地を埋める必要がある箇所を並べた再配置エントリがあります。デバッグ情報は任意です。代表的な形式は、LinuxのELF、macOSのMach-O、WindowsのCOFF/PEです。

単独では実行できない理由

コンパイラやアセンブラは各オブジェクトファイルを個別に作り、セクションが番地0から始まるものとして配置します。コードがprintfのように別ファイルの関数を呼ぶ場合、その番地はわからないので、命令には仮の値(多くは0)を入れ、そこに何を入れるべきかを示す再配置エントリを付けます。すべてのオブジェクトファイルとライブラリを一緒に見られるのはリンカだけです。リンカは未定義シンボルを定義と対応づけ、各セクションのメモリ上の位置を決め、仮の値を書き換え、OSがプログラムを読み込むのに必要なスタートアップコードやヘッダを加えます。

よくあるリンクエラーとその意味

undefined reference to foo のようなエラーは、どこかのオブジェクトファイルがfooを使っているのに、リンク対象のどこにも定義がないことを意味します。よくある原因は、定義しているファイルのリンク忘れ、-lmのようなライブラリ指定の漏れ、名前のつづり間違い、そしてC++からCのコードをextern "C"なしで呼ぶことです。最後のケースでは、C++の名前マングリングによって名前が食い違います。逆のmultiple definitionは、複数のソースファイルからインクルードされるヘッダで変数を定義したときによく起きます。GNUのリンカでは、コマンドライン上でスタティックライブラリを、それを使うオブジェクトファイルより後に書く必要があります。

オブジェクトファイル、静的ライブラリ、共有ライブラリ

静的ライブラリは、オブジェクトファイルをまとめたアーカイブにすぎません。リンカはその時点で未定義のシンボルを解決するメンバだけを取り出すので、コマンドラインの順序が重要になります。共有ライブラリは別物で、位置独立コードから作られたリンク済みの出力であり、実行時にメモリにマップされ、残りの番地は動的リンカが埋めます。nm、objdump、readelfなどのツールでオブジェクトファイルのセクション、シンボル、再配置エントリを表示でき、リンクが失敗する理由を調べるいちばんの近道です。

オブジェクトファイルの練習問題に挑戦

コンパイラが1つのソースファイルから出力するオブジェクトファイル(.o)について正しいものはどれか。

  1. AそのままOSで実行できる完成したプログラムである
  2. Bソースコードを圧縮しただけのもので、機械語は含まない
  3. C機械語を含むが、ほかのファイルにある関数や変数の番地はまだ決まっていない
答えと解説を見る

正解：C. 機械語を含むが、ほかのファイルにある関数や変数の番地はまだ決まっていない

オブジェクトファイルには、そのファイルの関数を翻訳した機械語、変数の初期値、定義や参照している名前の一覧(シンボルテーブル)、後から番地を埋める場所の一覧(再配置情報)が入っています。printfのようにほかのファイルにある関数を呼ぶ命令は、番地が分からないので仮の値のままです。リンカが複数のオブジェクトファイルをまとめて番地を決め、実行ファイルを作ります。

GNUのリンカで「gcc -lmylib main.o」のように、静的ライブラリをそれを使うオブジェクトファイルより前に書くと、未定義の参照のエラーになることがある。その理由として正しいものはどれか。

  1. Aリンカは左から順に処理し、ライブラリを読む時点でまだ参照されていない関数は取り出さないから
  2. Bライブラリは必ずコマンドの最後に1つしか書けない決まりだから
  3. Cライブラリを前に書くと、ライブラリの中身が消去されるから
答えと解説を見る

正解：A. リンカは左から順に処理し、ライブラリを読む時点でまだ参照されていない関数は取り出さないから

GNUのリンカは、コマンドラインに書かれた順にファイルを処理し、静的ライブラリに出会った時点で「まだ定義が見つかっていない参照」を解決するオブジェクトだけを取り出します。ライブラリを先に書くと、その時点ではmain.oの参照がまだないので何も取り出されず、後からmain.oを読んでも戻って探しません。そのため、ライブラリは使う側の後ろに書くのが原則です。

よくある質問

オブジェクトファイルと実行ファイルの違いは何ですか?

オブジェクトファイルは1つのソースファイルの機械語を含みますが、他のファイルへの参照は未解決で、最終的な番地もありません。実行ファイルはリンカの出力で、すべてのシンボルが解決されて番地が確定しており、OSに読み込み方を伝えるヘッダを持っています。

オブジェクトファイルのシンボルを一覧表示するには?

nm、objdump -t、readelf -s を使います。nmの出力でUと表示されるシンボルは未定義で、そのファイルが参照しており、別のオブジェクトファイルやライブラリでの定義を期待していることを示します。

bssセクションとは何ですか?

初期値がゼロのグローバル変数やstatic変数を置くセクションです。オブジェクトファイルにはサイズだけが記録され、プログラム起動時にローダがメモリを確保してゼロで埋めます。
