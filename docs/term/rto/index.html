RTO(目標復旧時間)とは

あーるてぃーおー

障害や災害が起きてから、業務やシステムを再開するまでに許される時間の目標(Recovery Time Objective)。RTOが短いほど、待機系やすぐ使えるバックアップなどの設備と費用が必要になる。

「RTO(目標復旧時間)」は、1分野の2問の練習問題に出てきます(システム構成と信頼性設計など)。

この用語の分野: システム構成と信頼性設計

RTO(目標復旧時間)の練習問題に挑戦

あるシステムで、RPO(目標復旧時点)を4時間、RTO(目標復旧時間)を2時間と定めた。障害はいつでも起こりうるものとし、バックアップの取得にかかる時間は無視できるものとする。この目標を満たすデータの保護の方式として、適切なものはどれか。

  1. A1時間ごとにバックアップを取り、障害が起きたときは復旧に3時間かかる
  2. B3時間ごとにバックアップを取り、障害が起きたときは復旧に1.5時間かかる
  3. C6時間ごとにバックアップを取り、障害が起きたときは復旧に1時間かかる
答えと解説を見る

正解：B. 3時間ごとにバックアップを取り、障害が起きたときは復旧に1.5時間かかる

障害が次のバックアップの直前に起きると、直前のバックアップの間隔の分だけデータが失われるので、RPOを満たすにはバックアップの間隔をRPO以下にする必要があります。また、復旧にかかる時間はRTO以下でなければなりません。3時間ごとのバックアップで復旧に1.5時間なら、失われるのは最大3時間分(4時間以下)、復旧は1.5時間(2時間以下)で、両方を満たします。1時間ごとの方式はRTOを、6時間ごとの方式はRPOを満たしません。
