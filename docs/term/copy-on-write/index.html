コピーオンライトとは

こぴーおんらいと

複製したメモリを最初は元と共有しておき、どちらかが書き込もうとしたときに初めてそのページだけを複製する方式。プロセスの生成を速くし、メモリを節約できる。

「コピーオンライト」は、2分野の5問の練習問題に出てきます(OSとハードウェア, リンカ・ローダと実行形式など)。

この用語の分野: OSとハードウェア

コピーオンライトのしくみ

プロセスを複製するとき、カーネルはページテーブルだけをコピーします。親と子のエントリは同じ物理フレームを指し、書き込み可能なプライベートページはすべて一時的に読み出し専用にされ、カーネルはフレームごとに参照カウントを持ちます。読み出しは通常どおりの速度で行えます。どちらかのプロセスが最初に書き込むと保護違反のフォールトが起き、カーネルはそれがコピーオンライトのページだと判断して新しいフレームを確保し、ページをコピーして書き込んだ側に書き込み可能としてマップし、フォールトした命令を再実行させます。参照カウントからもう共有されていないとわかれば、コピーせずに書き込み可能へ戻すだけで済みます。

プロセス生成で効果が大きい理由

Unix系のシステムでは、シェルがコマンドを起動するときのように、forkの直後にexecを呼ぶのがよくあるパターンです。execはアドレス空間をすべて捨てて新しいプログラムを読み込むので、親のメモリを最初から全部コピーするのはまったくの無駄になります。コピーオンライトなら、forkのコストはおおむねページテーブルの複製時間で済み、実際にコピーされるのはexecまでに書き換えられたページ(通常はスタックやデータの数ページ)だけです。どちらも書き込まないコードや読み出し専用データのページは、両プロセスが存在する間ずっと共有されたままなので、メモリも節約できます。

ほかに使われている場面

データを論理的には複製するものの、たいていは変更しない場面では、同じ考え方が使われます。プライベートなファイルマッピングもその一例で、共有ライブラリの書き込み可能なデータセクションは最初はファイルキャッシュと共有され、プロセスが書き込んだページだけがそのプロセス専用にコピーされます。多くのカーネルは、新しく確保した匿名メモリを、書き込まれるまで共有のゼロページ1枚にマップします。コピーオンライト型のファイルシステムやストレージのスナップショットは、変更したブロックを上書きせず別の場所に書きます。仮想マシンのスナップショットや一部の言語ランタイムも、ディスクイメージや文字列にこの原理を使っています。

コストと落とし穴

コピーオンライトはコストをなくすのではなく、後に回すだけです。共有ページへの最初の書き込みでは、フォールト、カーネルへのトラップ、ページのコピーが発生し、通常のストアよりはるかに遅くなります。大きなプロセスがforkした後に親がメモリの大半に書き込み続けると、ほぼすべてのページが結局コピーされ、メモリ使用量が2倍近くになることもあります。またfork時にページを読み出し専用にするには、他のコアの古いTLBエントリを無効化する必要があります。共有メモリと混同しないことも大切です。共有メモリでは互いの書き込みが見えますが、コピーオンライトでは書き込んだ側が自分専用のコピーを持ちます。

コピーオンライトの練習問題に挑戦

プロセスを複製するときにコピーオンライトを使う利点として正しいものはどれか。

  1. A複製したプロセスと元のプロセスが、書き込んだ内容を常に共有できる
  2. B書き込まれたページだけを後で複製するので、速く省メモリになる
  3. C書き込みのたびにすべてのページを複製するので、データの安全性が高まる
答えと解説を見る

正解：B. 書き込まれたページだけを後で複製するので、速く省メモリになる

プロセスを複製するとき、全メモリをすぐにコピーすると時間もメモリもかかり、直後に別のプログラムを読み込むならそのコピーは無駄になります。コピーオンライトでは両方のページテーブルが同じ物理ページを読み出し専用で指すようにしておき、どちらかが書き込むとページフォルトが起き、OSがそのページだけを複製します。書き込んだ内容は共有されず、それぞれのプロセスに別に保たれます。全ページを複製するわけでもありません。

よくある質問

forkは親プロセスのメモリをすべてコピーしますか?

現在のシステムではしません。forkはページテーブルを複製し、物理ページは読み出し専用にして共有します。ページがコピーされるのは、どちらかのプロセスがそのページに初めて書き込んだときだけです。

fork後に子プロセスがメモリに書き込むと何が起きますか?

書き込みでページフォールトが起き、カーネルがそのページ1枚だけを新しいフレームにコピーして、子プロセスに書き込み可能としてマップします。親は元のページを持ち続けるので、互いの変更は見えません。

コピーオンライトと共有メモリは同じものですか?

違います。共有メモリは書き込んだ後も両方のプロセスから見えるように意図されたものです。コピーオンライトは誰かが書き込むまでだけページを共有し、書き込んだ時点でその側に専用のコピーを作ります。

「コピーオンライト」が出てくる問題(5問)

  1. プロセスを複製するときにコピーオンライトを使う利点として正しいものはどれか。
  2. 100個のプロセスが同じ共有ライブラリを使っているとき、物理メモリの使い方として正しいものはどれか。
  3. ページ置き換えでFIFO方式を使うと、物理メモリのページ数を増やしたのにページフォルトが増える場合がある。この現象を何と呼ぶか。
  4. OSが、自分からCPUを手放さないプログラムからでも一定時間ごとにCPUを取り戻して、ほかのプロセスに切り替えられるのは、主にどのしくみによるか。
  5. 仮想マシンのOSが特権の必要な命令を実行したとき、ハイパーバイザに処理が移り、ハイパーバイザがその命令の効果を代わりに再現する方式を何と呼ぶか。
