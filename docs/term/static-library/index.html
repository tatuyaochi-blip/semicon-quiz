静的ライブラリとは

せいてきらいぶらり

多くのオブジェクトファイルを1つにまとめたアーカイブ(Linuxでは.a)。静的リンクのとき、リンカは必要なオブジェクトだけを取り出して実行ファイルに組み込む。

「静的ライブラリ」は、1分野の3問の練習問題に出てきます(リンカ・ローダと実行形式など)。

この用語の分野: リンカ・ローダと実行形式

静的ライブラリの練習問題に挑戦

静的ライブラリ(.aファイル)と一緒にリンクするとき、リンカが実行ファイルに組み込むものとして正しいものはどれか。

  1. Aライブラリの中のすべてのオブジェクトファイル
  2. Bライブラリのファイル名だけで、コードは組み込まない
  3. Cライブラリの中のオブジェクトファイルのうち、未定義の参照を解決するのに必要なものだけ
答えと解説を見る

正解：C. ライブラリの中のオブジェクトファイルのうち、未定義の参照を解決するのに必要なものだけ

静的ライブラリは、たくさんのオブジェクトファイルを1つにまとめたアーカイブです。リンカは、まだ定義が見つかっていないシンボルを定義しているオブジェクトファイルだけをアーカイブから取り出して組み込みます。そのため、標準ライブラリのように多くの関数を含むライブラリでも、使った関数の分だけ実行ファイルが大きくなります。

GNUのリンカで「gcc -lmylib main.o」のように、静的ライブラリをそれを使うオブジェクトファイルより前に書くと、未定義の参照のエラーになることがある。その理由として正しいものはどれか。

  1. Aリンカは左から順に処理し、ライブラリを読む時点でまだ参照されていない関数は取り出さないから
  2. Bライブラリは必ずコマンドの最後に1つしか書けない決まりだから
  3. Cライブラリを前に書くと、ライブラリの中身が消去されるから
答えと解説を見る

正解：A. リンカは左から順に処理し、ライブラリを読む時点でまだ参照されていない関数は取り出さないから

GNUのリンカは、コマンドラインに書かれた順にファイルを処理し、静的ライブラリに出会った時点で「まだ定義が見つかっていない参照」を解決するオブジェクトだけを取り出します。ライブラリを先に書くと、その時点ではmain.oの参照がまだないので何も取り出されず、後からmain.oを読んでも戻って探しません。そのため、ライブラリは使う側の後ろに書くのが原則です。
