意図しないラッチとは

いとしないらっち

組み合わせ回路のつもりの記述で、ある条件のときに出力への代入がないために、値を保つラッチが論理合成で作られてしまうこと。

「意図しないラッチ」は、1分野の1問の練習問題に出てきます(ハードウェア記述言語と検証など)。

この用語の分野: ハードウェア記述言語と検証

意図しないラッチの練習問題に挑戦

組み合わせ回路のalwaysブロックで、意図しないラッチを防ぐためによく使われる書き方はどれか。

  1. A条件分岐をできるだけ多く書き、elseは省略する
  2. Bブロックの先頭で、出力のすべての信号にデフォルトの値を代入してから条件分岐を書く
  3. C出力の信号をすべてwireにして、alwaysの中で代入する
答えと解説を見る

正解：B. ブロックの先頭で、出力のすべての信号にデフォルトの値を代入してから条件分岐を書く

ブロックの先頭で「y = 0; valid = 0;」のように出力にデフォルトの値を入れておけば、後の条件分岐でどの経路を通っても、少なくともデフォルトの値が代入されているので、値を保つ必要がなくなりラッチはできません。条件の多い状態機械の出力の記述などで特に役に立ちます。SystemVerilogのalways_combを使うと、ラッチができたときにツールが警告を出してくれます。
