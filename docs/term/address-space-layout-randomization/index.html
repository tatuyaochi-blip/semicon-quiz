ASLRとは

えーえすえるあーる

Address Space Layout Randomizationの略。スタック、ヒープ、共有ライブラリ、実行ファイルの番地を実行のたびに変え、攻撃者が番地を予測しにくくする対策。

「ASLR」は、1分野の3問の練習問題に出てきます(リンカ・ローダと実行形式など)。

この用語の分野: リンカ・ローダと実行形式

ASLRによる配置の変化

プログラムが起動すると、カーネルと動的ローダは、アドレス空間の主な領域ごとに、ページ境界にそろったランダムなベースオフセットを選びます。対象は、スタック、ヒープ、共有ライブラリをマップするmmap領域、そして位置独立実行形式(PIE)としてビルドされていれば実行ファイル自体です。領域の相対的な並び順は通常どおり(低い番地にテキスト、データ、BSS、ヒープ、最上部にスタック)ですが、絶対アドレスは実行のたびに変わります。つまり、アドレス空間配置のランダム化(ASLR)が変えるのは、ものがどこにあるかであって、プログラムが何をするかではありません。

攻撃者がアドレスを必要とする理由

スタックバッファオーバーフローなどのメモリ破壊を突く攻撃では、通常、戻りアドレスや関数ポインタを、攻撃に役立つもののアドレスで上書きします。スタック上のシェルコード、return-to-libc攻撃でのsystem()のようなライブラリ関数、リターン指向プログラミング(ROP)での命令断片の連鎖などです。いずれも正確なアドレスが必要です。ASLRがあると攻撃者はアドレスを推測しなければならず、推測を外せば、制御を奪われる代わりに普通はプロセスがクラッシュします。この保護は確率的なものなので、強さはランダムなビットの数で決まり、64ビットに比べて32ビットのアドレス空間ではかなり限られます。

PIEと位置独立コード

ASLRで動かせるのは、固定の読み込みアドレスを前提としないコードだけです。共有ライブラリは昔から位置独立コード(PIC)としてコンパイルされ、データにはPC相対アドレッシングとグローバルオフセットテーブル(GOT)でアクセスしてきました。一方、以前の実行ファイルは固定アドレス向けにリンクされていたため、メインプログラムのコードは既知の場所にとどまり、攻撃者にとって確実なROPガジェットの供給源になっていました。-fPIE と -pie でビルドすれば実行ファイルも再配置可能になり、ローダがランダム化できます。x86-64ではPC相対のデータアクセスが命令として備わっているので、コストは小さく済みます。

限界とあわせて使う防御策

ランダム化は領域単位で行われるため、ライブラリのポインタが1つ漏れると、そのライブラリ全体のオフセットがわかり、そこから中のすべての関数の位置もわかってしまいます。fork()で作られた子プロセスは親の配置を受け継ぐので、攻撃者はforkするサーバに何度も探りを入れられます。こうした理由から、ASLRは書き込み可能なメモリを実行不可にする仕組み(W^XやNX)、スタックカナリア、制御フローの保護と組み合わせて使われます。OSのカーネル自体もランダム化でき、これはKASLRと呼ばれます。Linuxでは、設定を/proc/sys/kernel/randomize_va_spaceで確認できます。

ASLRの練習問題に挑戦

ASLR(アドレス空間配置のランダム化)の目的として正しいものはどれか。

  1. Aスタックやヒープ、ライブラリなどの番地を実行のたびに変え、攻撃者が狙う番地を予測しにくくする
  2. Bメモリの番地をランダムに選んで、キャッシュのヒット率を上げる
  3. C使っていないメモリをランダムに解放して、空き容量を増やす
答えと解説を見る

正解：A. スタックやヒープ、ライブラリなどの番地を実行のたびに変え、攻撃者が狙う番地を予測しにくくする

バッファオーバーフローなどを悪用する攻撃では、ライブラリの関数やスタック上のデータの番地を知っていることが重要です。ASLRは、プロセスを起動するたびにスタック、ヒープ、共有ライブラリ、実行ファイルを置く番地をずらし、攻撃者が番地を決め打ちできないようにします。単独で完全に防げるわけではなく、書き込みと実行の分離などほかの対策と組み合わせて使います。

よくある質問

ASLRでバッファオーバーフロー攻撃は防げますか?

防げません。ASLRはオーバーフローそのものを止めるのではなく、どのアドレスに飛べばよいかをわかりにくくするだけで、そのためほとんどの試みは成功せずにクラッシュします。本物のアドレスが1つでも漏れると破られることがあるため、NXメモリやスタックカナリアと組み合わせて使います。

ASLRとPIEの違いは?

ASLRは、実行のたびにメモリ領域をランダムなアドレスに読み込むOSの仕組みです。PIEは、コードがどのアドレスでも動くように実行ファイルをコンパイル・リンクする方法で、これによりライブラリ、スタック、ヒープに加えてメインプログラムもASLRでランダム化できるようになります。

LinuxでASLRが有効か確認するには?

/proc/sys/kernel/randomize_va_spaceを読みます。0は無効、1はスタック、mmap領域、共有ライブラリをランダム化、2はさらにbrkによるヒープもランダム化します。ほとんどのディストリビューションの既定値は2です。
