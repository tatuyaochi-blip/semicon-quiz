クロックの不確かさとは

くろっくのふたしかさ

ジッタや、まだ確定していないクロックスキューの見込みとして、タイミング解析で使える時間から差し引く余裕。SDCではset_clock_uncertaintyで指定し、クロックツリーができる前の段階ではスキューの分も含めて大きめに設定する。

「クロックの不確かさ」は、2分野の4問の練習問題に出てきます(タイミング解析とCDC, LSI設計フロー・EDAなど)。

この用語の分野: タイミング解析とCDC

タイミングチェックへの入り方

静的タイミング解析(STA)において、クロックの不確かさはユーザーが指定するマージンで、セットアップチェックとホールドチェックを厳しくします。セットアップでは、取り込み側エッジまでに使える時間から差し引かれます。周期1.25 ns、セットアップ時間0.05 ns、不確かさ0.05 nsなら、データは1.15 nsまでに到着しなければなりません。ホールドでは要求値に加算されるため、データはエッジの後により長く安定している必要があります。指定はSDC(Synopsys Design Constraints)で行い、set_clock_uncertainty -setup 0.05 [get_clocks clk] のようなコマンドを使い、-holdには別の値を設定します。

マージンに含めるもの

通常は3つの要素を含めます。1つ目は、PLL(位相同期回路)やクロック分配によるジッタで、エッジの到着がサイクルごとに早まったり遅れたりします。2つ目は、クロックツリー合成(CTS)前のスキューの見積もりです。この段階ではクロックが理想的に扱われ、フリップフロップ間のスキューが不明なため、その推定値を加えます。3つ目に、電源ノイズなどその段階では正確にモデル化されない効果に対する設計マージンを加えるチームも多くあります。周期ジッタは2つの異なるエッジにまたがるセットアップでは効きますが、送り出しと取り込みが同じエッジを使うホールドではほぼ相殺されます。スキューの見積もりは両方に適用されます。

設計フローでの値の変化

クロックを理想として扱う論理合成や配置の段階では、ジッタと想定スキューをカバーするため、不確かさを比較的大きく設定します。CTSの後はクロックがプロパゲートモードになり、ツールが各フリップフロップの実際のクロックレイテンシを計算するので、スキューは明示的に解析されます。そのためスキュー分は不確かさから外し、ジッタとマージンだけを残します。-fromと-toオプションを使えば、特定のクロックの組の間にも不確かさを設定できます。たとえば、異なるPLL出力から生成された関連クロック間のパスなどです。値が大きすぎると設計を過剰に制約して面積や電力が増え、小さすぎるとシリコンで不良になるおそれがあります。

スキューやディレーティングとの違い

スキューは2つのフリップフロップでのクロック到着時刻の差を計算したもので、クロックツリーができて初めてわかります。クロックの不確かさは計算されるものではなく、そのクロックのすべてのパスに一律に適用される想定上のマージンです。OCV(オンチップばらつき)のディレーティングはさらに別物で、固定の時間を差し引くのではなく、セルや配線の遅延に係数を掛け、送り出し側のパスを遅く、取り込み側のパスを速く(あるいはその逆に)見積もります。完全なサインオフの設定では、一般にプロパゲートされたスキュー、ディレーティング、そして小さく残した不確かさを組み合わせます。

クロックの不確かさの練習問題に挑戦

フリップフロップ間の経路で、クロック→出力遅延が 0.15 ns、組み合わせ回路の最大遅延が 2.2 ns、セットアップ時間が 0.15 ns である。スキューとクロックの不確かさを無視すると、この経路で動作できる最大のクロック周波数はいくらか。

  1. A約 425 MHz
  2. B約 455 MHz
  3. C400 MHz
答えと解説を見る

正解：C. 400 MHz

最小のクロック周期は、クロック→出力遅延、組み合わせ回路の遅延、セットアップ時間の合計です。0.15 + 2.2 + 0.15 = 2.5 ns なので、最大周波数は 1 ÷ 2.5 ns = 400 MHz になります。約 425 MHz はセットアップ時間を入れ忘れた 2.35 ns から、約 455 MHz は組み合わせ回路の遅延 2.2 ns だけから計算した値です。チップ全体の最大周波数は、このような経路のうち最も厳しいクリティカルパスで決まります。

クロック周期 1.25 ns(800 MHz)の経路で、クロック→出力遅延と組み合わせ回路の遅延の合計が 1.05 ns、セットアップ時間が 0.05 ns、セットアップ用のクロックの不確かさが 0.05 ns に設定されている。セットアップのスラックはいくらか。

  1. A0.15 ns
  2. B0.20 ns
  3. C0.10 ns
答えと解説を見る

正解：C. 0.10 ns

クロックの不確かさは、ジッタやまだ確定していないスキューの見込みとして、使える時間から差し引く余裕です。要求時刻は 1.25 − 0.05(不確かさ)− 0.05(セットアップ時間)= 1.15 ns、到着時刻は 1.05 ns なので、スラックは 0.10 ns です。0.15 ns は不確かさを引き忘れた値、0.20 ns はセットアップ時間も不確かさも引かなかった値です。配置配線の前はクロックツリーがないので、スキューの分も不確かさに含めて大きめに設定するのが一般的です。

よくある質問

クロックの不確かさはホールドチェックにも適用されますか?

はい。ただしset_clock_uncertainty -holdで別に設定し、通常はより小さな値にします。送り出しと取り込みが同じエッジを使うため、周期ジッタがほぼ相殺されるからです。CTS前は、ホールドでも想定スキューを含めます。

クロックツリー合成の後にクロックの不確かさを小さくするのはなぜですか?

クロックツリーができると、ツールがツリーの遅延から実際のクロックスキューを計算するため、スキューを見積もっていた分のマージンが不要になるからです。残るのはジッタと設計マージンだけです。

クロックの不確かさを含めたセットアップスラックはどう計算しますか?

要求時刻は、クロック周期からセットアップ時間と不確かさを引いた値(クロックレイテンシで補正)で、スラックは要求時刻からデータ到着時刻を引いた値です。たとえば1.25 − 0.05 − 0.05 = 1.15 nsの要求時刻に対し、到着が1.05 nsならスラックは0.10 nsです。
