動的メモリ確保とは

どうてきめもりかくほ

プログラムの実行中に、必要な大きさのメモリを確保し、使い終わったら解放すること。C言語では malloc(大きさ) で確保して先頭の番地を受け取り、free(番地) で解放する。calloc は0で初期化した領域を、realloc は大きさを変えた領域を返す。確保に失敗すると NULL が返るので確かめる必要がある。領域はヒープに置かれ、解放するまで関数から戻っても残る。小さなマイコンでは、断片化や確保にかかる時間が予測しにくいため避けることが多い。

「動的メモリ確保」は、4分野の7問の練習問題に出てきます(C言語の基礎, リンカ・ローダと実行形式, 組込み・ファームウェアなど)。

動的メモリ確保の練習問題に挑戦

C言語で、(1) 関数の中で static を付けずに宣言した局所変数、(2) malloc で確保した領域、(3) 関数の外で宣言した変数、のそれぞれが存在する期間(寿命)の組み合わせとして正しいものはどれか。

  1. A(1) プログラムの終了まで、(2) 確保した関数から戻るまで、(3) プログラムの終了まで
  2. B(1) 宣言したブロックから抜けるまで、(2) free で解放するまで、(3) プログラムの終了まで
  3. C(1) 宣言したブロックから抜けるまで、(2) プログラムの終了まで(途中では解放できない)、(3) その変数を最初に使った関数から戻るまで
答えと解説を見る

正解：B. (1) 宣言したブロックから抜けるまで、(2) free で解放するまで、(3) プログラムの終了まで

(1) の自動変数は、一般にスタックに置かれ、宣言したブロックに入ったときに作られて、抜けると無くなります。(2) の malloc で確保した領域はヒープに置かれ、関数から戻っても残り、free で解放するまで使えます。(3) の関数の外の変数(および static を付けた変数)は、プログラムの実行中ずっと存在し、.data や .bss のような静的な領域に置かれます。寿命の終わった領域を指すポインタを使うことや、free を忘れて領域が残り続けることが、よくある誤りの原因になります。

小さなマイコンのファームウェアで、mallocなどの動的なメモリの確保を避けることが多い理由として正しいものはどれか。

  1. AマイコンではC言語の関数を一切使えないから
  2. BRAMが小さく、断片化で確保に失敗したり、確保にかかる時間が予測しにくかったりするから
  3. C動的に確保したメモリは、電源を切っても消えないから
答えと解説を見る

正解：B. RAMが小さく、断片化で確保に失敗したり、確保にかかる時間が予測しにくかったりするから

数KB〜数百KBのRAMしかないマイコンで確保と解放を繰り返すと、空きが細かく分かれて、合計は足りていても大きな確保に失敗することがあります。何か月も動き続ける機器では、いつか失敗する危険があります。また確保にかかる時間が一定でないので、リアルタイムの処理には向きません。そのため、必要なメモリを最初に静的に確保しておく設計がよく使われます。
