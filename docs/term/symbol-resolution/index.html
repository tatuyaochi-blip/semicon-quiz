シンボル解決とは

しんぼるかいけつ

あるファイルで参照されている関数や変数の名前を、どこかにあるその定義と対応づけるリンカの処理。定義がなければ未定義参照、2つ以上あれば多重定義のエラーになる。

「シンボル解決」は、1分野の2問の練習問題に出てきます(リンカ・ローダと実行形式など)。

この用語の分野: リンカ・ローダと実行形式

シンボル解決で行うこと

各オブジェクトファイルにはシンボルテーブルがあり、関数やグローバル変数など自分で定義している名前と、参照しているが定義していない名前が並んでいます。main.cがsumを呼び、sum.cがsumを定義しているなら、main.oにはsumへの未定義参照が、sum.oにはsumの定義が記録されます。シンボル解決は、リンカがすべてのシンボルテーブルを集め、すべての参照をちょうど1つの定義に結び付ける処理です。これは再配置より前に行われ、再配置ではそれらの定義の最終アドレスを、参照している命令やデータに書き込みます。

未定義参照と多重定義

参照に対応する定義がどこにもなければ、リンカは未定義参照を報告します。原因の多くは、ソースファイルやライブラリのリンク忘れか、名前のつづりの違いです。staticでないグローバルな定義が同じ名前で2つあると、参照をどちらに結び付けるべきか決められないため、多重定義のエラーになります。関数をstaticと宣言すると内部リンケージになり、ほかのファイルから見えなくなるので、同じ名前を再利用できます。extern int count; のような宣言は記憶領域を確保せず、定義がほかの場所にあることを約束するだけです。

weakシンボルとライブラリの順番

weakシンボルは、同じ名前の通常の(strongな)定義がない場合にだけ使われる予備の定義で、組み込みコードでは割り込みハンドラのデフォルトにこの手法が使われます。静的ライブラリはオブジェクトファイルのアーカイブで、GNUのリンカは入力を左から右へ処理し、その時点で未定義のシンボルを定義しているメンバだけをライブラリから取り出します。そのため gcc -lmylib main.o のようなコマンドは失敗します。ライブラリを走査する時点では、main.oの未解決シンボルがまだ1つもないからです。ライブラリは、それを使うファイルの後に置きます。

C++の名前と動的リンク

リンカは名前の文字列だけでシンボルを照合します。C++では print(int) と print(double) のような関数のオーバーロードができるため、コンパイラは引数の型や名前空間をシンボル名に埋め込みます。これを名前マングリングと呼びます。C言語は名前をマングリングしないので、C++のコードでC言語の関数を宣言するときは extern "C" を付けて名前を一致させます。共有ライブラリでは、シンボル解決の一部が後回しになり、動的リンカが読み込み時または最初の呼び出し時に、一般にPLTのスタブとGOTのエントリを通じてライブラリ関数への参照を結び付けます。

シンボル解決の練習問題に挑戦

リンカが行うシンボル解決の説明として正しいものはどれか。

  1. Aあるファイルで使われている関数や変数の名前を、別のファイルにあるその定義と対応づける
  2. Bソースコードの変数名を、短い名前に置き換えて読みにくくする
  3. C数学の記号を含む式を、数値に計算し直す
答えと解説を見る

正解：A. あるファイルで使われている関数や変数の名前を、別のファイルにあるその定義と対応づける

main.cでsum関数を呼び、sum.cでその中身を定義すると、main.oには「sumを参照する」、sum.oには「sumを定義する」という情報が入ります。リンカはすべてのオブジェクトファイルのシンボルテーブルを集めて、参照ごとに対応する定義を1つ見つけます。定義が見つからなければ「未定義の参照」、2つ以上あれば「多重定義」のエラーになります。

よくある質問

undefined reference(未定義参照)エラーの原因は?

リンカが関数や変数への参照を見つけたものの、リンクされたどのオブジェクトファイルやライブラリにも定義がなかったことが原因です。多くの場合、ファイルやライブラリがリンクコマンドに含まれていない、順番が間違っている、名前が一致していない、のいずれかです。

シンボル解決と再配置の違いは?

シンボル解決は、参照されている各名前がどの定義を指すかを決めます。再配置は、その定義の実際のアドレスを、それを使う機械語やデータに書き込みます。

multiple definition(多重定義)エラーはどう直せばよいですか?

staticでないグローバルな関数や変数は、それぞれちょうど1つのソースファイルで定義し、ヘッダにはextern宣言を書きます。ファイル内だけで使うものはstaticにして、名前が衝突しないようにします。

  • リンカは、各オブジェクトファイルで参照されている名前(シンボル)を、どこかで定義されている実体と対応づけ(シンボル解決)、各ファイルのコードとデータを並べて最終的な番地を決め、命令の中の仮の番地を正しい値に書き換え(再配置)ます。
