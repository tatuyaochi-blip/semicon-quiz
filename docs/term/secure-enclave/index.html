エンクレーブとは

えんくれーぶ

アプリケーションの一部を、CPUがメモリを暗号化して守る領域で実行し、OSやハイパーバイザからも中身を読めないようにするTEEの方式。

「エンクレーブ」は、2分野の2問の練習問題に出てきます(ハードウェアセキュリティ, ハードウェアセキュリティの最新動向など)。

この用語の分野: ハードウェアセキュリティ

エンクレーブのしくみ

エンクレーブは、アプリケーションの中で鍵や個人情報などの秘密を扱う部分だけを、CPUが守る特別なメモリ領域に置いて実行する方式です。代表例のIntel SGXでは、エンクレーブのページはCPUの外の主記憶では暗号化されていて、CPUの中でだけ復号されます。CPUは、エンクレーブ以外のコードからの読み書きを拒否し、実装によってはメモリの改ざんも検出します。OSやハイパーバイザは、メモリの割り当てやスケジューリングは引き続き担当しますが、エンクレーブの中身を読んだり書き換えたりすることはできません。

信頼する範囲を小さくする

通常のアプリケーションは、OS、ハイパーバイザ、ドライバ、管理者などをすべて信頼しなければ秘密を守れません。エンクレーブでは、信頼しなければならない範囲(TCB:Trusted Computing Base)が、CPUのハードウェアとファームウェア、そしてエンクレーブ自身のコードにまで小さくなります。エンクレーブのコードは起動時に測定され、その測定値をCPUの中の鍵で署名して示すリモートアテステーションによって、利用者は正しいコードが本物のエンクレーブで動いていることを確かめてから、秘密のデータを渡せます。

制約とサイドチャネル攻撃

エンクレーブは万能ではありません。エンクレーブの中からはシステムコールを直接呼べないため、ファイルや通信の処理は外のコードに任せる必要があり、出入りのたびに処理の負担がかかります。保護されたメモリの容量に上限がある実装もあり、大きなデータを扱うと性能が下がることがあります。さらに、キャッシュのタイミング、ページフォールトのパターン、投機実行などを使うサイドチャネル攻撃で秘密が漏れる例が、研究で報告されてきました。そのため、秘密によって分岐やメモリアクセスが変わらない書き方や、マイクロコードの更新が重要です。

TrustZoneや機密VMとの違い

TEEにはいくつかの形があります。ArmのTrustZoneは、CPUをセキュアワールドとノーマルワールドに分け、セキュアワールドで専用の小さなOSとアプリを動かす方式で、アプリケーションの一部を切り出すエンクレーブとは守る単位が違います。AMD SEVやIntel TDXのような機密VMは、仮想マシン全体のメモリを暗号化してハイパーバイザから守る方式で、既存のOSやアプリをほぼそのまま動かせる一方、ゲストOS全体を信頼する範囲に含めます。なお2020年代前半の時点で、IntelはSGXをクライアント向けCPUでは提供しなくなり、主にサーバ向けCPUで提供しています。

エンクレーブの練習問題に挑戦

IntelのSGXのような「エンクレーブ」型のTEEの特徴として正しいものはどれか。

  1. AOSのカーネル全体を、外付けのハードディスクで実行する
  2. Bアプリケーションの一部を、CPUがメモリを暗号化して守る領域で実行し、OSやハイパーバイザからも中身を読めないようにする
  3. Cエンクレーブの中のデータは、誰でも自由に書き換えられる
答えと解説を見る

正解：B. アプリケーションの一部を、CPUがメモリを暗号化して守る領域で実行し、OSやハイパーバイザからも中身を読めないようにする

エンクレーブでは、アプリケーションの秘密を扱う部分だけを特別なメモリの領域で実行し、その領域はCPUの中で暗号化されてから主記憶に置かれます(実装によっては改ざんの検出も行います)。OSやハイパーバイザ、物理的にメモリを読み取る攻撃者からも中身は見えません。信頼しなければならないのはCPUとそのコードだけになります。ただしサイドチャネル攻撃への弱さも報告されており、使い方に注意が必要です。

機密コンピューティングで使われるTEEのうち、仮想マシン全体を守るVM型のもの(AMD SEV-SNP、Intel TDXなど)と、アプリケーションの一部を守るエンクレーブ型のもの(Intel SGXなど)の違いの説明として、正しいものはどれか。

  1. AVM型は仮想マシンのメモリを暗号化せずにアクセスの権限の確認だけで守り、メモリを暗号化して守るのはエンクレーブ型だけである
  2. BVM型は既存のOSやアプリケーションをほぼそのまま動かせるが、ゲストOS全体を信頼する範囲(TCB)に含めることになる
  3. Cエンクレーブ型ではOSやハイパーバイザも信頼する範囲に含まれるが、VM型ではCPUだけを信頼すればよい
答えと解説を見る

正解：B. VM型は既存のOSやアプリケーションをほぼそのまま動かせるが、ゲストOS全体を信頼する範囲(TCB)に含めることになる

エンクレーブ型は、アプリケーションの中で秘密を扱う部分だけを保護された領域で動かすので、信頼しなければならない範囲(TCB:Trusted Computing Base)はCPUとエンクレーブのコードにまで小さくなりますが、アプリケーションを分けて作り直す必要があります。VM型は、仮想マシン全体のメモリを暗号化してハイパーバイザやクラウドの管理者から守るので、既存のソフトウェアをほぼそのまま移せます。その代わり、ゲストOSとその上のすべてのソフトウェアがTCBに入り、そこに脆弱性があれば秘密が漏れます。TCBが小さいほど検証しやすく、攻撃される面も狭くなるので、使いやすさと信頼する範囲の大きさのかね合いで選びます。

よくある質問

エンクレーブとは簡単にいうと何ですか?

アプリケーションの秘密を扱う部分を、CPUがメモリを暗号化して守る領域で実行し、OSやハイパーバイザからも中身を読めないようにする仕組みです。IntelのSGXが代表例で、TEE(信頼できる実行環境)の方式の1つです。

エンクレーブとTrustZoneの違いは?

TrustZoneはCPUをセキュアとノーマルの2つの世界に分け、セキュア側で専用のOSやアプリを動かします。エンクレーブは、通常のOSの上で動くアプリケーションの一部を、専用の保護された領域として切り出します。守る単位と、信頼しなければならないソフトウェアの範囲が違います。

AppleのSecure Enclaveも同じものですか?

名前は似ていますが、構成が違います。AppleのSecure Enclaveは、SoCの中にメインのCPUとは別に設けたセキュリティ用のサブシステムで、鍵の管理や生体認証のデータの処理などを担います。SGXのようなエンクレーブは、メインのCPU自身がアプリケーションの一部を保護して実行する方式です。
