MFUとは

えむえふゆー

Model FLOPs Utilizationの略。モデルに必要な演算の数から求めた実際の演算性能が、ハードウェアのピーク性能の何%にあたるかを示す指標。

「MFU」は、1分野の1問の練習問題に出てきます(AIハードウェアとソフトウェアスタックなど)。

この用語の分野: AIハードウェアとソフトウェアスタック

MFUの求め方

MFU(Model FLOPs Utilization)は、モデルの計算に本来必要な演算の数から求めた実際の演算性能が、ハードウェアのピーク性能の何%にあたるかを表す指標です。Transformerの学習では、パラメータ数Nのモデルで1トークンあたり約6N回の演算が必要とされます。そこで、1秒あたりに処理したトークンの数に6Nを掛けて実効の演算性能を求め、使ったアクセラレータのピーク性能の合計で割ります。例えば、ピーク性能の合計が1000 PFLOPSのシステムで実効の演算性能が400 PFLOPSなら、MFUは40%です。アテンションの演算を加えて計算することもあります。

HFUとの違い

似た指標にHFU(Hardware FLOPs Utilization)があります。HFUは、ハードウェアが実際に実行したすべての演算を数えるため、メモリを減らすための活性化の再計算(勾配チェックポイント)で増えた演算も含みます。MFUはモデルに必要な演算だけを数えるので、再計算をしてもMFUは上がらず、時間がかかる分だけむしろ下がります。HFUは装置がどれだけ忙しく働いたかを、MFUは有用な計算がどれだけ進んだかを表すため、実装の違う学習システムを公平に比べるにはMFUが向いています。MFUは、2022年に発表された大規模言語モデルPaLMの論文で提案されました。

MFUを下げる要因

実際の学習ではMFUが100%に近づくことはなく、大規模な学習では数十%程度にとどまることが多いとされます。下げる要因には、GPUどうしの通信の待ち、パイプライン並列の始まりと終わりの待ち時間(バブル)、正規化や活性化関数のようなメモリ律速の演算、データの読み込みの遅れ、障害からの復旧やチェックポイントの保存にかかる時間などがあります。また、ピーク性能はFP8で数えるかBF16で数えるかなど、精度によって大きく変わるため、どの精度のピーク性能で割ったかを確かめないと、値を比べられません。

使われ方と注意点

MFUは、学習の設定やソフトウェアの改善がどれだけ効いたかを測る目安として使われます。並列化の分け方、マイクロバッチの数、演算をまとめるカーネルの最適化、通信と計算の重ね合わせなどを変えて、MFUの変化を確かめます。ただし、MFUが高いことと学習全体が速いことは同じではありません。より少ない演算で同じ品質に達するモデルやアルゴリズムに変えれば、MFUが下がっても学習は早く終わることがあります。推論のデコードはメモリ帯域で律速されやすいため、演算の利用率よりも、メモリ帯域の利用率やトークンあたりのコストで評価することが多くなります。

正解：A. モデルの計算に必要な演算の数から求めた実際の演算性能が、ハードウェアのピーク性能の何%にあたるか

MFUは、1秒あたりに処理したトークンの数とモデルに必要な演算の数から実際に行った有用な計算の速さを求め、それをGPUのピーク性能で割った値です。通信の待ち、メモリ律速の演算、パイプラインのバブル、再計算などがあると下がります。どれだけハードウェアを生かせているかが分かるので、学習の設定やソフトウェアの改善の目安になります。

よくある質問

MFUとは簡単にいうと何ですか?

モデルの学習に本来必要な演算の数から求めた実際の演算性能が、ハードウェアのピーク性能の何%にあたるかを示す指標です。ハードウェアの性能をどれだけ有効に使えているかの目安になります。

MFUとHFUの違いは?

HFUは、活性化の再計算なども含めて、ハードウェアが実際に実行した演算をすべて数えます。MFUはモデルに必要な演算だけを数えるため、再計算などの余分な演算は含みません。同じピーク性能で割るので、HFUはMFU以上の値になります。

MFUはどうやって計算しますか?

Transformerの学習なら、1トークンあたり約6N回(Nはパラメータ数)の演算に1秒あたりに処理したトークンの数を掛けて実効の演算性能を求め、使ったハードウェアのピーク性能の合計で割ります。どの精度のピーク性能を使ったかを明記することが大切です。
