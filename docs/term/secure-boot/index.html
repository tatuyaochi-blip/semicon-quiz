セキュアブートとは

せきゅあぶーと

起動の各段階で次に動かすソフトウェアの電子署名を確かめ、正しいものだけを起動する仕組み。信頼の鎖をつないでいく。

「セキュアブート」は、1分野の7問の練習問題に出てきます(ハードウェアセキュリティなど)。

この用語の分野: ハードウェアセキュリティ

信頼の鎖の仕組み

電源を入れると、チップのROMにあるブートコードが最初のブートローダを読み込み、その電子署名を検証します。イメージのハッシュ値を計算し、そのハッシュに対するベンダの署名を確かめるのです。検証に合格した場合にだけブートローダを実行し、ブートローダも同様に次の段階やOSのカーネルを検証してから制御を渡します。各段階が次の段階を保証することで、信頼の鎖(チェーン・オブ・トラスト)が形成されます。どこかで署名の検証に失敗すると起動は止まるため、ブートローダやOSの起動コードを書き換えるマルウェアは実行できません。スマートフォン、PC、多くの組込み機器がこの仕組みを採用しています。

シリコンに置かれた信頼の起点

信頼の鎖は最初の検証以上には強くならないため、信頼の起点(ルート・オブ・トラスト)は書き換え不能でなければなりません。具体的には、製造時に固定されるマスクROMのブートコードと、署名の検証に使う公開鍵です。公開鍵は容量を節約するため、ハッシュ値としてeFuse(一度だけ書き込めるヒューズ)に格納されることがよくあります。ここでは公開鍵暗号であることが重要です。共通鍵方式では検証に使う鍵で署名もできてしまうため、1台から鍵を抜き取られると全機器向けの偽ファームウェアを作れてしまいます。公開鍵による署名なら、機器が持つのは検証用の鍵だけで、署名用の秘密鍵はベンダの安全な施設から外に出ません。

ロールバック防止とデバッグポートのロック

署名の検証だけでは古いファームウェアも受け入れてしまいます。ベンダが正規に署名したものだからです。脆弱性が修正された後に、攻撃者が脆弱な旧バージョンを再インストールできてしまうため、イメージにはバージョン番号を持たせ、チップはeFuseのような一度だけ書き込める記憶領域に許可する最小バージョンを保存し、更新のたびに引き上げます。JTAGやSWDなどのデバッグポートはメモリを読み書きしたりプロセッサを停止させたりでき、セキュアブートを完全に迂回できてしまいます。そのため出荷製品ではヒューズで無効化するか、暗号による認証の後にだけ開放します。

セキュアブートとメジャードブートの違い

セキュアブートは強制する仕組みで、検証されていないコードは起動しません。メジャードブートは記録する仕組みで、各段階が次の段階のハッシュ値を計算し、TPM(トラステッド・プラットフォーム・モジュール)のPCR(プラットフォーム構成レジスタ)に拡張します。PCRの新しい値は、古い値と新しいハッシュ値を組み合わせることでしか作れません。起動はそのまま続きますが、この記録により、後からソフトウェアやリモートのサーバが何が実行されたかを正確に検証できます。なお、署名が証明するのは真正性であって機密性ではなく、ファームウェアを秘密にするには暗号化が必要です。セキュアブートが守るのは起動経路だけなので、メモリ保護、TEE(信頼できる実行環境)、耐タンパ性と組み合わせた多層防御の一層と位置づけられます。

セキュアブートの練習問題に挑戦

セキュアブートの説明として正しいものはどれか。

  1. Aパソコンを速く起動するための仕組み
  2. B起動の各段階で、次に動かすソフトウェアの電子署名を確かめ、正しいものだけを起動する
  3. C起動のたびに、ディスクの内容をすべて消去する仕組み
答えと解説を見る

正解：B. 起動の各段階で、次に動かすソフトウェアの電子署名を確かめ、正しいものだけを起動する

セキュアブートでは、書き換えられないROMのコードが最初のブートローダの署名を確かめ、そのブートローダが次の段階やOSのカーネルの署名を確かめる、というように、信頼の鎖をつないでいきます。どこかの段階で署名が合わなければ起動を止めるので、マルウェアがブートローダやOSの起動の部分を書き換えても動かせません。スマートフォンやパソコン、組込み機器で広く使われています。

セキュアブートの「ルートオブトラスト(信頼の起点)」として、チップの中に置かれるものとして最も適切なものはどれか。

  1. A書き換えられないROMの起動コードと、署名を確かめるための公開鍵(またはそのハッシュ値)
  2. B誰でも書き換えられるフラッシュメモリの起動コード
  3. Cインターネットからダウンロードした最新のOS
答えと解説を見る

正解：A. 書き換えられないROMの起動コードと、署名を確かめるための公開鍵(またはそのハッシュ値)

信頼の鎖は、最初の確認をする部分が正しいことを前提にしています。そのため、チップの製造時に書き込まれ、後から変えられないマスクROMの起動コードと、署名の検証に使う公開鍵(容量を節約するためハッシュ値をeFuseに書くことも多い)をルートオブトラストにします。ここが書き換えられると、その後のすべての確認が意味を失います。

よくある質問

セキュアブートの信頼の起点(ルート・オブ・トラスト)とは何ですか?

チップのマスクROMにある書き換え不能なコードと、最初のブートローダの検証に使う公開鍵(またはeFuseに格納したそのハッシュ値)のことです。鎖の後に続くすべての段階は、これが変更できないことを前提にしています。

セキュアブートとメジャードブートの違いは?

セキュアブートは署名の検証に失敗したソフトウェアの実行を拒否します。メジャードブートはすべてを実行させたうえでハッシュ値をTPMに記録し、後から起動状態を確認したり証明(アテステーション)したりできるようにします。

セキュアブートにロールバック防止が必要なのはなぜですか?

古いバージョンのファームウェアも有効な署名を持っているため、最小バージョンのカウンタがないと、攻撃者が既知の脆弱性を持つバージョンを再インストールできてしまうからです。
