アムダールの法則とは

あむだーるのほうそく

プログラムの一部だけを並列化したとき、全体の高速化は並列化できない部分によって制限されるという法則。例えば90%を並列化しても、最大で10倍までしか速くならない。

「アムダールの法則」は、3分野の6問の練習問題に出てきます(性能評価・プロファイリング, CPU・アーキテクチャ, マルチコアと同期など)。

この用語の分野: CPU・アーキテクチャ

公式と高速化の上限

アムダールの法則によると、実行時間のうち割合pの部分をN個のプロセッサで並列化できるプログラムの高速化率は S = 1 / ((1 − p) + p/N) です。Nを限りなく大きくするとp/Nの項が消え、高速化率は 1 / (1 − p) に近づきます。p = 0.9 ならこの上限は10倍で、プロセッサが10個の場合は約5.3倍にしかならず、ハードウェアの半分が事実上むだになります。逐次処理の部分は、どれほど小さく見えても、並列部分を十分細かく分割した後には実行時間の大半を占めるようになります。

あらゆる高速化に当てはまる法則

この法則はコアを増やす場合に限らず、部分的な改善全般に当てはまります。実行時間の50%を占める部分を4倍速くすると、新しい実行時間は元の 0.5 + 0.5/4 = 0.625 となり、全体の高速化率は1.6倍です。その部分をいくら最適化しても2倍を超えることはできません。実行時間の1%しか占めない部分を無限に速くしても、得られるのは約1%です。これが「よくあるケースを速くせよ」という原則の定量的な根拠であり、最適化の前にプログラムをプロファイリングすべき理由でもあります。

アムダールの法則とグスタフソンの法則

アムダールの法則は問題の規模が固定されていることを前提としており、同じ仕事をより多くのプロセッサで分担するストロングスケーリングに対応します。グスタフソンの法則はその逆を前提とし、プロセッサが増えれば、たとえばシミュレーションの格子を細かくするなど、同じ時間でより大きな問題を解くと考えます。並列部分の仕事は問題の規模とともに増える一方、逐次部分はほぼ一定なので、逐次部分の割合が小さくなり、高速化率はプロセッサ数にほぼ比例して伸びます。これがウィークスケーリングです。どちらの法則も誤りではなく、処理の使われ方について異なる問いに答えているのです。

実際のプログラムが公式より悪くなる理由

アムダールの法則は、並列部分が完全にスケールすることをすでに前提としているので、実測の高速化率はたいていそれよりさらに低くなります。スレッドはロックやバリアで待たされ、共有データやフォールスシェアリングによってキャッシュラインがコア間を行き来し、仕事の偏りで一部のコアが遊び、多数のスレッドがメモリ帯域幅を使い切ることもあります。通信や同期のオーバーヘッドはNとともに増えることさえあり、コアを増やすとかえって遅くなる場合もあります。最もきれいにスケールするのは、各スレッドが主に自分専用のデータで処理し、通信や待ちがほとんどない場合です。

アムダールの法則の練習問題に挑戦

処理全体の50%を占める部分を4倍速くした。全体の速度向上率はいくらか(アムダールの法則)。

  1. A2倍
  2. B1.6倍
  3. C4倍
答えと解説を見る

正解：B. 1.6倍

改善後の時間は、速くしない残りの50%(0.5)と、4倍速くした50%(0.5÷4=0.125)の合計で0.625になります。速度向上率は1÷0.625=1.6倍です。速くした部分をどれだけ速くしても、残りの50%はそのまま残るので、全体は最大でも2倍にしかなりません。全体を大きく速くするには、時間を多く占める部分を見つけて改善する必要があります。

アムダールの法則から得られる、性能の改善の進め方についての教訓として最も適切なものはどれか。

  1. A時間を多く使っている部分(よくある場合)を速くすることを優先する
  2. Bめったに実行されない部分から先に速くする
  3. Cどの部分を速くしても、全体への効果は同じである
答えと解説を見る

正解：A. 時間を多く使っている部分(よくある場合)を速くすることを優先する

全体の1%しか使っていない部分を無限に速くしても、全体は約1%しか速くなりません。一方、80%を使っている部分を2倍速くすれば、全体は約1.7倍になります。そのため、まずプロファイラなどで時間を多く使っている部分を見つけ、そこから改善するのが基本です。「よくある場合を速くせよ」は、コンピュータの設計でも繰り返し使われる原則です。

よくある質問

アムダールの法則で高速化率を計算する方法は?

1を新しい相対実行時間で割ります。S = 1 / ((1 − p) + p/s) で、pは改善の対象となる時間の割合、sはその部分が何倍速くなるかです(N個のプロセッサなら s = N)。p = 0.5、s = 4 なら 1 / 0.625 = 1.6倍です。

プログラムの95%が並列化できる場合、最大で何倍速くなりますか?

プロセッサをいくつ使っても、上限は 1 / (1 − 0.95) = 20倍です。その上限に近づくだけでも、非常に多くのプロセッサとほぼ完全な並列効率が必要です。

アムダールの法則とグスタフソンの法則の違いは?

アムダールの法則は問題の規模を固定し、逐次部分が高速化率を頭打ちにすることを示します。グスタフソンの法則はプロセッサ数とともに問題の規模を大きくするので、逐次部分の割合が小さくなり、プロセッサ数にほぼ比例した高速化(スケールド・スピードアップ)が可能になります。

解説の中の「アムダールの法則」

  • アムダールの法則では、並列化できる割合をp、プロセッサ数をNとすると、高速化率は 1/((1 − p) + p/N) です。

    処理全体の90%を並列化できるプログラムを、プロセッサの数を限りなく増やして実行したとき、理論上の最大の高速化率はどれ…

  • 並列化の効果を妨げる主な原因には、並列にできない部分(アムダールの法則)、ロックやバリアによる待ち、共有データや偽共有によるキャッシュラインの行き来、仕事の偏り、メモリ帯域の不足などがあります。

    並列プログラムで、コアの数を増やしても性能が思うように伸びない原因として当てはまらないものはどれか。

  • アムダールの法則は、問題の大きさを変えずにプロセッサを増やす場合を考えるので、並列にできない部分が速度向上の上限を決めます。

    グスタフソンの法則が示す考え方として正しいものはどれか。

  • アムダールの法則のとおり、時間を多く使っている部分を改善するのが効果的なので、まず測ることが性能の改善の第一歩です。
