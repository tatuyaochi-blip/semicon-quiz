スタックフレームとは

すたっくふれーむ

関数が呼ばれるたびにスタック上に確保する領域。戻り先、保存したレジスタ、局所変数などを置き、関数から戻るときに解放する。

「スタックフレーム」は、3分野の5問の練習問題に出てきます(命令セット・アセンブリ, コンパイラ, リンカ・ローダと実行形式など)。

この用語の分野: 命令セット・アセンブリ

スタックフレームに置かれるもの

フレームは、1回の関数呼び出しが専有するスタックの一区画です。関数によって中身は異なりますが、戻りアドレス、その関数が使う予定のcallee-savedレジスタ(呼び出された側が保存するレジスタ)の元の値、レジスタに収まらない局所変数やアドレスを取られる局所変数、一時値の退避(スピル)領域、レジスタで渡しきれない引数などが置かれます。フレーム内の固定の基準点を示すために、フレームポインタ用のレジスタ(RISC-Vではs0)を使うこともできます。呼び出しごとに新しいフレームが用意されるので、再帰呼び出しの各回はそれぞれ独立した局所変数を持ちます。

プロローグとエピローグ

一般的な規約ではスタックは低いアドレスに向かって伸びるので、関数はスタックポインタから値を引いてフレームを確保します。RISC-Vの典型的なプロローグは、addi sp, sp, -16 の後に sw ra, 12(sp) と sw s0, 8(sp) を実行するものです。対応するエピローグは、s0とraを読み戻し、addi sp, sp, 16 を実行してretで戻ります。RISC-Vの標準呼び出し規約ではspを16バイト境界にそろえるため、小さなフレームも16バイトに切り上げられます。確保も解放も加算1回で済むので、スタック領域はヒープ割り当てよりはるかに安価です。

リーフ関数とISAによる違い

RISC-Vではjalで呼び出すと戻りアドレスがraレジスタに書かれるため、ほかの関数を呼ぶ関数は最初の呼び出しの前にraをフレームに保存しなければなりません。何も呼ばないリーフ関数はraを上書きしないので、保存せずに戻れます。さらにcaller-savedレジスタだけを使い、局所変数をレジスタに置けるなら、フレーム自体が不要です。x86では事情が異なり、call命令が戻りアドレスを必ずスタックにプッシュするので、呼び出しのたびにメモリにアクセスします。末尾呼び出し最適化は最後の呼び出しを現在のフレームを再利用するジャンプに変えるので、深い末尾再帰でもスタックが伸びません。

ヒープとの違いとよくあるバグ

フレームの中身は関数から戻るまでしか存在しませんが、ヒープのオブジェクトは解放されるまで残ります。そのため局所変数へのポインタを返すのはバグです。そのメモリは次に積まれるフレームのものになってしまいます。上限のない再帰や非常に深い再帰は、スレッドごとに固定で一般に数MB以下のスタックを使い切り、スタックオーバーフローを起こします。局所配列の終端を越えて書き込むと保存された戻りアドレスを上書きでき、これは古典的なセキュリティ脆弱性です。コンパイラはスタックカナリアという、戻る前にエピローグで確認する番兵値でこれに対抗します。

スタックフレームの練習問題に挑戦

ほかの関数を呼ばない関数(葉関数、リーフ関数)では、raをスタックに保存しなくてよい場合が多い。その理由として正しいものはどれか。

  1. A葉関数ではret命令を使わないから
  2. B葉関数の戻り先は、CPUが自動でスタックに積むから
  3. Cほかの関数を呼ばないので、raが上書きされず、戻り先がそのまま残るから
答えと解説を見る

正解：C. ほかの関数を呼ばないので、raが上書きされず、戻り先がそのまま残るから

raは関数を呼ぶjalのたびに上書きされるので、ほかの関数を呼ぶ関数は自分の戻り先を最初にスタックへ保存しなければなりません。葉関数はjalを使わないのでraが壊れず、保存なしでretできます。さらに呼び出し先保存のレジスタも使わなければ、スタックフレームを作る必要すらありません。x86のcall命令は戻り先を必ずスタックに積むので、ここはRISC-Vとの違いです。

RISC-Vの関数の先頭で「addi sp, sp, -16」を実行する目的として正しいものはどれか。

  1. Aスタックを番地の小さい方へ伸ばして、16バイトの作業領域を確保する
  2. Bスタック上の16バイトを解放する
  3. Cspに入っている値から16を引いて、戻り値として返す
答えと解説を見る

正解：A. スタックを番地の小さい方へ伸ばして、16バイトの作業領域を確保する

RISC-Vを含む多くのISAの慣習では、スタックは番地の大きい方から小さい方へ伸びます。spを16減らすと、新しいspから元のspまでの16バイトが、この関数のスタックフレームになり、戻り先や保存したレジスタ、局所変数を置けます。関数の終わりに「addi sp, sp, 16」でspを戻すと領域が解放され、呼ぶ前と同じ状態になります。

よくある質問

スタックポインタとフレームポインタの違いは何ですか?

スタックポインタはスタックの現在の先頭を示し、関数の実行中に動くことがあります。フレームポインタを使う場合は現在のフレーム内の固定番地を保持するので、局所変数や保存したレジスタを一定のオフセットで参照でき、デバッガが呼び出しの連鎖をたどるのにも役立ちます。

深い再帰でスタックオーバーフローが起きるのはなぜですか?

再帰呼び出しのたびに新しいスタックフレームが確保され、スタックの最大サイズは固定だからです。再帰が十分に深くなるとフレームがその領域を超えてしまいます。末尾呼び出し最適化や、再帰をループに書き換えることで伸びを防げます。

関数が局所変数へのポインタを返してはいけないのはなぜですか?

局所変数は関数のスタックフレームにあり、フレームは関数から戻ると解放され、後の呼び出しで再利用されるからです。そのポインタは、中身がいつ変わってもおかしくないメモリを指すことになります。
