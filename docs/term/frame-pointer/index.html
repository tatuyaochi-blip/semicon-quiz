フレームポインタとは

ふれーむぽいんた

関数に入った時点のスタックの位置を指したまま動かないレジスタ。RISC-Vではs0(fp)。局所変数を固定の距離で指定でき、呼び出しの連なりもたどりやすい。

「フレームポインタ」は、1分野の1問の練習問題に出てきます(命令セット・アセンブリなど)。

この用語の分野: 命令セット・アセンブリ

フレームポインタの役割

関数が呼ばれると、スタック上に戻りアドレスや保存したレジスタ、局所変数を置く領域(スタックフレーム)が確保されます。スタックポインタ(sp)は関数の中でも、可変長の配列の確保や引数の積み込みで動くことがありますが、フレームポインタ(fp)は関数に入った時点で決めた位置を指したまま、関数を抜けるまで動きません。そのため局所変数や引数を「fpから何バイト」という固定の距離で指定できます。RISC-Vではs0(x8)がfpを兼ね、x86-64ではrbp、AArch64ではx29がフレームポインタとして使われます。

プロローグとエピローグ

関数の最初の部分(プロローグ)では、spを下げてフレームを確保し、戻りアドレスと呼び出し元のfpをフレームに保存してから、fpに新しい値を設定します。RISC-Vの64ビットの典型的な例では、spから16バイトを確保し、raとs0を保存したあと、s0に関数に入った時点のspの値を入れます。関数の最後の部分(エピローグ)では逆に、保存したraとs0を読み戻し、spを元に戻してから呼び出し元に戻ります。x86-64では、rbpをスタックに積んでから、rspの値をrbpにコピーする2命令で同じことを行います。

呼び出しの連なりをたどる

各フレームに呼び出し元のfpと戻りアドレスを保存しておくと、フレームは連結リストのようにつながります。現在のfpから保存されたfpを順にたどれば、どの関数がどの関数を呼んだか(バックトレース)を、デバッグ情報がなくても速く求められます。デバッガでのスタックの表示、クラッシュしたときのログ、実行中のプログラムを一定の間隔で止めて呼び出し元を記録するプロファイラなどで、この方法が使われます。たどる処理が単純で速いため、カーネルの中や、本番の環境で常に動かすプロファイラでも扱いやすいのが利点です。

フレームポインタの省略

フレームポインタはレジスタを1本占め、プロローグとエピローグに命令も増えるため、最適化ではよく省略されます。GCCやClangでは、多くのターゲットで最適化を有効にすると-fomit-frame-pointerが既定になり、局所変数はspからの距離で指定されます。省略した場合でも、コンパイラが出力するDWARFの呼び出しフレーム情報(CFI)を使えばバックトレースを求められますが、処理は重くなります。近年は、プロファイリングのしやすさを重視して、フレームポインタを残してパッケージをビルドするLinuxディストリビューションも出てきています。

フレームポインタは、関数に入った時点のスタックの位置を指したまま動かないレジスタです。可変長の配列などでspが途中で変わっても、局所変数を「fpから何バイト」で指定できます。また、各フレームに前のfpを保存しておけば、たどることで呼び出しの連なり(バックトレース)を得られます。ただしレジスタを1本占めるので、最適化では省略されることも多いです。

よくある質問

フレームポインタとスタックポインタの違いは?

スタックポインタはスタックの現在の先頭を指し、値の出し入れやフレームの確保のたびに動きます。フレームポインタは関数に入った時点の位置を指したまま動かないため、局所変数を固定の距離で指定でき、呼び出しの連なりをたどる起点にもなります。

フレームポインタは必要ですか?

必須ではありません。局所変数はspからの距離でも指定できるので、最適化では省略されることが多くあります。ただし可変長の配列などでspが途中で変わる関数ではフレームポインタが使われ、バックトレースを手軽に得たい場合にも残しておくと便利です。

RISC-Vのフレームポインタはどのレジスタですか?

x8です。呼び出された側が保存するレジスタs0がフレームポインタを兼ね、fpという別名でも書けます。フレームポインタを使わない関数では、s0は普通の保存レジスタとして使われます。
