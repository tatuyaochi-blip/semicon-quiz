動的リンクとは

どうてきりんく

実行時に共有ライブラリを読み込んで結びつける方式。ライブラリをプロセス間で共有でき、差し替えで修正が反映されるが、実行環境に合うライブラリが必要。

「動的リンク」は、1分野の12問の練習問題に出てきます(リンカ・ローダと実行形式など)。

この用語の分野: リンカ・ローダと実行形式

プログラム起動時に起きること

動的リンクされた実行ファイルにはライブラリのコードが含まれていません。必要な共有ライブラリと、そこから使うシンボルが記録されているだけで、Linuxではプログラムインタプリタとして動的リンカも指定されています。プログラムが起動すると、カーネルが実行ファイルと動的リンカをメモリにマップします。動的リンカは検索パスに沿って各ライブラリを探してマップし、シンボル参照を解決し、残りの再配置を適用し、ライブラリの初期化処理を実行してから、プログラムのエントリポイントにジャンプします。WindowsのDLLでも、各実行ファイルのインポートテーブルを使って同じ処理が行われます。

位置独立コードとGOT・PLT

物理的に1つしかないライブラリのコードを多数のプロセスで共有するには、プロセスごとにロードされるアドレスが違っても、コードのページを書き換えないようにする必要があります。そこで共有ライブラリは位置独立コード(PIC)としてコンパイルされ、変化するアドレスはグローバルオフセットテーブル(GOT)というデータの表に置かれます。外部関数の呼び出しは、プロシージャリンケージテーブル(PLT)の小さなスタブを経由し、GOTを通してジャンプします。遅延バインディングではGOTのエントリは初回呼び出し時に埋められます。起動時にすべてを解決してからGOTを読み出し専用にするのは、よく使われるセキュリティ強化策です。

動的リンクと静的リンクの比較

静的リンクは、ビルド時に必要なオブジェクトコードを実行ファイルにコピーします。できあがったファイルは単体で完結し、実行時のシンボル探索も不要ですが、サイズが大きく、ライブラリの修正を取り込むには再ビルドが必要です。動的リンクでは、ライブラリのページをプロセス間で共有でき、ディスク容量を節約でき、ファイル1つを差し替えるだけでセキュリティ修正をすべてのプログラムに行き渡らせられます。代償は起動時の処理と実行環境への依存です。ライブラリがない、または互換性がないとプログラムは起動できません。ライブラリにバージョン付きの名前やシンボルがあるのはこのためです。

必要に応じたライブラリの読み込み

起動時に決まるライブラリのほかに、実行中のプログラムはPOSIXシステムならdlopen、WindowsならLoadLibraryでライブラリを明示的に読み込み、dlsymやGetProcAddressで関数を名前から探すことができます。プラグイン機構やオプション機能はこのしくみで実現されています。シンボルの結びつけが実行時に行われるため、事前に読み込ませたライブラリ(プリロード)が関数を独自の実装に差し替えることもでき、プロファイラやメモリデバッガがこの機構を利用しています。lddなどのツールを使うと、実行ファイルが読み込む共有ライブラリとその場所を一覧できます。

動的リンクの練習問題に挑戦

動的リンク(共有ライブラリ)の利点として正しいものはどれか。

  1. A実行環境にライブラリがなくても、必ず動く
  2. B複数のプログラムが1つのライブラリをメモリ上で共有でき、ライブラリを更新すれば作り直さずに修正が反映される
  3. C起動時の処理がまったく不要になり、静的リンクより必ず速く起動する
答えと解説を見る

正解：B. 複数のプログラムが1つのライブラリをメモリ上で共有でき、ライブラリを更新すれば作り直さずに修正が反映される

動的リンクでは、実行ファイルには「どの共有ライブラリのどの関数を使うか」だけを記録し、実行時に動的リンカがライブラリを読み込んで結びつけます。共有ライブラリのコードは書き換えないので、物理メモリ上の1つのコピーを多くのプロセスで共有できます。不具合や脆弱性の修正もライブラリを差し替えるだけで済みます。ただし起動時に結合の手間がかかります。

動的リンクを使ったプログラムを別のコンピュータにコピーして実行したら、起動しなかった。最も考えられる原因はどれか。

  1. A実行ファイルの中にライブラリのコードがすべて入っていて、大きすぎたから
  2. B動的リンクのプログラムは、作ったコンピュータでしか動かない決まりだから
  3. C必要な共有ライブラリが入っていないか、互換性のないバージョンしかない
答えと解説を見る

正解：C. 必要な共有ライブラリが入っていないか、互換性のないバージョンしかない

動的リンクのプログラムは、実行するコンピュータにある共有ライブラリを使います。必要なライブラリがない、または関数が足りない古いバージョンしかないと、動的リンカが結合できず起動に失敗します。Linuxではlddコマンドで、プログラムが必要とする共有ライブラリと、それが見つかるかどうかを確かめられます。配布しやすさを重視して、あえて静的リンクにすることもあります。

よくある質問

静的リンクと動的リンクの違いは何ですか?

静的リンクはビルド時にライブラリのコードを実行ファイルにコピーするため、外部のライブラリなしで動作します。動的リンクは参照だけを残して実行時に動的リンカが解決するため、プロセス間で1つのライブラリを共有でき、差し替えで修正を反映できます。

PLTとGOTとは何ですか?

グローバルオフセットテーブル(GOT)は、外部の関数や変数の実行時アドレスを保持する書き込み可能なデータの表です。プロシージャリンケージテーブル(PLT)はコードから呼ばれる小さなスタブの集まりで、GOTを経由して実際のライブラリ関数にジャンプします。

「error while loading shared libraries: cannot open shared object file」というエラーの意味は?

プログラムが依存するライブラリを、動的リンカが検索パスの中で見つけられなかったという意味です。ライブラリをインストールするか、システムのリンカ設定やrpathなどでその場所を検索パスに加えれば解決します。
