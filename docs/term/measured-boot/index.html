測定ブートとは

そくていぶーと

起動の各段階で次のソフトウェアのハッシュ値をTPMなどに積み重ねて記録し、後から起動の状態を確かめられるようにする仕組み。メジャードブート。

「測定ブート」は、1分野の1問の練習問題に出てきます(ハードウェアセキュリティなど)。

この用語の分野: ハードウェアセキュリティ

測定ブートのしくみ

測定ブート(メジャードブート)では、起動の最初に動く、信頼の基点となる小さなコードが、次に実行するファームウェアのハッシュ値を計算(測定)してTPMに記録し、それから制御を渡します。次の段階も同じように、ブートローダ、OSのカーネルと順に測定を引き継ぎます。記録先はTPMのPCR(プラットフォーム構成レジスタ)で、新しい値は「それまでのPCRの値と新しいハッシュ値をつないだもののハッシュ」として計算されます(拡張、extend)。起動の測定を記録するPCRは再起動しない限りリセットできないので、記録をあとから都合のよい値に書き換えることはできません。

セキュアブートとの違い

セキュアブートは、次に起動するソフトウェアの署名を検証し、正しく署名されていなければ起動を止める仕組みです。これに対し測定ブートは、起動を止めずに、何が起動したかを改ざんできない形で記録します。セキュアブートでは「信頼できる鍵で署名されているか」しか分からないため、署名は正しいが脆弱性のある古い版や、設定の変更は区別できません。測定ブートでは、実際に起動したものの値が残ります。両者は対立するものではなく、セキュアブートで不正な起動を防ぎ、測定ブートで起動の状態を証明する形で組み合わせて使われます。

記録した値の使い道

PCRの値は、主に二つの方法で使われます。一つはリモートアテステーションで、機器がPCRの値にTPMの中の鍵で署名したもの(クォート)と、各段階の記録の一覧(イベントログ)をサーバに送ります。サーバはイベントログから計算したPCRの値が一致するかを確かめ、期待どおりのソフトウェアで起動した機器にだけアクセスを許します。もう一つはシーリングで、ディスク暗号化の鍵などを、PCRが特定の値のときだけTPMが取り出せるようにします。起動の途中が書き換えられると鍵が取り出せず、データを守れます。

限界と関連する技術

測定ブートは記録するだけなので、不正なコードの実行そのものは防げず、記録を誰かが確かめて初めて意味をもちます。また、最初に測定を行うコードが信頼できることが前提で、ここが破られると記録全体が信用できなくなります。ソフトウェアを更新するとPCRの期待値も変わるため、正しい値の管理も必要です。関連する技術として、起動の途中から改めて信頼できる状態で測定を始める動的な信頼の基点(DRTM)や、TPMを持たない小型の機器向けに、ハードウェアの秘密と測定値から鍵を導き出すDICEがあります。

  3. C測定ブートは、起動にかかる時間を測るだけの機能である
答えと解説を見る

正解：B. セキュアブートは正しくないソフトウェアの起動を止め、測定ブートは起動したソフトウェアのハッシュ値をTPMなどに記録して、後で状態を確かめられるようにする

測定ブートでは、起動の各段階で次のソフトウェアのハッシュ値を計算し、TPMのレジスタ(PCR)に積み重ねるように記録します。PCRは前の値と新しいハッシュ値を組み合わせてしか更新できないので、記録を偽れません。起動そのものは止めませんが、記録された値を見れば、どのソフトウェアが起動したかを後から確かめたり、遠くのサーバに証明したりできます。

よくある質問

測定ブートとは何ですか?

起動の各段階で次に実行するソフトウェアのハッシュ値を計算し、TPMなどに積み重ねて記録する仕組みです。起動そのものは止めませんが、記録を見れば、どのソフトウェアが起動したかをあとから確かめたり、遠くのサーバに証明したりできます。

セキュアブートと測定ブートの違いは何ですか?

セキュアブートは署名を検証して、正しくないソフトウェアの起動を止めます。測定ブートは起動を止めず、起動したソフトウェアのハッシュ値を改ざんできない形で記録します。防ぐのがセキュアブート、証明するのが測定ブートで、多くの場合は組み合わせて使います。

測定ブートにはTPMが必要ですか?

一般にはTPMのPCRに記録します。TPMは独立したチップのほか、CPUやSoCの中のファームウェアとして実装されることもあります。TPMを持たないマイコンなどでは、DICEのように測定値から鍵を導き出す仕組みで、同様の目的を果たします。
