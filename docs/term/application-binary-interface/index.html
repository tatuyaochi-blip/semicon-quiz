ABI(アプリケーションバイナリインターフェース)とは

えーびーあい

コンパイル済みのプログラムやライブラリが一緒に動くための機械語レベルの約束。呼び出し規約、データ型の大きさや整列、システムコールの呼び方などを含む。

「ABI(アプリケーションバイナリインターフェース)」は、2分野の3問の練習問題に出てきます(命令セット・アセンブリ, リンカ・ローダと実行形式など)。

この用語の分野: 命令セット・アセンブリ

ABIが定めるもの

アプリケーションバイナリインターフェース(ABI)は、コンパイル済みの2つのコードが再ビルドなしに互いを呼び出すために合意しておくべきことを、すべて定めます。具体的には、呼び出し規約(どのレジスタで引数と戻り値を渡すか、呼ばれた側がどのレジスタを保持すべきか、スタックをどう配置し境界をそろえるか)、int、long、ポインタなどの基本型の大きさとアラインメント、構造体のレイアウトとパディング、C++の名前マングリングの方法、例外の巻き戻し方、オブジェクトファイルの形式、OSへのシステムコールに使う命令列などです。

APIとABIの違い

アプリケーションプログラミングインターフェース(API)は、関数名、引数の型、動作など、プログラマから見たソースコードレベルの約束です。ABIは、同じ約束をコンパイル後の形で表したものです。ライブラリは、APIを変えずにABIだけを壊してしまうことがあります。たとえば公開している構造体にフィールドを追加すると、構造体の大きさと後ろのフィールドのオフセットが変わります。新しいヘッダでもプログラムは問題なくコンパイルできますが、古い版に対してビルドされたバイナリは、再コンパイルしない限りメモリを読み違えます。共有ライブラリのバージョン番号は、主にこうしたABIの非互換を知らせるためにあります。

1つのISAに複数のABI

命令セットアーキテクチャ(ISA)はプロセッサが実行するものを定め、ABIはその上に重ねたソフトウェアの取り決めなので、1つのISAに複数のABIがありえます。x86-64では、Linuxが使うSystem V ABIは最初の6個の整数引数をRDI、RSI、RDX、RCX、R8、R9で渡し、longを64ビットとします。一方、Windows x64 ABIはRCX、RDX、R8、R9を使い、longは32ビットのままです。RISC-Vにはilp32、lp64、lp64dなどのABIがあり、lp64dは浮動小数点の引数を浮動小数点レジスタで渡します。

ライブラリのABIを小さく保つ

共有ライブラリがエクスポートするシンボルはすべてABIの一部になり、互換性を保ち続けなければなりません。また、エクスポートされた関数は別のモジュールにある同名のシンボルで上書きされうるため、ライブラリ内部からの呼び出しでさえ、手続きリンケージテーブル(PLT)やグローバルオフセットテーブル(GOT)を経由する必要があります。内部の関数をhidden可視性にすると、公開インターフェースから外れます。その結果、動的リンカが解決するシンボルが減り、内部の呼び出しは直接のPC相対呼び出しになり、ほかのライブラリとの名前の衝突も避けられ、それらの関数を後から自由に変更できるようになります。

ABI(アプリケーションバイナリインターフェース)の練習問題に挑戦

ABI(アプリケーションバイナリインターフェース)の説明として正しいものはどれか。

  1. Aソースコードのレベルで、関数の名前と引数の型を定めた約束
  2. BCPUの命令の種類とビットの並びだけを定めた約束
  3. C呼び出し規約やデータ型の大きさ・整列など、機械語のレベルでプログラム同士を結びつけるための約束
答えと解説を見る

正解：C. 呼び出し規約やデータ型の大きさ・整列など、機械語のレベルでプログラム同士を結びつけるための約束

ABIは、コンパイル済みのプログラムやライブラリが一緒に動くための機械語レベルの約束で、呼び出し規約、intやlongやポインタの大きさ、構造体の整列、システムコールの呼び方などを含みます。APIはソースコードで関数の使い方を決めるもので、APIが同じでもABIが違えば、作り直さないとライブラリは使えません。同じRISC-VのISAでも、OSや用途によってABIが違うことがあります。

よくある質問

APIとABIの違いは?

APIはプログラマがソースコードを書く際のインターフェースで、ABIはコンパイル済みのコードが前提とする、レジスタ、データ配置、呼び出し手順についてのバイナリレベルの取り決めです。APIを保ったままABIを変えると、依存するプログラムを再コンパイルしなければなりません。

プログラムを変えていないのに、ライブラリの更新で動かなくなるのはなぜですか?

更新で構造体の大きさや関数の引数の型などが変わってABIが変わると、既存のバイナリは古いレイアウトのまま、誤った形でデータを渡すためです。ソースは変更なしでコンパイルできても、ビルド済みのプログラムは再ビルドするまで正しく動きません。

呼び出し規約はABIの一部ですか?

はい。引数や戻り値をどこに置くか、それぞれの側がどのレジスタを保持すべきかを定める呼び出し規約は、ABIの中心的な要素の1つです。
