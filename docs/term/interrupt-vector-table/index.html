割り込みベクタテーブルとは

わりこみべくたてーぶる

割り込みや例外の種類ごとに、対応する割り込みハンドラの先頭アドレスを並べた表。CPUは原因の番号からこの表を引いて、処理の開始位置を決める。

「割り込みベクタテーブル」は、1分野の2問の練習問題に出てきます(OSとハードウェアなど)。

この用語の分野: OSとハードウェア

CPUがテーブルを使う仕組み

割り込みや例外を受け付けると、ハードウェアはその原因を表すベクタと呼ばれる番号を決めます。原因はタイマ、特定の周辺装置、ページフォールト、不正命令、システムコールなどです。CPUは次の命令のアドレスと動作モードなどの状態を保存し、ベクタを添字として割り込みベクタテーブルを引きます。一般には、ベースアドレス+ベクタ×エントリサイズの位置にあるエントリを読みます。このエントリにハンドラの先頭アドレスが入っています。ハンドラは使うレジスタを保存し、イベントを処理してから、割り込み復帰命令を実行します。

テーブルの置き場所

細部はアーキテクチャによって異なります。ArmのCortex-Mマイコンでは、テーブルはコードメモリの先頭にあり、最初のワードがスタックポインタの初期値、2番目がリセットハンドラのアドレスで、その後にフォルトや周辺装置のハンドラへのポインタが続きます。多くのコアではベクタテーブルオフセットレジスタ(VTOR)で、ソフトウェアから移動できます。x86のリアルモードでは、メモリの先頭1 KBに4バイトのエントリが256個並びます。プロテクトモードとロングモードでは、IDTRレジスタが指す割り込みディスクリプタテーブル(IDT)を使います。RISC-Vはmtvecレジスタを使い、すべてのトラップを1つのハンドラに送ることも、割り込みを別々のアドレスに振り分けることもできます。

組み込みファームウェアでの設定

OSのないマイコンでは、リセットの瞬間から、ハードウェアが想定するアドレスにベクタテーブルがなければなりません。スタートアップコードはテーブルを関数ポインタの配列として専用のセクションに定義し、リンカスクリプトがそのセクションを所定のフラッシュアドレスに配置します。一般的なスタートアップファイルでは、すべてのエントリに無限ループなどのweakなデフォルトハンドラを割り当てておき、アプリケーションは使う割り込みだけを同じ名前の関数を定義して上書きします。そのため、ハンドラ名のつづりを間違えてもエラーなくコンパイルでき、割り込みは知らないうちにデフォルトのループへ飛んでしまいます。

ベクタ方式とポーリングの違い

ベクタ方式では原因ごとに専用のハンドラへ直接飛ぶため、CPUはステータスレジスタを読んで何が起きたかを調べる必要がなく、割り込みレイテンシが短くなります。もう1つの方式は入口を1つにまとめ、そのハンドラが原因レジスタを読んでソフトウェアで振り分けるもので、RISC-Vのダイレクトモードがこれに当たります。汎用OSでは、カーネルが起動時にテーブルを設定し、タイマ割り込み、デバイス割り込み、ページフォールト、システムコールがそれぞれ正しいカーネルの処理に届くようにします。

割り込みベクタテーブルの練習問題に挑戦

割り込みベクタテーブルの役割として正しいものはどれか。

  1. A割り込みが起きた回数を種類ごとに記録しておく
  2. B割り込みや例外の種類ごとに、処理を始めるアドレスを決めておく
  3. C次にどのプロセスを実行するかの順番を記録しておく
答えと解説を見る

正解：B. 割り込みや例外の種類ごとに、処理を始めるアドレスを決めておく

割り込みや例外が起きると、CPUはその原因に対応する番号(ベクタ番号)を得て、割り込みベクタテーブルからハンドラの先頭アドレスを読み、そこへ処理を移します。表の中身はOSが起動時に設定し、タイマー、各装置、ページフォルト、システムコールなどで別々のハンドラを呼べるようにします。回数を数えるのは統計のための別のしくみで、実行するプロセスの順番はOSのスケジューラが管理します。

よくある質問

割り込みベクタとは何ですか?

割り込みや例外の発生源に割り当てられた番号で、ベクタテーブルを引く添字として使われます。ハンドラのアドレスが入ったテーブルのエントリそのものを指して、ゆるく使われることもあります。

ARM Cortex-Mのベクタテーブルはどこにありますか?

既定では、ブートメモリ(通常はフラッシュ)の先頭にあります。最初のエントリがスタックポインタの初期値、2番目がリセットハンドラで、多くのコアではベクタテーブルオフセットレジスタ(VTOR)を使ってRAMなどへ移動できます。

x86のIVTとIDTの違いは?

割り込みベクタテーブル(IVT)は、メモリの最下位に置かれる、セグメント:オフセット形式の256個のアドレスからなるリアルモード用の表です。割り込みディスクリプタテーブル(IDT)はプロテクトモードとロングモードでこれに代わる表で、特権情報を含むディスクリプタを保持し、IDTRレジスタによってメモリ上の任意の位置に置けます。
