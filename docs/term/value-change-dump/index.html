VCDに記録される内容

VCD(Value Change Dump)は、論理シミュレーションの間に、各信号の値がいつどう変わったかを記録するテキスト形式のファイルです。VerilogのIEEE 1364規格で定められた形式で、多くのシミュレータが出力でき、GTKWaveのような波形表示の道具で開いてデバッグに使います。値が変わった時刻と新しい値だけを記録するので、毎クロックすべての値を書くより小さくなります。値は0、1、x(不定)、z(ハイインピーダンス)の4値で表し、多ビットの信号はまとめてベクトルとして記録します。

ファイルの構造

VCDファイルは、前半のヘッダと後半の値の変化の並びからなります。ヘッダには、作成日時($date)、時間の単位($timescale)、モジュールの階層($scope、$upscope)、信号の定義($var)を書き、$enddefinitionsで終わります。$varでは、各信号に「!」や「%」などの短い識別記号を割り当てます。後半では、「#100」のように時刻を書き、その時刻に変化した信号を「1!」(1ビット)や「b1010 %」(ベクトル)のように値と識別記号で並べます。単純な形式なので、自作のスクリプトでも読み書きできます。

Verilogでの出力方法と注意点

Verilogでは、テストベンチの中で$dumpfileで出力するファイル名を指定し、$dumpvarsで記録する範囲を指定します。$dumpvars(0, top)なら、topモジュール以下の全階層の信号を記録します。$dumpoffと$dumponで記録を止めたり再開したりでき、調べたい時間帯だけを残せます。VCDはテキストなので、大きな回路の全信号を長時間記録するとファイルが非常に大きくなり、書き出しのためにシミュレーションも遅くなります。そのため、記録する階層や期間を絞るか、圧縮された別の形式を使います。

ほかの波形形式やSAIFとの違い

VCDは規格で定められた共通の形式なので、異なる会社のシミュレータと波形表示の道具の間でデータを受け渡すのに便利です。一方、大きな設計では、圧縮されて速く読める独自の形式(FST、FSDB、WLFなど)がよく使われます。また、VCDの値の変化から信号の切り替わりの回数を数えれば、消費電力の解析にも使えます。切り替わりの回数などだけをまとめたSAIF形式はVCDより小さく、電力の見積もりによく使われます。なお、IEEE 1364-2001では、ポートの方向や信号の強さも記録する拡張VCDも定められました。

VCD(Value Change Dump)は、シミュレーション中に各信号の値がいつどう変わったかを記録する標準のファイルの形式です。波形表示の道具で開けば、クロックごとの信号の変化を時間の軸に沿って見られるので、どこで期待と違う値になったかを追いかけられます。すべての信号を記録するとファイルが非常に大きくなるので、調べたい範囲や信号に絞ることもあります。

よくある質問

VCDファイルを見るには何を使いますか?

GTKWaveのような波形表示の道具で開くと、信号の変化を時間の軸に沿った波形として見られます。シミュレータに付属する波形表示の道具の多くもVCDを読み込めます。中身はテキストなので、エディタで直接確認することもできます。

VCDファイルが大きくなりすぎるときは?

$dumpvarsで記録する階層を絞る、$dumpoffと$dumponで記録する期間を限る、といった方法でデータを減らします。シミュレータが対応していれば、FSTやFSDBなどの圧縮された形式で出力すると、ファイルが小さくなり読み込みも速くなります。

VCDとSAIFの違いは?

VCDは、各信号の値がいつどう変わったかを時刻ごとにすべて記録します。SAIFは、信号ごとの切り替わりの回数や0・1でいた時間の長さだけをまとめた形式で、波形は再現できませんが、ファイルが小さく、消費電力の解析に向いています。
