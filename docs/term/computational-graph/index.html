計算グラフとは

けいさんぐらふ

演算を節、テンソルの受け渡しを矢印として、モデルの計算を表した図。自動微分やAIコンパイラの最適化の土台になる。

「計算グラフ」は、1分野の4問の練習問題に出てきます(AIハードウェアとソフトウェアスタックなど)。

この用語の分野: AIハードウェアとソフトウェアスタック

ノード、エッジとそれが運ぶもの

計算グラフは通常、有向非巡回グラフ(DAG)です。ノードは行列乗算、畳み込み、加算、活性化関数などの演算で、エッジはテンソルです。各テンソルは形状とデータ型が決まっており、それを生成する演算から消費する演算へと流れます。入力と学習対象の重みは、始点のノードとして現れます。依存関係が明示されているので、どの演算を並列に実行でき、どれが待つ必要があるかがひと目でわかります。また、モデルを生成したPythonコードから独立した、完全で解析可能なモデルの記述をソフトウェアに提供します。

計算グラフと自動微分

学習には、すべての重みについての損失の勾配が必要です。フレームワークは順伝播の間にグラフを記録し、リバースモード自動微分が損失からそのグラフを逆向きにたどります。各演算の局所的な微分規則と連鎖律を適用して勾配を累積していく処理が、誤差逆伝播法です。このためには順伝播で保存した中間出力(活性化)が必要で、これが推論よりも学習のほうがはるかに多くのメモリを使う理由です。アクティベーションチェックポインティングは、一部の活性化を捨てて逆伝播中に再計算することで、計算量と引き換えにメモリを節約します。

静的グラフと動的グラフ

静的なdefine-and-run方式では、まずグラフ全体を構築してから実行します。全体最適化はしやすい反面、データに依存する制御フローやデバッグが難しくなります。動的なdefine-by-run方式、いわゆるイーガー実行では、プログラムの進行に合わせて演算がすぐに実行され、グラフはその場で記録されます。柔軟ですが、演算をまたいだ最適化の余地はほとんどありません。現代のフレームワークでは両者を組み合わせることが一般的で、コードはイーガー形式で書き、コンパイルの段階でグラフをトレースまたはキャプチャして、実行前にコンパイラが最適化できるようにします。

コンパイラとランタイムでの活用

AIコンパイラは、コードを生成する前にグラフを書き換えます。演算子融合(オペレータフュージョン)は、行列乗算、バイアス加算、活性化といった連なりを1つのカーネルにまとめ、中間テンソルをDRAMに往復させずにオンチップメモリにとどめます。ほかにも、定数畳み込み、未使用ノードの削除、テンソルのメモリレイアウトの選択、キャッシュやスクラッチパッドに収まるようにするタイリング、生存期間が重ならないバッファを再利用するメモリ計画などの処理があります。ONNX(Open Neural Network Exchange)のような交換フォーマットはグラフと重みをシリアライズし、異なるランタイムやハードウェア向けツールチェーンで同じモデルを実行できるようにします。

答えと解説を見る

正解：C. 演算を節、データ(テンソル)の受け渡しを矢印として、モデルの計算を表した図

計算グラフは、行列の積、足し算、活性化関数などの演算を節に、それらの間を流れるテンソルを矢印にした、モデルの計算の設計図です。フレームワークはこのグラフを逆にたどって逆伝播の勾配を自動で計算し、コンパイラはグラフ全体を見て融合や並べ替えの最適化を行います。どの演算が独立に並列で行えるかも、グラフから分かります。

よくある質問

ディープラーニングの計算グラフとは何ですか?

モデルを、演算(ノード)と、演算間で受け渡されるテンソル(エッジ)のつながりとして表したものです。フレームワークはこれを使って勾配を自動計算し、コンパイラは実行の最適化に使います。

演算子融合でニューラルネットワークが速くなるのはなぜですか?

活性化や正規化など多くの演算はメモリ律速で、出力をDRAMに書き出して読み戻す時間が支配的になるためです。1つのカーネルに融合すれば中間結果をチップ上に保持でき、メモリトラフィックが減ります。

イーガー実行とグラフモードの違いは何ですか?

イーガー実行はPythonが各演算に到達した時点ですぐに実行し、グラフモードはまずグラフ全体を構築またはキャプチャしてから最適化して実行します。イーガー実行はデバッグしやすく、グラフモードでは演算子融合などモデル全体にわたる最適化が可能になります。
