CRC(巡回冗長検査)とは

しーあーるしー

データのビット列を多項式とみなして生成多項式で割った余りを検査用の値として付け、受け取った側で同じ計算をしてデータの誤りを検出する方法。イーサネットやPCI Express、USB、ファイル形式などで広く使われる。

「CRC(巡回冗長検査)」は、3分野の8問の練習問題に出てきます(情報理論と符号の基礎, 論理回路, インターフェース・バス規格など)。

この用語の分野: インターフェース・バス規格

しくみ

CRCは、データのビット列を2を法とする多項式の係数とみなし、生成多項式で割った余りを求めます。2を法とする計算では足し算も引き算もXORなので、割り算は「先頭が1なら生成多項式をXORして1桁ずらす」の繰り返しになります。幅wビットのCRCでは、データの後ろにw個の0を付けて割った余りのwビットを付けて送り、受け取った側で同じ計算をして一致するかを確かめます。実際の規格では、初期値、各バイトのビット反転、最後のXORなどの約束を加えて定義されます。

検出できる誤りと使われる場所

幅wビットのCRCは、長さw以下の連続した誤り(バースト誤り)をすべて検出でき、それ以外のでたらめな誤りを見逃す確率もおおよそ2⁻ʷと小さくなります。ただし誤りを見つけるだけで訂正はできないので、見つけたら再送などで回復します。イーサネットのFCS(CRC-32)、PCI Expressのパケット、USB、CAN、ストレージのコマンドやZIP・PNGなどのファイル形式で使われ、ハードウェアではフリップフロップとXORゲートの線形帰還シフトレジスタで計算できます。

CRC(巡回冗長検査)の練習問題に挑戦

データ 1101 に、生成多項式 x³ + x + 1(ビット列 1011)のCRCの検査ビット3ビットを付ける。検査ビットは、データの後ろに0を3つ付けた 1101000 を 1011 で割った余りで、割り算では引き算の代わりに排他的論理和を使う。検査ビットはどれか。

  1. A001
  2. B101
  3. C110
答えと解説を見る

正解：A. 001

1101000 を 1011 で割ります。先頭の 1101 と 1011 の排他的論理和は 0110、次のビットを下ろした 1100 と 1011 の排他的論理和は 0111、1110 と 1011 では 0101、最後に 1010 と 1011 では 0001 となり、余りは 001 です。送るのは 1101001 で、受信側は 1011 で割った余りが0なら、誤りがないと判断します。

生成多項式の次数がr(検査ビットがrビット)で、定数項が1のCRCの性質として、正しいものはどれか。

  1. A1ビットの誤りなら、どのビットが誤ったかを特定して訂正することが、主な使い方である
  2. B長さがrビット以下のバースト誤り(連続した範囲に収まる誤り)は、すべて検出できる
  3. C生成多項式をうまく選べば、どのような誤りのパターンでも、すべて検出できる
答えと解説を見る

正解：B. 長さがrビット以下のバースト誤り(連続した範囲に収まる誤り)は、すべて検出できる

誤りのパターンを多項式 E(x) で表すと、CRCで検出できないのは、E(x) が生成多項式 G(x) で割り切れるときだけです。長さr以下のバースト誤りは x^i × B(x)(B(x) は次数がr − 1以下で、定数項が1)と書け、定数項が1のr次の G(x) では割り切れないので、必ず検出できます。一方、G(x) そのものの形の誤りのように、割り切れるパターンは検出できません。CRCは主に誤りの検出に使われ、誤りがあればデータを送り直してもらいます。

よくある質問

CRCとチェックサムの違いは?

チェックサムはバイトを足し合わせるなどの単純な計算で、順番の入れ替えや打ち消し合う誤りを見逃しやすいのに対し、CRCは多項式の割り算に基づくのでビットの位置まで区別し、バースト誤りなどを確実に見つけられます。

CRCで誤りを訂正できますか?

一般にはできません。CRCは誤りの有無を調べる符号で、どのビットが誤ったかは分からないため、訂正が必要なメモリなどではハミング符号などのECCを使います。
