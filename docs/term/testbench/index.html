テストベンチとは

てすとべんち

検証する回路に入力を与え、出力が正しいかを確かめるためのシミュレーション用の記述。論理合成はしないので、遅延や表示の命令などを自由に使える。

「テストベンチ」は、2分野の8問の練習問題に出てきます(ハードウェア記述言語と検証, LSI設計フロー・EDAなど)。

この用語の分野: ハードウェア記述言語と検証

テストベンチの中身

テストベンチは、通常ポートを持たない最上位のHDLモジュールで、検証対象の設計(DUT)をインスタンス化し、それを動かすのに必要なものすべてで周りを固めます。クロックを生成し、たとえば always #5 clk = ~clk; は5時間単位ごとに反転するので、時間単位が1 nsなら周期10 nsになります。さらにリセットをかけ、入力の刺激を与え、出力を観測します。テストベクタをファイルから読んだり、ログを書いたり、波形をダンプしたりすることもあります。DUTは論理合成できる設計で、テストベンチはシミュレーションの中にだけ存在します。

シミュレーション専用の構文

テストベンチは論理合成されることがないので、ハードウェアとしての意味を持たない機能も使えます。#10 のような遅延文はシミュレーション時刻を進め、$display やファイル入出力は値を表示・記録します。ケース等価演算子 === はXやZのビットを文字どおりに比較するので、出力が不定になったことをテストで検出できます。論理合成はこれらの構文を無視するか拒否するため、RTLに入れてはいけません。設計のコードに紛れ込むと、シミュレーションとハードウェアの動作が、デバッグしにくい形で食い違うことがあります。

クロックエッジでの競合を避ける

テストベンチでよくあるバグは、クロックの立ち上がりとまったく同じシミュレーション時刻に、ブロッキング代入でDUTの入力を変えてしまうことです。すると、DUTのフリップフロップが古い値と新しい値のどちらを取り込むかが、シミュレータがイベントを実行する順序に依存します。これは競合(レース)で、結果がシミュレータによって異なることさえあります。より安全なのは、反対側のクロックエッジかアクティブエッジの少し後に入力を変えること、ノンブロッキング代入を使うこと、またはサンプリングと駆動のタイミングを明示的に定めるSystemVerilogのクロッキングブロックを使うことです。

波形確認から自己チェック型テストへ

小さなブロックなら目で波形を確認するだけで足りることもありますが、この方法は規模が大きくなると通用しません。自己チェック型のテストベンチは、多くの場合リファレンスモデルを使って各入力に対する期待値を計算または参照し、DUTの出力と自動的に比較して、不一致をエラーとして報告します。そうすれば、たとえば夜間のリグレッションで数千のテストを無人で実行できます。大規模なプロジェクトでは、これに制約付きランダム刺激、スコアボード、カバレッジ収集を組み合わせており、検証の工数は設計の工数と同等かそれ以上になることがよくあります。

テストベンチの練習問題に挑戦

SystemVerilogを使った検証で、再利用しやすいテスト環境(テストベンチ)を組み立てるための標準的な方法論はどれか。

  1. AOPC
  2. BCMP
  3. CUVM(Universal Verification Methodology)
答えと解説を見る

正解：C. UVM(Universal Verification Methodology)

UVMは、SystemVerilogでテストベンチを部品(入力を与えるドライバ、出力を監視するモニタ、期待値と比べるスコアボードなど)の組み合わせとして構成するための標準的な方法論とクラスライブラリです。部品を他の設計の検証にも再利用でき、制約付きランダムな入力の生成やカバレッジの収集を組み込みやすくなります。IEEE 1800.2として標準化されています。OPCとCMPは製造の技術です。

HDLの検証で使うテストベンチの説明として正しいものはどれか。

  1. A回路を製造するための工場の設備
  2. B検証する回路に入力を与え、出力が正しいかを確かめるためのシミュレーション用の記述で、論理合成はしない
  3. C回路の消費電力を測るための測定器
答えと解説を見る

正解：B. 検証する回路に入力を与え、出力が正しいかを確かめるためのシミュレーション用の記述で、論理合成はしない

テストベンチは、検証する回路(DUT)をインスタンス化し、クロックやリセット、入力の信号を作って与え、出力を観察するためのHDLの記述です。回路にはしないので、遅延の指定やファイルの読み書き、表示の命令など、シミュレーション用の機能を自由に使えます。設計と同じくらい、あるいはそれ以上の手間をかけて作られることもあります。

よくある質問

テストベンチは論理合成できますか?

できません。テストベンチはシミュレーション専用に書くもので、遅延、表示文、ファイル入出力など、ハードウェアにできない構文を自由に使います。

テストベンチのDUTとは何ですか?

Design Under Testの略で、検証対象の設計のことです。テストベンチがインスタンス化し、刺激を与えて動作を確認する、論理合成可能なモジュールです。

Verilogのテストベンチで == と === の違いは?

== 演算子は、ハードウェアの比較器と同じように、どちらかのオペランドにXやZのビットがあるとXを返します。=== 演算子はXとZを文字どおりに比較し、常に0か1を返すので、テストベンチで不定の出力を検出するのに使います。
