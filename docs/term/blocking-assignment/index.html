ブロッキング代入とは

ぶろっきんぐだいにゅう

Verilogの「=」の代入。その場で左辺が更新され、次の行ではその新しい値が使われる。組み合わせ回路のalwaysやテストベンチで使う。

「ブロッキング代入」は、1分野の4問の練習問題に出てきます(ハードウェア記述言語と検証など)。

この用語の分野: ハードウェア記述言語と検証

ブロッキング代入の動き

ブロッキング代入は等号1つ(=)で書き、右辺を評価して左辺の変数を更新してから、同じ手続きブロック内の次の文が実行されます。C言語の代入とほぼ同じです。そのため文は上から順に作用し、後の行は前の行が書き込んだばかりの値を参照します。一方、ノンブロッキング代入(<=)は、まずすべての右辺を評価し、その更新を同じタイムステップの後のほうでまとめて反映します。そのため、各文はクロックエッジの前の値を参照することになります。

クロック同期回路で問題になる理由

クロック同期のalwaysブロックでブロッキング代入を使うと、同じエッジの中で、あるレジスタが別のレジスタの新しい値を見てしまいます。2段のシフトレジスタを「q1 = d; q2 = q1;」と書くと、q2には更新されたばかりのq1、つまりdが入るため、シミュレーションでも合成後の回路でも1段分しか遅延しません。同様に「a = b; b = a;」と書いても入れ替わらず、両方とも元のbの値になります。クロック同期ブロック内のすべてのレジスタにノンブロッキング代入を使えば、文の順序に関係なく、並列に動くフリップフロップと同じ動作になります。

ブロッキング代入を使うべき場面

ブロッキング代入は、always @(*)やSystemVerilogのalways_combで書く組み合わせ回路のalwaysブロックで使います。ある行で計算した中間変数を次の行で使うことで、ゲートの連なりを記述できます。テストベンチの手続き的なコードや、functionやtaskの中の一時変数にも自然に使えます。広く守られているルールは、クロック同期回路にはノンブロッキング代入、組み合わせ回路にはブロッキング代入を使い、同じ変数に両方の代入を混在させない、というものです。

テストベンチでの競合

有効なクロックエッジとまったく同じシミュレーション時刻に、ブロッキング代入で設計の入力を駆動すると競合(レース)が生じます。設計内のフリップフロップが古い値と新しい値のどちらを取り込むかは、シミュレータがどのプロセスを先に実行するかで決まり、シミュレータによって結果が異なることもあります。よく使われる対策は、反対側のクロックエッジや有効エッジから少し遅れたタイミングで入力を変える、入力をノンブロッキング代入で駆動する、SystemVerilogのクロッキングブロックを使う、といったものです。

ブロッキング代入の練習問題に挑戦

テストベンチで、回路への入力をクロックの立ち上がりと同じ時刻にブロッキング代入で変えると、問題が起きることがある。主な理由と対策の組み合わせとして正しいものはどれか。

  1. A回路が変わる前と後のどちらの値を取り込むかが実行の順番で変わる(競合)ため。入力はクロックのエッジから少しずらすか、ノンブロッキング代入で変える
  2. Bクロックの周波数が自動で下がるため。クロックを速くする
  3. Cブロッキング代入は、テストベンチでは使えないため。すべてassign文にする
答えと解説を見る

正解：A. 回路が変わる前と後のどちらの値を取り込むかが実行の順番で変わる(競合)ため。入力はクロックのエッジから少しずらすか、ノンブロッキング代入で変える

同じ時刻に、テストベンチが入力を書き換える処理と、回路のフリップフロップが入力を取り込む処理が起こると、シミュレータがどちらを先に実行するかで、取り込まれる値が古い値にも新しい値にもなります。これはシミュレーションの競合(レース)で、シミュレータによって結果が変わることもあります。入力を立ち下がりで変える、少し遅らせる、ノンブロッキング代入やSystemVerilogのクロッキングブロックを使う、などで防ぎます。

よくある質問

Verilogでブロッキング代入とノンブロッキング代入はどう使い分けますか?

クロック同期のalwaysブロック内のレジスタにはノンブロッキング代入を、組み合わせ回路のブロックや一時変数にはブロッキング代入を使います。同じ変数に両方の代入を混在させてはいけません。

Verilogで書いたシフトレジスタが1クロック分しか遅延しないのはなぜですか?

おそらく各段をブロッキング代入で書いているため、各段が前の行で更新されたばかりの値を受け取っています。ノンブロッキング代入に変えれば、各段がエッジ前の値を取り込むようになります。

VHDLの変数代入はVerilogのブロッキング代入と同じですか?

おおむね同じです。VHDLの変数代入はプロセス内ですぐに反映され、VHDLの信号代入は更新が予約されるため、ノンブロッキング代入に近い動作をします。
