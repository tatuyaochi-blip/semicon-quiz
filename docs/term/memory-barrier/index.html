メモリバリアとは

めもりばりあ

バリアより前のメモリ操作が、後の操作より先にほかのコアから見えることを保証する命令。フェンスとも呼ぶ。RISC-Vのfenceなど。

「メモリバリア」は、1分野の2問の練習問題に出てきます(マルチコアと同期など)。

この用語の分野: マルチコアと同期

メモリバリアが保証すること

メモリバリアはフェンスとも呼ばれ、スレッドのメモリ操作をその前と後に分け、前の操作がほかのコアから見えるようになってから後の操作が行われることを保証する命令です。これがないと、プロセッサは異なる番地へのロードとストアを順不同に完了させることがあります。たとえばストアをストアバッファに置いたまま、後のロードを先に進めます。発行したスレッド自身から見える結果は変わらないため、バリアが問題になるのは、データをコア間で共有するときや、DMAエンジンなどのデバイスと共有するときだけです。

ストアバッファの例

x と y の初期値を0とし、コア0が x = 1 の後に r1 = y を、コア1が y = 1 の後に r2 = x を実行するとします。逐次一貫性のもとではどちらかのストアが先に起きるので、少なくとも一方のロードは1を返すはずです。しかしx86を含む実際のプロセッサでは、各ストアが自コアのストアバッファで待っている間に、続くロードがキャッシュから古い値を読むため、r1 と r2 がどちらも0になることがあります。各スレッドでストアとロードの間に完全なバリアを置くと、ロードの実行前にストアが見えるようになり、この結果は起こらなくなります。

実際の命令セットのバリア命令

RISC-Vには fence 命令があり、オペランドでどの先行アクセスをどの後続アクセスより前に順序付けるかを指定します。fence rw, rw はすべての読み書きを順序付けます。また、アトミック命令やロード予約/条件付きストア命令には acquire ビットと release ビットがあります。Armには順序付け用の dmb(データメモリバリア)、完了を待つ必要があるときの dsb、そしてロードアクワイア命令とストアリリース命令があります。x86はトータルストアオーダー(TSO)により大半の順序がもともと保たれるため、mfence やロック付き命令が必要なのは主にストアを後のロードより前に順序付ける場合です。バリアは保留中のストアが吐き出されるまでコアを止めることがあり、コストはゼロではありません。

ロックとコンパイラにおけるバリア

多くのプログラマはバリアを直接書くことはありません。ロックの獲得には acquire セマンティクスが含まれ、後のアクセスが獲得より前に移動しません。解放には release セマンティクスが含まれ、ロックが解放される前にそれまでの書き込みが見えるようになります。このため、ロックで保護されたデータはスレッド間で正しく受け渡されます。C11やC++11などの言語は、同じ考え方をメモリ順序付きのアトミック操作として提供しています。コンパイラバリアは別物で、ある地点をまたいだアクセスの並べ替えをコンパイラに禁じるだけで命令は出力しないため、ハードウェアの動作は制約しません。

メモリバリアの練習問題に挑戦

メモリバリア(フェンス)命令の役割として正しいものはどれか。

  1. Aバリアより前のメモリ操作が、バリアより後の操作より先にほかのコアから見えることを保証する
  2. Bメモリを物理的に区切って、アクセスを禁止する
  3. Cプログラムの実行をすべてのスレッドが揃うまで止める
答えと解説を見る

正解：A. バリアより前のメモリ操作が、バリアより後の操作より先にほかのコアから見えることを保証する

CPUはメモリ操作の順番を入れ替えることがあるので、ほかのコアと決まった順番でデータを受け渡すには、それを止める指示が必要です。メモリバリアは、その前の読み書きをすべて終えてから(ほかのコアに見えるようにしてから)、後ろの読み書きを行わせます。ロックの取得や解放の中にもバリアの働きが含まれていて、ロックで守った変数が正しく受け渡されます。

よくある質問

メモリバリアとフェンスの違いは?

同じ概念の2つの呼び名です。どちらも、ほかのコアから見て、命令より前のメモリ操作を後の操作より先に順序付ける命令を指します。RISC-Vでは命令名が fence で、Armではバリアと呼びます。

x86でもメモリバリアは必要ですか?

x86のトータルストアオーダーでは大半のロードとストアがプログラム順に保たれるため、弱い順序のアーキテクチャほど頻繁には必要ありません。ただし、ストアを別番地への後のロードより前に見えるようにしたい場合は、mfence などのバリアやロック付き命令が必要です。

コンパイラバリアとメモリバリアの違いは?

コンパイラバリアは、コンパイラがメモリアクセスをその地点をまたいで移動させないようにするだけで、機械語命令は生成しません。メモリバリアはハードウェア命令で、プロセッサがアクセスをほかのコアに見せる順序を制約します。
