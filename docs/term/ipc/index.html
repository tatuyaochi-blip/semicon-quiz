IPCとは

あいぴーしー

Instructions Per Cycle の略で、1クロックあたりに実行できる命令の数。CPUの設計上の効率を表し、性能はおおよそIPCとクロック周波数の積になる。逆数はCPI。

やさしい解説で読む: CPUとは? パソコンやスマホの中で何をしているのか

「IPC」は、3分野の6問の練習問題に出てきます(CPU・アーキテクチャ, 性能評価・プロファイリング, データシートの読み方など)。

この用語の分野: CPU・アーキテクチャ

性能の式におけるIPC

プログラムの実行時間は、命令数×CPI(1命令あたりのサイクル数)÷クロック周波数で表されます。IPC(1サイクルあたりの命令数)はCPIの逆数なので、同じプログラムであれば性能はIPCと周波数の積に比例します。3 GHzのコアのサイクル時間は約0.33 nsですが、同じ3 GHzのプロセッサーでもIPCが違えば速度は大きく異なります。命令セットが違えば同じ処理に必要な命令数も変わるため、IPCの比較が意味を持つのは、同じプログラム、同じ命令セットの場合に限られます。

IPCを高める技術

単純なパイプラインは1サイクルに1命令の実行を目指します。スーパースカラーコアは独立した複数の命令を1サイクルで発行し、最近の高性能設計では発行幅が6〜10程度あります。アウトオブオーダー実行は、先行命令が待たされている間に後続の独立した命令を実行して演算器を遊ばせず、分岐予測はパイプラインのフラッシュを避け、プリフェッチ付きの大容量キャッシュはメモリーのレイテンシーを隠します。ただし発行幅は自由には広げられません。依存関係をチェックする回路は発行幅のほぼ2乗で増え、実際のプログラムが持つ命令レベル並列性にも限りがあるため、実際のIPCはピークの発行幅を大きく下回ります。

IPCを下げる要因

最大の損失はストールです。最終レベルキャッシュでミスしてDRAMにアクセスすると数百サイクルを失い、分岐予測ミスは深いパイプラインですでに進めた処理を捨てさせ、依存関係が連鎖した命令は実行を直列化します。発行幅の広いコアでIPCが0.3など1を大きく下回る場合、通常はコアが時間の大半をメモリー待ちに費やしています。局所性を高めるデータ構造の見直し、ループの順序変更、キャッシュ再利用のためのブロッキングなどは、どのコンパイラーオプションよりも効果があることが多いです。クロック周波数を上げてもナノ秒単位のメモリーレイテンシーは短くならないため、メモリー律速のコードでは周波数を上げるほどIPCが下がります。

IPCの測定方法

プロセッサーには、サイクル数、リタイアした命令数、各レベルのキャッシュミス、TLBミス、分岐予測ミスを数えるハードウェアカウンターを備えたPMU(性能監視ユニット)が搭載されています。リタイアした命令数をサイクル数で割れば、IPCが直接求まります。Linuxのperfなどのツールはプログラム実行中にこれらのカウンターを読み取り、IPCをキャッシュミス率や分岐予測ミス率と比べることで、時間がメモリー、分岐、演算のどこに費やされているかがわかります。最近のCPUは負荷や温度に応じて常に周波数を変えるため、実時間ではなくサイクル数で数えるほうが、マイクロアーキテクチャーの効率をより正確に把握できます。

IPCの練習問題に挑戦

性能カウンタで測ったところ、あるプログラムのIPC(1サイクルあたりの命令数)が0.3と非常に低く、最後の段のキャッシュのミスが多かった。最も考えられる状況と対策の組み合わせはどれか。

  1. Aメモリの待ちでCPUが止まっている時間が長い。データの並べ方を変えたりブロッキングを行ったりして、キャッシュを有効に使う
  2. B計算が速すぎる。周波数を上げる
  3. C分岐が少なすぎる。分岐を増やす
答えと解説を見る

正解：A. メモリの待ちでCPUが止まっている時間が長い。データの並べ方を変えたりブロッキングを行ったりして、キャッシュを有効に使う

現在のCPUは1サイクルに数命令を実行できるので、IPCが0.3というのは、ほとんどの時間何かを待っていることを示します。最後の段のキャッシュのミスが多ければ、主記憶からのデータを待っている時間が長いと考えられます。データを続いた番地に並べる、ループの順番を変える、ブロッキングで同じデータを何度も使う、などでキャッシュのミスを減らすのが効果的です。

よくある質問

クロック周波数とIPCはどちらが高いほうが良いですか?

性能は両者の積で決まるため、どちらか一方だけでは速さは決まりません。クロック周波数が低くてもIPCがはるかに高いコアは、同じプログラムでより高クロックのコアを上回ることがあります。

プログラムのIPCはどうやって測定しますか?

Linuxのperfなどでハードウェア性能カウンターを使い、リタイアした命令数とサイクル数を数えます。IPCは命令数をサイクル数で割った値で、値が低い場合はキャッシュミスや分岐予測ミスの回数が原因の手がかりになります。

IPCが低いとはどういうことですか?

コアが多くのサイクルで何もできずにいることを意味します。最も多い原因はキャッシュミス後のメモリーからのデータ待ちで、ほかに分岐予測ミスからの回復や長い依存関係の連鎖があります。
