システムコールとは

しすてむこーる

アプリケーションがファイルの読み書きやメモリの確保などをOSに依頼するしくみ。専用の命令で例外を起こして特権モードに切り替え、カーネルの処理を呼び出す。

この用語の分野: OSとハードウェア

解説の中の「システムコール」

  • システムコールでは、ユーザモードから特権モードへの切り替え、レジスタの保存、引数の確認、元に戻る処理などが毎回必要で、処理する量が1バイトでもこの固定の負担がかかります。

    小さなデータを1バイトずつ書き出すときに、毎回システムコールを呼ぶより、ユーザ空間のバッファにためてからまとめて書き出…

  • そこでシステムコールを使い、専用の命令で特権モードに切り替えてカーネルの処理を呼び出し、ファイルの読み書きやメモリの確保、プロセスの生成などを依頼します。

    アプリケーションがファイルの読み書きなどをOSに依頼するしくみを何と呼ぶか。

  • カーネルはa7の番号でどのシステムコールかを判断し、a0〜a2を引数として処理して、結果を返したあとユーザモードに戻ります。

「システムコール」が出てくる問題(8問)

  1. 小さなデータを1バイトずつ書き出すときに、毎回システムコールを呼ぶより、ユーザ空間のバッファにためてからまとめて書き出す方が速くなる主な理由はどれか。
  2. アプリケーションがファイルの読み書きなどをOSに依頼するしくみを何と呼ぶか。
  3. 上のRISC-Vのコードの最後のecall命令が実行されたときに起こることとして正しいものはどれか。
  4. 割り込みと例外の違いとして一般的な説明はどれか。
  5. 割り込みベクタテーブルの役割として正しいものはどれか。
  6. 一般的なOSで、アプリケーションが装置のレジスタを直接読み書きできないようにしている主な理由はどれか。
  7. 多くのOSで、カーネルの領域を各プロセスのアドレス空間の一部(例えば上位の範囲)に割り当てておき、ページテーブルの保護ビットでユーザモードからのアクセスを禁止している。この配置の主な利点はどれか。
  8. ファイルをメモリに対応づける(mmapのような)しくみで、ファイルの内容を読むときに起こることの説明として正しいものはどれか。
