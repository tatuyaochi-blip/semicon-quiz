位置独立コードとは

いちどくりつこーど

メモリのどの番地に読み込んでも、コードを書き換えずに動く機械語。PICとも呼ぶ。PC相対の参照やGOTを使い、共有ライブラリやPIEで使われる。

「位置独立コード」は、2分野の5問の練習問題に出てきます(リンカ・ローダと実行形式, 命令セット・アセンブリなど)。

この用語の分野: リンカ・ローダと実行形式

PICでのコードとデータの参照方法

位置独立コード(PIC)は、命令の中に絶対アドレスを埋め込みません。分岐や呼び出しの飛び先はプログラムカウンタからの距離で指定するので、モジュール全体をどこに置いても距離は変わりません。分岐命令のフィールドでは届かない遠い飛び先には、RISC-Vでは、20ビットの即値を12ビット左シフトしてPCに足すauipcと、下位12ビットを与えるjalrやロード命令を組み合わせ、現在の命令から約±2 GiBの範囲をカバーします。x86-64には同じ目的のRIP相対アドレッシングがあり、位置独立コードを固定アドレスのコードとほぼ同じ速さで動かせます。

GOTとPLT

PC相対の距離が使えるのは1つのモジュールの中だけで、別の共有ライブラリにある変数や関数のアドレスは実行時までわかりません。そこでPICでは、そうしたシンボルにグローバルオフセットテーブル(GOT)を通じてアクセスします。GOTはモジュールごとのアドレスの表で、コードから決まった距離に置かれます。コードは必要なアドレスをGOTから読み込み、実際のアドレスは読み込み時に動的リンカが書き込みます。ELFのシステムでは、外部関数の呼び出しはさらに手続きリンケージテーブル(PLT)の小さなスタブを経由し、各関数を最初の呼び出し時に遅延解決できます。

共有ライブラリにPICが必要な理由

共有ライブラリは、それを使うプロセスごとに異なる仮想アドレスにマップされることがあります。コードに絶対アドレスが含まれていると、ローダはアドレスごとに命令を書き換えなければならず、共有の読み出し専用ページがプロセスごとの書き込み可能なコピーになって、共有の意味がなくなります。PICなら、プロセスごとに異なるのは書き込み可能な小さなGOTだけなので、コードのページは変更不要で、1つの物理的なコピーをすべてのプロセスにマップできます。これによりメモリを節約でき、どこに配置されてもライブラリを素早く読み込めます。

PICとPIE、セキュリティとの関係

位置独立実行形式(PIE)は、同じ技術をメインプログラムに適用したもので、GCCやClangでは通常 -fPIE と -pie オプションでビルドします。共有ライブラリには -fPIC を使います。以前の実行ファイルは固定の読み込みアドレスを前提としていたため、アドレス空間配置のランダム化(ASLR)でライブラリやスタックは動かせても、メインプログラムのコードは動かせず、そのアドレスは攻撃者に予測されやすいままでした。PIEはどこにでも読み込めるので、コードもランダム化されます。現在の多くのLinuxディストリビューションは、既定でPIEとしてビルドしています。代償はGOTを経由する間接参照による小さなオーバーヘッドで、32ビットのx86ではこれが目立って大きくなっていました。

位置独立コードの練習問題に挑戦

位置独立コード(PIC)の説明として正しいものはどれか。

  1. AどのCPUでも同じように動く機械語
  2. B実行中に自分の置き場所を移動し続ける機械語
  3. Cメモリのどの番地に読み込んでも、コードを書き換えずに正しく動くように作られた機械語
答えと解説を見る

正解：C. メモリのどの番地に読み込んでも、コードを書き換えずに正しく動くように作られた機械語

共有ライブラリは、プロセスごとに違う番地に読み込まれることがあります。位置独立コードでは、関数やデータを固定の番地ではなく、PCからの距離や、番地をまとめた表(GOT)を通して参照します。こうすると、読み込む番地が変わってもコードのページを書き換えずに済むので、物理メモリ上の1つのコピーを多くのプロセスで共有できます。

よくある質問

PICとは何の略ですか?

position-independent code(位置独立コード)の略で、どの読み込みアドレスでも書き換えなしに正しく動く機械語のことです。PC相対アドレッシングとグローバルオフセットテーブルを利用します。

-fPICと-fPIEの違いは?

どちらも位置独立コードを生成します。-fPICは、シンボルがほかのモジュールに上書きされうる共有ライブラリ向けで、-fPIEはメインの実行ファイル向けです。-fPIEでは自分自身のシンボルを少し安価な直接参照で扱えます。-fPIEでビルドしたものを -pie でリンクするとPIEになります。

グローバルオフセットテーブル(GOT)はなぜ必要なのですか?

別のモジュールにあるシンボルのアドレスは読み込み後にしか決まらないため、コードに埋め込めないからです。GOTはそれらのアドレスを保持し、値は動的リンカが書き込みます。コードはPC相対の参照でGOTにアクセスします。
