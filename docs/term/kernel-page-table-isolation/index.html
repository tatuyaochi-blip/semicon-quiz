KPTIとは

けーぴーてぃーあい

カーネルページテーブル分離。ユーザのプログラムが動く間はカーネルのメモリのほとんどをページテーブルから外し、Meltdownを防ぐOSの対策。

「KPTI」は、2分野の3問の練習問題に出てきます(ハードウェアセキュリティの最新動向, ハードウェアセキュリティなど)。

この用語の分野: ハードウェアセキュリティ

KPTIが必要になった背景

従来の多くのOSは、ユーザのプロセスのページテーブルにカーネルの領域も載せ、カーネルのページには「ユーザからはアクセス禁止」の印を付けていました。こうするとシステムコールや割り込みでカーネルに入るときにページテーブルを切り替えずに済み、速く処理できます。ところが2018年に公表されたMeltdownでは、影響を受けるCPUで、この権限の確認が終わる前にカーネルのデータが投機的に読まれ、キャッシュに残った痕跡からその値を推測できることが示されました。KPTI(カーネルページテーブル分離)は、このような読み出しをページテーブルの構成によって防ぐOSの対策です。

2組のページテーブル

KPTIでは、プロセスごとに2組のページテーブルを用意します。カーネルの実行中に使う方には、ユーザとカーネルの両方の領域が載っています。ユーザのプログラムの実行中に使う方には、ユーザの領域と、システムコールや割り込みの入口の処理に必要なごく一部のカーネルの領域だけを載せます。アドレスの変換そのものがなければ、投機的な実行でもカーネルのデータは読めません。カーネルに入ると入口の処理でページテーブルをカーネル用に切り替え、ユーザに戻るときにユーザ用に戻します。Linuxでは2018年の初めに導入され、研究段階ではKAISERと呼ばれていました。

性能への影響とPCID

KPTIでは、システムコール、割り込み、例外のたびにページテーブルを切り替えるため、その分の時間がかかります。さらにPCIDを使えないCPUでは、切り替えのたびにTLBの内容が無効になり、その後のTLBミスも性能を下げます。影響は処理の内容によって大きく異なり、計算が中心のプログラムではほとんど目立たない一方、システムコールの多いデータベースや入出力の多い処理では大きくなりがちです。x86のPCID(プロセスコンテキスト識別子)を使えば、ユーザ用とカーネル用のページテーブルに別の番号を付けて、TLBを空にせずに切り替えられるため、損失を減らせます。

KPTIが不要な場合

KPTIはMeltdownの影響を受けるCPUのための対策で、影響を受けないCPUでは不要です。Meltdownの公表後に設計されたCPUの多くは、権限のないデータが後続の命令に渡らないようにハードウェアで修正されており、LinuxはCPUが報告する情報などから影響の有無を判断して、不要な場合はKPTIを有効にしません。AMDのx86のCPUのように、もともとMeltdownの影響を受けないとされるCPUもあります。WindowsではKVA Shadowと呼ばれる同様の対策が導入されました。なおKPTIはMeltdown向けの対策で、分岐予測を悪用するSpectreには別の対策が必要です。

KPTIの練習問題に挑戦

Meltdownへのソフトウェアの対策として導入されたKPTI(カーネルページテーブル分離)の考え方として正しいものはどれか。

  1. Aユーザのプログラムが動いている間は、カーネルのメモリのほとんどをページテーブルから外し、投機的にも読めないようにする
  2. Bカーネルをすべて暗号化して、ディスクに置く
  3. Cユーザのプログラムの実行を禁止する
答えと解説を見る

正解：A. ユーザのプログラムが動いている間は、カーネルのメモリのほとんどをページテーブルから外し、投機的にも読めないようにする

従来のOSは、切り替えを速くするため、ユーザのプロセスのページテーブルにもカーネルのメモリを(アクセス禁止の印を付けて)載せていました。Meltdownでは、その印の確認より先に投機的に読めてしまったので、KPTIではユーザのプログラムが動く間はカーネルのページを対応づけ自体から外しました。番地の変換ができなければ投機的にも読めません。ただし、システムコールのたびにページテーブルを切り替えるので性能が下がります。

よくある質問

KPTIとは何ですか?

カーネルページテーブル分離(Kernel Page-Table Isolation)の略で、ユーザのプログラムが動いている間はカーネルのメモリのほとんどをページテーブルから外し、Meltdownによる読み出しを防ぐOSの対策です。

KPTIで性能が下がるのはなぜですか?

システムコールや割り込みでカーネルに出入りするたびにページテーブルを切り替えるため、その処理と、その後のTLBミスの分だけ時間がかかるからです。PCIDを使えるCPUではTLBを空にせずに済み、損失を減らせます。

KPTIは無効にしてもよいですか?

Meltdownの影響を受けないCPUやハードウェアで修正されたCPUでは不要で、OSも自動で無効にするのが一般的です。影響を受けるCPUで無効にすると、カーネルのメモリを読まれる危険が残ります。

「KPTI」が出てくる問題(3問)

  1. Meltdownへのソフトウェアの対策として導入されたKPTI(カーネルページテーブル分離)の考え方として正しいものはどれか。
  2. 制御フロー完全性をハードウェアで支える機能について、関数からの戻りを守るものと、関数ポインタなどによる間接的な呼び出しやジャンプを守るものの組み合わせとして、正しいものはどれか。
  3. ある処理は、投機的実行への対策を入れる前に10秒かかり、その間にシステムコールを500万回呼んでいた。対策を入れると、システムコール1回あたりの処理時間が0.4 µsから0.6 µsに増え、それ以外の部分の時間は変わらないとする。処理全体の時間の増加の割合はどれか。
