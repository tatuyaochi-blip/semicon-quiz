スラックとは

すらっく

タイミングの余裕を表す値。セットアップでは要求時刻から到着時刻を、ホールドでは到着時刻から要求時刻を引いて求め、負なら違反している。

「スラック」は、1分野の10問の練習問題に出てきます(タイミング解析とCDCなど)。

この用語の分野: タイミング解析とCDC

セットアップスラックの計算

静的タイミング解析(STA)では、データの到着時刻と要求時刻を比較します。セットアップでは、あるクロックエッジで送り出したデータが、次の取り込みエッジからセットアップ時間を引いた時刻までに届く必要があり、スラック = 要求時刻 − 到着時刻です。周期2.0 ns、クロック・出力間遅延0.2 ns、論理遅延1.4 ns、セットアップ時間0.1 nsなら、到着時刻は1.6 ns、要求時刻は1.9 nsで、スラックは+0.3 nsです。ジッタや未構築のクロックツリーを見込んだクロック不確かさも要求時刻から差し引きます。また、マルチサイクルパスを2に設定すると、取り込みエッジが1周期後ろにずれます。

ホールドスラックと周波数の関係

ホールドは逆の確認です。あるエッジで送り出された新しいデータが早く着きすぎて、同じエッジで取り込み中の値を壊さないかを調べます。この場合はスラック = 到着時刻 − 要求時刻で、最小遅延を使い、要求時刻は取り込み側クロックの到着時刻にホールド時間を足した値です。どちらも同じエッジを基準にするため、クロック周期は式に現れません。したがってクロックを遅くしてもホールド違反は直らず、シリコンで起きれば通常は致命的です。ホールドの問題はシフトレジスタのような短いパスで起きやすく、一般にデータパスへ遅延セルを挿入して修正します。

スキュー、OCV、CRPR

クロックスキューは2つのチェックを逆方向に動かします。取り込み側クロックが送り出し側より遅れて届く正のスキューでは、セットアップスラックがその分増え、ホールドスラックが同じだけ減ります。負のスキューではその逆です。オンチップばらつき(OCV)のディレーティングは解析を悲観側にし、セットアップでは送り出し側のクロックとデータパスを遅く、取り込み側クロックを速く見積もります。両方のクロックパスがルートからバッファを共有している区間は、同時に速くも遅くもなれないため、共通パス悲観性除去(CRPR)でその差を戻します。

タイミングレポートの読み方

レポートはエンドポイントごとのスラックをまとめたものです。WNS(ワーストネガティブスラック)は最悪の1つの値で、目標クロックまでどれだけ足りないかを示します。TNS(トータルネガティブスラック)は違反しているすべてのエンドポイントの負のスラックの合計で、残りの作業量の目安になります。−0.1 nsのエンドポイントが3つあれば、WNSは−0.1 ns、TNSは−0.3 nsです。どちらもセットアップとホールド、クロックグループごとに分けて報告されます。セットアップ違反は論理の短縮、セルのサイズアップ、回路の再構成で対処します。マルチサイクル例外は、論理が本当に1サイクルおきに取り込む場合にだけ正当です。

スラックの練習問題に挑戦

クロック周期 2.0 ns の同期回路で、送り側フリップフロップのクロック→出力遅延が 0.2 ns、組み合わせ回路の遅延が 1.4 ns、受け側フリップフロップのセットアップ時間が 0.1 ns である。クロックスキューを0とすると、セットアップのスラックはいくらか。

  1. A0.3 ns
  2. B0.4 ns
  3. C0.5 ns
答えと解説を見る

正解：A. 0.3 ns

セットアップのスラックは「要求時刻 − 到着時刻」で求めます。データの到着時刻は 0.2 + 1.4 = 1.6 ns、要求時刻は次のクロックエッジからセットアップ時間を引いた 2.0 − 0.1 = 1.9 ns なので、スラックは 1.9 − 1.6 = 0.3 ns です。正の値なので制約を満たしています。0.4 ns はセットアップ時間を引き忘れた値、0.5 ns はセットアップ時間を逆に足してしまった値です。スラックが負になると違反です。

クロック周期 1.0 ns、クロック→出力遅延 0.1 ns、組み合わせ回路の遅延 0.85 ns、セットアップ時間 0.08 ns の経路がある。受け側フリップフロップのクロックが送り側より 0.05 ns 遅れて届くとき、セットアップのスラックはいくらか。

  1. A−0.03 ns
  2. B+0.02 ns
  3. C−0.08 ns
答えと解説を見る

正解：B. +0.02 ns

受け側のクロックが遅れて届く(正のスキュー)と、データを取り込むエッジが後ろにずれるので、セットアップに使える時間が増えます。要求時刻は 1.0 + 0.05 − 0.08 = 0.97 ns、到着時刻は 0.1 + 0.85 = 0.95 ns なので、スラックは +0.02 ns です。−0.03 ns はスキューを無視した値、−0.08 ns はスキューの向きを逆に(受け側が早く届くとして)扱った値です。同じスキューはホールドには不利に働く点に注意が必要です。

よくある質問

タイミング解析で負のスラックは何を意味しますか?

パスが制約に違反していることを意味します。セットアップではデータが取り込みエッジに間に合わず、ホールドではデータが早く着きすぎて取り込み中の値を上書きするおそれがあります。その大きさが、削るべき遅延または追加すべき遅延の量を示します。

WNSとTNSの違いは何ですか?

WNSは最も悪い1本のパスのスラック、TNSは違反している全エンドポイントの負のスラックの合計です。多くのパスがわずかずつ違反していると、WNSは小さくてもTNSが大きくなることがあります。

ホールド違反はどうやって直しますか?

短いデータパスにバッファや遅延セルを入れて遅延を追加するか、取り込み側クロックを遅らせているスキューを減らします。ホールドチェックには周期が関係しないため、クロック周波数を下げても解決しません。

「スラック」が出てくる問題(10問)

  1. クロック周期 2.0 ns の同期回路で、送り側フリップフロップのクロック→出力遅延が 0.2 ns、組み合わせ回路の遅延が 1.4 ns、受け側フリップフロップのセットアップ時間が 0.1 ns である。クロックスキューを0とすると、セットアップのスラックはいくらか。
  2. クロック周期 1.0 ns、クロック→出力遅延 0.1 ns、組み合わせ回路の遅延 0.85 ns、セットアップ時間 0.08 ns の経路がある。受け側フリップフロップのクロックが送り側より 0.05 ns 遅れて届くとき、セットアップのスラックはいくらか。
  3. 送り側のクロック→出力遅延が最小 0.08 ns、組み合わせ回路の最小遅延が 0.02 ns、受け側のホールド時間が 0.05 ns である。受け側のクロックが送り側より 0.1 ns 遅れて届くとき、ホールドのスラックはいくらか。
  4. 同じクロックの立ち上がりエッジで送り出しと取り込みを行う通常の経路で、ホールド違反(スラック −0.03 ns)が見つかった。クロック周波数を半分に下げたときの、この違反の扱いとして正しいものはどれか。
  5. クロック周期 1.25 ns(800 MHz)の経路で、クロック→出力遅延と組み合わせ回路の遅延の合計が 1.05 ns、セットアップ時間が 0.05 ns、セットアップ用のクロックの不確かさが 0.05 ns に設定されている。セットアップのスラックはいくらか。
  6. OCVディレーティングとして、セットアップ解析で送り側のクロック経路とデータ経路の遅延を1.1倍、受け側のクロック経路の遅延を0.9倍にする。送り側クロック経路 1.0 ns、データ経路(クロック→出力を含む)1.5 ns、受け側クロック経路 1.0 ns(共通部分はない)、周期 3.0 ns、セットアップ時間 0.1 ns のとき、セットアップのスラックはいくらか。
  7. 周期 2.0 ns のクロックで動く回路で、データの到着時刻(クロック→出力遅延と組み合わせ回路の遅延の合計)が 3.3 ns、セットアップ時間が 0.1 ns の経路がある。この経路は2サイクルに1回だけ取り込めばよいので、セットアップのマルチサイクルパスを2に設定した。セットアップのスラックはいくらか。
  8. STAのレポートに出てくるWNSとTNSの説明として正しいものはどれか。
  9. 受け側フリップフロップのクロックが送り側より遅れて届く(正のスキュー)ときの、セットアップとホールドへの影響として正しいものはどれか。
  10. OCVディレーティングを使ったSTAで、送り側と受け側のクロック経路が途中まで共通な場合に行うCRPR(共通パスの悲観性の除去)の説明として正しいものはどれか。
