共有ライブラリとは

きょうゆうらいぶらり

動的リンクで実行時に読み込まれるライブラリ。Linuxでは.so、Windowsでは.dll。位置独立コードで作られ、コードのページを多くのプロセスで共有できる。

「共有ライブラリ」は、3分野の16問の練習問題に出てきます(リンカ・ローダと実行形式, 命令セット・アセンブリ, クラウドとコンテナの基礎など)。

この用語の分野: リンカ・ローダと実行形式

動的リンクの仕組み

共有ライブラリとリンクしたプログラムの実行ファイルには、必要なライブラリをsonameで識別した一覧と、取り込むシンボルだけが記録されます。起動時に動的リンカ(Linuxではld.so)が各ライブラリを探してプロセスのアドレス空間にマッピングし、シンボルの参照を解決して再配置を適用します。ライブラリ関数の呼び出しは通常PLT(プロシージャリンケージテーブル)を経由し、各関数を最初の呼び出し時に遅延解決できます。lddコマンドを使うと、必要なライブラリがどのファイルに解決されるかを確認でき、見つからないものは「not found」と表示されます。ただし信頼できないバイナリにlddを使うと、そのコードが実行されるおそれがあるので避けるべきです。

位置独立コードとページの共有

共有ライブラリはプロセスごとに異なるアドレスに配置される可能性があるため、位置独立コード(PIC)としてコンパイルされます。自身の関数やデータへはPC相対アドレッシングでアクセスし、外部のシンボルへはGOT(グローバルオフセットテーブル)を経由します。GOTはプロセスごとに持つデータ領域で、動的リンカが中身を書き込みます。そのためコードのページは書き換える必要がなく、読み出し専用かつ実行可能としてマッピングできます。OSは全プロセスのマッピングを同じ物理ページに向けるので、100個のプロセスが1つのライブラリを使ってもコードは1つ分しか占めません。一方、書き込み可能なデータページはプロセスごとに持ち、通常はコピーオンライトで扱います。

sonameによるバージョン管理

Linuxでは、libfoo.so.1.2.3のようなライブラリファイルがlibfoo.so.1のようなsonameを持ち、プログラムはこのsonameを記録します。ABI(アプリケーションバイナリインターフェース)の互換性を保ったバグ修正やセキュリティパッチではsonameを変えないため、ファイルを1つ置き換えるだけで、それを使うすべてのプログラムが更新されます。一方、引数の型や構造体のレイアウトを変えたり関数を削除したりすると古いバイナリが動かなくなるので、sonameの番号を上げ、新しいライブラリを古いものと並べてインストールします。

共有ライブラリと静的ライブラリの比較

静的ライブラリはオブジェクトファイルをまとめたアーカイブで、必要な部分がリンク時に実行ファイルへコピーされます。起動時の結合処理が不要な自己完結したバイナリになりますが、各プログラムが自分用のコピーを持ち、修正には再リンクが必要です。共有ライブラリはメモリとディスクを節約でき、その場で更新できる反面、起動時の結合処理、モジュールをまたぐ呼び出しでの間接参照、依存ライブラリが見つからないことによる失敗といった代償があります。内部関数をhidden属性にして公開APIだけをエクスポートすると、動的リンカが処理するシンボルが減り、内部呼び出しがPLTを経由せずに済み、名前の衝突も避けられ、ABIを小さく保てます。

共有ライブラリの練習問題に挑戦

動的リンク(共有ライブラリ)の利点として正しいものはどれか。

  1. A実行環境にライブラリがなくても、必ず動く
  2. B複数のプログラムが1つのライブラリをメモリ上で共有でき、ライブラリを更新すれば作り直さずに修正が反映される
  3. C起動時の処理がまったく不要になり、静的リンクより必ず速く起動する
答えと解説を見る

正解：B. 複数のプログラムが1つのライブラリをメモリ上で共有でき、ライブラリを更新すれば作り直さずに修正が反映される

動的リンクでは、実行ファイルには「どの共有ライブラリのどの関数を使うか」だけを記録し、実行時に動的リンカがライブラリを読み込んで結びつけます。共有ライブラリのコードは書き換えないので、物理メモリ上の1つのコピーを多くのプロセスで共有できます。不具合や脆弱性の修正もライブラリを差し替えるだけで済みます。ただし起動時に結合の手間がかかります。

共有ライブラリで使われるGOT(グローバルオフセットテーブル)の役割として正しいものはどれか。

  1. Aライブラリの関数の名前を、アルファベット順に並べた目次である
  2. Bキャッシュに入りきらなかったデータを一時的に置く表である
  3. C外部の変数や関数の実際の番地をまとめた表で、実行時に動的リンカが埋め、コードはこの表を通して参照する
答えと解説を見る

正解：C. 外部の変数や関数の実際の番地をまとめた表で、実行時に動的リンカが埋め、コードはこの表を通して参照する

位置独立コードは、ほかのライブラリにある変数の番地を命令に直接書けません。そこで、各モジュールに番地を並べた表(GOT)を用意し、コードはPCからの距離でGOTの項目を読み、そこに入っている番地を使います。動的リンカは読み込んだときにGOTに実際の番地を書き込みます。書き換えるのは書き込み可能なデータのGOTだけなので、コードのページは共有したままにできます。

よくある質問

静的ライブラリと共有ライブラリの違いは?

静的ライブラリ(.aや.lib)はリンク時に実行ファイルへコピーされます。共有ライブラリ(.soや.dll)は別ファイルのまま実行時に読み込まれ、多くのプロセスがメモリ上で共有できます。

共有ライブラリのビルドに-fPICが必要なのはなぜですか?

ライブラリはどのアドレスにも読み込まれる可能性があるため、コードで絶対アドレスを使えないからです。PICはPC相対アドレッシングとGOTを使うので、コードのページを書き換える必要がなく、共有できます。

lddの出力に出る「not found」はどういう意味ですか?

動的リンカが検索パスの中でその共有ライブラリを見つけられないという意味です。ライブラリをインストールするかパスを修正するまで、そのプログラムは起動に失敗します。
