共有ライブラリとは

きょうゆうらいぶらり

動的リンクで実行時に読み込まれるライブラリ。Linuxでは.so、Windowsでは.dll。位置独立コードで作られ、コードのページを多くのプロセスで共有できる。

「共有ライブラリ」は、2分野の15問の練習問題に出てきます(リンカ・ローダと実行形式, 命令セット・アセンブリなど)。

この用語の分野: リンカ・ローダと実行形式

共有ライブラリの練習問題に挑戦

動的リンク(共有ライブラリ)の利点として正しいものはどれか。

  1. A実行環境にライブラリがなくても、必ず動く
  2. B複数のプログラムが1つのライブラリをメモリ上で共有でき、ライブラリを更新すれば作り直さずに修正が反映される
  3. C起動時の処理がまったく不要になり、静的リンクより必ず速く起動する
答えと解説を見る

正解：B. 複数のプログラムが1つのライブラリをメモリ上で共有でき、ライブラリを更新すれば作り直さずに修正が反映される

動的リンクでは、実行ファイルには「どの共有ライブラリのどの関数を使うか」だけを記録し、実行時に動的リンカがライブラリを読み込んで結びつけます。共有ライブラリのコードは書き換えないので、物理メモリ上の1つのコピーを多くのプロセスで共有できます。不具合や脆弱性の修正もライブラリを差し替えるだけで済みます。ただし起動時に結合の手間がかかります。

共有ライブラリで使われるGOT(グローバルオフセットテーブル)の役割として正しいものはどれか。

  1. Aライブラリの関数の名前を、アルファベット順に並べた目次である
  2. Bキャッシュに入りきらなかったデータを一時的に置く表である
  3. C外部の変数や関数の実際の番地をまとめた表で、実行時に動的リンカが埋め、コードはこの表を通して参照する
答えと解説を見る

正解：C. 外部の変数や関数の実際の番地をまとめた表で、実行時に動的リンカが埋め、コードはこの表を通して参照する

位置独立コードは、ほかのライブラリにある変数の番地を命令に直接書けません。そこで、各モジュールに番地を並べた表(GOT)を用意し、コードはPCからの距離でGOTの項目を読み、そこに入っている番地を使います。動的リンカは読み込んだときにGOTに実際の番地を書き込みます。書き換えるのは書き込み可能なデータのGOTだけなので、コードのページは共有したままにできます。

「共有ライブラリ」が出てくる問題(15問)

  1. 動的リンク(共有ライブラリ)の利点として正しいものはどれか。
  2. 共有ライブラリで使われるGOT(グローバルオフセットテーブル)の役割として正しいものはどれか。
  3. 100個のプロセスが同じ共有ライブラリを使っているとき、物理メモリの使い方として正しいものはどれか。
  4. Linuxの共有ライブラリで、libfoo.so.1の「.1」のようなsonameのバージョン番号を上げるのは、一般にどのようなときか。
  5. 共有ライブラリを作るとき、外から使う関数だけを公開し、内部の関数はシンボルの可視性(visibility)を「hidden」にする利点として正しいものはどれか。
  6. 分岐やジャンプにPC相対アドレッシングを使うことの利点として正しいものはどれか。
  7. C言語の関数ポインタを使った呼び出し「(*fp)(x)」は、RISC-Vでは一般にどの命令で行われるか。
  8. 実行ファイルの.textセクションに入っているものはどれか。
  9. Linuxなどの一般的なプロセスのメモリ配置を、番地の小さい方から並べたものとして正しいものはどれか。
  10. 動的リンクを使ったプログラムを別のコンピュータにコピーして実行したら、起動しなかった。最も考えられる原因はどれか。
  11. 位置独立コード(PIC)の説明として正しいものはどれか。
  12. Linuxで動的リンクのプログラムを起動するときに働く動的リンカ(ld.soなど)の役割として正しいものはどれか。
  13. ASLR(アドレス空間配置のランダム化)の目的として正しいものはどれか。
  14. Linuxのdlopen関数(WindowsのLoadLibraryに相当)の使い道として最も適切なものはどれか。
  15. Linuxでlddコマンドを実行ファイルに使うと分かることはどれか。
