アセンブラとは

あせんぶら

アセンブリ言語で書いたプログラムを、機械語の命令のビット列に変換するソフトウェア。ラベルを番地に直し、疑似命令を本物の命令に置き換える。

やさしい解説で読む: コンパイラとは? プログラムが機械語になるまで

「アセンブラ」は、2分野の6問の練習問題に出てきます(命令セット・アセンブリ, コンパイラなど)。

この用語の分野: 命令セット・アセンブリ

ニーモニックからビット列へ

アセンブラはアセンブリ言語のソースを1行ずつ読みます。命令ごとにニーモニックを調べてオペランドをチェックし、オペコード、レジスタ番号、即値を、命令フォーマットの決まったフィールド(たとえばRISC-Vの32ビット語)に詰め込みます。.text、.data、.word、.globlなどのディレクティブ(疑似命令とは別の、アセンブラへの指示)は、どのセクションに出力するか、どんなデータを配置するか、どのシンボルを外部に公開するかを指定します。アセンブリ言語は機械語命令とほぼ1対1に対応するので、命令セットアーキテクチャ(ISA)ごとに専用のアセンブリ言語があります。

ラベル、シンボル、2パス方式

ラベルを使うと、分岐先やデータの名前を数値の番地ではなく名前で書けます。ラベルは定義より前で使われることもあるため、古典的なアセンブラは2パスで処理します。1パス目でソースをたどって各ラベルに番地を割り当ててシンボルテーブルを作り、2パス目でその番地を使って各命令を符号化します。同じセクション内のラベルまでの距離はその場で埋められます。しかし、他のファイルのシンボルへの参照や、最終的な配置で決まる番地はまだ解決できないので、アセンブラは仮の値を置き、出力するオブジェクトファイルにリンカ向けの再配置エントリを記録します。

疑似命令とその展開

アセンブラは、ハードウェアには存在しない便利な疑似命令も受け付けます。RISC-Vでは、nopは addi x0, x0, 0 に、mv rd, rs は addi rd, rs, 0 に、j label は jal x0, label に、ret は jalr x0, 0(ra) になります。liは任意の定数をロードします。小さな値ならaddi 1命令で済み、32ビットの値は上位20ビットのluiと下位12ビットのaddiになります。addiは即値を符号拡張するので、下位部分が負のときは上位部分を1だけ調整します。また、分岐先が条件分岐の届く範囲(約4 KiB)を超える場合、条件を反転した分岐でjalを飛び越える形に書き換えることもあります。

コンパイラ・リンカ・逆アセンブラとの違い

コンパイラは高級言語を翻訳します。1つの文が多くの命令になることもあり、レジスタの割り当てや最適化について実質的な判断を伴います。アセンブラはそうした判断をほとんどせず、仕事は命令の符号化、ラベルの解決、疑似命令の展開です。出力はオブジェクトファイルで、そのまま実行できるプログラムではありません。リンカがオブジェクトファイルとライブラリを結合し、最終的な番地を確定させる必要があります。逆アセンブラはビット列からニーモニックへと逆方向に変換しますが、コメントは復元できず、シンボルテーブルがなければ元のラベル名も復元できません。

アセンブラの練習問題に挑戦

RISC-Vの疑似命令「nop」(何もしない)は、アセンブラによって実際にはどの命令に置き換えられるか。

  1. Aaddi x0, x0, 0
  2. Bjal ra, 0
  3. Clw x0, 0(sp)
答えと解説を見る

正解：A. addi x0, x0, 0

RISC-Vには「何もしない」専用の命令はなく、nopは「addi x0, x0, 0」として表されます。x0への書き込みは捨てられるので、レジスタもメモリも何も変わりません。同様に「mv rd, rs」は「addi rd, rs, 0」、「j label」は「jal x0, label」、「ret」は「jalr x0, 0(ra)」です。x0を使って命令の種類を少なく保つのがRISC-Vの設計の考え方です。

よくある質問

アセンブラとコンパイラの違いは何ですか?

コンパイラはC言語などの高級言語をアセンブリ言語や機械語に翻訳し、レジスタの使い方や最適化について判断します。アセンブラはアセンブリ言語をほぼ1対1で機械語に翻訳するもので、主な仕事は命令の符号化とラベルの番地への変換です。

アセンブリ言語の疑似命令とは何ですか?

ハードウェアが直接実装していない便利なニーモニックで、アセンブラが1つ以上の実在する命令に置き換えます。たとえばRISC-Vでは、nopは addi x0, x0, 0 としてアセンブルされ、liはluiとaddiの組になることがあります。

アセンブラは実行ファイルを出力しますか?

通常は出力しません。出力するのは機械語、シンボルテーブル、再配置エントリを含むオブジェクトファイルで、1つ以上のオブジェクトファイルをリンカが実行ファイルにします。

解説の中の「アセンブラ」

  • アセンブリ言語は、機械語の命令を「add a0, a0, a1」のような人が読める記号(ニーモニック)で書いたもので、アセンブラが命令のビット列に変換します。

  • C言語のソースファイルは、まずコンパイラで機械語に近いアセンブリ言語(または直接オブジェクトファイル)に変換され、アセンブラで機械語のオブジェクトファイルになります。

「アセンブラ」が出てくる問題(6問)

  1. RISC-Vの疑似命令「nop」(何もしない)は、アセンブラによって実際にはどの命令に置き換えられるか。
  2. アセンブリ言語と機械語の関係として正しいものはどれか。
  3. RISC-Vで、12ビットの即値に収まらない32ビットの定数(例: 0x12345678)をレジスタに入れる一般的な方法はどれか。
  4. RISC-Vで定数0x12345FFFをluiとaddiの2命令で作るとき、正しい組み合わせはどれか。
  5. RISC-Vの条件分岐命令(B形式)は、分岐先までの距離を13ビットの符号付きのバイト数で表し、その最下位ビットは常に0として命令に入れない。分岐命令が直接届く範囲としておよそ正しいものはどれか。
  6. C言語のプログラムから実行ファイルができるまでの一般的な流れとして正しいものはどれか。
