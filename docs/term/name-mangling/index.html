名前修飾とは

なまえしゅうしょく

C++のコンパイラが、関数名に引数の型や名前空間の情報を埋め込んでシンボル名を作ること。マングリングとも呼ぶ。オーバーロードした関数をリンカが区別できる。

「名前修飾」は、1分野の2問の練習問題に出てきます(リンカ・ローダと実行形式など)。

この用語の分野: リンカ・ローダと実行形式

何が埋め込まれるか

修飾された名前(マングル名)は、ソース上で同じ名前を持つC++の要素どうしを区別する情報を、すべて1つのリンカ用シンボルに詰め込んだものです。囲んでいる名前空間やクラス、関数名、引数の型、メンバ関数の const や volatile 修飾、テンプレート引数が含まれます。オーバーロードは戻り値の型だけでは区別できないので、戻り値の型は通常含まれませんが、関数テンプレートのインスタンスでは含まれます。LinuxをはじめGCCやClangの多くのプラットフォームで使われるItanium C++ ABIでは、print(int) は _Z5printi に、ns::f(double) は _ZN2ns1fEd になります。各名前の前にその長さが付き、組み込み型は1文字で表されます。

extern "C" と言語の混在

C言語にはオーバーロードがないため、Cのコンパイラは関数名をそのままシンボルにします。C++のコードからCのライブラリを呼ぶときは、宣言を extern "C" で囲み、C++のコンパイラが修飾されていない名前を探すようにしなければなりません。そうしないと _Z3fooi のような名前を探して foo しか見つからず、未定義参照でリンクに失敗します。両方の言語で共有するヘッダでは、__cplusplus マクロの有無を確かめたうえで、宣言を extern "C" で囲むのが一般的です。extern "C" と宣言した関数はオーバーロードできません。2つあると同じシンボルに対応してしまうからです。

マングル名を読む

マングル名は nm の出力、逆アセンブル結果、クラッシュレポート、リンカのエラーなどに現れます。c++filt ツールを使えば読みやすい宣言に戻せ、nm -C は一覧表示の際に同じ変換を行います。多くのデバッガやリンカも、診断メッセージを表示するときに自動でデマングルします。それでも生の形を読めると役に立ちます。デマングルすると同じに見える2つのシンボルが const 修飾や引数の型で異なっていることがあり、ヘッダの宣言と実際にコンパイルされた定義が一致していないとわかるからです。

名前修飾はABIの一部

名前修飾の方式はコンパイラの系統ごとに定められており、MicrosoftのコンパイラはItanium ABIとはまったく異なる符号化を使います。この方式はアプリケーションバイナリインタフェース(ABI)の一部なので、方式の異なるコンパイラで作ったオブジェクトファイルは、ソースが同じでも直接リンクできません。引数の型を変えるなど、ライブラリのC++インタフェースを変更するとマングル名が変わり、古い版に対してビルドしたプログラムとのバイナリ互換性が失われます。Rustなど、オーバーロードやモジュールを持つほかの言語も、同じ理由で名前修飾を行います。

名前修飾の練習問題に挑戦

C++のコンパイラが関数名に引数の型などの情報を付け加えてシンボル名を作る「名前修飾(マングリング)」の主な目的はどれか。

  1. A関数名を読めなくして、プログラムを盗まれないようにする
  2. B関数名を短くして、実行ファイルを小さくする
  3. C同じ名前で引数の型が違う関数(オーバーロード)や名前空間を、リンカが区別できるようにする
答えと解説を見る

正解：C. 同じ名前で引数の型が違う関数(オーバーロード)や名前空間を、リンカが区別できるようにする

リンカはシンボルを名前の文字列だけで照合します。C++では「print(int)」と「print(double)」のように同じ名前の関数を作れるので、そのままでは区別できません。そこでコンパイラは「_Z5printi」のように引数の型などを名前に埋め込みます。C言語の関数は修飾されないので、C++からCの関数を呼ぶときは「extern "C"」を付けて修飾をやめさせます。

よくある質問

C++のシンボル名をデマングルするにはどうしますか?

c++filt に通します。たとえば echo _Z5printi | c++filt を実行すると print(int) と表示されます。nm -C や objdump -C は、シンボルを一覧表示すると同時にデマングルします。

C++の extern "C" は何をするものですか?

宣言した関数にCリンケージを与え、コンパイラが修飾なしの名前をそのまま使うようにします。これにより、C++のコードからCのライブラリを呼べるようになり、この方法で公開したC++の関数をCのコードから呼ぶこともできます。

関数のマングル名に戻り値の型が含まれないのはなぜですか?

C++のオーバーロードは引数で区別しなければならないので、引数だけで関数を特定できるからです。例外は関数テンプレートのインスタンスで、戻り値の型も符号化されます。

  • 定義したファイルをリンクし忘れた、ライブラリを指定し忘れた(-lm など)、名前のつづりが違う、C++で書いた関数をextern "C"なしで呼んでいて名前修飾で別の名前になっている、といった原因がよくあります。
