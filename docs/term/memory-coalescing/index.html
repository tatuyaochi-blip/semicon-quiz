メモリコアレッシングとは

めもりこあれっしんぐ

ワープの中の隣り合うスレッドが隣り合う番地にアクセスしたとき、まとめて少ない回数のメモリアクセスにすること。合体アクセス。

「メモリコアレッシング」は、1分野の1問の練習問題に出てきます(GPUプログラミングなど)。

この用語の分野: GPUプログラミング

コアレッシングの仕組み

GPUのグローバルメモリは、1語ずつではなく決まった大きさの塊でアクセスされます。一般的には128バイトのキャッシュラインの中の32バイトのセクタ単位です。スレッドはワープと呼ぶグループで実行され、通常は32スレッドが同じロード命令を一緒に発行します。ワープのスレッド i が番地 base + 4i の4バイトの要素を読むと、32個の要求は連続した128バイトに収まり、ハードウェアはそれを1回か数回のメモリトランザクションにまとめます。このまとめる処理がメモリコアレッシング(合体アクセス)で、これによりGPUは転送したバイトのほぼすべてを活用できます。

コアレッシングを妨げる要因

スレッドがストライドを持つ番地、たとえば4要素おきにアクセスすると、ワープが触れるセクタは4倍に増え、取ってきた各セクタの大部分は捨てられます。ランダムなアクセスや間接参照では、スレッドごとに別々のトランザクションが必要になることもあります。開始番地がアラインされていないと、セグメントが1つ余分に必要になることがあります。いずれの場合も実効帯域はピークの何分の一かに落ちます。多くのGPUカーネルは演算ではなくメモリ帯域で性能が制限されるため、コアレッシングされないアクセスはカーネルを大幅に遅くすることがよくあります。

AoSとSoA

アクセスがコアレッシングされるかどうかは、データの配置でほぼ決まります。粒子の位置を構造体の配列(AoS)で保存すると、粒子0の x、y、z の後に粒子1の x、y、z が続くので、各スレッドが x を読むときの番地は12バイトずつ離れます。配列の構造体(SoA)にすると、すべての x が連続して並ぶので、隣り合うスレッドが隣り合う番地を読み、ワープのロードがコアレッシングされます。同じ理由で、SoAは通常CPUのSIMDによるベクトル化にも有利です。隣のレーンが隣の要素を必要とするからです。

対策とよくある混同

よく使われる対策には、最も速く変わるスレッド番号(CUDAでは threadIdx.x)を配列の連続した次元に対応させること、AoSのデータをSoAに変換すること、オンチップの共有メモリを経由させることがあります。たとえば行方向のコアレッシングされた読み出しで行列のタイルを読み込み、転置して書き出します。コアレッシングはグローバルメモリのトランザクションに関する話です。共有メモリのバンクコンフリクトと混同しないようにしてください。バンクコンフリクトは、ワープの複数のスレッドが共有メモリの同じバンク内の異なる番地にアクセスし、アクセスが直列化される現象です。

メモリコアレッシングの練習問題に挑戦

GPUのメモリ合体アクセス(コアレッシング)の説明として正しいものはどれか。

  1. A2つのGPUのメモリを1つにまとめて容量を2倍にする
  2. Bメモリのデータを圧縮して容量を増やす
  3. Cワープの中の隣り合うスレッドが隣り合う番地を読むと、まとめて少ない回数のメモリアクセスで済む
答えと解説を見る

正解：C. ワープの中の隣り合うスレッドが隣り合う番地を読むと、まとめて少ない回数のメモリアクセスで済む

GPUのメモリは、32バイトや128バイトなどのまとまった単位で読み書きします。ワープの32本のスレッドがそれぞれ4バイトの続いた番地を読むと、合わせて128バイトのまとまりを1〜数回のアクセスで読めます。番地がばらばらだと、スレッドごとに別のまとまりを読むことになり、使わないデータまで運ぶので、実効的な帯域が何分の一にも落ちます。

よくある質問

CUDAのメモリコアレッシングとは何ですか?

ワープのスレッドによるグローバルメモリへのアクセスを、ハードウェアができるだけ少ないトランザクションにまとめることです。隣り合うスレッドが、アラインされた隣り合う番地にアクセスするときに起こります。

GPUのメモリアクセスでSoAが有利なのはなぜですか?

配列の構造体(SoA)では各フィールドが連続して保存されるため、隣り合うスレッドが同じフィールドを読むと連続した番地にアクセスし、ロードがコアレッシングされます。構造体の配列(AoS)では、その間にストライドが生じます。

メモリコアレッシングとバンクコンフリクトの違いは?

コアレッシングは、ワープのグローバルメモリへのアクセスがどのようにメモリトランザクションに対応するかの話です。バンクコンフリクトは、複数のスレッドがオンチップの共有メモリの同じバンクにアクセスし、直列化が必要になる現象です。
