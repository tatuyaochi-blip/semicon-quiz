ビューとは

びゅー

関係データベースで、SELECT文に名前を付けて定義する仮想的な表。ふつうは自分ではデータを持たず、参照するたびに元の表から結果を作る。複雑な問い合わせを簡単にしたり、見せる列や行を絞ってアクセスできる範囲を制限したりするのに使う。

「ビュー」は、1分野の2問の練習問題に出てきます(データベースの基礎など)。

この用語の分野: データベースの基礎

ビューの練習問題に挑戦

関係データベースのビューの説明として、正しいものはどれか。

  1. ASELECT文で定義した仮想的な表で、ふつうは自分ではデータを持たず、参照するたびに元の表から結果を作る
  2. B元の表のデータを複製して保存する表で、元の表を変更してもビューの内容は変わらない
  3. C表の特定の列の値を速く探すために作る、木構造のデータである
答えと解説を見る

正解：A. SELECT文で定義した仮想的な表で、ふつうは自分ではデータを持たず、参照するたびに元の表から結果を作る

ビューは、CREATE VIEW 営業部員 AS SELECT 社員番号, 氏名 FROM 社員 WHERE 部署 = '営業' のように、SELECT文に名前を付けて定義する仮想的な表(仮想表)です。ふつうのビューは自分ではデータを持たず、ビューを参照するたびに元の表(基底表)から結果が作られるので、元の表を更新するとビューの内容にもそのまま反映されます。よく使う複雑な問い合わせを簡単に書けるようにしたり、見せてよい列や行だけをビューにして利用者に権限を与え、アクセスできる範囲を絞ったりするのに使います。一方、結果をあらかじめ計算して保存しておくマテリアライズドビューもあり、読み出しは速くなりますが、元の表に合わせて内容を更新する必要があります。値を速く探すための木構造は、インデックスの説明です。

解説の中の「ビュー」

  • ビューは、CREATE VIEW 営業部員 AS SELECT 社員番号, 氏名 FROM 社員 WHERE 部署 = '営業' のように、SELECT文に名前を付けて定義する仮想的な表(仮想表)です。

    関係データベースのビューの説明として、正しいものはどれか。

  • DDL(Data Definition Language)は、表やビュー、インデックスといったデータベースの構造を定義する文で、CREATE、ALTER、DROPがあります。
