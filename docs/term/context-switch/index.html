コンテキストスイッチとは

こんてきすとすいっち

CPUで実行するプロセスやスレッドを切り替えること。レジスタやプログラムカウンタなどの状態を保存・復元し、プロセスの切り替えではアドレス空間も切り替える。

「コンテキストスイッチ」は、2分野の5問の練習問題に出てきます(OSとハードウェア, マルチコアと同期など)。

この用語の分野: OSとハードウェア

コンテキストスイッチの練習問題に挑戦

コンテキストスイッチで、切り替える前のプロセスについて保存しておく必要があるものはどれか。

  1. Aそのプロセスが使っているディスクのファイルの中身
  2. Bレジスタの値やプログラムカウンタなど、CPUの実行の状態
  3. Cそのプロセスの物理メモリの全内容
答えと解説を見る

正解：B. レジスタの値やプログラムカウンタなど、CPUの実行の状態

コンテキストスイッチでは、あとで同じ状態から再開できるように、汎用レジスタ、プログラムカウンタ、スタックポインタ、動作モードなどのCPUの状態を保存し、次に動かすプロセスの状態を読み込みます。プロセスを切り替える場合は、ページテーブルの場所を示すレジスタも切り替えます。メモリやファイルの中身はそのまま残っているので、切り替えのたびに保存する必要はありません。

プロセスのコンテキストスイッチが、レジスタの保存と復元にかかる時間よりも、実際には大きな性能の低下を招くことがある主な理由はどれか。

  1. A切り替えのたびに、CPUのクロック周波数が下がるから
  2. B切り替えのたびに、プログラムをディスクから読み直すから
  3. C切り替え後、キャッシュやTLBのミスが増えるから
答えと解説を見る

正解：C. 切り替え後、キャッシュやTLBのミスが増えるから

レジスタの保存と復元そのものは短時間で済みますが、切り替えたあとのプロセスにとって、キャッシュやTLBの中身は前のプロセスのもので、必要なデータや変換結果を読み込み直すまでミスが続きます。ASIDのないCPUでは、アドレス空間を切り替えるときにTLBを空にする必要もあります。この間接的なコストが、直接の切り替え時間より大きくなることがあります。クロックが下がったり、プログラムをディスクから読み直したりはしません。

解説の中の「コンテキストスイッチ」

  • コンテキストスイッチでは、あとで同じ状態から再開できるように、汎用レジスタ、プログラムカウンタ、スタックポインタ、動作モードなどのCPUの状態を保存し、次に動かすプロセスの状態を読み込みます。

    コンテキストスイッチで、切り替える前のプロセスについて保存しておく必要があるものはどれか。

  • コンテキストスイッチは実行するプロセスを切り替えること、デマンドページングはページを必要になったときに読み込む方式です。

    アプリケーションがファイルの読み書きなどをOSに依頼するしくみを何と呼ぶか。

  • 割り込みが起きるとCPUは必ずカーネルの割り込みハンドラに移るので、プログラムが無限ループしていても、OSは制御を取り戻して別のプロセスにコンテキストスイッチできます。

    OSが、自分からCPUを手放さないプログラムからでも一定時間ごとにCPUを取り戻して、ほかのプロセスに切り替えられるの…

  • 待つ間にCPUをむだにしないので長い待ちに向きますが、眠る・起きる処理とコンテキストスイッチに数マイクロ秒ほどかかります。

    ミューテックス(眠って待つロック)とスピンロックを比べた説明として正しいものはどれか。

「コンテキストスイッチ」が出てくる問題(5問)

  1. コンテキストスイッチで、切り替える前のプロセスについて保存しておく必要があるものはどれか。
  2. プロセスのコンテキストスイッチが、レジスタの保存と復元にかかる時間よりも、実際には大きな性能の低下を招くことがある主な理由はどれか。
  3. アプリケーションがファイルの読み書きなどをOSに依頼するしくみを何と呼ぶか。
  4. OSが、自分からCPUを手放さないプログラムからでも一定時間ごとにCPUを取り戻して、ほかのプロセスに切り替えられるのは、主にどのしくみによるか。
  5. ミューテックス(眠って待つロック)とスピンロックを比べた説明として正しいものはどれか。
