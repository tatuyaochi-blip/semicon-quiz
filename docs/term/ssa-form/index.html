SSA形式とは

えすえすえーけいしき

各変数への代入がプログラム中でちょうど1回になるよう名前を付け替えた中間表現の形式。合流点ではφ関数で値を選ぶ。定義と使用の関係が明確になり、最適化がしやすい。

「SSA形式」は、1分野の2問の練習問題に出てきます(コンパイラなど)。

この用語の分野: コンパイラ

名前の付け替えで定義を1つにする

SSA(静的単一代入)形式では、すべての代入に専用の変数名を与えます。分岐のない直線的なコードでは、これは単なる名前の付け替えです。x = 1; x = x + 2 は x1 = 1; x2 = x1 + 2 になり、後の各使用はそこに届く版を参照します。「静的」という言葉が重要で、ループの中で何度も実行される代入であっても、各名前への代入はプログラムのテキスト上でちょうど1か所です。どの使用にも定義がちょうど1つあるため、最適化に必要な定義と使用の関係を別の解析で求めなくても、名前そのものに明示されます。

合流点に置くφ関数

制御の流れが合流する場所では、名前の付け替えだけではうまくいきません。if-elseの後のxの値は、どちらの分岐を通ったかで決まるからです。SSAでは合流ブロックの先頭にφ(ファイ)関数 x3 = φ(x1, x2) を置きます。引数は入ってくる辺ごとに1つあり、実際に通った辺に対応する引数が値になります。ループでもループヘッダで同じものが必要で、初期値と前回の繰り返しの値を合流させます。標準的な構築アルゴリズムは制御フローグラフの支配関係の情報を使い、異なる経路からの定義が実際に出会う場所にだけφ関数を配置します。

最適化でSSAが好まれる理由

名前ごとに定義が1つしかないため、多くの最適化が単純かつ高速になります。定数伝播は各定義からその使用をたどるだけで済み、デッドコード削除は使用のない定義を取り除き、大域値番号付けは同じ名前の値に対する演算を比べて冗長な計算を見つけます。解析も、すべてのプログラム地点を繰り返し調べる代わりに定義と使用の辺に沿って進む疎な解析にできます。こうした理由から、LLVM IRをはじめ多くの実用コンパイラのIRはSSA形式です。通常SSAになっているのは仮想レジスタに置くスカラー値で、メモリは明示的なロードとストアでアクセスします。

SSAから抜ける

プロセッサにはφ命令がないため、コンパイラはレジスタ割り付けの前か途中でSSA形式から元に戻します。各φは先行ブロックの末尾に置くコピー命令に置き換えられ、どの経路から来ても選ばれた値が共通の場所に書き込まれるようにします。複数の後続を持つブロックから出て複数の先行を持つブロックに入る辺では、コピーを置く場所を作るために辺の分割が必要になることがあります。その後のレジスタ割り付けでは、コピーの両側に同じレジスタを割り当てる合併(コアレッシング)を試み、ほとんどのコピーを消します。

SSA形式の練習問題に挑戦

SSA形式の中間表現の特徴として正しいものはどれか。

  1. A各変数への代入がプログラム中でちょうど1回になる
  2. Bすべての変数が、レジスタではなくメモリ上に置かれる
  3. C条件分岐の命令を一切含まない形に書き直される
答えと解説を見る

正解：A. 各変数への代入がプログラム中でちょうど1回になる

SSA形式では、変数への代入が1回になるよう名前を付け替え、合流点ではφ関数で値を選びます。例えば x を2回代入するなら x1 と x2 に分け、どちらが使われているかを明確にします。定義と使用の関係がはっきりするため、定数伝播や不要コードの削除などの最適化がしやすくなります。分岐はφ関数で扱うので、分岐命令がなくなるわけではありません。変数がメモリに置かれる形でもなく、多くはレジスタの候補として扱われます。

よくある質問

コンパイラのSSAとは何の略ですか?

Static Single Assignment(静的単一代入)の略です。IRの各変数はプログラムのテキスト上でちょうど1か所で代入され、制御フローの経路が合流する場所ではφ関数が値を合流させます。

1回しか代入できないのに、SSAでループをどう表すのですか?

単一代入は静的なもので、動的なものではありません。ループヘッダのφ関数が、ループに入るときの値と前回の繰り返しで計算された値を合流させ、その1つの定義が毎回の繰り返しで実行されます。

φ関数はどこに置かれますか?

同じ元の変数の異なる定義が、異なる入力辺から届きうるブロックの先頭に置かれます。支配辺境(dominance frontier)に基づくアルゴリズムを使えば、不要なφを挿入せずにその位置を求められます。
