リターンアドレスとは

りたーんあどれす

関数の処理を終えたときに戻る番地。RISC-Vではjal命令が次の命令の番地をra(x1)に入れ、x86ではcall命令がスタックに積む。

「リターンアドレス」は、6分野の12問の練習問題に出てきます(命令セット・アセンブリ, CPU・アーキテクチャ, C言語の基礎など)。

この用語の分野: 命令セット・アセンブリ

関数呼び出しでの保存方法

関数呼び出しでは、実行を再開する場所、つまり呼び出し命令の次の命令のアドレスを記録しておく必要があります。RISC-Vでは、jal(jump and link)がPC + 4をレジスタ(慣例ではra、すなわちx1)に書き込んでジャンプし、戻るときはjalr x0, 0(ra)の疑似命令であるretを使います。関数ポインタ、仮想関数、共有ライブラリのスタブを経由する呼び出しでは、飛び先をレジスタで指定するjalrを使います。x86では、callがリターンアドレスをスタックにプッシュし、retがそれをポップして命令ポインタに戻すため、リターンアドレスは常にスタック上にあります。

リーフ関数と非リーフ関数

jalを実行するたびにraは上書きされるため、RISC-Vで他の関数を呼び出す関数は、先に自分のリターンアドレスを退避しておく必要があります。典型的なプロローグでは、addi sp, sp, -16で下位アドレスへ伸びるスタックにフレームを確保し、sw ra, 12(sp)とsw s0, 8(sp)でraと呼び出し先保存レジスタを退避します。エピローグではこれらを読み戻してspを元に戻し、retを実行します。何も呼び出さないリーフ関数はraをレジスタに置いたままでよく、スタックフレームがまったく要らない場合もあるため、小さな関数を低コストで実行できます。

攻撃の標的になる理由

スタック上のリターンアドレスはローカルのバッファのすぐ隣にあるため、バッファオーバーフローで上書きされると、関数から戻るときに実行先を乗っ取られてしまいます。古典的な攻撃はスタックに機械語を書き込んでそこへジャンプさせるものでしたが、ページテーブルの実行禁止ビットを使ったW^Xポリシーで防がれるようになりました。そこで攻撃者は、既存のコード断片をつなぎ合わせるリターン指向プログラミング(ROP)に移りました。さらなる対策として、戻る前に検査するスタックカナリア、アドレス空間配置のランダム化(ASLR)、各リターンアドレスの保護された複製を持つハードウェアのシャドウスタックがあります。

ハードウェアでの扱い

アウトオブオーダ実行のCPUは、raやスタックを読み出すよりずっと前にリターンの飛び先を予測します。分岐予測器のリターンアドレススタック(RAS)は、呼び出しのたびに次の命令のアドレスをプッシュし、リターンのたびにポップするので、きれいに入れ子になったコードでは非常に正確に予測できます。例外や割り込みは扱いが異なり、CPUは中断したPCをRISC-Vのmepcやsepcのような専用レジスタに、直前の特権モードとともに保存します。復帰には通常のretではなくmretやsretを使い、これらをまとめて元に戻します。

リターンアドレスの練習問題に挑戦

プログラムでサブルーチン(関数)を呼び出すとき、戻り先のアドレスなどを一時的に保存するために一般的に使われる領域はどれか。

  1. Aスタック
  2. Bキャッシュのタグ
  3. CROMの固定領域
答えと解説を見る

正解：A. スタック

サブルーチンを呼び出すと、戻り先のアドレス、保存すべきレジスタの値、局所変数などがスタックに積まれます。スタックは後から入れたものを先に取り出す(LIFO)構造で、呼び出しが入れ子や再帰になっても正しい順で戻れます。先頭位置はスタックポインタが示します。再帰が深すぎて領域を使い果たすとスタックオーバーフローになり、配列のはみ出しで戻り先を書き換える攻撃もあります。

よくある質問

RISC-Vではリターンアドレスはどこに保存されますか?

呼び出し時にjalまたはjalrが書き込むレジスタra(x1)に保存されます。非リーフ関数は、自分が他の関数を呼ぶ前にそれをスタックフレームに退避し、retの前に復元します。

x86のcall/retとRISC-Vのjal/retの違いは?

x86のcallは必ずリターンアドレスをスタックにプッシュし、retがそれをポップします。RISC-Vのjalはリターンアドレスをレジスタに入れ、関数が退避すると決めた場合にだけメモリに書き込みます。

リターンアドレスが上書きされると何が危険なのですか?

関数が戻るとき、CPUはそこに書かれたアドレスへジャンプします。そのため攻撃者がバッファオーバーフローでリターンアドレスを書き換えると、プログラムの制御を奪えてしまいます。
