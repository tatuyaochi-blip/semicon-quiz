バッチサイズとは

ばっちさいず

まとめて処理する入力の数。大きくすると重みを再利用できて効率が上がるが、応答の遅れとメモリが増える。

「バッチサイズ」は、1分野の2問の練習問題に出てきます(AIハードウェアとソフトウェアスタックなど)。

この用語の分野: AIハードウェアとソフトウェアスタック

バッチサイズの練習問題に挑戦

推論でバッチサイズ(まとめて処理する入力の数)を大きくすると、処理全体の効率が上がりやすい理由はどれか。

  1. A入力が多いほど、1つの入力の計算の回数が減るから
  2. Bバッチを大きくすると、重みの数が減るから
  3. C一度読み込んだ重みを複数の入力の計算に使えるので演算強度が上がり、演算器を有効に使えるから
答えと解説を見る

正解：C. 一度読み込んだ重みを複数の入力の計算に使えるので演算強度が上がり、演算器を有効に使えるから

バッチサイズがBなら、重みの行列とB個のベクトルの積は、重みの行列と幅Bの行列の積になります。重みの読み込みは同じなのに演算はB倍になるので、演算強度もおよそB倍になり、メモリ律速から演算律速に近づきます。サーバでの推論では、多くの利用者の要求をまとめて処理することで、GPUを効率よく使っています。

推論でバッチサイズを大きくしすぎたときの欠点として正しいものはどれか。

  1. Aまとめる入力がそろうのを待つ時間や1回の処理の時間が増えて、1つの要求の応答が遅くなり、メモリも多く使う
  2. B重みの値が変わって、答えが不正確になる
  3. C演算強度が下がって、効率が悪くなる
答えと解説を見る

正解：A. まとめる入力がそろうのを待つ時間や1回の処理の時間が増えて、1つの要求の応答が遅くなり、メモリも多く使う

バッチを大きくすると全体の処理量(スループット)は上がりますが、ほかの入力が集まるまで待ったり、まとめた分だけ1回の計算が長くなったりするので、1つの要求が返るまでの時間(レイテンシ)は長くなります。途中の結果やKVキャッシュのメモリもバッチに比例して増えます。対話のアプリケーションでは、応答の速さの目標を守れる範囲でバッチを大きくします。

解説の中の「バッチサイズ」

  • バッチサイズがBなら、重みの行列とB個のベクトルの積は、重みの行列と幅Bの行列の積になります。
