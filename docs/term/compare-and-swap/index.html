コンペア・アンド・スワップとは

こんぺあ・あんど・すわっぷ

メモリの値が期待した値と等しいときだけ新しい値を書き込むアトミック命令。CASとも書く。失敗したら読み直してやり直すループで、ロックなしの更新ができる。

「コンペア・アンド・スワップ」は、1分野の2問の練習問題に出てきます(マルチコアと同期など)。

この用語の分野: マルチコアと同期

CASが保証すること

CAS(コンペア・アンド・スワップ)は、アドレス、期待値、新しい値の3つを受け取ります。分割できない1つの操作の中で、その場所を読み、期待値と比較し、一致した場合にだけ新しい値を書き込みます。結果は成功か失敗かで返し、多くの場合は見つけた値を返すことで知らせます。x86では lock cmpxchg 命令がこれにあたります。C11では atomic_compare_exchange_strong と _weak として、C++では std::atomic の compare_exchange_strong と compare_exchange_weak として提供されています。ハードウェアでは、コアがキャッシュラインを排他状態で取得するので、操作の間ほかのコアはそこに書き込めません。

再試行ループ

ロックフリーの更新では、現在の値を読み、そこから新しい値を計算し、読んだ値を期待値としてCASを試みます。その間にほかのスレッドがその場所を変更していればCASは失敗し、ループで読み直してやり直します。どれかのスレッドは必ず成功するので、システム全体としてはロックなしで処理が進みます。このようなコードはロックフリーですがウェイトフリーではなく、運の悪いスレッドは際限なく再試行を繰り返す可能性があります。競合が激しいと、再試行の多さとコア間でのキャッシュラインの行き来によって、CASループのほうが単純なロックより遅くなることもあります。

ABA問題

CASが確かめるのは値が等しいことだけで、一度も変更されなかったことではありません。あるスレッドが値を読んでからCASを実行するまでの間に、値がAからBに変わって再びAに戻ると、データ構造が変わっている可能性があってもCASは成功します。典型例はロックフリーのスタックで、あるスレッドのpopが終わる前に、ノードがpopされて解放され、同じアドレスに再び割り当てられる場合です。一般的な対策は、変更のたびに更新するバージョンカウンタをポインタと組にすることと、ハザードポインタやエポックベースの回収といった安全なメモリ回収の仕組みを使うことです。

CASとLL/SC、フェッチ・アンド・アッドの比較

RISC系の多くのアーキテクチャは、CASの代わりにロードリンク/ストアコンディショナル(LL/SC)を備えています。RISC-Vでは lr がアドレスを予約し、sc はそれ以降そのアドレスにほかの書き込みがなかった場合にだけ書き込み、あれば失敗します。値を比べるのではなく途中の書き込みをすべて検出するので、原理的にはABA問題を避けられますが、無関係な理由で予約が失われることがあります。compare_exchange_weak が見かけ上の失敗を許されているのはこのためです。カウンタのような単純な操作には、再試行が不要なアトミックなフェッチ・アンド・アッドや、amoadd などのRISC-VのAMO命令のほうがCASループより適しています。

コンペア・アンド・スワップの練習問題に挑戦

アトミック命令CAS(コンペア・アンド・スワップ)の動作として正しいものはどれか。

  1. Aメモリの値が期待した値と等しいときだけ新しい値を書き込み、成功したかどうかが分かる
  2. B2つのメモリの値を比べて、大きい方を両方に書き込む
  3. Cメモリの値とレジスタの値を、条件なしに入れ替える
答えと解説を見る

正解：A. メモリの値が期待した値と等しいときだけ新しい値を書き込み、成功したかどうかが分かる

CASは「この番地の値がまだ期待値のままなら新しい値に変える」を不可分に行います。読んでから書くまでの間にほかのスレッドが値を変えていれば失敗するので、変えられていないことを確かめながら更新できます。失敗したらもう一度読み直して計算し、CASをやり直すループにすれば、ロックを使わずに共有の値を安全に更新できます。x86のcmpxchg命令などがこれに当たります。

よくある質問

コンペア・アンド・スワップのABA問題とは何ですか?

途中で値が別の値に変わって再び戻ったにもかかわらず、その場所が期待値を保持しているためにCASが成功してしまう問題です。メモリを再利用するロックフリーのデータ構造を壊すことがあり、通常はバージョンカウンタや安全なメモリ回収で防ぎます。

CASループはロックフリーですか、ウェイトフリーですか?

ロックフリーです。weak形式の見かけ上の失敗を除けば、CASが失敗するのはほかのスレッドの更新が成功したときだけなので、システム全体は前進します。ただし、個々のスレッドが何回再試行するかには上限がありません。

compare_exchange_weak と compare_exchange_strong の違いは何ですか?

weak形式は値が一致していても失敗することがある代わりに、LL/SC命令に直接対応させられるので、再試行ループに向いています。strong形式は値が実際に一致しない場合にだけ失敗しますが、LL/SCのマシンでは内部にループが必要になります。
