符号拡張とは

ふごうかくちょう

少ないビット数の符号付き整数を多いビット数に広げるとき、最上位ビット(符号)を上の桁すべてにコピーすること。値を変えずに広げられる。上位を0で埋めるのはゼロ拡張。

「符号拡張」は、1分野の5問の練習問題に出てきます(命令セット・アセンブリなど)。

この用語の分野: 命令セット・アセンブリ

符号ビットをコピーしても値が変わらない理由

n ビットの2の補数表現では、最上位ビットの重みは −2^(n−1) で、ほかのビットは通常の正の重みを持ちます。負の数を1ビット拡張すると、重み −2^n の新しい最上位ビットが加わり、それまでの最上位ビットの重みは正の 2^(n−1) に変わります。両者を合わせた寄与は −2^(n−1) のままなので、値は変わりません。追加するビットごとにこれを繰り返せば、規則が正しいことがわかります。たとえば4ビットの 1010(−6)は8ビットの 11111010 になり、値は −6 のままです。

命令セットで符号拡張が行われる場所

最もよくあるのは即値です。RISC-Vの12ビットのI形式即値は符号拡張されるので、addi は −2048 から 2047 までを受け付け、負の定数も別の減算命令なしで扱えます。ロード命令は対になっていて、lb と lh は符号拡張、lbu と lhu はゼロ拡張を行います。RV64では lw が32ビットの値を64ビットに符号拡張し、lwu はゼロ拡張します。また、addw などのワード命令は32ビットの結果を符号拡張します。x86には同じ目的の movsx と movzx があります。ハードウェアでは、符号拡張は最上位ビットを新しいすべての桁に配線するだけで、追加のコストはかかりません。

典型的な落とし穴:lui と addi

32ビットの定数を作るとき、RISC-Vのコードでは上位20ビットに lui を、下位12ビットに addi を使います。addi は即値を符号拡張するので、下位部分が 0x800 以上だと負の数、つまり元の値から4096を引いた値として扱われます。アセンブラは定数のビット11が1のときに上位部分に1を足して補正しており、%hi と %lo の再配置演算子はこれを自動で行います。定数を単純に分割する手書きのコードでは、値がちょうど4096ずれてしまいます。これはテストで見逃しやすいバグです。

C言語での符号拡張とゼロ拡張

C言語では、拡張の方法は変換元の型で決まります。signed char や int16_t を int に変換すると符号拡張され、符号なしの型を変換するとゼロ拡張されます。修飾なしの char はプラットフォームによって符号付きにも符号なしにもなり、たとえばx86では符号付きですが、Armの多くのLinuxシステムでは符号なしです。そのため、0xFF というバイト値はターゲットによって −1 にも 255 にもなります。この違いは、バイトを定数と比較したり配列の添字に使ったりするときにバグの原因になります。生のバイトには unsigned char や uint8_t を使えば、この曖昧さを避けられます。

符号拡張の練習問題に挑戦

RISC-Vのaddi命令の即値は12ビットの符号付き整数である。この即値で表せる範囲はどれか。

  1. A0〜4095
  2. B-2048〜2047
  3. C-4096〜4095
答えと解説を見る

正解：B. -2048〜2047

12ビットの2の補数で表せるのは、-2の11乗=-2048から2の11乗-1=2047までです。即値は計算の前に32ビット(RV64では64ビット)に符号拡張されるので、負の数もそのまま足せます。この範囲を超える定数を使うには、上位20ビットをlui命令で設定してからaddiで下位12ビットを足すなど、複数の命令を組み合わせます。

RISC-Vで定数0x12345FFFをluiとaddiの2命令で作るとき、正しい組み合わせはどれか。

  1. Alui t0, 0x12346 の後に addi t0, t0, -1
  2. Blui t0, 0x12345 の後に addi t0, t0, 0xFFF
  3. Clui t0, 0x12345 の後に addi t0, t0, -1
答えと解説を見る

正解：A. lui t0, 0x12346 の後に addi t0, t0, -1

addiの即値は符号拡張されるので、下位12ビットが0xFFF(最上位ビットが1)のときは-1として足されます。そこでluiで作る上位を1つ大きい0x12346にしておき、0x12346000に-1を足して0x12345FFFを得ます。下位12ビットのビット11が1のときは上位に1を足しておく、というこの補正は、アセンブラやリンカが自動で行います。

よくある質問

符号拡張とゼロ拡張の違いは何ですか?

符号拡張は新しく増えた上位ビットを元の最上位ビットのコピーで埋め、符号付きの数の値を保ちます。ゼロ拡張は上位ビットを0で埋め、符号なしの数の値を保ちます。

RISC-Vの addi が即値を符号拡張するのはなぜですか?

addi sp, sp, -16 のように、1命令で負の定数を加算できるようにするためです。これにより12ビットのフィールドで、0以上の値だけでなく −2048 から 2047 までを表せます。

C言語で値を符号拡張するにはどうしますか?

int8_t や int16_t など元の幅の符号付き型に値を格納し、それをより幅の広い符号付き型に代入します。この変換で自動的に符号拡張が行われ、コンパイラは対応する符号拡張命令を生成します。

  • 即値は計算の前に32ビット(RV64では64ビット)に符号拡張されるので、負の数もそのまま足せます。

  • addiはこれを32ビットに符号拡張する、つまり最上位ビットの1を上の桁すべてにコピーするので0xFFFFFFFFになり、2の補数で-1を表します。

  • lb(load byte)は読み込んだ1バイトを符号付きとみなし、最上位ビットを上位24ビットにコピーします(符号拡張)。
