メモリ一貫性モデルとは

めもりいっかんせいもでる

あるコアが行った複数の番地への読み書きが、ほかのコアからどの順番で見えうるかを定めた約束。逐次一貫性、x86のTSO、ARMやRISC-Vの弱いモデルなどがある。

「メモリ一貫性モデル」は、1分野の5問の練習問題に出てきます(マルチコアと同期など)。

この用語の分野: マルチコアと同期

ハードウェアがメモリ操作の順序を入れ替える理由

現代のコアは、ロードとストアをプログラムの順番どおりに厳密に実行するわけではありません。ストアはストアバッファにいったん置かれ、その間にコアは先へ進むことがよくあります。ロードは、キャッシュのレイテンシを隠すために早めに、あるいは順序を変えて発行されることがあります。コアは自分の未完了の書き込みを常に転送し、自分の結果を守るので、こうした最適化は1つのスレッドの中からは見えません。しかし、ほかのコアからは同じ操作が違う順番で見えることがあります。メモリ一貫性モデルは、こうした入れ替えのうちどれが見えうるかを正確に定めた約束で、これによりプログラマやコンパイラはいつ同期が必要かを判断できます。

逐次一貫性、TSO、弱いモデル

逐次一貫性(SC)は最も厳しいモデルで、すべての操作が、各コアのプログラム順序を守った1つの全体的な順序で起きたように見えます。x86はトータルストアオーダー(TSO)を採用しており、これもほぼ同じくらい強いモデルです。見える入れ替えは、後のロードが別のアドレスへの先のストアより先に完了することだけで、これはまさにFIFOのストアバッファから生じる現象です。ArmとRISC-Vは弱いモデルを採用しており、異なるアドレスへのロードとストアは、ほとんどの組み合わせで入れ替わりえます。そのため順序が必要な場合は、フェンスやバリア命令、またはアクワイア・リリース操作で明示的に指定しなければなりません。

代表例:ストアバッファのテスト

xとyの初期値を0とし、コア0がx = 1を実行してからyを読み、コア1がy = 1を実行してからxを読むとします。逐次一貫性のもとでは、少なくとも一方のコアは1を読みます。TSOのもとでは、相手のロードが実行された時点で各ストアがまだ自分のコアのストアバッファにあることがあるため、両方が0を読むことがありえます。DekkerやPetersonのロックアルゴリズムは、ストアとロードの間に完全なフェンスを入れない限り、まさにこの形で破綻します。弱いモデルでは、フラグを使ったデータの受け渡しでさえ、バリアでアクセスの順序を決めないと失敗することがあります。

一貫性とキャッシュコヒーレンスの違い

キャッシュコヒーレンスは1つのアドレスについての保証で、すべてのコアがその場所への書き込みの順序について合意し、やがて最新の値を読めることを保証します。一貫性モデルは、xへの書き込みがその後のyへの書き込みより先に見えるかどうかといった、異なるアドレスにまたがる順序を扱います。コヒーレンスが完全に保たれていても、このような入れ替えは見えることがあり、そのためにコヒーレンスプロトコルとは別にバリアが存在します。高水準言語はC11やC++11のアトミックのように独自のモデルを定めており、コンパイラはそれを、ハードウェアのモデルが必要とするバリア命令に変換します。

メモリ一貫性モデルの練習問題に挑戦

メモリ一貫性モデル(メモリコンシステンシモデル)が定めているものはどれか。

  1. Aキャッシュのラインの大きさとセットの数
  2. B主記憶のDRAMに使うトランジスタの種類
  3. Cあるコアが行った複数の番地への読み書きが、ほかのコアからどの順番で見えうるか
答えと解説を見る

正解：C. あるコアが行った複数の番地への読み書きが、ほかのコアからどの順番で見えうるか

CPUは性能のために、書き込みをストアバッファにためたり、読み出しを先に行ったりして、メモリ操作の順番を入れ替えることがあります。1つのコアの中では結果が変わらないように作られていますが、ほかのコアからは順番が入れ替わって見えることがあります。メモリ一貫性モデルは、どの入れ替えが起こりうるかを定め、プログラマが正しい同期を書くための約束になります。

x86のメモリ一貫性モデル(TSO、トータルストアオーダー)の特徴として正しいものはどれか。

  1. A読み書きのあらゆる組み合わせの入れ替えを許す、最も弱いモデルである
  2. B入れ替えを一切許さない逐次一貫性そのものである
  3. C書き込みの後の別の番地からの読み出しが、その書き込みより先に見えることだけを許す、比較的強いモデルである
答えと解説を見る

正解：C. 書き込みの後の別の番地からの読み出しが、その書き込みより先に見えることだけを許す、比較的強いモデルである

TSOでは、書き込みどうしの順番、読み出しどうしの順番、読み出しの後の書き込みの順番は保たれ、書き込みの後の別の番地への読み出しだけが追い越せます。これはストアバッファがあることをそのまま表したモデルです。多くのプログラムはこの範囲なら直感どおりに動くので、x86ではバリアが必要な場面が比較的少なくなります。

よくある質問

キャッシュコヒーレンスとメモリ一貫性の違いは?

コヒーレンスは、1つのアドレスへの書き込みがすべてのコアから同じ順序で見え、やがて最新の値を読めることを保証します。一貫性は、異なるアドレスへのアクセスがほかのコアからどの順番で観測されうるかを定めます。

TSOとは何の略ですか?

total store order(トータルストアオーダー)の略で、x86プロセッサが採用しているメモリモデルです。ストアバッファの影響として、別のアドレスへの後のロードが先のストアより先に観測されることだけが許されます。

ArmやRISC-Vでx86より多くのメモリバリアが必要なのはなぜですか?

ArmとRISC-Vは、異なるアドレスへのロードとストアのほとんどの入れ替えを許す弱いメモリモデルを採用しているため、順序を明示的に指定する必要があるからです。x86のTSOはもともとほとんどの順序を守るので、バリアが必要なのは、ストアの後に別のアドレスへのロードが続く場合などに限られます。
