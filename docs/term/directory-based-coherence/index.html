ディレクトリ方式とは

でぃれくとりほうしき

各ラインをどのコアが持っているかを表に記録し、関係するコアにだけ通知するコヒーレンシの方式。コアの数が多いシステムで使われる。

「ディレクトリ方式」は、2分野の3問の練習問題に出てきます(マルチコアと同期, CPU・アーキテクチャなど)。

この用語の分野: マルチコアと同期

ディレクトリに記録される情報

メモリの各ラインには、通常はアドレスで決まるホームノードがあり、ホームがそのラインのディレクトリエントリを管理します。エントリには、キャッシュされていない、共有、排他といったコヒーレンシの状態と、どのキャッシュがコピーを持っているかの記録が入ります。最も単純な記録方法は、コアまたはキャッシュごとに1ビットを割り当てる完全なビットベクタです。エントリはメモリコントローラの近くや、共有のラストレベルキャッシュに置かれます。要求は全員ではなく1つのホームに送られるので、相互接続網はブロードキャスト型のバスではなく、1対1のリンクをつないだメッシュにできます。

書き込みの流れ

所有していないラインに書き込みたいコアは、そのラインのホームに要求を送ります。ホームはディレクトリを調べ、共有者として記録されているキャッシュにだけ無効化を送ります。それらのキャッシュはコピーを破棄し、ホームか要求元に直接、確認応答を返します。すべての確認応答がそろうと、要求元は排他的な所有権を得て、ディレクトリはそれを所有者として記録します。ほかのキャッシュがラインを変更済みの状態で持っていた場合は、ホームが要求をその所有者に転送し、所有者が要求元にデータを送ります。これがいわゆる3ホップのトランザクションです。

スヌープ方式とディレクトリ方式の比較

スヌープ方式はすべてのミスをすべてのキャッシュにブロードキャストします。余分な参照がないので遅延は小さいものの、トラフィックとスヌープ処理の量がコア数とともに増えるため、小規模なシステムに限られます。ディレクトリ方式ではホームでの参照の遅延が加わり、ホップが1回増えることもありますが、メッセージを必要な相手にだけ送るので、トラフィックはコア数ではなく実際の共有の度合いに応じて増えます。そのため大規模なマルチコアチップやマルチソケットのシステムでは、ディレクトリ方式か、ラインを持っている可能性のあるキャッシュを記録してほとんどのブロードキャストを省くスヌープフィルタのような混合方式が使われます。

ディレクトリ自体を小さく保つ工夫

コア数が増えると、メモリの全ラインに完全なビットベクタを持たせるのは記憶容量の負担が大きすぎるため、実用的な設計では節約の工夫をします。限定ポインタ方式は共有者のIDを数個だけ記録し、それより多くのキャッシュが共有したらブロードキャストに切り替えます。粗いベクタ方式はコアのグループごとに1ビットを使います。スパースディレクトリは実際にキャッシュされているラインだけを追跡し、それ自体がキャッシュのような構成をとります。スパースディレクトリはエントリが足りなくなると1つを追い出す必要があり、そのラインを持つすべてのキャッシュで無効化が起きるので、追跡するキャッシュに対して容量に十分な余裕を持たせます。

ディレクトリ方式の練習問題に挑戦

コアの数が多いシステムで、スヌーピング方式の代わりにディレクトリ方式のコヒーレンシが使われる理由として正しいものはどれか。

  1. A各ラインをどのコアが持っているかを記録しておき、関係するコアにだけ通知することで通信を減らせるから
  2. Bディレクトリ方式ではキャッシュが不要になるから
  3. Cディレクトリ方式では書き込みのたびにすべてのコアへ通知できるから
答えと解説を見る

正解：A. 各ラインをどのコアが持っているかを記録しておき、関係するコアにだけ通知することで通信を減らせるから

ディレクトリ方式では、各ラインについて、どのコアがコピーを持ち、どの状態かを記録した表(ディレクトリ)を持ちます。書き込みがあると、ディレクトリを見てコピーを持つコアにだけ無効化の要求を送ります。すべてのキャッシュへ一斉に知らせるスヌーピングに比べて通信が少ないので、コアが数十以上あるサーバ向けのCPUなどで使われます。

よくある質問

ディレクトリ方式がスヌープ方式よりスケールしやすいのはなぜですか?

すべてのキャッシュにブロードキャストする代わりに、実際にラインを持っているキャッシュにだけ無効化や要求を送るからです。そのため、トラフィックはコア数とともに増えるのではなく、実際の共有の度合いに応じたものになります。

ディレクトリ方式はスヌープ方式より遅いですか?

ホームのディレクトリを参照したり要求が転送されたりするため、ミス1回あたりの時間は長くなることがあります。しかし大規模なシステムでは、トラフィックと競合が減る効果のほうが、通常はその遅延の増加を上回ります。

スヌープフィルタとは何ですか?

各ラインをどのキャッシュが持っている可能性があるかを記録し、コヒーレンシ要求をそのキャッシュにだけ送るための仕組みです。スヌープ型の設計でブロードキャストのトラフィックを減らすために使う、実質的なディレクトリです。
