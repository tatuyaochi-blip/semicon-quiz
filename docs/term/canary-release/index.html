カナリアリリースとは

かなりありりーす

新しい版を、まず一部の利用者や要求(例えば5%)だけに出し、エラーの率や応答時間などの指標を見ながら、問題がなければ割合を段階的に増やすリリースの方法。不具合があっても影響を受けるのは一部の要求に限られ、すぐに元の版へ戻せる。名前は、炭鉱で有毒なガスを早く知るためにカナリアを連れて入ったことに由来する。新旧の版を比べるには十分な数の要求が必要で、指標の監視と自動の切り戻しを組み合わせることが多い。

「カナリアリリース」は、1分野の2問の練習問題に出てきます(クラウドとコンテナの基礎など)。

カナリアリリースの練習問題に挑戦

1時間に12,000件の要求を受けるサービスで、新しい版をカナリアリリースし、要求の5%だけを新しい版に送った。新しい版には、受けた要求の3%が失敗する不具合があり、1時間後に気づいて、すべての要求を元の版に戻した。この1時間に不具合で失敗した要求の件数として、正しいものはどれか。

  1. A18件
  2. B360件
  3. C600件
答えと解説を見る

正解：A. 18件

新しい版に送られた要求は 12,000 × 5% = 600件で、そのうち3%が失敗するので、600 × 3% = 18件です。すべての要求を一度に新しい版へ切り替えていれば、12,000 × 3% = 360件が失敗していました。カナリアリリースは、このように不具合の影響を受ける要求を一部に限り、エラーの率や応答時間などを見ながら、問題がなければ割合を増やしていく方法です。新しい版と古い版の指標を比べるには十分な数の要求が必要なので、送る割合と観察する時間を合わせて決めます。

「カナリアリリース」が出てくる問題(2問)

  1. 1時間に12,000件の要求を受けるサービスで、新しい版をカナリアリリースし、要求の5%だけを新しい版に送った。新しい版には、受けた要求の3%が失敗する不具合があり、1時間後に気づいて、すべての要求を元の版に戻した。この1時間に不具合で失敗した要求の件数として、正しいものはどれか。
  2. 本番と同じ構成の環境を2つ用意し、一方で現在の版を動かしたまま、もう一方に新しい版を入れて確かめてから、ロードバランサの向き先を一度に切り替える。問題があれば、向き先を戻してすぐに元の版に戻す。このリリースの方法はどれか。
