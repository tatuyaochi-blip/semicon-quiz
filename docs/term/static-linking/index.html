静的リンクとは

せいてきりんく

使うライブラリのコードを実行ファイルの中にコピーして結合する方式。実行環境にライブラリがなくても動くが、ファイルが大きくなり、ライブラリの修正は作り直さないと反映されない。

「静的リンク」は、1分野の2問の練習問題に出てきます(リンカ・ローダと実行形式など)。

この用語の分野: リンカ・ローダと実行形式

リンカが行う処理

静的リンクでは、リンカはプログラムのオブジェクトファイルと、コマンドラインで指定された静的ライブラリを読み込み、未定義シンボルの解決に必要なアーカイブのメンバを取り込んで、同じ種類のセクションをまとめます。すべてのコードを1つのテキストセクションに、初期値付きのデータをすべて1つのデータセクションに、といった具合です。その後、最終的なアドレスを割り当て、再配置エントリを使ってすべての参照を書き換え、1つの実行ファイルを書き出します。GCCでは -static オプションを付けると、C標準ライブラリを含むすべてのライブラリが静的リンクされます。ただし、それらの静的版がインストールされている必要があります。

静的リンクと動的リンクの比較

静的リンクされた実行ファイルは自己完結しています。起動時に探すものはなく、ダイナミックリンカによるシンボルの結び付けもなく、ライブラリコードへの呼び出しは直接呼び出しになります。代償はサイズと保守性です。各プログラムが使うライブラリルーチンのコピーをそれぞれ持つため、共有ライブラリのページのようにプロセス間でメモリを共有できず、ライブラリのセキュリティ修正も再リンクしない限りプログラムに反映されません。動的リンクではこれらの損得が逆になりますが、その代わり、プログラムを動かすすべてのマシンに互換性のあるバージョンのライブラリが必要になります。

自己完結性の限界

静的実行ファイルでも、CPUアーキテクチャやOSのシステムコールインタフェースには依存するので、別のOSでそのまま動かすことはできません。また、ライブラリの機能の中には、裏で動的ロードを前提にしているものがあります。たとえばGNU libcは、静的リンクしたプログラムで getaddrinfo などの関数を使うと、名前解決のために実行時に共有ライブラリが必要になると警告します。さらに静的リンクでは、dlopen 方式のプラグインも使いにくくなります。プラグインはダイナミックリンカを前提とした共有オブジェクトだからです。

使われている場面

マイコンのファームウェアは、実行時にライブラリを提供するローダもファイルシステムもないため、ほぼ必ず1つのイメージに静的リンクされます。サーバや最小構成のコンテナイメージでは、互換性のあるカーネルさえあればファイルを1つコピーするだけでどこでも動くので、静的実行ファイルが重宝されます。多くのディストリビューションでライブラリのバージョンを気にせず動かしたいコマンドラインツールにも静的リンクが使われます。共有ライブラリが見つからない、互換性がないといった問題を避けられる代わりに、ファイルが大きくなるのを受け入れるわけです。

静的リンクの練習問題に挑戦

静的リンクの説明として正しいものはどれか。

  1. A使うライブラリのコードを実行ファイルの中にコピーして結合する
  2. Bプログラムを実行するたびに、ライブラリを読み込んで結合する
  3. Cライブラリを使わずに、すべての処理を1つのソースファイルに書く
答えと解説を見る

正解：A. 使うライブラリのコードを実行ファイルの中にコピーして結合する

静的リンクでは、リンカが静的ライブラリ(Linuxでは.aファイル)から必要な関数を取り出して実行ファイルに組み込みます。実行環境にライブラリがなくても動き、起動時の結合の手間もありませんが、実行ファイルが大きくなり、同じライブラリを使うプログラムごとにコピーを持ちます。ライブラリに不具合の修正があっても、作り直さないと反映されません。

よくある質問

gccでCプログラムを静的リンクするにはどうしますか?

リンクのコマンドに -static を付けます。たとえば gcc -static main.c -o main です。成功させるには、Cライブラリを含め、関係するすべてのライブラリの静的版(.a)がインストールされている必要があります。

静的リンクした実行ファイルが大きくなるのはなぜですか?

システムにすでにある共有ライブラリを参照する代わりに、Cランタイムの一部を含め、使用するすべてのライブラリコードのコピーを持っているからです。シンボルのstripや、未使用セクションを取り除くガベージコレクション付きのリンクでサイズを減らせます。

静的リンクしたプログラムは速いですか?

共有ライブラリのロードや結び付けが不要で、呼び出しも間接参照を経由しないので、通常は起動が速くなります。長時間動くプログラムの多くでは、定常状態での速度の差は小さいです。
