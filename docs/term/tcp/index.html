TCPとは

てぃーしーぴー

Transmission Control Protocolの略。トランスポート層のコネクション型のプロトコル。3ウェイハンドシェイクで接続を確立し、シーケンス番号、確認応答(ACK)、再送によって、データを欠けや重複なく、送った順に届ける。フロー制御と輻輳制御で送る量も調整する。Webのアクセス(HTTP/1.1・HTTP/2)、メール、SSHなどが使う。

「TCP」は、3分野の21問の練習問題に出てきます(ネットワークの基礎, ネットワークの設計と運用, Web技術の基礎など)。

この用語の分野: ネットワークの基礎

確実に届けるしくみ

TCPは、送るデータの1バイトごとに通し番号(シーケンス番号)を付けます。受信側は「次はこの番号から送ってください」という確認応答(ACK)を返し、送信側は決められた時間内にACKが来なければ、そのデータを送り直します(再送タイムアウト)。同じ番号のACK(重複ACK)を3つ受け取ったときは、タイムアウトを待たずに再送します(高速再送)。受信側は、順序が入れ替わって届いたデータを並べ直し、重複を捨て、チェックサムで壊れたデータを見つけます。アプリケーションからは、区切りのないバイトの流れ(ストリーム)として見えます。

ウィンドウで送る量を決める

送信側は、ACKを待たずに送ってよい量(ウィンドウ)の分だけ、続けてデータを送ります。受信側が伝える空きバッファの大きさ(受信ウィンドウ)に合わせるのがフロー制御、ネットワークの混み具合に合わせて送信側が持つ輻輳ウィンドウを増減するのが輻輳制御で、実際には両方の小さい方まで送ります。1往復の時間(RTT)に送れるのはウィンドウ分なので、スループットはおよそウィンドウ÷RTTになります。例えばウィンドウ64 KB、RTT 100 msでは約5 Mbit/sが上限で、速い回線を生かすにはウィンドウスケールのオプションでウィンドウを大きくします。

ヘッダと接続の管理

TCPのヘッダは、オプションなしで20バイトです。送信元と宛先のポート番号、シーケンス番号、確認応答番号、SYN・ACK・FIN・RSTなどのフラグ、ウィンドウの大きさ、チェックサムが入ります。1つの接続は、送信元と宛先のIPアドレスとポート番号の4つの組で区別されます。接続は3ウェイハンドシェイクで始め、両方向がそれぞれFINを送って閉じます。1つのセグメントが失われると、後ろのデータが届いていてもアプリケーションに渡せず待たされる(ヘッドオブラインブロッキング)ため、HTTP/3ではUDPの上のQUICが使われます。

TCPの練習問題に挑戦

TCP/IPの4階層のモデルで、TCPとUDPが属する層はどれか。

  1. Aアプリケーション層
  2. Bインターネット層
  3. Cトランスポート層
答えと解説を見る

正解：C. トランスポート層

TCP/IPのモデルは、下からリンク層(ネットワークインターフェース層)、インターネット層、トランスポート層、アプリケーション層の4つの層で表されます。TCPとUDPはトランスポート層のプロトコルで、ポート番号を使って、端末の中のどのアプリケーション宛ての通信かを区別します。インターネット層のIPは、端末から端末までパケットを届けることを担います。HTTPやDNSはアプリケーション層のプロトコルです。OSI参照モデルと対応させると、トランスポート層は第4層、インターネット層は第3層にあたります。

TCPでコネクションを確立する3ウェイハンドシェイクで、やり取りされるパケットの順序として正しいものはどれか。

  1. ASYN → ACK → FIN
  2. BACK → SYN → SYN+ACK
  3. CSYN → SYN+ACK → ACK
答えと解説を見る

正解：C. SYN → SYN+ACK → ACK

3ウェイハンドシェイクでは、まずクライアントがSYNで接続を求め、自分が送るデータの最初の番号(初期シーケンス番号)を伝えます。サーバはSYN+ACKで、それを受け取ったことを確認(ACK)すると同時に、自分の初期シーケンス番号を伝えます。最後にクライアントがACKを返すと、両方向の通信の準備が整います。3回のやり取りで両方の向きの番号を確かめ合うことで、遅れて届いた古いパケットによる誤った接続などを防ぎます。このため、TCPではデータを送り始めるまでに少なくとも1往復の時間(RTT)がかかります。FINはコネクションを終了するときに使います。

よくある質問

TCPとUDPの違いは何ですか?

TCPはコネクションを確立し、確認応答と再送、順序の制御によってデータを確実に届けます。UDPは接続の手順も再送もなく、データグラムを送りっぱなしにするので、ヘッダが小さく遅れも少なくなります。確実さが必要なWebやファイルの転送にはTCP、少しの損失より遅れの少なさが大事な通話や、問い合わせが短いDNSにはUDPが使われます。

TCPの再送はいつ起きますか?

2つのきっかけがあります。1つは、送ってから再送タイムアウトの時間(RTTの測定から計算する)が過ぎてもACKが来ないとき、もう1つは、同じ確認応答番号のACKを3つ続けて受け取ったときで、後者を高速再送と呼びます。再送が続くと、タイムアウトの時間を倍々に延ばします。

TCPのスループットが回線の速度より低いのはなぜですか?

1往復の時間(RTT)に送れるのはウィンドウの大きさまでなので、遠くの相手ほど、ウィンドウが小さいほど、スループットが下がります。パケットの損失で輻輳制御がウィンドウを小さくしたときや、受信側のアプリケーションの読み出しが遅いときにも下がります。
