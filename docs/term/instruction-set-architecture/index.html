命令セットアーキテクチャ(ISA)とは

めいれいせっとあーきてくちゃ

プロセッサが実行できる命令やレジスタなど、ソフトウェアから見たプロセッサの仕様。x86、Arm、RISC-Vなど。

やさしい解説で読む: CPUとは? パソコンやスマホの中で何をしているのか

「命令セットアーキテクチャ(ISA)」は、4分野の12問の練習問題に出てきます(命令セット・アセンブリ, CPU・アーキテクチャ, 性能評価・プロファイリングなど)。

この用語の分野: CPU・アーキテクチャ

ISAが定めるもの

命令セットアーキテクチャ(ISA)は、ソフトウェアとプロセッサのハードウェアとの間の取り決めです。命令とそのビット表現(エンコーディング)、プログラムから見えるレジスタ、データ型とアドレッシングモード、メモリアクセスの順序付け、特権レベル、割り込みと例外の振る舞いを定義します。ISAが定義するものはすべてアーキテクチャ状態であり、機械語から観測でき、それを前提にプログラムを書けます。アセンブラはアセンブリ言語のニーモニックをほぼ1対1でこのエンコーディングに変換するため、ISAごとに独自のアセンブリ言語があります。

ISAとマイクロアーキテクチャの違い

マイクロアーキテクチャは、個々のプロセッサがISAをどう実装するかを指し、パイプラインの段数、キャッシュの容量、分岐予測器、1サイクルに発行する命令数などが含まれます。1つのISAを、小型の低消費電力コアでも大規模なアウトオブオーダーコアでも実装でき、同じ機械語を大きく異なる速度で実行します。性能方程式「実行時間 = 命令数 × 1命令あたりのサイクル数(CPI) × サイクル時間」では、命令数は主にISAとコンパイラ、CPIはマイクロアーキテクチャ、サイクル時間は回路とプロセス技術で決まります。Spectre系の攻撃はこの境界を突くもので、投機実行の誤りでアーキテクチャ状態は元に戻されても、キャッシュの内容は戻りません。

ハードウェアを左右する設計上の選択

ISAの細部はハードウェアに長く影響します。RISC-Vの基本命令は32ビット固定長(16ビット形式は圧縮命令のC拡張のみ)で命令の境界が明確ですが、x86の命令は1〜15バイトの可変長で、次の命令の開始位置を知るには一部をデコードする必要があり、多命令を同時に扱うデコーダが複雑になります。x86の分岐命令は先行する比較命令が設定したフラグを調べますが、RISC-Vは分岐命令の中で2つのレジスタを比較するため、追跡すべき暗黙のフラグ状態がありません。MIPSの分岐遅延スロットは、特定のパイプラインの癖を、そのパイプラインより長く使われるISAに組み込んでしまう危険を示した例です。

モジュール型・オープンなISA

RISC-Vはオープンなアーキテクチャで、誰でもライセンス料なしで仕様を実装できます。約40命令の小さな基本整数命令セット(RV32IまたはRV64I)に、オプションの拡張を組み合わせます。Mは乗除算、Aはアトミック命令、FとDは浮動小数点、Cは圧縮命令、Vはベクトルで、さらにカスタム命令も追加できます。拡張を省くと面積は減りますが速度が落ちます。たとえばM拡張がないと、コンパイラはC言語の乗算を、シフトと加算で掛け算を行うライブラリ関数の呼び出しに変換します。一方、Armとx86はプロプライエタリで、所有者がライセンス供与または自ら実装しています。

命令セットアーキテクチャ(ISA)の練習問題に挑戦

同じ命令セットアーキテクチャ(ISA)を採用した2つのCPUについて正しいものはどれか。

  1. A同じ回路構成で作られているので、性能も消費電力も同じになる
  2. B内部の回路構成が違っても、同じ機械語のプログラムを実行できる
  3. C同じ半導体工場で、同じ製造プロセスを使って作る必要がある
答えと解説を見る

正解：B. 内部の回路構成が違っても、同じ機械語のプログラムを実行できる

ISAは、命令の種類、命令のビットの並び、レジスタの数などを定めたソフトウェアとハードウェアの約束です。パイプラインの段数やキャッシュの大きさ、分岐予測の方式といった内部の作りはマイクロアーキテクチャと呼ばれ、ISAとは別に決められます。そのため同じISAでも、小さな省電力コアと大きな高性能コアがあり、性能も電力も違いますが、同じ機械語のプログラムが動きます。製造工場やプロセスもISAとは関係ありません。

よくある質問

ISAとマイクロアーキテクチャの違いは?

ISAはソフトウェアから見える仕様で、命令やレジスタ、動作を定めます。マイクロアーキテクチャはその仕様を実装する具体的なハードウェア設計なので、マイクロアーキテクチャが異なるプロセッサでも、ISAが同じなら同じプログラムを実行できます。

x86、Arm、RISC-Vは命令セットアーキテクチャですか?

はい。3つは別々のISAなので、どれか1つ向けにコンパイルした機械語は、ほかのISAでは直接実行できません。それぞれのISAは多くの異なるプロセッサ設計で実装されています。

ISAとABIの違いは何ですか?

ISAはプロセッサが実行するものを定め、ABIはその上に成り立つソフトウェアの取り決めで、関数の呼び出し規約、データ型のサイズ、システムコールなどを定めます。1つのISAに、たとえばOSごとに複数のABIが存在することがあります。

「命令セットアーキテクチャ(ISA)」が出てくる問題(12問)

  1. 同じ命令セットアーキテクチャ(ISA)を採用した2つのCPUについて正しいものはどれか。
  2. ARM、x86、RISC-Vといった名前が主に表しているものはどれか。
  3. RISC-Vの特徴として正しいものはどれか。
  4. アセンブリ言語と機械語の関係として正しいものはどれか。
  5. RISC-Vで、12ビットの即値に収まらない32ビットの定数(例: 0x12345678)をレジスタに入れる一般的な方法はどれか。
  6. RISC-Vの関数の先頭で「addi sp, sp, -16」を実行する目的として正しいものはどれか。
  7. RISC-VのM拡張が基本の整数命令セットに追加する命令はどれか。
  8. M拡張のないRV32IのCPU向けに、C言語の「a * b」(int同士の掛け算)をコンパイルすると、一般にどうなるか。
  9. 昔のMIPSなどにあった分岐遅延スロット(分岐命令の直後の1命令は、分岐するかどうかに関係なく実行される決まり)について正しいものはどれか。
  10. ABI(アプリケーションバイナリインターフェース)の説明として正しいものはどれか。
  11. プログラムのCPUでの実行時間を表す基本の式として正しいものはどれか。
  12. 投機的に実行された命令の結果が取り消されても、Spectreのような攻撃で情報が漏れる理由として正しいものはどれか。
