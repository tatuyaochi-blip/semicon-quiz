フォールスパスとは

ふぉーるすぱす

回路上はつながっているが、実際の動作では信号が伝わらない経路。STAの解析の対象から外すタイミング例外で、SDCではset_false_pathで指定する。

「フォールスパス」は、1分野の2問の練習問題に出てきます(タイミング解析とCDCなど)。

この用語の分野: タイミング解析とCDC

フォールスパスの練習問題に挑戦

フォールスパス(set_false_path)を設定するのが適切な経路はどれか。

  1. A回路の構造上はつながっているが、選択条件が両立しないなどの理由で、実際には信号が伝わることのない経路
  2. Bタイミング違反が大きく、修正が難しい経路
  3. C2サイクルに1回だけデータを取り込めばよい経路
答えと解説を見る

正解：A. 回路の構造上はつながっているが、選択条件が両立しないなどの理由で、実際には信号が伝わることのない経路

STAは論理の意味を考えずに、つながっているすべての経路を調べます。そのため、2つのセレクタが同じ選択信号で互いに逆の入力を選ぶ回路のように、実際には通らない経路でも違反が出ることがあります。こうした経路をフォールスパスに指定して解析から外します。修正が難しいからといって外すと、本物の不具合を隠してしまいます。2サイクルに1回取り込む経路は、マルチサイクルパスとして時間を延ばして解析を続けるべきです。

非同期FIFOのグレイコードのポインタを相手のドメインに渡す経路を、非同期だからといって制約なし(フォールスパス)にすると問題になりうる理由として正しいものはどれか。

  1. Aフォールスパスにすると、同期化回路のフリップフロップが論理合成で削除されるから
  2. Bビットごとの遅延の差がポインタの更新間隔を超えると、1回に1ビットだけ変わるという前提が受け側で崩れるから
  3. Cフォールスパスにすると、ポインタがツールによってバイナリに戻されるから
答えと解説を見る

正解：B. ビットごとの遅延の差がポインタの更新間隔を超えると、1回に1ビットだけ変わるという前提が受け側で崩れるから

グレイコードのポインタは、受け側のどのエッジで見ても、変化中のビットが1つ以内であることを前提にしています。経路を制約なしにすると、配置配線でビットごとの遅延が大きくばらつくことがあります。例えば送り側の周期が 2 ns で、1回目に変わるビットが届くのに 3 ns、2回目に変わるビットが 1 ns かかると、どちらも時刻 3 ns に届き、2ビットが同時に変わったように見えます。そこで最大遅延の制約を付け、遅延の差を送り側の1周期以内に抑えます。

解説の中の「フォールスパス」

  • こうした経路をフォールスパスに指定して解析から外します。
