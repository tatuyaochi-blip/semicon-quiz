ストアバッファとは

すとあばっふぁ

コアが書き込みを一時的にためておく小さなバッファ。書き込みの完了を待たずに次の命令へ進めるが、ほかのコアからは書き込みが遅れて見える。

「ストアバッファ」は、1分野の4問の練習問題に出てきます(マルチコアと同期など)。

この用語の分野: マルチコアと同期

コアがストアをバッファにためる理由

コアがストア命令を実行するとき、対象のキャッシュラインがキャッシュになかったり、他のコアが保持していたりすることがあり、コヒーレンスプロトコルで書き込みの所有権を得るには多くのサイクルがかかります。そこでコアは停止せず、アドレスとデータをストアバッファに入れて実行を続けます。エントリは後でL1キャッシュへ書き出され、x86では通常プログラム順に書き出されます。アウトオブオーダー実行のプロセッサでは、ストアバッファは投機的なストアも保持します。これらは、ストア命令がコミットして取り消されないことが確定するまで、キャッシュには書き込めません。

ストア・ロード・フォワーディング

直前のストアがまだバッファに残っている可能性があるため、ロードはすべて、アドレスが一致するエントリがないかストアバッファを調べます。一致があれば、ロードはキャッシュからではなく、一致する最も新しいエントリからデータを受け取ります。この仕組みをストア・ロード・フォワーディングといいます。これによりシングルスレッドの動作が保たれ、コアは自分の書き込みを常にプログラム順どおり即座に見ることができます。フォワーディングがうまく働くのは、ロードが1つの先行ストアの書いたバイトをちょうど読む場合です。ロードとバッファ内のストアが部分的に重なると、多くの場合ロードはそれらのストアが書き出されるまで待たされます。

他のコアから書き込みが遅れて見える理由

他のコアはストアバッファの中を見られないため、バッファにある書き込みは書き出されるまで見えません。xとyがどちらも0で、コア1がx = 1の後にr1 = y、コア2がy = 1の後にr2 = xを実行する場合を考えます。逐次一貫性のもとでは、少なくとも一方のロードは1を読むはずです。しかしストアバッファがあると、両方のストアがバッファで待っている間に両方のロードがキャッシュから0を読むことができ、実際のx86マシンでもr1 = r2 = 0が起こります。ストアとロードの間にバッファが空になるまで待つメモリバリアを置けば、この結果は起こらなくなります。

ストアバッファとメモリ一貫性モデル

x86のメモリモデルであるTSO(トータルストアオーダー)は、本質的に先入れ先出しのストアバッファの動作を表しています。ストアどうし、ロードどうしの順序は保たれ、後のロードが別のアドレスへの先行ストアを追い越して見えることだけが許されます。ArmやRISC-Vのようなより弱いモデルでは、ほかの並べ替えに加えて、ストアが順不同で見えることも許されるため、フェンスやアクワイア/リリース命令がより頻繁に必要になります。プログラマは通常、言語レベルのアトミック操作に頼り、コンパイラがそれを適切なフェンスに変換します。

ストアバッファの練習問題に挑戦

メモリ一貫性モデル(メモリコンシステンシモデル)が定めているものはどれか。

  1. Aキャッシュのラインの大きさとセットの数
  2. B主記憶のDRAMに使うトランジスタの種類
  3. Cあるコアが行った複数の番地への読み書きが、ほかのコアからどの順番で見えうるか
答えと解説を見る

正解：C. あるコアが行った複数の番地への読み書きが、ほかのコアからどの順番で見えうるか

CPUは性能のために、書き込みをストアバッファにためたり、読み出しを先に行ったりして、メモリ操作の順番を入れ替えることがあります。1つのコアの中では結果が変わらないように作られていますが、ほかのコアからは順番が入れ替わって見えることがあります。メモリ一貫性モデルは、どの入れ替えが起こりうるかを定め、プログラマが正しい同期を書くための約束になります。

逐次一貫性(シーケンシャルコンシステンシ)の説明として正しいものはどれか。

  1. A各コアの操作が、毎回ランダムな順番で実行される
  2. Bすべてのコアの操作が、ある1つの順番に並べられ、各コアの操作はプログラムに書いた順番どおりに現れるように見える
  3. Cすべての操作が、1つのコアだけで実行される
答えと解説を見る

正解：B. すべてのコアの操作が、ある1つの順番に並べられ、各コアの操作はプログラムに書いた順番どおりに現れるように見える

逐次一貫性では、複数のコアの操作がトランプを混ぜるように1列に並べられ、各コアの操作はその中でプログラムの順番を保っているように見えます。プログラマにとって最も分かりやすいモデルですが、ハードウェアがストアバッファなどで順番を入れ替える最適化を大きく制限するので、実際の多くのCPUはもっと緩いモデルを採用しています。

よくある質問

ストア・ロード・フォワーディングとは何ですか?

ロードが、ストアバッファにまだ残っているアドレスの一致する先行ストアを見つけ、そこから直接データを受け取ることです。これによりコアは、保留中の自分の書き込みがキャッシュに届くのを待たずに、その値を参照できます。

ストアバッファリングのリトマステストで両方のスレッドが0を読めるのはなぜですか?

各コアの書き込みが自分のストアバッファにとどまって相手のコアから見えないまま、続くロードがキャッシュから古い値を読むからです。ストアとロードの間にメモリフェンスを入れると、これを防げます。

ストアバッファとTSOはどう関係していますか?

TSO(トータルストアオーダー)は、本質的にFIFOのストアバッファの振る舞いそのものです。許される並べ替えは、後の別アドレスへのロードが、先行ストアが見えるようになる前に完了することだけです。
