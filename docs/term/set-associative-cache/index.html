セットアソシアティブ方式とは

せっとあそしあてぃぶほうしき

アドレスから決まる1つのセットの中の、複数の場所(ウェイ)のどれにでもデータを置けるキャッシュの構成。nウェイなら各アクセスでn個のタグを並列に比べる。

「セットアソシアティブ方式」は、2分野の4問の練習問題に出てきます(メモリ階層と性能, CPU・アーキテクチャなど)。

この用語の分野: メモリ階層と性能

アドレスの分け方

キャッシュのアドレスは3つのフィールドに分けられます。下位のオフセットビットがライン内のバイトを、インデックスビットがセットを選び、残りの上位ビットがラインと一緒に格納されるタグになります。セット数は、容量÷(ラインサイズ×ウェイ数)です。32ビットアドレスで容量32 KB、ライン64バイトのキャッシュは512ラインあり、ダイレクトマップなら512セットでインデックス9ビット・タグ17ビット、4ウェイなら128セットでインデックス7ビット・タグ19ビットになります。連想度を2倍にするごとに、インデックスが1ビット減りタグが1ビット増えます。

アクセス時の動作

インデックスでセットを選ぶと、そのセット内のnウェイすべてのタグを読み出し、アドレスのタグと同時に比較します。そのため8ウェイなら比較器が8個必要です。比較では有効ビットも確認します。タグが一致したウェイがマルチプレクサを切り替えてデータを出力します。高速なL1キャッシュの多くは、タグ比較と並行して全ウェイのデータを読み出し最後に選択する方式をとり、電力と引き換えに速度を得ています。ミス時には、LRU(最も長く使われていないものを追い出す)や、より安価な擬似LRUなどの置き換えポリシーで、セット内のどのウェイを追い出すかを決めます。

ダイレクトマップ・セットアソシアティブ・フルアソシアティブ

この3つは1本の連続した選択肢の上にあります。ダイレクトマップは1ウェイで、各アドレスの置き場所は1つしかないため、インデックスが同じ2つのよく使うブロックが互いを追い出し続ける競合ミスが起きます。フルアソシアティブは全体が1セットで、どのラインもどこにでも置けるため競合ミスはなくなりますが、すべてのタグとの比較が必要です。セットアソシアティブはその中間です。連想度を上げると競合ミスは減りますが、初期参照ミスや容量ミスは減りません。8ウェイあたりを超えると効果は小さくなる一方、比較器、マルチプレクサの遅延、ヒット時間、電力は増え続けます。

代表的な値

L1キャッシュは容量が小さくヒット時間が重要なため、8〜12ウェイが一般的です。ミスするとDRAMまで取りに行くことになるラストレベルキャッシュでは、ヒットが少し遅くなってもミスを減らすほうが得なので、16ウェイ前後がよく使われます。TLB(アドレス変換バッファ)はエントリ数が少なくミスの代償が大きいため、高い連想度やフルアソシアティブにすることがよくあります。ハードウェアコストを見積もるときは、タグの記憶量も連想度とともに増える点に注意が必要です。ウェイを増やすごとにインデックスが1ビット減り、格納するタグがすべて長くなるからです。

セットアソシアティブ方式の練習問題に挑戦

セットアソシアティブ方式のキャッシュの説明として正しいものはどれか。

  1. Aあるアドレスのデータを、決まったセットの中の複数の場所(ウェイ)のどれかに置ける
  2. Bあるアドレスのデータを置ける場所が、キャッシュ内の1か所に決まっている
  3. Cデータをキャッシュのどこにでも置ける
答えと解説を見る

正解：A. あるアドレスのデータを、決まったセットの中の複数の場所(ウェイ)のどれかに置ける

セットアソシアティブ方式では、アドレスの一部でセットが決まり、その中の複数のウェイのどれかにデータを置けます。例えば8ウェイなら8か所の候補があり、ダイレクトマップ方式より同じ場所の取り合い(競合ミス)を減らせます。ウェイを増やすと比較回路と電力が増えるため、L1で8〜12ウェイ程度、L3で16ウェイ前後が一般的です。どこにでも置けるのはフルアソシアティブ方式です。

アドレスが32ビット、容量32 KB、ラインサイズ64バイトの4ウェイ・セットアソシアティブ方式のキャッシュのセット数はいくつか。

  1. A128
  2. B512
  3. C32
答えと解説を見る

正解：A. 128

ライン数は 32 KB ÷ 64 B = 512 です。4ウェイでは1つのセットに4ラインが入るので、セット数は 512 ÷ 4 = 128 = 2⁷ となり、インデックスは7ビット、タグは 32 − 7 − 6 = 19ビットになります。512はライン数そのもので、ダイレクトマップのときのセット数です。連想度を上げるとセット数が減り、その分タグのビット数が増えて比較器も増えます。32はセット数128をさらにウェイ数4で割ってしまった値です。

よくある質問

セットアソシアティブキャッシュのセット数はどう計算しますか?

容量をラインサイズで割ってライン数を求め、それをウェイ数で割ります。容量32 KB、4ウェイ、ライン64バイトなら512ラインなので、128セットです。

連想度を上げればキャッシュは必ず速くなりますか?

いいえ。競合ミスは減りますが、アクセスごとに比較するタグや選択するウェイが増えるため、ヒット時間が長くなり電力も増えがちです。そのキャッシュ階層に合わせて、ミス率とヒット時間のバランスで選びます。

セットとウェイの違いは何ですか?

セットは1つのインデックス値で選ばれる置き場所のまとまりで、ウェイはそのセットの中の1つの置き場所です。8ウェイキャッシュでは各セットに8つのウェイがあり、ブロックはそのどれにでも置けます。

解説の中の「セットアソシアティブ方式」

  • セットアソシアティブ方式では、アドレスの一部でセットが決まり、その中の複数のウェイのどれかにデータを置けます。

    セットアソシアティブ方式のキャッシュの説明として正しいものはどれか。

  • セットアソシアティブ方式では1つのセットに複数のウェイがあり、同じセットに対応するデータを複数置けるため、ダイレクトマップより競合ミスが減ります。

    ダイレクトマップ方式からセットアソシアティブ方式に変えたときに起こる変化として、正しいものはどれか。

  • セットアソシアティブ方式では、まずアドレスのインデックスで1つのセットを選び、そのセットにある全ウェイのタグを並列に比べます。

    8ウェイ・セットアソシアティブ方式のキャッシュで、1回のアクセスのたびに並列に比べるタグの数はいくつか。
