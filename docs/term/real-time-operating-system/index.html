RTOS(リアルタイムOS)とは

あーるとす

複数のタスクを優先度に従って切り替え、決められた時間内に応答できるようにする組込み向けのOS。FreeRTOSやZephyrなど。

やさしい解説で読む: マイコンとは? 家電や車を動かす小さなコンピュータ

「RTOS(リアルタイムOS)」は、1分野の7問の練習問題に出てきます(組込み・ファームウェアなど)。

この用語の分野: 組込み・ファームウェア

タスクのスケジューリング

RTOS(リアルタイムOS)は、ファームウェアをタスクという単位で構成します。各タスクは優先度と、実行可能、実行中、待ち(ブロック)などの状態を持ちます。多くのRTOSは優先度ベースのプリエンプティブスケジューリングを採用しており、割り込みやメッセージで優先度の高いタスクが実行可能になると、カーネルは実行中のタスクのコンテキストを退避してすぐに切り替えます。中断されたタスクは後で止まった場所から再開します。ハードウェアタイマによる周期的なティック(多くは1 ms)がタイムアウトや遅延を管理します。たとえば16 MHzをプリスケーラで16分周すると1 µsのカウントになり、1000カウントごとに割り込めば1 msのティックが得られます。

リアルタイムとは「速い」より「予測できる」こと

目標は、モータ制御や通信プロトコルなどの重要な処理で、上限が決まった予測可能な応答時間を守ることで、平均スループットの最大化ではありません。汎用OSは公平性とスループットを重視するため、タスクを予測できない形で遅らせることがあります。RTOSはカーネルを小さく保ち、スケジューリングの判断を決定的にしているので、メモリの少ないマイコンでも動作します。OSを使わない場合、ファームウェアはスーパーループ、つまりwhile (1)のループで各処理を順に呼び出し、緊急の事象は割り込みで処理してフラグを立てる構成がよく使われます。単純で軽量ですが、1つの処理が遅いと全体が遅れるため、そうなったときにRTOSの導入が見合うようになります。

タスク間の通信

RTOSには、タスクがビジーウェイトせずに協調するための仕組みが用意されています。メッセージキューを使うと、センサのタスクが測定値を送り、表示のタスクはデータが届くまでCPUを使わない待ち状態で眠っていられます。複数のデータをバッファできるので、一時的な速度の差を吸収してデータを失いません。ミューテックスはバスやバッファなどの共有資源を保護し、セマフォは割り込みハンドラなどから事象を通知します。タイムアウト付きの待ちを使えば、タスクは時間を区切ってブロックできます。共有変数やフラグのポーリングの代わりにこれらを使うと、データ競合や無駄なサイクルを避けられます。

優先度逆転と優先度継承

優先度逆転とは、高優先度のタスクが低優先度のタスクの持つミューテックスを待っているときに、無関係な中優先度のタスクが低優先度のタスクを横取りする現象です。低優先度のタスクは処理を終えてミューテックスを解放できないため、高優先度のタスクは事実上、中優先度のタスクによって際限なくブロックされます。1997年には、これが原因で火星探査機マーズ・パスファインダーのシステムがリセットを繰り返しました。優先度継承は、ミューテックスを持つタスクの優先度を、資源を解放するまで一時的に待っているタスクと同じ優先度に引き上げることでこの問題を解決し、多くのRTOSのミューテックスに標準のオプションとして備わっています。

RTOS(リアルタイムOS)の練習問題に挑戦

組込み機器でRTOS(リアルタイムOS)を使う主な目的はどれか。

  1. A画面に美しいウィンドウを表示する
  2. B処理の平均の速さを、パソコンのOSより必ず速くする
  3. C複数の処理(タスク)を優先度に従って切り替え、決められた時間内に応答できるようにする
答えと解説を見る

正解：C. 複数の処理(タスク)を優先度に従って切り替え、決められた時間内に応答できるようにする

RTOSは、処理をタスクに分け、優先度の高いタスクが実行できるようになったらすぐに切り替えて動かします。モーターの制御や通信の応答のように、遅れると困る処理を決められた時間内に確実に行えるようにすることが目的です。タスク間でデータを渡すキューや、資源を守るミューテックス、時間を待つ機能なども用意されています。FreeRTOSやZephyr、μITRONなどがあります。

プリエンプティブなRTOSで、優先度の低いタスクの実行中に、優先度の高いタスクが待っていたデータを受け取って実行できる状態になった。一般にどうなるか。

  1. A低いタスクが自分から終わるまで、高いタスクは待つ
  2. B両方のタスクが止まり、マイコンが再起動する
  3. C低いタスクを途中で止めて、すぐに高いタスクに切り替える
答えと解説を見る

正解：C. 低いタスクを途中で止めて、すぐに高いタスクに切り替える

プリエンプティブなRTOSでは、割り込みなどをきっかけに優先度の高いタスクが実行できる状態になると、カーネルが実行中の低いタスクの状態を保存して止め、高いタスクに切り替えます。高いタスクが終わるか待ち状態になると、低いタスクが続きから再開します。そのため、高い優先度の処理の応答の時間を短く予測しやすくできます。

よくある質問

RTOSとLinuxのような汎用OSの違いは?

RTOSは厳密な優先度ベースのプリエンプションと小さなフットプリントにより、最悪応答時間を予測できるように設計されています。汎用OSは平均スループットと公平性を重視し、機能は豊富ですが、タイミングの決定性は劣ります。

RTOSの優先度逆転とは何ですか?

高優先度のタスクが低優先度のタスクの持つ資源を待っている間に、その低優先度のタスクが中優先度のタスクに実行を奪われ、高優先度のタスクが動けなくなる現象です。資源を持つタスクの優先度を一時的に引き上げる優先度継承で防ぎます。

スーパーループではなくRTOSを使うべきなのはどんなときですか?

タイミング要件の異なる処理がいくつもあり、スーパーループ内の長い処理が時間に厳しい処理を遅らせてしまう場合です。単純で負荷の軽いファームウェアなら、スーパーループと割り込みで十分なことも多くあります。
