TRR(ターゲットロウリフレッシュ)とは

てぃーあーるあーる

ロウハンマーへの対策の1つ。頻繁に活性化された行を追跡し、その隣の行を通常より早くリフレッシュして、ビットの反転を防ぐ。DRAMの中やメモリコントローラに組み込まれる。DRAMの中のものは追跡できる行の数に限りがあることが多く、多くの行を順に活性化する方法で回避された例が研究で示されている。

「TRR(ターゲットロウリフレッシュ)」は、2分野の4問の練習問題に出てきます(ハードウェアセキュリティの最新動向, DRAMなど)。

この用語の分野: ハードウェアセキュリティの最新動向

TRR(ターゲットロウリフレッシュ)の練習問題に挑戦

DRAMの中のTRR(ターゲットロウリフレッシュ)によるロウハンマーへの対策が、研究で回避されたことがある理由として、正しいものはどれか。

  1. ATRRはリフレッシュを止めてしまう仕組みなので、TRRが働いている間は、かえってすべての行のビットが反転しやすくなったから
  2. BTRRはECCを無効にしてから動く仕組みなので、TRRが働くたびに訂正できない誤りが増え、そこから攻撃されたから
  3. C追跡できる行の数に限りがあり、多くの行を活性化すると見逃される行が出るうえ、2行離れた行で反転が起きる場合もあったから
答えと解説を見る

正解：C. 追跡できる行の数に限りがあり、多くの行を活性化すると見逃される行が出るうえ、2行離れた行で反転が起きる場合もあったから

DRAMの中のTRRは、回路の面積の制約から、頻繁に活性化された行を少数だけ記録し、その隣の行を余分にリフレッシュする作りのものが多くありました。2020年に公表されたTRRespassでは、多くの行を順に活性化する方法で記録が追いつかなくなり、守られない行でビットが反転することが示されました。2021年に公表されたHalf-Doubleでは、2行離れた行でも反転が起き、隣の行を守るための余分なリフレッシュ(活性化)自体が、その外側の行への干渉に加わりうることが示されました。こうした結果から、すべての行の活性化を正確に数える仕組みや、システム全体での多層の対策が求められるようになりました。

  • 対策として、頻繁に活性化された行の隣を追加でリフレッシュする仕組み(TRR、DDR5のRFMなど)がDRAMやコントローラに組み込まれています。

    DRAMで、ある行を短時間に何度も活性化すると、隣接する行のデータが反転してしまうことがある現象を何と呼ぶか。

  • ECCは反転の多くを抑える有効な層ですが、TRRやリフレッシュの管理のように、反転そのものを起こさせない対策と組み合わせる必要があります。

    「ECC付きのメモリを使えば、ロウハンマーの心配はない」という考えの問題点として、正しいものはどれか。

  • それまでの対策では、DRAMの中のTRRが少数の行だけを追跡したり、DDR5のRFMのように、メモリコントローラがバンクごとの活性化の回数を数えてDRAMに余分な時間を与えたりしていました。
