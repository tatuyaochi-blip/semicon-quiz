静的リンクと動的リンクの違い：ライブラリの結合方法を比較

リンクは、コンパイルしたコードを、それが使うライブラリのコードと結び付ける作業です。静的リンクでは、必要なライブラリのコードをビルド時に実行ファイルへコピーするので、プログラムだけで完結します。動的リンクでは、実行ファイルは必要な共有ライブラリを記録するだけで、プログラムの起動時にOSがそれらを読み込むので、多くのプログラムが1つのコピーを共有できます。静的は配布が簡単で、動的はメモリを節約でき、更新もしやすくなります。

項目静的リンク動的リンク
いつ行うかビルド時。ライブラリのコードを実行ファイルにコピーするロード時や実行時。動的リンカーが共有ライブラリ(.so、.dll)を探してマップする
実行ファイルの大きさ大きい小さい
メモリの使用量各プログラムが、ライブラリのコードのコピーを持つ共有ライブラリの1つのコピーを、多くのプロセスで共有できる
更新とセキュリティの修正プログラムを作り直して配り直す必要があるライブラリを1回更新すれば、作り直さなくても効果が出る(インターフェースに互換性があれば)
起動時間やや速いやや遅い。シンボルの解決が必要(遅延させることが多い)
配布自己完結。ライブラリがインストールされていなくても動く対象のシステムに正しいバージョンのライブラリが必要。なければ起動に失敗する
実行時のコストプログラム全体の最適化と直接の呼び出しができるGOTやPLTを通る間接呼び出しで、わずかな負荷がある
バージョンの問題実行時にはないプログラムと、インストールされたライブラリの不一致が起こりうる
主な用途組み込みのファームウェア、単一ファイルのツール、最小構成のコンテナ汎用OS上のほとんどのプログラム、プラグイン、libcなどのシステムのライブラリ

数値は代表的な目安で、世代や製品によって異なります。

どんなときに使うか

静的
どこでも動く、自己完結したバイナリが欲しいとき。または、組み込みのファームウェアのように、OSのローダーがないとき。
動的
多くのプログラムが同じライブラリを共有し、メモリを節約して、ライブラリをまとめて修正したいとき。

理解度チェック

  1. 静的リンクの説明として正しいものはどれか。
  2. 動的リンク(共有ライブラリ)の利点として正しいものはどれか。
  3. 動的リンクを使ったプログラムを別のコンピュータにコピーして実行したら、起動しなかった。最も考えられる原因はどれか。
  4. 静的ライブラリ(.aファイル)と一緒にリンクするとき、リンカが実行ファイルに組み込むものとして正しいものはどれか。
  5. 共有ライブラリで使われるGOT(グローバルオフセットテーブル)の役割として正しいものはどれか。
  6. 100個のプロセスが同じ共有ライブラリを使っているとき、物理メモリの使い方として正しいものはどれか。
