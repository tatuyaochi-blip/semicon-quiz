Softwareontwikkeling en projectmanagement

Welke beschrijving van de werkwijze bij testgedreven ontwikkeling (TDD) is juist?

  1. ASchrijf een test die nog niet slaagt, schrijf de minimale code om hem te laten slagen en refactor daarna terwijl de tests blijven slagen
  2. BSchrijf eerst alle code voor een functie en maak daarna testgevallen door de vertakkingen in die code te volgen
  3. CToegewijde testers schrijven de tests, en ontwikkelaars voeren geen tests uit tot de fase van de integratietest
Antwoord en toelichting tonen

Antwoord: A. Schrijf een test die nog niet slaagt, schrijf de minimale code om hem te laten slagen en refactor daarna terwijl de tests blijven slagen

Bij testgedreven ontwikkeling wordt eerst een klein stukje van de specificatie van de te bouwen functie als test geschreven, die wordt uitgevoerd om te bevestigen dat hij faalt (rood). Daarna wordt de minimale code geschreven om die test te laten slagen (groen), en vervolgens worden duplicatie en andere problemen opgeruimd terwijl de tests blijven slagen (refactor). Met deze korte cyclus worden functies stap voor stap toegevoegd, terwijl er steeds een volledige set tests is. Ook bij embedded firmware worden de hardwareafhankelijke delen vervangbaar gemaakt, zodat unittests herhaaldelijk op een ontwikkel-pc kunnen worden uitgevoerd.
