Basis van cloud en containers

Welke beschrijving van benoemde volumes en bind mounts in Docker, die worden gebruikt om gegevens te bewaren die een container schrijft, is juist?

  1. AEen volume wordt opgeslagen in een gebied dat Docker beheert en een bind mount in een opgegeven map van de host, en beide blijven bestaan nadat de container is verwijderd
  2. BDe gegevens in een benoemd volume blijven bestaan nadat de container is verwijderd, maar de gegevens van een bind mount verdwijnen bij het verwijderen van de container ook uit de map van de host
  3. CBeide worden gemaakt als deel van de beschrijfbare laag van de container; het verwijderen van de container met docker rm wist dus ook de gegevens
Antwoord en toelichting tonen

Antwoord: A. Een volume wordt opgeslagen in een gebied dat Docker beheert en een bind mount in een opgegeven map van de host, en beide blijven bestaan nadat de container is verwijderd

Gegevens die naar de beschrijfbare laag van een container worden geschreven, verdwijnen als de container wordt verwijderd; gegevens die bewaard moeten blijven, worden daarom buiten de container geplaatst. Een benoemd volume wordt gemaakt in een gebied dat Docker beheert en blijft bestaan tot het expliciet wordt verwijderd, bijvoorbeeld met docker volume rm. Een bind mount maakt een willekeurige map van de host zichtbaar in de container, en de gegevens blijven gewoon als bestanden op de host staan. Bind mounts zijn gebruikelijk tijdens de ontwikkeling, wanneer op de host bewerkte broncode meteen effect moet hebben, en volumes voor gegevens waarvan het beheer het best aan Docker wordt overgelaten, zoals de gegevens van een database.
