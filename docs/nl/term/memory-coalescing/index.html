Wat is Memory coalescing?

Het samenvoegen tot minder geheugentoegangen wanneer naburige threads in een warp naburige adressen benaderen. Gecombineerde toegang.

Japanse benaming: メモリコアレッシング

Vakgebied: GPU-programmeren

Hoe coalescing werkt

Het globale geheugen van een GPU wordt benaderd in brokken van vaste grootte, doorgaans sectoren van 32 bytes binnen cachelines van 128 bytes, niet per afzonderlijk woord. Threads draaien in groepen die warps heten, meestal 32 threads die samen dezelfde load-instructie uitgeven. Als thread i van een warp het element van 4 bytes op base + 4i leest, vallen de 32 verzoeken binnen 128 aaneengesloten bytes, en voegt de hardware ze samen tot een of enkele geheugentransacties. Dit samenvoegen is memory coalescing, en daardoor kan de GPU bijna alle bytes die hij verplaatst ook gebruiken.

Wat coalescing verhindert

Als threads adressen met een stride benaderen, bijvoorbeeld elk vierde element, raakt de warp vier keer zoveel sectoren aan en wordt het grootste deel van elke opgehaalde sector weggegooid. Willekeurige of indirecte toegangen kunnen voor elke thread een aparte transactie vereisen. Een niet-uitgelijnd beginadres kan één extra segment toevoegen. In al die gevallen daalt de effectieve bandbreedte tot een fractie van de piek, en omdat veel GPU-kernels eerder door geheugenbandbreedte dan door rekenwerk worden begrensd, vertraagt toegang zonder coalescing een kernel vaak met een grote factor.

Array of structures vs. structure of arrays

De gegevensindeling bepaalt grotendeels of toegangen worden samengevoegd. Als deeltjesposities als array of structures (AoS) zijn opgeslagen, volgen x, y en z van deeltje 0 op elkaar, gevolgd door die van deeltje 1, dus als elke thread x leest, liggen de adressen 12 bytes uit elkaar. Bij een structure of arrays (SoA) staan alle x-waarden aaneengesloten, zodat naburige threads naburige adressen lezen en de loads van de warp worden samengevoegd. SoA is om dezelfde reden meestal ook beter voor SIMD-vectorisatie op de CPU: naburige lanes willen naburige elementen.

Technieken en een veelvoorkomende verwarring

Gangbare oplossingen zijn de snelst veranderende thread-index, threadIdx.x in CUDA, koppelen aan de aaneengesloten dimensie van een array, AoS-data omzetten naar SoA en data via on-chip shared memory laten lopen, bijvoorbeeld door een matrixtegel met samengevoegde rijleesacties te laden en getransponeerd weg te schrijven. Coalescing gaat over transacties in het globale geheugen. Het moet niet worden verward met bankconflicten in shared memory, die optreden als meerdere threads van een warp verschillende adressen in dezelfde bank van het shared memory raken en hun toegangen worden geserialiseerd.

Veelgestelde vragen

Wat is memory coalescing in CUDA?

Het is het samenvoegen door de hardware van de toegangen tot het globale geheugen van de threads in een warp tot zo weinig mogelijk transacties, wat gebeurt als naburige threads naburige, uitgelijnde adressen benaderen.

Waarom is een structure of arrays beter voor geheugentoegang op een GPU?

In een structure of arrays wordt elk veld aaneengesloten opgeslagen, zodat naburige threads die hetzelfde veld lezen opeenvolgende adressen benaderen en hun loads worden samengevoegd; een array of structures zet er een stride tussen.

Wat is het verschil tussen memory coalescing en bankconflicten?

Coalescing gaat over hoe de toegangen tot het globale geheugen van een warp worden omgezet in geheugentransacties, terwijl bankconflicten gaan over meerdere threads die dezelfde bank van het on-chip shared memory benaderen, wat serialisatie afdwingt.
