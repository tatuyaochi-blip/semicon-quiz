Wat is ABI (application binary interface)?

Afspraken op machinetaalniveau waarmee gecompileerde programma's en bibliotheken samen kunnen werken. Omvat onder meer de aanroepconventie, de grootte en uitlijning van gegevenstypen en de manier waarop systeemaanroepen worden gedaan.

Japanse benaming: ABI(アプリケーションバイナリインターフェース)

“ABI (application binary interface)” komt voor in 3 oefenvragen uit 2 onderwerpen, bijv. Instructieset en assembly, Linker, loader en uitvoerbare formaten.

Vakgebied: Instructieset en assembly

Wat een ABI vastlegt

Een application binary interface (ABI) legt alles vast waarover twee stukken gecompileerde code het eens moeten zijn om elkaar aan te roepen zonder opnieuw gebouwd te worden. Daaronder vallen de aanroepconventie (welke registers argumenten en returnwaarden bevatten, welke registers een callee moet behouden, hoe de stack is uitgelijnd en ingedeeld), de grootte en uitlijning van basistypen zoals int, long en pointers, de indeling en padding van structs, de manier waarop C++-namen worden gemangeld, hoe exceptions de stack afwikkelen (unwinding), het objectbestandsformaat en de instructiereeks waarmee een systeemaanroep naar het besturingssysteem wordt gedaan.

API versus ABI

Een application programming interface (API) is een contract op broncodeniveau: functienamen, parametertypen en gedrag zoals een programmeur die ziet. Een ABI is datzelfde contract na compilatie. Een bibliotheek kan haar API ongewijzigd laten en toch haar ABI breken, bijvoorbeeld door een veld aan een publieke struct toe te voegen, wat de grootte van de struct en de offsets van latere velden verandert. Programma's compileren dan prima tegen de nieuwe header, maar binaries die tegen de oude versie zijn gebouwd, lezen het geheugen verkeerd tenzij ze opnieuw worden gecompileerd. Versienummers van gedeelde bibliotheken bestaan grotendeels om zulke ABI-breuken aan te geven.

Eén ISA, meerdere ABI's

De instruction set architecture (ISA) bepaalt wat de processor uitvoert; de ABI is een softwareconventie daarbovenop, dus één ISA kan er meerdere hebben. Op x86-64 geeft de System V-ABI die Linux gebruikt de eerste zes integerargumenten door in RDI, RSI, RDX, RCX, R8 en R9 en maakt long 64 bits, terwijl de Windows x64-ABI RCX, RDX, R8 en R9 gebruikt en long op 32 bits houdt. RISC-V definieert ABI's zoals ilp32, lp64 en lp64d, waarbij de laatste floating-point-argumenten in floating-point-registers doorgeeft.

De ABI van een bibliotheek klein houden

Elk symbool dat een gedeelde bibliotheek exporteert, wordt deel van haar ABI en moet compatibel blijven. Geëxporteerde functies kunnen bovendien worden overschreven door een symbool met dezelfde naam in een andere module, dus zelfs aanroepen binnen de bibliotheek moeten via de procedure linkage table (PLT) of global offset table (GOT) lopen. Door interne functies hidden visibility te geven, verdwijnen ze uit de publieke interface: de dynamische linker hoeft minder symbolen op te lossen, interne aanroepen worden directe PC-relatieve aanroepen, naamconflicten met andere bibliotheken worden vermeden en de bibliotheek mag die functies later vrij aanpassen.

Nu oefenen: vragen over ABI (application binary interface)

Welke omschrijving van de ABI (application binary interface) is juist?

  1. AEen afspraak op broncodeniveau die functienamen en argumenttypen vastlegt
  2. BEen afspraak die alleen de soorten CPU-instructies en hun bitindeling vastlegt
  3. CEen afspraak op machinecodeniveau om programma's aan elkaar te koppelen, zoals de aanroepconventie en de grootte en uitlijning van gegevenstypen
Antwoord en toelichting tonen

Antwoord: C. Een afspraak op machinecodeniveau om programma's aan elkaar te koppelen, zoals de aanroepconventie en de grootte en uitlijning van gegevenstypen

De ABI is een afspraak op machinecodeniveau waarmee gecompileerde programma's en bibliotheken samen kunnen werken en omvat de aanroepconventie, de grootte van int, long en pointers, de uitlijning van structuren en de manier van systeemaanroepen. De API legt in broncode vast hoe functies worden gebruikt; ook bij dezelfde API kan een bibliotheek niet worden gebruikt zonder opnieuw te bouwen als de ABI verschilt. Ook bij dezelfde RISC-V-ISA kan de ABI per OS en toepassing verschillen.

Veelgestelde vragen

Wat is het verschil tussen een API en een ABI?

Een API is de broncode-interface waartegen een programmeur schrijft, terwijl een ABI de afspraak op binair niveau is over registers, gegevensindeling en aanroepvolgorde waarop gecompileerde code vertrouwt. Als de API gelijk blijft maar de ABI verandert, moeten afhankelijke programma's opnieuw worden gecompileerd.

Waarom kan een bibliotheekupdate programma's breken die zelf niet zijn gewijzigd?

Als de update de ABI verandert, bijvoorbeeld de grootte van een struct of de argumenttypen van een functie, gebruiken bestaande binaries nog de oude indeling en geven ze gegevens in de verkeerde vorm door. De broncode compileert misschien ongewijzigd, maar al gebouwde programma's falen totdat ze opnieuw worden gebouwd.

Is een aanroepconventie onderdeel van de ABI?

Ja. De aanroepconventie, die vastlegt waar argumenten en returnwaarden terechtkomen en welke registers elke kant moet behouden, is een van de centrale onderdelen van een ABI.
