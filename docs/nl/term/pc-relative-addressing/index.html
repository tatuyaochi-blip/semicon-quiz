Wat is PC-relatieve adressering?

Methode om het doeladres van een sprong of gegevens uit te drukken als afstand tot het adres van de huidige instructie (PC). De afstand verandert niet waar het programma ook staat, dus vormt dit de basis voor positie-onafhankelijke code.

Japanse benaming: PC相対アドレッシング

“PC-relatieve adressering” komt voor in 2 oefenvragen uit 1 onderwerpen, bijv. Instructieset en assembly.

Vakgebied: Instructieset en assembly

Hoe het doeladres wordt berekend

De instructie bevat een offset met teken, en de hardware telt die na tekenextensie op bij een referentieadres dat van de programmateller (PC) is afgeleid. Bij RISC-V is de referentie het adres van de branch zelf. Conditionele branches coderen een even offset van 13 bits, met een bereik van ongeveer ±4 KiB, en jal codeert een offset van 21 bits, ongeveer ±1 MiB. Voor alles wat verder weg ligt, telt auipc een upper immediate van 20 bits, 12 posities naar links geschoven, op bij de PC, en levert een volgende jalr, addi of load de onderste 12 bits, waarmee samen ongeveer ±2 GiB wordt bereikt. Andere ISA's gebruiken andere referentiepunten, zoals het adres van de volgende instructie bij x86.

Waarom het positie-onafhankelijke code mogelijk maakt

Positie-onafhankelijke code (PIC) moet correct draaien op welk adres ze ook wordt geladen. Met absolute adressen zou de loader elke instructie die een adres noemt moeten patchen, wat tijd kost, de kopie van de code per proces anders maakt en voorkomt dat processen dezelfde fysieke pagina's delen. PC-relatieve offsets tussen delen van hetzelfde image veranderen niet wanneer het hele image verschuift, dus patchen is niet nodig. Shared libraries en executables die om veiligheidsredenen op willekeurige adressen worden geladen (address space layout randomization), zijn hiervan afhankelijk.

Ook data bereiken, niet alleen code

PC-relatieve adressering is net zo belangrijk voor data. x86-64 introduceerde RIP-relatieve adressering, zodat loads en stores globale variabelen relatief ten opzichte van de instructiepointer kunnen aanspreken, iets wat 32-bits x86 niet had, waardoor PIC op die architectuur de PC met een call-truc moest opvragen en er een register voor moest reserveren. Voor symbolen waarvan het definitieve adres pas tijdens de uitvoering bekend is, zoals variabelen in een andere shared library, gebruikt de code een PC-relatieve load uit de global offset table (GOT), een tabel met adressen die de dynamische linker bij het laden één keer invult.

PC-relatief versus andere adresseringsmodi

Absolute adressering noemt een vast adres en moet worden gereloceerd als de code verschuift. Register-indirecte adressering springt of laadt via een adres in een register; zo werken functiepointers, virtuele aanroepen en returns, omdat hun doelen niet bekend zijn wanneer de code wordt geassembleerd. PC-relatieve adressering dekt het grote middengebied van doelen die vastliggen ten opzichte van de code: lussprongen, aanroepen binnen een programma en toegang tot de eigen constanten en globale variabelen. De beperking is de breedte van het offsetveld, en daarom bestaan reeksen voor lange afstanden zoals auipc plus jalr.

Nu oefenen: vragen over PC-relatieve adressering

  2. BSprongvoorspelling is niet meer nodig en de pipeline stopt nooit
  3. CHet programma werkt zonder herschrijven van instructies, op welk geheugenadres het ook wordt geladen
Antwoord en toelichting tonen

Antwoord: C. Het programma werkt zonder herschrijven van instructies, op welk geheugenadres het ook wordt geladen

Een PC-relatieve sprong drukt de bestemming uit als afstand „zoveel bytes vanaf hier”, dus ook als het hele programma naar een ander adres wordt verschoven, verandert de afstand niet en werkt het ongewijzigd. Dit is de basis van position-independent code (PIC), zoals gebruikt in gedeelde bibliotheken. Omdat het aantal bits voor de afstand beperkt is, worden voor verre sprongen auipc en jalr gecombineerd. De noodzaak van sprongvoorspelling is niet afhankelijk van de manier van weergave.

Veelgestelde vragen

Wat is het bereik van een branchinstructie bij RISC-V?

Conditionele branches zoals beq hebben een offset met teken van 13 bits in veelvouden van 2 bytes, ongeveer ±4 KiB vanaf de branch. jal reikt tot ongeveer ±1 MiB, en auipc in combinatie met jalr tot ongeveer ±2 GiB.

Waarom gebruikt x86-64 RIP-relatieve adressering?

Daarmee kan code globale data relatief ten opzichte van de huidige instructie benaderen, zodat positie-onafhankelijke code geen patching bij het laden en geen gereserveerd basisregister nodig heeft. 32-bits x86 had zo'n modus niet voor data.

Is PC-relatieve adressering nodig voor shared libraries?

In de praktijk wel. Shared libraries worden in verschillende processen op verschillende adressen geladen, en PC-relatieve sprongen en dataverwijzingen, plus indirectie via tabellen zoals de GOT, zorgen ervoor dat dezelfde codepagina's overal werken.
