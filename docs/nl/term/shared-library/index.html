Wat is Gedeelde bibliotheek (shared library)?

Bibliotheek die bij dynamisch linken tijdens runtime wordt geladen. .so in Linux, .dll in Windows. Gemaakt met positie-onafhankelijke code, zodat de codepagina's door veel processen kunnen worden gedeeld.

Vakgebied: Linker, loader en uitvoerbare formaten

Hoe dynamisch linken werkt

Wanneer een programma tegen een gedeelde bibliotheek wordt gelinkt, legt het uitvoerbare bestand alleen vast welke bibliotheken het nodig heeft, geïdentificeerd door hun soname, en welke symbolen het importeert. Bij het opstarten vindt de dynamische linker (ld.so op Linux) elke bibliotheek, mapt hij die in de adresruimte van het proces, lost hij symboolverwijzingen op en past hij relocaties toe. Aanroepen naar bibliotheekfuncties lopen doorgaans via de procedure linkage table (PLT), die elke functie lui kan resolven bij de eerste aanroep. Het commando ldd toont naar welk bestand elke benodigde bibliotheek wordt opgelost en markeert ontbrekende als "not found"; het mag niet op onbetrouwbare binaries worden uitgevoerd, omdat dat hun code kan uitvoeren.

Positie-onafhankelijke code en het delen van pages

Een gedeelde bibliotheek kan in elk proces op een ander adres terechtkomen, dus ze wordt gecompileerd als positie-onafhankelijke code (PIC). De code bereikt haar eigen functies en data met PC-relatieve adressering en externe symbolen via de global offset table (GOT), een datagebied per proces dat de dynamische linker invult. De codepages hoeven daardoor nooit te worden gepatcht en kunnen als alleen-lezen en uitvoerbaar worden gemapt. Het besturingssysteem laat de mapping van elk proces naar dezelfde fysieke pages wijzen, dus 100 processen die één bibliotheek gebruiken, houden de code ervan maar één keer vast, terwijl beschrijfbare datapages per proces worden bijgehouden, doorgaans met copy-on-write.

Versiebeheer met sonames

Op Linux draagt een bibliotheekbestand zoals libfoo.so.1.2.3 een soname zoals libfoo.so.1, en programma's leggen de soname vast. Een bugfix of beveiligingspatch die de ABI (application binary interface) compatibel houdt, behoudt de soname, dus het vervangen van één bestand werkt elk programma bij dat het gebruikt. Het wijzigen van argumenttypen of de indeling van structs, of het verwijderen van functies, breekt oude binaries, dus dan wordt het soname-nummer verhoogd en wordt de nieuwe bibliotheek naast de oude geïnstalleerd.

Gedeelde versus statische bibliotheken

Een statische bibliotheek is een archief van objectbestanden waarvan de benodigde delen tijdens het linken in het uitvoerbare bestand worden gekopieerd, wat een zelfstandige binary oplevert zonder binding bij het opstarten, maar elk programma draagt dan zijn eigen kopie mee en een fix vereist opnieuw linken. Gedeelde bibliotheken besparen geheugen en schijfruimte en maken updates ter plaatse mogelijk, ten koste van bindingswerk bij het opstarten, een indirectie bij aanroepen tussen modules en fouten door ontbrekende afhankelijkheden. Door interne functies hidden visibility te geven en alleen de publieke API te exporteren, worden er minder symbolen die de dynamische linker moet verwerken, kunnen interne aanroepen de PLT overslaan, worden naamconflicten voorkomen en blijft de ABI klein.

Nu oefenen: vragen over Gedeelde bibliotheek (shared library)

Hoe wordt het fysieke geheugen gebruikt als 100 processen dezelfde gedeelde bibliotheek gebruiken?

  1. APagina's met niet-herschreven code delen één kopie, en pagina's met te schrijven data heeft elk proces zelf
  2. BZowel code als data hebben per proces 100 kopieën
  3. CAlles, inclusief datapagina's, wordt gedeeld en processen kunnen elkaars waarden zien
Antwoord en toelichting tonen

Antwoord: A. Pagina's met niet-herschreven code delen één kopie, en pagina's met te schrijven data heeft elk proces zelf

Het OS koppelt de gedeelde bibliotheek aan de virtuele adresruimte van elk proces en laat pagina's met niet-herschreven code en constanten naar dezelfde fysieke pagina wijzen. Pagina's met te schrijven data, zoals variabelen, worden per proces apart gehouden, bijvoorbeeld door op het moment van schrijven een kopie te maken (copy-on-write). Zo is ook bij 100 processen geheugen voor de bibliotheekcode maar één keer nodig.

Welk voordeel is juist van het zetten van de symboolzichtbaarheid (visibility) op „hidden” voor interne functies, terwijl bij het maken van een gedeelde bibliotheek alleen de van buiten gebruikte functies worden gepubliceerd?

  1. AInterne functies worden versleuteld en kunnen niet worden geanalyseerd
  2. BEr zijn minder symbolen voor de dynamische linker, waardoor het laden sneller gaat, en interne aanroepen hoeven niet via de PLT te lopen
  3. CDe bibliotheek werkt dan op elk OS
Antwoord en toelichting tonen

Antwoord: B. Er zijn minder symbolen voor de dynamische linker, waardoor het laden sneller gaat, en interne aanroepen hoeven niet via de PLT te lopen

Gepubliceerde symbolen van een gedeelde bibliotheek kunnen worden vervangen door een definitie met dezelfde naam in een andere module, dus ook aanroepen van binnenuit moeten via de PLT of GOT lopen. Met hidden zijn ze van buiten niet zichtbaar, vermindert het aantal symbolen dat de dynamische linker onderzoekt en kunnen interne aanroepen rechtstreeks PC-relatief plaatsvinden. Ook naamconflicten met andere bibliotheken worden vermeden en de gepubliceerde ABI blijft klein.

Veelgestelde vragen

Wat is het verschil tussen een statische en een gedeelde bibliotheek?

Een statische bibliotheek (.a of .lib) wordt tijdens het linken in het uitvoerbare bestand gekopieerd. Een gedeelde bibliotheek (.so of .dll) blijft een apart bestand dat tijdens de uitvoering wordt geladen en in het geheugen door veel processen kan worden gedeeld.

Waarom hebben gedeelde bibliotheken -fPIC nodig?

De bibliotheek kan op elk adres worden geladen, dus haar code moet absolute adressen vermijden. PIC gebruikt PC-relatieve adressering en de GOT, zodat codepages niet hoeven te worden aangepast en kunnen worden gedeeld.

Wat betekent "not found" in de uitvoer van ldd?

De dynamische linker kan die gedeelde bibliotheek niet in zijn zoekpad vinden, dus het programma start niet totdat de bibliotheek is geïnstalleerd of het pad is gecorrigeerd.
