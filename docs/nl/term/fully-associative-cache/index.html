Wat is Fully associative?

Cache-opbouw waarin elk gegeven op elke plaats in de cache kan staan. Er zijn geen conflictmissers, maar alle tags moeten worden vergeleken, waardoor het niet geschikt is voor grote caches. Wordt gebruikt in onder meer de TLB.

Japanse benaming: フルアソシアティブ方式

“Fully associative” komt voor in 1 oefenvragen uit 1 onderwerpen, bijv. CPU en architectuur.

Vakgebied: Geheugenhiërarchie en prestaties

Geen index, alleen tag en offset

In een volledig associatieve cache is de hele cache één set, zodat elk blok in elke line kan worden opgeslagen. Er zijn geen bits nodig om een set te selecteren: de index is 0 bits, en het adres wordt alleen opgesplitst in een offset binnen de line en een tag die uit alle overige bits bestaat. Bij elke toegang moet de gevraagde tag tegelijk worden vergeleken met de tags van alle geldige lines, wat doorgaans gebeurt met content-addressable memory (CAM), waarin elke entry een eigen comparator heeft.

Waarom het alleen voor kleine structuren wordt gebruikt

Een CAM met N entries heeft N brede comparators nodig die bij elke lookup actief zijn, plus een grote multiplexer om de overeenkomende data af te leveren. Oppervlak, vermogen en hittijd groeien snel met het aantal entries, dus grote datacaches zijn in plaats daarvan set-associatief. Volledige associativiteit is betaalbaar en de moeite waard in kleine structuren die intensief worden gebruikt en waar elke miss duur is, zoals translation lookaside buffers (TLB's) die paginatabel-entries cachen, of kleine victim caches die lines bewaren die recent uit een direct-mapped cache zijn verdrongen.

De vervangingsstrategie bepaalt de prestaties

Omdat elke line kan worden verdrongen, heeft de cache een vervangingsstrategie nodig. Least recently used (LRU) verdringt de line die het langst niet is gebruikt. Met twee lines en de referentiereeks A, B, A, C, B, A geeft LRU vijf misses: door de hit op A wordt B het slachtoffer wanneer C binnenkomt, en daarna worden A en C beurtelings verdrongen. Echte LRU wordt kostbaar om bij te houden voor veel entries, dus hardware gebruikt vaak pseudo-LRU of willekeurige vervanging. LRU presteert ook slecht bij cyclische patronen die iets groter zijn dan de cache, waar willekeurige vervanging het beter kan doen.

Wat volledige associativiteit niet kan oplossen

Volledige associativiteit elimineert conflictmisses, omdat blokken nooit om een bepaalde set concurreren. In het gebruikelijke model met drie categorieën worden conflictmisses zelfs gedefinieerd als de misses die een volledig associatieve cache van dezelfde grootte zou vermijden. Compulsory misses bij de eerste toegang blijven bestaan, net als capacity misses wanneer de werkset groter is dan de hele cache. Die vereisen een grotere cache, prefetching of het herstructureren van code zodat data eerder wordt hergebruikt, bijvoorbeeld door loop blocking (tiling).

Nu oefenen: vragen over Fully associative

Welke uitspraak over een set-associatieve cache is juist?

  1. ADe gegevens van een adres kunnen op een van meerdere plaatsen (ways) binnen een vaste set worden geplaatst
  2. BDe plaats waar de gegevens van een adres kunnen staan, ligt vast op één plek in de cache
  3. CDe gegevens kunnen overal in de cache worden geplaatst
Antwoord en toelichting tonen

Antwoord: A. De gegevens van een adres kunnen op een van meerdere plaatsen (ways) binnen een vaste set worden geplaatst

Bij een set-associatieve cache wordt de set bepaald door een deel van het adres, en kunnen de gegevens op een van meerdere ways daarbinnen worden geplaatst. Bij 8 ways zijn er bijvoorbeeld 8 kandidaatplaatsen, zodat conflicten om dezelfde plaats (conflictmisses) minder vaak voorkomen dan bij direct mapped. Meer ways betekent meer vergelijkingsschakelingen en meer vermogen; gebruikelijk zijn circa 8 tot 12 ways in L1 en circa 16 ways in L3. Gegevens overal kunnen plaatsen is een fully associative cache.

Veelgestelde vragen

Hoeveel indexbits heeft een volledig associatieve cache?

Nul. De hele cache is één set, dus het adres bestaat alleen uit een tag en een offset, en de tag wordt met elke line vergeleken.

Waarom zijn TLB's vaak volledig associatief?

TLB's zijn klein en elke miss dwingt een kostbare page table walk af, dus de extra comparators zijn het waard om conflictmisses volledig te vermijden.

Elimineert een volledig associatieve cache alle misses?

Nee. Hij verwijdert conflictmisses, maar compulsory misses bij het eerste gebruik en capacity misses door een werkset die groter is dan de cache treden nog steeds op.
