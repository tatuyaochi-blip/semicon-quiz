Wat is NUMA?

Afkorting van Non-Uniform Memory Access. Opzet waarin sommige geheugens dicht bij een core liggen en andere ver weg, en toegang tot ver geheugen meer tijd kost. Het is sneller als gegevens en threads aan dezelfde kant staan.

Japanse benaming: NUMA

“NUMA” komt voor in 4 oefenvragen uit 3 onderwerpen, bijv. Multicore en synchronisatie, Prestatiemeting en profiling, DRAM.

Vakgebied: Multicore en synchronisatie

Waarom geheugentoegang niet-uniform wordt

Moderne processors integreren hun geheugencontrollers, dus in een server met meerdere sockets heeft elke socket zijn eigen direct aangesloten DRAM. Een core die geheugen op zijn eigen socket benadert, gaat rechtstreeks via zijn lokale controller; geheugen op een andere socket benaderen vereist een tocht over de verbinding tussen sockets en via de controller op afstand. De groep cores plus hun lokale geheugen heet een NUMA-node. Toegangen op afstand vertonen doorgaans een merkbaar hogere latentie, vaak ruwweg 1,3 tot 2 keer die van lokaal, en een lagere bandbreedte, waarbij de exacte verhouding afhangt van het platform en hoe zwaar de verbinding wordt belast.

NUMA versus UMA en versus clusters

In een systeem met uniform memory access (UMA), vaak een machine met één socket en één geheugencontrollercomplex, ziet elke core elk adres tegen ongeveer dezelfde kosten. Een cache-coherent NUMA-systeem (ccNUMA) behoudt één gedeelde adresruimte en hardwarematige cachecoherentie, zodat ongewijzigde programma's correct draaien; alleen hun snelheid hangt af van waar data staat. Dat onderscheidt het van een cluster van afzonderlijke computers, waar elke node een eigen adresruimte heeft en data expliciet via message passing moeten worden uitgewisseld. Grote processors op basis van chiplets kunnen ook binnen één socket meer dan één NUMA-node tonen.

First-touch-plaatsing en de valkuil ervan

Linux plaatst een pagina meestal op de node van de thread die er als eerste naar schrijft, niet op die van de thread die hem toewees, omdat malloc alleen virtuele adressen reserveert. Als één thread een grote array met nullen initialiseert, belandt elke pagina op de node van die thread, en latere parallelle lussen op andere nodes draaien bijna volledig vanuit geheugen op afstand, terwijl één geheugencontroller verzadigd is en de andere stilstaan. De oplossing is data parallel te initialiseren met dezelfde werkverdeling als de berekening, zodat het deel van elke thread lokaal bij die thread terechtkomt.

Tools en goede praktijk

Op Linux toont numactl --hardware de nodes, hun geheugen en een afstandstabel waarin lokale toegang volgens conventie 10 is en waarden op afstand groter zijn. Dezelfde tool kan een proces binden aan de CPU's en het geheugen van een node, of pagina's over nodes interleaven, wat past bij data die elke thread gelijkmatig leest. Threads vastpinnen (CPU-affiniteit instellen) voorkomt dat de scheduler een thread bij zijn data vandaan migreert en maakt benchmarks reproduceerbaar. De kernel kan pagina's ook automatisch naar de threads migreren die ze gebruiken, maar expliciete plaatsing is voorspelbaarder voor prestatiekritische code.

Nu oefenen: vragen over NUMA

Welke uitleg over een NUMA-systeem (Non-Uniform Memory Access) is juist?

  1. AAlle cores hebben dezelfde toegangstijd tot al het geheugen
  2. BEr is geheugen dichtbij en ver van een core, en toegang tot ver geheugen kost meer tijd
  3. CElke core kan alleen zijn eigen geheugen lezen en het geheugen van andere cores niet gebruiken
Antwoord en toelichting tonen

Antwoord: B. Er is geheugen dichtbij en ver van een core, en toegang tot ver geheugen kost meer tijd

In bijvoorbeeld servers met meerdere CPU-sockets is er per socket rechtstreeks verbonden geheugen, en het geheugen van andere sockets wordt via de verbinding tussen sockets benaderd. Daardoor is ver geheugen trager dan nabij geheugen en is ook de bandbreedte kleiner. Alle geheugen is als één adresruimte zichtbaar, dus programma's werken ongewijzigd, maar als gegevens en threads aan dezelfde kant worden geplaatst, nemen de prestaties toe.

Waarop moet worden gelet bij het first-touch-beleid dat vaak wordt gebruikt in Linux-NUMA-systemen (een pagina wordt geplaatst in het geheugen van het knooppunt waarop de thread draait die er het eerst naar schrijft)?

  1. ABij first touch worden pagina's op willekeurige knooppunten geplaatst
  2. BOp het moment dat malloc wordt aangeroepen, ligt de plaats van alle pagina's vast
  3. CAls een grote array door slechts één thread op 0 wordt geïnitialiseerd, komt alles op één knooppunt en gebruiken threads op andere knooppunten ver geheugen
Antwoord en toelichting tonen

Antwoord: C. Als een grote array door slechts één thread op 0 wordt geïnitialiseerd, komt alles op één knooppunt en gebruiken threads op andere knooppunten ver geheugen

Met malloc alleen worden nog geen fysieke pagina's toegewezen; bij de paginafout bij de eerste schrijfactie worden ze in het geheugen van het knooppunt van die thread geplaatst. Als de initialisatie door één thread gebeurt, komt de hele array op dat knooppunt, en bij de parallelle berekening is een groot deel van het door elke thread bewerkte gedeelte ver geheugen. Als de initialisatie parallel met dezelfde taakverdeling als de berekening gebeurt, komt elk deel in de buurt van de bijbehorende thread.

Veelgestelde vragen

Hoe controleer ik of mijn machine NUMA is?

Voer op Linux lscpu of numactl --hardware uit; staat er meer dan één NUMA-node vermeld, dan hangen de kosten van geheugentoegang af van de locatie. De meeste servers met twee sockets tonen ten minste twee nodes.

Moeten programma's worden herschreven voor NUMA?

Nee, een ccNUMA-machine biedt één coherente adresruimte, dus programma's draaien zoals ze zijn correct. Herschrijven is alleen van belang voor de prestaties, vooral door de data van elke thread op zijn eigen node te houden.

Wat is het first-touch-beleid?

Het is de gangbare regel dat een fysieke pagina wordt toegewezen op de NUMA-node van de thread die er als eerste naar schrijft. Daarom is parallelle initialisatie van arrays belangrijk op NUMA-systemen.
