Wat is Secure boot?

Mechanisme dat in elke opstartfase de digitale handtekening controleert van de volgende software en alleen de juiste software start. Bouwt een vertrouwensketen op.

Japanse benaming: セキュアブート

“Secure boot” komt voor in 7 oefenvragen uit 1 onderwerpen, bijv. Hardwarebeveiliging.

Vakgebied: Hardwarebeveiliging

Hoe de chain of trust werkt

Bij het inschakelen laadt bootcode in het ROM van de chip de eerste bootloader en controleert ze de digitale handtekening ervan: ze berekent de hash van het image en verifieert de handtekening van de leverancier over die hash. Alleen als de controle slaagt, voert ze de bootloader uit, die op zijn beurt de volgende fase of de OS-kernel verifieert voordat hij de controle overdraagt. Elke schakel staat in voor de volgende en zo ontstaat een chain of trust. Als een handtekening niet klopt, stopt het opstarten, dus malware die de bootloader of de opstartcode van het OS herschrijft, kan niet draaien. Smartphones, pc's en veel embedded apparaten gebruiken dit schema.

De root of trust in silicium

De keten is maar zo sterk als haar eerste controle, dus de root of trust moet onveranderlijk zijn: bootcode in mask-ROM, vastgelegd bij de fabricage, plus de publieke sleutel waarmee handtekeningen worden geverifieerd, vaak als hash opgeslagen in eFuses (eenmalig programmeerbare zekeringen) om ruimte te besparen. Publieke-sleutelcryptografie is hier belangrijk. Bij een symmetrisch schema zou de sleutel die verifieert ook kunnen ondertekenen, dus het extraheren ervan uit één apparaat zou valse firmware voor alle apparaten mogelijk maken. Met handtekeningen op basis van publieke sleutels bevatten apparaten alleen een verificatiesleutel en verlaat de private ondertekeningssleutel nooit de beveiligde faciliteit van de leverancier.

Anti-rollback en vergrendelde debugpoorten

Handtekeningcontroles alleen accepteren nog steeds oude firmware, omdat de leverancier die legitiem heeft ondertekend. Nadat een kwetsbaarheid is verholpen, zou een aanvaller de kwetsbare versie opnieuw kunnen installeren, dus images dragen een versienummer en de chip bewaart een minimaal toegestane versie in eenmalig beschrijfbare opslag zoals eFuses, die bij elke update wordt verhoogd. Debugpoorten zoals JTAG en SWD kunnen geheugen lezen en schrijven en de processor stilzetten, wat secure boot volledig zou omzeilen, dus geleverde producten schakelen ze uit met zekeringen of openen ze alleen na cryptografische authenticatie.

Secure boot versus measured boot

Secure boot dwingt af: ongeverifieerde code start niet. Measured boot registreert: elke fase berekent de hash van de volgende en verwerkt het resultaat in de platform configuration registers van een TPM (trusted platform module), waarin een nieuwe waarde alleen kan ontstaan door de oude waarde te combineren met een nieuwe hash. Het opstarten gaat hoe dan ook door, maar dankzij de registratie kan software of een externe server later precies verifiëren wat er heeft gedraaid. Merk ook op dat een handtekening authenticiteit bewijst, geen vertrouwelijkheid; om firmware geheim te houden is versleuteling nodig. Secure boot beschermt alleen het opstartpad, dus het is één laag in defense in depth, naast geheugenbescherming, trusted execution environments en sabotagebestendigheid.

Nu oefenen: vragen over Secure boot

Welke uitspraak over secure boot is juist?

  1. AEen mechanisme om een pc sneller op te starten
  2. BEen mechanisme dat in elke fase van het opstarten de digitale handtekening van de volgende software controleert en alleen correcte software start
  3. CEen mechanisme dat bij elke start de volledige inhoud van de schijf wist
Antwoord en toelichting tonen

Antwoord: B. Een mechanisme dat in elke fase van het opstarten de digitale handtekening van de volgende software controleert en alleen correcte software start

Bij secure boot controleert de code in een niet herschrijfbaar ROM de handtekening van de eerste bootloader, controleert die bootloader de handtekening van de volgende fase of de OS-kernel, enzovoort, zodat een vertrouwensketen wordt opgebouwd. Als op enig moment een handtekening niet klopt, wordt het opstarten gestopt, dus ook als malware de bootloader of het opstartgedeelte van het OS herschrijft, kan het niet worden gestart. Het wordt veel gebruikt bij smartphones, pc's en embedded apparaten.

Wat wordt het best als 'root of trust' (vertrouwensanker) van secure boot in de chip geplaatst?

  1. ADe opstartcode in een niet herschrijfbaar ROM en de publieke sleutel (of de hash daarvan) voor het controleren van handtekeningen
  2. BDe opstartcode in flashgeheugen dat door iedereen herschreven kan worden
  3. CHet nieuwste OS dat van internet is gedownload
Antwoord en toelichting tonen

Antwoord: A. De opstartcode in een niet herschrijfbaar ROM en de publieke sleutel (of de hash daarvan) voor het controleren van handtekeningen

De vertrouwensketen veronderstelt dat het deel dat de eerste controle uitvoert juist is. Daarom worden de opstartcode in een mask-ROM, dat bij de fabricage van de chip wordt geschreven en later niet kan worden gewijzigd, en de publieke sleutel waarmee handtekeningen worden gecontroleerd (om capaciteit te besparen wordt vaak de hash in een eFuse geschreven) als root of trust genomen. Als dit wordt herschreven, verliezen alle latere controles hun betekenis.

Veelgestelde vragen

Wat is de root of trust bij secure boot?

Onveranderlijke code in het mask-ROM van de chip, samen met de publieke sleutel, of de hash daarvan in eFuses, waarmee de eerste bootloader wordt geverifieerd. Alles wat later in de keten komt, is ervan afhankelijk dat deze onveranderlijk is.

Wat is het verschil tussen secure boot en measured boot?

Secure boot weigert software uit te voeren waarvan de handtekening niet klopt. Measured boot laat alles draaien, maar registreert hashes in een TPM, zodat de opstarttoestand later kan worden gecontroleerd of geattesteerd.

Waarom heeft secure boot anti-rollbackbescherming nodig?

Oudere firmwareversies hebben ook geldige handtekeningen, dus zonder een teller voor de minimale versie zou een aanvaller een versie met een bekende kwetsbaarheid opnieuw kunnen installeren.
